## 한 방향으로 늘어놓는 flex, 칸을 먼저 긋는 grid

Flexbox는 1차원 레이아웃이다. 아이템을 한 방향(가로 또는 세로)으로 늘어놓고, 그 방향의 남는 공간이나 모자란 공간을 아이템끼리 나눈다. 줄을 바꿔도(`flex-wrap: wrap`) 줄마다 따로 계산한다. 윗줄과 아랫줄의 칸이 서로 맞춰지지 않는다.

Grid는 2차원 레이아웃이다. 컨테이너에 가로 줄(행)과 세로 줄(열)을 먼저 긋고, 아이템을 그 칸에 넣는다. 한 열의 너비는 그 열의 모든 아이템에 똑같이 적용된다.

이 차이를 "내용에서 바깥으로"와 "바깥에서 내용으로"라고도 말한다. flex는 아이템의 내용 크기에서 출발해 공간을 나누고, grid는 컨테이너가 정한 트랙에서 출발해 아이템을 배치한다. 버튼 세 개를 내용 길이대로 늘어놓고 남는 공간을 오른쪽에 두는 건 flex의 일이다. 카드 열두 개를 세 열로 맞춰 세우는 건 grid의 일이다.

## 주축과 교차축

flex 컨테이너에는 축이 두 개 있다. `flex-direction`이 정하는 방향이 주축(main axis)이고, 그에 수직인 방향이 교차축(cross axis)이다. 기본값 `row`면 주축이 가로다.

- `justify-content`: 주축에서 남는 공간을 어디에 둘지 (`flex-start`, `center`, `space-between` …)
- `align-items`: 교차축에서 아이템을 어떻게 놓을지. 기본값은 `stretch`라 아이템이 줄 높이만큼 늘어난다
- `align-self`: 아이템 하나만 교차축 정렬을 바꾼다

`align-items: stretch`가 기본이라 생기는 일이 있다. 사이드바와 본문을 flex로 나란히 두면 사이드바가 본문 높이만큼 늘어난다. 높이를 맞추고 싶을 때는 고마운 동작이지만, 사이드바 안의 sticky가 움직일 자리가 사라지는 원인이 되기도 한다. 이 경우는 [sticky와 scroll-snap](/posts/css-sticky-scroll-snap)에서 재 봤다.

주축 방향의 `margin: auto`는 남는 공간을 모두 가져간다. 메뉴 항목들 중 마지막 "로그인" 버튼에만 `margin-left: auto`를 주면 그 버튼이 오른쪽 끝으로 밀린다. `justify-content`로는 아이템 하나만 따로 보낼 수 없어서 자주 쓰는 방법이다.

간격은 `gap`으로 준다. 아이템마다 마진을 주면 마지막 아이템 뒤에도 마진이 남아 `:last-child`로 지워야 하지만, `gap`은 아이템 사이에만 생긴다. flex의 `gap`은 크롬 84, 파이어폭스 63, 사파리 14.1부터 지원한다. 사파리 14.0 이하를 지원해야 하는 프로젝트가 아니라면 마진 대신 `gap`을 쓴다. `gap`은 공간을 나누기 전에 먼저 빠진다. 600px 컨테이너에 `gap: 20px`과 `flex: 1` 아이템 셋을 두면 600 − 40 = 560을 셋으로 나눠 각각 186.67px이다.

## 아이템 크기가 정해지는 순서

flex 아이템의 주축 크기는 세 값으로 정해진다. `flex-basis`(출발 크기), `flex-grow`(남을 때 더 가져가는 비율), `flex-shrink`(모자랄 때 덜 가져가는 비율)다. 브라우저는 대략 이 순서로 계산한다.

1. 아이템마다 `flex-basis`로 출발 크기를 정한다. `auto`면 `width`를, `width`도 `auto`면 내용 크기를 쓴다.
2. 컨테이너 크기에서 출발 크기의 합과 `gap`을 뺀다. 남으면 남는 공간, 음수면 모자란 공간이다.
3. 남으면 `flex-grow` 비율로 나눠 더한다.
4. 모자라면 `flex-shrink × flex-basis` 비율로 나눠 뺀다.
5. 결과가 `min-width`·`max-width`를 넘으면 그 값에 고정하고 나머지 아이템으로 다시 나눈다.

4번이 3번과 다르다는 점이 면접에서 자주 나온다. 늘릴 때는 grow 값만 보지만 줄일 때는 shrink에 basis를 곱한다. 큰 아이템이 더 많이 줄어들어야 비율이 유지되기 때문이다. shrink 값만 보면 작은 아이템이 큰 아이템과 같은 픽셀만큼 줄어 금방 0이 된다.

## flex: 1은 1 1 0%다

`flex`는 grow, shrink, basis를 한 번에 쓰는 단축 속성이다. 자주 쓰는 값이 실제로 무엇으로 펼쳐지는지 알아야 결과를 예측할 수 있다.

| 쓴 값 | 펼친 값 | 뜻 |
|---|---|---|
| (안 씀) | `0 1 auto` | 내용 크기로 출발, 늘어나지 않고 줄어들 수는 있다 |
| `flex: 1` | `1 1 0%` | 0에서 출발해 남는 공간을 비율대로 다 나눈다 |
| `flex: auto` | `1 1 auto` | 내용 크기로 출발해 남는 공간을 나눈다 |
| `flex: none` | `0 0 auto` | 내용 크기 그대로, 늘지도 줄지도 않는다 |
| `flex: 200px` | `1 1 200px` | 200px에서 출발해 남는 공간을 나눈다 |

`flex: 1`과 `flex: auto`의 차이는 출발 크기다. 600px 컨테이너에 "짧음"과 "조금 더 긴 텍스트가 들어 있는 칸" 두 아이템을 두었다.

```text
flex: 1     300   300
flex: auto  약 199  약 401
```

`flex: 1`은 둘 다 0에서 출발하니 600px 전체가 남는 공간이 되고 1:1로 나뉘어 정확히 반씩이다. 내용 길이는 상관없다. `flex: auto`는 각자 내용 폭에서 출발해 남는 공간만 1:1로 나누므로 긴 쪽이 더 넓다. 탭 버튼처럼 칸을 똑같이 나누고 싶으면 `flex: 1`, 내용에 비례해 나누고 싶으면 `flex: auto`다.

단축 속성의 함정이 하나 있다. `flex: 1`을 쓰면 basis가 `0%`로 바뀌므로, 같은 요소에 따로 적은 `width`는 basis로 쓰이지 않는다. "width: 200px을 줬는데 무시된다"면 `flex` 단축 속성이 basis를 덮었는지 본다.

## 직접 나눠 보기

위의 1~4단계를 함수로 옮겨 보자. 컨테이너 너비, gap, 아이템 목록(`basis`, `grow`, `shrink`)을 받아 각 아이템의 너비를 소수 둘째 자리까지 돌려준다. min·max 제한은 없다고 가정한다(모든 아이템이 `min-width: 0`).

  const space = container - gap * (items.length - 1);
  const free = space - items.reduce((s, i) => s + i.basis, 0);
  let sizes;
  if (free >= 0) {
    const g = items.reduce((s, i) => s + i.grow, 0);
    sizes = items.map((i) => (g === 0 ? i.basis : i.basis + (free * i.grow) / g));
  } else {
    const sc = items.reduce((s, i) => s + i.shrink * i.basis, 0);
    sizes = items.map((i) => (sc === 0 ? i.basis : i.basis + (free * i.shrink * i.basis) / sc));
  }
  return sizes.map((s) => Math.round(s * 100) / 100);
}`}

## 줄어들지 않는 아이템과 min-width: 0

flex 아이템의 `min-width` 초깃값은 0이 아니라 `auto`다. flex 아이템에서 `auto`는 "내용의 최소 크기"를 뜻한다. 글자라면 더 이상 줄을 바꿀 수 없는 가장 긴 단어의 폭, 이미지라면 지정한 너비다. 그래서 위 계산에서 아이템이 이 크기보다 작아져야 하면 브라우저는 최소 크기에 고정하고 넘치게 둔다.

처음 예제의 제목 칸에는 `white-space: nowrap`인 URL이 있었다. 줄을 바꿀 수 없으니 최소 크기가 URL 전체 폭 약 390px이고, 제목 칸은 그 아래로 줄지 못한다. 안쪽의 `overflow: hidden; text-overflow: ellipsis`는 자기 상자가 좁아야 말줄임표를 만드는데, 상자가 390px까지 늘어났으니 자를 게 없다. 크로미움에서 비교했다.

```text
300px 컨테이너, 40px 아이콘 + flex: 1 제목 칸
  min-width 기본(auto)    제목 칸 약 390   말줄임표 없음, 넘침
  min-width: 0            제목 칸 260      말줄임표 생김
  overflow: hidden        제목 칸 260      말줄임표 생김
  overflow: clip          제목 칸 약 390   말줄임표 없음, 넘침
```

고치는 방법은 둘이다. `min-width: 0`으로 최소 크기를 직접 0으로 내리거나, 아이템을 스크롤 컨테이너로 만드는 `overflow`(`hidden`, `auto`, `scroll`)를 준다. 명세는 내용 기반 최소 크기를 스크롤 컨테이너가 아닌 아이템에만 적용하기 때문이다. 그래서 스크롤 컨테이너를 만들지 않는 `overflow: clip`으로는 풀리지 않는다. 넘친 내용을 잘라도 되는 상황이면 `hidden`도 되지만, 의도를 드러내는 건 `min-width: 0` 쪽이다.

같은 문제가 여러 모양으로 나타난다.

- 이미지: 300px 컨테이너에 `width: 400px` 이미지를 flex 아이템으로 두면 이미지가 400px 그대로 넘친다. 지정 너비가 최소 크기가 된다.
- 코드 블록: `pre`나 넓은 표가 든 아이템이 줄지 않아 본문 칸 전체가 화면 밖으로 밀린다. 아이템에 `min-width: 0`을 주고 `pre`에 `overflow-x: auto`를 준다.
- 세로 방향: `flex-direction: column`이면 같은 문제가 `min-height: auto`로 생긴다. 스크롤 영역으로 만든 아이템이 스크롤되지 않고 늘어나면 `min-height: 0`을 준다.
- 긴 단어: `overflow-wrap: break-word`는 최소 크기 계산에 반영되지 않아 아이템을 줄이지 못한다. `overflow-wrap: anywhere`를 쓴다. 이 차이는 [박스 모델과 일반 흐름](/posts/css-box-model-layout)에서 재 봤다.

중첩된 flex에서는 바깥 아이템과 안쪽 아이템 모두에 `min-width: 0`이 필요할 수 있다. 바깥 아이템이 안쪽 내용의 최소 크기를 그대로 물려받기 때문이다. 넘친 상자를 찾으면 거기서부터 flex 아이템인 조상을 거슬러 올라가며 하나씩 확인한다.

## 줄을 바꾸면 마지막 줄이 늘어난다

flex로 카드 목록을 만들면 흔히 이렇게 쓴다.

```css
.list { display: flex; flex-wrap: wrap; }
.card { flex: 1 1 200px; } /* 200px에서 출발해 남는 공간을 나눈다 */
```

500px 컨테이너에 카드 세 장을 넣고 크로미움에서 쟀다.

```text
flex-wrap        첫 줄 250, 250   둘째 줄 500
grid auto-fill   첫 줄 250, 250   둘째 줄 250
```

flex는 줄마다 따로 공간을 나누기 때문에 둘째 줄에 혼자 남은 카드가 남는 공간 전체를 가져가 500px이 된다. 1차원이라는 말의 뜻이 이것이다. 윗줄의 칸에 맞추려면 `max-width`로 막거나 빈 아이템을 끼워 넣는 꼼수를 써야 한다. 행과 열을 함께 맞추는 게 목적이라면 처음부터 grid가 맞다. 아래 `repeat(auto-fill, minmax(200px, 1fr))` 한 줄이 같은 목록을 칸에 맞춰 세운다.

## Grid는 트랙을 먼저 정한다

grid는 `grid-template-columns`와 `grid-template-rows`로 트랙(열과 행)의 크기를 먼저 정한다. 크기에는 고정 길이, 퍼센트, `auto`, 그리고 `fr`을 쓸 수 있다.

`fr`은 남는 공간의 몫이다. 고정 크기 트랙과 `gap`을 먼저 빼고 남은 공간을 `fr` 비율로 나눈다.

```css
.layout {
  display: grid;
  width: 600px;
  grid-template-columns: 200px 1fr 2fr;
  gap: 30px;
}
```

```text
200   113.33   226.67
```

600 − 200 − 30 × 2 = 340을 1:2로 나눠 113.33px과 226.67px이다. flex의 grow와 비슷하지만 대상이 아이템이 아니라 트랙이라서, 그 열에 들어가는 모든 아이템이 같은 너비를 갖는다.

### 1fr도 내용보다 작아지지 않는다

`1fr`은 사실 `minmax(auto, 1fr)`이다. 최솟값 `auto`가 flex의 `min-width: auto`처럼 내용의 최소 크기를 지킨다. 그래서 grid에서도 같은 넘침이 생긴다.

```html
<div style="display: grid; width: 300px; grid-template-columns: 1fr 1fr">
  <pre>const veryLongVariableName = 1;</pre>
  <div></div>
</div>
```

```text
1fr 1fr              약 298.6   약 1.4
minmax(0, 1fr) 1fr   150        150
```

반씩 나뉠 줄 알았던 두 열이 약 298.6px과 1.4px이 됐다. `pre`는 줄을 바꾸지 않으니 그 열의 최소 크기가 코드 한 줄 폭이고, 나머지 열이 남은 것만 받았다. 열 정의를 `minmax(0, 1fr)`로 바꾸면 최솟값이 0이 되어 정확히 반씩 나뉘고, 넘친 코드는 `pre`의 `overflow: auto`로 스크롤된다. 본문과 사이드바 레이아웃에서 코드 블록 하나가 본문 열을 밀어내는 증상이 이것이다.

## auto-fill과 auto-fit

`repeat()`는 같은 트랙을 반복한다. 반복 횟수에 숫자 대신 `auto-fill`이나 `auto-fit`을 쓰면 "들어갈 수 있는 만큼"이 된다. `minmax(200px, 1fr)`과 함께 쓰면 미디어 쿼리 없이 화면 폭에 맞춰 열 수가 바뀌는 카드 목록이 된다.

둘은 아이템이 트랙 수보다 적을 때만 다르다. 1000px 컨테이너에 카드 두 장을 넣고 `grid-template-columns`의 계산값을 읽었다.

```text
repeat(auto-fill, minmax(200px, 1fr))   200px 200px 200px 200px 200px
repeat(auto-fit,  minmax(200px, 1fr))   500px 500px 0px 0px 0px
```

## 영역에 이름 붙이기

`grid-template-areas`는 레이아웃을 글자로 그린다. 같은 이름이 차지한 칸이 하나의 영역이 된다.

```css
.page {
  display: grid;
  grid-template-columns: 240px minmax(0, 1fr);
  grid-template-rows: auto minmax(0, 1fr) auto;
  grid-template-areas:
    "header header"
    "nav    main"
    "footer footer";
}
.page > header { grid-area: header; }
.page > nav    { grid-area: nav; }
.page > main   { grid-area: main; }
.page > footer { grid-area: footer; }
```

영역은 사각형이어야 한다. `"a b" "b b"`처럼 ㄱ자 모양을 만들면 선언 전체가 무효가 되어 아무 영역도 생기지 않는다. 빈 칸은 `.`으로 적는다. 화면 폭에 따라 `grid-template-areas`만 바꾸면 HTML을 건드리지 않고 배치를 통째로 바꿀 수 있다.

이 자유에는 대가가 있다. 화면에 보이는 순서와 HTML 순서가 달라진다. 키보드의 Tab 이동과 스크린 리더는 HTML 순서를 따른다. 화면에서는 사이드바가 왼쪽에 먼저 보여도 HTML에서 본문 뒤에 있으면, Tab을 누를 때 본문의 링크를 다 지난 뒤에야 사이드바로 간다. flex의 `order`, `flex-direction: row-reverse`도 같다. 읽는 순서가 의미를 갖는 내용이면 HTML 순서를 화면 순서와 맞추고, grid로는 위치만 정한다.

## 서브그리드로 카드 안쪽 줄 맞추기

카드 세 장을 grid로 나란히 놓았다. 카드마다 제목, 본문, 버튼이 있는데 제목 길이가 달라서 본문 시작 위치와 버튼 위치가 카드마다 어긋난다. 카드 안쪽도 grid로 만들 수 있지만, 카드 안의 grid는 자기 내용만 보고 행 높이를 정하므로 옆 카드와 맞지 않는다.

서브그리드(`subgrid`)는 자식 grid가 자기 트랙을 따로 만들지 않고 부모 grid의 트랙을 그대로 쓰게 한다.

```css
.cards {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 16px;
}
.card {
  display: grid;
  grid-row: span 3;              /* 부모의 행 세 개를 차지하고 */
  grid-template-rows: subgrid;   /* 그 세 행을 자기 행으로 쓴다 */
}
```

이제 세 카드의 제목 행은 부모 grid의 같은 행이라 가장 긴 제목에 맞춰 높이가 정해지고, 본문과 버튼이 모든 카드에서 같은 높이에 선다. 브라우저 지원은 파이어폭스 71, 사파리 16, 크롬·엣지 117부터다. 2023년 9월 이후로 주요 브라우저가 모두 지원하지만, 그 전 버전 사파리나 크롬을 써야 하는 환경이라면 `@supports (grid-template-rows: subgrid)`로 감싸고, 지원하지 않을 때는 카드마다 줄이 어긋나는 모양을 감수하는 식으로 점진적으로 적용한다.

## 칸에 넣지 않고 단을 따라 흐르는 multi-column

grid와 비슷해 보이지만 전혀 다르게 움직이는 레이아웃이 하나 더 있다. multi-column은 신문처럼 단(column)을 나누고, 내용이 첫 단을 위에서 아래로 채운 뒤 다음 단으로 넘어간다. grid가 아이템을 칸에 하나씩 놓는다면, multi-column에는 아이템이라는 개념이 없다. 블록 하나의 내용 전체가 단을 따라 흐를 뿐이다.

```css
.notes {
  column-width: 16rem;   /* 단 하나의 목표 폭. 들어가는 만큼 단을 만든다 */
  column-gap: 1.5rem;
  /* column-count: 3;    함께 주면 단 수의 상한이 된다 */
}
.note {
  break-inside: avoid;   /* 카드 하나가 두 단에 걸쳐 잘리지 않게 한다 */
}
```

`column-width`는 정확한 폭이 아니라 목표값이다. 명세의 계산은 단 수를 `(컨테이너 폭 + gap) ÷ (column-width + gap)`의 소수점 아래를 버린 값(최소 1)으로 정하고, 남는 폭은 단끼리 똑같이 나눈다. 800px 컨테이너에 위 규칙(256px, gap 24px)이면 824 ÷ 280 = 2.94라서 2단이 되고, 단 하나는 824 ÷ 2 − 24 = 388px이다. 390px 화면에서 좌우 16px 여백을 뺀 358px이면 1단으로 접힌다. 미디어 쿼리 없이 화면 폭에 따라 단 수가 바뀌니 `auto-fill`과 닮았다.

`break-inside: avoid`를 빼먹으면 카드의 위쪽 절반은 첫 단 맨 아래에, 아래쪽 절반은 둘째 단 맨 위에 그려진다. 긴 글을 신문처럼 읽게 하려는 원래 용도에서는 자연스러운 일이지만 카드 목록에서는 버그로 보인다. `column-gap`은 단 사이만 벌리니 카드 사이의 세로 간격은 카드의 `margin-bottom`으로 준다.

높이가 제각각인 카드를 빈틈없이 쌓는 메이슨리 배치를 multi-column으로 흉내 내는 경우가 많다. grid는 같은 행의 카드가 가장 키 큰 카드에 맞춰 빈 공간을 남기는데, multi-column은 단마다 위에서부터 차곡차곡 쌓으니 빈틈이 없다. 대신 순서가 세로로 흐른다. 카드 1~9를 3단에 넣으면 첫 단에 1·2·3, 둘째 단에 4·5·6이 선다. 눈은 왼쪽에서 오른쪽으로 읽으니 맨 윗줄에 1·4·7이 보인다. 최신순 목록이라면 두 번째로 새로운 글이 오른쪽 옆이 아니라 첫 글 아래에 숨는다. 무한 스크롤로 카드를 덧붙이면 더 곤란하다. 내용 전체가 다시 흐르면서 이미 보던 카드가 다른 단으로 옮겨 간다.

순서가 중요하지 않은 사진 모음이라면 multi-column으로 충분하다. 왼쪽에서 오른쪽 순서가 의미를 갖는다면 자바스크립트로 카드 높이를 재서 가장 짧은 단에 하나씩 넣거나, 카드를 단 수만큼 번갈아 나눠 단마다 flex 열로 쌓는다. 키보드 Tab 순서는 어느 쪽이든 HTML 순서를 따르니, 화면에서 보이는 순서와 크게 어긋나지 않는지 함께 본다. grid 자체에 메이슨리 배치를 넣는 명세가 논의되고 있고 일부 브라우저가 실험적으로 구현하고 있지만, 아직 모든 브라우저에서 기본으로 쓸 수 있는 단계는 아니다.

## 개발자 도구로 트랙과 남는 공간 보기

flex와 grid는 눈에 보이지 않는 선과 공간으로 동작해서, 화면만 봐서는 어느 단계에서 크기가 정해졌는지 알기 어렵다. 크롬 개발자 도구에는 이걸 그려 주는 기능이 있다.

Elements 패널에서 flex나 grid 컨테이너 옆에 `flex`, `grid`라는 작은 배지가 붙는다. 배지를 누르면 페이지 위에 오버레이가 켜진다. grid 오버레이는 트랙 경계선, 선 번호, `gap` 영역을 빗금으로 보여 주고, Layout 탭에서 트랙 크기와 영역 이름 표시를 켤 수 있다. `1fr 1fr`인데 한 열이 거의 0이 된 앞의 예제에 오버레이를 켜면 오른쪽 열이 선 하나처럼 좁아진 게 바로 보인다. flex 오버레이는 아이템 사이의 남는 공간과 정렬을 점선으로 표시한다.

크기를 숫자로 확인할 때는 아이템을 선택하고 Computed 탭의 `width`와 `min-width`를 본다. `min-width`가 `auto`로 나오면 내용 기반 최소 크기가 걸려 있을 수 있다는 신호다. 콘솔에서는 컨테이너를 선택한 뒤 아래처럼 실제 트랙 크기를 읽는다.

```js
// grid 컨테이너의 실제 열 너비(px로 계산된 값)
getComputedStyle($0).gridTemplateColumns;
// flex 아이템들의 실제 너비
[...$0.children].map((el) => el.getBoundingClientRect().width);
```

```text
"500px 500px 0px 0px 0px"
[500, 500]
```

`gridTemplateColumns`의 계산값은 `repeat()`와 `fr`을 모두 풀어 픽셀로 돌려준다. 앞에서 auto-fill과 auto-fit의 차이를 확인한 것도 이 값이다. `0px` 트랙이 보이면 auto-fit이 빈 트랙을 접은 것이다.

## 무엇을 고를까

둘 중 하나가 정답인 경우는 드물고, 한 화면에 둘을 섞어 쓰는 게 보통이다. 고를 때는 "크기를 누가 정하나"를 묻는다.

내용이 크기를 정해야 하면 flex다. 버튼 묶음, 내비게이션 메뉴, 아이콘과 글자 한 줄, 태그 목록처럼 아이템마다 길이가 다르고 남는 공간을 어딘가에 몰아 두면 되는 경우다. 한 줄 안의 정렬(가운데 맞추기, 끝으로 밀기)도 flex가 간단하다.

컨테이너가 크기를 정해야 하면 grid다. 페이지 뼈대, 카드 격자, 폼의 라벨과 입력칸 정렬처럼 행과 열이 서로 맞아야 하는 경우다. 아이템을 겹쳐 놓아야 할 때도 grid가 쉽다. 두 아이템에 같은 `grid-area`를 주면 `position: absolute` 없이 같은 칸에 겹친다.

어느 쪽이든 아이템이 줄어들지 않고 넘치면 가장 먼저 `min-width: 0`(grid는 `minmax(0, 1fr)`)을 떠올린다. 그다음은 넘친 아이템이 flex 아이템인 조상을 거슬러 올라가며 확인한다. 화면 폭에 따라 이 배치를 바꾸는 방법과 컨테이너 쿼리는 반응형 디자인을 다룬 글에서 따로 다룬다.

## 면접에서 나올 만한 질문

### Flexbox와 Grid의 차이는? 각각 언제 쓰나?

Flexbox는 한 방향으로 아이템을 늘어놓고 그 방향의 남는 공간을 나누는 1차원 레이아웃이고, Grid는 행과 열의 트랙을 먼저 긋고 아이템을 칸에 넣는 2차원 레이아웃이다. flex는 줄을 바꿔도 줄끼리 칸이 맞지 않는다. 내용이 크기를 정하는 메뉴·버튼 묶음은 flex, 행과 열을 맞춰야 하는 페이지 뼈대·카드 격자는 grid를 쓴다.

### flex: 1은 정확히 무슨 값인가? flex: auto와 어떻게 다른가?

`flex: 1`은 `1 1 0%`다. 출발 크기가 0이라 컨테이너 전체를 grow 비율로 나누고, 그래서 내용 길이와 상관없이 같은 너비가 된다. `flex: auto`는 `1 1 auto`라 각자 내용 크기에서 출발해 남는 공간만 나누므로 긴 아이템이 더 넓다. `flex: 1`을 쓰면 basis가 0%로 바뀌어 따로 쓴 `width`가 basis로 쓰이지 않는다.

### 공간이 모자랄 때 flex-shrink는 어떻게 나누나?

`flex-shrink × flex-basis` 비율로 모자란 양을 나눠 뺀다. 600px 컨테이너에 basis 200, 300, 400px 아이템을 shrink 1로 두면 모자란 300px을 2:3:4로 나눠 133.33, 200, 266.67px이 된다. 늘릴 때는 grow만 보지만 줄일 때 basis를 곱하는 건, 큰 아이템이 더 많이 줄어야 비율이 유지되기 때문이다.

### flex 아이템에 text-overflow: ellipsis가 안 먹고 넘친다. 왜 그런가?

flex 아이템의 `min-width` 초깃값이 `auto`이고, 이게 내용의 최소 크기를 뜻하기 때문이다. `nowrap` 텍스트나 긴 URL이 있으면 그 폭 아래로 줄어들지 않아서 안쪽에서 자를 게 없다. 아이템에 `min-width: 0`을 주거나 `overflow: hidden`처럼 스크롤 컨테이너를 만드는 값을 주면 줄어들고 말줄임표가 생긴다. 세로 방향이면 `min-height: 0`이다.

### grid에서 1fr 1fr인데 두 열이 반씩 안 나뉜다. 왜 그런가?

`1fr`은 `minmax(auto, 1fr)`이라 최솟값이 내용의 최소 크기다. 줄을 바꿀 수 없는 코드 블록이나 긴 단어가 한 열에 있으면 그 열이 내용 폭까지 커지고 다른 열이 남은 것만 받는다. `minmax(0, 1fr)`로 최솟값을 0으로 내리면 정확히 나뉘고, 넘친 내용은 그 요소의 `overflow`로 처리한다.

### auto-fill과 auto-fit의 차이는?

둘 다 들어가는 만큼 트랙을 반복하는데, 아이템이 트랙 수보다 적을 때 빈 트랙을 다루는 방식이 다르다. `auto-fill`은 빈 트랙을 그대로 남겨 열 너비를 유지하고, `auto-fit`은 빈 트랙을 0으로 접어서 아이템이 든 트랙이 남은 공간을 나눠 갖는다. 1000px에 `minmax(200px, 1fr)` 카드 두 장이면 auto-fill은 200px씩, auto-fit은 500px씩이다.

### grid-template-areas나 order로 순서를 바꿀 때 주의할 점은?

화면 순서만 바뀌고 HTML 순서는 그대로라서 Tab 이동과 스크린 리더는 HTML 순서를 따른다. 화면에서 앞에 보이는 링크로 포커스가 뒤늦게 가는 식으로 어긋난다. 읽는 순서가 의미를 갖는 내용은 HTML 순서를 화면 순서와 맞추고 시각적 위치만 grid로 조정한다.

### subgrid는 무엇을 풀어 주나? 지금 써도 되나?

자식 grid가 자기 트랙을 만들지 않고 부모 grid의 트랙을 그대로 쓰게 해서, 나란히 놓인 카드들의 제목·본문·버튼 줄을 서로 맞춘다. 파이어폭스 71, 사파리 16, 크롬·엣지 117부터 지원해서 2023년 9월 이후 주요 브라우저가 모두 지원한다. 오래된 브라우저를 지원해야 하면 `@supports`로 감싸 지원하지 않는 곳에서는 줄이 어긋나는 정도로 물러나게 한다.
