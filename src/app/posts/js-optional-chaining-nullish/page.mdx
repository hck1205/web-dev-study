주문 상세 화면이 특정 주문에서만 하얗게 비었다. 콘솔에는 오류 한 줄이 남아 있었다. 매장 픽업 주문은 배송 정보가 없어서 서버가 `shipping: null`을 내려 주는데, 화면 코드는 배송지가 늘 있다고 믿고 있었다.

```js
const order = { id: 1, shipping: null };
try { console.log(order.shipping.address.city); } catch (e) { console.log(e.message); }
console.log(order.shipping?.address.city);
console.log(order.shipping?.address?.city ?? "주소 없음");
```

```text
Cannot read properties of null (reading 'address')
undefined
주소 없음
```

`?.` 하나로 오류가 사라지고, `??` 하나로 기본 문구가 생겼다. 둘 다 ES2020에 들어온 문법이다. 짧아서 아무 데나 찍기 쉬운데, 어디서 멈추는지와 무엇을 "없음"으로 보는지를 정확히 알아야 버그를 숨기지 않는다. 이 글은 옵셔널 체이닝(`?.`)이 체인을 어디까지 건너뛰는지, `??`와 `||`가 언제 갈리는지, `??=`가 왜 대입을 건너뛰는지, React에서 `?? []`가 일으키는 effect 반복까지 따라간다. 출력은 모두 Node 22에서 돌린 결과다.

falsy 값의 목록과 `if (!x)`의 함정은 [truthy·falsy 글](/posts/js-truthy-falsy-typeof)에서, `&&`와 `||`가 값을 돌려주는 방식은 [단락 평가 글](/posts/js-short-circuit)에서 다룬다. 여기서는 그 위에서 `?.`와 `??`만 본다.

## 물음표 하나가 체인을 멈춘다

`a?.b`는 "`a`가 `null`이나 `undefined`면 거기서 멈추고 `undefined`를 돌려주고, 아니면 `a.b`를 읽는다"는 뜻이다. 검사하는 것은 왼쪽 값 하나뿐이다. 그래서 `?.`를 어디에 찍느냐가 중요하다.

```js
const o2 = { shipping: {} };
try { console.log(o2.shipping?.address.city); } catch (e) { console.log(e.message); }
```

```text
Cannot read properties of undefined (reading 'city')
```

`shipping`은 빈 객체라서 `?.`는 통과했다. 그다음 `address`가 `undefined`인데 그 뒤는 평범한 `.`이라 `city`를 읽다가 터졌다. `?.`는 "이 체인 전체를 안전하게"가 아니라 "바로 왼쪽 값이 없을 수 있다"는 표시다. 아래 그림에서 다음을 누르며 `order.shipping?.address.city`가 한 칸씩 읽히는 모습을 보자.

## 한 번 멈추면 체인 끝까지 건너뛴다

그림의 마지막 단계가 중요하다. `?.`에서 멈추면 그 뒤에 이어지는 `.city`, `[key]`, `()`는 하나도 실행하지 않는다. 명세에서는 이것을 단락(short-circuit)이라고 부른다. `undefined.city`를 읽다가 터지는 것이 아니라 아예 읽으러 가지 않는다. 그 안에 든 함수 호출도 부르지 않는다.

```js
let calls = 0;
const id = () => { calls++; return "k"; };
const nothing = null;
console.log(nothing?.[id()], nothing?.a.b.c(id()), calls);
const obj = { a: { b: 1 } };
console.log(obj?.[id()], calls);
```

```text
undefined undefined 0
undefined 1
```

`nothing`이 `null`이라 대괄호 안의 `id()`도, `c(id())`의 인자도 평가되지 않았다(`calls`가 0). `obj`가 있을 때만 `id()`가 한 번 불렸다. 엔진 입장에서 `a?.b.c.d`는 대략 이런 코드다.


`nothing?.a`는 `undefined`가 됐고, 괄호 밖의 `.b`는 그 `undefined`에서 읽으려다 터졌다. 줄이 길어 괄호로 감싸고 줄을 나누다가 이 실수를 하기 쉽다.

`?.`는 세 모양이 있다. 점 접근 `a?.b`, 계산된 키 `a?.[key]`, 호출 `fn?.(args)`다. 아래 식을 조각으로 눌러 보면 각 `?.`가 무엇을 검사하는지 보인다.

`fn?.()`는 함수가 "없을 수 있을 때" 쓰는 것이지 "함수가 아닐 수 있을 때" 쓰는 것이 아니다.

```js
const api = { name: "api", hello() { return this?.name; } };
console.log(api.hello?.(), api.bye?.());
try { api.name?.(); } catch (e) { console.log(e.message); }
```

```text
api undefined
api.name is not a function
```

`api.hello?.()`는 메서드로 불려서 `this`가 `api`다. `api.bye`는 없으니 부르지 않고 `undefined`다. 그런데 `api.name`은 문자열이라 `?.`가 통과시키고, 문자열을 부르다 터졌다. React 컴포넌트에서 `onChange?.(value)`처럼 선택적 콜백 prop을 부를 때 흔히 쓰는 모양인데, prop 타입이 함수 또는 `undefined`라는 전제가 있어야 안전하다.

선언되지 않은 변수에는 `?.`가 소용없다. `?.`는 값이 `null`인지 보는 것이지 이름이 있는지 보는 것이 아니다. Node에서 `document?.title`을 돌리면 `ReferenceError: document is not defined`가 그대로 난다. 서버 렌더링 코드에서 브라우저 전역을 확인할 때는 `typeof document !== "undefined"`를 쓴다.

## 옵셔널 체이닝을 쓸 수 없는 자리

`?.`는 읽기 전용이다. 왼쪽에 놓고 대입하거나, `new`나 태그 템플릿과 섞으면 문법 오류다. 실제 오류 문구는 이렇다.

```js
a?.b = 1;      // SyntaxError: Invalid left-hand side in assignment
x?.y++;        // SyntaxError: Invalid left-hand side expression in postfix operation
new a?.b();    // SyntaxError: Invalid optional chain from new expression
a?.b`x`;       // SyntaxError: Invalid tagged template on optional chain
```

"없으면 대입하지 마"라는 뜻으로 `a?.b = 1`을 쓰고 싶어지는데, 그런 문법은 없다. `if (a) a.b = 1`로 쓴다. 반대로 `delete a?.b`는 허용된다. `a`가 없으면 아무것도 지우지 않고 `true`를 돌려준다.

## null 병합은 null과 undefined만 없는 값으로 본다

`??`는 null 병합 연산자(nullish coalescing operator)라고 부른다. `a ?? b`는 `a`가 `null`이나 `undefined`일 때만 `b`를 고른다. `||`는 `a`가 falsy이기만 하면 `b`를 고른다. 차이가 나는 값은 `0`, `""`, `false`, `NaN` 네 개다.

```js
const values = [0, "", false, NaN, null, undefined];
for (const v of values)
  console.log(String(v).padEnd(9), "||", String(v || "기본").padEnd(4), "??", String(v ?? "기본"));
```

```text
0         || 기본   ?? 0
          || 기본   ?? 
false     || 기본   ?? false
NaN       || 기본   ?? NaN
null      || 기본   ?? 기본
undefined || 기본   ?? 기본
```

어느 쪽이 맞는지는 데이터의 의미가 정한다. 수량, 금액, 할인율, 켜짐·꺼짐 설정처럼 `0`과 `false`가 정상 값인 곳은 `??`다. 화면에 보일 이름처럼 빈 문자열도 "없음"으로 보고 싶은 곳은 `||`가 맞을 수 있다. 습관적으로 `||`를 전부 `??`로 바꾸면 빈 제목이 빈칸으로 보이는 다른 버그가 생긴다.

### 기본 매개변수와 구조 분해의 기본값은 undefined에만 듣는다

함수의 기본 매개변수(`limit = 20`)와 구조 분해의 기본값(`{ size = "M" }`)은 `??`와 비슷해 보이지만 기준이 하나 다르다. `undefined`일 때만 기본값을 쓰고, `null`은 값으로 받는다.

```js
function withDefault(limit = 20) { return limit; }
console.log(withDefault(undefined), withDefault(null), withDefault(0));
const { size = "M" } = { size: null };
console.log(size);
const fromQuery = (v) => v ?? 20;
console.log(fromQuery(undefined), fromQuery(null), fromQuery(0));
```

```text
20 null 0
null
20 20 0
```

JSON에는 `undefined`가 없어서 서버가 "값 없음"을 `null`로 보내는 일이 많다. 그 응답을 구조 분해 기본값으로 받으면 기본값이 들어가지 않고 `null`이 그대로 남는다. API 응답에는 `??`를 쓰는 편이 안전하다. 구조 분해의 다른 함정은 [구조 분해 글](/posts/js-destructuring)에 모아 뒀다.

## 괄호 없이는 섞을 수 없다

`??`는 `||`나 `&&`와 괄호 없이 한 식에 섞으면 문법 오류다.

```js
const a = 0, b = 1, c = 2;
const r = a ?? b || c;
```

```text
const a = 0, b = 1, c = 2; const r = a ?? b || c;
                                            ^^

SyntaxError: Unexpected token '||'
```

```js
console.log((a ?? b) || c, a ?? (b || c));
```

```text
2 0
```

괄호 위치에 따라 결과가 `2`와 `0`으로 갈린다. 명세는 어느 쪽이 맞는지 정하지 않고 개발자에게 괄호를 쓰라고 강제했다. 반면 다른 연산자와는 우선순위대로 섞인다. `??`는 우선순위가 아주 낮아서 산술 연산이 먼저 끝난다.

```js
const bonus = null;
console.log(10 + bonus ?? 5, 10 + (bonus ?? 5));
const b2 = undefined;
console.log(10 + b2 ?? 5, 10 + (b2 ?? 5));
```

```text
10 15
NaN 15
```

`10 + bonus ?? 5`는 `(10 + bonus) ?? 5`다. `null`은 덧셈에서 `0`이 되니 `10`, `undefined`는 `NaN`이 된다. 둘 다 `null`이 아니니 `?? 5`는 아무 일도 하지 않는다. 기본값을 계산에 쓸 때는 반드시 괄호로 감싼다. 삼항 연산자 앞도 마찬가지로 `a ?? 0 ? "참" : "거짓"`은 `(a ?? 0) ? ...`으로 묶인다.

`?.`와 산술이 만나도 같은 문제가 생긴다. `x?.price * x?.qty`는 `x`가 `null`이면 `undefined * undefined`라 `NaN`이다. `?.`는 오류를 막아 줄 뿐 계산 결과를 지켜 주지 않는다.

## 비어 있을 때만 대입하는 논리 대입

ES2021에는 논리 대입 연산자 `??=`, `||=`, `&&=`가 들어왔다. `a ??= b`는 `a = a ?? b`와 결과가 같아 보이지만 한 가지가 다르다. `a`가 이미 값이 있으면 대입 자체를 하지 않는다.

```js
const settings = {
  _theme: "dark",
  get theme() { return this._theme; },
  set theme(v) { console.log("setter 호출:", v); this._theme = v; },
};
settings.theme ??= "light";
settings.theme = settings.theme ?? "light";
```

```text
setter 호출: dark
```

첫 줄에서는 setter가 불리지 않았다. 두 번째 줄은 같은 값 `"dark"`를 다시 넣느라 setter를 불렀다. setter가 저장이나 이벤트 발행을 한다면, 또는 Proxy로 감싼 반응형 상태라면 이 차이가 불필요한 저장과 다시 그리기로 이어진다. 얼린 객체에서도 차이가 난다.

```js
"use strict";
const frozen = Object.freeze({ lang: "ko" });
frozen.lang ??= "en";
console.log("??= 통과");
try { frozen.lang = frozen.lang ?? "en"; } catch (e) { console.log(e.message); }
```

```text
??= 통과
Cannot assign to read only property 'lang' of object '#<Object>'
```

이 성질 덕분에 `??=`는 "처음 한 번만 계산해서 저장"하는 지연 초기화에 잘 맞는다.

```js
const memo = {};
function load(key) {
  return (memo[key] ??= (console.log("계산", key), key.length));
}
console.log(load("abc"), load("abc"), load("de"));
```

```text
계산 abc
계산 de
3 3 2
```

아래 그림에서 다음을 누르면 같은 키를 두 번 부를 때 두 번째는 계산까지 가지 않는 모습이 보인다.

캐시 값이 `0`이나 `""`일 수 있다면 `||=`가 아니라 `??=`를 써야 한다. `||=`는 `0`을 비었다고 보고 매번 다시 계산한다. `&&=`는 반대로 값이 있을 때만 바꾼다. `user &&= normalize(user)`처럼 "있으면 다듬는다"에 쓴다.

## 오래된 환경으로 내려가면 코드가 길어진다

`?.`와 `??`는 크롬 계열 80 이후, 사파리 13.1 이후처럼 2020년 무렵의 브라우저부터 지원한다. 그보다 오래된 환경을 지원해야 하면 빌드 도구가 문법을 풀어 쓴다. TypeScript로 ES2019를 목표로 컴파일해 봤다.

```ts
const city = user?.profile?.address?.city ?? "주소 없음";
```

```js
var _a, _b, _c;
const city = (_c = (_b = (_a = user === null || user === void 0 ? void 0 : user.profile) === null || _a === void 0 ? void 0 : _a.address) === null || _b === void 0 ? void 0 : _b.city) !== null && _c !== void 0 ? _c : "주소 없음";
```

한 줄이 이렇게 불어난다. 결과는 같고 성능 차이도 거의 없지만, 번들 크기가 늘고 디버거에서 임시 변수가 보인다. 지원 범위가 넓지 않다면 browserslist 목표를 올려 변환을 끄는 것이 낫다. 풀어 쓴 코드가 `== null` 대신 `=== null || === void 0`을 쓰는 이유는 `document.all`처럼 `== null`이 참인 특이한 객체 때문이다.

## React에서 빈 배열 기본값이 effect를 계속 부른다

데이터 패칭 라이브러리로 받은 값은 처음 렌더링에서 `undefined`다. 그래서 컴포넌트에서는 `data?.items ?? []`를 자주 쓴다. 화면만 그린다면 문제없다. 그런데 이 값을 effect나 `useMemo`의 의존성에 넣으면 이야기가 달라진다. React 19.3과 jsdom으로 다시 렌더링을 두 번 일으켜 봤다.

```js
const EMPTY = [];
function List({ data, label, stable }) {
  const items = stable ? data?.items ?? EMPTY : data?.items ?? [];
  useEffect(() => {
    console.log(`${label}: effect 실행 (items ${items.length}개)`);
  }, [items]);
  return <ul>{items.map((x) => <li key={x}>{x}</li>)}</ul>;
}
// App은 data = undefined인 채로 List 두 개를 그리고, 상태를 바꿔 두 번 다시 렌더링한다
```

```text
?? []: effect 실행 (items 0개)
?? EMPTY: effect 실행 (items 0개)
-- 다시 렌더링 1
?? []: effect 실행 (items 0개)
-- 다시 렌더링 2
?? []: effect 실행 (items 0개)
```

`?? []`는 렌더링마다 새 배열을 만든다. 내용은 똑같이 비어 있어도 React는 의존성을 `Object.is`로 비교하니 매번 "바뀌었다"고 본다. effect 안에서 상태를 바꾸면 무한 렌더링이 된다. 모듈 바깥에 둔 `EMPTY`는 늘 같은 배열이라 첫 렌더링에서만 실행됐다.

같은 문제가 `?? {}`, `|| []`, 그리고 `props.options ?? defaultOptions`를 컴포넌트 안에서 객체 리터럴로 만들 때도 생긴다. 의존성 비교 규칙은 [리렌더링 글](/posts/react-rerender)에서 자세히 다룬다. 데이터 라이브러리의 `select`나 `placeholderData`로 처음부터 안정된 기본값을 받는 방법도 있다. 캐시 쪽 이야기는 [클라이언트 데이터 캐시 글](/posts/client-data-cache)에 있다.

## 물음표가 늘어날수록 버그는 조용해진다

`?.`는 오류를 없애 주지만 원인을 없애 주지는 않는다. 서버가 필드 이름을 `address`에서 `addr`로 바꾸면 `order?.shipping?.address?.city ?? ""`는 오류 없이 빈칸을 그린다. 오류 모니터링에도 잡히지 않는다. 사용자가 "주소가 안 보인다"고 문의해야 알게 된다.

그래서 기준을 둔다. "없는 게 정상인 값"에만 `?.`를 쓴다. 픽업 주문의 `shipping`처럼 API 명세상 `null`일 수 있는 값이다. 반대로 언제나 있어야 하는 값이 없다면 그건 계약이 깨진 것이니 조용히 넘기지 말고 드러내야 한다. 실무에서는 응답을 받는 경계에서 zod 같은 스키마 검사기로 한 번 검사하고, 안쪽 코드는 타입을 믿고 `?.` 없이 쓰는 구성을 많이 쓴다.

TypeScript에서는 `?.`의 반대편에 non-null 단언 `!`가 있다. `user!.name`은 "없을 리 없다"는 약속이라 검사 코드를 만들지 않는다. 약속이 틀리면 그대로 TypeError다. `?.`는 런타임에 검사하고, `!`는 컴파일러만 조용히 시킨다.

현장에서 이 문법이 얽힌 증상은 대개 이런 모양이다.

- 화면 일부가 비어 있는데 콘솔에 오류가 없다. 응답 JSON의 필드 이름과 `?.` 체인을 나란히 놓고 비교한다.
- 수량이 0인 상품에 기본값이 보인다. `||`로 기본값을 준 곳을 찾는다.
- 합계가 `NaN`으로 나온다. `?.`로 읽은 값이 산술에 들어갔거나, `a + b ?? 0`처럼 괄호가 빠졌다.
- effect가 렌더링마다 돈다. 의존성 중에 `?? []`나 `?? {}`로 만든 값이 있는지 본다.

## 없어도 되는 값에만 물음표를 찍는다

`?.`는 바로 왼쪽 값이 `null`이나 `undefined`인지 보고, 그렇다면 체인의 나머지를 통째로 건너뛰어 `undefined`를 돌려준다. `??`는 같은 두 값만 "없음"으로 보고 기본값을 고르니 `0`, `""`, `false`를 지킨다. `??=`는 값이 이미 있으면 대입조차 하지 않는다. 셋 다 "없을 수 있는 값"을 다루는 도구이고, 없으면 안 되는 값에 쓰면 오류 대신 빈 화면을 얻는다. 같은 단락 개념이 `&&`와 `||`에서는 어떻게 동작하는지 [단락 평가 글](/posts/js-short-circuit)에서 이어 본다.

## 면접에서 나올 만한 질문

### 옵셔널 체이닝은 무엇을 검사하나

바로 왼쪽 값이 `null`이나 `undefined`인지 검사한다. 그렇다면 속성을 읽지 않고 `undefined`를 돌려준다. 체인 전체를 검사하는 것이 아니라서 `a?.b.c`는 `a.b`가 `undefined`면 `.c`에서 TypeError가 난다. 없을 수 있는 자리마다 따로 붙여야 한다.

### a?.b.c에서 a가 null이면 .c는 어떻게 되나

실행되지 않는다. `?.`에서 멈추면 같은 체인에 이어지는 속성 접근, 대괄호 안의 식, 함수 호출과 그 인자까지 모두 건너뛰고 체인 전체가 `undefined`가 된다. 이것을 단락이라고 한다. 단, 괄호로 `(a?.b).c`처럼 감싸면 체인이 끊겨서 `undefined.c`를 읽다가 터진다.

### ??와 ||의 차이는

`||`는 왼쪽이 falsy면 오른쪽을 고르고, `??`는 `null`이나 `undefined`일 때만 오른쪽을 고른다. 그래서 `0`, `""`, `false`, `NaN`에서 결과가 갈린다. 수량이나 설정 플래그처럼 0과 false가 정상 값이면 `??`를 쓴다. 빈 문자열도 없음으로 보고 싶다면 `||`가 맞을 수 있다.

### 기본 매개변수와 ??는 무엇이 다른가

기본 매개변수와 구조 분해 기본값은 `undefined`일 때만 적용되고 `null`은 값으로 받는다. `??`는 `null`에도 기본값을 쓴다. JSON 응답은 없는 값을 `null`로 보내는 경우가 많아서 구조 분해 기본값만 믿으면 `null`이 그대로 들어온다.

### a ?? b || c는 왜 문법 오류인가

`??`를 `||`나 `&&`와 괄호 없이 섞는 것을 명세가 금지했기 때문이다. `(a ?? b) || c`와 `a ?? (b || c)`는 결과가 다를 수 있는데, 어느 쪽인지 헷갈리지 않게 괄호를 강제했다. 산술과는 섞이는데 `??`의 우선순위가 낮아서 `10 + x ?? 5`는 `(10 + x) ?? 5`가 된다.

### a ??= b와 a = a ?? b는 같은가

결과 값은 같지만 동작이 다르다. `??=`는 `a`가 이미 값이 있으면 대입을 아예 하지 않아서 setter나 Proxy 트랩이 불리지 않고, 얼린 객체에서도 오류가 나지 않는다. `a = a ?? b`는 언제나 대입한다. 그래서 `??=`는 지연 초기화나 캐시에 잘 맞는다.

### React에서 const items = data?.items ?? []를 쓰면 생길 수 있는 문제는

`[]`가 렌더링마다 새로 만들어져 의존성 비교에서 매번 바뀐 것으로 보인다. 이 값을 `useEffect`나 `useMemo`의 의존성에 넣으면 렌더링마다 다시 실행되고, effect에서 상태를 바꾸면 무한 렌더링이 된다. 모듈 밖에 빈 배열 상수를 두거나 `useMemo`로 감싸서 같은 객체를 유지한다.

### 옵셔널 체이닝을 많이 쓰면 안 좋은 이유는

필수 값이 빠진 계약 위반을 오류 없이 `undefined`로 덮어서, 빈 화면만 남고 모니터링에도 잡히지 않는다. 없는 게 정상인 값에만 쓰고, 응답 경계에서 스키마 검사로 한 번 걸러 안쪽 코드는 타입을 믿는 편이 낫다. 오래된 목표 환경으로 변환하면 코드가 길어지는 부수 비용도 있다.
