회의 예약 기능을 만들다 보면 "새 예약이 기존 예약과 겹치나"를 판정하는 코드를 쓰게 된다. 처음 짠 코드는 대개 조건문 네 개로 "앞쪽이 걸치는 경우, 뒤쪽이 걸치는 경우, 안에 들어가는 경우, 밖을 감싸는 경우"를 다 나눈다. 그러다 하나를 빠뜨린다. 겹침 판정은 사실 한 줄이면 된다.

구간 문제는 LeetCode에서 하나의 묶음으로 나온다. 합치기, 끼워 넣기, 최소 제거, 동시에 겹치는 최대 개수, 교집합. 이 글은 이 묶음을 푸는 틀을 정리하는 허브다. 문제 하나하나의 풀이는 문제 글에 있고, 여기서는 왜 정렬부터 하는지, 무엇으로 정렬해야 하는지, 경계값(닫힌 구간과 열린 구간)이 어디서 답을 바꾸는지를 본다. 시작 기준 정렬과 끝 기준 정렬이 맞는 이유는 그리디의 교환 논증과 이어지는데, 그 증명은 [그리디 알고리즘](/posts/greedy-algorithms)에 자세히 있다. 전체 공부 순서는 [LeetCode 공부법](/posts/leetcode-study-guide)에 있다.

## 두 구간이 겹치는 조건은 한 줄이다

구간 `[a, b]`와 `[c, d]`가 겹치지 않는 경우는 둘뿐이다. 하나가 완전히 앞에 있거나(`b < c`), 완전히 뒤에 있거나(`d < a`). 나머지는 전부 겹친다. 그러니 겹치는 조건은 그 둘의 부정이다.

```js
// 닫힌 구간 [a, b]와 [c, d]: 끝점이 닿아도 겹친다고 본다
const overlapsClosed = (a, b, c, d) => a <= d && c <= b;
// 반쯤 열린 구간 [a, b)와 [c, d): 끝점이 닿는 건 겹치지 않는다 (회의 시간이 보통 이렇다)
const overlapsHalfOpen = (a, b, c, d) => a < d && c < b;
```

같은 말을 다르게 쓰면 `Math.max(a, c) <= Math.min(b, d)`다. 더 늦은 시작이 더 이른 끝보다 앞이면 겹친다. 이 식은 겹침 판정과 동시에 교집합 `[max(a, c), min(b, d)]`를 알려 줘서 쓸모가 많다. 아래에서 교집합 문제를 풀 때 그대로 쓴다.

조건문 네 개짜리 코드가 틀리는 이유도 여기서 보인다. 겹치는 모양을 하나씩 나열하는 쪽은 경우가 많고, 겹치지 않는 모양은 둘뿐이다. 적은 쪽을 세고 뒤집는 게 덜 틀린다.

## 왜 정렬부터 하나

구간이 n개면 짝은 n(n − 1) / 2개다. 정렬 없이 겹침을 다 찾으려면 O(n²)이다. 시작 시각으로 정렬하면 이야기가 달라진다.

정렬된 순서에서 i번째 구간이 앞의 어떤 구간과 겹친다면, 앞 구간들을 합친 결과 중 마지막 것과 반드시 겹친다. 앞 구간들은 모두 i보다 일찍 시작했으니 i와 겹치려면 i의 시작보다 늦게 끝나야 한다. 그런 구간이 있다면 마지막 합친 구간의 끝이 그 끝 이상이다. 마지막 합친 구간의 끝은 지금까지 나온 끝 중 가장 큰 값이기 때문이다. 그래서 정렬 뒤에는 "마지막 하나와만 비교"가 안전하다. 정렬 O(n log n) + 한 번 훑기 O(n)이 된다.

## 시작 순으로 합치기

[Merge Intervals](/posts/leetcode-merge-intervals)의 틀이다.

```js
function merge(intervals) {
  const a = [...intervals].sort((x, y) => x[0] - y[0]); // 입력을 건드리지 않으려고 복사한다
  const out = [];
  for (const [s, e] of a) {
    const last = out.at(-1);
    if (last && s <= last[1]) last[1] = Math.max(last[1], e); // 겹치면 끝을 늘린다
    else out.push([s, e]);                                   // 떨어져 있으면 새로 넣는다
  }
  return out;
}
console.log(JSON.stringify(merge([[8, 10], [1, 3], [2, 6], [15, 18], [9, 12]])));
console.log(JSON.stringify(merge([[1, 4], [4, 5]])), JSON.stringify(merge([[1, 10], [2, 3], [4, 5]])));
```

```text
[[1,6],[8,12],[15,18]]
[[1,5]] [[1,10]]
```

두 군데가 자주 틀린다. 첫째, `Math.max` 없이 `last[1] = e`로 쓰면 앞 구간이 뒤 구간을 감싸는 경우가 깨진다. `[[1, 10], [2, 3], [4, 5]]`를 그렇게 돌리면 `[[1,3],[4,5]]`가 나온다. `[2, 3]`이 끝을 10에서 3으로 줄여 버렸다. 둘째, `s <= last[1]`의 등호다. LeetCode 56번은 `[1, 4]`와 `[4, 5]`를 겹친다고 보고 `[1, 5]`로 합친다. 닫힌 구간이라는 뜻이다. 회의실 예약처럼 반쯤 열린 구간이라면 `<`로 바꿔야 한다. 이 차이는 아래 "경계값" 섹션에서 문제별로 모아 본다.

## 이미 정렬된 목록에 끼워 넣기

[Insert Interval](/posts/leetcode-insert-interval)은 겹치지 않고 정렬된 목록에 새 구간 하나를 넣는다. 이미 정렬돼 있으니 정렬을 다시 할 필요가 없고, 한 번 훑어서 O(n)에 끝난다. 훑는 구간이 세 덩어리로 나뉜다.

```js
function insert(intervals, [s, e]) {
  const out = [];
  let i = 0;
  while (i < intervals.length && intervals[i][1] < s) out.push(intervals[i++]); // 1. 새 구간보다 완전히 앞
  while (i < intervals.length && intervals[i][0] <= e) {                        // 2. 새 구간과 겹친다
    s = Math.min(s, intervals[i][0]);
    e = Math.max(e, intervals[i][1]);
    i++;
  }
  out.push([s, e]);
  while (i < intervals.length) out.push(intervals[i++]);                        // 3. 완전히 뒤
  return out;
}
console.log(JSON.stringify(insert([[1, 2], [3, 5], [6, 7], [8, 10], [12, 16]], [4, 8])));
```

```text
[[1,2],[3,10],[12,16]]
```

두 번째 `while`의 조건이 위의 "겹치는 조건 한 줄"에서 왔다. 첫 `while`을 지났으니 `intervals[i][1] >= s`는 이미 성립하고, 남은 조건 `intervals[i][0] <= e`만 보면 된다. 목록 끝에 새 구간을 붙이고 다시 합치기를 돌려도 답은 같지만 O(n log n)이다. 면접에서는 "이미 정렬돼 있다는 걸 쓰라"는 신호로 읽는다.

## 끝 순으로 정렬해야 할 때

"겹치지 않게 하려면 최소 몇 개를 지워야 하나"([Non-overlapping Intervals](/posts/leetcode-non-overlapping-intervals))는 정렬 기준이 다르다. 많이 남기는 게 목표라서, 가장 일찍 끝나는 구간을 먼저 고르는 게 이득이다. 일찍 끝날수록 뒤에 남는 자리가 넓다.

시작 순으로 정렬해서 같은 그리디를 돌리면 틀린다. 실제로 비교해 봤다.

```js
const intervals = [[1, 10], [2, 3], [4, 5], [6, 7]];
// 끝 순 정렬 후 겹치지 않으면 남긴다 → 지울 개수
console.log("erase end", eraseByEnd(intervals), "naive start", eraseByStart(intervals));
```

```text
erase end 1 naive start 3
```

`eraseByEnd`와 `eraseByStart`는 정렬 기준만 다른 같은 코드다. 시작 순으로 하면 가장 먼저 시작한 `[1, 10]`을 남기고, 그게 나머지 셋을 모두 막아서 셋을 지운다. 끝 순으로 하면 `[2, 3]`, `[4, 5]`, `[6, 7]`을 남기고 `[1, 10]` 하나만 지운다. 정답은 1이다.

시작 순으로 정렬하고도 맞게 푸는 방법은 있다. 겹치면 "둘 중 끝이 더 늦은 쪽을 지운다"로 바꾸면 된다. 결국 끝이 이른 쪽을 남긴다는 같은 원리다. 어느 쪽이든, 왜 끝이 이른 걸 남겨도 손해가 없는지(교환 논증)를 말로 할 수 있어야 한다. 그 증명은 [그리디 알고리즘](/posts/greedy-algorithms)에서 그림과 함께 다뤘다. 풍선을 화살 최소 개수로 터뜨리는 문제(452번)도 같은 끝 순 정렬이다.

정리하면 기준은 이렇다. 구간을 합치거나 끼워 넣는 것처럼 "이어 붙이는" 문제는 시작 순이다. 최대한 많이 고르거나 최소로 지우는 "선택" 문제는 끝 순이다.

## 동시에 몇 개가 겹치나

회의실이 최소 몇 개 필요한지([Meeting Rooms](/posts/leetcode-meeting-rooms)의 II 변형)는 "어느 순간 동시에 열려 있는 구간의 최대 개수"와 같다. 가장 일반적인 풀이가 스위프 라인이다. 구간을 시작 사건(+1)과 끝 사건(−1)으로 쪼개 시각 순으로 늘어놓고, 왼쪽부터 쓸고 지나가며 누적 값을 센다.

```js
function maxOverlap(intervals) {
  const ev = [];
  for (const [s, e] of intervals) { ev.push([s, 1]); ev.push([e, -1]); }
  ev.sort((x, y) => x[0] - y[0] || x[1] - y[1]); // 같은 시각이면 -1(끝)이 먼저
  let cur = 0, best = 0;
  for (const [, d] of ev) { cur += d; best = Math.max(best, cur); }
  return best;
}
console.log(maxOverlap([[0, 30], [5, 10], [15, 20]]));
```


아래 그림에서 다음을 누르면 사건을 하나씩 쓸고 지나간다. 칸의 `+`는 시작, `−`는 끝이고, 오른쪽 상자는 지금 열려 있는 회의 수다.

## 두 목록의 교집합

정렬되고 서로 겹치지 않는 구간 목록 두 개의 교집합을 구하는 문제(986번)는 [투 포인터 패턴](/posts/two-pointers-pattern)의 "두 줄을 나란히 훑기"와 구간 겹침 공식이 만나는 곳이다. 두 포인터가 가리키는 구간의 교집합을 `[max(시작), min(끝)]`으로 구하고, 끝이 먼저 오는 쪽을 옮긴다. 끝이 먼저 오는 구간은 상대 목록의 다음 구간과 겹칠 수 없기 때문이다. 상대 목록의 다음 구간은 지금 상대 구간이 끝난 뒤에 시작하고, 지금 상대 구간은 내 구간보다 늦게 끝나니까.

직접 짜 보자. 이 문제의 구간은 닫힌 구간이라 `[1, 2]`와 `[2, 3]`의 교집합은 `[2, 2]`다. 내 풀이는 무작위 목록 3,000쌍으로 모든 짝을 비교하는 풀이와 같은 결과를 내는 걸 확인했다.

## 질의가 따로 올 때

[Minimum Interval to Include Each Query](/posts/leetcode-minimum-interval-to-include-each-query)(1851번)는 구간 목록과 질의(점) 목록이 따로 오고, 질의마다 그 점을 포함하는 가장 짧은 구간의 길이를 묻는다. 질의마다 모든 구간을 보면 O(nq)다.

여기서 쓰는 기술은 질의를 정렬해서 "오프라인"으로 처리하는 것이다. 질의를 작은 점부터 처리하면, 구간 중 시작이 그 점 이하인 것만 차례로 힙에 넣으면 된다. 힙은 길이가 짧은 순서이고, 맨 위 구간의 끝이 점보다 앞이면 이미 지나간 구간이니 꺼낸다. 질의 순서가 바뀌니 원래 순서대로 답을 돌려주려면 (점, 원래 인덱스) 쌍으로 정렬한다. 스위프 라인과 힙과 정렬이 한 문제에 다 나와서 이 묶음의 마지막 문제로 둔다.

## 경계값: 닫힌 구간과 열린 구간

구간 문제에서 가장 많이 틀리는 곳은 로직이 아니라 끝점이 닿는 경우다. 문제마다 정의가 다르니 예제에서 확인해야 한다.

- Merge Intervals(56번): `[1, 4]`와 `[4, 5]`를 합친다. 닿으면 겹친다. 비교는 `s <= last[1]`.
- Non-overlapping Intervals(435번): `[1, 2]`와 `[2, 3]`은 겹치지 않는다. 남길 조건은 `s >= end`.
- Meeting Rooms(252번): `[5, 10]`과 `[10, 15]`는 둘 다 참석할 수 있다. 반쯤 열린 구간이다.
- Interval List Intersections(986번): `[1, 2]`와 `[2, 3]`의 교집합은 `[2, 2]`다. 닫힌 구간이다.
- Minimum Arrows(452번): 풍선 `[1, 2]`와 `[2, 3]`은 x = 2에 쏜 화살 하나로 둘 다 터진다. 닫힌 구간이다.

문제 문장에 "touching", "inclusive"가 나오는지, 예제에 끝점이 닿는 경우가 있는지 본다. 없으면 면접관에게 묻는다. 묻는 것 자체가 좋은 신호다.

그 밖의 흔한 실수 몇 가지.

### 숫자 정렬 비교 함수를 빠뜨린다

자바스크립트에서 `intervals.sort()`는 배열을 문자열 `"10,12"`처럼 바꿔 사전 순으로 정렬한다. `[10, 12]`가 `[2, 6]`보다 앞에 온다. 항상 `(x, y) => x[0] - y[0]`처럼 숫자 비교 함수를 넣는다.

### Java에서 빼기로 비교한다

`(x, y) -> x[0] - y[0]`은 값이 int 범위 양 끝에 가까우면 빼기가 넘쳐 부호가 뒤집힌다. Java 21에서 시작값이 2147483646, −2147483646, 1인 구간을 두 방식으로 정렬해 봤다.

```text
[[2147483646, 2147483647], [-2147483646, 0], [1, 2]]
[[-2147483646, 0], [1, 2], [2147483646, 2147483647]]
```

위가 빼기 비교, 아래가 `Integer.compare`다. 빼기 비교는 정렬이 전혀 안 됐다. LeetCode 452번은 실제로 값 범위가 −2^31부터 2^31 − 1까지라 이 버그로 떨어진다. 자바스크립트는 숫자가 2^53까지 정확하니 이 문제가 없다.

### 입력 배열을 그대로 고친다

합치기에서 `last[1] = ...`로 결과를 고치는데, 결과에 입력의 배열 객체를 그대로 넣었다면 입력도 바뀐다. 채점에는 문제가 없지만 실무 코드에서는 호출한 쪽의 데이터가 몰래 바뀌는 버그가 된다. 위 코드처럼 `[s, e]`로 새 배열을 만들어 넣는다.

LeetCode의 Intervals 묶음을 이 블로그에서는 아래 순서로 푼다.

2. [Merge Intervals](/posts/leetcode-merge-intervals): 시작 순 정렬과 "마지막 결과 하나와 비교".

## 면접에서 나올 만한 질문

### 두 구간이 겹치는지 어떻게 판정하나요?

겹치지 않는 경우가 "완전히 앞"과 "완전히 뒤" 둘뿐이라 그 부정을 쓴다. 닫힌 구간이면 a ≤ d이고 c ≤ b일 때 겹친다. 같은 말로 max(시작) ≤ min(끝)이고, 이 식은 교집합 구간도 바로 준다. 반쯤 열린 구간이면 부등호에서 등호를 뺀다.

### 구간 문제는 왜 정렬부터 하나요?

시작 순으로 정렬하면 새 구간이 앞의 어떤 구간과 겹칠 때 마지막으로 합친 구간과도 반드시 겹친다. 마지막 결과의 끝이 지금까지 나온 끝 중 가장 크기 때문이다. 그래서 모든 짝을 볼 필요 없이 이웃 하나와만 비교해 O(n log n)에 끝난다.

### 시작 기준 정렬과 끝 기준 정렬은 언제 쓰나요?

합치기나 끼워 넣기처럼 구간을 이어 붙이는 문제는 시작 기준이다. 최대한 많이 고르거나 최소로 지우는 선택 문제는 끝 기준이다. 일찍 끝나는 구간을 남겨야 뒤에 남는 자리가 가장 넓다는 교환 논증이 근거다.

### 회의실이 최소 몇 개 필요한지는 어떻게 구하나요?

동시에 열려 있는 회의의 최대 개수와 같다. 시작을 +1, 끝을 −1 사건으로 만들어 시각 순으로 정렬하고 누적 값의 최대를 구한다. 같은 시각이면 끝을 먼저 처리해야 이어지는 회의가 방을 나눠 쓴다. 최소 힙에 끝 시각을 넣는 방법도 같은 답을 내고, 회의별 방 배정까지 알려 준다.

### 정렬된 구간 목록에 새 구간을 넣을 때 다시 정렬하지 않는 이유는요?

이미 정렬돼 있으니 한 번 훑어 새 구간보다 앞, 겹치는 것, 뒤 세 덩어리로 나누면 O(n)이다. 겹치는 것들은 시작의 최솟값과 끝의 최댓값으로 합친다. 붙이고 다시 정렬하면 O(n log n)이라 주어진 조건을 쓰지 않은 답이 된다.

### 두 구간 목록의 교집합에서 어느 포인터를 옮기나요?

끝이 먼저 오는 쪽을 옮긴다. 그 구간은 상대 목록의 다음 구간과 겹칠 수 없다. 상대의 다음 구간은 지금 상대 구간이 끝난 뒤에 시작하고, 지금 상대 구간은 내 구간보다 늦게 끝나기 때문이다.

### Java로 구간을 정렬할 때 조심할 점은요?

비교자를 x[0] − y[0]처럼 빼기로 쓰면 값이 int 범위 끝에 가까울 때 넘쳐서 정렬이 깨진다. Integer.compare를 쓴다. 값 범위가 int 전체인 문제(452번)에서 실제로 이 버그로 틀린다.
