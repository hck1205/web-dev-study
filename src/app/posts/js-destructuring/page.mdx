API를 부르는 작은 함수를 만들었다. 두 번째 인자로 옵션 객체를 받아 바로 꺼내 쓴다.

```js
function fetchJson(url, { retry, timeoutMs }) {
  // ...
}

fetchJson("/api/me");
```

옵션을 안 넘긴 호출에서 바로 터진다.

```text
TypeError: Cannot destructure property 'retry' of 'undefined' as it is undefined.
```

옵션 자리에 아무것도 안 넘겼으니 두 번째 인자는 `undefined`이고, `undefined`에서는 속성을 꺼낼 수 없다. 기본값 `= {}` 하나면 고쳐진다. 그런데 이번엔 다른 사람이 `fetchJson("/api/me", null)`이라고 불러서 또 터진다. 기본값을 줬는데도 터진다. 구조 분해(destructuring)는 한 줄로 많은 걸 해 주는 만큼, 그 한 줄이 어떤 순서로 무엇을 하는지 알아야 이런 사고를 피한다. 이 글은 그 순서를 따라간다. 기준은 Node 22와 최신 크롬 계열이다.

이 시리즈에서 `...`를 쓰는 전개와 나머지 문법은 [전개와 나머지 문법](/posts/js-spread-rest)에서, `?.`와 `??`는 [옵셔널 체이닝과 널 병합](/posts/js-optional-chaining-nullish)에서 따로 다룬다.

## 꺼내 담는 일을 한 줄로

구조 분해는 객체나 배열에서 값을 꺼내 변수에 담는 일을, 값의 모양을 본뜬 패턴으로 적는 문법이다. ES2015에 들어왔다.

```js
const res = { data: { user: { name: "kim" } }, status: 200 };

// 예전 방식
const data = res.data;
const status = res.status;

// 구조 분해
const { data, status } = res;
```

왼쪽의 `{ data, status }`는 객체를 만드는 게 아니라 "이 모양에서 이 이름으로 꺼내라"는 패턴이다. 오른쪽 값의 모양을 왼쪽에 그대로 그린다고 생각하면 된다. 아래 그림은 패턴의 각 자리가 오른쪽 객체의 어디와 이어지는지 보여 준다.

## 기본값은 undefined일 때만 들어간다

```js
const { a = 1, b = 2, c = 3, d = 4 } = { a: undefined, b: null, c: 0, d: "" };
console.log(a, b, c, d);
```

```text
1 null 0 
```

기본값이 들어간 건 `a` 하나다. 명세는 꺼낸 값이 정확히 `undefined`일 때만 기본값을 평가한다. `null`, `0`, 빈 문자열은 값이 있는 것으로 본다. `||`로 기본값을 주던 옛 코드(`retry || 3`)와 다르다. `||`는 `0`도 바꿔 버려서 "재시도 0번"을 표현할 수 없었는데, 구조 분해 기본값은 `0`을 지킨다. `??`와 비교하면 `??`는 `null`까지 바꾸고 구조 분해 기본값은 `null`을 그대로 둔다. 이 셋의 차이는 [옵셔널 체이닝과 널 병합](/posts/js-optional-chaining-nullish)에서 표로 비교한다.

서버 JSON에는 `undefined`가 없다는 점이 실무에서 중요하다. JSON은 없는 값을 `null`로 보낸다. 그래서 API 응답을 구조 분해하면서 기본값을 걸어 두면, 필드가 아예 빠진 응답에서는 기본값이 들어가지만 `"nickname": null`로 온 응답에서는 `null`이 그대로 들어온다. 화면에 "null님 환영합니다"가 찍히는 버그가 이렇게 생긴다.

### 기본값은 필요할 때만 계산한다

기본값 자리에는 함수 호출 같은 식도 쓸 수 있다. 이 식은 값이 `undefined`일 때만, 왼쪽에서 오른쪽 순서로 평가된다. getter도 꺼내는 순간 한 번 불린다.

```js
const obj = { get price() { console.log("  price getter"); return 100; } };
const fallback = () => { console.log("  fallback 호출"); return 0; };
const { price = fallback(), discount = fallback() } = obj;
console.log(price, discount);

const log = (s) => { console.log("  평가:", s); return s; };
const { [log("k1")]: v1 = log("d1"), [log("k2")]: v2 = log("d2") } = { k1: "x" };
console.log(v1, v2);
```

```text
  price getter
  fallback 호출
100 0
  평가: k1
  평가: k2
  평가: d2
x d2
```

## 배열 패턴은 이터레이터를 돈다

배열 구조 분해는 인덱스로 꺼내는 게 아니다. 오른쪽 값에서 이터레이터를 얻어 `next()`를 필요한 만큼 부른다. 그래서 배열이 아니어도 이터러블(문자열, Map, Set, 제너레이터)이면 된다.

```js
const [first, , third = "기본", ...others] = ["a", "b", undefined, "d", "e"];
console.log(first, third, others);

const [ch1, ch2] = "한글";
console.log(ch1, ch2);

const [[k1, v1]] = new Map([["id", 7]]);
console.log(k1, v1);

const [s1, s2] = new Set([1, 1, 2]);
console.log(s1, s2);
```

```text
a 기본 [ 'd', 'e' ]
한 글
id 7
1 2
```

쉼표만 쓰고 이름을 비우면 그 자리를 건너뛴다. Map을 돌면 `[키, 값]` 쌍이 나오니 패턴을 한 겹 더 쓴다.

이터레이터를 돈다는 걸 눈으로 확인해 보자. 제너레이터가 값을 내줄 때마다 로그를 찍게 했다.

```js
function* ids() {
  console.log("  next → 1"); yield 1;
  console.log("  next → 2"); yield 2;
  console.log("  next → 3"); yield 3;
  console.log("  끝");
}
console.log("[a, b] 시작");
const [a, b] = ids();
console.log("결과", a, b);

console.log("[a, ...rest] 시작");
const [h, ...t] = ids();
console.log("결과", h, t);
```

```text
[a, b] 시작
  next → 1
  next → 2
결과 1 2
[a, ...rest] 시작
  next → 1
  next → 2
  next → 3
  끝
결과 1 [ 2, 3 ]
```

꺼낼 자리를 다 채우면 이터레이터를 닫는다(명세의 IteratorClose). 그래서 `yield 3` 앞의 로그가 찍히지 않았다. 제너레이터 안에 `try...finally`가 있다면 이때 `finally`가 실행된다. 무한 제너레이터에서 앞의 몇 개만 꺼내는 건 안전하지만, `...rest`를 붙이면 끝나지 않는다.

이 차이는 성능에도 이어진다. 배열 패턴은 이터레이터 프로토콜을 따르기 때문에, 진짜 배열에서도 엔진은 원칙적으로 이터레이터 객체를 만들어야 한다. V8은 진짜 배열이면 이 과정을 상당 부분 최적화하지만, Babel로 ES5까지 내리는 설정이라면 배열 패턴이 이터레이터 헬퍼 코드로 바뀌어 번들이 커진다. 핫 루프에서 `const [x, y] = point`를 수백만 번 돌릴 일이 있다면 인덱스 접근과 비교해 볼 만하다.

### 원시값과 null에서 꺼낼 때

객체 패턴은 오른쪽이 원시값이면 래퍼 객체로 바꿔서 꺼낸다. 막는 건 `null`과 `undefined`뿐이다(명세의 RequireObjectCoercible). 배열 패턴은 오른쪽이 이터러블이어야 한다.

```js
const { length } = "hello";
console.log(length);
const { toFixed } = 1;
console.log(typeof toFixed);

try { const { x } = null; } catch (e) { console.log(`${e.name}: ${e.message}`); }
try { const [y] = {}; } catch (e) { console.log(`${e.name}: ${e.message}`); }
try { const [z] = null; } catch (e) { console.log(`${e.name}: ${e.message}`); }
```

```text
5
function
TypeError: Cannot destructure property 'x' of 'null' as it is null.
TypeError: {} is not iterable
TypeError: null is not iterable
```

`{} is not iterable`은 API가 배열 대신 객체(예를 들어 `{ items: [...] }`로 감싼 응답)를 줬을 때 `const [first] = res`에서 보게 되는 에러다. 응답 모양이 바뀐 걸 이 메시지로 알아챈다.

## 매개변수 자리에서 바로 꺼내기

함수 매개변수에도 패턴을 쓸 수 있다. 인자가 많은 함수를 옵션 객체 하나로 받으면, 호출하는 쪽은 이름을 붙여 넘기고 순서를 신경 쓰지 않아도 된다. 맨 앞의 `fetchJson`이 그 모양이다. 문제는 옵션 객체 자체가 안 올 때였다.

```js
function fetchJson(url, { retry = 3, timeoutMs = 5000 } = {}) {
  return [url, retry, timeoutMs];
}
console.log(fetchJson("/api/me"));
console.log(fetchJson("/api/me", { retry: 0 }));

try {
  fetchJson("/api/me", null);
} catch (e) {
  console.log(`${e.name}: ${e.message}`);
}
```

```text
[ '/api/me', 3, 5000 ]
[ '/api/me', 0, 5000 ]
TypeError: Cannot read properties of null (reading 'retry')
```

기본값이 두 겹이다. 바깥 `= {}`는 두 번째 인자가 `undefined`일 때 빈 객체를 쓰고, 안쪽 `retry = 3`은 그 객체에 `retry`가 없을 때 3을 쓴다. 둘 다 `undefined`에만 반응하니 `null`을 넘기면 바깥 기본값이 무시되고, `null`에서 `retry`를 꺼내다가 터진다. 같은 상황인데 에러 메시지가 "Cannot destructure"가 아니라 "Cannot read properties"인 것도 기억해 두면 로그를 읽을 때 도움이 된다(Node 22 기준이고 문구는 엔진 버전마다 조금씩 다르다).

`null`까지 받아야 하는 공개 API라면 패턴을 본문으로 옮긴다.

```js
function fetchJson(url, options) {
  const { retry = 3, timeoutMs = 5000 } = options ?? {};
  // ...
}
```

### 중첩이 깊을수록 터질 곳이 많다

중첩 패턴은 경로의 중간 값 하나만 없어도 터진다.

```js
try { const { data: { user } } = { status: 500 }; } catch (e) { console.log(`${e.name}: ${e.message}`); }
try { const { data: { user } } = { data: null }; } catch (e) { console.log(`${e.name}: ${e.message}`); }
```

```text
TypeError: Cannot read properties of undefined (reading 'user')
TypeError: Cannot read properties of null (reading 'user')
```

에러 응답에는 `data`가 없는 API가 많다. 성공 응답만 보고 `const { data: { user } } = await res.json()`을 쓰면 서버가 500을 준 날 화면 전체가 깨진다. 중첩 패턴은 모양이 보장된 데이터(내가 만든 객체, 스키마 검증을 통과한 응답)에만 쓰고, 바깥에서 온 데이터는 먼저 검증하거나 `res.data?.user`처럼 경로마다 확인한다. 패턴 두세 겹을 넘어가면 읽기도 어렵다.

## 이미 있는 변수에 담을 때 생기는 두 가지 함정

`const`나 `let` 없이 이미 선언한 변수에 패턴으로 대입할 수도 있다. 객체 패턴은 괄호로 감싸야 한다.

```js
let p, q;
const point = { p: 1, q: 2 };
({ p, q } = point); // 괄호 필수
console.log(p, q);
```

```text
1 2
```

괄호를 빼면 문장 맨 앞의 `{`를 블록으로 읽어서 문법 에러가 난다.

```text
{ p, q } = point;
         ^

SyntaxError: Unexpected token '='
```

배열 패턴 쪽 함정은 더 조용하다. 세미콜론 없이 쓰는 스타일에서 두 변수를 맞바꾸는 코드다.

```js
let a = 1, b = 2
const list = [3, 4]
[a, b] = [b, a]
console.log(a, b)
```

```text
1 2
```

## React 코드 곳곳의 구조 분해

React 코드는 구조 분해 없이 거의 쓸 수 없다. 세 군데에서 자주 보인다.

첫째, 훅의 반환값이다. `useState`가 객체가 아니라 배열(튜플)을 돌려주는 건 이름을 마음대로 붙이게 하려는 설계다. 객체였다면 `const { value: count, setValue: setCount } = useState(0)`처럼 매번 이름을 바꿔야 했다. 직접 만드는 훅도 같은 판단을 한다.

```js
function useToggle(init) {
  let v = init;
  return [v, () => (v = !v)];
}
const [isOpen, toggleOpen] = useToggle(false);
const [isDark, toggleDark] = useToggle(true);
console.log(isOpen, typeof toggleOpen, isDark, typeof toggleDark);
```

```text
false function true function
```

같은 훅을 한 컴포넌트에서 두 번 써도 이름이 겹치지 않는다. 반대로 돌려줄 값이 서너 개를 넘으면 순서를 외워야 하니 객체로 돌려주는 편이 낫다. TanStack Query의 `useQuery`가 `{ data, isPending, error }` 객체를 돌려주는 이유다.

둘째, props다. `function Card({ title, size = "md", ...rest })`처럼 매개변수에서 바로 꺼내고 기본값을 준다. 함수 컴포넌트의 `defaultProps`는 React 19에서 제거됐고, 매개변수 기본값이 그 자리를 대신한다.

셋째, 여기서 실무 사고가 난다. props 기본값에 객체나 배열 리터럴을 쓰면 렌더링마다 새 객체가 만들어진다.

```jsx
function Profile({ userId, options = {} }) {
  const [data, setData] = useState(null);
  useEffect(() => {
    fetchProfile(userId, options).then(setData);
  }, [userId, options]); // options가 매번 새 객체
  return <p>{data?.id}</p>;
}
```

`options`를 안 넘기면 렌더링마다 새 `{}`가 생기고, 의존성 배열은 참조로 비교하니 매번 바뀐 것으로 본다. effect가 돌고, `setData`가 렌더링을 부르고, 또 새 `{}`가 생긴다. 아래 그림이 그 고리다.

## 반복문과 콜백에서 쓰는 패턴

`Object.entries`와 배열 패턴을 같이 쓰면 객체를 키와 값으로 돌 수 있다. 콜백 매개변수에서 바로 꺼내는 것도 흔하다.

```js
const stock = { apple: 3, pear: 0, kiwi: 12 };
for (const [name, count] of Object.entries(stock)) {
  if (count === 0) console.log(`${name} 품절`);
}

const low = Object.entries(stock)
  .filter(([, count]) => count < 5) // 키는 건너뛰고 값만
  .map(([name]) => name);
console.log(low);

const users = [{ id: 1, profile: { nick: "kim" } }, { id: 2, profile: { nick: "lee" } }];
console.log(users.map(({ id, profile: { nick } }) => `${id}:${nick}`));
```

```text
pear 품절
[ 'apple', 'pear' ]
[ '1:kim', '2:lee' ]
```

콜백 매개변수의 중첩 패턴도 앞에서 본 것과 같은 위험이 있다. `profile`이 없는 사용자가 하나라도 섞이면 `map` 전체가 터진다. `Object.entries`가 어떤 속성을 돌려주는지(자기 속성, 열거 가능한 것만)는 [객체 메서드](/posts/js-object-methods)에서 다룬다.

## TypeScript에서 콜론의 뜻이 겹친다

TypeScript는 타입을 콜론으로 적는데, 구조 분해 패턴도 이름을 바꿀 때 콜론을 쓴다. 그래서 이런 코드가 나온다.

```ts
function greet({ name: string, age: number }) {
  return `${string} ${number}`;
}
```

작성자는 `name`이 문자열이라고 적은 의도였겠지만, 실제로는 `name` 키를 `string`이라는 변수에, `age` 키를 `number`라는 변수에 담는 이름 바꾸기다. `strict`(정확히는 `noImplicitAny`)를 켜면 이렇게 잡힌다.

```text
tsd.ts(1,24): error TS7031: Binding element 'string' implicitly has an 'any' type.
tsd.ts(1,37): error TS7031: Binding element 'number' implicitly has an 'any' type.
```

`strict` 없이 컴파일하면 에러가 하나도 나지 않는다. 타입은 패턴 전체 뒤에 따로 붙인다.

```ts
function greet({ name, age }: { name: string; age: number }) {
  return `${name} ${age}`;
}
```

타입이 길어지면 `type GreetProps = { ... }`로 빼고 `({ name, age }: GreetProps)`로 쓴다. React 컴포넌트 props가 이 모양이다.

## 패턴이 하는 일을 순서대로

구조 분해 한 줄은 꺼낼 대상이 `null`이나 `undefined`인지 확인하고, 객체 패턴이면 키마다 값을 읽고(getter도 이때 불린다), 배열 패턴이면 이터레이터에서 필요한 만큼 `next()`를 부르고, 값이 정확히 `undefined`인 자리에만 기본값을 계산해 넣는다. 맨 앞의 `fetchJson`이 `null`에서 터진 건 기본값이 `undefined`에만 반응하기 때문이다. 바깥에서 온 데이터에는 `?? {}`로 한 번 감싸고, 중첩은 모양이 보장된 데이터에만 쓴다.

## 면접에서 나올 만한 질문

### 구조 분해 기본값은 언제 적용되나?

꺼낸 값이 정확히 `undefined`일 때만 적용된다. `null`, `0`, 빈 문자열은 값이 있다고 보고 그대로 담는다. 그래서 JSON 응답에서 `null`로 온 필드에는 기본값이 들어가지 않는다. `null`까지 바꾸고 싶으면 `??`를 함께 쓴다.

### `function f({ a } = {})`에서 `= {}`가 하는 일은?

인자가 `undefined`일 때 빈 객체를 대신 써서 구조 분해가 터지지 않게 한다. 이게 없으면 `f()` 호출에서 `Cannot destructure property 'a' of 'undefined'`가 난다. 다만 `f(null)`은 기본값이 적용되지 않아 여전히 터지니, `null`을 받을 수 있는 API라면 본문에서 `options ?? {}`로 꺼낸다.

### 배열 구조 분해와 객체 구조 분해는 내부적으로 어떻게 다른가?

객체 패턴은 키마다 속성을 읽는다. 오른쪽이 원시값이면 래퍼 객체로 바꾸고, `null`과 `undefined`만 TypeError다. 배열 패턴은 오른쪽의 이터레이터를 얻어 자리 수만큼 `next()`를 부르고 다 채우면 이터레이터를 닫는다. 그래서 문자열, Map, Set, 제너레이터도 배열 패턴으로 꺼낼 수 있고, 객체 `{}`는 이터러블이 아니라 TypeError가 난다.

### 무한 제너레이터에 `const [a, b] = gen()`을 써도 되나?

된다. 배열 패턴은 필요한 만큼만 `next()`를 부르고 `return()`으로 닫는다. 두 자리면 두 번 부르고 끝난다. 하지만 `const [a, ...rest] = gen()`은 `done`이 나올 때까지 부르므로 끝나지 않는다.

### 세미콜론 없이 `[a, b] = [b, a]`를 쓰면 어떤 문제가 생기나?

앞줄이 식으로 끝나면 ASI가 세미콜론을 넣지 않고 다음 줄의 `[`를 앞 식의 인덱스 접근으로 이어 읽는다. `[3, 4][a, b] = [b, a]`가 되어 쉼표 연산자로 인덱스 접근 후 대입하고, 교환은 일어나지 않는다. 에러도 없어서 찾기 어렵다. 그 줄 앞에 세미콜론을 붙이거나 세미콜론을 쓰는 스타일을 택한다.

### useState는 왜 객체가 아니라 배열을 돌려주나?

배열 구조 분해는 위치로 꺼내니 호출하는 쪽이 이름을 자유롭게 붙일 수 있다. 한 컴포넌트에서 `useState`를 여러 번 써도 `[count, setCount]`, `[name, setName]`처럼 겹치지 않는다. 객체였다면 매번 `{ value: count }`처럼 이름을 바꿔야 한다. 반환값이 많아지면 순서를 외워야 해서 객체가 낫다.

### props 기본값을 `options = {}`로 주면 어떤 문제가 있나?

기본값 식은 렌더링마다 평가되니 매번 새 객체가 생긴다. 이 값을 `useEffect`나 `useMemo`의 의존성에 넣으면 매번 바뀐 것으로 보여 effect가 반복된다. effect 안에서 상태를 바꾸면 끝없이 돈다. 직접 재 보니 5ms 응답 기준 1초에 179번 돌았다. 모듈 상수로 빼거나 원시값 필드만 의존성에 넣는다.

### TypeScript에서 `function f({ a: string })`의 의미는?

타입 표기가 아니라 `a` 키를 `string`이라는 변수에 담는 이름 바꾸기다. `noImplicitAny`가 켜져 있으면 `Binding element 'string' implicitly has an 'any' type`으로 잡히지만, 꺼져 있으면 아무 에러 없이 지나간다. 타입은 `({ a }: { a: string })`처럼 패턴 뒤에 붙인다.
