장바구니 할인 규칙을 테스트하려고 "담을 수 있는 묶음"을 전부 만들어야 했다. 장바구니에는 사과 두 개와 배 하나가 있었다. [Subsets](/posts/leetcode-subsets)에서 쓴 함수를 그대로 돌렸더니 이렇게 나왔다.

```text
[] [사과] [사과,사과] [사과,사과,배] [사과,배] [사과] [사과,배] [배]
```

`[사과]`와 `[사과,배]`가 두 번씩 있다. 사과 두 개를 서로 다른 물건으로 셌기 때문이다. 테스트가 같은 경우를 두 번 돌릴 뿐이면 그나마 낫지만, 이 묶음 수를 화면에 "가능한 조합 8가지"로 보여 주면 틀린 숫자가 된다.

[LeetCode 90. Subsets II](https://leetcode.com/problems/subsets-ii/)가 이 상황이다. 부분집합을 만드는 틀은 [Subsets](/posts/leetcode-subsets)에서 자세히 봤으니 여기서는 반복하지 않는다. 이 글은 "같은 값이 섞이면 어떻게 겹침을 막나" 하나에 집중해서, 다 만들고 거르는 방법부터 처음부터 겹치지 않게 만드는 방법까지 여섯 가지를 비교한다. 재귀와 백트래킹의 기본 틀은 [재귀와 백트래킹 글](/posts/recursion-backtracking)에 있다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 같은 값이 섞인 배열의 부분집합

정수 배열 `nums`가 주어진다. 같은 값이 여러 번 들어 있을 수 있다. 이 원소들로 만들 수 있는 부분집합을 모두 돌려주는데, 같은 부분집합은 한 번만 넣는다. 답의 순서와 부분집합 안의 순서는 상관없다.

여기서 "같은 부분집합"은 담긴 값의 개수가 같다는 뜻이다. `[1,2]`와 `[2,1]`은 같은 부분집합이고, `[2]`와 `[2,2]`는 다른 부분집합이다. 2를 몇 개 담았는지가 다르기 때문이다.

제약은 이렇다.

- 길이는 1 이상 10 이하다. 부분집합을 전부 만들어도 최대 1024개라 시간은 걱정 없다.
- 값은 -10 이상 10 이하다. 범위가 작다는 건 뒤에서 "값마다 개수를 세는" 풀이를 쓸 때 도움이 된다.

시간이 넉넉한데도 이 문제가 Medium인 이유는 정확성 때문이다. 겹친 답을 걸러 내는 방법은 쉽게 떠오르지만, 거르는 기준을 잘못 잡으면 답이 빠지거나 남는다. 면접에서는 "처음부터 겹치지 않게 만드는 조건"을 정확히 설명할 수 있느냐를 본다.

## [1, 2, 2]를 손으로 적으면 어디서 겹치나

두 개의 2를 구분하려고 두 번째 2에 따옴표를 붙여 `2'`라고 쓰자. 서로 다른 원소 셋으로 보면 부분집합은 2^3 = 8개다.

```text
[]  [1]  [2]  [2']  [1,2]  [1,2']  [2,2']  [1,2,2']
```

따옴표를 지우면 `[2]`와 `[2']`가 같고, `[1,2]`와 `[1,2']`가 같다. 그래서 서로 다른 부분집합은 6개다.

```text
[]  [1]  [2]  [1,2]  [2,2]  [1,2,2]
```

개수를 세는 다른 방법도 있다. 값 1은 0개 또는 1개를 담을 수 있으니 2가지, 값 2는 0개, 1개, 2개를 담을 수 있으니 3가지다. 2 × 3 = 6이다. 일반적으로 값마다 개수가 c₁, c₂, …라면 서로 다른 부분집합은 (c₁ + 1)(c₂ + 1)…개다. 원소가 모두 다르면 모든 c가 1이라 2^n이 되고, 모두 같으면 n + 1개다.

겹침이 생기는 자리를 보자. `[2]`와 `[2']`는 "2 중에서 하나를 고른다"는 같은 결정을 두 원소로 따로 내린 결과다. 같은 값 중 어느 것을 골랐는지는 답에 드러나지 않는데, 코드가 그걸 다른 선택으로 쳤다. 그러니 같은 값 여러 개 중 "몇 개를 고르나"만 결정하고 "어느 것을 고르나"는 정해 버리면 된다. 늘 앞에 있는 것부터 쓴다고 정하면 `[2']`는 만들어지지 않는다. 뒤의 풀이들은 모두 이 생각을 서로 다른 방법으로 코드에 옮긴 것이다.

## 다 만들고 문자열로 걸러 내기

가장 먼저 떠오르는 방법이다. 겹치든 말든 부분집합을 전부 만들고, 이미 본 것은 버린다. 배열은 `Set`에 그대로 넣으면 참조로 비교되니, 내용을 문자열 키로 바꿔서 넣는다.

```js
function subsetsWithDup(nums) {
  nums = [...nums].sort((a, b) => a - b); // 이 정렬이 없으면 [1,2]와 [2,1]이 다른 키가 된다
  const seen = new Set();
  const res = [];
  const path = [];

  function go(start) {
    const key = path.join(","); // 구분자가 꼭 있어야 한다
    if (!seen.has(key)) {
      seen.add(key);
      res.push([...path]);
    }
    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);
      go(i + 1);
      path.pop();
    }
  }

  go(0);
  return res;
}
```

`[2, 1, 2]`를 넣으면 `[[],[1],[1,2],[1,2,2],[2],[2,2]]` 6개가 나온다.

여기에는 함정이 두 개 숨어 있다.

첫째, 정렬을 빼면 틀린다. `[2, 1, 2]`를 정렬하지 않고 돌리면 `[2,1]`과 `[1,2]`가 키 `"2,1"`과 `"1,2"`로 서로 다르게 들어가서 7개가 나왔다.

```text
[[],[2],[2,1],[2,1,2],[2,2],[1],[1,2]]
```

부분집합은 순서를 따지지 않는데 키는 순서를 따진다. 정렬해 두면 모든 부분집합이 오름차순으로 만들어지니 같은 부분집합은 언제나 같은 키가 된다.

둘째, 구분자를 빼면 서로 다른 부분집합이 같은 키가 된다. `[1,12].join("")`과 `[11,2].join("")`은 둘 다 `"112"`다. 이 문제는 값이 -10에서 10이라 `[1,-1]`과 `[-11]` 같은 충돌은 안 나지만, 값 범위가 넓은 문제에서 그대로 쓰면 답이 조용히 빠진다. 구분자를 넣거나 `JSON.stringify`를 쓴다.

복잡도는 값이 얼마나 겹치든 같다. 탐색은 늘 2^n번 호출하고, 호출마다 길이 n까지의 키를 만든다. 시간 O(n · 2^n), 공간은 `Set`에 키가 답의 개수만큼 들어간다. 같은 값 10개짜리 `[5,5,…,5]`는 답이 11개뿐인데도 호출은 1024번이다. 버릴 답을 만드느라 일을 대부분 쓴다. 답을 거르는 대신 겹칠 답을 아예 만들지 않는 방법이 필요하다.

## 같은 값이면 방금 생긴 것에만 붙인다

[Subsets](/posts/leetcode-subsets)의 첫 풀이는 원소를 하나씩 들이며 지금까지의 부분집합 전부에 그 원소를 붙였다. 정렬된 `[1, 2, 2]`로 그대로 하면 두 번째 2를 들일 때 문제가 생긴다.

```text
1 들인 뒤:   [] [1]
2 들인 뒤:   [] [1] [2] [1,2]
2' 들인 뒤:  [] [1] [2] [1,2] | [2] [1,2] [2,2] [1,2,2]
```

두 번째 2를 `[]`와 `[1]`에 붙이면 `[2]`, `[1,2]`가 또 나온다. 이 둘은 첫 번째 2를 들일 때 이미 만든 것이다. 두 번째 2를 붙여서 새로운 답이 되는 건 "이미 2가 들어 있는" 부분집합, 곧 바로 앞 단계에서 새로 생긴 `[2]`, `[1,2]`뿐이다. 거기에 붙이면 `[2,2]`, `[1,2,2]`가 된다.

그래서 규칙은 이렇다. 들이는 값이 바로 앞 값과 다르면 전부에 붙이고, 같으면 바로 앞 단계에서 새로 생긴 것에만 붙인다. 새로 생긴 것들이 시작하는 위치만 기억해 두면 된다.

```js
function subsetsWithDup(nums) {
  nums = [...nums].sort((a, b) => a - b);
  const res = [[]];
  let prevStart = 0; // 바로 앞 단계에서 새로 생긴 것들이 시작하는 위치
  for (let i = 0; i < nums.length; i++) {
    const size = res.length;
    // 앞 값과 같으면 방금 생긴 것에만, 다르면 전부에 붙인다
    const from = i > 0 && nums[i] === nums[i - 1] ? prevStart : 0;
    for (let j = from; j < size; j++) {
      res.push([...res[j], nums[i]]);
    }
    prevStart = size; // 이번에 새로 붙인 것들은 size부터 시작한다
  }
  return res;
}
```

`res`가 늘어나는 모습을 따라가 보자. 세 번째 단계에서 붙이기 시작하는 위치가 0이 아니라 2다.

찍어 본 값도 같다.

```text
i=0 from 0: [[],[1]]
i=1 from 0: [[],[1],[2],[1,2]]
i=2 from 2: [[],[1],[2],[1,2],[2,2],[1,2,2]]
```

왜 방금 생긴 것만으로 충분한지 따져 보자. 같은 값 2가 k개 연속으로 있다면, k번째 2를 들이기 직전의 `res`에는 2가 0개부터 k-1개까지 들어 있는 부분집합이 다 있다. k번째 2를 붙여 새로 만들 수 있는 건 2가 정확히 k개인 부분집합이고, 그건 2가 k-1개인 것에 붙여야만 나온다. 2가 k-1개인 것이 바로 앞 단계에서 새로 생긴 것들이다. 그보다 적게 들어 있는 것에 붙이면 이미 있는 것이 또 생긴다.

재귀가 없고 버리는 답도 없다. 만드는 부분집합이 곧 답이라 시간은 답의 총 길이에 비례한다. 원소가 모두 다르면 O(n · 2^n)이고 같은 값이 많을수록 줄어든다.

한계는 [Subsets](/posts/leetcode-subsets)의 반복문과 같다. 모든 부분집합을 메모리에 들고 있어야 다음 원소를 붙일 수 있어서, "크기가 k인 것만"이나 "합이 target인 것만" 같은 조건을 붙이기 어렵다. 또 `prevStart`의 의미가 코드만 봐서는 잘 안 보여서, 면접에서 설명하다 막히기 쉽다.

## 값마다 몇 개를 넣을지 고르기

손으로 개수를 셀 때 "값 2는 0개, 1개, 2개 중 하나"라고 생각했다. 그 생각을 그대로 코드로 옮길 수 있다. 원소 단위가 아니라 서로 다른 값 단위로 결정 트리를 만든다. 값마다 몇 개를 넣을지가 한 번의 결정이다.

```js
function subsetsWithDup(nums) {
  const count = new Map(); // 값 → 개수
  for (const x of nums) count.set(x, (count.get(x) || 0) + 1);
  const vals = [...count.keys()].sort((a, b) => a - b); // 서로 다른 값들
  const res = [];
  const path = [];

  function go(k) {
    if (k === vals.length) {      // 모든 값의 개수를 정했다
      res.push([...path]);
      return;
    }
    const v = vals[k];
    const c = count.get(v);
    go(k + 1);                    // v를 0개 넣는다
    for (let t = 1; t <= c; t++) {
      path.push(v);               // v를 t개 넣은 상태로
      go(k + 1);
    }
    for (let t = 1; t <= c; t++) path.pop(); // 넣은 만큼 되돌린다
  }

  go(0);
  return res;
}
```

`[2, 1, 2]`면 `vals`가 `[1, 2]`, 개수가 1과 2다. 결과는 `[[],[2],[2,2],[1],[1,2],[1,2,2]]`로 6개다. 정렬된 입력이 필요 없고, 같은 값을 건너뛰는 조건도 없다. 같은 값 중 "어느 것"을 고를지는 처음부터 질문에 없기 때문이다.

이 풀이가 가장 설명하기 쉽다. "값마다 0개부터 c개까지 고르니 (c₁ + 1)(c₂ + 1)…가지"라는 개수 공식이 코드 구조와 똑같다. 잎 하나가 답 하나이고 버리는 잎이 없다. 시간은 답의 총 길이에 안쪽 마디를 더한 만큼이라 원소가 모두 달라도 O(n · 2^n)이다.

값 범위가 -10에서 10으로 작으니 `Map` 대신 길이 21짜리 배열 `count[x + 10]`을 써도 된다. 그러면 정렬도 필요 없다. 0번 칸부터 훑으면 이미 오름차순이다.

이 방식은 개수 상한이 있는 조합 문제로 바로 이어진다. [Combination Sum](/posts/leetcode-combination-sum)의 "수마다 쓸 수 있는 횟수에 상한이 있다면"이 이 모양이고, [Combination Sum II](/posts/leetcode-combination-sum-ii)도 이렇게 풀 수 있다. 다만 되돌리기를 개수만큼 해야 하는 게 번거롭고, 면접관이 기대하는 표준 답은 다음 풀이다.

## 같은 자리에서 같은 값은 한 번만 고른다

[Subsets](/posts/leetcode-subsets)의 시작 위치 백트래킹은 "다음에 넣을 원소를 `start`부터 끝까지에서 하나 고른다"였다. 한 번의 for문이 "이번 칸(path의 다음 자리)에 무엇을 넣을까"를 정한다. 정렬된 `[1, 2, 2]`에서 빈 path가 다음 자리에 넣을 후보는 1, 2, 2'이다. 2와 2'은 같은 값이니 둘 중 무엇을 고르든 그 아래로 펼쳐지는 부분집합이 똑같다. 그래서 같은 for문 안에서는 같은 값을 처음 한 번만 고르고, 두 번째부터는 건너뛴다.

```js
if (i > start && nums[i] === nums[i - 1]) continue;
```

`i > start`가 "같은 for문 안에서 첫 후보가 아니다"라는 뜻이다. 첫 후보는 앞 값과 같더라도 고른다. `[2]`에서 다음 자리를 고를 때 `start`는 2이고 첫 후보 `nums[2]`도 2인데, 이건 "2를 하나 더 넣는" 정당한 선택이다. 이걸 막으면 `[2,2]`가 사라진다.

코드는 이렇다.

```js
function subsetsWithDup(nums) {
  nums = [...nums].sort((a, b) => a - b); // 같은 값을 붙여 놓는다 (원본은 건드리지 않는다)
  const res = [];
  const path = [];

  function go(start) {
    res.push([...path]);                   // 이 호출 자체가 부분집합 하나
    for (let i = start; i < nums.length; i++) {
      // 같은 for문(같은 자리)에서 앞과 같은 값은 이미 시도했다
      if (i > start && nums[i] === nums[i - 1]) continue;
      path.push(nums[i]);                  // 고른다
      go(i + 1);                           // i보다 뒤에서만 이어서 고른다
      path.pop();                          // 되돌린다
    }
  }

  go(0);
  return res;
}
```

### Python과 Java로 쓰면

Python은 `sorted(nums)`가 새 리스트를 돌려주니 원본을 건드리지 않는다. 재귀 깊이는 최대 n + 1 = 11이라 기본 한도 1000과 거리가 멀다.

```python
from typing import List

def subsets_with_dup(nums: List[int]) -> List[List[int]]:
    nums = sorted(nums)            # 같은 값을 붙여 놓는다 (원본은 그대로)
    res, path = [], []

    def go(start: int) -> None:
        res.append(path[:])        # 이 호출 자체가 부분집합 하나
        for i in range(start, len(nums)):
            if i > start and nums[i] == nums[i - 1]:
                continue           # 이 자리에 같은 값은 한 번만
            path.append(nums[i])
            go(i + 1)
            path.pop()

    go(0)
    return res
```

Java는 `Arrays.sort(nums)`가 넘겨받은 배열 자체를 정렬한다. LeetCode에서는 상관없지만, 실무 코드에서 호출한 쪽의 배열 순서가 바뀌는 게 문제가 되면 `nums.clone()`을 정렬한다. `int[]`의 기본 정렬은 숫자 오름차순이라 비교자가 필요 없다.

```java
import java.util.*;

class Solution {
    public List<List<Integer>> subsetsWithDup(int[] nums) {
        Arrays.sort(nums); // int[]는 기본 정렬이 오름차순 숫자 정렬이다
        List<List<Integer>> res = new ArrayList<>();
        go(nums, 0, new ArrayList<>(), res);
        return res;
    }

    private void go(int[] nums, int start, List<Integer> path, List<List<Integer>> res) {
        res.add(new ArrayList<>(path)); // 복사본을 기록한다
        for (int i = start; i < nums.length; i++) {
            if (i > start && nums[i] == nums[i - 1]) continue; // 같은 자리에 같은 값은 한 번만
            path.add(nums[i]);
            go(nums, i + 1, path, res);
            path.remove(path.size() - 1);
        }
    }
}
```

세 언어 모두 `[2, 1, 2]`에서 `[[], [1], [1, 2], [1, 2, 2], [2], [2, 2]]`를, `[0]`에서 `[[], [0]]`을, `[4, 4, 4, 1, 4]`에서 10개를 냈다. 10개는 값 1이 2가지, 값 4가 0~4개로 5가지라 2 × 5 = 10이다.

JavaScript의 `sort()`는 비교자를 빼면 문자열로 비교한다. `[10, 9, 1, 2].sort()`가 `[1, 10, 2, 9]`다. 그런데 이 문제에서는 비교자를 빼도 답이 맞게 나왔다. 같은 값은 같은 문자열이라 여전히 나란히 붙기 때문이다. `[10, 2, 10, 9]`에서 `[10,10,2,9]` 순으로 정렬돼도 12개가 정확히 나왔다. 그래도 비교자는 꼭 쓴다. 정렬이 "같은 값 붙이기"가 아니라 "작은 값부터"라는 성질에 기대는 순간(합이 넘치면 멈추는 가지치기) 바로 틀리기 때문이다. [Combination Sum II](/posts/leetcode-combination-sum-ii)가 그 경우다.

## 안 넣기로 했으면 같은 값을 모두 건너뛴다

[Subsets](/posts/leetcode-subsets)의 두 번째 풀이는 원소마다 "넣는다"와 "안 넣는다" 두 갈래로 나누는 이진 트리였다. 이 방식에서 겹침은 어디서 생길까. 정렬된 `[1, 2, 2]`에서 2를 넣고 2'을 안 넣으면 `[2]`, 2를 안 넣고 2'을 넣으면 또 `[2]`다.

규칙을 이렇게 바꾼다. 어떤 값을 "안 넣기로" 했으면 그 뒤에 이어지는 같은 값도 모두 안 넣는다. 같은 값 중 앞의 것을 건너뛰고 뒤의 것을 넣는 경로를 막는 것이다. "앞의 것부터 쓴다"는 약속을 이진 트리 쪽에서 표현한 모양이다.

```js
function subsetsWithDup(nums) {
  nums = [...nums].sort((a, b) => a - b);
  const res = [];
  const path = [];

  function go(i) {
    if (i === nums.length) {
      res.push([...path]);
      return;
    }
    path.push(nums[i]);        // nums[i]를 넣는 갈래
    go(i + 1);
    path.pop();

    let j = i + 1;             // 안 넣는 갈래: 같은 값을 모두 건너뛴다
    while (j < nums.length && nums[j] === nums[i]) j++;
    go(j);
  }

  go(0);
  return res;
}
```

결과는 `[[1,2,2],[1,2],[1],[2,2],[2],[]]`로 큰 것부터 나온다. 넣는 갈래를 먼저 가기 때문이다.

잎 하나가 답 하나라 버리는 잎은 없다. 다만 답은 잎에서만 나오니 안쪽 마디가 따로 있고, 호출 수가 답의 개수보다 많다. 시간 복잡도는 같은 O(n · 2^n)이다.

이 모양은 "원소마다 결정하고, 결정에 조건을 붙이는" 문제에 잘 맞는다. 0/1 배낭처럼 넣을 때 무게를 더하고 넘으면 끊는 식이다. 같은 값 처리 규칙이 "안 넣는 갈래에서만" 생긴다는 걸 이해하면, 시작 위치 풀이의 `i > start` 조건이 왜 그 자리에 있는지도 같이 설명된다. 시작 위치 풀이에서 for문이 `i`를 건너뛰는 것이 바로 "`nums[i]`를 이 자리에 안 넣는다"는 결정이다.

## 비트마스크에 "앞의 것부터" 규칙을 건다

0부터 2^n - 1까지 정수의 비트를 부분집합으로 읽는 방법도 같은 약속으로 고칠 수 있다. 정렬된 배열에서 `nums[i] === nums[i - 1]`인데 i번 비트는 켜져 있고 i-1번 비트는 꺼져 있다면, 같은 값 중 뒤의 것만 쓴 경우다. 그런 mask는 건너뛴다.

```js
function subsetsWithDup(nums) {
  nums = [...nums].sort((a, b) => a - b);
  const n = nums.length;
  const res = [];
  for (let mask = 0; mask < (1 << n); mask++) {
    let ok = true;
    const sub = [];
    for (let i = 0; i < n; i++) {
      if (!(mask & (1 << i))) continue;
      // 같은 값인데 앞의 것은 안 쓰고 뒤의 것만 썼다면 겹치는 경우다
      if (i > 0 && nums[i] === nums[i - 1] && !(mask & (1 << (i - 1)))) {
        ok = false;
        break;
      }
      sub.push(nums[i]);
    }
    if (ok) res.push(sub);
  }
  return res;
}
```

정렬된 `[1, 2, 2]`에서 mask를 따라가 보면 이렇다. 비트는 오른쪽이 0번째다.

```text
mask  비트  읽은 값     판단
 0    000   []         기록
 1    001   [1]        기록
 2    010   [2]        기록
 3    011   [1,2]      기록
 4    100   [2']       버림: 2'은 켜졌는데 2는 꺼졌다
 5    101   [1,2']     버림: 같은 이유
 6    110   [2,2']     기록
 7    111   [1,2,2']   기록
```

버린 둘이 손으로 적을 때 겹쳤던 `[2']`, `[1,2']`이다. 결과는 `[[],[1],[2],[1,2],[2,2],[1,2,2]]` 6개다.

재귀가 없고 mask 하나만 보고 답인지 판단할 수 있다는 게 장점이다. 하지만 버릴 mask도 전부 세기 때문에 반복은 늘 2^n번이다. 처음 풀이처럼 같은 값이 많을수록 낭비가 크다. 그리고 `1 << n`이 32비트 정수라 n이 31을 넘으면 깨지는 한계는 [Subsets](/posts/leetcode-subsets)에서 본 그대로다.

## 답이 빠지거나 두 번 나오는 코드

### `i > start` 대신 `i > 0`

가장 흔한 실수다. "앞과 같은 값이면 건너뛴다"만 기억하고 조건을 이렇게 쓴다.

```js
if (i > 0 && nums[i] === nums[i - 1]) continue; // start가 아니라 0
```

정렬된 `[1, 2, 2]`에서 결과가 `[[],[1],[1,2],[2]]` 4개로 나왔다. `[2,2]`와 `[1,2,2]`가 빠졌다. `[2]`에서 다음 자리를 고를 때 첫 후보 `nums[2]`도 앞 값과 같은 2라서, 이 조건이 "2를 하나 더 넣는" 정당한 선택까지 막는다. 막아야 하는 건 같은 자리의 두 번째 후보뿐이다. `i > start`가 그 뜻이다.

### 정렬을 빼먹기

정렬하지 않으면 같은 값이 떨어져 있어서 `nums[i] === nums[i - 1]` 비교가 같은 값을 못 찾는다.

```js
function bug(nums) {      // 정렬이 없다
  const res = [], path = [];
  function go(start) {
    res.push([...path]);
    for (let i = start; i < nums.length; i++) {
      if (i > start && nums[i] === nums[i - 1]) continue;
      path.push(nums[i]); go(i + 1); path.pop();
    }
  }
  go(0);
  return res;
}
```

`[2, 1, 2]`에서 `[[],[2],[2,1],[2,1,2],[2,2],[1],[1,2],[2]]` 8개가 나왔다. `[2]`가 두 번이고, `[2,1]`과 `[1,2]`도 같은 부분집합이 두 번이다. 예시를 `[1, 2, 2]`처럼 이미 정렬된 것으로만 시험하면 이 버그가 안 보인다. 테스트에 정렬 안 된 입력을 꼭 넣는다.

### `Set`에 배열을 그대로 넣기

```js
const seen = new Set();
seen.add([1, 2]);
seen.has([1, 2]); // false
```

`Set`은 배열을 참조로 비교한다. 내용이 같아도 다른 배열이면 다른 값이다. 거르는 풀이에서 키를 문자열로 바꾸는 이유다. Python도 `list`는 `set`에 넣을 수 없어서(`TypeError: unhashable type: 'list'`) `tuple`로 바꾼다. Java의 `HashSet<List<Integer>>`는 `List.equals`로 내용을 비교하니 그대로 써도 된다. 언어마다 "같다"의 기준이 다르다는 걸 알고 있어야 한다.

### 복사 없이 기록하기

`res.push(path)`로 넣으면 모든 칸이 같은 배열을 가리켜서 끝나고 보면 전부 빈 배열이다. [Subsets](/posts/leetcode-subsets)에서 자세히 본 버그라 여기서는 이름만 적는다.

## 조건을 하나씩 바꿔 보면

### 크기가 k인 것만 달라면

`path.length === k`일 때만 기록하고 돌아간다. 같은 값 처리 조건은 그대로 둔다. `[1, 2, 2, 3]`에서 k = 2면 `[1,2] [1,3] [2,2] [2,3]` 4개다. `[2,2]`가 한 번만, 그리고 빠지지 않고 나온다.

### 개수만 달라면

목록을 만들 필요가 없다. 값마다 개수를 세서 (c₁ + 1)(c₂ + 1)…을 곱하면 O(n)이다. `[4, 4, 4, 1, 4]`는 1이 1개, 4가 4개라 2 × 5 = 10이다. 면접에서 "목록이 아니라 개수라면?"이라고 물으면 백트래킹을 버리는 게 답이다.

### 합이 target인 부분집합만 달라면

시작 위치 틀에 남은 합을 들고 다니고, 정렬돼 있으니 `nums[i]`가 남은 합보다 크면 for문을 끝낸다. 이게 [Combination Sum II](/posts/leetcode-combination-sum-ii)다. 같은 값 처리 조건이 한 글자도 다르지 않다.

### 순서가 다르면 다른 답이라면

부분집합이 아니라 순열이다. LeetCode 47 Permutations II이고, 시작 위치 대신 `used` 배열을 쓰고 `!used[i - 1]`로 같은 값의 순서를 강제한다. [Permutations](/posts/leetcode-permutations)의 "같은 값이 섞여 있다면"에 코드가 있다. 같은 생각을 다른 틀에 옮긴 것이다.

### 입력이 정렬돼 있지 않고 정렬도 하면 안 된다면

원본 순서를 지켜야 하는 경우다. 값마다 개수를 세는 풀이는 정렬이 필요 없으니 그대로 쓴다. 시작 위치 틀을 쓰고 싶다면 for문마다 `Set`을 하나 두고, 이 자리에서 이미 고른 값이면 건너뛴다.

```js
function go(start) {
  res.push([...path]);
  const tried = new Set(); // 이 자리에서 이미 고른 값
  for (let i = start; i < nums.length; i++) {
    if (tried.has(nums[i])) continue;
    tried.add(nums[i]);
    path.push(nums[i]); go(i + 1); path.pop();
  }
}
```

다만 이것만으로는 `[2,1]`과 `[1,2]` 같은 순서만 다른 겹침이 남는다. `[2, 1, 2]`에서 2로 시작하는 갈래가 `[2,1]`을, 1로 시작하는 갈래가 `[1,2]`를 만든다. 같은 자리에서 같은 값을 막는 것만으로는 부족하고, 결국 값의 순서를 하나로 정해야 한다. 정렬을 못 하면 개수 세기 풀이가 답이다.

### 비슷한 문제

[Subsets](/posts/leetcode-subsets)가 이 문제의 중복 없는 버전이다. [Combination Sum II](/posts/leetcode-combination-sum-ii)는 같은 건너뛰기 조건에 합 조건을 더한다. [Combination Sum](/posts/leetcode-combination-sum)은 같은 수를 여러 번 쓸 수 있어서 `go(i)`를 넘긴다. LeetCode 47 Permutations II는 순열판이다. LeetCode 491 Non-decreasing Subsequences는 정렬을 할 수 없는 부분수열 문제라 위의 "for문마다 `Set`" 방식이 정답이 된다.

## 장바구니 묶음으로 돌아가면

처음의 장바구니 `["사과", "사과", "배"]`를 표준 풀이에 넣었다. 문자열이라 기본 `sort()`로 정렬해도 된다.

```text
[] [배] [배,사과] [배,사과,사과] [사과] [사과,사과]
```

여섯 개다. 사과 0~2개(3가지) × 배 0~1개(2가지)와 맞는다. 테스트 이름도 겹치지 않고, 화면에 보여 줄 조합 수도 정확하다.

실무에서는 같은 물건을 배열에 여러 번 넣는 대신 `{ 사과: 2, 배: 1 }`처럼 개수로 들고 있는 경우가 더 많다. 그때는 값마다 개수를 고르는 풀이가 자료 모양에 그대로 맞는다. 데이터가 이미 "값과 개수"로 정리돼 있다면 펼쳐서 정렬하지 말고 그 모양대로 탐색하는 게 자연스럽다.

## 정렬로 붙이고, 같은 자리에서 한 번만

같은 값이 섞이면 "어느 것을 골랐나"가 답에 드러나지 않는데도 코드는 그걸 다른 선택으로 센다. 그래서 겹침이 생긴다. 같은 값 중에서는 늘 앞의 것부터 쓴다고 약속하면 겹침이 사라진다. 시작 위치 백트래킹에서는 정렬한 뒤 `i > start && nums[i] === nums[i - 1]`이면 건너뛰는 한 줄이 그 약속이다. 같은 for문 안의 두 번째 후보만 막고, 더 깊이 들어가 같은 값을 이어 고르는 건 살린다. 이 조건은 [Combination Sum II](/posts/leetcode-combination-sum-ii)와 Permutations II에서도 그대로 다시 나온다.

## 면접에서 나올 만한 질문

### 같은 부분집합이 두 번 나오지 않게 하려면 어떻게 하나요?

정렬해서 같은 값을 붙여 놓고, 시작 위치 백트래킹의 for문에서 `i > start`이면서 `nums[i] === nums[i - 1]`이면 건너뛴다. 같은 자리에 같은 값을 두 번 놓으면 그 아래 펼쳐지는 부분집합이 똑같기 때문이다. 결과적으로 같은 값 중 늘 앞의 것부터 쓰게 된다.

### 왜 `i > 0`이 아니라 `i > start`인가요?

`i > 0`이면 더 깊은 단계의 첫 후보까지 막는다. `[2]` 다음 자리의 첫 후보도 2인데, 이건 2를 하나 더 넣는 정당한 선택이다. `[1, 2, 2]`에 `i > 0`을 쓰면 `[2,2]`와 `[1,2,2]`가 빠져 4개가 나온다. 막아야 하는 건 같은 for문의 두 번째 후보부터다.

### 정렬은 왜 하나요?

같은 값이 나란히 있어야 바로 앞 칸과 비교해서 같은 값을 알아챌 수 있다. 정렬하지 않으면 `[2, 1, 2]`에서 `[2]`가 두 번 나오고, `[2,1]`과 `[1,2]`도 따로 나온다. 정렬이 부분집합 안의 순서를 하나로 정해 준다는 효과도 있다.

### 결과를 `Set`으로 걸러도 되지 않나요?

답은 맞게 만들 수 있다. 다만 정렬된 키를 써야 하고, 겹칠 답까지 전부 만든 뒤 버리니 같은 값이 많을수록 낭비가 크다. 같은 값 10개면 답 11개를 얻으려고 1024번 호출한다. 건너뛰기 조건을 쓰면 호출 수가 답의 개수와 같다.

### 서로 다른 부분집합은 몇 개인가요?

값마다 개수가 c₁, c₂, …라면 (c₁ + 1)(c₂ + 1)…개다. 값마다 0개부터 cᵢ개까지 고를 수 있고 값끼리는 서로 영향을 주지 않기 때문이다. 모두 다르면 2^n, 모두 같으면 n + 1이다. 개수만 물으면 이 곱으로 O(n)에 답한다.

### 시간 복잡도는 어떻게 되나요?

최악은 원소가 모두 다를 때라 [Subsets](/posts/leetcode-subsets)와 같은 O(n · 2^n)이다. 같은 값이 있으면 답의 개수가 줄고, 건너뛰기 풀이는 호출 하나가 답 하나라 실제 일도 그만큼 준다. 정렬 O(n log n)은 출력 크기에 비하면 무시된다.

### 정렬을 할 수 없다면 어떻게 하나요?

값마다 개수를 세서 값 단위로 몇 개 넣을지 고르면 정렬이 필요 없다. for문마다 `Set`을 두는 방법은 같은 자리의 같은 값만 막아 줄 뿐, `[2,1]`과 `[1,2]`처럼 순서만 다른 겹침은 남는다. 순서가 의미 있는 부분수열 문제(LeetCode 491)라면 그 `Set` 방식이 맞는 답이 된다.
