월말 리포트를 백업하는 한 줄짜리 스크립트가 있었다. 파일 이름이 `monthly report.csv`로 바뀐 달부터 백업이 실패했다.

```bash
f="monthly report.csv"
cp $f /srv/backup/
```

```text
cp: cannot stat 'monthly': No such file or directory
cp: cannot stat 'report.csv': No such file or directory
```

`cp`는 파일 두 개를 받았다. 변수에는 분명 하나를 넣었는데 명령에는 둘이 갔다. `set -x`로 bash가 실제로 무엇을 실행하는지 찍어 보면 바로 보인다.

```bash
bash -xc 'f="monthly report.csv"; cp $f{,.bak}'
```

```text
+ f='monthly report.csv'
+ cp monthly report.csv monthly report.csv.bak
cp: target 'report.csv.bak': No such file or directory
```

`$f{,.bak}`는 "파일과 그 `.bak` 사본"을 뜻하려고 쓴 건데, 펼친 결과는 단어 네 개가 됐다. bash는 명령을 실행하기 전에 줄을 여러 번 고쳐 쓰고, 그 순서 안에 공백에서 자르는 단계가 끼어 있다. 이 글은 그 순서를 처음부터 끝까지 따라간다. 중괄호, 틸드, 매개변수, 명령 치환, 산술, 단어 분할, 경로 확장이 언제 일어나는지, 그리고 `${var:-기본값}`, `${var#접두사}`, `${var//a/b}` 같은 문자열 조작, `$(( ))`와 `let`·`expr`·`bc`의 차이, 배열과 연관 배열, 위치 매개변수를 다룬다.

기준은 Ubuntu 24.04의 bash 5.2이고 출력은 모두 직접 돌렸다. 실패를 숨기지 않는 스크립트 습관(`set -euo pipefail`, trap, shellcheck)은 [bash 스크립트 글](/posts/bash-scripting)에서, 명령 줄의 `>`와 `|`가 어떻게 처리되는지는 [리다이렉션과 파이프 글](/posts/shell-redirection-pipes)에서 다뤘다. `if`, `[[ ]]`, 반복문과 함수는 [조건문과 함수 글](/posts/bash-control-flow-functions)에 있다. 여기서는 "무엇이 언제 펼쳐지나"에 집중한다.

## bash는 명령을 실행하기 전에 줄을 고쳐 쓴다

bash 매뉴얼은 확장(expansion) 순서를 이렇게 적는다. 중괄호 확장, 틸드 확장, 매개변수와 변수 확장, 산술 확장, 명령 치환, 단어 분할, 경로 이름 확장, 그리고 따옴표 제거. 이 중 틸드부터 명령 치환까지 넷은 한 단계로 묶여 왼쪽에서 오른쪽으로 함께 처리된다. 받은 인자를 하나씩 대괄호로 찍는 `show` 함수로 한 줄에 모두 넣어 봤다.

```bash
show() { printf '%s개:' "$#"; printf ' [%s]' "$@"; echo; }
n=1; v="1 2"
show {a,b}$((n+1)) ~ $v $(hostname) *.csv
```

```text
8개: [a2] [b2] [/root] [1] [2] [vm] [a.csv] [monthly report.csv]
```

순서에서 실무 규칙 세 개가 나온다. 따옴표 없는 변수와 명령 치환은 단어 분할과 경로 확장을 거친다(처음의 `cp` 버그). 경로 확장으로 나온 파일 이름은 공백이 있어도 잘리지 않는다(그래서 `for x in *.csv`는 안전하다). 중괄호는 변수보다 먼저라 변수를 쓸 수 없다. 따옴표가 정확히 어느 단계를 막는지와 "항상 감싸라"는 습관은 [bash 스크립트 글](/posts/bash-scripting)의 따옴표 절에 있다. 처음의 백업 줄은 `cp "$f" "$f.bak"`나 `cp "$f"{,.bak}`로 고친다. 후자는 중괄호가 따옴표 밖에 있어서 먼저 펼쳐지고, `"$f"`는 따옴표 안이라 잘리지 않는다.

## 중괄호 확장은 변수보다 먼저 펼쳐진다

중괄호 확장은 파일 시스템도 변수도 보지 않고 글자만 늘린다.

```bash
show {a,b}{1,2}
show file{01..03}.log
show {1..10..3}
n=3; show {1..$n}
```

```text
4개: [a1] [a2] [b1] [b2]
3개: [file01.log] [file02.log] [file03.log]
4개: [1] [4] [7] [10]
1개: [{1..3}]
```

`{01..03}`처럼 한쪽에 앞자리 0이 있으면 자릿수를 맞춰 준다. `{1..10..3}`의 셋째 칸은 간격이다. 그리고 `{1..$n}`은 그대로 남았다. 중괄호 단계에서는 `$n`이 아직 글자일 뿐이라 `{1..$n}`은 올바른 범위가 아니고, 그다음 단계에서 `$n`만 3으로 바뀌어 `{1..3}`이라는 글자가 됐다. 변수로 범위를 만들려면 `for ((i=1; i<=n; i++))`나 `seq 1 "$n"`을 쓴다.

실무에서는 `cp nginx.conf{,.bak}`(백업 사본), `mkdir -p app/{src,test,docs}`, `mv report.{csv,tsv}`(확장자 바꾸기) 같은 데 쓴다. 중괄호 확장은 bash, zsh에 있고 POSIX sh에는 없다. Ubuntu의 `/bin/sh`인 dash로 돌리면 `dash -c 'echo {a,b}'`가 `{a,b}`를 그대로 찍는다. `#!/bin/sh` 스크립트에 쓰면 조용히 다르게 동작한다.

## 틸드는 홈 디렉터리로 바뀐다

```bash
show ~ ~root ~nosuch "~"
```

```text
4개: [/root] [/root] [~nosuch] [~]
```

`~`는 `$HOME`, `~사용자`는 그 사용자의 홈이다. 없는 사용자면 글자 그대로 남고, 따옴표 안에서는 펼쳐지지 않는다. `path="~/data"`처럼 따옴표 안에 쓰고 나중에 `cd "$path"`하면 `~`라는 이름의 디렉터리를 찾다가 실패한다. 변수에 담을 때는 `"$HOME/data"`로 쓴다.

## 매개변수 확장으로 기본값과 필수값을 정한다

`${이름}`은 변수 값을 꺼내는 기본형이고, 중괄호 안에 연산자를 붙이면 꺼내면서 가공할 수 있다. 가장 많이 쓰는 건 "비어 있으면" 계열이다.

```bash
unset PORT;  echo "1 ${PORT:-8080} / ${PORT-8080}"
PORT="";     echo "2 [${PORT:-8080}] [${PORT-8080}]"
unset PORT;  echo "3 ${PORT:=3000} then PORT=$PORT"
             echo "4 [${PORT:+--port=$PORT}]"
unset T;     ( : "${T:?T is required}" ); echo "exit=$?"
```

```text
1 8080 / 8080
2 [8080] []
3 3000 then PORT=3000
4 [--port=3000]
bash: line 1: T: T is required
exit=1
```

콜론이 있느냐 없느냐가 갈린다. `${PORT:-8080}`은 "없거나 빈 문자열이면" 8080이고, `${PORT-8080}`은 "아예 없을 때만" 8080이다. 2번 줄에서 빈 문자열을 넣었더니 콜론 없는 쪽은 빈 값을 그대로 썼다. 환경 변수를 `PORT=`처럼 비워서 넘기는 실수가 흔해서 보통 콜론을 붙인다.

`:=`는 기본값을 쓰면서 변수에 저장까지 한다. `:+`는 반대로 "값이 있을 때만" 뒤의 글자를 쓴다. 옵션을 조건부로 붙일 때 좋다. `:?`는 비어 있으면 메시지를 찍고 셸을 끝낸다. 스크립트 맨 위에 `: "${DB_URL:?DB_URL is required}"`를 두면 필수 설정이 빠졌을 때 엉뚱한 기본값으로 돌지 않고 바로 멈춘다. 맨 앞의 `:`는 아무것도 하지 않는 명령이라, 확장만 일으키고 결과는 버린다.

## 문자열은 앞뒤를 자르고 바꿔서 다룬다

bash는 외부 명령 없이도 문자열을 자르고 바꿀 수 있다. 로그 경로 하나로 다 해 봤다.

```bash
p=/var/log/nginx/access.log.2.gz
echo "${p#*/}"      # 앞에서 */ 에 맞는 가장 짧은 부분을 뺀다
echo "${p##*/}"     # 앞에서 가장 긴 부분을 뺀다 = basename
echo "${p%.*}"      # 뒤에서 .* 에 맞는 가장 짧은 부분을 뺀다
echo "${p%%.*}"     # 뒤에서 가장 긴 부분을 뺀다
echo "${p%/*}"      # = dirname
```

```text
var/log/nginx/access.log.2.gz
access.log.2.gz
/var/log/nginx/access.log.2
/var/log/nginx/access
/var/log/nginx
```

`#`은 앞, `%`는 뒤를 자르고, 하나면 가장 짧게, 둘이면 가장 길게 맞춘다. 키보드에서 `#`이 `$`의 왼쪽, `%`가 오른쪽에 있다고 외우면 쉽다. 패턴은 정규식이 아니라 `*`, `?`, `[...]`를 쓰는 글로브다. 아래 그림은 `%`와 `%%`가 같은 패턴 `.*`로 다른 곳을 자르는 모습이다.

바꾸기는 `/`로 한다.

```bash
s="Hello World Hello"
echo "${#s}"              # 길이
echo "${s/Hello/Bye}"     # 처음 하나만
echo "${s//Hello/Bye}"    # 전부
echo "${s/#Hello/X}"      # 맨 앞일 때만
echo "${s/%Hello/X}"      # 맨 뒤일 때만
f="monthly report.csv"
echo "${f// /_}"          # 공백을 밑줄로
echo "${f%.csv}.tsv"      # 확장자 바꾸기
```

```text
17
Bye World Hello
Bye World Bye
X World Hello
Hello World X
monthly_report.csv
monthly report.tsv
```

부분 문자열과 대소문자 변환도 있다. 여기에 실수 하나가 숨어 있다.

```bash
echo "${s:6:5}"     # 6번째(0부터)에서 5글자
echo "${s: -5}"     # 끝에서 5글자 (공백 필수)
echo "${s:-5}"      # 공백을 빼먹었다
echo "${s^^}" ; echo "${s,,}"
n="kim"; echo "${n^}"
```

```text
World
Hello
Hello World Hello
HELLO WORLD HELLO
hello world hello
Kim
```

`${s:-5}`는 "끝에서 5글자"가 아니라 앞 절의 "비어 있으면 5"다. `s`가 비어 있지 않으니 전체가 나왔다. 음수 위치는 `${s: -5}`처럼 콜론 뒤에 공백을 넣거나 `${s:(-5)}`로 쓴다. `^^`와 `,,`는 bash 4부터라 macOS 기본 bash 3.2에서는 오류가 난다.

길이와 위치는 글자 단위인데, 무엇을 글자로 볼지는 로케일이 정한다.

```bash
LANG=C.UTF-8 bash -c 'k="한글"; echo ${#k}'
LC_ALL=C     bash -c 'k="한글"; echo ${#k}'
```

```text
2
6
```

UTF-8 로케일에서는 2글자, C 로케일에서는 6바이트다. 크론이나 컨테이너처럼 로케일이 비어 있는 환경에서는 C로 돌아서, 한글 이름을 10글자로 자르는 스크립트가 글자 중간을 잘라 깨진 문자를 만든다. 그런 스크립트는 맨 위에서 `export LC_ALL=C.UTF-8`을 정한다.

이 연산자들은 외부 명령을 띄우지 않아서 빠르다. 파일 수만 개를 도는 루프에서 `$(basename "$f")` 대신 `${f##*/}`를 쓰면 프로세스를 수만 번 덜 만든다. 다만 정규식이 필요하면 `[[ $s =~ ^v([0-9]+) ]]`와 `BASH_REMATCH`를 쓰거나, 한 번에 많은 줄을 다룰 때는 [awk와 sed](/posts/linux-grep-awk-sed)가 낫다.

## 명령 치환은 출력을 끼워 넣는다

`$(명령)`은 그 명령을 서브셸에서 실행하고 stdout을 그 자리에 넣는다. 옛 문법인 백틱보다 `$()`를 쓰는 이유는 겹쳐 쓸 때 보인다.

```bash
echo "a$(echo b$(echo c))d"
echo "a`echo b\`echo c\``d"
show "$(printf 'a\n\n\n')"
```

```text
abcd
abcd
1개: [a]
```

결과는 같지만 백틱은 안쪽 백틱마다 역슬래시를 붙여야 한다. 셋째 줄은 명령 치환이 끝의 줄바꿈을 모두 지운다는 걸 보여 준다. 덕분에 `today=$(date +%F)`에 줄바꿈이 붙지 않지만, 파일 내용을 그대로 담아야 할 때는 끝의 빈 줄이 사라진다.

명령 치환의 결과도 따옴표가 없으면 단어 분할과 경로 확장을 거친다. 그래서 `for x in $(ls)`는 공백 있는 파일 이름을 자른다.

```bash
for x in $(ls *.csv); do echo "[$x]"; done
echo ---
for x in *.csv; do echo "[$x]"; done
```

```text
[a.csv]
[monthly]
[report.csv]
---
[a.csv]
[monthly report.csv]
```

파일 목록은 `ls`의 출력을 자르지 말고 글로브로 받는다. 맞는 파일이 하나도 없으면 글로브는 `*.nope`이라는 글자 그대로 남아 루프가 한 번 돈다. 스크립트에서는 `shopt -s nullglob`으로 "맞는 게 없으면 빈 목록"으로 바꾼다.

종료 코드도 챙긴다. `x=$(false); echo $?`는 1이지만, 함수 안에서 `local y=$(false); echo $?`는 0이다. `local`이라는 명령 자체가 성공했기 때문이다. 실패를 잡으려면 `local y; y=$(cmd)`로 나눠 쓴다.

## 산술 확장은 정수만 안다

`$(( 식 ))`은 C와 비슷한 문법으로 정수를 계산한다. 안에서는 변수 앞에 `$`를 붙이지 않아도 된다.

```bash
echo $(( 7 / 2 )) $(( 7 % 2 )) $(( 2 ** 10 )) $(( 0x1F )) $(( 010 )) $(( 1 << 4 ))
a=5; (( a++ )); echo "a=$a"
let "b = a * 2"; echo "b=$b"
echo $(( 2**63 )) $(( 2**63 - 1 ))
```

```text
3 1 1024 31 8 16
a=6
b=12
-9223372036854775808 9223372036854775807
```

나눗셈은 버림이고, `010`은 8진수라 8이다. 64비트 부호 있는 정수라 2의 63제곱은 경고 없이 음수로 넘친다. `let`은 `(( ))`의 옛 형태다.

8진수 해석은 날짜를 다룰 때 터진다.

```bash
m=08; echo $(( m + 1 ))
```

```text
bash: line 1: 08: value too great for base (error token is "08")
```

`date +%m`이 낸 `08`이 8진수로 읽혀 실패했다. `$(( 10#$m + 1 ))`처럼 진법을 밝히면 9가 나온다.

`(( ))`는 명령으로도 쓰이고, 계산 결과가 0이면 종료 코드 1을 낸다. 이게 `set -e`와 만나면 이상한 버그가 된다.

```bash
x=0; (( x++ )); echo "(( x++ )) exit=$? x=$x"
bash -c 'set -e; i=0; (( i++ )); echo "not reached"'; echo "set -e exit=$?"
```

```text
(( x++ )) exit=1 x=1
set -e exit=1
```

`x++`는 증가 전의 값 0을 결과로 내서 종료 코드가 1이다. `set -e` 스크립트는 카운터를 처음 올리는 줄에서 조용히 끝난다. `(( ++i ))`나 `i=$((i+1))`로 쓰면 된다.

`expr`는 산술을 외부 프로그램으로 하는 옛 방법이다. 인자 하나하나가 셸을 거쳐 가서 함정이 많다.

```bash
expr 7 \* 3
expr 7 * 3          # 현재 디렉터리에 a.csv, args.sh 같은 파일이 있다
```

```text
21
expr: syntax error: unexpected argument 'a.csv'
```

`*`가 경로 확장으로 파일 이름들로 바뀌었다. 게다가 매번 프로세스를 띄워서 느리다. 1부터 3000까지 더하는 루프를 둘로 재 봤다.

```bash
time (s=0; for i in $(seq 1 3000); do s=$(expr $s + $i); done; echo $s)
time (s=0; for ((i=1; i<=3000; i++)); do s=$((s+i)); done; echo $s)
```

```text
4501500

real	0m7.993s
user	0m4.960s
sys	0m1.894s
4501500

real	0m0.010s
user	0m0.010s
sys	0m0.000s
```

같은 결과에 800배 가까운 차이다. `expr` 쪽은 덧셈 한 번마다 명령 치환용 서브셸과 `expr` 프로세스를 띄웠다. 새 스크립트에서 `expr`를 쓸 이유는 없다.

소수가 필요하면 `bc`를 쓴다.

```bash
echo "scale=3; 7/2" | bc
echo "7/2" | bc
echo "0.1+0.2" | bc
echo "2^64" | bc
echo $(( 0.5 + 1 ))
```

```text
3.500
3
.3
18446744073709551616
bash: line 1: 0.5 + 1 : syntax error: invalid arithmetic operator (error token is ".5 + 1 ")
```

`bc`는 `scale`(소수 자릿수)을 정하지 않으면 정수로 자른다. 임의 정밀도라 2의 64제곱도 넘치지 않고, 0.1+0.2도 십진수로 계산해 정확히 `.3`이다(앞의 0은 생략해서 찍는다). bash의 `$(( ))`에 소수를 넣으면 그 자리에서 오류다. 응답 시간 평균처럼 소수 계산이 많아지면 `awk '{s+=$1} END {print s/NR}'`가 더 편하다.

## 배열과 연관 배열

bash의 변수는 기본적으로 문자열 하나다. 여러 값을 공백으로 이어 한 변수에 넣으면 꺼낼 때 단어 분할에 기대게 되고, 공백 있는 값에서 깨진다. 목록은 배열에 담는다.

```bash
files=("monthly report.csv" a.csv)
show "${files[@]}"
show ${files[@]}
show "${files[*]}"
echo "len=${#files[@]} first=${files[0]} last=${files[-1]}"
files+=("b c.csv"); echo "${!files[@]}"
unset 'files[1]'; echo "idx=${!files[@]} len=${#files[@]}"
```

```text
2개: [monthly report.csv] [a.csv]
3개: [monthly] [report.csv] [a.csv]
1개: [monthly report.csv a.csv]
len=2 first=monthly report.csv last=a.csv
0 1 2
idx=0 2 len=2
```

`"${files[@]}"`(따옴표 + `@`)만 원소를 하나씩 그대로 넘긴다. 따옴표가 없으면 다시 잘리고, `*`는 전부를 한 문자열로 붙인다. `unset`으로 가운데를 지우면 번호가 당겨지지 않고 구멍이 난다(0과 2). 그래서 `for ((i=0; i<${#a[@]}; i++))`로 도는 코드는 지운 뒤에 마지막 원소를 놓친다. 원소는 `for x in "${a[@]}"`로, 번호가 필요하면 `"${!a[@]}"`로 돈다.

이름으로 찾는 연관 배열은 bash 4부터 있고, 반드시 `declare -A`로 선언한다.

```bash
declare -A port=([web]=80 [api]=8080)
port[db]=5432
for k in "${!port[@]}"; do echo "$k=${port[$k]}"; done | sort
echo "has api? ${port[api]+yes}"
declare -p port
h=(); h[web]=1; h[api]=2; declare -p h     # declare -A를 빼먹었다
```

```text
api=8080
db=5432
web=80
has api? yes
declare -A port=([db]="5432" [api]="8080" [web]="80" )
declare -a h=([0]="2")
```

연관 배열의 순서는 넣은 순서가 아니라 해시 순서라 정렬이 필요하면 `sort`에 넘긴다. 키가 있는지는 `${port[api]+yes}`처럼 `+`로 본다. 마지막 줄이 흔한 실수다. `declare -A` 없이 `h[web]=1`을 쓰면 일반 배열로 취급되어 `web`과 `api`가 산술식으로 풀린다. 그런 이름의 변수가 없으니 둘 다 0번 칸이 되고, 나중 값 2만 남았다. 오류도 경고도 없다.

## 위치 매개변수와 shift

스크립트에 넘긴 인자는 `$1`, `$2`, ...에 들어간다. 인자 열 개를 넘기는 스크립트로 특수 변수를 한 번에 찍었다.

```bash
cat > args.sh <<'EOF'
#!/bin/bash
show() { printf '%s개:' "$#"; printf ' [%s]' "$@"; echo; }
echo "\$0=$0 \$#=$# \$1=$1 \${10}=${10} \$10=$10"
show "$@"
show "$*"
show $@
IFS=,; echo "\"\$*\" with IFS=, -> $*"; unset IFS
shift; echo "after shift: \$1=$1 \$#=$#"
shift 20; echo "shift 20 exit=$? \$#=$#"
EOF
chmod +x args.sh
./args.sh "a b" c d e f g h i j k
```

```text
$0=./args.sh $#=10 $1=a b ${10}=k $10=a b0
10개: [a b] [c] [d] [e] [f] [g] [h] [i] [j] [k]
1개: [a b c d e f g h i j k]
11개: [a] [b] [c] [d] [e] [f] [g] [h] [i] [j] [k]
"$*" with IFS=, -> a b,c,d,e,f,g,h,i,j,k
after shift: $1=c $#=9
shift 20 exit=1 $#=9
```

읽을 곳이 많다. `$0`은 스크립트를 부른 이름이다. `$10`은 열 번째 인자가 아니라 `$1` 뒤에 글자 0을 붙인 것이라 `a b0`이 됐다. 아홉 번째 넘어서는 `${10}`으로 쓴다. `"$@"`는 받은 인자를 개수 그대로 넘기고, `"$*"`는 IFS의 첫 글자로 이어 붙인 문자열 하나를 만든다. 따옴표 없는 `$@`는 다시 잘려서 `a b`가 둘로 갈라졌다. 다른 명령에 인자를 전달하는 래퍼 스크립트는 거의 항상 `exec real-command "$@"`로 쓴다.

`shift`는 `$1`을 버리고 나머지를 한 칸씩 당긴다. 옵션을 하나씩 처리하는 루프의 기본 재료다. 남은 개수보다 많이 shift하면 아무것도 하지 않고 1을 돌려준다.

```bash
# 간단한 옵션 처리: -v, -o 파일, 나머지는 대상
verbose=0; out=""
while [ $# -gt 0 ]; do
  case "$1" in
    -v) verbose=1 ;;
    -o) out="${2:?-o needs a file}"; shift ;;
    --) shift; break ;;
    -*) echo "unknown option: $1" >&2; exit 2 ;;
    *)  break ;;
  esac
  shift
done
echo "verbose=$verbose out=$out targets=$*"
```

짧은 옵션만 다룬다면 내장 명령 `getopts`가 `-vo file`처럼 붙여 쓴 옵션까지 처리해 준다(쓰는 법은 [조건문과 함수 글](/posts/bash-control-flow-functions)에 있다). `$#`(개수), `$?`(직전 종료 코드), `$$`(이 셸의 PID), `$!`(마지막 백그라운드 PID), `$-`(켜진 셸 옵션)도 같은 무리의 특수 변수다.

## echo 대신 printf

값을 찍을 때 `echo`는 셸마다 동작이 다르다.

```bash
echo -e 'a\tb'
sh -c "echo -e 'a\tb'"           # Ubuntu의 sh는 dash다
echo '-n'                        # 옵션으로 먹혀서 아무것도 안 찍힌다
printf '%s\n' -n
printf '%-8s|%5d|%.2f|%x\n' api 8080 3.14159 255
printf '[%q]\n' "monthly report.csv"
```

```text
a	b
-e a	b
-n
api     | 8080|3.14|ff
[monthly\ report.csv]
```

bash의 `echo`는 `-e`를 옵션으로 알아듣지만 dash의 `echo`는 `-e`를 글자로 찍고 `\t`는 기본으로 해석한다. 값이 `-n`이나 `-e`로 시작하면 `echo`가 옵션으로 먹는다. `printf '%s\n' "$값"`은 어느 셸에서나 같고, 칸 맞추기와 숫자 형식도 된다. `%q`는 셸에 다시 넣어도 안전하게 따옴표를 붙여 주어서, 로그에 "실제로 실행한 명령"을 남길 때 쓴다.

## 중괄호 확장을 직접 구현해 보기

중괄호 확장은 파일도 변수도 보지 않는 순수한 글자 놀이라서 코드로 옮기기 좋다. 아래 함수는 단어 하나를 받아 bash가 펼치는 결과를 배열로 돌려준다. 쉼표 목록(`{a,b}`), 숫자 범위(`{1..10..3}`, 앞자리 0 맞추기), 여러 개가 이어진 경우(`{a,b}{1,2}`)를 다루고, 겹친 중괄호는 다루지 않는다. 쉼표도 `..`도 없는 `{a}`는 글자 그대로 둔다. 테스트의 기대값은 모두 bash 5.2에서 `echo`로 확인한 결과다.

  const m = word.match(/^(.*?)\\{([^{}]*)\\}(.*)$/);
  if (!m) return [word];

  let items = null;
  const r = body.match(/^(-?\\d+)\\.\\.(-?\\d+)(?:\\.\\.(-?\\d+))?$/);

  return items.flatMap((it) => expandBraces(pre + it + post));

## 줄이 명령에 닿기 전에

bash는 명령을 실행하기 전에 중괄호, 틸드·변수·산술·명령 치환, 단어 분할, 경로 확장, 따옴표 제거 순으로 줄을 고쳐 쓴다. 변수가 공백에서 갈라지는 것도, `{1..$n}`이 안 펼쳐지는 것도, `expr 7 * 3`이 파일 이름을 만나는 것도 이 순서에서 나온다. 막히면 `set -x`로 마지막 모습을 찍어 보면 어느 단계에서 어긋났는지 보인다.

## 면접에서 나올 만한 질문

### bash의 확장 순서를 설명해 달라.

중괄호 확장이 가장 먼저이고, 그다음 틸드, 매개변수, 산술, 명령 치환이 왼쪽부터 함께 처리된다. 그 결과 중 따옴표 밖에 있는 것은 IFS로 단어 분할되고, `*`·`?`가 있는 단어는 경로 이름으로 확장된 뒤 마지막에 따옴표가 제거된다. 그래서 따옴표 없는 변수는 공백에서 잘리고 글로브가 펼쳐지며, 중괄호 안에는 변수를 쓸 수 없다.

### 변수를 따옴표로 감싸지 않으면 무슨 일이 생기나?

값이 펼쳐진 뒤 단어 분할과 경로 확장을 한 번 더 거친다. `f="monthly report.csv"; cp $f dst/`는 `cp`에 인자 두 개를 넘기고, 값에 `*`가 있으면 현재 디렉터리의 파일 이름들로 바뀐다. `"$f"`로 감싸면 두 단계를 건너뛰어 값이 한 인자로 그대로 간다.

### `${var:-default}`와 `${var-default}`의 차이는?

콜론이 있으면 변수가 없거나 빈 문자열일 때 기본값을 쓰고, 콜론이 없으면 아예 정의되지 않았을 때만 쓴다. 환경 변수를 빈 값으로 넘기는 실수가 흔해서 보통 콜론을 붙인다. `:=`는 기본값을 변수에 저장까지 하고, `:?`는 비어 있으면 메시지를 찍고 스크립트를 멈춰 필수 설정을 검사하는 데 쓴다.

### `"$@"`와 `"$*"`는 어떻게 다른가?

`"$@"`는 받은 인자를 원래 개수와 경계 그대로 하나씩 넘기고, `"$*"`는 IFS의 첫 글자로 이어 붙인 문자열 하나를 만든다. 다른 명령에 인자를 전달하는 래퍼는 `"$@"`를 써야 공백 있는 인자가 깨지지 않는다. 따옴표 없는 `$@`, `$*`는 둘 다 다시 단어 분할된다.

### $(( ))와 expr, bc는 언제 쓰나?

정수 계산은 셸 안에서 바로 하는 `$(( ))`가 기본이고, 빠르고 `*`를 이스케이프할 필요도 없다. `expr`는 외부 프로그램이라 매번 프로세스를 띄워 느리고 `*`가 글로브로 펼쳐지는 함정이 있어 새 코드에서는 쓰지 않는다. 소수나 64비트를 넘는 수가 필요하면 `bc`를 쓰고, `scale`을 정해야 소수 자리가 나온다.

### 08 같은 값으로 산술을 하면 왜 오류가 나나?

bash 산술에서 0으로 시작하는 숫자는 8진수로 읽히는데 8은 8진수 숫자가 아니라서 `value too great for base`가 난다. `date +%m`이나 `%d`가 내는 08, 09에서 자주 터진다. `$(( 10#$m + 1 ))`처럼 진법을 밝히거나 `date +%-m`으로 앞자리 0을 빼고 받는다.

### 연관 배열을 쓸 때 흔한 실수는?

`declare -A`를 빠뜨리는 것이다. 선언 없이 `h[web]=1`을 쓰면 일반 배열로 취급되어 키가 산술식으로 풀리고, 없는 변수 이름은 0이 되어 모든 키가 0번 칸에 덮어써진다. 오류도 나지 않는다. 또 연관 배열의 순회 순서는 넣은 순서가 아니어서 순서가 필요하면 정렬한다.

### for x in $(ls)가 왜 나쁜가?

`ls`의 출력이 명령 치환 뒤 단어 분할을 거쳐 공백이나 줄바꿈이 있는 파일 이름이 여러 조각으로 갈리고, 조각에 `*`가 있으면 다시 글로브로 펼쳐진다. `for x in *.csv`처럼 글로브를 직접 쓰면 경로 확장이 만든 이름은 다시 잘리지 않아 안전하다. 맞는 파일이 없을 때를 위해 `shopt -s nullglob`을 켠다.
