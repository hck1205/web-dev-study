[Power of Two](https://leetcode.com/problems/power-of-two/)는 LeetCode 231번이다. 정수 n이 2의 거듭제곱인지 판별한다. 반복문으로 나눠 보면 끝나는 쉬운 문제인데, 문제가 "반복문이나 재귀 없이 풀 수 있겠느냐"고 덧붙인다. 그 답이 비트 연산에서 가장 유명한 한 줄 `n & (n - 1)`이다.

`n & (n - 1)`이 가장 낮은 1 비트를 끄는 원리는 [비트 연산 글](/posts/bit-manipulation#가장-낮은-1-비트를-다루는-두-가지-요령)과 [Number of 1 Bits](/posts/leetcode-number-of-1-bits#켜진-비트만-골라-지운다)에서 봤다. 이 글은 그 요령을 판별 문제 하나에 적용하고, 나눠 보기, 비트 세기, 가장 큰 거듭제곱으로 나누기, 로그까지 여덟 가지로 풀어 비교한다. 0, 음수, 32비트 최솟값에서 어느 풀이가 깨지는지와 3·4의 거듭제곱 변형도 본다. 코드는 Node.js 22, Python 3.13, Java 21에서 직접 돌렸다.

## 1, 2, 4, 8 중 하나인가

정수 `n`이 주어진다. n = 2^x를 만족하는 0 이상의 정수 x가 있으면 참, 아니면 거짓을 돌려준다.

풀이에 영향을 주는 제약은 이것이다.

- n은 -2^31 이상 2^31 - 1 이하다. 0과 음수도 들어온다.
- 덧붙인 질문: 반복문이나 재귀 없이 풀 수 있는가.

0과 음수는 2의 거듭제곱이 아니다. 2^x는 x가 0이면 1이고, 그 뒤로 커지기만 한다. 이 범위에서 2의 거듭제곱은 2^0 = 1부터 2^30 = 1073741824까지 31개뿐이다. 2^31은 32비트 부호 있는 정수에 담기지 않는다. 이 "31개뿐"이라는 사실이 뒤의 두 풀이(가장 큰 거듭제곱으로 나누기, 미리 만든 집합)의 근거가 된다.

## 2의 거듭제곱을 이진수로 쓰면

십진수에서 10의 거듭제곱은 1, 10, 100, 1000이다. 1 하나 뒤에 0만 이어진다. 이진수에서 2의 거듭제곱도 똑같다.

```text
 1 =      1
 2 =     10
 4 =    100
 8 =   1000
16 =  10000
40 = 101000   ← 1이 두 개라 2의 거듭제곱이 아니다
```

그러니 질문을 이렇게 바꿀 수 있다. "n은 양수이고, 이진수로 썼을 때 1이 정확히 하나인가." 이 문장 하나에서 풀이 대부분이 나온다. 1을 세면 비트 세기 풀이, 1 하나를 지워 보면 `n & (n - 1)`, 1 하나만 남겨 보면 `n & -n`이다. 나눠 보기 풀이도 사실은 이진수의 끝자리 0을 하나씩 지우는 일이다.

## 2로 안 나눠질 때까지 나눈다

가장 먼저 떠오르는 건 정의를 거꾸로 따라가는 것이다. 2로 나누어떨어지는 동안 계속 나누고, 남은 값이 1이면 2의 거듭제곱이다.

```js
function isPowerOfTwo(n) {
  if (n <= 0) return false;     // 0과 음수는 2의 거듭제곱이 아니다
  while (n % 2 === 0) n /= 2;   // 2로 나누어떨어지는 동안 나눈다
  return n === 1;               // 다른 홀수 인자가 없으면 1이 남는다
}

console.log([1, 16, 40, 0, -8, 1073741824, -2147483648, 2147483647, 6].map(isPowerOfTwo).join(" "));
```

```text
true true false false false true false false false
```

`n <= 0` 검사가 먼저인 이유가 있다. 0은 `0 % 2 === 0`이 영원히 참이라 이 검사 없이는 무한 루프가 된다. 음수는 -8이 -4, -2, -1로 줄어 -1에서 멈추고 `-1 === 1`이 거짓이라 답은 맞지만, 처음부터 거르는 쪽이 분명하다.

2로 나누는 일은 이진수로 보면 오른쪽으로 한 칸 미는 일이다. 아래 그림에서 다음을 누르면 48을 나눌 때마다 끝자리 0이 하나씩 떨어져 나간다.

끝자리 0이 다 떨어지고 나면, 남는 건 이진수에서 가장 낮은 1부터 위쪽이다. 1이 하나뿐이었다면 1만 남고, 둘 이상이었다면 3이나 5 같은 홀수가 남는다. 앞 절의 "1이 정확히 하나인가"를 끝에서부터 확인하는 셈이다.

시간은 나누는 횟수만큼이다. 끝자리 0의 개수만큼 도니 최악은 2^30에서 30번, O(log n)이다. 공간은 O(1)이다. 덧붙인 질문의 "반복문 없이"를 지키지 못한다.

### 재귀로 써도 같다

```js
function isPowerOfTwo(n) {
  if (n <= 0) return false;
  if (n === 1) return true;              // 2^0
  return n % 2 === 0 && isPowerOfTwo(n / 2); // 짝수일 때만 반으로 줄여 다시 묻는다
}

console.log([1, 16, 40, 0, -8, 1073741824, -2147483648, 2147483647, 6].map(isPowerOfTwo).join(" "));
```

```text
true true false false false true false false false
```

재귀 깊이가 많아야 31이라 스택 걱정은 없다. 하지만 재귀도 덧붙인 질문이 금지한 것이고, 반복문보다 나을 것도 없다. 면접에서는 "반복문 풀이를 재귀로 바꿔 보라"는 질문에 대비하는 정도로 알아 둔다.

## 켜진 비트를 세어 하나인지 본다

앞에서 바꾼 질문을 그대로 코드로 옮긴다. 1의 개수를 세서 하나면 참이다. 1의 개수를 세는 방법은 [Number of 1 Bits](/posts/leetcode-number-of-1-bits)에 여섯 가지가 있고, 여기서는 켜진 비트만 골라 지우는 Kernighan 방식을 쓴다.

```js
function isPowerOfTwo(n) {
  if (n <= 0) return false;
  let count = 0;
  while (n !== 0) {
    n &= n - 1; // 가장 낮은 1을 끈다
    count++;
  }
  return count === 1;
}

console.log([1, 16, 40, 0, -8, 1073741824, -2147483648, 2147483647, 6].map(isPowerOfTwo).join(" "));
```

```text
true true false false false true false false false
```

시간은 1의 개수만큼이라 최악 O(31), 공간은 O(1)이다. 2147483647처럼 1이 31개인 수에서 가장 오래 돈다. 그런데 이 코드를 보면 낭비가 보인다. 우리는 1이 "하나인지"만 알고 싶은데, 끝까지 다 센다. 1을 하나 지운 뒤 0이 됐는지만 보면 된다. 그게 다음 풀이다.

내장 함수를 쓸 수 있다면 Java의 `Integer.bitCount(n) == 1`, Python 3.10 이상의 `n.bit_count() == 1`이 이 풀이를 한 줄로 만든다. 둘 다 CPU의 popcount 명령으로 처리되는 경우가 많아 빠르다.

## 가장 낮은 1을 끄면 0이 되는가

n에서 1을 빼면 이진수에서 무슨 일이 일어나는지 보자. 가장 낮은 1이 0이 되고, 그 아래의 0들이 모두 1이 된다. 받아내림이 가장 낮은 1까지 번지기 때문이다. 그 위쪽 비트는 그대로다.

```text
         n        n - 1      n & (n - 1)
40    101000     100111       100000   ← 가장 낮은 1만 꺼졌다. 위에 1이 남았다
32    100000     011111       000000   ← 1이 하나뿐이라 모두 꺼졌다
```

`n & (n - 1)`은 n과 n - 1에서 둘 다 1인 자리만 남긴다. 가장 낮은 1 자리부터 아래는 n과 n - 1이 서로 반대라 모두 0이 되고, 위쪽은 n 그대로 남는다. 결국 "n에서 가장 낮은 1 하나를 끈 값"이다. 1이 하나뿐인 수라면 그 하나를 끄는 순간 0이 된다.

```js
function isPowerOfTwo(n) {
  // 양수이고, 가장 낮은 1을 껐을 때 0이 되면 1이 하나뿐이었다
  return n > 0 && (n & (n - 1)) === 0;
}

console.log([1, 16, 40, 0, -8, 1073741824, -2147483648, 2147483647, 6].map(isPowerOfTwo).join(" "));
```

```text
true true false false false true false false false
```

시간 O(1), 공간 O(1)이다. 반복문도 재귀도 없다. 덧붙인 질문에 대한 기본 답이다.

괄호 `(n & (n - 1))`는 빼면 안 된다. JavaScript, Java, C에서 `===`(또는 `==`)가 `&`보다 먼저 계산되기 때문이다. 이 실수는 뒤의 엣지 케이스 절에서 실제 출력으로 본다.

### Python과 Java

```python
class Solution:
    def isPowerOfTwo(self, n: int) -> bool:
        # Python은 &가 ==보다 먼저 계산된다. 괄호가 없어도 (n & (n - 1)) == 0
        return n > 0 and n & (n - 1) == 0

    def isPowerOfTwoCount(self, n: int) -> bool:
        return n > 0 and n.bit_count() == 1   # Python 3.10부터

s = Solution()
xs = [1, 16, 40, 0, -8, 2**30, -2**31, 2**31 - 1, 2**40]
print([s.isPowerOfTwo(x) for x in xs])
print([s.isPowerOfTwoCount(x) for x in xs])
print(0 & -1 == 0, -8 & -9)
```

```text
[True, True, False, False, False, True, False, False, True]
[True, True, False, False, False, True, False, False, True]
True -16
```

Python은 연산자 우선순위가 다른 언어와 반대다. 비교 연산자가 비트 연산자보다 늦게 계산되어 `n & (n - 1) == 0`이 `(n & (n - 1)) == 0`으로 읽힌다. 괄호를 써도 되고 안 써도 된다. 다른 언어로 옮길 때 그대로 가져가면 틀리니, 습관적으로 괄호를 치는 편이 낫다.

Python의 정수는 크기 제한이 없어서 2^40 같은 큰 수도 그대로 판별한다. 마지막 줄은 `n > 0`을 빼면 안 되는 이유다. `0 & -1`은 0이라 0을 2의 거듭제곱으로 잘못 판단한다. -8은 Python에서 `-8 & -9`가 -16이라 우연히 걸러진다.

```java
class Solution {
    public boolean isPowerOfTwo(int n) {
        // n > 0을 먼저 본다. 최솟값 -2^31은 n - 1이 넘쳐 n & (n - 1)이 0이 된다
        return n > 0 && (n & (n - 1)) == 0;
    }

    public boolean isPowerOfTwoCount(int n) {
        return n > 0 && Integer.bitCount(n) == 1;
    }

    public static void main(String[] args) {
        Solution s = new Solution();
        int[] xs = { 1, 16, 40, 0, -8, 1 << 30, Integer.MIN_VALUE, Integer.MAX_VALUE };
        StringBuilder a = new StringBuilder(), b = new StringBuilder();
        for (int x : xs) { a.append(s.isPowerOfTwo(x)).append(' '); b.append(s.isPowerOfTwoCount(x)).append(' '); }
        System.out.println(a.toString().trim());
        System.out.println(b.toString().trim());
        int m = Integer.MIN_VALUE;
        System.out.println((m - 1) + " " + (m & (m - 1)) + " " + Integer.bitCount(m));
    }
}
```

```text
true true false false false true false false
true true false false false true false false
2147483647 0 1
```

마지막 줄이 Java에서 `n > 0`이 꼭 필요한 이유다. 최솟값 -2147483648은 이진수로 1 하나 뒤에 0이 31개다. 비트만 보면 1이 하나라서 `Integer.bitCount`가 1을 돌려준다. 게다가 `m - 1`은 넘쳐서 최댓값 2147483647(0 하나 뒤에 1이 31개)이 되고, 둘을 AND하면 0이다. `n > 0` 없이는 두 풀이 모두 최솟값을 2의 거듭제곱이라고 답한다.

## 가장 낮은 1만 남겨도 그대로인가

반대 방향으로도 물을 수 있다. 가장 낮은 1만 남긴 값이 n 자신과 같다면, 1이 그것 하나뿐이다. 가장 낮은 1만 남기는 식이 `n & -n`이다. 2의 보수에서 -n은 "모든 비트를 뒤집고 1을 더한 값"이라, 가장 낮은 1 자리만 n과 같고 그 위는 모두 반대가 된다.

```text
         n        -n (아래 6자리)   n & -n
40    101000     011000            001000   ← 8만 남았다. 40과 다르다
32    100000     100000            100000   ← 32 그대로다
```

```js
function isPowerOfTwo(n) {
  return n > 0 && (n & -n) === n; // 가장 낮은 1만 남긴 값이 자기 자신이면 1이 하나뿐이다
}

console.log([1, 16, 40, 0, -8, 1073741824, -2147483648, 2147483647, 6].map(isPowerOfTwo).join(" "));
```

```text
true true false false false true false false false
```

시간과 공간은 O(1)로 앞 풀이와 같다. `n & -n`은 펜윅 트리(구간 합 자료구조)에서 다음 칸으로 건너뛸 때 쓰는 식이라, 면접에서 함께 알아 두면 좋다. 이 문제에서는 `n & (n - 1)`과 차이가 없으니 둘 중 익숙한 쪽을 쓴다.

## 가장 큰 거듭제곱으로 나눠 보기

비트 연산 없이도 반복문 없는 답이 있다. 32비트 범위에서 가장 큰 2의 거듭제곱은 2^30 = 1073741824다. 2는 소수라서 2^30의 약수는 1, 2, 4, …, 2^30, 즉 2의 거듭제곱뿐이다. 그러니 양수 n이 2^30을 나누어떨어뜨리면 n은 2의 거듭제곱이다.

```js
function isPowerOfTwo(n) {
  // 2^30의 약수는 2의 거듭제곱뿐이다
  return n > 0 && (1 << 30) % n === 0;
}

console.log([1, 16, 40, 0, -8, 1073741824, -2147483648, 2147483647, 6].map(isPowerOfTwo).join(" "));
```

```text
true true false false false true false false false
```

시간 O(1), 공간 O(1)이다. 이 풀이는 비트를 전혀 몰라도 성립한다. 그래서 3의 거듭제곱(LeetCode 326)처럼 비트 요령이 통하지 않는 문제에서 같은 생각이 그대로 쓰인다. 단, 밑이 소수일 때만 된다. 4의 거듭제곱은 4^15의 약수에 2나 8 같은 수가 섞여 이 방법이 틀린다. 변형 절에서 다시 본다.

### 31개를 미리 집합에 넣기

2의 거듭제곱이 31개뿐이니 미리 집합에 넣어 두고 찾아봐도 된다.

```js
const POWERS = new Set();
for (let k = 0; k < 31; k++) POWERS.add(2 ** k); // 1부터 2^30까지 31개

function isPowerOfTwo(n) {
  return POWERS.has(n);
}

console.log([1, 16, 40, 0, -8, 1073741824, -2147483648, 2147483647, 6].map(isPowerOfTwo).join(" "));
```

```text
true true false false false true false false false
```

찾기는 평균 O(1)이고 집합은 31칸이라 공간도 상수다. 0과 음수를 따로 거를 필요도 없다. 집합에 없으니까. 다만 비트 연산 한 번보다 해시 계산이 훨씬 무거워서, 뒤의 측정에서 다섯 배쯤 느리다. 판별할 대상이 "정해진 몇 개의 값 중 하나인가"처럼 규칙이 없을 때나 쓰는 방식이다.

## 로그로 지수를 구하면 생기는 일

수학으로 생각하면 n = 2^x이면 x = log₂ n이다. 로그를 구해 정수인지 보면 될 것 같다.

```js
const viaLog2 = (n) => n > 0 && Number.isInteger(Math.log2(n));
const viaLn = (n) => n > 0 && Number.isInteger(Math.log(n) / Math.log(2));

console.log(viaLog2(536870912), viaLn(536870912), Math.log(536870912) / Math.log(2));
```

```text
true false 29.000000000000004
```

`Math.log2`는 2의 거듭제곱 31개에서 모두 정확한 정수를 돌려줬다. 그런데 자연로그를 2의 자연로그로 나누는 방식은 2^29 = 536870912에서 29.000000000000004를 내서 거짓이라고 답한다. 부동소수점 나눗셈의 반올림 오차다. 1부터 2^30까지 31개 중 이 한 개만 틀린다. 테스트 몇 개로는 잡히지 않는 버그라 더 위험하다.

`Math.log2`가 맞는 건 이 구현이 2의 거듭제곱을 특별히 정확하게 다루기 때문인데, 언어와 플랫폼마다 보장이 다르다. 게다가 2의 거듭제곱이 아닌 아주 큰 수에서 로그가 우연히 정수로 반올림될 위험도 있다. 정수 문제는 정수 연산으로 푸는 게 원칙이다. 면접에서 로그 풀이를 냈다면 이 오차 문제를 스스로 짚어야 한다.

## 0, 음수, 최솟값에서 깨지는 코드

### `n > 0`을 빼먹기

```js
const noPositiveCheck = (n) => (n & (n - 1)) === 0;
console.log(noPositiveCheck(0), noPositiveCheck(-2147483648), noPositiveCheck(-8));
```

```text
true true false
```

0은 `0 & -1`이 0이라 참이 나온다. 최솟값 -2147483648은 JavaScript가 비트 연산 전에 `n - 1`(-2147483649)을 32비트로 자르면서 2147483647이 되고, AND하면 0이라 참이 나온다. Java에서 본 넘침과 같은 결과다. -8은 위쪽 비트가 잔뜩 켜져 있어 우연히 걸러진다. LeetCode 테스트에는 0과 최솟값이 모두 들어 있어서 이 검사를 빼면 바로 틀린다.

### 괄호를 빼먹기

```js
const noParens = (n) => n > 0 && n & (n - 1) === 0; // ===가 먼저 계산된다
console.log(noParens(16), noParens(40), noParens(1));
```

```text
0 0 1
```

`n & (n - 1) === 0`은 `n & ((n - 1) === 0)`으로 읽힌다. `(n - 1) === 0`은 n이 1일 때만 참이고, 참은 비트 연산에서 1, 거짓은 0으로 바뀐다. 그래서 16은 `16 & 0`으로 0, 1은 `1 & 1`로 1이 나온다. 결과가 불리언도 아니고 숫자다. 1만 맞히고 나머지 2의 거듭제곱은 모두 틀린다. Java는 같은 코드를 아예 컴파일하지 않는다.

```java
class Prec {
    static boolean isPowerOfTwo(int n) {
        return n > 0 && n & (n - 1) == 0;
    }
}
```

```text
Prec.java:3: error: bad operand types for binary operator '&'
        return n > 0 && n & (n - 1) == 0;
                          ^
  first type:  int
  second type: boolean
1 error
```

`int & boolean`은 Java에서 허용되지 않아 컴파일러가 잡아 준다. JavaScript는 조용히 숫자로 바꿔 계산하니 더 위험하다.

### 나눗셈 풀이에서 0 거르기를 빼먹기

`while (n % 2 === 0) n /= 2;`에 0이 들어가면 `0 % 2`가 계속 0이라 끝나지 않는다. 비트 풀이는 `n > 0`을 빼먹어도 틀린 답이 나올 뿐인데, 나눗셈 풀이는 멈추지 않는다. 0을 맨 먼저 거른다.

## 3의 거듭제곱, 4의 거듭제곱, 다음 2의 거듭제곱

### 4의 거듭제곱이라면

LeetCode 342. Power of Four. 4의 거듭제곱은 2의 거듭제곱 중에서 1이 짝수 번째 자리(0번, 2번, 4번, …)에 있는 수다. 1 = 1, 4 = 100, 16 = 10000이다. 그래서 2의 거듭제곱인지 먼저 보고, 그 1이 짝수 자리에 있는지를 마스크 `0x55555555`(이진수 0101…0101)로 확인한다.

```js
const isPowerOfFour = (n) => n > 0 && (n & (n - 1)) === 0 && (n & 0x55555555) !== 0;
console.log([1, 4, 16, 8, 64, 2, 0].map(isPowerOfFour).join(" "));
```

```text
true true true false true false false
```

마스크 대신 `(n - 1) % 3 === 0`을 써도 된다. 4^k - 1은 언제나 3의 배수이고, 홀수 자리의 2의 거듭제곱(2, 8, 32)은 1을 빼면 3으로 나눈 나머지가 1이다.

### 3의 거듭제곱이라면

LeetCode 326. Power of Three는 비트 요령이 통하지 않는다. 3의 거듭제곱은 이진수에서 특별한 모양이 없다. 대신 앞의 "가장 큰 거듭제곱으로 나눠 보기"가 그대로 된다. 32비트 안의 가장 큰 3의 거듭제곱은 3^19 = 1162261467이다(3^20은 2^31을 넘는다). 3이 소수라서 3^19의 약수는 3의 거듭제곱뿐이다.

```js
const isPowerOfThree = (n) => n > 0 && 1162261467 % n === 0;
console.log([1, 3, 27, 9, 6, 45, 0, -3].map(isPowerOfThree).join(" "));
```

```text
true true true true false false false false
```

같은 방법이 4에서 안 되는 이유는 4가 소수가 아니라서다. 4^15의 약수에는 2, 8, 32처럼 4의 거듭제곱이 아닌 2의 거듭제곱이 섞여 있다.

### n 이상인 가장 작은 2의 거듭제곱을 구하라면

해시 테이블은 크기를 2의 거듭제곱으로 맞추는 경우가 많다. 그러면 `hash % size` 대신 `hash & (size - 1)`로 칸 번호를 구할 수 있어서다. Java의 `HashMap`이 이렇게 한다. 원하는 크기 n을 받으면 n 이상인 가장 작은 2의 거듭제곱으로 올려야 하는데, n - 1의 가장 높은 1 아래를 모두 1로 채운 뒤 1을 더하면 된다.

```js
function nextPowerOfTwo(n) {
  if (n <= 1) return 1;
  n = n - 1;          // 이미 2의 거듭제곱이면 그대로 나오게 하나 뺀다
  n |= n >>> 1;       // 가장 높은 1 바로 아래를 채운다
  n |= n >>> 2;       // 이제 두 칸씩 번진다
  n |= n >>> 4;
  n |= n >>> 8;
  n |= n >>> 16;      // 32비트 전체에 번졌다
  return n + 1;       // 111…1에 1을 더하면 1000…0
}
console.log([1, 2, 3, 5, 17, 64, 100].map(nextPowerOfTwo).join(" "));
```

```text
1 2 4 8 32 64 128
```

메모리 정렬 확인도 같은 원리다. 주소가 8의 배수인지는 `(addr & 7) === 0`으로 본다. 정렬 단위가 2의 거듭제곱이라 `size - 1`이 아래쪽 비트를 모두 덮는 마스크가 되기 때문이다. 링 버퍼(원형 큐)도 크기를 2의 거듭제곱으로 잡아 `index & (size - 1)`로 감싼다.

2의 거듭제곱은 이진수에서 1이 하나뿐인 수다. 이 한 문장을 떠올리면 `n & (n - 1)`로 그 하나를 끄고 0이 되는지 보는 데까지 금방 간다. 남는 건 0과 음수, 그리고 괄호다. 비트 요령이 안 통하는 3의 거듭제곱에서는 "가장 큰 거듭제곱의 약수인가"로 생각을 바꾸면 된다.

## 면접에서 나올 만한 질문

### 반복문 없이 2의 거듭제곱을 판별하는 방법은 무엇인가요?

`n > 0 && (n & (n - 1)) == 0`이다. 2의 거듭제곱은 이진수에서 1이 하나뿐이고, `n & (n - 1)`은 가장 낮은 1 하나를 끈 값이다. 1이 하나뿐이면 그걸 끄는 순간 0이 된다. 시간과 공간 모두 O(1)이다.

### `n & (n - 1)`이 가장 낮은 1을 끄는 이유를 설명해 주세요.

n에서 1을 빼면 받아내림이 가장 낮은 1까지 번져, 그 1은 0이 되고 아래의 0들은 모두 1이 된다. 그 위쪽 비트는 그대로다. 그래서 n과 n - 1을 AND하면 가장 낮은 1 자리부터 아래는 서로 반대라 0이 되고, 위쪽만 남는다. 40(101000)이면 32(100000)가 된다.

### `n > 0` 검사는 왜 필요한가요?

0과 32비트 최솟값에서 틀리기 때문이다. 0은 `0 & -1`이 0이라 참이 나온다. 최솟값 -2^31은 이진수로 1이 하나뿐이고 n - 1이 넘쳐 최댓값이 되어 AND가 0이 된다. 2의 거듭제곱은 양수뿐이니 먼저 거른다.

### 비트 연산을 쓰지 않고 반복 없이 풀 수 있나요?

32비트 범위에서 가장 큰 2의 거듭제곱 2^30을 n으로 나눠 떨어지는지 본다. 2가 소수라 2^30의 약수는 2의 거듭제곱뿐이기 때문이다. 같은 방식으로 3의 거듭제곱은 3^19 = 1162261467로 판별한다. 밑이 소수가 아니면 이 방법은 통하지 않는다.

### 로그를 써서 판별하면 안 되나요?

부동소수점 오차 때문에 위험하다. `Math.log(n) / Math.log(2)`는 2^29에서 29.000000000000004가 나와 틀린다. `Math.log2`는 이번에 돌려 본 환경에서는 맞았지만 플랫폼마다 보장이 다르다. 정수 판별은 정수 연산으로 한다.

### 4의 거듭제곱은 어떻게 판별하나요?

2의 거듭제곱이면서 그 1이 짝수 번째 자리에 있어야 한다. `n > 0 && (n & (n - 1)) == 0 && (n & 0x55555555) != 0`으로 본다. 마스크 대신 `(n - 1) % 3 == 0`을 써도 된다. 4^k - 1은 늘 3의 배수이기 때문이다.

### 이 요령이 실무에서 쓰이는 곳이 있나요?

해시 테이블과 링 버퍼가 크기를 2의 거듭제곱으로 잡아 `% size` 대신 `& (size - 1)`로 칸 번호를 구한다. Java의 `HashMap`이 그렇다. 메모리 주소가 8바이트 정렬인지 보는 `(addr & 7) == 0`도 같은 원리다. 크기를 2의 거듭제곱으로 올릴 때는 가장 높은 1 아래를 모두 채우고 1을 더한다.
