연결 리스트 문제를 몇 개 풀고 나면 "가운데 찾기", "뒤집기", "두 리스트 합치기"를 각각 짤 수 있게 된다. 그런데 이 셋을 한 문제에서 동시에 쓰라고 하면 손이 멈춘다. 어디서 끊고 무엇을 먼저 해야 할지 순서가 안 잡혀서다.

[LeetCode 143. Reorder List](https://leetcode.com/problems/reorder-list/)가 그런 문제다. 앞에서 하나, 뒤에서 하나씩 번갈아 다시 엮으라는 요구는 간단한데, 단일 연결 리스트에서는 뒤에서부터 걸어올 수 없어서 바로 짜기 어렵다. 이 글은 꼬리를 매번 찾아오는 느린 풀이부터 배열, 스택, 재귀 풀이를 거쳐 "자르고, 뒤집고, 엮는" O(1) 공간 풀이까지 다섯 가지를 따라간다. 부품이 되는 세 문제는 [Linked List Cycle](/posts/leetcode-linked-list-cycle)(빠른·느린 포인터), [Reverse Linked List](/posts/leetcode-reverse-linked-list), [Merge Two Sorted Lists](/posts/leetcode-merge-two-sorted-lists)에서 각각 자세히 다뤘다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 앞에서 하나, 뒤에서 하나

단일 연결 리스트 `L0 → L1 → … → Ln-1 → Ln`이 주어진다. 이걸 `L0 → Ln → L1 → Ln-1 → L2 → Ln-2 → …` 순서로 바꾼다. 노드의 값을 바꾸면 안 되고 노드 자체를 다시 이어야 한다. 함수는 아무것도 돌려주지 않고, 주어진 리스트를 제자리에서 바꾼다.

```text
1 → 2 → 3 → 4 → 5 → 6   →   1 → 6 → 2 → 5 → 3 → 4
1 → 2 → 3 → 4 → 5       →   1 → 5 → 2 → 4 → 3
1 → 2                   →   1 → 2
```

노드는 1개에서 5×10^4개, 값은 1에서 1000 사이다. 5×10^4개면 n²이 25억이라 O(n²)은 시간 안에 못 들어온다. O(n)이 필요하다. 뒤에서 보겠지만 재귀 깊이로도 5×10^4는 위험한 숫자다.

## 손으로 엮어 보면 보이는 세 가지 일

`1→2→3→4→5→6`을 손으로 바꿔 보자. 결과는 `1 6 2 5 3 4`다. 이 결과를 두 줄로 나눠 읽으면 규칙이 보인다.

```text
홀수 번째 자리:  1   2   3        ← 원래 리스트의 앞쪽 절반, 원래 순서
짝수 번째 자리:    6   5   4      ← 원래 리스트의 뒤쪽 절반, 거꾸로
```

결과는 "앞쪽 절반"과 "거꾸로 된 뒤쪽 절반"을 하나씩 번갈아 엮은 것이다. 그러니 할 일은 세 가지다.

1. 리스트를 가운데에서 두 조각으로 나눈다.
2. 뒤쪽 조각을 뒤집는다.
3. 두 조각에서 하나씩 번갈아 꺼내 엮는다.

노드가 홀수 개면 앞쪽이 하나 더 많다. `1→2→3→4→5`는 앞쪽 `1 2 3`, 뒤쪽 `5 4`를 엮어 `1 5 2 4 3`이 된다. 이 관찰이 마지막 풀이다. 하지만 이 분해가 바로 떠오르지 않는다면, 우선 문제 문장 그대로 "뒤에서 하나를 가져와 끼운다"를 짜는 데서 시작한다.

## 매번 꼬리를 찾아 끼워 넣기

가장 직접적인 방법은 문장을 그대로 따라 하는 것이다. 현재 노드 `cur` 뒤에 리스트의 꼬리를 떼어 와서 끼우고, `cur`를 두 칸 옮긴다. 남은 노드가 두 개 이하가 되면 멈춘다.

```js
function reorderList(head) {
  let cur = head;
  // cur 뒤에 노드가 둘 이상 남아 있어야 옮길 꼬리가 있다
  while (cur && cur.next && cur.next.next) {
    // 꼬리 바로 앞 노드를 찾는다
    let beforeTail = cur;
    while (beforeTail.next.next) beforeTail = beforeTail.next;

    const tail = beforeTail.next;
    beforeTail.next = null;     // 꼬리를 떼어 낸다
    tail.next = cur.next;       // cur 바로 뒤에 끼운다
    cur.next = tail;
    cur = tail.next;            // 끼운 꼬리 다음 노드로
  }
}
```

`1→2→3→4→5→6`에서 첫 바퀴는 6을 떼어 1 뒤에 끼우고(`1→6→2→3→4→5`), 둘째 바퀴는 5를 떼어 2 뒤에 끼운다(`1→6→2→5→3→4`). 다음 `cur`인 3 뒤에는 4 하나만 남아서 멈춘다.

맞기는 한데 느리다. 꼬리를 찾을 때마다 남은 리스트를 끝까지 걸어야 해서, n/2번 반복하며 매번 O(n)을 쓴다. 전체 O(n²), 공간 O(1)이다. 노드 1만 개에서 64ms, 5만 개에서 1.75초가 걸렸다. 길이가 다섯 배가 되자 시간이 스물일곱 배가 됐다. 꼬리를 매번 처음부터 찾는 게 문제다. 뒤쪽 노드에 바로 갈 수 있다면 이 걸음을 없앨 수 있다.

## 노드를 배열에 담고 양 끝에서 좁혀 오기

배열은 아무 칸에나 바로 갈 수 있다. 노드를 전부 배열에 담으면 뒤쪽 노드를 `nodes[j]`로 바로 꺼낼 수 있다. 그다음은 [투 포인터](/posts/two-pointers-pattern) 문제다. 왼쪽 `i`, 오른쪽 `j`를 양 끝에 두고 `i → j → i+1 → j-1 → …` 순서로 화살표를 다시 건다.

```js
function reorderList(head) {
  const nodes = [];
  for (let n = head; n; n = n.next) nodes.push(n);

  let i = 0, j = nodes.length - 1;
  while (i < j) {
    nodes[i].next = nodes[j]; // 앞 → 뒤
    i++;
    if (i === j) break;       // 가운데에서 만났다
    nodes[j].next = nodes[i]; // 뒤 → 다음 앞
    j--;
  }
  nodes[i].next = null;       // 마지막 노드가 새 꼬리
}
```

아래 그림은 `1→2→3→4→5`를 이 방법으로 바꾸는 과정이다. 화살표 표시가 붙은 칸이 `i`, 초록 칸이 `j`다.

마지막 `nodes[i].next = null`이 중요하다. 3은 원래 4를 가리키고 있었다. 이걸 끊지 않으면 `3→4→3→4…` 고리가 생긴다. 노드가 짝수 개일 때도 같다. `1→2→3→4→5→6`이면 `i`가 4에 닿고 4가 원래 가리키던 5를 끊는다.

시간 O(n), 공간 O(n)이다. 노드 5만 개에서 약 4ms로 앞의 풀이보다 수백 배 빠르다. 코드도 짧고 실수할 곳이 적어서, 면접에서 시간이 부족하면 이 풀이를 먼저 내는 것도 방법이다. 다만 "추가 공간 없이"라는 요구가 붙으면 배열을 없애야 한다.

## 스택에서 뒤쪽 노드를 꺼내 끼우기

배열 대신 스택을 쓰면 "뒤에서부터 하나씩"이 자연스럽게 나온다. 노드를 모두 스택에 넣고, 앞에서부터 걸으면서 스택에서 꺼낸 노드를 하나씩 끼운다. 꼬리를 매번 찾아오던 첫 풀이에서, 꼬리 찾기만 스택의 `pop`으로 바꾼 셈이다.

```js
function reorderList(head) {
  const stack = [];
  for (let n = head; n; n = n.next) stack.push(n);

  // 뒤에서 가져와 끼울 노드 수. 6개면 2개(6, 5), 5개면 2개(5, 4)
  const moves = Math.floor((stack.length - 1) / 2);
  let cur = head;
  for (let k = 0; k < moves; k++) {
    const last = stack.pop();  // 남은 노드 중 가장 뒤
    last.next = cur.next;      // cur 뒤에 끼운다
    cur.next = last;
    cur = last.next;
  }
  // 스택에 남은 맨 위 노드가 새 꼬리. 옛 next를 끊는다
  stack[stack.length - 1].next = null;
}
```

몇 개를 옮겨야 하는지 세는 부분이 까다롭다. 노드 n개 중 앞쪽 절반은 제자리에 있고 뒤쪽 `floor((n-1)/2)`개만 끼워 들어간다. 6개면 6과 5, 5개면 5와 4다. 다 옮긴 뒤 스택에 남은 맨 위 노드(6개일 때 4, 5개일 때 3)가 결과의 꼬리가 된다. 이 노드는 아직 옮겨 간 노드를 가리키고 있으니 끊어야 한다.

시간 O(n), 공간 O(n)으로 배열 풀이와 같다. 장점이 있다면 노드를 앞에서부터 하나씩 처리하는 흐름이 문제 문장과 닮았다는 것 정도다. 개수를 세는 실수가 나기 쉬워서 배열 풀이보다 낫지는 않다.

## 재귀로 뒤쪽 노드를 하나씩 돌려받기

스택을 직접 만들지 않고 콜 스택에 맡길 수도 있다. 재귀로 리스트 끝까지 내려가면, 돌아오는 길에 노드를 뒤에서부터 하나씩 받는다. 앞쪽 포인터 `left`는 바깥에 두고, 돌아올 때마다 `left` 뒤에 지금 노드 `right`를 끼운다.

```js
function reorderList(head) {
  let left = head;   // 앞에서부터 움직이는 포인터
  let done = false;  // 가운데에서 만나면 더 할 일이 없다

  function go(right) {
    if (!right) return;
    go(right.next);  // 끝까지 내려간다. 돌아올 때 right는 뒤에서부터 나온다
    if (done) return;

    // left와 right가 만났거나 바로 이웃이면, right가 새 꼬리다
    if (left === right || left.next === right) {
      right.next = null;
      done = true;
      return;
    }
    const nxt = left.next;
    left.next = right;   // left 뒤에 right를 끼운다
    right.next = nxt;
    left = nxt;          // left는 한 칸 앞으로
  }
  go(head);
}
```

돌아오는 순서가 6, 5, 4, …이고 `left`는 1, 2, 3, …으로 나아가니, 두 포인터가 양 끝에서 좁혀 오는 배열 풀이와 같은 일을 한다. 둘이 만나거나 이웃이 되면 그 자리가 꼬리다.

시간 O(n), 공간은 콜 스택이 O(n)이다. 깊이를 재 보면 Node.js에서 노드 5000개는 됐지만 1만 개에서 `RangeError: Maximum call stack size exceeded`가 났다. 문제 제약이 5×10^4라서 이 환경에서는 최대 입력을 버티지 못한다. Python은 기본 재귀 한도가 1000이라 더 일찍 터진다. 재귀가 "뒤에서부터 돌려받기"를 공짜로 해 준다는 걸 보여 주는 데 의미가 있고, 제출용으로는 맞지 않는다.

## 가운데에서 자르고, 뒤집고, 엮는다

앞의 세 풀이는 모두 "뒤쪽 노드에 바로 가기" 위해 O(n) 공간을 썼다. 손으로 풀며 찾은 분해를 쓰면 그럴 필요가 없다. 뒤쪽 절반을 미리 뒤집어 두면 뒤에서부터 나와야 할 노드가 앞에서부터 나온다. 그러면 두 리스트를 앞에서부터 하나씩 엮기만 하면 된다.

1. 빠른·느린 포인터로 앞쪽 절반의 끝 `slow`를 찾는다. `fast`가 두 칸씩 가다가 더 못 가면 멈춘다.
2. `slow.next`부터를 떼어 내고(`slow.next = null`), 그 뒤쪽 절반을 뒤집는다.
3. 앞쪽 `first`와 뒤집힌 뒤쪽 `second`에서 하나씩 번갈아 엮는다. 다음 노드를 미리 잡아 두고 화살표를 건다.

아래 그림은 `1→2→3→4→5→6`을 세 단계로 바꾸는 과정이다. 화살표 표시가 지금 보는 노드이고, 초록 칸은 결과 자리에 엮인 노드다.

엮는 단계에서 `결과`가 `1→6→2→3`처럼 보이는 건, 2가 아직 앞쪽 조각에서 3을 가리키고 있어서다. 엮기는 앞쪽 조각 사이사이에 뒤쪽 노드를 끼워 넣는 일이라, 끼우지 않은 부분은 원래 연결을 그대로 쓴다. 뒤쪽 조각이 비면 앞쪽에 남은 노드(홀수 개일 때 가운데 하나)는 이미 제자리에 이어져 있으니 따로 할 일이 없다.

```js
function reorderList(head) {
  if (!head || !head.next) return;

  // 1) 가운데 찾기: slow가 앞쪽 절반의 끝에 선다
  let slow = head, fast = head;
  while (fast.next && fast.next.next) {
    slow = slow.next;
    fast = fast.next.next;
  }

  // 2) 뒤쪽 절반을 떼어 내고 뒤집는다
  let second = slow.next;
  slow.next = null;              // 앞쪽 조각의 끝을 끊는다
  let prev = null;
  while (second) {
    const next = second.next;
    second.next = prev;
    prev = second;
    second = next;
  }
  second = prev;                 // 뒤집힌 뒤쪽의 머리

  // 3) 앞에서 하나, 뒤에서 하나씩 엮는다
  let first = head;
  while (second) {
    const n1 = first.next;       // 다음 앞쪽 노드
    const n2 = second.next;      // 다음 뒤쪽 노드
    first.next = second;         // 앞 → 뒤
    second.next = n1;            // 뒤 → 다음 앞
    first = n1;
    second = n2;
  }
}
```

각 단계가 리스트를 한 번 이하로 훑는다. 가운데 찾기는 n/2걸음, 뒤집기는 n/2개, 엮기는 n/2번이다. 전체 O(n), 공간은 포인터 몇 개라 O(1)이다. 노드 5만 개에서 약 2ms가 걸렸다.

엮기 반복 조건이 `while (second)` 하나인 이유가 있다. 앞쪽 조각은 뒤쪽보다 길거나 같다. 그래서 뒤쪽이 남아 있는 동안 앞쪽 `first`는 항상 노드를 가리킨다. 뒤쪽이 먼저 끝나거나 동시에 끝나니 `first`를 따로 확인할 필요가 없다.

### 가운데는 어느 쪽이어도 된다

노드가 짝수 개면 가운데가 둘이다. 위 코드는 `fast.next && fast.next.next` 조건으로 앞쪽 가운데(6개 중 3)에서 멈춘다. [Linked List Cycle](/posts/leetcode-linked-list-cycle)에서 쓴 `fast && fast.next` 조건이면 뒤쪽 가운데(6개 중 4)에서 멈춘다. 이때 `slow.next`부터 떼면 앞쪽이 `1→2→3→4`, 뒤쪽이 `5→6`이 된다.

결과는 똑같이 맞다. 직접 돌려 보면 6개, 5개, 4개, 3개, 2개 모두 같은 답이 나온다. 뒤쪽이 `6→5`로 하나 짧아도, 엮기가 끝난 뒤 앞쪽에 남은 `3→4`가 원래 연결 그대로 꼬리에 붙기 때문이다. 두 조건 중 어느 쪽을 쓰든 "앞쪽이 뒤쪽보다 길거나 같게" 자르기만 하면 된다. 반대로 뒤쪽이 더 길게 자르면 엮기 중에 `first`가 먼저 `null`이 되어 `null.next`를 읽다 터진다.

### Python과 Java로 쓰면

Python은 다중 대입으로 세 단계를 짧게 쓸 수 있다. 뒤집기 줄에서는 `second.next`를 맨 왼쪽에 둬야 한다. 왼쪽은 왼쪽부터 대입되니 `second`를 먼저 바꾸면 엉뚱한 노드의 화살표를 건드린다. 이 함정은 [Reverse Linked List](/posts/leetcode-reverse-linked-list)에서 자세히 봤다.

```python
def reorder_list(head):
    if not head or not head.next:
        return
    # 1) 가운데: slow가 앞쪽 절반의 끝에 선다
    slow = fast = head
    while fast.next and fast.next.next:
        slow, fast = slow.next, fast.next.next
    # 2) 뒤쪽 절반을 떼어 뒤집는다
    second, slow.next = slow.next, None
    prev = None
    while second:
        second.next, prev, second = prev, second, second.next
    # 3) 하나씩 번갈아 엮는다
    first, second = head, prev
    while second:
        n1, n2 = first.next, second.next
        first.next, second.next = second, n1
        first, second = n1, n2
```

Java는 JavaScript와 같은 모양이다. 반환형은 `void`다. 머리 노드는 바뀌지 않으니(결과의 첫 노드는 언제나 원래 머리) 돌려줄 필요가 없다.

```java
class Solution {
    public void reorderList(ListNode head) {
        if (head == null || head.next == null) return;
        ListNode slow = head, fast = head;
        while (fast.next != null && fast.next.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        ListNode second = slow.next;
        slow.next = null;                 // 앞쪽 절반을 끊는다
        ListNode prev = null;
        while (second != null) {          // 뒤쪽 절반 뒤집기
            ListNode next = second.next;
            second.next = prev;
            prev = second;
            second = next;
        }
        ListNode first = head;
        second = prev;
        while (second != null) {          // 번갈아 엮기
            ListNode n1 = first.next, n2 = second.next;
            first.next = second;
            second.next = n1;
            first = n1;
            second = n2;
        }
    }
}
```

세 언어로 돌린 결과다.

```text
[1,2,3,4,5,6]  →  [1, 6, 2, 5, 3, 4]
[1,2,3,4,5]    →  [1, 5, 2, 4, 3]
[1]            →  [1]
[1,2]          →  [1, 2]
[1,2,3]        →  [1, 3, 2]
[7,7,8,8]      →  [7, 8, 7, 8]
```

## 다섯 풀이를 나란히 놓으면

| 풀이 | 시간 | 공간 | 언제 고르나 |
|---|---|---|---|
| 매번 꼬리 찾기 | O(n²) | O(1) | 문제를 처음 이해할 때. 5×10^4에서는 시간 초과 |
| 배열 + 투 포인터 | O(n) | O(n) | 빨리 맞는 답을 내야 할 때. 실수할 곳이 적다 |
| 스택에서 꺼내 끼우기 | O(n) | O(n) | 배열 풀이의 변형. 옮길 개수 계산이 까다롭다 |
| 재귀로 뒤에서 돌려받기 | O(n) | O(n) 콜 스택 | 재귀를 보여 줄 때. 큰 입력에서 스택이 넘친다 |
| 자르고 뒤집고 엮기 | O(n) | O(1) | 기본 답. 추가 공간 없이 제자리에서 바꾼다 |

면접에서는 배열 풀이로 아이디어를 먼저 말하고, O(1) 공간을 요구받으면 "뒤쪽에 바로 가려고 배열을 썼는데, 뒤쪽을 뒤집어 두면 앞에서부터 갈 수 있다"로 넘어가면 흐름이 자연스럽다.

## 끊지 않은 화살표가 만드는 고리

가장 흔한 실수는 2단계에서 `slow.next = null`을 빼먹는 것이다. 뒤쪽을 뒤집기만 하고 앞쪽 끝을 끊지 않으면, 앞쪽의 마지막 노드(3)가 여전히 4를 가리킨다. 그 4는 뒤집힌 뒤쪽 조각의 꼬리이기도 하다. 마지막 엮기에서 `first`인 3의 다음 노드 `n1`이 바로 그 4라서, `second.next = n1`이 4가 자기 자신을 가리키게 만든다. 결과를 앞에서 열두 개만 찍어 보면 이렇게 나온다.

```text
[1,2,3,4,5,6] → 1→6→2→5→3→4→4→4→4→4→4→4   (4가 자기 자신을 가리킨다)
[1,2,3,4,5]   → 1→5→2→4→3→4→3→4→3→4→3→4   (3과 4가 서로를 가리킨다)
```

LeetCode 채점기는 고리를 만나면 오류를 낸다. 로컬에서 출력 함수를 돌리면 끝나지 않는다. 고리가 의심되면 [Linked List Cycle](/posts/leetcode-linked-list-cycle)의 Floyd 검사를 끼워 넣어 어느 단계 뒤에 생겼는지 확인한다.

엮기에서 다음 노드를 잡아 두지 않는 실수도 있다. `first.next = second`를 먼저 하면 `first`의 원래 다음 노드를 잃는다. 뒤집기의 "끊기 전에 붙잡는다"와 같은 규칙이다. `n1`, `n2` 두 개를 모두 먼저 잡고 화살표를 건다.

함수 안에서 `head`를 다른 노드로 바꾸거나 새 리스트를 만들어 돌려주는 것도 틀린다. 이 문제는 반환값을 보지 않고 원래 `head`부터 따라가며 채점한다. 새 노드로 결과를 만들어 `return`하면 원래 리스트는 그대로라 오답이다. 값만 바꾸는 풀이도 "노드를 바꾸라"는 조건을 어긴다.

노드가 하나나 둘이면 바꿀 게 없다. 맨 앞의 `if (!head || !head.next) return`이 없어도 위 코드는 맞게 동작하지만(`fast.next`가 `null`이면 가운데 찾기를 안 돌고, 뒤쪽 조각이 비거나 하나), 노드 하나일 때 `fast.next.next`를 읽기 전에 `fast.next`를 확인하는 순서가 지켜져야 한다. 조건을 `fast.next.next && fast.next`로 뒤집어 쓰면 노드 하나에서 `TypeError`가 난다.

## 같은 부품으로 푸는 다른 문제

### 앞뒤가 같은지 확인하라면

LeetCode 234 Palindrome Linked List는 이 글의 1, 2단계를 그대로 쓴다. 가운데를 찾고 뒤쪽 절반을 뒤집은 다음, 엮는 대신 앞쪽과 한 칸씩 값을 비교한다. 비교가 끝나면 뒤쪽을 다시 뒤집어 붙여서 입력을 원래대로 돌려놓는다.

```js
function isPalindrome(head) {
  let slow = head, fast = head;
  while (fast.next && fast.next.next) { slow = slow.next; fast = fast.next.next; }
  const secondHead = reverse(slow.next);   // 뒤쪽 절반 뒤집기
  let p1 = head, p2 = secondHead, ok = true;
  while (p2) {
    if (p1.val !== p2.val) { ok = false; break; }
    p1 = p1.next;
    p2 = p2.next;
  }
  slow.next = reverse(secondHead);         // 원래대로 돌려놓는다
  return ok;
}
// 1221 → true,  12321 → true,  12 → false,  7 → true (검사 후 리스트는 그대로)
```

### 재배치를 되돌리라면

`1→6→2→5→3→4`를 받아 `1→2→3→4→5→6`으로 되돌리는 문제다. 이번엔 반대 순서로 한다. 홀수 번째 노드와 짝수 번째 노드를 두 조각으로 나누고(LeetCode 328 Odd Even Linked List가 이 분리다), 짝수 번째 조각을 뒤집어 홀수 조각 뒤에 붙인다.

```js
function undoReorder(head) {
  if (!head || !head.next) return;
  let odd = head, even = head.next;
  const evenHead = even;
  while (even && even.next) {   // 홀수 자리와 짝수 자리를 나눈다
    odd.next = even.next;
    odd = odd.next;
    even.next = odd.next;
    even = even.next;
  }
  odd.next = reverse(evenHead); // 짝수 조각을 뒤집어 뒤에 붙인다
}
// 1→6→2→5→3→4 → 1→2→3→4→5→6,  1→5→2→4→3 → 1→2→3→4→5
```

재배치가 "자르기 → 뒤집기 → 엮기"였으니 되돌리기는 "풀기 → 뒤집기 → 붙이기"다. 두 문제를 나란히 놓으면 각 부품이 어떤 일을 하는지 더 또렷해진다.

### k개씩 묶어서 다루라면

[Reverse Nodes in k-Group](/posts/leetcode-reverse-nodes-in-k-group)은 k개씩 끊어서 뒤집고 다시 잇는다. 이 글의 "끊고, 뒤집고, 다시 잇기"를 k칸마다 되풀이하는 문제라, 조각의 앞뒤 이음매를 잡아 두는 감각이 그대로 쓰인다.

### 이중 연결 리스트라면

노드에 `prev`가 있으면 꼬리에서 뒤로 걸어올 수 있다. 머리와 꼬리 포인터를 양 끝에 두고 배열 투 포인터 풀이처럼 좁혀 오면, 뒤집기 없이 O(1) 공간으로 끝난다. 이 경우 `prev` 화살표도 함께 고쳐야 해서 한 번에 바꿔야 하는 화살표가 네 개로 는다. 단일 연결 리스트에서 뒤집기가 필요한 건 결국 "뒤로 가는 화살표가 없어서"다.

### 원본을 보존하고 새 리스트로 만들라면

노드를 복사해서 결과를 만들라고 하면 제자리 조건이 사라진다. 배열에 값을 담아 투 포인터로 순서를 정한 뒤 새 노드를 만들면 O(n) 공간으로 간단하다. 원본을 공유하는 다른 코드가 있을 때는 이쪽이 안전하다.

## 자르고, 뒤집고, 엮는다

결과를 두 줄로 나눠 읽으면 앞쪽 절반과 거꾸로 된 뒤쪽 절반이 번갈아 서 있다. 그래서 빠른·느린 포인터로 가운데를 찾아 자르고, 뒤쪽을 뒤집고, 두 조각을 하나씩 엮으면 O(n) 시간, O(1) 공간에 제자리에서 끝난다. 배열이나 스택, 재귀를 쓴 풀이는 모두 "뒤쪽 노드에 바로 가려고" 공간을 쓴 것이고, 뒤집기가 그 필요를 없앤다. 자를 때 앞쪽 끝을 `null`로 끊고, 엮을 때 다음 노드 두 개를 먼저 잡는 것만 지키면 된다.

## 면접에서 나올 만한 질문

### 이 문제를 어떤 하위 문제로 나눠서 푸나요?

가운데 찾기, 뒤쪽 절반 뒤집기, 두 리스트 번갈아 엮기 세 가지로 나눈다. 결과를 홀수 자리와 짝수 자리로 나눠 보면 앞쪽 절반이 원래 순서로, 뒤쪽 절반이 거꾸로 서 있기 때문이다. 각각 빠른·느린 포인터, 세 포인터 뒤집기, 다음 노드를 잡아 두고 잇기로 푼다.

### 시간과 공간 복잡도는 어떻게 되나요?

시간 O(n), 공간 O(1)이다. 가운데 찾기, 뒤집기, 엮기가 각각 리스트의 절반 정도를 한 번씩 훑고, 쓰는 건 포인터 몇 개뿐이다. 새 노드를 만들지 않고 화살표만 바꾼다.

### 배열에 노드를 담는 풀이는 왜 부족한가요?

시간은 O(n)으로 같지만 노드 수만큼 배열 공간이 든다. 배열을 쓴 이유는 뒤쪽 노드에 바로 가기 위해서인데, 뒤쪽 절반을 뒤집어 두면 앞에서부터 걸어도 뒤쪽 노드가 필요한 순서로 나온다. 그래서 O(1) 공간이 가능하다. 다만 코드가 짧고 실수가 적어서 첫 답으로 내기에는 좋다.

### `slow.next = null`을 빼먹으면 어떻게 되나요?

앞쪽 조각의 마지막 노드가 뒤쪽 조각의 노드를 계속 가리켜서, 엮고 나면 리스트 끝에 고리가 생긴다. `[1,2,3,4,5,6]`이면 4가 자기 자신을, `[1,2,3,4,5]`면 3과 4가 서로를 가리킨다. 출력이 끝나지 않거나 채점기가 오류를 낸다.

### 노드가 짝수 개일 때 가운데는 어느 쪽을 골라야 하나요?

어느 쪽이어도 앞쪽 조각이 뒤쪽보다 길거나 같게만 자르면 결과가 같다. 엮기가 뒤쪽이 빌 때 끝나고, 앞쪽에 남은 노드는 원래 연결 그대로 꼬리에 붙기 때문이다. 뒤쪽이 더 길면 엮는 중에 앞쪽이 먼저 바닥나서 `null`을 읽다가 터진다.

### 재귀로 풀면 무엇이 문제인가요?

끝까지 내려갔다가 돌아오며 뒤쪽 노드를 하나씩 받는 방식이라 콜 스택이 노드 수만큼 쌓인다. 직접 재 보니 Node.js에서 1만 개에서 스택이 넘쳤고, 제약은 5×10^4개다. Python은 기본 한도가 1000이라 더 빨리 터진다. 그래서 제출용은 반복 풀이다.

### 같은 리스트가 회문인지 O(1) 공간으로 볼 수 있나요?

이 문제의 1, 2단계를 그대로 쓴다. 가운데를 찾아 뒤쪽 절반을 뒤집고 앞쪽과 한 칸씩 값을 비교한다. 입력을 바꾸는 방법이라 비교가 끝나면 뒤쪽을 다시 뒤집어 붙여서 원래대로 돌려놓는다.
