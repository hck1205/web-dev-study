코드에서 정규식을 매일 쓰면서도 그 안에서 무슨 일이 일어나는지는 잘 안 들여다본다. [LeetCode 10. Regular Expression Matching](https://leetcode.com/problems/regular-expression-matching/)은 아주 작은 정규식 엔진을 직접 만들라는 문제다. 지원하는 기호는 `.`과 `*` 두 개뿐인데도 Hard로 분류된다. `*`가 몇 글자를 먹을지 정해지지 않아서, 순진하게 짜면 시간이 폭발하고, 꼼꼼하게 짜면 2차원 DP가 된다.

이 글은 풀이 여섯 개를 놓는다. 언어의 내장 정규식(면접에서는 안 되는 답), 재귀 백트래킹, 메모이제이션, 2차원 표, 두 줄 DP, 그리고 상태 집합을 들고 가는 NFA 시뮬레이션이다. 두 문자열로 표를 채우는 틀은 [Longest Common Subsequence](/posts/leetcode-longest-common-subsequence)와 [Edit Distance](/posts/leetcode-edit-distance)와 같고, 재귀가 갈래마다 불어나는 이유는 [재귀와 백트래킹 글](/posts/recursion-backtracking)에 있다. 코드는 모두 Node.js 22, Python 3, Java 21에서 돌렸다.

## 점 하나와 별 하나로 만든 정규식

문자열 `s`와 패턴 `p`가 주어진다. 패턴이 문자열 전체와 맞으면 `true`를 돌려준다. 패턴의 기호 규칙은 둘이다.

- `.`은 아무 글자 하나와 맞는다.
- `*`는 바로 앞의 원소(글자 하나 또는 `.`)를 0번 이상 반복한다. `a*`는 빈 문자열, `a`, `aa`, …와 맞고, `.*`는 아무 문자열과 맞는다.

부분이 아니라 전체가 맞아야 한다. 패턴 `ab`는 `"xaby"`와 맞지 않는다. JavaScript로 치면 `/^(?:ab)$/`처럼 양 끝을 묶은 것이다.

- `s`와 `p`의 길이는 1 이상 20 이하다.
- `s`는 영어 소문자, `p`는 영어 소문자와 `.`, `*`로만 되어 있다.
- `*` 앞에는 항상 맞출 글자가 있다. `*`로 시작하거나 `**`가 연달아 나오는 패턴은 들어오지 않는다.

길이 상한이 20이라 표는 21 × 21칸이면 된다. 다만 재귀 백트래킹은 이 작은 크기에서도 수천만 번 호출될 수 있다. 뒤에서 직접 잰다.

`*`는 파일 이름에서 쓰는 와일드카드(`*.log`)와 뜻이 다르다는 점을 먼저 짚는다. 와일드카드의 `*`는 혼자서 "아무 문자열"이지만, 정규식의 `*`는 혼자 쓸 수 없고 앞 원소를 반복할 뿐이다. 와일드카드 버전은 별도 문제(LeetCode 44)이고 마지막에 비교한다.

## abbd에 패턴을 손으로 맞춰 보기

예시로 `s = "abbd"`, `p = "x*ab*.d"`를 쓴다. 패턴을 원소 단위로 끊으면 다섯 조각이다.

```text
x*   a   b*   .   d
```

하나씩 맞춰 본다.

```text
x*  → x를 0번 쓴다 (s에 x가 없다)
a   → a
b*  → b를 몇 번?
.   → 아무 글자 하나
d   → d
```

`b*`가 몇 개를 먹느냐가 갈림길이다. 두 개를 다 먹으면 `.`이 `d`를 먹고, 마지막 `d`가 맞출 글자가 없어 실패한다. 하나만 먹으면 `.`이 두 번째 `b`를 먹고 `d`가 `d`와 맞아 성공이다. 0개를 먹으면 `.`이 첫 번째 `b`, `d`가 두 번째 `b`와 비교돼 실패한다. 답은 `true`이고, 맞는 방법은 "`b*`가 b 하나"뿐이다.

여기서 보이는 건 `*`의 선택이 뒤의 성공 여부를 바꾼다는 것이다. "가능한 한 많이 먹는다"로 정해 버리면 이 예시에서 틀린다. 그렇다고 모든 개수를 시도하면 `*`가 여러 개일 때 경우의 수가 곱으로 늘어난다.

## 내장 정규식으로 끝내면 안 되는 이유

JavaScript에는 정규식 엔진이 있으니 한 줄로 풀린다.

```js
function isMatch(s, p) {
  return new RegExp("^(?:" + p + ")$").test(s); // 양 끝을 묶어 전체가 맞는지 본다
}
console.log(isMatch("abbd", "x*ab*.d"), isMatch("ab", "a")); // true false
```

LeetCode는 통과하지만 면접에서는 "직접 구현해 보세요"로 바로 넘어간다. 이 문제의 목적이 엔진 내부를 짜 보는 것이라서다. 이 한 줄도 쓸모는 있다. 아래에서 짠 풀이들을 무작위 입력 2만 쌍으로 이 함수와 비교했다.

내장 엔진을 쓸 때 알아 둘 것도 있다. JavaScript, Python, Java의 표준 정규식은 대부분 백트래킹 방식이라 특정 패턴에서 입력 길이에 지수적으로 느려진다. 별 안에 별이 있는 패턴으로 재 봤다.

```js
const re = /^(a*)*c$/;               // 별 안에 별: 백트래킹 엔진이 약한 모양
for (const n of [22, 24, 26, 28]) {
  const s = "a".repeat(n) + "b";     // 끝이 c가 아니라 결국 실패한다
  const t = performance.now();
  re.test(s);
  console.log(n + 1, "글자", Math.round(performance.now() - t), "ms");
}
```

```text
23 글자 403 ms
25 글자 191 ms
27 글자 774 ms
29 글자 3406 ms
```

첫 줄은 엔진이 정규식을 준비하는 시간이 섞여 들쑥날쑥하지만, 그 뒤로는 두 글자 늘 때마다 네 배씩 늘어난다. 서른 글자 남짓한 문자열 하나로 서버가 몇 초씩 멈춘다. 사용자 입력에 이런 정규식을 돌리면 그게 곧 ReDoS(정규식 서비스 거부) 공격이 된다. 이 문제의 패턴 문법에는 괄호가 없어서 이렇게까지 나빠지지는 않지만, 같은 종류의 폭발이 다음 절의 재귀에서도 나온다.

## 별 앞에서 두 갈래로 나뉘는 재귀

`go(i, j)`를 "`s[i..]`와 `p[j..]`가 전체로 맞나"로 둔다. 패턴의 다음 원소를 본다.

- 패턴이 끝났으면 문자열도 끝났어야 맞는다.
- 지금 글자가 맞는지 먼저 구해 둔다. `first = i < s.length && (p[j] === s[i] || p[j] === ".")`.
- 다음 칸이 `*`이면 두 갈래다. `x*`를 0번 쓰고 넘어가거나(`go(i, j + 2)`), 지금 글자가 맞으면 하나 먹고 같은 `x*`에 머문다(`go(i + 1, j)`).
- `*`가 아니면 지금 글자가 맞아야 하고, 둘 다 한 칸씩 간다(`go(i + 1, j + 1)`).

```js
function isMatch(s, p) {
  function go(i, j) {
    if (j === p.length) return i === s.length;                    // 패턴 끝: 문자열도 끝나야 한다
    const first = i < s.length && (p[j] === s[i] || p[j] === "."); // 지금 글자가 맞나
    if (j + 1 < p.length && p[j + 1] === "*")
      return go(i, j + 2)                // x*를 0번 쓰고 넘어간다
        || (first && go(i + 1, j));      // 글자 하나를 먹고 x*에 머문다
    return first && go(i + 1, j + 1);    // 보통 글자나 . 하나
  }
  return go(0, 0);
}
console.log(isMatch("abbd", "x*ab*.d")); // true
```

`*`에서 "몇 개 먹을지"를 한 번에 정하지 않고, "하나 먹고 다시 묻기"로 바꾼 것이 요령이다. 이렇게 하면 갈래가 늘 둘뿐이라 코드가 짧다.

문자열이 빈 쪽은 바닥으로 따로 처리하지 않았다는 데 주목한다. `i === s.length`여도 패턴이 `c*`처럼 남아 있으면 `go(i, j + 2)`로 0번 쓰고 넘어갈 수 있어서 계속 진행해야 한다. "문자열이 끝나면 false"로 끝내 버리면 `("a", "ab*")`를 놓친다.

얼마나 느린지 잰다. 실패하는 입력이 가장 나쁘다. 성공하면 `||`가 일찍 끝내지만 실패하면 모든 갈래를 다 본다.

```text
s 20글자, p "a*" 9개 + "c" (19글자)   호출 16,921,904번    308 ms
s 31글자, 같은 패턴                    호출 485,354,011번   8422 ms
```

제약 안의 입력에서도 호출이 1700만 번이다. `a*`가 아홉 개면 a 19개를 아홉 묶음으로 나누는 모든 방법을 시도하기 때문이다. a 19개를 아홉 묶음으로 나누는 방법만 해도 C(27, 8) = 2,220,075가지이고, 문자열과 별이 늘면 지수적으로 커진다. 그런데 이 1700만 번의 호출에서 서로 다른 `(i, j)`는 21 × 20개뿐이다. 같은 질문을 수만 번씩 반복하고 있다.

## 같은 (i, j)는 한 번만 묻는다

메모 표를 붙인다. 답이 `true`/`false`라서 "모름"은 `undefined`로 둔다. `false`를 표시로 쓰면 실패한 칸을 매번 다시 계산하는데, 이 문제에서 느린 건 정확히 그 실패한 칸들이다.

```js
function isMatch(s, p) {
  const m = s.length, n = p.length;
  const memo = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(undefined)); // undefined = 모름
  function go(i, j) {
    if (memo[i][j] !== undefined) return memo[i][j];
    let res;
    if (j === n) res = i === m;
    else {
      const first = i < m && (p[j] === s[i] || p[j] === ".");
      if (j + 1 < n && p[j + 1] === "*") res = go(i, j + 2) || (first && go(i + 1, j));
      else res = first && go(i + 1, j + 1);
    }
    return (memo[i][j] = res);
  }
  return go(0, 0);
}
```

`i`가 `m`까지 갈 수 있어서 표를 `(m + 1) × (n + 1)`로 만들었다. 문자열이 끝났는데 패턴이 남은 상태도 진짜 상태다.

시간은 칸 `(m+1)(n+1)`개를 한 번씩 계산하고 칸마다 O(1)이라 O(mn)이다. 공간은 O(mn)에 재귀 깊이 O(m + n)이다. 길이 20이면 깊이 40쯤이라 어느 언어에서도 문제없다. 면접에서 가장 빨리 맞게 쓸 수 있는 답이 이것이다. 재귀가 문제 정의를 그대로 따라가서 설명하기도 쉽다.

## 별 칸은 윗줄의 같은 열을 본다

바텀업은 방향을 뒤집어 `dp[i][j]`를 "`s`의 앞 i글자와 `p`의 앞 j글자가 맞나"로 둔다. `p[j-1]`이 지금 보는 패턴 글자다.

- `dp[0][0] = true`. 빈 문자열과 빈 패턴은 맞는다.
- 0번 줄(빈 문자열): `p[j-1]`이 `*`이면 `dp[0][j] = dp[0][j-2]`. `x*`를 0번 쓰면 빈 문자열과 맞으니 그 앞까지가 맞았는지를 따른다. `"x*"`, `"x*y*"`가 빈 문자열과 맞는 이유다.
- 보통 글자나 `.`: 글자가 맞고 `dp[i-1][j-1]`이 참이면 참.
- `*`: 두 가지 중 하나면 참이다.
  - `x*`를 0번 쓴다: `dp[i][j-2]`
  - `x`가 `s[i-1]`과 맞고, `s`의 앞 i-1글자가 이미 같은 `x*`까지와 맞았다: `dp[i-1][j]`

마지막 줄이 이 문제의 고비다. `dp[i-1][j]`는 "`x*`가 이미 몇 개를 먹은 상태에서 하나를 더 먹는다"는 뜻이다. 열은 그대로 j라서 같은 `x*`가 계속 쓰인다. 하나 먹을 때마다 한 줄씩 내려가니, 별이 먹는 개수가 몇이든 따로 반복문을 돌릴 필요가 없다.

```js
function isMatch(s, p) {
  const m = s.length, n = p.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(false));
  dp[0][0] = true;                                       // 빈 문자열과 빈 패턴
  for (let j = 2; j <= n; j++)
    if (p[j - 1] === "*") dp[0][j] = dp[0][j - 2];       // x*를 0번 써서 빈 문자열에 맞춘다
  for (let i = 1; i <= m; i++)
    for (let j = 1; j <= n; j++) {
      if (p[j - 1] === "*") {
        const prevMatches = p[j - 2] === s[i - 1] || p[j - 2] === ".";
        dp[i][j] = dp[i][j - 2]                          // x*를 0번
          || (prevMatches && dp[i - 1][j]);              // x가 s[i-1]을 하나 더 먹는다
      } else {
        const match = p[j - 1] === s[i - 1] || p[j - 1] === ".";
        dp[i][j] = match && dp[i - 1][j - 1];            // 한 글자씩 맞춘다
      }
    }
  return dp[m][n];
}
```

`abbd`와 `x*ab*.d`의 표를 찍으면 이렇다. T가 참이다.

```text
     ε x * a b * . d
ε    T . T . . . . .
a    . . . T . T . .
b    . . . . T T T .
b    . . . . . T T .
d    . . . . . . T T
```

0번 줄의 `*` 칸이 T인 건 `x*`가 빈 문자열과 맞아서다. a 줄 `*`(`b*`의 끝) 칸이 T인 건 `"a"`가 `"x*ab*"`와 맞는다는 뜻이다(b를 0번). 첫 b 줄의 `.` 칸은 `"ab"`와 `"x*ab*."`가 맞는다는 것이고, 마지막 d 줄의 끝 칸이 답 T다.

시간 O(mn), 공간 O(mn)이다.

## 두 줄이면 된다

`dp[i][j]`가 쓰는 칸은 같은 줄의 `dp[i][j-2]`, 윗줄의 `dp[i-1][j]`와 `dp[i-1][j-1]`이다. 윗줄과 이번 줄 두 개만 있으면 된다.

```js
function isMatch(s, p) {
  const n = p.length;
  let prev = new Array(n + 1).fill(false);              // 윗줄 (처음엔 빈 문자열 줄)
  prev[0] = true;
  for (let j = 2; j <= n; j++) if (p[j - 1] === "*") prev[j] = prev[j - 2];
  for (let i = 1; i <= s.length; i++) {
    const cur = new Array(n + 1).fill(false);           // 이번 줄. cur[0]은 늘 false
    for (let j = 1; j <= n; j++) {
      if (p[j - 1] === "*")
        cur[j] = cur[j - 2] || ((p[j - 2] === s[i - 1] || p[j - 2] === ".") && prev[j]);
      else
        cur[j] = (p[j - 1] === s[i - 1] || p[j - 1] === ".") && prev[j - 1];
    }
    prev = cur;
  }
  return prev[n];
}
```

공간이 O(n)이다. 배열 하나로 더 줄이려면 왼쪽 위 값을 변수에 들고 가야 하는데, 같은 줄의 `j-2` 칸은 이미 이번 줄 값이어야 하니 LCS보다 신경 쓸 곳이 많다. 길이가 20인 문제에서 그만한 가치는 없다. `cur[0]`이 늘 `false`인 이유도 확인해 둔다. 빈 패턴은 비어 있지 않은 문자열과 맞을 수 없다.

## 지금 서 있을 수 있는 자리를 모두 들고 간다

전혀 다른 생각도 있다. 패턴을 원소 단위로 끊어 칸 번호를 매긴다. abbd 예시라면 `x*`가 0번, `a`가 1번, `b*`가 2번, `.`이 3번, `d`가 4번, 끝이 5번이다. 문자열을 한 글자씩 읽으며 "지금 패턴의 어느 칸에 서 있을 수 있나"의 집합을 들고 간다.

- 별 칸에 서 있으면 그 칸을 건너뛴 다음 칸에도 서 있을 수 있다(0번 쓰기). 이렇게 공짜로 퍼지는 걸 닫힘(closure)이라고 부른다.
- 글자 하나를 읽으면, 그 글자와 맞는 칸에서 다음 자리로 옮긴다. 별 칸이면 제자리에 머물고, 보통 칸이면 한 칸 앞으로 간다.
- 다 읽었을 때 끝 칸이 집합에 있으면 맞는다.

이것이 정규식을 비결정 유한 오토마톤(NFA)으로 보고 모든 갈래를 동시에 진행하는 Thompson 방식이다. 백트래킹은 갈래를 하나씩 끝까지 가 보고 되돌아오지만, 이 방식은 모든 갈래를 한 글자씩 나란히 민다. 같은 칸에 두 갈래가 도착하면 집합이라 하나로 합쳐진다. 메모이제이션이 같은 `(i, j)`를 한 번만 계산하는 것과 같은 효과다.

```js
function isMatch(s, p) {
  const toks = [];                                   // 패턴을 원소 단위로: { c, star }
  for (let j = 0; j < p.length; j++) {
    if (p[j + 1] === "*") { toks.push({ c: p[j], star: true }); j++; }
    else toks.push({ c: p[j], star: false });
  }
  const k = toks.length;                             // k번 칸 = 패턴 끝
  function closure(set) {                            // 별 칸은 건너뛸 수 있다 (0번 쓰기)
    const stack = [...set];
    while (stack.length) {
      const t = stack.pop();
      if (t < k && toks[t].star && !set.has(t + 1)) { set.add(t + 1); stack.push(t + 1); }
    }
    return set;
  }
  let cur = closure(new Set([0]));
  for (const ch of s) {
    const next = new Set();
    for (const t of cur) {
      if (t === k) continue;                         // 패턴이 끝난 자리에서는 더 못 먹는다
      const { c, star } = toks[t];
      if (c === ch || c === ".") next.add(star ? t : t + 1); // 별은 제자리, 보통 칸은 다음 칸
    }
    cur = closure(next);
    if (cur.size === 0) return false;                // 서 있을 자리가 없으면 끝
  }
  return cur.has(k);
}
console.log(isMatch("abbd", "x*ab*.d")); // true
```

아래 그림은 abbd를 읽는 동안 서 있을 수 있는 칸의 집합이다. 초록 칸이 지금 서 있을 수 있는 자리다.

## Python과 Java의 바텀업

```python
class Solution:
    def isMatch(self, s: str, p: str) -> bool:
        m, n = len(s), len(p)
        dp = [[False] * (n + 1) for _ in range(m + 1)]
        dp[0][0] = True                              # 빈 문자열과 빈 패턴
        for j in range(2, n + 1):
            if p[j - 1] == "*":
                dp[0][j] = dp[0][j - 2]              # x*를 0번 써서 빈 문자열에 맞춘다
        for i in range(1, m + 1):
            for j in range(1, n + 1):
                if p[j - 1] == "*":
                    prev_ok = p[j - 2] in (s[i - 1], ".")
                    dp[i][j] = dp[i][j - 2] or (prev_ok and dp[i - 1][j])
                else:
                    ok = p[j - 1] in (s[i - 1], ".")
                    dp[i][j] = ok and dp[i - 1][j - 1]
        return dp[m][n]

s = Solution()
print(s.isMatch("abbd", "x*ab*.d"), s.isMatch("ab", ".*"), s.isMatch("ab", "a"), s.isMatch("", "c*"))
```

`p[j - 2] in (s[i - 1], ".")`는 "같거나 점이거나"를 한 번에 쓴 것이다. 표를 `[[False] * (n + 1)] * (m + 1)`로 만들면 모든 줄이 같은 리스트라 한 칸을 바꾸면 전부 바뀐다. 줄마다 새 리스트를 만든다. 탑다운으로 쓴다면 `functools.cache`를 붙인 재귀가 짧고, 이 제약에서는 재귀 깊이도 40 안쪽이다.

```java
class Solution {
    public boolean isMatch(String s, String p) {
        int m = s.length(), n = p.length();
        boolean[][] dp = new boolean[m + 1][n + 1];   // 기본값 false
        dp[0][0] = true;
        for (int j = 2; j <= n; j++)
            if (p.charAt(j - 1) == '*') dp[0][j] = dp[0][j - 2];
        for (int i = 1; i <= m; i++) {
            char sc = s.charAt(i - 1);
            for (int j = 1; j <= n; j++) {
                char pc = p.charAt(j - 1);
                if (pc == '*') {
                    char before = p.charAt(j - 2);
                    dp[i][j] = dp[i][j - 2] || ((before == sc || before == '.') && dp[i - 1][j]);
                } else {
                    dp[i][j] = (pc == sc || pc == '.') && dp[i - 1][j - 1];
                }
            }
        }
        return dp[m][n];
    }

    public static void main(String[] args) {
        Solution s = new Solution();
        System.out.println(s.isMatch("abbd", "x*ab*.d") + " " + s.isMatch("ab", ".*") + " " + s.isMatch("ab", "a") + " " + s.isMatch("", "c*"));
    }
}
```

```text
true true false true
```

Java의 `boolean` 배열은 기본값이 `false`라 초기화가 필요 없다. 탑다운으로 쓸 때는 `boolean[][]`로는 "모름"을 나타낼 수 없으니 `Boolean[][]`(기본값 `null`)을 쓴다. `p.charAt(j - 2)`는 `*`가 맨 앞에 오지 않는다는 약속 덕분에 안전하다. 그 약속이 없는 입력이라면 `j >= 2`를 먼저 확인한다.

## 별에서 자주 틀리는 곳

### 별이 가능한 만큼 다 먹게 하는 경우

되돌아가지 않는 그리디로 짜면 틀린다.

```js
function greedyMatch(s, p) {
  let i = 0, j = 0;
  while (j < p.length) {
    const c = p[j], star = p[j + 1] === "*";
    if (star) {
      while (i < s.length && (c === "." || s[i] === c)) i++; // 되돌아오지 않는다
      j += 2;
    } else {
      if (i >= s.length || (c !== "." && s[i] !== c)) return false;
      i++; j++;
    }
  }
  return i === s.length;
}
console.log(greedyMatch("aaa", "a*a"), greedyMatch("abbd", "x*ab*.d"), greedyMatch("ab", ".*b")); // false false false
```

세 개 모두 답은 `true`다. `a*`가 a 세 개를 다 먹어 마지막 `a`가 맞출 글자가 없다. `.*`는 특히 위험하다. 모든 글자를 먹어 버리니 뒤에 무엇이 오든 실패한다. 별이 먹는 개수를 "가장 많이"나 "가장 적게" 중 하나로 정하면 반례가 늘 있다.

### 빈 문자열 줄을 안 채우는 경우

`dp[0][j]`를 `dp[0][0]`만 참으로 두고 끝내면, 패턴 앞쪽의 `x*`가 빈 부분과 맞는 경우를 모두 놓친다. `("", "c*")`, `("b", "a*b")`, 그리고 예시 `("abbd", "x*ab*.d")`까지 셋 다 `false`가 나온다. 예시가 틀리는 이유는 맨 앞 `x*`가 s의 아무것도 먹지 않아야 하기 때문이다. 패턴이 별로 시작하는 테스트를 꼭 넣는다.

### 별이 하나만 먹게 쓰는 경우

`*`의 둘째 경우를 `dp[i-1][j]` 대신 `dp[i-1][j-2]`로 쓰면 "x를 정확히 한 번"이 된다. 열이 j-2로 넘어가 버려서 같은 별을 다시 쓸 수 없다. `("abd", "ab*d")`는 맞히지만 `("abbbd", "ab*d")`는 `false`가 나온다. 예시 abbd는 `b*`가 하나만 먹는 게 답이라 이 버그를 통과해 버린다. 별이 여러 개를 먹어야 하는 테스트도 함께 둔다.

### 지금 글자 비교를 빼먹는 경우

`*` 분기에서 `dp[i-1][j]`만 보고 `p[j-2]`가 `s[i-1]`과 맞는지 확인하지 않으면, 별이 아무 글자나 먹는다. `a*`가 b도 먹어 `("b", "a*")`가 `true`가 된다. 점(`.`)일 때만 아무 글자나 먹을 수 있다.

### 부분 일치로 착각하는 경우

내장 정규식을 검증용으로 쓸 때 `^`와 `$`를 빼먹으면 `/x*ab*.d/.test("zzabbdzz")`처럼 부분 일치로 `true`가 나온다. 이 문제는 전체 일치다. 또 `"^" + p + "$"`로만 붙이면 패턴에 `|`가 있을 때 뜻이 바뀌니 `(?:…)`로 감싸는 버릇을 들인다(이 문제의 패턴에는 `|`가 없다).

## 패턴 문법이 바뀌면

### 와일드카드 매칭

LeetCode 44. Wildcard Matching은 파일 이름 패턴처럼 `?`가 아무 글자 하나, `*`가 아무 문자열(빈 문자열 포함)이다. `*`가 앞 글자에 묶이지 않으니 점화식이 오히려 단순하다. `*`에서 "0글자 먹기" `dp[i][j-1]`와 "한 글자 더 먹기" `dp[i-1][j]` 중 하나면 된다.

```js
function isWildcardMatch(s, p) {
  const m = s.length, n = p.length;
  let prev = new Array(n + 1).fill(false);
  prev[0] = true;
  for (let j = 1; j <= n; j++) prev[j] = prev[j - 1] && p[j - 1] === "*"; // 앞이 모두 *면 빈 문자열과 맞는다
  for (let i = 1; i <= m; i++) {
    const cur = new Array(n + 1).fill(false);
    for (let j = 1; j <= n; j++) {
      if (p[j - 1] === "*") cur[j] = cur[j - 1] || prev[j];   // 0글자 먹기 || 한 글자 더 먹기
      else cur[j] = (p[j - 1] === "?" || p[j - 1] === s[i - 1]) && prev[j - 1];
    }
    prev = cur;
  }
  return prev[n];
}
console.log(isWildcardMatch("report.log", "*.log"), isWildcardMatch("abbd", "a*?d"), isWildcardMatch("ab", "*a")); // true true false
```

정규식 버전과 나란히 놓으면 `*`의 "0번"이 정규식은 `j-2`(앞 글자까지 지움), 와일드카드는 `j-1`(별만 지움)이라는 차이가 한눈에 보인다. 와일드카드는 표 대신 "마지막 별 위치를 기억해 두고 실패하면 거기로 돌아가는" 투 포인터 그리디로도 풀리는데, 정규식 버전은 별이 앞 글자에 묶여 그 방법이 통하지 않는다.

### +와 ?를 더하면

`x+`는 `xx*`로, `x?`는 "0번 또는 1번"으로 바꿔 생각하면 같은 표에 들어간다. `x?`의 칸은 `dp[i][j-2] || (맞으면 dp[i-1][j-2])`다. 별과 달리 열이 j-2로 넘어가서 한 번만 먹는다. 앞의 "별이 하나만 먹는 버그"가 바로 `?`의 올바른 점화식인 셈이다.

### 괄호와 선택(|)까지 넣으면

이제는 표 하나로 안 된다. 실제 엔진처럼 패턴을 먼저 파싱해 NFA를 만들고 앞 절의 상태 집합 시뮬레이션을 돌리는 게 정석이다. 백트래킹 엔진은 이 지점에서 `(a*)*` 같은 패턴에 지수 시간을 쓰게 되고, 그게 앞에서 본 ReDoS다. 사용자 입력에 정규식을 돌리는 서버라면 RE2 계열 엔진을 쓰거나, 입력 길이와 실행 시간에 상한을 둔다. Node.js에서는 `re2` 패키지가 RE2를 감싼 것이다.

### 같은 표 위의 다른 문제들

두 문자열을 가로세로에 놓고 "마지막 원소를 어떻게 처리했나"로 나누는 틀은 [Edit Distance](/posts/leetcode-edit-distance), [Longest Common Subsequence](/posts/leetcode-longest-common-subsequence), [Distinct Subsequences](/posts/leetcode-distinct-subsequences), [Interleaving String](/posts/leetcode-interleaving-string)과 같다. 이 문제가 특별한 건 별 칸이 같은 열의 윗줄(`dp[i-1][j]`)을 써서 "한 원소가 여러 글자를 먹는" 상황을 한 칸씩 쪼갠다는 점뿐이다. 문자열 대신 단어 목록으로 쪼개는 [Word Break](/posts/leetcode-word-break)도 같은 "앞부분이 맞았나"를 묻는 DP다.

## 면접에서 나올 만한 질문

### 점화식을 설명해 보세요

`dp[i][j]`는 s의 앞 i글자와 p의 앞 j글자가 전체로 맞는지다. 보통 글자나 점이면 그 글자가 맞고 `dp[i-1][j-1]`이 참이어야 한다. `*`이면 `x*`를 0번 쓰는 `dp[i][j-2]`, 또는 x가 s의 i번째 글자와 맞고 `dp[i-1][j]`가 참인 경우다. 바닥은 `dp[0][0] = true`이고, 빈 문자열 줄은 `x*`를 0번 써서 `dp[0][j] = dp[0][j-2]`로 채운다.

### 별 칸에서 왜 dp[i-1][j-2]가 아니라 dp[i-1][j]인가요?

같은 `x*`를 계속 쓸 수 있어야 하기 때문이다. `dp[i-1][j]`는 "앞 i-1글자가 이미 이 `x*`까지와 맞았다"는 뜻이라, 거기서 x 하나를 더 먹어도 여전히 같은 별에 있다. 이걸 줄마다 반복하면 별이 몇 개를 먹든 표현된다. `j-2`로 쓰면 정확히 한 번만 먹는 `x?`가 되어 `("abbbd", "ab*d")`를 놓친다.

### 그냥 재귀로 풀면 왜 느린가요?

별마다 "0번 쓰기"와 "하나 먹고 머물기" 두 갈래로 나뉘고, 실패하는 입력에서는 모든 갈래를 끝까지 본다. `a*`가 아홉 개인 패턴과 a 19개 뒤에 b가 붙은 문자열에서 호출이 1700만 번이었다. 서로 다른 `(i, j)`는 420개 정도인데 같은 질문을 반복한 것이라 메모만 붙이면 O(mn)이 된다.

### 공간을 줄일 수 있나요?

각 칸이 같은 줄의 `j-2`와 윗줄의 `j`, `j-1`만 쓰니 두 줄, O(n)으로 줄인다. NFA 시뮬레이션으로 보면 패턴 원소 수만큼의 상태 집합만 들고 가니 O(k)다. 이 문제는 길이가 20이라 실익은 작지만, 같은 원리가 긴 로그를 한 번에 훑는 실제 엔진에서 쓰인다.

### 언어 내장 정규식을 쓰면 안 되나요? 실무에서는 무엇을 조심하나요?

문제 의도가 엔진 구현이라 면접 답으로는 안 되고, 검증용으로만 쓴다. 실무에서는 JavaScript, Java, Python의 기본 엔진이 백트래킹이라 `(a*)*c` 같은 패턴에 실패하는 입력을 주면 길이에 지수적으로 느려진다. 29글자 문자열에서 3초가 넘었다. 사용자 입력을 받는 곳이면 패턴을 단순하게 유지하고, RE2처럼 선형 시간을 보장하는 엔진을 쓰거나 실행 시간에 상한을 둔다.

### 와일드카드 매칭과는 무엇이 다른가요?

와일드카드의 `*`는 혼자서 아무 문자열이고, 정규식의 `*`는 앞 원소를 반복한다. 그래서 "0번"이 와일드카드는 `dp[i][j-1]`(별만 지움), 정규식은 `dp[i][j-2]`(앞 글자와 별을 함께 지움)이다. 와일드카드는 마지막 별 위치로 되돌아가는 그리디로도 풀리지만, 정규식은 별이 특정 글자에 묶여 있어 그 방법이 통하지 않는다.

### NFA 방식은 표 DP와 어떤 관계인가요?

같은 계산을 다른 순서로 하는 것이다. 표의 i번째 줄에서 참인 칸들이 곧 "i글자를 읽은 뒤 서 있을 수 있는 패턴 위치"의 집합이다. NFA 시뮬레이션은 그 줄 하나만 집합으로 들고 다니며 다음 줄을 만든다. 입력을 앞에서부터 한 번만 읽고 되돌아가지 않아 스트림에도 쓸 수 있고, 실제 선형 시간 엔진(RE2, Go `regexp`)의 원리다.
