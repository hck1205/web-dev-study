<EasyIntro>
  골목에 집이 한 줄로 늘어서 있고, 집마다 든 사탕 수가 다른 사탕 상자가 하나씩 있다. 붙어 있는 두 집을 연달아 열면 경보가 울리니, 사탕을 가장 많이 모으려면 어느 집들을 골라야 할까. 가장 많이 든 집부터 고르면 될 것 같지만, 가운데 집에 4개, 양옆에 3개씩 있으면 4개짜리를 고르는 순간 양옆을 둘 다 못 열어서 양옆을 고른 6개보다 적다. 그래서 골목 앞에서부터 한 집씩 걸어가며 공책에 적는다. 이 집을 지나치면 바로 앞 집까지 모은 최고 기록이 그대로 남고, 열면 두 집 앞까지의 최고 기록에 이 집 사탕을 더한다. 둘 중 큰 쪽이 지금까지의 최고 기록이다. 공책에는 앞의 두 기록만 있으면 되니, 숫자 두 개를 들고 골목 끝까지 걸어가면 답이 나온다.
</EasyIntro>

[House Robber](https://leetcode.com/problems/house-robber/)는 LeetCode 198번이다. [계단 오르기](/posts/leetcode-climbing-stairs)가 "방법의 수를 더하는" DP였다면, 이 문제는 처음으로 "고를지 말지 정하고 더 큰 쪽을 남기는" DP다. 점화식 한 줄과 변수 두 개로 끝나지만, 면접에서는 "왜 탐욕으로 안 되나", "어느 집을 털었는지도 알려 달라", "집이 원형이면?", "트리 모양이면?"이 이어진다. 이 글은 틀리는 탐욕 두 가지부터 보고, 모든 조합을 다 보는 풀이에서 O(1) 공간 풀이까지 일곱 가지를 차례로 놓는다.

DP를 처음 본다면 [동적 계획법 글](/posts/dynamic-programming)에서 상태 정의와 탑다운·바텀업의 차이를 먼저 보는 게 좋다. 탐욕이 언제 통하고 언제 무너지는지는 [그리디 알고리즘 글](/posts/greedy-algorithms)에서 다뤘다. 코드는 Node.js 22, Python 3, Java 21에서 직접 돌렸다.

## 붙어 있는 두 집은 함께 고를 수 없다

음이 아닌 정수 배열 `nums`가 주어진다. `nums[i]`는 i번째 집에 있는 돈이다. 서로 이웃한 두 칸(인덱스 차이가 1)을 함께 고르지 않으면서 고른 칸의 합을 최대로 만든다. 그 최댓값을 돌려준다. 아무 집도 안 고르는 것도 허용되니 답은 최소 0이다.

제약은 길이 1 이상 100 이하, 값 0 이상 400 이하다. 길이가 100이라 모든 조합(2^100)은 당연히 안 되고, O(n)이나 O(n²)이면 넉넉하다. 합의 최댓값은 100 × 400 = 40,000이라 어떤 언어에서도 정수 범위 걱정은 없다. 값이 음수가 아니라는 조건은 뒤에서 탐욕과 초기값을 이야기할 때 다시 쓴다.

## 일곱 집을 손으로 골라 본다

글 끝까지 쓸 예시다.

```text
인덱스   0   1   2   3   4   5   6
nums     4   1   2   7   5   3   1
```

큰 수에 먼저 눈이 간다. 7(3번)을 고르면 2와 5를 못 쓴다. 4(0번)는 7과 떨어져 있으니 함께 고를 수 있고, 7 오른쪽으로 하나 건너 3(5번)도 된다. 4 + 7 + 3 = 14. 다른 조합을 몇 개 대 보자.

```text
0, 2, 4, 6   → 4 + 2 + 5 + 1 = 12
0, 3, 5      → 4 + 7 + 3     = 14
0, 3, 6      → 4 + 7 + 1     = 12
1, 3, 5      → 1 + 7 + 3     = 11
0, 2, 4      → 4 + 2 + 5     = 11
```

답은 14다. 그런데 이걸 "다 대 보지 않고" 확신하려면 규칙이 필요하다. 사람이 무의식적으로 쓰는 탐욕부터 시험해 본다.

## 탐욕으로 고르면 틀린다

### 짝수 칸 합과 홀수 칸 합 중 큰 쪽

하나씩 건너뛰면 이웃 조건은 자동으로 지켜지니, 0, 2, 4…번 합과 1, 3, 5…번 합 중 큰 쪽을 고르는 방법이 먼저 떠오른다. 예시에서는 짝수 칸 4 + 2 + 5 + 1 = 12, 홀수 칸 1 + 7 + 3 = 11이라 12를 낸다. 답은 14다. 4 + 7 + 3처럼 두 칸을 건너뛰는(0번 다음 3번) 선택을 못 하기 때문이다. 더 짧은 반례는 `[2, 1, 1, 2]`다. 짝수 칸 3, 홀수 칸 3인데 양 끝을 고르면 4다.

### 가장 큰 집부터 고르기

남은 집 중 가장 큰 것을 고르고 그 이웃을 지우는 방법도 틀린다. `[3, 4, 3]`이면 4를 먼저 골라 양옆이 막혀서 4로 끝나지만, 양 끝 3 + 3 = 6이 답이다. 실제로 돌려 보면 `[2, 3, 2]`는 3(답 4), `[5, 6, 5, 1]`은 7(답 10)을 낸다.

두 탐욕 모두 "지금 좋은 선택이 나중의 더 좋은 선택을 막는" 경우를 못 본다. 한 집을 고르면 이웃이 막히니, 지금의 선택이 뒤의 선택지를 바꾼다. 이렇게 선택끼리 얽혀 있으면 지금 시점의 최선만 보는 탐욕은 보장을 잃는다. 그래서 모든 경우를 따지되, 같은 계산은 반복하지 않는 방향으로 간다.

## 모든 조합을 다 대 본다

집마다 고르거나 안 고르거나 두 가지라 조합은 2ⁿ개다. 비트마스크로 모두 만들고, 이웃한 두 비트가 함께 켜진 조합은 건너뛴다.

```js
function rob(nums) {
  const n = nums.length;
  let best = 0;
  for (let mask = 0; mask < (1 << n); mask++) {
    if (mask & (mask >> 1)) continue;        // 붙어 있는 두 비트가 켜졌다 = 이웃 두 집
    let sum = 0;
    for (let i = 0; i < n; i++) if ((mask >> i) & 1) sum += nums[i];
    best = Math.max(best, sum);
  }
  return best;
}
```

`mask & (mask >> 1)`은 마스크를 한 칸 민 것과 겹치는 비트가 있는지 본다. 겹치면 i번과 i+1번이 둘 다 켜져 있다는 뜻이다. 비트 연산은 [비트 조작 글](/posts/bit-manipulation)에 정리했다.

시간 O(2ⁿ × n), 공간 O(1)이다. n이 20이면 2천만 번 남짓으로 돌지만, JavaScript의 `1 << n`은 32비트라 n이 31을 넘으면 그 자체로 틀린다. 길이 100은 어림도 없다. 이 풀이는 뒤의 빠른 풀이를 검증하는 정답 생성기로 쓴다. 실제로 길이 1~12인 무작위 배열 2000개에서 이 풀이와 뒤의 DP 풀이들의 답이 모두 같았다.

조합 대부분은 이웃 조건 때문에 버려진다. 처음부터 조건을 지키는 조합만 만들면 훨씬 줄어든다.

## 이 집을 열까, 지나칠까

앞에서부터 집을 하나씩 보며 결정을 내린다고 하자. i번째 집 앞에서 선택은 둘이다.

- 지나친다. 그러면 i+1번째 집부터 다시 같은 질문을 한다.
- 연다. `nums[i]`를 얻고, i+1번은 이웃이라 건너뛰고 i+2번부터 같은 질문을 한다.

`best(i)`를 "i번째 집부터 끝까지에서 얻을 수 있는 최댓값"이라 정하면

```text
best(i) = max(best(i + 1), nums[i] + best(i + 2))
best(i) = 0   (i ≥ n, 남은 집이 없다)
```

```js
function rob(nums) {
  function best(i) {
    if (i >= nums.length) return 0;               // 남은 집이 없다
    return Math.max(best(i + 1), nums[i] + best(i + 2)); // 지나친다 vs 연다
  }
  return best(0);
}
```

이제 이웃 조건을 어기는 조합은 아예 만들어지지 않는다. 그래도 호출 나무는 계단 오르기와 똑같은 모양(i+1과 i+2로 갈라짐)이라 시간은 O(φⁿ)이다. 길이 30에서 호출이 435만 번이었다. 서로 다른 질문은 `best(0)`부터 `best(n)`까지 n+1개뿐인데, 같은 i를 여러 번 묻는다. [계단 오르기](/posts/leetcode-climbing-stairs)에서 본 그 문제다.

## 같은 집에서 다시 묻지 않게 적어 둔다

`best(i)`의 답을 한 번 구하면 배열에 적는다. 값이 0 이상이라 "아직 안 구함"은 -1로 표시한다.

```js
function rob(nums) {
  const memo = new Array(nums.length).fill(-1); // -1: 아직 안 구함
  function best(i) {
    if (i >= nums.length) return 0;
    if (memo[i] !== -1) return memo[i];
    memo[i] = Math.max(best(i + 1), nums[i] + best(i + 2));
    return memo[i];
  }
  return best(0);
}
```

i마다 본문이 한 번만 실행되니 시간 O(n), 공간은 장부 O(n)과 콜 스택 O(n)이다. 여기서 "안 구함"을 0으로 표시하면 미묘하게 느려진다. 모든 값이 0인 구간(`[0, 0, 0, …]`)은 답이 0이라, 구해 놓고도 "안 구함"으로 읽혀 매번 다시 계산하기 때문이다. 답은 맞는데 그 구간에서 지수 시간으로 돌아간다. 0을 "안 구함"으로 쓴 버전에 0이 25개인 배열을 넣었더니 호출이 392,835번이었고, 1이 25개인 배열에서는 51번이었다. 답이 될 수 없는 값(-1)이나 `undefined`로 표시해야 한다.

## 마지막으로 연 집을 기준으로 센다

상태를 다르게 잡는 길도 있다. "i번 집을 반드시 열고 거기서 끝나는 최댓값"을 `end[i]`라 하자. i번을 열었다면 그 직전에 연 집은 i-2번 이하 어딘가다(i-1번은 이웃이라 안 된다). 직전에 연 집이 없을 수도 있다. 그러면

```text
end[i] = nums[i] + max(0, end[0], end[1], …, end[i-2])
답 = end 전체의 최댓값
```

"끝나는 칸을 상태로 두고, 그 앞의 모든 칸을 훑는다"는 이 모양은 [최장 증가 부분 수열](/posts/leetcode-longest-increasing-subsequence)의 O(n²) 풀이와 같은 뼈대다. 처음 DP를 세울 때 이쪽이 더 먼저 떠오르는 사람도 많다.

```js
function rob(nums) {
  const n = nums.length;
  const end = new Array(n).fill(0); // end[i]: i번 집을 열고 끝나는 최댓값
  let best = 0;
  for (let i = 0; i < n; i++) {
    let before = 0;                              // 직전에 연 집이 없는 경우
    for (let j = 0; j <= i - 2; j++) before = Math.max(before, end[j]);
    end[i] = nums[i] + before;
    best = Math.max(best, end[i]);
  }
  return best;
}
```

예시에서 `end`는 `[4, 1, 6, 11, 11, 14, 12]`가 되고 최댓값 14가 답이다. 6번 집(1원)을 열고 끝나면 12라 마지막 칸이 답이 아니다. 이 상태 정의에서는 답이 마지막 칸이 아니라 전체 최댓값이다. 앞의 풀이와 달라지는 부분이라 놓치기 쉽다.

시간 O(n²), 공간 O(n)이다. 안쪽 반복문이 `end[0]`부터 `end[i-2]`까지의 최댓값을 매번 다시 구하는데, 이 값은 i가 하나 늘 때 `end[i-2]` 하나만 새로 들어온다. 누적 최댓값을 변수 하나로 들고 다니면 안쪽 반복문이 사라져 O(n)이 되고, 그걸 정리하면 결국 다음 절의 표와 같은 식이 나온다. "i번까지의 최댓값"으로 상태를 잡으면 이 누적 최댓값이 상태 안에 이미 들어 있기 때문이다.

## 앞에서부터 표를 채운다

재귀 방향을 뒤집어 앞에서부터 채운다. 이번에는 "앞에서부터 몇 집까지"로 상태를 다시 정한다. `dp[i]`는 "앞의 i개 집(0번부터 i-1번)만 볼 때의 최댓값"이다. 크기를 n+1로 두고 `dp[0] = 0`(집이 하나도 없다)부터 시작하면 경계 처리가 사라진다.

```text
dp[0] = 0
dp[1] = nums[0]
dp[i] = max(dp[i - 1], dp[i - 2] + nums[i - 1])
         지나친다      i-1번 집을 연다
```

```js
function rob(nums) {
  const n = nums.length;
  const dp = new Array(n + 1).fill(0); // dp[i]: 앞의 i개 집에서의 최댓값
  dp[1] = nums[0];
  for (let i = 2; i <= n; i++) {
    dp[i] = Math.max(dp[i - 1], dp[i - 2] + nums[i - 1]);
  }
  return dp[n];
}
```

예시로 표가 채워지는 과정이다. 칸 위의 숫자는 그 집의 돈이고, 기억 칸에 쌓이는 것은 그 집까지 본 최댓값이다.

4번 집에서 "지나친다"와 "연다"가 똑같이 11이 나온 게 눈에 띈다. 0, 2, 4번(4 + 2 + 5)과 0, 3번(4 + 7)이 같은 합이라서다. 최댓값만 묻는다면 어느 쪽이든 상관없다.

이 식이 정말 최댓값을 내는지 따져 보자. 앞의 i개 집에서 고른 최적의 조합을 하나 생각하면, 그 조합은 i-1번 집을 쓰거나 안 쓴다. 안 쓰면 그 조합은 앞의 i-1개 집 안의 조합이니 `dp[i-1]`보다 클 수 없다. 쓰면 i-2번은 못 쓰니 나머지는 앞의 i-2개 집 안의 조합이고, 그 부분도 최적이어야 한다(더 좋은 부분 조합이 있으면 바꿔 끼워 전체가 더 커지니까). 그래서 `dp[i-2] + nums[i-1]`보다 클 수 없다. 두 경우 중 큰 쪽이 곧 최적이다. 큰 문제의 최적해가 작은 문제의 최적해로 이루어지는 이 성질을 최적 부분 구조라고 부른다.

시간 O(n), 공간 O(n)이다. 표를 남겨 두면 좋은 점이 하나 있다. 어느 집을 열었는지 되짚을 수 있다.

### 어느 집을 열었는지 되짚기

끝에서부터 거꾸로 걷는다. `dp[i]`가 `dp[i-1]`과 같으면 i-1번 집을 지나친 것이니 한 칸 앞으로 간다. 다르면 i-1번 집을 연 것이니 기록하고 두 칸 앞으로 간다.

```js
function robWithHouses(nums) {
  const n = nums.length;
  const dp = new Array(n + 1).fill(0);
  dp[1] = nums[0];
  for (let i = 2; i <= n; i++) dp[i] = Math.max(dp[i - 1], dp[i - 2] + nums[i - 1]);

  const picked = [];
  let i = n;
  while (i >= 1) {
    if (i === 1 || dp[i] !== dp[i - 1]) { // i-1번 집을 열어야 이 값이 나온다
      picked.push(i - 1);
      i -= 2;                             // 이웃은 건너뛴다
    } else {
      i -= 1;                             // 지나쳤다
    }
  }
  return { total: dp[n], houses: picked.reverse() };
}
```

## 기록 두 개만 들고 골목을 걷는다

점화식은 `dp[i-1]`과 `dp[i-2]` 두 칸만 본다. 표 전체가 필요 없으면(최댓값만 물으면) 변수 두 개로 충분하다. 이 풀이가 기본 답이다.

```js
function rob(nums) {
  let prev = 0; // 두 집 앞까지의 최댓값 (dp[i-2])
  let cur = 0;  // 바로 앞 집까지의 최댓값 (dp[i-1])
  for (const x of nums) {
    const next = Math.max(cur, prev + x); // 지나친다 vs 연다
    prev = cur;
    cur = next;
  }
  return cur;
}
```

`prev`와 `cur`를 0으로 시작하면 "집이 없는 골목" 두 칸을 앞에 붙인 셈이라 첫 집과 둘째 집을 따로 처리할 필요가 없다. 길이 1이면 `max(0, 0 + nums[0])`, 길이 2면 `max(nums[0], 0 + nums[1])`이 자연스럽게 나온다.

두 변수가 움직이는 모습이다. 다음을 누르면 집 하나씩 지나간다.

이 풀이에서 `cur`가 "바로 앞 집을 열었는지"를 기억하지 않는다는 점이 처음엔 이상하게 보인다. 바로 앞 집을 열었을지도 모르는데 어떻게 `prev + x`로 이 집을 여나? `prev`는 두 집 앞까지의 최댓값이라 바로 앞 집은 절대 포함하지 않는다. 바로 앞 집을 열었을 가능성은 `cur` 쪽에만 있고, `prev + x`는 처음부터 그 집을 빼고 계산한다. 그래서 이웃 조건이 자동으로 지켜진다.

## 열었다와 안 열었다를 따로 들고 다니기

같은 문제를 다르게 볼 수도 있다. 집마다 두 상태를 따로 기록한다.

- `take`: 지금 집을 연 경우의 최댓값
- `skip`: 지금 집을 안 연 경우의 최댓값

지금 집을 열려면 바로 앞 집은 안 열었어야 하니 `take = skip(앞) + x`다. 지금 집을 안 열면 앞 집은 열었든 안 열었든 상관없으니 `skip = max(take(앞), skip(앞))`이다.

```js
function rob(nums) {
  let take = 0; // 지금 집을 연 경우의 최댓값
  let skip = 0; // 지금 집을 안 연 경우의 최댓값
  for (const x of nums) {
    const newTake = skip + x;             // 앞 집은 안 열었어야 한다
    const newSkip = Math.max(skip, take); // 앞 집은 아무래도 된다
    take = newTake;
    skip = newSkip;
  }
  return Math.max(take, skip);
}
```

예시에서 두 값은 이렇게 움직인다.

```text
x 4 take 4 skip 0
x 1 take 1 skip 4
x 2 take 6 skip 4
x 7 take 11 skip 6
x 5 take 11 skip 11
x 3 take 14 skip 11
x 1 take 12 skip 14
```

마지막에 `max(12, 14) = 14`다. 복잡도는 앞 풀이와 같다. 그런데도 이 모양을 따로 보여 주는 이유는 변형 문제에서 강하기 때문이다. "이 집을 열었는가"가 상태로 드러나 있어서, 트리 모양 골목(337번)에서는 노드마다 `[take, skip]` 쌍을 돌려주면 되고, 주식 매매에 쿨다운이 붙는 문제([Best Time to Buy and Sell Stock with Cooldown](/posts/leetcode-stock-with-cooldown))도 "보유 / 방금 팜 / 쉼" 같은 상태 몇 개를 들고 다니는 같은 방식으로 푼다. 상태가 둘을 넘어가는 문제에서 두 변수 풀이로는 표현이 안 되고, 이 상태 기계 모양이 필요해진다.

## Python과 Java로 옮길 때

```python
from typing import List

class Solution:
    def rob(self, nums: List[int]) -> int:
        prev, cur = 0, 0              # 두 집 앞까지, 바로 앞 집까지의 최댓값
        for x in nums:
            prev, cur = cur, max(cur, prev + x)
        return cur
```

동시 대입이라 오른쪽의 `prev`와 `cur`는 모두 바뀌기 전 값이다. 예시 입력에 14, `[5]`에 5, `[2, 1, 1, 2]`에 4가 나왔다. 탑다운으로 쓴다면 `@functools.cache`를 붙인 내부 함수가 가장 짧은데, 길이가 100이라 재귀 한도 1000에는 걸리지 않는다.

```java
class Solution {
    public int rob(int[] nums) {
        int prev = 0, cur = 0;            // 두 집 앞까지, 바로 앞 집까지의 최댓값
        for (int x : nums) {
            int next = Math.max(cur, prev + x); // 안 연다 vs 연다
            prev = cur;
            cur = next;
        }
        return cur;
    }
}
```

합의 최댓값이 40,000이라 `int`로 충분하다. 값의 범위가 커져서 합이 21억을 넘을 수 있으면 `long`으로 바꾼다. 세 언어 모두 차이가 거의 없는 문제라, 언어보다는 초기값과 갱신 순서를 맞게 쓰는 게 관건이다.

## 틀리기 쉬운 자리

### dp[1]을 nums[1]로 두는 경우

0부터 시작하는 표를 `dp[0] = nums[0]`, `dp[1] = nums[1]`로 시작하는 코드가 흔하다.

```js
function rob(nums) {
  if (nums.length === 1) return nums[0];
  const dp = [nums[0], nums[1]];          // dp[1]을 nums[1]로 둔 게 실수
  for (let i = 2; i < nums.length; i++) dp[i] = Math.max(dp[i - 1], dp[i - 2] + nums[i]);
  return dp[nums.length - 1];
}
```

`dp[1]`은 "1번 집까지 봤을 때의 최댓값"이라 `max(nums[0], nums[1])`이어야 한다. 이 코드에 `[5, 1]`을 넣으면 1, `[2, 1, 1, 2]`를 넣으면 3이 나온다(답은 5와 4). 표의 칸 하나가 무엇을 뜻하는지 문장으로 적어 두면 이런 실수가 줄어든다. 앞에서처럼 크기 n+1 표에 `dp[0] = 0`을 두거나, 두 변수를 0으로 시작하면 이 경계가 아예 없다.

### 길이 1과 길이 2를 따로 처리하다 빠뜨리는 경우

`nums[1]`을 읽는 코드는 길이 1에서 `undefined`(JavaScript)나 예외(Java, Python)를 낸다. 두 변수를 0으로 시작하는 풀이는 길이 1에서도 반복문을 한 번 돌고 끝나서 특별 처리가 필요 없다.

### 메모의 "안 구함"을 0으로 두는 경우

앞에서 짚었다. 값이 0인 집이 길게 이어지면 메모가 듣지 않는다. 답은 맞으니 테스트에서 잘 안 잡힌다.

### 정답을 짝수·홀수 합으로 내는 경우

`[2, 1, 1, 2]`에서 3을 낸다. 두 칸 건너뛰는 선택이 필요하다. 이 문제는 입력이 작은 반례로 탐욕을 깨 보는 연습으로도 좋다.

## 면접관이 조건을 바꾸면

### 집이 원형으로 놓여 있다면

첫 집과 마지막 집도 이웃이 된다. [House Robber II](/posts/leetcode-house-robber-ii)다. 첫 집과 마지막 집을 둘 다 열 수는 없으니 "첫 집을 뺀 줄"과 "마지막 집을 뺀 줄"로 나눠 원래 풀이를 두 번 돌리고 큰 쪽을 고른다. `[2, 3, 2]`면 3, 이 글의 예시를 원형으로 놓으면 0번과 6번이 이웃이 되지만 원래 답 0, 3, 5번은 6번을 안 써서 그대로 14다. 길이 1이면 두 줄이 모두 비어 0이 되니 따로 `nums[0]`을 돌려줘야 한다.

### 집이 트리 모양이라면

LeetCode 337 House Robber III다. 부모와 자식을 함께 못 연다. 노드마다 `[이 노드를 연 경우, 안 연 경우]`를 후위 순회로 돌려준다. 연 경우는 `노드 값 + 두 자식의 안 연 경우`, 안 연 경우는 `두 자식 각각의 max(연, 안 연)` 합이다. 앞의 take / skip 풀이를 나무에 그대로 옮긴 모양이고 O(n)이다. 트리를 재귀로 도는 법은 [이진 트리 글](/posts/ds-binary-tree-bst)에 있다.

```js
function robTree(root) {
  // 노드마다 [이 노드를 연 경우, 안 연 경우]를 돌려준다 (후위 순회)
  function go(node) {
    if (!node) return [0, 0];
    const [lt, ls] = go(node.left);
    const [rt, rs] = go(node.right);
    const take = node.val + ls + rs;                  // 열면 자식은 못 연다
    const skip = Math.max(lt, ls) + Math.max(rt, rs); // 안 열면 자식은 마음대로
    return [take, skip];
  }
  return Math.max(...go(root));
}
```

레벨 순서 `[4, 9, 2, null, 3, 6, 1]`로 만든 나무(뿌리 4, 왼쪽 자식 9, 오른쪽 자식 2, 그 아래 3, 6, 1)에서 16이 나왔다. 9와 손자 6, 1을 고른 값이다. 뿌리를 열면 4 + 3 + 6 + 1 = 14라 더 작다. 노드마다 두 값을 돌려주지 않고 "이 노드부터의 최댓값" 하나만 메모하면 손자까지 내려가 봐야 해서 코드가 길어지고, 메모 없이 쓰면 같은 노드를 여러 번 방문한다.

### 적어도 k집을 털면서 가장 비싼 집을 최소로 하라면

LeetCode 2560 House Robber IV다. 이번에는 합이 아니라 "고른 집 중 최댓값"을 최소로 만든다. 답이 될 값 x를 하나 정하면 "x 이하인 집만으로 이웃 없이 k집 이상 고를 수 있나"는 앞에서부터 되는 대로 고르는 탐욕으로 O(n)에 판정되고, x가 커질수록 판정이 참이 되기 쉬우니 x를 [이분 탐색](/posts/binary-search)한다. 같은 이름이지만 DP보다 "답을 정해 놓고 가능한지 묻는" 쪽으로 푸는 문제다.

### 같은 값을 고르면 이웃 값이 모두 사라진다면

LeetCode 740 Delete and Earn이다. 숫자 x를 고르면 x-1과 x+1이 모두 지워진다. 값별로 총점을 모아 `points[x] = x × (x의 개수)` 배열을 만들면, 인덱스가 붙은 두 값을 함께 못 고르는 House Robber가 된다. `[2, 2, 3, 3, 3, 4]`면 points가 `[0, 0, 4, 9, 4]`가 되고 답은 9다. 문제를 아는 모양으로 바꾸는 연습으로 좋다.

### 최소 k칸 떨어져야 한다면

i번을 열면 i-k+1부터 i-1까지 못 연다. `dp[i] = max(dp[i-1], dp[i-k] + nums[i-1])`가 되고, 변수 두 개 대신 최근 k개를 원형 버퍼로 들고 있다. k = 2가 원래 문제다.

### 값이 음수일 수도 있다면

음수 집은 열 이유가 없고, "지나친다" 쪽이 항상 이기니 점화식은 그대로 맞는다. 다만 "적어도 한 집은 열어야 한다"는 조건이 붙으면 모두 음수일 때 0이 아니라 가장 덜 음수인 값을 내야 해서 초기값을 `-Infinity`로 바꾼다.

비슷한 문제로는 [House Robber II](/posts/leetcode-house-robber-ii), House Robber III(337), Delete and Earn(740), Maximum Sum of Non-Adjacent Elements 계열이 있고, "고르면 다음을 못 고른다"는 뼈대는 [Best Time to Buy and Sell Stock with Cooldown](/posts/leetcode-stock-with-cooldown)에서 상태가 셋으로 늘어난 모습으로 다시 나온다.

## 면접에서 나올 만한 질문

### 왜 탐욕으로는 안 되나요?

한 집을 고르면 이웃이 막혀서 지금의 선택이 뒤의 선택지를 바꾸기 때문이다. 가장 큰 집부터 고르면 `[3, 4, 3]`에서 4를 내고(답 6), 짝수·홀수 칸 합 중 큰 쪽을 고르면 `[2, 1, 1, 2]`에서 3을 낸다(답 4). 두 칸 이상 건너뛰는 선택까지 따져야 해서 DP로 푼다.

### 점화식을 어떻게 세웠나요?

i번째 집 앞에서 선택이 둘뿐이라는 데서 출발했다. 지나치면 i-1번 집까지의 최댓값이 그대로 남고, 열면 이웃을 뺀 i-2번 집까지의 최댓값에 이 집 돈을 더한다. 그래서 `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`다. 표의 칸이 "i번 집까지 봤을 때의 최댓값"이라는 걸 먼저 문장으로 정해야 바닥값을 틀리지 않는다.

### 공간을 O(1)로 줄일 수 있나요?

있다. 점화식이 앞의 두 칸만 보니 변수 두 개를 0으로 시작해 한 집씩 밀면 된다. 0으로 시작하면 집이 없는 칸 두 개를 앞에 붙인 셈이라 길이 1, 2를 따로 처리하지 않아도 된다. 대신 어느 집을 열었는지는 되짚을 수 없다.

### 어느 집을 털었는지도 알려 달라면요?

표를 남겨 두고 끝에서 거꾸로 걷는다. `dp[i]`가 `dp[i-1]`과 같으면 그 집을 지나친 것이고, 다르면 연 것이라 기록하고 두 칸 앞으로 간다. 동점일 때 어느 쪽을 고를지 정해야 하고, O(1) 공간 풀이로는 이 정보가 남지 않으니 O(n) 공간이 든다.

### 집이 원형이면 어떻게 바꾸나요?

첫 집과 마지막 집을 동시에 열 수 없으니 둘 중 하나를 빼고 일직선 문제를 두 번 푼다. 첫 집을 뺀 경우와 마지막 집을 뺀 경우 중 큰 값이 답이다. 길이 1일 때 두 경우가 모두 빈 배열이 되므로 그 경우만 따로 처리한다.

### 이 풀이가 스트림에서도 동작하나요?

동작한다. 두 변수 풀이는 배열을 앞에서 뒤로 한 번만 읽고 앞의 두 기록만 들고 있으니, 값이 하나씩 들어올 때마다 갱신하면 그 시점까지의 최댓값을 늘 알고 있다. 메모리는 입력 길이와 상관없이 상수다.
