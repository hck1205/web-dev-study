"abba"를 회문 조각으로만 잘라 보라고 하면 대부분 "abba" 통째로 하나와 "a, b, b, a"로 한 글자씩 자른 것을 먼저 떠올린다. 하나가 더 있다. "a, bb, a"다. 손으로 찾으면 이렇게 하나씩 빠뜨리기 쉽다. 빠짐없이 찾는 순서를 정하는 게 이 문제의 일이다.

[LeetCode 131. Palindrome Partitioning](https://leetcode.com/problems/palindrome-partitioning/)이 그 문제다. 백트래킹 패턴에서 [Subsets](/posts/leetcode-subsets)나 [Combination Sum](/posts/leetcode-combination-sum)이 "원소를 고르는" 문제였다면, 이건 "문자열을 자르는" 문제다. 고르는 대신 자르는 위치를 정할 뿐, 시작 위치를 넘기며 고르고 들어가고 되돌리는 틀은 같다. 그 틀은 [재귀와 백트래킹 글](/posts/recursion-backtracking)에 있다. 여기에 "이 조각이 회문인가"를 얼마나 빨리 답하느냐가 더해지고, 그 부분에서 [동적 계획법](/posts/dynamic-programming)이 들어온다. 이 글은 자를 틈을 비트로 고르는 풀이부터, 회문 표를 미리 만드는 풀이, 가운데에서 넓히는 풀이, 뒤쪽 답을 먼저 쌓는 풀이까지 다섯 가지를 비교한다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 모든 조각이 회문이 되게 자르는 방법

문자열 `s`가 주어진다. `s`를 이어진 조각 여러 개로 나누되, 모든 조각이 회문(앞뒤로 읽어도 같은 문자열)이어야 한다. 이렇게 나누는 방법을 모두 돌려준다. 조각의 순서는 원래 문자열 순서 그대로이고, 답의 순서는 상관없다.

제약은 이렇다.

- 길이는 1 이상 16 이하다. 자를 수 있는 틈이 15개뿐이라 자르는 방법은 최대 2^15 = 32,768가지다.
- 영어 소문자만 나온다.

길이 16이 작아 보이지만 출력이 커질 수 있다. "aaaa…a"(a 16개)는 어떻게 잘라도 모든 조각이 회문이라 답이 32,768개다. 그래서 이 문제의 시간 복잡도는 출력 크기에 묶인다. 빠른 풀이란 답이 아닌 갈래에 시간을 덜 쓰고, 회문 확인을 덜 반복하는 풀이다.

## "abba"를 손으로 잘라 보면

자를 수 있는 틈은 글자 사이 세 곳이다. `a|b|b|a`처럼 세 곳을 다 자르면 한 글자씩, 하나도 안 자르면 통째다. 틈마다 자르거나 말거나 두 가지라 자르는 방법은 2^3 = 8가지다. 하나씩 적고 조각이 모두 회문인지 보자.

```text
a|b|b|a   a, b, b, a      모두 회문     답
a|b|ba    a, b, ba        ba가 아님
a|bb|a    a, bb, a        모두 회문     답
a|bba     a, bba          bba가 아님
ab|b|a    ab, b, a        ab가 아님
ab|ba     ab, ba          둘 다 아님
abb|a     abb, a          abb가 아님
abba      abba            회문          답
```

답은 세 개다. 이렇게 적으면 빠뜨리지는 않지만, 8가지를 다 만든 뒤에 확인했다. 확인을 앞당길 수 있다. 첫 조각이 "ab"인 순간 이미 실패인데, 위 표에서는 "ab"로 시작하는 두 가지를 다 만들어 봤다.

그래서 순서를 바꾼다. 왼쪽 끝에서 첫 조각을 정하는데, 회문인 것만 고른다. "abba"의 첫 조각 후보는 "a", "ab", "abb", "abba"이고 그중 회문은 "a"와 "abba"다. "a"를 떼면 남은 "bba"를 같은 방법으로 자른다. "abba"를 떼면 남은 게 없으니 그 자체로 답이다. 남은 문자열이 원래 문제보다 짧은 같은 문제라 재귀가 된다.

## 자를 틈마다 자를지 말지 정하기

손으로 적은 표를 그대로 코드로 옮긴 풀이다. 틈 n - 1개에 비트 하나씩을 주고, 0부터 2^(n-1) - 1까지 세면서 켜진 비트 자리에서 자른다. 조각마다 양 끝에서 가운데로 글자를 비교해 회문인지 본다. 비트를 다루는 법은 [비트 조작 글](/posts/bit-manipulation)에 있다.

```js
function isPal(s, l, r) {        // s[l..r]이 회문인가
  while (l < r) {
    if (s[l] !== s[r]) return false;
    l++;
    r--;
  }
  return true;
}

function partition(s) {
  const n = s.length;
  const res = [];
  for (let mask = 0; mask < (1 << (n - 1)); mask++) { // 틈 n-1개의 자르기 여부
    const parts = [];
    let start = 0;
    let ok = true;
    for (let i = 0; i < n; i++) {
      // i번 틈(s[i]와 s[i+1] 사이)을 자르거나, 마지막 글자라면 조각을 끝낸다
      if (i === n - 1 || (mask & (1 << i))) {
        if (!isPal(s, start, i)) { ok = false; break; }
        parts.push(s.slice(start, i + 1));
        start = i + 1;
      }
    }
    if (ok) res.push(parts);
  }
  return res;
}
```

`"abba"`에서 세 답이 나온다. 회문이 아닌 조각을 만나면 그 mask의 나머지는 보지 않고 넘어간다.

자르는 방법이 2^(n-1)가지이고 하나마다 글자 n개를 훑으니 시간은 O(n · 2^n)이다. 문제는 답이 적어도 이 시간을 다 쓴다는 것이다. "abcdefghijklmnop"처럼 글자가 모두 다르면 답은 한 글자씩 자른 하나뿐인데, 32,768개 mask를 다 셌다. 첫 조각 "ab"가 실패해도 "ab"로 시작하는 mask 수천 개를 하나씩 다시 시도한다. 실패한 앞부분을 공유하는 mask들을 한꺼번에 버리려면 앞에서부터 조각을 정해 나가는 탐색이 필요하다.

## 앞에서 회문 조각을 하나 떼고 나머지를 맡긴다

재귀 함수 `go(start)`는 "`s[start..]`를 회문 조각으로 자르는 모든 방법"을 찾는다. 첫 조각의 끝 `end`를 `start`부터 하나씩 늘려 보며, `s[start..end]`가 회문이면 그 조각을 `path`에 넣고 `go(end + 1)`로 나머지를 맡긴다. `start`가 끝에 닿으면 `path`가 답 하나다.

"abba"에서 이 탐색이 어떻게 갈라지는지 그림으로 보자. 점선은 회문이 아니라 들어가지 않은 갈래다.

"ab"와 "abb"에서 바로 멈췄기 때문에 그 아래는 펼치지 않는다. 앞 풀이에서 mask 여러 개로 나눠 다시 시도하던 부분이다.

```js
function partition(s) {
  const res = [];
  const path = [];

  function go(start) {
    if (start === s.length) {        // 끝까지 잘랐다
      res.push([...path]);
      return;
    }
    for (let end = start; end < s.length; end++) {
      if (!isPal(s, start, end)) continue; // 회문이 아닌 첫 조각은 들어가지 않는다
      path.push(s.slice(start, end + 1));  // slice의 끝은 포함하지 않으니 end + 1
      go(end + 1);                         // 나머지를 같은 방법으로 자른다
      path.pop();                          // 되돌린다
    }
  }

  go(0);
  return res;
}
```

결과는 `[["a","b","b","a"],["a","bb","a"],["abba"]]`이다. 첫 조각을 짧은 것부터 시도해서 한 글자씩 자른 답이 먼저 나온다.

여기서 continue가 맞고 break가 아니다. [Combination Sum](/posts/leetcode-combination-sum)에서는 정렬된 후보가 넘치면 뒤도 다 넘치니 break했다. 회문은 그런 성질이 없다. "ab"가 회문이 아니어도 "abba"는 회문이다. 첫 조각을 늘리다 실패해도 더 늘리면 다시 회문이 될 수 있다.

이 풀이의 남은 낭비는 회문 확인이다. "aaaa…a"(a 16개)에서 `isPal`이 글자를 비교한 횟수를 세어 보니 43,682번이었다. `go(5)`, `go(6)` 같은 같은 호출이 앞쪽 자르는 방법마다 다시 불리고, 그때마다 "s[5..9]가 회문인가"를 처음부터 다시 비교한다. 서로 다른 조각은 n(n+1)/2 = 136개뿐인데 같은 질문을 수백 번씩 반복하는 셈이다.

## 회문인지를 미리 표로 만들어 둔다

조각 `s[i..j]`가 회문인지는 두 가지로 정해진다. 양 끝 글자 `s[i]`와 `s[j]`가 같고, 안쪽 `s[i+1..j-1]`이 회문이면 된다. 안쪽이 비었거나 한 글자면(`j - i < 2`) 양 끝만 같으면 된다. 짧은 조각의 답으로 긴 조각의 답을 만드니 표 하나로 채울 수 있다.

```js
pal[i][j] = s[i] === s[j] && (j - i < 2 || pal[i + 1][j - 1]);
```

"abba"로 채운 표다. T가 회문이고, 행이 시작 i, 열이 끝 j다.

```text
     j=0 1 2 3
i=0    T . . T     a, abba
i=1      T T .     b, bb
i=2        T .     b
i=3          T     a
```

`pal[0][3]`을 보려면 `pal[1][2]`가 먼저 있어야 한다. i가 큰 행이 먼저 채워져 있어야 하니 i를 뒤에서부터 돈다. 이 방향은 아래 "표를 채우는 방향"에서 다시 본다.

표를 만든 뒤 백트래킹은 `isPal` 대신 `pal[start][end]`를 본다.

```js
function partition(s) {
  const n = s.length;
  // pal[i][j]: s[i..j]가 회문인가. i를 뒤에서부터 채워야 pal[i+1][j-1]이 먼저 준비된다
  const pal = Array.from({ length: n }, () => new Array(n).fill(false));
  for (let i = n - 1; i >= 0; i--) {
    for (let j = i; j < n; j++) {
      pal[i][j] = s[i] === s[j] && (j - i < 2 || pal[i + 1][j - 1]);
    }
  }

  const res = [];
  const path = [];
  function go(start) {
    if (start === n) {
      res.push([...path]);
      return;
    }
    for (let end = start; end < n; end++) {
      if (!pal[start][end]) continue;      // 표에서 O(1)로 확인
      path.push(s.slice(start, end + 1));
      go(end + 1);
      path.pop();
    }
  }

  go(0);
  return res;
}
```

"abba"에서 `path`가 쌓이고 빠지는 모습이다. 초록 칸이 지금까지 잘라 낸 부분이고, 기억 장소가 잘라 낸 조각들이다.

표를 만드는 데 O(n²) 시간과 공간이 들고, 그 뒤로는 회문 확인이 한 번에 끝난다. 탐색 자체는 답이 2^(n-1)개까지 나올 수 있고 답마다 길이 n의 조각을 복사하니 O(n · 2^n)이다. 앞 풀이도 같은 O(n · 2^n)이라고 말할 수 있지만, 확인 비용이 빠진 만큼 "aaaa…a"(a 16개)에서 11.8ms가 3.3ms로 줄었다. 추가 공간은 표 O(n²)와 재귀 깊이 O(n)이다. 면접에서 기대하는 답이 이 풀이다.

### 표를 채우는 방향

i를 앞에서부터 돌면 틀린다.

```js
for (let i = 0; i < n; i++)          // 앞에서부터
  for (let j = i; j < n; j++)
    pal[i][j] = s[i] === s[j] && (j - i < 2 || pal[i + 1][j - 1]);
```

"abba"에서 `pal[0][3]`을 채울 때 `pal[1][2]`는 아직 초깃값 false다. 그래서 "abba"가 회문이 아니라고 나왔다. "aaaa"와 "abcba"도 통째 조각을 놓쳤다. 에러가 나지 않고 답 하나만 빠지니 찾기 어렵다. 표를 채울 때는 "이 칸이 읽는 칸이 먼저 채워졌나"를 확인한다. `pal[i][j]`는 `pal[i+1][j-1]`, 곧 아래 행의 왼쪽 칸을 읽으니 아래 행부터 채운다. 길이 1인 조각, 길이 2인 조각 순으로 길이를 늘리며 채워도 된다.

### Python과 Java로 옮기면

Python은 슬라이스 `s[start:end + 1]`가 끝을 포함하지 않는다. 재귀 깊이는 많아야 n + 1 = 17이다. 표를 `[[False] * n] * n`으로 만들면 모든 행이 같은 리스트를 가리켜서 한 칸을 바꾸면 한 열이 통째로 바뀐다. 리스트 내포로 행마다 새로 만든다.

```python
from typing import List

def partition(s: str) -> List[List[str]]:
    n = len(s)
    # pal[i][j]: s[i..j]가 회문인가. i를 뒤에서부터 채워야 pal[i+1][j-1]이 먼저 준비된다
    pal = [[False] * n for _ in range(n)]
    for i in range(n - 1, -1, -1):
        for j in range(i, n):
            pal[i][j] = s[i] == s[j] and (j - i < 2 or pal[i + 1][j - 1])

    res, path = [], []

    def go(start: int) -> None:
        if start == n:
            res.append(path[:])
            return
        for end in range(start, n):
            if pal[start][end]:
                path.append(s[start:end + 1])
                go(end + 1)
                path.pop()

    go(0)
    return res
```

Java는 `substring(start, end + 1)`이고 역시 끝을 포함하지 않는다. `boolean[][]`은 false로 초기화된다.

```java
import java.util.*;

class Solution {
    public List<List<String>> partition(String s) {
        int n = s.length();
        boolean[][] pal = new boolean[n][n]; // pal[i][j]: s[i..j]가 회문인가
        for (int i = n - 1; i >= 0; i--) {
            for (int j = i; j < n; j++) {
                pal[i][j] = s.charAt(i) == s.charAt(j) && (j - i < 2 || pal[i + 1][j - 1]);
            }
        }
        List<List<String>> res = new ArrayList<>();
        go(s, 0, pal, new ArrayList<>(), res);
        return res;
    }

    private void go(String s, int start, boolean[][] pal, List<String> path, List<List<String>> res) {
        if (start == s.length()) {
            res.add(new ArrayList<>(path));
            return;
        }
        for (int end = start; end < s.length(); end++) {
            if (!pal[start][end]) continue;
            path.add(s.substring(start, end + 1)); // substring의 끝은 포함하지 않는다
            go(s, end + 1, pal, path, res);
            path.remove(path.size() - 1);
        }
    }
}
```

## 가운데에서 넓혀 가며 회문을 모은다

회문 표를 만드는 다른 방법이 있다. 회문은 가운데를 중심으로 양쪽이 대칭이다. 가운데를 하나 정하고 양쪽으로 한 칸씩 넓히면서 두 글자가 같은 동안 계속 회문이다. 가운데는 글자 위(홀수 길이 회문)와 글자 사이(짝수 길이 회문) 두 종류라 2n - 1곳이다. [Longest Palindromic Substring](/posts/leetcode-longest-palindromic-substring)에서 쓰는 방법과 같다.

넓히다가 찾은 회문 `s[l..r]`을 "l에서 시작하는 회문의 끝 목록" `ends[l]`에 넣어 두면, 백트래킹은 `ends[start]`에 있는 끝만 돌면 된다. 회문이 아닌 조각을 아예 시도하지 않는다.

```js
function partition(s) {
  const n = s.length;
  const ends = Array.from({ length: n }, () => []); // ends[l]: l에서 시작하는 회문의 끝들
  for (let c = 0; c < 2 * n - 1; c++) {
    let l = c >> 1;           // 짝수 c는 글자 위, 홀수 c는 글자 사이
    let r = l + (c & 1);
    while (l >= 0 && r < n && s[l] === s[r]) {
      ends[l].push(r);        // s[l..r]은 회문
      l--;
      r++;
    }
  }
  for (const e of ends) e.sort((a, b) => a - b); // 짧은 조각부터 시도하려고

  const res = [];
  const path = [];
  function go(start) {
    if (start === n) {
      res.push([...path]);
      return;
    }
    for (const end of ends[start]) {             // 회문인 끝만 돈다
      path.push(s.slice(start, end + 1));
      go(end + 1);
      path.pop();
    }
  }
  go(0);
  return res;
}
```

## 뒤쪽 답을 먼저 만들어 앞에 붙인다

백트래킹은 같은 `go(start)`를 여러 번 부른다. "aab…"에서 "a, a"로 자르든 "aa"로 자르든 남은 부분은 `go(2)`다. 그 결과를 기억해 두면 다시 탐색하지 않아도 된다. `memo[i]`를 "`s[i..]`를 자르는 모든 방법"으로 두고, 끝에서부터 채운다.

```js
function partition(s) {
  const n = s.length;
  const pal = Array.from({ length: n }, () => new Array(n).fill(false));
  for (let i = n - 1; i >= 0; i--)
    for (let j = i; j < n; j++) pal[i][j] = s[i] === s[j] && (j - i < 2 || pal[i + 1][j - 1]);

  const memo = new Array(n + 1);
  memo[n] = [[]];                          // 빈 문자열을 자르는 방법은 "아무것도 안 자름" 하나
  for (let i = n - 1; i >= 0; i--) {
    memo[i] = [];
    for (let j = i; j < n; j++) {
      if (!pal[i][j]) continue;
      const head = s.slice(i, j + 1);      // 첫 조각
      for (const rest of memo[j + 1]) {    // 나머지를 자르는 방법마다 앞에 붙인다
        memo[i].push([head, ...rest]);
      }
    }
  }
  return memo[0];
}
```

"abba"면 `memo[3] = [["a"]]`, `memo[2] = [["b","a"]]`, `memo[1] = [["b","b","a"],["bb","a"]]`, `memo[0]`이 세 답이다.

재귀가 없고 같은 부분 문제를 두 번 풀지 않는다. 그런데 빨라지지 않았다. "aaaa…a"(a 16개)에서 13.4ms로, 표 백트래킹(3.3ms)보다 네 배 느렸다. 기억해 둔 답을 앞에 붙일 때마다 `[head, ...rest]`로 배열을 통째로 새로 만들기 때문이다. 답의 개수가 지수적이면 그 답들을 기억해 두는 것 자체가 지수적인 메모리를 쓰고, `memo[1]`, `memo[2]`처럼 최종 답이 아닌 목록까지 다 만든다. 같은 부분 문제를 다시 푸는 비용보다 목록을 복사하는 비용이 크다.

이 풀이가 빛나는 건 답의 개수만 셀 때다. 목록 대신 개수를 기억하면 `count[i] = Σ count[j + 1]`(pal[i][j]가 참인 j마다)로 O(n²)이다. 뒤의 변형에서 다시 본다.

## 조각이 비어 나오거나 회문을 놓치는 코드

### slice의 끝을 하나 덜 넣기

`s.slice(start, end)`로 쓰면 `end` 글자가 빠진다. "abba"에서 `[["","","",""],["","b",""],["abb"]]`이 나왔다. 회문 확인은 `s[start..end]`로 하고 잘라 넣는 건 `s[start..end-1]`이라 둘이 어긋났다. 확인한 범위와 잘라 넣는 범위가 같은지 늘 맞춰 본다. JavaScript `slice`, Python 슬라이스, Java `substring` 모두 끝을 포함하지 않는다.

### 회문이 아니면 break

정렬된 후보 문제를 풀던 습관으로 "회문이 아니면 더 늘려도 안 되겠지" 하고 break를 쓰면 답이 빠진다. "abba"에서 "ab"가 실패한 순간 멈추니 통째 "abba"를 못 찾는다. 조각이 길어진다고 회문 여부가 한쪽으로만 바뀌지 않는다. 늘리다 실패해도 더 늘리면 다시 회문일 수 있다.

### 표를 앞에서부터 채우기

앞의 "표를 채우는 방향"에서 본 대로, i를 앞에서부터 돌면 `pal[i+1][j-1]`이 아직 false라 긴 회문을 놓친다. "abba", "noon", "abcba"처럼 통째가 회문인 입력을 테스트에 꼭 넣는다. "aab"만으로 시험하면 이 버그가 안 보인다.

### 복사 없이 기록하기

`res.push(path)`로 넣으면 모든 답이 같은 배열을 가리켜서 끝나고 보면 다 빈 배열이다. [Subsets](/posts/leetcode-subsets)에서 자세히 본 버그다.

### 최소 몇 번 잘라야 하나

LeetCode 132 Palindrome Partitioning II다. 모든 방법이 아니라 자르는 횟수의 최솟값만 묻는다. 목록을 만들면 지수 시간이라 시간 초과가 나고, 표에 기댄 DP로 바꾼다. `cut[j]`를 `s[0..j]`를 자르는 최소 횟수로 두면, `s[0..j]` 자체가 회문이면 0이고 아니면 `pal[i][j]`가 참인 i마다 `cut[i-1] + 1`의 최솟값이다.

```js
function minCut(s) {
  const n = s.length;
  const pal = Array.from({ length: n }, () => new Array(n).fill(false));
  for (let i = n - 1; i >= 0; i--)
    for (let j = i; j < n; j++) pal[i][j] = s[i] === s[j] && (j - i < 2 || pal[i + 1][j - 1]);
  const cut = new Array(n).fill(0);
  for (let j = 0; j < n; j++) {
    if (pal[0][j]) continue;             // 통째로 회문이면 0번
    cut[j] = j;                          // 한 글자씩 자르면 j번
    for (let i = 1; i <= j; i++) {
      if (pal[i][j]) cut[j] = Math.min(cut[j], cut[i - 1] + 1); // 마지막 조각이 s[i..j]
    }
  }
  return cut[n - 1];
}
```

"abba"는 0, "aab"는 1, "abcde"는 4, "noonabbad"는 2("noon", "abba", "d")가 나왔다. O(n²)이라 길이 2000에서도 금방 끝난다.

### 방법의 개수만 달라면

뒤쪽 답을 쌓는 풀이에서 목록 대신 개수를 쌓는다. `count[n] = 1`로 두고 i를 뒤에서부터, `pal[i][j]`가 참인 j마다 `count[i] += count[j + 1]`이다. "abba"는 3, a 16개는 32,768, "aabbaabbaabbaabb"는 864가 나왔다. 백트래킹 결과의 길이와 같다. 문자열이 길어 개수가 2^53을 넘을 수 있으면 JavaScript는 `BigInt`, Java는 `long`이나 나머지 연산을 쓴다.

### 정확히 세 조각으로 나눌 수 있나

LeetCode 1745 Palindrome Partitioning IV다. 회문 표만 있으면 첫 조각의 끝 i와 둘째 조각의 끝 j를 두 겹으로 돌며 `pal[0][i] && pal[i+1][j] && pal[j+1][n-1]`을 확인한다. O(n²)이다.

## 해시태그를 단어로 나누는 코드와 같은 모양

회문 분할 자체를 서비스에서 쓸 일은 드물다. 그런데 이 코드에서 회문 확인 한 줄만 바꾸면 띄어쓰기 없는 해시태그를 단어로 나누는 코드가 된다.

```js
function splitWords(s, dict) {
  const words = new Set(dict);
  const res = [], path = [];
  function go(start) {
    if (start === s.length) { res.push(path.join(" ")); return; }
    for (let end = start; end < s.length; end++) {
      const w = s.slice(start, end + 1);
      if (!words.has(w)) continue;   // 회문 검사 자리에 사전 검사
      path.push(w); go(end + 1); path.pop();
    }
  }
  go(0);
  return res;
}
```

검색 색인이나 태그 분석에서 이런 후보를 만든 뒤 가장 그럴듯한 하나를 고른다. 이때도 이 글에서 본 판단이 그대로 쓰인다. 후보가 지수적으로 늘 수 있으니 전부 만들기 전에 개수부터 세 보고, 같은 위치에서 다시 시작하는 계산은 표나 메모로 기억해 둔다. 실제로 가장 그럴듯한 하나만 필요하면 목록을 만들지 않고, 최소 자르기처럼 점수를 DP로 고른다.

## 앞 조각을 떼고, 회문 확인은 표에서

회문 분할은 문자열의 왼쪽 끝에서 회문인 첫 조각을 하나 떼고, 남은 문자열을 같은 방법으로 자르는 백트래킹이다. 회문이 아닌 첫 조각에서 멈추니 실패할 갈래를 펼치지 않는다. 같은 조각의 회문 확인이 수없이 반복되니 `pal[i][j] = s[i] === s[j] && pal[i+1][j-1]`로 표를 미리 만들어 O(1)로 답한다. 표는 i를 뒤에서부터 채운다. 답의 개수가 지수적이라 전체 시간은 O(n · 2^n)이고, 개수나 최소 자르기만 묻는다면 목록을 버리고 같은 표 위에서 O(n²) DP로 바꾼다.

## 면접에서 나올 만한 질문

### 시간 복잡도는 어떻게 되나요?

자를 수 있는 틈이 n - 1개라 자르는 방법은 최대 2^(n-1)개이고, 답 하나를 복사하는 데 O(n)이 든다. 그래서 O(n · 2^n)이다. "aaaa…a"처럼 모든 방법이 답인 입력이 실제로 있어서 이보다 좋아질 수 없다. 회문 표를 만드는 O(n²)은 그에 비하면 작다.

### 회문 표를 왜 미리 만드나요?

백트래킹은 같은 시작 위치에서 같은 조각을 여러 번 확인한다. a 16개에서 양 끝 비교로 확인하면 글자 비교가 4만 번이 넘는데, 서로 다른 조각은 136개뿐이다. 표를 O(n²)에 만들어 두면 확인이 한 번에 끝나고 실제로 세 배 넘게 빨라졌다.

### 표는 왜 i를 뒤에서부터 채우나요?

`pal[i][j]`는 안쪽 `pal[i+1][j-1]`을 읽는다. i + 1 행이 먼저 채워져 있어야 하니 i를 큰 쪽부터 돈다. 앞에서부터 채우면 안쪽이 아직 false라 "abba" 같은 긴 회문을 놓친다. 길이 순으로 채워도 된다.

### 회문이 아닌 조각을 만나면 왜 break가 아니라 continue인가요?

조각이 길어진다고 회문 여부가 한쪽으로만 바뀌지 않는다. "ab"는 회문이 아니지만 "abba"는 회문이다. 정렬된 후보에서 합이 넘치면 뒤도 다 넘치는 Combination Sum과 달라서, break를 쓰면 더 긴 회문 조각을 놓친다.

### 메모이제이션으로 빨라지나요?

같은 `go(start)`가 여러 번 불리니 그 결과 목록을 기억할 수는 있다. 하지만 답이 지수적으로 많으면 목록을 앞에 붙여 복사하는 비용이 더 크다. 실제로 a 16개에서 표 백트래킹보다 네 배 느렸다. 개수만 세거나 최소 자르기를 구할 때는 기억할 값이 숫자 하나라 메모이제이션이 확실히 이긴다.

### 최소 자르기 횟수만 구하려면요?

LeetCode 132다. 목록을 만들면 지수 시간이라 DP로 바꾼다. `cut[j]`를 `s[0..j]`의 최소 자르기로 두고, 마지막 조각 `s[i..j]`가 회문인 i마다 `cut[i-1] + 1`의 최솟값을 고른다. 회문 표와 함께 O(n²)이다.

### 회문 표 없이 공간을 줄일 수 있나요?

가운데에서 넓히는 방법으로 각 시작 위치의 회문 끝 목록만 모으면 회문 수만큼만 메모리를 쓴다. 회문이 드문 문자열에서는 O(n²) 표보다 훨씬 작다. 양 끝 비교로 매번 확인하면 추가 공간은 O(n)이지만 확인이 반복돼 느려진다.
