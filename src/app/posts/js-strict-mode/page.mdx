import { getPostMetadata } from "@/features/posts";

장바구니 합계가 늘 0으로 나온다. 에러는 없다. 코드를 한참 보다가 변수 이름 오타를 찾았다.

```js
function cartTotal(items) {
  let total = 0;
  for (const it of items) {
    totl = total + it.price * it.qty; // 오타: total
  }
  return total;
}
console.log("total:", cartTotal([{ price: 1000, qty: 2 }, { price: 500, qty: 1 }]));
console.log("leaked global:", globalThis.totl);
```

이 파일을 CommonJS(`s1.cjs`)로 Node.js 22에서 돌린 출력이다.

```text
total: 0
leaked global: 500
```

선언한 적 없는 `totl`에 값을 넣었는데 엔진은 말없이 전역 변수를 하나 만들어 줬다. 함수는 0을 돌려주고, 전역에는 엉뚱한 값이 남았다. 똑같은 내용을 확장자만 바꿔 ES 모듈(`s1.mjs`)로 돌리면 이렇다.

```text

         ^

```

첫 실행에서 바로 오타 위치를 알려 준다. 두 파일의 차이는 엄격 모드(strict mode) 하나다. 이 글은 엄격 모드가 무엇을 바꾸는지, 언제 켜지고 언제 꺼지는지, 그리고 이름이 비슷해서 헷갈리는 타입스크립트의 `strict`와 React의 `StrictMode`가 각각 무엇인지 정리한다. 출력은 Node.js 22와 크로미움(React 19.3)에서 실제로 돌린 결과다.

## 조용한 실패를 에러로 바꾸는 모드

자바스크립트는 처음에 웹 페이지에 몇 줄 붙이는 언어로 만들어져서, 실수를 해도 최대한 계속 돌도록 설계됐다. 선언 안 한 변수에 쓰면 전역을 만들고, 못 쓰는 속성에 쓰면 무시하고, `this`가 없으면 전역 객체를 넣어 줬다. 페이지가 멈추지 않는 대신 버그가 조용히 숨었다.

ES5(2009)는 이 동작을 바꾸고 싶었지만 기존 웹 페이지를 깨뜨릴 수 없었다. 그래서 선택해서 켜는 모드를 만들었다. 그게 엄격 모드이고, 켜지 않은 쪽을 비공식적으로 느슨한 모드(sloppy mode)라고 부른다. 엄격 모드가 바꾸는 건 크게 세 갈래다. 조용히 넘어가던 실수를 에러로 바꾸고, 엔진이 최적화하기 어렵게 만들던 기능을 막고, 앞으로 쓸 예약어를 미리 잡아 둔다.

## 어디서 켜지고 어디서 꺼지나

엄격 모드를 켜는 방법은 파일이나 함수의 맨 앞에 `"use strict";`라는 문자열 문장을 두는 것이다. 지시어(directive)라고 부른다. 맨 앞이어야 한다는 조건이 중요하다.

```js
function late() {
  const x = 1;
  "use strict";
  return this === undefined;
}
function early() {
  "use strict";
  return this === undefined;
}
console.log("directive after a statement:", late(), "| first statement:", early());
const isStrict = (function () { return this === undefined; })();
console.log("this file is strict?", isStrict);
```

```text
directive after a statement: false | first statement: true
this file is strict? false
```

`late` 안의 `"use strict"`는 다른 문장 뒤에 있어서 그냥 쓸모없는 문자열 식이 됐다. 에러도 경고도 없다. 마지막 두 줄은 지금 코드가 엄격 모드인지 확인하는 흔한 방법이다. 엄격 모드에서 그냥 부른 함수의 `this`는 `undefined`라서다.

그런데 요즘 코드에서는 이 지시어를 직접 쓸 일이 거의 없다. 자동으로 켜지는 곳이 많기 때문이다.

```js
const viaFunction = new Function("return this === undefined;")();
const viaEval = eval("(function () { return this === undefined; })()");
const indirect = (0, eval)("(function () { return this === undefined; })()");
class K { static m() { return (function () { return this === undefined; })(); } }
console.log("module:", (function () { return this === undefined; })(), "| new Function:", viaFunction, "| direct eval:", viaEval, "| indirect eval:", indirect, "| class:", K.m());
```

```text
module: true | new Function: false | direct eval: true | indirect eval: false | class: true
```

ES 모듈 파일 안이라서 모듈 최상위와 클래스 안은 엄격 모드다. 직접 `eval`은 부른 쪽의 모드를 물려받는다. 하지만 `new Function`과 간접 `eval`(`(0, eval)(...)`)은 전역 스코프에서 새로 시작하는 코드라 모듈 안에서 불러도 느슨한 모드다.

## 지시어 하나가 남의 코드까지 바꾼다

파일 단위 지시어는 파일을 이어 붙이면 문제가 된다. 번들러가 없던 시절에는 빌드 단계에서 스크립트를 그냥 `cat`으로 합쳐 배포하는 일이 흔했다. 지시어가 있는 파일과 없는 파일을 합쳐 봤다.

```bash

cat analytics.js legacy-widget.js > bundle1.js
# 오래된 스크립트 뒤에 엄격 모드 라이브러리를 붙인다
cat legacy-first.js strict-lib.js > bundle2.js
```

```js
// analytics.js
"use strict";
window.track = function (e) { return e; };
// legacy-widget.js
var widget = { mode: 0644 };
counter = 0;
// strict-lib.js
"use strict";
function check() { return this === undefined; }
console.log("strict-lib strict?", check());

```

## 에러로 바뀌는 조용한 실패들

선언 없는 대입 말고도 느슨한 모드가 무시하던 쓰기가 여럿 있다. 같은 코드를 지시어를 붙인 파일과 뗀 파일로 나눠 돌렸다.

```js
"use strict";
const frozen = Object.freeze({ a: 1 });
const getterOnly = { get b() { return 2; } };
const sealed = Object.preventExtensions({});
const cases = {
  "write frozen": () => { frozen.a = 2; },
  "write getter-only": () => { getterOnly.b = 3; },
  "add to non-extensible": () => { sealed.c = 1; },
  "delete non-configurable": () => { delete Object.prototype; },
  "write to primitive": () => { "abc".length = 1; },
  "arguments.callee": function () { return arguments.callee; },
};
for (const [name, fn] of Object.entries(cases)) {
  try { fn(); console.log(name.padEnd(24), "ok (silently)"); }
  catch (e) { console.log(name.padEnd(24), e.constructor.name + ": " + e.message); }
}
```

엄격 모드(지시어 있음):

```text
write frozen             TypeError: Cannot assign to read only property 'a' of object '#<Object>'
write getter-only        TypeError: Cannot set property b of #<Object> which has only a getter
add to non-extensible    TypeError: Cannot add property c, object is not extensible
delete non-configurable  TypeError: Cannot delete property 'prototype' of function Object() { [native code] }
write to primitive       TypeError: Cannot assign to read only property 'length' of string 'abc'
arguments.callee         TypeError: 'caller', 'callee', and 'arguments' properties may not be accessed on strict mode functions or the arguments objects for calls to them
```

느슨한 모드(지시어 없음):

```text
write frozen             ok (silently)
write getter-only        ok (silently)
add to non-extensible    ok (silently)
delete non-configurable  ok (silently)
write to primitive       ok (silently)
arguments.callee         ok (silently)
```

"ok"라고 찍혔지만 실제로 값이 바뀐 건 하나도 없다. `Object.freeze`로 얼린 설정 객체를 고치려는 코드가 느슨한 모드에서는 아무 일도 안 하고 지나간다. 불변 객체를 만들어도 그걸 어기는 코드를 잡아 주는 건 엄격 모드다. `freeze`와 속성 설명자는 [객체 메서드와 속성 설명자](/posts/js-object-methods)에서 다룬다.

느슨한 모드의 `this` 보정도 사라진다. 그냥 부른 함수의 `this`는 전역 객체가 아니라 `undefined`이고, `call(5)`로 넘긴 원시값은 래퍼 객체로 감싸지지 않는다. 이 차이가 메서드를 떼어 부를 때 조용한 오동작 대신 `TypeError`를 만든다. 자세한 건 [this 바인딩](/posts/js-this-binding)에 있다.

## 파싱 단계에서 막히는 문법

어떤 것은 실행 전, 코드를 읽는 순간 막힌다. Node.js의 `vm.Script`로 지시어 유무만 바꿔 컴파일해 봤다.

```js
const vm = require("node:vm");
const snippets = {
  "duplicate params": "function f(a, a) {}",
  "octal literal": "const n = 010;",
  "with statement": "with (Math) { max(1, 2); }",
  "delete identifier": "let x = 1; delete x;",
  "reserved word": "const interface = 1;",
  "eval as name": "let eval = 1;",
};
for (const [name, code] of Object.entries(snippets)) {
  let sloppy, strict;
  try { new vm.Script(code); sloppy = "ok"; } catch (e) { sloppy = e.constructor.name; }
  try { new vm.Script('"use strict";\n' + code); strict = "ok"; } catch (e) { strict = e.constructor.name + ": " + e.message; }
  console.log(name.padEnd(18), "| sloppy:", sloppy.padEnd(11), "| strict:", strict);
}
```

```text
duplicate params   | sloppy: ok          | strict: SyntaxError: Duplicate parameter name not allowed in this context
octal literal      | sloppy: ok          | strict: SyntaxError: Octal literals are not allowed in strict mode.
with statement     | sloppy: ok          | strict: SyntaxError: Strict mode code may not include a with statement
delete identifier  | sloppy: ok          | strict: SyntaxError: Delete of an unqualified identifier in strict mode.
reserved word      | sloppy: ok          | strict: SyntaxError: Unexpected strict mode reserved word
eval as name       | sloppy: ok          | strict: SyntaxError: Unexpected eval or arguments in strict mode
```

`with`는 블록 안의 이름이 객체 속성인지 바깥 변수인지 실행해 봐야 알 수 있게 만들어서, 엔진이 이름을 미리 정리하지 못하게 했다. 엄격 모드가 이걸 없애면서 스코프가 코드만 보고 정해지게 됐다. 8진수가 필요하면 `0o644`처럼 ES2015 표기를 쓴다. `interface`, `implements`, `package`, `private`, `protected`, `public`, `static`, `let`, `yield` 같은 이름은 엄격 모드에서 변수 이름으로 쓸 수 없다. 나중에 문법으로 쓸 자리를 비워 둔 것이다.

`eval`도 바뀐다. 느슨한 모드의 `eval`은 부른 함수의 스코프에 `var`를 새로 만들 수 있었다.

```js
function sloppyEval() { eval("var leaked = 1"); return typeof leaked; }
function strictEval() { "use strict"; eval("var leaked = 1"); return typeof leaked; }
console.log("sloppy eval var:", sloppyEval(), "| strict eval var:", strictEval());
```

```text
sloppy eval var: number | strict eval var: undefined
```

엄격 모드에서는 `eval`이 자기만의 스코프를 가져서 바깥에 변수를 흘리지 않는다. 엔진 입장에서는 함수 안에 `eval`이 있어도 그 함수의 변수 목록이 바뀌지 않는다는 보장이 생긴다.

## arguments가 매개변수를 따라 바뀌지 않는다

느슨한 모드에서 단순한 매개변수 목록을 가진 함수는 `arguments[0]`과 첫 매개변수가 서로 연결돼 있다. 한쪽을 바꾸면 다른 쪽도 바뀐다.

```js
function sloppyArgs(a) { a = 99; return arguments[0]; }
function strictArgs(a) { "use strict"; a = 99; return arguments[0]; }
console.log("sloppy arguments[0]:", sloppyArgs(1), "| strict arguments[0]:", strictArgs(1));
```

```text
sloppy arguments[0]: 99 | strict arguments[0]: 1
```

이 연결 때문에 엔진은 매개변수를 레지스터에 두는 최적화를 마음껏 하지 못했다. 그 밖의 `arguments` 이야기는 [함수 선언문, 표현식, 화살표 함수](/posts/js-function-forms)에 있다. 기본값이나 구조 분해가 있는 매개변수 목록이면 느슨한 모드에서도 연결이 끊긴다. 같은 이유로 그런 함수에는 아예 지시어를 쓸 수 없다.

```text
non-simple params: SyntaxError: Illegal 'use strict' directive in function with non-simple parameter list
```

`function g(a = 1) { "use strict"; }`를 컴파일한 결과다. 매개변수의 기본값 식은 함수 본문보다 먼저 평가되는데, 그 식을 어느 모드로 읽을지 애매해지는 걸 ES2016에서 막았다. 필요하면 파일이나 바깥 함수에서 켠다.

## 이름만 비슷한 두 strict

엄격 모드를 이야기하면 늘 함께 나오는 두 설정이 있다. 둘 다 이 모드와 관계가 있지만 같은 것은 아니다.

### React의 StrictMode

`<React.StrictMode>`는 자바스크립트 엄격 모드와 상관이 없다. 개발 빌드에서만 동작하는 검사 도구로, 순수하지 않은 렌더링과 정리되지 않는 effect를 드러내려고 일부러 두 번 실행한다. 크로미움에서 React 19.3 개발 빌드로 클래식 스크립트(느슨한 모드) 안에 돌렸다.

```js
let renders = 0, effects = 0;
function Clock() {
  renders += 1;
  React.useEffect(() => { effects += 1; return () => console.log("cleanup ran"); }, []);
  return h("p", null, "clock");
}
createRoot(el).render(h(React.StrictMode, null, h(Clock)));
```

```text
cleanup ran
StrictMode renders: 2 effects: 2
is this script strict? false
```

컴포넌트가 두 번 렌더링되고, effect가 실행됐다가 정리됐다가 다시 실행됐다. 마지막 줄을 보면 이 스크립트는 자바스크립트로는 느슨한 모드였다. 이름만 같은 두 기능이다.

## 오래된 코드를 엄격 모드로 옮길 때

레거시 스크립트를 ES 모듈로 바꾸거나 번들러에 넣으면, 코드는 한 글자도 안 바뀌었는데 엄격 모드가 켜진다. 그때 깨지는 순서는 대체로 정해져 있다. 파싱 에러(`with`, 8진수, 중복 매개변수)는 빌드나 로드 단계에서 바로 드러나니 오히려 쉽다. 어려운 건 실행 중에 특정 경로로 들어가야 나는 에러다.

먼저 확인할 것은 세 가지다. 선언 없는 대입으로 전역을 만들던 곳(`ReferenceError: x is not defined`), 함수를 그냥 불러 `this`로 전역에 접근하던 곳(`TypeError: Cannot read properties of undefined`), 얼린 객체나 getter에 쓰던 곳(`TypeError: Cannot assign to read only property`)이다. ESLint의 `no-undef` 규칙이 첫 번째를 정적으로 거의 다 잡는다. 나머지는 테스트를 엄격 모드로 돌려 봐야 나온다. 마이그레이션 직후 에러 모니터링에서 이 세 메시지가 갑자기 늘었다면 원인은 대부분 모드 전환이다.

## 연습: 엄격 모드라면 이 대입이 성공할까

`checkAssign(target, key)`를 만들어 본다. 엄격 모드에서 `target[key] = 값`을 했을 때의 결과를 실제로 대입하지 않고 미리 알려 주는 함수다. 돌려줄 값은 다섯 가지다.

- `"ok"`: 성공한다.
- `"read-only"`: 자기나 체인 위의 데이터 속성이 `writable: false`다.
- `"getter-only"`: 자기나 체인 위의 접근자 속성에 setter가 없다.
- `"not-extensible"`: 새 속성을 만들어야 하는데 객체가 확장 불가다.
- `"primitive"`: 대상이 원시값이다.

체인 위에 setter가 있으면 객체가 확장 불가여도 setter가 불리니 `"ok"`다. 이 규칙은 [프로토타입 체인](/posts/js-prototype-chain#읽을-때는-올라가고-쓸-때는-올라가지-않는다)에서 봤다.

## 실수를 늦게 알 이유가 없다

처음 장바구니 합계는 오타 하나를 엔진이 받아 준 탓에 0이 됐다. 엄격 모드는 그런 너그러움을 거둬 간다. 선언 없는 대입, 얼린 객체에 쓰기, 떼어 낸 메서드의 `this`가 모두 그 자리에서 에러가 된다. 요즘은 ES 모듈과 클래스가 기본으로 켜 주니 일부러 쓸 일은 줄었지만, CommonJS 파일, 클래식 스크립트, 콘솔, `new Function`은 여전히 느슨한 모드로 시작한다. 같은 코드가 환경에 따라 다르게 돌면 모드부터 확인한다.

## 면접에서 나올 만한 질문

### 엄격 모드는 무엇이고 왜 생겼나요?

ES5에서 추가된, 선택해서 켜는 자바스크립트의 더 엄격한 변형이다. 선언 없는 변수 대입, 읽기 전용 속성 쓰기 같은 조용한 실패를 에러로 바꾸고, `with`처럼 엔진 최적화를 막는 문법을 금지하고, 앞으로 쓸 예약어를 잡아 둔다. 기존 웹을 깨지 않으려고 기본값을 바꾸지 않고 켜는 방식으로 만들었다.

### 엄격 모드는 어떻게 켜고, 자동으로 켜지는 곳은 어디인가요?

파일이나 함수 본문의 맨 앞에 `"use strict";` 지시어를 둔다. 다른 문장 뒤에 있으면 그냥 문자열 식이 되어 무시된다. ES 모듈과 `class` 본문은 자동으로 엄격 모드이고, 직접 `eval`은 부른 쪽의 모드를 물려받는다. CommonJS 파일, 클래식 스크립트, 개발자 도구 콘솔, `new Function`은 느슨한 모드로 시작한다.

### 엄격 모드에서 this는 어떻게 달라지나요?

그냥 부른 함수의 `this`가 전역 객체가 아니라 `undefined`가 된다. `call`이나 `apply`로 넘긴 원시값도 래퍼 객체로 감싸지 않고 그대로 쓴다. 그래서 메서드를 떼어 불렀을 때 전역 객체를 조용히 건드리는 대신 `TypeError`가 난다.

### 엄격 모드에서 에러가 되는 대표적인 동작은 무엇인가요?

선언 없는 변수 대입은 `ReferenceError`, 얼린 객체나 쓰기 금지 속성에 쓰기, getter만 있는 속성에 쓰기, 확장 불가 객체에 속성 추가, 삭제 불가 속성 `delete`는 `TypeError`다. 중복 매개변수 이름, `0644` 같은 옛 8진수, `with`, 식별자 `delete`, 예약어를 변수 이름으로 쓰는 것은 파싱 단계의 `SyntaxError`다. 느슨한 모드에서는 대부분 조용히 무시된다.

### 파일을 이어 붙이는 빌드에서 엄격 모드가 왜 문제가 되나요?

지시어는 파일 맨 앞에 있을 때만 그 파일 전체에 걸린다. 엄격 모드 파일 뒤에 느슨한 모드용 파일을 붙이면 뒤 파일까지 엄격 모드가 되어 문법 에러로 전체가 죽을 수 있고, 반대 순서면 뒤 파일의 지시어가 무시된다. 그래서 라이브러리는 IIFE 안에 지시어를 두었고, 지금은 번들러가 모듈 스코프를 나눠 해결한다.

### tsconfig의 strict와 자바스크립트 엄격 모드는 같은 건가요?

다르다. `strict: true`는 `strictNullChecks`, `noImplicitAny` 등 타입 검사 옵션 아홉 개를 함께 켜는 스위치다. 그중 `alwaysStrict`만 출력에 `"use strict"`를 넣어 런타임 엄격 모드와 관계가 있고, 나머지는 컴파일할 때만 검사한다.

### React의 StrictMode는 자바스크립트 엄격 모드와 어떤 관계인가요?

관계가 없다. React StrictMode는 개발 빌드에서 컴포넌트를 두 번 렌더링하고 effect를 실행, 정리, 재실행해 순수하지 않은 렌더링과 정리 누락을 드러내는 도구다. 실제로 느슨한 모드 스크립트 안에서도 그대로 동작했다. 요청이 두 번 나간다고 끄기보다 effect의 정리 함수를 고친다.

### 기본값이 있는 매개변수를 가진 함수에 "use strict"를 쓰면 어떻게 되나요?

`SyntaxError`가 난다. 기본값이나 구조 분해 같은 단순하지 않은 매개변수 목록은 함수 본문보다 먼저 평가되는데, 본문 안의 지시어로 그 부분의 모드를 정하면 애매해져서 ES2016부터 금지됐다. 그런 함수는 파일이나 바깥 함수에서 엄격 모드를 켠다.
