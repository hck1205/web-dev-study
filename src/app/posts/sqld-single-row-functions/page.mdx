<EasyIntro>
  한 데이터베이스에서 잘 돌던 질문을 다른 데이터베이스로 옮겼더니 에러는 없는데 이름 끝 세 글자 대신 이름 전체가 나왔다. 같은 이름의 함수가 데이터베이스마다 조금씩 다르게 움직여서 생긴 일이다.

  단일행 함수는 줄 하나를 넣으면 값 하나를 내놓는 작은 기계다. 열 줄을 넣으면 결과도 열 줄이고, 여러 줄을 합쳐 하나로 줄이는 합계 함수와는 다르다. 이 기계로 글자를 자르거나 채우고, 숫자를 반올림하거나 버리고, 날짜에 며칠이나 몇 달을 더한다.

  알아 두면 시험의 함정과 현장의 사고가 같은 곳에 있다는 게 보인다. 음수를 반올림할 때 어느 쪽으로 가는지, 1월 31일에 한 달을 더하면 며칠이 되는지 같은 작은 규칙에서 값이 갈린다. 그래서 옮기기 전과 후에 같은 데이터로 결과를 뽑아 비교하는 것이 가장 확실하다.
</EasyIntro>

Oracle에서 돌던 월말 리포트 쿼리를 PostgreSQL로 옮겼다. 에러는 하나도 안 났다. 그런데 사원 이름의 끝 세 글자를 뽑던 열에 이름이 통째로 나오고, 2월 29일 입사자의 "한 달 뒤 말일"이 3월 31일이 아니라 3월 29일로 찍혔다. 둘 다 함수 하나가 DB마다 조금씩 다르게 동작해서 생긴 일이다.

이런 함수는 한 행을 받아 값 하나를 돌려준다. 문자를 자르고, 숫자를 반올림하고, 날짜에 달을 더한다. SQLD 시험은 이 함수들의 결과를 Oracle 문법으로 묻고, 실무에서는 같은 이름의 함수가 DB마다 다른 값을 내는 곳에서 사고가 난다. 이 글은 단일행 함수가 무엇인지부터 보고 문자, 숫자, 날짜 함수를 EMP 데이터로 하나씩 돌려 본다. NULL을 다루는 함수와 CASE는 [NULL 글](/posts/sqld-null-functions)에서, `TO_CHAR` 형식과 형 변환은 [형 변환 글](/posts/sqld-type-conversion)에서 이어 간다.

SQLD 문제는 주로 Oracle 문법으로 나오고, SQL Server와 다른 점을 묻는 문제가 섞여 나온다. 그래서 SQL은 Oracle 문법을 먼저 쓰고, PostgreSQL 16과 SQL Server에서 다른 부분을 옆에 적었다. 결과 표는 모두 PostgreSQL 16.15에 같은 데이터를 넣고 실제로 돌린 출력이다. `INSTR`, `ADD_MONTHS`처럼 Oracle에만 있는 함수는 PostgreSQL에서 같은 뜻의 식으로 돌렸고, 결과 값은 Oracle과 같다. psql은 NULL을 빈칸으로 보여 주는데, 눈에 띄게 `(null)`로 표시하도록 설정했다.

## 이 글에서 쓸 사원 테이블

Oracle을 설치하면 따라오는 SCOTT 계정의 `EMP`(사원)와 `DEPT`(부서) 테이블을 쓴다. SQLD 교재와 기출이 거의 다 이 데이터로 문제를 낸다. 집계와 조인을 다루는 다음 글들도 이 테이블을 그대로 쓴다.

## 한 행에 하나씩 돌려주는 함수

`UPPER(ename)`은 행마다 한 번씩 실행되고, 행마다 결과를 하나씩 돌려준다. 입력이 3행이면 출력도 3행이다. 이런 함수를 단일행 함수라고 한다. `SUM`, `COUNT`, `AVG`처럼 여러 행을 받아 값 하나로 줄이는 함수는 다중행 함수(집계 함수)다. 커미션의 NULL을 0으로 바꾸는 `NVL(comm, 0)`도 행마다 도는 단일행 함수다.

```sql
-- 단일행 함수: 3행이 들어가서 3행이 나온다
SELECT ename, UPPER(ename), LENGTH(ename) FROM emp WHERE deptno = 10 ORDER BY empno;

-- 다중행 함수: 3행이 들어가서 1행이 나온다
SELECT COUNT(*), SUM(sal) FROM emp WHERE deptno = 10;
```

```text
 ename  | upper  | length
--------+--------+--------
 CLARK  | CLARK  |      5
 KING   | KING   |      4
 MILLER | MILLER |      6
(3 rows)

 count | sum
-------+------
     3 | 8750
(1 row)
```

단일행 함수는 `SELECT`, `WHERE`, `ORDER BY` 어디에나 쓸 수 있고, 함수 안에 함수를 넣을 수도 있다(`UPPER(SUBSTR(ename, 1, 3))`). 중첩하면 안쪽부터 계산한다. 인자는 여러 개여도(`SUBSTR(ename, 1, 3)`) 결과는 행마다 하나다. 다중행 함수는 `WHERE`에 쓸 수 없는데, 이건 [집계와 GROUP BY 글](/posts/sqld-group-by-having)에서 실행 순서와 함께 다룬다.

함수 결과만 보고 싶을 때가 있다. `SELECT UPPER('sql')`처럼 테이블이 필요 없는 계산이다. Oracle은 `SELECT`에 반드시 `FROM`이 있어야 해서, 한 행 한 열짜리 가짜 테이블 `DUAL`을 쓴다. 소유자는 SYS이고 모든 사용자가 쓸 수 있다.

```sql
-- Oracle
SELECT UPPER('sql') FROM DUAL;

-- PostgreSQL, SQL Server: FROM 없이 된다
SELECT UPPER('sql');
```

Oracle도 23ai부터는 `FROM` 없이 쓸 수 있지만, 시험은 `FROM DUAL`을 기준으로 낸다. 이 글의 함수 예제 중 테이블 없는 것은 Oracle이라면 끝에 `FROM DUAL`을 붙인다고 보면 된다.

## 문자를 다듬는 함수

### 대소문자 바꾸기

`LOWER`는 소문자로, `UPPER`는 대문자로, `INITCAP`은 단어마다 첫 글자만 대문자로 바꾼다. 검색할 때 대소문자를 무시하려고 `WHERE UPPER(ename) = 'SMITH'`처럼 많이 쓴다.

```sql
SELECT LOWER('SQL Expert') AS lo, UPPER('sql expert') AS up, INITCAP('sql expert') AS ini;
```

```text
     lo     |     up     |    ini
------------+------------+------------
 sql expert | SQL EXPERT | Sql Expert
(1 row)
```

SQL Server에는 `INITCAP`이 없다. `LOWER`, `UPPER`만 있다.

### 이어 붙이기

Oracle은 `||` 연산자나 `CONCAT` 함수로 문자열을 잇는다. Oracle의 `CONCAT`은 인자를 딱 두 개만 받는다는 게 자주 나오는 함정이다. 셋 이상이면 `CONCAT(CONCAT(a, b), c)`처럼 감싸거나 `||`를 쓴다.

```sql
SELECT CONCAT(ename, job) AS c1,
       ename || ' is a ' || job AS c2
FROM emp WHERE deptno = 10 ORDER BY empno;
```

```text
      c1       |         c2
---------------+---------------------
 CLARKMANAGER  | CLARK is a MANAGER
 KINGPRESIDENT | KING is a PRESIDENT
 MILLERCLERK   | MILLER is a CLERK
(3 rows)
```

PostgreSQL의 `concat`은 인자를 몇 개든 받는다(`concat('A', 'B', 'C')` → `ABC`). SQL Server는 `+` 연산자로 잇고(`ename + ' is a ' + job`), `CONCAT`은 2012 버전부터 여러 인자를 받는다. NULL을 이을 때의 차이는 [NULL 글](/posts/sqld-null-functions)에서 따로 본다.

### 잘라 내고 위치 찾기

`SUBSTR(문자열, 시작, 길이)`는 시작 위치부터 길이만큼 잘라 낸다. 위치는 1부터 센다. 길이를 빼면 끝까지 가져간다. 시작 위치가 음수면 뒤에서부터 센다. `SUBSTR('CLARK', -3)`은 뒤에서 세 번째 글자부터라서 `ARK`다.

`INSTR(문자열, 찾을 문자열, 시작, 몇 번째)`은 찾는 문자열이 처음 나오는 위치를 돌려준다. 없으면 0이다. 세 번째, 네 번째 인자로 "어디서부터 찾기 시작해서 몇 번째로 나오는 것"을 고를 수 있다. Oracle 문서에도 나오는 예제로 보자. 아래 그림에서 다음을 누르면 `INSTR('CORPORATE FLOOR', 'OR', 3, 2)`가 위치를 찾는 과정이 나온다.

사원 이름에 적용하면 이렇다. PostgreSQL에는 `INSTR`이 없어서 `strpos`(또는 `position('A' IN ename)`)로 돌렸다. 시작 위치나 몇 번째를 지정하는 인자는 없다.

```sql
-- Oracle
SELECT ename, SUBSTR(ename, 2, 3) AS s1, SUBSTR(ename, 3) AS s2, SUBSTR(ename, -3) AS s3
FROM emp WHERE deptno = 10 ORDER BY empno;

SELECT ename, INSTR(ename, 'A') AS pos_a, INSTR(ename, 'L') AS pos_l
FROM emp WHERE deptno = 30 ORDER BY empno;
```

```text
 ename  | s1  |  s2  | s3
--------+-----+------+-----
 CLARK  | LAR | ARK  | ARK
 KING   | ING | NG   | ING
 MILLER | ILL | LLER | LER
(3 rows)

 ename  | pos_a | pos_l
--------+-------+-------
 ALLEN  |     1 |     2
 WARD   |     2 |     0
 MARTIN |     2 |     0
 BLAKE  |     3 |     2
 TURNER |     0 |     0
 JAMES  |     2 |     0
(6 rows)
```

`s3` 열은 PostgreSQL에서 `right(ename, 3)`으로 구한 값이다. PostgreSQL의 `substr`에 음수 시작 위치를 주면 뒤에서 세지 않는다. 실제로 `substr('CLARK', -3)`을 돌리면 `CLARK`가 그대로 나온다(0, -1, -2 같은 가상의 위치부터 센다). Oracle에서 옮긴 쿼리가 조용히 다른 값을 내는 대표적인 경우다. SQL Server는 `SUBSTRING(ename, 2, 3)`처럼 길이 인자가 꼭 있어야 하고, 위치 찾기는 `CHARINDEX('A', ename)`이다.

### 길이와 공백

`LENGTH`는 글자 수를 센다. SQL Server는 `LEN`이고, 끝의 공백은 세지 않는다.

```sql
SELECT ename, LENGTH(ename) FROM emp WHERE LENGTH(ename) >= 6 ORDER BY empno;
```

```text
 ename  | length
--------+--------
 MARTIN |      6
 TURNER |      6
 MILLER |      6
(3 rows)
```

`LTRIM`, `RTRIM`은 왼쪽, 오른쪽에서 지정한 문자들을 지운다. 두 번째 인자를 빼면 공백을 지운다. 두 번째 인자는 "문자열"이 아니라 "문자 집합"으로 읽힌다. `LTRIM('xyxSMITH', 'xy')`는 x와 y를 만나는 동안 계속 지워서 `SMITH`가 된다. `TRIM`은 양쪽을 지우는데, Oracle의 `TRIM`은 `TRIM('x' FROM ...)`처럼 한 글자만 지정할 수 있다. 가운데에 있는 문자는 어느 함수도 건드리지 않는다.

```sql
SELECT LTRIM('xxSMITHxx', 'x') AS l,
       RTRIM('xxSMITHxx', 'x') AS r,
       TRIM('x' FROM 'xxSMITHxx') AS t,     -- 기본은 BOTH(양쪽)
       '[' || TRIM('  SQL  ') || ']' AS t2;  -- 공백 지우기

SELECT LTRIM('0012300', '0') AS a, RTRIM('0012300', '0') AS b, TRIM('0' FROM '0012300') AS c;
```

```text
    l    |    r    |   t   |  t2
---------+---------+-------+-------
 SMITHxx | xxSMITH | SMITH | [SQL]
(1 row)

   a   |   b   |  c
-------+-------+-----
 12300 | 00123 | 123
(1 row)
```

`TRIM('0' FROM '0012300')`이 `123`이 되는 걸 봐 둔다. 숫자 끝의 0까지 지워 버린다. SQL Server의 `LTRIM`, `RTRIM`은 오래 공백만 지웠고, 지울 문자를 고르는 인자는 2022 버전에서 들어왔다.

### 채우기와 바꾸기

`LPAD(문자열, 전체 길이, 채울 문자)`는 왼쪽을 채워서 전체 길이를 맞춘다. `RPAD`는 오른쪽이다. 채울 문자를 빼면 공백으로 채운다. 전체 길이가 원래보다 짧으면 잘라 낸다는 점이 함정이다.

```sql
SELECT ename,
       LPAD(ename, 8, '*') AS lp,
       RPAD(ename, 8, '-') AS rp,
       LPAD(sal, 6, '0')   AS lsal,   -- PostgreSQL은 sal::text로 바꿔서 넘긴다
       LPAD(ename, 3)      AS cut     -- 3글자보다 길면 잘린다
FROM emp WHERE deptno = 10 ORDER BY empno;
```

```text
 ename  |    lp    |    rp    |  lsal  | cut
--------+----------+----------+--------+-----
 CLARK  | ***CLARK | CLARK--- | 002450 | CLA
 KING   | ****KING | KING---- | 005000 | KIN
 MILLER | **MILLER | MILLER-- | 001300 | MIL
(3 rows)
```

`REPLACE(문자열, 찾을 것, 바꿀 것)`은 찾은 부분을 모두 바꾼다. Oracle은 세 번째 인자를 빼면 찾은 부분을 지운다. PostgreSQL과 SQL Server는 세 번째 인자가 꼭 있어야 해서 `''`을 넘겼다.

```sql
SELECT job,
       REPLACE(job, 'MAN', 'PERSON') AS r,
       REPLACE(job, 'A') AS r2          -- Oracle. PostgreSQL은 REPLACE(job, 'A', '')
FROM emp WHERE job IN ('SALESMAN', 'MANAGER') GROUP BY job ORDER BY job;
```

```text
   job    |      r      |   r2
----------+-------------+--------
 MANAGER  | PERSONAGER  | MNGER
 SALESMAN | SALESPERSON | SLESMN
(2 rows)
```

`MANAGER`가 `PERSONAGER`가 됐다. `REPLACE`는 단어를 보지 않고 글자 조각이 맞으면 바꾼다.

## 숫자를 자르고 올리는 함수

`ROUND(n, d)`는 소수점 아래 d자리로 반올림하고, `TRUNC(n, d)`는 d자리 아래를 버린다. d를 빼면 0이다. d가 음수면 소수점 왼쪽으로 간다. -1은 일의 자리, -2는 십의 자리에서 반올림하거나 버린다.

```sql
SELECT ROUND(1234.5678, 2)  AS r2,   -- 소수 셋째 자리에서 반올림
       ROUND(1234.5678)     AS r0,
       ROUND(1234.5678, -1) AS rm1,  -- 일의 자리에서 반올림
       ROUND(1234.5678, -2) AS rm2,  -- 십의 자리에서 반올림
       ROUND(1250, -2)      AS r1250,
       ROUND(1249, -2)      AS r1249;

SELECT TRUNC(1234.5678, 2) AS t2, TRUNC(1234.5678) AS t0, TRUNC(1234.5678, -2) AS tm2,
       TRUNC(-1.5) AS tneg, ROUND(-1.5) AS rneg;
```

```text
   r2    |  r0  | rm1  | rm2  | r1250 | r1249
---------+------+------+------+-------+-------
 1234.57 | 1235 | 1230 | 1200 |  1300 |  1200
(1 row)

   t2    |  t0  | tm2  | tneg | rneg
---------+------+------+------+------
 1234.56 | 1234 | 1200 |   -1 |   -2
(1 row)
```

`ROUND(1234.5678, -2)`가 헷갈리면 "-2는 백의 자리까지 남긴다"로 읽으면 된다. 십의 자리 3을 보고 버려서 1200이다. `ROUND(1250, -2)`는 십의 자리가 5라 올려서 1300이다. 음수의 반올림은 0에서 먼 쪽으로 간다. `ROUND(-1.5)`는 -2, `TRUNC(-1.5)`는 그냥 소수를 버려서 -1이다.

`CEIL`은 그 수보다 크거나 같은 가장 작은 정수, `FLOOR`는 작거나 같은 가장 큰 정수다. 양수에서는 올림, 버림처럼 보이지만 음수에서 차이가 난다. `FLOOR(-3.1)`은 -3이 아니라 -4다. `TRUNC`는 0 쪽으로 버리고 `FLOOR`는 아래쪽으로 내린다.

```sql
SELECT CEIL(3.1) AS c1, CEIL(-3.1) AS c2, FLOOR(3.9) AS f1, FLOOR(-3.1) AS f2;

SELECT MOD(17, 5) AS m1, MOD(-17, 5) AS m2, MOD(17, -5) AS m3,
       ABS(-17) AS a, SIGN(-17) AS s1, SIGN(0) AS s0, SIGN(3.5) AS s2;
```

```text
 c1 | c2 | f1 | f2
----+----+----+----
  4 | -3 |  3 | -4
(1 row)

 m1 | m2 | m3 | a  | s1 | s0 | s2
----+----+----+----+----+----+----
  2 | -2 |  2 | 17 | -1 |  0 |  1
(1 row)
```

`MOD`는 나머지다. 결과의 부호는 나눠지는 수(첫 번째 인자)를 따른다. `MOD(-17, 5)`는 -2다. Oracle은 `MOD(17, 0)`이 17을 돌려주지만 PostgreSQL은 0으로 나눴다는 에러를 낸다. `ABS`는 절댓값, `SIGN`은 양수면 1, 0이면 0, 음수면 -1이다. SQL Server는 `CEIL` 대신 `CEILING`, `MOD` 대신 `%` 연산자를 쓴다.

사원 급여를 12로 나눠 월급을 구해 보면 함수마다 차이가 보인다.

```sql
SELECT ename, sal,
       ROUND(sal / 12, 1) AS monthly,  -- 소수 첫째 자리까지
       TRUNC(sal / 12)    AS mt,       -- 원 단위 버림
       CEIL(sal / 12)     AS mc,       -- 원 단위 올림
       ROUND(sal, -3)     AS r3        -- 천 단위 반올림
FROM emp WHERE deptno = 20 ORDER BY empno;
```

```text
 ename | sal  | monthly | mt  | mc  |  r3
-------+------+---------+-----+-----+------
 SMITH |  800 |    66.7 |  66 |  67 | 1000
 JONES | 2975 |   247.9 | 247 | 248 | 3000
 SCOTT | 3000 |   250.0 | 250 | 250 | 3000
 ADAMS | 1100 |    91.7 |  91 |  92 | 1000
 FORD  | 3000 |   250.0 | 250 | 250 | 3000
(5 rows)
```

PostgreSQL은 `ROUND(250, 1)`을 `250.0`으로 보여 주고, Oracle은 같은 값을 `250`으로 보여 준다. 값은 같고 표시만 다르다.

아래 칸에서 Oracle의 `ROUND(n, d)`를 직접 만들어 볼 수 있다. 음수 자릿수와 음수의 반올림이 모두 맞아야 통과한다.

## 날짜는 숫자처럼 더하고 뺀다

Oracle은 날짜에 숫자를 더하면 그만큼의 일(day)을 더한다. 날짜에서 날짜를 빼면 두 날짜 사이의 일수가 숫자로 나온다. `SYSDATE`는 지금 날짜와 시각이다. 이 글에서는 결과가 매일 바뀌지 않게 `SYSDATE` 대신 `DATE '2026-10-17'`을 오늘로 썼다.

```sql
SELECT ename, hiredate,
       hiredate + 30                 AS plus30,  -- 30일 뒤
       DATE '2026-10-17' - hiredate  AS days     -- 입사 후 지난 일수
FROM emp WHERE deptno = 10 ORDER BY empno;
```

```text
 ename  |  hiredate  |   plus30   | days
--------+------------+------------+-------
 CLARK  | 1981-06-09 | 1981-07-09 | 16566
 KING   | 1981-11-17 | 1981-12-17 | 16405
 MILLER | 1982-01-23 | 1982-02-22 | 16338
(3 rows)
```

Oracle의 `DATE`에는 시각이 있어서 1시간은 `1/24`, 1분은 `1/1440`로 더한다. `SYSDATE - hiredate`는 시각까지 계산해서 `16566.5868...` 같은 소수가 나온다. 그래서 `TRUNC(SYSDATE)`로 시각을 자정으로 버리고 쓰는 경우가 많다. PostgreSQL은 `date + 정수`, `date - date`가 Oracle과 같게 동작하고, 시각은 `timestamp + interval '1 hour'`처럼 `interval`로 더한다. SQL Server는 `GETDATE()`, `DATEADD(day, 30, hiredate)`, `DATEDIFF(day, hiredate, GETDATE())`를 쓴다.

### 달 단위 계산

달은 길이가 28일부터 31일까지 달라서 숫자로 더할 수 없다. `ADD_MONTHS(날짜, n)`은 n달 뒤를, `MONTHS_BETWEEN(날짜1, 날짜2)`는 두 날짜 사이가 몇 달인지를 돌려준다. `MONTHS_BETWEEN`은 앞 날짜에서 뒤 날짜를 뺀다. 순서를 바꾸면 음수가 나온다.

```sql
-- Oracle
SELECT ename, hiredate,
       ADD_MONTHS(hiredate, 6)                           AS add6,
       TRUNC(MONTHS_BETWEEN(DATE '2026-10-17', hiredate)) AS months
FROM emp WHERE deptno = 10 ORDER BY empno;
```

```text
 ename  |  hiredate  |    add6    | months
--------+------------+------------+--------
 CLARK  | 1981-06-09 | 1981-12-09 |    544
 KING   | 1981-11-17 | 1982-05-17 |    539
 MILLER | 1982-01-23 | 1982-07-23 |    536
(3 rows)
```

PostgreSQL에는 두 함수가 없다. `add6`은 `hiredate + interval '6 months'`로 구했다. `months`는 Oracle 문서에 적힌 계산 방식대로 식을 세워 구했다. 날짜(일)가 같으면 정수 개월이고, 다르면 일 차이를 31로 나눈 소수가 붙는다. KING은 입사일이 17일이라 딱 539개월이다. CLARK은 `544 + (17 - 9) / 31` = 544.258...이고, `TRUNC`로 소수를 버렸다.

`ADD_MONTHS`에는 말일 규칙이 있다. 1월 31일에 한 달을 더하면 2월 31일이 없으니 2월 말일(1981-02-28)이 된다. 여기까지는 PostgreSQL도 같다. 그런데 Oracle은 입력이 그달의 말일이면 결과도 말일로 맞춘다. `ADD_MONTHS(DATE '2024-02-29', 1)`은 2024-03-31이다. PostgreSQL의 `date '2024-02-29' + interval '1 month'`는 2024-03-29다. 월말 정산 쿼리를 옮길 때 조심할 부분이다.

`EXTRACT(YEAR FROM hiredate)`는 날짜에서 연, 월, 일을 숫자로 꺼낸다. Oracle의 `DATE`에서는 `YEAR`, `MONTH`, `DAY`만 꺼낼 수 있고, 시, 분, 초는 `TIMESTAMP`여야 한다. 이 밖에 `LAST_DAY(날짜)`(그달 말일), `NEXT_DAY(날짜, '금요일')`(다음 금요일)도 있다.

```sql
SELECT ename, EXTRACT(YEAR FROM hiredate) AS y, EXTRACT(MONTH FROM hiredate) AS m,
       EXTRACT(DAY FROM hiredate) AS d
FROM emp WHERE deptno = 10 ORDER BY empno;
```

```text
 ename  |  y   | m  | d
--------+------+----+----
 CLARK  | 1981 |  6 |  9
 KING   | 1981 | 11 | 17
 MILLER | 1982 |  1 | 23
(3 rows)
```

### 시각 때문에 사라지는 행

날짜 비교에서 가장 흔한 실수가 있다. Oracle에 `SYSDATE`로 넣은 행에는 시각이 붙어 있다. 그런데 `WHERE created = DATE '2026-10-17'`로 찾으면 자정(00:00:00)과 정확히 같은 행만 나온다. 행 세 개(10월 17일 00:00:00, 10월 17일 14:05:09, 10월 16일 23:59:59)로 실험하면 이렇다.

```sql
SELECT COUNT(*) FROM t WHERE created = DATE '2026-10-17';                                -- 1
SELECT COUNT(*) FROM t WHERE TRUNC(created) = DATE '2026-10-17';                         -- 2
SELECT COUNT(*) FROM t WHERE created >= DATE '2026-10-17' AND created < DATE '2026-10-18'; -- 2
```

PostgreSQL에서는 `TRUNC(created)` 자리에 `date_trunc('day', created)`를 써서 같은 값(1, 2, 2)이 나왔다. 두 번째와 세 번째는 결과가 같지만, 컬럼에 인덱스가 있으면 세 번째가 낫다. 컬럼에 함수를 씌우면 인덱스를 못 쓰기 때문이다. 실행 계획으로 확인하는 과정은 [형 변환 글](/posts/sqld-type-conversion)에서 본다.

## SQL Server 함수를 PostgreSQL에서 찾기

시험 문제는 Oracle과 SQL Server 사이를 오가지만, 실제로 손에 잡히는 DB가 PostgreSQL이면 이름부터 다르다. 자주 찾는 것만 짝지어 두면 이렇다.

| SQL Server | PostgreSQL 16 | 다른 점 |
|---|---|---|
| `DATEADD(month, 3, d)` | `d + interval '3 months'` | `date + interval`의 결과는 `timestamp`다 |
| `DATEADD(day, 7, d)` | `d + 7` | `date + 정수`는 `date` 그대로 |
| `DATEPART(year, d)`, `YEAR(d)` | `extract(year FROM d)` | 결과가 `numeric`이다 |
| `DATEPART(weekday, d)` | `extract(dow FROM d)` | `dow`는 일요일 0, `isodow`는 월요일 1. SQL Server는 `DATEFIRST` 설정을 따른다 |
| `DATETRUNC(month, d)` (2022부터) | `date_trunc('month', d)` | `date`를 넣으면 `timestamptz`가 나온다 |
| `CAST(ts AS date)`, `CAST(ts AS time)` | `ts::date`, `ts::time` | 같다 |
| `LEN(s)` | `length(s)`, `char_length(s)` | 글자 수. 바이트는 `octet_length` |
| `DATALENGTH(s)` | `octet_length(s)` | 바이트 수 |
| `SUBSTRING(s, 2, 3)` | `substring(s FROM 2 FOR 3)`, `substr(s, 2, 3)` | PostgreSQL은 길이를 빼도 된다 |
| `CEILING(n)`, `n % m` | `ceil(n)`, `mod(n, m)` 또는 `n % m` | 이름만 다르다 |

사원 데이터에 날짜 쪽을 돌려 보면 결과 타입이 섞여 나오는 게 보인다.

```sql
SELECT ename, hiredate,
       date_trunc('month', hiredate)::date AS month_start,  -- 그달 1일
       extract(year FROM hiredate)         AS y,
       extract(dow FROM hiredate)          AS dow,          -- 0 = 일요일
       hiredate + interval '3 months'      AS plus3m,       -- timestamp가 된다
       hiredate + 7                        AS plus7         -- date 그대로
FROM emp WHERE deptno = 10 ORDER BY empno;
```

```text
 ename  |  hiredate  | month_start |  y   | dow |       plus3m        |   plus7
--------+------------+-------------+------+-----+---------------------+------------
 CLARK  | 1981-06-09 | 1981-06-01  | 1981 |   2 | 1981-09-09 00:00:00 | 1981-06-16
 KING   | 1981-11-17 | 1981-11-01  | 1981 |   2 | 1982-02-17 00:00:00 | 1981-11-24
 MILLER | 1982-01-23 | 1982-01-01  | 1982 |   6 | 1982-04-23 00:00:00 | 1982-01-30
(3 rows)
```

`plus3m`에는 시각이 붙었고 `plus7`에는 없다. `date_trunc`도 `date`를 받으면 세션 시간대가 붙은 `timestamptz`를 돌려주니, 날짜만 원하면 `::date`로 다시 바꾼다. 날짜와 시각을 합친 `timestamp`에서 날짜만, 시각만 떼어 낼 때도 `::date`, `::time`이면 된다.

숫자 함수는 이름이 같아도 음수와 타입에서 갈린다. 앞에서 본 규칙을 PostgreSQL 값으로 한 줄에 모았다.

```sql
SELECT round(-2.5) AS rn, round(-2.5::float8) AS rf, ceil(-0.5) AS c, floor(-0.5) AS f,
       mod(-7, 3) AS m, -7 % 3 AS pct, abs(-7.25) AS a, round(7.25, 1) AS r1, trunc(-7.99) AS t;

SELECT length('데이터') AS len, octet_length('데이터') AS bytes,
       length('ab  '::char(4)) AS ch_len, length('ab  '::varchar) AS vc_len;
```

```text
 rn | rf | c | f  | m  | pct |  a   | r1  | t
----+----+---+----+----+-----+------+-----+----
 -3 | -2 | 0 | -1 | -1 |  -1 | 7.25 | 7.3 | -7
(1 row)

 len | bytes | ch_len | vc_len
-----+-------+--------+--------
   3 |     9 |      2 |      4
(1 row)
```

`numeric`의 `round(-2.5)`는 0에서 먼 -3, `float8`은 짝수인 -2다. `mod`와 `%`는 같고 부호는 첫 인자를 따른다. UTF-8에서 한글은 한 글자가 3바이트라 `length`는 3, `octet_length`는 9다. `varchar(10)`이 "10바이트"가 아니라 "10글자"라는 것도 여기서 나온다. `char(n)`은 끝 공백을 세지 않는다. SQL Server의 `LEN`이 끝 공백을 빼고 세는 것과 비슷하지만, `varchar`에서는 PostgreSQL이 공백까지 센다.

문자열을 이을 때 PostgreSQL의 `||`는 NULL이 하나라도 끼면 결과가 NULL이고, `concat`은 NULL을 건너뛴다(`'A' || NULL`은 NULL, `concat('A', NULL)`은 `A`). 구분자를 넣으며 이으려면 `concat_ws('-', 'A', NULL, 'C')`가 `A-C`를 돌려준다. Oracle과 반대로 움직이는 부분이라 [NULL 글](/posts/sqld-null-functions)에서 자세히 본다.

## 현장에서 함수 결과가 조용히 달라지는 순간

함수 문제는 시험에서는 값 하나를 고르는 일이지만, 현장에서는 에러 없이 틀린 값이 쌓이는 일이다. 자주 만나는 경우를 PostgreSQL 16에서 돌려 본다.

첫째, 금액을 `double precision`(float)에 담은 경우다. 0.1을 열 번 더해도 1이 안 되고, 반올림 규칙도 `numeric`과 다르다. PostgreSQL의 `round`는 `numeric`에서는 0에서 먼 쪽으로 반올림하지만, `double precision`에서는 가장 가까운 짝수로 반올림한다.

```sql
CREATE TABLE pay (id integer, amount_f double precision, amount_n numeric(12,2));
INSERT INTO pay SELECT i, 0.1, 0.1 FROM generate_series(1, 10) AS i;

-- 0.1을 열 번 더한 합계
SELECT sum(amount_f) AS f_total, sum(amount_n) AS n_total FROM pay;

-- 2.5를 반올림
SELECT round(2.5::numeric) AS num_25, round(2.5::float8) AS float_25,
       round(3.5::float8) AS float_35, round(0.125::numeric, 2) AS num_0125;
```

```text
      f_total       | n_total
--------------------+---------
 0.9999999999999999 |    1.00
(1 row)

 num_25 | float_25 | float_35 | num_0125
--------+----------+----------+----------
      3 |        2 |        4 |     0.13
(1 row)
```

`float_25`가 2, `float_35`가 4다. 2.5는 짝수인 2로, 3.5는 짝수인 4로 간다. 정산 금액이 1원씩 어긋난다는 문의가 오면 컬럼 타입부터 본다(`\d pay`). 돈, 수량, 비율처럼 정확해야 하는 값은 `numeric`(Oracle은 `NUMBER`)에 담는다. 위의 `ROUND` 실습에서 본 1.005 문제와 같은 뿌리다.

둘째, 다른 DB에서 옮겨 온 쿼리다. 처음 장면의 두 열을 PostgreSQL에서 그대로 돌리면 이렇다.

```sql
-- Oracle의 SUBSTR('CLARK', -3)과 ADD_MONTHS(DATE '2024-02-29', 1)을 옮긴 모양
SELECT substr('CLARK', -3) AS pg_substr, right('CLARK', 3) AS pg_right;

SELECT date '2024-02-29' + interval '1 month' AS pg_add_month,
       (date_trunc('month', date '2024-02-29') + interval '2 month' - interval '1 day')::date AS month_end;
```

```text
 pg_substr | pg_right
-----------+----------
 CLARK     | ARK
(1 row)

    pg_add_month     | month_end
---------------------+------------
 2024-03-29 00:00:00 | 2024-03-31
(1 row)
```

`substr`은 음수 위치를 뒤에서 세지 않아 이름 전체가 나왔고, `right`로 바꿔야 Oracle과 같다. `interval '1 month'`는 Oracle의 말일 규칙이 없어서 3월 29일이 됐다. "다음 달 말일"이 필요하면 `month_end`처럼 그달 1일로 내린 뒤 두 달을 더하고 하루를 빼는 식으로 직접 쓴다. 이런 차이는 문법 변환 도구가 잡아 주지 않는다. 옮기기 전과 후에 같은 데이터로 결과를 뽑아 비교하는 테스트가 가장 확실하다.

셋째, 0으로 나누기다. Oracle의 `MOD(17, 0)`은 17을 돌려주지만 PostgreSQL은 쿼리 전체를 멈춘다.

```sql
SELECT mod(17, 0);
```

```text
ERROR:  division by zero
```

배치가 새벽에 이 에러로 멈췄다면 나누는 값이 0이 될 수 있는 행부터 찾는다. 0을 NULL로 바꿔 나누는 `NULLIF`는 [NULL 글](/posts/sqld-null-functions)에서 본다.

## SQLD 시험 포인트

함수 문제는 "결과로 옳은 것은?" 형식으로 짧은 쿼리를 주고 값을 고르게 한다. 외울 건 많지 않고, 아래 함정에서 대부분 나온다.

- 단일행 함수는 행 수를 바꾸지 않고 `SELECT`, `WHERE`, `ORDER BY` 어디에나 쓴다. 중첩하면 안쪽부터 계산한다. Oracle은 테이블 없는 계산에 `FROM DUAL`을 붙인다.
- `SUBSTR`의 음수 시작 위치는 뒤에서 센다. `INSTR`은 없으면 0이다. Oracle `CONCAT`은 인자 두 개다.
- `ROUND(n, -1)`은 일의 자리에서 반올림한다. `TRUNC`는 0 쪽으로, `FLOOR`는 아래쪽으로 간다(`FLOOR(-3.1)` = -4). `MOD`의 부호는 첫 인자를 따른다.
- 날짜 + 숫자는 일 단위다. 날짜 - 날짜는 일수(숫자)다. `MONTHS_BETWEEN(뒤, 앞)` 순서로 써야 양수다.
- SQL Server 대응: `+`(이어 붙이기), `LEN`, `SUBSTRING`, `CHARINDEX`, `CEILING`, `%`, `GETDATE()`, `DATEADD`, `DATEDIFF`. `DUAL`이 없다.

## 면접에서 나올 만한 질문

### 단일행 함수와 다중행 함수는 어떻게 다른가요?

단일행 함수는 행마다 한 번씩 실행되어 행마다 결과 하나를 돌려주고, 입력 행 수와 출력 행 수가 같다. `UPPER`, `SUBSTR`, `ROUND`, `NVL`이 여기에 속하고 `SELECT`, `WHERE`, `ORDER BY` 어디에나 쓸 수 있다. 다중행 함수는 여러 행을 받아 값 하나로 줄이는 집계 함수로, `WHERE`에는 쓸 수 없고 `SELECT`, `HAVING`, `ORDER BY`에 쓴다.

### ROUND, TRUNC, FLOOR는 음수에서 어떻게 다른가요?

`ROUND`는 0에서 먼 쪽으로 반올림해서 `ROUND(-1.5)`가 -2다. `TRUNC`는 0 쪽으로 소수를 버려서 `TRUNC(-1.5)`가 -1이고, `FLOOR`는 그 수보다 작거나 같은 가장 큰 정수라 `FLOOR(-3.1)`이 -4다. 자릿수 인자가 음수면 소수점 왼쪽으로 가서 `ROUND(1250, -2)`는 1300이다. PostgreSQL의 `round`는 `double precision`에서 짝수 쪽으로 반올림하니 금액은 `numeric`에 담는다.

### 날짜 컬럼에 TRUNC를 씌워 하루치를 찾으면 무엇이 문제인가요?

결과는 맞지만 컬럼에 함수가 씌워져서 그 컬럼의 인덱스를 쓰지 못한다. Oracle의 `DATE`에는 시각이 있어서 `created = DATE '2026-10-17'`로는 자정 행만 나오니 `TRUNC`를 쓰고 싶어지는데, `created >= DATE '2026-10-17' AND created < DATE '2026-10-18'`처럼 범위로 쓰면 같은 결과를 인덱스로 찾는다.

### ADD_MONTHS와 MONTHS_BETWEEN은 왜 숫자 더하기와 따로 있나요?

달마다 길이가 28일부터 31일까지 달라서 일수로는 "한 달 뒤"를 정확히 셀 수 없기 때문이다. `ADD_MONTHS`는 n달 뒤를, 없는 날짜면 그달 말일을 돌려주고, 입력이 말일이면 결과도 말일로 맞춘다. `MONTHS_BETWEEN(뒤, 앞)`은 개월 수를 소수로 돌려주고 순서를 바꾸면 음수다. PostgreSQL의 `interval '1 month'`에는 말일 규칙이 없어서 월말 정산을 옮길 때 조심한다.

### Oracle에서 PostgreSQL로 옮길 때 함수 쪽에서 조심할 점은요?

에러가 나는 것보다 조용히 다른 값을 내는 것이 더 위험하다. `SUBSTR`의 음수 시작 위치는 PostgreSQL에서 뒤에서 세지 않아 `right`로 바꿔야 하고, `ADD_MONTHS`의 말일 규칙은 직접 식으로 써야 한다. `MOD(n, 0)`은 Oracle은 n을, PostgreSQL은 에러를 낸다. `INSTR`, `DUAL`, `NVL`, `DECODE`처럼 없는 함수도 있다. 같은 데이터로 결과를 비교하는 테스트를 함께 옮긴다.

### LTRIM의 두 번째 인자는 어떻게 동작하나요?

문자열이 아니라 문자 집합으로 읽힌다. `LTRIM('xyxSMITH', 'xy')`는 왼쪽에서 x나 y를 만나는 동안 계속 지워서 `SMITH`가 된다. 가운데 문자는 건드리지 않고, `TRIM('0' FROM '0012300')`처럼 양쪽을 지우면 숫자 끝의 0까지 사라져 `123`이 되니 숫자 문자열을 다룰 때 조심한다.

### SQL Server의 DATEADD와 DATEPART는 PostgreSQL에서 무엇으로 쓰나요?

더하기는 `interval`, 꺼내기는 `extract`, 자르기는 `date_trunc`로 쓴다. `DATEADD(month, 3, d)`는 `d + interval '3 months'`인데, `date`에 `interval`을 더하면 `timestamp`가 되니 날짜가 필요하면 `::date`로 돌린다. 요일은 `extract(dow ...)`가 일요일 0이라 SQL Server의 `DATEPART(weekday, ...)`와 번호가 다르다. 옮길 때는 같은 날짜 몇 개로 두 쪽 결과를 비교해 본다.
