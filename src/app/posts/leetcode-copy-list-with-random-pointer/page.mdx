평범한 연결 리스트를 복사하는 건 쉽다. 앞에서부터 걸으며 같은 값의 노드를 만들고 이어 붙이면 된다. 그런데 노드마다 화살표가 하나 더 있고, 그 화살표가 리스트 안의 아무 노드나 가리킬 수 있다면 이야기가 달라진다. 화살표가 가리키는 노드가 아직 만들어지지 않았을 수 있기 때문이다.

[LeetCode 138. Copy List with Random Pointer](https://leetcode.com/problems/copy-list-with-random-pointer/)가 이 문제다. 위치를 세어 같은 자리를 찾는 느린 풀이부터 배열, 해시맵 두 번 훑기와 한 번 훑기, 재귀, 그리고 원본 사이에 복사본을 끼워 넣어 장부 없이 끝내는 풀이까지 여섯 가지를 따라간다. 해시맵으로 "원본 → 복사본"을 기억하는 방법은 그래프를 복사하는 [Clone Graph](/posts/leetcode-clone-graph)와 같은 생각이다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 화살표가 둘인 리스트를 통째로 복사한다

노드마다 `val`, `next`, `random`이 있다. `next`는 보통의 다음 노드이고, `random`은 리스트 안의 아무 노드나 가리키거나 `null`이다. 자기 자신을 가리켜도 되고, 여러 노드가 같은 노드를 가리켜도 된다. 이 리스트를 깊은 복사(deep copy)해서 새 리스트의 머리를 돌려준다. 깊은 복사란 노드를 전부 새로 만들고, 새 노드의 `next`와 `random`도 모두 새 노드만 가리키게 한다는 뜻이다. 복사본에서 원본 노드를 가리키는 화살표가 하나라도 있으면 틀린다.

입력과 출력은 `[값, random이 가리키는 노드의 위치]` 쌍의 목록으로 보여 준다. 이 글에서 계속 쓸 예시다.

```text
[[7,null],[13,0],[11,3],[10,1]]

  위치:      0        1        2        3
  next:      7  →    13  →    11  →    10  →  null
  random:  null      7       10       13
```

13은 위치 0인 7을, 11은 위치 3인 10을, 10은 위치 1인 13을 가리킨다. 7의 `random`은 `null`이다. 복사본도 이 표와 똑같이 나와야 한다.

노드는 0개에서 1000개, 값은 -10^4에서 10^4 사이다. 1000개라 O(n²)도 백만 번이라 시간 안에 들어온다. 그래도 `n`이 커지면 차이가 크게 벌어진다. 그리고 1000은 재귀 풀이에 아슬아슬한 숫자다. 뒤에서 직접 확인한다.

## 복사본의 random이 갈 곳을 모른다

`next`만 복사한다면 걸으면서 만들고 잇기만 하면 된다. 문제는 `random`이다. 13의 복사본을 만들 때 그 `random`은 "7의 복사본"을 가리켜야 한다. 7의 복사본은 이미 만들었으니 어딘가 있다. 그런데 11의 복사본은 "10의 복사본"을 가리켜야 하는데, 10은 아직 만들지 않았다.

그리고 더 근본적인 어려움이 있다. 원본 13의 `random`을 보면 원본 7이 나온다. 원본 7에서 "7의 복사본"으로 가는 길이 없다. 그래서 모든 풀이는 결국 하나의 질문에 답하는 방식이 다르다. 원본 노드를 받으면 그 복사본을 어떻게 찾느냐다.

값으로 찾으면 안 된다. 값이 같은 노드가 여러 개 있을 수 있어서다. `[[3,null],[3,0],[3,null]]`처럼 모두 3이면 값만 보고는 어느 노드의 복사본인지 알 수 없다. 찾는 기준은 노드 그 자체, 곧 노드의 주소여야 한다.

## 위치를 세어 같은 자리를 찾기

가장 먼저 떠오르는 방법은 "위치"를 다리로 쓰는 것이다. 원본 13의 `random`이 원본 7이라면, 원본 머리에서 걸어 7이 몇 번째인지 센다. 0번째다. 그러면 복사본 머리에서 0칸 걸은 노드가 7의 복사본이다.

```js
function copyRandomList(head) {
  // 1) next만 따라 값을 복사한다
  const dummy = new Node(0);
  let t = dummy;
  for (let p = head; p; p = p.next) t = t.next = new Node(p.val);

  // 2) 노드마다 random의 위치를 세고, 복사본에서 같은 칸을 찾는다
  let p = head, c = dummy.next;
  while (p) {
    if (p.random) {
      let k = 0;
      for (let q = head; q !== p.random; q = q.next) k++; // random이 몇 번째인지
      let r = dummy.next;
      for (let i = 0; i < k; i++) r = r.next;             // 복사본에서 같은 자리
      c.random = r;
    }
    p = p.next;
    c = c.next;
  }
  return dummy.next;
}
```

비교는 `q !== p.random`으로 노드 자체를 비교한다. 값이 같아도 다른 노드는 다르게 본다. 위치는 노드마다 하나뿐이라 중복 값 문제도 없다.

맞기는 한데 노드 하나마다 원본과 복사본을 최대 n칸씩 걷는다. 시간 O(n²), 추가 공간 O(1)이다(복사본 자체는 답이라 공간에 세지 않는다). 노드 1000개에서 약 5ms, 1만 개에서 약 224ms가 걸렸다. 길이가 열 배가 되자 시간이 마흔 배 넘게 늘었다. 위치를 매번 걸어서 세는 게 문제다. 위치를 한 번에 알 수 있으면 이 걸음이 사라진다.

## 노드를 배열에 담고 위치 장부를 만들기

원본 노드를 배열에 담고, "노드 → 위치"를 해시맵에 적어 둔다. 복사본도 배열로 만들면 위치 하나로 양쪽을 오갈 수 있다. 원본 `olds[i].random`의 위치를 장부에서 찾고, 같은 위치의 `news[j]`를 잇는다.

```js
function copyRandomList(head) {
  const olds = [];
  for (let p = head; p; p = p.next) olds.push(p);
  const index = new Map(olds.map((n, i) => [n, i])); // 원본 노드 → 위치

  const news = olds.map((n) => new Node(n.val));
  news.forEach((n, i) => {
    n.next = news[i + 1] ?? null;
    const r = olds[i].random;
    n.random = r ? news[index.get(r)] : null;         // 같은 위치의 복사본
  });
  return news[0] ?? null;
}
```

`Map`의 키로 노드 객체를 그대로 쓴다. 자바스크립트 `Map`은 객체 키를 참조로 비교하니, 값이 같은 다른 노드는 다른 키가 된다. 시간 O(n), 공간은 배열 둘과 장부 하나로 O(n)이다. 그런데 장부에 위치를 적고 다시 배열에서 꺼내는 건 한 단계를 더 거친 것이다. 장부에 위치 대신 복사본을 바로 적으면 배열이 필요 없다.

## 원본에서 복사본으로 가는 장부

해시맵에 "원본 노드 → 그 복사본"을 적어 둔다. 그러면 원본의 어느 노드를 보든 장부에서 바로 복사본을 꺼낼 수 있다. 앞에서 던진 질문, 원본 노드를 받으면 복사본을 어떻게 찾느냐에 가장 직접적으로 답하는 방법이다.

두 번 훑는다. 첫 번째에는 노드만 만들어 장부에 적는다. 두 번째에는 모든 복사본이 이미 있으니, 화살표를 장부에서 꺼내 잇기만 한다. 10의 복사본이 아직 없다는 문제가 첫 번째 훑기에서 사라진다.

```js
function copyRandomList(head) {
  const map = new Map(); // 원본 노드 → 복사본 노드

  // 1) 노드만 만든다
  for (let p = head; p; p = p.next) map.set(p, new Node(p.val));

  // 2) 화살표를 잇는다. 원본이 가리키는 노드의 복사본을 장부에서 꺼낸다
  for (let p = head; p; p = p.next) {
    const c = map.get(p);
    c.next = map.get(p.next) ?? null;     // p.next가 null이면 undefined → null
    c.random = map.get(p.random) ?? null;
  }
  return map.get(head) ?? null;
}
```

아래 그림은 첫 번째 훑기가 끝난 상태다. 위 줄이 원본, 아래 줄이 복사본이고, 세로 점선이 장부에 적힌 짝이다. 복사본끼리는 아직 아무 화살표도 없다. 두 번째 훑기에서 원본의 화살표를 하나씩 보고, 장부의 세로선을 따라 내려가 같은 모양으로 잇는다.

예를 들어 두 번째 훑기에서 원본 11을 볼 때, `11.random`은 원본 10이다. 장부에서 10을 찾으면 10'이 나오니 `11'.random = 10'`이다. 원본 13의 `random`은 7이고 장부에서 7'을 꺼낸다. 이렇게 원본의 모양을 복사본에 그대로 옮긴다.

시간 O(n), 공간 O(n)이다. 1만 개 노드에서 약 7ms로 위치를 세는 풀이보다 서른 배쯤 빠르다. 면접에서 가장 먼저 내기 좋은 답이다. 코드가 짧고, 왜 맞는지 설명하기도 쉽다.

`p.next`가 `null`일 때 `map.get(null)`은 `undefined`라서 `?? null`로 바꿔 준다. Python이라면 장부에 `None: None`을 미리 넣어 두는 방법을 많이 쓴다(`old_to_new = {None: None}`). 그러면 `old_to_new[p.random]`을 분기 없이 쓸 수 있다.

## 처음 만나는 순간 만들어 두기

두 번 훑지 않고 한 번에 끝낼 수도 있다. 노드를 볼 때 그 노드, 그 `next`, 그 `random`의 복사본이 장부에 없으면 그 자리에서 만들어 적는다. 있으면 꺼내 쓴다. "없으면 만들고 있으면 꺼낸다"를 함수 하나로 묶으면 코드가 깔끔하다.

```js
function copyRandomList(head) {
  const map = new Map();
  // 원본 노드를 받아 복사본을 돌려준다. 없으면 지금 만든다
  const get = (n) => {
    if (!n) return null;
    if (!map.has(n)) map.set(n, new Node(n.val));
    return map.get(n);
  };

  for (let p = head; p; p = p.next) {
    const c = get(p);
    c.next = get(p.next);
    c.random = get(p.random); // 아직 안 지나간 노드라도 미리 만들어 둔다
  }
  return get(head);
}
```

11을 볼 때 `11.random`인 10은 아직 지나가지 않았지만 `get`이 10'을 미리 만들어 장부에 적는다. 나중에 10에 도착하면 `get(10)`이 새로 만들지 않고 그 10'을 꺼낸다. 같은 원본에서 복사본이 두 개 생기는 일이 없다.

시간 O(n), 공간 O(n)으로 두 번 훑기와 같다. 리스트를 한 번만 걷는다는 차이뿐이고, 해시맵 조회 횟수는 비슷하다. 어느 쪽을 써도 되는데, 두 번 훑기가 단계가 분명해서 설명하기는 더 쉽다.

## 재귀로 따라가며 복사하기

리스트를 노드와 화살표로 된 그래프로 보면 이 문제는 그래프 복사다. 노드 하나를 복사하는 함수가 `next`와 `random`을 재귀로 복사하면 된다. 장부는 이미 복사한 노드를 다시 복사하지 않게 막는 역할을 한다. [Clone Graph](/posts/leetcode-clone-graph)의 DFS 풀이와 같은 모양이다.

```js
function copyRandomList(head) {
  const map = new Map();
  function clone(n) {
    if (!n) return null;
    if (map.has(n)) return map.get(n); // 이미 만들었으면 그대로
    const c = new Node(n.val);
    map.set(n, c);                     // 재귀 전에 먼저 적어야 고리에서 멈춘다
    c.next = clone(n.next);
    c.random = clone(n.random);
    return c;
  }
  return clone(head);
}
```

장부에 적는 순서가 중요하다. `map.set`을 재귀 호출 뒤에 하면, 자기 자신을 가리키는 `random`이나 서로를 가리키는 노드에서 끝없이 재귀한다.

시간 O(n), 공간 O(n)인데, 공간에 콜 스택이 더해진다. `next`를 따라 끝까지 재귀가 내려가니 깊이가 노드 수만큼 된다. 직접 재 보니 Node.js는 1000개는 됐지만 1만 개에서 `RangeError`가 났다. Python은 더 심하다. 기본 재귀 한도가 1000이라, 노드 900개는 됐고 문제의 최대 크기인 1000개에서 `RecursionError: maximum recursion depth exceeded`가 났다. 제약 안의 입력에서 터지니 Python으로는 이 풀이를 그대로 내면 안 된다. `sys.setrecursionlimit`을 올리는 방법이 있지만, 반복 풀이를 쓰는 편이 낫다.

## 원본 바로 뒤에 복사본을 끼워 넣기

여기까지 빠른 풀이는 모두 O(n) 크기의 장부를 썼다. 장부가 하는 일은 "원본 X의 복사본은 어디 있나"에 답하는 것 하나다. 이 답을 리스트의 모양 자체에 숨겨 두면 장부가 필요 없다. 원본 노드마다 바로 뒤에 그 복사본을 끼워 넣는 것이다.

```text
원본:        7 → 13 → 11 → 10
끼운 뒤:     7 → 7' → 13 → 13' → 11 → 11' → 10 → 10'
```

이제 어떤 원본 X의 복사본은 언제나 `X.next`다. 장부의 역할을 `next` 화살표가 대신한다. 그러면 복사본의 `random`은 한 줄로 정해진다.

```text
X'.random = X.random.next      (X.random이 null이면 null)
```

X의 `random`이 Y라면, X'의 `random`은 Y'이어야 하고, Y'은 Y 바로 뒤에 있다. 마지막으로 섞인 리스트에서 원본과 복사본을 번갈아 떼어 내어 두 리스트로 나눈다. 원본은 원래 모양으로 돌아가고 복사본이 따로 남는다.

1. 끼우기: 원본 노드 `p`마다 `p.next = new Node(p.val, p.next)`로 바로 뒤에 복사본을 넣는다.
2. random 잇기: 원본 `p`마다 `p.next.random = p.random ? p.random.next : null`.
3. 떼어 내기: 원본 `p`와 그 복사본 `c = p.next`마다 `p.next = c.next`, `c.next = c.next ? c.next.next : null`로 고친다.

2단계와 3단계를 따로 도는 데 이유가 있다. random을 이을 때는 모든 원본 뒤에 복사본이 붙어 있어야 `X.random.next`가 복사본이다. 떼어 내기를 함께 하면 이미 떼어 낸 원본의 `next`는 다시 원본을 가리키니, 그쪽을 `random`으로 가리키는 복사본이 원본 노드를 잇게 된다. 뒤의 "틀리는 자리"에서 실제로 돌려 본다.

```js
function copyRandomList(head) {
  if (!head) return null;

  // 1) 끼우기: A → A' → B → B' …
  for (let p = head; p; p = p.next.next) {
    p.next = new Node(p.val, p.next);
  }

  // 2) random 잇기: X'.random = X.random.next
  for (let p = head; p; p = p.next.next) {
    p.next.random = p.random ? p.random.next : null;
  }

  // 3) 떼어 내기: 원본과 복사본을 번갈아 나눈다
  const newHead = head.next;
  for (let p = head; p; p = p.next) {
    const c = p.next;
    p.next = c.next;                       // 원본은 다음 원본으로
    c.next = c.next ? c.next.next : null;  // 복사본은 다음 복사본으로
  }
  return newHead;
}
```

1, 2단계는 `p = p.next.next`로 원본만 밟는다. 원본 바로 뒤는 언제나 복사본이고, 그 뒤가 다음 원본이기 때문이다. 3단계는 `p.next`를 이미 다음 원본으로 고쳐 두었으니 `p = p.next`로 한 칸만 간다.

시간 O(n), 추가 공간 O(1)이다. 새로 만드는 건 답이 되는 복사본 노드뿐이다. 1만 개 노드에서 약 1.3ms로 해시맵 풀이보다도 빨랐다. 해시맵 조회가 없고 메모리를 덜 쓰기 때문이다. 대신 실행하는 동안 원본 리스트를 잠시 바꾼다. 다른 스레드가 같은 리스트를 읽고 있다면 쓸 수 없는 방법이다.

### Python과 Java로 쓰면

```python
class Solution:
    def copyRandomList(self, head: 'Optional[Node]') -> 'Optional[Node]':
        if not head:
            return None
        # 1) 원본 노드마다 바로 뒤에 복사본을 끼운다: A → A' → B → B' …
        p = head
        while p:
            p.next = Node(p.val, p.next)
            p = p.next.next
        # 2) 복사본의 random은 원본 random의 바로 뒤 노드다
        p = head
        while p:
            p.next.random = p.random.next if p.random else None
            p = p.next.next
        # 3) 두 리스트를 떼어 내고 원본을 되돌린다
        new_head = head.next
        p = head
        while p:
            c = p.next
            p.next = c.next
            c.next = c.next.next if c.next else None
            p = p.next
        return new_head
```

Java는 LeetCode가 주는 `Node`에 `(int val)` 생성자만 있어서 끼울 때 두 줄로 나눈다.

```java
class Solution {
    public Node copyRandomList(Node head) {
        if (head == null) return null;
        for (Node p = head; p != null; p = p.next.next) {      // 1) 끼우기
            Node c = new Node(p.val);
            c.next = p.next;
            p.next = c;
        }
        for (Node p = head; p != null; p = p.next.next) {      // 2) random 잇기
            p.next.random = (p.random != null) ? p.random.next : null;
        }
        Node newHead = head.next;
        for (Node p = head; p != null; p = p.next) {           // 3) 떼어 내기
            Node c = p.next;
            p.next = c.next;
            c.next = (c.next != null) ? c.next.next : null;
        }
        return newHead;
    }
}
```

세 언어 모두 복사본과 원본을 다시 읽어 같은 표가 나오는지 확인했다.

```text
[[7,null],[13,0],[11,3],[10,1]]  →  [[7,null],[13,0],[11,3],[10,1]]   원본 그대로
[[1,1],[2,1]]                    →  [[1,1],[2,1]]                     원본 그대로
[]                               →  []
```

해시맵 풀이를 Java로 쓸 때는 `HashMap<Node, Node>`를 쓴다. LeetCode의 `Node`는 `equals`와 `hashCode`를 덮어쓰지 않아서 주소로 비교된다. 만약 값으로 `equals`를 덮어쓴 노드 클래스라면 값이 같은 노드가 한 키로 합쳐지니 `IdentityHashMap`을 써야 한다. Python의 `dict`도 직접 만든 클래스는 기본으로 `id`로 해시하니 노드를 키로 써도 된다.

## 여섯 풀이를 한눈에

| 풀이 | 시간 | 추가 공간 | 언제 고르나 |
|---|---|---|---|
| 위치를 세어 찾기 | O(n²) | O(1) | 해시맵을 쓸 수 없을 때의 출발점. 1만 개면 느려진다 |
| 배열 + 위치 장부 | O(n) | O(n) | 위치 정보를 따로 쓸 일이 있을 때 |
| 해시맵 두 번 훑기 | O(n) | O(n) | 기본 답. 설명하기 가장 쉽다 |
| 해시맵 한 번 훑기 | O(n) | O(n) | 한 번만 걷고 싶을 때. 일하는 양은 두 번 훑기와 비슷하다 |
| 재귀 DFS | O(n) | O(n) + 콜 스택 | 그래프 복사로 일반화할 때. Python은 1000개에서 터진다 |
| 끼우고 떼어 내기 | O(n) | O(1) | 추가 공간 없이 하라는 요구가 올 때. 원본을 잠시 바꾼다 |

면접에서는 해시맵 두 번 훑기를 먼저 내고, "장부 없이 할 수 있나"라는 질문이 오면 "장부가 하는 일은 원본에서 복사본으로 가는 것인데, 복사본을 원본 바로 뒤에 두면 `next`가 그 일을 한다"로 넘어가면 된다.

## 복사본이 원본을 가리키는 순간

이 문제의 오답은 "출력 모양은 맞는데 깊은 복사가 아니다"인 경우가 많다. 직접 돌려 본 틀린 코드 네 개다.

### random을 원본에서 그대로 가져오면

해시맵 풀이에서 `c.random = map.get(p.random)` 대신 `c.random = p.random`으로 쓰는 실수다. `next`는 복사본끼리 이었으니 리스트를 걸어 보면 값은 제대로 나온다. 그런데 복사본의 `random`이 전부 원본 노드를 가리킨다. 복사본 안에서 random 위치를 찾으면 하나도 찾을 수 없다.

```text
c.random = p.random   →  [[7,null],[13,?],[11,?],[10,?]]   복사본 안에 random 대상이 없다
```

LeetCode 채점기는 복사본이 원본 노드를 가리키면 오답으로 처리한다. 화살표 두 개를 모두 장부를 거쳐 이어야 한다.

### 장부의 키를 값으로 잡으면

`map.set(p.val, new Node(p.val))`처럼 값을 키로 쓰면, 값이 같은 노드가 한 칸에 겹친다. `[[3,null],[3,0],[3,null]]`을 넣으면 장부에 노드가 하나만 남고, 마지막 노드의 `next`가 `null`로 덮어써져서 복사본이 노드 하나짜리가 된다. 키는 노드 자체여야 한다.

### random 잇기와 떼어 내기를 한 번에 돌면

끼우기 풀이에서 반복문 하나를 줄이려고 2단계와 3단계를 합친 코드다.

```js
for (let p = head; p; p = p.next) {
  const c = p.next;
  c.random = p.random ? p.random.next : null; // 이미 떼어 낸 노드라면?
  p.next = c.next;
  c.next = c.next ? c.next.next : null;
}
```

```text
[[7,null],[13,0],[11,3],[10,1]]  →  [[7,null],[13,?],[11,3],[10,?]]
```

13'의 `random`을 정할 때 13의 `random`인 7은 이미 떼어져서 `7.next`가 원본 13이다. 그래서 13'이 원본 13을 가리킨다. 10'도 마찬가지로 이미 떼어 낸 13을 거쳐 원본 11을 가리킨다. 11'만 맞은 건 11이 가리키는 10이 아직 떼어지지 않아서다. 앞쪽을 가리키는 `random`이 있으면 틀린다. 반복문을 따로 두는 게 정답이다.

### 복사본만 떼어 내고 원본을 두면

3단계에서 복사본의 `next`만 고치고 원본의 `next`를 되돌리지 않은 코드다. 복사본은 `[[7,null],[13,0],[11,3],[10,1]]`로 맞게 나온다. 하지만 원본 머리에서 걸어 보면 `7, 7, 13, 11, 10`이 나온다. 원본 7이 아직 7'을 가리키고 있어서, 원본을 따라가면 곧바로 복사본 줄로 넘어간다. 함수가 입력을 망가뜨린 셈이다. 위 실습 칸은 이 경우 `"원본이 바뀌었다"`를 돌려준다. 원본의 `p.next = c.next`가 떼어 내기의 절반이다.

빈 리스트도 따로 본다. 끼우기 풀이는 `head.next`를 읽기 때문에 맨 앞의 `if (!head) return null`이 없으면 빈 입력에서 터진다. 해시맵 풀이는 `map.get(null) ?? null`이 `null`이라 따로 처리하지 않아도 된다.

## 장부로 복사하는 다른 구조들

### 그래프를 복사하라면

[Clone Graph](/posts/leetcode-clone-graph)는 노드마다 이웃 목록이 있는 그래프를 복사한다. 이웃이 몇 개든 "원본 → 복사본" 장부와 BFS 또는 DFS로 똑같이 푼다. 끼워 넣기 풀이는 리스트라서 가능했다. 복사본을 둘 "바로 뒤"라는 자리가 있어야 하는데, 그래프에는 그런 자리가 없다. 그래서 그래프 복사는 해시맵 풀이가 일반적인 답이다.

### 트리의 노드에 random이 있다면

LeetCode 1485 Clone Binary Tree With Random Pointer(프리미엄 문제)는 이진 트리 노드에 `random`이 하나 더 있다. 트리를 DFS로 돌며 장부에 복사본을 만들고, 두 번째 순회에서 `random`을 잇는다. 이 글의 해시맵 두 번 훑기를 트리 순회로 바꾼 것이다.

### 자바스크립트 객체를 깊은 복사하라면

실무에서 비슷한 일을 만나는 곳이 자바스크립트 객체의 깊은 복사다. `JSON.parse(JSON.stringify(obj))`는 서로를 가리키는 객체를 만나면 `TypeError: Converting circular structure to JSON`으로 멈춘다. `structuredClone`은 내부에서 이 글의 장부와 같은 일을 해서 고리와 공유된 참조를 그대로 복사한다. 직접 돌려 보면 `a.random = b`, `b.random = a`인 객체를 복사해도 복사본끼리 서로를 가리킨다. 다만 클래스 인스턴스는 프로토타입이 사라져 평범한 객체가 된다(`instanceof Node`가 `false`). 메서드가 필요한 객체라면 직접 복사 함수를 짜야 하고, 그때 이 문제의 해시맵 풀이가 그대로 쓰인다.

### 원본을 잠시도 바꾸면 안 된다면

여러 스레드가 같은 리스트를 읽고 있거나, 원본이 읽기 전용이면 끼워 넣기 풀이를 쓸 수 없다. 이때는 해시맵 풀이로 돌아간다. 추가 공간 O(1)은 "원본을 잠시 고쳐 써도 된다"는 조건 위에서만 성립한다. 면접에서 공간을 줄였다고 말할 때 이 조건도 함께 말하면 좋다.

## 장부를 리스트 안에 숨긴다

복사본의 `random`을 잇는 게 어려운 이유는 원본 노드에서 그 복사본으로 가는 길이 없어서다. 해시맵으로 "원본 → 복사본" 장부를 만들어 두 번 훑으면 O(n) 시간, O(n) 공간에 바로 풀린다. 장부를 없애려면 복사본을 원본 바로 뒤에 끼워 넣어 `X.next`가 장부 노릇을 하게 한다. 그러면 `X'.random = X.random.next`로 화살표가 정해지고, 마지막에 두 리스트를 번갈아 떼어 내면 O(1) 추가 공간으로 끝난다. random 잇기와 떼어 내기를 따로 돌고, 원본의 `next`도 되돌리는 것만 지키면 된다.

## 면접에서 나올 만한 질문

### 이 문제가 일반 연결 리스트 복사보다 어려운 이유는 무엇인가요?

`random`이 리스트의 아무 노드나 가리킬 수 있어서, 복사본을 만들 때 가리킬 대상의 복사본이 아직 없거나 어디 있는지 모른다. 원본 노드에서 그 복사본으로 가는 길이 없다는 게 근본 문제다. 모든 풀이는 이 "원본 → 복사본" 연결을 해시맵, 위치, 리스트 모양 중 하나로 만든다.

### 해시맵 풀이를 설명해 보세요.

원본 노드를 키로, 복사본을 값으로 하는 해시맵을 쓴다. 첫 번째 훑기에서 노드만 만들어 적고, 두 번째 훑기에서 `copy.next = map[p.next]`, `copy.random = map[p.random]`으로 잇는다. 모든 복사본이 먼저 만들어져 있으니 아직 없는 노드 문제가 사라진다. 시간과 공간 모두 O(n)이다.

### 해시맵의 키를 노드의 값으로 쓰면 안 되나요?

안 된다. 값이 같은 노드가 여러 개 있을 수 있어서 서로 다른 노드가 한 칸에 겹친다. 모두 3인 리스트를 넣으면 복사본이 노드 하나로 줄어든다. 키는 노드 객체 자체, 곧 주소여야 한다. Java라면 노드가 `equals`를 값으로 덮어쓰지 않았는지도 확인한다.

### 추가 공간 O(1)로 풀 수 있나요?

원본 노드마다 바로 뒤에 복사본을 끼워 넣으면 된다. 그러면 X의 복사본은 언제나 `X.next`라서 `X'.random = X.random.next`로 정할 수 있다. 마지막에 원본과 복사본을 번갈아 떼어 내면서 원본을 되돌린다. 실행 중에 원본을 잠시 바꾸기 때문에 다른 곳에서 원본을 동시에 읽는다면 쓸 수 없다.

### 끼워 넣기 풀이에서 random 잇기와 떼어 내기를 한 번에 하면 어떻게 되나요?

앞쪽 노드를 가리키는 `random`이 있으면 틀린다. 이미 떼어 낸 원본은 `next`가 다시 원본을 가리켜서, `X.random.next`가 복사본이 아니라 원본 노드가 된다. 예시 리스트에서는 13'과 10'이 원본 노드를 가리킨다. 모든 원본 뒤에 복사본이 붙어 있는 동안 random을 먼저 다 이어야 한다.

### 재귀로 풀면 어떤 문제가 있나요?

`next`를 따라 재귀가 끝까지 내려가서 깊이가 노드 수만큼 된다. Python은 기본 재귀 한도가 1000이라 이 문제의 최대 입력인 노드 1000개에서 `RecursionError`가 났다. 재귀 한도를 올릴 수는 있지만 반복 풀이가 안전하다. 장부에 복사본을 재귀 호출 전에 적어야 자기 자신을 가리키는 노드에서 멈춘다는 점도 짚어야 한다.

### 이 방법을 그래프 복사에도 쓸 수 있나요?

해시맵 풀이는 그대로 쓴다. 노드마다 이웃 목록을 돌며 장부에 없는 노드를 만들고 BFS나 DFS로 따라가면 된다. 끼워 넣기 풀이는 쓸 수 없다. 리스트에는 복사본을 둘 "바로 뒤"라는 자리가 있지만, 그래프에는 그런 순서가 없기 때문이다.
