A가 1번째, Z가 26번째, AA가 27번째다. 우리가 쓰는 숫자는 0부터 9까지 열 개로 자리를 채우고, 9 다음엔 자리가 하나 늘어 10이 된다. 엑셀 이름은 A부터 Z까지 스물여섯 개로 자리를 채운다는 점만 다르다. 그런데 하나가 더 다르다. 숫자에는 0이 있지만 엑셀 이름에는 0에 해당하는 글자가 없다. 그래서 Z 다음이 "A0" 같은 게 아니라 AA가 된다. 왼쪽부터 한 글자씩 읽으면서 지금까지 읽은 값에 26을 곱하고 새 글자의 값을 더하면 답이 나온다.

스프레드시트를 내보내거나 읽어 들이는 코드를 짜다 보면 `AB12` 같은 셀 주소를 행과 열 번호로 바꿔야 하는 순간이 온다. 행은 숫자라 그대로 읽으면 되는데 열 이름이 문제다. A=1, Z=26까지는 쉽지만 AA는 27이고, 26진수로 읽으려 하면 어딘가 하나씩 어긋난다. [Excel Sheet Column Number](https://leetcode.com/problems/excel-sheet-column-number/)가 그 열 이름을 숫자로 바꾸는 문제다.

이 글은 풀이 다섯 개를 놓는다. A부터 하나씩 세어 올라가는 방법, 길이별로 묶어 세는 방법, 오른쪽부터 자릿값을 곱해 더하는 방법, 왼쪽부터 26을 곱하고 더하는 방법(가장 짧고 기본 답), 그리고 그 방법을 재귀와 `reduce`로 쓴 형태다. 이 문제가 "그냥 26진수"가 아닌 이유와, 거꾸로 숫자를 열 이름으로 바꿀 때 왜 1을 빼야 하는지도 같이 본다. 코드는 모두 Node.js 22, Python 3.13, Java 21에서 직접 돌렸다.

## 열 이름을 열 번호로 바꾼다

대문자로 된 문자열 `columnTitle`이 주어진다. 엑셀의 열 이름 규칙(A, B, ..., Z, AA, AB, ..., AZ, BA, ..., ZZ, AAA, ...)으로 몇 번째 열인지 돌려준다.

- 길이는 1 이상 7 이하이고 대문자만 들어온다.
- 답은 1 이상 2^31 - 1 이하다. 가장 큰 입력은 `FXSHRXW`로 정확히 2,147,483,647이다.

길이가 7이라 속도는 문제가 아니다. 이 문제의 무게는 "0이 없는 진법"을 정확히 이해하는 데 있다. 그리고 답이 `int` 최댓값까지 가니, 계산 도중 넘치지 않는지도 한 번은 따져야 한다.

## A부터 세어 보면 보이는 것

열 이름을 길이별로 세어 본다.

```text
길이 1   A  B  C ... Z                      26개      1 ~ 26
길이 2   AA AB ... AZ BA ... ZZ             26² = 676개   27 ~ 702
길이 3   AAA ... ZZZ                        26³ = 17,576개   703 ~ 18,278
...
길이 7   AAAAAAA ... ZZZZZZZ                26⁷ = 8,031,810,176개
```

길이 2짜리를 자세히 보자. 앞 글자가 A인 것이 AA부터 AZ까지 26개, B인 것이 BA부터 BZ까지 26개다. 그래서 AZ는 26 + 26 = 52번째, BA는 53번째다. ZY는 길이 1짜리 26개 뒤에, 앞 글자가 A부터 Y까지인 묶음 25개(25 × 26 = 650개)가 있고, Z 묶음 안에서 25번째라 26 + 650 + 25 = 701이다.

이 셈법은 우리가 쓰는 10진수와 닮았다. 10진수에서 37은 3 × 10 + 7이다. 엑셀 열에서 ZY는 26(Z) × 26 + 25(Y) = 701이다. 글자의 값을 A=1, ..., Z=26으로 두고 자릿값을 26의 거듭제곱으로 두면 그대로 맞는다.

## 0이 없는 26진법

그런데 왜 A=0, ..., Z=25로 두는 보통의 26진수가 아닐까. 직접 해 보면 바로 깨진다. A=0이면 `A`도 0, `AA`도 0 × 26 + 0 = 0, `AAA`도 0이다. 10진수에서 7, 07, 007이 모두 같은 수인 것처럼, 0인 글자가 앞에 붙어도 값이 변하지 않기 때문이다. 엑셀에서는 A, AA, AAA가 서로 다른 열이니 이 방식은 쓸 수 없다.

엑셀 이름은 0이 없다. 한 자리에 올 수 있는 값이 1부터 26까지다. 이런 표기를 전단사 진법(bijective numeration)이라고 부른다. 모든 양의 정수와 모든 이름(빈 문자열 제외)이 정확히 하나씩 짝지어진다는 뜻이다. 보통의 10진수에는 "앞에 0을 붙인 이름"이 같은 수를 가리키는 중복이 있는데, 전단사 진법에는 그런 중복이 없다.

| 수 | 보통 26진수 (A=0) | 엑셀 이름 (A=1, 0 없음) |
|---|---|---|
| 1 | B | A |
| 25 | Z | Y |
| 26 | BA | Z |
| 27 | BB | AA |
| 52 | CA | AZ |

26이 보통 26진수에서는 "BA"(1 × 26 + 0)인데 엑셀에서는 Z 한 글자다. 0이 없으니 26을 "한 자리에 26"으로 쓴다. 10진수로 치면 10을 "1과 0"이 아니라 "한 자리에 10"이라는 글자로 쓰는 셈이다. 이 차이가 숫자에서 이름으로 거꾸로 바꿀 때 문제를 만든다. 그건 뒤에서 다룬다.

## A부터 하나씩 세어 올라간다

규칙을 몰라도 풀 수 있는 방법이 있다. A에서 시작해 열 이름에 하나씩 1을 더하며, 입력과 같아질 때까지 센다. 열 이름에 1을 더하는 건 [Plus One](/posts/leetcode-plus-one)과 똑같다. 9 대신 Z가 경계이고, 전부 Z면 앞에 A를 붙인다.

```js
function titleToNumber(columnTitle) {
  let cur = ["A"], n = 1;
  while (cur.join("") !== columnTitle) {
    let i = cur.length - 1;
    while (i >= 0 && cur[i] === "Z") { cur[i] = "A"; i--; }   // Z는 A가 되고 왼쪽으로 올린다
    if (i < 0) cur.unshift("A");                               // 전부 Z였다면 한 글자 늘린다
    else cur[i] = String.fromCharCode(cur[i].charCodeAt(0) + 1);
    n++;
  }
  return n;
}
console.log(titleToNumber("ZY"));   // 701
```

전부 Z일 때 앞에 "A"가 붙는 게 Plus One과 다르다. Plus One에서는 전부 9면 앞에 1을 붙이고 나머지가 0이 됐다. 여기서는 Z가 A로 돌아가고 앞에 A가 붙는다. ZZ 다음이 AAA다. 0이 없으니 "1 다음에 0들"이 아니라 "A 다음에 A들"이다.

답이 n이면 n번 이름을 만들어야 하니 시간은 O(n × 길이)다. `ZZZZ`(475,254)까지 약 51ms, `ZZZZZ`(12,356,630)까지 약 1.5초가 걸렸다. 가장 큰 입력 `FXSHRXW`는 21억 번을 돌아야 해서 사실상 끝나지 않는다. 그래도 이 풀이에는 쓸모가 있다. 규칙을 전혀 쓰지 않으니, 다른 풀이를 작은 범위에서 검증하는 정답지가 된다. 이 글의 풀이들을 1부터 3,000까지 이 방법과 맞춰 봤다.

## 길이별로 묶어서 센다

손으로 셀 때 쓴 방법이다. 길이가 L인 이름 앞에는 길이 1부터 L - 1까지의 이름이 모두 있다. 그 개수는 26 + 26² + ... + 26^(L-1)이다. 그다음 같은 길이 안에서 몇 번째인지는, 글자를 A=0으로 두는 보통의 26진수로 읽으면 된다. 같은 길이끼리는 앞에 붙는 0 문제가 없기 때문이다. 길이 2 안에서 AA는 0번째, AZ는 25번째, BA는 26번째다.

```js
function titleToNumber(columnTitle) {
  const L = columnTitle.length;
  let before = 0, block = 1;
  for (let k = 1; k < L; k++) {          // 길이가 L보다 짧은 이름의 수
    block *= 26;
    before += block;                     // 26 + 26² + ... + 26^(L-1)
  }
  let offset = 0;                        // 같은 길이 안에서의 순서(A=0인 26진수)
  for (const ch of columnTitle) offset = offset * 26 + (ch.charCodeAt(0) - 65);
  return before + offset + 1;            // 순서는 0부터라 1을 더한다
}
console.log(titleToNumber("ZY"), titleToNumber("AAA"), titleToNumber("FXSHRXW")); // 701 703 2147483647
```

ZY는 길이 2라 앞에 26개가 있고, 같은 길이 안에서 Z=25, Y=24로 읽어 25 × 26 + 24 = 674번째(0부터)다. 26 + 674 + 1 = 701이다.

이 풀이는 "0이 없는 진법 = 길이별 묶음 + 보통 진법"이라는 관계를 보여 준다. 시간은 O(L)이고 공간은 O(1)이다. 다만 반복이 두 번이고 1을 더하는 위치를 신경 써야 해서, 같은 답을 내는 더 짧은 식이 있다면 그쪽이 낫다. 그 식이 다음 두 풀이다.

## 오른쪽부터 자릿값을 곱해 더한다

A=1, ..., Z=26으로 두고 자릿값을 26의 거듭제곱으로 둔다. 10진수에서 오른쪽 끝이 일의 자리, 그 왼쪽이 십의 자리인 것처럼, 오른쪽 끝 글자가 26⁰의 자리, 그 왼쪽이 26¹의 자리다.

```js
function titleToNumber(columnTitle) {
  let result = 0, power = 1;               // power는 이번 자리의 자릿값 26^k
  for (let i = columnTitle.length - 1; i >= 0; i--) {
    const v = columnTitle.charCodeAt(i) - 64;   // 'A'의 코드가 65라 A=1, Z=26
    result += v * power;
    power *= 26;
  }
  return result;
}
console.log(titleToNumber("ZY"));   // 25 × 1 + 26 × 26 = 701
```

이 식이 왜 길이별 묶음 풀이와 같은 답을 내는지 짚어 둔다. A=1인 값은 A=0인 값보다 자리마다 1씩 크다. 길이 L이면 그 차이는 1 + 26 + 26² + ... + 26^(L-1)이고, 이게 정확히 "길이가 짧은 이름의 수 + 1"이다. 길이별 묶음 풀이가 따로 더하던 `before + 1`이 글자값에 1을 더하는 순간 저절로 들어간다.

`charCodeAt(i) - 64`는 문자 코드로 글자값을 구하는 흔한 방법이다. 대문자 A~Z의 코드가 65~90으로 이어져 있어서 가능하다. 거듭제곱을 `Math.pow(26, k)`로 매번 계산해도 답은 같다. 26^6 = 308,915,776까지는 부동소수점으로도 정확한 정수라 오차가 없다. 그래도 반복마다 26을 곱해 가는 쪽이 계산이 적고 실수 걱정도 없다.

시간 O(L), 공간 O(1)이다. 남은 불편함은 거듭제곱 변수를 따로 들고 다녀야 한다는 것이다. Java에서는 이 변수가 문제를 일으키기도 한다. 마지막 글자를 처리한 뒤 `power`가 26⁷ = 8,031,810,176이 되어 `int`를 넘는다. 실제로 `FXSHRXW`를 넣어 보니 답은 맞게 나왔지만 반복이 끝난 뒤 `power`가 -558,124,416이었다. 쓰지 않는 값이라 이번엔 괜찮지만, 거듭제곱을 먼저 곱하고 쓰는 식으로 순서를 바꾸면 그대로 답이 틀린다.

## 왼쪽부터 26을 곱하고 더한다

거듭제곱을 들고 다니지 않는 방법이 있다. 왼쪽부터 읽으면서 "지금까지 읽은 값에 26을 곱하고 새 글자값을 더한다". 10진수 문자열 "37"을 숫자로 바꿀 때 0 → 0 × 10 + 3 = 3 → 3 × 10 + 7 = 37로 하는 것과 같다. 이렇게 다항식을 안쪽부터 계산하는 방법을 호너의 방법(Horner's method)이라고 부른다.

```js
function titleToNumber(columnTitle) {
  let result = 0;
  for (let i = 0; i < columnTitle.length; i++) {
    // 지금까지의 값을 한 자리 왼쪽으로 밀고(× 26) 새 글자값을 더한다
    result = result * 26 + (columnTitle.charCodeAt(i) - 64);
  }
  return result;
}
console.log(titleToNumber("A"), titleToNumber("AA"), titleToNumber("ZY"), titleToNumber("FXSHRXW"));
// 1 27 701 2147483647
```

ZY라면 0 × 26 + 26 = 26, 26 × 26 + 25 = 701이다. 앞에서 더한 값은 뒤로 갈수록 26이 여러 번 곱해져서, 결국 첫 글자에는 26^(L-1)이, 마지막 글자에는 1이 곱해진다. 오른쪽부터 더한 식과 정확히 같은 값이다.

아래 그림은 가장 큰 입력 `FXSHRXW`를 실제로 돌리며 `result`를 찍은 그대로다. 화살표가 지금 읽는 글자다.

시간 O(L), 공간 O(1)이다. 반복 하나에 변수 하나라 틀릴 곳이 거의 없다. 이 풀이가 기본 답이다. 10진수 문자열을 손으로 숫자로 바꿀 때 쓰는 방법과 똑같아서 설명하기도 쉽다.

## 재귀와 reduce로 같은 식을 쓴다

호너의 방법은 "앞부분의 값 × 26 + 마지막 글자값"으로도 읽힌다. 그대로 재귀가 된다.

```js
function titleToNumber(s) {
  if (s.length === 0) return 0;                  // 빈 이름은 0
  const last = s.charCodeAt(s.length - 1) - 64;
  return titleToNumber(s.slice(0, -1)) * 26 + last;   // 앞부분 값 × 26 + 마지막 글자
}
```

`reduce`로 쓰면 한 줄이다.

```js
const titleToNumber = (s) => [...s].reduce((acc, ch) => acc * 26 + ch.charCodeAt(0) - 64, 0);
```

둘 다 하는 계산은 같다. 재귀는 호출이 L번 쌓이고 `slice`가 매번 새 문자열을 만들어 O(L²)이지만, L이 7이라 의미 있는 차이는 없다. 면접에서는 반복문 풀이를 쓰고, 재귀식은 "왜 26을 곱하나"를 설명할 때 꺼내면 좋다. 1부터 2만까지의 모든 열 이름으로 다섯 풀이의 답이 같은 걸 확인했다.

## Python과 Java에서 글자를 숫자로

```python
class Solution:
    def titleToNumber(self, columnTitle: str) -> int:
        result = 0
        for ch in columnTitle:
            result = result * 26 + (ord(ch) - ord("A") + 1)   # A=1, ..., Z=26
        return result

s = Solution()
print([s.titleToNumber(t) for t in ("A", "Z", "AA", "ZY", "AAA", "FXSHRXW")])
```

```text
[1, 26, 27, 701, 703, 2147483647]
```

Python은 문자 하나의 코드를 `ord`로 얻는다. 문자열끼리 뺄 수는 없어서 `ch - "A"`는 `TypeError`다. 정수 크기 제한이 없으니 넘침 걱정도 없다. `functools.reduce`로 한 줄로 쓸 수도 있지만 반복문이 더 읽기 쉽다.

```java
class Solution {
    public int titleToNumber(String columnTitle) {
        int result = 0;
        for (int i = 0; i < columnTitle.length(); i++) {
            result = result * 26 + (columnTitle.charAt(i) - 'A' + 1);   // char끼리 빼면 int
        }
        return result;
    }

    public static void main(String[] args) {
        Solution s = new Solution();
        for (String t : new String[]{"A", "Z", "AA", "ZY", "AAA", "FXSHRXW"}) System.out.print(s.titleToNumber(t) + " ");
        System.out.println();
        System.out.println(s.titleToNumber("FXSHRXX"));   // 범위를 하나 넘긴 입력
    }
}
```

```text
1 26 27 701 703 2147483647 
-2147483648
```

Java의 `char`는 숫자 타입이라 `charAt(i) - 'A'`가 바로 `int`다. 두 번째 줄은 문제 범위를 하나 넘긴 `FXSHRXX`(2^31)를 일부러 넣은 결과다. `int`가 넘쳐 -2,147,483,648이 나왔다. 오류 없이 조용히 음수가 된다. 입력 범위가 보장되지 않는 실무 코드라면 `long`으로 계산하거나 `Math.multiplyExact`, `Math.addExact`로 넘침을 예외로 바꾼다.

## 다섯 가지 읽는 법을 나란히

| 풀이 | 시간 | 공간 | 언제 고르나 |
|---|---|---|---|
| A부터 세어 올라가기 | O(답 × L) | O(L) | 다른 풀이를 작은 범위에서 검증할 때만 |
| 길이별로 묶어 세기 | O(L) | O(1) | 0 없는 진법과 보통 진법의 관계를 설명할 때 |
| 오른쪽부터 자릿값 | O(L) | O(1) | 자릿값 개념을 그대로 옮길 때. 거듭제곱 넘침에 주의 |
| 왼쪽부터 × 26 + 값 | O(L) | O(1) | 기본 답. 변수 하나로 끝난다 |
| 재귀, reduce | O(L²), O(L) | O(L) | 식의 구조를 보여 줄 때 |

L은 이름의 길이(7 이하)다. A부터 세는 풀이만 답의 크기에 비례해서 쓸 수 없고, 나머지는 사실상 모두 상수 시간이다. 고르는 기준은 짧고 틀릴 곳이 적은지다.

## 글자값과 진법에서 틀린다

### A를 0으로 둔다

```js
let r = 0;
for (const ch of s) r = r * 26 + (ch.charCodeAt(0) - 65);   // A=0
// "A" → 0, "Z" → 25, "AA" → 0, "BA" → 26
```

`charCodeAt(0) - 65`는 다른 문자 문제에서 흔히 쓰는 식이라 손이 먼저 간다. A가 0이 되면서 `A`와 `AA`가 둘 다 0이 되고 모든 답이 틀어진다. 이 문제의 글자값은 1부터 26이다. 64를 빼거나 `- 65 + 1`로 쓴다.

### parseInt에 진법을 넘긴다

`parseInt("ZY", 26)`은 `NaN`이다. `parseInt`의 26진수는 0~9 다음에 a~p를 쓰는 표기라 Z는 숫자가 아니다. `parseInt("AB", 26)`은 A=10, B=11로 읽어 271이 나온다. 정답 28과 전혀 다르다. 표준 진법 변환 함수는 0이 있는 진법을 가정하니 이 문제에는 맞지 않는다.

### 소문자가 들어온다

이 문제는 대문자만 들어온다고 보장하지만, 실무에서 사용자가 `ab`라고 적으면 `"a".charCodeAt(0) - 64`가 33이 되어 엉뚱한 값이 나온다. 오류도 나지 않는다. 입력을 받는 쪽이라면 `toUpperCase()`로 맞추고 `/^[A-Z]+$/`로 검사한다.

### 거듭제곱을 먼저 곱한다

오른쪽부터 더하는 풀이에서 `power *= 26`을 `result +=`보다 먼저 두면 모든 글자가 한 자리씩 높게 계산된다. `A`가 26이 된다. 자릿값을 쓰는 순서와 올리는 순서를 바꾸는 실수라, 왼쪽부터 26을 곱하는 풀이로 쓰면 아예 생기지 않는다.

## 거꾸로 숫자를 열 이름으로

꼬리 질문으로 가장 많이 나오는 게 반대 방향, 168. Excel Sheet Column Title이다. 번호를 받아 열 이름을 돌려준다. 보통 진법이라면 26으로 나눈 나머지가 마지막 자리이고 몫으로 계속하면 된다. 그대로 해 보면 틀린다.

```js
const naiveTitle = (n) => {
  let out = "";
  while (n > 0) {
    out = String.fromCharCode(65 + (n % 26)) + out;   // 나머지 0~25를 A~Z로
    n = Math.floor(n / 26);
  }
  return out;
};
console.log(naiveTitle(26), naiveTitle(27), naiveTitle(52));   // BA BB CA (정답 Z AA AZ)
```

26의 나머지는 0이라 A가 되고, 몫 1이 B가 되어 BA가 나온다. 0이 없는 진법에서는 한 자리 값이 1~26인데, 나머지는 0~25라 범위가 하나 어긋나서다. 고치는 방법은 나누기 전에 1을 빼는 것이다. 1~26을 0~25로 옮겨 놓고 나머지를 구하면 그 나머지가 그대로 A~Z의 순서가 된다.

```js
function convertToTitle(n) {
  let out = "";
  while (n > 0) {
    n--;                                            // 1~26을 0~25로 옮긴다
    out = String.fromCharCode(65 + (n % 26)) + out; // 0~25가 A~Z
    n = Math.floor(n / 26);                         // 남은 앞부분의 번호
  }
  return out;
}
console.log(convertToTitle(26), convertToTitle(52), convertToTitle(701)); // Z AZ ZY
```

26이면 25가 되어 Z, 몫 0으로 끝난다. 52면 51이 되어 나머지 25(Z), 몫 1. 다시 1에서 1을 빼 0이 되어 A, 그래서 AZ다. 아래 그림은 2,147,483,647을 실제로 바꾸며 찍은 값이다. 오른쪽 글자부터 정해진다. `memory`의 "남은 수"가 앞의 호너 그림에서 본 중간값과 정확히 같다는 걸 볼 수 있다. 같은 계산을 거꾸로 되감고 있어서다.

## 셀 주소를 읽는 코드

실무에서 이 변환을 쓰는 곳은 셀 주소다. `AB12`는 28열 12행이다. 정규식으로 글자와 숫자를 나누고, 글자 쪽을 이 글의 함수로 바꾼다.

```js
function parseCell(ref) {
  const m = /^([A-Z]+)([1-9][0-9]*)$/.exec(ref);   // 글자 1개 이상 + 0으로 시작하지 않는 숫자
  if (!m) return null;
  return { col: titleToNumber(m[1]), row: Number(m[2]) };
}
console.log(parseCell("B3"), parseCell("XFD1048576"), parseCell("b3"), parseCell("A0"));
// { col: 2, row: 3 } { col: 16384, row: 1048576 } null null
```

`XFD1048576`은 엑셀 2007 이후 시트의 오른쪽 아래 끝 셀이다. 열이 16,384개(XFD), 행이 1,048,576개다. 그 범위를 넘는 주소는 엑셀에 없으니, 검사 단계에서 `col <= 16384`를 함께 확인하면 잘못된 입력을 일찍 걸러 낸다. 소문자나 0행처럼 형식이 틀린 주소는 `null`로 돌려 호출한 쪽이 처리하게 했다. 라이브러리마다 열 번호를 0부터 세기도 하고 1부터 세기도 해서, 받은 번호를 배열 인덱스로 쓸 때 1을 빼야 하는지 꼭 확인한다. 이 어긋남이 표 데이터가 한 칸씩 밀려 들어가는 버그의 흔한 원인이다.

### 범위를 셀 목록으로 펼치기

`Y1:AB2` 같은 범위를 셀 하나하나로 펼치는 일도 자주 한다. 열 이름을 번호로 바꿔 반복을 돌리고, 다시 이름으로 바꾸면 된다. Z에서 AA로 넘어가는 경계를 반복문이 알아서 처리한다.

```js
function expandRange(range) {
  const [a, b] = range.split(":");
  const parse = (ref) => {
    const m = /^([A-Z]+)(\d+)$/.exec(ref);
    return [titleToNumber(m[1]), Number(m[2])];       // [열 번호, 행 번호]
  };
  const [c1, r1] = parse(a), [c2, r2] = parse(b);
  const out = [];
  for (let r = Math.min(r1, r2); r <= Math.max(r1, r2); r++)      // 뒤집힌 범위도 받는다
    for (let c = Math.min(c1, c2); c <= Math.max(c1, c2); c++) out.push(convertToTitle(c) + r);
  return out;
}
console.log(expandRange("Y1:AB2").join(" "));   // Y1 Z1 AA1 AB1 Y2 Z2 AA2 AB2
console.log(expandRange("B3:A2").join(" "));    // A2 B2 A3 B3
```

열 이름끼리 문자열로 비교하면 이 경계에서 틀린다. `"Z" < "AA"`는 사전 순으로 `false`다. 그래서 `"Y" <= col && col <= "AB"` 같은 조건으로는 범위 안의 열을 고를 수 없다. 열을 비교하거나 정렬할 때는 반드시 번호로 바꾼 뒤에 한다. 문자열로 비교하려면 길이를 먼저 비교하고 길이가 같을 때만 사전 순으로 비교해야 한다. 길이가 긴 이름이 항상 뒤에 오기 때문이다.

### 열 이름을 정렬할 때

같은 함정이 정렬에서도 나온다. 열 이름 배열을 `sort()`로 정렬하면 사전 순이 되어 순서가 틀린다.

```js
const cols = ["AB", "C", "Z", "AA", "B", "BA"];
console.log([...cols].sort().join(" "));
// AA AB B BA C Z        ← 사전 순. AA가 B보다 앞에 온다
console.log([...cols].sort((a, b) => a.length - b.length || (a < b ? -1 : a > b ? 1 : 0)).join(" "));
// B C Z AA AB BA        ← 길이 먼저, 같은 길이끼리 사전 순
console.log([...cols].sort((a, b) => titleToNumber(a) - titleToNumber(b)).join(" "));
// B C Z AA AB BA        ← 번호로 바꿔 비교
```

길이를 먼저 비교하는 비교자와 번호로 바꾸는 비교자가 같은 결과를 낸다. 길이가 같은 이름끼리는 A=0인 보통 26진수로 읽은 값의 순서가 사전 순과 같고, 길이가 다르면 긴 쪽이 항상 크기 때문이다. 앞에서 본 "길이별 묶음 + 보통 진법" 관계가 정렬에서도 그대로 쓰인다. 비교할 때마다 번호로 바꾸는 게 아깝다면 길이 비교자를 쓴다.

엑셀에는 열도 숫자로 쓰는 R1C1 표기가 있다. `AB12`는 `R12C28`이다. 변환은 이 글의 함수를 한 번 부르는 것으로 끝난다. 수식을 코드로 만들어 내는 경우에는 처음부터 R1C1로 다루면 열 이름 계산이 아예 필요 없어지기도 한다.

### 두 함수가 서로의 거꾸로인지 확인하기

번호를 이름으로, 이름을 번호로 바꾸는 함수를 함께 쓴다면 왕복이 맞는지 한 번에 확인할 수 있다. 0이 없는 진법은 번호와 이름이 하나씩 짝지어지니, 번호를 이름으로 바꿨다가 되돌리면 원래 번호가 나와야 하고 서로 다른 번호는 서로 다른 이름이 되어야 한다.

```js
let mismatch = 0;
const seen = new Set();
for (let n = 1; n <= 500000; n++) {
  const t = convertToTitle(n);
  if (titleToNumber(t) !== n) mismatch++;
  seen.add(t);
}
console.log(`어긋난 번호 ${mismatch}개, 서로 다른 이름 ${seen.size}개`);
```

```text
어긋난 번호 0개, 서로 다른 이름 500000개
```

1을 빼지 않는 `naiveTitle`로 바꿔 돌리면 26에서 바로 어긋난다. 이름 길이도 같은 성질로 구할 수 있다. 길이 L 이하 이름의 수는 26 + 26² + ... + 26^L이니, 이 합이 n 이상이 되는 가장 작은 L이 n의 이름 길이다.

```js
function titleLength(n) {
  let L = 1, block = 26, upto = 26;     // upto: 길이 L 이하 이름의 수
  while (n > upto) {
    L++;
    block *= 26;
    upto += block;
  }
  return L;
}
console.log([26, 27, 702, 703, 16384, 18279, 2147483647].map(titleLength));
// [1, 2, 2, 3, 3, 4, 7]
```

702까지는 두 글자, 703부터 세 글자, 18,279부터 네 글자다. 엑셀 마지막 열 16,384가 세 글자(XFD)인 이유다. 문자열을 만들기 전에 길이를 알면 결과를 담을 칸을 미리 잡아 오른쪽부터 채울 수 있다.

## 알파벳과 규칙이 바뀌면

### 글자 수가 다른 체계라면

알파벳이 k개인 체계라면 26을 k로 바꾸면 끝이다. 글자값은 1~k다. 0이 없는 진법이라는 구조는 그대로다. 예를 들어 A~C 세 글자로 이름을 붙이면 A, B, C, AA, AB, AC, BA, ...가 1, 2, 3, 4, 5, 6, 7이 된다. 길이별 묶음 풀이로 보면 길이 2짜리 앞에 3개, 길이 3짜리 앞에 3 + 9 = 12개가 있다.

### 숫자가 아주 커진다면

이름이 수십 글자라 답이 2^53을 넘으면 JavaScript `Number`로는 정확하지 않다. 같은 식을 `BigInt`로 하면 된다(`result * 26n + BigInt(v)`). Java는 `long`이 26^13 근처까지, 그 위는 `BigInteger`다. 계산 방법은 바뀌지 않는다. 큰 수를 직접 곱하는 방법은 [Multiply Strings](/posts/leetcode-multiply-strings)에 있다.

### 다음 열 이름을 구하라면

번호로 바꾸고 1을 더해 다시 이름으로 바꿔도 되지만, 이름에서 바로 다음 이름을 만들 수도 있다. 오른쪽부터 Z를 A로 바꾸다가 처음 만나는 Z가 아닌 글자를 하나 올리고, 전부 Z였으면 앞에 A를 붙인다. 이 글의 첫 풀이에서 쓴 바로 그 증가 연산이다. 셀을 한 칸씩 옮기며 주소를 만드는 코드에서는 이쪽이 변환을 두 번 하지 않아 단순하다.

### 사용자가 입력한 열 이름을 받는다면

문제는 대문자만 들어온다고 보장하지만 실제 입력은 그렇지 않다. 앞뒤 공백을 지우고 대문자로 맞춘 뒤, 글자만 있는지와 엑셀 범위 안인지를 확인한다.

```js
function excelColumn(input) {
  const s = String(input).trim().toUpperCase();
  if (!/^[A-Z]{1,3}$/.test(s)) return null;      // 엑셀 열은 세 글자까지
  const n = titleToNumber(s);
  return n <= 16384 ? n : null;                   // XFD를 넘으면 없는 열
}
// "ab" → 28, "XFD" → 16384, "XFE" → null, " c " → 3, "A1" → null, "" → null
```

세 글자 정규식이 넘침도 함께 막는다. 세 글자의 최댓값 ZZZ가 18,278이라 계산이 커질 일이 없다.

### 비슷한 문제

- [7. Reverse Integer](/posts/leetcode-reverse-integer)도 자릿수를 다루며 32비트 넘침을 확인한다.

## 면접에서 나올 만한 질문

### 어떻게 바꿨나요?

왼쪽부터 한 글자씩 읽으면서 지금까지의 값에 26을 곱하고 새 글자값을 더했다. 글자값은 A=1부터 Z=26까지다. 10진수 문자열을 숫자로 바꿀 때 10을 곱하고 더하는 것과 같은 호너의 방법이고, 시간 O(L), 공간 O(1)이다.

### 그냥 26진수와 무엇이 다른가요?

0에 해당하는 글자가 없다. 한 자리 값이 0~25가 아니라 1~26이다. A를 0으로 두면 A, AA, AAA가 모두 0이 되어 구별되지 않는다. 0이 없는 진법이라 모든 양의 정수와 이름이 정확히 하나씩 짝지어지고, 26이 BA가 아니라 Z 한 글자가 된다.

### 거꾸로 번호를 이름으로 바꾸려면요?

반복마다 먼저 1을 빼고 26으로 나눈 나머지를 A~Z로 바꿔 앞에 붙이고, 몫으로 계속한다. 1을 빼는 건 한 자리 값 1~26을 나머지 범위 0~25로 옮기기 위해서다. 빼지 않으면 26이 BA로 나오고, 처음 한 번만 빼면 52가 BZ로 나온다.

### 넘침은 없나요?

이 문제의 범위에서는 없다. 가장 큰 입력 FXSHRXW의 마지막 단계에서 82,595,524 × 26 = 2,147,483,624라 `int` 최댓값보다 23 작고, 23을 더해 정확히 최댓값이 된다. 범위를 하나 넘긴 입력이면 Java `int`가 조용히 음수가 되니, 범위가 보장되지 않으면 `long`이나 `Math.addExact`를 쓴다.

### 오른쪽부터 계산하는 방법과 어느 쪽이 낫나요?

답은 같다. 오른쪽부터는 자릿값 26^k를 변수로 들고 다녀야 하고, Java에서는 마지막 반복 뒤 그 변수가 26⁷이 되어 넘친다. 왼쪽부터 26을 곱하는 방법은 변수 하나로 끝나고 중간값이 항상 답 이하라 넘칠 걱정도 적다. 그래서 왼쪽부터를 기본으로 쓴다.

### parseInt(s, 26)으로 안 되나요?

안 된다. 표준 진법 변환은 0이 있는 진법이고 글자도 0~9 다음 a~p를 쓴다. `parseInt("ZY", 26)`은 Z가 26진수 숫자가 아니라 `NaN`이고, `parseInt("AB", 26)`은 A=10, B=11로 읽어 271이 나온다. 정답은 28이다.

### 실무에서 이 변환을 쓸 때 조심할 점은요?

셀 주소를 읽을 때는 소문자나 0행 같은 잘못된 형식을 먼저 걸러야 한다. 엑셀의 최대 열 XFD(16,384)를 넘는 값도 검사한다. 그리고 라이브러리마다 열 번호가 0부터인지 1부터인지 다르니, 배열 인덱스로 쓸 때 하나씩 밀리지 않는지 확인한다.
