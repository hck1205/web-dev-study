트리 모양 데이터를 화면에 그릴 때 층마다 가장 끝에 있는 노드를 알아야 할 때가 있다. 층 끝에 "더 보기" 버튼을 붙이거나, 층마다 오른쪽 여백을 맞추려면 그렇다. 사람 눈으로는 그림을 오른쪽에서 보면 바로 보이는데, 코드로는 "층"이라는 개념을 직접 만들어야 한다.

[LeetCode 199. Binary Tree Right Side View](https://leetcode.com/problems/binary-tree-right-side-view/)가 이 계산을 묻는다. [Binary Tree Level Order Traversal 글](/posts/leetcode-binary-tree-level-order-traversal)에서 층마다 노드를 묶는 방법을 익혔다면 거의 같은 코드로 풀린다. 그래서 면접에서는 BFS로 푼 다음 "DFS로도 풀어 보라", "왼쪽에서 본 모습은?", "메모리를 덜 쓰려면?"이 따라온다. 이 글은 오른쪽 가지만 따라가는 틀린 생각에서 출발해 BFS 세 가지, DFS 세 가지를 본다.

층 순서 순회의 기본(큐, 층 경계 나누기)은 위의 Level Order 글에서, 깊이 우선 탐색의 기본은 [그래프 BFS와 DFS 글](/posts/ds-graph-bfs-dfs)에서 다뤘다. 여기서는 그 위에서 "층마다 하나만 고르기"에 집중한다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 층마다 가장 오른쪽에 있는 노드

이진 트리의 뿌리가 주어진다. 트리를 오른쪽 옆에서 바라본다고 할 때 보이는 노드의 값을 위층부터 차례로 돌려준다. 같은 층(뿌리에서 같은 수의 간선만큼 떨어진 노드들)에서는 가장 오른쪽 노드 하나만 보이고 나머지는 가려진다. 그러니 답의 길이는 트리의 층 수와 같다.

제약에서 볼 것은 노드 수가 0개에서 100개라는 것이다. 모든 노드를 봐야 어느 노드가 층의 끝인지 확신할 수 있으니 O(n)이 하한이고, 100개라 어떤 풀이든 시간은 넉넉하다. 빈 트리면 빈 배열을 돌려준다.

이 글에서 쓸 예시다. 위층부터 왼쪽에서 오른쪽으로 읽고, 빈 자리는 `null`로 둔다.

```text
[1, 2, 3, 4, 5, null, null, 6]

          1          ← 1이 보인다
        /   \
       2     3       ← 3이 보인다
      / \
     4   5           ← 5가 보인다
    /
   6                 ← 6이 보인다

답: [1, 3, 5, 6]
```

셋째 층과 넷째 층에서 보이는 5와 6은 뿌리의 왼쪽 가지에 있다. 오른쪽 가지(3)는 둘째 층에서 끝나 버려서, 그 아래층에서는 왼쪽 가지 노드가 가장 오른쪽이 된다. 아래 그림에서 다음을 누르면 층마다 보이는 노드를 위에서부터 잇는다.

## 오른쪽 자식만 따라가면 놓치는 노드

이름만 보면 오른쪽 포인터를 따라 내려가면 될 것 같다.

```js
function rightSideView(root) {
  const res = [];
  for (let node = root; node !== null; node = node.right) {
    res.push(node.val); // 틀렸다: 오른쪽 가지가 먼저 끝나면 아래층을 놓친다
  }
  return res;
}
```

예시에서 `[1, 3]`이 나온다. 정답 `[1, 3, 5, 6]`의 뒤 두 개를 놓쳤다. `[1, 2]`처럼 오른쪽 자식이 아예 없는 트리에서는 `[1]`이 나오는데, 정답은 `[1, 2]`다. 오른쪽 자식이 없으면 왼쪽 자식이 그 층의 가장 오른쪽이다.

이 실수를 고치려면 "층"을 제대로 다뤄야 한다. 층을 다루는 방법은 두 가지다. 큐로 한 층씩 내려가거나(BFS), 깊이를 숫자로 들고 다니거나(DFS).

## 층 번호마다 트리 전체를 훑는다

층 개념을 가장 단순하게 만드는 방법부터 보자. 먼저 트리 높이 h를 구한다. 그다음 층 번호 d = 0, 1, …, h-1마다 트리 전체를 왼쪽부터 훑어서, 깊이가 d인 노드를 만날 때마다 값을 덮어쓴다. 왼쪽부터 훑으니 마지막으로 덮어쓴 값이 그 층의 가장 오른쪽이다.

```js
function height(node) {
  return node ? 1 + Math.max(height(node.left), height(node.right)) : 0;
}

function rightSideView(root) {
  const res = [];
  for (let d = 0; d < height(root); d++) {
    let last = null;
    (function walk(node, depth) {
      if (!node) return;
      if (depth === d) {
        last = node.val; // 왼쪽부터 오니 나중 값이 더 오른쪽이다
        return; // d층 아래는 볼 필요가 없다
      }
      walk(node.left, depth + 1);
      walk(node.right, depth + 1);
    })(root, 0);
    res.push(last);
  }
  return res;
}
```

예시에서 `[1, 3, 5, 6]`이 나온다. 하지만 층마다 위층을 전부 다시 훑는다. 시간은 O(n·h)이고, 일자 트리면 O(n²)이다. 반복문 조건에 `height(root)`를 넣어서 높이를 매번 다시 재는 것도 낭비다. 공간은 호출 스택 O(h)다.

층마다 위층을 다시 내려가는 게 문제였다. 한 번 내려간 층에서 다음 층으로 바로 넘어가면 된다.

## 층을 통째로 모아 두고 끝만 고른다

한 층의 노드 배열에서 다음 층의 노드 배열을 만든다. 지금 층 노드들의 자식을 왼쪽부터 모으면 그게 다음 층이다. 층마다 값 배열을 저장해 두고, 다 끝난 뒤 각 층의 마지막 값을 고른다.

```js
function rightSideView(root) {
  const levels = [];
  let level = root ? [root] : [];
  while (level.length > 0) {
    levels.push(level.map((n) => n.val)); // 이 층의 값을 모두 저장
    const next = [];
    for (const n of level) {
      if (n.left) next.push(n.left); // 왼쪽 자식부터 넣어야 층 순서가 유지된다
      if (n.right) next.push(n.right);
    }
    level = next;
  }
  return levels.map((vals) => vals[vals.length - 1]);
}
```

예시의 `levels`는 `[[1], [2, 3], [4, 5], [6]]`이고, 각 층의 마지막을 고르면 `[1, 3, 5, 6]`이다. 시간은 노드마다 한 번이라 O(n)이다. 공간은 `levels`에 모든 값이 들어가서 O(n)이다.

Level Order Traversal의 답을 그대로 만든 다음 가공하는 셈이라, 그 문제를 막 풀었다면 가장 먼저 떠오른다. 그런데 필요한 건 층마다 값 하나인데 층 전체를 저장했다. 다음 풀이는 저장 없이 마지막 노드만 적는다.

## 층의 크기를 고정하고 마지막만 적는다

큐 하나로 층을 나누는 방법이다. 한 층을 처리하기 직전에 큐에 든 노드 수 `size`를 적어 둔다. 그 순간 큐에는 정확히 이번 층 노드만 들어 있다. `size`번 꺼내는 동안 다음 층 노드가 뒤에 쌓이지만, 횟수를 고정했으니 섞이지 않는다. 꺼내는 순서가 왼쪽에서 오른쪽이니 `size`번째로 꺼낸 노드가 그 층의 가장 오른쪽이다.

```js
function rightSideView(root) {
  if (root === null) return [];
  const res = [];
  const queue = [root];
  let head = 0; // shift()는 O(n)이라 머리 위치만 옮긴다
  while (head < queue.length) {
    const size = queue.length - head; // 이번 층의 노드 수를 먼저 고정한다
    for (let i = 0; i < size; i++) {
      const node = queue[head++];
      if (i === size - 1) res.push(node.val); // 이 층의 마지막 노드
      if (node.left) queue.push(node.left);
      if (node.right) queue.push(node.right);
    }
  }
  return res;
}
```

아래 그림은 예시 트리에서 큐가 바뀌는 모습이다. 칸은 노드를 층 순서로 펼친 것이고, 초록 칸은 답에 들어간 노드다.

노드마다 한 번 넣고 한 번 꺼내니 시간 O(n)이다. 공간은 큐가 가장 클 때, 즉 가장 넓은 층의 노드 수 w만큼 든다. 꽉 찬 트리라면 마지막 층에 노드의 절반 가까이가 있으니 O(n)까지 갈 수 있고, 일자 트리라면 큐에 늘 하나뿐이다. 답 배열은 층 수만큼이다.

같은 코드를 `for (let i = 0; i < size; i++)` 대신 `i === 0`일 때 적도록 바꾸면 왼쪽에서 본 모습이 된다. 층마다 모든 값의 합을 구하면 층 평균(LeetCode 637), 최댓값을 구하면 층별 최댓값(LeetCode 515)이다. 이 틀 하나로 층 단위 문제가 여럿 풀린다.

### Python과 Java로 쓰면

Python은 `collections.deque`의 `popleft()`가 O(1)이다. 리스트의 `pop(0)`은 O(n)이라 쓰지 않는다. `range(len(queue))`는 반복을 시작할 때 한 번만 계산되므로 루프 안에서 큐가 커져도 안전하지만, 읽는 사람을 위해 `size`로 따로 적어 둔다.

```python
from collections import deque

class Solution:
    def rightSideView(self, root: Optional[TreeNode]) -> List[int]:
        if root is None:
            return []
        res = []
        queue = deque([root])
        while queue:
            size = len(queue)  # 이번 층의 노드 수를 먼저 고정한다
            for i in range(size):
                node = queue.popleft()
                if i == size - 1:  # 이 층의 마지막 노드
                    res.append(node.val)
                if node.left:
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)
        return res
```

```text
[1, 3, 5, 6]
```

Java에서는 `for (int i = 0; i < queue.size(); i++)`처럼 조건에 `queue.size()`를 직접 쓰면 루프 안에서 자식을 넣을 때마다 조건이 바뀐다. 반드시 루프 전에 지역 변수로 고정한다. `ArrayDeque`는 `null`을 넣을 수 없어서 자식이 있는지 먼저 확인한다.

```java
class Solution {
    public List<Integer> rightSideView(TreeNode root) {
        List<Integer> res = new ArrayList<>();
        if (root == null) return res;
        Deque<TreeNode> queue = new ArrayDeque<>();
        queue.offer(root);
        while (!queue.isEmpty()) {
            int size = queue.size(); // 반복문 조건에 queue.size()를 직접 쓰면 안 된다
            for (int i = 0; i < size; i++) {
                TreeNode node = queue.poll();
                if (i == size - 1) res.add(node.val);
                if (node.left != null) queue.offer(node.left);
                if (node.right != null) queue.offer(node.right);
            }
        }
        return res;
    }
}
```

```text
[1, 3, 5, 6]
[]
```

두 번째 줄은 빈 트리를 넣은 결과다.

## 오른쪽부터 내려가며 처음 닿은 깊이를 적는다

큐 없이 깊이 우선으로도 풀린다. 생각은 이렇다. 오른쪽 자식을 왼쪽 자식보다 먼저 방문하는 전위 순회를 하면, 어떤 깊이에 처음 도착하는 노드가 그 층의 가장 오른쪽 노드다. 오른쪽에 있는 노드일수록 먼저 방문되기 때문이다.

"이 깊이에 처음 왔나"는 답 배열의 길이로 안다. 깊이 d에 처음 오면 그때 답 배열에는 0층부터 d-1층까지 d개가 들어 있다. 그래서 `depth === res.length`면 새 층이다.

```js
function rightSideView(root) {
  const res = [];
  function walk(node, depth) {
    if (node === null) return;
    if (depth === res.length) res.push(node.val); // 이 깊이에 처음 닿았다
    walk(node.right, depth + 1); // 오른쪽을 먼저
    walk(node.left, depth + 1);
  }
  walk(root, 0);
  return res;
}
```

아래 그림은 같은 예시에서 방문 순서다. 기억 칸은 호출 스택이다.

## 왼쪽부터 가며 나중 값으로 덮어쓴다

방문 순서를 평범한 전위 순회(왼쪽 먼저)로 두고, 깊이마다 값을 계속 덮어써도 된다. 같은 깊이에서는 오른쪽 노드가 나중에 방문되니 마지막에 남는 값이 가장 오른쪽이다.

```js
function rightSideView(root) {
  const res = [];
  function walk(node, depth) {
    if (node === null) return;
    res[depth] = node.val; // 같은 깊이는 나중에 온 값이 더 오른쪽이다
    walk(node.left, depth + 1);
    walk(node.right, depth + 1);
  }
  walk(root, 0);
  return res;
}
```

예시에서 깊이 1의 값은 2로 적혔다가 3으로 덮이고, 깊이 2는 4 → 5로 덮인다. 결과는 `[1, 3, 5, 6]`이다. 시간과 공간은 앞 풀이와 같고, 대입이 노드 수만큼 일어난다.

이 버전은 기존 전위 순회 코드를 거의 그대로 쓸 수 있다는 게 장점이다. 다만 "왜 마지막 값이 오른쪽인가"를 한 번 더 설명해야 한다. 같은 깊이의 두 노드 A, B에서 A가 B보다 왼쪽이면, 두 노드의 공통 조상에서 A는 왼쪽 가지에, B는 오른쪽 가지에 있다. 전위 순회는 왼쪽 가지를 다 끝낸 뒤 오른쪽으로 가니 B가 늘 나중이다.

## 스택에 깊이를 같이 넣는다

오른쪽 먼저 DFS를 반복문으로 옮긴다. 스택에 `[노드, 깊이]` 쌍을 넣는다. 스택은 나중에 넣은 것이 먼저 나오니, 오른쪽을 먼저 꺼내려면 왼쪽을 먼저 넣는다.

```js
function rightSideView(root) {
  const res = [];
  const stack = root ? [[root, 0]] : [];
  while (stack.length > 0) {
    const [node, depth] = stack.pop();
    if (depth === res.length) res.push(node.val);
    if (node.left) stack.push([node.left, depth + 1]); // 왼쪽을 먼저 넣어야
    if (node.right) stack.push([node.right, depth + 1]); // 오른쪽이 먼저 나온다
  }
  return res;
}
```

시간 O(n), 공간 O(h)에서 O(n) 사이다. 재귀가 없으니 깊은 트리에서도 호출 스택이 넘치지 않는다. 넣는 순서를 거꾸로 하면 왼쪽이 먼저 나와 왼쪽에서 본 모습 `[1, 2, 4, 6]`이 나온다. 이 실수는 뒤에서 다시 본다.

## 오른쪽 풍경을 얻는 여섯 방법 견주기

| 풀이 | 시간 | 추가 공간 | 언제 고르나 |
|---|---|---|---|
| 층마다 트리 전체 훑기 | O(n·h), 최악 O(n²) | O(h) | 층 개념을 처음 만들어 볼 때. 실제로는 쓰지 않는다 |
| 층 전체 저장 후 끝 고르기 | O(n) | O(n) | Level Order 답이 이미 있을 때 |
| BFS, 층 크기 고정 | O(n) | O(w) 가장 넓은 층 | 기본 답. 층 단위 변형으로 넓히기 쉽다 |
| DFS, 오른쪽 먼저 | O(n) | O(h) | 넓고 얕은 트리, 코드를 가장 짧게 쓰고 싶을 때 |
| DFS, 왼쪽 먼저 덮어쓰기 | O(n) | O(h) | 이미 있는 전위 순회 코드를 재사용할 때 |
| 스택 DFS | O(n) | O(h)~O(n) | 깊이가 아주 깊을 수 있어 재귀를 피할 때 |

## 층을 잘못 나누는 코드

### 루프 조건에서 큐 길이를 다시 읽기

```js
const q = [root];
while (q.length) {
  for (let i = 0; i < q.length; i++) { // q.length가 루프 안에서 계속 바뀐다
    const n = q.shift();
    if (i === q.length - 1) res.push(n.val);
    if (n.left) q.push(n.left);
    if (n.right) q.push(n.right);
  }
}
```

`shift()`로 하나 빠지고 `push()`로 자식이 들어오면서 `q.length`가 매 반복마다 달라진다. 층 경계가 무너져서 예시 트리에서 `[4]`라는 엉뚱한 답이 나왔다. 층 크기는 층을 시작하기 전에 변수로 고정한다. Java의 `queue.size()`도 같다.

### 자식을 넣는 순서를 뒤집기

BFS에서 오른쪽 자식을 먼저 넣으면 층 안의 순서가 오른쪽에서 왼쪽이 된다. 그러면 층의 마지막이 아니라 첫 번째가 가장 오른쪽 노드다. 둘 중 하나만 바꾸면 왼쪽에서 본 모습이 나온다. 스택 DFS에서는 반대로, 오른쪽을 먼저 넣으면 왼쪽이 먼저 나와 예시에서 `[1, 2, 4, 6]`이 나왔다. 큐와 스택은 꺼내는 순서가 반대라서 넣는 순서도 반대로 맞춰야 한다.

### DFS에서 왼쪽을 먼저 가며 처음 값만 적기

```js
if (depth === res.length) res.push(node.val);
walk(node.left, depth + 1); // 왼쪽 먼저면 처음 닿는 노드가 가장 왼쪽이다
walk(node.right, depth + 1);
```

"처음 닿은 노드만 적기"는 오른쪽을 먼저 갈 때만 맞다. 왼쪽을 먼저 가면 왼쪽에서 본 모습 `[1, 2, 4, 6]`이 된다. 왼쪽부터 가려면 처음 값만 적지 말고 덮어써야 한다. 방문 순서와 기록 규칙은 짝으로 정해진다.

### 가려진 노드 아래로 내려가지 않기

DFS에서 이미 적힌 깊이의 노드를 만나면 `return`해 버리는 실수다. 예시에서는 깊이 1의 2에서 바로 돌아오는 바람에 그 아래 5와 6을 영영 못 보고 `[1, 3]`으로 끝났다. 이 노드는 안 보여도 자식은 보일 수 있다.

### 빈 트리

BFS에서 `queue = [root]`로 시작하고 `null` 확인을 빼면, 빈 트리에서 `null.left`를 읽다 `TypeError`가 난다. 첫 줄에서 빈 배열을 돌려준다.

## 보는 방향을 바꾸는 변형들

### 왼쪽에서 본 모습이라면

BFS에서 층의 첫 노드(`i === 0`)를 적거나, DFS에서 왼쪽을 먼저 가며 처음 닿은 노드를 적는다. 예시에서는 `[1, 2, 4, 6]`이다. LeetCode 513 Find Bottom Left Tree Value는 이 중 마지막 값 하나만 묻는다.

### 층마다 평균이나 최댓값이라면

LeetCode 637 Average of Levels in Binary Tree, 515 Find Largest Value in Each Tree Row다. 층 크기를 고정한 BFS에서 마지막 노드 대신 합이나 최댓값을 모은다. DFS로 할 때는 깊이별 배열에 누적한다.

### 위나 아래에서 본 모습이라면

위에서 보면 가로 위치가 같은 노드 중 가장 위 노드가 보인다. 그래서 층 대신 가로 좌표(뿌리 0, 왼쪽 자식 -1, 오른쪽 자식 +1)를 들고 다녀야 한다. BFS로 가로 좌표마다 처음 만난 노드를 적는다. 좌표마다 노드를 모두 모아 정렬하는 문제가 LeetCode 987 Vertical Order Traversal of a Binary Tree다. 오른쪽에서 본 모습은 층이 열쇠였고, 위에서 본 모습은 가로 좌표가 열쇠다.

### 같은 층의 오른쪽 이웃을 이어 달라면

LeetCode 116, 117 Populating Next Right Pointers in Each Node다. 층마다 노드를 왼쪽에서 오른쪽으로 꺼내며 앞 노드의 `next`를 지금 노드로 잇는다. 층의 마지막 노드, 이 문제의 답에 해당하는 노드는 `next`가 `null`로 남는다. 117은 추가 공간 O(1)을 요구해서, 이미 이은 윗층의 `next`를 따라가며 아래층을 잇는다.

### 지그재그로 읽으라면

LeetCode 103 Binary Tree Zigzag Level Order Traversal이다. 층마다 방향을 바꿔서 담는다. 층을 나누는 BFS 틀은 같고, 홀수 층에서 배열을 뒤집거나 앞쪽에 넣으면 된다.

### 같은 패턴의 다른 문제

층을 나누는 BFS 틀은 [Level Order Traversal](/posts/leetcode-binary-tree-level-order-traversal)이 기본이고, 깊이를 들고 다니는 DFS 틀은 [Maximum Depth of Binary Tree](/posts/leetcode-maximum-depth-of-binary-tree)의 탑다운 풀이와 같다. 트리를 층 순서 배열로 바꾸고 되돌리는 일은 [Serialize and Deserialize Binary Tree](/posts/leetcode-serialize-and-deserialize-binary-tree)에서 다룬다.

## 층을 알면 끝이 보인다

오른쪽에서 보이는 노드는 층마다 가장 오른쪽 노드이고, 그 노드는 오른쪽 가지에 있을 수도 왼쪽 가지에 있을 수도 있다. 그래서 층을 만드는 게 먼저다. 큐로 한 층씩 내려가며 층 크기를 고정하면 마지막 노드가, 깊이를 들고 오른쪽부터 내려가면 처음 닿은 노드가 답이 된다. 메모리는 BFS가 가장 넓은 층만큼, DFS가 높이만큼 쓴다.

## 면접에서 나올 만한 질문

### 오른쪽 자식만 따라가면 왜 틀리나요?

오른쪽 가지가 먼저 끝나면 그 아래층에서는 왼쪽 가지 노드가 가장 오른쪽이 되기 때문이다. `[1, 2]`처럼 오른쪽 자식이 없는 트리에서 바로 드러난다. 층마다 실제로 가장 오른쪽인 노드를 찾으려면 층을 만들어야 한다.

### BFS에서 층 경계는 어떻게 나누나요?

층을 시작하기 전에 큐의 길이를 변수에 고정하고 그 횟수만큼만 꺼낸다. 그 순간 큐에는 이번 층 노드만 있고, 꺼내는 동안 들어오는 자식은 다음 층이다. 루프 조건에서 큐 길이를 다시 읽으면 경계가 무너진다.

### DFS로 푼다면 어떻게 하나요?

깊이를 함께 넘기며 오른쪽 자식을 먼저 방문하고, 답 배열 길이와 깊이가 같을 때만 적는다. 그 깊이에 처음 닿은 노드가 가장 오른쪽이기 때문이다. 왼쪽을 먼저 간다면 처음 값이 아니라 마지막 값으로 덮어써야 한다.

### BFS와 DFS 중 메모리는 어느 쪽이 적게 드나요?

트리 모양에 달렸다. BFS는 가장 넓은 층만큼, DFS는 높이만큼 쓴다. 꽉 찬 트리는 넓이가 n/2 가까이라 DFS가 유리하고, 일자 트리는 높이가 n이라 BFS가 유리하다.

### 시간 복잡도는요?

모든 노드를 한 번씩 보니 O(n)이다. 층의 마지막 노드인지는 그 층을 다 보기 전에 알 수 없어서 노드를 건너뛸 수 없다. 층마다 트리를 처음부터 다시 훑는 풀이는 O(n·h)가 된다.

### 왼쪽에서 본 모습으로 바꾸려면요?

BFS라면 층의 첫 번째 노드를 적고, DFS라면 왼쪽을 먼저 방문하며 처음 닿은 노드를 적는다. 바꾸는 곳은 한 줄이다. 넣는 순서까지 같이 바꾸면 다시 오른쪽 모습이 되니 한 곳만 바꾼다.

### 위에서 본 모습도 같은 방법으로 되나요?

층이 아니라 가로 좌표가 기준이라 그대로는 안 된다. 뿌리를 0으로 두고 왼쪽 자식은 -1, 오른쪽 자식은 +1인 좌표를 들고 BFS로 내려가며, 좌표마다 처음 만난 노드를 적는다. BFS를 써야 같은 좌표에서 위층 노드가 먼저 잡힌다.
