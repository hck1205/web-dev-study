에디터에서 코드를 붙여 넣었더니 맨 끝 줄에 빨간 밑줄이 그어졌다. 어딘가 괄호가 하나 덜 닫혔다는 뜻인데, 에디터는 그걸 어떻게 알았을까. 괄호 개수만 세는 걸로는 부족하다. `(]`는 여는 것 하나, 닫는 것 하나로 개수는 맞지만 종류가 다르고, `([)]`는 종류별 개수까지 맞는데도 순서가 엉켜 있다.

[LeetCode 20. Valid Parentheses](https://leetcode.com/problems/valid-parentheses/)가 바로 이 검사를 함수로 짜는 문제다. 스택 문제의 입문으로 가장 먼저 나오고, 면접에서도 워밍업으로 자주 낸다. 쉬워 보이지만 빈 스택에서 꺼내기, 끝에 남은 괄호, 한 종류일 때와 여러 종류일 때의 차이 같은 곳에서 실수가 나온다. 이 글은 느린 풀이부터 시작해 스택 풀이와 재귀 풀이까지 여섯 가지를 따라가고, 면접관이 조건을 바꿔 묻는 변형도 함께 본다. 스택 자체가 무엇인지는 [스택·큐·덱 글](/posts/ds-stack-queue-deque)에서 다뤘다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 무엇을 확인하라는 문제인가

입력은 `(`, `)`, `[`, `]`, `{`, `}` 여섯 글자로만 이뤄진 문자열 `s`다. 다음 세 조건을 모두 지키면 `true`, 하나라도 어기면 `false`를 돌려준다.

- 여는 괄호는 같은 종류의 닫는 괄호로 닫힌다.
- 나중에 연 괄호가 먼저 닫힌다. 안쪽부터 닫아야 한다.
- 모든 닫는 괄호에는 그보다 앞에 열린 짝이 있다.

길이는 1 이상 10^4 이하다. 10^4이면 O(n²)도 1억 번 안쪽이라 돌기는 하지만, 이 문제는 O(n)이 자연스럽게 나오는 문제라 면접에서는 O(n)을 기대한다.

몇 개를 직접 판정해 보자.

```text
"()"        true   가장 단순한 짝
"()[]{}"    true   나란히 놓인 세 쌍
"{[()]}"    true   세 겹으로 겹친 쌍
"(]"        false  종류가 다르다
"([)]"      false  개수는 맞지만 순서가 엉켰다
"(("        false  닫히지 않고 끝났다
"]"         false  열지도 않았는데 닫았다
```

`([)]`를 손으로 따라가 보면 문제의 본질이 보인다. `(`를 열고, `[`를 열었다. 다음 글자는 `)`다. 이 `)`가 닫을 수 있는 건 무엇일까. `(`는 아니다. `(` 안에 `[`가 아직 열려 있으니, `(`를 닫으려면 `[`부터 닫아야 한다. 닫는 괄호가 나왔을 때 짝이 될 자격이 있는 건 "가장 최근에 열었고 아직 안 닫힌 괄호" 딱 하나다.

## 붙어 있는 짝부터 지워 나가기

손으로 풀 때 가장 먼저 떠오르는 방법은 이렇다. 올바른 괄호 문자열에는 반드시 바로 붙어 있는 짝(`()`, `[]`, `{}`)이 하나 이상 있다. 가장 안쪽 쌍은 사이에 아무것도 없기 때문이다. 그 짝을 지워도 나머지는 여전히 올바른 문자열이다. 그러니 붙은 짝을 더 지울 수 없을 때까지 지우고, 빈 문자열이 남는지 보면 된다.

```text
"{[()]}"  →  "()" 지움  →  "{[]}"  →  "[]" 지움  →  "{}"  →  "{}" 지움  →  ""   true
"([)]"    →  붙은 짝이 없다                                                       false
```

```js
function isValid(s) {
  let prev = null;
  // 한 바퀴 돌아도 문자열이 그대로면 더 지울 짝이 없다
  while (prev !== s) {
    prev = s;
    s = s.replace("()", "").replace("[]", "").replace("{}", "");
  }
  return s.length === 0;
}
```

`replace`에 문자열을 넘기면 처음 하나만 바꾼다. 그래서 한 바퀴에 종류별로 하나씩만 지워진다. `replaceAll`로 바꿔도 결과는 같고 바퀴 수만 줄어든다.

맞기는 한데 느리다. `replace` 한 번이 문자열 전체를 훑고 새 문자열을 만드니 O(n)이고, 최악에는 한 바퀴에 한 쌍만 지워진다. `(((...)))`처럼 n/2겹으로 겹친 입력이면 가장 안쪽 쌍 하나씩만 붙어 있어서 n/2바퀴를 돈다. 전체 O(n²)이다. 실제로 재 봤다.

```text
"(" * 5000 + ")" * 5000   →  5001바퀴, 101 ms
"(" * 20000 + ")" * 20000 →  1643 ms
```

10^4 길이에서 100ms 정도라 LeetCode는 통과하지만, 길이를 네 배로 늘리면 시간이 열여섯 배가 된다. 그리고 이 방법은 "가장 안쪽 쌍을 먼저 지운다"는 성질을 쓰고 있는데, 그걸 매번 문자열 전체를 다시 뒤져서 찾고 있다. 가장 안쪽 쌍이 어디서 생기는지 기억해 두면 다시 뒤질 필요가 없다. 그 기억 장치가 뒤에 나올 스택이다.

## 한 종류라면 숫자 하나로 충분하다

괄호가 `(`와 `)` 한 종류뿐이라면 스택조차 필요 없다. 지금 열려 있는 괄호의 개수만 세면 된다. 여는 괄호에서 1을 더하고 닫는 괄호에서 1을 뺀다. 중간에 음수가 되면 열지 않은 괄호를 닫은 것이고, 끝에 0이 아니면 닫히지 않은 괄호가 남은 것이다.

```js
// 소괄호 한 종류만 있을 때
function isValidOneKind(s) {
  let open = 0;
  for (const ch of s) {
    if (ch === "(") open++;
    else {
      open--;
      if (open < 0) return false; // 짝 없는 ')'
    }
  }
  return open === 0;
}
```

한 종류면 "가장 최근에 연 괄호"가 무엇인지 물을 필요가 없다. 어차피 다 `(`라서 아무거나 하나 닫으면 된다. 기억할 정보가 개수 하나뿐이니 공간이 O(1)이다.

그럼 종류마다 카운터를 하나씩 두면 세 종류도 풀릴까. 짜서 돌려 보면 `([)]`에서 `true`가 나온다. 종류별 개수는 모두 맞고 어느 순간에도 음수가 되지 않기 때문이다. 카운터는 "몇 개가 열려 있나"는 알지만 "어떤 순서로 열렸나"는 잊는다. 여러 종류에서는 바로 그 순서가 답을 가른다. 순서를 기억하려면 열린 괄호를 연 순서대로 늘어놓아야 하고, 꺼낼 때는 가장 나중 것부터 꺼내야 한다.

## 아직 닫히지 않은 괄호를 쌓아 두는 스택

"가장 최근에 넣은 것을 가장 먼저 꺼낸다"는 규칙이 스택(stack)이다. 접시를 쌓듯 위에만 올리고(push), 위에서만 내린다(pop). 괄호 검사에 딱 맞는다.

- 여는 괄호가 나오면 스택에 올린다. 아직 닫히지 않은 괄호 목록에 추가하는 셈이다.
- 닫는 괄호가 나오면 스택 맨 위를 내린다. 맨 위가 같은 종류의 여는 괄호여야 한다. 아니거나 스택이 비어 있으면 그 자리에서 `false`다.
- 끝까지 읽은 뒤 스택이 비어 있어야 `true`다. 남아 있으면 닫히지 않은 괄호가 있다.

스택의 맨 위는 항상 "가장 최근에 열었고 아직 안 닫힌 괄호"다. 앞에서 손으로 풀며 찾은 "짝이 될 자격이 있는 단 하나"가 바로 맨 위에 와 있다. 첫 번째 풀이가 매번 문자열을 뒤져서 찾던 가장 안쪽 쌍을, 스택은 위치를 기억해 두고 바로 꺼낸다.

뒤의 `)}`는 읽지도 않는다. 틀린 걸 알게 되는 순간 끝내면 된다.

코드로 옮기면 이렇다. 닫는 괄호를 키로, 그 짝인 여는 괄호를 값으로 둔 표를 하나 만들어 두면 비교가 한 줄이 된다.

```js
function isValid(s) {
  // 길이가 홀수면 짝이 맞을 수 없다
  if (s.length % 2 === 1) return false;

  // 닫는 괄호 → 짝이 되는 여는 괄호
  const pair = { ")": "(", "]": "[", "}": "{" };
  const stack = [];

  for (const ch of s) {
    if (ch in pair) {
      // 닫는 괄호: 맨 위가 짝이어야 한다
      // 빈 스택이면 pop()이 undefined라서 비교에서 자연스럽게 걸린다
      if (stack.pop() !== pair[ch]) return false;
    } else {
      // 여는 괄호: 쌓아 둔다
      stack.push(ch);
    }
  }
  // 닫히지 않은 괄호가 남았으면 false
  return stack.length === 0;
}
```

시간은 O(n)이다. 글자마다 push나 pop을 한 번씩 하고, 둘 다 O(1)이다. 공간은 최악 O(n)이다. `((((((`처럼 여는 괄호만 이어지면 전부 쌓인다. 정확히는 스택이 n/2를 넘는 순간 남은 글자를 다 닫아도 0이 될 수 없으니, 거기서 끊으면 스택 크기를 n/2로 묶을 수 있다. 차수는 그대로 O(n)이다.

맨 앞의 홀수 길이 검사는 정답에 꼭 필요하지는 않다. 빼도 결과는 같다. 다만 입력이 이 여섯 글자로만 이뤄진다는 조건이 있어서 성립하는 지름길이라, 다른 글자가 섞이는 변형에서는 지워야 한다.

### Python과 Java로 쓰면

Python은 리스트가 그대로 스택이다. `append`로 넣고 `pop`으로 뺀다. 한 가지 다른 점은 빈 리스트에서 `pop()`을 부르면 `undefined`가 아니라 `IndexError`가 난다는 것이다. 그래서 비었는지 먼저 확인한다.

```python
def is_valid(s: str) -> bool:
    if len(s) % 2 == 1:
        return False
    pair = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in pair:
            # 빈 스택이면 pop()이 IndexError를 내므로 먼저 확인한다
            if not stack or stack.pop() != pair[ch]:
                return False
        else:
            stack.append(ch)
    return not stack
```

Java는 `Stack` 클래스가 있지만 쓰지 않는 편이 좋다. `Stack`은 `Vector`를 상속해서 모든 메서드에 동기화가 걸려 있고, Java 문서도 `Deque` 구현체인 `ArrayDeque`를 쓰라고 권한다. 아래 코드는 여는 괄호 대신 기대하는 닫는 괄호를 넣는 방식이다(다음 절에서 설명한다).

```java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public boolean isValid(String s) {
        if (s.length() % 2 == 1) return false;
        Deque<Character> stack = new ArrayDeque<>();
        for (char ch : s.toCharArray()) {
            switch (ch) {
                case '(' -> stack.push(')');
                case '[' -> stack.push(']');
                case '{' -> stack.push('}');
                default -> {
                    // 빈 스택에서 pop()은 예외를 던지므로 isEmpty를 먼저 본다
                    if (stack.isEmpty() || stack.pop() != ch) return false;
                }
            }
        }
        return stack.isEmpty();
    }
}
```

Java에서 조심할 곳이 두 군데 있다. `ArrayDeque.pop()`은 비어 있으면 `NoSuchElementException`을 던진다. 그리고 `stack.pop() != ch`는 오른쪽이 `char`라서 왼쪽 `Character`가 언박싱되어 값으로 비교된다. 양쪽이 모두 `Character` 객체였다면 `==`는 참조 비교가 된다. 아스키 범위 문자는 캐시된 객체를 써서 우연히 맞게 나오지만, 습관적으로 객체끼리 `==`를 쓰면 다른 문제에서 틀린다. 객체끼리는 `equals`로 비교한다.

세 언어로 같은 입력을 돌린 결과다.

```text
""          true
"()"        true
"()[]{}"    true
"{[()]}"    true
"([)]"      false
"(("        false
"]"         false
"(([]){})"  true
```

## 여는 괄호 대신 기다리는 닫는 괄호를 쌓는다

위 Java 코드처럼 여는 괄호를 만났을 때 그 짝인 닫는 괄호를 쌓아도 된다. 스택에는 "앞으로 나와야 할 닫는 괄호"가 순서대로 쌓이고, 닫는 괄호를 만나면 맨 위와 같은지만 보면 된다.

```js
function isValid(s) {
  const stack = []; // 앞으로 나와야 할 닫는 괄호
  for (const ch of s) {
    if (ch === "(") stack.push(")");
    else if (ch === "[") stack.push("]");
    else if (ch === "{") stack.push("}");
    else if (stack.pop() !== ch) return false; // 기다리던 것과 다르다
  }
  return stack.length === 0;
}
```

복잡도는 똑같이 시간 O(n), 공간 O(n)이다. 짝 표를 거꾸로 찾는 단계가 없어서 비교가 조금 더 직접적이고, `switch`로 쓰기 좋다. 스택 안의 내용을 위에서부터 읽으면 "이 문자열을 올바르게 끝내려면 뒤에 붙여야 할 글자"가 그대로 나온다는 것도 재미있는 성질이다. `{[(`까지 읽었다면 스택은 바닥부터 `}`, `]`, `)`이고, 위에서부터 읽은 `)]}`를 붙이면 올바른 문자열이 된다. 에디터가 괄호를 자동으로 닫아 줄 때 이 정보를 쓴다.

## 배열과 top 하나로 직접 만든 스택

JavaScript 배열의 `push`, `pop`은 이미 분할 상환 O(1)이라 실전에서는 충분하다. 그래도 면접관이 "스택 자료구조를 쓰지 말고 짜 보라"고 하거나, C처럼 동적 배열이 없는 언어라면 고정 크기 배열과 맨 위를 가리키는 정수 하나로 스택을 만든다.

```js
function isValid(s) {
  const st = new Array(s.length); // 최대 크기를 미리 잡는다
  let top = 0;                     // 다음에 넣을 자리 = 현재 높이
  for (const ch of s) {
    if (ch === "(" || ch === "[" || ch === "{") {
      st[top++] = ch;
    } else {
      if (top === 0) return false;  // 열린 괄호가 없다
      const open = st[--top];
      if ((ch === ")" && open !== "(") ||
          (ch === "]" && open !== "[") ||
          (ch === "}" && open !== "{")) return false;
    }
  }
  return top === 0;
}
```

top 아래 칸만 유효하고 위 칸에 남은 값은 쓰레기다. 지우지 않고 덮어쓴다. 할당이 처음 한 번뿐이라 GC가 할 일이 없다. 언어가 문자 배열을 바꿀 수 있게 해 준다면(C, C++, Java의 `char[]`) 입력 배열의 앞부분 자체를 스택으로 써서 추가 공간을 없앨 수도 있다. 읽기 위치 i는 항상 top 이상이라서, 이미 읽은 칸에만 덮어쓰기 때문이다. 입력을 망가뜨리니 실무 코드에서는 쓰지 않는 트릭이고, 면접에서 "추가 공간을 더 줄일 수 있나"를 물으면 꺼낼 만하다.

## 재귀로 읽으면 콜 스택이 스택 노릇을 한다

스택을 직접 만들지 않고 재귀로도 풀 수 있다. 올바른 괄호 문자열을 문법으로 쓰면 "여는 괄호, 올바른 괄호 문자열, 같은 종류의 닫는 괄호"가 0번 이상 이어진 것이다. 정의 안에 자기 자신이 들어 있으니 재귀 함수로 그대로 옮긴다. 컴파일러가 코드를 읽을 때 쓰는 재귀 하강 파서(recursive descent parser)와 같은 방식이다.

```js
function isValid(s) {
  const close = { "(": ")", "[": "]", "{": "}" };
  let i = 0; // 지금 읽는 위치. 모든 호출이 함께 쓴다

  // 지금 위치부터 올바른 괄호 묶음을 읽을 수 있는 만큼 읽는다
  function group() {
    while (i < s.length && s[i] in close) {
      const want = close[s[i]];
      i++;                              // 여는 괄호를 먹는다
      if (!group()) return false;       // 안쪽 내용은 재귀로 읽는다
      if (s[i] !== want) return false;  // 그다음엔 짝이 와야 한다
      i++;                              // 닫는 괄호를 먹는다
    }
    return true; // 닫는 괄호나 끝을 만나면 이 층은 끝
  }
  // 다 읽고 나서 남은 글자가 없어야 한다. "))"는 i가 0에서 멈춘다
  return group() && i === s.length;
}
```

명시적인 스택은 없지만 `want`를 들고 있는 호출들이 콜 스택에 쌓인다. 여는 괄호 하나에 호출 하나가 쌓이고, 닫히면 그 호출이 끝난다. 앞 절의 "기다리는 닫는 괄호 스택"을 언어가 대신 관리해 주는 셈이다. 시간 O(n), 공간은 중첩 깊이만큼 O(n)이다.

문제는 콜 스택이 힙보다 훨씬 작다는 것이다. 깊게 겹친 입력으로 재 봤다.

```text
JavaScript (Node 22)  깊이 10000  → true
                      깊이 100000 → RangeError: Maximum call stack size exceeded
Python 3.13           깊이 500    → True
                      깊이 5000   → RecursionError: maximum recursion depth exceeded
```

Python은 기본 재귀 한도가 1000이라 LeetCode 제약(길이 10^4, 깊이 최대 5000) 안에서도 터진다. `sys.setrecursionlimit`으로 올릴 수는 있지만 인터프리터 자체가 죽을 수 있어서 권하지 않는다. 그래서 이 문제는 명시적 스택이 기본 답이고, 재귀 풀이는 "스택과 재귀가 같은 일을 한다"는 걸 보여 주는 용도로 꺼낸다. 재귀와 콜 스택의 관계는 [재귀와 백트래킹 글](/posts/recursion-backtracking)에서 더 다뤘다.

## 여섯 풀이를 나란히 놓으면

| 풀이 | 시간 | 공간 | 언제 고르나 |
|---|---|---|---|
| 붙은 짝 지우기 | O(n²) | O(n) | 원리를 손으로 확인할 때. 실전에서는 쓰지 않는다 |
| 카운터 하나 | O(n) | O(1) | 괄호가 한 종류뿐일 때만 맞다 |
| 여는 괄호 스택 + 짝 표 | O(n) | O(n) | 기본 답. 괄호 종류가 늘어도 표에 한 줄만 추가하면 된다 |
| 닫는 괄호 스택 | O(n) | O(n) | 비교를 더 단순하게 쓰고 싶을 때, 자동 닫기처럼 남은 짝이 필요할 때 |
| 고정 배열 + top | O(n) | O(n), 입력 재사용 시 O(1) 추가 | 스택 라이브러리 없이 짜라고 할 때, 할당을 줄이고 싶을 때 |
| 재귀 하강 | O(n) | O(n) 콜 스택 | 문법 정의를 그대로 옮기고 싶을 때. 깊은 입력에서 스택 오버플로가 난다 |

## 틀리기 쉬운 입력들

스택 풀이는 짧아서 틀릴 곳이 없어 보이지만, 실제로 자주 빠뜨리는 곳이 정해져 있다.

끝에 스택이 비었는지 확인하지 않는 실수가 가장 흔하다. 반복문 안에서는 "닫는 괄호가 맨 위와 맞는가"만 보니, 여는 괄호만 있는 입력은 반복문을 무사히 통과한다.

```js
// 마지막 확인이 빠진 코드
for (const ch of s) {
  if (ch in pair) {
    if (stack.pop() !== pair[ch]) return false;
  } else stack.push(ch);
}
return true; // "((" 에서 true가 나온다
```

빈 스택에서 꺼내는 경우도 언어마다 다르게 터진다. JavaScript는 `pop()`이 `undefined`를 돌려줘서 짝 비교에서 저절로 `false`가 되지만, Python은 `IndexError`, Java는 `NoSuchElementException`이 난다. `]`나 `)(` 같은 입력으로 꼭 돌려 본다. JavaScript에서도 짝 표를 여는 괄호 기준(`{"(": ")"}`)으로 만들고 `pair[stack.pop()] !== ch`로 비교하면, 빈 스택일 때 `pair[undefined]`가 `undefined`라서 우연히 맞게 동작한다. 우연히 맞는 코드는 고칠 때 깨진다. 빈 스택을 명시적으로 확인하는 편이 읽는 사람에게도 친절하다.

괄호 종류를 판별하는 조건이 겹치는 실수도 있다. `if (ch === "(" || "[" || "{")`처럼 쓰면 `"["`가 항상 참이라 모든 글자가 여는 괄호로 처리된다. 비교는 하나씩 따로 써야 한다.

빈 문자열은 LeetCode 제약에서는 나오지 않지만(길이 1 이상), 함수로 쓸 때는 `true`로 보는 게 일반적이다. 괄호가 하나도 없으면 어긋난 괄호도 없다. 위 코드는 반복문을 돌지 않고 빈 스택을 확인해 `true`를 돌려준다.

## 면접관이 조건을 바꾸면

### 괄호가 아닌 글자가 섞여 있다면

코드 한 줄을 통째로 검사하는 상황이다. 괄호가 아닌 글자는 건너뛰면 된다. 홀수 길이 지름길은 더는 쓸 수 없다.

```js
function isValidWithText(s) {
  const pair = { ")": "(", "]": "[", "}": "{" };
  const opens = new Set(["(", "[", "{"]);
  const stack = [];
  for (const ch of s) {
    if (opens.has(ch)) stack.push(ch);
    else if (ch in pair) {
      if (stack.pop() !== pair[ch]) return false;
    }
    // 그 밖의 글자는 무시한다
  }
  return stack.length === 0;
}
// "if (a[0] > 1) { f(x); }" → true,  "call(a[1)]" → false
```

진짜 에디터는 여기서 한 단계 더 간다. 문자열 리터럴이나 주석 안의 괄호는 세지 않아야 한다. `")"`라는 문자열 하나 때문에 코드 전체가 틀렸다고 하면 안 되니, 따옴표를 만나면 "문자열 안" 상태로 바꾸고 닫는 따옴표까지 괄호를 무시한다. 상태 하나를 더 두는 것만으로 처리된다.

### 어디가 틀렸는지 알려 달라면

`true`/`false` 대신 첫 오류 위치를 돌려주게 바꾼다. 스택에 글자 대신 인덱스를 넣으면 남은 괄호가 어디서 열렸는지도 알 수 있다. 짝이 안 맞는 닫는 괄호가 나오면 그 위치가 오류이고, 끝까지 갔는데 스택이 남았으면 가장 바닥의 인덱스, 즉 가장 먼저 열고 안 닫은 괄호가 오류다.

```js
function firstError(s) {
  const pair = { ")": "(", "]": "[", "}": "{" };
  const stack = []; // 여는 괄호의 인덱스
  for (let i = 0; i < s.length; i++) {
    const ch = s[i];
    if (ch in pair) {
      if (!stack.length || s[stack.at(-1)] !== pair[ch]) return i;
      stack.pop();
    } else stack.push(i);
  }
  return stack.length ? stack[0] : -1; // -1이면 오류 없음
}
// "{[(])}" → 3,  "(()" → 0,  "()]" → 2,  "(())" → -1
```

에디터의 빨간 밑줄도 이렇게 위치를 잡는다. 스택에 인덱스를 넣는 이 습관은 [Daily Temperatures](/posts/leetcode-daily-temperatures)나 [히스토그램의 가장 큰 직사각형](/posts/leetcode-largest-rectangle-in-histogram)처럼 "몇 칸 떨어졌나"를 계산해야 하는 스택 문제에서 그대로 쓰인다.

### 최소 몇 개를 붙이면 올바르게 되나

LeetCode 921 Minimum Add to Make Parentheses Valid다. 소괄호 한 종류라서 카운터로 충분하다. 짝 없는 `)`를 만날 때마다 앞에 `(`를 하나 붙여야 하고, 끝에 남은 `(` 개수만큼 `)`를 붙여야 한다.

```js
function minAddToMakeValid(s) {
  let open = 0; // 아직 짝을 못 찾은 '('
  let add = 0;  // 짝이 없어 '('를 붙여야 하는 ')'
  for (const ch of s) {
    if (ch === "(") open++;
    else if (open > 0) open--;
    else add++;
  }
  return add + open;
}
// "())(" → 2,  "(((" → 3,  ")))(((" → 6
```

여러 종류의 괄호로 최소 수정 횟수를 묻는다면 스택으로는 안 되고 구간 DP가 필요하다. 문제가 갑자기 어려워지는 지점이라, 면접에서 이걸 물으면 "한 종류는 그리디로 O(n), 여러 종류는 구간 DP로 O(n³)"이라고 차이를 짚는다. DP의 기본은 [동적 계획법 글](/posts/dynamic-programming)에 있다.

### 어떤 글자로든 바뀔 수 있는 와일드카드가 있다면

LeetCode 678 Valid Parenthesis String이다. `*`가 `(`, `)`, 빈칸 중 무엇이든 될 수 있다. 경우의 수를 다 따지면 3^k가지지만, 열린 괄호 개수가 될 수 있는 범위 `[lo, hi]`만 들고 다니면 O(n)에 끝난다.

```js
function checkValidString(s) {
  let lo = 0, hi = 0; // 열린 '(' 개수의 최소·최대
  for (const ch of s) {
    if (ch === "(") { lo++; hi++; }
    else if (ch === ")") { lo--; hi--; }
    else { lo--; hi++; }      // '*'는 ')' 또는 '(' 또는 빈칸
    if (hi < 0) return false; // '*'를 전부 '('로 써도 모자란다
    if (lo < 0) lo = 0;       // 개수는 음수가 될 수 없다
  }
  return lo === 0;
}
// "(*))" → true,  "(*)(" → false,  "*)" → true,  "((*" → false
```

카운터를 범위로 넓힌 그리디다. 이것도 괄호가 한 종류라서 가능하다.

### 문자열이 메모리에 다 안 들어간다면

수 GB짜리 JSON 파일의 괄호가 맞는지 보는 상황이다. 스택 풀이는 앞에서 뒤로 한 번만 읽고 지나간 글자를 다시 보지 않으니, 파일을 청크 단위로 흘려 읽으면서 그대로 돌릴 수 있다. 필요한 메모리는 입력 크기가 아니라 최대 중첩 깊이에 비례한다. 실제 JSON 파서도 같은 이유로 중첩 깊이에 상한을 둔다. 깊이 제한이 없으면 `[[[[...`만 수백만 개 보내는 입력 하나로 메모리나 재귀 스택을 터뜨릴 수 있기 때문이다.

### 올바른 괄호를 모두 만들라면

검사의 반대 방향이다. n쌍으로 만들 수 있는 올바른 괄호 문자열을 전부 나열하는 [LeetCode 22. Generate Parentheses](/posts/leetcode-generate-parentheses)가 이어지는 문제다. 거기서는 "지금까지 연 개수와 닫은 개수"라는 이 글의 카운터 아이디어가 백트래킹의 가지치기 조건이 된다. 가장 긴 올바른 괄호 부분 문자열을 찾는 LeetCode 32 Longest Valid Parentheses도 스택에 인덱스를 넣는 방식으로 푼다.

스택 문제 전체의 흐름은 [단조 스택 패턴 글](/posts/monotonic-stack-pattern)에서 이어서 볼 수 있고, 같은 패턴의 다음 문제로 [Min Stack](/posts/leetcode-min-stack)이 있다.

## 가장 최근에 연 괄호 하나만 보면 된다

괄호 검사는 "닫는 괄호의 짝이 될 수 있는 건 가장 최근에 연 괄호 하나뿐"이라는 관찰에서 끝난다. 가장 최근 것을 바로 꺼내 주는 자료구조가 스택이라, 여는 괄호는 쌓고 닫는 괄호는 맨 위와 맞춰 본다. 마지막에 스택이 비었는지 확인하는 것까지가 한 세트다. 한 종류라면 순서를 기억할 필요가 없어서 카운터 하나로 줄어든다는 것도 같이 기억해 두면, 변형 문제가 나와도 무엇이 스택을 필요하게 만드는지 설명할 수 있다.

## 면접에서 나올 만한 질문

### 왜 스택을 썼나요?

닫는 괄호가 짝을 맞출 수 있는 대상은 가장 최근에 열었고 아직 닫히지 않은 괄호 하나뿐이기 때문이다. 나중에 들어온 것이 먼저 나가는 구조가 스택이라, 스택 맨 위가 항상 그 괄호가 된다. 덕분에 닫는 괄호마다 O(1)에 확인하고 전체가 O(n)이 된다.

### 시간과 공간 복잡도는 어떻게 되나요?

시간은 O(n)이다. 글자마다 push나 pop을 한 번 하고 각각 O(1)이다. 공간은 최악 O(n)으로, 여는 괄호만 이어지는 입력에서 전부 쌓인다. 스택이 남은 글자 수보다 커지면 바로 false를 내서 n/2로 묶을 수는 있지만 차수는 같다.

### 공간을 O(1)로 줄일 수 있나요?

괄호가 한 종류라면 열린 개수를 세는 카운터 하나로 O(1)이 된다. 세 종류에서는 일반적으로 안 된다. 종류별 카운터는 `([)]`를 통과시키는데, 순서 정보가 사라지기 때문이다. 입력 문자 배열을 바꿔도 된다면 읽은 앞부분을 스택으로 재사용해 추가 공간을 O(1)로 만들 수는 있다.

### 이 코드가 틀리는 입력을 말해 보라면요?

가장 흔한 버그는 마지막에 스택이 비었는지 확인하지 않는 것이고, `((`에서 true가 나온다. 다음은 빈 스택에서 pop하는 경우로, `]`를 넣으면 Python과 Java는 예외가 난다. 개수만 세는 풀이라면 `([)]`가 반례다.

### Java에서는 어떤 스택을 쓰나요?

`Stack` 대신 `ArrayDeque`를 쓴다. `Stack`은 `Vector`를 상속해 모든 메서드가 동기화되어 있고, 공식 문서도 `Deque` 구현을 권한다. `ArrayDeque.pop()`은 비었을 때 예외를 던지니 `isEmpty()`를 먼저 보고, `Character` 객체끼리는 `==` 대신 `equals`로 비교한다.

### 문자열이 수 GB라서 메모리에 다 못 올리면요?

스택 풀이는 한 번만 앞에서 뒤로 읽으니 스트리밍으로 그대로 돌릴 수 있다. 메모리는 입력 크기가 아니라 최대 중첩 깊이에 비례한다. 다만 악의적인 입력이 깊이를 끝없이 늘릴 수 있으니, 실제 파서처럼 깊이 상한을 두고 넘으면 거부한다.

### 와일드카드 `*`가 섞이면 어떻게 푸나요?

`*`가 `(`, `)`, 빈칸 중 하나가 될 수 있다면, 열린 괄호 개수가 될 수 있는 최소와 최대를 함께 들고 다닌다. 최대가 음수가 되면 실패, 최소가 음수가 되면 0으로 올린다. 끝에 최소가 0이면 성공이고, O(n) 시간, O(1) 공간이다.
