<EasyIntro>
  신발장에 신발이 잔뜩 있는데, 모두 짝이 맞고 딱 한 짝만 짝이 없다고 해 보자. 신발을 하나 집을 때마다 나머지 신발을 전부 뒤져 보면 확실하지만 신발이 많으면 하루 종일 걸린다. 조금 나은 방법은 바닥에 빈 자리를 두고, 신발을 하나 꺼낼 때마다 바닥에 짝이 있으면 둘을 같이 치우고 없으면 내려놓는 것이다. 끝까지 하면 바닥에는 짝 없는 신발 하나만 남지만 바닥 자리가 꽤 넓어야 한다. 가장 신기한 방법은 같은 신발이 두 번 들어오면 둘 다 없애 버리는 마법 상자를 쓰는 것이다. 신발을 순서와 상관없이 하나씩 넣기만 하면 마지막에 짝 없는 신발 하나만 남고, 상자 크기는 신발 한 켤레만큼이면 충분하다. 컴퓨터에서는 XOR라는 연산이 바로 이 상자 노릇을 한다.

[Single Number](https://leetcode.com/problems/single-number/)는 LeetCode 136번이다. 배열의 모든 수가 두 번씩 나오고 딱 하나만 한 번 나온다. 그 하나를 찾으면 된다. 해시맵으로 세면 금방 풀리는데, 문제가 "추가 메모리는 상수만 쓰라"는 조건을 붙여 둔다. 이 조건 하나 때문에 이 문제가 비트 연산 문제의 첫 관문이 된다.

XOR가 무엇이고 왜 같은 수를 지우는지는 [비트 연산 글](/posts/bit-manipulation#짝이-없는-수는-xor가-찾는다)에서 한 번 봤다. 이 글은 그 성질을 문제 하나에 끝까지 적용해 본다. 느린 풀이부터 XOR까지 여섯 가지로 풀고, 정렬된 배열이면 어떻게 하나, 짝 없는 수가 둘이면, 세 번씩 나오면 같은 꼬리 질문까지 간다. 코드는 Node.js 22, Python 3.13, Java 21에서 직접 돌렸다.

## 두 번씩 나오는 수들 사이의 외톨이

정수 배열 `nums`가 주어진다. 한 수만 빼고 모든 수가 정확히 두 번 나온다. 한 번만 나오는 그 수를 돌려준다. 답은 언제나 하나 있다.

제약 중 풀이를 정하는 건 이 정도다.

- 배열 길이는 1 이상 3 × 10^4 이하이고 항상 홀수다(짝 개수 × 2 + 1).
- 값은 -3 × 10^4 이상 3 × 10^4 이하다. 음수가 섞여 있다.
- 시간은 선형(O(n)), 추가 공간은 상수(O(1))로 풀라고 문제에 적혀 있다.

n이 3만이면 O(n²)도 4억 5천만 번 정도라 아주 느리긴 해도 운 좋으면 통과한다. 그래서 이 문제의 진짜 벽은 시간이 아니라 세 번째 줄, 공간이다. 해시맵이나 집합처럼 n에 비례해 커지는 메모리를 쓰지 말라는 뜻이다.

## 손으로 짝을 지워 보면

예시 하나를 정해 두고 끝까지 쓴다.

```text
인덱스   0   1   2   3   4
nums     5   3   8   3   5
```

답은 8이다. 손으로 찾을 때 머릿속에서 하는 일은 "짝이 맞은 수는 지운다"다. 5를 보고, 3을 보고, 8을 보고, 다시 3을 보면 아까 본 3과 짝이 맞으니 둘 다 지운다. 마지막 5도 처음 5와 짝이 맞아 지운다. 남은 건 8이다.

이 "지운다"를 어떻게 하느냐가 풀이를 가른다. 매번 배열 전체를 다시 세면 브루트포스, 같은 수끼리 붙여 놓고 지우면 정렬, 본 수를 장부에 적었다 지우면 해시, 그리고 장부 없이 숫자 하나 안에서 지우면 XOR다.

## 수마다 몇 번 나오는지 다시 세기

가장 먼저 떠오르는 건 정의를 그대로 옮기는 것이다. 각 수가 배열에 몇 번 나오는지 세고, 한 번인 수를 돌려준다.

```js
function singleNumber(nums) {
  for (let i = 0; i < nums.length; i++) {
    let count = 0;
    // nums[i]가 배열 전체에 몇 번 나오는지 센다
    for (let j = 0; j < nums.length; j++) {
      if (nums[j] === nums[i]) count++;
    }
    if (count === 1) return nums[i];
  }
}

console.log(singleNumber([5, 3, 8, 3, 5]), singleNumber([7]), singleNumber([-4, 2, 2]));
```

```text
8 7 -4
```

시간은 O(n²)다. 바깥 반복이 n번, 안쪽 반복도 매번 n번이다. 공간은 `count` 하나라 O(1)이다. 공간 조건은 지키지만 시간 조건을 못 지킨다.

외톨이가 배열 앞쪽에 있으면 일찍 끝나고, 맨 끝에 있으면 끝까지 돈다. 길이 59999짜리 배열에서 외톨이를 맨 끝에 두었더니 2443ms가 걸렸다. 같은 배열을 XOR 풀이는 1ms도 안 걸려 끝낸다(뒤의 측정 절).

이 풀이가 느린 이유는 같은 수를 여러 번 센다는 데 있다. 3을 셀 때도, 다른 3을 셀 때도 배열 전체를 훑는다. 한 번 센 결과를 어디에 남겨 두면 다시 세지 않아도 된다.

## 정렬하면 짝이 나란히 선다

배열을 정렬하면 같은 수는 반드시 이웃한다. 짝이 있는 수는 두 칸씩 붙어 서고, 외톨이 하나 때문에 그 뒤로 짝의 자리가 한 칸씩 밀린다.

```text
정렬 전   5  3  8  3  5
정렬 후   3  3  5  5  8
짝 묶음  [3  3][5  5][8
```

그러니 0번과 1번, 2번과 3번처럼 두 칸씩 묶어 보다가 묶음 안의 두 수가 다르면 그 묶음의 첫 칸이 외톨이다. 끝까지 다 맞으면 맨 마지막 칸이 외톨이다.

```js
function singleNumber(nums) {
  const a = [...nums].sort((x, y) => x - y); // 입력을 망가뜨리지 않으려고 복사한다
  for (let i = 0; i < a.length - 1; i += 2) {
    // 짝의 첫 칸(짝수 인덱스)과 다음 칸을 비교한다
    if (a[i] !== a[i + 1]) return a[i];
  }
  return a[a.length - 1]; // 모든 묶음이 맞으면 외톨이는 맨 끝에 있다
}

console.log(singleNumber([5, 3, 8, 3, 5]), singleNumber([7]), singleNumber([-4, 2, 2]));
```

```text
8 7 -4
```

왜 첫 칸을 돌려줄까. 외톨이 x가 정렬된 자리에 들어가면, x 앞쪽의 묶음은 모두 온전하고 x가 들어간 묶음에서 처음으로 어긋난다. x가 묶음의 첫 칸이 되고 둘째 칸에는 x보다 큰 다음 수가 온다. 예시에서 3과 5 묶음은 맞고, 8은 짝 없이 혼자 남는다.

시간은 정렬 때문에 O(n log n)이다. 공간은 복사본 O(n)이고, 입력을 바로 정렬해도 된다면 정렬 구현이 쓰는 만큼만 든다. 시간과 공간 조건을 둘 다 못 지킨다. 그래도 이 풀이에서 나온 "짝의 자리"라는 생각은 뒤의 정렬된 배열 변형에서 이진 탐색으로 다시 쓴다.

## 장부에 횟수를 적어 두기

브루트포스가 같은 수를 여러 번 센 문제는 장부로 푼다. 한 번 훑으며 수마다 몇 번 나왔는지 해시맵에 적고, 장부에서 횟수가 1인 수를 찾는다.

```js
function singleNumber(nums) {
  const count = new Map(); // 수 → 나온 횟수
  for (const x of nums) count.set(x, (count.get(x) ?? 0) + 1);
  for (const [x, c] of count) {
    if (c === 1) return x; // 한 번만 나온 수
  }
}

console.log(singleNumber([5, 3, 8, 3, 5]), singleNumber([7]), singleNumber([-4, 2, 2]));
```

```text
8 7 -4
```

시간은 평균 O(n)이다. 배열을 한 번, 장부를 한 번 훑는다. 공간은 서로 다른 수의 개수만큼이라 약 n/2, 즉 O(n)이다. 해시맵이 왜 평균 O(1)에 찾고 넣는지는 [해시맵 글](/posts/ds-hash-map)에 있다.

이 풀이는 이 문제에만 묶이지 않는다는 장점이 있다. 세 번씩 나오든, 외톨이가 여럿이든, 횟수만 바꿔 보면 된다. 면접에서 "일단 동작하는 풀이"로 가장 먼저 내기 좋다. 다만 공간 조건은 여전히 못 지킨다.

## 짝이 맞으면 바닥에서 치운다

횟수를 끝까지 셀 필요는 없다. 짝이 맞는 순간 지워 버리면 된다. 집합에 없으면 넣고, 있으면 뺀다. 끝까지 돌면 집합에는 외톨이 하나만 남는다. 앞의 "손으로 짝을 지워 보면"에서 머릿속으로 하던 일을 그대로 옮긴 셈이다.

```js
function singleNumber(nums) {
  const open = new Set(); // 아직 짝을 못 만난 수들
  for (const x of nums) {
    if (open.has(x)) open.delete(x); // 짝을 만났다 → 둘 다 치운다
    else open.add(x);                // 처음 봤다 → 짝을 기다린다
  }
  return open.values().next().value; // 하나만 남아 있다
}

console.log(singleNumber([5, 3, 8, 3, 5]), singleNumber([7]), singleNumber([-4, 2, 2]));
```

```text
8 7 -4
```

아래 그림에서 다음을 누르면 한 칸씩 넘어가며 집합이 커졌다 줄어든다.

이 그림을 잘 보면 이상한 점이 하나 있다. 집합이 들고 있는 건 "지금까지 홀수 번 나온 수"다. 넣을 때 한 번, 뺄 때 두 번째, 다시 넣을 때 세 번째. 결국 집합은 수마다 "홀수인가 짝수인가" 한 칸짜리 정보만 쓴다. 이 정보를 집합 대신 숫자 하나에 담을 수 있다면 공간이 O(1)이 된다.

## 합으로 계산하기

XOR로 가기 전에 산수로 푸는 방법도 있다. 서로 다른 수를 한 번씩 더해 두 배 하면 "모든 수가 짝을 이뤘을 때의 합"이 된다. 실제 배열의 합은 외톨이의 짝 하나가 빠진 값이다. 둘의 차이가 외톨이다.

```text
서로 다른 수   5 + 3 + 8      = 16,  두 배 하면 32
배열 전체      5 + 3 + 8 + 3 + 5 = 24
외톨이         32 - 24        = 8
```

```js
function singleNumber(nums) {
  let all = 0, uniq = 0;
  for (const x of nums) all += x;           // 배열 전체의 합
  for (const x of new Set(nums)) uniq += x; // 서로 다른 수의 합
  return 2 * uniq - all;                    // 짝이 다 있었다면의 합 - 실제 합
}

console.log(singleNumber([5, 3, 8, 3, 5]), singleNumber([7]), singleNumber([-4, 2, 2]));
```

```text
8 7 -4
```

시간 O(n), 공간 O(n)이다. 결국 "서로 다른 수"를 구하려고 집합을 쓰니 공간은 줄지 않았다. 그래도 이 풀이를 알아 두면 좋은 이유가 있다. 바로 다음 풀이의 생각이 같기 때문이다. 짝이 맞는 것끼리 서로 상쇄되게 만들고, 상쇄되지 않고 남는 것을 읽는다. 덧셈은 같은 수를 두 번 더하면 커지기만 해서 집합이 필요했다. 같은 수를 두 번 하면 0이 되는 연산이 있으면 집합 없이 된다.

Java처럼 정수 폭이 정해진 언어라면 합이 넘치지 않는지도 봐야 한다. 이 문제의 범위에서는 서로 다른 수의 합이 최대 약 1.5 × 10^4개 × 3 × 10^4 = 4.5 × 10^8이고 두 배 해도 9 × 10^8이라 `int` 안에 든다. 범위가 커지면 `long`으로 바꾼다.

## 같은 수를 두 번 섞으면 사라진다

XOR(배타적 논리합)는 두 비트가 다르면 1, 같으면 0을 내는 연산이다. 정수끼리 XOR하면 자리마다 이 규칙을 적용한다. 이 문제에 필요한 성질은 셋이다.

- 같은 수를 두 번 XOR하면 0이다. `a ^ a = 0`
- 0과 XOR하면 그대로다. `a ^ 0 = a`
- 순서와 묶는 방법을 바꿔도 결과가 같다. `a ^ b ^ a = a ^ a ^ b`

세 번째 성질 덕분에 배열 순서가 어떻든 같은 수끼리 모아 놓고 생각할 수 있다.

```text
5 ^ 3 ^ 8 ^ 3 ^ 5
= (5 ^ 5) ^ (3 ^ 3) ^ 8   ← 순서를 바꿔 짝끼리 모은다
= 0 ^ 0 ^ 8
= 8
```

앞 절의 집합이 수마다 "홀수 번 나왔나"를 들고 있었다고 했다. XOR는 그 정보를 비트마다 들고 있다. 결과의 어떤 자리가 1이라는 건 그 자리가 1인 수가 홀수 번 섞였다는 뜻이다. 짝이 있는 수는 모든 자리에서 짝수 번 섞이니 흔적이 남지 않고, 외톨이의 비트만 남는다.

예시를 이진수로 세로로 세워 보면 이 말이 바로 보인다.

```text
          8의 자리  4의 자리  2의 자리  1의 자리
5            0        1        0        1
3            0        0        1        1
8            1        0        0        0
3            0        0        1        1
5            0        1        0        1
1의 개수     1        2        2        4
홀짝         홀       짝       짝       짝
결과         1        0        0        0   → 8
```

자리마다 1의 개수를 세서 홀수면 1, 짝수면 0을 적으면 결과가 된다. 5와 3은 두 번씩 나오니 자기가 켠 자리에 1을 짝수 개만 보탠다. 8만 8의 자리에 1을 한 개 보태 홀수로 만든다. XOR는 이 "자리마다 홀짝 세기"를 덧셈 없이 한 번에 하는 연산이다. 뒤의 세 번씩 나오는 변형은 이 표에서 "홀짝" 대신 "3으로 나눈 나머지"를 보는 것으로 풀린다.

```js
function singleNumber(nums) {
  let acc = 0;            // 아무것도 섞지 않은 상태
  for (const x of nums) {
    acc ^= x;             // 같은 수가 두 번 들어오면 그 비트들이 다시 꺼진다
  }
  return acc;             // 짝이 있는 수는 모두 지워지고 외톨이만 남는다
}

console.log(singleNumber([5, 3, 8, 3, 5]), singleNumber([7]), singleNumber([-4, 2, 2]));
```

```text
8 7 -4
```

아래 그림에서 다음을 누르면 누적값 `acc`가 비트 단위로 어떻게 바뀌는지 보인다. 중간 값(6, 14, 13)은 의미 없는 숫자처럼 보이지만, 마지막에 짝이 다 맞으면 외톨이만 남는다.

시간은 O(n)이다. 칸마다 XOR 한 번이다. 공간은 변수 `acc` 하나라 O(1)이다. 문제의 두 조건을 모두 지키는 풀이는 여섯 개 중 이것 하나다.

### 음수도 그대로 된다

예시에 `[-4, 2, 2]`를 넣은 이유가 있다. 음수는 2의 보수로 저장된다. -4는 32비트로 `11111111111111111111111111111100`이다. 비트가 잔뜩 켜져 있지만 XOR는 자리마다 독립적으로 계산하니 상관없다. `-4 ^ 2`는 -2이고, 거기에 2를 한 번 더 섞으면 다시 -4다. 부호 비트도 다른 비트와 똑같이 지워지고 남는다.

JavaScript는 비트 연산 전에 수를 32비트 정수로 바꾼다. 이 문제의 값은 ±3 × 10^4라 잘릴 일이 없다. 2^31을 넘는 수를 섞으면 조용히 틀리니, 그런 입력이면 BigInt를 쓴다. 이 함정은 [비트 연산 글](/posts/bit-manipulation#자바스크립트는-비트-연산-앞에서-32비트로-자른다)에서 실제 출력으로 봤다.

### Python과 Java

```python
from functools import reduce
from operator import xor
from typing import List

class Solution:
    def singleNumber(self, nums: List[int]) -> int:
        acc = 0
        for x in nums:
            acc ^= x      # 같은 수는 두 번 섞이면 사라진다
        return acc

    def singleNumberReduce(self, nums: List[int]) -> int:
        return reduce(xor, nums, 0)

s = Solution()
print(s.singleNumber([5, 3, 8, 3, 5]), s.singleNumber([7]), s.singleNumber([-4, 2, 2]))
print(s.singleNumberReduce([5, 3, 8, 3, 5]), s.singleNumberReduce([-4, 2, 2]))
```

```text
8 7 -4
8 -4
```

Python의 정수는 크기 제한이 없고, 음수는 "왼쪽으로 1이 끝없이 이어지는 2의 보수"처럼 다뤄진다. 그래서 XOR 결과도 JavaScript·Java와 같다. `reduce(xor, nums, 0)`은 한 줄로 쓰는 방법인데, 세 번째 인자 0을 빼면 빈 배열에서 에러가 난다. 이 문제는 빈 배열이 없지만 습관적으로 초기값을 준다.

```java
class Solution {
    public int singleNumber(int[] nums) {
        int acc = 0;
        for (int x : nums) acc ^= x; // 짝이 있는 수는 서로 지워진다
        return acc;
    }

    public static void main(String[] args) {
        Solution s = new Solution();
        System.out.println(s.singleNumber(new int[] { 5, 3, 8, 3, 5 }) + " " + s.singleNumber(new int[] { 7 }) + " " + s.singleNumber(new int[] { -4, 2, 2 }));
    }
}
```

```text
8 7 -4
```

Java의 `int`는 32비트 2의 보수라 JavaScript와 같은 결과가 나온다. 스트림으로 `Arrays.stream(nums).reduce(0, (a, b) -> a ^ b)`라고 써도 되지만, 이런 짧은 반복에서는 일반 `for`가 더 빠르고 읽기도 쉽다.

## 틀리기 쉬운 곳

### 초기값을 첫 원소로 잡고 처음부터 돌기

```js
function wrong(nums) {
  let acc = nums[0];
  for (const x of nums) acc ^= x; // nums[0]을 한 번 더 섞는다
  return acc;
}
console.log(wrong([5, 3, 8, 3, 5]));
```

```text
13
```

`acc`를 `nums[0]`으로 시작했으면 반복은 1번 칸부터 돌아야 한다. 0번 칸까지 다시 섞으면 첫 수가 두 번 들어가 지워지고, 마지막 5 하나가 짝 없이 남아 8 ^ 5 = 13이 나온다. 0에서 시작하면 이런 실수를 할 일이 없다. 0이 XOR의 항등원이기 때문이다.

### 정렬 풀이에서 마지막 칸을 빼먹기

두 칸씩 보는 반복을 `i < a.length`로 쓰면 마지막 칸에서 `a[i + 1]`을 읽는다. JavaScript는 `undefined`를 돌려주니 `a[i] !== undefined`가 참이 되어 우연히 맞는 답이 나온다. Java는 같은 코드에서 `ArrayIndexOutOfBoundsException`이 난다. 반복은 `i < a.length - 1`까지 돌고, 끝까지 맞으면 마지막 칸을 따로 돌려준다.

### 비교 함수 없는 정렬

`[10, 9, 9, 1, 10].sort()`는 문자열 순서로 정렬해 `[1, 10, 10, 9, 9]`가 된다. 숫자 순서는 아니지만 같은 수가 같은 문자열이 되니 여전히 붙어 서고, 이 문제에서는 우연히 1이 답으로 나온다. 다른 정렬 문제에서는 그대로 틀리니 `(x, y) => x - y`를 습관처럼 붙인다.

### "두 번"이 아니라 "짝수 번"이어도 된다

XOR 풀이는 짝이 있는 수가 정확히 두 번일 필요가 없다. 네 번, 여섯 번 나와도 짝수 번이면 지워진다. `[4, 4, 4, 9, 9]`처럼 외톨이 대신 "홀수 번 나오는 수 하나"가 있어도 XOR는 4를 돌려준다. 반대로 세 번씩 나오는 수가 있으면 XOR로는 지워지지 않는다. 그 경우는 아래 변형에서 따로 푼다.

## 조건이 바뀌면 어떻게 하나

### 배열이 정렬돼 있다면

LeetCode 540. Single Element in a Sorted Array는 정렬된 배열에서 같은 문제를 O(log n)에 풀라고 한다. XOR도 O(n)이라 부족하다. 앞의 정렬 풀이에서 본 "짝의 자리"가 열쇠다. 외톨이보다 앞에서는 짝이 (짝수 인덱스, 홀수 인덱스)로 서고, 외톨이 뒤에서는 한 칸 밀려 (홀수, 짝수)로 선다. 가운데를 짝수 인덱스로 맞춰 다음 칸과 같은지만 보면 외톨이가 어느 쪽에 있는지 안다. [이진 탐색](/posts/binary-search)의 "조건이 바뀌는 첫 지점 찾기"와 같은 모양이다.

```js
function singleNonDuplicate(nums) {
  let lo = 0, hi = nums.length - 1;
  while (lo < hi) {
    let mid = (lo + hi) >> 1;
    if (mid % 2 === 1) mid--;                       // 짝의 첫 칸(짝수 인덱스)에 맞춘다
    if (nums[mid] === nums[mid + 1]) lo = mid + 2;  // 짝이 온전하다 → 외톨이는 오른쪽
    else hi = mid;                                  // 짝이 어긋났다 → 외톨이는 mid 이하
  }
  return nums[lo];
}
console.log(singleNonDuplicate([1, 1, 2, 3, 3, 4, 4, 8, 8]), singleNonDuplicate([3, 3, 7, 7, 10, 11, 11]), singleNonDuplicate([5]));
```

```text
2 10 5
```

### 외톨이가 둘이라면

LeetCode 260. Single Number III은 한 번씩 나오는 수가 둘이다. 전부 XOR하면 두 외톨이의 XOR가 남는다. 두 수가 다르니 이 값은 0이 아니고, 켜진 비트가 있다는 건 두 수가 그 자리에서 다르다는 뜻이다. 그 비트 하나(`both & -both`, 가장 낮은 1 비트)가 켜졌는지로 배열을 두 무리로 나누면 두 외톨이는 서로 다른 무리로 가고, 짝은 같은 무리로 함께 간다. 무리마다 XOR하면 하나씩 남는다. 가장 낮은 1 비트를 꺼내는 원리는 [비트 연산 글](/posts/bit-manipulation#가장-낮은-1-비트를-다루는-두-가지-요령)에 있다.

```js
function singleNumberIII(nums) {
  const both = nums.reduce((a, b) => a ^ b, 0); // 두 외톨이의 XOR
  const bit = both & -both;                     // 두 수가 다른 자리 하나
  let a = 0;
  for (const x of nums) if (x & bit) a ^= x;    // 그 자리가 켜진 무리만 섞는다
  return [a, both ^ a];
}
console.log(singleNumberIII([1, 2, 1, 3, 2, 5]));
```

```text
[ 3, 5 ]
```

### 나머지가 세 번씩 나온다면

[Single Number II](/posts/leetcode-single-number-ii)는 외톨이를 뺀 모든 수가 세 번씩 나온다. XOR는 두 번에 지워지는 연산이라 세 번이면 흔적이 남는다. 대신 비트 자리마다 1의 개수를 세서 3으로 나눈 나머지를 보면 된다. 세 번씩 나오는 수는 각 자리에 3의 배수만큼 1을 보태니, 나머지가 1인 자리가 곧 외톨이의 1이다.

```js
function singleNumberII(nums) {
  let ans = 0;
  for (let b = 0; b < 32; b++) {
    let cnt = 0;
    for (const x of nums) cnt += (x >> b) & 1; // b번 자리가 켜진 수를 센다
    if (cnt % 3) ans |= 1 << b;               // 3으로 안 나눠떨어지면 외톨이의 비트
  }
  return ans;
}
console.log(singleNumberII([2, 2, 3, 2]), singleNumberII([0, 1, 0, 1, 0, 1, -99]));
```

```text
3 -99
```

32자리를 각각 n번씩 보니 시간은 O(32n)이고 공간은 O(1)이다. 31번 자리까지 세면 부호 비트도 살아나 음수 -99가 그대로 나온다. 이 "자리마다 세기"는 "k번씩 나온다"로 일반화된다. `% 3`을 `% k`로 바꾸면 된다.

### 데이터가 스트림으로 들어온다면

XOR 풀이는 원래 스트림 친화적이다. 값을 하나 받을 때마다 `acc ^= x`만 하면 되고, 배열 전체를 기억할 필요가 없다. 로그 줄이 끝없이 들어오는 상황에서 "짝이 안 맞는 요청 ID 하나"를 찾는 것처럼 쓸 수 있다. 단, 짝이 안 맞는 게 정말 하나뿐이라는 보장이 있어야 한다. 둘 이상이면 섞인 값이 나와서 틀린 줄도 모른다. 보장이 없으면 해시 풀이로 돌아가야 한다.

## 면접에서 나올 만한 질문

### 왜 XOR를 쓰면 한 번만 나오는 수가 남나요?

XOR는 같은 수를 두 번 하면 0이 되고, 0과 하면 그대로이며, 순서를 바꿔도 결과가 같다. 그래서 배열 전체를 XOR하면 짝이 있는 수끼리 모아서 지운 것과 같아지고, 짝이 없는 수 하나만 남는다. 비트로 보면 결과의 각 자리는 "그 자리가 1인 수가 홀수 번 섞였나"를 나타낸다.

### 해시맵 풀이와 XOR 풀이 중 무엇을 내야 하나요?

문제 조건이 공간 O(1)이면 XOR다. 해시맵은 서로 다른 수만큼 메모리를 써서 O(n)이다. 다만 해시맵 풀이는 "세 번씩 나온다", "외톨이가 여럿이다"처럼 조건이 바뀌어도 그대로 쓸 수 있어서, 처음에 해시맵으로 동작하는 답을 말하고 XOR로 줄이는 흐름이 자연스럽다.

### 음수가 섞여 있어도 XOR 풀이가 맞나요?

맞다. 음수는 2의 보수로 저장되고, XOR는 부호 비트를 포함한 모든 자리를 똑같이 다룬다. 짝이 있는 음수는 부호 비트까지 지워지고, 외톨이가 음수면 부호 비트가 남아 음수로 나온다. JavaScript는 비트 연산 전에 32비트로 자르니 범위 밖의 큰 수에서만 주의하면 된다.

### 이 XOR 풀이가 틀리는 입력이 있나요?

전제가 깨지면 틀린다. 홀수 번 나오는 수가 둘 이상이면 그 수들이 섞인 값이 나오고, 세 번씩 나오는 수가 있으면 그 수가 지워지지 않는다. 짝수 번이라면 네 번, 여섯 번이어도 상관없다. 전제를 검증할 수 없는 실무 데이터라면 해시로 세는 쪽이 안전하다.

### 배열이 정렬돼 있다면 더 빨리 풀 수 있나요?

O(log n)으로 풀 수 있다. 외톨이 앞에서는 짝이 짝수 인덱스에서 시작하고, 뒤에서는 홀수 인덱스에서 시작한다. 가운데를 짝수 인덱스로 맞춰 다음 칸과 같은지 보면 외톨이가 오른쪽인지 왼쪽인지 정해져 이진 탐색이 된다. LeetCode 540번이다.

### 한 번만 나오는 수가 두 개라면요?

전체를 XOR해서 두 수의 XOR를 구하고, 그 값에서 켜진 비트 하나를 고른다. 그 비트가 켜졌는지로 배열을 두 무리로 나누면 두 외톨이는 다른 무리에, 짝은 같은 무리에 들어간다. 무리마다 XOR하면 두 수가 하나씩 나온다. 시간 O(n), 공간 O(1)이다.

### 나머지 수가 세 번씩 나오면 어떻게 바꾸나요?

XOR는 두 번에 지워지니 바로는 안 된다. 비트 자리마다 1이 몇 번 나왔는지 세고 3으로 나눈 나머지를 보면 외톨이의 비트가 된다. 32자리를 각각 세니 O(32n) 시간, O(1) 공간이다. 두 개의 비트 변수로 자리마다 "몇 번째인지"를 상태 기계처럼 들고 다니는 더 짧은 풀이도 있다.
