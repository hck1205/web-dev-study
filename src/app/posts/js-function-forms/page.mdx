오래된 유틸 파일을 정리하면서 `function`을 전부 화살표 함수로 바꿨다. 요즘 코드처럼 보이게 하려는 기계적인 변환이었다. 바꾸기 전에는 잘 돌던 코드다.

```js
function Money(amount) {
  this.amount = amount;
}
const cart = {
  items: [1200, 3400],
  total: function () {
    return this.items.reduce((sum, p) => sum + p, 0);
  },
};
console.log(new Money(4600).amount, cart.total());
```

```text
4600 4600
```

`function` 두 개를 화살표 함수로 바꾼 뒤 같은 두 줄을 돌렸다.

```js
const Money = (amount) => {
  this.amount = amount;
};
const cart = {
  items: [1200, 3400],
  total: () => {
    return this.items.reduce((sum, p) => sum + p, 0);
  },
};
try { console.log(new Money(4600).amount); } catch (e) { console.log(e.constructor.name + ": " + e.message); }
try { console.log(cart.total()); } catch (e) { console.log(e.constructor.name + ": " + e.message); }
```

```text
TypeError: Money is not a constructor
TypeError: Cannot read properties of undefined (reading 'reduce')
```

둘 다 "함수"인데 하나는 생성자로 쓸 수 없게 됐고, 하나는 `this`로 객체에 닿지 못하게 됐다. 자바스크립트에는 함수를 만드는 문법이 여럿 있고, 겉모양만 다른 게 아니라 `this`와 `arguments`를 갖는지, `new`로 부를 수 있는지, 매개변수를 어떻게 받는지가 다르다. 이 글은 그 차이를 하나씩 짚고, 어떤 자리에 어떤 모양을 쓸지 정한다. 예제 출력은 Node.js 22와 크로미움(React 19.3)에서 실제로 돌린 결과다.

이 주제의 다른 글: 함수를 값으로 넘기는 이야기는 [일급 함수와 콜백](/posts/js-first-class-callbacks), 함수가 바깥 변수를 기억하는 원리는 [클로저](/posts/js-closures)에서 이어 간다. 선언문을 `const` 화살표 함수로 바꿨을 때 "정의 전에 쓸 수 있음"이 사라지는 문제는 [호이스팅과 TDZ](/posts/js-hoisting-tdz)가 따로 다룬다.

## 함수를 만드는 문법들

자주 쓰는 모양은 넷이다.

```js
function declared() {}               // 함수 선언문
const expressed = function () {};    // 함수 표현식 (익명)
const named = function inner() {};   // 이름 있는 함수 표현식
const arrow = () => {};              // 화살표 함수 (ES2015부터)
const obj = { method() {} };         // 메서드 축약 (ES2015부터)
```

선언문은 `function`으로 문장을 시작한다. 표현식은 값이 들어갈 자리(대입 오른쪽, 인자, 배열 원소)에 함수를 쓴 것이다. 문법상 차이는 이것뿐인데, 엔진이 이 둘을 처리하는 시점이 다르다.

모양마다 붙는 `name`도 다르다. 익명 표현식과 화살표 함수도 변수에 바로 대입하면 엔진이 그 변수 이름을 `name`에 넣어 준다(ES2015부터 명세에 들어간 이름 추론).

```js
const obj = { method() {}, ["computed" + 1]: () => {} };
console.log(declared.name, expressed.name, named.name, arrow.name);
console.log(obj.method.name, obj.computed1.name);
console.log(typeof inner);
```

```text
declared expressed inner arrow
method computed1
undefined
```

`named.name`은 변수 이름 `named`가 아니라 `inner`다. 그리고 `inner`라는 이름은 바깥에서 보이지 않는다. 이름 있는 함수 표현식의 이름은 그 함수 안에서만 쓰는 이름이라서 그렇다. 뒤에서 이걸 어디에 쓰는지 본다.

## 정의보다 위에서 부를 수 있는 함수

문법마다 언제부터 쓸 수 있는지도 다르다. 엔진은 코드를 실행하기 전에 스코프 안의 선언을 먼저 등록하는데, 함수 선언문은 이때 함수 객체까지 만들어 둔다. 그래서 정의보다 위에서 불러도 된다. 표현식과 화살표 함수는 그 함수를 담은 변수의 규칙을 따른다. `const`에 담았다면 정의 전에 부를 때 `ReferenceError: Cannot access ... before initialization`, `var`에 담았다면 `TypeError: ... is not a function`이 난다. 등록 단계와 TDZ, 그리고 이 두 에러 문구로 원인을 가르는 법은 [호이스팅과 TDZ](/posts/js-hoisting-tdz)에 있다.

이 차이 때문에 스타일 선택이 갈린다. 선언문을 쓰면 파일 위쪽에 큰 흐름을 쓰고 아래에 세부 함수를 모아 둘 수 있다. 표현식이나 화살표 함수를 `const`에 담으면 반드시 정의를 먼저 써야 하지만, 정의 전에 쓰는 실수를 엔진이 바로 잡아 준다. 어느 쪽이든 한 프로젝트 안에서 섞지 않는 게 낫고, ESLint의 `func-style`이나 `no-use-before-define` 규칙으로 정해 둘 수 있다.

## 화살표 함수가 갖지 않는 것

화살표 함수는 짧게 쓰는 문법만이 아니다. 일반 함수가 호출될 때마다 새로 정하는 것들 몇 가지를 아예 갖지 않는다.

- 자기 `this`가 없다. 바깥 함수의 `this`를 그대로 쓴다.
- 자기 `arguments`가 없다. 바깥 함수의 `arguments`를 쓴다.
- `prototype` 속성이 없고, `new`로 부를 수 없다.
- `super`, `new.target`도 바깥 것을 쓴다.

타이머 예제로 보면 차이가 바로 드러난다.

```js
const timer = {
  seconds: 0,
  startRegular() {
    setTimeout(function () {
      console.log("regular:", this === timer, typeof this.seconds);
    }, 0);
  },
  startArrow() {
    setTimeout(() => {
      console.log("arrow:", this === timer, this.seconds);
    }, 0);
  },
  stopArrow: () => {
    console.log("method as arrow:", this === timer, this);
  },
};
timer.startRegular();
timer.startArrow();
timer.stopArrow();
```

```text
method as arrow: false {}
regular: false undefined
arrow: true 0
```

세 줄이 각각 다른 이유가 있다.

`startRegular` 안의 일반 함수는 `setTimeout`이 부른다. `timer.`을 앞에 붙여 부른 게 아니니 `this`가 `timer`가 아니다. Node.js에서는 타이머 객체가, 브라우저에서는 `window`가 `this`로 들어온다. 어느 쪽이든 `seconds`는 없다.

`startArrow` 안의 화살표 함수는 자기 `this`가 없어서, 자기를 감싼 `startArrow`의 `this`를 쓴다. `startArrow`는 `timer.startArrow()`로 불렸으니 그 `this`는 `timer`다.

`stopArrow`는 메서드 자리에 화살표 함수를 쓴 경우다. 객체 리터럴은 스코프를 만들지 않는다. 그래서 바깥, 즉 모듈 최상위의 `this`를 쓴다. CommonJS 모듈에서는 `module.exports`인 `{}`가 찍혔다. 메서드를 화살표로 쓰면 `this`로 객체에 닿을 수 없다는 뜻이다.

`this`가 정해지는 규칙 전체(기본, 암시적, 명시적, `new`)는 [this 바인딩](/posts/js-this-binding)에서, `bind`로 고정하는 방법은 [call, apply, bind](/posts/js-call-apply-bind)에서 다룬다. 여기서는 "화살표 함수의 `this`는 정의한 자리에서 정해진다"만 기억하면 된다.

생성자로 부르면 바로 막힌다. 메서드 축약도 마찬가지로 생성자가 아니다.

```js
const Arrow = () => {};
console.log(Arrow.prototype);
console.log(typeof function () {}.prototype);
try { new Arrow(); } catch (e) { console.log(e.constructor.name + ": " + e.message); }
const o = { m() {} };
try { new o.m(); } catch (e) { console.log(e.constructor.name + ": " + e.message); }
```

```text
undefined
object
TypeError: Arrow is not a constructor
TypeError: o.m is not a constructor
```

`function`으로 만든 함수는 일반 호출도 되고 `new`도 된다. 한 함수가 두 역할을 하니 `new`를 빼먹으면 `this`가 엉뚱한 곳을 가리키는 버그가 생겼다. ES2015 이후의 문법들은 역할을 나눴다. 생성자는 `class`, 콜백은 화살표 함수, 메서드는 메서드 축약이다. 각각 할 수 없는 일을 하려고 하면 엔진이 에러로 막아 준다. `class`는 반대로 `new` 없이 부르면 막힌다.

```js
class User {}
try { User(); } catch (e) { console.log(e.constructor.name + ": " + e.message); }
```

```text
TypeError: Class constructor User cannot be invoked without 'new'
```

## 이름 있는 함수 표현식을 쓰는 자리

표현식에 이름을 붙이면 두 가지가 좋아진다.

하나는 재귀다. 바깥 변수 이름 대신 함수 안의 이름으로 자기를 부르면, 바깥 변수가 바뀌어도 재귀가 깨지지 않는다.

```js
let countdown = function step(n) {
  if (n === 0) return "발사";
  return step(n - 1);
};
const saved = countdown;
countdown = null;
console.log(saved(3));

const f = function g() {
  g = 1; // 조용히 무시된다 (strict 모드라면 TypeError)
  return typeof g;
};
console.log(f());
```

```text
발사
function
```

`step`은 함수 안에서만 보이고 다시 대입할 수도 없다. `g = 1`이 먹히지 않은 이유다.

다른 하나는 스택 트레이스다. 콜백을 그 자리에서 익명으로 넘기면 이름 추론이 일어날 변수가 없다. 에러가 나면 위치만 남는다.

```js
function run(cb) { cb(); }
try {
  run(function () { throw new Error("boom"); });
} catch (e) { console.log(e.stack.split("\n").slice(0, 3).join("\n")); }
try {
  run(function onSave() { throw new Error("boom"); });
} catch (e) { console.log(e.stack.split("\n").slice(0, 3).join("\n")); }
```

```text
Error: boom
    at stack.js:3:27
    at run (stack.js:1:20)
Error: boom
    at onSave (stack.js:6:33)
    at run (stack.js:1:20)
```

(경로는 줄여서 옮겼다.) 위쪽은 줄 번호만 있고, 아래쪽은 `onSave`라는 이름이 있다. 운영 환경에서는 코드가 압축되어 줄 번호가 의미 없어지는 경우가 많다. 소스맵이 없을 때 에러 수집 도구에서 단서가 되는 건 함수 이름이다. 이벤트 핸들러나 재시도 로직처럼 에러가 자주 지나가는 콜백에는 이름을 붙여 두면 추적이 쉬워진다.

기본값이 언제 쓰이는지부터 확인한다.

```js
function greet(name = "손님", greeting = `안녕, ${name}`) {
  return greeting;
}
console.log(greet());
console.log(greet(undefined));
console.log(greet(null));
console.log(greet(""));
console.log(greet("민지"));
```

```text
안녕, 손님
안녕, 손님
안녕, null
안녕, 
안녕, 민지
```

인자를 빼먹은 것과 `undefined`를 직접 넘긴 것은 똑같이 취급된다. `null`과 빈 문자열은 값으로 본다. 그래서 `||`로 쓰던 옛 코드를 기본값으로 바꾸면 동작이 바뀔 수 있다. `retry = retry || 3`은 `0`을 넘겨도 3이 되지만, `retry = 3`은 0을 그대로 받는다. 서버에서 `null`로 온 값에 기본값이 안 먹는다는 버그도 여기서 나온다. `null`까지 기본값으로 바꾸고 싶으면 본문에서 `??`를 쓴다. 이 연산자는 [옵셔널 체이닝과 ??](/posts/js-optional-chaining-nullish)에서 다룬다.

기본값 식은 정의할 때 한 번이 아니라 호출할 때마다 평가된다.

```js
let calls = 0;
function nextId() { calls += 1; return calls; }
function create(item, id = nextId()) { return `${item}#${id}`; }
console.log(create("a"), create("b"), create("c", 10), create("d"));

function push(item, list = []) { list.push(item); return list; }
console.log(push(1), push(2));

try { (function (a = b, b = 1) { return a; })(); } catch (e) { console.log(e.constructor.name + ": " + e.message); }
```

```text
a#1 b#2 c#10 d#3
[ 1 ] [ 2 ]
ReferenceError: Cannot access 'b' before initialization
```

`create("c", 10)`에서는 `nextId()`가 아예 불리지 않았다. 값이 있으면 기본값 식을 건너뛴다. `push`의 빈 배열도 호출마다 새로 만든다. 파이썬처럼 기본값 객체가 호출 사이에 공유되는 문제는 없다. 대신 이 성질이 React에서는 다른 문제를 만든다. 아래에서 다시 본다.

## arguments 객체와 나머지 매개변수

화살표 함수가 아닌 함수에는 호출할 때 `arguments`라는 객체가 생긴다. 넘어온 인자를 전부 담고 있어서, 매개변수 개수가 정해지지 않은 함수를 만들 때 쓰였다. 배열처럼 `length`와 인덱스는 있지만 배열 메서드가 없는 유사 배열이다. 새 코드에서는 진짜 배열을 주는 나머지 매개변수(`...nums`)를 쓰고, 둘의 차이는 [스프레드와 나머지 문법](/posts/js-spread-rest)에 정리돼 있다. 여기서는 옛 코드를 고치거나 화살표 함수로 옮길 때 만나는 함정 두 가지만 본다.

옛 코드를 고치다 보면 더 이상한 동작을 만난다. strict 모드가 아니고 매개변수가 단순하면 `arguments[0]`과 첫 매개변수가 서로 연결되어 있다.

```js
function sloppy(a) {
  arguments[0] = 99;
  return a;
}
function strict(a) {
  "use strict";
  arguments[0] = 99;
  return a;
}
function withDefault(a = 0) {
  arguments[0] = 99;
  return a;
}
console.log(sloppy(1), strict(1), withDefault(1));
```

```text
99 1 1
```

이 연결 때문에 엔진은 매개변수를 함부로 최적화하지 못한다. 모듈(ESM)과 `class` 본문은 자동으로 strict 모드라서 요즘 코드에서는 만날 일이 적다. strict 모드가 바꾸는 다른 동작들은 [strict 모드](/posts/js-strict-mode)에서 다룬다.

화살표 함수에는 `arguments`가 없다는 걸 앞에서 봤다. 그런데 어디서 실행하느냐에 따라 증상이 다르다.

```js
// show.mjs (ES 모듈)
const show = () => console.log(arguments.length);
show(1, 2);
```

```text
ReferenceError: arguments is not defined
    at show (file:///…/show.mjs:1:32)
```

```js
// show.cjs (CommonJS)
const show = () => console.log(arguments.length, typeof arguments[1]);
show(1, 2, 3);
```

```text
5 function
```

ES 모듈에서는 바깥에 `arguments`가 없어서 에러가 난다. CommonJS에서는 에러 없이 `5`가 찍힌다. Node.js가 CommonJS 파일을 `(exports, require, module, __filename, __dirname)`를 받는 함수로 감싸서 실행하기 때문이다. 화살표 함수가 그 감싸는 함수의 `arguments`를 빌려 왔고, `arguments[1]`은 `require`다. 넘긴 `1, 2, 3`과는 아무 상관이 없는 값이 조용히 섞여 들어온다.

함수의 `length`도 알아 두면 라이브러리 코드를 읽을 때 도움이 된다. 기본값이나 나머지 매개변수가 처음 나오는 자리 앞까지만 센다.

```js
console.log([function (a, b) {}, function (a, b = 1, c) {}, function (...rest) {}, (a, { b } = {}) => {}].map((f) => f.length));
```

```text
[ 2, 1, 0, 1 ]
```

Express는 이 `length`가 4인 함수만 에러 미들웨어로 본다. 에러 미들웨어의 `next`를 안 쓴다고 지우거나, 나머지 매개변수로 받는 래퍼로 감싸면 일반 미들웨어로 취급된다. 래퍼가 `length`를 바꿔서 생기는 버그는 [일급 함수와 콜백](/posts/js-first-class-callbacks)에서 실제로 재현했다.

## React 컴포넌트에서 만나는 함수 모양

React 함수 컴포넌트도 그냥 함수다. 그래서 여기서 본 차이가 그대로 나타난다.

컴포넌트를 `function Card() {}`로 쓰든 `const Card = () => {}`로 쓰든 렌더링 결과는 같다. 이름 추론 덕분에 개발자 도구에도 둘 다 `Card`로 보인다. 다만 `export default () => {}`처럼 변수 없이 바로 내보내면 이름이 비어서 개발자 도구에 `Anonymous`로 뜨고, Fast Refresh가 상태를 유지하지 못하는 경우도 있다. 컴포넌트에는 이름이 있어야 한다.

핸들러를 넘기는 자리에서 흔한 실수가 있다. 함수를 넘겨야 할 곳에서 함수를 불러 버리는 것이다.

```js
function Counter() {
  const [count, setCount] = useState(0);
  const handleClick = () => setCount(count + 1);
  return <button onClick={handleClick()}>{count}</button>;
}
```

```text
Too many re-renders. React limits the number of renders to prevent an infinite loop.
```

React 19.3 개발 빌드로 크로미움에서 렌더링한 결과다. `onClick={handleClick()}`은 렌더링하는 도중에 `handleClick`을 실행하고, 그 반환값 `undefined`를 `onClick`에 넣는다. 실행된 `handleClick`은 상태를 바꾸고, 상태가 바뀌니 다시 렌더링하고, 렌더링하면서 또 실행한다.

고치는 방법은 함수를 넘기는 것이다. 인자가 필요하면 화살표 함수로 한 번 감싼다.

```js
<button onClick={handleClick}>{count}</button>
<button onClick={() => remove(item.id)}>삭제</button>
```

기본값 매개변수가 호출마다 새로 평가된다는 성질은 props에서도 그대로다. `function TagList({ tags = [] })`는 `tags`를 안 넘기면 렌더링마다 새 빈 배열을 만든다. 이 값을 `useEffect`의 의존성에 넣으면 매번 바뀐 것으로 보여 effect가 끝없이 다시 돈다. 기본값을 컴포넌트 바깥 상수로 빼면 고쳐진다. 이 장면은 [구조 분해](/posts/js-destructuring)에서 실제로 재 봤다. React 19부터 함수 컴포넌트의 `defaultProps`는 지원이 끊겼고, 기본값 매개변수가 그 자리를 대신한다.

## 어떤 모양을 고를까

차이를 한곳에 모으면 이렇다.

| | 선언문 | 함수 표현식 | 화살표 함수 | 메서드 축약 |
|---|---|---|---|---|
| 정의 전에 호출 | 된다 | 변수 선언 방식을 따른다 | 변수 선언 방식을 따른다 | 객체가 생긴 뒤 |
| 자기 `this` | 호출 방식으로 정해짐 | 호출 방식으로 정해짐 | 없음 (바깥 것) | 호출 방식으로 정해짐 |
| `arguments` | 있음 | 있음 | 없음 (바깥 것) | 있음 |
| `new`로 호출 | 된다 | 된다 | TypeError | TypeError |
| `super` 사용 | 안 됨 | 안 됨 | 바깥 것 | 된다 |

실무에서 쓰는 기준은 단순하다.

- 모듈의 최상위 함수, React 컴포넌트는 선언문이나 `const` 화살표 함수 중 하나로 통일한다. 정의 전에 부르고 싶은 구조라면 선언문이다.
- 콜백, 특히 바깥 `this`를 써야 하는 콜백은 화살표 함수다. `that = this`나 `.bind(this)`가 필요 없어진다.
- 객체와 클래스의 메서드는 메서드 축약이다. 메서드에 화살표 함수를 쓰면 `this`로 객체에 닿지 못한다.
- 생성자가 필요하면 `function`이 아니라 `class`를 쓴다.
- 재귀하거나 스택 트레이스에 이름이 남아야 하는 콜백에는 이름 있는 함수 표현식을 쓴다.

클래스 필드에 화살표 함수를 두는 `handleClick = () => {}` 패턴도 있다. `this`가 인스턴스에 묶여서 이벤트 핸들러로 넘기기 좋지만, 함수가 프로토타입이 아니라 인스턴스마다 하나씩 생긴다. 인스턴스가 수천 개면 그만큼 함수가 늘어나고, 하위 클래스에서 `super.handleClick()`으로 부를 수도 없다.

## 기계적인 변환이 깨뜨린 두 줄

처음 리팩터링이 깨진 건 화살표 함수가 `function`의 짧은 표기가 아니라서다. `Money`는 생성자였는데 화살표 함수에는 `prototype`이 없어 `new`가 막혔고, `cart.total`은 메서드였는데 화살표 함수는 자기 `this`가 없어 객체에 닿지 못했다. 생성자는 `class`로, 메서드는 메서드 축약으로 바꿨다면 둘 다 그대로 돌았다. 함수 문법을 고를 때는 모양보다 이 함수가 무엇을 가져야 하는지를 먼저 본다. 정의 전에 불려야 하는지, 자기 `this`가 필요한지, 생성자인지. 그 답이 문법을 정한다. 다음 글 [일급 함수와 콜백](/posts/js-first-class-callbacks)에서는 이렇게 만든 함수를 값처럼 넘길 때 생기는 일을 본다.

## 면접에서 나올 만한 질문

### 함수 선언문과 함수 표현식의 차이는 무엇인가요?

가장 큰 차이는 언제 쓸 수 있게 되느냐다. 선언문은 스코프에 들어서는 순간 함수 객체까지 준비되어 정의보다 위에서 불러도 된다. 표현식은 그 값을 담은 변수의 규칙을 따라서, `const`면 정의 전에 부를 때 `ReferenceError`, `var`면 `TypeError`가 난다. 이름 추론 덕분에 디버깅에서 보이는 이름은 대부분 비슷하다.

### 화살표 함수와 일반 함수는 무엇이 다른가요?

화살표 함수는 자기 `this`, `arguments`, `super`, `new.target`이 없고 바깥 스코프의 것을 쓴다. `prototype`이 없어서 `new`로 부르면 `TypeError`가 난다. 그래서 바깥 `this`를 써야 하는 콜백에 잘 맞고, 객체 메서드나 생성자로는 맞지 않는다.

### 객체 메서드를 화살표 함수로 쓰면 어떻게 되나요?

`this`가 그 객체가 아니게 된다. 객체 리터럴은 스코프를 만들지 않아서 화살표 함수는 객체를 감싼 바깥(모듈 최상위나 바깥 함수)의 `this`를 쓴다. ES 모듈 최상위라면 `undefined`, CommonJS라면 `module.exports`다. 메서드에는 메서드 축약 문법을 쓴다.

### 기본값 매개변수는 언제 적용되고, || 로 쓰던 방식과 무엇이 다른가요?

인자가 `undefined`일 때만 적용된다. `null`, `0`, `false`, 빈 문자열은 값으로 그대로 들어간다. `x = x || 기본값`은 falsy 값을 모두 기본값으로 바꾸므로, 0을 정상 값으로 쓰는 옵션을 옮길 때 동작이 바뀐다. 기본값 식은 호출할 때마다 왼쪽부터 평가되고, 뒤에 있는 매개변수를 참조하면 TDZ 에러가 난다.

### arguments 객체 대신 나머지 매개변수를 쓰라고 하는 이유는요?

`arguments`는 배열이 아니라 배열 메서드가 없고, 화살표 함수에는 없으며, sloppy 모드에서는 매개변수와 연결되어 한쪽을 바꾸면 다른 쪽이 바뀐다. 나머지 매개변수는 진짜 배열이고 시그니처에 드러나서 읽기 쉽다. CommonJS에서 화살표 함수가 모듈 래퍼의 `arguments`를 조용히 빌려 오는 함정도 피할 수 있다.

### function을 전부 화살표 함수로 바꿔도 되나요?

안 된다. 생성자로 쓰던 함수는 화살표 함수에 `prototype`이 없어서 `new`에서 `TypeError`가 나고, 객체 메서드는 `this`가 객체가 아니게 된다. `arguments`를 쓰던 함수도 깨지고, CommonJS에서는 모듈 래퍼의 `arguments`가 조용히 섞여 들어온다. 생성자는 `class`, 메서드는 메서드 축약, 콜백은 화살표 함수처럼 역할에 맞춰 바꾼다.

### onClick에 handleClick() 처럼 괄호를 붙이면 어떻게 되나요?

클릭이 아니라 렌더링할 때 함수가 실행되고, 그 반환값이 핸들러로 들어간다. 그 함수가 상태를 바꾸면 렌더링 중 상태 변경이 반복되어 React가 "Too many re-renders" 에러로 멈춘다. 함수 자체를 넘기거나, 인자가 필요하면 `() => handleClick(id)`로 감싼다.

### 이름 있는 함수 표현식은 언제 쓰나요?

재귀와 디버깅에 쓴다. 함수 안에서만 보이는 이름으로 자기를 부르면 바깥 변수가 바뀌어도 재귀가 안전하다. 그 자리에서 익명으로 넘긴 콜백은 스택 트레이스에 위치만 남는데, 이름을 붙이면 함수 이름이 남아 운영 에러를 추적하기 쉽다.
