[Longest Consecutive Sequence](https://leetcode.com/problems/longest-consecutive-sequence/)는 LeetCode 128번 Medium 문제다. 정렬하면 쉽게 풀리는데, 문제가 O(n)을 요구해서 정렬을 쓸 수 없다. 그래서 "해시 집합으로 O(n)을 만드는 방법"을 묻는 대표 문제가 됐다. 면접에서는 풀이보다 "while 루프가 안에 있는데 왜 O(n)인가"를 설명하는 데서 갈린다.

이 글은 풀이를 여섯 가지 놓는다. 수마다 배열을 뒤지는 풀이, 정렬, 시작점 확인이 없는 집합, 시작점에서만 세는 집합, 끝점에 길이를 적어 이어 붙이는 해시맵, 유니온 파인드다. 해시 집합의 동작은 [해시맵 글](/posts/ds-hash-map)에, 유니온 파인드의 원리는 [유니온 파인드 글](/posts/ds-union-find)에 있다. 같은 묶음의 기본 문제인 [Contains Duplicate](/posts/leetcode-contains-duplicate)를 먼저 보면 집합을 쓰는 감각이 잡힌다. 코드는 모두 Node.js 22, Python 3.13, Java 21에서 직접 돌렸다.

## 1씩 이어지는 수의 가장 긴 줄

정렬되지 않은 정수 배열 `nums`가 주어진다. 배열에 들어 있는 값만으로 1씩 커지는 수열(연속 수열)을 만들 때, 가장 긴 것의 길이를 돌려준다. 배열 안에서의 위치나 순서는 상관없다. 값만 본다.

- 배열 길이는 0 이상 10^5 이하다. 빈 배열이 들어올 수 있고, 그때 답은 0이다.
- 값은 -10^9 이상 10^9 이하다. 값의 범위가 넓어서 "값을 칸 번호로 쓰는 배열"은 만들 수 없다.
- O(n) 시간에 풀어야 한다. 정렬은 O(n log n)이라 이 요구를 못 맞춘다.

같은 값이 여러 번 나와도 한 번으로 친다. `[1, 2, 2, 3]`의 답은 1, 2, 3으로 3이다. 이 중복이 뒤에서 두 번이나 함정이 된다.

## 손으로 줄 세워 보기

글 끝까지 쓸 예시다.

```text
nums = [8, 3, 10, 1, 4, 9, 2, 3]
```

크기 순서로 다시 적고 중복 3을 하나 지우면 `1 2 3 4 8 9 10`이다. 1부터 4까지 이어지고, 4 다음은 8이라 끊긴다. 8부터 10까지 다시 이어진다. 줄은 `1 2 3 4`(길이 4)와 `8 9 10`(길이 3) 두 개고, 답은 4다.

사람이 셀 때 자연스럽게 하는 일이 두 가지다. 하나는 크기 순서로 줄 세우기, 다른 하나는 "줄의 첫 수부터 다음 수가 있는지 따라가기"다. 앞의 방법은 정렬 풀이가 되고, 뒤의 방법은 해시 집합 풀이가 된다. 뒤의 방법에서 중요한 건 "첫 수"다. 2에서 세기 시작하면 2, 3, 4로 3을 얻는데, 이건 1에서 센 줄의 일부일 뿐이다. 줄의 중간에서 세는 건 낭비다.

## 수마다 다음 수를 배열에서 찾는 풀이

가장 곧이곧대로 옮기면, 수 `x`마다 `x + 1`, `x + 2`, ...가 배열에 있는지 배열을 처음부터 뒤져 확인한다.

```js
function longestConsecutive(nums) {
  let best = 0;
  for (const x of nums) {
    let len = 1;
    // includes는 배열을 처음부터 끝까지 훑는다
    while (nums.includes(x + len)) len++;
    best = Math.max(best, len);
  }
  return best;
}

console.log(longestConsecutive([8, 3, 10, 1, 4, 9, 2, 3]));
```

```text
4
```

`best`를 0으로 시작하니 빈 배열이면 0이 그대로 나온다. 원소가 하나라도 있으면 `len`이 1에서 시작하니 최소 1이다.

시간은 최악 O(n³)이다. 수가 n개이고, 수마다 줄을 따라가는 걸음이 최대 n번, 걸음마다 `includes`가 O(n)이다. 0부터 999까지 섞은 배열 1,000개로 재니 253ms였다. 10^5개면 셀 수 없을 만큼 걸린다. 공간은 O(1)이다.

느린 이유가 두 개 겹쳐 있다. "x + 1이 있나"를 찾는 데 O(n)이 들고, 같은 줄을 중간에서 또 센다. 하나씩 고쳐 간다.

## 정렬하고 이어진 구간 세기

정렬하면 이어진 수가 옆 칸에 붙는다. 한 번 훑으며 바로 앞 칸과 비교하면 된다.

- 앞 칸과 같으면 중복이니 건너뛴다. 줄 길이를 늘리지도 끊지도 않는다.
- 앞 칸보다 정확히 1 크면 줄이 이어진다. 길이를 1 늘린다.
- 그 밖이면 줄이 끊긴다. 길이를 1로 되돌린다.

```js
function longestConsecutive(nums) {
  if (nums.length === 0) return 0;
  const a = [...nums].sort((x, y) => x - y); // 숫자 비교자를 꼭 넘긴다
  let best = 1, cur = 1;
  for (let i = 1; i < a.length; i++) {
    if (a[i] === a[i - 1]) continue;        // 중복: 아무것도 바꾸지 않는다
    if (a[i] === a[i - 1] + 1) cur++;       // 이어진다
    else cur = 1;                           // 끊긴다
    best = Math.max(best, cur);
  }
  return best;
}

console.log(longestConsecutive([8, 3, 10, 1, 4, 9, 2, 3]));
console.log(longestConsecutive([1, 2, 2, 3]));
```

```text
4
3
```

정렬된 배열은 `[1, 2, 3, 3, 4, 8, 9, 10]`이다. 3이 두 번 나오는 자리에서 `continue`가 없으면 줄이 끊긴 것으로 보고 `cur`를 1로 돌린다. 그러면 `[1, 2, 2, 3]`에서 3이 아니라 2가 나온다. 실제로 돌려 본 틀린 출력은 뒤의 "틀리기 쉬운 자리" 절에 있다.

시간은 정렬 O(n log n)과 훑기 O(n)으로 O(n log n)이다. 공간은 복사한 배열 때문에 O(n)이다. 원래 배열을 고쳐도 되면 제자리 정렬로 추가 공간을 줄일 수 있다.

실제로는 꽤 빠르다. 10^5개에서 33ms였다. 면접에서도 이 풀이를 먼저 말하고 "O(n)을 요구하니 정렬을 빼야 한다"로 넘어가는 흐름이 자연스럽다. 정렬을 뺀다는 건 "옆 칸이 바로 다음 수"라는 정보를 잃는다는 뜻이다. 그 정보를 "다음 수가 있나"를 O(1)에 묻는 집합으로 대신한다.

## 집합에 넣고 다음 수를 묻기

첫 번째 풀이의 `includes`를 집합의 `has`로 바꾼다. 집합은 "이 값이 있나"를 평균 O(1)에 답한다. 중복도 집합에 넣는 순간 사라진다.

```js
function longestConsecutive(nums) {
  const set = new Set(nums);
  let best = 0;
  for (const x of set) {
    let len = 1;
    while (set.has(x + len)) len++; // 다음 수가 있는 동안 따라간다
    best = Math.max(best, len);
  }
  return best;
}

console.log(longestConsecutive([8, 3, 10, 1, 4, 9, 2, 3]));
```

```text
4
```

찾기는 O(1)이 됐지만 아직 O(n)이 아니다. 1에서 1, 2, 3, 4를 세고, 3에서 3, 4를 또 세고, 2에서 2, 3, 4를 또 센다. 줄의 모든 수에서 줄 끝까지 따라가니, 0부터 n-1까지 다 있는 배열이면 걸음 수가 n + (n-1) + ... + 1 = n(n+1)/2다. O(n²)이다.

실제로 0부터 29,999까지 섞은 배열을 넣었더니 10.3초가 걸렸다. 다음 풀이는 같은 입력에서 3.78ms다. 집합을 썼다고 O(n)이 되는 게 아니라는 걸 보여 주는 숫자다. 남은 낭비는 "줄의 중간에서 세는 것" 하나다.

## 줄의 첫 수에서만 센다

`x - 1`이 집합에 있으면 `x`는 줄의 첫 수가 아니다. 앞에서 누군가 이미 `x`를 지나며 세었거나 앞으로 셀 것이다. 그러니 `x - 1`이 없을 때만 세기 시작한다. 조건 한 줄이 O(n²)를 O(n)으로 바꾼다.

```js
function longestConsecutive(nums) {
  const set = new Set(nums); // 중복이 사라지고, 있나를 O(1)에 묻는다
  let best = 0;
  for (const x of set) {     // nums가 아니라 set을 돈다
    if (set.has(x - 1)) continue; // 앞 수가 있으면 줄의 첫 수가 아니다
    let len = 1;
    while (set.has(x + len)) len++;
    best = Math.max(best, len);
  }
  return best;
}

console.log(longestConsecutive([8, 3, 10, 1, 4, 9, 2, 3]));
```

```text
4
```

집합은 넣은 순서대로 돈다. 중복 3이 빠져 `8, 3, 10, 1, 4, 9, 2` 순서다. 아래 그림에서 다음을 누르면 수마다 "앞 수가 있나"를 먼저 묻고, 첫 수일 때만 줄을 따라가는 모습이 보인다.

### while이 안에 있는데 왜 O(n)인가

이 문제 면접의 핵심 질문이다. 걸음 수를 바깥 반복과 안쪽 반복으로 나눠 센다.

바깥 `for`는 집합의 수마다 한 번, 많아야 n번이다. 각 수에서 `set.has(x - 1)` 한 번을 한다. 여기까지 O(n)이다.

안쪽 `while`은 첫 수에서만 돈다. 첫 수 `x`에서 시작한 `while`은 그 줄의 수를 하나씩 밟고 줄 끝에서 멈춘다. 줄들은 서로 겹치지 않는다. 어떤 수 `y`가 두 줄에 동시에 들어갈 수는 없고, `y`가 속한 줄의 첫 수는 하나뿐이다. 그래서 모든 `while`이 밟는 수를 다 합치면 집합의 수 개수, 많아야 n이다.

둘을 더하면 O(n) + O(n) = O(n)이다. 반복문이 겹쳐 있다고 곱하는 게 아니라, 안쪽 반복이 전체에서 몇 번 도는지를 세는 방식이다. 이런 계산을 분할 상환 분석이라고 부른다. [슬라이딩 윈도](/posts/sliding-window-pattern)에서 안쪽 `while`이 있어도 O(n)인 것과 같은 논리다.

공간은 집합 O(n)이다. 10^5개에서 16.5ms로 여섯 풀이 중 가장 빨랐다.

이 풀이의 한계는 입력 전체가 처음부터 있어야 한다는 점이다. 수가 하나씩 들어오고 그때마다 답을 물으면 매번 전체를 다시 돌아야 한다. 다음 풀이는 수가 들어올 때마다 답을 갱신한다.

## 끝점에 길이를 적어 두고 이어 붙이기

해시맵 하나에 "이 수가 끝점인 줄의 길이"를 적는다. 새 수 `x`가 들어오면 왼쪽 이웃 `x - 1`과 오른쪽 이웃 `x + 1`을 본다.

1. `x - 1`이 맵에 있으면, 그건 어떤 줄의 오른쪽 끝이다. 그 줄의 길이를 `left`라 한다. 없으면 0이다.
2. `x + 1`도 같은 식으로 `right`를 얻는다. 그 줄의 왼쪽 끝이다.
3. `x`가 두 줄을 잇는다. 새 길이는 `left + right + 1`이다.
4. 새 줄의 양 끝 `x - left`와 `x + right`, 그리고 `x` 자신에 새 길이를 적는다.

```js
function longestConsecutive(nums) {
  const len = new Map(); // 수 → 그 수가 끝점인 줄의 길이
  let best = 0;
  for (const x of nums) {
    if (len.has(x)) continue;              // 중복은 건너뛴다. 다시 붙이면 길이가 부풀어 오른다
    const left = len.get(x - 1) ?? 0;      // 왼쪽 줄의 길이
    const right = len.get(x + 1) ?? 0;     // 오른쪽 줄의 길이
    const total = left + right + 1;
    len.set(x, total);                     // x도 맵에 넣어 둔다 (중복 확인용)
    len.set(x - left, total);              // 새 줄의 왼쪽 끝
    len.set(x + right, total);             // 새 줄의 오른쪽 끝
    best = Math.max(best, total);
  }
  return best;
}

console.log(longestConsecutive([8, 3, 10, 1, 4, 9, 2, 3]));
```

```text
4
```

왜 양 끝만 고쳐도 될까. 새로 들어오는 수 `x`는 아직 맵에 없는 수다. `x - 1`이 맵에 있는데 `x`가 없다면 `x - 1`은 반드시 어떤 줄의 오른쪽 끝이다. 줄의 중간이라면 `x`도 이미 있었을 것이다. 그래서 새 수가 물어보는 자리는 언제나 끝점이고, 줄 안쪽의 낡은 길이는 다시 읽히지 않는다. 아래 그림에서 4가 3을, 9가 8과 10을, 2가 1과 3-4를 잇는 장면을 보자.

## 유니온 파인드로 이웃끼리 묶기

"x와 x + 1은 같은 줄"이라는 관계로 수를 묶으면, 가장 큰 묶음의 크기가 답이다. 묶기와 같은 묶음 찾기를 빠르게 하는 구조가 [유니온 파인드](/posts/ds-union-find)다.

```js
function longestConsecutive(nums) {
  const parent = new Map(), size = new Map();
  const find = (x) => {
    while (parent.get(x) !== x) {
      parent.set(x, parent.get(parent.get(x))); // 경로 절반 압축
      x = parent.get(x);
    }
    return x;
  };
  const union = (a, b) => {
    a = find(a); b = find(b);
    if (a === b) return;
    if (size.get(a) < size.get(b)) [a, b] = [b, a]; // 작은 묶음을 큰 묶음 아래에
    parent.set(b, a);
    size.set(a, size.get(a) + size.get(b));
  };

  for (const x of nums) if (!parent.has(x)) { parent.set(x, x); size.set(x, 1); }
  for (const x of parent.keys()) if (parent.has(x + 1)) union(x, x + 1);

  let best = 0;
  for (const x of parent.keys()) if (find(x) === x) best = Math.max(best, size.get(x));
  return best;
}

console.log(longestConsecutive([8, 3, 10, 1, 4, 9, 2, 3]));
```

```text
4
```

시간은 O(n α(n))이다. α는 아커만 함수의 역함수로, 현실적인 입력에서는 4를 넘지 않아 사실상 O(n)이다. 그런데 10^5개에서 110ms로 가장 느렸다. 맵을 두 개 들고 `find`마다 맵을 여러 번 오가니 상수가 크다.

이 문제만 놓고 보면 유니온 파인드는 과하다. 그래도 알아 둘 이유는 있다. "이웃"의 정의가 바뀌는 변형, 예를 들어 "차이가 k 이하면 같은 무리"나 2차원 격자의 이웃이라면 집합 풀이의 "첫 수에서 세기"가 바로 통하지 않는다. 그럴 때도 유니온 파인드는 "이웃끼리 묶는다"만 바꾸면 그대로 쓴다.

## Python과 Java로 옮기기

기본 답인 "줄의 첫 수에서만 센다" 풀이다.

```python
from typing import List

class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        s = set(nums)
        best = 0
        for x in s:                 # nums가 아니라 집합을 돈다 (중복 시작점 방지)
            if x - 1 in s:          # 앞 수가 있으면 시작점이 아니다
                continue
            length = 1
            while x + length in s:
                length += 1
            best = max(best, length)
        return best

sol = Solution()
print(sol.longestConsecutive([8, 3, 10, 1, 4, 9, 2, 3]), sol.longestConsecutive([]), sol.longestConsecutive([-1, 0, 1, -3]))
```

```text
4 0 3
```

Python에서 `for x in nums`로 쓰면 아래 "틀리기 쉬운 자리"의 중복 함정에 그대로 걸린다. 반복문 대상이 `s`인지 꼭 확인한다. 변수 이름을 `len`으로 지으면 내장 함수 `len`을 가려 버리니 `length`처럼 다른 이름을 쓴다.

```java
import java.util.*;

class Solution {
    public int longestConsecutive(int[] nums) {
        Set<Integer> set = new HashSet<>();
        for (int x : nums) set.add(x);
        int best = 0;
        for (int x : set) {
            if (set.contains(x - 1)) continue;   // 시작점만 센다
            int len = 1;
            while (set.contains(x + len)) len++;
            best = Math.max(best, len);
        }
        return best;
    }

    public static void main(String[] args) {
        Solution s = new Solution();
        System.out.println(s.longestConsecutive(new int[] { 8, 3, 10, 1, 4, 9, 2, 3 }));
        System.out.println(s.longestConsecutive(new int[] {}));
        System.out.println(s.longestConsecutive(new int[] { -1, 0, 1, -3 }));
        System.out.println(s.longestConsecutive(new int[] { Integer.MAX_VALUE, Integer.MIN_VALUE }));
    }
}
```

```text
4
0
3
2
```

마지막 줄을 보자. `Integer.MAX_VALUE`와 `Integer.MIN_VALUE`는 전혀 이어지지 않는 두 수인데 답이 2로 나왔다. `MAX_VALUE + 1`이 넘쳐서 `MIN_VALUE`로 돌아갔기 때문이다. 이 문제는 값이 ±10^9 안이라 `x + 1`이 넘치지 않지만, 제약이 `int` 전체 범위인 변형이라면 `x != Integer.MAX_VALUE`를 확인하거나 `long`으로 계산해야 한다. JavaScript와 Python은 이 범위에서 넘치지 않는다.

`HashSet<Integer>`는 수마다 `Integer` 객체를 만든다(박싱). 10^5개면 상관없지만, 같은 일을 수천만 개로 한다면 기본형 정수를 담는 별도 라이브러리나 정렬 풀이가 메모리 면에서 낫다.

## 틀리기 쉬운 자리

### 집합을 만들고 nums를 돈다

첫 수 확인을 넣고도 반복문을 `for (const x of nums)`로 쓰면 O(n²)가 될 수 있다. 1부터 50,000까지에 1을 50,000번 더 붙인 배열을 넣어 봤다.

```text
for (const x of nums)  51236.51ms
for (const x of set)      10.73ms
```

1은 줄의 첫 수다. `nums`를 돌면 1이 나올 때마다, 즉 50,001번 1부터 50,000까지 줄을 다 따라간다. 첫 수 확인은 줄의 중간에서 세는 걸 막을 뿐, 같은 첫 수를 여러 번 세는 건 막지 못한다. 집합을 돌면 1은 한 번만 나온다. LeetCode에도 이런 테스트가 있어서, `nums`를 돌면 시간 초과가 날 수 있다.

### 정렬 풀이에서 중복에 줄을 끊는다

```js
function sortedNoDup(nums) {
  if (!nums.length) return 0;
  const a = [...nums].sort((x, y) => x - y);
  let best = 1, cur = 1;
  for (let i = 1; i < a.length; i++) {
    if (a[i] === a[i - 1] + 1) cur++;
    else cur = 1; // 같은 값도 여기로 와서 줄이 끊긴다
    best = Math.max(best, cur);
  }
  return best;
}
console.log(sortedNoDup([1, 2, 2, 3]));
```

```text
2
```

두 번째 2에서 `cur`가 1로 돌아가 1, 2, 3이 2와 2, 3으로 쪼개진다. 같은 값은 끊지도 늘리지도 말고 건너뛴다.

### 비교자 없이 정렬한다

`[9, 10, 11, 8]`을 `sort()`만 하면 `[10, 11, 8, 9]`가 된다. 문자열로 바꿔 사전 순으로 정렬하기 때문이다. 이 상태로 세면 10, 11과 8, 9가 따로 놀아 답이 4가 아니라 2로 나온다. 정렬 풀이에서는 `(x, y) => x - y`를 꼭 넘긴다.

### 원소가 하나인 배열

최댓값을 0으로 시작하고 정렬 후 `i = 1`부터 돌면, 원소가 하나일 때 반복문이 한 번도 돌지 않아 답이 1이 아니라 0이 나온다. 빈 배열은 따로 0을 돌려주고, 나머지는 `best = 1`로 시작한다. 집합 풀이는 `len`이 1에서 시작하니 이 문제가 없다.

### 음수와 0

`[-1, 0, 1, -3]`의 답은 -1, 0, 1로 3이다. 집합 풀이는 부호와 상관없이 맞는다. 값을 칸 번호로 쓰는 개수 배열을 만들면 음수에서 깨지고, 범위가 ±10^9라 메모리도 감당이 안 된다.

## 조건이 바뀌면

### 길이가 아니라 줄 자체를 돌려 달라면

첫 수에서만 세는 풀이에서 최댓값이 바뀔 때 첫 수 `x`와 길이를 함께 기억하면 된다. 줄은 `x`부터 `x + 길이 - 1`까지다. 길이가 같은 줄이 여러 개일 때 무엇을 돌려줄지(가장 작은 첫 수? 먼저 나온 것?)는 먼저 정하고 시작한다.

### 수가 하나씩 들어온다면

"`add(x)`를 하고, 아무 때나 지금까지의 가장 긴 줄 길이를 묻는다"면 끝점 해시맵 풀이가 그대로 맞는다. `add`마다 O(1)에 갱신하고 최댓값을 들고 있으면 질문도 O(1)이다. 이어진 구간을 목록으로 보여 달라는 LeetCode 352. Data Stream as Disjoint Intervals는 같은 생각에 정렬된 구조가 더해진 문제다. 구간을 합치는 감각은 [Merge Intervals](/posts/leetcode-merge-intervals)에서 연습할 수 있다.

### 수를 지우기도 한다면

끝점 해시맵은 지우기에 약하다. 줄 가운데 수를 지우면 줄이 둘로 쪼개지는데, 양쪽 줄의 새 끝점을 찾으려면 줄을 따라가야 한다. 지우기가 잦으면 정렬된 구간 목록(균형 이진 탐색 트리나 Java의 `TreeMap`)에 구간을 담아 지울 때 구간을 나누는 쪽이 낫다. 유니온 파인드도 묶음을 푸는 연산이 없어서 지우기를 지원하지 않는다.

### 메모리를 O(1)로 줄이라면

해시 집합 없이 O(n) 시간은 어렵다. 배열을 고쳐도 된다면 제자리 정렬 후 한 번 훑기로 O(n log n) 시간, 추가 공간 O(1)(정렬 구현에 따라 O(log n))이다. 시간과 공간을 맞바꾸는 지점이라는 걸 말하면 된다.

### 비슷한 문제

배열 안에서 위치가 붙어 있어야 하는 "연속 증가 부분 배열"(LeetCode 674. Longest Continuous Increasing Subsequence)은 한 번 훑으며 세면 된다. 위치는 떨어져도 되고 값이 커지기만 하면 되는 [Longest Increasing Subsequence](/posts/leetcode-longest-increasing-subsequence)는 동적 계획법이나 이분 탐색이 필요하다. 이름이 비슷해도 셋은 완전히 다른 문제다. 같은 배열·해시 묶음에서는 [Two Sum](/posts/leetcode-two-sum), [Top K Frequent Elements](/posts/leetcode-top-k-frequent-elements)가 집합과 맵을 다르게 쓰는 모습을 보여 준다.

## 면접에서 나올 만한 질문

### 정렬하면 쉬운데 왜 집합을 쓰나요?

문제가 O(n) 시간을 요구하는데 비교 정렬은 O(n log n)이기 때문이다. 정렬이 주는 "옆 칸이 바로 다음 수"라는 정보를 "다음 수가 있나"를 평균 O(1)에 묻는 해시 집합으로 대신한다. 실제 시간 차이는 10^5개에서 두 배 정도라, 메모리를 아껴야 하면 정렬도 좋은 선택이다.

### while 루프가 안에 있는데 왜 O(n)인가요?

while은 줄의 첫 수에서만 돌고, 그 줄의 수만 밟는다. 줄들은 서로 겹치지 않으니 모든 while이 밟는 수를 합치면 집합 크기, 많아야 n이다. 바깥 for의 n번과 더해 O(n)이다. 반복문을 곱하지 않고 안쪽이 전체에서 몇 번 도는지를 세는 분할 상환 분석이다.

### x - 1 확인을 빼면 어떻게 되나요?

줄의 모든 수에서 줄 끝까지 따라가게 되어 O(n²)가 된다. 0부터 n-1까지 다 있으면 n(n+1)/2걸음이다. 실제로 3만 개에서 10초가 걸렸고, 확인을 넣으면 4ms 안쪽이다.

### 집합이 아니라 nums를 돌면 무엇이 문제인가요?

같은 첫 수가 여러 번 들어 있으면 그때마다 같은 줄을 처음부터 다시 센다. 1부터 50,000까지에 1을 50,000개 더 붙이면 줄 길이 50,000을 50,001번 세서 51초가 걸렸다. 집합을 돌면 중복이 사라져 10ms다.

### 수가 하나씩 들어오는 상황이면요?

끝점에 줄 길이를 적어 두는 해시맵을 쓴다. 새 수가 들어오면 x - 1과 x + 1의 줄 길이를 읽어 합치고, 새 줄의 양 끝에만 길이를 적는다. 새 수가 묻는 자리는 항상 끝점이라 줄 안쪽은 고칠 필요가 없다. 들어온 수를 맵에 함께 넣어 중복을 걸러야 길이가 부풀지 않는다.

### Java로 풀 때 조심할 점은요?

`x + 1`이 `Integer.MAX_VALUE`에서 넘치면 `MIN_VALUE`가 되어, 이어지지 않는 두 수를 이어진 것으로 센다. 이 문제는 값이 ±10^9라 괜찮지만 `int` 전체 범위라면 경계를 확인하거나 `long`을 쓴다. `HashSet<Integer>`는 박싱 비용이 있어서 아주 큰 입력이면 정렬 풀이가 메모리 면에서 낫다.

### 유니온 파인드로도 풀 수 있나요?

x와 x + 1을 묶고 가장 큰 묶음의 크기를 답하면 된다. O(n α(n))으로 사실상 선형이지만 상수가 커서 10^5개에서 집합 풀이보다 여섯 배쯤 느렸다. 이웃의 정의가 바뀌거나 2차원으로 넓어지는 변형에서 같은 틀을 그대로 쓸 수 있다는 게 장점이다.
