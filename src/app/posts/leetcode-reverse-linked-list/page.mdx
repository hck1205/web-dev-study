연결 리스트를 처음 배우고 뒤집기 코드를 짜서 돌렸더니 결과에 노드가 하나만 남았다. `1→2→3`을 넣었는데 `1`만 나온다. 나머지 노드는 메모리 어딘가에 그대로 있는데, 가리키는 화살표가 없어져서 찾아갈 길이 끊긴 것이다. 연결 리스트 문제에서 가장 많이 나는 실수가 이 "화살표를 먼저 덮어써서 뒤를 잃는" 실수다.

[LeetCode 206. Reverse Linked List](https://leetcode.com/problems/reverse-linked-list/)는 그 실수를 하지 않고 리스트를 뒤집는 문제다. 쉬움 난이도지만, 여기서 익힌 "다음 노드를 붙잡고 화살표를 돌린다"는 동작이 [Reorder List](/posts/leetcode-reorder-list), [Reverse Nodes in k-Group](/posts/leetcode-reverse-nodes-in-k-group), 회문 연결 리스트 같은 문제의 부품으로 그대로 들어간다. 면접에서는 반복과 재귀 두 가지로 모두 짜 보라는 요구가 자주 붙는다. 연결 리스트 자체의 구조는 [연결 리스트 글](/posts/ds-linked-list)에서 다뤘으니, 여기서는 이 문제를 푸는 다섯 가지 방법과 각각이 깨지는 지점을 본다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 화살표 방향만 바꾸면 되는 문제

단일 연결 리스트(singly linked list)의 머리 노드 `head`가 주어진다. 노드마다 값 `val`과 다음 노드를 가리키는 `next`가 있고, 마지막 노드의 `next`는 `null`이다. 이 리스트를 뒤집은 뒤 새 머리를 돌려주면 된다.

```text
입력:  1 → 2 → 3 → 4 → null
출력:  4 → 3 → 2 → 1 → null
```

노드 개수는 0개에서 5000개, 값은 -5000에서 5000 사이다. 노드가 0개면 `head`가 `null`로 들어온다. 5000개라는 숫자는 시간보다는 재귀 깊이에서 의미가 있다. 뒤에서 보겠지만 Python은 기본 설정으로 5000번 재귀를 못 한다.

LeetCode가 쓰는 노드 정의는 이렇다. 이 글의 코드는 모두 이 모양을 전제로 한다.

```js
function ListNode(val, next) {
  this.val = val === undefined ? 0 : val;
  this.next = next === undefined ? null : next;
}
```

뒤집는다는 게 무슨 뜻인지 짚고 가자. 노드를 새로 만들거나 메모리에서 옮기라는 게 아니다. 각 노드가 들고 있는 `next` 화살표의 방향만 반대로 돌리면 된다. 2가 3을 가리키던 걸 2가 1을 가리키게 바꾸는 식이다. 화살표가 다 돌아가면 원래 꼬리였던 4가 누구에게서도 가리켜지지 않는 머리가 되고, 원래 머리였던 1은 `null`을 가리키는 꼬리가 된다.

## 손으로 네 칸을 뒤집어 보기

종이에 `1→2→3→4`를 그리고 화살표를 하나씩 돌려 보면 막히는 지점이 바로 보인다. 1의 화살표를 `null`로 돌리는 순간, 1에서 2로 가는 길이 사라진다. 2를 가리키는 건 원래 1의 `next`뿐이었으니, 이제 2, 3, 4로 갈 방법이 없다.

그래서 화살표를 돌리기 전에 "원래 다음 노드"를 따로 적어 둬야 한다. 손으로 할 때 필요한 메모는 세 개다.

- 이미 뒤집은 부분의 머리. 처음에는 아무것도 없으니 `null`이다.
- 지금 화살표를 돌릴 노드.
- 그 노드의 원래 다음 노드. 돌리기 직전에 적어 둔다.

이 세 메모를 들고 한 칸씩 오른쪽으로 가면 된다. 이 관찰이 뒤에 나올 가장 좋은 풀이의 전부다. 다만 처음부터 이걸 떠올리기 어렵다면, 화살표를 건드리지 않는 방법부터 시작해도 된다.

## 값만 꺼내서 거꾸로 다시 쓰기

가장 먼저 떠오르는 방법은 리스트를 배열처럼 다루는 것이다. 배열은 뒤집기 쉽다. 그러니 값을 전부 배열에 옮겨 담고, 리스트를 처음부터 다시 훑으면서 배열 뒤쪽 값부터 덮어쓴다.

```js
function reverseList(head) {
  // 1) 값을 앞에서부터 모두 꺼낸다
  const vals = [];
  for (let n = head; n; n = n.next) vals.push(n.val);

  // 2) 다시 앞에서부터 훑으며 배열 끝 값부터 써 넣는다
  let i = vals.length - 1;
  for (let n = head; n; n = n.next) n.val = vals[i--];

  return head; // 머리 노드는 그대로, 값만 바뀌었다
}
```

리스트를 두 번 훑으니 시간은 O(n), 값을 담은 배열 때문에 공간도 O(n)이다. `1→2→3→4`를 넣으면 노드 네 개는 제자리에 있고 값만 `4, 3, 2, 1`로 바뀐다.

LeetCode에서는 이 코드도 통과한다. 출력이 값의 순서로만 채점되기 때문이다. 하지만 면접에서 꺼내면 거의 확실히 "노드를 바꿔야 한다"는 말이 돌아온다. 이유가 있다. 실제 코드에서 노드에는 값 하나가 아니라 큰 객체가 붙어 있고, 다른 곳에서 특정 노드를 참조하고 있을 수 있다. 값만 바꾸면 "3번 노드"를 들고 있던 쪽은 갑자기 다른 데이터를 보게 된다. 값을 바꿀 수 없는 불변 객체라면 이 방법은 아예 안 된다. 문제가 원하는 건 화살표를 돌리는 것이다.

## 노드를 스택에 쌓았다가 다시 잇기

값 대신 노드 자체를 모으면 화살표를 다시 이을 수 있다. 노드를 앞에서부터 스택에 쌓으면 꺼낼 때 뒤에서부터 나온다. 꺼낸 순서대로 이어 붙이면 뒤집힌 리스트다.

```js
function reverseList(head) {
  if (!head) return null;

  const stack = [];
  for (let n = head; n; n = n.next) stack.push(n);

  const newHead = stack.pop(); // 원래 꼬리가 새 머리
  let tail = newHead;
  while (stack.length) {
    tail.next = stack.pop();   // 하나씩 꺼내 뒤에 붙인다
    tail = tail.next;
  }
  tail.next = null;            // 원래 머리가 새 꼬리. 이 줄이 없으면 고리가 생긴다
  return newHead;
}
```

마지막 `tail.next = null`이 중요하다. 원래 머리였던 1은 여전히 2를 가리키고 있다. 이 줄을 빼면 `4→3→2→1→2→1→...`처럼 1과 2가 서로를 가리키는 고리가 생기고, 결과를 출력하는 코드가 끝나지 않는다.

시간 O(n), 공간 O(n)이다. 이번에는 노드를 바꿨으니 문제의 요구는 맞췄다. 그런데 스택을 쓴 이유를 생각해 보면 "뒤에서부터 접근하고 싶어서"였다. 단일 연결 리스트에는 이전 노드로 가는 화살표가 없으니 거꾸로 걸으려고 노드를 전부 저장한 것이다. 이전 노드를 하나만 기억하면서 앞으로 걷는다면 스택 없이도 될까. 앞 절에서 손으로 찾은 세 개의 메모가 바로 그 방법이다.

## 세 개의 손가락으로 제자리에서 뒤집기

포인터 세 개를 손가락처럼 리스트 위에 올려 둔다고 생각하면 쉽다.

- `prev`: 이미 뒤집은 부분의 머리. 처음엔 `null`.
- `cur`: 지금 화살표를 돌릴 노드. 처음엔 `head`.
- `next`: `cur`의 원래 다음 노드. 돌리기 직전에 잡아 둔다.

한 바퀴에 하는 일은 네 줄이다.

1. `next = cur.next`로 뒤쪽 리스트를 붙잡는다.
2. `cur.next = prev`로 화살표를 뒤로 돌린다. 이제 `cur`가 뒤집힌 부분의 새 머리다.
3. `prev = cur`로 뒤집힌 부분의 머리를 한 칸 옮긴다.
4. `cur = next`로 붙잡아 둔 다음 노드로 간다.

`cur`가 `null`이 되면 모든 노드의 화살표를 돌린 것이고, 그때 `prev`가 원래 꼬리, 즉 새 머리를 가리킨다.

아래 그림은 `1→2→3→4`를 이 방법으로 뒤집는 과정이다. 다음을 누르면 `cur`가 한 칸씩 오른쪽으로 가고, 초록 칸은 화살표가 이미 돌아간 노드다. 아래 상자에서 `prev`쪽 리스트가 길어지고 `cur`쪽 리스트가 짧아지는 걸 보면 된다.

그림에서 `next` 메모는 바퀴 안에서만 잠깐 쓰인다. 바퀴가 끝나면 `cur`가 그 자리를 이어받는다. 매 순간 리스트가 두 조각으로 나뉘어 있다는 것도 볼 만하다. `prev`에서 시작하는 뒤집힌 앞부분과 `cur`에서 시작하는 아직 손대지 않은 뒷부분이다. 두 조각은 서로 연결돼 있지 않고, 노드는 하나도 사라지지 않는다. 이 성질이 반복문 내내 유지되기 때문에 코드가 맞다.

```js
function reverseList(head) {
  let prev = null;   // 뒤집은 부분의 머리
  let cur = head;    // 지금 돌릴 노드

  while (cur) {
    const next = cur.next; // 1) 끊기 전에 뒤쪽을 잡아 둔다
    cur.next = prev;       // 2) 화살표를 뒤로 돌린다
    prev = cur;            // 3) 뒤집은 부분의 머리를 옮긴다
    cur = next;            // 4) 잡아 둔 다음 노드로 간다
  }
  return prev;             // cur가 null일 때 prev가 원래 꼬리
}
```

시간은 O(n)이다. 노드마다 반복문을 한 번 돌고, 안에서 하는 일은 대입 네 번뿐이다. 공간은 O(1)이다. 노드 수와 상관없이 변수 세 개만 쓴다. 노드 100만 개짜리 리스트로 재 보니 이 풀이는 약 9ms, 값 복사 풀이와 스택 풀이는 각각 50ms 정도였다. 배열에 100만 개를 넣었다 빼는 비용이 그대로 드러난 것이다.

빈 리스트와 노드 하나짜리도 따로 처리할 필요가 없다. `head`가 `null`이면 반복문을 한 번도 안 돌고 `prev`인 `null`을 돌려준다. 노드가 하나면 한 바퀴 돌며 그 노드의 `next`를 `null`로 바꾸고(원래도 `null`이었다) 그 노드를 돌려준다.

네 줄의 순서는 바꿀 수 없다. 1번 전에 2번을 하면 뒤를 잃고, 3번 전에 4번을 하면 `prev`가 엉뚱한 노드를 가리킨다. 외우기 어렵다면 "잡고, 돌리고, 한 칸, 한 칸"으로 기억하면 된다. 줄의 왼쪽과 오른쪽을 이어 읽으면 `next → cur.next → prev → cur → next`로 대각선을 그리는 모양이라 이걸로 외우는 사람도 많다.

### 새 리스트 맨 앞에 하나씩 끼운다고 봐도 같다

같은 코드를 다르게 읽는 방법도 있다. 옛 리스트에서 맨 앞 노드를 하나 떼어 내서, 새 리스트의 맨 앞에 끼운다. 카드 더미 위에서 한 장씩 집어 다른 더미 위에 올려놓는 것과 같다. 처음 집은 카드가 새 더미의 맨 아래로 가니, 다 옮기고 나면 순서가 거꾸로다.

```js
function reverseList(head) {
  const result = new ListNode(); // 새 리스트 머리 앞의 빈자리 (dummy)
  while (head) {
    const node = head;        // 옛 리스트 맨 앞 노드를 떼어 낸다
    head = head.next;
    node.next = result.next;  // 새 리스트 맨 앞에 끼운다
    result.next = node;
  }
  return result.next;
}
```

변수 이름만 바꾸면 앞의 코드와 한 줄씩 대응한다. `head`가 `cur`·`next` 역할을, `result.next`가 `prev` 역할을 한다. 이렇게 "맨 앞에 끼우기"로 이해해 두면 [구간 뒤집기](#일부만-묶음으로-거꾸로-읽기만)처럼 dummy 노드가 등장하는 변형을 짤 때 머릿속 그림이 하나로 이어진다.

### Python과 Java로 쓰면

Python은 다중 대입 한 줄로 쓸 수 있다. 오른쪽 식을 모두 먼저 계산한 다음 왼쪽에 차례로 넣기 때문에 임시 변수가 필요 없다.

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def reverse_list(head):
    prev, cur = None, head
    while cur:
        # 오른쪽 (prev, cur, cur.next)를 먼저 다 계산한 뒤 왼쪽에 넣는다
        cur.next, prev, cur = prev, cur, cur.next
    return prev
```

편하지만 함정이 있다. 오른쪽은 한꺼번에 계산되는데 왼쪽은 왼쪽부터 하나씩 대입된다. 그래서 왼쪽 순서를 바꾸면 결과가 달라진다. `prev, cur, cur.next = cur, cur.next, prev`로 쓰면 `cur`가 먼저 다음 노드로 바뀐 뒤 `cur.next`에 대입하니 엉뚱한 노드의 화살표를 끊는다. 실제로 돌려 보면 두 번째 바퀴에서 `cur`가 `None`이 된 상태로 `cur.next`에 대입하려다 `AttributeError: 'NoneType' object has no attribute 'next' and no __dict__ for setting new attributes`가 난다. 한 줄 대입을 쓴다면 `cur.next`를 맨 왼쪽에 둔다. 헷갈리면 JavaScript처럼 `nxt = cur.next`를 따로 쓰는 편이 안전하다.

Java는 JavaScript와 거의 같다. `null` 비교를 명시적으로 쓰는 점만 다르다.

```java
class Solution {
    public ListNode reverseList(ListNode head) {
        ListNode prev = null, cur = head;
        while (cur != null) {
            ListNode next = cur.next; // 끊기 전에 다음 노드를 잡아 둔다
            cur.next = prev;          // 화살표를 뒤로 돌린다
            prev = cur;
            cur = next;
        }
        return prev;
    }
}
```

세 언어로 같은 입력을 돌린 결과다.


## 뒤에서부터 돌아오며 뒤집는 재귀

LeetCode 문제 아래에 "반복과 재귀 둘 다로 풀 수 있나"라는 후속 질문이 붙어 있다. 재귀로 생각하면 문제가 이렇게 바뀐다. "머리를 뺀 나머지 리스트를 뒤집는 건 재귀 호출에 맡긴다. 나는 돌아온 결과 뒤에 머리 하나만 붙이면 된다."

`1→2→3`에서 `reverse(2→3)`이 일을 끝내고 돌아오면 `3→2`가 돼 있다. 이때 1은 여전히 2를 가리키고 있다. 2가 이제 뒤집힌 리스트의 꼬리니까, 2의 `next`를 1로 바꾸면 1이 꼬리 뒤에 붙는다. 2를 따로 찾을 필요가 없다. `head.next`가 바로 2다.

```js
function reverseList(head) {
  // 노드가 없거나 하나면 그대로가 뒤집힌 모습이다
  if (!head || !head.next) return head;

  // 나머지를 뒤집는다. 돌아오는 값은 원래 꼬리, 즉 새 머리
  const newHead = reverseList(head.next);

  // head.next는 뒤집힌 리스트의 꼬리다. 그 뒤에 head를 붙인다
  head.next.next = head;
  head.next = null; // head가 새 꼬리. 고리를 끊는다

  return newHead;   // 새 머리는 끝까지 그대로 전달한다
}
```

`head.next.next = head`가 처음 보면 낯설다. 읽는 법은 "내 다음 노드야, 너의 다음을 나로 해라"다. 그다음 `head.next = null`로 내가 다음 노드를 가리키던 화살표를 끊는다. 이 줄을 빼면 1과 2가 서로를 가리키는 고리가 남는다. 실제로 빼고 돌려서 결과를 앞에서 여덟 개만 찍어 보면 `3→2→1→2→1→2→1→2`가 나온다.

아래 그림은 `1→2→3`을 넣었을 때 콜 스택이 쌓였다가 풀리는 모습이다. 내려갈 때는 아무것도 바꾸지 않고, 돌아오는 길에 화살표를 하나씩 돌린다.

Python의 기본 재귀 한도는 1000이라서, 문제 제약의 최댓값인 5000개를 로컬에서 그대로 넣으면 터진다. `sys.setrecursionlimit`으로 올릴 수 있지만 C 스택이 먼저 바닥나면 인터프리터가 죽는다. 재귀 풀이는 "연결 리스트가 재귀 구조라는 걸 안다"는 걸 보여 주는 용도이고, 실제로 제출하거나 실무에 쓸 코드는 반복 풀이다. 재귀가 콜 스택을 어떻게 쓰는지는 [재귀와 백트래킹 글](/posts/recursion-backtracking)에 있다.

Python과 Java 코드도 모양은 같다.

```python
def reverse_list(head):
    if head is None or head.next is None:
        return head
    new_head = reverse_list(head.next)
    head.next.next = head
    head.next = None
    return new_head
```

```java
public ListNode reverseList(ListNode head) {
    if (head == null || head.next == null) return head;
    ListNode newHead = reverseList(head.next);
    head.next.next = head;
    head.next = null;
    return newHead;
}
```

## 뒤집힌 앞부분을 들고 내려가는 재귀

재귀를 다른 방향으로 짤 수도 있다. 앞 풀이는 끝까지 내려간 다음 돌아오면서 일했다. 이번에는 내려가면서 일한다. 반복 풀이의 `prev`와 `cur`를 함수 인자로 넘기면 된다.

```js
function reverseList(head) {
  return go(head, null);
}

// cur: 아직 안 뒤집은 부분의 머리, prev: 이미 뒤집은 부분의 머리
function go(cur, prev) {
  if (!cur) return prev;     // 다 뒤집었다
  const next = cur.next;     // 잡고
  cur.next = prev;           // 돌리고
  return go(next, cur);      // 한 칸씩 옮겨서 다음 호출에 넘긴다
}
```

반복문의 한 바퀴가 호출 하나가 됐을 뿐 하는 일은 똑같다. 재귀 호출이 함수의 맨 마지막 동작이라서 꼬리 재귀(tail recursion)라고 부른다. 꼬리 호출 최적화(TCO)를 해 주는 언어라면 호출이 쌓이지 않고 반복문처럼 돌아서 공간이 O(1)이 된다.

문제는 이 글에서 쓰는 세 언어가 모두 그 최적화를 해 주지 않는다는 것이다. JavaScript는 ES2015 명세에 꼬리 호출 최적화가 들어갔지만 V8(Node.js, 크롬)은 구현하지 않았고, 사파리의 JavaScriptCore만 지원한다. 노드 100만 개로 돌리면 Node.js에서 `RangeError`가 난다. Python과 Java도 꼬리 호출을 최적화하지 않는다. 그래서 이 풀이도 실제 공간은 O(n)이다. 면접에서는 "꼬리 재귀로 바꾸면 Scala나 Kotlin의 `tailrec`처럼 최적화해 주는 환경에서 O(1)이 되지만, JS·Python·Java에서는 여전히 O(n)이다"라고 범위를 밝혀 말하면 된다. 반복 풀이와 재귀 풀이가 사실 같은 생각이라는 걸 보여 주는 다리 역할로는 좋은 풀이다.

## 다섯 풀이를 나란히 놓으면

| 풀이 | 시간 | 공간 | 언제 고르나 |
|---|---|---|---|
| 값 꺼내서 다시 쓰기 | O(n) | O(n) | 값만 맞으면 될 때. 노드를 바꾸라는 요구에는 맞지 않는다 |
| 노드 스택 | O(n) | O(n) | 거꾸로 걷는 감을 잡을 때. 마지막 `null` 처리를 잊기 쉽다 |
| 포인터 세 개 반복 | O(n) | O(1) | 기본 답. 제출과 실무 모두 이것 |
| 뒤에서 돌아오는 재귀 | O(n) | O(n) 콜 스택 | 재귀로 짜 보라는 후속 질문. 깊은 리스트에서 터진다 |
| 꼬리 재귀 | O(n) | O(n), TCO 환경에서 O(1) | 반복과 재귀가 같은 생각임을 보여 줄 때 |

모든 풀이가 노드를 한 번씩은 봐야 하니 시간 O(n)보다 빠를 수는 없다. 차이는 공간과 노드를 실제로 바꾸느냐에 있다. 면접에서는 반복 풀이를 먼저 짜고, 재귀를 요구하면 뒤에서 돌아오는 버전을 짜면서 "콜 스택 때문에 O(n)"을 덧붙이는 흐름이 자연스럽다.

## 화살표를 잃어버리는 실수들

글 첫머리의 "노드 하나만 남는" 버그는 `next`를 잡아 두지 않아서 생긴다.

```js
// next를 잡아 두지 않은 코드
while (cur) {
  cur.next = prev; // 화살표를 먼저 돌렸다
  prev = cur;
  cur = cur.next;  // 방금 돌린 화살표를 따라가니 prev(뒤쪽)로 간다
}
// [1, 2, 3] → [1]
```

첫 바퀴에서 1의 `next`가 `null`이 되고, `cur = cur.next`가 그 `null`을 따라가서 반복이 끝난다. 2와 3은 아무도 가리키지 않게 되어 사라진다. 결과는 `[1]`이다.

반환값을 헷갈리는 실수도 흔하다. 반복문이 끝났을 때 `cur`는 항상 `null`이다. `return cur`로 쓰면 어떤 입력이든 빈 리스트가 나온다. `return head`도 틀린다. `head`는 원래 머리였고 지금은 꼬리라서, 노드 하나짜리 리스트가 나온다.

재귀 풀이에서는 `head.next = null`을 빠뜨리면 마지막 두 노드 사이에 고리가 남는다. LeetCode 채점기는 결과를 따라가다 고리를 만나면 오류를 낸다. 스택 풀이의 마지막 `tail.next = null`도 같은 이유로 필요하다.

재귀의 종료 조건을 `if (!head) return head`만 쓰는 실수도 있다. 그러면 마지막 노드에서 `reverseList(null)`이 `null`을 돌려주고, 마지막 노드가 `head.next.next = head`를 실행하려다 `head.next`가 `null`이라서 `TypeError`가 난다. 노드가 하나 남았을 때도 멈춰야 한다.

입력 쪽에서 볼 엣지 케이스는 많지 않다. 빈 리스트, 노드 하나, 노드 둘이다. 노드 둘은 화살표가 하나뿐이라 돌린 뒤 원래 머리의 `next`를 `null`로 만드는지 바로 드러난다. 값의 범위나 중복은 화살표만 다루는 이 문제에 영향을 주지 않는다.

## 일부만, 묶음으로, 거꾸로 읽기만

### 가운데 구간만 뒤집으라면

LeetCode 92 Reverse Linked List II다. `left`번째부터 `right`번째 노드까지만 뒤집는다. 구간 바로 앞 노드를 찾아 두고, 구간 안에서만 세 포인터 뒤집기를 돌린 뒤 양 끝을 다시 이어 붙인다. 구간이 1번 노드부터 시작할 수도 있으니 머리 앞에 가짜 노드(dummy)를 하나 두면 "앞 노드가 없는 경우"를 따로 처리하지 않아도 된다.

```js
function reverseBetween(head, left, right) {
  const dummy = new ListNode(0, head);
  let before = dummy;
  for (let i = 1; i < left; i++) before = before.next; // left 바로 앞 노드

  let prev = null, cur = before.next;
  for (let i = left; i <= right; i++) {                 // 구간 안만 뒤집는다
    const next = cur.next;
    cur.next = prev;
    prev = cur;
    cur = next;
  }
  before.next.next = cur; // 구간의 옛 머리(이제 꼬리)를 구간 뒤에 잇는다
  before.next = prev;     // 앞 노드를 구간의 새 머리에 잇는다
  return dummy.next;
}
// [1,2,3,4,5], 2, 4 → [1,4,3,2,5]
// [1,2,3], 1, 3     → [3,2,1]
```

반복이 끝나면 `prev`는 구간의 새 머리, `cur`는 구간 바로 뒤 노드다. 이음매 두 군데만 다시 잡아 주면 된다.

### k개씩 묶어서 뒤집으라면

[LeetCode 25. Reverse Nodes in k-Group](/posts/leetcode-reverse-nodes-in-k-group)이다. 위의 구간 뒤집기를 k칸마다 반복하는데, 남은 노드가 k개보다 적으면 뒤집지 않는다. 그래서 뒤집기 전에 k개가 남아 있는지 먼저 세어 본다. 이음매 관리가 까다로워서 어려움 난이도가 붙었지만, 안에서 돌아가는 건 이 글의 반복 풀이 그대로다.

### 리스트를 바꾸지 말고 거꾸로 출력만 하라면

리스트가 다른 곳에서도 쓰여서 건드리면 안 되는 상황이다. 그러면 화살표를 돌리지 않고 거꾸로 읽기만 한다. 재귀로 끝까지 내려간 뒤 돌아오면서 출력하거나, 스택에 쌓았다가 꺼낸다. 둘 다 O(n) 공간이 든다. 리스트를 잠깐 뒤집었다가 출력하고 다시 뒤집으면 O(1) 공간이지만, 그 사이에 다른 스레드가 리스트를 읽으면 깨진 모습을 보게 되니 공유 자료에는 쓰지 않는다.

### 앞뒤가 같은지 확인하라면

LeetCode 234 Palindrome Linked List다. O(1) 공간으로 풀려면 이 글의 뒤집기가 필요하다. 빠른 포인터와 느린 포인터로 가운데를 찾고, 뒤쪽 절반을 뒤집은 다음, 앞쪽 절반과 한 칸씩 비교한다. 가운데를 찾는 방법은 [Linked List Cycle](/posts/leetcode-linked-list-cycle)에서 쓰는 두 속도 포인터와 같다. 비교가 끝나면 뒤쪽을 다시 뒤집어서 입력을 원래대로 돌려놓는 것까지가 예의 바른 답이다.

"가운데 찾기 → 뒤쪽 절반 뒤집기 → 두 절반 합치기"를 그대로 쓰는 문제가 [Reorder List](/posts/leetcode-reorder-list)다. 합치는 단계는 [Merge Two Sorted Lists](/posts/leetcode-merge-two-sorted-lists)의 이어 붙이기와 닮았다.

### 이중 연결 리스트라면

노드마다 `prev`와 `next`가 둘 다 있으면, 각 노드의 두 화살표를 서로 바꾸기만 하면 된다. 바꾼 뒤에는 원래의 `next`가 `prev` 자리에 있으니, 다음 노드로 갈 때 `prev`를 따라가야 한다. 마지막으로 방문한 노드가 새 머리다.

### 숫자가 거꾸로 저장돼 있다면

[LeetCode 2. Add Two Numbers](/posts/leetcode-add-two-numbers)는 자릿수가 일의 자리부터 저장된 두 리스트를 더한다. 자릿수가 큰 자리부터 저장된 변형(LeetCode 445 Add Two Numbers II)은 두 리스트를 뒤집어서 2번 문제로 바꾼 다음, 결과를 다시 뒤집는 방법으로 풀 수 있다.

## 끊기 전에 붙잡는다

연결 리스트 뒤집기는 "화살표를 돌리기 전에 다음 노드를 붙잡아 둔다"는 한 가지 규칙으로 끝난다. `prev`, `cur`, `next` 세 포인터로 잡고, 돌리고, 한 칸씩 옮기면 O(n) 시간, O(1) 공간에 제자리에서 뒤집힌다. 재귀 풀이는 같은 일을 콜 스택에 맡긴 것이라 깊이만큼 공간이 들고, 깊은 리스트에서는 터진다. 이 네 줄은 구간 뒤집기, k개 묶음 뒤집기, 회문 검사, 리스트 재배치에 부품으로 들어가니 손에 익혀 두면 연결 리스트 문제의 절반이 쉬워진다.

## 면접에서 나올 만한 질문

### 반복 풀이의 시간과 공간 복잡도는 어떻게 되나요?

시간 O(n), 공간 O(1)이다. 노드마다 반복문을 한 번 돌며 대입 네 번만 하고, 노드 수와 상관없이 `prev`, `cur`, `next` 세 변수만 쓴다. 노드를 새로 만들지 않고 기존 노드의 화살표만 바꾸는 제자리 알고리즘이다.

### 왜 next를 따로 저장해야 하나요?

단일 연결 리스트에서 다음 노드로 가는 길은 `cur.next` 하나뿐이다. `cur.next = prev`로 화살표를 돌리는 순간 그 길이 사라지니, 돌리기 전에 `next`에 붙잡아 둬야 뒤쪽 리스트를 계속 따라갈 수 있다. 이걸 빼먹으면 첫 노드만 남고 나머지를 잃는다.

### 재귀로 짜면 무엇이 달라지나요?

나머지 리스트를 재귀로 뒤집고, 돌아와서 `head.next.next = head`, `head.next = null`로 자기를 꼬리에 붙인다. 시간은 똑같이 O(n)이지만 콜 스택에 노드 수만큼 호출이 쌓여 공간이 O(n)이다. Python은 기본 재귀 한도 1000에 걸리고, JS와 Java도 10만 개 정도에서 스택 오버플로가 난다.

### 꼬리 재귀로 바꾸면 공간이 O(1)이 되나요?

꼬리 호출 최적화를 해 주는 환경에서만 그렇다. `go(next, cur)`처럼 재귀 호출이 마지막 동작이면 Scala나 Kotlin의 `tailrec`은 반복문으로 바꿔 주지만, V8 기반 JavaScript, Python, Java는 최적화하지 않아서 여전히 O(n)이다. 그래서 공간을 줄이려면 반복문으로 쓴다.

### 값만 바꿔서 뒤집으면 안 되나요?

LeetCode 채점은 통과하지만 보통 요구 사항을 어긴 것으로 본다. 노드에 큰 데이터가 붙어 있거나 외부에서 특정 노드를 참조하고 있으면, 값을 옮기는 순간 그 참조가 엉뚱한 데이터를 보게 된다. 값을 바꿀 수 없는 불변 객체라면 아예 쓸 수 없고, 추가 배열 때문에 O(n) 공간도 든다.

### 일부 구간만 뒤집으려면 어떻게 하나요?

구간 바로 앞 노드를 찾고, 구간 안에서만 같은 세 포인터 뒤집기를 돌린 다음 이음매 두 곳을 다시 잇는다. 앞 노드의 `next`는 새 구간 머리로, 구간의 옛 머리(이제 꼬리)의 `next`는 구간 바로 뒤 노드로 바꾼다. 구간이 머리부터 시작하는 경우를 따로 처리하지 않으려고 dummy 노드를 앞에 둔다.

### 리스트를 바꾸지 않고 앞뒤가 같은지 볼 수 있나요?

리스트를 전혀 건드리지 않으려면 값을 배열에 옮기거나 스택을 써야 해서 O(n) 공간이 든다. O(1) 공간이 필요하면 빠른·느린 포인터로 가운데를 찾고 뒤쪽 절반을 뒤집어 비교한 다음, 비교가 끝나면 다시 뒤집어 원래대로 돌려놓는다. 잠깐 바뀌는 동안 다른 스레드가 읽지 않는다는 전제가 필요하다.
