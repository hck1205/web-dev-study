지도 앱에서 "이 근처 사각 구역 안의 가게"를 찾거나, 게임에서 격자 위 유닛들이 어떤 모양을 이뤘는지 판정하는 코드는 공통된 고민을 한다. 점이 계속 들어오는데, 질문이 올 때마다 전부 다시 훑을 것인가, 아니면 들어올 때 정리해 두고 질문엔 빨리 답할 것인가. [Detect Squares](https://leetcode.com/problems/detect-squares/)는 그 고민을 정사각형 세기로 줄여 놓은 설계 문제다.

이 글은 풀이 다섯 개를 놓는다. 점 목록을 두 번 훑는 방법, 목록에 개수 장부를 더한 방법, 서로 다른 점만 대각선 후보로 보는 방법, 질문 점과 같은 세로줄의 점만 보는 방법, 변의 길이를 1부터 1000까지 직접 대 보는 방법이다. 어느 풀이든 바탕은 "대각선 하나가 정사각형을 정한다"는 기하 성질 하나다. 코드는 모두 Node.js 22, Python 3.13, Java 21에서 직접 돌렸다.

## 점을 모아 두고 정사각형 개수를 묻는다

`DetectSquares` 클래스를 만든다.

- `add([x, y])`: 점 하나를 저장한다. 같은 점이 여러 번 들어오면 각각 다른 점으로 친다.
- `count([qx, qy])`: 질문 점을 한 모서리로 하고, 저장된 점 세 개를 나머지 모서리로 하는 정사각형의 개수를 돌려준다. 정사각형은 변이 x축, y축과 나란해야 하고(축 정렬), 넓이가 0보다 커야 한다.

제약 중 풀이에 영향을 주는 건 두 가지다.

- 좌표는 0 이상 1000 이하의 정수다. 그래서 1001 × 1001칸짜리 배열을 만들 수도 있고, `x * 1001 + y`로 좌표 하나를 정수 키 하나로 바꿀 수도 있다.
- `add`와 `count`를 합쳐 많아야 3000번 부른다. 점이 3000개 가까이 쌓일 수 있으니, `count` 한 번에 점 목록을 두 번 겹쳐 훑는 O(N²)은 900만 번이 넘고 그걸 수천 번 하면 느리다.

질문 점 자체는 저장된 점이 아니어도 된다. 그리고 질문 점과 같은 자리에 저장된 점이 있어도 그 점은 질문 점의 역할을 대신하지 않는다. 질문 점은 질문 점이고, 나머지 세 모서리만 저장된 점에서 고른다.

## 대각선 하나가 정사각형을 정한다

질문 점이 (4, 4)이고, 저장된 점 중 하나가 (1, 1)이라고 하자. 두 점의 x 차이는 3, y 차이도 3으로 같다. 그러면 두 점은 한 변이 3인 정사각형의 대각선 양 끝이 될 수 있고, 나머지 두 모서리는 반드시 (4, 1)과 (1, 4)다. 다른 선택지가 없다.

```text
y
4   (1,4) ────── Q(4,4)
      │            │
      │            │
1   (1,1) ────── (4,1)
     1            4      x
```

축 정렬 정사각형에서는 대각선의 두 끝이 (x1, y1), (x2, y2)라면 나머지 두 끝이 (x1, y2), (x2, y1)이다. 두 점의 x 좌표와 y 좌표를 서로 바꿔 조합한 자리다. 그리고 정사각형이 되려면 가로와 세로 길이가 같아야 하니 `|x1 - x2| = |y1 - y2|`여야 한다. 이 차이가 0이면 두 점이 같은 자리라 넓이가 0이다.

그래서 세는 방법이 정해진다. 저장된 점 중 질문 점과의 x 차이와 y 차이가 같고 0이 아닌 점을 대각선 후보로 고른다. 후보마다 나머지 두 자리에 점이 몇 개씩 있는지 세어 곱한다. 같은 자리에 점이 여러 개면 그중 아무거나 고를 수 있으니 곱이 된다. (1, 1)에 2개, (4, 1)에 1개, (1, 4)에 1개가 있다면 정사각형은 2 × 1 × 1 = 2개다.

대각선이 아니라 질문 점과 같은 가로줄이나 세로줄에 있는 점에서 출발해도 된다. 그때는 변의 길이가 정해지지만 정사각형이 그 변의 양쪽(위아래 또는 좌우)에 하나씩 생길 수 있어 두 방향을 모두 봐야 한다. 이 방법은 뒤에서 네 번째 풀이로 쓴다.

### 질문 점이 가운데에 있으면 네 방향을 다 본다

예시의 정사각형은 둘 다 질문 점의 왼쪽 아래에 있었다. 질문 점이 점들 가운데에 있으면 정사각형이 네 방향 어디에나 생긴다. 점 (3,3), (3,5), (5,3), (7,7), (7,5), (5,7), (3,7)을 저장하고 (5,5)를 물어 본다.

```text
y
7   (3,7) ──── (5,7) ──── (7,7)
      │          │          │
5   (3,5) ──── Q(5,5) ──── (7,5)
      │          │
3   (3,3) ──── (5,3)
     3          5          7      x
```

대각선 후보는 (3,3), (7,7), (3,7) 셋이다. 모두 질문 점과 x 차이 2, y 차이 2다. (3,3)은 왼쪽 아래, (7,7)은 오른쪽 위, (3,7)은 왼쪽 위 정사각형을 만든다. 오른쪽 아래의 (7,3)은 저장되지 않아 그 방향은 없다. 답은 3이다.

여기서 눈여겨볼 건 (3,5)와 (5,7)이 정사각형 두 개에 동시에 쓰인다는 것이다. 한 점이 여러 정사각형의 모서리가 될 수 있으니, 점을 한 번 쓰면 지우는 식으로 세면 안 된다. 대각선 후보마다 독립적으로 세어 더한다. 이 입력은 뒤의 직접 세어 보기 테스트에도 넣었다.

## 점 목록을 두 번 훑는다

장부 없이 들어온 점을 배열에 그대로 쌓아 두는 방법부터 본다. `count`에서는 목록의 점을 하나씩 대각선 후보로 보고, 후보마다 나머지 두 자리에 몇 개가 있는지 목록을 다시 처음부터 훑어 센다.

```js
class DetectSquares {
  constructor() {
    this.pts = [];                       // 들어온 점을 그대로 쌓는다(중복 포함)
  }
  add([x, y]) {
    this.pts.push([x, y]);
  }
  count([qx, qy]) {
    let total = 0;
    for (const [dx, dy] of this.pts) {   // 이 점을 대각선 끝으로 본다
      if (Math.abs(dx - qx) !== Math.abs(dy - qy) || dx === qx) continue;
      let a = 0, b = 0;
      for (const [x, y] of this.pts) {   // 나머지 두 자리를 세려고 다시 훑는다
        if (x === qx && y === dy) a++;
        if (x === dx && y === qy) b++;
      }
      total += a * b;
    }
    return total;
  }
}
```

대각선 후보가 목록에 중복으로 들어 있으면 바깥 반복이 그 점을 여러 번 만난다. 그래서 바깥 반복에서는 개수를 곱하지 않고, 안쪽에서 센 두 개수만 곱해 더한다. (1, 1)이 두 번 들어 있으면 2 × 1 × 1이 1 × 1 × 1을 두 번 더하는 것으로 바뀔 뿐이다.

`dx === qx` 검사는 넓이 0을 거른다. x 차이와 y 차이가 같은데 x 차이가 0이면 y 차이도 0이라 같은 자리다. y 쪽은 따로 검사하지 않아도 된다.

`add`는 O(1)이다. `count`는 바깥과 안쪽이 모두 N번이라 O(N²)이다. 점이 3000개 가까이 쌓이고 `count`가 많이 불리면 문제가 된다. 20 × 20 좁은 영역에 점 1500개를 넣고 질문을 1500번 던졌더니 약 2.2초가 걸렸다. 점이 좁은 곳에 모여야 대각선 후보가 많아져 안쪽 반복이 많이 돈다. 시간 대부분은 같은 개수를 몇 번이고 다시 세는 데 쓰인다. 개수를 미리 적어 두면 안쪽 반복이 사라진다.

## 목록 옆에 개수 장부를 둔다

`add`할 때 "이 자리에 점이 몇 개인가"를 해시맵에 적어 둔다. 그러면 `count`의 안쪽 반복이 해시맵 조회 두 번으로 바뀐다.

```js
class DetectSquares {
  constructor() {
    this.pts = [];                       // 대각선 후보로 훑을 목록(중복 포함)
    this.cnt = new Map();                // 좌표 키 -> 개수
  }
  add([x, y]) {
    this.pts.push([x, y]);
    const k = x * 1001 + y;              // 좌표가 0~1000이라 키가 겹치지 않는다
    this.cnt.set(k, (this.cnt.get(k) || 0) + 1);
  }
  count([qx, qy]) {
    let total = 0;
    for (const [dx, dy] of this.pts) {
      if (Math.abs(dx - qx) !== Math.abs(dy - qy) || dx === qx) continue;
      // 목록에 중복이 그대로 있으니 대각선 쪽 개수는 곱하지 않는다
      total += (this.cnt.get(qx * 1001 + dy) || 0) * (this.cnt.get(dx * 1001 + qy) || 0);
    }
    return total;
  }
}
```

### 좌표를 키 하나로 만드는 법

JavaScript의 `Map`은 배열 `[1, 4]`를 키로 쓰면 값이 아니라 배열 객체가 같은지를 본다. `cnt.get([1, 4])`는 새 배열이라 항상 `undefined`다. 그래서 좌표를 값으로 비교되는 키로 바꿔야 한다. 문자열 `` `${x},${y}` ``도 되고, 정수 `x * 1001 + y`도 된다. y가 0~1000이라 1001을 곱하면 서로 다른 좌표가 같은 키가 되지 않는다. 다시 좌표로 돌릴 때는 `Math.floor(k / 1001)`이 x, `k % 1001`이 y다. 정수 키는 조회할 때마다 문자열을 만들지 않아도 된다.

Python은 튜플 `(x, y)`가 그대로 해시 가능한 키라 이런 변환이 필요 없다. Java는 `int[]`가 JavaScript 배열처럼 객체 비교라 키로 못 쓴다. `x * 1001 + y` 같은 정수 키나 `List.of(x, y)`를 쓴다.

`count`는 O(N)이 됐다. 같은 1500개 점과 1500번 질문에서 약 15ms였다. 2.2초에서 150배쯤 빨라졌다. 다만 목록에 중복이 그대로 있어서, 같은 자리에 점이 1000개 쌓이면 그 자리를 1000번 따로 본다. 1000번 모두 같은 계산이다.

### 목록과 장부를 섞으면 두 번 센다

이 풀이에서 흔히 하는 실수는 장부만 남기고 목록을 지운 뒤, 목록을 훑던 코드를 그대로 장부의 키로 돌리는 것이다. 그러면 대각선 쪽 개수가 빠진다. 반대로 목록을 훑으면서 대각선 쪽 개수까지 곱하면 중복이 두 번 반영된다. (1, 1)이 두 개일 때 목록에서 두 번 만나고, 매번 2를 곱하니 2 × 2 = 4가 된다. 정답은 2다. 무엇을 훑느냐(중복 포함 목록인가, 서로 다른 자리인가)와 무엇을 곱하느냐를 짝지어 기억한다.

## 서로 다른 자리만 대각선으로 본다

목록을 없애고 장부의 키, 즉 서로 다른 자리만 훑는다. 같은 자리에 점이 여러 개 있으면 그 개수를 대각선 쪽에도 곱한다.

```js
class DetectSquares {
  constructor() {
    this.cnt = new Map();                       // 좌표 키 -> 개수. 목록은 따로 두지 않는다
  }
  add([x, y]) {
    const k = x * 1001 + y;
    this.cnt.set(k, (this.cnt.get(k) || 0) + 1);
  }
  count([qx, qy]) {
    let total = 0;
    for (const [k, c] of this.cnt) {            // 서로 다른 자리만 한 번씩
      const dx = Math.floor(k / 1001), dy = k % 1001;
      if (Math.abs(dx - qx) !== Math.abs(dy - qy) || dx === qx) continue;
      // 대각선 자리의 개수 c까지 곱한다
      total += c * (this.cnt.get(qx * 1001 + dy) || 0) * (this.cnt.get(dx * 1001 + qy) || 0);
    }
    return total;
  }
}
```

앞의 예시로 `count([4, 4])`를 실제로 돌리며 장부를 훑는 순서와 합계를 찍었다. `Map`은 넣은 순서대로 훑으니 칸 순서가 곧 `add` 순서다. 두 번째 (1, 1)은 새 칸을 만들지 않고 개수만 2로 올렸다.

이 풀이가 이 문제의 기본 답이다. 장부 하나로 끝나고, 대각선 하나가 정사각형을 정한다는 성질이 코드에 그대로 보인다.

## 같은 세로줄의 점만 본다

대각선 후보를 고르려고 장부 전체를 훑지만, 대부분은 대각선이 아니라 바로 버려진다. 질문 점과 같은 세로줄(x가 같은 줄)에 있는 점만 보면 처음부터 쓸모 있는 점만 만난다. 같은 세로줄의 점 (qx, y)가 정해지면 변 길이 d = y - qy가 정해지고, 정사각형은 그 변의 오른쪽(x = qx + d)이나 왼쪽(x = qx - d)에 생긴다.

```js
class DetectSquares {
  constructor() {
    this.cols = new Map();                     // x -> (y -> 개수)
  }
  add([x, y]) {
    if (!this.cols.has(x)) this.cols.set(x, new Map());
    const col = this.cols.get(x);
    col.set(y, (col.get(y) || 0) + 1);
  }
  get(x, y) {
    const col = this.cols.get(x);
    return col ? col.get(y) || 0 : 0;          // 없는 줄이나 칸은 0
  }
  count([qx, qy]) {
    const col = this.cols.get(qx);
    if (!col) return 0;                        // 질문 점의 세로줄이 비었으면 정사각형도 없다
    let total = 0;
    for (const [y, c] of col) {
      if (y === qy) continue;                  // 변 길이 0
      const d = y - qy;                        // 음수여도 된다. 위로든 아래로든
      total += c * this.get(qx + d, qy) * this.get(qx + d, y);   // 한쪽
      total += c * this.get(qx - d, qy) * this.get(qx - d, y);   // 반대쪽
    }
    return total;
  }
}
```

d가 음수여도 따로 나눌 필요가 없다. d = -3이면 `qx + d`가 왼쪽, `qx - d`가 오른쪽이 되어 두 방향을 그대로 다 본다. 두 방향을 모두 더해야 하는 게 이 풀이의 함정이다. 한쪽만 더하면 질문 점 왼쪽에 생기는 정사각형을 놓친다. 앞의 예시에서 세로줄 x = 4에는 (4, 1)과 (4, 2)가 있고, 둘 다 왼쪽으로 정사각형이 생겨 2 + 1 = 3이 나온다.

`count`는 질문 점의 세로줄에 있는 서로 다른 자리 수만큼 돈다. 점이 1001 × 1001 전체에 흩어지면 한 줄에 점이 몇 개 없어서 아주 빠르다. 같은 1500개 점을 흩뿌린 시험에서 서로 다른 자리 풀이가 약 20ms일 때 이 풀이는 1ms 안팎이었다. 대신 점이 모두 한 세로줄에 몰리면 그 줄을 다 훑으면서 조회를 네 번씩 해서 오히려 느렸다(약 48ms, 서로 다른 자리 풀이는 약 13ms). 이건 입력 모양에 따라 승부가 갈리는 풀이다.

## 변의 길이를 하나씩 대 본다

좌표가 0~1000으로 정해져 있다는 걸 끝까지 쓰는 방법이다. 장부를 1001 × 1001칸 배열로 만들고, `count`에서는 저장된 점을 훑는 대신 변의 길이 d를 1부터 1000까지 늘리며 네 대각선 방향(오른쪽 위, 오른쪽 아래, 왼쪽 위, 왼쪽 아래)의 칸을 직접 본다.

```js
class DetectSquares {
  constructor() {
    this.g = new Int32Array(1001 * 1001);       // 칸마다 점 개수. 처음엔 모두 0
  }
  add([x, y]) {
    this.g[x * 1001 + y]++;
  }
  at(x, y) {
    return x < 0 || y < 0 || x > 1000 || y > 1000 ? 0 : this.g[x * 1001 + y];
  }
  count([qx, qy]) {
    let total = 0;
    for (let d = 1; d <= 1000; d++) {
      for (const [sx, sy] of [[1, 1], [1, -1], [-1, 1], [-1, -1]]) {
        const x = qx + sx * d, y = qy + sy * d;            // 대각선 끝 후보
        if (x < 0 || y < 0 || x > 1000 || y > 1000) continue;
        const c = this.g[x * 1001 + y];
        if (c) total += c * this.at(qx, y) * this.at(x, qy);
      }
    }
    return total;
  }
}
```

`count`가 점의 개수와 상관없이 많아야 4000칸을 본다. 시간이 입력에 따라 흔들리지 않는다는 게 장점이다. 실제로 세 가지 입력 모양 모두 35~60ms 사이였다. 하지만 점이 적을 때도 4000칸을 다 보니 앞의 장부 풀이들보다 대체로 느리고, 배열에 약 100만 칸(`Int32Array`라 약 4MB)을 미리 잡는다. 좌표 범위가 10^9로 커지면 아예 쓸 수 없다. "좌표 범위가 작으면 배열이 해시맵을 대신할 수 있다"는 걸 보여 주는 풀이로 기억한다.

## Python과 Java, 장부를 만드는 도구가 다르다

서로 다른 자리 풀이를 옮겼다.

```python
from collections import Counter
from typing import List

class DetectSquares:
    def __init__(self):
        self.cnt = Counter()                      # (x, y) -> 몇 번 들어왔나

    def add(self, point: List[int]) -> None:
        self.cnt[tuple(point)] += 1               # 리스트는 키가 될 수 없어 튜플로 바꾼다

    def count(self, point: List[int]) -> int:
        qx, qy = point
        total = 0
        for (x, y), c in self.cnt.items():
            if abs(x - qx) != abs(y - qy) or x == qx:
                continue                          # 대각선이 아니거나 넓이가 0
            # Counter는 없는 키를 0으로 돌려준다(키를 새로 만들지도 않는다)
            total += c * self.cnt[(qx, y)] * self.cnt[(x, qy)]
        return total

ds = DetectSquares()
for p in [[1, 1], [1, 4], [4, 1], [2, 2], [2, 4], [4, 2], [6, 6], [5, 3], [1, 1]]:
    ds.add(p)
print(ds.count([4, 4]), ds.count([1, 1]), len(ds.cnt))
```

```text
3 0 8
```

여기서 `Counter` 대신 `defaultdict(int)`를 쓰면 터진다. `defaultdict`는 없는 키를 읽기만 해도 그 키를 0으로 새로 만든다. `items()`로 훑는 도중에 `self.cnt[(qx, y)]`가 새 키를 만들면 반복 중에 딕셔너리 크기가 바뀌어 `RuntimeError: dictionary changed size during iteration`이 난다. 실제로 (4, 4)를 물었을 때 이 오류가 났다. `defaultdict`를 쓰려면 조회를 `self.cnt.get((qx, y), 0)`으로 바꾼다. `Counter`는 없는 키를 읽을 때 0만 돌려주고 키를 만들지 않는다. 마지막 줄의 `len(ds.cnt)`가 8로 그대로인 게 그 증거다.

```java
import java.util.HashMap;
import java.util.Map;

class DetectSquares {
    private final Map<Integer, Integer> cnt = new HashMap<>();   // x * 1001 + y -> 개수

    private static int key(int x, int y) { return x * 1001 + y; } // 좌표가 0~1000이라 겹치지 않는다

    public void add(int[] point) {
        cnt.merge(key(point[0], point[1]), 1, Integer::sum);
    }

    public int count(int[] point) {
        int qx = point[0], qy = point[1];
        long total = 0;                                           // 곱 하나가 10^9 가까이 될 수 있다
        for (Map.Entry<Integer, Integer> e : cnt.entrySet()) {
            int x = e.getKey() / 1001, y = e.getKey() % 1001;
            if (Math.abs(x - qx) != Math.abs(y - qy) || x == qx) continue;
            total += (long) e.getValue()
                   * cnt.getOrDefault(key(qx, y), 0)
                   * cnt.getOrDefault(key(x, qy), 0);
        }
        return (int) total;
    }

    public static void main(String[] args) {
        DetectSquares ds = new DetectSquares();
        int[][] pts = {{1, 1}, {1, 4}, {4, 1}, {2, 2}, {2, 4}, {4, 2}, {6, 6}, {5, 3}, {1, 1}};
        for (int[] p : pts) ds.add(p);
        System.out.println(ds.count(new int[]{4, 4}) + " " + ds.count(new int[]{1, 1}));
        DetectSquares big = new DetectSquares();
        for (int i = 0; i < 999; i++) { big.add(new int[]{0, 1}); big.add(new int[]{1, 0}); big.add(new int[]{1, 1}); }
        System.out.println(big.count(new int[]{0, 0}));
    }
}
```

```text
3 0
997002999
```

`cnt.merge(k, 1, Integer::sum)`은 "없으면 1, 있으면 더하기"를 한 줄로 쓴 것이다. 두 번째 시험은 세 자리에 점을 999개씩 넣은 경우다. 정사각형 하나의 곱이 999³ = 997,002,999로 `int` 최댓값(약 21억)의 절반에 가깝다. 이 문제의 호출 수 제한에서 답은 `int`로 돌려주지만, 곱하는 도중엔 `long`으로 계산해 두는 편이 안전하다. 첫 곱셈에서 `(long)`을 붙여야 나머지 곱셈이 `long`으로 이어진다. 끝에 붙이면 이미 넘친 `int`를 바꿀 뿐이다.

## 다섯 장부를 같은 입력으로 재 보면

`add` 1500번 뒤 `count` 1500번을 한 묶음으로 재었다(Node.js 22, 내 컴퓨터). 좁은 영역은 20 × 20 안에 점이 몰린 경우, 흩뿌림은 1001 × 1001 전체에 고르게 뿌린 경우다.

| 풀이 | add | count | 공간 | 좁은 영역 | 흩뿌림 | 언제 고르나 |
|---|---|---|---|---|---|---|
| 목록을 두 번 훑기 | O(1) | O(N²) | O(N) | 약 2.2초 | 약 60ms | 다음 풀이로 가는 출발점 |
| 목록 + 개수 장부 | O(1) | O(N) | O(N) | 약 15ms | 약 10ms | 중복이 적을 때. 무엇을 곱할지 헷갈리지 않게 |
| 서로 다른 자리만 | O(1) | O(D) | O(D) | 약 8ms | 약 20ms | 기본 답. 장부 하나로 끝난다 |
| 같은 세로줄만 | O(1) | O(한 줄의 자리 수) | O(D) | 약 3~8ms | 약 1ms | 점이 넓게 흩어질 때. 한 줄에 몰리면 느려진다 |
| 변 길이를 대 보기 | O(1) | O(좌표 범위) | O(좌표 범위²) | 약 35ms | 약 55ms | 좌표 범위가 작고 시간이 일정해야 할 때 |

흩뿌림에서 서로 다른 자리 풀이가 목록 풀이보다 느린 건 정수 키를 다시 좌표로 나누는 계산이 더 들어서로 보인다. 그 경우 대각선 후보가 거의 없어 둘 다 사실상 "전부 훑고 버리기"다. 차수로는 D ≤ N이라 서로 다른 자리 풀이가 나쁠 일이 없다.

## 넓이 0과 중복에서 틀린다

### 넓이 0을 거르지 않는다

```js
if (Math.abs(dx - qx) !== Math.abs(dy - qy)) continue;   // dx === qx 검사가 없다
```

질문 점과 같은 자리에 저장된 점이 있으면 x 차이 0, y 차이 0으로 통과한다. 나머지 두 자리도 질문 점 자신이라 그 자리의 개수를 세 번 곱한다. (3, 3)에 점 세 개를 넣고 (3, 3)을 물으면 정답 0 대신 3 × 3 × 3 = 27이 나온다.

### 질문 점을 장부에 넣는다

`count` 안에서 질문 점을 `add`해 버리거나, 질문 점이 저장된 점이라고 개수를 하나 빼는 코드가 있다. 둘 다 필요 없다. 질문 점은 장부와 별개로 한 모서리를 맡고, 장부에서는 나머지 세 모서리만 고른다. (0, 0), (0, 2), (2, 0), (2, 2)를 저장하고 (0, 0)을 물으면 답은 1이다. 저장된 (0, 0)은 이 정사각형의 대각선 후보가 될 수 없어서(차이 0) 자연스럽게 빠진다.

### 세로줄 풀이에서 한쪽만 본다

`qx + d`만 보면 위쪽 점은 오른쪽으로, 아래쪽 점은 왼쪽으로만 정사각형을 찾는다. 앞의 예시 (4, 4)는 정사각형이 둘 다 왼쪽 아래라 우연히 3이 맞게 나와서 버그가 숨는다. (3,3), (3,5), (5,3), (7,7), (7,5), (5,7), (3,7)을 넣고 (5,5)를 물으면 정답은 3인데, 한쪽만 보면 왼쪽 위 정사각형을 놓쳐 2가 나온다. d가 음수든 양수든 `qx + d`와 `qx - d`를 둘 다 더한다.

### 좌표 키가 겹친다

`x * 1000 + y`로 쓰면 (0, 1000)과 (1, 0)이 둘 다 1000이 된다. y가 0~1000으로 1001가지라 1001 이상을 곱해야 한다. 좌표 범위가 바뀌면 이 수도 같이 바꿔야 해서, 범위를 모르면 문자열 키나 튜플 키가 안전하다.

## 모양과 조건을 바꾸면

### 직사각형을 세라면

정사각형은 대각선 하나로 정해졌지만 직사각형은 가로와 세로 길이가 달라도 된다. 그래서 "x 차이와 y 차이가 같다"는 조건만 빼면 된다. 대각선 후보가 x도 y도 질문 점과 다른 모든 점으로 늘어나고, 나머지 계산은 같다. 점 집합에서 가장 작은 직사각형 넓이를 구하는 939. Minimum Area Rectangle이 이 생각을 쓴다.

### 축에 나란하지 않은 정사각형까지라면

기울어진 정사각형은 대각선 두 끝 (x1, y1), (x2, y2)에서 나머지 두 끝을 벡터 회전으로 구한다. 중심 (cx, cy)에서 한 끝까지의 벡터 (a, b)를 90도 돌린 (-b, a)를 더하고 빼면 다른 두 끝이다. 좌표가 정수가 아닐 수 있으니 모든 좌표를 2배해서 다루는 게 흔한 요령이다. 점 쌍마다 이렇게 하면 O(N²)이다. 963. Minimum Area Rectangle II가 비슷한 문제다.

### 점을 지울 수도 있다면

장부의 개수를 하나 줄이면 끝이다. 개수가 0이 되면 키를 지워야 서로 다른 자리 풀이가 빈 자리를 훑지 않는다. 세로줄 풀이라면 그 줄의 맵에서도 지운다. 목록 풀이는 배열에서 지우는 게 O(N)이라 불리하다.

### 좌표 범위가 10^9라면

배열 풀이는 버린다. 정수 키는 `x * (범위 + 1) + y`가 10^18이 되어 JavaScript `Number`의 정밀도를 넘으니 문자열 키를 쓰거나, Java라면 `long` 키를 쓴다. 해시맵 풀이들은 범위와 상관없이 그대로 동작한다. 해시맵이 왜 범위가 아니라 들어온 개수에만 공간을 쓰는지는 [해시맵 글](/posts/ds-hash-map)에 있다.

### 비슷한 문제

- 같은 패턴의 [48. Rotate Image](/posts/leetcode-rotate-image)와 [54. Spiral Matrix](/posts/leetcode-spiral-matrix)도 좌표 계산을 정확히 하는 게 전부인 문제다.
- 939. Minimum Area Rectangle, 963. Minimum Area Rectangle II는 이 글의 대각선 아이디어를 직사각형으로 넓힌다.
- 149. Max Points on a Line은 점 쌍의 기울기를 해시맵 키로 세는 기하 + 해시 문제다.
- [Two Sum](/posts/leetcode-two-sum)은 "필요한 짝이 장부에 몇 개 있나"를 묻는 가장 단순한 형태다.

## 면접에서 나올 만한 질문

### 정사각형을 어떻게 셌나요?

질문 점과 x 차이, y 차이가 같고 0이 아닌 저장된 점을 대각선 끝으로 고른다. 축 정렬 정사각형은 대각선 두 끝이 정해지면 나머지 두 끝이 두 점의 x, y를 바꿔 조합한 자리로 정해진다. 그래서 대각선 후보마다 세 자리의 개수를 곱해 더하면 된다.

### 왜 개수를 곱하나요?

같은 자리에 점이 여러 개면 그중 하나를 고르는 방법이 그 개수만큼 있고, 세 자리의 선택은 서로 독립이기 때문이다. (1, 1)에 2개, (4, 1)에 1개, (1, 4)에 1개면 2 × 1 × 1 = 2가지 정사각형이 된다. 문제가 중복된 점을 서로 다른 점으로 친다고 했으니 이렇게 센다.

### add와 count의 복잡도는요?

장부에 개수를 더하는 `add`는 O(1)이다. `count`는 서로 다른 자리를 한 번씩 훑으니 O(D)이고 D는 저장된 점 수 이하다. 공간도 O(D)다. 질문 점과 같은 세로줄의 점만 훑으면 그 줄의 자리 수로 줄일 수 있지만, 점이 한 줄에 몰리면 이득이 없다.

### 넓이 0인 경우는 어떻게 거르나요?

대각선 후보의 x가 질문 점의 x와 같으면 건너뛴다. x 차이와 y 차이가 같다는 조건이 이미 있으니 x 차이가 0이면 y 차이도 0이라, 같은 자리 하나만 거르면 된다. 이 검사가 없으면 질문 점과 같은 자리의 점 개수를 세제곱한 값이 답에 섞인다.

### 해시맵 키는 무엇으로 했나요?

좌표가 0~1000이라 `x * 1001 + y`로 정수 키를 만들었다. 서로 다른 좌표가 같은 키가 되지 않고, 문자열을 만들지 않아도 된다. JavaScript와 Java는 배열을 키로 쓰면 값이 아니라 객체가 같은지를 보니 그대로 쓰면 안 되고, Python은 튜플이 그대로 키가 된다.

### add가 아주 많고 count가 드물다면 설계를 바꾸나요?

지금 설계가 이미 `add`를 O(1)로 두고 `count`에 일을 몰아 둔 형태라 그대로 맞다. 반대로 `count`가 압도적으로 많고 점이 적다면, `add`할 때 그 점이 만드는 정사각형 수를 관련 자리에 미리 더해 두는 식으로 일을 옮길 수 있다. 다만 새 점 하나가 바꾸는 답이 많아 `add`가 무거워지니, 호출 비율을 보고 고른다.

### Python에서 defaultdict를 쓰면 무엇이 문제인가요?

없는 키를 읽기만 해도 키가 새로 생긴다. 장부를 `items()`로 훑는 도중 나머지 두 자리를 `cnt[(qx, y)]`로 읽으면 반복 중에 딕셔너리 크기가 바뀌어 `RuntimeError`가 난다. `Counter`를 쓰거나 `get(key, 0)`으로 읽으면 키를 만들지 않는다.
