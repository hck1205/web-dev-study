## 문제

숫자들이 줄 서 있어요. 그중 **두 개를 더해서 목표 숫자(target)가 되는 짝**을 찾아서, 그 둘이 몇 번째 칸에 있는지 알려 주세요.

```text
숫자들: [2, 7, 11, 15]   목표: 9
답: [0, 1]   (0번 칸의 2 + 1번 칸의 7 = 9)
```

## 한 줄로 말하면

"지금 보는 숫자의 **짝이 될 숫자**가 이미 지나갔는지, 장부를 보고 바로 찾는다."

## 비유로 이해하기: 짝꿍 찾기 게임

반 친구들이 한 명씩 들어와요. 각자 번호표를 들고 있고, **번호표 두 개를 더해서 9**가 되면 짝꿍이에요.

친구가 들어올 때마다 이렇게 해요.

1. "너는 2번이구나. 짝꿍은 9 − 2 = **7번**이어야 해."
2. 장부를 봐요. "7번은 아직 안 왔네."
3. 장부에 "2번 친구는 0번째 자리"라고 적어 둬요.
4. 다음 친구는 7번. 짝꿍은 **2번**. 장부를 보니 있어요! 끝!

이 **장부**가 바로 해시맵이에요. 이름만 어렵지, "누가 어디 있는지 적어 둔 공책"이에요.

## 두 가지 방법 비교

| 방법 | 어떻게? | 얼마나 걸리나 |
|---|---|---|
| 무식하게 | 모든 짝을 하나하나 더해 봄 | 숫자가 많아질수록 **훨씬** 오래 걸림 `O(n²)` |
| 장부 사용 | 한 번 훑으면서 장부 확인 | 숫자 수에 **비례**해서만 걸림 `O(n)` |

<Callout kind="note" title="O(n)이 뭐예요?">
  "숫자가 n개일 때 일을 몇 번 하나"를 나타내는 표시예요. `O(n)`은 숫자가 10배 많아지면 일도 10배, `O(n²)`은 100배가 된다는 뜻이에요.
</Callout>

## 코드

```ts
function twoSum(nums: number[], target: number): [number, number] {
  const seen = new Map<number, number>(); // 장부: 숫자 → 칸 번호
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];        // 내 짝이 될 숫자
    const j = seen.get(need);             // 장부에 있나?
    if (j !== undefined) return [j, i];   // 있으면 정답!
    seen.set(nums[i], i);                 // 없으면 나를 장부에 적기
  }
  throw new Error("no solution");
}
```

## 헷갈리는 부분

<Callout kind="warning" title="장부에 적는 순서가 중요해요">
  **먼저 짝을 찾고, 그다음에 나를 적어야** 해요. 나를 먼저 적으면 `[5]`, 목표 `10`처럼 내가 나 자신과 짝이 되는 잘못된 답이 나올 수 있어요. 같은 칸은 두 번 쓸 수 없으니까요.
</Callout>

<details>
<summary>Q1. 왜 장부(해시맵)를 쓰면 빨라지나요?</summary>

"짝이 이미 지나갔나?"를 **처음부터 다시 훑지 않고** 한 번에 알아낼 수 있어서예요. 대신 기억할 공간을 조금 써요. 시간을 아끼려고 공간을 쓰는 거래(time–space trade-off)예요.

</details>

<details>
<summary>Q2. 숫자 [3, 3], 목표 6이면 답은?</summary>

`[0, 1]`이에요. 첫 번째 3을 볼 때는 장부가 비어 있어서 적기만 하고, 두 번째 3을 볼 때 장부에서 짝(3)을 찾아요.

</details>

<Callout kind="tip" title="12살 친구에게 설명한다면">
  "숫자를 한 명씩 만나면서, **'내 짝이 될 숫자가 이미 지나갔나?'** 를 공책에서 확인해. 있으면 끝이고, 없으면 나를 공책에 적고 다음 사람으로 넘어가."
</Callout>
