알고리즘 문제집을 펴면 대개 첫 장에 나오는 문제다. 쉬운 문제로 분류되지만, 여기서 쓰는 생각 하나가 뒤에 나오는 문제들에서 계속 반복된다. 그래서 풀이보다 그 생각을 기록해 두려고 한다.

## 문제

정수 배열 `nums`와 목표값 `target`이 주어진다. 더해서 `target`이 되는 두 수를 찾아 그 인덱스를 돌려준다. 답은 정확히 하나 있고, 같은 원소를 두 번 쓸 수는 없다.

```text
nums = [2, 7, 11, 15], target = 9
→ [0, 1]   (2 + 7 = 9)
```

## 처음 떠오르는 방법

모든 쌍을 더해 보면 된다. 첫 번째 수를 고정하고 나머지와 하나씩 더해 보고, 다음 수로 넘어가서 또 반복한다. 틀릴 일은 없지만 수가 n개면 쌍이 대략 n²/2개다. 수가 10배 늘면 일은 100배가 된다. 만 개만 돼도 5천만 번을 더해야 한다.

## 짝이 이미 지나갔는지 기억해 두기

다르게 생각해 보면, 지금 보고 있는 수가 2라면 필요한 짝은 정해져 있다. 9 − 2 = 7이다. 그러니 "7을 앞에서 본 적이 있나?"만 빠르게 확인하면 된다. 확인을 빠르게 하려면, 지나간 수를 "어떤 수가 몇 번 칸에 있었는지"로 적어 둔 장부가 있으면 된다. 그 장부가 해시맵이다.

배열을 한 번만 지나가니 시간은 O(n)이다. 대신 장부를 들고 다니느라 메모리를 O(n)만큼 더 쓴다. 시간을 아끼려고 공간을 쓰는 이런 맞바꿈은 앞으로도 자주 나온다.

```ts
function twoSum(nums: number[], target: number): [number, number] {
  const seen = new Map<number, number>(); // 수 → 칸 번호
  for (let i = 0; i < nums.length; i++) {
    const j = seen.get(target - nums[i]);
    if (j !== undefined) return [j, i];
    seen.set(nums[i], i);
  }
  throw new Error("no solution");
}
```

## 순서를 바꾸면 틀린다

루프 안에서 장부를 먼저 확인하고, 그다음에 적는다. 이 순서를 뒤집으면 `nums = [5]`, `target = 10` 같은 입력에서 5가 자기 자신과 짝을 지어 `[0, 0]`을 돌려준다. 같은 원소를 두 번 쓰면 안 된다는 조건을 어기게 된다. 처음 짤 때 가장 흔하게 하는 실수다.

중복된 수도 같은 이유로 자연스럽게 처리된다. `[3, 3]`에 `target = 6`이면, 첫 번째 3을 볼 때는 장부가 비어 있어 적기만 하고, 두 번째 3을 볼 때 장부에서 짝을 찾는다.

## 정리

"짝을 찾는" 문제는 지금 원소에 필요한 짝이 무엇인지 계산하고, 그 짝을 이미 봤는지 해시맵으로 확인하면 한 번의 순회로 풀린다. 부분 배열의 합, 두 수의 차 같은 문제에도 같은 틀이 그대로 쓰인다.
