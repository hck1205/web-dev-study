[Longest Increasing Subsequence](https://leetcode.com/problems/longest-increasing-subsequence/)는 LeetCode 300번이다. 줄여서 LIS라고 부른다. [동적 계획법 글](/posts/dynamic-programming)에서 O(n²) 풀이와 tails 배열 + 이분 탐색 풀이를 짧게 보였고, n이 커질 때 두 방법의 시간 차이도 그 글에서 쟀다. 이 글은 거기서 넘어간 질문들을 판다. tails가 왜 맞는지, 실제 수열은 어떻게 꺼내는지, 같은 값이 있으면 무엇이 달라지는지, 다른 길(펜윅 트리, LCS로 바꾸기)은 무엇인지, 그리고 2차원으로 넓힌 문제까지.

1차원 DP 시리즈의 앞 글들([계단 오르기](/posts/leetcode-climbing-stairs), [House Robber](/posts/leetcode-house-robber), [Coin Change](/posts/leetcode-coin-change), [Word Break](/posts/leetcode-word-break))은 "바로 앞 몇 칸"이나 "정해진 거리만큼 앞"을 봤다. LIS는 처음으로 "앞의 모든 칸"을 본다. 그래서 기본 풀이가 O(n²)이고, 그걸 줄이는 데 DP 밖의 도구([이분 탐색](/posts/binary-search))가 필요하다. 코드는 Node.js 22, Python 3, Java 21에서 직접 돌렸다.

## 순서를 지키며 점점 커지게 고르기

정수 배열 `nums`가 주어진다. 원소 몇 개를 골라(순서는 유지, 건너뛰기 허용) 만든 수열이 엄격하게 증가할 때, 그 수열의 최대 길이를 돌려준다. 엄격하게 증가한다는 건 같은 값이 연달아 올 수 없다는 뜻이다. [7, 7, 7]의 답은 1이다.

용어 하나를 짚고 간다. 부분 수열(subsequence)은 건너뛰어도 되는 것, 부분 배열(subarray)은 붙어 있어야 하는 것이다. 이 문제는 부분 수열이다. 둘을 헷갈리면 "연속 증가 구간 중 가장 긴 것"을 구하게 되고, 그건 한 번 훑기로 끝나는 전혀 다른 쉬운 문제다.

제약은 길이 1 이상 2500 이하, 값 -10^4 이상 10^4 이하다. n이 2500이라 O(n²) = 625만이 넉넉히 들어간다. 그래서 LeetCode는 문제 끝에 "O(n log n)으로 풀 수 있나"를 따로 붙여 둔다. 면접에서도 O(n²)에서 멈추면 거의 항상 그 질문이 온다. 값이 음수일 수 있다는 건 "이전 값 없음"을 -1이나 0으로 표시하면 안 된다는 뜻이다.

## 여덟 장의 카드로 손으로 찾기

글 끝까지 쓸 예시다.

```text
인덱스   0   1   2   3   4   5   6   7
nums     3   1   8   2   5   9   4   6
```

눈으로 찾으면 1, 2, 5, 9 또는 1, 2, 4, 6 또는 1, 2, 5, 6이 길이 4다. 3으로 시작하면 3, 5, 9나 3, 4, 6처럼 3이 최대다. 답은 4다.

사람이 찾을 때는 무의식적으로 "1은 3보다 작으니 1로 시작하는 게 낫다", "2는 8보다 작으니 1 다음에 2를 두는 게 낫다"처럼 작은 값을 고른다. 이 직감이 뒤의 O(n log n) 풀이의 출발점이다. 하지만 작은 값만 고르는 탐욕은 틀린다. [1, 100, 2, 3]에서 1 다음 가장 가까운 큰 값 100을 바로 붙이면 길이 2로 끝나지만, 100을 건너뛰고 2, 3을 붙이면 3이다. 언제 바꿔 끼울지를 체계적으로 정해야 한다.

## 모든 부분 수열을 다 본다

원소마다 고르거나 안 고르거나라서 부분 수열은 2ⁿ개다. 각각이 증가하는지 확인하고 가장 긴 것을 고른다.

```js
function lengthOfLIS(nums) {
  const n = nums.length;
  let best = 0;
  for (let mask = 1; mask < (1 << n); mask++) {  // 비어 있지 않은 모든 고르기
    let last = -Infinity, len = 0, ok = true;
    for (let i = 0; i < n; i++) {
      if (!((mask >> i) & 1)) continue;
      if (nums[i] <= last) { ok = false; break; } // 증가가 깨졌다
      last = nums[i];
      len++;
    }
    if (ok) best = Math.max(best, len);
  }
  return best;
}
```

시간 O(2ⁿ × n), 공간 O(1)이다. n이 20을 넘으면 쓸 수 없고, `1 << n`이 32비트라 n이 31을 넘으면 그 자체로 틀린다. 뒤의 빠른 풀이를 검증하는 정답 생성기로만 쓴다. 길이 1~12인 무작위 배열 3000개로 이 풀이와 뒤의 모든 풀이를 비교했고 답이 모두 같았다.

## 고를지 말지를 재귀로 정한다

앞에서부터 원소를 보며 "넣을까 말까"를 정한다. 넣으려면 지금까지 마지막으로 넣은 값보다 커야 한다. 그래서 재귀 함수는 "지금 보는 위치 i"와 "마지막으로 넣은 원소의 위치 prev" 두 가지를 알아야 한다.

```js
function lengthOfLIS(nums) {
  function go(i, prev) {           // prev: 마지막으로 넣은 원소의 인덱스, 없으면 -1
    if (i === nums.length) return 0;
    let best = go(i + 1, prev);                        // nums[i]를 안 넣는다
    if (prev === -1 || nums[i] > nums[prev]) {
      best = Math.max(best, 1 + go(i + 1, i));         // nums[i]를 넣는다
    }
    return best;
  }
  return go(0, -1);
}
```

`prev`를 값이 아니라 인덱스로 둔 이유가 있다. 값으로 두면 "아직 아무것도 안 넣음"을 나타낼 값이 필요한데, 값의 범위가 음수까지라 -1이나 0을 쓸 수 없다. `-Infinity`를 써도 되지만, 다음 절에서 메모 표의 칸 번호로 쓰려면 인덱스가 편하다.

배열이 이미 증가하는 최악의 경우, 모든 원소에서 두 갈래가 다 살아 있어서 호출이 2^(n+1) - 1번이다.

```text
rec inc n 16 calls 131071 6.7ms
rec inc n 20 calls 2097151 43.0ms
rec inc n 24 calls 33554431 362.1ms
```

## (지금 위치, 마지막으로 고른 위치)를 적어 둔다

`go(i, prev)`의 답은 i와 prev에만 달려 있다. 가능한 쌍은 i가 n+1가지, prev가 n+1가지(-1 포함)라 O(n²)개다. 2차원 표에 적어 둔다.

```js
function lengthOfLIS(nums) {
  const n = nums.length;
  // memo[i][prev + 1]: i부터 볼 때, 마지막으로 고른 게 prev일 때의 최대 길이 (-1: 안 구함)
  const memo = Array.from({ length: n }, () => new Array(n + 1).fill(-1));
  function go(i, prev) {
    if (i === n) return 0;
    if (memo[i][prev + 1] !== -1) return memo[i][prev + 1];
    let best = go(i + 1, prev);
    if (prev === -1 || nums[i] > nums[prev]) best = Math.max(best, 1 + go(i + 1, i));
    return (memo[i][prev + 1] = best);
  }
  return go(0, -1);
}
```

`prev + 1`로 칸을 고르는 건 prev가 -1일 수 있어서다. 시간 O(n²), 공간 O(n²)이다. n = 2500이면 표가 625만 칸이라 메모리를 꽤 쓴다(JavaScript 배열 기준 수십 MB). 재귀 깊이는 n이라 2500단계다. Node.js 기본 스택에서는 이 깊이가 대개 버티지만, Python에서는 기본 재귀 한도 1000에 걸린다.

이 풀이는 틀린 건 아니지만 상태 하나에 정보를 너무 많이 담았다. 다음 풀이는 상태를 하나로 줄인다.

## 이 원소로 끝나는 가장 긴 줄

상태를 "`dp[i]`는 `nums[i]`로 끝나는 가장 긴 증가 수열의 길이"로 바꾼다. `nums[i]`로 끝나려면 그 앞 원소는 i보다 왼쪽에 있으면서 `nums[i]`보다 작아야 한다. 그런 j 중 `dp[j]`가 가장 큰 것에 `nums[i]`를 붙인다. 아무것도 없으면 `nums[i]` 혼자라 1이다.

```text
dp[i] = 1 + max(dp[j])   (j < i 이고 nums[j] < nums[i] 인 j들, 없으면 0)
답    = max(dp[0], …, dp[n-1])
```

답이 `dp[n-1]`이 아니라 전체 최댓값이라는 데 주의한다. 가장 긴 수열이 마지막 원소로 끝난다는 보장이 없다. 앞의 재귀가 "prev"라는 마지막 원소를 상태에 넣었던 걸, 이번에는 "끝나는 원소 = i"로 고정해서 상태 하나로 줄인 셈이다. 이 "끝을 고정하는" 상태 정의가 이 문제의 첫 번째 고비다.

```js
function lengthOfLIS(nums) {
  const n = nums.length;
  const dp = new Array(n).fill(1); // dp[i]: nums[i]로 끝나는 가장 긴 증가 수열의 길이
  let best = 1;
  for (let i = 1; i < n; i++) {
    for (let j = 0; j < i; j++) {
      // nums[j] 뒤에 nums[i]를 붙일 수 있으면 dp[j] + 1이 후보다
      if (nums[j] < nums[i] && dp[j] + 1 > dp[i]) dp[i] = dp[j] + 1;
    }
    best = Math.max(best, dp[i]);
  }
  return best;
}
```

### 실제 수열 꺼내기

dp를 채울 때 "누구 뒤에 붙었나"를 `parent[i] = j`로 적어 두면, dp가 최대인 칸에서 parent를 따라 거꾸로 가며 수열을 꺼낼 수 있다. 예시에서 dp가 처음 4가 되는 칸은 5번(9)이고 9 → 5 → 2 → 1을 따라가면 1, 2, 5, 9다. 마지막 칸 7번(6)에서 출발하면 1, 2, 5, 6이 나온다. 6은 j를 앞에서부터 보다가 4번 칸의 5에서 먼저 길이 4를 받았고, 6번 칸의 4도 같은 길이 4를 주지만 더 크지 않아서 부모가 바뀌지 않았다. 같은 길이의 답이 여럿일 때 어느 것을 꺼낼지는 동점 처리로 정해진다.

## 길이마다 가장 작은 끝값만 남긴다

안쪽 반복문을 없애는 생각은 이렇다. 같은 길이의 증가 수열이 여러 개 있으면, 그중 끝값이 가장 작은 것만 기억하면 된다. 길이 2짜리 수열로 [1, 8]과 [1, 2]가 있다면, 뒤에 무엇이 오든 [1, 2]에 붙일 수 있는 값은 [1, 8]에도 붙일 수 있고 그 반대는 아니다. 끝값 8은 2보다 손해만 본다.

그래서 `tails[k]`를 "길이 k+1인 증가 수열이 끝날 수 있는 가장 작은 값"으로 둔다. 새 값 x가 오면

- x가 `tails`의 모든 값보다 크면, 가장 긴 수열 뒤에 x를 붙여 길이가 하나 는다. 맨 뒤에 추가한다.
- 아니면 x 이상인 첫 칸 k를 찾아 `tails[k] = x`로 바꾼다. 길이 k인 수열(끝값 `tails[k-1]`이 x보다 작다) 뒤에 x를 붙이면 길이 k+1이 되고, 끝값이 원래보다 작거나 같아진다.

```js
function lengthOfLIS(nums) {
  const tails = []; // tails[k]: 길이 k+1인 증가 수열의 가장 작은 끝값
  for (const x of nums) {
    // x 이상인 첫 자리를 찾는다 (lower bound)
    let lo = 0, hi = tails.length;
    while (lo < hi) {
      const mid = (lo + hi) >>> 1;
      if (tails[mid] < x) lo = mid + 1;
      else hi = mid;
    }
    tails[lo] = x; // lo가 끝이면 뒤에 붙고, 아니면 그 칸을 더 작은 값으로 바꾼다
  }
  return tails.length;
}
```

`tails`는 항상 엄격하게 증가한다. 길이 k+1인 수열의 끝값은, 그 수열의 앞 k개가 길이 k인 수열이니 `tails[k-1]`보다 커야 하기 때문이다. 정렬돼 있으니 x가 들어갈 자리를 이분 탐색으로 찾는다. 원소마다 O(log n)이라 전체 O(n log n), 공간 O(n)이다.

마지막 `tails`는 [1, 2, 4, 6]이다. 이번에는 우연히 실제 증가 수열이지만 늘 그렇지는 않다. 예를 들어 [3, 4, 1]이면 마지막 `tails`가 [1, 4]인데, 1은 4보다 뒤에 있어서 1, 4는 부분 수열이 아니다. `tails`의 길이만 믿을 수 있고 내용은 여러 수열의 끝값이 섞인 것이다. 면접에서 "tails가 답 수열인가요?"라고 물으면 아니라고 답한다.

### 왜 길이가 맞는지

두 가지를 보이면 된다. 하나, `tails`의 길이가 L이면 길이 L인 증가 수열이 실제로 있다. `tails[L-1]`을 마지막으로 바꾼(또는 붙인) 순간, 그 값은 길이 L-1인 수열 뒤에 붙었다. 그 수열도 같은 방식으로 실제로 존재하니, 거꾸로 따라가면 길이 L인 수열이 나온다. 둘, 길이 L+1인 증가 수열은 없다. 그런 수열이 있다면 그 수열의 원소를 차례로 넣을 때 각 원소가 이전 원소보다 오른쪽 칸(또는 같은 칸보다 뒤)에 들어가야 해서 칸이 L+1개 생겨야 한다. 수열의 j번째 원소는 항상 j-1번 칸 이후에 들어간다는 걸 귀납으로 보이면 된다.

카드 더미로 말하면 이렇다. 증가하는 수열의 카드는 서로 같은 더미에 들어갈 수 없다(같은 더미는 위로 갈수록 작거나 같으니까). 그래서 증가 수열의 길이는 더미 수를 넘지 못한다. 반대로 더미 수만큼 긴 증가 수열은 각 더미에서 하나씩 뽑아 실제로 만들 수 있다. 이 카드 놀이를 페이션스 정렬(patience sorting)이라고 부른다.

### 이분 탐색 없이 같은 생각을 쓰면

`tails`에서 자리를 앞에서부터 선형으로 찾아도 답은 맞다. 다만 원소마다 O(n)이라 O(n²)으로 돌아간다. 이 풀이의 속도는 전부 `tails`가 정렬돼 있다는 성질에서 나온다. 이분 탐색의 lower bound를 정확히 쓰는 법은 [이분 탐색 글](/posts/binary-search)과 [Binary Search 문제 글](/posts/leetcode-binary-search)에 있다.

### tails로 실제 수열까지 꺼내기

`tails`에 값 대신 인덱스를 넣고, 원소를 놓을 때마다 "바로 왼쪽 칸에 있던 원소"를 부모로 적는다.

```js
function lisSequence(nums) {
  const tailsIdx = [];                       // tailsIdx[k]: 길이 k+1의 가장 작은 끝값이 있는 인덱스
  const parent = new Array(nums.length).fill(-1);
  for (let i = 0; i < nums.length; i++) {
    const x = nums[i];
    let lo = 0, hi = tailsIdx.length;
    while (lo < hi) {
      const mid = (lo + hi) >>> 1;
      if (nums[tailsIdx[mid]] < x) lo = mid + 1;
      else hi = mid;
    }
    if (lo > 0) parent[i] = tailsIdx[lo - 1]; // 길이 lo인 수열 뒤에 붙었다
    tailsIdx[lo] = i;
  }
  const seq = [];
  for (let k = tailsIdx[tailsIdx.length - 1]; k !== -1; k = parent[k]) seq.push(nums[k]);
  return seq.reverse();
}
```

예시에서 `[1, 2, 4, 6]`, [0, 1, 0, 3, 2, 3]에서 `[0, 1, 2, 3]`이 나왔다. 부모는 "놓는 순간"의 왼쪽 칸이라 나중에 그 칸이 바뀌어도 이미 적힌 부모는 그대로다. 그래서 `tails` 내용이 섞여도 부모 사슬은 실제 부분 수열이다. 시간 O(n log n), 공간 O(n)이다.

## 값 순서대로 최댓값을 묻는 나무

O(n²) 풀이의 안쪽 반복문은 "nums[i]보다 작은 값으로 끝나는 dp 중 최댓값"을 구했다. 값을 좌표로 보면 이건 구간 최댓값 질의다. 값 축 위에 "이 값으로 끝나는 최장 길이"를 적어 두고, `[가장 작은 값, nums[i] - 1]` 구간의 최댓값을 묻는다. 펜윅 트리(Fenwick tree, Binary Indexed Tree)나 세그먼트 트리가 이걸 O(log n)에 한다.

```js
function lengthOfLIS(nums) {
  // 값을 1부터 시작하는 순위로 바꾼다 (좌표 압축)
  const sorted = [...new Set(nums)].sort((a, b) => a - b);
  const rank = new Map(sorted.map((v, i) => [v, i + 1]));
  const m = sorted.length;
  const bit = new Array(m + 1).fill(0);  // bit: 순위 구간별 최장 길이의 최댓값
  const query = (i) => {                 // 순위 1..i 중 최댓값
    let r = 0;
    for (; i > 0; i -= i & -i) r = Math.max(r, bit[i]);
    return r;
  };
  const update = (i, v) => {             // 순위 i에 길이 v를 반영
    for (; i <= m; i += i & -i) bit[i] = Math.max(bit[i], v);
  };
  let best = 0;
  for (const x of nums) {
    const r = rank.get(x);
    const len = query(r - 1) + 1;        // x보다 작은 값으로 끝나는 최장 길이 + 1
    update(r, len);
    best = Math.max(best, len);
  }
  return best;
}
```

`query(r - 1)`로 "엄격하게 작은" 값만 본다. 같은 값도 허용하는 비감소 버전이면 `query(r)`로 바꾸면 된다. 시간은 정렬 O(n log n)과 질의·갱신 O(n log n)이라 O(n log n), 공간 O(n)이다. 값의 범위가 -10^4~10^4로 좁으니 압축 없이 값 + 10001을 바로 순위로 써도 된다.

`tails` 풀이보다 코드가 길지만 쓸모가 따로 있다. "길이"가 아니라 "합"을 최대로 하는 증가 부분 수열(최대 합 증가 부분 수열)이나, 최장 길이의 "개수"를 세는 문제(673번)를 O(n log n)으로 풀 때는 `tails`로는 안 되고 이 구간 질의 방식이 필요하다. 펜윅 트리의 `i & -i`는 가장 낮은 1비트를 뽑는 연산이다([비트 조작 글](/posts/bit-manipulation)).

## 정렬한 배열과의 최장 공통 부분 수열

전혀 다른 길도 있다. `nums`를 정렬하고 중복을 없앤 배열 `b`를 만든다. 그러면 `nums`의 증가 부분 수열은 정확히 `nums`와 `b`의 공통 부분 수열이다. `b`가 엄격하게 증가하니 `b`의 부분 수열은 모두 엄격한 증가 수열이고, 그게 `nums`에도 순서대로 있으면 LIS 후보다. 그래서 LIS = LCS(`nums`, `b`)다.

```js
function lengthOfLIS(nums) {
  const b = [...new Set(nums)].sort((x, y) => x - y); // 정렬 + 중복 제거
  const n = nums.length, m = b.length;
  let prev = new Array(m + 1).fill(0);                // LCS 표의 이전 줄
  for (let i = 1; i <= n; i++) {
    const cur = new Array(m + 1).fill(0);
    for (let j = 1; j <= m; j++) {
      cur[j] = nums[i - 1] === b[j - 1] ? prev[j - 1] + 1 : Math.max(prev[j], cur[j - 1]);
    }
    prev = cur;
  }
  return prev[m];
}
```

시간 O(n × m), 공간 O(m)(두 줄만 쓴다)이다. O(n²) 풀이보다 빠르지 않으니 실전에서 고를 이유는 없다. 그래도 면접에서 "LIS를 다른 문제로 바꿀 수 있나"를 물으면 꺼낼 만하다. 거꾸로 LCS의 특수한 경우(한쪽 수열에 같은 값이 없을 때)는 LIS로 바꿔 O(n log n)에 풀 수 있다. LCS 자체는 [Longest Common Subsequence](/posts/leetcode-longest-common-subsequence)에서 다룬다.

## Python과 Java로 옮길 때

```python
from bisect import bisect_left
from typing import List

class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        tails = []                       # tails[k]: 길이 k+1인 증가 수열의 가장 작은 끝값
        for x in nums:
            k = bisect_left(tails, x)    # x 이상이 처음 나오는 자리
            if k == len(tails):
                tails.append(x)          # 가장 긴 수열 뒤에 붙는다
            else:
                tails[k] = x             # 같은 길이의 끝을 더 작게 바꾼다
        return len(tails)
```

Python은 표준 라이브러리 `bisect`가 lower bound(`bisect_left`)와 upper bound(`bisect_right`)를 바로 준다. 여기서 `bisect_right`를 쓰면 같은 값이 다른 칸을 차지해 [7, 7, 7, 7]에서 1이 아니라 4가 나온다. 실제로 돌려서 확인했다. Python에서 JavaScript처럼 `tails[k] = x`를 범위 밖 인덱스에 쓰면 `IndexError`라서 `append`를 따로 써야 한다.

```java
class Solution {
    public int lengthOfLIS(int[] nums) {
        int[] tails = new int[nums.length]; // tails[k]: 길이 k+1인 증가 수열의 가장 작은 끝값
        int size = 0;
        for (int x : nums) {
            int lo = 0, hi = size;          // [0, size)에서 x 이상이 처음 나오는 자리
            while (lo < hi) {
                int mid = (lo + hi) >>> 1;
                if (tails[mid] < x) lo = mid + 1;
                else hi = mid;
            }
            tails[lo] = x;
            if (lo == size) size++;         // 맨 뒤에 붙었으면 길이가 는다
        }
        return size;
    }
}
```

Java는 크기를 미리 n으로 잡은 배열에 `size`를 따로 둔다. `Arrays.binarySearch(tails, 0, size, x)`를 써도 이 문제에서는 맞는다. 찾으면 그 인덱스를, 못 찾으면 `-(삽입 위치) - 1`을 돌려주니 음수일 때 `-(i + 1)`로 바꾸면 된다. `tails`가 엄격하게 증가해서 같은 값이 둘 있을 수 없기 때문에 안전하다. 같은 값이 여러 개인 배열에서는 `binarySearch`가 그중 아무 인덱스나 돌려줄 수 있다고 문서에 적혀 있어서, 비감소 버전처럼 `tails`에 같은 값이 생기는 변형에서는 직접 짠 이분 탐색을 써야 한다. `(lo + hi) >>> 1`은 `lo + hi`가 `int`를 넘어도 맞는 가운데를 준다. 이 문제의 n으로는 넘칠 일이 없지만 습관으로 둔다.

## 틀리기 쉬운 자리

### 답을 dp[n-1]로 내는 경우

`dp[i]`는 i로 끝나는 길이다. 가장 긴 수열이 마지막 원소로 끝나지 않으면 틀린다. [1, 2, 3, 0]이면 `dp[3]`은 1이고 답은 3이다. 전체 최댓값을 따로 들고 다닌다.

### lower bound 대신 upper bound를 쓰는 경우

엄격한 증가에서 `tails[mid] <= x`로 비교하면(upper bound) 같은 값이 새 칸을 만든다. [7, 7, 7, 7]에서 4, [2, 2, 3, 3, 1, 4]에서 5가 나온다(답은 1과 3). 반대로 문제가 "감소하지 않는(같은 값 허용) 부분 수열"을 물으면 upper bound가 맞다. 예시 [3, 1, 8, 2, 5, 9, 4, 6]은 같은 값이 없어서 두 방식 모두 4라, 중복이 있는 테스트를 넣어야 이 버그가 잡힌다.

### tails를 답 수열로 내는 경우

앞에서 본 대로 [3, 4, 1]의 `tails`는 [1, 4]이고 이건 부분 수열이 아니다. 수열이 필요하면 부모 배열을 쓴다.

### 부분 배열로 착각하는 경우

연속 구간을 구하면 예시에서 2, 5, 9의 3이 나온다. 이 문제는 건너뛰기를 허용한다. LeetCode 674 Longest Continuous Increasing Subsequence가 연속 버전이고, 그건 한 번 훑으며 길이를 세면 끝난다.

## 면접관이 조건을 바꾸면

### 같은 값도 허용하라면 (비감소)

`tails` 풀이에서 lower bound를 upper bound로 바꾼다(`tails[mid] <= x`면 오른쪽으로). [2, 2, 3, 3, 1, 4]의 비감소 최장 길이는 5(2, 2, 3, 3, 4)다. O(n²) 풀이에서는 `nums[j] < nums[i]`를 `<=`로 바꾼다.

### 최장 증가 부분 수열의 개수를 세라면

LeetCode 673 Number of Longest Increasing Subsequence다. O(n²) 풀이에 `cnt[i]`(i로 끝나는 최장 수열의 개수)를 함께 둔다. `dp[j] + 1`이 `dp[i]`보다 크면 `cnt[i] = cnt[j]`로 바꾸고, 같으면 `cnt[i] += cnt[j]`로 더한다. 예시에서 1, 2, 5, 9 / 1, 2, 5, 6 / 1, 2, 4, 6의 3이 나온다. O(n log n)이 필요하면 펜윅 트리 칸에 (최장 길이, 개수) 쌍을 담는다.

```js
function countLIS(nums) {
  const n = nums.length;
  const len = new Array(n).fill(1); // len[i]: nums[i]로 끝나는 최장 길이
  const cnt = new Array(n).fill(1); // cnt[i]: 그 길이를 만드는 방법의 수
  for (let i = 0; i < n; i++) {
    for (let j = 0; j < i; j++) {
      if (nums[j] >= nums[i]) continue;
      if (len[j] + 1 > len[i]) { len[i] = len[j] + 1; cnt[i] = cnt[j]; } // 더 긴 길을 찾았다: 개수를 새로 시작
      else if (len[j] + 1 === len[i]) cnt[i] += cnt[j];                  // 같은 길이의 다른 길: 개수를 더한다
    }
  }
  const best = Math.max(...len);
  let total = 0;
  for (let i = 0; i < n; i++) if (len[i] === best) total += cnt[i]; // 최장 길이로 끝나는 칸을 모두 더한다
  return total;
}
```

예시에서 3, `[2, 2, 2]`에서 3(길이 1인 수열이 세 개), `[1, 3, 5, 4, 7]`에서 2가 나왔다. 마지막에 `cnt[i]`를 한 칸만 보지 않고 최장 길이인 칸을 모두 더해야 한다. 끝나는 원소가 다른 수열은 서로 다른 수열이기 때문이다. `tails` 풀이는 길이만 남기고 "어떤 길로 왔나"를 버리기 때문에 개수 세기로 넓힐 수 없다.

### 봉투를 겹겹이 넣으라면 (2차원)

LeetCode 354 Russian Doll Envelopes다. (너비, 높이) 둘 다 커야 안에 넣을 수 있다. 너비 오름차순으로 정렬하되 너비가 같으면 높이 내림차순으로 정렬하고, 높이만 놓고 LIS를 구한다. 같은 너비의 봉투끼리는 높이가 내림차순이라 증가 수열에 둘이 함께 들어갈 수 없어서, 너비가 같은 봉투를 잘못 겹치는 일이 막힌다. 정렬 비교자를 `(a, b) => a[0] - b[0] || b[1] - a[1]`로 쓰는 게 이 문제의 전부다.

```js
function maxEnvelopes(envelopes) {
  // 너비 오름차순, 같은 너비면 높이 내림차순
  const sorted = [...envelopes].sort((a, b) => a[0] - b[0] || b[1] - a[1]);
  const tails = [];
  for (const [, h] of sorted) {          // 높이만 보고 LIS
    let lo = 0, hi = tails.length;
    while (lo < hi) {
      const mid = (lo + hi) >>> 1;
      if (tails[mid] < h) lo = mid + 1;
      else hi = mid;
    }
    tails[lo] = h;
  }
  return tails.length;
}
```

봉투 `[[4, 5], [4, 6], [6, 7], [2, 3], [1, 1]]`이면 (1,1) → (2,3) → (4,5) → (6,7)로 4가 나온다. 같은 너비를 높이 오름차순으로 정렬하면 (4,5)와 (4,6)이 둘 다 들어가 5가 나왔다. 너비가 같은 두 봉투는 서로 넣을 수 없으니 틀린 답이다.

### 수열이 스트림으로 들어온다면

`tails` 풀이는 원소를 앞에서 한 번씩만 보고 `tails`만 들고 있으니 그대로 스트림에 쓸 수 있다. 메모리는 지금까지의 LIS 길이만큼이다. 실제 수열까지 필요하면 부모 배열 때문에 본 원소 수만큼 필요하다.

### 배열을 증가하게 만들려면 최소 몇 개를 지워야 하나

n에서 LIS 길이를 빼면 된다. 남길 수 있는 최대 개수가 LIS이기 때문이다. "산 모양"(증가 후 감소)으로 만들려면(LeetCode 1671) 각 위치에서 왼쪽 LIS와 오른쪽 LDS를 구해 더한다.

비슷한 문제로는 Number of Longest Increasing Subsequence(673), Russian Doll Envelopes(354), Increasing Triplet Subsequence(334, 길이 3이면 변수 두 개), Longest Continuous Increasing Subsequence(674), [Longest Common Subsequence](/posts/leetcode-longest-common-subsequence)가 있다.

## 면접에서 나올 만한 질문

### dp[i]를 왜 "i로 끝나는" 길이로 정의하나요?

다음 원소를 붙일 수 있는지 판단하려면 수열의 마지막 값을 알아야 하기 때문이다. "앞의 i개에서의 최장 길이"로 두면 그 수열이 어떤 값으로 끝나는지 몰라서 점화식이 안 나온다. 끝을 i로 고정하면 `nums[j] < nums[i]`인 j들의 dp에 1을 더하면 된다. 대신 답은 dp 전체의 최댓값이다.

### O(n log n) 풀이의 원리는 무엇인가요?

같은 길이의 증가 수열 중에서는 끝값이 작은 것만 남겨도 손해가 없다는 데서 출발한다. `tails[k]`에 길이 k+1의 가장 작은 끝값을 두면 이 배열은 항상 증가하고, 새 값은 lower bound 자리를 덮어쓰거나 뒤에 붙는다. 원소마다 이분 탐색 한 번이라 O(n log n)이다.

### tails 배열이 실제 LIS인가요?

아니다. 길이만 맞다. [3, 4, 1]이면 마지막 `tails`가 [1, 4]인데 1이 4보다 뒤에 있어서 부분 수열이 아니다. 실제 수열이 필요하면 원소를 놓을 때 왼쪽 칸 원소를 부모로 적고, 마지막 칸에서 부모를 따라 거꾸로 꺼낸다.

### 같은 값이 있으면 무엇을 조심하나요?

엄격한 증가인지 비감소인지에 따라 이분 탐색이 달라진다. 엄격한 증가는 lower bound, 비감소는 upper bound다. 엄격한 증가에 upper bound를 쓰면 [7, 7, 7, 7]에서 4가 나온다. 같은 값이 없는 테스트로는 이 버그가 안 잡힌다.

### 이분 탐색 말고 O(n log n)으로 푸는 방법이 있나요?

값을 좌표 압축하고 펜윅 트리나 세그먼트 트리로 "x보다 작은 값으로 끝나는 최장 길이"를 구간 최댓값으로 묻는다. 시간은 같지만, 길이 대신 합을 최대로 하거나 최장 수열의 개수를 셀 때도 그대로 쓸 수 있어서 쓸모가 더 넓다.

### 2차원(봉투 겹치기)으로 바꾸면 어떻게 푸나요?

한 축으로 정렬하고 다른 축으로 LIS를 구한다. 너비 오름차순, 같은 너비면 높이 내림차순으로 정렬해야 같은 너비끼리 겹치는 걸 막는다. 그 뒤 높이 배열에 O(n log n) LIS를 쓰면 된다.

### 원소 몇 개를 지워야 배열이 증가하나요?

n에서 LIS 길이를 뺀 값이다. 남길 수 있는 원소의 최대 개수가 LIS 길이라서, 나머지를 지우면 된다. 비감소로 만들려면 비감소 LIS를 쓴다.
