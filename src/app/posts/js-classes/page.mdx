UI 위젯 기본 클래스가 생성자에서 `render()`를 부르게 만들었다. 하위 클래스는 필드에 텍스트를 두고 `render`를 덮어쓴다. 그런데 화면에 `undefined`가 찍힌다.

```js
class Widget {
  constructor() {
    this.render();
  }
  render() {}
}
class Label extends Widget {
  text = "hello";
  render() {
    console.log("render text:", this.text);
  }
}
const l = new Label();
console.log("after constructor:", l.text);

class SecretLabel extends Widget {
  #text = "hello";
  render() {
    console.log("render #text:", this.#text);
  }
}
try { new SecretLabel(); } catch (e) { console.log(e.constructor.name + ": " + e.message); }
```

Node.js 22에서 돌린 출력이다.

```text
render text: undefined
after constructor: hello
TypeError: Cannot read private member #text from an object whose class did not declare it
```

생성이 끝난 뒤에는 `text`가 `"hello"`인데, 생성 도중에 불린 `render`는 `undefined`를 봤다. 같은 값을 `#text`로 숨겼더니 이번에는 아예 에러가 났다. 필드가 언제 생기는지를 몰라서 생긴 일이다.

이 글은 `class` 문법이 실제로 무엇을 만드는지, 상속받은 객체가 어떤 순서로 만들어지는지, `super`, `static`, `#private`가 각각 어디에 붙는지를 따라간다. 출력은 Node.js 22에서 실제로 돌린 결과다.

이 주제의 다른 글: 클래스 아래에 깔린 연결 구조는 [프로토타입 체인](/posts/js-prototype-chain)에, 메서드를 콜백으로 넘길 때 `this`가 사라지는 이야기는 [this 바인딩](/posts/js-this-binding)에 있다. 상속 대신 합성을 고르는 기준은 [디자인 패턴 개요](/posts/design-patterns-overview)에서 다룬다.

## 클래스를 벗기면 함수와 프로토타입이 나온다

ES2015의 `class`는 새로운 객체 모델이 아니다. 생성자 함수와 그 `prototype` 객체를 만드는 문법이다.

```js
class User {
  constructor(name) { this.name = name; }
  hello() { return `hi ${this.name}`; }
}
console.log(typeof User, Object.getOwnPropertyNames(User.prototype));
```

```text
function [ 'constructor', 'hello' ]
```

`User`는 함수이고, `hello`는 `User.prototype`에 들어갔다. `new User("kim")`으로 만든 객체의 `[[Prototype]]`이 `User.prototype`이니 `hello`를 찾을 수 있다. 여기까지는 ES5에서 `function User() {}`와 `User.prototype.hello = ...`로 하던 일과 같다.

선언 한 줄을 조각으로 나눠 보면 각 부분이 어디에 붙는지 보인다.

## 함수 생성자와 다른 점

설탕이라고 해서 완전히 같지는 않다. 클래스는 실수하기 쉬운 부분을 엔진이 막는다.

```js
console.log(Object.keys(User.prototype), Object.getOwnPropertyDescriptor(User.prototype, "hello").enumerable);
try { User("kim"); } catch (e) { console.log(e.constructor.name + ": " + e.message); }
try { new Early(); } catch (e) { console.log(e.constructor.name + ": " + e.message); }
class Early {}
function OldUser(name) { this.name = name; }
OldUser.prototype.hello = function () { return `hi ${this.name}`; };
console.log(Object.keys(OldUser.prototype));
```

```text
[] false
TypeError: Class constructor User cannot be invoked without 'new'
ReferenceError: Cannot access 'Early' before initialization
[ 'hello' ]
```

클래스 메서드는 열거되지 않아서 `for...in`에 끼어들지 않는다. 손으로 `prototype`에 대입한 `OldUser`의 메서드는 열거된다. `new` 없이 부르면 막힌다. 함수 생성자는 `new`를 빼먹으면 `this`가 전역 객체가 되어 전역 변수를 만들며 조용히 지나갔다. 클래스 선언은 `let`처럼 TDZ가 있어서 선언 전에 쓸 수 없다([호이스팅과 TDZ](/posts/js-hoisting-tdz)). 그리고 클래스 본문은 항상 엄격 모드다. 메서드를 떼어 부르면 `this`가 전역 객체가 아니라 `undefined`가 되는 이유다.

## 필드는 인스턴스에, 메서드는 프로토타입에

ES2022에 표준이 된 클래스 필드는 메서드와 사는 곳이 다르다. 필드는 객체가 만들어질 때마다 그 객체의 자기 속성으로 생긴다. 메서드는 프로토타입에 하나만 있다. 이 차이는 화살표 함수를 필드로 둘 때 드러난다.

```js
class WithMethod { handle() {} }
class WithArrow { handle = () => {}; }
const a1 = new WithMethod(), a2 = new WithMethod();
const b1 = new WithArrow(), b2 = new WithArrow();
console.log("method shared:", a1.handle === a2.handle, "arrow shared:", b1.handle === b2.handle);
console.log("on prototype:", "handle" in WithArrow.prototype, Object.keys(b1));
```

```text
method shared: true arrow shared: false
on prototype: false [ 'handle' ]
```

화살표 필드는 `this`가 인스턴스에 고정되어 콜백으로 넘기기 편하지만, 인스턴스마다 함수가 새로 생기고 프로토타입에 없으니 하위 클래스에서 `super.handle()`로 부를 수 없다. 화살표 함수의 `this` 규칙은 [함수 선언문, 표현식, 화살표 함수](/posts/js-function-forms)에 있다. 수가 적은 UI 객체라면 편의를 택해도 되고, 수만 개를 만드는 데이터 객체라면 일반 메서드가 낫다.

## 하위 클래스는 부모가 먼저 만든다

처음 `Label` 버그로 돌아간다. 하위 클래스(`extends`가 있는 클래스)의 생성자는 객체를 직접 만들지 않는다. `super()`를 불러 부모에게 맡기고, 부모가 돌려준 객체를 `this`로 받는다. 그래서 `super()` 전에는 `this`가 아직 없다.

```js
class Base { constructor() { this.a = 1; } }
class Derived extends Base {
  constructor() {
    try { this.b = 2; } catch (e) { console.log(e.constructor.name + ": " + e.message); }
    super();
    this.b = 2;
  }
}
console.log(new Derived());
```

```text
ReferenceError: Must call super constructor in derived class before accessing 'this' or returning from derived constructor
Derived { a: 1, b: 2 }
```

필드는 이 흐름의 어디에 끼어들까. 기본 클래스(부모가 없는 클래스)의 필드는 생성자 본문이 시작되기 직전에, 하위 클래스의 필드는 `super()`가 돌아온 직후에 붙는다. 아래 그림에서 `new Label()`의 순서를 따라가 보면 `render`가 왜 `undefined`를 봤는지 보인다.

## super가 찾아가는 곳

`super.speak()`는 "내 부모 클래스의 speak"처럼 보이지만, 엔진은 클래스 이름을 보지 않는다. 메서드가 정의될 때 자기가 속한 객체(`Dog.prototype`)를 `[[HomeObject]]`라는 슬롯에 기록해 두고, `super`를 만나면 그 객체의 `[[Prototype]]`에서 찾는다.

```js
class Animal {
  speak() { return "...";}
}
class Dog extends Animal {
  speak() { return "woof / parent said " + super.speak(); }
}
const robot = { speak() { return "beep"; } };
const borrowed = { speak: Dog.prototype.speak };
Object.setPrototypeOf(borrowed, robot);
console.log(borrowed.speak());
```

```text
woof / parent said ...
```

`borrowed`의 프로토타입은 `robot`인데도 `super.speak()`는 `robot`의 `beep`이 아니라 `Animal`의 `...`을 불렀다. `this`는 호출할 때 정해지지만, `super`는 정의할 때 정해진다는 뜻이다.

```js

  static registry = [];
  static create(data) { const m = new this(data); this.registry.push(m); return m; }

}

```

```text

```

`Post.create`는 `Post` 자신에게 없고 `Model`에서 찾았다. 그런데 안의 `this`는 `Post`다. 정적 메서드도 점 앞의 객체가 `this`라서다. 그래서 `new this(data)`가 `Post` 인스턴스를 만들고, `this.registry`는 `Post`가 따로 선언한 배열을 가리킨다. `Post`에 `registry`를 다시 선언하지 않았다면 `Model.registry`를 함께 썼을 것이다. 앞의 [프로토타입에 둔 배열](/posts/js-prototype-chain#프로토타입에-둔-배열은-모두가-같이-쓴다)과 같은 공유 문제다. `static { }` 블록(ES2022)은 클래스가 정의될 때 한 번 도는 초기화 코드다.

## 정말로 숨기는 #private

`#`으로 시작하는 필드와 메서드(ES2022)는 이름 규칙이 아니라 엔진이 지키는 접근 제한이다. 객체의 일반 속성이 아니라 따로 붙은 칸에 들어가서, 키 목록에도 JSON에도 전개에도 나오지 않는다.

```js
class Account {
  #balance = 0;
  static isAccount(x) { return #balance in x; }
  deposit(n) { this.#balance += n; return this.#balance; }
  get balance() { return this.#balance; }
}
const acc = new Account();
acc.deposit(100);
console.log(acc.balance, Object.keys(acc), JSON.stringify(acc), { ...acc });
console.log(Account.isAccount(acc), Account.isAccount({ balance: 100 }));
const proxied = new Proxy(acc, {});
try { proxied.deposit(1); } catch (e) { console.log("proxy:", e.constructor.name + ": " + e.message); }
try { Account.prototype.deposit.call({}, 1); } catch (e) { console.log("borrow:", e.constructor.name + ": " + e.message); }
```

```text
100 [] {} {}
true false
proxy: TypeError: Cannot read private member #balance from an object whose class did not declare it
borrow: TypeError: Cannot read private member #balance from an object whose class did not declare it
```

`#balance in x`는 "이 객체가 이 클래스의 생성자를 거쳐 만들어졌나"를 묻는 브랜드 검사다. `instanceof`와 달리 프로토타입을 바꿔 속일 수 없다. 대신 숨긴 정도가 강해서 생기는 부작용이 있다. 객체를 `Proxy`로 감싸면 메서드 안의 `this`가 프록시가 되는데, 프록시에는 그 칸이 없어서 `TypeError`가 난다. 상태 객체를 프록시로 감싸 변경을 추적하는 라이브러리와 섞어 쓸 때 이 에러를 만난다. 하위 클래스도 부모의 `#` 필드에 닿을 수 없다. 이건 실행할 때가 아니라 파싱할 때 막힌다.

```js
class Account { #balance = 0; }
class Savings extends Account {
  peek() { return this.#balance; }
}
```

```text
SyntaxError: Private field '#balance' must be declared in an enclosing class
```

하위 클래스가 써야 하는 값이라면 `protected` 같은 것이 자바스크립트에 없으니, 부모에 getter나 메서드를 두어 열어 준다.

타입스크립트의 `private` 키워드와는 다르다. 타입스크립트 5.9로 변환해 돌렸다.

```text
TS private keys: [ 'balance' ] 100
```

`private balance`는 컴파일할 때만 막고, 실행 중에는 평범한 속성이라 `Object.keys`에도 나오고 `(a as any).balance`로 읽힌다. 로그나 API 응답으로 값이 새지 않아야 한다면 `#`을 쓴다.

## 필드 선언은 대입이 아니다

부모에 setter가 있고 하위 클래스가 같은 이름의 필드를 선언하면 어떻게 될까.

```js
class Base {
  set value(v) { console.log("Base setter called with", v); this._v = v; }
  get value() { return this._v; }
}
class Child extends Base {
  value = 1;
}
const c = new Child();
console.log("own value:", Object.getOwnPropertyDescriptor(c, "value"), "_v:", c._v);
```

```text
own value: { value: 1, writable: true, enumerable: true, configurable: true } _v: undefined
```

부모의 setter는 불리지 않았다. 표준 클래스 필드는 `this.value = 1` 같은 대입이 아니라 `Object.defineProperty`와 같은 정의라서, 체인 위의 setter를 무시하고 자기 속성을 만든다. [프로토타입 체인](/posts/js-prototype-chain#읽을-때는-올라가고-쓸-때는-올라가지-않는다)에서 본 대입과 정의의 차이다.

이게 실무에서 문제가 되는 곳이 타입스크립트다. 예전 타입스크립트는 필드를 생성자 안의 대입으로 바꿔 출력했다. `useDefineForClassFields`의 기본값은 `target`이 ES2022 이상(또는 ESNext)이면 `true`라서, `target`만 올려도 동작이 바뀐다. 같은 코드를 두 target으로 변환해 돌린 결과다.

```text
== target ES2017 (useDefineForClassFields default)
Base setter called with 1
== target ES2022 (useDefineForClassFields default)
```

ES2017로 출력하면 setter가 불리고, ES2022로 출력하면 불리지 않는다. 데코레이터나 부모 setter에 기대던 코드(옛 MobX의 `@observable` 필드 같은 것)가 `target` 변경 뒤 반응을 멈추는 이유가 이것이다. 필드에 초깃값을 주지 않고 타입만 선언했는데 부모가 생성자에서 넣은 값이 `undefined`로 덮이는 증상도 같은 원인이다. 그런 필드는 `declare value: number;`로 선언만 하면 출력에서 빠진다.

## 내장 객체 상속하기

`Error`, `Array`, `Map` 같은 내장 객체도 `extends`로 상속할 수 있다. ES5 시절의 함수 생성자로는 제대로 안 되던 일이다.

```js
class HttpError extends Error {
  constructor(status, message, options) {
    super(message, options);
    this.name = "HttpError";
    this.status = status;
  }
}
try {
  try { JSON.parse("{"); } catch (cause) { throw new HttpError(400, "bad body", { cause }); }
} catch (e) {
  console.log(e instanceof HttpError, e instanceof Error, e.name, e.status);
  console.log(String(e), "| cause:", e.cause.constructor.name);
  console.log(e.stack.split("\n")[0]);
}
class Stack extends Array {
  peek() { return this[this.length - 1]; }
}
const s = Stack.from([1, 2, 3]);
const doubled = s.map((x) => x * 2);
console.log(doubled instanceof Stack, doubled.peek(), Array.isArray(s));
```

```text
true true HttpError 400
HttpError: bad body | cause: SyntaxError
HttpError: bad body
true 6 true
```

에러 클래스에서는 `this.name`을 꼭 정한다. 안 하면 로그와 스택 첫 줄에 그냥 `Error`로 찍혀 구분이 안 된다. 두 번째 인자 `{ cause }`(ES2022)로 원래 에러를 감싸면 원인을 잃지 않는다. 배열을 상속하면 `map`, `filter`의 결과도 하위 클래스 인스턴스가 된다. `Symbol.species`라는 장치 때문인데, 이 동작이 엔진 최적화를 방해하고 예상 밖의 결과를 만든다는 이유로 TC39에서 없애자는 논의가 계속 나온다. 데이터를 담는 용도라면 배열을 상속하기보다 배열을 필드로 갖는 편이 단순하다.

## React에 남은 클래스

React는 함수 컴포넌트와 훅이 기본이 됐지만 클래스가 남은 자리가 하나 있다. 렌더링 중 에러를 잡는 에러 경계는 React 19에서도 클래스로만 만든다.

```js
class ErrorBoundary extends React.Component {
  state = { error: null };
  static getDerivedStateFromError(error) {
    return { error };
  }
  componentDidCatch(error, info) {
    reportError(error, info.componentStack);
  }
  render() {
    return this.state.error ? this.props.fallback : this.props.children;
  }
}
```

`getDerivedStateFromError`가 `static`인 이유는 React가 인스턴스 없이 에러에서 다음 상태만 계산하게 하려는 것이다. 그래서 그 안에서는 `this`를 쓸 수 없다. `state = {...}`는 앞에서 본 클래스 필드다. 직접 작성하기보다 `react-error-boundary` 같은 패키지를 쓰는 경우가 많은데, 그 안도 결국 이 모양의 클래스다. 클래스 컴포넌트에서 메서드를 핸들러로 넘길 때의 `this` 문제는 [this 바인딩](/posts/js-this-binding#react-클래스-컴포넌트에서-사라지던-this)에서 다뤘다.

## 연습: 계좌 클래스 만들기

`Account`와 `Savings`를 완성한다. 조건은 이렇다.

- 잔액은 `#balance`로 숨긴다. `Object.keys`에 아무것도 나오지 않아야 한다.
- `deposit(n)`, `withdraw(n)`은 바뀐 잔액을 돌려준다. 잔액보다 많이 빼면 `Error("insufficient funds")`를 던진다.
- `balance`는 getter다.
- `static from({ balance })`는 그 잔액으로 시작하는 인스턴스를 만든다. `Savings.from`은 `Savings`를 만들어야 한다.
- `Savings`는 `rate = 0.02` 필드를 갖고, `addInterest()`는 이자를 `super.deposit`으로 넣고 잔액을 돌려준다(소수점 이하는 버림).

## 문법 아래에서 일어나는 일

처음 `Label`은 클래스 문법이 감춘 순서 하나를 몰라서 틀렸다. 하위 클래스의 필드는 부모 생성자가 끝난 뒤에 붙는다. 클래스는 함수와 프로토타입을 만드는 문법이고, 그 위에 생성 순서, 정의할 때 정해지는 `super`, 두 줄의 체인을 타는 `static`, 엔진이 지키는 `#private`가 얹혀 있다. 클래스가 이상하게 동작하면 그 동작이 체인의 어느 쪽에서, 생성의 어느 순간에 일어나는지부터 본다.

## 면접에서 나올 만한 질문

### 자바스크립트의 클래스는 다른 언어의 클래스와 같은가요?

아니다. 생성자 함수와 `prototype` 객체를 만드는 문법이고, 상속은 프로토타입 체인으로 동작한다. 다만 단순한 설탕은 아니어서, `new` 없이 부르면 막히고, 메서드가 열거되지 않고, 본문이 항상 엄격 모드이며, 선언에 TDZ가 있다. `#private`와 필드처럼 함수 생성자로는 흉내 내기 어려운 기능도 있다.

### 하위 클래스 생성자에서 super()를 먼저 불러야 하는 이유는요?

하위 클래스는 객체를 직접 만들지 않고 부모 생성자가 만든 객체를 `this`로 받기 때문이다. `super()`가 끝나기 전에는 `this`가 초기화되지 않아 접근하면 `ReferenceError`가 난다. 이 구조 덕분에 `Error`나 `Array` 같은 내장 객체도 부모가 내부 슬롯을 갖춘 객체를 만들어 줄 수 있다.

### 부모 생성자에서 호출한 메서드가 하위 클래스 필드를 undefined로 보는 이유는요?

하위 클래스의 필드는 `super()`가 돌아온 직후에 초기화된다. 부모 생성자가 실행되는 동안 덮어쓴 메서드가 불리면 그 필드는 아직 없다. `#private` 필드라면 칸 자체가 없어서 `TypeError`가 난다. 부모 생성자에서는 덮어쓸 수 있는 메서드를 부르지 않고, 생성과 초기화를 나눈다.

### 메서드와 화살표 함수 필드의 차이는 무엇인가요?

메서드는 프로토타입에 하나만 있어 모든 인스턴스가 공유하고, `this`는 호출 방식으로 정해진다. 화살표 필드는 인스턴스마다 새 함수가 자기 속성으로 생기고 `this`가 인스턴스에 고정된다. 콜백으로 넘기기 편한 대신 메모리를 더 쓰고, 하위 클래스에서 `super`로 부를 수 없다.

### static 메서드는 어떻게 상속되나요?

`extends`가 하위 클래스 함수 자체의 `[[Prototype]]`을 부모 클래스로 이어서, 하위 클래스에 없는 정적 메서드를 부모에서 찾는다. 정적 메서드 안의 `this`는 호출한 클래스라서 `new this()`로 하위 클래스 인스턴스를 만들 수 있다. 정적 필드에 배열 같은 객체를 두면 하위 클래스가 다시 선언하지 않는 한 공유된다.

### #private와 TypeScript의 private은 무엇이 다른가요?

`#private`는 엔진이 실행 중에 막는 진짜 비공개라서 `Object.keys`, JSON, 전개에 나오지 않고 클래스 밖에서 읽으면 문법 에러다. TypeScript의 `private`은 컴파일할 때만 검사하고 실행 중에는 평범한 속성이다. 대신 `#private`는 `Proxy`로 감싼 객체에서 `TypeError`가 나고 하위 클래스에서도 접근할 수 없다.

### super.method()는 어떻게 부모 메서드를 찾나요?

메서드가 정의될 때 자기가 속한 객체를 `[[HomeObject]]`에 기록해 두고, `super`는 그 객체의 `[[Prototype]]`에서 찾는다. 그래서 `this`와 달리 정의할 때 정해지고, 메서드를 다른 객체로 옮겨도 원래 클래스의 부모를 부른다. 찾은 메서드는 지금의 `this`로 실행된다.

### TypeScript에서 target을 ES2022로 올렸더니 동작이 바뀌었습니다. 무엇을 의심하나요?

클래스 필드 시맨틱을 의심한다. `useDefineForClassFields`의 기본값이 ES2022 이상에서 `true`가 되어, 필드가 생성자 안의 대입이 아니라 `defineProperty` 정의로 바뀐다. 그러면 부모의 setter가 불리지 않고, 초깃값 없는 필드 선언이 부모가 넣은 값을 `undefined`로 덮는다. 타입만 필요한 필드는 `declare`로 선언하고, setter에 기대는 코드는 생성자에서 대입하도록 고친다.
