LeetCode 문제 목록의 2번이라 많은 사람이 두 번째로 푸는 문제다. 그런데 처음 풀 때 꽤 많은 사람이 리스트를 숫자로 바꿔 더하고 다시 리스트로 만든다. 예시는 다 통과하는데 제출하면 틀린다. 숫자가 100자리까지 나오기 때문이다.

[LeetCode 2. Add Two Numbers](https://leetcode.com/problems/add-two-numbers/)는 그래서 "큰 수를 자리별로 더하기"를 연결 리스트 위에서 하는 문제다. 숫자로 바꿔 더하기, 언어의 큰 정수 쓰기, 자리마다 더하고 올림 넘기기, 재귀, 입력 노드를 다시 쓰기까지 다섯 가지를 따라가고, 자릿수가 반대로 적힌 변형까지 본다. 연결 리스트가 처음이라면 [연결 리스트](/posts/ds-linked-list) 글을 먼저 보면 좋다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 거꾸로 적힌 두 수를 더한다

음이 아닌 정수 두 개가 연결 리스트로 주어진다. 각 노드에는 숫자 한 자리(0~9)가 들어 있고, 일의 자리가 맨 앞에 온다. 다시 말해 수를 거꾸로 적었다. 두 수를 더한 값을 같은 형식의 연결 리스트로 돌려준다.

```text
l1 = 2 → 4 → 9        (942)
l2 = 5 → 6 → 4 → 9    (9465)
답 = 7 → 0 → 4 → 0 → 1   (10407)
```

리스트마다 노드는 1개에서 100개다. 수 자체가 0이 아니면 맨 앞자리(리스트의 꼬리)는 0이 아니다. 100자리 수라는 게 이 문제의 함정이다. 자바스크립트 `Number`가 정확히 표현하는 정수는 2^53 - 1(약 9×10^15, 16자리)까지이고, Java `long`도 19자리를 넘으면 넘친다. 숫자로 바꿔 계산하는 방법은 제약 안의 입력에서 틀린다.

## 세로 덧셈을 그대로 따라가면

942 + 9465를 세로 덧셈으로 하면 이렇다. 일의 자리부터 더하고, 10이 넘으면 1을 다음 자리로 올린다.

```text
         9 4 2
   +   9 4 6 5
   -----------
     1 0 4 0 7

자리   l1   l2   올림   합   적는 숫자   새 올림
일      2    5    0      7       7          0
십      4    6    0     10       0          1
백      9    4    1     14       4          1
천      -    9    1     10       0          1
만      -    -    1      1       1          0
```

표를 보면 할 일이 세 가지로 정리된다.

1. 이 자리의 합은 `l1의 숫자 + l2의 숫자 + 올림`이다. 리스트가 이미 끝났으면 그 숫자는 0으로 친다.
2. 적는 숫자는 `합 % 10`, 다음 자리로 가는 올림은 `합 / 10`의 몫이다. 두 숫자와 올림을 더해도 최대 9 + 9 + 1 = 19라서 올림은 언제나 0 아니면 1이다.
3. 두 리스트가 모두 끝나도 올림이 남아 있으면 자리를 하나 더 적는다. 마지막 만의 자리가 그 경우다.

수가 거꾸로 적혀 있다는 조건이 사실은 도움이다. 세로 덧셈은 일의 자리부터 해야 하는데, 리스트의 머리가 바로 일의 자리다. 앞에서부터 걸어가기만 하면 덧셈 순서와 맞는다. 자릿수가 정방향으로 적혀 있었다면 뒤에서부터 걸어야 해서 더 어렵다. 그 변형은 뒤에서 따로 본다.

## 리스트를 숫자로 바꿔 더하기

처음 떠오르는 방법부터 보자. 각 리스트를 정수로 바꾸고, 더한 다음, 다시 자리별로 쪼개 리스트를 만든다.

```js
function addTwoNumbers(l1, l2) {
  const toNum = (l) => {
    let n = 0, place = 1;
    for (let p = l; p; p = p.next) {
      n += p.val * place;   // 앞에서부터 일, 십, 백 … 자리
      place *= 10;
    }
    return n;
  };
  let sum = toNum(l1) + toNum(l2);

  if (sum === 0) return new ListNode(0);
  const dummy = new ListNode();
  let t = dummy;
  while (sum > 0) {
    t = t.next = new ListNode(sum % 10); // 일의 자리부터 떼어 붙인다
    sum = Math.floor(sum / 10);
  }
  return dummy.next;
}
```

예시 942 + 9465는 `[7,0,4,0,1]`로 맞게 나온다. 하지만 30자리 수 `10^29 + 1`과 465를 더하면 이렇게 나온다.

```text
기대값:  [6,6,4,0,0, … ,0,1]      (100000000000000000000000000466)
실제값:  [6,2,2,4,4,2,8,0, … ,0,1]
```

자바스크립트 숫자는 64비트 부동소수점이라 2^53을 넘는 정수는 사이사이 값을 표현하지 못한다. `9007199254740993`을 찍으면 `9007199254740992`가 나온다. 30자리 수는 아래쪽 자리가 통째로 뭉개진다. Java에서 `long`으로 하면 더 일찍, 20자리 수 `10000000000000000001`이 `-8446744073709551615`로 넘친다.

시간은 O(m + n)이지만 답이 틀린다. 숫자 하나에 담을 수 없는 크기를 다루려면 숫자를 자리별로 들고 다녀야 한다.

## 언어의 큰 정수에 맡기기

자바스크립트에는 크기 제한이 없는 `BigInt`가 있다. 자릿수를 문자열로 이어 `BigInt`로 바꾸면 정확하게 더할 수 있다. Python은 기본 `int`가 크기 제한이 없어서 앞의 "숫자로 바꿔 더하기" 코드가 그대로 맞는다. 직접 돌려 보면 `10^29 + 1`에 465를 더해 `100000000000000000000000000466`이 정확히 나온다. Java는 `BigInteger`를 쓰면 된다.

```js
function addTwoNumbers(l1, l2) {
  const toBig = (l) => {
    const digits = [];
    for (let p = l; p; p = p.next) digits.push(p.val);
    return BigInt(digits.reverse().join("")); // 거꾸로 적힌 자리를 뒤집어 읽는다
  };
  const s = (toBig(l1) + toBig(l2)).toString();

  const dummy = new ListNode();
  let t = dummy;
  for (let i = s.length - 1; i >= 0; i--) t = t.next = new ListNode(Number(s[i]));
  return dummy.next;
}
```

통과는 한다. 시간은 자릿수에 비례해 O(m + n), 공간은 문자열과 큰 정수 때문에 O(m + n)이다. 하지만 면접에서 이 답을 내면 "BigInt 없이 해 보라"는 말이 곧바로 돌아온다. 이 문제가 묻는 건 큰 정수 덧셈을 직접 구현할 수 있느냐이고, 큰 정수 라이브러리 안에서도 결국 자리별 덧셈이 돌아간다. 그 덧셈을 리스트 위에서 직접 하는 게 다음 풀이다.

## 자리마다 더하고 올림을 넘긴다

세로 덧셈 표를 그대로 코드로 옮긴다. 두 리스트를 앞에서부터 한 칸씩 함께 걷고, 올림을 변수 하나에 들고 다닌다. 결과 리스트는 더미 노드 뒤에 꼬리를 늘려 가며 만든다. 더미를 쓰면 첫 노드를 만드는 경우를 따로 처리하지 않아도 된다.

```js
function addTwoNumbers(l1, l2) {
  const dummy = new ListNode();
  let tail = dummy, carry = 0;

  // 한쪽이라도 남았거나, 올림이 남아 있으면 계속한다
  while (l1 || l2 || carry) {
    const sum = (l1 ? l1.val : 0) + (l2 ? l2.val : 0) + carry; // 끝난 쪽은 0
    carry = Math.floor(sum / 10);           // 다음 자리로 넘길 올림 (0 또는 1)
    tail = tail.next = new ListNode(sum % 10); // 이 자리에 적을 숫자
    l1 = l1 && l1.next;
    l2 = l2 && l2.next;
  }
  return dummy.next;
}
```

반복 조건 `l1 || l2 || carry`가 세 가지 일을 한 번에 맡는다. 길이가 다른 두 리스트를 끝까지 걷고, 짧은 쪽이 끝나면 0으로 채우고, 마지막 올림이 남으면 한 바퀴 더 돌아 노드를 하나 붙인다.

아래 그림은 942 + 9465를 이 코드로 따라간 것이다. 칸은 결과 리스트의 자리이고, 화살표 표시가 지금 만드는 자리다.

### Python과 Java로 쓰면

Python은 `divmod`가 몫과 나머지를 함께 돌려줘서 올림과 자리 숫자를 한 줄로 얻는다.

```python
from typing import Optional

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class Solution:
    def addTwoNumbers(self, l1: Optional[ListNode], l2: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode()
        tail, carry = dummy, 0
        while l1 or l2 or carry:
            total = (l1.val if l1 else 0) + (l2.val if l2 else 0) + carry
            carry, digit = divmod(total, 10)   # 올림과 이 자리 숫자
            tail.next = ListNode(digit)
            tail = tail.next
            l1 = l1.next if l1 else None
            l2 = l2.next if l2 else None
        return dummy.next
```

Java는 `int`끼리 나누면 몫만 남아서 `Math.floor`가 필요 없다. 합에 숫자를 더하는 김에 포인터도 함께 옮기면 분기가 줄어든다.

```java
class Solution {
    public ListNode addTwoNumbers(ListNode l1, ListNode l2) {
        ListNode dummy = new ListNode();
        ListNode tail = dummy;
        int carry = 0;
        while (l1 != null || l2 != null || carry != 0) {
            int sum = carry;
            if (l1 != null) { sum += l1.val; l1 = l1.next; }
            if (l2 != null) { sum += l2.val; l2 = l2.next; }
            carry = sum / 10;               // 정수 나눗셈이라 Math.floor가 필요 없다
            tail.next = new ListNode(sum % 10);
            tail = tail.next;
        }
        return dummy.next;
    }
}
```

세 언어로 같은 입력을 돌린 결과다.

```text
[2,4,9] + [5,6,4,9]           →  [7, 0, 4, 0, 1]
[0] + [0]                     →  [0]
[9,9,9,9,9,9,9] + [9,9,9,9]   →  [8, 9, 9, 9, 0, 0, 0, 1]
[5] + [5]                     →  [0, 1]
```

언어 차이로 짚을 곳은 나눗셈이다. 자바스크립트와 Python 3의 `/`는 실수 나눗셈이라 `14 / 10`이 `1.4`다. 자바스크립트는 `Math.floor`(합이 음수가 아니니 `sum >= 10 ? 1 : 0`이나 `(sum / 10) | 0`도 된다), Python은 `//`나 `divmod`를 쓴다. Java와 C++의 `int` 나눗셈은 몫만 남긴다. 이 문제는 합이 음수가 될 일이 없어서 음수 나눗셈의 방향(Python은 내림, Java는 0 쪽으로 버림) 차이는 걱정하지 않아도 된다.

## 남은 자리를 재귀에 넘기기

"이 자리를 더하고, 나머지 자리는 올림과 함께 다음 노드에게 맡긴다"는 문장을 그대로 재귀로 쓸 수 있다. 올림을 인자로 넘기면 바깥 변수가 필요 없다.

```js
function addTwoNumbers(l1, l2, carry = 0) {
  if (!l1 && !l2 && !carry) return null;  // 더할 것이 없으면 끝
  const sum = (l1 ? l1.val : 0) + (l2 ? l2.val : 0) + carry;
  return new ListNode(
    sum % 10,
    addTwoNumbers(l1 && l1.next, l2 && l2.next, Math.floor(sum / 10)) // 나머지 자리
  );
}
```

종료 조건이 반복 풀이의 `while` 조건을 뒤집은 것이다. 짧고 읽기 좋다. 다만 자리 하나마다 함수 호출이 하나씩 쌓여서 공간이 O(max(m, n))이다. 이 문제는 100자리라 깊이 101이면 끝나서 문제없다. 같은 코드를 큰 수 덧셈 라이브러리에 쓰면 이야기가 다르다. Node.js에서 1000자리는 됐지만 1만 자리에서 `RangeError: Maximum call stack size exceeded`가 났다. Python은 기본 재귀 한도가 1000이다.

## 입력 노드를 결과로 다시 쓰기

새 노드를 만들지 않고 `l1`의 노드에 합을 덮어쓰면 결과 리스트를 위한 공간도 아낄 수 있다. `l1`이 먼저 끝나면 `l2`의 남은 노드를 이어 받아 계속 쓰고, 마지막 올림이 남을 때만 새 노드를 하나 만든다.

```js
function addTwoNumbers(l1, l2) {
  const head = l1;
  let carry = 0, prev = null;
  while (l1 || l2) {
    if (!l1) {            // l1이 끝나면 l2의 나머지를 l1 뒤에 이어 쓴다
      prev.next = l2;
      l1 = l2;
      l2 = null;
    }
    const sum = l1.val + (l2 ? l2.val : 0) + carry;
    l1.val = sum % 10;    // l1 노드에 결과를 덮어쓴다
    carry = Math.floor(sum / 10);
    prev = l1;
    l1 = l1.next;
    l2 = l2 && l2.next;
  }
  if (carry) prev.next = new ListNode(carry); // 새로 만드는 건 많아야 노드 하나
  return head;
}
```

시간 O(max(m, n)), 새로 만드는 노드는 많아야 하나다. 그런데 입력이 망가진다. `[1] + [9,9,9]`를 넣으면 결과 `[0,0,0,1]`이 나오고, 함수가 끝난 뒤 `l2`를 다시 읽어 보면 `[9,0,0,1]`로 바뀌어 있다. 결과가 `l2`의 꼬리 노드를 빌려 썼기 때문이다. 호출한 쪽이 입력을 계속 쓰는 코드라면 찾기 어려운 버그가 된다. 면접에서 공간을 더 줄여 보라고 하면 이 방법을 말할 수 있지만, "입력을 바꿔도 되는지"를 먼저 물어보는 게 맞다.

## 다섯 풀이를 한 줄씩

| 풀이 | 시간 | 추가 공간 | 언제 고르나 |
|---|---|---|---|
| 숫자로 바꿔 더하기 | O(m+n) | O(1) | 고르지 않는다. 16자리(JS), 19자리(Java long)를 넘으면 틀린다 |
| 큰 정수(BigInt, Python int) | O(m+n) | O(m+n) | 실무에서 큰 수가 필요할 때. 면접 답으로는 의도를 피한 것이다 |
| 자리마다 더하고 올림 넘기기 | O(max(m,n)) | O(1) | 기본 답. 결과 리스트만 새로 만든다 |
| 재귀 | O(max(m,n)) | O(max(m,n)) 콜 스택 | 짧게 쓰고 싶을 때. 아주 긴 수에서는 스택이 넘친다 |
| 입력 노드 다시 쓰기 | O(max(m,n)) | O(1), 새 노드 최대 1개 | 입력을 바꿔도 된다고 확인했을 때만 |

## 마지막 1이 사라지는 코드

이 문제의 오답은 대부분 끝에서 나온다. 직접 돌려 본 틀린 코드 세 개다.

### 반복 조건에서 carry를 빼면

```js
while (l1 || l2) {   // carry가 빠졌다
  // … 본문은 같다
}
```

```text
[5] + [5]      →  [0]       (10이어야 하니 [0, 1])
[9,9] + [1]    →  [0, 0]    (100이어야 하니 [0, 0, 1])
```

두 리스트가 끝났을 때 남은 올림을 버린다. 가장 흔한 실수다. 반복문 뒤에 `if (carry) tail.next = new ListNode(carry);`를 붙여도 되지만, 조건에 `carry`를 넣어 두면 그 줄이 필요 없다.

### 둘 다 남아 있을 때만 돌면

```js
while (l1 && l2) {
  const sum = l1.val + l2.val + carry;
  // …
}
if (carry) tail.next = new ListNode(carry);
```

```text
[2,4,9] + [5,6,4,9]  →  [7, 0, 4, 1]       (10407이 아니라 1407로 읽힌다)
[1] + [9,9,9]        →  [0, 1]
```

짧은 쪽이 끝나는 순간 반복문을 빠져나와서 긴 쪽의 남은 자리를 버린다. `[2,4,9] + [5,6,4,9]`에서 l2의 마지막 자리 9가 통째로 사라졌다. 길이가 같은 예시로만 확인하면 놓치기 쉽다. 끝난 쪽을 0으로 보고 계속 도는 게 맞다.

### 올림을 나누기만 하면

자바스크립트에서 `carry = sum / 10`으로 쓰고 `Math.floor`를 빠뜨린 경우다.

```text
[2,4,9] + [5,6,4,9]  →  [7, 0.6999999999999993, 4.07, 0.40700000000000003, 1.0407, …]
```

첫 자리 합 7에서 올림이 `0.7`이 되고, 다음 자리 합이 `10.7`이 된다. 그 뒤로는 소수 올림이 계속 10으로 나뉘어 작아질 뿐 정확히 0이 되지 않아서, 부동소수점이 0으로 떨어질 때까지 돈다. 이 입력에서 노드가 328개 만들어지고서야 멈췄다. Python에서 `//` 대신 `/`를 써도 같은 일이 생긴다. Java는 `int` 나눗셈이라 이 실수가 없다.

결과가 0인 경우도 한 번 본다. `[0] + [0]`은 첫 바퀴에서 합 0으로 노드 하나를 만들고, 다음 바퀴에서 셋 다 비어 멈춘다. 결과 `[0]`이 맞다. 숫자로 바꾸는 풀이는 `while (sum > 0)`이 한 번도 돌지 않아 빈 리스트가 나오기 쉬워서, 앞에서 `sum === 0`을 따로 처리했다.

## 자릿수가 반대 방향이라면

### 큰 자리가 앞에 오면

LeetCode 445 Add Two Numbers II는 같은 덧셈인데 자릿수가 정방향이다. `7→2→4→3`(7243)과 `5→6→4`(564)를 더해 `7→8→0→7`(7807)을 만든다. 이제 머리가 가장 큰 자리라 앞에서부터 걸으면 덧셈 순서와 반대다.

방법은 세 가지다. 두 리스트를 [뒤집어서](/posts/leetcode-reverse-linked-list) 이 글의 풀이를 돌리고 결과를 다시 뒤집는다. 아니면 자릿수를 스택 두 개에 담아 위에서부터 꺼내며 더한다. 스택에서 나오는 순서가 일의 자리부터라서 세로 덧셈 순서와 맞는다. 결과는 꼬리에 붙이지 않고 머리 앞에 붙여 나가면 된다. 입력을 뒤집지 말라는 조건이 붙으면 스택 풀이를 쓴다.

```js
function addTwoNumbersII(l1, l2) {
  const s1 = [], s2 = [];
  for (let p = l1; p; p = p.next) s1.push(p.val);
  for (let p = l2; p; p = p.next) s2.push(p.val);

  let head = null, carry = 0;
  while (s1.length || s2.length || carry) {
    const sum = (s1.pop() ?? 0) + (s2.pop() ?? 0) + carry; // 일의 자리부터 꺼낸다
    carry = Math.floor(sum / 10);
    head = new ListNode(sum % 10, head);                  // 결과는 앞에 붙인다
  }
  return head;
}
// [7,2,4,3] + [5,6,4] → [7, 8, 0, 7]     [9,9] + [1] → [1, 0, 0]
```

아래 그림이 7243 + 564를 스택으로 더하는 과정이다. 칸은 결과 리스트이고, 새 자리가 머리 앞에 붙으며 왼쪽으로 자란다.

### 1을 더하기만 하라면

LeetCode 369 Plus One Linked List(프리미엄 문제)는 정방향 리스트에 1을 더한다. 올림은 9가 이어지는 구간에서만 생긴다는 점을 쓰면 스택 없이 O(1) 공간으로 된다. 앞에 0을 담은 더미를 붙이고, 걸으면서 마지막으로 본 9가 아닌 노드를 기억한다. 그 노드에 1을 더하고 뒤의 9를 모두 0으로 바꾼다. 더미가 1이 됐으면 더미가 새 머리다. `[1,2,9,9]`는 `[1,3,0,0]`, `[9,9]`는 `[1,0,0]`이 된다.

### 리스트가 아니라 문자열이나 배열이라면

LeetCode 415 Add Strings, 67 Add Binary, 989 Add to Array-Form of Integer는 모두 같은 덧셈을 문자열이나 배열 위에서 한다. 이번에는 끝에서부터 인덱스를 줄여 가며 걷는다. 2진수라면 `% 10`, `/ 10`이 `% 2`, `/ 2`로 바뀔 뿐이다. 곱셈은 [Multiply Strings](/posts/leetcode-multiply-strings)에서 자리마다의 곱을 칸에 모았다가 올림을 정리하는 방식으로 확장된다.

### 뺄셈이라면

뺄셈은 올림 대신 빌림이 생긴다. 이 자리 차가 음수면 10을 더하고 빌림 1을 다음 자리로 넘긴다. 그리고 덧셈에 없던 일이 둘 생긴다. 어느 쪽이 큰지 먼저 알아야 하고(여기서는 `l1`이 크거나 같다고 가정한다), 결과 앞자리에 0이 남을 수 있다. 1000 - 999는 자리별로 계산하면 0001이다. 거꾸로 저장했으니 앞자리 0은 리스트의 꼬리 쪽에 쌓인다. 마지막으로 0이 아닌 자리를 기억해 두었다가 그 뒤를 잘라 낸다.

```js
// l1 >= l2라고 가정한다. 두 수 모두 거꾸로 저장되어 있다
function subtract(l1, l2) {
  const dummy = new ListNode();
  let tail = dummy, borrow = 0, lastNonZero = dummy;
  while (l1) {
    let diff = l1.val - (l2 ? l2.val : 0) - borrow;
    borrow = diff < 0 ? 1 : 0;
    if (diff < 0) diff += 10;
    tail = tail.next = new ListNode(diff);
    if (diff !== 0) lastNonZero = tail;   // 마지막으로 0이 아닌 자리
    l1 = l1.next;
    l2 = l2 && l2.next;
  }
  if (lastNonZero === dummy) return new ListNode(0); // 결과가 0
  lastNonZero.next = null;                           // 꼬리 쪽 0(앞자리 0)을 잘라 낸다
  return dummy.next;
}
// [0,0,0,1] - [9,9,9] → [1]      (1000 - 999)
// [2,4,9] - [5,6]     → [7,7,8]  (942 - 65 = 877)
// [5,5] - [5,5]       → [0]
```

### 수가 여러 개라면

리스트 k개를 한꺼번에 더하면 올림이 1을 넘는다. 99를 열두 개 더하면 일의 자리 합이 9 × 12 = 108이라 8을 적고 올림 10을 넘긴다. 코드는 그대로 `Math.floor(sum / 10)`으로 두면 되고, 반복 조건만 "아직 남은 리스트가 있거나 올림이 남았다"로 넓힌다. 직접 돌리면 `[8,8,1,1]`, 곧 1188이 나온다. 올림이 언제나 0 아니면 1이라는 성질은 두 수를 더할 때만 성립한다.

## 세로 덧셈을 리스트 위에서

이 문제는 큰 수를 숫자 하나에 담지 않고 자리별로 더하는 연습이다. 자릿수가 거꾸로 적혀 있어서 리스트의 머리가 곧 일의 자리이고, 두 리스트를 앞에서부터 함께 걸으며 `합 = 두 숫자 + 올림`, `적기 = 합 % 10`, `올림 = 합 / 10의 몫`을 반복하면 된다. 반복 조건을 `l1 || l2 || carry`로 두면 길이가 다른 수와 마지막 올림이 한 번에 처리된다. 시간 O(max(m, n)), 결과 리스트를 빼면 공간 O(1)이다.

## 면접에서 나올 만한 질문

### 리스트를 정수로 바꿔 더하면 안 되나요?

안 된다. 리스트 길이가 100까지라 수가 100자리까지 나온다. 자바스크립트 `Number`는 2^53 - 1을 넘는 정수를 정확히 담지 못하고, Java `long`은 19자리를 넘으면 넘친다. Python은 정수 크기 제한이 없어서 통과하지만, 이 문제가 묻는 건 큰 수 덧셈을 자리별로 구현할 수 있느냐다.

### 시간과 공간 복잡도는 어떻게 되나요?

시간은 O(max(m, n))이다. 긴 쪽 리스트 길이만큼 돌고 마지막 올림 때문에 한 번 더 돌 수 있다. 추가 공간은 변수 몇 개라 O(1)이고, 결과 리스트까지 세면 O(max(m, n))이다. 결과는 긴 쪽보다 많아야 한 자리 길다.

### 올림이 2 이상이 될 수 있나요?

없다. 한 자리 합은 많아야 9 + 9 + 1 = 19라서 올림은 0 아니면 1이다. 귀납적으로 첫 자리의 올림이 0이고, 올림이 1 이하면 다음 합도 19 이하라 다음 올림도 1 이하다. 세 수 이상을 더하거나 곱셈이라면 올림이 커질 수 있다.

### 반복 조건을 `l1 || l2 || carry`로 쓰는 이유는 무엇인가요?

길이가 다른 두 수와 마지막 올림을 한 번에 처리하려고다. 한쪽이 끝나도 다른 쪽이 남아 있으면 계속 돌면서 끝난 쪽을 0으로 보고, 둘 다 끝나도 올림이 있으면 한 바퀴 더 돌아 노드를 붙인다. `carry`를 빼면 5 + 5가 10이 아니라 0이 된다.

### 자릿수가 정방향이면 어떻게 푸나요?

LeetCode 445다. 두 리스트를 뒤집어서 같은 풀이를 돌리고 결과를 다시 뒤집거나, 자릿수를 스택 두 개에 담아 위에서부터 꺼내며 더한다. 스택에서는 일의 자리부터 나오니 세로 덧셈 순서와 맞고, 결과는 머리 앞에 붙여 나가면 된다. 입력을 바꾸지 말라는 조건이 있으면 스택 풀이를 쓴다.

### 결과용 노드를 새로 만들지 않을 수 있나요?

`l1`의 노드에 합을 덮어쓰고, `l1`이 먼저 끝나면 `l2`의 남은 노드를 이어 쓰면 새 노드는 마지막 올림 하나뿐이다. 대신 두 입력이 모두 바뀐다. `[1] + [9,9,9]`를 넣으면 함수가 끝난 뒤 `l2`가 `[9,0,0,1]`로 바뀌어 있다. 입력을 바꿔도 되는지 먼저 확인해야 하는 풀이다.

### 재귀로 풀면 어떤가요?

"이 자리를 만들고 나머지는 올림과 함께 다음 호출에 맡긴다"로 짧게 쓸 수 있다. 다만 자리마다 호출이 쌓여 공간이 O(max(m, n))이다. 이 문제의 100자리는 괜찮지만, 같은 코드로 1만 자리 수를 더하면 Node.js에서도 스택이 넘쳤다.
