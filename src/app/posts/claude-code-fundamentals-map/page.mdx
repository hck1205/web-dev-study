"AI Engineering Fundamentals"라는 제목의 그림이 돈다. 카드 열두 장에 CLAUDE.md, 컨텍스트 창, 체크포인트, 플랜 모드, 아티팩트, 훅, 서브에이전트, 스킬, Goal, Loops, Worktrees, Routines가 한 줄씩 적혀 있다. 다 맞는 말 같은데, 처음 보는 사람은 어디서부터 익혀야 할지 모른다. 어떤 카드는 다른 카드 없이는 이해가 안 되고, 어떤 카드의 이름은 이미 바뀌었다.

이 글은 그 열두 장과 함께 도는 "프로젝트 구조" 그림까지 공식 문서에 하나씩 맞춰 보고, 배우는 순서대로 다시 늘어놓는 지도다. 카드마다 한 문단으로 무엇이고 언제 꺼내는지만 적고, 자세한 내용은 이 시리즈의 네 글로 넘긴다.

- [Claude Code 프로젝트 구조](/posts/claude-code-project-structure): CLAUDE.md와 메모리, settings의 층, 권한, `.mcp.json`, 커밋할 것
- [Claude Code 확장](/posts/claude-code-extensions): 슬래시 명령, 스킬, 서브에이전트, 훅
- [Claude Code 컨텍스트 창](/posts/claude-code-context-window): 창이 차고 압축되는 과정, 체크포인트, 플랜 모드
- [병렬 세션과 예약 작업](/posts/claude-code-parallel-and-scheduled): worktree, `/loop`, `/goal`, 클라우드 예약 작업, 아티팩트

기준은 2026년 10월에 읽은 공식 문서(code.claude.com/docs)와 Claude Code 2.1.306이다.

## 열두 장을 문서에 맞춰 보면

결론부터 말하면 열두 장 모두 Claude Code 공식 문서에 있는 기능이다. 다만 그림의 한 줄 설명은 많이 줄인 것이라, 문서와 맞춰 보면 고쳐 읽어야 할 데가 있다.

| 카드 | 그림의 설명 | 문서에서 확인한 것 |
| :- | :- | :- |
| CLAUDE.md | 매 세션 읽는다 | 공식. 위 폴더의 것은 시작할 때, 하위 폴더의 것은 그 폴더를 건드릴 때 읽는다 |
| Context Window | 차면 압축한다 | 공식. 자동 압축과 `/compact`. 무엇이 다시 올라오는지는 경로마다 다르다 |
| Checkpoints | Esc Esc로 코드와 대화를 되감는다 | 공식. 입력창이 비어 있을 때만. Bash로 바꾼 파일은 되돌리지 않는다 |
| Plan Mode | 승인 전에는 고치지 않는다 | 공식. 소스 편집만 막고, 탐색용 셸 명령은 돈다 |
| Artifacts | 비공개 페이지를 올린다 | 공식. claude.ai 로그인 세션과 유료 플랜이 필요하다. claude.ai 채팅의 아티팩트와는 다른 진입점이다 |
| Hooks | PreToolUse, PostToolUse, Stop | 공식 이벤트 이름. `guard.sh`, prettier, `npm test`는 예시 스크립트다 |
| Subagents | 자기 컨텍스트, 요약만 돌려준다 | 공식 |
| Skills | 필요할 때 SKILL.md를 읽는다 | 공식. 설명은 늘 올라가 있고 본문만 필요할 때 읽는다 |
| Goal | 조건이 맞을 때까지 일한다 | 공식 `/goal`. 작은 모델이 턴마다 판정한다 |
| Loops | 5분마다 다시 돈다 | 공식 `/loop`. 세션이 열려 있어야 하고 7일 뒤 만료된다 |
| Worktrees | 저장소 하나에 작업 폴더 여럿 | 공식 `--worktree`. 파일만 나누고 포트·DB는 나누지 않는다 |
| Routines | 정해진 시각에 클라우드 에이전트가 PR을 연다 | 지금 이름은 cloud scheduled tasks(예전 이름 routines). research preview, 최소 간격 1시간 |

그림 제목의 "AI Engineering Fundamentals"는 문서의 용어가 아니다. 카드 묶음에 붙인 이름일 뿐이다. 그리고 Routines 카드의 "9:00"은 문서가 오히려 피하라고 하는 시각이다. 정각에 건 실행은 몇 분 늦을 수 있어서 9:07처럼 건다.

프로젝트 구조 그림(`CLAUDE.md`, `CLAUDE.local.md`, `.mcp.json`, `.claude/settings.json`, `rules/`, `commands/`, `skills/`, `agents/`, `hooks/`)도 대부분 문서와 맞는다. 어긋나는 곳은 두 군데다. `hooks/`는 정해진 폴더가 아니라서 스크립트를 넣기만 해서는 아무 일도 없고 `settings.json`의 `hooks` 키에 등록해야 돈다. `commands/`는 아직 동작하지만 스킬로 합쳐진 옛 형식이다. 이 대조는 [프로젝트 구조 글](/posts/claude-code-project-structure)에서 한 줄씩 했다.

그 그림 아래에는 "이렇게 동작한다"는 다섯 단계도 붙어 있다. CLAUDE.md를 읽고, 설정·규칙·스킬을 불러오고, 명령과 서브에이전트를 쓰고, MCP로 도구를 잇고, 훅을 돌린다. 순서대로 한 번씩 일어나는 것처럼 보이지만 실제로는 두 시점으로 나뉜다.

- 세션을 열 때: 설정 파일의 층이 합쳐지고, 위 폴더의 CLAUDE.md와 경로 조건 없는 rules, 자동 메모리, 스킬 설명, MCP 도구 이름이 컨텍스트에 올라간다. MCP 서버 연결도 이때 시작된다.
- 일하는 내내: 하위 폴더 CLAUDE.md와 경로 조건 rules는 해당 파일을 건드릴 때, 스킬 본문은 쓸 때, MCP 도구 정의는 필요할 때 올라온다. 훅은 마지막 단계가 아니라 이벤트가 일어날 때마다 돈다. SessionStart는 맨 처음, PreToolUse·PostToolUse는 도구 호출마다, Stop은 턴이 끝날 때다.

"다섯 단계"를 시간 순서가 아니라 층으로 읽으면 맞다. 처음에 깔리는 것과 그때그때 올라오는 것을 구분해야, 압축 뒤에 무엇이 다시 올라오는지(시작 때 깔린 것은 대부분 다시 읽고, 그때그때 올라온 것은 요약된다)도 이해된다.

### 1. CLAUDE.md

프로젝트에서 Claude가 매번 알아야 하는 사실과 규칙을 적는 파일이다. 작업 폴더와 그 위 폴더의 CLAUDE.md는 세션 시작 때, 하위 폴더의 것은 그 폴더를 건드릴 때 올라간다. 강제가 아니라 지시라는 것을 먼저 알아 둔다. 문서는 200줄 아래를 권하고, 길수록 지시를 덜 따른다고 적는다. 위치와 우선순위, `CLAUDE.local.md`와 rules는 [프로젝트 구조 글](/posts/claude-code-project-structure)에서 본다.

### 2. 컨텍스트 창

Claude가 한 번에 보는 전부다. 시스템 프롬프트, CLAUDE.md, 도구 이름, 스킬 설명이 먼저 깔리고, 읽은 파일과 명령 출력이 그 위에 쌓인다. 한도에 가까워지면 대화가 요약으로 바뀌는데, 루트 CLAUDE.md처럼 디스크에서 다시 읽는 것은 살아남고 대화로만 한 말은 흐려질 수 있다. 그래서 끝까지 지킬 규칙은 CLAUDE.md에 둔다. 무엇이 남는지, `/compact`와 `/clear`를 언제 치는지는 [컨텍스트 창 글](/posts/claude-code-context-window)에 있다.

### 3. 플랜 모드

조사하고 계획을 내되, 내가 승인할 때까지 소스를 고치지 않는 권한 모드다. `Shift+Tab`, 프롬프트 앞의 `/plan`, `--permission-mode plan`으로 들어간다. 파일 여러 개에 걸친 변경이나 처음 보는 코드에서 방향을 먼저 맞추는 데 쓴다. 탐색용 셸 명령은 돌기 때문에 샌드박스는 아니다.

### 4. 체크포인트

턴을 시작하는 프롬프트마다 코드 상태를 잡아 두고, 입력창이 빈 상태에서 `Esc` 두 번이나 `/rewind`로 되감는다. 코드만, 대화만, 둘 다 되돌리거나 일부만 요약할 수 있다. Claude의 편집 도구가 만든 변경만 돌아오고, Bash로 지운 파일이나 push 같은 바깥의 일은 돌아오지 않는다. 세션 안의 되돌리기이고 git을 대신하지 않는다.

### 5. 스킬

자주 붙여 넣는 절차나 체크리스트를 `SKILL.md`로 만든 것이다. 설명(description)은 늘 컨텍스트에 있고, 본문은 Claude가 그 스킬을 쓸 때나 내가 `/이름`으로 부를 때 올라간다. 그래서 긴 참고 자료를 넣어도 평소에는 거의 비용이 없다. CLAUDE.md의 한 절이 "사실"이 아니라 "절차"로 커졌다면 스킬로 옮길 때다. frontmatter와 자동 로딩 조건은 [확장 글](/posts/claude-code-extensions)에서 다룬다.

### 6. 서브에이전트

자기 컨텍스트 창과 시스템 프롬프트, 제한된 도구로 곁가지 일을 하고 요약만 돌려주는 일꾼이다. 파일 수십 개를 읽는 조사를 맡기면 내 창은 거의 그대로 남는다. 자기 요청을 따로 보내 사용량은 그만큼 쓰고, 근거 없이 요약만 오니 중요한 결론은 확인한다. 만드는 법은 [확장 글](/posts/claude-code-extensions)에 있다.

### 7. 훅

Claude Code의 정해진 시점에 내 스크립트를 돌리는 장치다. CLAUDE.md가 부탁이라면 훅은 강제다. PreToolUse 훅은 도구 호출 전에 돌아서 exit 2로 막을 수 있고, PostToolUse는 성공한 도구 호출 뒤에, Stop은 Claude가 응답을 마칠 때 돈다. 훅은 내 권한으로 실행되니 남의 저장소를 열 때 조심한다. 이벤트 목록과 검증 스크립트 예제는 [확장 글](/posts/claude-code-extensions)에서 본다.

### 8. Worktrees

`.git` 하나를 공유하면서 세션마다 작업 폴더와 브랜치를 따로 주는 git 기능이고, Claude Code는 `--worktree`로 그것을 만들고 치운다. 세션 둘이 서로의 파일을 덮는 일은 막지만, 같은 파일을 고치면 merge에서 만나고 포트와 DB는 여전히 하나다. 실제 명령 출력과 함께 [병렬 세션 글](/posts/claude-code-parallel-and-scheduled)에서 따라가 본다.

### 9. Loops

`/loop 5m check the deploy`처럼 세션 안에서 같은 프롬프트를 일정 간격으로 되풀이하는 번들 스킬이다. 간격을 빼면 Claude가 매번 다음 간격을 고른다. 세션이 열려 있어야 돌고, 반복 작업은 7일 뒤 스스로 지워지며, 실행 시각은 최대 30분까지 흩어진다.

### 10. Goal

`/goal`에 완료 조건을 주면 턴이 끝날 때마다 작은 모델이 조건을 판정하고, 아직이면 Claude가 다음 턴을 스스로 시작한다. 평가 모델은 대화에 드러난 것만 보니, 조건은 "`npm test`가 0으로 끝난다"처럼 대화로 증명할 수 있게 쓰고 턴 상한을 붙인다. 권한 모드는 바꾸지 않는다.

### 11. Routines, 지금 이름은 클라우드 예약 작업

프롬프트와 저장소, 커넥터를 묶어 두고 스케줄·API 호출·GitHub 이벤트로 클라우드에서 돌리는 기능이다. 노트북이 꺼져 있어도 돌고, 매번 저장소를 새로 clone해서 `claude/` 브랜치로 push한다. 실행 중에 권한 확인이 없어서 저장소와 커넥터 범위를 좁혀 두는 것이 설계의 시작이다. 내 컴퓨터의 파일이 필요하면 데스크톱 앱의 로컬 예약 작업을 쓴다.

### 12. Artifacts

세션의 결과를 claude.ai의 비공개 웹 페이지로 올려 링크로 나누는 기능이다. 주석 달린 diff, 대시보드, 설계안 비교처럼 터미널 글보다 보는 편이 나은 것에 쓴다. 백엔드 없는 정적 페이지 한 장이라 사내 도구 배포용은 아니다. claude.ai 로그인 세션에서만 올릴 수 있고, API 키나 클라우드 제공자 인증으로 쓰는 세션은 못 올린다.

## 어떤 카드를 꺼낼까

상황을 보고 카드를 고르는 규칙을 코드로 써 보면 순서가 중요하다는 것이 드러난다. 반드시 막아야 하는 일이면 다른 무엇보다 훅이 먼저고, 내가 없을 때 돌아야 하면 세션 범위의 `/loop`나 `/goal`은 후보에서 빠진다. 아래 규칙은 이 글의 정리를 단순화한 것이다. 우선순위대로 하나만 고른다.

- `mustBlock`: 모델 판단과 상관없이 막아야 한다 → `"hook"`
- `runWhileAway`: 내 컴퓨터가 꺼져 있어도 돌아야 한다 → `"scheduled task"`
- `doneWhen`: 확인할 수 있는 끝 상태가 있다 → `"/goal"`
- `everyMinutes`: 일정 간격으로 확인한다 → `"/loop"`
- `parallelEdits`: 여러 세션이 동시에 파일을 고친다 → `"worktree"`
- `floodsContext`: 곁가지 조사가 창을 채운다 → `"subagent"`
- `repeatedProcedure`: 같은 절차를 자주 시킨다 → `"skill"`
- `alwaysTrue`: 매 세션 알아야 하는 사실이다 → `"CLAUDE.md"`
- 아무것도 아니면 그냥 말로 시킨다 → `"prompt"`

## 카드를 잘못 꺼내는 순간

- 막아야 할 규칙을 CLAUDE.md에만 적었다. 어느 날 지켜지지 않는다. 권한 deny나 PreToolUse 훅으로 옮긴다.
- CLAUDE.md가 수백 줄이다. 규칙이 잡음에 묻히고 매 요청 비용이 든다. 절차는 스킬로, 특정 폴더 규칙은 경로 조건 rules로 옮긴다.
- 체크포인트를 믿고 마이그레이션과 push를 허용해 뒀다. 되감아도 바깥의 일은 돌아오지 않는다. 큰 작업 전에는 커밋을 찍고, 바깥에 흔적을 남기는 명령은 묻게 둔다.
- 플랜 모드면 아무것도 안 돈다고 여겼다. 탐색 명령은 돈다. 위험한 명령은 권한과 샌드박스로 막는다.
- 세션 셋을 같은 폴더에서 돌렸다. 서로의 파일을 덮는다. 세션마다 worktree를 준다.
- 테스트가 통과할 때까지 `/loop 5m`을 걸었다. 통과해도 루프는 계속 돈다. 끝 상태가 있으면 `/goal`이다.
- 로컬 파일이 필요한 일을 클라우드 예약 작업으로 걸었다. 클라우드는 새 clone이라 그 파일이 없다. 데스크톱 로컬 예약 작업을 쓴다.
- 아티팩트로 사내 도구를 만들려 했다. 백엔드도 여러 경로도 없다. 보여 주는 용도로만 쓴다.

열두 장을 하나로 꿰는 실은 컨텍스트 창이다. Claude가 무엇을 보고 일하는지 알면, 무엇을 CLAUDE.md에 두고 무엇을 스킬과 서브에이전트로 빼며 무엇을 훅으로 강제할지가 정해진다. 그 위에서 세션을 여럿으로, 시간 축으로, 바깥 사람에게로 넓혀 가는 것이 나머지 카드다. 처음이라면 [프로젝트 구조](/posts/claude-code-project-structure)와 [컨텍스트 창](/posts/claude-code-context-window)부터 읽고, [확장](/posts/claude-code-extensions)과 [병렬 세션과 예약 작업](/posts/claude-code-parallel-and-scheduled)으로 넘어가면 된다.

## 면접에서 나올 만한 질문

### CLAUDE.md와 훅은 무엇이 다른가요?

CLAUDE.md는 모델에게 주는 지시이고 훅은 클라이언트가 실행하는 강제다. CLAUDE.md의 규칙은 컨텍스트로 들어가서 Claude가 참고하지만, 판단에 따라 어기거나 압축 뒤에 흐려질 수 있다. PreToolUse 훅은 도구 호출 전에 돌아 exit 2로 그 호출을 막으므로 모델의 판단과 상관없다. 그래서 사실과 관례는 CLAUDE.md에, 반드시 지킬 금지는 권한 규칙과 훅에 둔다.

### 스킬과 서브에이전트는 언제 각각 쓰나요?

스킬은 반복하는 절차를 담는 그릇이고, 서브에이전트는 따로 일하는 일꾼이다. 스킬은 설명만 늘 올라가 있다가 쓸 때 본문을 내 컨텍스트에 넣는다. 서브에이전트는 자기 컨텍스트 창에서 일하고 요약만 돌려주니, 곁가지 조사가 내 창을 채울 때 쓴다. 둘을 합쳐 스킬을 서브에이전트에서 돌리게 할 수도 있다.

### 체크포인트가 있는데 git 커밋을 자주 해야 하나요?

해야 한다. 체크포인트는 Claude의 편집 도구가 만든 변경만 세션 안에서 되돌린다. Bash로 바꾼 파일, 대부분의 서브에이전트 편집, 직접 고친 파일, push나 마이그레이션 같은 바깥의 일은 돌아오지 않고 스냅샷도 일정 기간 뒤 정리된다. 영구 기록과 협업, 복구는 git이 맡는다.

### /loop, /goal, 클라우드 예약 작업은 어떻게 고르나요?

무엇이 다음 턴을 시작하느냐로 고른다. 일정 간격으로 바깥 상태를 확인하면 `/loop`, 확인할 수 있는 끝 상태까지 이어 가면 `/goal`이고, 둘 다 세션이 열려 있어야 돈다. 내 컴퓨터가 꺼져 있어도 돌아야 하면 클라우드 예약 작업인데, 최소 간격이 1시간이고 저장소를 새로 clone하며 권한 확인 없이 돈다.

### 플랜 모드는 늘 켜 두는 게 좋은가요?

아니다. 승인 왕복이 생기니 오타나 한 줄 수정에는 시간만 늘린다. 파일 여러 개에 걸친 변경, 처음 보는 코드베이스, 스키마나 공개 API처럼 되돌리기 어려운 작업에서 방향을 먼저 맞출 때 값을 한다. 팀이 늘 계획부터 받기로 했다면 프로젝트 설정의 `defaultMode`를 `plan`으로 둔다.

### 여러 세션을 병렬로 돌릴 때 가장 먼저 무엇을 하나요?

세션마다 작업 폴더를 나눈다. 같은 폴더에서 돌리면 checkout, stash, 포매터가 서로의 작업을 덮는다. `claude --worktree`로 세션마다 worktree와 브랜치를 주고, 일을 나눌 때 같은 파일을 고치지 않게 자르며, 포트와 DB 이름처럼 worktree가 나누지 않는 자원은 세션마다 다르게 준다.

### 열두 기능을 꿰는 하나의 개념을 꼽으라면 무엇인가요?

컨텍스트 창이다. 모델은 요청에 실린 것만 보고, 창이 차면 품질이 떨어지고 압축된다. CLAUDE.md를 짧게 쓰는 이유, 스킬이 본문을 필요할 때만 올리는 이유, 서브에이전트가 따로 창을 쓰는 이유, 되감기와 플랜 모드로 실패한 시도를 줄이는 이유가 모두 여기서 나온다. 나머지 기능은 그 위에서 일을 여러 세션과 시간으로 넓힌다.
