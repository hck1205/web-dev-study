"JavaScript 개념"이라는 이미지 열두 장을 저장해 뒀다. 변수와 스코프, 데이터 타입, 함수 두 장, 배열, 객체와 구조 분해, 복사와 불변성, 최신 문법, this와 프로토타입, 비동기, 자바스크립트가 실행되는 방식, 브라우저와 DOM과 이벤트. 장마다 용어가 빼곡하고 귀퉁이에 "React와의 연결"이라는 상자가 붙어 있다.

용어를 따로따로 외우면 금방 흐려진다. 실제 버그는 한 장에서만 나오지 않아서다. 아래 코드는 장바구니 화면에서 흔히 보는 줄을 모은 것이다.

```js
const cart = { items: [{ name: "pen", price: 1000 }], coupon: null };
const draft = { ...cart };
draft.items.push({ name: "ink", price: 500 });
console.log("1", cart.items.length);
console.log("2", cart.coupon?.rate ?? 0, cart.coupon?.rate || "none");
console.log("3", [10, 1, 2].sort());
console.log("4", typeof cart.coupon, "5" == 5);
const total = { sum: 0, add(p) { this.sum += p; } };
const add = total.add;
try { cart.items.forEach(i => add(i.price)); } catch (e) { console.log("5", e.constructor.name + ":", e.message); }
for (var i = 0; i < 3; i++) setTimeout(() => console.log("6 timer", i));
Promise.resolve().then(() => console.log("7 then"));
console.log("8 sync end");
```

사본에 넣은 물건이 원본 장바구니에도 들어갔고(복사), 정렬은 10을 1 뒤에 뒀고(배열), `null`의 `typeof`는 `"object"`이고(타입), 꺼낸 메서드에서 `this`가 사라졌고(this와 strict 모드), 타이머는 셋 다 3을 찍었고(변수), 출력 순서는 코드 순서와 다르다(실행 방식). 열 줄 남짓에 여섯 장이 들어 있다.

## 01 변수와 스코프

[var, let, const](/posts/js-var-let-const)는 "반복문의 `setTimeout`이 왜 모두 3을 찍나"에 답한다. 변수 상자가 함수마다 생기는지 반복마다 생기는지가 갈림길이고, `const`가 막는 건 재할당이지 값의 변경이 아니라는 것까지 짚는다.

[스코프와 렉시컬 스코프](/posts/js-scope-lexical)는 "이 이름을 엔진이 어디서 찾나"에 답한다. 함수를 쓴 자리가 바깥 스코프를 정한다는 규칙과 환경 레코드를 따라가고, React 컴포넌트 안에 컴포넌트를 정의하면 왜 상태가 날아가는지도 본다.

[호이스팅과 TDZ](/posts/js-hoisting-tdz)는 "선언보다 먼저 쓰면 왜 어떤 건 `undefined`이고 어떤 건 에러인가"에 답한다. 함수 선언을 `const` 화살표 함수로 바꿨을 때, 순환 import에서 `Cannot access before initialization`이 나는 이유가 여기 있다.

## 02 데이터 타입

[원시값과 참조](/posts/js-primitive-vs-reference)는 "함수에 객체를 넘기면 무엇이 복사되나"에 답한다. 위 장바구니 1번 줄처럼 사본을 고쳤는데 원본이 바뀌는 버그의 뿌리이고, 뒤의 복사와 불변성 장 전체가 이 글을 전제로 한다.

[==와 ===, 타입 변환](/posts/js-equality-coercion)은 "`select`에서 고른 `"5"`로 id `5`인 상품을 왜 못 찾나"에 답한다. 느슨한 비교가 값을 바꾸는 순서와 `NaN`, `-0` 같은 예외를 다룬다.

[truthy·falsy와 typeof](/posts/js-truthy-falsy-typeof)는 "`typeof`로 객체인지 확인했는데 왜 `null`에서 터지나"에 답한다. falsy 여덟 개, `null`과 `undefined`가 생기는 자리, React 화면에 찍히는 `0`까지 따라간다.

## 03 함수 1: 만들고 넘기고 기억하기

[함수를 만드는 방법](/posts/js-function-forms)은 "`function`을 화살표 함수로 바꾸면 무엇이 깨지나"에 답한다. 문법마다 `this`, `arguments`, `new`가 어떻게 다른지 정리한다.

[일급 함수와 콜백](/posts/js-first-class-callbacks)은 "함수를 값으로 넘길 때 받는 쪽은 무엇을 보나"에 답한다. 래퍼로 감싼 Express 에러 처리기가 왜 불리지 않는지(`fn.length`), 메서드를 넘길 때 사라지는 `this`를 다룬다.

[클로저](/posts/js-closures)는 "React 타이머가 왜 1에서 멈추나"에 답한다. 클로저는 값이 아니라 변수를 잡는다는 것, 오래된 클로저를 업데이터 함수와 의존성으로 고치는 장면이 이 글의 중심이다.

## 04 함수 2: 조합과 재사용

[IIFE와 모듈 패턴](/posts/js-iife-module-pattern)은 "모듈 시스템이 없던 시절 파일마다 스코프를 어떻게 만들었나"에 답한다. 번들러 출력과 UMD를 읽을 때, effect 안에서 async 함수를 바로 부를 때 다시 만난다.

[커링과 부분 적용](/posts/js-currying-partial)은 "인자를 지금 받고 실행은 나중에 하려면"에 답한다. 범용 `curry`가 깨지는 경우와, React 핸들러를 커링으로 만들면 `memo`가 깨지는 이유를 본다.

[순수 함수와 부수 효과](/posts/js-pure-functions)는 "같은 입력에 같은 결과가 왜 테스트와 캐시와 React 렌더링의 전제인가"에 답한다. 숨은 입력과 숨은 출력을 찾아 바깥으로 모으는 법을 다룬다.

[메모이제이션](/posts/js-memoization)은 "기억해 둔 답이 언제 틀린 답을 빠르게 내나"에 답한다. 캐시 키 설계, 버리지 않는 캐시의 누수, 칸 하나짜리 캐시인 `useMemo`까지 간다.

## 05 배열

[map, filter, reduce, flatMap](/posts/js-array-transform)은 "빈 장바구니에서 `reduce`가 왜 터지나"에 답한다. 메서드마다 무엇을 돌려주는지, `map(parseInt)`와 빈 배열의 `every` 같은 함정을 정리한다.

[배열을 고치는 메서드와 사본을 주는 메서드](/posts/js-array-mutation)는 "`push` 후 `setItems`를 불렀는데 화면이 왜 안 바뀌나", 그리고 위 3번 줄의 `sort`가 왜 10을 1 뒤에 두나에 답한다. ES2023의 `toSorted`와 `with`가 여기 있다.

## 06 객체와 구조 분해

[객체 메서드](/posts/js-object-methods)는 "`Object.keys`가 서버가 보낸 키 순서를 왜 바꾸나"에 답한다. 속성 설명자, getter와 setter, `freeze`와 `seal`의 차이를 실행 결과로 본다.

[구조 분해](/posts/js-destructuring)는 "옵션을 안 넘기거나 `null`을 넘기면 왜 터지나"에 답한다. 기본값이 `undefined`에만 반응한다는 규칙과, props 기본값 `{}`가 만드는 무한 effect를 다룬다.

[전개와 나머지 문법](/posts/js-spread-rest)은 "`Math.max(...prices)`가 왜 13만 개에서 스택을 넘기나"에 답한다. 같은 점 세 개가 자리마다 반대로 동작하는 것과, `reduce` 안의 전개가 n²이 되는 비용을 본다.

## 07 복사와 불변성

[얕은 복사와 깊은 복사](/posts/js-shallow-deep-copy)는 "편집 폼에서 취소했는데 왜 원본이 바뀌나"에 답한다. 위 1번 줄의 `{ ...cart }`가 몇 층까지 새로 만드는지, `structuredClone`이 무엇을 바꾸는지 잰다.

[React 상태를 불변으로 바꾸기](/posts/js-immutability-react)는 "바깥만 새로 만들었더니 `memo` 자식이 왜 옛 값을 보이나"에 답한다. 바뀐 길만 새로 만드는 구조 공유와 Immer의 동작을 따라간다.

## 08 최신 문법

[템플릿 리터럴과 태그된 템플릿](/posts/js-template-literals)은 "`${user}`가 왜 `[object Object]`로 찍히나", 그리고 태그 함수로 SQL 인젝션과 XSS를 어떻게 막나에 답한다.

[옵셔널 체이닝과 ??](/posts/js-optional-chaining-nullish)는 "`shipping: null` 하나에 왜 화면이 하얘지나"에 답한다. 위 2번 줄처럼 `??`와 `||`가 갈리는 값이 무엇인지가 이 글의 중심이다.

[단락 평가](/posts/js-short-circuit)는 "`&&`로 렌더링했더니 화면에 왜 `0`이 찍히나"에 답한다. `&&`와 `||`가 불리언이 아니라 피연산자를 그대로 돌려준다는 규칙을 따라간다.

[ES 모듈](/posts/js-es-modules)은 "같은 카운터가 ESM에서는 2, CommonJS에서는 0인 이유"에 답한다. 라이브 바인딩, 평가 순서, Node 22의 `require(esm)`까지 다룬다.

다섯 가지 응답을 넣고 Node 22에서 돌린 결과다.

```text
undefined → []
{"data":null} → []
{"data":{}} → []
{"data":{"items":null}} → null
{"data":{"items":[1]}} → [1]
```

네 번째 줄이 함정이다. 서버가 `items: null`을 보내면 기본값이 끼어들지 않아 `items.map`에서 터진다. 기본값은 `undefined`에만 반응한다.

## 09 this, 프로토타입, 객체 지향

[this 바인딩](/posts/js-this-binding)은 "메서드를 변수에 담거나 `setTimeout`에 넘기면 왜 터지나"에 답한다. 위 5번 줄의 `TypeError`가 정확히 이 장면이고, `this`가 함수가 아니라 호출에 붙는다는 네 가지 규칙을 따라간다.

[call, apply, bind](/posts/js-call-apply-bind)는 "`bind`를 두 번 부르면 왜 리스너가 안 떨어지나"에 답한다. 바운드 함수의 정체와 `apply`의 인자 수 한계를 본다.

[프로토타입 체인](/posts/js-prototype-chain)은 "`constructor`라는 단어에서 단어 세기 함수가 왜 깨지나"에 답한다. 읽기는 체인을 올라가고 쓰기는 제자리에 만든다는 규칙, 프로토타입 오염 공격을 다룬다.

[클래스와 상속](/posts/js-classes)은 "부모 생성자에서 부른 메서드가 왜 하위 클래스 필드를 `undefined`로 보나"에 답한다. 생성 순서, `#private`와 TypeScript `private`의 차이를 본다.

[strict 모드](/posts/js-strict-mode)는 "오타 하나로 전역 변수가 생기고 합계가 0이 되는 이유"에 답한다. 위 5번 줄이 `undefined`의 `sum`을 읽다 터진 것도 ES 모듈이 늘 strict 모드라서다. 느슨한 모드였다면 전역 객체에 `sum`이 조용히 생겼다.

## 10 비동기

[콜백 지옥](/posts/js-callback-hell)은 "들여쓰기보다 무서운 게 뭔가"에 답한다. 응답을 두 번 보내는 서버 버그로 제어의 역전을 보고, `util.promisify`로 옮기는 법을 다룬다.

[Promise](/posts/js-promises)는 "`then`이 돌려주는 건 무엇이고 에러는 어디로 흐르나"에 답한다. 상태가 한 번만 정해진다는 규칙, 처리되지 않은 거부가 Node와 브라우저에서 어떻게 다뤄지는지를 본다.

[async/await](/posts/js-async-await)는 "`forEach` 안의 `await`가 왜 기다리지 않나"에 답한다. 차례대로와 동시 실행, 동시성 제한, effect 안에서 쓰는 법이 이어진다.

[Promise.all, allSettled, race, any](/posts/js-promise-combinators)는 "위젯 하나의 실패가 왜 대시보드 전체를 죽이나"에 답한다. 네 함수가 각각 어떤 질문에 답하는지와, `race` 타임아웃이 아무것도 멈추지 않는 이유를 본다.

## 11 자바스크립트가 실행되는 방식

[실행 컨텍스트와 콜 스택](/posts/js-execution-context)은 "함수를 부를 때마다 엔진이 무엇을 쌓고, 왜 넘치나"에 답한다. 스택 오버플로를 힙으로 옮겨 고치는 법과 `await` 너머의 스택 트레이스 읽기가 있다.

[이벤트 루프](/posts/event-loop)는 "스택이 하나뿐인데 기다리는 일은 누가 하나, 화면은 언제 그려지나"에 답한다. 위 출력에서 `8 sync end`가 `7 then`보다, `7 then`이 `6 timer`보다 먼저인 이유가 여기 있고, 긴 작업이 INP를 망치는 모습과 Node의 단계도 다룬다.

[마이크로태스크와 매크로태스크](/posts/js-microtask-macrotask)는 이벤트 루프 글의 다음 편으로, "복잡한 출력 순서 퍼즐을 어떻게 틀리지 않고 푸나"에 답한다. 대기열을 장부로 적어 가며 `then` 체인과 `await`를 푼다.

[타이머는 왜 늦게 울리나](/posts/js-timers-accuracy)는 "`setTimeout(fn, 1000)`이 왜 1초 뒤가 아닌가"에 답한다. 4ms 규칙, 백그라운드 탭 스로틀링, `requestAnimationFrame`을 실측으로 본다.

[가비지 컬렉션](/posts/garbage-collection)은 "엔진은 무엇을 쓰레기로 보고, 치우는 동안 왜 멈추나"에 답한다. V8의 세대별 GC 로그와, 컨테이너 메모리 한도에서 로그 없이 죽는 경우까지 간다.

[메모리 누수 찾기](/posts/js-memory-leak)는 "오래 켜 둔 탭이 왜 점점 무거워지나"에 답한다. 떼지 않은 리스너, 문서에서 떨어진 DOM, 끝없이 자라는 캐시를 힙 스냅샷으로 찾는 순서가 있다.

## 12 브라우저, DOM, 이벤트

[DOM 기초](/posts/dom-basics)는 "DOM을 바꾸는 것보다 무엇이 더 비싸나"에 답한다. 살아 있는 목록과 찍어 둔 목록, 바꾼 직후 크기를 읽을 때 생기는 강제 레이아웃을 횟수로 확인한다.

[이벤트 전파](/posts/event-propagation)는 "클릭 하나가 어디로 내려갔다 올라오나, `stopPropagation`과 `preventDefault`는 각각 무엇을 막나"에 답한다.

[이벤트 위임](/posts/event-delegation)은 "나중에 붙은 버튼은 왜 클릭이 안 먹나"에 답한다. 부모 하나가 받는 구조와, React가 이미 루트에서 그렇게 하고 있다는 것을 본다.

[디바운스와 스로틀](/posts/debounce-throttle)은 "입력마다 요청이 나가는 검색창을 어떻게 진정시키나"에 답한다. React에서 디바운스가 망가지는 이유와, 디바운스로 풀리지 않는 응답 순서 문제를 짚는다.

[fetch 제대로 쓰기](/posts/browser-fetch)는 "500이 왔는데 `fetch`는 왜 성공하나"에 답한다. 한 번만 읽히는 본문, 늦게 온 응답이 화면을 덮는 경쟁, 재시도를 다룬다.

[AbortController로 취소 설계하기](/posts/abort-controller)는 fetch 글의 다음 편으로, "`abort()`를 불렀는데 왜 옛 응답이 화면을 덮나"에 답한다. 신호를 받는 함수 만들기, React effect의 취소, 서버까지 취소를 잇는 법을 본다.

[브라우저 저장소](/posts/browser-storage)는 "`localStorage`에 넣은 `false`가 왜 참이 되나, 토큰은 어디에 두나"에 답한다. 동기 API의 멈춤, `storage` 이벤트, 출처 범위, XSS가 읽어 가는 것을 비교한다.

[CORS](/posts/cors)는 "서버는 응답했는데 브라우저가 왜 막나"에 답한다. 같은 출처 정책, preflight, credentials를 정리한다. 저장소 글의 출처 개념과 같은 규칙이다.

`Cannot access 'x' before initialization`이 난다. [호이스팅과 TDZ](/posts/js-hoisting-tdz)를 펴고, import 순환이 있는지 본다.

id로 찾는데 분명히 있는 항목이 안 나온다. 문자열 `"5"`와 숫자 `5`를 비교하고 있지 않은지 [타입 변환 글](/posts/js-equality-coercion)에서 확인한다.

`Cannot read properties of null`로 화면이 하얘진다. 어느 단계에서 `null`이 생겼는지 [옵셔널 체이닝 글](/posts/js-optional-chaining-nullish)을 보되, 물음표로 덮기 전에 그 `null`이 정상인지부터 따진다.

목록에 `0`이 찍힌다. [단락 평가](/posts/js-short-circuit)다.

`forEach` 안에서 `await`했는데 다음 줄이 먼저 돈다. [async/await](/posts/js-async-await)다.

`Maximum call stack size exceeded`가 난다. 재귀 깊이인지 큰 배열 전개인지 [실행 컨텍스트 글](/posts/js-execution-context)과 [전개 문법 글](/posts/js-spread-rest)에서 가린다.

클릭이 안 먹는 버튼이 있다. 나중에 붙은 요소면 [이벤트 위임](/posts/event-delegation), 다른 요소가 막고 있으면 [이벤트 전파](/posts/event-propagation)다.

입력이 버벅인다. 입력마다 무거운 일을 하면 [디바운스와 스로틀](/posts/debounce-throttle), 저장할 때마다 멈추면 [브라우저 저장소](/posts/browser-storage)의 동기 API 부분을 본다.

`fetch`가 500인데 `catch`로 안 간다. [fetch 제대로 쓰기](/posts/browser-fetch)다. 콘솔에 `Access-Control-Allow-Origin`이 보이면 [CORS](/posts/cors)다.

## 다 읽지 않아도 된다

처음 장면의 열 줄짜리 코드에 여섯 장이 들어 있었던 것처럼, 자바스크립트 버그는 대개 두세 장의 규칙이 겹친 자리에서 난다. 그래서 이 지도는 순서대로 읽는 길과 증상에서 거꾸로 찾는 길을 함께 놓았다. 각 글의 첫 장면을 보고 "이건 이미 안다"면 넘어가고, 낯설면 그 글부터 읽는다. 읽고 나서 처음 코드의 출력 열 줄을 다시 보고, 줄마다 이유를 자기 말로 설명할 수 있으면 이 지도가 할 일은 끝났다.

## 면접에서 나올 만한 질문

### 위 장바구니 코드에서 출력 순서가 8, 7, 6인 이유를 설명해 보라

동기 코드가 먼저 끝까지 돌고, 그다음 마이크로태스크 큐, 그다음 태스크 큐 순서로 실행되기 때문이다. `console.log("8 sync end")`는 동기 코드라 먼저 찍힌다. `then` 콜백은 마이크로태스크라서 콜 스택이 비자마자 실행되고, `setTimeout` 콜백은 태스크라서 그 뒤에 하나씩 실행된다. 자세한 순서는 이벤트 루프 글과 마이크로태스크 글에 있다.

### 왜 타이머 세 개가 모두 3을 찍나요? 어떻게 고치나요?

`var`는 함수 단위로 변수 하나만 만들어서, 세 콜백이 같은 `i`를 잡고 있다가 반복이 끝난 뒤의 값 3을 읽는다. `let`으로 바꾸면 반복마다 새 바인딩이 생겨 0, 1, 2가 찍힌다. 클로저가 값이 아니라 변수를 잡는다는 규칙과 함께 설명하면 꼬리 질문까지 이어진다.

### `{ ...cart }`로 복사했는데 왜 원본 items가 바뀌었나요?

객체 전개는 얕은 복사라서 바깥 객체만 새로 만들고, 안쪽 `items` 배열은 같은 참조를 공유한다. 사본의 `items`에 `push`하면 원본의 `items`도 같은 배열이라 함께 바뀐다. React에서는 바뀌는 길을 따라 배열까지 새로 만들어야 하고, 정말 독립된 사본이 필요하면 `structuredClone`을 쓴다.

### 메서드를 변수에 담아 부르면 왜 this가 undefined인가요?

`this`는 함수를 정의한 자리가 아니라 부르는 방식이 정하기 때문이다. `total.add()`처럼 점으로 부르면 `total`이 `this`지만, `add()`처럼 점 없이 부르면 기본 바인딩이 적용되고, strict 모드(ES 모듈과 클래스는 항상 strict)에서는 `undefined`가 된다. `bind`로 묶거나 화살표 함수로 감싸서 고친다.

### 자바스크립트를 처음 배우는 사람에게 어떤 순서를 권하나요?

변수와 스코프, 타입과 참조로 바닥을 깔고, 함수와 클로저, 객체와 배열과 복사, this와 프로토타입, 비동기, 실행 방식, 브라우저 순으로 권한다. 클로저는 스코프를, 불변 업데이트는 참조를, async/await는 Promise를 전제로 하기 때문이다. 이미 실무에서 쓰는 사람이라면 증상에서 거꾸로 들어가는 편이 빠르다.

### React를 잘 쓰려면 자바스크립트의 어느 부분이 특히 중요한가요?

참조와 얕은 복사, 클로저, 단락 평가, 비동기 취소다. React는 상태를 참조로 비교하니 배열과 객체를 사본으로 바꿔야 다시 그리고, 핸들러와 effect는 그 렌더의 값을 클로저로 잡는다. `&&` 렌더링은 `0`을 찍을 수 있고, effect의 요청은 정리 함수에서 취소해야 늦은 응답이 화면을 덮지 않는다.
