## 같은 속도로 날아가는 소행성들

정수 배열 `asteroids`가 한 줄에 놓인 소행성을 나타낸다. 절댓값이 크기, 부호가 방향이다. 양수는 오른쪽, 음수는 왼쪽으로 간다. 0은 없다. 모든 소행성은 같은 속도로 움직인다.

두 소행성이 만나면 작은 쪽이 터진다. 크기가 같으면 둘 다 터진다. 같은 방향으로 가는 소행성끼리는 속도가 같으니 영원히 만나지 않는다. 모든 충돌이 끝난 뒤 남은 소행성을 원래 순서대로 돌려준다.

배열 길이는 2 이상 10^4 이하, 크기는 1000 이하다. O(n²) 시뮬레이션도 1억 번 언저리라 겨우 돌아가지만, 스택으로 O(n)에 깔끔하게 풀린다.

결과가 빈 배열일 수도 있다. 모두 짝을 이뤄 터지면 아무것도 남지 않는다. `[8, -8]`이 그런 입력이다.

왼쪽이 양수, 오른쪽이 음수일 때만 충돌한다. 왼쪽이 음수이고 오른쪽이 양수면 서로 멀어진다. 이 문제에서 가장 많이 하는 실수가 "부호가 다르면 충돌"이라고 짜는 것인데, `[-2, -1, 1, 2]`는 부호가 바뀌는 자리가 있어도 아무도 부딪히지 않는다.

이 관찰에서 하나가 더 나온다. 맨 왼쪽부터 이어지는 음수들은 왼쪽으로 날아가 버려서 아무와도 만나지 않는다. 맨 오른쪽까지 이어지는 양수들도 마찬가지다. 그래서 최종 결과는 언제나 "음수들 뒤에 양수들" 모양이다. 음수 뒤에 양수가 오는 건 괜찮지만, 양수 뒤에 음수가 남아 있다면 아직 충돌이 덜 끝난 것이다.

## 예시 하나를 끝까지 부숴 보기

이 글에서 계속 쓸 예시다.

```text
[4, 7, -3, 2, -7, -5, 6]
```

이웃한 "양수, 음수" 쌍을 찾아 하나씩 처리해 본다.

```text
[4, 7, -3, 2, -7, -5, 6]   7과 -3이 만난다. 7이 크다. -3이 터진다
[4, 7, 2, -7, -5, 6]       2와 -7이 만난다. -7이 크다. 2가 터진다
[4, 7, -7, -5, 6]          7과 -7이 만난다. 크기가 같다. 둘 다 터진다
[4, -5, 6]                 4와 -5가 만난다. -5가 크다. 4가 터진다
[-5, 6]                    -5는 왼쪽으로, 6은 오른쪽으로. 더 만날 쌍이 없다
```

답은 `[-5, 6]`이다. -7은 2를 부수고 계속 왼쪽으로 가다가 7과 부딪혔다. 왼쪽으로 가는 소행성 하나가 오른쪽으로 가는 소행성을 여러 개 연달아 만날 수 있다는 것, 그리고 만나는 순서가 "가까운 것부터"라는 것을 기억해 둔다. 실제 시간 순서로 따져 보자. 소행성이 배열 칸 번호 위치에 1칸 간격으로 서 있고 모두 1초에 1칸씩 움직인다고 하면 이렇다.

```text
시각 0.5   7(1칸) 과 -3(2칸) 이 1.5칸에서, 2(3칸) 와 -7(4칸) 이 3.5칸에서 동시에 부딪힌다
           → -3 터짐, 2 터짐
시각 1.5   7 과 -7 이 2.5칸에서 부딪힌다 → 둘 다 터짐
시각 2.5   4 와 -5 가 2.5칸에서 부딪힌다 → 4 터짐
이후       -5 는 왼쪽으로, 6 은 오른쪽으로 멀어진다
```

손으로 처리한 순서와 실제 시간 순서가 다르지만 남는 건 똑같이 `[-5, 6]`이다. 서로 다른 쌍의 충돌은 상대의 결과에 영향을 주지 않기 때문이다. 이 성질이 있어서 왼쪽부터 차례로 처리하는 스택 풀이가 맞는 답을 낸다. 시각을 계산할 필요가 없다는 점은 [Car Fleet](/posts/leetcode-car-fleet)과 같다.

## 이웃한 충돌 쌍을 찾을 때마다 처음부터 다시

손으로 한 걸 그대로 옮긴다. 배열을 왼쪽부터 훑어 "양수 바로 뒤 음수"인 첫 쌍을 찾고, 크기를 비교해 진 쪽을 지운다. 지운 뒤에는 처음부터 다시 훑는다. 한 번 훑어서 쌍이 없으면 끝이다.

```js
function asteroidCollision(asteroids) {
  const a = [...asteroids];
  let changed = true;
  while (changed) {
    changed = false;
    for (let i = 0; i + 1 < a.length; i++) {
      if (a[i] > 0 && a[i + 1] < 0) { // 마주 오는 이웃 쌍
        const left = a[i], right = -a[i + 1];
        if (left > right) a.splice(i + 1, 1);      // 오른쪽이 터진다
        else if (left < right) a.splice(i, 1);     // 왼쪽이 터진다
        else a.splice(i, 2);                       // 둘 다 터진다
        changed = true;
        break; // 처음부터 다시 훑는다
      }
    }
  }
  return a;
}
```

충돌이 한 번 일어날 때마다 소행성이 하나 이상 사라지니 충돌은 많아야 n번이다. 충돌마다 쌍을 찾는 데 O(n), `splice`로 지우는 데 O(n)이 들어 전체 O(n²)이다. 공간은 복사한 배열 O(n)이다.

길이 10^4로 재 봤다. 앞 절반은 `1`, 뒤 절반은 `-2`인 배열에서는 `-2`가 `1`을 하나씩 부수며 충돌이 5000번 일어나 76ms가 걸렸다. 같은 입력을 스택 풀이는 0.1ms에 끝냈다.

느린 이유는 충돌을 하나 처리하고 나서 처음부터 다시 보기 때문이다. 그런데 방금 처리한 자리 왼쪽은 이미 정리가 끝난 상태다. 새로 생길 수 있는 충돌은 방금 살아남은 소행성과 그 바로 왼쪽 이웃 사이뿐이다. 정리가 끝난 왼쪽 부분을 따로 들고 다니면 다시 볼 필요가 없다.

## 살아남은 소행성을 쌓아 두는 스택

왼쪽부터 한 번만 훑으면서, 지금까지 본 소행성들끼리 충돌을 다 끝낸 결과를 스택에 들고 간다. 새 소행성 `a`가 오면 이렇게 한다.

- `a`가 양수면 왼쪽에 있는 누구와도 만나지 않는다. 오른쪽으로 가니까. 스택에 넣는다.
- `a`가 음수이고 스택 맨 위가 양수면 둘이 만난다.
  - 맨 위가 더 작으면 맨 위가 터진다. 꺼내고, `a`는 계속 날아가 새 맨 위와 다시 비교한다.
  - 크기가 같으면 둘 다 터진다. 맨 위를 꺼내고 `a`도 버린다.
  - 맨 위가 더 크면 `a`가 터진다. `a`를 버린다.
- `a`가 음수인데 스택이 비었거나 맨 위가 음수면 아무와도 만나지 않는다. 스택에 넣는다.

-7의 장면이 두 단계에 걸쳐 있다. 하나의 소행성이 스택에서 여러 개를 꺼낼 수 있다는 것, 그래서 안쪽에 반복문이 필요하다는 게 여기서 보인다.

```js
function asteroidCollision(asteroids) {
  const stack = []; // 지금까지 본 소행성끼리 충돌을 끝낸 결과
  for (const a of asteroids) {
    let alive = true; // a가 아직 살아 있나
    // a가 왼쪽으로 가고, 맨 위가 오른쪽으로 갈 때만 만난다
    while (alive && a < 0 && stack.length && stack[stack.length - 1] > 0) {
      const top = stack[stack.length - 1];
      if (top < -a) {
        stack.pop(); // 맨 위가 작다: 맨 위가 터지고 a는 계속 간다
      } else if (top === -a) {
        stack.pop(); // 크기가 같다: 둘 다 터진다
        alive = false;
      } else {
        alive = false; // 맨 위가 크다: a가 터진다
      }
    }
    if (alive) stack.push(a);
  }
  return stack;
}
```

소행성마다 스택에 많아야 한 번 들어가고 한 번 나온다. `while`이 한 번 돌 때마다 스택에서 하나가 빠지거나 `a`가 터져 반복이 끝나니, 전체 반복 횟수는 O(n)이다. 공간은 결과를 담는 스택 O(n)이다. 안쪽에 반복문이 있는데 O(n)인 이유는 [Daily Temperatures](/posts/leetcode-daily-temperatures)의 분할 상환 설명과 같다.

### 스택은 늘 음수들 뒤에 양수들

반복문의 어느 시점에 멈춰도 스택은 "음수 몇 개, 그 뒤에 양수 몇 개" 모양이다. 스택은 지금까지 본 소행성끼리의 최종 결과이고, 앞에서 본 것처럼 최종 결과는 항상 그 모양이기 때문이다.

이 불변식이 알려 주는 게 두 가지 있다. 첫째, 새 음수 소행성이 부딪힐 상대는 스택 위쪽의 양수들뿐이고, 그 양수들을 다 부수고 나면 바로 아래는 음수이거나 바닥이다. 그래서 `while` 조건에 "맨 위가 양수"를 넣으면 거기서 멈춘다. 둘째, 스택 바닥 쪽의 음수들은 이후에 무엇이 와도 바뀌지 않는다. 왼쪽으로 날아가는 소행성이고 그 왼쪽에는 아무도 없다. 소행성이 하나씩 실시간으로 들어오는 변형이라면 이 음수들은 바로 내보내도 된다.

### 세 가지 결말을 하나의 반복문에서

음수 소행성 `a`의 결말은 셋 중 하나다. 맨 위들을 다 부수고 살아남거나, 같은 크기와 함께 사라지거나, 더 큰 것에 부딪혀 사라진다. 코드에서 `alive` 변수가 이 결말을 기억한다. 반복문이 끝났을 때 살아 있으면 넣고, 아니면 넣지 않는다.

`alive` 없이 짜면 결말을 두 군데에서 따로 처리하게 되고, 그 사이에서 같은 크기 경우를 빼먹기 쉽다. 이 실수는 뒤에서 실제로 틀리는 출력과 함께 본다.

### Python의 while-else와 Java의 배열 스택

Python에는 `while ... else`가 있다. `else`는 반복문이 `break` 없이 끝났을 때만 실행된다. "`a`가 터지면 `break`"로 쓰면 `else`가 곧 "살아남았다"가 되어 `alive` 변수가 필요 없다.

```python
from typing import List

def asteroid_collision(asteroids: List[int]) -> List[int]:
    stack = []
    for a in asteroids:
        while a < 0 and stack and stack[-1] > 0:  # 오른쪽으로 가는 맨 위와 왼쪽으로 오는 a가 만난다
            if stack[-1] < -a:
                stack.pop()       # 맨 위가 작다: 맨 위가 터지고 a는 계속 간다
                continue
            if stack[-1] == -a:
                stack.pop()       # 크기가 같다: 둘 다 터진다
            break                 # a가 터졌다 (같거나 더 작아서)
        else:
            stack.append(a)       # while이 break 없이 끝났다 = a가 살아남았다
    return stack
```

익숙하지 않은 문법이라 면접에서 쓸 때는 "`else`는 `break`가 없을 때 실행된다"고 한마디 붙인다. 헷갈린다면 JavaScript처럼 `alive` 변수를 써도 된다.

Java는 결과가 `int[]`라 스택도 `int[]`로 만들고 높이 변수 `top`을 둔다. 끝에 `Arrays.copyOf`로 높이만큼 잘라 돌려준다. `Deque<Integer>`를 쓰면 마지막에 배열로 옮기는 반복문이 하나 더 필요하고, `ArrayDeque`는 앞에서 꺼내는 방향과 뒤에서 꺼내는 방향을 헷갈리기 쉽다.

```java
import java.util.*;

class Solution {
    public int[] asteroidCollision(int[] asteroids) {
        int[] stack = new int[asteroids.length];
        int top = 0;
        for (int a : asteroids) {
            boolean alive = true;
            while (alive && a < 0 && top > 0 && stack[top - 1] > 0) {
                if (stack[top - 1] < -a) {
                    top--;               // 맨 위가 작다: 맨 위가 터진다
                } else {
                    if (stack[top - 1] == -a) top--; // 같다: 둘 다 터진다
                    alive = false;       // a가 터졌다
                }
            }
            if (alive) stack[top++] = a;
        }
        return Arrays.copyOf(stack, top); // 남은 높이만큼 잘라서 돌려준다
    }
}
```

크기가 1000 이하라 `-a`가 넘칠 일은 없다. 크기 범위가 `int` 전체라면 `-Integer.MIN_VALUE`가 다시 음수가 되니 `Math.abs` 대신 `long`으로 바꿔 비교해야 한다. 세 언어 모두 예시에서 `[-5, 6]`, `[8, -8]`에서 빈 배열, `[-2, -1, 1, 2]`에서 입력 그대로를 낸다.

## 입력 배열을 그대로 결과로 쓰기

스택 크기는 지금까지 본 소행성 수를 넘지 않는다. 그러니 입력 배열의 앞부분을 스택으로 쓰면 된다. [Evaluate Reverse Polish Notation](/posts/leetcode-evaluate-reverse-polish-notation)에서 쓴 방식과 같다. `top`은 언제나 지금 읽는 위치 `i` 이하라서 아직 읽지 않은 소행성을 덮어쓰지 않는다.

```js
function asteroidCollision(asteroids) {
  let top = 0; // asteroids[0..top-1]이 스택이다
  for (let i = 0; i < asteroids.length; i++) {
    const a = asteroids[i]; // 덮어쓰기 전에 먼저 읽어 둔다
    let alive = true;
    while (alive && a < 0 && top > 0 && asteroids[top - 1] > 0) {
      if (asteroids[top - 1] < -a) top--;
      else if (asteroids[top - 1] === -a) { top--; alive = false; }
      else alive = false;
    }
    if (alive) asteroids[top++] = a;
  }
  asteroids.length = top; // 남은 부분을 잘라 낸다
  return asteroids;
}
```

추가 공간은 O(1)이다. 결과 배열은 원래 답에 포함되니 따로 세지 않는다. 대신 입력 배열을 바꾼다. 호출한 쪽이 원래 배열을 다시 쓴다면 이 풀이는 버그가 된다. `top`이 `i`와 같은 순간에는 `asteroids[top++] = a`가 자기 자리에 같은 값을 다시 쓰는 것이라 문제가 없다. 충돌이 한 번이라도 일어나면 `top`이 `i`보다 작아지고, 그 뒤로는 이미 읽고 지나간 칸에만 쓴다.

## 오른쪽에서 왼쪽으로 읽어도 같다

충돌 규칙은 좌우 대칭이다. 그러니 배열을 오른쪽 끝에서부터 읽으면서 왼쪽으로 가는 소행성을 쌓고, 오른쪽으로 가는 소행성이 오면 맨 위의 왼쪽으로 가는 소행성들과 부딪히게 해도 된다. 끝나면 스택을 뒤집어 원래 순서로 돌린다.

```js
function asteroidCollision(asteroids) {
  const stack = []; // 오른쪽부터 본 소행성끼리의 결과. 바닥이 가장 오른쪽
  for (let i = asteroids.length - 1; i >= 0; i--) {
    const a = asteroids[i];
    let alive = true;
    // 이번엔 a가 오른쪽으로 가고 맨 위가 왼쪽으로 올 때 만난다
    while (alive && a > 0 && stack.length && stack[stack.length - 1] < 0) {
      const top = -stack[stack.length - 1];
      if (top < a) stack.pop();
      else if (top === a) { stack.pop(); alive = false; }
      else alive = false;
    }
    if (alive) stack.push(a);
  }
  return stack.reverse(); // 바닥이 오른쪽이었으니 뒤집는다
}
```

복잡도는 똑같이 O(n), O(n)이다. 방향만 바뀐 같은 풀이라 따로 쓸 일은 많지 않지만, 무작위 입력 5000개로 앞의 네 풀이를 서로 비교했을 때 결과가 모두 같았다. 면접에서 "충돌 순서가 바뀌어도 답이 같은가"를 물으면 이 대칭 풀이가 근거가 된다. 왼쪽부터 처리하든 오른쪽부터 처리하든 같은 답이 나오는 건, 서로 다른 쌍의 충돌이 서로의 결과를 바꾸지 않기 때문이다.

## 반으로 나눠 따로 정리한 뒤 합치기

오른쪽부터 읽어도 같은 답이 나온다는 건, 충돌을 처리하는 순서가 답을 바꾸지 않는다는 뜻이다. 그러면 배열을 반으로 나눠 왼쪽 절반과 오른쪽 절반을 따로 정리한 뒤 둘을 합쳐도 된다.

정리된 절반은 둘 다 "음수들 뒤에 양수들" 모양이다. 두 절반을 이어 붙이면 새로 부딪힐 수 있는 건 왼쪽 절반 끝의 양수들과 오른쪽 절반 앞의 음수들뿐이다. 왼쪽 절반의 음수들은 이미 왼쪽 끝으로 빠져나갔고, 오른쪽 절반의 양수들은 오른쪽 끝으로 빠져나간다. 그래서 합치기는 왼쪽 결과를 스택으로 삼아 오른쪽 결과의 음수들을 차례로 부딪히는 일이다.

```js
function merge(left, right) {
  // left, right는 각각 [음수들..., 양수들...] 모양으로 정리된 결과
  const res = [...left];
  let j = 0;
  for (; j < right.length && right[j] < 0; j++) { // 오른쪽 결과의 앞쪽 음수들만 부딪힌다
    const a = right[j];
    let alive = true;
    while (alive && res.length && res[res.length - 1] > 0) {
      const top = res[res.length - 1];
      if (top < -a) res.pop();
      else if (top === -a) { res.pop(); alive = false; }
      else alive = false;
    }
    if (alive) res.push(a);
  }
  for (; j < right.length; j++) res.push(right[j]); // 남은 양수들은 그대로 붙는다
  return res;
}

function solve(a, lo, hi) {
  if (hi - lo === 1) return [a[lo]]; // 소행성 하나는 그 자체로 정리된 결과
  const mid = (lo + hi) >> 1;
  return merge(solve(a, lo, mid), solve(a, mid, hi));
}

function asteroidCollision(asteroids) {
  return asteroids.length ? solve(asteroids, 0, asteroids.length) : [];
}
```

이 문제 하나만 놓고 보면 스택보다 느린 풀이다. 쓸모는 다른 데 있다. `merge`는 어떤 순서로 묶어도 같은 결과를 내는 연산이다. `merge(merge(A, B), C)`와 `merge(A, merge(B, C))`가 둘 다 A, B, C를 이어 붙인 배열의 정답이기 때문이다. 이런 연산은 데이터를 여러 조각으로 나눠 기계마다 따로 정리한 뒤 결과만 모아 합칠 수 있다. 소행성이 수십억 개라 한 기계에 다 올릴 수 없을 때 꺼낼 수 있는 방법이다.

## 다섯 풀이의 비용과 쓰임

| 풀이 | 시간 | 추가 공간 | 언제 고르나 |
|---|---|---|---|
| 충돌 쌍마다 처음부터 | O(n²) | O(n) | 규칙을 그대로 옮겨 정답을 확인할 때 |
| 스택 | O(n) | O(n) | 기본 답 |
| 입력 배열을 스택으로 | O(n) | O(1) | 입력을 바꿔도 된다고 합의한 뒤 |
| 오른쪽부터 스택 | O(n) | O(n) | 대칭성을 보여 줄 때, 오른쪽부터 데이터가 올 때 |

## 같은 크기와 터진 뒤에 틀리는 코드

### 같은 크기를 빼먹는다

```js
while (alive && a < 0 && stack.length && stack[stack.length - 1] > 0) {
  if (stack[stack.length - 1] < -a) stack.pop();
  else alive = false; // 틀림: 같을 때 맨 위도 터져야 한다
}
```

같은 크기면 `a`만 터지고 맨 위는 살아남는 코드다. `[8, -8]`에서 빈 배열 대신 `[8]`이 나왔다. 본문 예시에서는 7과 -7이 함께 사라지지 않아서, 7이 남은 채 -5를 부수고 `[4, 7, 6]`이 나왔다. 정답 `[-5, 6]`과 전혀 다른 모양이다.

### 터진 소행성을 넣어 버린다

반복문 안에서 맨 위를 꺼내기만 하고 `a`가 터졌는지는 기억하지 않은 채, 반복문이 끝나면 무조건 `a`를 넣는 코드도 흔하다.

```js
while (a < 0 && stack.length && stack[stack.length - 1] > 0 && stack[stack.length - 1] < -a) {
  stack.pop();
}
if (a < 0 && stack.length && stack[stack.length - 1] === -a) { stack.pop(); continue; }
stack.push(a); // 틀림: 맨 위가 더 커서 a가 터졌어도 넣는다
```

`[10, 2, -5]`에서 -5는 2를 부순 뒤 10에 부딪혀 터져야 하는데, 이 코드는 -5를 그대로 넣어 `[10, -5]`를 냈다. 정답은 `[10]`이다. 본문 예시에서는 7에 진 -3까지 들어가 `[4, 7, -3, -7, -5, 6]`이 나왔다. 스택에 "양수 뒤 음수"가 남아 있다는 것 자체가 틀렸다는 신호다. 불변식을 알고 있으면 이런 출력을 보는 순간 어디가 틀렸는지 짐작할 수 있다.

### 부호가 다르면 무조건 부딪힌다고 본다

`Math.sign(top) !== Math.sign(a)`로 충돌을 판단하면 왼쪽으로 가는 맨 위와 오른쪽으로 가는 새 소행성도 부딪힌다. `[-2, -1, 1, 2]`에서 입력이 그대로 나와야 하는데 빈 배열이 나왔고, 본문 예시에서는 `[6]`이 나왔다. 만나는 건 "왼쪽이 오른쪽으로, 오른쪽이 왼쪽으로" 갈 때뿐이다. 스택에서는 "맨 위가 양수이고 새 것이 음수"다.

### 음수끼리도 비교한다

`while` 조건에 `stack[stack.length - 1] > 0`을 빠뜨리면 새 음수가 맨 위의 음수와도 크기를 겨룬다. 같은 방향으로 가는 소행성은 속도가 같아 만나지 않으니, `[1, -2, -2, -2]`에서 `[-2, -2, -2]`가 나와야 한다. 크기를 `Math.abs`로 비교하면서 방향 검사를 빠뜨린 코드는 같은 크기의 -2끼리 서로 지워 `[-2]`를 냈고, `[-2, -1, 1, 2]`에서도 -1이 -2를 지워 `[-2, 1, 2]`가 나왔다.

### 빈 배열과 하나뿐인 배열을 따로 막지 않는다

스택 풀이와 입력 배열 재사용 풀이는 길이가 0이든 1이든 반복문이 그대로 돌고 맞는 답을 낸다. 따로 검사할 필요가 없다. 반으로 나눠 합치는 풀이는 다르다. `solve`가 길이 1에서 멈추도록 짰기 때문에 빈 배열을 넣으면 `hi - lo === 1`에 영영 닿지 않고 `mid`가 0에 머물러 재귀가 끝나지 않는다. 그래서 바깥 함수에서 빈 배열을 먼저 걸렀다. 원래 문제는 길이가 2 이상이라 이 경우가 테스트에 없지만, 재귀 풀이를 쓸 때는 종료 조건이 모든 길이에서 닿는지 한 번 따져 본다.

## 규칙을 바꿔 묻는 꼬리 질문

### 소행성이 하나씩 실시간으로 들어온다면

스택 풀이는 왼쪽부터 한 번 훑으니 그대로 쓸 수 있다. 앞에서 본 불변식대로 스택 바닥의 음수들은 이후에 무엇이 와도 바뀌지 않으니 바로 확정해서 내보낼 수 있다. 메모리에 들고 있어야 하는 건 스택 위쪽의 양수들뿐이다. 오른쪽으로 가는 소행성은 나중에 더 큰 음수가 오면 터질 수 있어서 끝까지 확정할 수 없다.

그래서 스트림 버전은 양수들만 스택에 들고 있다가, 음수가 스택을 다 부수고 빠져나가는 순간 그 음수를 확정 결과로 내보낸다.

```js
class AsteroidStream {
  constructor() { this.right = []; } // 아직 확정되지 않은, 오른쪽으로 가는 소행성들
  add(a) {
    if (a > 0) { this.right.push(a); return []; }
    while (this.right.length && this.right[this.right.length - 1] < -a) this.right.pop(); // 맨 위가 작다
    if (this.right.length && this.right[this.right.length - 1] === -a) { this.right.pop(); return []; } // 둘 다
    if (this.right.length) return []; // a가 터졌다
    return [a]; // 왼쪽으로 빠져나간다. 이제 확정
  }
  pending() { return [...this.right]; } // 입력이 끝나면 이것들도 결과다
}
// 4, 7, -3, 2, -7 까지는 아무것도 확정되지 않는다
// -5 → [-5] 확정, 남은 대기열 []
// 6  → [],  남은 대기열 [6]
```

예시를 넣으면 -5가 들어오는 순간 처음으로 확정 결과가 나온다. 메모리는 대기 중인 양수 수만큼만 쓴다. 양수만 계속 들어오는 입력이라면 대기열이 끝없이 커지는데, 이건 이 문제의 본질이다. 나중에 아주 큰 음수 하나가 오면 그 양수들이 전부 터질 수 있어서 미리 버릴 수 없다.

### 터진 순서나 횟수를 알려 달라면

`stack.pop()`과 `alive = false`가 일어나는 자리마다 기록을 남기면 된다. "누가 누구에게 터졌나"는 그 자리의 두 값이다. 실제 시간 순서까지 필요하다면 이야기가 달라진다. 두 소행성 사이의 거리가 다르면 충돌 시각이 다르니, 위치 정보가 주어져야 하고 [Car Fleet](/posts/leetcode-car-fleet)처럼 시각을 계산해야 한다.

### 부딪힌 뒤 이긴 쪽이 작아진다면

LeetCode 2751 Robot Collisions가 이 형태다. 로봇들이 위치와 체력, 방향을 갖고, 부딪히면 체력이 낮은 쪽이 사라지고 이긴 쪽은 체력이 1 줄어든다. 위치가 정렬돼 있지 않으니 먼저 위치로 정렬하고, 이 글의 스택 풀이에서 "맨 위가 터진다/새 것이 터진다" 자리에 체력을 1 줄이는 코드를 넣는다. 이긴 쪽이 맨 위라면 스택 안의 값을 바꾸고, 이긴 쪽이 새 것이라면 줄어든 체력으로 다음 맨 위와 다시 겨룬다.

### 속도가 서로 다르다면

같은 방향끼리도 따라잡아 부딪힐 수 있고, 충돌 순서가 결과를 바꾸게 된다. 이웃한 쌍마다 충돌 시각을 계산해 우선순위 큐에 넣고, 가장 이른 충돌부터 처리하면서 새로 이웃이 된 쌍의 시각을 다시 넣는 이벤트 시뮬레이션이 필요하다. O(n log n)이고, 우선순위 큐는 [힙 글](/posts/ds-heap)에 있다.

### 같은 것끼리 붙으면 둘 다 사라진다면

LeetCode 1047 Remove All Adjacent Duplicates In String은 문자열에서 같은 글자가 나란히 붙으면 둘 다 지우고, 지운 뒤 새로 붙은 글자도 같으면 또 지운다. 소행성 문제에서 "크기가 같으면 둘 다 터진다"만 남긴 것과 같다. 크기 비교가 없으니 반복문도 필요 없다. 새 글자가 맨 위와 같으면 꺼내고, 다르면 넣는다.

```js
function removeDuplicates(str) {
  const st = [];
  for (const c of str) {
    if (st.length && st[st.length - 1] === c) st.pop(); // 같은 글자와 만나 둘 다 사라진다
    else st.push(c);
  }
  return st.join("");
}
// "abccbd" → "ad"  (cc가 사라지면 bb가 붙고, bb도 사라진다)
```

- [Car Fleet](/posts/leetcode-car-fleet): 같은 방향으로 가는 차들이 붙는 문제. 정렬 뒤 스택이다.
- [Last Stone Weight](/posts/leetcode-last-stone-weight): 가장 무거운 두 돌을 부딪혀 차이만 남긴다. 힙으로 푼다.
- [Remove K Digits](/posts/leetcode-remove-k-digits): 새 값이 스택 맨 위를 "이길 때" 꺼내는 그리디 스택.

## 정리가 끝난 왼쪽을 들고 가는 스택

만나는 건 오른쪽으로 가는 소행성 바로 뒤에서 왼쪽으로 오는 소행성뿐이다. 왼쪽부터 훑으며 충돌이 끝난 결과를 스택에 들고 가면, 새 음수 소행성은 스택 맨 위의 양수들과만 차례로 부딪힌다. 소행성마다 한 번 들어가고 한 번 나오니 O(n)이다. 같은 크기에서 둘 다 사라지는 경우와, 새 소행성이 살아남았는지 기억해 두는 것만 놓치지 않으면 된다. 스택은 언제나 음수들 뒤에 양수들 모양이고, 이 모양이 깨진 출력은 틀린 출력이다.

## 면접에서 나올 만한 질문

### 왜 스택을 쓰나요?

새 소행성이 부딪힐 수 있는 상대는 지금까지 남은 것 중 가장 오른쪽, 곧 가장 최근에 남은 것부터다. 그걸 부수면 그다음 오른쪽 것과 부딪힌다. 가장 최근 것부터 꺼내 보는 순서가 스택과 같고, 정리가 끝난 왼쪽 부분을 다시 볼 필요가 없어 O(n)이 된다.

### 어떤 경우에 충돌이 일어나나요?

왼쪽 소행성이 오른쪽으로 가고 오른쪽 소행성이 왼쪽으로 갈 때뿐이다. 스택으로 말하면 맨 위가 양수이고 새 것이 음수일 때다. 부호가 다르다고 다 만나는 게 아니어서, 음수 뒤에 양수가 오면 서로 멀어지고 같은 방향은 속도가 같아 만나지 않는다.

### 반복문 안에 반복문이 있는데 왜 O(n)인가요?

안쪽 `while`이 한 번 돌 때마다 스택에서 소행성 하나가 빠지거나 새 소행성이 터져서 반복이 끝난다. 소행성마다 스택에 많아야 한 번 들어가고 한 번 나오니, 전체 반복 횟수의 합이 n의 상수 배를 넘지 않는다.

### 결과 배열은 어떤 모양이 되나요?

언제나 음수 몇 개 뒤에 양수 몇 개다. 양수 뒤에 음수가 있으면 아직 둘이 부딪힐 일이 남은 것이기 때문이다. 이 불변식 덕분에 새 음수는 스택 위쪽 양수만 상대하면 되고, 스택 바닥의 음수들은 확정된 결과라서 스트림 변형에서 바로 내보낼 수 있다.

### 크기가 같을 때 처리를 빼먹으면 어떻게 되나요?

맨 위가 살아남아 결과에 남는다. `[8, -8]`에서 빈 배열 대신 `[8]`이 나오고, 살아남은 그 소행성이 뒤의 소행성들과 또 부딪혀 결과 전체가 틀어진다. 같으면 맨 위를 꺼내고 새 것도 버린다.

### 추가 메모리를 줄일 수 있나요?

스택 크기가 지금까지 읽은 소행성 수를 넘지 않으니 입력 배열의 앞부분을 스택으로 쓰면 추가 공간 O(1)이다. 쓰기 전에 지금 원소를 먼저 읽어 두고, 끝에 높이만큼 잘라 낸다. 입력을 바꾸므로 그래도 되는지 먼저 확인한다.

### 소행성마다 속도가 다르면 어떻게 하나요?

같은 방향끼리도 부딪힐 수 있고 충돌 순서가 결과를 바꾼다. 이웃한 쌍의 충돌 시각을 우선순위 큐에 넣고 가장 이른 것부터 처리하면서, 새로 이웃이 된 쌍의 시각을 다시 넣는 이벤트 시뮬레이션으로 푼다. 시간은 O(n log n)이다.
