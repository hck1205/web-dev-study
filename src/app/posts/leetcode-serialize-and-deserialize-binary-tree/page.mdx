<EasyIntro>
  레고로 멋진 나무 모양 탑을 쌓았는데, 멀리 사는 친구에게 똑같은 탑을 만들어 주고 싶다. 탑을 통째로 보낼 수는 없으니 설명서를 글로 적어 보내야 한다. 블록 이름만 순서대로 적으면 친구는 어느 블록이 왼쪽에 붙고 어느 블록이 오른쪽에 붙는지 알 수 없다. 그래서 블록을 하나 적을 때마다 왼쪽 자리부터 살펴보고, 그 자리에 아무것도 없으면 "비었음"이라고 꼭 적어 둔다. 왼쪽을 다 적고 나면 오른쪽 자리도 같은 방법으로 적는다. 친구는 설명서를 앞에서부터 읽으며 블록을 놓다가 "비었음"이 나오면 그 자리를 비워 두고 다음 자리로 넘어간다. 빈자리까지 적어 두었기 때문에 친구가 헷갈릴 일이 없고, 똑같은 탑이 그대로 다시 만들어진다. 이렇게 모양을 글자로 바꾸는 걸 직렬화, 글자를 다시 모양으로 바꾸는 걸 역직렬화라고 부른다.
</EasyIntro>

메모리 안의 트리는 노드끼리 참조(메모리 주소)로 이어져 있다. 그 트리를 파일에 저장하거나, Redis에 캐시하거나, 다른 서버로 보내려면 주소는 쓸모가 없다. 받는 쪽 메모리에서는 그 주소에 아무것도 없다. 그래서 트리를 문자열 같은 평평한 데이터로 바꿔 보내고, 받는 쪽에서 똑같은 트리로 다시 세운다. 앞의 일이 직렬화(serialize), 뒤의 일이 역직렬화(deserialize)다.

[LeetCode 297. Serialize and Deserialize Binary Tree](https://leetcode.com/problems/serialize-and-deserialize-binary-tree/)가 이 두 함수를 직접 설계하는 문제다. 난이도는 Hard지만 코드가 어렵다기보다 형식을 정하는 문제라서, "어떤 정보를 적어야 모양이 유일하게 정해지나"를 설명할 수 있는지가 관건이다. 이 글은 JSON으로 통째로 적는 방법부터 시작해 순회 두 개를 함께 적기, 층 순서로 적기, 전위 순회에 빈자리를 끼워 적기, 그걸 반복문으로 옮기기, 후위 순회로 적기까지 따라가고, 마지막에는 받은 문자열을 믿으면 안 되는 이유까지 본다.

트리 순회 네 가지는 [이진 트리와 BST 글](/posts/ds-binary-tree-bst)에, 층 순서로 훑는 BFS는 [Binary Tree Level Order Traversal](/posts/leetcode-binary-tree-level-order-traversal)에 있다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 무엇을 적어야 똑같이 다시 세울 수 있나

함수 두 개를 만든다. `serialize(root)`는 트리를 문자열로 바꾸고, `deserialize(data)`는 그 문자열로 트리를 다시 만든다. 문자열 형식은 마음대로 정해도 된다. 조건은 하나, `deserialize(serialize(root))`가 원래 트리와 모양도 값도 같아야 한다. 그리고 두 함수는 서로 상태를 나눠 가지면 안 된다. 전역 변수에 트리를 숨겨 두고 꺼내 쓰는 꼼수는 금지다. 받는 쪽은 문자열만 받는다고 생각해야 한다.

제약 중 설계에 영향을 주는 것은 셋이다.

- 노드 수가 0 이상 10^4 이하다. 한쪽으로 기운 트리면 깊이가 10^4까지 간다. 재귀로 짜면 언어마다 스택이 버티는지 따져야 한다.
- 값은 -1000 이상 1000 이하다. 음수가 있으니 `-` 기호도 숫자의 일부로 읽어야 한다.
- 값이 서로 다르다는 약속이 없다. 같은 값이 여러 번 나올 수 있다. 이게 뒤에서 한 풀이를 무너뜨린다.

이 글의 예시 트리다.

```text
[5, 2, 8, null, 3]

       5
      / \
     2   8
      \
       3
```

먼저 값만 순서대로 적으면 왜 안 되는지 보자. 전위 순회(나 → 왼쪽 → 오른쪽)로 값만 적으면 `5,2,3,8`이다. 그런데 3이 2의 왼쪽인지 오른쪽인지 이 문자열만으로는 알 수 없다. 더 작은 예로, 뿌리 1에 왼쪽 자식 2가 있는 트리와 오른쪽 자식 2가 있는 트리는 둘 다 `1,2`가 된다. 값만으로는 모양이 정해지지 않는다. 모양 정보를 어떤 식으로든 더 적어야 하고, 아래 풀이들은 그 방법이 다르다.

## JSON으로 통째로 적기

JavaScript라면 가장 먼저 떠오르는 방법이다. 노드 객체가 `val`, `left`, `right`만 갖고 있으니 그대로 JSON으로 바꾸면 모양이 다 담긴다.

```js
function serialize(root) {
  return JSON.stringify(root);
}
function deserialize(data) {
  return JSON.parse(data); // TreeNode 인스턴스가 아니라 평범한 객체로 돌아온다
}
```

예시 트리는 이렇게 된다.

```text
{"val":5,"left":{"val":2,"left":null,"right":{"val":3,"left":null,"right":null}},"right":{"val":8,"left":null,"right":null}}
```

모양은 정확히 담기지만 단점이 셋 있다. 먼저 크다. 노드마다 `"val"`, `"left"`, `"right"`라는 키 이름을 반복해서 적는다. 무작위 트리 노드 1만 개로 재 보니 32만 4천 글자였고, 뒤에 나올 풀이는 6만 4천 글자였다. 다섯 배다. 둘째, 돌아온 객체가 `TreeNode` 클래스의 인스턴스가 아니다. 클래스에 메서드가 있었다면 사라진다. 셋째, `JSON.stringify`도 안에서 재귀로 내려간다. 깊이 1만짜리 일자 트리에서 `Maximum call stack size exceeded`가 났다.

무엇보다 면접에서는 이 답으로 끝낼 수 없다. 면접관이 보고 싶은 건 "모양을 담으려면 무엇이 필요한가"에 대한 내 설계다. JSON은 그 질문을 라이브러리에 떠넘긴다. 다른 언어에서는 이렇게 쓸 라이브러리가 기본으로 있지도 않다.

## 전위와 중위를 두 줄로 적기

값만으로 모양이 안 정해진다면, 순회를 두 개 적으면 어떨까. 전위 순회의 첫 값은 뿌리다. 중위 순회(왼쪽 → 나 → 오른쪽)에서 그 뿌리의 위치를 찾으면 그 왼쪽이 왼쪽 서브트리, 오른쪽이 오른쪽 서브트리다. 이걸 재귀로 반복하면 트리가 다시 선다. LeetCode 105 [Construct Binary Tree from Preorder and Inorder Traversal](/posts/leetcode-construct-tree-from-preorder-inorder)이 바로 이 복원 문제다.

```js
function serialize(root) {
  const pre = [], ino = [];
  (function walk(n) {
    if (!n) return;
    pre.push(n.val);   // 전위: 나를 먼저
    walk(n.left);
    ino.push(n.val);   // 중위: 왼쪽 다음에 나
    walk(n.right);
  })(root);
  return pre.join(",") + "|" + ino.join(",");
}

function deserialize(data) {
  const [a, b] = data.split("|");
  if (!a) return null;
  const pre = a.split(",").map(Number);
  const ino = b.split(",").map(Number);
  const pos = new Map(ino.map((v, i) => [v, i])); // 값 → 중위 위치
  let p = 0;
  function make(lo, hi) {
    if (lo > hi) return null;
    const val = pre[p++];
    const node = { val, left: null, right: null };
    const mid = pos.get(val);
    node.left = make(lo, mid - 1);
    node.right = make(mid + 1, hi);
    return node;
  }
  return make(0, ino.length - 1);
}
```

예시 트리는 `5,2,3,8|2,3,5,8`이 되고, 되돌리면 원래 트리가 나온다. 시간 O(n), 공간 O(n)이다.

그런데 이 풀이는 "값으로 중위 위치를 찾는다"에 기대고 있다. 같은 값이 두 번 나오면 위치가 하나로 정해지지 않는다. 뿌리 1에 왼쪽 자식 1이 있는 트리와 오른쪽 자식 1이 있는 트리를 적어 보면 둘 다 `1,1|1,1`이다. 문자열이 같으니 둘 중 하나는 반드시 틀리게 복원된다. 값이 겹칠 수 있는 무작위 트리 3000개로 돌려 보니 2430개가 원래 모양으로 돌아오지 않았다. 이 문제는 값이 서로 다르다는 약속이 없으니 쓸 수 없다. 게다가 값을 두 번씩 적어서 길이도 두 배다.

여기서 얻을 교훈이 있다. 값에 기대지 말고 모양 자체를 적어야 한다. 모양의 정체는 "어디가 비어 있는가"다.

## 빈자리까지 층 순서로 적기

LeetCode가 문제 입력으로 트리를 적는 방식이 이미 그 답이다. 층 순서로 훑으면서 빈자리도 `null`로 적는다. 여기서는 짧게 `#`으로 적는다.

```js
function serialize(root) {
  if (!root) return "";
  const out = [];
  const queue = [root];
  for (let head = 0; head < queue.length; head++) {
    const node = queue[head];
    if (node === null) { out.push("#"); continue; }
    out.push(String(node.val));
    queue.push(node.left, node.right); // 빈 자식도 큐에 넣어 #으로 남긴다
  }
  while (out[out.length - 1] === "#") out.pop(); // 끝에 붙은 #는 없어도 복원된다
  return out.join(",");
}

function deserialize(data) {
  if (!data) return null;
  const t = data.split(",");
  const root = { val: Number(t[0]), left: null, right: null };
  const queue = [root];
  let i = 1;
  for (let head = 0; head < queue.length && i < t.length; head++) {
    const node = queue[head]; // 이 노드의 두 자식 자리를 차례로 채운다
    if (i < t.length && t[i] !== "#") {
      node.left = { val: Number(t[i]), left: null, right: null };
      queue.push(node.left);
    }
    i++;
    if (i < t.length && t[i] !== "#") {
      node.right = { val: Number(t[i]), left: null, right: null };
      queue.push(node.right);
    }
    i++;
  }
  return root;
}
```

예시 트리는 `5,2,8,#,3`이다. 원래는 `5,2,8,#,3,#,#,#,#`인데 끝의 `#` 넷을 지웠다. 복원할 때는 큐에서 노드를 꺼낼 때마다 다음 두 토큰이 그 노드의 왼쪽, 오른쪽 자리다. 토큰이 떨어지면 남은 자리는 모두 비어 있는 것으로 본다.

빈자리를 적었으니 값이 겹쳐도 상관없다. 같은 값 1을 가진 두 트리도 `1,1`과 `1,#,1`로 갈린다. 시간 O(n), 공간은 큐 때문에 O(너비)다. 재귀가 없어서 깊이 1만, 10만짜리 일자 트리도 문제없이 돈다.

`#`는 몇 개나 적힐까. 노드가 n개인 이진 트리는 자식 자리가 2n개이고 그중 n-1개를 뿌리 아닌 노드가 차지하니, 빈자리는 정확히 n+1개다. 그래서 끝을 다듬기 전 토큰 수는 늘 2n+1개다. 끝의 `#`를 지우면 조금 줄어드는데, 꽉 찬 트리는 마지막 층 아래 빈자리가 전부 끝에 몰려 있어서 크게 줄고, 오른쪽으로 기운 일자 트리 `[4, null, 3, null, 2, ...]`처럼 빈자리가 중간에 끼면 거의 안 준다.

이 형식은 사람이 읽기 쉽고 LeetCode 입력과 같아서 디버깅하기 좋다. 코드가 조금 길다는 게 아쉬운 점이고, 다음 풀이가 같은 일을 훨씬 짧게 한다.

코드는 순회 코드에 `#` 한 줄을 더한 것뿐이다.

```js
function serialize(root) {
  const out = [];
  function walk(node) {
    if (!node) {
      out.push("#"); // 빈자리도 빠짐없이 적는다
      return;
    }
    out.push(String(node.val));
    walk(node.left);
    walk(node.right);
  }
  walk(root);
  return out.join(",");
}

function deserialize(data) {
  const tokens = data.split(",");
  let i = 0; // 다음에 읽을 토큰
  function make() {
    const t = tokens[i++];
    if (t === "#") return null; // 빈자리
    const node = { val: Number(t), left: null, right: null };
    node.left = make();  // 다음 토큰부터는 왼쪽 서브트리다
    node.right = make(); // 왼쪽이 끝난 다음부터는 오른쪽이다
    return node;
  }
  return make();
}
```

복원 함수가 직렬화 함수와 거울처럼 같은 모양이라는 게 이 풀이의 장점이다. 적을 때 "나, 왼쪽 전부, 오른쪽 전부" 순서로 적었으니, 읽을 때도 토큰 하나로 나를 만들고, 이어지는 토큰으로 왼쪽 전부를 만들고, 그다음 토큰으로 오른쪽 전부를 만든다.

왜 이 문자열이 모양을 하나로 정할까. 문법으로 쓰면 트리 T는 `#` 하나이거나, `값 T T`다. 읽는 쪽은 첫 토큰만 보면 어느 경우인지 안다. `#`면 거기서 끝이고, 값이면 뒤에 T가 정확히 두 개 온다. 왼쪽 T가 어디서 끝나는지는 그 안의 `#`가 알려 준다. 어느 순간에도 "이 토큰이 누구 자리인가"를 고민할 필요가 없으니 해석이 하나뿐이다. 그래서 값이 겹쳐도 상관없다.

복원 과정을 한 토큰씩 보자. 기억 칸은 아직 자식 자리가 비어 있어서 돌아가 채워야 하는 노드들이다. 재귀로 짜면 이게 그대로 호출 스택이다.

### 재귀가 버티지 못하는 깊이

문제는 그 O(h)다. 노드가 10^4개까지라서 일자 트리면 깊이도 10^4다. 왼쪽으로만 이어진 트리를 만들어 세 언어로 돌려 봤다.

```text
Node.js 22   깊이 8000   통과
             깊이 10000  serialize에서 RangeError: Maximum call stack size exceeded
Python 3.13  깊이 10000  RecursionError (기본 한도 1000)
Java 21      깊이 5000   통과
             깊이 10000  StackOverflowError
```

Node.js에서 같은 1만 깊이를 [Maximum Depth 글](/posts/leetcode-maximum-depth-of-binary-tree)의 한 줄 재귀는 버텼는데 여기서는 넘쳤다. 함수 안에서 배열에 넣고 문자열로 바꾸는 일이 프레임을 더 키우기 때문이다. 같은 깊이라도 재귀 함수가 무엇을 하느냐에 따라 한계가 달라진다. 채점 환경은 스택을 다르게 잡을 수 있어서 통과할 수도 있지만, 제약의 최댓값에서 내 환경이 터진다면 반복문으로 옮겨 두는 게 맞다.

## 재귀 없이 같은 문자열을 만들고 읽기

직렬화는 전위 순회를 스택으로 옮기면 된다. 꺼낸 노드를 적고, 오른쪽 자식을 먼저 넣고 왼쪽을 나중에 넣는다. 그래야 왼쪽이 먼저 나온다. 빈 자식도 스택에 넣어서 꺼낼 때 `#`로 적는다.

복원은 위 그림의 기억 칸을 그대로 스택으로 만든다. 스택에는 `[노드, 이미 채운 자식 수]`를 넣는다. 토큰을 하나 읽을 때마다 맨 위 노드의 다음 빈자리에 붙이고, 두 자리를 다 채운 노드는 꺼낸다. 새로 만든 노드가 있으면 그 노드의 자리를 먼저 채워야 하니 스택에 올린다.

```js
function serialize(root) {
  const out = [];
  const stack = [root];
  while (stack.length) {
    const node = stack.pop();
    if (!node) { out.push("#"); continue; }
    out.push(String(node.val));
    stack.push(node.right, node.left); // 왼쪽이 먼저 나오게 오른쪽부터
  }
  return out.join(",");
}

function deserialize(data) {
  const tokens = data.split(",");
  if (tokens[0] === "#") return null;
  const root = { val: Number(tokens[0]), left: null, right: null };
  const stack = [[root, 0]]; // [노드, 이미 채운 자식 수]
  for (let i = 1; i < tokens.length; i++) {
    const top = stack[stack.length - 1];
    const child = tokens[i] === "#" ? null : { val: Number(tokens[i]), left: null, right: null };
    if (top[1] === 0) top[0].left = child;
    else top[0].right = child;
    top[1]++;
    if (top[1] === 2) stack.pop();      // 두 자리를 다 채웠다
    if (child) stack.push([child, 0]); // 새 노드의 자리를 먼저 채운다
  }
  return root;
}
```

같은 입력에 재귀 버전과 똑같은 문자열이 나온다. 무작위 트리 3000개로 대조했고, 깊이 10만짜리 일자 트리도 왕복이 됐다. 스택은 힙 메모리에 있어서 깊이 제한을 받지 않는다. 시간 O(n), 공간 O(h)로 재귀와 같다.

### Python과 Java로 쓰면

Python은 재귀 한도가 1000이라 반복 버전을 쓰는 편이 안전하다.

```python
from typing import Optional

class Codec:
    def serialize(self, root: Optional[TreeNode]) -> str:
        out = []
        stack = [root]
        while stack:
            node = stack.pop()
            if node is None:
                out.append("#")
                continue
            out.append(str(node.val))
            stack.append(node.right)  # 왼쪽이 먼저 나오게 오른쪽부터 넣는다
            stack.append(node.left)
        return ",".join(out)

    def deserialize(self, data: str) -> Optional[TreeNode]:
        tokens = data.split(",")
        if tokens[0] == "#":
            return None
        root = TreeNode(int(tokens[0]))
        stack = [[root, 0]]  # [노드, 이미 채운 자식 수]
        for t in tokens[1:]:
            top = stack[-1]
            child = None if t == "#" else TreeNode(int(t))
            if top[1] == 0:
                top[0].left = child
            else:
                top[0].right = child
            top[1] += 1
            if top[1] == 2:
                stack.pop()  # 두 자식을 다 채웠다
            if child:
                stack.append([child, 0])
        return root
```

재귀로 쓴다면 `iter(data.split(","))`로 만든 반복자를 `next()`로 하나씩 읽는 방식이 깔끔하다. 다만 깊이 1만 일자 트리에서 `RecursionError`가 났다.

Java는 재귀 버전을 보자. 언어 차이가 잘 드러난다.

```java
public class Codec {
    public String serialize(TreeNode root) {
        StringBuilder sb = new StringBuilder();
        write(root, sb);
        sb.setLength(sb.length() - 1); // 마지막 쉼표를 지운다
        return sb.toString();
    }

    private void write(TreeNode node, StringBuilder sb) {
        if (node == null) { sb.append("#,"); return; }
        sb.append(node.val).append(',');
        write(node.left, sb);
        write(node.right, sb);
    }

    private int pos;

    public TreeNode deserialize(String data) {
        String[] tokens = data.split(",");
        pos = 0;
        return read(tokens);
    }

    private TreeNode read(String[] tokens) {
        String t = tokens[pos++];
        if (t.equals("#")) return null; // == 로 비교하면 안 된다
        TreeNode node = new TreeNode(Integer.parseInt(t));
        node.left = read(tokens);
        node.right = read(tokens);
        return node;
    }
}
```

Java에서 짚을 곳이 셋이다. 문자열을 `+`로 이어 붙이면 붙일 때마다 새 문자열을 만들어 O(n²)이 되니 `StringBuilder`를 쓴다. 토큰 비교는 `equals`로 한다. `split`으로 잘라 낸 `"#"`는 리터럴 `"#"`와 다른 객체라 `==`가 `false`다(`new String("#") == "#"`도 `false`가 나왔다). 그리고 `split(",")`은 끝의 빈 문자열을 버린다. 끝에 쉼표를 남겨 둬도 여기서는 우연히 맞지만, 빈 토큰에 의미를 두는 형식이라면 `split(",", -1)`을 써야 한다. 깊이 1만에서는 이 재귀도 `StackOverflowError`가 났으니, 실제로는 위 Python과 같은 반복 구조로 옮기거나 큰 스택을 가진 스레드에서 돌린다.

## 후위 순회로 적고 뒤에서부터 읽기

전위 대신 후위 순회(왼쪽 → 오른쪽 → 나)로 적어도 된다. 예시 트리는 `#,#,#,3,2,#,#,8,5`가 된다. 뿌리가 맨 끝에 오니, 복원은 뒤에서부터 읽는다. 뒤에서 읽으면 순서가 "나 → 오른쪽 → 왼쪽"이 되므로 오른쪽 서브트리를 먼저 만든다.

```js
function serialize(root) {
  const out = [];
  (function walk(n) {
    if (!n) { out.push("#"); return; }
    walk(n.left);
    walk(n.right);
    out.push(String(n.val)); // 나를 마지막에
  })(root);
  return out.join(",");
}

function deserialize(data) {
  const tokens = data.split(",");
  let i = tokens.length - 1; // 뒤에서부터 읽는다
  function make() {
    const t = tokens[i--];
    if (t === "#") return null;
    const node = { val: Number(t), left: null, right: null };
    node.right = make(); // 뒤에서 읽으면 나 → 오른쪽 → 왼쪽 순서다
    node.left = make();
    return node;
  }
  return make();
}
```

길이와 복잡도는 전위와 같다. 일부러 고를 이유는 많지 않지만, "중위 순회에 빈자리를 끼우면 되나"라는 질문에 답할 때 쓸모가 있다. 중위는 안 된다. 뿌리 1에 왼쪽 자식 2가 있는 트리와, 뿌리 2에 오른쪽 자식 1이 있는 트리는 빈자리를 끼운 중위가 둘 다 `#,2,#,1,#`이다. 전위와 후위는 뿌리가 맨 앞이나 맨 끝이라 어디서 시작할지 알지만, 중위는 뿌리가 가운데 어딘가에 묻혀 찾을 방법이 없다.

## 받은 문자열을 그대로 믿으면

LeetCode는 내 `serialize`가 만든 문자열만 `deserialize`에 넣어 주지만, 실무에서 문자열은 파일, 캐시, 네트워크를 거쳐 온다. 잘리거나, 다른 버전 코드가 만들었거나, 누군가 일부러 조작했을 수 있다. 위 재귀 `deserialize`에 망가진 문자열을 넣어 봤다.

```text
"1,2"        RangeError: Maximum call stack size exceeded
"1,x,#,#"    RangeError: Maximum call stack size exceeded
"1,#,#,9"    {"val":1,"left":null,"right":null}  (뒤의 9는 조용히 버려진다)
```

토큰이 모자라면 `tokens[i++]`가 `undefined`가 되는데, `undefined`는 `"#"`가 아니라서 `Number(undefined)`, 즉 `NaN` 값의 노드를 만들고 끝없이 내려간다. 스택이 넘쳐 `RangeError`로 멈추는 걸 다행이라 해야 할 정도다. 숫자가 아닌 토큰도 `NaN` 노드가 되어 뒤의 토큰을 엉뚱한 자리에 끼운다. 남는 토큰은 에러 없이 무시된다. 셋 다 앞에서 본 "채울 자리가 0이 되는 순간 토큰도 끝나야 한다"를 확인하면 잡힌다.

```js
function deserialize(data) {
  const tokens = data.split(",");
  let i = 0;
  function make() {
    if (i >= tokens.length) throw new Error("토큰이 모자란다");
    const t = tokens[i++];
    if (t === "#") return null;
    const val = Number(t);
    if (!Number.isInteger(val)) throw new Error("숫자가 아닌 토큰: " + t);
    const node = { val, left: null, right: null };
    node.left = make();
    node.right = make();
    return node;
  }
  const root = make();
  if (i !== tokens.length) throw new Error("토큰이 남는다"); // 다 읽었어야 한다
  return root;
}
// "1,2" → 토큰이 모자란다,  "1,x,#,#" → 숫자가 아닌 토큰: x,  "1,#,#,9" → 토큰이 남는다
```

검증을 넣어도 남는 공격이 있다. `1,1,1,1,…`처럼 값만 수십만 개 이어진 문자열은 형식상 올바른 깊은 트리라서, 재귀 복원은 스택을 터뜨리고 반복 복원은 메모리를 잡아먹는다. 신뢰할 수 없는 입력이라면 문자열 길이와 깊이에 상한을 두고, 복원은 반복문으로 한다. 많은 JSON 파서가 중첩 깊이에 상한을 두는 것도 같은 이유다.

구분자도 형식의 일부다. 쉼표 없이 이어 붙이면 `[1, 23]`과 `[12, 3]`이 둘 다 `123###`이 되어 구분할 수 없다. 값에 쉼표가 들어갈 수 있는 데이터(문자열 값)라면 이스케이프 규칙이나 길이를 앞에 붙이는 방식이 필요하다.

## 면접관이 이어서 묻는 것

### 이진 탐색 트리라면 더 짧게 적을 수 있나

LeetCode 449 Serialize and Deserialize BST다. BST는 값만으로 모양이 정해지니 `#`를 적지 않아도 된다. 전위 순회 값만 적고, 복원할 때 "이 자리에 올 수 있는 값의 범위"를 들고 내려간다. 다음 값이 범위를 벗어나면 그 자리는 빈자리다.

```js
function serialize(root) {
  const out = [];
  (function walk(n) {
    if (!n) return;
    out.push(n.val);
    walk(n.left);
    walk(n.right);
  })(root);
  return out.join(",");
}

function deserialize(data) {
  if (!data) return null;
  const vals = data.split(",").map(Number);
  let i = 0;
  function make(lo, hi) {
    // 다음 값이 이 자리의 범위를 벗어나면 여기는 빈자리다
    if (i === vals.length || vals[i] < lo || vals[i] > hi) return null;
    const node = { val: vals[i++], left: null, right: null };
    node.left = make(lo, node.val);
    node.right = make(node.val, hi);
    return node;
  }
  return make(-Infinity, Infinity);
}
// [20, 10, 30, 5, 15, 25, 35, null, null, 12, 18]
// → "20,10,5,15,12,18,30,25,35"  (# 를 끼우면 토큰 19개, 빼면 9개)
```

`#`가 n+1개 빠지니 토큰이 절반 가까이 준다. 값이 서로 다르다는 BST 조건이 있어야 성립한다. 범위를 들고 내려가는 이 모양은 [Validate Binary Search Tree](/posts/leetcode-validate-binary-search-tree)와 같다.

### 문자열이 아니라 바이트로 최대한 작게

값이 -1000~1000이라 2바이트 정수(Int16)에 들어간다. 노드마다 값 2바이트에, 왼쪽·오른쪽 자식이 있는지 2비트만 적으면 된다. 전위 순서로 값 배열과 비트 배열을 따로 적고 base64로 감쌌더니, 노드 1만 개에서 30,004글자였다. 쉼표 문자열의 절반 이하다. 비트를 쓰는 기법은 [비트 조작 글](/posts/bit-manipulation)에 있다. 실무에서는 Protocol Buffers처럼 이미 있는 이진 형식을 쓰고, 트리 구조만 그 위에 이렇게 얹는다.

### 트리가 너무 커서 한 번에 못 담는다면

전위 + `#` 형식은 앞에서부터 한 번만 읽으며 복원하니 스트리밍에 잘 맞는다. 직렬화는 토큰이 나오는 대로 흘려보내고, 복원도 청크를 받는 대로 반복 버전 스택에 먹이면 된다. 필요한 메모리는 트리 높이만큼이다. 층 순서 형식도 스트리밍은 되지만 큐가 너비만큼 커진다.

### 직렬화를 다른 문제에 쓰는 경우

서브트리를 문자열로 바꾸면 "모양과 값이 같은 서브트리"를 해시맵 키로 비교할 수 있다. LeetCode 652 Find Duplicate Subtrees는 노드마다 `값,왼쪽 문자열,오른쪽 문자열`을 키로 만들어 두 번 나온 키를 모은다. `#`를 끼워야 서로 다른 모양이 같은 키가 되지 않는다는 이 글의 논리가 그대로 쓰인다. 다만 키 문자열을 매번 새로 만들면 O(n²)이라, 키마다 정수 id를 붙여 `(값, 왼쪽 id, 오른쪽 id)`로 줄이는 최적화가 따라 나온다. LeetCode 572 Subtree of Another Tree도 직렬화한 문자열에서 부분 문자열 찾기로 풀 수 있다.

### 자식이 여러 개인 트리라면

LeetCode 428(프리미엄 문제)이다. 빈자리 표시 대신 노드마다 자식 수를 같이 적으면 된다. `값,자식 수,첫째 자식…` 꼴로 쓰면, 읽는 쪽이 몇 개의 서브트리를 이어서 읽어야 하는지 안다. 이진 트리의 `#`는 "자식 수가 정해진 자리마다 있는지 없는지"를 적은 것이고, N진 트리에서는 그 정보를 개수로 바꿔 적는 셈이다.

### 같은 패턴의 다음 문제

트리 묶음의 마지막 문제는 바텀업 재귀로 경로 합을 구하는 [Binary Tree Maximum Path Sum](/posts/leetcode-binary-tree-maximum-path-sum)이다. 순회 결과로 트리를 다시 세우는 [Construct Binary Tree from Preorder and Inorder Traversal](/posts/leetcode-construct-tree-from-preorder-inorder)도 이 글의 두 번째 풀이와 바로 이어진다. 전체 순서는 [LeetCode 공부 가이드](/posts/leetcode-study-guide)에 있다.

## 빈자리를 적어야 모양이 남는다

값만 적으면 트리 모양이 사라진다. 빈자리를 `#`로 빠짐없이 적으면, 전위 순회 문자열은 "`#` 하나이거나 값 뒤에 서브트리 둘"이라는 규칙으로 해석이 하나뿐이라 값이 겹쳐도 똑같이 되살아난다. 직렬화와 복원이 거울처럼 같은 재귀 모양이고 둘 다 O(n)이다. 노드가 n개면 `#`는 n+1개라 토큰은 2n+1개이고, 복원이 끝나는 순간 채울 자리와 토큰이 함께 바닥나야 한다는 이 성질로 망가진 입력도 걸러 낸다. 깊은 트리는 재귀가 버티지 못하니 스택이나 층 순서로 옮기고, 남이 준 문자열은 길이와 깊이에 상한을 둔다.

## 면접에서 나올 만한 질문

### 왜 빈자리를 적어야 하나요?

값만 적으면 모양이 정해지지 않는다. 뿌리 1에 왼쪽 자식 2가 있는 트리와 오른쪽 자식 2가 있는 트리는 전위 값이 둘 다 `1,2`다. 빈자리를 `#`로 적으면 `1,2,#,#,#`와 `1,#,2,#,#`로 갈린다.

### 전위 + `#` 문자열이 트리 하나로만 해석되는 이유는요?

트리를 "`#`이거나, 값 뒤에 트리 두 개"로 정의하면 읽는 쪽은 첫 토큰만 보고 어느 경우인지 안다. 값이면 왼쪽 트리를 끝까지 읽고 이어서 오른쪽 트리를 읽으면 되는데, 왼쪽이 어디서 끝나는지는 그 안의 `#`가 알려 준다. 매 순간 다음 토큰이 누구의 자리인지 정해져 있어서 해석이 하나뿐이다.

### 전위와 중위 두 줄로 적으면 안 되나요?

값이 모두 다를 때만 된다. 복원할 때 전위의 뿌리 값을 중위에서 찾아 왼쪽과 오른쪽을 나누는데, 같은 값이 여러 번 나오면 어느 위치인지 정할 수 없다. 뿌리 1에 왼쪽 자식 1인 트리와 오른쪽 자식 1인 트리는 둘 다 `1,1|1,1`이 된다. 이 문제는 값 중복을 허용하니 쓸 수 없고, 값을 두 번 적어 길이도 두 배다.

### 중위 순회에 `#`를 끼우면 되나요?

안 된다. 뿌리가 가운데 어딘가에 묻혀 있어서 어디서부터 나눌지 알 수 없다. 뿌리 1에 왼쪽 자식 2인 트리와 뿌리 2에 오른쪽 자식 1인 트리가 둘 다 `#,2,#,1,#`이 된다. 전위나 후위는 뿌리가 맨 앞이나 맨 끝이라 된다.

### 시간과 공간 복잡도는요?

노드가 n개면 빈자리가 정확히 n+1개라 토큰은 2n+1개다. 직렬화와 복원 모두 토큰마다 상수 시간 일을 해서 O(n)이고 문자열 길이도 O(n)이다. 추가 공간은 재귀나 스택 깊이로 O(h), 층 순서 형식이면 큐 때문에 O(너비)다.

### 트리가 한쪽으로 10^4 깊이로 기울면요?

재귀 직렬화가 터질 수 있다. 이 환경에서 Node.js, Python, Java 모두 깊이 1만 일자 트리에서 스택이 넘쳤다. 전위 순회를 스택으로 옮기고, 복원은 "자식 자리가 남은 노드" 스택에 토큰을 하나씩 붙이는 방식으로 바꾸거나, 층 순서 형식을 쓰면 깊이와 상관없이 돈다.

### 받은 문자열이 망가져 있으면 어떻게 되나요?

검증 없는 재귀 복원은 토큰이 모자라면 `undefined`를 값으로 읽어 끝없이 내려가다 스택 오버플로로 죽고, 남는 토큰은 조용히 버린다. 토큰이 모자라면 에러, 숫자가 아니면 에러, 복원이 끝났는데 토큰이 남으면 에러로 처리한다. 외부 입력이면 길이와 깊이 상한도 둔다.
