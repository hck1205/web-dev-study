[Car Pooling](https://leetcode.com/problems/car-pooling/)은 LeetCode 1094번이다. 동쪽으로만 가는 차 한 대가 여러 여행(몇 명이, 어디서 타서, 어디서 내리는지)을 모두 태울 수 있는지 정원과 비교해 판정한다.

구간 묶음에서 이 문제가 맡은 역할은 차분 배열이다. 필요한 회의실 수를 세는 [Meeting Rooms II](/posts/leetcode-meeting-rooms-ii)(253번, 프리미엄 문제)와 뼈대가 같지만, 회의 하나가 방 하나를 쓰는 대신 여행 하나가 여러 명을 태운다는 점이 다르다. 이 가중치 때문에 Meeting Rooms II에서 잘 통하던 "시작·끝 따로 정렬" 풀이는 여기서 쓸 수 없고, 대신 위치 범위가 좁다는 조건 덕분에 정렬 없는 O(n + L) 풀이가 주인공이 된다. 겹침과 경계값은 [구간 문제 패턴](/posts/interval-problems-pattern)에 정리했다. 코드는 Node.js 22, Python 3.13, Java 21에서 돌렸다.

## 동쪽으로만 가는 차에 다 태울 수 있나

입력은 `trips`와 `capacity`다. `trips[i] = [p, from, to]`는 p명이 위치 `from`에서 타서 위치 `to`에서 내린다는 뜻이다. 차는 위치 0에서 출발해 동쪽(위치가 커지는 쪽)으로만 가고 되돌아가지 않는다. 어느 순간에도 탄 사람이 `capacity`를 넘지 않으면 `true`다.

풀이를 고르는 데 영향을 주는 조건은 이렇다.

- 여행은 1,000개 이하다. O(n²)도 100만 번이라 통과는 한다.
- 위치는 0 이상 1,000 이하이고 `from < to`다. 위치마다 칸을 만드는 배열이 1,001칸이면 된다. 이 조건이 이 문제의 열쇠다.
- 한 여행의 인원은 100명 이하, 정원은 10^5 이하다. 모두 더해도 10^5라 32비트 정수로 충분하다.
- 손님은 `to`에서 내린다. 그래서 여행은 반쯤 열린 구간 `[from, to)`다. 위치 5에서 내리는 2명과 위치 5에서 타는 2명은 자리를 나눠 쓴다.

마지막 조건이 경계값이다. 문제 지문의 예제에도 "내리는 곳과 타는 곳이 같은" 경우가 들어 있으니 반드시 확인한다.

## 세 여행을 길 위에 쌓아 본다

capacity = 5 이면? 4 이면?

쌓인 모양의 윤곽선이 "위치별 탑승 인원" 그래프다. 답은 이 윤곽선의 가장 높은 곳이 정원 이하인지로 정해진다. 아래 풀이들은 이 윤곽선을 어떻게 빨리 그리느냐의 차이다.

## 위치를 하나씩 지나가며 센다

윤곽선을 그대로 그린다. 위치 0부터 가장 먼 `to` 직전까지, 위치마다 그 위치에 걸친 여행의 인원을 더한다.

```js
function carPooling(trips, capacity) {
  let last = 0;
  for (const [, , to] of trips) last = Math.max(last, to);
  for (let x = 0; x < last; x++) {             // 위치마다
    let load = 0;
    for (const [p, from, to] of trips) {
      if (from <= x && x < to) load += p;       // x에서 차에 타 있는 여행
    }
    if (load > capacity) return false;
  }
  return true;
}
```

`x < to`에 등호가 없는 부분이 "to에서는 이미 내렸다"를 옮긴 것이다. 위치가 L개, 여행이 n개면 시간 O(n·L), 공간 O(1)이다. 이 문제에서는 1,000 × 1,000 = 100만 번이라 여행 1,000개에서 18.6ms였다. 위치가 10억까지라면 이 방법은 쓸 수 없다.

## 태우는 곳에서만 세도 충분하다

위치를 다 볼 필요는 없다. 탑승 인원은 누군가 탈 때만 늘어난다. 그러니 가장 붐비는 순간은 반드시 어떤 여행의 `from`에서 시작된다. 위치 대신 여행의 출발점만 보면 된다.

```js
function carPooling(trips, capacity) {
  for (const [, x] of trips) {                  // 누군가 타는 위치에서만
    let load = 0;
    for (const [p, from, to] of trips) {
      if (from <= x && x < to) load += p;
    }
    if (load > capacity) return false;
  }
  return true;
}
```

시간 O(n²), 공간 O(1)이다. 위치 범위와 상관이 없어져서 위치가 10억까지여도 쓸 수 있다. 여행 1,000개에서 7.3ms였다. 두 풀이 모두 짧고 틀릴 곳이 적어서, 아래 빠른 풀이들을 무작위 입력으로 검증하는 기준으로 썼다.

같은 논리가 [Meeting Rooms II](/posts/leetcode-meeting-rooms-ii)의 "회의가 시작하는 순간마다 센다"에도 나온다. 겹침의 최댓값은 언제나 어떤 구간의 시작점에서 처음 나온다.

## 내릴 곳이 가장 가까운 손님부터 내린다

차를 실제로 몰아 보자. 여행을 타는 위치 순으로 정렬하고, 정류장에 도착할 때마다 그 전에 내릴 손님을 먼저 내린다. 지금 타 있는 손님 중 "가장 먼저 내리는 손님"을 빨리 찾으려면 내릴 곳 기준 최소 [힙](/posts/ds-heap)을 쓴다.

```js
function carPooling(trips, capacity) {
  const a = [...trips].sort((x, y) => x[1] - y[1]);   // 타는 위치 순
  const heap = new Heap((x, y) => x[0] < y[0]);       // [내릴 곳, 인원], 내릴 곳이 가까운 순
  let load = 0;
  for (const [p, from, to] of a) {
    while (heap.size && heap.peek()[0] <= from) {     // 여기 오기 전에(또는 여기서) 내리는 손님을 모두 내린다
      load -= heap.pop()[1];
    }
    load += p;                                         // 이번 손님을 태운다
    if (load > capacity) return false;
    heap.push([to, p]);
  }
  return true;
}
```

`Heap`은 비교 함수를 받는 배열 기반 이진 힙이다(`push`, `pop`, `peek`, `size`).

Meeting Rooms II의 힙 풀이와 모양이 거의 같은데 한 군데가 다르다. 거기서는 `if`로 하나만 꺼냈고, 여기서는 `while`로 내릴 손님을 모두 내린다. Meeting Rooms II는 방 하나만 있으면 새 회의를 넣을 수 있어서 하나만 꺼내도 됐다. 여기서는 내린 사람 수만큼 자리가 비는 거라 내릴 사람을 다 내려야 지금 인원이 정확하다. `[[1,0,1],[1,0,1],[3,2,3]]`, 정원 3에서 `if`로 바꾸면 위치 2에서 한 여행만 내려 1 + 3 = 4명으로 계산하고 `false`를 낸다. 답은 `true`다.

시간은 정렬 O(n log n)과 힙 연산 O(n log n)이다. 공간 O(n). 여행 1,000개에서 0.63ms였다. 위치 범위에 의존하지 않으니 좌표가 10억이어도 그대로 된다. 그리고 "지금 누가 타 있는가"를 실제로 들고 다니는 유일한 풀이라, 넘치는 순간 어떤 여행들이 타 있었는지 알려 달라는 변형에 바로 쓸 수 있다.

## 타고 내리는 사건을 줄 세운다

손님을 누구인지 구분할 필요가 없다면 힙도 필요 없다. 여행마다 "from에서 +p", "to에서 −p" 두 사건을 만들어 위치 순으로 정렬하고 차례로 더한다. [Meeting Rooms](/posts/leetcode-meeting-rooms)에서 본 스위프에서 +1, −1이 +p, −p로 바뀐 것뿐이다.

```js
function carPooling(trips, capacity) {
  const ev = [];
  for (const [p, from, to] of trips) { ev.push([from, p]); ev.push([to, -p]); }
  ev.sort((x, y) => x[0] - y[0] || x[1] - y[1]);   // 위치 순, 같은 위치면 음수(내림)가 먼저
  let load = 0;
  for (const [, d] of ev) {
    load += d;
    if (load > capacity) return false;
  }
  return true;
}
```

같은 위치의 사건은 내리는 쪽을 먼저 처리해야 한다. 두 번째 기준 `x[1] - y[1]`이 음수(−p)를 앞으로 보낸다. 거꾸로 하면 예시의 위치 5에서 2명이 먼저 타서 7명이 되고, 정원 5에서 `false`가 나온다.

Meeting Rooms II에서 쓴 "시작만, 끝만 따로 정렬해 두 포인터로 세기"가 여기서 안 되는 이유도 여기서 보인다. 그 풀이는 시작 하나와 끝 하나가 똑같이 1씩 바꾼다는 전제로 "끝난 개수"만 셌다. 여행마다 인원이 다르면 시작 배열과 끝 배열을 인원과 함께 정렬해야 하고, 그러면 그게 곧 이 사건 스위프다.

시간 O(n log n), 공간 O(n)이다. 여행 1,000개에서 0.78ms였다.

## 길이 1001짜리 장부에 적는다

위치가 0~1,000뿐이라는 조건을 쓰면 정렬조차 필요 없다. 사건을 정렬하던 일을 "위치 번호 = 배열 인덱스"가 대신한다. 길이 1,001짜리 배열 `diff`를 만들고 여행마다 `diff[from] += p`, `diff[to] -= p`를 적는다. 이걸 차분 배열이라고 부른다. 원래 값(위치별 탑승 인원)의 "이웃 사이 차이"를 적어 둔 배열이라는 뜻이다. 앞에서부터 누적 합을 구하면 원래 값이 살아난다.

```js
function carPooling(trips, capacity) {
  const diff = new Array(1001).fill(0);   // 위치 0~1000의 변화량
  for (const [p, from, to] of trips) {
    diff[from] += p;                      // 여기서 p명이 탄다
    diff[to] -= p;                        // 여기서 p명이 내린다 (to에서는 이미 내렸다)
  }
  let load = 0;                           // 지금 차에 탄 사람 수
  for (let x = 0; x <= 1000; x++) {
    load += diff[x];
    if (load > capacity) return false;
  }
  return true;
}
```

예시의 여행 셋을 적으면 `diff`의 앞 아홉 칸은 이렇게 바뀐다.

```text
[2,1,5] 적은 뒤  0, 2, 0, 0, 0, -2, 0,  0,  0
[3,3,7] 적은 뒤  0, 2, 0, 3, 0, -2, 0, -3,  0
[2,5,8] 적은 뒤  0, 2, 0, 3, 0,  0, 0, -3, -2
누적 합          0, 2, 2, 5, 5,  5, 5,  2,  0
```

위치 5의 칸이 −2 + 2 = 0이 됐다. 내리는 2명과 타는 2명이 한 칸에서 서로 지워졌다. 스위프에서 "같은 위치면 내림이 먼저"를 정렬 비교자로 챙겨야 했던 문제가 여기서는 저절로 풀린다. 한 칸 안의 더하기와 빼기는 누적 합에 한꺼번에 들어가기 때문이다.

아래 그림에서 다음을 누르면 완성된 `diff`를 앞에서부터 누적한다. 칸의 숫자는 그 위치의 변화량이고, 오른쪽 상자는 그 위치에서 차에 탄 사람 수다.

### 내리는 곳 칸에서 바로 빼는 이유

`diff[to] -= p`가 맞는 건 손님이 `to`에서 이미 내리기 때문이다. 구간이 `[from, to)`라서 `to` 칸부터 인원이 줄어든다.

구간이 양 끝을 포함하는 닫힌 구간이라면 `to + 1`에서 빼야 한다. 1109번 Corporate Flight Bookings가 그런 문제다. 예약 `[first, last, seats]`가 first번부터 last번 항공편까지 모두 좌석을 잡으니 `diff[last + 1] -= seats`다. 이 문제에 같은 코드를 쓰면 예시의 위치 5에서 내리는 2명이 아직 타 있는 것으로 계산되어 7명이 되고, 정원 5에서 `false`가 나온다. 차분 배열을 쓸 때는 먼저 "끝 칸이 구간에 들어가나"를 정한다.

## accumulate와 int[1001]로 옮긴다

차분 배열 풀이를 Python과 Java로 옮겼다.

```python
from itertools import accumulate

def car_pooling(trips, capacity):
    diff = [0] * 1001                         # 위치 0~1000
    for p, frm, to in trips:
        diff[frm] += p                        # 타는 곳에서 늘고
        diff[to] -= p                         # 내리는 곳에서 준다 (to에서는 이미 내렸다)
    return max(accumulate(diff)) <= capacity  # 누적 합이 그 위치의 탑승 인원

trips = [[2, 1, 5], [3, 3, 7], [2, 5, 8]]
print(car_pooling(trips, 5), car_pooling(trips, 4))
```

```text
True False
```

`from`은 Python 예약어라 변수 이름으로 쓸 수 없어서 `frm`으로 바꿨다. `itertools.accumulate`는 누적 합을 차례로 내놓는 반복자라 `max`에 바로 넘길 수 있다. 이 코드는 넘치는 순간에 멈추지 않고 끝까지 더한다. 칸이 1,001개뿐이라 차이가 없지만, 일찍 멈추고 싶으면 JavaScript처럼 반복문으로 쓴다.

```java
public class Main {
    static boolean carPooling(int[][] trips, int capacity) {
        int[] diff = new int[1001];              // new int[]는 0으로 채워져 있다
        for (int[] t : trips) {
            diff[t[1]] += t[0];
            diff[t[2]] -= t[0];
        }
        int load = 0;
        for (int d : diff) {
            load += d;
            if (load > capacity) return false;   // 넘치는 첫 위치에서 바로 멈춘다
        }
        return true;
    }

    public static void main(String[] args) {
        int[][] trips = {{2, 1, 5}, {3, 3, 7}, {2, 5, 8}};
        System.out.println(carPooling(trips, 5) + " " + carPooling(trips, 4));
    }
}
```

```text
true false
```

Java의 `int[]`는 0으로 초기화되니 따로 채울 필요가 없다. 인원은 최대 1,000 × 100 = 10^5라 `int`로 넘치지 않는다. 인원이나 여행 수 제한이 훨씬 크다면 누적 값이 `int` 범위(약 21억)를 넘을 수 있으니 `long`을 쓴다.

위치가 10억까지라 배열을 만들 수 없을 때는 같은 아이디어를 정렬된 맵으로 옮긴다. Java의 `TreeMap`은 키를 정렬된 순서로 돌려주니 "있는 위치만 칸으로 쓰는 차분 배열"이 된다.

```java
import java.util.*;

public class Tree {
    static boolean carPooling(int[][] trips, int capacity) {
        TreeMap<Integer, Integer> diff = new TreeMap<>();   // 위치 -> 변화량, 위치 순으로 정렬된다
        for (int[] t : trips) {
            diff.merge(t[1], t[0], Integer::sum);
            diff.merge(t[2], -t[0], Integer::sum);
        }
        int load = 0;
        for (int d : diff.values()) {                       // 키 순서대로 값을 돈다
            load += d;
            if (load > capacity) return false;
        }
        return true;
    }

    public static void main(String[] args) {
        int[][] trips = {{2, 1, 5}, {3, 3, 7}, {2, 5, 8}};
        System.out.println(carPooling(trips, 5) + " " + carPooling(trips, 4));
        System.out.println(carPooling(new int[][]{{2, 1, 1_000_000_000}, {3, 999_999_999, 1_000_000_000}}, 4));
    }
}
```

```text
true false
false
```

`merge`는 같은 위치에 내리고 타는 손님을 한 칸에 합쳐서, 차분 배열처럼 같은 위치의 순서 문제를 없앤다. 맵에 넣는 데 O(log n)씩 들어 전체 O(n log n)이다. 사실상 사건 스위프를 맵으로 한 것이다.

## 무작위 여행으로 다섯 풀이를 맞춰 본다

같은 위치에서 내리고 타는 경우는 손으로 만든 예제에서 빠지기 쉽다. 위치마다 세는 풀이를 기준으로 두고, 위치를 0~15 정도로 좁혀 무작위 여행을 많이 만들어 비교했다. 위치가 좁아야 내리는 곳과 타는 곳이 자주 겹친다.

```js
const { byLocation, heapPool, sweep, diffArray } = require("./sol.js");

function randomTrips() {
  const n = 1 + Math.floor(Math.random() * 6);
  const trips = [];
  for (let i = 0; i < n; i++) {
    const from = Math.floor(Math.random() * 10);           // 위치를 좁게: 내리고 타는 곳이 자주 겹친다
    trips.push([1 + Math.floor(Math.random() * 4), from, from + 1 + Math.floor(Math.random() * 5)]);
  }
  return trips;
}

for (let k = 1; k <= 50000; k++) {
  const trips = randomTrips();
  const cap = 1 + Math.floor(Math.random() * 8);
  const want = byLocation(trips, cap);
  for (const f of [heapPool, sweep, diffArray]) {
    if (f(trips, cap) !== want) {
      console.log(k, "번째 반례", f.name, JSON.stringify(trips), cap);
      process.exit(1);
    }
  }
}
console.log("50000개 모두 같다");
```

```text
50000개 모두 같다
```

`diff[to + 1]`에서 빼는 닫힌 구간 버그를 같은 방식으로 돌리자 33번째 입력에서 반례가 나왔다. `[[2,0,3],[2,4,5],[1,5,10],[2,4,5],[1,9,12],[3,5,8]]`, 정원 7이다. 위치 5에서 두 여행(4명)이 내리고 두 여행(4명)이 타는데, 틀린 코드는 내릴 4명을 한 칸 더 태워 두어 위치 5를 8명으로 계산하고 `false`를 냈다. 기준 풀이는 `true`다. 반례가 30여 번 만에 나온 것은 그만큼 이 경계가 흔하다는 뜻이다.

## 다섯 풀이를 위치 범위로 고른다

| 풀이 | 시간 | 공간 | 언제 고르나 |
|---|---|---|---|
| 위치마다 세기 | O(n·L) | O(1) | 검증 기준. 위치 범위가 작을 때만 |
| 타는 곳에서만 세기 | O(n²) | O(1) | 검증 기준. 위치 범위가 커도 된다 |
| 정렬 + 내릴 곳 힙 | O(n log n) | O(n) | 넘친 순간 누가 타 있었는지도 필요할 때 |
| 사건 스위프 (또는 TreeMap) | O(n log n) | O(n) | 위치가 10억까지라 배열을 못 만들 때 |
| 차분 배열 | O(n + L) | O(L) | 위치 범위가 작을 때. 이 문제의 기본 답 |

n은 여행 수, L은 위치 범위(1,001)다. 여행 1,000개에서 차분 배열 0.01ms, 힙 0.63ms, 스위프 0.78ms, 타는 곳에서만 세기 7.3ms, 위치마다 세기 18.6ms였다.

면접에서는 먼저 "위치 범위가 1,000으로 작다"는 조건을 짚고 차분 배열로 답한다. 그다음 "범위가 10억이라면"이라는 질문이 올 것을 알고 사건 스위프나 TreeMap을 준비해 둔다. 힙 풀이는 "누가 타 있는가"를 묻는 변형이 왔을 때 꺼낸다.

세 풀이가 공유하는 생각은 하나다. 탑승 인원이라는 함수의 값을 직접 구하지 않고, 값이 바뀌는 지점과 그 변화량만 기록한 뒤 순서대로 더한다. 차분 배열은 지점을 인덱스로, 스위프는 정렬로, 힙은 내릴 곳 순서로 그 순서를 만든다.

## 같은 정류장에서 내리고 타는 순서

이 문제의 버그는 거의 다 "같은 위치에서 내리는 손님과 타는 손님"에서 나온다. 예시의 위치 5가 그 자리다.

### 닫힌 구간처럼 `to + 1`에서 뺀다

```js
diff[to + 1] -= p;   // to에서도 타 있다고 본다
```

정원 5에서 `false`를 낸다. 위치 5에서 내려야 할 2명이 아직 타 있어서 2 + 3 + 2 = 7명이 됐다. 1109번처럼 끝을 포함하는 문제에서 가져온 코드를 그대로 쓰면 이렇게 된다.

### 스위프에서 타는 사건을 먼저 처리한다

```js
ev.sort((x, y) => x[0] - y[0] || y[1] - x[1]);   // 같은 위치면 양수(탐)가 먼저
```

역시 정원 5에서 `false`다. 위치 5에서 2명이 먼저 타서 잠깐 7명이 된다. 힙 풀이에서 `heap.peek()[0] < from`으로 등호를 빼도 같은 이유로 `false`가 난다. 세 풀이 모두 "to에서는 이미 내렸다"를 다른 모양으로 담고 있다.

### 힙에서 하나만 내린다

앞에서 본 대로 `while` 대신 `if`를 쓰면 한 위치에서 여러 여행이 끝날 때 일부만 내린다. Meeting Rooms II의 힙 코드를 가져와 인원만 붙이면 이 버그가 생긴다. 그 문제에서는 방 하나만 비면 충분했지만 여기서는 비는 좌석 수가 중요하다.

### 배열을 0으로 채우지 않는다

```js
const diff = new Array(1001);   // .fill(0)이 빠졌다
```

`[[5,0,1]]`, 정원 4에서 `true`를 낸다. 답은 `false`다. 빈 칸은 `undefined`라 `undefined + 5`가 `NaN`이 되고, 누적 값이 처음부터 끝까지 `NaN`이다. `NaN > 4`는 언제나 거짓이라 한 번도 넘치지 않은 것처럼 끝난다. 예외 없이 틀린 답이 나와서 찾기 어렵다. `new Array(n).fill(0)`이나 `new Int32Array(n)`을 쓴다. Python의 `[0] * 1001`, Java의 `new int[1001]`은 처음부터 0이다.

### 정원이 넘는지 마지막에 한 번만 본다

누적 합을 끝까지 구한 뒤 마지막 값만 정원과 비교하면 늘 `true`다. 모든 손님이 결국 내리니 마지막 값은 0이다. 비교는 칸마다 해야 하고, Python 코드처럼 최댓값과 비교해도 된다.

## 정류장이 10억 개라면

### 위치 범위가 아주 크다

배열을 만들 수 없으니 사건 스위프나 `TreeMap` 차분으로 바꾼다. 또는 등장하는 위치만 모아 정렬한 뒤 번호를 다시 매기는 좌표 압축을 하고, 그 번호로 차분 배열을 쓴다. 위치는 많아야 2n개라 칸이 2n개면 된다. 어느 쪽이든 정렬이 들어가서 O(n log n)이다.

### 정원이 최소 몇이어야 하나

판정 대신 필요한 정원을 묻는다면 누적 합의 최댓값을 돌려준다. 예시에서는 5다. 이게 Meeting Rooms II에 가중치가 붙은 형태다. 회의마다 인원이 1이면 그대로 필요한 회의실 수가 된다.

### 어디서 처음 넘치는지 알려 달라면

차분 배열을 훑다가 넘치는 첫 위치 `x`를 돌려준다. 정원 4인 예시에서는 위치 3이다. 그 순간 타 있는 여행이 누구인지까지 원하면 힙 풀이로 바꾼다. 힙에 남아 있는 것이 바로 그 손님들이다. 힙에 여행 번호를 함께 넣으면 된다.

```python
import heapq

def first_overflow(trips, capacity):
    order = sorted(range(len(trips)), key=lambda i: trips[i][1])  # 타는 위치 순, 원래 번호를 들고 간다
    heap, load = [], 0                                            # (내릴 곳, 여행 번호)
    for i in order:
        p, frm, to = trips[i]
        while heap and heap[0][0] <= frm:                         # 여기까지 내릴 손님을 모두 내린다
            load -= trips[heapq.heappop(heap)[1]][0]
        heapq.heappush(heap, (to, i))
        load += p
        if load > capacity:
            return frm, sorted(j for _, j in heap)                # 넘친 위치와 그때 타 있던 여행들
    return None

trips = [[2, 1, 5], [3, 3, 7], [2, 5, 8]]
print(first_overflow(trips, 5))
print(first_overflow(trips, 4))
print(first_overflow([[1, 0, 4], [1, 1, 2], [1, 2, 3], [1, 3, 5]], 1))
```

```text
None
(3, [0, 1])
(1, [0, 1])
```

정원 5에서는 넘치지 않아 `None`, 정원 4에서는 위치 3에서 여행 0과 1이 함께 타 있을 때 넘쳤다. 마지막 입력은 긴 여행 `[1,0,4]` 위에 짧은 여행이 차례로 겹치는 경우로, 위치 1에서 바로 넘친다. 힙에서 내릴 손님을 먼저 다 내린 뒤에 새 손님을 넣기 때문에, 힙에 남은 여행이 정확히 그 순간 차에 있는 여행이다.

### 여행 예약이 하나씩 들어온다면

예약마다 "이걸 받아도 정원을 넘지 않나"를 판정하고 받거나 거절한다. 예약마다 차분 배열 전체를 훑으면 O(L)이다. 예약이 많으면 구간 더하기와 구간 최댓값을 O(log L)에 하는 세그먼트 트리(지연 전파)를 쓴다. 겹치면 무조건 거절하는 단순한 버전이 [My Calendar I](/posts/leetcode-my-calendar-i)(729번)이고, 겹침 수를 세는 버전이 732번 My Calendar III다.

### 같은 차분 배열이 나오는 문제들

1109번 Corporate Flight Bookings(닫힌 구간이라 `last + 1`에서 뺀다), 370번 Range Addition(프리미엄 문제, 구간 더하기를 모아 한 번에 적용), 2계 차분이 필요한 구간 등차수열 더하기 문제들이 같은 장부를 쓴다. 구간 묶음의 다른 문제로는 [Merge Intervals](/posts/leetcode-merge-intervals), 모두의 빈 시간을 찾는 [Employee Free Time](/posts/leetcode-employee-free-time)(759번, 프리미엄 문제), [Interval List Intersections](/posts/leetcode-interval-list-intersections)(986번)가 있다.

## 면접에서 나올 만한 질문

### 가장 빠른 풀이와 복잡도는요?

위치가 0~1,000이라 길이 1,001짜리 차분 배열에 타는 곳 +p, 내리는 곳 −p를 적고 누적 합이 정원을 넘는지 본다. 시간 O(n + L), 공간 O(L)이고 정렬이 없다. 위치 범위가 크면 사건 스위프나 TreeMap으로 바꿔 O(n log n)이다.

### 내리는 곳과 타는 곳이 같으면 어떻게 처리하나요?

내리는 손님이 먼저 내린다. 여행이 `[from, to)`라서 `to`에서는 이미 차에 없다. 차분 배열은 `diff[to]`에서 빼면 같은 칸에서 더하기와 빼기가 함께 반영되어 순서 문제가 사라진다. 스위프라면 같은 위치에서 음수 사건을 먼저 처리하도록 정렬한다.

### Meeting Rooms II와 무엇이 다른가요?

뼈대는 같고 구간마다 가중치(인원)가 붙은 것이 다르다. 그래서 시작과 끝을 따로 정렬해 개수만 세는 풀이는 쓸 수 없고, 힙 풀이도 하나만 꺼내던 `if`가 내릴 사람을 모두 내리는 `while`로 바뀐다. 가중치를 받는 스위프와 차분 배열은 그대로 쓸 수 있다.

### 차분 배열이 왜 맞나요?

`diff`는 위치별 탑승 인원의 이웃 간 차이를 적은 배열이다. 여행 하나는 `from`에서 p만큼 오르고 `to`에서 p만큼 내려오는 계단이라 두 칸만 바뀐다. 누적 합을 구하면 모든 계단이 겹친 높이, 즉 위치별 탑승 인원이 살아난다.

### JavaScript로 짤 때 조심할 곳은요?

`new Array(1001)`만 쓰고 0으로 채우지 않으면 `undefined + p`가 `NaN`이 되어 비교가 전부 거짓이 되고 언제나 `true`가 나온다. 정렬을 쓰는 풀이에서는 비교 함수를 반드시 넘긴다. 없으면 문자열로 비교해서 10이 2보다 앞에 온다.

### 위치가 10억까지라면 어떻게 바꾸나요?

배열을 만들 수 없으니 등장하는 위치만 칸으로 쓴다. TreeMap에 위치별 변화량을 합쳐 넣고 키 순서로 누적하거나, 사건을 정렬해 스위프한다. 위치를 정렬해 번호를 다시 매기는 좌표 압축 뒤 차분 배열을 써도 된다. 셋 다 정렬이 들어가서 O(n log n)이다.

### 예약이 하나씩 들어오며 받을지 정해야 한다면요?

예약마다 차분 배열 전체를 다시 훑으면 O(L)이다. 예약이 많으면 구간에 값을 더하고 구간 최댓값을 묻는 세그먼트 트리(지연 전파)로 바꿔 예약 하나에 O(log L)로 처리한다. 받을 수 있는지 먼저 구간 최댓값으로 확인하고, 받으면 그 구간에 인원을 더한다.
