에디터는 괄호 짝이 안 맞는 줄에 빨간 줄을 긋는다. 이 문제가 바로 그 판단을 하는 문제다. 풀어 보면 스택이 왜 필요한지 가장 직관적으로 보여 주는 예이기도 하다.

## 문제

`()`, `[]`, `{}`로만 이루어진 문자열 `s`가 주어진다. 여는 괄호가 같은 종류의 닫는 괄호로, 올바른 순서대로 닫혀 있는지 판별한다.

```text
"()[]{}"  → true
"(]"      → false  (종류가 다르다)
"([)]"    → false  (순서가 꼬였다)
```

## 가장 최근에 연 것부터 닫아야 한다

`"([)]"`이 틀린 이유를 말로 풀어 보면 이렇다. `(`를 열고 `[`를 열었으면, 다음에 닫을 수 있는 건 `]`뿐이다. `[`가 아직 열려 있는데 그 바깥의 `(`를 먼저 닫을 수는 없다. 마지막에 연 것을 가장 먼저 닫아야 한다.

마지막에 넣은 것을 가장 먼저 꺼내는 자료구조가 스택이다. 식당에서 접시를 쌓아 두고 맨 위부터 꺼내 쓰는 것과 같다. 여는 괄호를 만나면 쌓고, 닫는 괄호를 만나면 맨 위를 꺼내서 짝이 맞는지 본다.

## 코드

```ts
function isValid(s: string): boolean {
  const pairs: Record<string, string> = { ")": "(", "]": "[", "}": "{" };
  const stack: string[] = [];

  for (const ch of s) {
    if (ch in pairs) {
      if (stack.pop() !== pairs[ch]) return false;
    } else {
      stack.push(ch);
    }
  }
  return stack.length === 0;
}
```

문자열을 한 번 읽으니 시간은 O(n), 최악의 경우 여는 괄호가 전부 쌓이니 공간도 O(n)이다.

마지막 줄의 `stack.length === 0`은 빼먹기 쉽다. `"(("`는 읽는 동안 한 번도 틀리지 않지만, 다 읽고 나면 닫히지 않은 괄호가 두 개 남는다. 반대로 닫는 괄호가 먼저 나오는 `")("` 같은 경우는 빈 스택에서 `pop()`이 `undefined`를 돌려주니 짝 비교에서 자연스럽게 걸린다.

## 정리

"가장 최근에 시작한 것을 가장 먼저 끝내야 한다"는 조건이 보이면 스택을 떠올리면 된다. 괄호 검사뿐 아니라 함수 호출, 실행 취소(undo), HTML 태그 짝 맞추기도 모두 같은 모양이다.
