## 문제

괄호 `()`, `[]`, `{}`로만 이루어진 글자가 있어요. **여는 괄호는 알맞은 닫는 괄호로, 올바른 순서대로** 닫혀 있으면 "올바른 괄호"예요.

```text
"()[]{}"  → 올바름
"(]"      → 틀림  (종류가 달라요)
"([)]"    → 틀림  (순서가 꼬였어요)
```

## 한 줄로 말하면

"열린 괄호는 **쌓아 두고**, 닫는 괄호가 나오면 **맨 위에 쌓인 것과 짝이 맞는지** 본다."

## 비유로 이해하기: 접시 쌓기

식당에서 접시를 **위에 하나씩 올려 쌓고**, 쓸 때는 **맨 위에서부터** 꺼내죠. 가장 나중에 올린 접시가 가장 먼저 나와요.

여는 괄호는 "아직 닫지 못한 약속"이에요. 약속은 **가장 최근에 한 것부터** 지켜야 해요. 그래서 접시처럼 쌓아 두는 도구, **스택**이 딱 맞아요.

## 코드

```ts
function isValid(s: string): boolean {
  const pairs: Record<string, string> = { ")": "(", "]": "[", "}": "{" };
  const stack: string[] = [];

  for (const ch of s) {
    if (ch in pairs) {
      // 닫는 괄호: 맨 위와 짝이 맞아야 해요
      if (stack.pop() !== pairs[ch]) return false;
    } else {
      // 여는 괄호: 쌓아 둬요
      stack.push(ch);
    }
  }
  return stack.length === 0; // 다 지켰으면 스택이 비어 있어야 해요
}
```

## 헷갈리는 부분

<Callout kind="warning" title="끝에서 스택이 비었는지도 꼭 확인해요">
  `"(("` 는 읽는 동안 틀린 곳이 없지만, 끝나고 보면 **닫지 못한 약속**이 둘 남아 있어요. 마지막에 `stack.length === 0`을 확인하지 않으면 이걸 놓쳐요.
</Callout>

## 내 말로 다시 설명해보기

<details>
<summary>Q1. 왜 큐(줄서기)가 아니라 스택(접시 쌓기)일까요?</summary>

가장 **나중에** 열린 괄호가 가장 **먼저** 닫혀야 하기 때문이에요. 마지막에 들어간 것이 먼저 나오는 도구가 스택이에요.

</details>

<details>
<summary>Q2. 닫는 괄호가 나왔는데 스택이 비어 있다면?</summary>

닫을 약속이 없는데 닫으려는 거라 **틀린 괄호**예요. 코드에서는 빈 스택에서 꺼내면 `undefined`가 나와서 짝이 맞지 않으니 자연스럽게 `false`가 돼요.

</details>
