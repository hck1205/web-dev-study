쿠폰 코드나 주문 번호처럼 긴 숫자 문자열에서 몇 자리를 빼고 남은 값을 비교해야 하는 일이 가끔 있다. 이때 숫자로 바꿔서 비교하면 10^5자리 문자열은 JavaScript의 `Number`로 담을 수조차 없다. 자리마다 따져야 한다.

[LeetCode 402. Remove K Digits](https://leetcode.com/problems/remove-k-digits/)는 숫자 문자열에서 k자리를 지워 가장 작은 수를 만드는 문제다. [단조 스택 패턴 글](/posts/monotonic-stack-pattern)에서 "꺼내는 조건이 비교가 아니라 이득일 때"의 예로 짧게 본 문제인데, 여기서는 그 풀이가 왜 맞는지, 그 풀이에 이르기까지 어떤 풀이들이 있는지를 차례로 본다. 조합을 전부 만드는 풀이, 내려가는 첫 자리를 k번 지우는 풀이, 자리마다 고를 범위에서 최솟값을 고르는 풀이와 그 덱 버전, 단조 스택까지 다섯 가지다. 탐욕 알고리즘이 무엇인지는 [그리디 알고리즘 글](/posts/greedy-algorithms)에 있다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 숫자 k개를 지워 가장 작은 수 만들기

음이 아닌 정수를 나타내는 문자열 `num`과 정수 `k`가 주어진다. `num`에서 숫자 k개를 지워 만들 수 있는 가장 작은 수를 문자열로 돌려준다. 남은 숫자의 순서는 바꾸지 않는다. 결과의 앞에 붙은 0은 떼고, 다 지워져 아무것도 없으면 `"0"`이다.

풀이를 고르는 데 영향을 주는 제약은 이렇다.

- `num`의 길이는 최대 10^5이고 `k`는 0 이상 길이 이하다. O(nk)는 최악에 수십억 번이 된다.
- `num`은 0 하나인 경우를 빼면 0으로 시작하지 않는다. 하지만 중간에 0이 있어서, 앞자리를 지우면 결과가 0으로 시작할 수 있다.
- 숫자로 바꾸면 안 된다. 10^5자리는 어떤 기본 숫자형에도 들어가지 않는다.

## 앞자리가 작아야 작은 수다

남는 자리 수는 항상 `n - k`로 같다. 앞의 0을 떼기 전에는 길이가 같은 두 수의 크기 비교이니, 사전 순 비교와 같다. 맨 앞자리가 작은 쪽이 작고, 같으면 다음 자리를 본다. 그래서 뒷자리를 아무리 잘 골라도 앞자리 하나가 크면 진다.

이 글에서 계속 쓸 예시다.

```text
num = "4205379", k = 3
```

7자리에서 3자리를 지우니 4자리가 남는다. 맨 앞자리부터 정해 보자. 결과의 첫 자리로 쓸 수 있는 건 `num`의 앞 네 자리 `4, 2, 0, 5` 중 하나다. 다섯째 자리 3을 첫 자리로 쓰면 그 뒤에 남은 숫자가 `7, 9` 두 개뿐이라 4자리를 채울 수 없다. 네 후보 중 가장 작은 건 0이다. 0을 고르면 그 앞의 4와 2를 지우게 되고, 지울 기회는 하나 남는다.

다음 자리는 0 뒤에서 고른다. 남은 숫자는 `5, 3, 7, 9`이고 3자리를 더 채워야 하니, 둘째 자리 후보는 `5, 3`이다. 3이 작다. 5를 지우면 지울 기회를 다 쓴다. 나머지 `7, 9`는 그대로 붙는다.

```text
4 2 0 5 3 7 9
x x . x . . .    → "0379" → 앞의 0을 떼면 "379"
```

답은 `"379"`다. 이렇게 손으로 풀면서 두 가지 생각이 나온다. 하나는 "자리마다 고를 수 있는 범위에서 가장 작은 숫자를 고른다"이고, 다른 하나는 "작은 숫자가 나타나면 그 앞의 큰 숫자를 지운다"이다. 둘 다 풀이가 되고, 두 번째가 스택이다.

## 지울 조합을 전부 만들어 보기

먼저 정답을 확실히 아는 방법이다. n자리 중 남길 `n - k`자리를 고르는 모든 경우를 만들고 가장 작은 것을 고른다.

```js
function clean(s) {
  s = s.replace(/^0+/, ""); // 앞의 0을 뗀다
  return s === "" ? "0" : s;
}

function removeKdigits(num, k) {
  const n = num.length, m = n - k; // m자리를 남긴다
  let best = null;
  function go(i, cur) {
    if (cur.length === m) {
      if (best === null || cur < best) best = cur; // 길이가 같으니 문자열 비교 = 수 비교
      return;
    }
    if (n - i < m - cur.length) return; // 남은 숫자로는 m자리를 못 채운다
    go(i + 1, cur + num[i]); // i번째 숫자를 남긴다
    go(i + 1, cur);          // i번째 숫자를 지운다
  }
  go(0, "");
  return clean(best);
}
```

경우의 수가 C(n, k)라 n이 20만 넘어도 수십만 가지, 30이면 1억 가지를 넘는다. 시간은 O(C(n, k) · n)이다. 길이 10^5에는 쓸 수 없지만, 다른 풀이를 무작위 작은 입력으로 검증할 때 기준이 된다. 이 글의 풀이들은 길이 10 이하 무작위 입력 4000개에서 이 풀이와 결과가 모두 같았다.

길이가 같은 문자열끼리 `<`로 비교한 것도 짚어 둔다. 숫자 문자열은 길이가 같으면 사전 순이 곧 수의 크기 순이다. `"0379" < "2053"`처럼 앞에 0이 있어도 길이가 같으니 맞다. 0을 떼고 나서 비교하면 길이가 달라져서 이 비교가 틀린다.

## 내려가는 첫 자리를 하나씩 지우기

한 자리만 지운다면 어디를 지워야 할까. 왼쪽부터 보다가 처음으로 다음 숫자보다 큰 숫자, 곧 처음 내려가는 자리를 지우면 된다. 그런 자리가 없으면, 곧 숫자가 계속 오르거나 같으면 마지막 숫자를 지운다.

이유는 이렇다. 처음 내려가는 자리를 `i`라고 하자. `num[0..i]`는 오르거나 같고, `num[i] > num[i+1]`이다. `i`를 지우면 `i`번째 자리에 더 작은 `num[i+1]`이 온다. `i`보다 앞을 지우면 그 자리에 같거나 더 큰 숫자가 당겨지니 손해이거나 같다. `i`보다 뒤를 지우면 `i`번째 자리는 그대로 `num[i]`라서 `num[i+1]`이 온 경우보다 크다. 그래서 `i`를 지우는 게 가장 작다.

k자리를 지우려면 이걸 k번 반복한다. 한 번 지운 결과에서 다시 처음 내려가는 자리를 찾는다.

```js
function removeKdigits(num, k) {
  let s = num;
  for (let r = 0; r < k; r++) {
    let i = 0;
    while (i + 1 < s.length && s[i] <= s[i + 1]) i++; // 처음 내려가는 자리 (없으면 마지막)
    s = s.slice(0, i) + s.slice(i + 1);
  }
  return clean(s);
}
```

예시에 돌리면 `4205379`에서 4를 지워 `205379`, 2를 지워 `05379`, 5를 지워 `0379`가 된다. 손으로 푼 것과 같다.

한 번에 하나씩 지우는 걸 k번 반복해도 전체에서 가장 작은 결과가 나오는지는 따로 따져야 한다. "한 자리를 지운 결과가 가장 작으면 거기서 더 지운 결과도 가장 작다"는 식으로는 증명이 안 된다. `"29"`는 `"30"`보다 작지만 한 자리를 더 지우면 `"2"`와 `"0"`이 되어 순서가 뒤집힌다. 대신 바꿔치기로 따진다. 가장 작은 결과를 만드는 지우기 방법 중에는 처음 내려가는 자리 `i`를 지우는 방법이 꼭 하나 있다. 어떤 최선의 방법이 `i`를 지우지 않았다면 두 경우뿐이다.

- `i`보다 앞에서 지운 자리가 있다면, 그중 `i`에 가장 가까운 자리 `j` 대신 `i`를 지워 본다. `j`부터 `i`까지는 오르거나 같은 구간이라, 그 사이 자리에 같거나 작은 숫자가 오고 나머지는 그대로다. 결과가 커지지 않는다.
- `i`보다 앞은 하나도 안 지웠다면, `i` 뒤에서 처음 지운 자리 대신 `i`를 지워 본다. `i`번째 자리에 `num[i]`보다 작은 `num[i+1]`이 오니 오히려 더 작아진다. 최선이라는 가정과 맞지 않는다.

그러니 `i`를 먼저 지우고, 남은 문자열에서 k-1자리를 같은 방법으로 지우면 된다. 이걸 k번 이어 붙이면 반복 풀이가 맞다는 게 나온다.

시간은 지울 때마다 처음부터 찾고 문자열을 새로 만드니 O(nk)다. 길이 10^5, k = 5 × 10^4로 재 봤다. 무작위 숫자는 1.6초, 거의 오르기만 하는 숫자는 처음 내려가는 자리를 찾느라 매번 끝까지 가서 30초 가까이 걸렸다.

이 풀이의 낭비는 분명하다. 한 자리를 지우고 나서 처음부터 다시 찾는다. 그런데 방금 지운 자리 앞쪽은 이미 오르거나 같은 상태다. 다음 내려가는 자리는 방금 지운 자리 바로 앞이거나 그 뒤에 있다. 이걸 이용하는 게 스택 풀이다.

## 자리마다 고를 수 있는 범위에서 가장 작은 숫자

손으로 풀 때 쓴 첫 번째 생각을 코드로 옮긴다. 결과는 `m = n - k`자리다. 결과의 `j`번째 자리는 `num`의 어디에서 올 수 있을까. 앞자리를 고른 위치 다음부터, 그리고 뒤에 `m - j - 1`자리를 더 채울 수 있을 만큼 앞에서 와야 한다. 그래서 `j`번째 자리의 후보 구간은 `[start, k + j]`다. 그 구간에서 가장 작은 숫자를, 같은 게 여러 개면 가장 왼쪽 것을 고른다. 왼쪽 것을 골라야 뒤에 후보가 더 많이 남는다.

```js
function removeKdigits(num, k) {
  const n = num.length, m = n - k;
  let res = "", start = 0;
  for (let j = 0; j < m; j++) {
    let best = start;
    for (let i = start; i <= k + j; i++) {
      if (num[i] < num[best]) best = i; // 같으면 왼쪽 것을 둔다
    }
    res += num[best];
    start = best + 1; // 다음 자리는 고른 자리 뒤에서
  }
  return clean(res);
}
```

이 풀이가 맞는 이유는 사전 순 비교 그 자체다. 첫 자리를 가능한 가장 작게 만들고, 그 조건 아래서 둘째 자리를 가장 작게 만드는 식으로 가면 사전 순으로 가장 작은 결과가 된다.

구간 길이가 최대 k+1이라 시간은 O(m · k), 곧 O(nk)다. 앞의 풀이와 같은 차수이고, 같은 입력에서 0.7초와 21초가 걸렸다. 공간은 결과 문자열 O(n)이다.

### 구간의 최솟값을 덱으로 빠르게

구간의 오른쪽 끝은 `k + j`라서 자리마다 한 칸씩 늘어난다. 왼쪽 끝은 고른 위치 다음으로 옮겨 가니 줄어들지 않는다. 양 끝이 모두 한 방향으로만 움직이는 창이다. 이런 창의 최솟값은 [Sliding Window Maximum](/posts/leetcode-sliding-window-maximum)에서 쓴 단조 덱으로 구할 수 있다.

```js
function removeKdigits(num, k) {
  const n = num.length, m = n - k;
  const dq = []; // 숫자가 오르거나 같은 순서로 인덱스를 담는다. 맨 앞이 창의 최솟값
  let head = 0;  // shift() 대신 앞 위치를 숫자로 들고 간다
  let res = "", next = 0;
  for (let j = 0; j < m; j++) {
    while (next <= k + j) { // 창 오른쪽 끝까지 새 숫자를 넣는다
      // 새 숫자보다 큰 뒤쪽 숫자는 다시는 최솟값이 될 수 없다
      while (dq.length > head && num[dq[dq.length - 1]] > num[next]) dq.pop();
      dq.push(next++);
    }
    res += num[dq[head++]]; // 맨 앞이 가장 왼쪽의 최솟값. 고르고 창에서 뺀다
  }
  return clean(res);
}
```

뒤에서 꺼내는 조건이 `>`라서 같은 숫자는 남는다. 같은 숫자 중 왼쪽 것이 덱 앞에 남아야 "가장 왼쪽의 최솟값"을 고를 수 있다. 고른 숫자를 앞에서 빼면 덱에 남은 인덱스는 모두 고른 자리보다 뒤이니, 왼쪽 끝을 따로 옮길 필요도 없다.

숫자마다 덱에 한 번 들어가고 한 번 나오니 O(n)이다. 앞의 두 입력에서 2ms, 10ms였다. 예시에서 덱이 바뀌는 모습을 찍어 보면 이렇다.

```text
넣기 4   뒤에서 뺌: -   덱: 4
넣기 2   뒤에서 뺌: 4   덱: 2
넣기 0   뒤에서 뺌: 2   덱: 0
넣기 5   뒤에서 뺌: -   덱: 0 5
고름 0                  덱: 5
넣기 3   뒤에서 뺌: 5   덱: 3
고름 3                  덱:
넣기 7 → 고름 7,  넣기 9 → 고름 9
```

Python이라면 `collections.deque`가 앞에서 꺼내는 `popleft()`를 O(1)에 해 준다. 리스트의 `pop(0)`은 뒤를 다 당겨서 O(n)이라 이 자리에 쓰면 전체가 O(n²)으로 돌아간다.

```python
from collections import deque

def remove_kdigits(num: str, k: int) -> str:
    m = len(num) - k
    dq = deque()  # 인덱스. 숫자가 오르거나 같은 순서
    res = []
    nxt = 0
    for j in range(m):
        while nxt <= k + j:  # 창 오른쪽 끝까지 넣는다
            while dq and num[dq[-1]] > num[nxt]:
                dq.pop()  # 새 숫자보다 큰 뒤쪽은 최솟값이 될 수 없다
            dq.append(nxt)
            nxt += 1
        res.append(num[dq.popleft()])  # 맨 앞이 가장 왼쪽의 최솟값
    return "".join(res).lstrip("0") or "0"
```

이 코드도 예시에서 `"379"`, `"3090"`과 `k = 2`에서 `"0"`을 낸다. 다시 덱의 기록으로 돌아가서, 뒤에서 빼는 장면만 모아 보면 4, 2, 5다. 손으로 풀 때 지운 세 숫자와 같다. 덱 뒤에서 빼는 일이 곧 "새 숫자보다 큰 앞 숫자를 지운다"이고, 앞에서 고르는 일은 지우지 않은 숫자를 차례로 내보내는 것뿐이다. 그러면 덱을 스택처럼만 써도 된다. 그게 다음 절의 풀이다.

## 지울 기회가 남아 있으면 맨 위를 지운다

왼쪽부터 숫자를 하나씩 스택에 쌓는다. 새 숫자 `d`가 오면, 지울 기회 `k`가 남아 있고 스택 맨 위가 `d`보다 큰 동안 맨 위를 지운다. 맨 위 자리에 더 작은 `d`가 들어오면 수가 작아지기 때문이다. 그다음 `d`를 쌓는다.

이건 "내려가는 첫 자리를 지운다"를 한 번에 해내는 방법이다. 스택은 언제나 오르거나 같은 순서로 쌓여 있다. 그래서 새 숫자가 맨 위보다 작은 순간이 곧 "처음 내려가는 자리"이고, 맨 위를 지우면 그 아래가 다시 새 맨 위가 되어 또 비교한다. 처음부터 다시 찾을 필요가 없다.

아래 그림에서 다음을 누르면 숫자마다 스택과 남은 `k`가 바뀐다.

```js
function removeKdigits(num, k) {
  const st = []; // 남길 숫자들. 아래에서 위로 오르거나 같은 순서
  for (const d of num) {
    // 맨 위를 더 작은 d로 바꿀 수 있고, 지울 기회가 남아 있으면 지운다
    while (k > 0 && st.length && st[st.length - 1] > d) {
      st.pop();
      k--;
    }
    st.push(d);
  }
  st.length -= k; // 남은 기회는 뒤에서 지운다. 스택이 오름차순이라 뒤가 가장 크다
  return clean(st.join(""));
}
```

숫자마다 한 번 들어가고 많아야 한 번 나오니 O(n)이다. 공간은 스택 O(n)이다. 앞의 입력에서 3ms였다. 숫자 문자 `"0"`부터 `"9"`는 문자열로 비교해도 크기 순서가 그대로라 숫자로 바꾸지 않았다.

### 왜 이 탐욕이 가장 작은 수를 만드나

"내려가는 첫 자리를 하나 지우는 게 한 자리 지우기의 최선"이고 "그걸 k번 반복하는 게 k자리 지우기의 최선"이라는 것을 앞에서 봤다. 스택 풀이는 그 k번의 지우기를 같은 순서로 해낸다. 스택에서 맨 위를 꺼내는 순간, 스택과 아직 안 본 숫자를 이어 붙인 문자열에서 맨 위가 정확히 처음 내려가는 자리다. 스택 안은 오르거나 같고, 맨 위 다음 숫자가 `d`인데 맨 위가 `d`보다 크기 때문이다. 그래서 스택 풀이는 반복 지우기 풀이와 같은 자리를 같은 순서로 지운다. 다른 점은 처음부터 다시 찾지 않는다는 것뿐이다.

### 끝에 남은 k와 앞에 남은 0

반복이 끝나도 `k`가 남을 수 있다. `"12345"`처럼 숫자가 계속 오르면 한 번도 꺼내지 않는다. 이때 스택은 오르거나 같은 순서이니, 가장 큰 숫자들이 뒤에 몰려 있다. 뒤에서 `k`개를 지우면 된다. 내려가는 자리가 없을 때 마지막 숫자를 지우던 규칙과 같다.

앞의 0은 결과를 만든 뒤 한꺼번에 떼어도 되고, 쌓을 때 막아도 된다. 스택이 비어 있을 때 0이 오면 쌓지 않는 것이다. 앞의 0은 어차피 떼어 낼 숫자라서 쌓지 않아도 결과가 같고, 이때 `k`를 쓰지 않는 게 맞다. 0은 지운 게 아니라 떼어 낸 것이기 때문이다.

```js
for (const d of num) {
  while (k > 0 && st.length && st[st.length - 1] > d) { st.pop(); k--; }
  if (st.length || d !== "0") st.push(d); // 맨 앞에 올 0은 쌓지 않는다
}
while (k > 0 && st.length) { st.pop(); k--; } // 스택이 k보다 짧아졌을 수 있다
return st.length ? st.join("") : "0";
```

이 방식에서는 0을 쌓지 않은 만큼 스택이 짧아져서, 끝에 남은 `k`가 스택 길이보다 클 수 있다. `"3090"`, `k = 2`가 그렇다. 3을 0이 지우고(k = 1), 0은 쌓지 않고, 9를 쌓고, 마지막 0이 9를 지운다(k = 0). 결과는 빈 스택이라 `"0"`이다. 길이를 빼는 `st.length -= k` 대신 비어 있는지 보면서 꺼내야 음수 길이 오류가 나지 않는다.

### 문자열을 다루는 방식이 언어마다 다르다

Python에서는 리스트를 스택으로 쓰고 끝에 `"".join(...).lstrip("0") or "0"`으로 마무리한다. 빈 문자열은 거짓이라 `or "0"`이 빈 결과를 처리한다.

```python
def remove_kdigits(num: str, k: int) -> str:
    stack = []
    for d in num:
        while k and stack and stack[-1] > d:  # 앞자리를 더 작은 숫자로 바꿀 수 있으면 지운다
            stack.pop()
            k -= 1
        stack.append(d)
    if k:
        del stack[-k:]  # 남은 횟수는 뒤에서 지운다. k가 0이면 stack[-0:]이 전체라서 막아 둔다
    return "".join(stack).lstrip("0") or "0"
```

`if k:` 없이 `del stack[-k:]`를 쓰면 `k`가 0일 때 `stack[-0:]`이 `stack[0:]`, 곧 전체가 되어 스택이 통째로 지워진다. 실제로 `[1, 2, 3]`에 `del s[-0:]`을 하면 빈 리스트가 됐다. 자주 걸리는 함정이다.

Java는 `char[]`를 스택으로 쓴다. `char`끼리 `>`로 비교하면 문자 코드 순서인데 `'0'`부터 `'9'`가 연속이라 숫자 순서와 같다. `StringBuilder`의 `deleteCharAt`을 스택으로 써도 되지만, 앞의 0을 뗄 때 `deleteCharAt(0)`을 반복하면 매번 뒤를 당겨서 O(n²)이 될 수 있다. 시작 위치만 옮기고 마지막에 한 번 문자열을 만든다.

```java
class Solution {
    public String removeKdigits(String num, int k) {
        char[] stack = new char[num.length()];
        int top = 0;
        for (char d : num.toCharArray()) {
            while (k > 0 && top > 0 && stack[top - 1] > d) { // char도 숫자 순서대로 비교된다
                top--;
                k--;
            }
            stack[top++] = d;
        }
        top -= k;                       // 남은 횟수는 뒤에서 지운다
        int start = 0;
        while (start < top && stack[start] == '0') start++; // 앞의 0 건너뛰기
        return start == top ? "0" : new String(stack, start, top - start);
    }
}
```

`top -= k`가 음수가 되지 않는 건, 0도 스택에 쌓기 때문이다. 스택에는 언제나 `n - (지운 수)`개가 있고 지운 수와 남은 `k`를 더하면 처음 `k`라서, 끝에 `top = n - 처음 k`가 된다. 처음 `k`가 길이 이하이니 0 이상이다. 세 언어 모두 예시에서 `"379"`, `"10200"`과 `k = 1`에서 `"200"`, `"10"`과 `k = 2`에서 `"0"`을 낸다.

## 지우는 방법 다섯 가지의 비용

| 풀이 | 시간 | 추가 공간 | 언제 고르나 |
|---|---|---|---|
| 조합 전부 | O(C(n, k) · n) | O(n) | n이 아주 작을 때, 정답 검증용 |
| 내려가는 첫 자리 k번 지우기 | O(nk) | O(n) | 탐욕이 맞는 이유를 설명할 때 |
| 자리마다 구간 최솟값 | O(nk) | O(n) | "자리마다 고른다"는 관점을 보여 줄 때 |
| 구간 최솟값 + 단조 덱 | O(n) | O(n) | 남길 자리 수 m이 주어지는 변형 |
| 단조 스택 | O(n) | O(n) | 기본 답 |

길이 10^5, `k` = 5 × 10^4에서 잰 시간이다.

```text
입력                     k번 지우기   구간 최솟값   구간 최솟값 + 덱   단조 스택
무작위 숫자                 1606 ms       728 ms          2 ms            3 ms
거의 오르기만 하는 숫자    29808 ms     20785 ms         10 ms            3 ms
```

O(nk) 풀이 둘은 입력 모양에 따라 열 배 넘게 차이가 나고, O(n) 풀이 둘은 어느 입력에서나 몇 밀리초에 끝난다.

면접에서는 "같은 길이면 앞자리가 작을수록 작다"에서 시작해 "작은 숫자가 오면 앞의 큰 숫자를 지운다"를 끌어내고, 스택으로 바로 간다. 그다음 끝에 남은 `k`, 앞의 0, 빈 결과 세 가지 마무리를 빠짐없이 말한다. 왜 맞는지 물으면 "한 자리 지우기의 최선은 처음 내려가는 자리"로 답한다.

## 등호, 남은 k, 0에서 틀리는 코드

### 같은 숫자도 지운다

```js
while (k > 0 && st.length && st[st.length - 1] >= d) { st.pop(); k--; } // 틀림
```

같은 숫자를 같은 숫자로 바꿔 봐야 수는 그대로인데 지울 기회만 쓴다. `"1121"`, `k = 1`에서 정답 `"111"` 대신 `"121"`이 나왔다. 두 코드의 스택을 한 줄씩 찍어 보면 갈라지는 자리가 보인다.

```text
>  로 비교 (맞는 코드)
1  지움: -   스택: 1     k=1
1  지움: -   스택: 11    k=1
2  지움: -   스택: 112   k=1
1  지움: 2   스택: 111   k=0

>= 로 비교 (틀린 코드)
1  지움: -   스택: 1     k=1
1  지움: 1   스택: 1     k=0
2  지움: -   스택: 12    k=0
1  지움: -   스택: 121   k=0
```

틀린 코드는 두 번째 1이 첫 1을 지우느라 기회를 써 버려서, 정작 지워야 할 2를 못 지웠다. 본문 예시처럼 같은 숫자가 붙어 있지 않은 입력에서는 두 코드의 답이 같아서, 같은 숫자가 이어지는 테스트를 넣어야 드러난다.

### 끝에 남은 k를 버린다

`st.length -= k` 줄이 없으면 `"12345"`, `k = 2`에서 `"123"` 대신 `"12345"`가, `"1111"`, `k = 2`에서 `"11"` 대신 `"1111"`이 나온다. 반복이 끝난 뒤에도 지울 횟수가 남을 수 있다는 걸 기억해 두면 된다. [단조 스택 패턴 글](/posts/monotonic-stack-pattern)에서도 짚은 실수다.

### 앞의 0과 빈 결과를 처리하지 않는다

마무리 없이 `st.join("")`을 그대로 돌려주면 `"10200"`, `k = 1`에서 `"0200"`이, `"10"`, `k = 2`에서 빈 문자열 `""`이 나온다. 0을 떼는 것과 빈 결과를 `"0"`으로 바꾸는 것은 따로 있는 두 단계다. 하나만 하면 `"10"`, `k = 2`처럼 둘 다 걸리는 입력에서 틀린다.

### 숫자로 바꿔서 계산한다

`Number(num)`이나 `parseInt`로 바꾸면 15~16자리를 넘는 순간 정밀도를 잃는다. `Number("12345678901234567890")`은 `12345678901234567000`이 됐다. 10^5자리는 아예 `Infinity`다. `BigInt`는 정확하지만 자리마다 지워 보는 비교를 큰 정수 연산으로 하면 매우 느리다. 이 문제는 처음부터 끝까지 문자 단위로 다룬다.

### k가 0이거나 길이와 같은 경우를 놓친다

`k = 0`이면 아무것도 지우지 않으니 입력을 그대로 돌려주면 된다. 스택 풀이는 이 경우 반복문이 꺼내지 않고 다 쌓기만 해서 저절로 맞는다. Python에서 `del stack[-k:]`를 `if k:` 없이 쓰면 바로 이 경우에 스택 전체가 지워진다는 건 앞에서 봤다. `k`가 길이와 같으면 전부 지워 빈 결과가 되고 `"0"`을 돌려준다. `"4205379"`, `k = 7`이 그렇다. 두 경우 모두 테스트에 넣어 둔다.

### 앞의 0을 쌓지 않으면서 길이로 k를 뺀다

앞 절의 "0을 쌓지 않는" 방식과 `st.length -= k`를 섞으면, 스택이 남은 `k`보다 짧을 때 배열 길이에 음수를 넣게 된다. JavaScript는 `RangeError: Invalid array length`를 던진다. 두 방식 중 하나로 통일한다.

## 지우는 대신 고르라고 하면

### 가장 큰 수를 만들어라

비교 방향만 바꾼다. 새 숫자가 맨 위보다 크면 맨 위를 지운다.

```js
function removeKdigitsLargest(num, k) {
  const st = [];
  for (const d of num) {
    while (k > 0 && st.length && st[st.length - 1] < d) { st.pop(); k--; } // 맨 위가 작으면 지운다
    st.push(d);
  }
  st.length -= k; // 이번엔 스택이 내려가는 순서라 뒤가 가장 작다
  return st.join("");
}
```

예시에서 `"4205379"`, `k = 3`은 `"5379"`가 되고, `"54321"`, `k = 2`는 `"543"`이 된다. 내려가기만 하는 입력이라 끝에서 지운다. 가장 큰 수에서는 앞의 0 문제가 생기지 않는다. 첫 자리가 0이 되려면 남은 숫자가 모두 0이어야 하기 때문이다.

### k개를 지우는 대신 m개를 남겨라

`k = n - m`으로 바꾸면 같은 문제다. 정수 배열에서 길이 m의 사전 순으로 가장 작은 부분 수열을 고르는 LeetCode 1673 Find the Most Competitive Subsequence가 이 형태다. 숫자 대신 정수라서 앞의 0 문제는 없고, 스택 길이를 m으로 자르면 된다.

```js
function mostCompetitive(nums, m) {
  const st = [];
  let drop = nums.length - m; // 지울 수 있는 개수 = 이 글의 k
  for (const x of nums) {
    while (drop > 0 && st.length && st[st.length - 1] > x) { st.pop(); drop--; }
    st.push(x);
  }
  st.length = m; // 남은 drop만큼 뒤를 자른다
  return st;
}
// [6, 2, 9, 4, 1, 7], m = 3 → [2, 1, 7]
```

2가 6을, 4가 9를, 1이 4를 지운다. 1이 2까지 지우려는 순간 지울 수 있는 개수가 다 떨어져 멈추니 2가 남는다.

### 두 배열에서 골라 합쳐라

LeetCode 321 Create Maximum Number(Hard)는 두 숫자 배열에서 합쳐서 m개를 골라 가장 큰 수를 만든다. 첫 배열에서 `i`개, 둘째에서 `m - i`개를 가장 크게 고르는 데 이 글의 스택을 쓰고, 두 결과를 병합하는 단계를 `i`마다 돌린다. 이 문제의 풀이가 부품으로 들어가는 셈이다.

### 같은 글자를 하나씩만 남겨라

LeetCode 316 Remove Duplicate Letters(같은 문제가 1081번에도 있다)는 글자마다 하나씩만 남기면서 사전 순으로 가장 작은 문자열을 만든다. 스택 맨 위가 새 글자보다 크고, 맨 위 글자가 뒤에 또 나온다면 지금 지워도 된다. "지울 기회 k"가 "뒤에 같은 글자가 남아 있는가"로 바뀌었을 뿐 모양이 같다. 이미 스택에 있는 글자는 다시 넣지 않는다는 조건이 하나 더 붙는다.

```js
function removeDuplicateLetters(s) {
  const last = {}; // 글자마다 마지막으로 나오는 위치
  for (let i = 0; i < s.length; i++) last[s[i]] = i;
  const st = [], inStack = new Set();
  for (let i = 0; i < s.length; i++) {
    const c = s[i];
    if (inStack.has(c)) continue; // 이미 남겨 둔 글자
    // 맨 위가 c보다 크고 뒤에 또 나온다면, 지금 지우고 나중에 다시 쓴다
    while (st.length && st[st.length - 1] > c && last[st[st.length - 1]] > i) {
      inStack.delete(st.pop());
    }
    st.push(c);
    inStack.add(c);
  }
  return st.join("");
}
// "dbcadcb" → "adcb"
```

`"dbcadcb"`에서 b가 오면서 뒤에 또 나오는 d를 지우고, a가 오면 역시 뒤에 또 나오는 b와 c를 지운다. 그 뒤의 d, c, b는 더 뒤에 같은 글자가 없어서 지울 수 없고 그대로 쌓인다.

## 작은 숫자가 오면 앞의 큰 숫자를 지운다

같은 자리 수라면 앞자리가 작은 수가 작다. 한 자리를 지울 때의 최선은 처음 내려가는 자리를 지우는 것이고, 단조 스택은 그 지우기를 처음부터 다시 찾지 않고 k번 해낸다. 새 숫자가 맨 위보다 작고 기회가 남아 있으면 맨 위를 지운다. 반복이 끝나면 남은 기회만큼 뒤에서 지우고, 앞의 0을 떼고, 비었으면 `"0"`을 돌려준다. 같은 숫자는 지우지 않는다는 등호까지 챙기면 된다.

## 면접에서 나올 만한 질문

### 왜 앞자리부터 작게 만들어야 하나요?

남는 자리 수가 `n - k`로 정해져 있어서, 0을 떼기 전에는 길이가 같은 수끼리의 비교다. 길이가 같으면 앞자리가 작은 쪽이 무조건 작고, 뒷자리는 앞자리가 같을 때만 의미가 있다. 그래서 앞자리를 줄일 수 있는 지우기를 먼저 한다.

### 한 자리만 지운다면 어디를 지우나요?

왼쪽부터 보다가 처음으로 다음 숫자보다 큰 자리를 지운다. 그 자리에 더 작은 다음 숫자가 오기 때문이다. 그보다 앞을 지우면 같거나 큰 숫자가 당겨지고, 그보다 뒤를 지우면 그 자리가 큰 채로 남는다. 내려가는 자리가 없으면 마지막 숫자를 지운다.

### 스택 풀이의 시간 복잡도는요? 안에 while이 있는데요.

숫자마다 스택에 한 번 들어가고 많아야 한 번 나오니 O(n)이다. `while`이 한 번 돌 때마다 스택에서 하나가 빠지고 `k`도 하나 준다. 그래서 전체에서 `while`이 도는 횟수는 처음 `k` 이하다.

### 반복이 끝났는데 k가 남으면 어떻게 하나요?

스택은 아래에서 위로 오르거나 같은 순서라서 뒤쪽이 가장 큰 숫자다. 뒤에서 남은 `k`개를 지운다. `"12345"`, `k = 2`처럼 오르기만 하는 입력이 이 경우이고, 이 처리가 빠지면 지우지 않은 원래 문자열이 그대로 나온다.

### 꺼내는 조건에 등호를 넣으면 안 되나요?

안 된다. 같은 숫자를 같은 숫자로 바꿔도 수는 그대로인데 지울 기회만 줄어든다. `"1121"`, `k = 1`에서 정답 `"111"` 대신 `"121"`이 나온다. 꺼내는 조건은 "바꾸면 이득일 때", 곧 맨 위가 엄격하게 클 때다.

### 앞의 0은 어떻게 처리하나요?

마지막에 결과에서 앞의 0을 떼고, 남은 게 없으면 `"0"`을 돌려준다. 쌓을 때 스택이 비어 있으면 0을 쌓지 않는 방법도 있는데, 이 0은 지운 게 아니라 떼어 낸 것이니 `k`를 쓰지 않는다. 이 방식에서는 스택이 짧아질 수 있어 끝에 남은 `k`를 지울 때 스택이 비었는지 확인한다.

### 가장 큰 수를 만들라고 하면 무엇이 바뀌나요?

비교 방향만 바뀐다. 새 숫자가 맨 위보다 크고 기회가 남아 있으면 맨 위를 지운다. 끝에 남은 `k`는 똑같이 뒤에서 지우는데, 이번에는 스택이 내려가는 순서라 뒤가 가장 작은 숫자다. 결과가 0으로 시작하려면 남은 숫자가 전부 0이어야 하니 앞의 0 처리는 사실상 필요 없다.
