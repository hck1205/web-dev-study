JavaScript에서 `123456789 * 987654321`을 계산하면 `121932631112635260`이 나온다. 진짜 답은 `121932631112635269`다. 끝자리 9가 0으로 바뀌었다. `Number`는 2^53 - 1(9,007,199,254,740,991)까지만 정수를 정확히 담고, 그 위로는 가까운 짝수 근처 값으로 반올림하기 때문이다. 돈 계산, 암호, ID처럼 자릿수가 긴 숫자를 다루는 코드는 이 한계를 넘는 순간 조용히 틀린다.

[Multiply Strings](https://leetcode.com/problems/multiply-strings/)는 그 상황을 연습 문제로 만든 것이다. 큰 수 라이브러리를 쓰지 않고, 문자열로 된 두 수를 곱한다. 이 글은 풀이 다섯 개를 느린 것부터 놓는다. 한 자리씩 곱해 문자열로 더하는 세로 곱셈, 결과 칸 배열에 바로 적는 방법, 올림을 마지막에 한꺼번에 하는 방법, 일곱 자리씩 묶어 곱하는 방법, 그리고 곱셈 횟수 자체를 줄이는 카라츠바다. 코드는 모두 Node.js 22, Python 3.13, Java 21에서 직접 돌렸다.

## 문자열 두 개를 곱해 문자열로 돌려준다

음이 아닌 정수 두 개가 문자열 `num1`, `num2`로 주어진다. 두 수의 곱을 문자열로 돌려준다. 내장 큰 수 타입(`BigInt`, Python의 `int` 변환, Java의 `BigInteger`)을 쓰거나 입력을 정수로 바로 바꾸면 안 된다.

- 길이는 각각 1 이상 200 이하다. 200자리끼리 곱하면 400자리가 나오니 어떤 언어의 기본 정수 타입에도 들어가지 않는다.
- 숫자 문자만 들어 있고, "0" 자체가 아니면 앞에 0이 붙지 않는다.

길이가 200이라 200 × 200 = 40,000번 한 자리 곱셈을 해도 아주 빠르다. 그래서 이 문제에서 O(m·n)은 충분하다. 면접에서 묻는 건 속도보다 "자리를 정확히 맞추는가"와 "올림을 빠뜨리지 않는가"다.

## 정수로 바꾸면 어디서 틀리나

가장 먼저 떠오르는 코드는 이것이다.

```js
function multiply(num1, num2) {
  return String(Number(num1) * Number(num2));
}
console.log(multiply("123", "45"));               // "5535"
console.log(multiply("123456789", "987654321"));  // "121932631112635260" (틀림)
```

작은 수에서는 맞는다. 곱이 2^53을 넘는 순간부터 끝자리가 틀어지고, 결과가 10^21 이상이면 `String`이 `1e+21` 같은 지수 표기를 내놓아 형식부터 망가진다. Java에서 `Long.parseLong`으로 바꾸면 19자리를 넘는 입력에서 `NumberFormatException`이 난다. 곱하기 전에 이미 담을 수 없다.

`BigInt`를 쓰면 `(BigInt(num1) * BigInt(num2)).toString()` 한 줄로 맞는 답이 나온다. 문제가 금지하는 방법이지만 버리지는 않는다. 아래 풀이들을 무작위 입력 3,000쌍으로 검증할 때 정답지로 썼다.

## 세로 곱셈을 손으로 해 보기

123 × 45를 공책에 쓰는 방식 그대로 풀어 본다.

```text
        1 2 3
      ×   4 5
      -------
        6 1 5     ← 123 × 5
      4 9 2       ← 123 × 4, 한 칸 왼쪽으로 밀어 쓴다
      -------
      5 5 3 5
```

두 가지를 한다. 아래 수의 한 자리로 위 수 전체를 곱하고, 그 줄을 자리에 맞게 밀어서 더한다. 밀어 쓰는 칸 수는 아래 수의 자리가 오른쪽에서 몇 번째인지로 정해진다. 4는 십의 자리라 한 칸, 백의 자리 숫자였다면 두 칸이다.

컴퓨터로 옮기려면 두 도구가 필요하다. 문자열 수에 한 자리 수를 곱하는 함수, 그리고 문자열 수 두 개를 더하는 함수다. 둘 다 오른쪽 끝에서부터 한 자리씩 계산하고 올림을 다음 자리로 넘긴다.

## 한 줄씩 곱해서 문자열로 더한다

```js
// 두 문자열 수를 더한다. 오른쪽 끝부터 한 자리씩
function addStrings(a, b) {
  let i = a.length - 1, j = b.length - 1, carry = 0;
  const out = [];
  while (i >= 0 || j >= 0 || carry) {
    const s = (i >= 0 ? a.charCodeAt(i--) - 48 : 0)   // '0'의 문자 코드가 48
            + (j >= 0 ? b.charCodeAt(j--) - 48 : 0)
            + carry;
    out.push(s % 10);                 // 이 자리에 남는 숫자
    carry = Math.floor(s / 10);       // 다음 자리로 넘길 올림
  }
  return out.reverse().join("");
}

// 문자열 수 a에 한 자리 수 d를 곱하고, 뒤에 0을 zeros개 붙인다
function multiplyDigit(a, d, zeros) {
  if (d === 0) return "0";
  let carry = 0;
  const out = [];
  for (let i = a.length - 1; i >= 0; i--) {
    const p = (a.charCodeAt(i) - 48) * d + carry;
    out.push(p % 10);
    carry = Math.floor(p / 10);
  }
  if (carry) out.push(carry);         // 맨 앞 올림을 잊지 않는다
  return out.reverse().join("") + "0".repeat(zeros);
}

function multiply(num1, num2) {
  if (num1 === "0" || num2 === "0") return "0";
  let total = "0";
  // num2의 오른쪽 자리부터. k는 밀어 쓸 칸 수
  for (let j = num2.length - 1, k = 0; j >= 0; j--, k++) {
    total = addStrings(total, multiplyDigit(num1, num2.charCodeAt(j) - 48, k));
  }
  return total;
}
console.log(multiply("123", "45")); // "5535"
```

`charCodeAt(i) - 48`은 문자 `'7'`을 숫자 7로 바꾸는 흔한 방법이다. 숫자 문자 `'0'`~`'9'`의 코드가 48~57로 붙어 있어서 가능하다. `Number(a[i])`로 써도 답은 같다.

`multiplyDigit`에서 `d === 0`이면 바로 `"0"`을 돌려준다. 그대로 계산하면 `"000"` 같은 줄이 생기는데, `addStrings`가 앞의 0을 지우지 않으니 결과 앞에 0이 남을 수 있다. 실제로 `addStrings("0", "000")`은 `"000"`이다.

### 얼마나 걸리나

`num1` 길이를 m, `num2` 길이를 n이라 하자. 줄 하나를 만드는 데 O(m), 그 줄은 0까지 붙어 최대 m + n자리라 더하는 데 O(m + n)이다. 줄이 n개라 전체는 O(n·(m + n))이다. m과 n이 비슷하면 O(m·n)과 같은 차수다. 공간은 중간 문자열들 때문에 O(m + n)이다.

맞는 풀이지만 n번 동안 매번 새 문자열을 만들고 뒤집고 합친다. 200자리끼리 곱하는 데 내 컴퓨터에서 한 번에 약 2.5ms가 걸렸다. 줄을 따로 만들지 않고 결과에 바로 더할 수 있다면 이 낭비가 사라진다.

## 곱이 들어갈 칸은 i + j로 정해진다

세로 곱셈의 줄들을 다시 보면, 결국 "위 수의 i번째 자리 × 아래 수의 j번째 자리"를 어느 칸에 더하느냐의 문제다. 그 칸 번호를 식으로 구하면 줄을 만들 필요가 없다.

먼저 결과의 길이다. m자리 수는 10^m보다 작고 n자리 수는 10^n보다 작으니 곱은 10^(m+n)보다 작다. 그래서 곱은 많아야 m + n자리다. 99 × 99 = 9801처럼 정확히 m + n자리가 될 수도 있고, 10 × 10 = 100처럼 m + n - 1자리가 될 수도 있다. 길이 m + n짜리 배열 `pos`를 0으로 만들어 두고, 맨 앞이 0이면 마지막에 지운다.

다음은 칸 번호다. 왼쪽부터 세어 `num1`의 i번째 자리는 10^(m-1-i)의 자리, `num2`의 j번째 자리는 10^(n-1-j)의 자리다. 둘을 곱하면 10^(m+n-2-i-j)의 자리에 들어간다. 길이 m + n짜리 배열에서 10^p의 자리는 왼쪽부터 (m + n - 1 - p)번 칸이니, 계산하면 i + j + 1번 칸이다. 한 자리끼리의 곱은 많아야 81이라 두 자리가 되는데, 일의 자리는 `pos[i + j + 1]`, 십의 자리(올림)는 한 칸 왼쪽인 `pos[i + j]`로 간다.

```text
num1 = "123" (i = 0, 1, 2)   num2 = "45" (j = 0, 1)

pos 칸:      0     1     2     3     4
1 × 4               ■     ■                  i=0, j=0 → 칸 1, 올림은 칸 0
2 × 5                     ■     ■            i=1, j=1 → 칸 3, 올림은 칸 2
3 × 5                           ■     ■      i=2, j=1 → 칸 4, 올림은 칸 3
```

이 식 하나가 이 문제의 전부라고 해도 된다. 세로 곱셈에서 "한 칸 밀어 쓴다"가 j가 하나 줄 때 칸 번호가 하나 줄어드는 것으로 바뀌었다.

## 결과 칸에 바로 적고 올림을 넘긴다

```js
function multiply(num1, num2) {
  if (num1 === "0" || num2 === "0") return "0";
  const m = num1.length, n = num2.length;
  const pos = new Array(m + n).fill(0);       // 곱은 많아야 m + n자리
  for (let i = m - 1; i >= 0; i--) {          // 오른쪽 자리부터
    const a = num1.charCodeAt(i) - 48;
    for (let j = n - 1; j >= 0; j--) {
      // 이 칸에 이미 있던 값까지 더한다
      const sum = a * (num2.charCodeAt(j) - 48) + pos[i + j + 1];
      pos[i + j + 1] = sum % 10;              // 일의 자리는 이 칸에 남기고
      pos[i + j] += Math.floor(sum / 10);     // 넘친 만큼은 한 칸 왼쪽에 더한다
    }
  }
  let k = 0;
  while (k < pos.length - 1 && pos[k] === 0) k++;  // 앞의 0을 건너뛴다(마지막 한 칸은 남긴다)
  return pos.slice(k).join("");
}
console.log(multiply("123", "45"), multiply("99", "99"), multiply("0", "52")); // 5535 9801 0
```

`sum`에 `pos[i + j + 1]`을 더하는 게 중요하다. 그 칸에는 앞에서 다른 곱이 남긴 숫자와 오른쪽에서 넘어온 올림이 이미 있다. 이 셋을 합친 값을 다시 일의 자리와 올림으로 나눈다.

`pos[i + j]`에는 `+=`만 하고 10으로 나누지 않는다. 잠깐 10을 넘어도 괜찮다. 그 칸은 반복의 다음 차례(j가 하나 줄었을 때)에 `pos[i + j + 1]` 자리가 되어 다시 나눠지기 때문이다. 다만 j = 0일 때 올림을 받은 `pos[i]`는 이번 줄에서는 다시 처리되지 않고, 다음 i(한 줄 위 자리)의 첫 계산에서 처리된다. 맨 마지막 `pos[0]`은 누구도 다시 나누지 않지만, 곱 전체가 m + n자리를 넘지 않으니 9를 넘을 수 없다.

### 복잡도

이중 반복이 m × n번 돌고 한 번에 하는 일은 상수라 시간 O(m·n)이다. 공간은 `pos` 배열 m + n칸과 결과 문자열이라 O(m + n)이다. 중간 문자열을 만들지 않으니 200자리끼리 곱하는 데 약 0.72ms로, 앞 풀이보다 세 배 넘게 빨랐다.

이 풀이가 면접에서 가장 많이 기대하는 답이다. 짧고, 칸 번호를 식으로 설명할 수 있고, 올림 처리가 한 곳에 모여 있다.

## 올림은 마지막에 한 번만 넘긴다

앞 풀이는 안쪽 반복마다 `% 10`과 `Math.floor(/ 10)`을 한다. 나눗셈은 곱셈이나 덧셈보다 비싼 연산이다. 그런데 꼭 매번 나눠야 할까. 각 칸에 곱을 그냥 계속 더해 두고, 모든 곱이 끝난 뒤 오른쪽 칸부터 한 번만 올림을 넘겨도 답은 같다. 덧셈은 순서를 바꿔도 결과가 같기 때문이다.

```js
function multiply(num1, num2) {
  if (num1 === "0" || num2 === "0") return "0";
  const m = num1.length, n = num2.length;
  const pos = new Array(m + n).fill(0);
  for (let i = 0; i < m; i++)
    for (let j = 0; j < n; j++)
      pos[i + j + 1] += (num1.charCodeAt(i) - 48) * (num2.charCodeAt(j) - 48);  // 쌓기만 한다
  for (let k = m + n - 1; k > 0; k--) {       // 오른쪽 칸부터 올림을 한 번에 넘긴다
    pos[k - 1] += Math.floor(pos[k] / 10);
    pos[k] %= 10;
  }
  return pos[0] === 0 ? pos.slice(1).join("") : pos.join("");
}
```

123 × 45로 쌓기만 끝낸 배열은 `[0, 4, 13, 22, 15]`다. 칸 4의 15에서 1을 넘기면 칸 3이 23, 거기서 2를 넘기면 칸 2가 15, 다시 1을 넘기면 칸 1이 5가 되어 `[0, 5, 5, 3, 5]`로 앞 풀이와 같아진다.

이런 순서를 쓸 수 있는 건 칸이 넘치지 않아서다. 한 칸에 쌓이는 곱은 많아야 min(m, n)개이고 각각 81 이하라, 200자리끼리라도 200 × 81 = 16,200이다. JavaScript `Number`는 물론 Java `int`에도 넉넉하다. 입력이 수천만 자리로 커지면 이 계산을 다시 해야 한다.

나눗셈이 m·n번에서 m + n번으로 줄었고, 측정해 보니 200자리끼리 약 0.09ms로 앞 풀이보다 일곱 배쯤 빨랐다. 안쪽 반복이 곱하고 더하기만 해서 앞 계산을 기다리는 일이 줄어든 덕으로 보인다. 복잡도 차수는 O(m·n)으로 같다. 면접에서는 앞 풀이를 먼저 쓰고 "올림을 미룰 수 있다"를 덧붙이는 정도가 좋다.

## 일곱 자리씩 묶어서 곱한다

한 칸에 한 자리씩 담는 건 10진법으로 계산하는 셈이다. 칸 하나에 일곱 자리를 담으면 10^7진법이 되고, 칸 수가 1/7로 줄어 곱셈 횟수는 1/49로 준다. 실제 큰 수 라이브러리들이 32비트나 64비트 단위로 묶어 계산하는 것과 같은 생각이다.

왜 일곱 자리인가. 칸 값은 10^7 미만이니 두 칸의 곱은 10^14 미만이다. 여기에 그 칸에 있던 값과 올림을 더해도 약 10^14라, JavaScript가 정확히 담는 2^53(약 9 × 10^15) 안에 든다. 여덟 자리로 묶으면 곱이 10^16에 가까워 이 한계를 넘는다.

```js
function multiply(num1, num2) {
  if (num1 === "0" || num2 === "0") return "0";
  const B = 1e7, W = 7;
  // 오른쪽부터 일곱 자리씩 잘라 숫자 배열로. 0번이 가장 낮은 칸이다
  const split = (s) => {
    const r = [];
    for (let e = s.length; e > 0; e -= W) r.push(Number(s.slice(Math.max(0, e - W), e)));
    return r;
  };
  const a = split(num1), b = split(num2);
  const r = new Array(a.length + b.length).fill(0);
  for (let i = 0; i < a.length; i++) {
    let carry = 0;
    for (let j = 0; j < b.length; j++) {
      const cur = r[i + j] + a[i] * b[j] + carry;   // 1e14 정도라 안전하다
      carry = Math.floor(cur / B);
      r[i + j] = cur % B;
    }
    let k = i + b.length;
    while (carry) {                                 // 남은 올림을 위 칸으로
      const cur = r[k] + carry;
      r[k] = cur % B;
      carry = Math.floor(cur / B);
      k++;
    }
  }
  let top = r.length - 1;
  while (top > 0 && r[top] === 0) top--;
  let s = String(r[top]);                            // 가장 높은 칸은 앞에 0을 붙이지 않는다
  for (let t = top - 1; t >= 0; t--) s += String(r[t]).padStart(W, "0");  // 나머지 칸은 일곱 자리를 채운다
  return s;
}
```

여기서는 칸 번호가 i + j다. 배열을 가장 낮은 칸부터 담아서(리틀 엔디언) 그렇다. 앞 풀이처럼 높은 자리부터 담으면 i + j + 1이 되는데, 어느 쪽이든 "두 위치의 합"이라는 구조는 같다.

다시 문자열로 바꿀 때 `padStart`가 중요하다. 칸 값이 `305`라면 실제로는 `0000305`라는 일곱 자리다. 이걸 빼먹으면 중간의 0이 사라진다. 가장 높은 칸만은 0을 채우지 않는다. 200자리끼리 약 0.014ms였다. 대신 묶음 크기를 정한 근거(2^53)를 말할 수 있어야 하고, Java에서 같은 방법을 쓰면 곱이 `int`를 넘으니 `long`으로 계산한다. `long`이면 10^9씩 묶어도 된다(10^18 미만).

## 곱셈 세 번으로 줄이는 카라츠바

지금까지는 모두 O(m·n)이다. 자리 수가 수만, 수백만이 되면 차수 자체를 낮춰야 한다. 1960년 카라츠바(Karatsuba)가 찾은 방법은 큰 수를 반으로 나눠 곱셈 네 번이 필요한 자리를 세 번으로 줄인다.

x = x1 × 10^h + x0, y = y1 × 10^h + y0로 나누면 다음과 같이 펼쳐진다.

```text
x × y = x1·y1 × 10^(2h) + (x1·y0 + x0·y1) × 10^h + x0·y0
```

가운데 항에 곱셈이 두 번 필요해 보이지만 `(x1 + x0)(y1 + y0) = x1·y1 + x1·y0 + x0·y1 + x0·y0`이다. 여기서 이미 구한 x1·y1과 x0·y0을 빼면 가운데 항이 나온다. 곱셈 세 번과 덧셈·뺄셈 몇 번으로 끝난다. 이걸 재귀로 반복하면 T(n) = 3T(n/2) + O(n)이고, 풀면 O(n^log₂3) ≈ O(n^1.585)다.

```js
// a ≥ b인 두 문자열 수의 차
function subStrings(a, b) {
  let i = a.length - 1, j = b.length - 1, borrow = 0;
  const out = [];
  while (i >= 0) {
    let d = (a.charCodeAt(i--) - 48) - borrow - (j >= 0 ? b.charCodeAt(j--) - 48 : 0);
    if (d < 0) { d += 10; borrow = 1; } else borrow = 0;
    out.push(d);
  }
  return out.reverse().join("").replace(/^0+/, "") || "0";
}
const strip = (s) => s.replace(/^0+/, "") || "0";

function karatsuba(x, y) {
  x = strip(x); y = strip(y);
  if (x.length <= 16 && y.length <= 16) return multiply(x, y);  // 작으면 앞의 O(m·n) 풀이로
  const n = Math.max(x.length, y.length), h = Math.floor(n / 2);
  x = x.padStart(n, "0"); y = y.padStart(n, "0");               // 길이를 맞춘다
  const x1 = x.slice(0, n - h), x0 = x.slice(n - h);            // 아래 h자리와 나머지
  const y1 = y.slice(0, n - h), y0 = y.slice(n - h);
  const z2 = karatsuba(x1, y1);
  const z0 = karatsuba(x0, y0);
  const z1 = subStrings(subStrings(karatsuba(addStrings(x1, x0), addStrings(y1, y0)), z2), z0);
  return strip(addStrings(addStrings(z2 + "0".repeat(2 * h), z1 + "0".repeat(h)), z0));
}
```

`multiply`는 앞의 칸 배열 풀이고, `addStrings`는 세로 곱셈 풀이의 함수다. 16자리 이하에서 재귀를 멈추는 건 작은 수에서는 카라츠바의 덧셈·뺄셈 비용이 줄어든 곱셈보다 커서다.

실제로 재 보면 200자리끼리 약 0.55ms로, 칸 배열 풀이(0.72ms)보다 조금 빠르고 올림을 미루는 풀이(0.09ms)보다는 훨씬 느리다. 문자열을 자르고 붙이는 비용이 크고, 200자리는 차수의 이득이 드러나기에 너무 작다. 그래서 이 문제의 답으로는 쓰지 않는다. 다만 "입력이 10만 자리라면?"이라는 꼬리 질문의 답이 이것이고, 실제 큰 수 라이브러리가 쓰는 방법이기도 하다. CPython의 `int`와 Java의 `BigInteger`는 숫자가 일정 크기를 넘으면 카라츠바로 바꾼다(Java는 더 크면 Toom-Cook 3까지 쓴다). 그보다 훨씬 큰 수는 FFT로 O(n log n)에 곱하지만 이 글의 범위를 넘는다.

분할 정복과 재귀식 풀이는 [재귀와 백트래킹](/posts/recursion-backtracking), 차수 읽는 법은 [빅오 표기법](/posts/big-o-notation)에 있다.

## Python의 int와 Java의 equals

칸 배열 풀이를 옮겼다.

```python
class Solution:
    def multiply(self, num1: str, num2: str) -> str:
        if num1 == "0" or num2 == "0":
            return "0"
        m, n = len(num1), len(num2)
        pos = [0] * (m + n)                      # 곱의 자릿수는 많아야 m + n
        for i in range(m - 1, -1, -1):
            a = ord(num1[i]) - 48                # '0'의 코드가 48
            for j in range(n - 1, -1, -1):
                s = a * (ord(num2[j]) - 48) + pos[i + j + 1]
                pos[i + j + 1] = s % 10          # 이 자리에 남는 숫자
                pos[i + j] += s // 10            # 올림은 한 칸 왼쪽으로
        k = 0
        while k < len(pos) - 1 and pos[k] == 0:  # 앞의 0을 건너뛴다
            k += 1
        return "".join(map(str, pos[k:]))

s = Solution()
print(s.multiply("123", "45"), s.multiply("99", "99"), s.multiply("0", "52"))
print(s.multiply("9" * 20, "9" * 20) == str(int("9" * 20) ** 2))
```

```text
5535 9801 0
True
```

Python은 `int`가 크기 제한이 없어서 `str(int(num1) * int(num2))`가 그냥 맞는 답을 낸다. 채점에서는 통과하지만 문제가 금지한 방법이라 면접에서는 감점이다. 대신 마지막 줄처럼 자기 풀이를 검증하는 데 쓰면 좋다. 올림은 `//`(정수 나눗셈)로 구한다. `/`를 쓰면 실수가 되어 `pos`에 `1.5` 같은 값이 들어간다.

```java
class Solution {
    public String multiply(String num1, String num2) {
        if (num1.equals("0") || num2.equals("0")) return "0";
        int m = num1.length(), n = num2.length();
        int[] pos = new int[m + n];                    // 0으로 채워진 채 만들어진다
        for (int i = m - 1; i >= 0; i--) {
            int a = num1.charAt(i) - '0';
            for (int j = n - 1; j >= 0; j--) {
                int sum = a * (num2.charAt(j) - '0') + pos[i + j + 1];
                pos[i + j + 1] = sum % 10;             // 이 자리에 남는 숫자
                pos[i + j] += sum / 10;                // int 나눗셈은 소수점을 버린다
            }
        }
        StringBuilder sb = new StringBuilder();
        for (int p : pos) {
            if (sb.length() == 0 && p == 0) continue;  // 앞의 0을 건너뛴다
            sb.append(p);
        }
        return sb.toString();
    }

    public static void main(String[] args) {
        Solution s = new Solution();
        System.out.println(s.multiply("123", "45") + " " + s.multiply("99", "99") + " " + s.multiply("0", "52"));
        String big = "9".repeat(200);
        System.out.println(s.multiply(big, big).equals(new java.math.BigInteger(big).pow(2).toString()));
    }
}
```

```text
5535 9801 0
true
```

Java에서 `num1 == "0"`으로 비교하면 안 된다. 문자열 객체가 같은지를 보는 비교라, 입력으로 들어온 `"0"`이 리터럴과 다른 객체면 `false`가 된다. `equals`를 쓴다. 문자에서 `'0'`을 빼면 `int`가 나오는 건 `char`가 숫자 타입이라서다. 결과를 붙일 때 `String`에 `+=`를 반복하면 매번 새 문자열을 만드니 `StringBuilder`를 쓴다. 앞의 0을 건너뛰는 이 방식은 `"0"`이 들어오면 빈 문자열을 내놓으니, 맨 앞의 `"0"` 검사가 여기서는 꼭 필요하다.

## 다섯 가지 곱셈을 재 보면

200자리 9끼리 곱하기를 3,000번 돌린 평균이다(Node.js 22, 내 컴퓨터). 절대값보다 서로의 비율을 본다.

| 풀이 | 시간 | 추가 공간 | 200자리 한 번 | 언제 고르나 |
|---|---|---|---|---|
| 줄마다 곱해 문자열로 더하기 | O(n·(m + n)) | O(m + n) | 약 2.5ms | 세로 곱셈을 그대로 옮기고 싶을 때. 설명은 쉽지만 문자열을 많이 만든다 |
| 결과 칸에 바로 적기 | O(m·n) | O(m + n) | 약 0.72ms | 면접의 기본 답. 칸 번호 i + j + 1을 설명할 수 있다 |
| 올림을 마지막에 | O(m·n) | O(m + n) | 약 0.09ms | 같은 차수에서 상수를 줄이고 싶을 때. 칸이 넘치지 않는 근거를 댄다 |
| 일곱 자리씩 묶기 | O(m·n / 49) | O(m + n) | 약 0.014ms | 실제 큰 수 구현. 묶음 크기를 정밀도 한계에서 정한다 |
| 카라츠바 | O(n^1.585) | O(n) | 약 0.55ms | 수만 자리 이상. 이 문제 크기에서는 오히려 이득이 없다 |

카라츠바의 공간은 재귀가 한 갈래로 내려가는 동안 동시에 살아 있는 문자열 길이의 합이다. 층마다 길이가 절반이라 n + n/2 + n/4 + ... = O(n)이다.

## 앞의 0과 올림에서 자주 틀린다

### 앞의 0을 모두 지운다

```js
let k = 0;
while (k < pos.length && pos[k] === 0) k++;   // 마지막 칸까지 지운다
return pos.slice(k).join("");                  // multiply("0", "52") → ""
```

맨 앞의 `"0"` 검사를 빼고 이렇게 쓰면 곱이 0일 때 빈 문자열이 나온다. 반복 조건을 `k < pos.length - 1`로 두면 마지막 한 칸은 남아 `"0"`이 된다. 정규식 `replace(/^0+/, "")`도 같은 함정이 있어서 `|| "0"`을 붙여야 한다.

### 배열 길이를 m + n - 1로 잡는다

123 × 45 = 5535처럼 곱이 m + n - 1자리인 경우만 떠올리면 그렇게 잡기 쉽다. 길이를 `m + n - 1`로 줄이고 곱을 i + j 칸, 올림을 i + j - 1 칸에 적게 고쳐 봤다. 123 × 45는 맞게 나오지만, 99 × 99 = 9801은 i = j = 0일 때 올림 9를 받을 칸(-1번)이 없어 그대로 버려지고 `801`이 나온다. 꽉 찬 경우를 테스트에 꼭 넣어야 잡힌다.

### 칸에 있던 값을 더하지 않는다

```js
const sum = a * b;                       // pos[i + j + 1]을 빠뜨렸다
pos[i + j + 1] = sum % 10;               // 앞에서 적힌 값을 덮어쓴다
pos[i + j] += Math.floor(sum / 10);
```

123 × 45에서 세 번째 단계가 칸 3의 3을 덮어써 버린다. 그 칸에는 앞 계산이 남긴 숫자가 있으니 곱과 함께 다시 나눠야 한다. 덮어쓰지 않고 `pos[i + j + 1] += sum % 10`으로 고치면 이번엔 칸이 10을 넘은 채로 남을 수 있다. 앞 풀이처럼 합쳐서 나누거나, 올림을 미루는 풀이처럼 끝에서 한꺼번에 정리해야 한다.

### 문자를 숫자로 바꾸지 않고 더한다

JavaScript에서 `"3" * "5"`는 15지만 `"3" + 5`는 `"35"`다. 곱셈은 문자열을 숫자로 바꿔 주고 덧셈은 이어 붙인다. `pos[k] + num1[i]`처럼 쓰는 순간 배열에 문자열이 섞인다. 문자를 꺼낼 때 바로 `charCodeAt(i) - 48`로 숫자로 만들어 두면 이 실수가 없다.

### 묶음 풀이에서 0을 채우지 않는다

일곱 자리씩 묶을 때 중간 칸이 `305`이면 `"0000305"`로 붙여야 한다. `String(r[t])`만 쓰면 1 × 10000003에서 아래 칸 `3`이 `0000003`이 되지 못해 답이 `13`으로 나온다. 실제로 돌려 본 결과다.

415. Add Strings가 그 문제다. 이 글의 `addStrings`가 답이고, 두 수의 길이가 다를 때 짧은 쪽을 0으로 보는 것과 마지막 올림을 빠뜨리지 않는 것만 보면 된다. 같은 생각을 배열로 하면 [66. Plus One](/posts/leetcode-plus-one), 연결 리스트로 하면 [2. Add Two Numbers](/posts/leetcode-add-two-numbers)다. 2진수 문자열이면 67. Add Binary다.

### 입력이 수만 자리라면

O(m·n)이 수억 번이 된다. 먼저 일곱 자리 묶기로 상수를 줄이고, 더 크면 카라츠바나 FFT로 차수를 낮춘다. 실무라면 직접 짜지 않고 언어의 큰 수 타입이나 GMP 같은 라이브러리를 쓴다. 직접 구현이 필요한 건 그런 라이브러리를 쓸 수 없는 환경이나, 정해진 자리 수의 고정 소수점 계산을 직접 다룰 때 정도다.

### 결과를 어떤 수로 나눈 나머지만 필요하다면

곱 전체를 만들 필요가 없다. 각 수를 문자열 앞에서부터 읽으며 `r = (r * 10 + d) % M`으로 나머지를 구하고, 두 나머지를 곱해 다시 나눈다. 이때 곱이 `Number`의 정밀도를 넘지 않게 M이 크면 `BigInt`나 나눠 곱하기를 쓴다. 거듭제곱의 나머지는 [Pow(x, n)](/posts/leetcode-powx-n)의 빠른 거듭제곱과 이어진다.

### 비슷한 문제

- 415. Add Strings, 67. Add Binary는 같은 올림 처리의 덧셈판이다.
- [66. Plus One](/posts/leetcode-plus-one)은 올림이 맨 앞까지 번지는 가장 작은 경우다.
- [2. Add Two Numbers](/posts/leetcode-add-two-numbers)는 자릿수가 연결 리스트로 거꾸로 들어온다.
- [371. Sum of Two Integers](/posts/leetcode-sum-of-two-integers)는 올림을 비트 연산으로 만든다.
- 같은 패턴의 [50. Pow(x, n)](/posts/leetcode-powx-n)도 곱셈 횟수를 줄이는 문제다.

## 면접에서 나올 만한 질문

### 결과 배열의 길이를 왜 m + n으로 잡았나요?

m자리 수는 10^m보다 작고 n자리 수는 10^n보다 작아서 곱은 10^(m+n)보다 작다. 그래서 많아야 m + n자리다. 99 × 99 = 9801처럼 꽉 차는 경우가 있으니 하나 적게 잡으면 맨 앞 올림을 담을 곳이 없다. 꽉 차지 않으면 맨 앞이 0으로 남는데, 마지막에 그 0을 지운다.

### 두 자리의 곱이 왜 i + j + 1 칸에 들어가나요?

`num1`의 i번째 자리는 10^(m-1-i)의 자리, `num2`의 j번째 자리는 10^(n-1-j)의 자리라서 곱은 10^(m+n-2-i-j)의 자리에 속한다. 길이 m + n짜리 배열에서 그 자리를 왼쪽부터 세면 i + j + 1번이다. 한 자리 곱은 두 자리까지라 일의 자리는 그 칸에, 십의 자리 올림은 한 칸 왼쪽인 i + j 칸에 간다.

### 올림이 칸 하나를 10 이상으로 남겨 두지는 않나요?

`pos[i + j]`에 올림을 더한 직후에는 10을 넘을 수 있다. 하지만 그 칸은 다음 계산에서 `pos[i + j + 1]` 자리가 되어 곱과 함께 다시 10으로 나눠지니 결국 한 자리로 정리된다. 맨 앞 칸 `pos[0]`만 다시 나눠지지 않는데, 곱이 m + n자리를 넘지 않으니 9를 넘을 수 없다.

### 시간 복잡도를 더 줄일 수 있나요?

차수를 줄이려면 카라츠바를 쓴다. 큰 수를 반으로 나눠 곱셈 네 번을 세 번으로 바꾸고 재귀로 반복해 O(n^1.585)가 된다. 더 크면 FFT로 O(n log n)이다. 다만 200자리에서는 덧셈·뺄셈과 문자열 처리 비용 때문에 오히려 느려서, 이 문제에서는 올림을 미루거나 여러 자리를 묶어 상수를 줄이는 쪽이 실제로 빠르다.

### 왜 BigInt나 int 변환을 쓰면 안 되나요?

문제가 큰 수 곱셈을 직접 구현하는지를 보려는 것이라 금지한다. 실무에서는 오히려 그걸 쓰는 게 맞다. 다만 JavaScript의 `Number`는 2^53 - 1까지만 정수를 정확히 담아서 그 위로는 조용히 틀린다는 건 알아야 한다. 123456789 × 987654321이 끝자리 9 대신 0으로 나오는 게 그 예다.

### 여러 자리를 묶을 때 몇 자리까지 묶을 수 있나요?

곱하고 더한 중간값이 그 언어의 정확한 정수 범위 안에 들어와야 한다. JavaScript `Number`는 2^53(약 9 × 10^15)까지라 일곱 자리로 묶으면 곱이 10^14 정도로 안전하고, 여덟 자리면 10^16에 가까워 넘는다. Java `long`은 약 9.2 × 10^18이라 아홉 자리씩 묶을 수 있다.

### 곱이 0일 때 따로 처리해야 하나요?

앞의 0을 건너뛸 때 마지막 한 칸을 남기면 따로 처리하지 않아도 `"0"`이 나온다. 하지만 마지막 칸까지 지우는 코드나 `StringBuilder`로 0을 건너뛰는 코드는 빈 문자열을 내놓는다. 어느 쪽이든 맨 앞에서 `"0"`을 검사해 두면 안전하고 불필요한 계산도 줄어든다.
