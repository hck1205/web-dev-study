[Valid Parenthesis String](https://leetcode.com/problems/valid-parenthesis-string/)은 LeetCode 678번이다. [Valid Parentheses](/posts/leetcode-valid-parentheses)에 별표 하나를 더했을 뿐인데 문제의 성격이 바뀐다. 별표가 무엇이 될지 미리 정할 수 없어서, 스택 하나로 순서대로 지워 나가는 방법이 그대로 통하지 않는다. 그래서 완전 탐색, 동적 계획법, 스택, 그리디가 모두 성립하는 드문 문제가 되고, 면접에서 "다른 풀이도 있나"를 계속 물을 수 있다.

이 글은 여섯 풀이를 느린 것부터 본다. 별표를 모두 바꿔 보는 완전 탐색, 구간 DP, 열린 개수를 상태로 둔 메모 재귀와 그 표 버전, 여는 괄호와 별표의 위치를 따로 쌓는 두 스택, 열린 개수의 범위만 들고 다니는 그리디, 양쪽에서 한 번씩 훑는 풀이다. 코드는 Node.js 22, Python 3, Java 21에서 돌렸다.

## 별표가 섞인 괄호 줄

문자열 `s`는 `(`, `)`, `*` 세 글자로만 이루어져 있다. 다음 규칙을 만족하면 올바르다.

- 여는 괄호마다 그 뒤에 짝이 되는 닫는 괄호가 있다.
- 닫는 괄호마다 그 앞에 짝이 되는 여는 괄호가 있다.
- `*`는 `(`, `)`, 빈 문자열 중 하나로 바꿔 생각할 수 있다.

별표를 적당히 바꿔서 올바른 괄호 줄이 되면 `true`다. 길이는 1 이상 100 이하다. 짧아서 O(n³)도 통과하지만, 별표를 모두 바꿔 보는 O(3^k)는 별표가 20개만 넘어도 무너진다. 면접에서는 O(n)까지 내려가는 과정을 보여 주는 게 목표다.

괄호 종류가 하나뿐이어서 다행이다. 종류가 하나면 "지금 열려 있는 괄호가 몇 개인가"라는 숫자 하나로 올바른지를 판정할 수 있다. 앞에서부터 읽으며 `(`면 1을 더하고 `)`면 1을 빼서, 그 숫자가 한 번도 음수가 되지 않고 끝에서 0이면 올바르다. 이 숫자를 이 글에서는 "열린 수"라고 부른다. 별표가 없을 때의 이 판정은 [Valid Parentheses 글](/posts/leetcode-valid-parentheses#한-종류라면-숫자-하나로-충분하다)에 자세히 있다.

## 별표 하나에 세 갈래 길

작은 예시로 손으로 풀어 본다. `s = "(*))"`다.

별표를 `(`로 바꾸면 `(())`이고, 올바르다. `)`로 바꾸면 `()))`이고, 셋째 글자에서 열린 수가 음수가 되어 틀린다. 빈 문자열로 바꾸면 `())`이고, 역시 틀린다. 하나만 맞으면 되니 답은 `true`다.

이번엔 `s = "(**)("`다. 마지막 글자가 `(`라서 그 괄호를 닫아 줄 것이 뒤에 없다. 별표를 어떻게 바꿔도 끝에 열린 괄호가 하나 남는다. 답은 `false`다.

손으로 하다 보면 별표마다 세 갈래로 길이 나뉘는 게 보인다. 별표가 k개면 3^k가지다. 다행히 갈래가 많아도 "지금 열린 수"가 같아지면 그 뒤의 운명은 같다. 이 관찰이 DP로 가는 길이고, 열린 수가 될 수 있는 값이 띄엄띄엄이 아니라 이어진 구간이라는 관찰이 그리디로 가는 길이다.

## 별표를 하나씩 바꿔 보는 완전 탐색

곧은 풀이부터 쓴다. 별표 위치를 모아 두고, 별표마다 `(`, `)`, 빈 문자열을 차례로 넣어 보는 백트래킹이다. 모든 별표를 정하면 열린 수로 올바른지 본다. 백트래킹의 일반적인 틀은 [재귀와 백트래킹 글](/posts/recursion-backtracking)에 있다.

```js
function isBalanced(t) {                           // 별표가 없는 괄호 줄 판정
  let bal = 0;
  for (const ch of t) {
    bal += ch === "(" ? 1 : -1;
    if (bal < 0) return false;                     // 닫는 괄호가 먼저 나왔다
  }
  return bal === 0;
}

function checkValidString(s) {
  const stars = [];
  for (let i = 0; i < s.length; i++) if (s[i] === "*") stars.push(i);
  const chars = s.split("");
  function go(k) {
    if (k === stars.length) return isBalanced(chars.filter(c => c !== "").join(""));
    for (const r of ["(", ")", ""]) {              // k번째 별표를 셋 중 하나로 바꾼다
      chars[stars[k]] = r;
      if (go(k + 1)) return true;
    }
    chars[stars[k]] = "*";                         // 되돌려 놓는다
    return false;
  }
  return go(0);
}
```

별표가 k개면 3^k가지를 만들고 하나마다 O(n)으로 판정하니 O(3^k · n)이다. 공간은 재귀 깊이와 문자 배열로 O(n)이다. 답이 `false`라 모든 경우를 다 보는 입력으로 재 봤다.

```text
11 brute false 41.6
14 brute false 587.5
```

별표 10개에서 42ms, 13개에서 0.6초다. 별표가 하나 늘 때마다 세 배씩 느려진다. 길이 100짜리 문자열이 모두 별표면 3^100가지라 끝나지 않는다.

## 구간마다 올바른지 표에 적는다

부분 문자열 `s[i..j]`가 올바른지를 `dp[i][j]`에 적는 구간 DP다. 구간 DP의 생각은 [동적 계획법 글](/posts/dynamic-programming)에 있다. 길이가 짧은 구간부터 채운다.

`s[i..j]`가 올바르려면 둘 중 하나다.

- `s[i]`가 별표이고 그걸 빈 문자열로 쓴다. 그러면 `s[i+1..j]`가 올바르면 된다.
- `s[i]`를 여는 괄호로 쓴다(`(`이거나 `*`). 그 짝이 되는 닫는 괄호 `s[k]`(`)`이거나 `*`)를 골라, 사이 `s[i+1..k-1]`과 뒤 `s[k+1..j]`가 모두 올바르면 된다. 사이나 뒤가 비어 있으면 올바른 것으로 친다.

```js
function checkValidString(s) {
  const n = s.length;
  const dp = Array.from({ length: n }, () => new Array(n).fill(false));
  const canOpen = c => c === "(" || c === "*";
  const canClose = c => c === ")" || c === "*";
  for (let i = 0; i < n; i++) if (s[i] === "*") dp[i][i] = true;       // 길이 1: 별표만
  for (let i = 0; i + 1 < n; i++)                                       // 길이 2
    if (canOpen(s[i]) && canClose(s[i + 1])) dp[i][i + 1] = true;
  for (let len = 2; len < n; len++) {                                   // 길이 3부터
    for (let i = 0; i + len < n; i++) {
      const j = i + len;
      if (s[i] === "*" && dp[i + 1][j]) { dp[i][j] = true; continue; }  // 별표를 비운다
      if (!canOpen(s[i])) continue;
      for (let k = i + 1; k <= j; k++) {                                // s[i]의 짝 s[k]를 고른다
        if (canClose(s[k]) && (k === i + 1 || dp[i + 1][k - 1]) && (k === j || dp[k + 1][j])) {
          dp[i][j] = true;
          break;
        }
      }
    }
  }
  return dp[0][n - 1];
}
```

길이 2짜리 `**`는 둘째 줄에서 `(`와 `)`로 짝이 맞아 참이 된다. 둘 다 비워도 되니 맞는 값이다.

구간이 O(n²)개이고 구간마다 짝 k를 O(n)개 보니 시간 O(n³), 공간 O(n²)이다. 길이 100에서 18ms라 LeetCode는 통과한다. 그런데 길이 1000이면 1초 가까이 걸렸다. 구간 DP는 "어디서 끊을지"를 매번 다 해 보는 게 비용이다. 왼쪽부터 읽는 순서를 쓰면 끊을 곳을 고를 필요가 없어진다.

## 열린 수를 상태로 두는 메모 재귀

왼쪽부터 읽으며 상태를 "몇 번째 글자까지 읽었나(i)"와 "지금 열린 수(open)" 두 개로 둔다. 별표에서는 세 갈래로 나뉘지만, 같은 (i, open)에 다시 도착하면 앞에서 구한 답을 그대로 쓴다. 완전 탐색에서 3^k가지 길이 사실은 n × n개의 상태로 겹친다는 걸 이용하는 것이다. 메모이제이션 자체는 [JS 메모이제이션 글](/posts/js-memoization)에 있다.

```js
function checkValidString(s) {
  const n = s.length;
  const seen = new Map();                          // (i, open) -> 답
  function go(i, open) {
    if (open < 0) return false;                    // 닫는 괄호가 너무 많다
    if (i === n) return open === 0;                // 끝에서 열린 괄호가 없어야 한다
    const key = i * (n + 1) + open;
    if (seen.has(key)) return seen.get(key);
    let res;
    if (s[i] === "(") res = go(i + 1, open + 1);
    else if (s[i] === ")") res = go(i + 1, open - 1);
    else res = go(i + 1, open + 1) || go(i + 1, open - 1) || go(i + 1, open); // 별표는 세 갈래
    seen.set(key, res);
    return res;
  }
  return go(0, 0);
}
```

open은 0부터 n까지라 상태가 O(n²)개이고, 상태마다 일이 O(1)이니 시간 O(n²), 공간 O(n²)이다. 재귀 깊이는 n이다. 길이 100이면 1ms였다. 길이 1000에서는 217ms였는데, 이건 깊이 1000짜리 재귀와 Map 접근 비용이 커서다. 재귀 깊이가 걱정되면 같은 생각을 표로 옮긴다.

### 앞에서부터 표로 채운다

`can[o]`를 "지금까지 읽은 앞부분에서 열린 수가 o가 될 수 있는가"로 둔다. 처음엔 `can[0]`만 참이다. 글자를 하나 읽을 때마다 가능한 o들을 다음 표로 옮긴다.

```js
function checkValidString(s) {
  const n = s.length;
  let can = new Array(n + 2).fill(false);
  can[0] = true;                                   // 아무것도 읽지 않았을 때 열린 수는 0
  for (const ch of s) {
    const next = new Array(n + 2).fill(false);
    for (let o = 0; o <= n; o++) {
      if (!can[o]) continue;
      if (ch === "(" || ch === "*") next[o + 1] = true;            // 하나 연다
      if ((ch === ")" || ch === "*") && o > 0) next[o - 1] = true; // 하나 닫는다
      if (ch === "*") next[o] = true;                              // 별표를 비운다
    }
    can = next;
  }
  return can[0];                                   // 끝에서 열린 수 0이 가능한가
}
```

시간 O(n²)이지만 공간은 표 두 줄이라 O(n)이다. 재귀가 없어서 길이 1000에서 26ms, 3000에서 180ms로 메모 재귀보다 훨씬 빨랐다.

이 표를 찍어 보면 재미있는 게 보인다. 참인 칸이 언제나 한 덩어리로 붙어 있다. `(*))`를 읽으면 열린 수가 될 수 있는 값은 `{1}`, `{0, 1, 2}`, `{0, 1}`, `{0}`으로 바뀐다. 중간에 빈 칸이 없다. 그렇다면 표 전체를 들고 다닐 필요 없이 양 끝 두 숫자만 기억해도 된다. 이게 뒤의 그리디다. 그 전에 전혀 다른 방향의 풀이를 하나 보자.

## 여는 괄호와 별표의 자리를 따로 쌓는다

[Valid Parentheses](/posts/leetcode-valid-parentheses)에서 하던 대로 스택을 쓰되, 스택을 둘 둔다. 하나에는 여는 괄호의 위치를, 하나에는 별표의 위치를 쌓는다. 스택 자체는 [스택·큐 글](/posts/ds-stack-queue-deque)에 있다.

- `(`를 만나면 그 위치를 여는 괄호 스택에 넣는다.
- `*`를 만나면 그 위치를 별표 스택에 넣는다.
- `)`를 만나면 짝을 찾는다. 여는 괄호가 있으면 그걸 먼저 쓰고, 없으면 별표를 여는 괄호로 쓴다. 둘 다 없으면 실패다.

끝까지 읽은 뒤 여는 괄호가 남았으면, 남은 별표를 닫는 괄호로 써서 짝을 맞춘다. 이때 별표가 여는 괄호보다 뒤에 있어야 한다. 별표가 앞에 있으면 닫는 괄호가 여는 괄호보다 먼저 오는 꼴이라 짝이 될 수 없다. 두 스택의 꼭대기끼리 위치를 비교하며 꺼낸다.

```js
function checkValidString(s) {
  const open = [], star = [];                      // 위치를 쌓는다
  for (let i = 0; i < s.length; i++) {
    if (s[i] === "(") open.push(i);
    else if (s[i] === "*") star.push(i);
    else {                                         // ')'
      if (open.length) open.pop();                 // 진짜 여는 괄호를 먼저 쓴다
      else if (star.length) star.pop();            // 없으면 별표를 '('로 쓴다
      else return false;                           // 짝이 될 것이 없다
    }
  }
  while (open.length && star.length) {             // 남은 '('를 뒤쪽 별표로 닫는다
    if (open.pop() > star.pop()) return false;     // 별표가 앞에 있으면 닫을 수 없다
  }
  return open.length === 0;                        // 남은 별표는 비우면 된다
}
```

`)`를 만났을 때 여는 괄호를 먼저 쓰는 이유가 있다. 별표는 쓰임이 셋이라 아껴 두면 나중에 닫는 괄호로도 쓸 수 있지만, 여는 괄호는 닫히는 것 말고는 할 일이 없다. 그래서 확실한 것부터 쓴다. 순서를 바꿔 별표를 먼저 쓰면 `(*)`에서 별표가 닫는 괄호의 짝으로 써 버려지고, 처음의 `(`가 닫히지 못해 `false`가 나온다. 정답은 `true`다.

꼭대기끼리 짝짓는 것도 이유가 있다. 남은 여는 괄호 중 가장 뒤의 것은 가장 뒤의 별표와 짝짓는 게 가장 유리하다. 가장 뒤의 별표가 그 여는 괄호보다 앞이면, 다른 어떤 별표도 그 뒤에 있지 않으니 바로 실패다.

`(*)(*(*`로 따라가 본다. 끝까지 읽었을 때 여는 괄호 스택은 `[3, 5]`, 별표 스택은 `[1, 4, 6]`이다.

```text
pair open 5 star 6 ok
pair open 3 star 4 ok
left open []
```

5번 `(`는 6번 별표로, 3번 `(`는 4번 별표로 닫힌다. 1번 별표는 남는데, 비우면 된다. 아래 그림에서 다음을 누르면 두 스택이 쌓였다가 짝지어 빠지는 과정을 볼 수 있다.

## 열린 수의 가장 작은 값과 가장 큰 값만 든다

앞의 표에서 본 관찰을 쓴다. 지금까지 읽은 앞부분에서 열린 수가 될 수 있는 값들은 늘 끊김 없는 구간 `[lo, hi]`다. 그러니 `lo`(될 수 있는 가장 작은 열린 수)와 `hi`(가장 큰 열린 수) 두 숫자만 들고 다닌다.

- `(`: 모든 경우에서 하나 열리니 `lo`와 `hi`가 1씩 커진다.
- `)`: 모든 경우에서 하나 닫히니 1씩 작아진다.
- `*`: 가장 작은 경우는 닫는 괄호로 써서 `lo - 1`, 가장 큰 경우는 여는 괄호로 써서 `hi + 1`. 빈 문자열은 그 사이를 채운다.

두 가지를 바로잡는다. `hi`가 음수가 되면 별표를 모두 여는 괄호로 써도 닫는 괄호가 많다는 뜻이라 바로 실패다. `lo`가 음수가 되면, 음수가 되는 선택은 원래 허용되지 않으니 그 경우만 버리고 `lo`를 0으로 올린다. 끝에서 `lo`가 0이면 열린 수 0으로 끝내는 경우가 있다는 뜻이라 성공이다.

```js
function checkValidString(s) {
  let lo = 0, hi = 0;                              // 열린 수가 될 수 있는 범위 [lo, hi]
  for (const ch of s) {
    if (ch === "(") { lo++; hi++; }
    else if (ch === ")") { lo--; hi--; }
    else { lo--; hi++; }                           // '*': 닫으면 lo - 1, 열면 hi + 1
    if (hi < 0) return false;                      // 별표를 모두 열어도 닫는 괄호가 많다
    if (lo < 0) lo = 0;                            // 음수가 되는 선택은 버린다
  }
  return lo === 0;                                 // 열린 수 0으로 끝낼 수 있나
}
```

`((*)*)*)`로 찍었다. 괄호 안은 0으로 올리기 전의 `lo`다.

```text
0 ( lo 1 hi 1
1 ( lo 2 hi 2
2 * lo 1 hi 3
3 ) lo 0 hi 2
4 * lo 0 hi 3 (clamped from -1)
5 ) lo 0 hi 2 (clamped from -1)
6 * lo 0 hi 3 (clamped from -1)
7 ) lo 0 hi 2 (clamped from -1)
end lo 0
```

### 범위가 끊기지 않는 이유

이 풀이가 맞으려면 "가능한 열린 수가 늘 이어진 구간"이어야 한다. 귀납으로 보인다. 처음엔 `{0}`이라 구간이다. 지금 가능한 값이 `[lo, hi]`라면, `(`와 `)`는 구간을 통째로 1 옮길 뿐이다. `*`는 각 값 v에서 v - 1, v, v + 1을 만드니 결과는 `[lo - 1, hi + 1]`로 이어진다. 빈 문자열이 v를 그대로 두는 덕분에 사이에 구멍이 생기지 않는다. 마지막으로 음수 값을 잘라 내도 구간의 아래쪽만 잘리니 여전히 구간이다.

`lo`를 0으로 올리는 게 왜 안전한지도 여기서 나온다. 음수 열린 수는 "닫는 괄호가 여는 괄호보다 많아진 순간"이라 그 선택 자체가 규칙 위반이다. 그런 선택을 한 경우만 지우는 것이지, 다른 경우를 잃는 게 아니다. 반면 `hi`가 음수면 구간 전체가 음수라 살아남는 경우가 하나도 없다.

별표가 빈 문자열이 될 수 없는 변형에서는 이 구간에 구멍이 생긴다. 아래 "규칙이 바뀌면"에서 다시 본다.

## 양쪽에서 한 번씩 훑는다

같은 문제를 두 번의 단순한 검사로 쪼갤 수도 있다.

- 왼쪽에서 오른쪽으로 읽으며 별표를 모두 `(`로 본다. 이때도 열린 수가 음수가 되면, 즉 닫는 괄호가 너무 많으면 어떻게 해도 안 된다.
- 오른쪽에서 왼쪽으로 읽으며 별표를 모두 `)`로 보고, 거꾸로 닫는 괄호 수를 센다. 이때 음수가 되면 여는 괄호가 너무 많아 어떻게 해도 안 된다.

두 검사를 모두 통과하면 `true`다.

```js
function checkValidString(s) {
  let bal = 0;
  for (const ch of s) {                            // 별표를 모두 '('로 본다
    bal += ch === ")" ? -1 : 1;
    if (bal < 0) return false;                     // 닫는 괄호가 너무 많다
  }
  bal = 0;
  for (let i = s.length - 1; i >= 0; i--) {        // 거꾸로 읽으며 별표를 모두 ')'로 본다
    bal += s[i] === "(" ? -1 : 1;
    if (bal < 0) return false;                     // 여는 괄호가 너무 많다
  }
  return true;
}
```

첫 번째 반복은 그리디의 `hi` 검사와 같다. 두 번째 반복은 `lo` 쪽 검사를 뒤집어서 한 것이다. 거꾸로 읽으면 닫는 괄호가 "여는" 역할을 하니, 어떤 접미사에서든 여는 괄호가 닫는 괄호와 별표를 합친 것보다 많으면 실패한다. 두 조건을 모두 만족하면 올바르게 바꾸는 방법이 있다는 게 알려져 있고, 무작위 입력으로 다른 풀이와 맞춰 봤다.

시간 O(n), 공간 O(1)이다. 그리디보다 한 번 더 읽지만, 각 반복이 별표 없는 괄호 검사와 똑같이 생겨서 설명하기 쉽다. `*()(`는 왼쪽 검사를 통과하지만 오른쪽 검사에서 마지막 `(`를 닫을 것이 없어 `false`다.

여섯 풀이가 길이 0~10의 무작위 문자열 4만 개에서 모두 같은 답을 내는지 맞춰 봤다. 어긋난 입력은 없었다.

## Python과 Java로 옮긴 범위 풀이

```python
class Solution:
    def checkValidString(self, s: str) -> bool:
        lo = hi = 0                        # 열린 수가 될 수 있는 가장 작은 값, 가장 큰 값
        for ch in s:
            if ch == "(":
                lo += 1
                hi += 1
            elif ch == ")":
                lo -= 1
                hi -= 1
            else:                          # '*'는 ')', 빈 문자열, '(' 중 하나
                lo -= 1
                hi += 1
            if hi < 0:                     # '*'를 모두 '('로 써도 닫는 괄호가 많다
                return False
            lo = max(lo, 0)                # 음수가 되는 선택은 버린다
        return lo == 0
```

```text
'()' True True
'(*)' True True
'(*))' True True
'*((' False False
')*(' False False
'' True True
'(**)(' False False
'((*)*)*)' True True
'*)' True True
```

둘째 열은 범위 풀이, 셋째 열은 `functools.lru_cache`로 쓴 메모 재귀의 결과다. Python의 기본 재귀 한도는 1000이라, 길이가 수천인 변형에서 메모 재귀를 쓰면 `RecursionError`가 난다. 이 문제는 길이 100이라 괜찮다. 범위 풀이는 재귀가 없어 걱정할 것이 없다.

```java
class Solution {
    public boolean checkValidString(String s) {
        int lo = 0, hi = 0;                 // 열린 수가 될 수 있는 범위
        for (int i = 0; i < s.length(); i++) {
            char ch = s.charAt(i);
            if (ch == '(') { lo++; hi++; }
            else if (ch == ')') { lo--; hi--; }
            else { lo--; hi++; }            // '*'는 세 가지 중 하나
            if (hi < 0) return false;       // 어떻게 골라도 닫는 괄호가 많다
            lo = Math.max(lo, 0);           // 음수가 되는 선택은 버린다
        }
        return lo == 0;
    }
}
```

```text
"()" true
"(*)" true
"(*))" true
"*((" false
")*(" false
"" true
"(**)(" false
"((*)*)*)" true
"*)" true
```

`main`에서 같은 입력을 넣은 결과다. Java에서는 `charAt`으로 글자를 꺼내고 작은따옴표로 비교한다. `s.charAt(i) == "("`처럼 큰따옴표를 쓰면 `char`와 `String`을 비교해서 컴파일이 안 된다. 길이가 100이라 `int` 넘침은 걱정할 필요가 없다.

## 괄호 판정 방법별 비용

n은 문자열 길이, k는 별표 개수다.

| 풀이 | 시간 | 공간 | 언제 고르나 |
|---|---|---|---|
| 별표 모두 바꿔 보기 | O(3^k · n) | O(n) | 작은 입력으로 답을 맞춰 볼 때 |
| 구간 DP | O(n³) | O(n²) | 구간 DP를 연습할 때 |
| 메모 재귀 (i, open) | O(n²) | O(n²) | DP로 먼저 접근할 때 |
| 열린 수 표 | O(n²) | O(n) | 재귀 없이 DP를 쓸 때, 그리디로 가는 다리 |
| 두 스택 | O(n) | O(n) | 실제 짝을 알아야 할 때 |
| 범위 lo, hi | O(n) | O(1) | 기본 답 |
| 양쪽에서 훑기 | O(n) | O(1) | 별표 없는 검사 두 번으로 설명하고 싶을 때 |

## 별표를 잘못 다루는 코드

### 개수만 맞춰 본다

```js
function checkValidString(s) {
  let open = 0, close = 0, stars = 0;
  for (const ch of s) {
    if (ch === "(") open++;
    else if (ch === ")") close++;
    else stars++;
  }
  return Math.abs(open - close) <= stars;          // 순서를 보지 않는다
}
```

여는 괄호와 닫는 괄호의 차이를 별표로 메울 수 있는지만 본다. `)*`에서 `true`가 나온다. 첫 글자가 닫는 괄호라 어떻게 해도 안 되는데, 순서를 보지 않았다. 정답은 `false`다. 괄호 문제는 개수보다 순서가 먼저다.

### lo를 0으로 올리지 않는다

`if (lo < 0) lo = 0;`을 빼고 끝에서 `lo <= 0 && 0 <= hi`로 판정하면 `*(`에서 `true`가 나온다. 별표에서 `lo`가 -1이 되고, `(`에서 0이 되어 마지막 판정을 통과한다. 하지만 `lo` -1은 "닫는 괄호를 먼저 쓴" 불가능한 경우였다. 그 경우를 버리지 않고 끌고 와서 가짜 0을 만들었다. 정답은 `false`다.

### hi 검사를 끝에만 한다

`hi < 0` 검사를 반복 안이 아니라 끝에만 하면 `)*`처럼 중간에 무너졌다가 다시 올라오는 입력을 놓친다. `)`에서 hi가 -1이 됐는데 그냥 지나가고, `*`에서 0으로 돌아온다. lo는 0으로 올려져 있으니 끝에서는 멀쩡해 보여 `true`가 나온다. 정답은 `false`다. 반복 안에서 바로 실패해야 한다. 별표 없는 괄호 검사에서 "한 번이라도 음수가 되면 실패"인 것과 같은 이유다.

### 닫는 괄호의 짝으로 별표를 먼저 쓴다

두 스택 풀이에서 `)`를 만났을 때 별표 스택을 먼저 꺼내면 `(*)`에서 `false`가 나온다. 앞에서 본 대로 여는 괄호는 닫히는 것 말고 할 일이 없으니 먼저 써야 한다.

### 남은 짝을 위치 비교 없이 센다

두 스택 풀이의 마지막에서 `open.length <= star.length`만 보면 `*(`에서 `true`가 나온다. 별표 하나가 여는 괄호 하나를 닫을 수 있을 것 같지만, 별표가 앞에 있어서 닫는 괄호 노릇을 못 한다. 위치를 비교해야 한다.

이 다섯 실수를 무작위 입력 4만 개로 완전 탐색과 맞춰 보면 적게는 2천여 개, 많게는 1만 1천여 개씩 어긋났다. 위의 예시들은 그중 가장 짧은 입력이다.

## 규칙이 바뀌면

### 별표가 빈 문자열이 될 수 없다면

별표가 `(`나 `)` 둘 중 하나여야 하면, 열린 수가 될 수 있는 값은 이어진 구간이 아니라 한 칸씩 건너뛴 값이 된다. 글자를 하나 읽을 때마다 열린 수가 반드시 1씩 바뀌니, 지금까지 읽은 길이와 홀짝이 같은 값만 나온다. 그래서 `lo`가 -1이 되면 0이 아니라 1로 올려야 한다.

```js
function checkNoEmpty(s) {
  let lo = 0, hi = 0;
  for (const ch of s) {
    if (ch === "(") { lo++; hi++; }
    else if (ch === ")") { lo--; hi--; }
    else { lo--; hi++; }
    if (hi < 0) return false;
    if (lo < 0) lo += 2;                           // 가능한 값은 홀짝이 같다: -1 다음은 1
  }
  return lo === 0;
}
```

별표를 `(`와 `)` 두 가지로만 바꿔 보는 완전 탐색과 무작위 입력 4만 개로 맞춰 봤다. 어긋난 입력은 없었다. `(*)`는 원래 문제에서 `true`지만 이 변형에서는 길이가 홀수라 `false`다.

### 실제로 어떻게 바꿨는지 돌려 달라면

두 스택 풀이가 답을 준다. `)`의 짝으로 꺼낸 별표는 `(`, 마지막 짝짓기에서 꺼낸 별표는 `)`, 남은 별표는 빈 문자열로 바꾸면 올바른 문자열이 된다. 범위 풀이는 가능한지만 알려 주고 어떤 선택을 했는지는 기억하지 않는다.

### 괄호 종류가 여러 개라면

`()`, `[]`, `{}`에 어떤 괄호든 될 수 있는 와일드카드가 섞이면 숫자 하나로는 부족하다. 어떤 종류가 열려 있는지 순서까지 기억해야 해서 범위 그리디가 통하지 않는다. 길이가 짧으면 구간 DP가 그대로 쓰인다. 짝을 지을 때 두 글자가 같은 종류로 맞춰지는지만 검사를 바꾸면 된다.

### 올바르게 만들려면 최소 몇 글자를 지워야 하나

LeetCode 1249번 Minimum Remove to Make Valid Parentheses는 별표 없이 괄호를 최소로 지워 올바르게 만든다. 스택에 여는 괄호 위치를 쌓고, 짝이 없는 닫는 괄호와 끝까지 남은 여는 괄호를 지운다. 이 글의 두 스택 풀이에서 별표 스택만 뺀 모양이다. 921번 Minimum Add to Make Parentheses Valid는 넣을 괄호 수를 세는데, 열린 수가 음수가 될 때마다 하나를 더하면 된다.

괄호 줄을 직접 만들어 내는 문제는 [Generate Parentheses](/posts/leetcode-generate-parentheses)에 있다. 같은 그리디 묶음의 다른 문제로는 [Hand of Straights](/posts/leetcode-hand-of-straights), [Merge Triplets to Form Target Triplet](/posts/leetcode-merge-triplets-to-form-target-triplet), [Candy](/posts/leetcode-candy), [IPO](/posts/leetcode-ipo)가 있다.

## 면접에서 나올 만한 질문

### 별표가 있으면 왜 스택 하나로는 안 되나요?

닫는 괄호를 만났을 때 별표를 여는 괄호로 쓸지, 끝에 남은 여는 괄호를 닫는 데 쓸지, 비울지를 그 자리에서 정할 수 없기 때문이다. 스택을 둘로 나눠 여는 괄호와 별표의 위치를 따로 기억하면 된다. 닫는 괄호는 진짜 여는 괄호부터 쓰고, 끝에 남은 여는 괄호는 그보다 뒤에 있는 별표로 닫는다.

### lo와 hi 두 숫자만으로 되는 이유는 뭔가요?

지금까지 읽은 앞부분에서 열린 수가 될 수 있는 값이 늘 끊김 없는 구간이기 때문이다. 여는 괄호와 닫는 괄호는 구간을 통째로 옮기고, 별표는 양쪽으로 1씩 넓히며 빈 문자열 덕분에 사이에 구멍이 없다. 그래서 양 끝만 알면 구간 전체를 안다.

### lo가 음수가 되면 왜 0으로 올려도 되나요?

음수 열린 수는 닫는 괄호가 여는 괄호보다 많아진 순간이라 그 선택 자체가 규칙 위반이다. 그 경우만 지우는 것이라 살아 있는 다른 경우를 잃지 않는다. 반대로 hi가 음수면 모든 경우가 위반이라 바로 `false`다.

### 두 스택 풀이에서 닫는 괄호의 짝으로 여는 괄호를 먼저 쓰는 이유는?

여는 괄호는 닫히는 것 말고 할 일이 없지만 별표는 나중에 닫는 괄호나 빈 문자열로도 쓸 수 있다. 쓰임이 많은 별표를 아껴 두는 게 손해가 없다. 순서를 바꾸면 `(*)`에서 별표를 먼저 써 버려 앞의 `(`가 남고 틀린다.

### DP로 푼다면 상태는 무엇인가요?

(지금까지 읽은 글자 수, 지금 열린 수) 두 개다. 별표에서 세 갈래로 나뉘어도 같은 상태에 오면 뒤의 결과가 같아서 메모할 수 있다. 상태가 O(n²)개라 시간 O(n²)이고, 앞에서부터 표로 채우면 공간을 O(n)으로 줄일 수 있다. 이 표에서 참인 칸이 늘 붙어 있다는 걸 보면 범위 그리디로 넘어간다.

### 별표가 빈 문자열이 될 수 없다면 무엇이 바뀌나요?

열린 수가 매 글자마다 꼭 1씩 바뀌어서 가능한 값이 홀짝이 같은 값만 남는다. 구간에 한 칸씩 구멍이 생기니 lo가 -1이 됐을 때 0이 아니라 1로 올려야 한다. 나머지는 그대로다.

### 양쪽에서 한 번씩 훑는 풀이는 왜 맞나요?

왼쪽에서 별표를 모두 여는 괄호로 봐도 닫는 괄호가 많아지는 지점이 있으면 어떤 선택도 안 된다. 오른쪽에서 별표를 모두 닫는 괄호로 봐도 여는 괄호가 많아지는 지점이 있으면 역시 안 된다. 이 두 조건만 통과하면 올바르게 바꿀 수 있고, 범위 풀이의 hi 검사와 lo 검사를 각각 따로 한 것과 같다.
