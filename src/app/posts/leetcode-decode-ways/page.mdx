[Decode Ways](https://leetcode.com/problems/decode-ways/)는 LeetCode 91번이다. 생김새는 [계단 오르기](/posts/leetcode-climbing-stairs)와 거의 같다. 한 번에 한 칸이나 두 칸을 오르듯 한 글자나 두 글자를 떼어 낸다. 다른 점은 "그 칸을 밟을 수 있는가"에 조건이 붙는다는 것이고, 그 조건이 숫자 0 때문에 생각보다 까다롭다. 이 문제에서 틀리는 코드는 거의 다 0을 잘못 다룬 코드다.

DP를 처음 본다면 [동적 계획법 글](/posts/dynamic-programming)에서 상태와 점화식, 탑다운과 바텀업의 차이를 먼저 보는 게 좋다. 문자열을 여러 조각으로 나누는 다른 DP로는 [Word Break](/posts/leetcode-word-break)가 있다. 이 글은 모든 길을 따라가는 재귀부터 변수 두 개짜리 풀이까지 다섯 가지를 놓고, 0이 만드는 함정을 따로 모아 본다. 코드는 Node.js 22, Python 3, Java 21에서 직접 돌렸다.

## 숫자 문자열을 글자로 되돌리는 방법의 수

A부터 Z까지를 1부터 26으로 바꿔 이어 붙인 숫자 문자열 `s`가 주어진다. 이 문자열을 다시 글자로 읽는 방법이 몇 가지인지 센다. 조각 하나는 "1부터 26 사이의 수"여야 하고, 앞에 0이 붙은 조각(`"06"`)은 6으로 읽지 않는다. 읽을 방법이 하나도 없으면 0을 돌려준다.

제약은 길이 1 이상 100 이하, 숫자로만 이루어져 있고 0으로 시작할 수도 있다. 답은 32비트 정수 범위 안이라고 보장된다. 길이가 100이라 모든 읽는 법을 하나씩 만들어 보는 건 안 된다. 1만 100개 있으면 읽는 법이 약 5.7 × 10^20가지라서다. 그 정도 큰 답은 테스트에 나오지 않는다는 보장이 따로 있는 셈이다.

## "121026"을 손으로 나눠 본다

글 끝까지 쓸 예시다.

```text
인덱스   0   1   2   3   4   5
s        1   2   1   0   2   6
```

3번의 0이 열쇠다. 0은 혼자 읽을 수 없으니 반드시 앞의 1과 붙어 10(J)이 된다. 그러면 2번의 1은 10에 쓰였으니, 1번의 2와 붙어 21이 될 수 없다. 문자열이 `12 | 10 | 26`처럼 사실상 세 덩어리로 갈린다.

- 앞의 `12`는 1, 2로 읽거나 12로 읽는다. 두 가지다.
- `10`은 10 한 가지뿐이다.
- 뒤의 `26`은 2, 6으로 읽거나 26으로 읽는다. 두 가지다.

그래서 2 × 1 × 2 = 4가지다. 실제로 꺼내 보면 이렇다.

```text
1, 2, 10, 2, 6  → ABJBF
1, 2, 10, 26    → ABJZ
12, 10, 2, 6    → LJBF
12, 10, 26      → LJZ
```

손으로는 덩어리를 나눠 곱했지만, 덩어리를 어디서 나눌지 정하는 규칙을 일반적으로 쓰기는 번거롭다. 대신 "앞에서부터 한 글자 또는 두 글자를 떼어 낸다"는 단순한 규칙으로 처음부터 끝까지 가면 이 곱셈이 저절로 나온다.

## 0이 끼면 갈 길이 막힌다

풀이에 들어가기 전에 0의 규칙을 정리해 둔다. 이걸 먼저 확실히 해 두면 뒤의 코드가 짧아진다.

- `0` 한 글자는 어떤 글자도 아니다. 한 글자로 떼어 낼 수 없다.
- 두 글자 조각은 10 이상 26 이하여야 한다. `06`은 앞에 0이 붙은 조각이라 안 되고, `27`, `30`은 26을 넘어서 안 된다.
- 그래서 0은 앞 숫자가 1이나 2일 때만 살아남는다. `"30"`, `"100"`, `"06"`은 모두 답이 0이다.

`"100"`이 왜 0인지 한 번 따라가 보자. 1, 0, 0으로 읽으면 0이 혼자다. 10, 0으로 읽으면 마지막 0이 혼자다. 1, 00은 00이 조각이 될 수 없다. 한 자리만 막혀도 전체가 0이 된다. 이 문제의 표에 0이 자주 보이는 이유다.

반대로 0이 살아남는 경우도 하나 보자. `"2101"`은 0 앞이 1이라 10으로 읽힌다. 그런데 그 1을 10에 쓰면 앞의 2는 혼자 B가 되어야 하고, 마지막 1도 혼자 A다. 21로 먼저 묶으면 0이 혼자 남아 막힌다. 그래서 2, 10, 1 한 가지뿐이다.

```text
2, 10, 1   → BJA     (된다)
21, 0, 1   → 0이 혼자 (막힌다)
2, 1, 01   → 01은 조각이 아니다 (막힌다)
```

0은 자기 앞 글자의 선택지를 하나로 묶어 버린다. 이 묶임이 뒤의 표에서 값이 줄어드는 모습으로 나타난다.

## 앞에서부터 한 글자 또는 두 글자를 떼어 낸다

i번 위치부터 끝까지를 읽는 방법의 수를 `go(i)`라고 하자. i번 앞에서 할 수 있는 선택은 둘뿐이다.

1. i번 한 글자를 떼어 낸다. `s[i]`가 0이 아니면 된다. 그 뒤는 `go(i+1)`가지다.
2. i번과 i+1번 두 글자를 떼어 낸다. 두 글자가 10 이상 26 이하면 된다. 그 뒤는 `go(i+2)`가지다.

두 선택은 첫 조각이 달라서 겹치는 읽는 법이 없으니 그냥 더한다. 끝에 도착하면(`i === s.length`) 읽는 법 하나를 완성한 것이라 1이다. `s[i]`가 0이면 한 글자로도, 두 글자 조각의 첫 글자로도 쓸 수 없으니 바로 0이다.

```js
function numDecodings(s) {
  function go(i) {
    if (i === s.length) return 1;     // 끝까지 다 읽었다: 방법 하나
    if (s[i] === "0") return 0;       // 0으로 시작하는 조각은 없다
    let ways = go(i + 1);             // 한 글자 떼기
    if (i + 1 < s.length && (s[i] === "1" || (s[i] === "2" && s[i + 1] <= "6"))) {
      ways += go(i + 2);              // 두 글자 떼기 (10~26)
    }
    return ways;
  }
  return go(0);
}
```

두 글자 조건을 `s[i] === "1"`이거나 `s[i] === "2"`이면서 다음 글자가 6 이하인 것으로 썼다. 첫 글자가 0이 아님은 바로 위에서 걸렀으니, 이 조건이 곧 10 이상 26 이하다.

## 같은 꼬리를 다시 세지 않게 적어 둔다

`go(i)`의 답은 i에만 달려 있다. 앞에서 어떻게 왔는지는 상관없다. 그러니 한 번 구한 `go(i)`를 적어 두고 다시 물으면 꺼내 주면 된다.

```js
function numDecodings(s) {
  const memo = new Array(s.length + 1).fill(-1); // -1 = 아직 안 구함
  function go(i) {
    if (i === s.length) return 1;
    if (memo[i] !== -1) return memo[i];
    if (s[i] === "0") return (memo[i] = 0);
    let ways = go(i + 1);
    if (i + 1 < s.length && (s[i] === "1" || (s[i] === "2" && s[i + 1] <= "6"))) {
      ways += go(i + 2);
    }
    return (memo[i] = ways);
  }
  return go(0);
}
```

"안 구함" 표시를 0이 아니라 -1로 둔 데 이유가 있다. 이 문제는 답이 0인 칸이 흔하다. 0을 "안 구함"으로 쓰면 `"30"`처럼 막힌 칸을 물을 때마다 다시 계산한다. 답은 맞으니 테스트에서 잘 안 잡히는 실수다.

`go(i)`가 i마다 한 번씩만 계산되고 한 번에 O(1)만 일하니 시간 O(n), 메모와 재귀 깊이로 공간 O(n)이다. 길이 100이면 재귀 깊이 100이라 어느 언어에서도 넉넉하다.

### 꼬리부터 표로 채우기

메모 풀이의 `go(i)`는 `go(i+1)`과 `go(i+2)`만 부른다. 그러니 i가 큰 쪽부터, 즉 문자열 끝에서 앞으로 오면서 표를 채우면 재귀가 필요 없다. 메모를 그대로 반복문으로 옮긴 모양이다.

```js
function numDecodings(s) {
  const n = s.length;
  const dp = new Array(n + 2).fill(0);   // dp[i] = i번부터 끝까지 읽는 방법의 수
  dp[n] = 1;                             // 다 읽은 뒤: 방법 하나
  for (let i = n - 1; i >= 0; i--) {
    if (s[i] === "0") continue;          // 0으로 시작하는 꼬리는 0가지 (그대로 둔다)
    dp[i] = dp[i + 1];                   // 한 글자 떼기
    if (i + 1 < n && Number(s.slice(i, i + 2)) <= 26) dp[i] += dp[i + 2]; // 두 글자 떼기
  }
  return dp[0];
}
```

예시를 넣으면 표가 `dp[0]`부터 `dp[6]`까지 `4 2 2 0 2 1 1`로 채워진다. 3번 칸이 0인 게 보인다. `"026"`처럼 0으로 시작하는 꼬리는 읽을 방법이 없다. 2번 칸의 1은 이 0가지 꼬리를 한 글자로 이어 받지 못하고, 두 글자 `10`으로 4번 칸의 2가지를 이어 받는다.

꼬리 기준으로 세든 머리 기준으로 세든 답과 복잡도는 같다. 다음 절에서는 많이 쓰는 머리 기준, 즉 "앞 i글자"로 표를 다시 세운다. 그쪽이 두 변수 풀이로 줄이기 편하고, 글자가 앞에서부터 하나씩 들어오는 상황에도 그대로 맞는다.

## 앞 i글자를 읽는 방법을 표로 채운다

`dp[i]`를 "s의 앞 i글자를 읽는 방법의 수"로 정한다. 앞 i글자의 마지막 조각은 한 글자이거나 두 글자다.

- 마지막 조각이 한 글자 `s[i-1]`이면, 그게 0이 아닐 때 앞 i-1글자를 읽는 방법 `dp[i-1]`가지가 이어진다.
- 마지막 조각이 두 글자 `s[i-2..i-1]`이면, 그게 10 이상 26 이하일 때 앞 i-2글자를 읽는 방법 `dp[i-2]`가지가 이어진다.

그래서 점화식은 이렇다.

```text
dp[i] = (s[i-1] ≠ '0' ? dp[i-1] : 0) + (10 ≤ s[i-2..i-1] ≤ 26 ? dp[i-2] : 0)
```

바닥은 `dp[0] = 1`이다. 아무것도 안 읽은 빈 문자열을 읽는 방법은 "아무것도 안 하는 것" 한 가지다. 이걸 0으로 두면 첫 조각이 이어 붙을 곳이 없어 모든 답이 0이 된다. 계단 오르기에서 "0층에 서 있는 방법 1가지"와 같은 바닥이다.

```js
function numDecodings(s) {
  const n = s.length;
  const dp = new Array(n + 1).fill(0);
  dp[0] = 1;                                  // 빈 문자열을 읽는 방법 1가지
  for (let i = 1; i <= n; i++) {
    if (s[i - 1] !== "0") dp[i] += dp[i - 1]; // 마지막 조각이 한 글자
    if (i >= 2) {
      const two = Number(s.slice(i - 2, i));
      if (two >= 10 && two <= 26) dp[i] += dp[i - 2]; // 마지막 조각이 두 글자
    }
  }
  return dp[n];
}
```

두 글자 조건을 `two >= 10`으로 쓰면 `"06"`처럼 0으로 시작하는 조각이 저절로 빠진다. `Number("06")`은 6이라 10보다 작다. 이 한 줄이 앞의 "0으로 시작하면 안 된다" 규칙을 대신한다.

시간 O(n), 공간 O(n)이다. 표가 있으니 읽는 법을 하나씩 거꾸로 꺼내는 것도 가능하지만, 방법의 수만 필요하면 표 전체는 필요 없다.

## 계단을 오르듯 기록 두 개만 남긴다

점화식은 `dp[i-1]`과 `dp[i-2]`만 본다. 계단 오르기와 똑같다. 차이는 각 항 앞에 "이 칸을 밟을 수 있나"라는 조건이 붙은 것뿐이다. 그러니 표 대신 변수 두 개를 밀고 간다.

```js
function numDecodings(s) {
  let prev2 = 0; // dp[i-2]. i = 1일 때는 없는 칸이라 0
  let prev1 = 1; // dp[i-1]. 처음에는 dp[0] = 1
  for (let i = 1; i <= s.length; i++) {
    let cur = 0;
    if (s[i - 1] !== "0") cur += prev1;               // 한 글자 조각
    if (i >= 2) {
      const two = (s.charCodeAt(i - 2) - 48) * 10 + (s.charCodeAt(i - 1) - 48);
      if (two >= 10 && two <= 26) cur += prev2;       // 두 글자 조각
    }
    prev2 = prev1;
    prev1 = cur;
  }
  return prev1;
}
```

두 글자를 숫자로 바꿀 때 `slice`와 `Number` 대신 문자 코드를 썼다. `"0"`의 코드가 48이라 빼면 숫자가 나온다. 문자열을 새로 만들지 않아 조금 더 빠르지만, 길이 100에서는 차이를 느낄 수 없으니 읽기 편한 쪽을 써도 된다.

`prev2`를 0으로 시작한 이유도 짚어 두자. i = 1일 때 `dp[-1]`에 해당하는 칸은 없다. 두 글자 조각은 `i >= 2`일 때만 보니 이 값이 실제로 쓰이지는 않지만, 0으로 두면 "그런 칸은 없다"는 뜻이 분명하다.

1만 이어진 `"1111111111"`을 넣으면 89가 나온다. 모든 칸에서 두 갈래가 다 열리니 조건이 전부 참이 되고, 점화식이 그대로 피보나치가 된다. 계단 10칸을 한두 칸씩 오르는 방법의 수와 같다.

## Python과 Java에서 두 글자를 읽는 법

```python
class Solution:
    def numDecodings(self, s: str) -> int:
        prev2, prev1 = 0, 1                     # dp[i-2], dp[i-1]  (dp[0] = 1)
        for i in range(1, len(s) + 1):
            cur = 0
            if s[i - 1] != "0":                 # 한 글자 조각
                cur += prev1
            if i >= 2 and 10 <= int(s[i - 2:i]) <= 26:  # 두 글자 조각
                cur += prev2
            prev2, prev1 = prev1, cur
        return prev1
```

`int("06")`은 6이라 `10 <= ... <= 26`에서 저절로 빠진다. Python은 `10 <= x <= 26`처럼 비교를 이어 쓸 수 있어서 조건이 짧다. 정수 크기 제한이 없으니 답이 아무리 커도 넘치지 않는다. 예시에 4, `"226"`에 3, `"06"`과 `"100"`에 0이 나왔다.

```java
class Solution {
    public int numDecodings(String s) {
        int prev2 = 0, prev1 = 1;                      // dp[i-2], dp[i-1]  (dp[0] = 1)
        for (int i = 1; i <= s.length(); i++) {
            int cur = 0;
            char c = s.charAt(i - 1);
            if (c != '0') cur += prev1;                // 한 글자 조각
            if (i >= 2) {
                int two = (s.charAt(i - 2) - '0') * 10 + (c - '0');
                if (two >= 10 && two <= 26) cur += prev2; // 두 글자 조각
            }
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
}
```

Java의 `char`에서 `'0'`을 빼면 `int` 숫자가 나온다. `Integer.parseInt(s.substring(i - 2, i))`로 써도 되지만 문자열을 매번 만든다. 답이 32비트 안이라는 보장이 있어서 `int`로 썼다. 그 보장이 없으면 Java `int`는 21억을 넘는 순간 조용히 음수로 넘어가고, JavaScript `Number`는 2^53을 넘으면 끝자리가 틀어진다. 큰 답이 나올 수 있는 변형에서는 보통 "10^9 + 7로 나눈 나머지"를 요구한다(뒤의 Decode Ways II).

## 다섯 풀이를 시간과 공간으로 재면

| 풀이 | 시간 | 추가 공간 | 언제 고르나 |
|---|---|---|---|
| 한 글자·두 글자 재귀 | O(φⁿ) | O(n) 스택 | 점화식을 세울 때 출발점 |
| 탑다운 메모 | O(n) | O(n) | 재귀에서 바로 옮길 때 |
| 꼬리부터 채우는 표 | O(n) | O(n) | 메모를 재귀 없이 옮길 때 |
| 바텀업 표 | O(n) | O(n) | 표를 그려 0이 어떻게 막는지 설명할 때 |
| 두 변수 | O(n) | O(1) | 기본 답. 스트림에도 쓴다 |

다섯 풀이 모두 "마지막(또는 첫) 조각이 한 글자인가 두 글자인가"로 경우를 나눈다는 점은 같다. 다른 건 같은 질문을 몇 번 하느냐, 그리고 답을 어디에 적어 두느냐뿐이다.

## 0을 잘못 다뤄서 틀리는 코드

### 0도 한 글자로 읽어 버리는 경우

```js
// 한 글자 조각에 0 검사가 없다
for (let i = 1; i <= n; i++) {
  dp[i] += dp[i - 1];
  if (i >= 2) { const two = Number(s.slice(i - 2, i)); if (two >= 10 && two <= 26) dp[i] += dp[i - 2]; }
}
```

0을 글자 하나로 세니 `"10"`에서 2(답 1), `"100"`에서 2(답 0), 예시에서 10(답 4)이 나온다. 0은 반드시 앞과 붙여야 한다는 규칙이 통째로 빠졌다.

### 두 글자 조건에 아래쪽 경계를 빼는 경우

```js
if (two <= 26) dp[i] += dp[i - 2]; // 10 이상인지 안 본다
```

`"06"`을 6으로 읽어서 1(답 0)이 나온다. `"100"`도 `"00"`을 0으로 읽어 1이 나오고, 예시는 `"02"`를 2로 읽어 7이 된다. `Number`가 앞의 0을 지워 주는 게 여기서는 독이 된다.

### dp[1]을 무조건 1로 두는 경우

```js
const dp = new Array(n + 1).fill(0);
dp[0] = 1;
dp[1] = 1;               // s[0]이 0이어도 1
for (let i = 2; i <= n; i++) { /* ... */ }
```

0으로 시작하는 입력에서 틀린다. `"0"`에서 1, `"06"`과 `"01"`에서 1이 나온다(셋 다 답 0). `dp[1] = s[0] === "0" ? 0 : 1`로 고치거나, 앞의 코드처럼 반복문을 1부터 돌려 같은 규칙으로 처리하면 이 경계가 사라진다.

### 처음부터 0이면 바로 0을 돌려주고 끝내는 경우

`if (s[0] === "0") return 0;`은 맞는 처리다. 문제는 이것만 있으면 충분하다고 여기고 중간의 0을 놓치는 경우다. `"301"`은 0으로 시작하지 않지만 `30`도 `0`도 안 되니 답이 0이다. 중간의 0은 점화식이 알아서 처리해야 한다.

### 문자열 그대로 비교하기

`s.slice(i - 2, i) <= "26"`처럼 문자열끼리 비교해도 두 자리끼리라 사전 순과 수의 순서가 같아서 맞게 동작한다. 다만 `"06" >= "10"`도 함께 걸어야 하고, 한쪽이 한 자리가 되는 순간 깨진다(`"3" > "26"`은 참). 숫자로 바꿔 비교하는 쪽이 안전하다.

## 별표가 들어오거나 모두 꺼내라면

### 읽는 법을 전부 출력하라면

개수 대신 실제 문자열 목록을 원하면 앞의 재귀를 그대로 쓰되, 떼어 낸 조각을 글자로 바꿔 이어 붙인다. 답의 개수가 지수적으로 늘 수 있으니 출력 크기 자체가 지수라 메모로 줄일 수 없다. 이런 문제는 [백트래킹](/posts/recursion-backtracking)이 맞는 도구다.

```js
function decodeAll(s) {
  const out = [];
  function go(i, acc) {
    if (i === s.length) { out.push(acc); return; }
    if (s[i] === "0") return;                                 // 0으로 시작하는 조각은 없다
    go(i + 1, acc + String.fromCharCode(64 + Number(s[i])));  // 한 글자
    if (i + 1 < s.length && Number(s.slice(i, i + 2)) <= 26)  // 두 글자 (첫 글자는 0이 아님)
      go(i + 2, acc + String.fromCharCode(64 + Number(s.slice(i, i + 2))));
  }
  go(0, "");
  return out;
}
```

```text
decodeAll("121026") → [ 'ABJBF', 'ABJZ', 'LJBF', 'LJZ' ]
decodeAll("226")    → [ 'BBF', 'BZ', 'VF' ]
decodeAll("06")     → []
```

A의 문자 코드가 65라 `64 + 숫자`가 그 글자다. 첫 글자가 0이 아님을 위에서 걸렀으니 두 글자 조건은 26 이하만 보면 된다. 전화번호 숫자를 글자 조합으로 바꾸는 [Letter Combinations of a Phone Number](/posts/leetcode-letter-combinations-of-a-phone-number)와 같은 모양의 백트래킹이다.

### 별표가 1부터 9 중 아무 숫자라면

LeetCode 639 Decode Ways II다. `*`는 1부터 9 중 하나를 뜻한다(0은 아니다). 점화식 모양은 그대로이고, "이 조각을 읽는 방법이 1가지냐 0가지냐" 대신 "몇 가지냐"를 곱한다.

- 한 글자: `*`는 9가지, 0은 0가지, 나머지 숫자는 1가지.
- 두 글자 `**`: 11~19와 21~26이라 15가지.
- `*` 뒤 숫자 b: b가 6 이하면 1b와 2b로 2가지, 7 이상이면 1b만 1가지.
- 숫자 a 뒤 `*`: a가 1이면 11~19로 9가지, 2면 21~26으로 6가지, 그 외 0가지.

```js
function numDecodingsStar(s) {
  const MOD = 1_000_000_007;
  const one = (c) => (c === "*" ? 9 : c === "0" ? 0 : 1);   // 한 글자로 읽는 방법 수
  const two = (a, b) => {                                     // 두 글자로 읽는 방법 수
    if (a === "*" && b === "*") return 15;                    // 11~19, 21~26
    if (a === "*") return b <= "6" ? 2 : 1;                   // 1b와 2b, 또는 1b만
    if (b === "*") return a === "1" ? 9 : a === "2" ? 6 : 0;  // 11~19, 21~26
    const v = Number(a + b);
    return v >= 10 && v <= 26 ? 1 : 0;
  };
  let prev2 = 0, prev1 = 1;
  for (let i = 1; i <= s.length; i++) {
    let cur = one(s[i - 1]) * prev1;
    if (i >= 2) cur += two(s[i - 2], s[i - 1]) * prev2;
    cur %= MOD;
    prev2 = prev1;
    prev1 = cur;
  }
  return prev1;
}
```

`"*"`에 9, `"1*"`에 18, `"2*"`에 15, `"**"`에 96, `"*0"`에 2(10과 20)가 나왔다. 별표를 1~9로 모두 바꿔 넣고 원래 문제의 답을 더하는 무식한 방법과도 맞춰 봤다. 곱셈 결과는 많아야 15 × (10^9 + 7) + 9 × (10^9 + 7)쯤이라 2^53보다 훨씬 작아서 JavaScript `Number`로도 정확하다. Java에서는 이 곱이 `int`를 넘으니 `long`으로 계산하고 나머지를 취한다.

### 숫자가 한 글자씩 흘러 들어온다면

두 변수 풀이는 앞에서 뒤로 한 번만 읽고, 바로 앞 글자 하나와 기록 두 개만 들고 있다. 글자가 하나 들어올 때마다 갱신하면 "지금까지 받은 문자열을 읽는 방법의 수"를 늘 알고 있다. 메모리는 입력 길이와 상관없이 상수다.

### 매핑이 1부터 26이 아니라면

조각 길이의 최댓값이 L이면 점화식이 앞의 L칸을 보게 된다. 예를 들어 1부터 260까지면 세 글자 조각까지 봐야 하니 기록이 세 개 필요하다. 조각마다 "올바른 수인가"만 판정하면 되고, 앞에 0이 붙은 조각을 막는 규칙은 그대로다. 사전에 있는 단어로만 자르는 [Word Break](/posts/leetcode-word-break)는 이 L이 단어 길이의 최댓값인 경우로 볼 수 있다.

비슷한 문제로는 [계단 오르기](/posts/leetcode-climbing-stairs), [Word Break](/posts/leetcode-word-break), Decode Ways II(639), 문자열을 회문 조각으로 나누는 [Palindrome Partitioning](/posts/leetcode-palindrome-partitioning)이 있다.

## 면접에서 나올 만한 질문

### 점화식을 어떻게 세웠나요?

앞 i글자의 마지막 조각이 한 글자인지 두 글자인지로 나눴다. 한 글자가 0이 아니면 `dp[i-1]`가지가, 두 글자가 10부터 26 사이면 `dp[i-2]`가지가 이어지고, 두 경우는 마지막 조각이 달라 겹치지 않으니 더한다. 바닥은 빈 문자열을 읽는 방법 1가지인 `dp[0] = 1`이다.

### 0은 어떻게 처리하나요?

0은 혼자 글자가 될 수 없으니 한 글자 조각에서 빼고, 두 글자 조각은 10 이상이어야 한다는 조건으로 앞에 0이 붙은 조각을 막는다. 이 두 조건만 있으면 `"30"`, `"100"`, `"06"`처럼 0이 막히는 입력은 점화식이 알아서 0을 낸다. 따로 예외를 둘 필요가 없다.

### 계단 오르기와 무엇이 같고 무엇이 다른가요?

둘 다 한 칸이나 두 칸 앞의 값을 더하는 같은 점화식이다. 다른 점은 Decode Ways는 각 항 앞에 "그 조각이 올바른 글자인가" 조건이 붙는다는 것이다. 모든 조건이 참인 `"111…1"`에서는 정확히 피보나치가 된다.

### 공간을 O(1)로 줄일 수 있나요?

있다. 점화식이 `dp[i-1]`과 `dp[i-2]`만 보니 변수 두 개를 밀고 가면 된다. 처음 값을 `dp[-1] = 0`, `dp[0] = 1`로 두면 길이 1 입력도 반복문 하나로 처리된다.

### 메모에서 "안 구함"을 0으로 두면 왜 문제인가요?

이 문제는 실제 답이 0인 칸이 흔해서, 0을 "안 구함"으로 쓰면 그런 칸을 물을 때마다 다시 계산한다. 결과는 맞지만 메모가 듣지 않아 최악에는 재귀와 같은 속도가 된다. -1이나 `undefined`처럼 답이 될 수 없는 값으로 표시한다.

### 답이 매우 커지면 어떻게 하나요?

1만 100개면 약 5.7 × 10^20가지라 Java `int`도 JavaScript `Number`도 정확하게 담지 못한다. 원래 문제는 32비트 안이라는 보장이 있지만, 그 보장이 없는 변형은 보통 10^9 + 7로 나눈 나머지를 묻는다. 매 단계 더한 뒤 나머지를 취하고, 곱셈이 끼면 Java는 `long`으로 계산한다.

### 읽는 법을 모두 출력하라면요?

같은 재귀를 백트래킹으로 바꿔 떼어 낸 조각을 글자로 이어 붙인다. 출력 개수가 지수적으로 늘 수 있어서 메모로는 줄어들지 않고, 시간은 출력 크기에 비례한다. 개수만 필요하면 DP, 목록이 필요하면 백트래킹이다.
