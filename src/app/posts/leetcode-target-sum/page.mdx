[LeetCode 494. Target Sum](https://leetcode.com/problems/target-sum/)은 처음 보면 백트래킹 문제처럼 생겼다. 수마다 `+`와 `-` 중 하나를 고르니 갈래가 둘씩 나뉜다. 실제로 그렇게 풀어도 통과한다. 이 문제가 재미있는 건 같은 질문을 전혀 다른 문제로 바꿔 풀 수 있다는 점이다. 식을 조금 정리하면 "부분집합의 합이 P가 되는 경우의 수"가 되고, 그건 [Partition Equal Subset Sum](/posts/leetcode-partition-equal-subset-sum)에서 본 0/1 배낭이다.

이 글에서는 모든 부호를 다 해 보는 재귀, 반으로 나눠 합치는 중간에서 만나기, 메모이제이션, 합을 축으로 한 2차원 표, 부분집합 합으로 바꾼 1차원 배열까지 다섯 풀이를 본다. 배낭 문제의 바탕은 [동적 계획법 글](/posts/dynamic-programming#배낭에-넣을지-말지)에 있다. 코드는 Node.js 22, Python 3, Java 21에서 돌렸다.

## 수마다 더하기나 빼기를 붙인다

음이 아닌 정수 배열 `nums`와 정수 `target`이 주어진다. 각 수 앞에 `+`나 `-`를 하나씩 붙여 식을 만들고, 그 값이 `target`이 되는 식의 개수를 돌려준다. 수의 순서는 바꾸지 않는다.

풀이를 고를 때 볼 제약은 이렇다.

- 수는 1개 이상 20개 이하다. 부호 조합은 많아야 2^20 = 1,048,576개다.
- 각 수는 0 이상 1000 이하이고, 전체 합도 1000 이하다.
- `target`은 -1000 이상 1000 이하다. 음수가 될 수 있다.

20개뿐이라 2^20을 다 해 보는 브루트포스도 시간 안에 들어온다. 이 문제는 "느린 풀이도 통과하지만 왜 더 나은 풀이가 있는가"를 묻는 쪽에 가깝다. 합이 1000 이하라는 제약이 DP 표의 크기를 정해 준다.

## 카드 네 장으로 열여섯 가지를 다 써 보기

`nums = [2, 1, 1, 3]`, `target = 1`로 한다. 부호를 붙이는 16가지 중 값이 1인 것을 찾으면 셋이다.

```text
+2 +1 +1 -3  =  1
-2 +1 -1 +3  =  1
-2 -1 +1 +3  =  1
```

두 번째와 세 번째는 1이 두 개라 생긴 쌍이다. 값이 같은 수라도 자리가 다르면 다른 식으로 센다. 그래서 중복을 없애려고 애쓸 필요가 없다. 0이 있으면 더 재미있다. `+0`과 `-0`이 모두 같은 값을 내니 0 하나마다 답이 두 배가 된다. `[0, 0, 1]`에서 1을 만드는 식은 4개다.

## 갈래마다 더하거나 빼는 재귀

i번째 수까지 부호를 정했고 지금까지 합이 `sum`이라면, 다음 수에 `+`를 붙이거나 `-`를 붙인다.

```js
function findTargetSumWays(nums, target) {
  function go(i, sum) {
    if (i === nums.length) return sum === target ? 1 : 0; // 다 붙였다: 맞으면 한 가지
    return go(i + 1, sum + nums[i])   // + 를 붙인다
         + go(i + 1, sum - nums[i]);  // - 를 붙인다
  }
  return go(0, 0);
}
console.log(findTargetSumWays([2, 1, 1, 3], 1)); // 3
```

바닥에서 `i === nums.length`를 확인한 다음에만 `sum`을 본다. 중간에 `sum === target`이 됐다고 1을 돌려주면 남은 수에 부호를 붙이지 않은 식을 세게 된다.

호출은 정확히 2^(n+1) - 1번이다. 모두 1인 배열로 재 봤다.

```text
n = 20   호출 2,097,151번      12 ms
n = 24   호출 33,554,431번     218 ms
n = 28   호출 536,870,911번    3,566 ms
```

앞의 세 수 `[2, 1, 1]`까지만 호출을 펼쳐 보면 반복이 눈에 띈다.

```text
go(0, 0)
  go(1, 2)
    go(2, 3)
      go(3, 4)
      go(3, 2)
    go(2, 1)
      go(3, 2)
      go(3, 0)
  go(1, -2)
    go(2, -1)
      go(3, 0)
      go(3, -2)
    go(2, -3)
      go(3, -2)
      go(3, -4)
```

`go(3, 2)`, `go(3, 0)`, `go(3, -2)`가 두 번씩 나온다. 같은 칸에서 남은 수 3에 부호를 붙이는 계산을 두 번 한다는 뜻이다. 수가 늘수록 이런 겹침이 폭발적으로 늘어난다. 이 관찰이 뒤에서 메모이제이션으로 이어진다.

n이 20으로 막혀 있어서 통과는 한다. 하지만 n이 4 늘 때마다 16배다. 면접에서 "n이 40이면요?"라고 물으면 이 풀이로는 답할 수 없다.

## 반씩 나눠 세고 가운데서 맞춘다

n이 40쯤으로 커지는데 수의 값도 커서 표를 만들기 어렵다면 쓸 수 있는 방법이 있다. 배열을 앞 절반과 뒤 절반으로 나눈다. 앞 절반의 모든 부호 조합에서 나오는 합을 세어 해시맵에 담고(합 → 그 합이 나온 횟수), 뒤 절반도 똑같이 한다. 그다음 앞 절반 합이 `s`일 때 뒤 절반 합이 `target - s`인 개수를 곱해서 더한다. [Two Sum](/posts/leetcode-two-sum)에서 짝을 해시맵으로 찾던 것과 같은 생각이다.

```js
function findTargetSumWays(nums, target) {
  const half = nums.length >> 1;
  function sums(arr) {                         // 부호 조합의 합 → 개수
    let m = new Map([[0, 1]]);
    for (const x of arr) {
      const next = new Map();
      for (const [s, c] of m) {
        next.set(s + x, (next.get(s + x) || 0) + c);
        next.set(s - x, (next.get(s - x) || 0) + c);
      }
      m = next;
    }
    return m;
  }
  const left = sums(nums.slice(0, half));
  const right = sums(nums.slice(half));
  let count = 0;
  for (const [s, c] of left) count += c * (right.get(target - s) || 0); // 짝이 되는 합
  return count;
}
```

예시에서 앞 절반 `[2, 1]`의 합은 -3, -1, 1, 3이 한 번씩이고, 뒤 절반 `[1, 3]`도 -4, -2, 2, 4가 한 번씩이다. 앞이 -3이면 뒤가 4, -1이면 2, 3이면 -2라 1 × 1을 세 번 더해 3이다.

양쪽이 많아야 2^(n/2)개씩이라 시간과 공간이 O(2^(n/2))다. n = 40이면 2^20 남짓으로 버틸 만하다. 값이 10^9까지인 수 40개로 돌려 보니 1.3초가 걸렸다. 브루트포스라면 2^40, 1조 번이 넘는 호출이라 시도할 수도 없다. 시간 대부분은 해시맵에 100만 개 남짓 넣는 데 든다. 이 문제의 제약에서는 오히려 지나친 풀이지만, 값이 커서 DP 표를 못 만들 때 남는 선택지다. 길이 20짜리 배열(합 500)에서 0.7 ms였다.

## (몇 번째 수, 지금 합)이 같으면 답도 같다

재귀를 다시 보면 `go(i, sum)`의 답은 i와 `sum`에만 달려 있다. 앞에서 어떤 부호를 붙여 이 합에 왔든 남은 수로 target을 만드는 방법 수는 같다. 예시에서 `+2 +1 -1`과 `+2 -1 +1`은 부호를 붙인 자리가 다르지만, 세 번째 수까지 보고 합이 2인 같은 칸에 온다. 남은 수 3으로 target을 만드는 방법은 두 길에서 똑같다.

`sum`은 `-total`부터 `total`까지라 서로 다른 칸은 `n × (2·total + 1)`개다. 음수 합을 배열 첨자로 쓰려고 `total`만큼 밀어(오프셋) 넣는다.

```js
function findTargetSumWays(nums, target) {
  const total = nums.reduce((a, b) => a + b, 0);
  const n = nums.length;
  // memo[i][sum + total]: 합이 음수일 수 있어 total만큼 밀어 둔다
  const memo = Array.from({ length: n }, () => new Array(2 * total + 1).fill(-1));
  function go(i, sum) {
    if (i === n) return sum === target ? 1 : 0;
    const k = sum + total;
    if (memo[i][k] !== -1) return memo[i][k];
    return (memo[i][k] = go(i + 1, sum + nums[i]) + go(i + 1, sum - nums[i]));
  }
  return go(0, 0);
}
```

시간과 공간이 O(n · total)이다. n = 20, total = 1000이면 4만 칸 남짓이다. 재귀 깊이는 n이라 20을 넘지 않아 어느 언어든 안전하다.

메모 열쇠에 i를 빼먹고 `sum`만 쓰면 틀린다. 같은 합이라도 남은 수가 다르면 답이 다르기 때문이다. `[1, 2, 3]`, target 0의 답은 2(`+1 +2 -3`, `-1 -2 +3`)인데 합만 열쇠로 쓰면 1이 나온다.

## 합을 축으로 한 장부를 한 줄씩 넘긴다

메모를 아래에서 위로 바꾸면 "지금까지 수로 만들 수 있는 합마다, 그 합을 만드는 방법 수"를 한 줄씩 갱신하는 표가 된다. 다음 수 x를 만나면 모든 합 s가 s + x와 s - x 두 칸으로 갈라진다.

```js
function findTargetSumWays(nums, target) {
  const total = nums.reduce((a, b) => a + b, 0);
  if (Math.abs(target) > total) return 0;     // 표 밖이다
  const off = total, W = 2 * total + 1;       // 칸 s + off가 합 s
  let dp = new Array(W).fill(0);
  dp[off] = 1;                                // 아무 수도 안 썼을 때 합 0
  for (const x of nums) {
    const next = new Array(W).fill(0);
    for (let s = 0; s < W; s++) {
      if (dp[s] === 0) continue;
      next[s + x] += dp[s];                   // + x
      next[s - x] += dp[s];                   // - x
    }
    dp = next;
  }
  return dp[target + off];
}
```

`Math.abs(target) > total`을 먼저 거르지 않으면 `dp[target + off]`가 배열 밖을 읽는다. JavaScript는 `undefined`를 돌려주고 Java는 예외를 던진다.

0이 들어오면 `next[s + 0]`과 `next[s - 0]`이 같은 칸이라 두 번 더해져 값이 두 배가 된다. 앞에서 말한 "0 하나마다 두 배"가 따로 처리하지 않아도 저절로 나온다.

아래 그림은 같은 표를 해시맵으로 들고 다닌 모습이다. 칸은 수 네 개이고, 수를 하나 지날 때마다 장부가 어떻게 갈라지는지 본다.

표 전체를 펼치면 이렇다. 가로가 합, 세로가 지금까지 본 수의 개수다. 점은 0이다.

두 가지가 보인다. 하나는 줄마다 칸이 한 칸 걸러 비어 있다는 것이다. 지금까지 본 수의 합이 짝수면 만들 수 있는 합도 모두 짝수고, 홀수면 모두 홀수다. 부호를 하나 바꾸면 합이 그 수의 두 배만큼 변해서 홀짝이 그대로이기 때문이다. 뒤에서 볼 "홀수면 답이 0"이 이 그림의 빈칸이다. 다른 하나는 좌우 대칭이다. 부호를 모두 뒤집으면 합의 부호만 바뀌니 s 칸과 -s 칸이 언제나 같다. 마지막 줄에서 1과 -1이 둘 다 3이다.

시간 O(n · total), 공간은 두 줄만 들고 있어 O(total)이다. 해시맵 버전은 실제로 닿은 합만 담아서 수가 크고 드문드문할 때 유리하다.

## 더하기 바구니의 합은 정해져 있다

이제 식을 정리해 본다. `+`를 붙인 수들의 합을 P, `-`를 붙인 수들의 합을 N이라 하자. 모든 수는 둘 중 한 바구니에 들어가니 두 식이 생긴다.

```text
P - N = target
P + N = total
```

두 식을 더하면 `2P = total + target`, 즉 `P = (total + target) / 2`다. 예시에서 total은 7, target은 1이라 P는 4다. 부호를 고르는 문제가 "합이 4가 되도록 수를 고르는 방법 수"로 바뀌었다. `-`쪽은 나머지가 알아서 채운다.

부호를 붙이는 방법 하나는 `+` 바구니에 들어갈 수를 고르는 방법 하나와 정확히 짝지어진다. 바구니를 고르면 부호가 정해지고, 부호가 정해지면 바구니가 정해진다. 그래서 두 문제의 답의 개수가 같다. 값이 같은 두 1도 자리가 다르니 서로 다른 고르기로 센다. 부호 문제에서 두 1을 따로 센 것과 맞아떨어진다.

이 식에서 답이 0인 경우도 바로 읽힌다.

- `total + target`이 홀수면 P가 정수가 아니라 만들 수 없다. `[2, 2, 2]`로 1을 만들 수 없는 이유다.
- `|target| > total`이면 모든 수를 한쪽에 몰아도 닿지 않는다.

target이 음수면 모든 부호를 뒤집은 식이 -target을 만드니 개수가 같다. 그래서 `|target|`로 바꿔 계산한다. 그러지 않으면 P가 음수가 될 수 있다.

합이 P가 되는 부분집합 수는 각 수를 한 번씩만 쓰는 0/1 배낭이다. [Coin Change II](/posts/leetcode-coin-change-ii)의 1차원 배열과 같은 모양인데, 수마다 한 번만 쓰니 합을 큰 쪽부터 돈다.

```js
function findTargetSumWays(nums, target) {
  const total = nums.reduce((a, b) => a + b, 0);
  const t = Math.abs(target);                 // 부호를 다 뒤집으면 -target. 개수가 같다
  if (t > total || (total + t) % 2 === 1) return 0;
  const P = (total + t) / 2;                  // + 바구니의 합
  const dp = new Array(P + 1).fill(0);        // dp[s]: 합이 s가 되게 고르는 방법 수
  dp[0] = 1;                                  // 아무것도 안 고르기
  for (const x of nums)
    for (let s = P; s >= x; s--)              // 큰 쪽부터: 수마다 한 번만
      dp[s] += dp[s - x];
  return dp[P];
}
```

펼친 표와 이 배열은 같은 정보를 다르게 적은 것이다. 앞의 i개 수의 합을 S라 하면 합 축 표의 i번째 줄 s 칸은 "앞의 i개에서 합이 (S + s) / 2가 되도록 고르는 방법 수"와 같다. 4번째 줄 1 칸은 (7 + 1) / 2 = 4라 3, 3번째 줄 0 칸은 앞 세 수의 합이 4라 (4 + 0) / 2 = 2를 만드는 방법(2 하나, 또는 1 두 개)이라 2다. 부분집합 풀이는 합 축 표에서 필요한 한 칸과 그 칸에 닿는 칸만 남기고 나머지를 버린 셈이다.

시간 O(n · P), 공간 O(P)다. P는 많아야 1000이라 2차원 표보다 칸이 절반 이하다. 다섯 풀이 중 가장 빠르고 짧다. 길이 20 배열에서 0.3 ms였다.

0도 저절로 처리된다. x가 0이면 `s >= 0`까지 돌며 `dp[s] += dp[s]`가 되어 모든 칸이 두 배가 된다. `[0, 0, 1]`에서 4가 나온다. 0을 건너뛰는 최적화(`if (x === 0) continue`)를 넣으면 1이 나와 틀린다.

## 세 언어로 쓴 부분집합 풀이

```python
from typing import List

class Solution:
    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        total = sum(nums)
        t = abs(target)                      # 부호를 모두 뒤집으면 -target이 되니 개수가 같다
        if t > total or (total + t) % 2:     # 닿을 수 없거나 P가 정수가 아니다
            return 0
        P = (total + t) // 2                 # + 쪽에 둘 수들의 합
        dp = [0] * (P + 1)
        dp[0] = 1
        for x in nums:
            for s in range(P, x - 1, -1):    # 큰 쪽부터: 수마다 한 번만 쓴다
                dp[s] += dp[s - x]
        return dp[P]
```

```java
class Solution {
    public int findTargetSumWays(int[] nums, int target) {
        int total = 0;
        for (int x : nums) total += x;
        int t = Math.abs(target);
        if (t > total || (total + t) % 2 != 0) return 0;
        int P = (total + t) / 2;
        int[] dp = new int[P + 1];
        dp[0] = 1;
        for (int x : nums)
            for (int s = P; s >= x; s--) dp[s] += dp[s - x]; // 큰 쪽부터
        return dp[P];
    }
}
```

세 언어 모두 `[2, 1, 1, 3]`과 1에서 3, `[0, 0, 1]`과 1에서 4, `[3, 1, 2]`와 -4에서 1, `[1]`과 2에서 0, `[0]`과 0에서 2를 냈다.

Python은 `range(P, x - 1, -1)`의 끝이 포함되지 않아 `x - 1`로 써야 x까지 돈다. `range(P, x, -1)`로 쓰면 `s = x` 칸을 빠뜨려 "x 하나만 고르는" 경우를 놓친다. Java는 답이 2^20을 넘지 않아 `int`로 넉넉하다. 나눗셈과 나머지가 언어마다 음수에서 다르게 동작하는데(JavaScript와 Java에서 `-3 % 2`는 -1, Python에서는 1), 여기서는 `|target|`을 써서 `total + t`가 늘 0 이상이라 걱정할 필요가 없다.

길이 9 이하, 값 0~5, target -10~10인 무작위 입력 4000개에서 다섯 풀이의 답이 모두 같았다. 시간은 길이 20, 합 500인 배열 하나로 쟀다.

|---|---|---|---|---|
| 부호 재귀 | O(2^n) | O(n) | 10 ms | n이 20 이하로 작을 때, 식을 나열할 때 |
| 중간에서 만나기 | O(2^(n/2)) | O(2^(n/2)) | 0.7 ms | n이 40쯤이고 값이 커서 표가 안 될 때 |

## 부호 문제에서 자주 틀리는 자리

### 합을 작은 쪽부터 돈다

```js
for (const x of nums)
  for (let s = x; s <= P; s++) dp[s] += dp[s - x]; // 작은 쪽부터
```

이러면 같은 수를 여러 번 쓰는 무한 배낭이 되어 `[2, 1, 1, 3]`에서 11이 나온다. 부호는 수마다 하나씩이라 수를 한 번만 써야 한다. 무한 개면 작은 쪽부터, 한 번씩이면 큰 쪽부터다.

### 메모 열쇠에서 i를 뺀다

`Map`에 합만 넣으면 남은 수가 다른 상황을 같은 칸으로 본다. `[1, 2, 3]`, target 0에서 정답 2 대신 1이 나온다. 상태는 "어디까지 봤나"와 "지금 합" 두 가지다.

### 음수 합을 그대로 첨자로 쓴다

JavaScript 배열에 `memo[i][-3] = 5`를 넣으면 오류 없이 "-3"이라는 이름의 속성이 생긴다. 이번에는 우연히 맞게 돌아가지만, 배열이 아니라 객체의 속성으로 다뤄져 느려질 수 있고 의도가 숨는다. Java와 Python은 다르다. Java는 예외를 던지고, Python은 `memo[-3]`이 뒤에서 세 번째 칸을 가리켜 조용히 엉뚱한 값을 읽는다. 오프셋을 더하거나 해시맵을 쓴다.

### 합 축 표를 배열 하나에서 덮어쓴다

부분집합 풀이처럼 배열 하나로 줄이고 싶어 `next` 없이 `dp`를 바로 고치면, 이번 수로 옮겨 놓은 값을 같은 반복에서 또 옮긴다. 작은 합에서 큰 합으로 훑는 동안 `s + x`로 옮긴 값이 나중에 다시 `s`로 걸려 한 번 더 움직이기 때문이다. `[2, 1, 1, 3]`, target 1에서 3 대신 40이 나왔다. 합이 양쪽으로 갈라지는 표는 어느 방향으로 훑어도 이 문제가 생겨서 두 줄을 번갈아 쓴다. 부분집합 풀이가 배열 하나로 되는 건 한쪽 방향(더하기)으로만 옮기기 때문이다.

### 범위와 홀짝 검사를 빼먹는다

`[3, 1, 2]`, target -8이면 total이 6이라 `(6 - 8) / 2 = -1`이 P가 된다. `|target| > total` 검사 없이 `new Array(P + 1)`을 만들면 길이 0 배열에서 `dp[-1]`을 읽어 `undefined`가 나온다. P가 -2 이하면 `new Array`가 `RangeError`를 던진다. `total + target`이 홀수인 경우도 거르지 않으면 P가 1.5 같은 소수가 되어 배열 첨자로 쓸 수 없다.

### 0을 건너뛴다

0은 합을 바꾸지 않으니 건너뛰어도 될 것 같지만, 부호를 붙이는 방법은 두 배가 된다. `[0, 0, 1]`의 답은 4다. 건너뛰면 1이 나온다. 0을 따로 세어 마지막에 2의 거듭제곱을 곱하는 방법도 있지만, 반복문을 `s >= x`로 두면 0도 저절로 두 배가 된다.

## 부호 문제를 비틀면

### 식을 모두 보여 달라면

재귀에 지금까지 만든 식을 문자열로 들고 다니다가 바닥에서 합이 맞으면 모은다. 예시에서 `+2+1+1-3`, `-2+1-1+3`, `-2-1+1+3`이 나온다. 답의 개수만큼 출력해야 하니 O(2^n)보다 나아질 수 없다. 부분집합 표를 먼저 채워 두면, 가는 길에 `dp`가 0인 갈래(그쪽으로는 P를 만들 수 없는 갈래)를 미리 잘라 헛걸음을 없앨 수 있다. [Subsets](/posts/leetcode-subsets)의 백트래킹 틀과 같다.

### 식 하나만 돌려 달라면

부분집합 표를 2차원으로 남기고 끝에서 거꾸로 걷는다. `dp[i][s]`가 "앞의 i개로 합 s를 만드는 방법 수"일 때, i번째 수 x를 `+` 쪽에 넣어도 남은 `s - x`를 앞의 수로 만들 수 있으면(`dp[i-1][s-x] > 0`) 넣는다.

```js
function oneExpression(nums, target) {
  const total = nums.reduce((a, b) => a + b, 0);
  const t = Math.abs(target);
  if (t > total || (total + t) % 2) return null;
  const P = (total + t) / 2, n = nums.length;
  const dp = Array.from({ length: n + 1 }, () => new Array(P + 1).fill(0));
  dp[0][0] = 1;
  for (let i = 1; i <= n; i++)
    for (let s = 0; s <= P; s++)
      dp[i][s] = dp[i - 1][s] + (s >= nums[i - 1] ? dp[i - 1][s - nums[i - 1]] : 0);
  if (dp[n][P] === 0) return null;
  const plus = new Array(n).fill(false);
  let s = P;
  for (let i = n; i >= 1; i--) {
    const x = nums[i - 1];
    if (s >= x && dp[i - 1][s - x] > 0) { plus[i - 1] = true; s -= x; } // x를 P 쪽에 넣는다
  }
  const positive = target >= 0;              // 음수 target이면 부호를 뒤집는다
  return nums.map((x, i) => (plus[i] === positive ? "+" : "-") + x).join(" ");
}
```

`[2, 1, 1, 3]`과 1에서 `-2 -1 +1 +3`, -1에서 `+2 +1 -1 -3`, `[1, 2, 3, 4, 5]`와 3에서 `-1 -2 -3 +4 +5`가 나온다. `[2, 2, 2]`와 1처럼 만들 수 없으면 `null`이다. 걷는 동안 0인 칸으로는 들어가지 않으니 막다른 길이 없다.

### 더하기, 빼기, 안 쓰기 셋 중에 고른다면

수를 아예 빼 버리는 선택이 생기면 갈래가 셋이 된다. 합 축 표에서 `next[s] += dp[s]`를 하나 더하면 끝이다. 부분집합 변환은 더 이상 쓸 수 없다. 바구니가 셋이 되어 P가 하나로 정해지지 않기 때문이다. `[2, 1, 1, 3]`으로 1을 만드는 방법은 9가지가 되고, 3^n 브루트포스로 센 값과 같았다.

### 수에 음수가 섞인다면

부분집합 변환은 식으로는 여전히 맞지만 P가 음수가 되거나 배낭에 음수 무게가 들어가 1차원 배열 풀이가 깨진다. 합 축 표나 해시맵 풀이는 그대로 돈다. 합의 범위를 "음수의 합"부터 "양수의 합"까지로 잡으면 된다.

### 수가 많고 합이 작다면, 수가 적고 값이 크다면

n이 1000이어도 합이 1000 이하면 DP는 100만 칸이라 문제없다. 반대로 n이 40이고 값이 10^9까지면 표를 만들 수 없으니 중간에서 만나기로 간다. 제약의 어느 쪽이 작은지 보고 풀이를 고르는 것이 이 문제가 가르치는 판단이다.

### 같은 변환을 쓰는 문제들

부분집합을 둘로 나눠 차이를 보는 문제는 모두 이 변환이 통한다. [Partition Equal Subset Sum](/posts/leetcode-partition-equal-subset-sum)은 target이 0인 경우에 "가능한가"만 묻는다. LeetCode 1049(Last Stone Weight II)는 두 바구니의 차이를 가장 작게 만드는 문제라, 합이 total / 2 이하에서 만들 수 있는 가장 큰 P를 찾는다. 경우의 수가 커져서 나머지로 묻는 변형은 덧셈마다 `% 1_000_000_007`을 한다.

## 면접에서 나올 만한 질문

### 브루트포스로도 통과하는데 왜 DP를 쓰나요?

n이 20이라 2^20은 통과하지만 n이 조금만 커져도 4 늘 때마다 16배씩 느려진다. DP는 합의 범위(많아야 2001칸)만큼만 상태를 만들어 n에 선형이다. 면접에서는 브루트포스로 시작해 "같은 (i, 합)이 반복된다"를 짚고 DP로 넘어가는 흐름을 보여 주면 된다.

### 부분집합 합으로 바뀌는 이유를 설명해 주세요.

`+` 쪽 합을 P, `-` 쪽 합을 N이라 하면 `P - N = target`, `P + N = total`이 성립한다. 더하면 `P = (total + target) / 2`라 P가 정해지고, 부호를 고르는 것은 합이 P가 되는 수를 고르는 것과 일대일로 대응한다. 홀수면 답이 0이고 `|target| > total`이어도 0이다.

### target이 음수면 어떻게 하나요?

모든 부호를 뒤집으면 값이 -target이 되니 경우의 수가 같다. `|target|`로 바꿔 계산하면 P가 늘 0 이상이 된다. 합 축 표를 쓰면 오프셋만 맞춰 그대로 읽어도 된다.

### 왜 합을 큰 쪽부터 도나요?

수마다 부호가 하나라 각 수를 한 번만 써야 하기 때문이다. 큰 쪽부터 돌면 `dp[s - x]`가 아직 이번 수를 반영하지 않은 값이다. 작은 쪽부터 돌면 같은 수를 여러 번 쓰는 무한 배낭이 되어 `[2, 1, 1, 3]`에서 3 대신 11이 나온다.

### 0이 있으면 무엇이 달라지나요?

`+0`과 `-0`이 같은 값을 내서 0 하나마다 경우의 수가 두 배가 된다. 1차원 반복을 `s >= x`로 두면 x가 0일 때 모든 칸이 두 배가 되어 저절로 맞는다. 0을 건너뛰는 최적화를 넣으면 틀린다.

### n이 40이고 값이 아주 크면요?

표를 만들 수 없으니 중간에서 만나기를 쓴다. 앞 절반과 뒤 절반의 부호 조합 합을 각각 해시맵에 세고, 앞 합 s마다 뒤에서 `target - s`의 개수를 곱해 더한다. 시간과 공간이 O(2^(n/2))라 2^20 남짓이다.

### 모든 target에 대한 답이 한 번에 필요하다면요?

합 축 표를 쓴다. 마지막 줄의 각 칸이 그 합을 만드는 방법 수라 `-total`부터 `total`까지 답이 다 들어 있다. 부분집합 풀이로도 `dp[(total + t) / 2]`를 읽으면 되지만, 그러려면 P의 범위를 total까지 넓혀 표를 채워야 한다.
