## 오른쪽에서 처음 만나는 더 큰 값

단조 스택이 푸는 질문은 대개 이 모양이다. "각 원소에 대해, 오른쪽(또는 왼쪽)에서 처음 만나는 나보다 큰(또는 작은) 원소는?" 이걸 다음 큰 원소(next greater element)라고 부른다. 방향 둘, 크기 비교 둘이라 변형이 넷이다.

기본형부터 보자. `[2, 1, 2, 4, 3]`에서 각 원소의 다음 큰 원소를 구한다. 없으면 −1이다.

```js
function nextGreater(a) {
  const ans = new Array(a.length).fill(-1); // 끝까지 못 찾으면 -1
  const st = [];                            // 아직 답을 못 찾은 원소의 인덱스
  for (let i = 0; i < a.length; i++) {
    while (st.length && a[st.at(-1)] < a[i]) ans[st.pop()] = a[i]; // 내가 그들의 답이다
    st.push(i);
  }
  return ans;
}
console.log(nextGreater([2, 1, 2, 4, 3]));
```

```text
[ 4, 2, 4, -1, -1 ]
```

스택에는 인덱스를 넣는다. 값을 넣으면 꺼냈을 때 "누구의 답인지" 기록할 자리를 모른다. 아래 그림에서 다음을 누르면 원소가 하나씩 들어오며 스택을 정리한다. 오른쪽 상자가 스택이고 왼쪽이 바닥이다.

## 꺼낸 값이 다시 필요 없는 이유

스택이 늘 위로 갈수록 작아지는(단조 감소) 상태를 유지하는 건 결과일 뿐이고, 진짜 이유는 따로 있다. 꺼낸 값은 이후 어떤 원소의 답도 될 수 없다.

인덱스 j의 값이 i의 값보다 작고 j가 i보다 왼쪽이라고 하자. i보다 오른쪽에 있는 원소 x가 "왼쪽에서 처음 만나는 더 큰 값"을 찾는다면 j까지 갈 일이 없다. j보다 크고 x에 더 가까운 i가 먼저 걸리기 때문이다. j는 i에 가려졌다. 가려진 값은 버려도 된다. 단조 스택은 "아직 가려지지 않은 후보"만 남겨 두는 구조다.

같은 논리로 스택에 남은 값들은 저절로 정렬된다. 새 값이 자기보다 작은 값을 모두 치우고 위에 서니, 위로 갈수록 값이 작아진다. 다음 큰 원소를 찾으면 감소 스택, 다음 작은 원소를 찾으면 증가 스택이 된다. 어느 쪽을 써야 할지 헷갈리면 이 순서로 생각한다. 꺼내는 조건이 "새 값이 더 크다"면 남는 건 새 값보다 큰 것들이고, 그러니 스택은 감소한다.

## 넣을 때와 꺼낼 때, 두 번 답이 정해진다

같은 반복문 한 번에서 답이 두 번 나온다는 걸 알아 두면 변형 네 개가 한 틀로 정리된다.

- 꺼낼 때: 꺼내는 원소의 오른쪽 답이 정해진다. 꺼낸 원소에게 지금 들어온 원소가 "오른쪽에서 처음 만난 더 큰 값"이다.
- 꺼낸 뒤 넣기 직전: 지금 원소의 왼쪽 답이 정해진다. 꺼낼 만큼 꺼낸 뒤 스택 맨 위에 남은 원소가 "왼쪽에서 처음 만나는 나보다 큰 값"이다. 같은 값을 답으로 칠지는 꺼내는 조건의 등호로 정한다.

왼쪽에서 처음 만나는 작은 값(previous smaller element)을 구하는 코드로 확인해 보자. 이번엔 증가 스택이다.

```js
function prevSmaller(a) {
  const ans = new Array(a.length).fill(-1);
  const st = [];
  for (let i = 0; i < a.length; i++) {
    while (st.length && a[st.at(-1)] >= a[i]) st.pop(); // 나보다 크거나 같은 건 가려진다
    ans[i] = st.length ? a[st.at(-1)] : -1;              // 남은 맨 위가 내 왼쪽 답
    st.push(i);
  }
  return ans;
}
console.log(prevSmaller([3, 1, 4, 1, 5]));
```

```text
[ -1, -1, 1, -1, 1 ]
```

네 번째 원소 1의 답이 −1이다. 왼쪽의 1은 "나보다 작은" 값이 아니니 `>=`로 꺼냈다. 등호를 빼고 `>`로 쓰면 그 1이 남아 답이 1이 된다. 둘 중 무엇이 맞는지는 문제가 "작은"인지 "작거나 같은"인지에 달렸다.

정리하면 네 가지 변형은 이렇게 갈린다.

| 구하는 것 | 훑는 방향 | 스택 | 답이 정해지는 때 |
|---|---|---|---|
| 오른쪽 첫 큰 값 | 왼쪽 → 오른쪽 | 감소 | 꺼낼 때 (꺼낸 원소의 답) |
| 오른쪽 첫 작은 값 | 왼쪽 → 오른쪽 | 증가 | 꺼낼 때 |
| 왼쪽 첫 큰 값 | 왼쪽 → 오른쪽 | 감소 | 넣기 직전 (지금 원소의 답) |
| 왼쪽 첫 작은 값 | 왼쪽 → 오른쪽 | 증가 | 넣기 직전 |

오른쪽 답을 오른쪽에서 왼쪽으로 훑으며 "넣기 직전"에 구해도 된다. 방향을 바꾸면 표의 왼쪽·오른쪽이 뒤집힐 뿐이다. 늘 왼쪽에서 오른쪽으로 훑고 답이 정해지는 때만 바꾸는 쪽이 덜 헷갈린다.

## 안에 while이 있어도 O(n)

`for` 안에 `while`이 있지만 전체는 O(n)이다. 원소마다 스택에 한 번 들어가고 많아야 한 번 나온다. `while` 몸통은 돌 때마다 하나를 꺼내니, 모든 반복을 통틀어 n번을 넘을 수 없다. 기온이 계속 내려가는 구간에서는 `while`이 한 번도 안 돌다가, 높은 날 하루에 몰아서 많이 돈다. 몰아서 돈 만큼 앞에서 쉬었다. 이런 계산을 분할 상환 분석이라고 한다([Big O 표기법](/posts/big-o-notation)).

공간은 최악 O(n)이다. 값이 계속 내려가면 전부 스택에 쌓인다. 처음 구한 측정에서 이중 반복문이 1.7초나 걸린 것도 같은 입력 때문이다. 내려가는 구간의 모든 날이 마지막 날까지 오른쪽을 훑었다.

## 배열이 원형이면 두 바퀴 돈다

LeetCode 503번은 배열의 끝이 처음과 이어진 원형이다. 마지막 원소의 오른쪽은 첫 원소다. 배열을 두 번 이어 붙인 것처럼 인덱스를 `0`부터 `2n - 1`까지 돌리고 `i % n`으로 값을 읽으면 된다. 두 번째 바퀴에서는 새 원소를 넣지 않고 남은 원소의 답만 채운다.

직접 짜 보자. 내 풀이는 무작위 입력 3,000개로 "원형으로 한 칸씩 훑는" 이중 반복문과 같은 결과를 내는 걸 확인했다.

## 히스토그램으로 이어지는 흐름

단조 스택의 대표 난제가 [Largest Rectangle in Histogram](/posts/leetcode-largest-rectangle-in-histogram)이다. 막대 높이 배열에서 만들 수 있는 가장 큰 직사각형 넓이를 구한다. 이 문제가 단조 스택이라는 걸 알아보는 연결 고리는 이렇다.

어떤 막대 i의 높이를 그대로 쓰는 직사각형을 최대한 넓히면, 왼쪽으로는 i보다 낮은 막대를 만날 때까지, 오른쪽으로도 i보다 낮은 막대를 만날 때까지 간다. 곧 "왼쪽 첫 작은 값"과 "오른쪽 첫 작은 값"을 구하는 문제다. 위 표에서 둘 다 증가 스택이었다. 그리고 꺼낼 때 오른쪽 경계(지금 들어온 막대)와 왼쪽 경계(꺼낸 뒤 스택 맨 위)가 동시에 정해지니 한 번 훑으면 끝난다.

네 번째 단계의 "끝에 높이 0을 넣는다"가 이 문제의 흔한 장치다. 반복이 끝났는데 스택에 남은 막대들은 오른쪽 끝까지 넓어질 수 있는 막대다. 끝에 높이 0인 가짜 막대(보초)를 하나 넣으면 남은 막대가 모두 꺼내지면서 같은 코드로 넓이를 잰다. 보초를 빼먹으면 `[1, 2, 3]`처럼 계속 오르는 입력에서 아무것도 꺼내지 않아 답이 0이 된다.

같은 "양쪽 경계" 생각을 합으로 바꾼 문제가 부분 배열 최솟값의 합(907번)이다. 원소 a[i]가 최솟값이 되는 부분 배열의 개수는 (왼쪽으로 뻗을 수 있는 칸 수) × (오른쪽으로 뻗을 수 있는 칸 수)이니, a[i]에 그 개수를 곱해 더한다. 여기서 같은 값이 있으면 등호가 문제를 일으킨다.

```js
// left: 왼쪽은 "나보다 큰 것"만 넘어간다 (같은 값에서 멈춘다)
// right: 오른쪽은 "나보다 크거나 같은 것"을 넘어간다
while (st.length && a[st.at(-1)] > a[i]) st.pop();  // 왼쪽 경계용
while (st.length && a[st.at(-1)] >= a[i]) st.pop(); // 오른쪽 경계용
```

`[2, 2]`의 부분 배열은 `[2]`, `[2]`, `[2, 2]`라 최솟값 합이 6이다. 위처럼 한쪽만 등호를 넣으면 6이 나온다. 양쪽 다 `>`로 쓰면 `[2, 2]`를 어느 2도 자기 몫으로 세지 않아 4가 나오고, 양쪽 다 `>=`로 쓰면 두 2가 모두 `[2, 2]`를 자기 몫으로 세어 8이 나온다. 같은 최솟값이 여러 개인 구간은 "가장 왼쪽(또는 오른쪽) 것"이 맡는다고 한쪽만 등호를 넣어 정한다. 이 비대칭을 말로 설명할 수 있으면 면접관이 꽤 만족한다.

히스토그램과 짝을 이루는 문제가 빗물 가두기다. 히스토그램은 "막대 위로 얼마나 넓게 덮을 수 있나"를 묻고, 빗물은 "막대 사이 움푹한 곳에 얼마나 차나"를 묻는다. 스택 방향만 반대다. 빗물은 감소 스택을 쓰고, 더 높은 막대가 들어와 바닥을 꺼낼 때 그 바닥 위로 가로 한 층씩 물을 채운다.

```js
function trap(h) {
  const st = []; // 인덱스. 높이가 줄어드는 순서
  let water = 0;
  for (let i = 0; i < h.length; i++) {
    while (st.length && h[st.at(-1)] < h[i]) {
      const bottom = st.pop();              // 물이 고일 바닥
      if (!st.length) break;                // 왼쪽 벽이 없으면 물이 샌다
      const left = st.at(-1);
      const width = i - left - 1;
      const height = Math.min(h[left], h[i]) - h[bottom];
      water += width * height;              // 바닥 위로 가로 한 층을 채운다
    }
    st.push(i);
  }
  return water;
}
console.log(trap([0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1]), trap([4, 2, 0, 3, 2, 5]));
```

```text
6 9
```

꺼낼 때 왼쪽 벽(꺼낸 뒤 스택 맨 위)과 오른쪽 벽(지금 막대)이 정해지는 구조가 히스토그램과 똑같다. 차이는 왼쪽 벽이 없을 때 물이 새서 아무것도 더하지 않는다는 것뿐이다. 투 포인터 풀이는 칸마다 세로로 물을 세고, 이 풀이는 층마다 가로로 센다. 같은 답을 다른 방향으로 잘라 센 셈이다.

## 단조 덱: 창이 움직이는 단조 스택

단조 스택은 오른쪽에서만 넣고 빼는데, 앞쪽 원소가 시간이 지나 무효가 되는 상황이 있다. 길이 k인 창의 최댓값([Sliding Window Maximum](/posts/leetcode-sliding-window-maximum))이 그렇다. 창이 밀리면 가장 오래된 후보가 창 밖으로 나간다. 그래서 앞에서도 뺄 수 있는 덱을 쓴다. 뒤쪽 동작은 단조 스택과 똑같다.

```js
function maxSlidingWindow(a, k) {
  const dq = [], out = []; // 인덱스. 값이 줄어드는 순서
  let head = 0;            // shift() 대신 앞 위치를 숫자로 들고 간다
  for (let i = 0; i < a.length; i++) {
    while (dq.length > head && a[dq.at(-1)] <= a[i]) dq.pop(); // 뒤: 단조 스택과 같다
    dq.push(i);
    if (dq[head] <= i - k) head++;                            // 앞: 창 밖으로 나간 후보
    if (i >= k - 1) out.push(a[dq[head]]);
  }
  return out;
}
console.log(maxSlidingWindow([1, 3, -1, -3, 5, 3, 6, 7], 3));
```

```text
[ 3, 3, 5, 5, 6, 7 ]
```

덱의 맨 앞이 늘 창 안의 최댓값이다. 뒤에서 꺼내는 이유는 단조 스택과 같다. 새로 들어온 값보다 작은 옛 값은 새 값보다 먼저 창을 떠나니 다시는 최댓값이 될 수 없다. 앞에서 꺼내는 건 단조성과 상관없이 창 밖으로 나갔기 때문이다. 자바스크립트의 `shift()`는 O(n)이라 앞 위치를 `head` 숫자로 들고 갔다. 이유와 다른 방법은 [스택, 큐, 덱](/posts/ds-stack-queue-deque)에 있다. 창 쪽의 이야기는 [슬라이딩 윈도 패턴](/posts/sliding-window-pattern)으로 이어진다.

## 꺼내는 조건이 비교가 아니라 이득일 때

단조 스택은 "다음 큰 값" 말고 그리디 문제에도 나온다. 숫자 문자열에서 k자리를 지워 가장 작은 수를 만드는 문제(402번)를 보자. 앞자리가 작을수록 수가 작으니, 새 숫자가 스택 맨 위보다 작으면 맨 위를 지우는 게 이득이다. 지울 횟수가 남아 있는 동안만 꺼낸다.

```js
function removeKdigits(num, k) {
  const st = [];
  for (const d of num) {
    while (k > 0 && st.length && st.at(-1) > d) { st.pop(); k--; } // 앞자리를 줄일 수 있으면 지운다
    st.push(d);
  }
  while (k-- > 0) st.pop();                 // 남은 횟수는 뒤에서 지운다 (이미 오름차순)
  const s = st.join("").replace(/^0+/, ""); // 앞의 0은 떼어 낸다
  return s === "" ? "0" : s;
}
console.log(removeKdigits("1432219", 3), removeKdigits("10200", 1), removeKdigits("10", 2), removeKdigits("12345", 2));
```

```text
1219 200 0 123
```

`"12345"`처럼 이미 오르는 입력은 반복 중에 아무것도 꺼내지 않는다. 남은 k를 뒤에서 지우는 줄이 없으면 그대로 `"12345"`가 나온다. 중복 문자 지우기(316번)도 "뒤에 같은 글자가 또 나오면 지금 지워도 된다"는 조건을 붙인 같은 모양이다.

## 자주 틀리는 곳

### 스택에 값을 넣는다

답을 "며칠 뒤"처럼 거리로 내거나 꺼낸 원소의 자리에 답을 써야 하면 인덱스가 필요하다. 값은 `a[idx]`로 언제든 읽을 수 있으니 처음부터 인덱스를 넣는 습관이 낫다.

### 등호를 아무렇게나 둔다

같은 값이 답인지 아닌지를 문제 문장에서 확인하고, 경계 두 개를 세는 문제에서는 한쪽만 등호를 넣는다. 테스트에 `[3, 3, 3]`, `[2, 2]`처럼 같은 값만 있는 입력을 꼭 넣는다.

### 끝까지 남은 원소를 잊는다

반복이 끝난 뒤 스택에 남은 원소는 답을 못 찾은 원소다. 기본값(−1이나 0)으로 미리 채워 두거나, 히스토그램처럼 보초를 넣어 꺼내지게 만든다.

### 스택 문제를 전부 단조 스택으로 본다

같은 Stack 묶음이라도 [Valid Parentheses](/posts/leetcode-valid-parentheses)는 짝 맞추기, [Min Stack](/posts/leetcode-min-stack)은 보조 스택 설계, [Generate Parentheses](/posts/leetcode-generate-parentheses)는 백트래킹이다. "처음 만나는 더 큰/작은 값"이나 "양쪽 경계"를 묻는지가 단조 스택을 고르는 기준이다.

## 면접에서 나올 만한 질문

### 단조 스택은 어떤 문제에 쓰나요?

각 원소에 대해 왼쪽이나 오른쪽에서 처음 만나는 더 큰 값, 더 작은 값을 구할 때 쓴다. 히스토그램의 최대 직사각형처럼 원소가 영향을 미치는 양쪽 경계를 구하는 문제도 결국 이 질문이다. 이중 반복문 O(n²)을 O(n)으로 줄인다.

### 왜 스택에서 꺼낸 값은 다시 볼 필요가 없나요?

꺼낸 값은 자기보다 크고 더 오른쪽에 있는 새 값에 가려졌기 때문이다. 이후 원소가 왼쪽으로 더 큰 값을 찾으면 새 값이 먼저 걸리니 꺼낸 값까지 갈 일이 없다. 그래서 스택에는 가려지지 않은 후보만 남고, 그 결과로 한 방향으로 정렬된다.

### while이 안에 있는데 시간 복잡도가 O(n)인 이유는요?

원소마다 스택에 한 번 들어가고 많아야 한 번 나오기 때문이다. while 몸통은 돌 때마다 하나를 꺼내니 전체를 통틀어 n번을 넘지 않는다. 한 반복에서 많이 돌면 그만큼 다른 반복에서 덜 도는 분할 상환 분석이다.

### 같은 값이 있을 때 비교에 등호를 넣을지는 어떻게 정하나요?

다음 큰 값을 구할 때는 문제가 "큰"인지 "크거나 같은"인지로 정한다. 부분 배열 최솟값의 합처럼 원소마다 맡는 구간 수를 셀 때는 한쪽 경계에만 등호를 넣어, 같은 최솟값이 여러 개인 구간을 한 원소만 세게 한다. 양쪽 다 빼면 덜 세고, 양쪽 다 넣으면 두 번 센다.

### Largest Rectangle in Histogram을 단조 스택으로 푸는 원리는요?

막대 하나의 높이로 만드는 가장 넓은 직사각형은 양쪽으로 처음 만나는 더 낮은 막대 사이다. 증가 스택에서 막대를 꺼낼 때 지금 들어온 막대가 오른쪽 경계, 꺼낸 뒤 스택 맨 위가 왼쪽 경계라서 넓이를 바로 잰다. 끝에 높이 0인 보초를 넣어 남은 막대도 같은 코드로 처리한다.

### 단조 스택과 단조 덱은 어떤 관계인가요?

단조 덱은 뒤쪽 동작이 단조 스택과 같고, 앞쪽에서 창 밖으로 나간 원소를 빼는 동작이 더해진 것이다. 길이 k인 창의 최댓값처럼 후보가 시간이 지나 무효가 될 때 쓴다. 넣고 빼는 횟수가 원소마다 한 번씩이라 역시 O(n)이다.

### 원형 배열에서 다음 큰 원소는 어떻게 구하나요?

인덱스를 2n까지 돌리고 i % n으로 값을 읽어 배열을 두 번 이어 붙인 것처럼 처리한다. 두 번째 바퀴에서는 새로 넣지 않고 남은 원소의 답만 채운다. 시간은 O(n), 공간은 O(n)이다.
