배달 앱에서 "같은 도로를 달리는 차량 몇 대가 사실상 한 덩어리로 도착하나"를 묻는다고 해 보자. 일차선 도로에서는 빠른 차도 앞의 느린 차를 넘지 못하니, 결국 느린 차 뒤에 줄줄이 붙어서 같이 들어온다. 차가 수만 대면 만나는 순간을 하나하나 시뮬레이션하기는 번거롭다.

[LeetCode 853. Car Fleet](https://leetcode.com/problems/car-fleet/)이 이 질문이다. 스택 묶음에 들어 있지만, 정렬이 먼저이고 스택은 그다음에 나온다. 이 글은 차마다 앞차를 다 확인하는 풀이에서 시작해 정렬과 스택, 변수 하나, 위치 버킷, 뒤에서 받는 단조 스택까지 다섯 가지를 본다. 단조 스택 자체는 [단조 스택 패턴 글](/posts/monotonic-stack-pattern)에, 정렬은 [정렬 알고리즘 글](/posts/sorting-algorithms)에 있다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 앞차를 넘을 수 없는 일차선 도로

목표 지점 `target`과 차 n대의 시작 위치 `position`, 속도 `speed`가 주어진다. 모든 차는 같은 방향으로 목표를 향해 달린다. 길이 하나뿐이라 뒤차는 앞차를 추월하지 못한다. 뒤차가 앞차를 따라잡으면 그때부터 앞차 속도로 같이 달리고, 이렇게 붙어 달리는 차들을 무리(fleet) 하나로 친다. 차 한 대만 달려도 무리 하나다. 목표 지점에서 딱 따라잡는 경우도 같은 무리로 본다. 목표에 도착하는 무리 수를 구하면 된다.

풀이 선택에 영향을 주는 제약은 이렇다.

- 차는 최대 10^5대라 O(n²)은 최악에 100억 번 가까운 비교가 된다.
- 시작 위치는 모두 다르고 0 이상 `target` 미만이다. `target`은 최대 10^6이다.
- 속도는 1 이상 10^6 이하의 정수다.

입력 배열이 위치 순서로 정렬돼 있지 않다는 점을 놓치기 쉽다. `position[0]`이 가장 앞차라는 보장이 없다.

## 손으로 그려 보기: 누가 누구를 따라잡나

이 글에서 계속 쓸 예시다. 목표는 20km 지점이고 차가 여섯 대 있다.

```text
position  6  14  0  10  2  16
speed     2   3  4   1  1   2
```

차마다 아무에게도 막히지 않고 혼자 달렸을 때 목표까지 걸리는 시간을 계산해 둔다. 남은 거리를 속도로 나누면 된다.

```text
위치   16   14   10    6    2    0
속도    2    3    1    2    1    4
시간    2    2   10    7   18    5     (20 - 위치) / 속도
```

목표에 가까운 차부터 다시 늘어놓았다. 이제 차 사이 관계를 하나씩 본다.

- 16km 차는 맨 앞이라 막을 차가 없다. 2시간 만에 도착한다.
- 14km 차도 혼자라면 2시간이 걸린다. 앞차와 같은 시간에 목표에 닿으니 목표에서 딱 따라잡는다. 같은 무리다.
- 10km 차는 10시간 걸린다. 앞 무리(2시간)보다 늦으니 절대 따라잡지 못한다. 새 무리다.
- 6km 차는 혼자라면 7시간이다. 10km 차보다 먼저 닿을 만큼 빠르니 도중에 따라잡는다. 실제로 4시간 뒤 14km 지점에서 만나고, 그 뒤로는 시속 1km로 같이 간다. 10km 차의 무리에 들어간다.
- 2km 차는 18시간 걸린다. 앞 무리의 10시간보다 늦으니 새 무리다.
- 0km 차는 5시간짜리 빠른 차지만 앞의 2km 차에 막힌다. 그 무리에 들어간다.

그림에서 규칙이 보인다. 어떤 차의 오른쪽(더 앞)에 그 차보다 위에 있는(더 늦게 닿는) 점이 하나라도 있으면, 그 차는 결국 막혀서 누군가의 무리에 들어간다. 오른쪽에 자기보다 위인 점이 하나도 없는 차만 무리의 맨 앞, 무리장이 된다. 16km, 10km, 2km 차가 그렇다.

## 차마다 앞의 모든 차를 확인하기

관찰을 그대로 코드로 옮긴다. 차 `i`마다 다른 모든 차를 보고, 나보다 앞에 있으면서 나보다 늦거나 같은 시간에 닿는 차가 있으면 `i`는 무리장이 아니다. 무리장의 수가 곧 무리 수다.

```js
function carFleet(target, position, speed) {
  const n = position.length;
  let fleets = 0;
  for (let i = 0; i < n; i++) {
    const ti = (target - position[i]) / speed[i]; // 혼자 달렸을 때 걸리는 시간
    let blocked = false;
    for (let j = 0; j < n; j++) {
      // 나보다 앞에 있는데 나보다 늦게(또는 같이) 닿는 차가 있으면 결국 막힌다
      if (position[j] > position[i] && (target - position[j]) / speed[j] >= ti) {
        blocked = true;
        break;
      }
    }
    if (!blocked) fleets++; // 아무도 막지 않으면 무리장
  }
  return fleets;
}
```

정렬도 필요 없고 공간은 O(1)이다. 시간은 O(n²)이다. 예시에서는 3이 나온다.

왜 맞는지 한 번 짚고 간다. 내 앞에 나보다 늦게 닿는 차 `j`가 있다고 하자. 나는 `j`보다 뒤에서 출발했는데 혼자라면 `j`보다 먼저 목표에 닿을 수 있다. 추월이 안 되니 목표 전(또는 목표에서) 반드시 `j`를 따라잡거나, 그 전에 `j`보다 더 앞의 누군가에게 막힌다. 어느 쪽이든 나는 무리장이 아니다. 반대로 앞의 모든 차가 나보다 일찍 닿는다면, 앞차들이 무리로 묶여 느려져도 그 무리는 가장 느린 차의 시간, 곧 나보다 이른 시간에 닿는다. 나는 아무도 따라잡지 못한다.

무작위 입력에서는 금방 막는 차를 찾고 `break`해서 빠르다. 나쁜 입력은 모든 차가 무리장인 경우다. 속도가 전부 같으면 아무도 서로를 따라잡지 못하니 안쪽 반복문이 매번 끝까지 돈다. 차 10^4대로 재 보니 178ms였고, n이 10배면 시간은 100배가 된다. 10^5대에서는 시간 초과다.

이 풀이가 느린 건 차마다 "앞에 있는 차"를 처음부터 다시 찾기 때문이다. 차를 위치 순으로 늘어놓으면 "앞에 있는 차"가 한쪽에 모인다.

## 목표에 가까운 차부터 보면 바로 앞 무리만 알면 된다

차를 위치가 큰 순서, 곧 목표에 가까운 순서로 정렬한다. 그러면 지금 보는 차의 앞차들은 모두 이미 본 차다. 그리고 이미 본 차들은 무리로 묶여 있다. 지금 차를 막을 수 있는 건 바로 앞 무리 하나뿐이다.

- 바로 앞 무리가 목표에 닿는 시간을 `T`라고 하자. 무리는 무리장의 속도로 달리니 `T`는 무리장의 시간이다.
- 지금 차의 시간 `t`가 `T` 이하이면, 혼자라면 앞 무리보다 먼저 닿을 차라서 도중에 따라잡힌다. 그 무리에 들어간다.
- `t`가 `T`보다 크면 앞 무리를 따라잡지 못한다. 새 무리를 만든다. 이제부터 바로 앞 무리는 이 무리다.

무리마다 도착 시간을 스택에 쌓는다. 새 차의 시간을 일단 넣어 보고, 그 시간이 바로 아래(앞 무리) 이하이면 앞 무리에 합쳐진 것이니 다시 뺀다. 끝나면 스택에 남은 칸 수가 무리 수다.

아래 그림의 칸은 위치 순으로 정렬한 차들이고, 칸 글자는 `위치:시간`이다. 기억 장소에 무리마다의 도착 시간이 쌓인다.

```js
function carFleet(target, position, speed) {
  // [위치, 혼자 달렸을 때 걸리는 시간]을 목표에 가까운 순으로
  const cars = position.map((p, i) => [p, (target - p) / speed[i]]);
  cars.sort((a, b) => b[0] - a[0]);

  const stack = []; // 무리마다 목표에 닿는 시간. 맨 위가 바로 앞 무리
  for (const [, t] of cars) {
    stack.push(t);
    // 앞 무리보다 일찍(또는 같이) 닿을 차라면 따라잡혀 앞 무리에 합쳐진다
    if (stack.length >= 2 && stack[stack.length - 1] <= stack[stack.length - 2]) {
      stack.pop();
    }
  }
  return stack.length;
}
```

정렬이 O(n log n), 그 뒤 반복은 O(n)이라 전체 O(n log n)이다. 공간은 차 배열과 스택 O(n)이다.

### 만나는 지점을 계산하지 않아도 되는 이유

6km 차가 10km 차를 언제 어디서 따라잡는지(4시간 뒤 14km 지점) 몰라도 답은 같다. 묻는 게 "목표에 무리가 몇 개 들어오나"뿐이라서다. 따라잡은 뒤 6km 차는 앞차 속도로 달리니 도착 시간도 앞 무리와 같아진다. 그래서 무리마다 기억할 값은 무리장의 도착 시간 하나다. 합쳐진 차는 그 시간을 바꾸지 못한다. 무리 안에서 가장 느린 차가 맨 앞에 있고, 뒤차들은 그보다 빨라서 붙었기 때문이다.

"목표에서 딱 만나는 것도 같은 무리"라는 조건이 비교의 등호를 정한다. 14km 차와 16km 차는 둘 다 2시간이라 목표에서 만난다. 이걸 같은 무리로 치려면 합치는 조건이 `<=`여야 한다. 반대로 목표를 지난 뒤에 따라잡는 차는 무리가 아니다. 그런 차는 혼자 시간이 앞 무리보다 크니 자연스럽게 새 무리가 된다.

### 시간을 실수로 비교해도 괜찮나

시간은 `(target - p) / speed`라는 분수다. 부동소수점으로 계산하면 오차가 생기지 않을까 걱정할 수 있다. 두 경우로 나눠 본다.

- 두 시간이 분수로 정확히 같다면, 컴퓨터는 같은 실수를 같은 규칙으로 반올림하므로 결과 두 개도 정확히 같다. 등호 비교가 깨지지 않는다.
- 두 시간이 다르다면 그 차이는 분모 곱의 역수 이상이다. 이 문제 범위(거리와 속도가 10^6 이하)에서는 상대 차이가 10^-12보다 크고, 배정밀도 실수의 상대 오차 약 2.2 × 10^-16보다 훨씬 크다. 다른 시간이 같은 실수로 뭉개지지 않는다.

그래도 불안하면 나눗셈을 곱셈으로 바꿔 정수로 비교한다. `t1 <= t2`는 `(target - p1) * s2 <= (target - p2) * s1`과 같다. 곱은 최대 10^12라 JavaScript의 안전한 정수 범위 안이지만 Java에서는 `int`(약 2.1 × 10^9)를 넘으니 `long`으로 계산해야 한다.

아래는 바로 앞 무리장의 남은 거리와 속도를 분수 그대로 들고 다니는 Java 코드다. 뒤에서 볼 변수 하나 풀이를 정수 비교로 바꾼 것이다.

```java
import java.util.*;

class Solution {
    public int carFleet(int target, int[] position, int[] speed) {
        int n = position.length;
        Integer[] idx = new Integer[n];
        for (int i = 0; i < n; i++) idx[i] = i;
        Arrays.sort(idx, (a, b) -> Integer.compare(position[b], position[a]));
        int fleets = 0;
        long dist = 0, spd = 1; // 바로 앞 무리장의 남은 거리와 속도. 처음엔 시간 0 = 0/1
        for (int i : idx) {
            long d = target - position[i], s = speed[i];
            if (d * spd > dist * s) { // d/s > dist/spd 를 곱셈으로. 곱은 최대 10^12라 long
                fleets++;
                dist = d;
                spd = s;
            }
        }
        return fleets;
    }
}
```

예시에서 3, 위치 `[12, 11]`·속도 `[2, 2]`에서 2가 나온다. `d`와 `s`를 `int`로 두면 `999999 * 1000000`이 `-728379968`로 넘쳐 비교가 뒤집힌다. 그래서 곱하기 전에 `long`으로 올려 둔다.

## 스택 대신 변수 하나

스택 풀이를 다시 보면 맨 위 칸만 쓴다. 바로 아래 칸과 비교하는 순간에도 비교 대상은 직전 무리, 곧 맨 위다. 그러니 스택을 들고 갈 필요 없이 "바로 앞 무리의 도착 시간" 하나와 무리 수만 세면 된다.

```js
function carFleet(target, position, speed) {
  const order = position.map((_, i) => i).sort((a, b) => position[b] - position[a]);
  let fleets = 0;
  let slowest = 0; // 바로 앞 무리가 목표에 닿는 시간
  for (const i of order) {
    const t = (target - position[i]) / speed[i];
    if (t > slowest) { // 앞 무리보다 늦게 닿는다 → 따라잡지 못한다 → 새 무리
      fleets++;
      slowest = t;
    }
  }
  return fleets;
}
```

`slowest`가 늘 커지기만 한다는 점이 보인다. 새 무리가 생길 때마다 더 큰 시간으로 바뀐다. 그래서 이 풀이를 한 문장으로 하면 "목표에 가까운 차부터 보며 지금까지의 최대 시간을 갱신한 횟수"다. 처음 그림에서 "오른쪽에 자기보다 위인 점이 없는 차"를 센 것과 같은 말이다.

시간은 정렬 때문에 여전히 O(n log n)이고, 추가 공간은 정렬할 인덱스 배열 O(n)이다. 스택이 없어진 만큼 가볍다. 차 10^5대에서 스택 풀이가 139ms, 이 풀이가 58ms였다. 차이의 대부분은 `[위치, 시간]` 쌍 배열을 만들고 정렬하는 비용이다.

### 정렬보다 빨라질 수 있나

변수 하나 풀이를 차 10^5대로 나눠 재 보면 정렬이 42~59ms, 정렬 뒤 반복문이 4~10ms였다. 시간 대부분이 정렬이다. 그러면 비교만 쓰면서 정렬을 피할 수 있을까.

처음 그림을 다시 보면 무리장은 "오른쪽에 자기보다 위인 점이 없는 점"이었다. 2차원 점들 가운데 다른 어떤 점에도 두 좌표가 모두 밀리지 않는 점을 찾는 문제를 최대점(maxima) 문제라고 하는데, 무리장은 위치와 도착 시간 두 좌표에 대한 최대점이다. 비교만 쓰는 방식으로 최대점들을 찾는 데는 O(n log n)이 하한으로 알려져 있다. 그래서 일반적인 입력에서는 정렬 수준의 비용을 피하기 어렵고, 피하려면 다음 절처럼 "위치가 작은 정수"라는 추가 조건을 써야 한다.

### 세 언어로 쓰면 달라지는 곳

Python은 `zip`으로 위치와 속도를 묶어 `sorted(..., reverse=True)`로 정렬한다. 튜플은 첫 원소인 위치로 비교되고, 위치가 모두 다르니 두 번째 원소까지 볼 일이 없다. Python 3의 `/`는 늘 실수 나눗셈이다.

```python
from typing import List

def car_fleet(target: int, position: List[int], speed: List[int]) -> int:
    cars = sorted(zip(position, speed), reverse=True)  # 목표에 가까운 차부터
    fleets = 0
    slowest = 0.0  # 바로 앞 무리가 목표에 닿는 시간
    for p, s in cars:
        t = (target - p) / s
        if t > slowest:  # 앞 무리보다 늦게 닿는다 → 따라잡지 못한다 → 새 무리
            fleets += 1
            slowest = t
    return fleets
```

Java는 원시 `int[]`를 비교자로 정렬할 수 없어서 `Integer[]` 인덱스 배열을 정렬하거나 `int[][]`로 묶는다. 비교자의 `position[b] - position[a]`는 위치가 0 이상 10^6 미만이라 넘치지 않는다. 범위가 더 넓다면 `Integer.compare`를 쓴다.

```java
import java.util.*;

class Solution {
    public int carFleet(int target, int[] position, int[] speed) {
        int n = position.length;
        Integer[] idx = new Integer[n];
        for (int i = 0; i < n; i++) idx[i] = i;
        Arrays.sort(idx, (a, b) -> position[b] - position[a]); // 목표에 가까운 차부터
        int fleets = 0;
        double slowest = 0;  // 바로 앞 무리가 목표에 닿는 시간
        for (int i : idx) {
            double t = (double) (target - position[i]) / speed[i]; // int끼리 나누면 소수점이 사라진다
            if (t > slowest) {
                fleets++;
                slowest = t;
            }
        }
        return fleets;
    }
}
```

Java에서 가장 위험한 줄은 시간 계산이다. `(double)` 없이 `(target - position[i]) / speed[i]`라고 쓰면 정수 나눗셈이 먼저 일어나고 그 결과가 `double`에 담긴다. 목표 20, 위치 `[12, 11]`, 속도 `[2, 2]`를 넣어 보면, 두 차는 속도가 같아 영원히 만나지 않으니 정답은 2인데 이 버그가 있는 코드는 1을 냈다. 4시간과 4.5시간이 둘 다 4가 되어 같은 무리로 묶였다. 세 언어 모두 예시에서 3이 나온다.

## 위치가 좁은 범위의 정수라면 정렬도 필요 없다

정렬은 위치 순서를 알려고 했다. 그런데 위치는 0 이상 `target` 미만의 정수이고 서로 다르다. 그러면 길이 `target`인 배열을 만들고 위치를 칸 번호로 써서 시간을 적어 두면, 칸 번호 순서가 곧 위치 순서다. 계수 정렬과 같은 생각이다.

```js
function carFleet(target, position, speed) {
  const time = new Array(target).fill(-1); // time[p] = p에서 출발한 차의 시간, 차가 없으면 -1
  for (let i = 0; i < position.length; i++) {
    time[position[i]] = (target - position[i]) / speed[i];
  }
  let fleets = 0;
  let slowest = 0;
  for (let p = target - 1; p >= 0; p--) { // 목표에 가까운 칸부터
    if (time[p] > slowest) { // 빈 칸(-1)은 저절로 건너뛴다
      fleets++;
      slowest = time[p];
    }
  }
  return fleets;
}
```

시간은 O(n + target), 공간은 O(target)이다. 빈 칸을 -1로 채워 두면 `-1 > slowest`가 항상 거짓이라 따로 검사하지 않아도 된다. 차 10^5대, `target` 10^6에서 14ms로 다섯 풀이 중 가장 빨랐다.

대신 `target`이 크면 쓸 수 없다. 차가 10대뿐인데 `target`이 10^9이면 10억 칸 배열을 만들게 된다. 위치가 정수가 아니어도 안 된다. 면접에서는 "제약이 `target` 10^6이라 가능하다"는 조건을 말하고 꺼낸다.

## 뒤에서 들어오는 차를 받는 단조 스택

지금까지는 목표에 가까운 차부터 봤다. 반대로 목표에서 먼 차, 곧 맨 뒤 차부터 보는 방법도 있다. 이번에는 스택에 "아직 앞차를 만나지 않은 무리들"을 쌓는다. 새로 보는 차는 지금까지 본 모든 차보다 앞에 있다. 그러면 스택에 있던 무리 중 새 차보다 일찍(또는 같이) 닿는 무리는 새 차를 따라잡아 새 차의 무리에 들어간다. 그 무리들을 꺼내고 새 차를 넣는다.

```js
function carFleet(target, position, speed) {
  const order = position.map((_, i) => i).sort((a, b) => position[a] - position[b]); // 먼 차부터
  const stack = []; // 무리마다 도착 시간. 바닥이 가장 뒤 무리
  for (const i of order) {
    const t = (target - position[i]) / speed[i];
    // 뒤에 있으면서 나보다 일찍 닿는 무리는 나를 따라잡아 내 무리가 된다
    while (stack.length && stack[stack.length - 1] <= t) stack.pop();
    stack.push(t);
  }
  return stack.length;
}
```

## 같은 시간, 정렬, 비교 대상에서 틀리는 코드

### 바로 앞차와만 비교한다

```js
let fleets = 0, prev = 0;
for (const [, t] of cars) {
  if (t > prev) fleets++;
  prev = t; // 틀림: 합쳐진 차의 시간으로 바꿔 버린다
}
```

목표 20, 위치 `[10, 6, 4]`, 속도 `[1, 2, 2]`에서 시간은 앞에서부터 10, 7, 8이다. 6km 차(7시간)는 10km 차에 붙어 무리 시간은 그대로 10이다. 4km 차(8시간)도 10 이하라 같은 무리이고 정답은 1이다. 그런데 이 코드는 `prev`를 7로 바꿔 버려서 8 > 7로 새 무리를 세고 2를 냈다. 비교할 대상은 직전 차가 아니라 직전 무리의 시간, 곧 무리장의 시간이다. 합쳐진 차는 그 값을 바꾸지 않는다.

### 같은 시간을 다른 무리로 센다

합치는 조건을 `<`로, 곧 새 무리 조건을 `t >= slowest`로 쓰면 목표에서 딱 만나는 차를 따로 센다. 예시의 14km 차가 16km 차와 같은 2시간이라 따로 세어져 3이 아니라 4가 나온다. 뒤에서 오는 단조 스택에서 `while`의 조건을 `<`로 바꿔도 같은 이유로 4가 나왔다. 문제의 "목표에서 따라잡아도 같은 무리"가 등호다.

### 기본 정렬을 쓴다

```js
cars.sort().reverse(); // 틀림: 배열을 문자열로 바꿔 사전 순으로 정렬한다
```

JavaScript의 `sort()`는 비교 함수가 없으면 원소를 문자열로 바꿔 비교한다. `[6, 7]`은 `"6,7"`, `[16, 2]`는 `"16,2"`가 되어 `"6,7"`이 `"16,2"`보다 뒤로 간다. 예시에 돌리면 정렬 결과가 `[6,7], [2,18], [16,2], [14,2], [10,10], [0,5]`로 엉키고 답이 2가 나왔다. 숫자 배열 `[10, 8, 0, 5, 3, 16, 2].sort()`도 `[0, 10, 16, 2, 3, 5, 8]`이 된다. 숫자는 늘 `(a, b) => a - b` 같은 비교 함수를 준다.

### 위치만 정렬하고 속도를 따로 둔다

`position.sort(...)`로 위치 배열만 정렬하면 `speed[i]`가 더는 같은 차의 속도가 아니다. 위치와 속도를 쌍으로 묶어 정렬하거나, 인덱스 배열을 정렬해서 두 배열을 같은 인덱스로 읽는다.

### 속도 차이로 만나는 지점을 계산하려 한다

"뒤차가 앞차보다 빠르면 `(앞 위치 - 뒤 위치) / (뒤 속도 - 앞 속도)` 뒤에 만난다"를 계산하기 시작하면, 속도가 같을 때 0으로 나누기, 목표를 지난 뒤에 만나는 경우, 앞차가 이미 다른 무리에 막혀 느려진 경우를 전부 따로 다뤄야 한다. 도착 시간 하나로 비교하면 이 경우들이 전부 저절로 처리된다. 속도가 같으면 뒤차의 시간이 더 크고, 목표를 지나 만나는 경우도 시간이 더 크고, 막힌 앞차의 무리는 무리장의 시간으로 비교되기 때문이다.

## 도로 조건을 바꿔 묻는 꼬리 질문

### 차마다 앞차를 따라잡는 시각을 구하라면

LeetCode 1776 Car Fleet II다. 목표 없이, 차마다 바로 앞차(또는 앞 무리)와 처음 부딪히는 시각을 구한다. 이번에는 정말 만나는 시점이 필요하다. 뒤에서부터 보면서 스택에 앞차 후보를 두고, 후보가 나보다 빠르거나 내가 따라잡기 전에 후보가 이미 그 앞 무리에 합쳐져 버리면 후보를 꺼낸다. 남은 맨 위가 내가 처음 부딪히는 차다. 차마다 한 번 들어가고 한 번 빠지는 단조 스택이라 O(n)이다. 1번 문제의 "도착 시간만 비교" 관찰이 통하지 않는 이유를 설명할 수 있으면 좋다.

### 시각 T에 길 위에 무리가 몇 개인지 묻는다면

목표에 도착한 뒤가 아니라 중간 시각 `T`의 상태를 묻는다면 도착 시간 대신 위치를 비교한다. 차마다 "막히지 않았다면 시각 `T`에 있을 위치" `p + s·T`를 구한다. 목표에 가까운 차부터 보면서, 이 값이 바로 앞 무리장의 위치보다 작으면 아직 따라잡지 못한 것이니 따로 달리는 무리장이고, 크거나 같으면 이미 붙었다.

```js
function fleetsOnRoad(target, position, speed, T) {
  const order = position.map((_, i) => i).sort((a, b) => position[b] - position[a]);
  let fleets = 0;
  let front = Infinity; // 바로 앞 무리의 무리장이 시각 T에 있을 위치
  for (const i of order) {
    const free = position[i] + speed[i] * T; // 막히지 않았다면 있을 위치
    if (free < front) {            // 앞 무리에 아직 닿지 못했다 → 따로 달리는 무리장
      front = free;
      if (free < target) fleets++; // 목표에 닿은 무리는 길 위에 없다
    }
  }
  return fleets;
}
// 예시에서 T = 0, 1, 2, 4, 10, 18 → 6 5 3 2 1 0
```

시각 1에는 0km 차가 이미 2km 차를 따라잡아 5개, 시각 4에는 6km 차가 10km 차에 붙어 2개다. 시각 10에 10km 무리가 목표에 들어가 1개가 남는다. 이 글의 변수 하나 풀이에서 "시간이 크면 새 무리"가 "위치가 작으면 새 무리"로 바뀌었을 뿐 모양이 같다.

### 무리마다 차가 몇 대인지도 알려 달라면

스택 풀이에서 무리마다 `[도착 시간, 차 수]`를 쌓고, 합쳐질 때 맨 위 칸의 차 수를 하나 늘린다.

```js
function fleetSizes(target, position, speed) {
  const order = position.map((_, i) => i).sort((a, b) => position[b] - position[a]);
  const stack = []; // [도착 시간, 차 수]
  for (const i of order) {
    const t = (target - position[i]) / speed[i];
    if (stack.length && t <= stack[stack.length - 1][0]) stack[stack.length - 1][1]++; // 앞 무리에 합쳐진다
    else stack.push([t, 1]);
  }
  return stack;
}
// 예시 → [[2, 2], [10, 2], [18, 2]]
```

예시에서는 무리마다 두 대씩이다. 이번에는 스택의 칸이 단순한 시간이 아니라 무리 정보를 들고 있어서, 변수 하나로 줄이는 것보다 스택이 더 자연스럽다.

### 위치가 같은 차가 있을 수 있다면

원래 문제는 위치가 모두 다르다고 보장한다. 같은 위치에서 출발한 차는 출발과 동시에 붙은 것이니 그중 느린 차의 속도로 같이 달린다. 정렬할 때 위치가 같으면 시간이 큰(느린) 차가 먼저 오도록 두 번째 기준을 주면, 빠른 차가 그 뒤에서 합쳐진다. 위치 버킷 풀이라면 칸마다 시간의 최댓값을 적는다.

## 도착 시간 하나로 줄인 문제

차가 언제 어디서 만나는지 계산하지 않아도 된다. 차마다 혼자 달렸을 때 목표까지 걸리는 시간을 구하고, 목표에 가까운 차부터 보면서 바로 앞 무리보다 늦게 닿는 차만 새 무리로 센다. 앞 무리보다 일찍 닿을 차는 결국 막혀 그 무리에 들어간다. 정렬 O(n log n)이 대부분이고, 스택의 맨 위만 쓰니 변수 하나로 줄어든다. 목표에서 딱 만나는 경우를 같은 무리로 치는 등호와, 숫자 정렬의 비교 함수만 조심하면 된다.

## 면접에서 나올 만한 질문

### 왜 위치로 정렬하나요?

추월이 안 되니 어떤 차를 막을 수 있는 건 그 차보다 앞에 있는 차들뿐이다. 목표에 가까운 순으로 정렬하면 지금 차를 볼 때 앞차들은 이미 무리로 묶여 있고, 바로 앞 무리 하나와만 비교하면 된다. 정렬하지 않으면 차마다 앞차를 다시 찾아야 해서 O(n²)이 된다.

### 차들이 만나는 시점을 계산하지 않아도 되는 이유는요?

묻는 것이 목표에 들어오는 무리 수뿐이기 때문이다. 따라잡은 차는 그 뒤로 앞 무리 속도로 달려 도착 시간이 앞 무리와 같아지니, 무리는 무리장의 도착 시간 하나로 대표된다. 혼자 달렸을 때 앞 무리보다 일찍 닿을 차라면 목표 전이나 목표에서 반드시 따라잡는다.

### 스택이 꼭 필요한가요?

아니다. 스택 풀이는 맨 위, 곧 바로 앞 무리의 시간만 비교에 쓴다. 그래서 그 시간 하나와 무리 수만 들고 가도 같다. 이 값은 새 무리가 생길 때마다 커지기만 해서, 목표에 가까운 차부터 보며 최대 시간을 갱신한 횟수가 답이 된다.

### 도착 시간을 실수로 비교해도 안전한가요?

이 문제 범위에서는 안전하다. 같은 분수는 같은 실수로 반올림되니 같음 비교가 유지되고, 서로 다른 분수의 상대 차이는 10^-12 이상이라 배정밀도 오차보다 훨씬 크다. 그래도 정확히 하려면 `(target - p1) * s2`와 `(target - p2) * s1`을 정수로 비교하는데, 곱이 10^12까지 가니 Java에서는 `long`을 쓴다.

### 정렬을 피할 수 있나요?

위치가 0 이상 `target` 미만의 서로 다른 정수이고 `target`이 10^6 정도로 작으니, 위치를 칸 번호로 하는 배열에 시간을 적으면 칸 순서가 곧 위치 순서다. O(n + target)이 되고 실제로 가장 빨랐다. 하지만 `target`이 크거나 위치가 실수라면 쓸 수 없다.

### 이 문제가 왜 스택 문제로 분류되나요?

뒤 차부터 보면 단조 스택 문제가 된다. 새로 본 앞차보다 일찍 닿는 뒤 무리들을 스택에서 꺼내 그 차의 무리로 합치고, 남은 스택은 뒤로 갈수록 늦게 닿는 순서를 유지한다. Daily Temperatures와 같은 모양이고, 앞쪽에 차가 계속 추가되는 변형에 그대로 쓸 수 있다.

### 바로 앞차의 시간과 비교하면 왜 틀리나요?

합쳐진 차는 무리의 도착 시간을 바꾸지 않기 때문이다. 시간이 10, 7, 8인 세 차에서 7시간 차는 10시간 무리에 붙지만 무리 시간은 그대로 10이다. 8시간 차를 직전 차의 7과 비교하면 새 무리로 잘못 세고, 무리의 10과 비교해야 같은 무리가 된다.
