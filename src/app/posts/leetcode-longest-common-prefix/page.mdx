로그 파일 경로 수백 개를 받아서 공통 디렉터리를 찾아야 할 때가 있다. 터미널 자동완성도 비슷한 일을 한다. `inter`까지 치고 탭을 누르면, 후보가 `interview`, `internet`, `interval`이라 더 채울 수 있는 글자가 없어서 거기서 멈춘다. 후보들의 가장 긴 공통 접두사(앞부분)까지만 채우는 것이다.

[LeetCode 14. Longest Common Prefix](https://leetcode.com/problems/longest-common-prefix/)가 이 계산이다. Easy 문제라서 풀이 하나는 금방 나오지만, 풀이 방법이 유난히 많아서 면접관이 "다른 방법은요?"를 계속 묻기 좋은 문제다. 트라이 패턴에 들어 있지만 트라이가 가장 좋은 답은 아니다. 이 글은 가로로 줄이기, 세로로 훑기, 분할 정복, 길이 이진 탐색, 정렬, 최솟값·최댓값만 보기, 트라이까지 일곱 가지를 보고, 트라이가 언제 제값을 하는지 따져 본다. 트라이 자체는 [Implement Trie](/posts/leetcode-implement-trie)에서 만들었다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 모두가 함께 가진 앞부분

문자열 배열 `strs`가 주어진다. 모든 문자열의 앞부분으로 공통인 가장 긴 문자열을 돌려준다. 없으면 빈 문자열이다.

- 문자열은 1개 이상 200개 이하, 길이는 0 이상 200 이하, 모두 소문자.

입력이 작아서 어떤 풀이든 통과한다. 그래서 이 문제는 "통과하느냐"보다 "얼마나 일찍 멈추느냐", "빈 문자열과 짧은 문자열을 안전하게 다루느냐"를 본다. 길이가 0인 문자열이 들어올 수 있다는 조건을 놓치면 바로 틀린다.

이 글에서 쓸 예시다.

```text
strs = [interview, internet, interval, internal]
답   = inter
```

세로로 나란히 놓고 보면 금방 보인다.

```text
interview
internet
interval
internal
^^^^^
```

다섯째 글자 `r`까지는 넷이 같고, 여섯째 글자에서 `v`, `n`, `v`, `n`으로 갈린다. 그래서 답은 `inter`다. 다른 예로 `[apple, banana]`는 첫 글자부터 달라서 빈 문자열, `[ab, a]`는 `a`가 한 글자에서 끝나서 `a`다.

공통 접두사는 줄어들기만 한다는 성질이 있다. 문자열 하나를 더 볼 때마다 공통 접두사는 그대로이거나 짧아질 뿐 길어지지 않는다. 그리고 답은 가장 짧은 문자열보다 길 수 없다. 아래 풀이들은 모두 이 두 가지를 다른 방식으로 쓴다.

## 하나씩 비교하며 줄여 나가기

첫 문자열을 일단 답이라고 놓고, 나머지 문자열을 하나씩 보면서 맞지 않으면 끝 글자를 하나씩 떼어 낸다. 공통 접두사는 줄어들기만 하니, 문자열 하나와 맞춰 줄인 결과를 다음 문자열에 이어서 쓰면 된다.

```js
function longestCommonPrefix(strs) {
  let prefix = strs[0];                  // 일단 첫 문자열 전체가 답이라고 본다
  for (let i = 1; i < strs.length; i++) {
    while (!strs[i].startsWith(prefix)) {
      prefix = prefix.slice(0, -1);      // 맞을 때까지 끝 글자를 뗀다
    }
    if (prefix === "") return "";        // 더 줄일 게 없다
  }
  return prefix;
}
```

예시라면 `interview`에서 시작해 `internet`과 맞추느라 `interview` → `intervie` → ... → `inter`로 넷을 뗀다. `interval`, `internal`은 이미 `inter`로 시작하니 그대로 통과한다.

첫 문자열 길이를 m, 문자열 수를 n이라 하자. 문자열마다 `startsWith`를 적어도 한 번 부르고 한 번에 최대 m글자를 비교하니 O(n · m), 끝 글자를 떼는 일은 전체를 통틀어 m번을 넘지 않고 그때마다 `startsWith`를 한 번 더 부르니 O(m²)이 더해진다. 공간은 `slice`가 새 문자열을 만드니 O(m)이다.

동작은 맞지만 낭비가 있다. 첫 문자열이 아주 길고 공통 접두사가 짧으면, 첫 번째 비교에서 끝 글자를 하나씩 수십 번 떼면서 그때마다 처음부터 다시 비교한다. 줄일 때 한 글자씩이 아니라 "어디서 처음 달라지는지"를 바로 찾으면 더 낫다. 그 생각이 다음 풀이로 이어진다.

## 세로로 한 칸씩 훑는다

가로로 문자열 하나씩 보는 대신 세로로 글자 위치 하나씩 본다. 위치 0에서 모든 문자열의 글자가 같은지 보고, 같으면 위치 1로 간다. 어떤 문자열이 그 위치에서 끝났거나 글자가 다르면 거기서 멈춘다. 멈춘 위치 직전까지가 답이다.

```js
function longestCommonPrefix(strs) {
  const first = strs[0];
  for (let j = 0; j < first.length; j++) {   // 글자 위치 j
    const ch = first[j];
    for (let i = 1; i < strs.length; i++) {  // 문자열 i
      // 이 문자열이 여기서 끝났거나, 글자가 다르면 멈춘다
      if (j === strs[i].length || strs[i][j] !== ch) return first.slice(0, j);
    }
  }
  return first; // 첫 문자열 전체가 공통이다
}
```

아래 그림에서 다음을 누르면 `interview`의 글자를 한 칸씩 보며 나머지 세 문자열의 같은 위치를 확인한다.

마지막 칸이 이 풀이의 장점이다. 다른 글자를 하나라도 만나면 그 위치의 나머지 문자열도, 그 뒤의 위치도 보지 않는다. 비교 횟수는 많아야 n · (답 길이 + 1)이다. 최악은 모든 문자열이 같을 때로, 이때는 글자 전부를 보니 O(S)다. S는 모든 문자열 길이의 합이다. 추가 공간은 답을 잘라 낼 때 말고는 O(1)이다.

`j === strs[i].length` 검사가 글자 비교보다 앞에 있어야 한다. JS에서는 범위를 넘은 `strs[i][j]`가 `undefined`라 비교가 그냥 다르다고 나와서 순서를 바꿔도 우연히 맞지만, Java의 `charAt`은 예외를 던진다. 의도를 분명히 하려고 길이부터 본다.

이 풀이가 이 문제의 기본 답이다. 짧고, 가장 일찍 멈추고, 추가 메모리가 없다.

### Python과 Java로 쓰면

Python으로 그대로 옮기면 이렇다. `zip(*strs)`를 쓰면 세로 줄을 바로 얻을 수 있어서 한 번 더 짧아진다.

```python
import os
from typing import List


def longest_common_prefix(strs: List[str]) -> str:
    first = strs[0]
    for j, ch in enumerate(first):
        for s in strs[1:]:
            if j == len(s) or s[j] != ch:  # 짧은 문자열이 먼저 끝나거나 글자가 다르다
                return first[:j]
    return first


def lcp_zip(strs: List[str]) -> str:
    out = []
    for column in zip(*strs):  # 가장 짧은 문자열 길이만큼 세로 줄을 만든다
        if len(set(column)) != 1:
            break
        out.append(column[0])
    return "".join(out)


words = ["interview", "internet", "interval", "internal"]
print(longest_common_prefix(words), lcp_zip(words), os.path.commonprefix(words))
print(repr(longest_common_prefix(["ab", "a"])), repr(lcp_zip([""])), repr(os.path.commonprefix(["apple", "banana"])))
print(os.path.commonprefix(["/usr/lib", "/usr/local"]))
```

```text
inter inter inter
'a' '' ''
/usr/l
```

`zip`은 가장 짧은 입력이 끝나면 멈추니 길이 검사가 따로 필요 없다. `strs[1:]`는 리스트를 복사하므로 바깥 루프마다 복사가 일어난다. 문자열이 200개라 상관없지만 아주 많다면 인덱스로 돈다.

표준 라이브러리에 `os.path.commonprefix`가 이미 있다. 이름과 달리 경로가 아니라 글자 단위로 비교해서, 셋째 줄처럼 `/usr/lib`와 `/usr/local`의 답이 `/usr/l`이 된다. 경로의 공통 디렉터리를 원하면 Python 3.5부터 있는 `os.path.commonpath`를 쓴다(답은 `/usr`). 코딩 테스트에서 이 함수를 쓰면 면접관이 직접 짜 보라고 할 가능성이 크니, 있다는 것만 알아 둔다.

Java도 세로 훑기가 가장 깔끔하다.

```java
class Solution {
    public String longestCommonPrefix(String[] strs) {
        String first = strs[0];
        for (int j = 0; j < first.length(); j++) {
            char ch = first.charAt(j);
            for (int i = 1; i < strs.length; i++) {
                // 길이 검사가 먼저다. 순서를 바꾸면 charAt에서 예외가 난다
                if (j == strs[i].length() || strs[i].charAt(j) != ch) {
                    return first.substring(0, j);
                }
            }
        }
        return first;
    }
}
```

```text
inter
[a]
[]
```

세 줄은 각각 예시, `[ab, a]`, `[apple, banana]`의 결과다. 문제 조건상 배열이 비어 있을 수는 없지만, 실무 코드라면 `strs.length == 0`일 때 `""`를 돌려주는 줄을 맨 앞에 둔다. 없으면 `strs[0]`에서 `ArrayIndexOutOfBoundsException`이 난다.

## 반으로 나눠 합치기

공통 접두사는 묶는 순서와 상관없다. 앞 절반의 공통 접두사와 뒤 절반의 공통 접두사를 구한 뒤, 그 둘의 공통 접두사를 구해도 답이 같다. 그러면 분할 정복(문제를 반으로 나눠 각각 풀고 합치는 방법)으로 짤 수 있다.

```js
function longestCommonPrefix(strs) {
  const two = (a, b) => {               // 두 문자열의 공통 접두사
    let j = 0;
    while (j < a.length && j < b.length && a[j] === b[j]) j++;
    return a.slice(0, j);
  };
  const go = (lo, hi) => {              // strs[lo..hi]의 공통 접두사
    if (lo === hi) return strs[lo];
    const mid = (lo + hi) >> 1;
    return two(go(lo, mid), go(mid + 1, hi));
  };
  return go(0, strs.length - 1);
}
```

예시라면 `[interview, internet]`이 `inter`, `[interval, internal]`이 `inter`가 되고, 둘을 합쳐 `inter`다.

비교하는 글자 수는 많아야 S이니 시간은 O(S)이고, 재귀 깊이 log n에 층마다 중간 결과 문자열을 들고 있으니 공간은 O(m · log n)이다. 세로 훑기보다 나은 점은 없다. 그래도 이 모양은 문자열이 여러 기계에 나뉘어 있을 때 쓸모가 있다. 기계마다 자기 몫의 공통 접두사를 구해 보내면, 받는 쪽은 그 결과끼리만 합치면 된다. 맵리듀스(MapReduce)에서 리듀스 단계가 하는 일이 이것이다.

## 길이를 이진 탐색한다

"길이 k짜리 앞부분이 모두에게 공통인가"라는 질문을 생각해 보자. k가 답 이하면 `예`, 답보다 크면 `아니오`다. 길이 k에서 `예`면 그보다 짧은 길이에서도 모두 `예`다. 이렇게 답이 어느 지점을 경계로 `예`에서 `아니오`로 한 번만 바뀌면 이진 탐색을 쓸 수 있다([이진 탐색 글](/posts/binary-search)).

```js
function longestCommonPrefix(strs) {
  let minLen = Infinity;
  for (const s of strs) minLen = Math.min(minLen, s.length); // 답은 이보다 길 수 없다
  const ok = (len) => {                     // 길이 len짜리 앞부분이 모두에게 공통인가
    const p = strs[0].slice(0, len);
    return strs.every((s) => s.startsWith(p));
  };
  let lo = 0, hi = minLen;                  // 답은 [lo, hi] 안에 있다
  while (lo < hi) {
    const mid = (lo + hi + 1) >> 1;         // 위쪽 가운데. lo = mid가 무한 루프가 되지 않게
    if (ok(mid)) lo = mid;
    else hi = mid - 1;
  }
  return strs[0].slice(0, lo);
}
```

예시의 가장 짧은 문자열은 `internet`, `interval`, `internal`로 8글자다. 길이 4를 물으면 `예`, 6을 물으면 `아니오`, 5를 물으면 `예`라서 답은 5, `inter`다.

`ok` 한 번에 O(n · k)이고 log(최소 길이)번 부르니 O(n · m · log m)이다. 세로 훑기의 O(S)보다 느리다. `mid`를 `(lo + hi) >> 1`로 잡으면 `lo = mid`가 `lo`를 그대로 두는 경우가 생겨 무한 루프에 빠진다. 경계를 다루는 연습으로는 좋지만, 이 문제에서 고를 이유는 없다. 비교 한 번이 아주 비싼 상황, 예를 들어 문자열이 원격 저장소에 있어서 "앞 k글자를 해시로 받아 비교"만 할 수 있을 때 의미가 생긴다.

## 정렬하면 처음과 끝만 보면 된다

문자열을 사전 순으로 정렬해 보자.

```text
internal
internet
interval
interview
```

정렬된 배열에서 맨 앞과 맨 뒤의 공통 접두사가 곧 전체의 공통 접두사다. 맨 앞 `internal`과 맨 뒤 `interview`는 `inter`까지 같다. 여섯째 글자 `n`이 `v`보다 앞이라 `internal`, `internet`이 먼저 온다.

왜 그럴까. 맨 앞과 맨 뒤의 공통 접두사를 p라고 하자. 가운데 문자열이 p로 시작하지 않는다면, p의 어느 위치에서 처음 달라질 것이다. 그 글자가 p의 글자보다 작으면 그 문자열은 맨 앞보다 앞에 와야 하고, 크면 맨 뒤보다 뒤에 와야 한다. 둘 다 정렬 결과와 어긋난다. 그러니 가운데 문자열은 모두 p로 시작하고, 전체의 공통 접두사는 p보다 길 수 없으니(맨 앞과 맨 뒤도 포함되므로) 답이 정확히 p다.

```js
function longestCommonPrefix(strs) {
  const s = [...strs].sort();          // 사전 순. 원본을 건드리지 않게 복사
  const a = s[0], b = s[s.length - 1]; // 가장 앞과 가장 뒤
  let j = 0;
  while (j < a.length && a[j] === b[j]) j++;
  return a.slice(0, j);
}
```

정렬에 비교 O(n log n)번, 비교 한 번에 최대 m글자라 O(n log n · m)이다. 공간은 복사본 O(n)이다. 코드는 짧고 이유를 설명하는 맛이 있어서 면접에서 두 번째 풀이로 내기 좋다. JS의 `sort()`는 비교자가 없으면 문자열을 UTF-16 코드 단위 순서로 정렬하는데, 소문자만 오는 이 문제에서는 사전 순과 같다. 숫자 배열이었다면 `[10, 9].sort()`가 `[10, 9]`가 되는 함정이 있다.

## 정렬하지 않고 가장 작은 것과 가장 큰 것만

정렬 풀이를 다시 보면 정렬 결과 전체를 쓰지 않는다. 쓰는 건 맨 앞과 맨 뒤, 즉 사전 순으로 가장 작은 문자열과 가장 큰 문자열뿐이다. 그렇다면 정렬할 필요 없이 한 번 훑어서 둘만 찾으면 된다.

```js
function longestCommonPrefix(strs) {
  let a = strs[0], b = strs[0];
  for (const s of strs) {
    if (s < a) a = s; // 사전 순으로 가장 작은 것
    if (s > b) b = s; // 가장 큰 것
  }
  let j = 0;
  while (j < a.length && a[j] === b[j]) j++;
  return a.slice(0, j);
}
```

문자열 비교 한 번은 처음 다른 글자에서 끝나니, 최솟값과 최댓값을 찾는 데 많아야 O(S)이고 마지막 비교가 O(m)이다. 추가 공간은 O(1)이다. 세로 훑기와 같은 복잡도를 다른 방향에서 얻은 셈이다.

Python의 `os.path.commonprefix`가 바로 이 방식이다. CPython의 구현은 `min`과 `max`로 두 문자열을 고른 뒤 그 둘만 앞에서부터 비교한다. 다만 세로 훑기처럼 "다른 글자를 만나면 즉시 멈추기"가 문자열 전체 단위로는 안 된다. 최솟값과 최댓값을 찾느라 모든 문자열을 한 번씩은 비교해야 하기 때문이다. 첫 두 문자열이 첫 글자부터 다른 입력에서 세로 훑기는 비교 한 번에 끝나지만, 이 풀이는 n번 비교한다.

뿌리에서 시작해 자식이 정확히 하나인 동안 내려간다. 자식이 둘 이상이면 문자열들이 거기서 갈라진 것이니 멈춘다. 끝 표시를 만나도 멈춘다. 어떤 문자열이 거기서 끝났다는 뜻이라, 그보다 긴 공통 접두사는 있을 수 없다. `[ab, a]`에서 `a` 노드는 자식이 `b` 하나뿐이지만 `a`의 끝 표시가 있어서 멈춰야 답이 `a`가 된다.

```js
function longestCommonPrefix(strs) {
  const root = { children: new Map(), isEnd: false };
  for (const s of strs) {
    let node = root;
    for (const ch of s) {
      if (!node.children.has(ch)) node.children.set(ch, { children: new Map(), isEnd: false });
      node = node.children.get(ch);
    }
    node.isEnd = true;
  }
  let node = root, out = "";
  // 자식이 하나뿐이고, 여기서 끝나는 문자열이 없는 동안 내려간다
  while (node.children.size === 1 && !node.isEnd) {
    const [ch, child] = node.children.entries().next().value; // 하나뿐인 자식
    out += ch;
    node = child;
  }
  return out;
}
```

트라이를 만드는 데 O(S), 내려가는 데 O(m)이다. 공간은 노드 수 O(S)다. 빈 문자열이 들어오면 뿌리에 끝 표시가 붙어서 바로 빈 문자열을 돌려주니, 따로 처리할 필요가 없다.

시간은 세로 훑기와 같은 O(S)인데 메모리를 O(S)나 쓰고, 모든 문자열을 끝까지 넣어야 해서 일찍 멈추지도 못한다. 공통 접두사를 한 번 구하는 데는 트라이가 가장 나쁜 선택이다. 트라이가 제값을 하는 건 같은 문자열 집합에 질문이 여러 번 들어올 때다. 뒤의 꼬리 질문에서 본다.

## 글자 비교 횟수를 세어 보면

복잡도 식은 비슷해 보여도, 실제로 글자를 몇 번 비교하는지는 입력 모양에 따라 크게 다르다. 글자 비교마다 수를 세는 함수를 끼워 넣고 네 풀이를 세 가지 입력에 돌렸다. 정렬은 JS `sort`에 같은 수를 세는 비교자를 넘겼다.

```text
입력                                세로 훑기   가로 줄이기   최솟값·최댓값   정렬
모두 같은 200글자 문자열 200개          39,800       39,800         80,200      79,800
둘째 문자열만 첫 글자가 다르다              1          200         40,201     128,452
첫 문자열만 200글자, 나머지는 a 한 글자     199          398            799         694
```

첫 줄은 모든 풀이의 최악이다. 답이 200글자라 누구든 글자 대부분을 봐야 한다. 세로 훑기와 가로 줄이기가 199 × 200 = 39,800번으로 같고, 최솟값·최댓값과 정렬은 문자열끼리 비교하느라 두 배쯤 더 본다.

둘째 줄에서 차이가 벌어진다. 세로 훑기는 위치 0에서 둘째 문자열과 한 번 비교하고 끝난다. 가로 줄이기는 첫 문자열 200글자를 한 글자씩 떼느라 200번 비교한다. 최솟값·최댓값과 정렬은 답이 빈 문자열인 걸 알 방법이 없어서, 나머지 199개의 똑같은 문자열끼리 끝까지 비교한다. 같은 O(S)라도 일찍 멈추는 풀이가 이기는 입력이다.

셋째 줄은 첫 문자열이 유난히 긴 경우다. 세로 훑기는 위치 1에서 짧은 문자열들이 끝나서 금방 멈춘다. 가로 줄이기는 첫 비교에서 199글자를 떼어 내야 하지만, 떼는 동안의 비교는 짧은 문자열 길이에서 끊겨 오래 걸리지 않는다.

## 일곱 풀이를 나란히 놓으면

n은 문자열 수, m은 첫 문자열(또는 가장 짧은 문자열) 길이, S는 모든 문자열 길이의 합이다.

| 풀이 | 시간 | 추가 공간 | 언제 고르나 |
|---|---|---|---|
| 가로로 줄이기 | O(n · m + m²) | O(m) | 문자열이 하나씩 들어올 때. 지금까지의 답만 들고 있으면 된다 |
| 세로로 훑기 | O(S), 다르면 즉시 멈춤 | O(1) | 기본 답 |
| 분할 정복 | O(S) | O(m · log n) | 문자열이 여러 기계에 나뉘어 있을 때 |
| 길이 이진 탐색 | O(n · m · log m) | O(m) | 앞부분 비교만 할 수 있고 그게 비쌀 때 |
| 정렬 후 처음·끝 | O(n log n · m) | O(n) | 이미 정렬된 목록일 때 |
| 최솟값·최댓값만 | O(S) | O(1) | 한 줄로 짜고 싶을 때. Python의 commonprefix |
| 트라이 | O(S) | O(S) | 같은 집합에 질문이 여러 번 들어올 때 |

## 짧은 문자열과 빈 문자열에서 틀린다

가장 흔한 실수는 바깥 루프를 첫 문자열 길이로 돌면서 다른 문자열이 더 짧을 수 있다는 걸 잊는 것이다.

```js
function longestCommonPrefix(strs) {
  let j = 0;
  while (j < strs[0].length && strs.every((s) => s[j] === strs[0][j])) j++;
  return strs[0].slice(0, j);
}
// JS에서는 ["ab", "a"] -> "a"로 우연히 맞는다
```

JS에서는 범위를 넘은 `s[j]`가 `undefined`라 `strs[0][j]`와 다르다고 나와서 우연히 맞는다. 같은 코드를 Java로 옮겨 `s.charAt(j)`로 쓰면 `StringIndexOutOfBoundsException`이 난다. Python의 `s[j]`도 `IndexError`다. 언어를 바꿔 옮길 때 터지는 버그라서, 길이 검사를 명시해 두는 편이 안전하다.

두 번째는 답을 찾는 루프가 끝난 뒤의 처리다.

```js
function longestCommonPrefix(strs) {
  const first = strs[0];
  for (let j = 0; j < first.length; j++) {
    for (let i = 1; i < strs.length; i++) {
      if (j === strs[i].length || strs[i][j] !== first[j]) return first.slice(0, j);
    }
  }
  return ""; // 끝까지 다 같았는데 빈 문자열을 돌려준다
}
// ["same", "same"] -> "" (정답은 "same"), ["alone"] -> "" (정답은 "alone")
```

루프를 무사히 빠져나왔다는 건 첫 문자열 전체가 공통이라는 뜻이다. 다른 데서 습관처럼 "못 찾으면 빈 값"을 쓰다가 이렇게 된다. 위 테스트의 "모두 같다", "문자열 하나"가 이걸 잡는다.

그 밖에 이 문제에서 조심할 것들이다.

- 가로로 줄이기에서 `indexOf(prefix) !== 0`으로 검사하면 맞지 않을 때 문자열 전체를 훑어 찾느라 느려진다. 접두사인지만 볼 때는 `startsWith`를 쓴다.
- 트라이 풀이에서 끝 표시 검사를 빼면 `[ab, a]`에서 `ab`를 돌려준다. `a` 노드의 자식이 `b` 하나뿐이라 계속 내려가기 때문이다.
- 이진 탐색 풀이에서 `mid`를 아래쪽 가운데로 잡으면 `lo = mid`에서 무한 루프에 빠진다.
- 경로의 공통 디렉터리를 글자 단위로 구하면 `/usr/lib`와 `/usr/local`에서 `/usr/l`이 나온다. 경로라면 `/`로 나눈 조각 단위로 같은 알고리즘을 돌린다.

## 면접관이 이어서 묻는 것

### 문자열이 하나씩 계속 들어온다면

가로로 줄이기가 그대로 답이다. 지금까지의 공통 접두사 하나만 들고 있다가, 새 문자열이 오면 그것과 맞춰 줄인다. 공통 접두사는 줄어들기만 하니 지난 문자열을 기억할 필요가 없다. 답이 빈 문자열이 되면 더 볼 필요도 없다.

### 같은 문자열 집합에 질문이 여러 번 들어온다면

예를 들어 "질문 문자열 q와 목록의 어떤 문자열이 가진 가장 긴 공통 접두사의 길이"를 여러 번 묻는다면, 목록으로 트라이를 한 번 만들어 두고 q를 따라 내려가다 길이 끊기는 곳이 답이다. 질문 하나에 O(q 길이)다. 목록의 일부 구간(i번부터 j번까지)의 공통 접두사를 여러 번 묻는다면, 정렬된 문자열 배열에서 이웃끼리의 공통 접두사 길이를 미리 구해 두고 구간 최솟값을 구하는 방식(LCP 배열 + 구간 최소 질의)을 쓴다. 접미사 배열(suffix array)이 이 아이디어를 쓴다.

### 공통 접미사를 구하라면

모든 문자열을 뒤집어서 같은 알고리즘을 돌리고 결과를 다시 뒤집는다. 뒤집지 않고 끝에서부터 세로로 훑어도 된다.

### 접두사가 아니라 공통 부분 문자열이라면

문자열 어디에 있어도 되는 가장 긴 공통 부분 문자열은 훨씬 어려운 문제다. 문자열 둘이라면 DP로 O(n · m)이고(LeetCode 718. Maximum Length of Repeated Subarray가 배열 버전), 여럿이라면 접미사 자동자나 일반화된 접미사 트리를 쓴다. 면접에서는 "접두사는 앞에서부터 한 줄로만 비교하면 되지만 부분 문자열은 시작 위치가 자유로워서 경우가 폭발한다"는 차이를 말할 수 있으면 된다.

### 이모지나 다른 언어 글자가 섞인다면

JS 문자열은 UTF-16 코드 단위로 인덱싱된다. 이모지처럼 코드 단위 두 개로 된 글자는 앞 단위가 같고 뒤 단위만 다를 수 있다. `["😀a", "😃b"]`에 세로 훑기를 돌리면 길이 1짜리 `"\ud83d"`가 나온다. 반쪽짜리 글자라 `isWellFormed()`가 `false`이고, 화면에는 깨진 문자로 보인다. `[...s]`로 코드 포인트 배열을 만든 뒤 같은 알고리즘을 돌리면 빈 문자열이 제대로 나온다. 악센트가 붙은 글자처럼 같은 모양을 다른 코드로 쓸 수 있는 경우까지 맞추려면 비교 전에 `normalize("NFC")`로 정규화한다.

- [Search Suggestions System](/posts/leetcode-search-suggestions-system) (1268): 정렬 후 이진 탐색, 또는 트라이로 접두사가 같은 단어를 모은다.
- 1062. Longest Repeating Substring(프리미엄 문제): 길이 이진 탐색과 해시를 함께 쓴다.

## 다른 글자를 만나는 순간 멈춘다

공통 접두사는 문자열을 하나 더 볼 때마다 줄어들기만 하고, 가장 짧은 문자열보다 길 수 없다. 세로로 한 칸씩 훑으면 다른 글자나 끝난 문자열을 만나는 순간 멈출 수 있어서, 추가 메모리 없이 가장 적게 비교한다. 정렬이나 최솟값·최댓값 풀이는 "사전 순으로 가운데 있는 문자열은 양 끝의 공통 접두사를 반드시 가진다"는 성질을 쓰고, 분할 정복과 이진 탐색은 문제를 나누는 방법을 연습하기 좋다. 트라이는 이 문제 하나에는 과하지만, 같은 문자열 집합에 질문이 여러 번 들어오는 순간 가장 좋은 답이 된다.

## 면접에서 나올 만한 질문

### 가장 좋은 풀이와 그 복잡도는요?

세로로 한 칸씩 훑는 풀이다. 첫 문자열의 글자 위치마다 나머지 문자열의 같은 위치를 보고, 끝났거나 다르면 그 앞까지를 돌려준다. 비교는 많아야 n · (답 길이 + 1)번이고 최악은 모든 문자열이 같을 때의 O(S)다. 추가 공간은 O(1)이다.

### 정렬해서 처음과 끝만 비교해도 되는 이유는요?

가운데 문자열이 처음과 끝의 공통 접두사 p로 시작하지 않는다면, p 안의 어느 위치에서 처음 달라진다. 그 글자가 작으면 처음보다 앞에, 크면 끝보다 뒤에 와야 해서 정렬 결과와 어긋난다. 그래서 가운데는 모두 p로 시작하고, 처음과 끝도 포함되니 답이 정확히 p다. 정렬 없이 최솟값과 최댓값만 찾아도 같은 답이 나와서 O(S)로 줄일 수 있다.

### 트라이로 풀면 어떤가요?

모든 문자열을 넣고, 뿌리에서 자식이 하나뿐이고 끝 표시가 없는 동안 내려간다. 시간은 O(S)로 같지만 공간을 O(S) 쓰고 일찍 멈추지 못해서, 한 번 구하는 데는 세로 훑기보다 나쁘다. 같은 집합에 "이 문자열과의 가장 긴 공통 접두사는?" 같은 질문이 여러 번 들어올 때 트라이를 고른다.

### 빈 문자열이 섞이면 어떻게 되나요?

답은 빈 문자열이다. 세로 훑기에서는 위치 0에서 그 문자열의 길이가 0이라 바로 멈춘다. 트라이에서는 뿌리에 끝 표시가 붙어서 내려가지 않는다. 길이 검사를 빼먹은 코드는 JS에서는 우연히 맞고 Java와 Python에서는 범위 예외가 나니, 언어를 옮길 때 특히 조심한다.

### 문자열이 스트림으로 하나씩 들어온다면요?

지금까지의 공통 접두사 하나만 들고 있다가 새 문자열이 오면 그것과 맞춰 줄인다. 공통 접두사는 줄어들기만 하니 지난 문자열을 기억할 필요가 없고, 빈 문자열이 되면 더 볼 필요도 없다. 메모리는 답 길이만큼이다.

### 이진 탐색 풀이는 왜 가능하고 왜 잘 안 쓰나요?

길이 k짜리 앞부분이 공통이면 그보다 짧은 길이도 모두 공통이라, 답의 경계에서 `예`가 `아니오`로 한 번만 바뀐다. 그래서 길이를 이진 탐색할 수 있다. 하지만 확인 한 번에 O(n · k)가 들어서 전체가 O(n · m · log m)이고, 세로 훑기의 O(S)보다 느리다. 앞부분 비교만 가능하고 그게 아주 비쌀 때나 의미가 있다.
