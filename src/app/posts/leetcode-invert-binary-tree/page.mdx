아랍어나 히브리어처럼 오른쪽에서 왼쪽으로 읽는 언어를 지원하면 화면을 좌우로 뒤집어야 한다. 메뉴가 트리 모양이라면 형제 메뉴의 순서까지 거꾸로 놓아야 하는데, 한 층만 뒤집으면 안쪽 메뉴는 그대로 남는다. 모든 층에서 왼쪽과 오른쪽을 바꿔야 진짜 거울상이 된다.

[LeetCode 226. Invert Binary Tree](https://leetcode.com/problems/invert-binary-tree/)가 이 작업을 이진 트리에서 하는 문제다. Homebrew를 만든 Max Howell이 2015년에 "구글 면접에서 화이트보드에 이진 트리를 뒤집지 못해 떨어졌다"고 트윗해서 유명해졌다. 코드는 다섯 줄이면 끝나지만, 면접관은 그다음을 묻는다. 순회 순서를 바꿔도 되나, 원본을 지켜야 하면 어떻게 하나, 재귀 없이 짜 보라, 대칭 트리 판별로 넓혀 보라.

이 글은 같은 문제를 다섯 가지 방법으로 푼다. 트리 구조와 순회 이름(전위, 중위, 후위, 층 순서)은 [이진 트리와 BST 글](/posts/ds-binary-tree-bst)에서, 바텀업 재귀의 기본 틀은 [Maximum Depth of Binary Tree 글](/posts/leetcode-maximum-depth-of-binary-tree)에서 다뤘으니 여기서는 짧게만 짚는다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 모든 층에서 왼쪽과 오른쪽을 맞바꾼다

이진 트리의 뿌리(root) 노드를 받아서, 모든 노드의 왼쪽 자식과 오른쪽 자식을 서로 바꾼 트리의 뿌리를 돌려준다. 뿌리 노드 자체는 자리를 옮기지 않는다. 바뀌는 건 각 노드가 가리키는 두 포인터뿐이다.

제약에서 볼 것은 노드 수 하나다. 0개에서 100개까지다. 노드마다 한 번은 손대야 하니 O(n)보다 빨라질 수 없고, 100개라 어떤 풀이든 시간은 넉넉하다. 그래서 이 문제에서 풀이를 가르는 건 속도가 아니라 원본을 고치느냐, 호출 스택을 쓰느냐, 어떤 순서로 노드를 들르느냐다. 빈 트리(노드 0개)도 입력으로 들어온다.

이 글 내내 쓸 예시다. 트리는 LeetCode처럼 위층부터 왼쪽에서 오른쪽으로 읽은 배열로 적고, 빈 자리는 `null`로 둔다.

```text

        5                                  5
      /   \                              /   \
     3     8                            8     3
    / \     \                          /     / \

```

## 거울에 비친 새 트리를 따로 만든다

처음 떠올리기 쉬운 방법은 원래 트리는 건드리지 않고, 거울상 트리를 새로 짓는 것이다. 새 노드를 만들 때 값은 그대로 쓰고, 새 노드의 왼쪽에는 원래 오른쪽 자식의 거울상을, 오른쪽에는 원래 왼쪽 자식의 거울상을 단다.

```js
function invertTree(root) {
  if (root === null) return null; // 빈 자리의 거울상은 빈 자리다
  return {
    val: root.val,
    left: invertTree(root.right), // 오른쪽을 뒤집어 왼쪽에
    right: invertTree(root.left), // 왼쪽을 뒤집어 오른쪽에
  };
}
```

정의를 그대로 옮긴 코드라 맞는지 따지기 쉽다. "트리 T의 거울상은, 뿌리가 같고 왼쪽에 T.right의 거울상, 오른쪽에 T.left의 거울상이 달린 트리다." 이 문장을 그대로 읽으면 위 코드가 된다.

노드마다 한 번 방문하고 새 노드를 하나 만드니 시간은 O(n)이다. 공간은 새 노드 n개로 O(n), 거기에 호출 스택이 트리 높이 h만큼 O(h) 든다. 결과로 돌려줄 트리를 따로 만드는 비용이라, 원본이 필요 없는 상황에서는 낭비다.

장점도 분명하다. 원본 트리가 다른 곳에서 계속 쓰이고 있거나, 함수형 스타일로 입력을 고치지 않아야 하는 코드라면 이게 맞는 답이다. React 상태처럼 불변 데이터를 다룰 때가 그렇다. 실제로 돌려 보면 원본은 `[5, 3, 8, 1, 4, null, 9]` 그대로 남아 있다. LeetCode 채점은 돌려준 트리만 보므로 이 풀이도 통과한다. 다만 면접에서는 "새로 만들지 않고 제자리에서 할 수 있나"가 바로 따라온다.

## 내 두 자식을 바꾸고 아래로 내려보낸다

제자리에서 하려면 노드마다 포인터 두 개를 맞바꾸면 된다. 순서는 이렇다. 지금 노드의 왼쪽과 오른쪽을 바꾼다. 그다음 두 자식에게 같은 일을 시킨다. 자기 일을 먼저 하고 자식에게 내려가니 전위 순회(preorder) 순서다.

```js
function invertTree(root) {
  if (root === null) return null;
  const tmp = root.left; // 덮어쓰기 전에 왼쪽을 잠시 들고 있는다
  root.left = root.right;
  root.right = tmp;
  invertTree(root.left); // 바꾼 뒤라 원래 오른쪽 가지로 내려간다
  invertTree(root.right); // 원래 왼쪽 가지
  return root;
}
```

바꾼 다음에 내려가니 `root.left`는 이미 원래 오른쪽 가지다. 헷갈릴 것 같지만 상관없다. 두 가지 모두 뒤집어야 하고, 어느 쪽부터 하든 서로 영향이 없다. 두 가지는 노드를 공유하지 않기 때문이다.

복잡도를 따지면, 노드마다 한 번 불리고 그 안에서 포인터 대입 세 번을 하니 시간은 O(n)이다. 빈 자리에도 호출이 한 번씩 가지만, 노드 n개짜리 이진 트리에는 빈 자리가 정확히 n+1개라서 차수는 그대로다. 추가 공간은 호출 스택 O(h)다. 균형 잡힌 트리면 O(log n), 한쪽으로 쭉 늘어선 트리면 O(n)이다.

이 풀이의 약점은 그 O(n) 쪽이다. 한쪽으로만 이어진 트리를 Node.js 22에서 만들어 이 함수에 넣어 보면, 이 환경에서는 깊이 15,694까지는 돌고 그보다 깊으면 `RangeError: Maximum call stack size exceeded`가 난다. 정확한 한계는 함수의 지역 변수 수와 V8 설정에 따라 달라진다. LeetCode는 100개라 문제없지만, 실무 데이터라면 생각해 둘 지점이다.

### Python과 Java로 쓰면

Python은 튜플 대입으로 임시 변수 없이 바꿀 수 있다. 오른쪽 식 `(root.right, root.left)`가 먼저 다 계산된 다음 왼쪽에 대입되기 때문이다.

```python
class Solution:
    def invertTree(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        if root is None:
            return None
        # 튜플 대입이라 임시 변수가 필요 없다
        root.left, root.right = root.right, root.left
        self.invertTree(root.left)
        self.invertTree(root.right)
        return root
```

```text
[5, 8, 3, 9, None, 4, 1]
```

Python의 기본 재귀 한도는 1000이다. 노드 5,000개짜리 일자 트리를 넣으면 `RecursionError: maximum recursion depth exceeded`가 난다. `sys.setrecursionlimit`으로 올릴 수는 있지만, 한도를 너무 크게 잡으면 버전과 환경에 따라 인터프리터가 예외 대신 비정상 종료될 수 있다. 깊은 트리라면 아래의 반복 풀이로 바꾸는 편이 안전하다.

Java는 임시 변수가 꼭 필요하다. 구조 분해 대입이 없다.

```java
class Solution {
    public TreeNode invertTree(TreeNode root) {
        if (root == null) return null;
        TreeNode tmp = root.left; // 바꾸기 전에 왼쪽을 잠시 들고 있는다
        root.left = root.right;
        root.right = tmp;
        invertTree(root.left);
        invertTree(root.right);
        return root;
    }
}
```

```text
[5, 8, 3, 9, null, 4, 1]
```

Java는 스레드 스택 크기(`-Xss`)가 한계를 정한다. 이 환경의 기본 설정에서 10만 단계 일자 트리를 넣으면 `StackOverflowError`가 났다. 10만 단계를 꼭 재귀로 돌려야 한다면 `new Thread(null, task, "big", 1 << 26)`처럼 스택을 크게 잡은 스레드에서 돌리는 방법도 있지만, 면접에서는 반복 풀이로 옮기는 답이 더 낫다.

## 아래부터 뒤집어 올라온다

같은 일을 순서만 바꿔 할 수도 있다. 먼저 두 자식 가지를 각각 뒤집어서 받아 오고, 받아 온 두 결과를 반대쪽에 단다. 자식을 먼저 처리하고 자기 일을 나중에 하니 후위 순회(postorder)다.

```js
function invertTree(root) {
  if (root === null) return null;
  const left = invertTree(root.left); // 왼쪽 가지를 뒤집은 결과
  const right = invertTree(root.right); // 오른쪽 가지를 뒤집은 결과
  root.left = right; // 뒤집힌 오른쪽을 왼쪽에
  root.right = left;
  return root;
}
```

결과와 복잡도는 전위 버전과 같다. 시간 O(n), 공간 O(h). 차이는 생각하는 방식이다. 전위 버전은 "위에서 일을 하고 아래로 넘긴다"이고, 후위 버전은 "아래에서 답을 받아 위에서 조립한다"다. [최대 깊이 글](/posts/leetcode-maximum-depth-of-binary-tree)의 바텀업 재귀, [최대 경로 합 글](/posts/leetcode-binary-tree-maximum-path-sum)의 풀이가 모두 이 모양이다.

후위 버전은 임시 변수가 따로 필요 없다. 두 자식의 결과를 지역 변수 `left`, `right`에 이미 받아 두었기 때문이다. 두 자식을 받은 다음에야 답을 정할 수 있는 문제(지름, 균형 검사)로 넓힐 때는 이 틀이 그대로 쓰인다.

## 중위 순서로 하면 한쪽이 두 번 뒤집힌다

전위와 후위가 둘 다 되니 중위 순회(inorder, 왼쪽 → 나 → 오른쪽)도 될 것 같다. 그대로 옮겨 보면 이렇다.

```js
function invertTree(root) {
  if (root === null) return null;
  invertTree(root.left);
  [root.left, root.right] = [root.right, root.left];
  invertTree(root.right); // 틀렸다
  return root;
}
```

예시 트리에 넣으면 `[5, 8, 3, 9, null, 4, 1]`이 아니라 `[5, 8, 3, null, 9, 1, 4]`가 나온다. 뿌리만 바뀌고 아래는 원래 방향이다. 순서를 따라가 보면 이유가 보인다.

1. 왼쪽 가지(3 아래)를 먼저 뒤집는다.
2. 뿌리에서 두 자식을 바꾼다. 방금 뒤집은 3 가지가 이제 오른쪽에 있다.
3. `root.right`로 내려간다. 그런데 그건 이미 뒤집힌 3 가지다. 한 번 더 뒤집어 원래대로 되돌린다.
4. 8 가지는 한 번도 손대지 않은 채 끝난다.

고치려면 바꾼 다음에 `root.left`로 한 번 더 내려가면 된다. 바꾸기 전의 오른쪽 가지가 이제 왼쪽에 있으니까.

```js
function invertTree(root) {
  if (root === null) return null;
  invertTree(root.left); // 원래 왼쪽 가지
  [root.left, root.right] = [root.right, root.left];
  invertTree(root.left); // 바꾼 뒤의 왼쪽 = 원래 오른쪽 가지
  return root;
}
```

이 코드는 맞는 답을 낸다. 그래도 읽는 사람이 `left`를 두 번 부르는 이유를 따로 생각해야 해서 굳이 고를 이유는 없다. 면접에서 "순회 순서를 바꿔도 되나요"라는 질문이 나오면 이 예시를 들면 된다. 전위와 후위는 바꾸기와 내려가기가 섞이지 않지만, 중위는 내려가는 사이에 바꾸기가 끼어들어 포인터가 가리키는 대상이 바뀐다.

## 재귀 없이 스택에 쌓아 두고 꺼낸다

호출 스택이 넘치는 문제를 피하려면, 재귀가 하던 일을 배열 스택으로 직접 한다. 스택에서 노드를 하나 꺼내 두 자식을 바꾸고, 자식이 있으면 스택에 넣는다. 스택이 빌 때까지 반복한다.

```js
function invertTree(root) {
  if (root === null) return null;
  const stack = [root];
  while (stack.length > 0) {
    const node = stack.pop();
    [node.left, node.right] = [node.right, node.left];
    if (node.left) stack.push(node.left); // null은 넣지 않는다
    if (node.right) stack.push(node.right);
  }
  return root;
}
```

노드마다 바꾸는 일은 서로 독립이라 어느 순서로 꺼내든 결과가 같다. 이 점이 이 문제를 반복문으로 옮기기 쉽게 만든다. 순서가 결과에 영향을 주는 문제(중위 순서로 값을 모으기 등)였다면 스택에 "돌아와서 할 일"을 따로 표시해야 했을 것이다.

시간은 O(n)이다. 스택에는 최악의 경우 O(h)에서 O(n)까지 쌓인다. 일자 트리에서는 늘 한 개만 들어 있고, 꽉 찬 트리에서는 대략 높이 × 1 정도다. 차이는 공간이 호출 스택이 아니라 힙에 잡힌다는 것이다. 힙은 수백 MB까지 쓸 수 있으니 앞에서 터졌던 10만 단계 일자 트리도 이 코드로는 문제없이 돈다. 직접 돌려 봐도 그랬다.

한 가지 주의할 점은 JavaScript의 구조 분해 대입 `[a, b] = [b, a]`가 매번 작은 배열을 하나 만든다는 것이다. 노드 100개에서는 의미 없는 차이지만, 아주 뜨거운 반복문이라면 임시 변수 세 줄이 조금 더 빠르다. 면접에서는 읽기 쉬운 쪽을 쓰고, 물어보면 이 차이를 말하면 된다.

## 한 층씩 줄 세워 뒤집는다

스택 대신 큐를 쓰면 위층부터 한 층씩 내려가며 뒤집는다. 층 순서 순회(BFS)는 [Level Order Traversal 글](/posts/leetcode-binary-tree-level-order-traversal)에서 자세히 다뤘다. 여기서는 층을 구분할 필요가 없어서 더 간단하다.

```js
function invertTree(root) {
  if (root === null) return null;
  const queue = [root];
  let head = 0; // shift()는 O(n)이라 머리 위치만 옮긴다
  while (head < queue.length) {
    const node = queue[head++];
    [node.left, node.right] = [node.right, node.left];
    if (node.left) queue.push(node.left);
    if (node.right) queue.push(node.right);
  }
  return root;
}
```

아래 그림은 같은 예시를 큐로 뒤집는 과정이다. 기억 칸은 큐에 남은 노드이고, 왼쪽이 다음에 꺼낼 노드다.

큐에 들어 있는 노드는 많아야 한 층 반 정도다. 꽉 찬 트리라면 마지막 층에 노드의 절반 가까이가 있으니 큐가 O(n)까지 커진다. 반대로 일자 트리라면 큐에 늘 하나뿐이다. 스택 풀이와 BFS 풀이는 공간이 커지는 트리 모양이 정반대다.

Python에서는 리스트의 `pop(0)`이 O(n)이라 `collections.deque`의 `popleft()`를 쓴다. Java는 `ArrayDeque`가 기본인데, 이 자료구조는 `null`을 넣으면 `NullPointerException`을 던진다. 그래서 자식이 있는지 먼저 확인하고 넣는다.

```python
from collections import deque

def invertTree(self, root):
    queue = deque([root] if root else [])
    while queue:
        node = queue.popleft()
        node.left, node.right = node.right, node.left
        if node.left:
            queue.append(node.left)
        if node.right:
            queue.append(node.right)
    return root
```

```java
public TreeNode invertTree(TreeNode root) {
    if (root == null) return null;
    Deque<TreeNode> queue = new ArrayDeque<>(); // ArrayDeque는 null을 넣을 수 없다
    queue.offer(root);
    while (!queue.isEmpty()) {
        TreeNode node = queue.poll();
        TreeNode tmp = node.left;
        node.left = node.right;
        node.right = tmp;
        if (node.left != null) queue.offer(node.left);
        if (node.right != null) queue.offer(node.right);
    }
    return root;
}
```

두 코드 모두 예시 트리에서 `[5, 8, 3, 9, null, 4, 1]`을 냈다.

## 뒤집는 다섯 가지 방법 견주기

| 풀이 | 시간 | 추가 공간 | 언제 고르나 |
|---|---|---|---|
| 새 거울 트리 만들기 | O(n) | O(n) 새 노드 + O(h) 스택 | 원본을 고치면 안 될 때(불변 데이터, 다른 곳에서 쓰는 트리) |
| 전위 재귀 (바꾸고 내려가기) | O(n) | O(h) 호출 스택 | 기본 답. 가장 짧고 설명하기 쉽다 |
| 후위 재귀 (받아서 조립하기) | O(n) | O(h) 호출 스택 | 자식 결과를 받아 쓰는 문제로 넓힐 때 |
| 반복 DFS (스택) | O(n) | O(h)~O(n) 힙 | 트리가 아주 깊을 수 있을 때, 재귀를 금지할 때 |
| BFS (큐) | O(n) | O(너비) 힙 | 층 순서로 처리해야 할 때, 깊고 좁은 트리 |

시간은 모두 같으니 고르는 기준은 원본을 지켜야 하는지, 트리가 얼마나 깊은지다. 중위 순서는 고친 버전도 맞지만 표에서는 뺐다. 다른 풀이보다 나은 점이 없다.

## 뒤집기 코드가 조용히 틀리는 경우

### 임시 변수 없이 두 줄로 바꾸기

```js
root.left = root.right;
root.right = root.left; // 이미 덮어쓴 값을 다시 읽는다
```

첫 줄에서 왼쪽 원래 값이 사라진다. 둘째 줄은 방금 넣은 오른쪽 값을 다시 읽으니, 두 포인터가 같은 가지를 가리킨다. 예시 트리에 넣으면 `[5, 8, 8, 9, 9, 9, 9]`처럼 같은 노드가 여러 번 찍힌다. 원래 왼쪽 가지는 아무도 가리키지 않게 되어 잃어버린다. 오류 없이 틀린 답이 나와서 더 찾기 어렵다. 임시 변수, 구조 분해 대입, Python의 튜플 대입 중 하나를 쓴다.

### 아무것도 돌려주지 않기

```js
function invertTree(root) {
  if (!root) return;
  [root.left, root.right] = [root.right, root.left];
  invertTree(root.left);
  invertTree(root.right);
  // return root;를 빠뜨렸다
}
```

트리 자체는 제자리에서 제대로 뒤집힌다. 그런데 LeetCode는 함수가 돌려준 값을 뿌리로 보고 채점하므로 `undefined`를 받아 빈 트리로 처리한다. 재귀 호출 결과를 쓰지 않는 전위 풀이에서 특히 잘 빠뜨린다. 후위 풀이는 반환값을 받아 써야 해서 이 실수가 나기 어렵다.

### 빈 트리를 먼저 막지 않기

BFS나 스택 풀이에서 `if (root === null) return null;`을 빼고 `queue = [root]`로 시작하면, 빈 트리에서 `null.left`를 읽다가 `TypeError`가 난다. 위의 Python 코드처럼 처음부터 `root`가 있을 때만 큐에 넣는 방법도 있다.

### 한 층만 바꾸기

```js
const tmp = root.left;
root.left = root.right;
root.right = tmp; // 아래로 내려가지 않았다
```

뿌리의 두 자식만 바뀌고 아래층은 원래 방향 그대로다. 예시에서 `[5, 8, 3, null, 9, 1, 4]`가 나온다. 앞에서 본 틀린 중위 순서와 결과가 같다. 노드 세 개 이하의 작은 테스트로는 이 실수가 드러나지 않는다. 손자 노드가 한쪽에만 있는 트리로 꼭 확인한다.

### 재귀 깊이

LeetCode 입력은 100개라 괜찮다. 같은 코드를 사내 데이터에 쓴다면 깊이 상한부터 확인한다. 앞에서 잰 대로 Node.js는 약 1만 5천, Python은 기본 1000, Java는 스택 크기에 따라 수천에서 수만 단계에서 넘친다. 상한을 장담할 수 없으면 스택이나 큐 풀이를 쓴다.

## 거울 트리에서 뻗어 나가는 문제들

### 원본을 그대로 두고 뒤집은 트리를 따로 달라면

첫 번째 풀이, 새 거울 트리 만들기를 쓴다. 다른 풀이로 원본을 깊은 복사한 다음 뒤집는 방법도 있지만, 노드를 두 번 도는 셈이라 처음부터 거울상을 지으며 복사하는 쪽이 한 번에 끝난다.

### 트리가 좌우 대칭인지 확인하라면

LeetCode 101 Symmetric Tree다. 트리가 자기 거울상과 같으면 대칭이다. 뒤집어서 비교해도 되지만 원본을 고치게 되니, 두 포인터로 바깥쪽끼리, 안쪽끼리 비교하는 편이 깔끔하다.

```js
function isMirror(a, b) {
  if (!a || !b) return a === b; // 둘 다 비었을 때만 참
  return a.val === b.val && isMirror(a.left, b.right) && isMirror(a.right, b.left);
}
const isSymmetric = (root) => !root || isMirror(root.left, root.right);
```

`[1, 2, 2, 3, 4, 4, 3]`은 `true`, `[1, 2, 2, null, 3, null, 3]`은 `false`가 나왔다. 뒤집기 코드에서 `left`와 `right`를 엇갈려 쓰던 자리가 여기서는 비교 대상을 엇갈려 고르는 자리로 바뀌었을 뿐이다.

### 두 트리가 몇 군데 뒤집으면 같아지는지 묻는다면

LeetCode 951 Flip Equivalent Binary Trees다. 노드마다 "그대로 같다" 또는 "자식을 바꾸면 같다" 둘 중 하나가 성립하면 된다. 재귀 한 번에 두 경우를 모두 검사한다. 최악의 경우 두 가지를 다 내려가 보지만, 값이 모두 다르다는 조건이 있으면 한 노드에서 맞는 쪽은 하나뿐이라 O(n)에 끝난다.

### BST를 뒤집으면 어떻게 되나

예시 트리는 사실 이진 탐색 트리(BST)다. 왼쪽 가지는 모두 작고 오른쪽 가지는 모두 크다. 뒤집으면 그 관계가 정반대가 된다. 중위 순회로 값을 읽어 보면 원래는 `1, 3, 4, 5, 8, 9`이고, 뒤집은 뒤에는 `9, 8, 5, 4, 3, 1`이 나왔다. 오름차순 BST를 뒤집으면 내림차순 BST가 된다. 그래서 "BST에서 k번째로 큰 값"을 묻는 문제는 트리를 뒤집는 대신 오른쪽부터 도는 역중위 순회로 푼다. BST가 맞는지 검사하는 일은 [Validate Binary Search Tree 글](/posts/leetcode-validate-binary-search-tree)에서 다룬다.

### 두 번 뒤집으면

원래 트리로 돌아온다. 뒤집기는 자기 자신의 역연산이다. 실제로 `invert(invert(t))`를 돌리면 `[5, 3, 8, 1, 4, null, 9]`가 그대로 나온다. 테스트를 짤 때 이 성질을 쓰면 정답을 손으로 적지 않아도 검증할 수 있다.

### 자식이 여러 개인 트리라면

N진 트리에서는 자식 배열을 뒤집으면 된다. 노드마다 `children.reverse()`를 하고 각 자식에게 내려간다. 시간은 노드 수와 간선 수를 더한 만큼이다.

### 같은 패턴의 다음 문제

자식 결과를 받아 조립하는 후위 틀은 [Diameter of Binary Tree](/posts/leetcode-diameter-of-binary-tree)에서 그대로 쓴다. 층 순서로 훑는 BFS 틀은 [Binary Tree Right Side View](/posts/leetcode-binary-tree-right-side-view)로 이어진다. 두 순회 결과로 트리를 다시 짓는 [Construct Binary Tree from Preorder and Inorder Traversal](/posts/leetcode-construct-tree-from-preorder-inorder)은 이번 글의 "새 트리 만들기"를 더 어렵게 만든 문제다.

## 노드마다 같은 일을 한 번씩

거울상은 모든 노드에서 두 자식을 바꾼 결과다. 그래서 노드를 빠짐없이 한 번씩 들르기만 하면 되고, 들르는 순서는 전위든 후위든 스택이든 큐든 상관없다. 중위 순서만은 내려가는 사이에 포인터가 바뀌어 한쪽을 두 번 뒤집는다. 나머지 판단은 원본을 지켜야 하는지, 트리가 얼마나 깊은지 두 가지로 정해진다.

## 면접에서 나올 만한 질문

### 시간과 공간 복잡도는 어떻게 되나요?

시간은 O(n)이다. 모든 노드의 포인터를 한 번씩 바꿔야 하니 이보다 빠를 수 없다. 재귀 풀이의 추가 공간은 호출 스택 O(h)이고, 균형 트리면 O(log n), 한쪽으로 늘어선 트리면 O(n)이다. 원본을 두고 새 트리를 만들면 결과 노드 O(n)이 더 든다.

### 전위, 중위, 후위 중 아무 순서나 써도 되나요?

전위와 후위는 된다. 바꾸는 일과 두 가지로 내려가는 일이 서로 섞이지 않기 때문이다. 중위는 왼쪽을 뒤집고, 바꾸고, 다시 오른쪽으로 내려가는데, 그 오른쪽이 방금 뒤집은 원래 왼쪽이라 두 번 뒤집혀 원래대로 돌아온다. 굳이 중위로 하려면 바꾼 다음에 왼쪽으로 한 번 더 내려가야 한다.

### 재귀 없이 짜 보라면요?

스택이나 큐에 루트를 넣고, 꺼낼 때마다 두 자식을 바꾸고 자식을 넣는다. 노드마다 바꾸는 일이 독립이라 꺼내는 순서가 결과에 영향을 주지 않는다. 공간은 힙에 잡히니 깊은 트리에서도 호출 스택이 넘치지 않는다.

### 원본 트리를 바꾸면 안 된다면요?

거울상을 새로 지으면서 복사한다. 새 노드의 왼쪽에는 원래 오른쪽 자식의 거울상을, 오른쪽에는 원래 왼쪽 자식의 거울상을 단다. 시간은 그대로 O(n)이고 결과 트리 몫의 O(n) 공간이 든다.

### 트리가 10만 단계로 깊으면 어떻게 되나요?

재귀 풀이는 언어마다 한계에 걸린다. 내가 돌려 본 환경에서 Node.js는 약 1만 5천 단계, Python은 기본 한도 1000, Java는 기본 스택에서 10만 단계에 넘쳤다. 이런 입력이 올 수 있다면 명시적 스택이나 큐로 바꾼다. 깊고 좁은 트리라면 큐에는 늘 노드가 몇 개 없어서 BFS가 메모리도 적게 쓴다.

### 이 문제를 대칭 트리 판별로 넓히면요?

트리가 자기 거울상과 같은지 보면 된다. 실제로 뒤집어 비교하면 원본이 바뀌니, 왼쪽 가지와 오른쪽 가지를 동시에 내려가며 바깥쪽끼리(왼쪽의 왼쪽과 오른쪽의 오른쪽), 안쪽끼리 비교한다. 시간 O(n), 공간 O(h)이다.

### BST를 뒤집으면 여전히 BST인가요?

크기 관계가 반대가 된 BST가 된다. 원래 왼쪽이 작고 오른쪽이 컸다면, 뒤집은 뒤에는 왼쪽이 크고 오른쪽이 작다. 중위 순회 결과가 오름차순에서 내림차순으로 바뀐다. 그래서 일반적인 BST 탐색 코드를 그대로 쓰면 잘못된 방향으로 내려간다.
