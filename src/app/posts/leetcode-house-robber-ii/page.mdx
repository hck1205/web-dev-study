[House Robber II](https://leetcode.com/problems/house-robber-ii/)는 LeetCode 213번이다. [House Robber](/posts/leetcode-house-robber)에서 집 배열의 양 끝을 이어 붙여 원으로 만든 문제다. 점화식은 하나도 바뀌지 않는다. 바뀌는 건 "원을 어떻게 일직선으로 바꾸느냐"이고, 이 생각은 원형 배열이 나오는 다른 문제에서도 그대로 쓰인다.

일직선 문제의 점화식, 두 변수 풀이, take / skip 상태는 앞 글에서 자세히 다뤘으니 여기서는 짧게 가져다 쓴다. DP 자체가 처음이라면 [동적 계획법 글](/posts/dynamic-programming)을 먼저 보는 게 좋다. 이 글은 원형 조건을 그대로 다 따지는 풀이부터 시작해서 원을 끊는 풀이까지 다섯 가지를 놓고, 끊는 방법이 왜 맞는지를 따로 짚는다. 코드는 Node.js 22, Python 3, Java 21에서 직접 돌렸다.

## 첫 집과 마지막 집이 이웃이 된다

음이 아닌 정수 배열 `nums`가 원형으로 놓여 있다. 인덱스 차이가 1인 두 칸에 더해 0번과 마지막 칸(n-1번)도 이웃이다. 이웃한 두 칸을 함께 고르지 않으면서 고른 값의 합을 최대로 만들고, 그 합을 돌려준다.

제약은 길이 1 이상 100 이하, 값 0 이상 1000 이하다. 길이가 100이라 모든 조합을 보는 건 안 되고 O(n)이면 충분하다. 합은 많아야 100 × 1000 = 100,000이라 어느 언어든 `int`로 된다.

길이 1이 경계다. 집이 하나면 0번과 n-1번이 같은 집이라 "자기 자신과 이웃"인 이상한 모양이 되는데, LeetCode는 이 경우 그 집을 열 수 있다고 본다. `[5]`의 답은 5다.

## 여섯 집을 둥글게 놓고 손으로 풀어 본다

글 끝까지 쓸 예시다.

```text
인덱스   0   1   2   3   4   5
nums     6   2   3   7   1   5
          ↖___________________↗   0번과 5번도 이웃
```

원으로 그리면 이렇다. 선으로 이어진 두 집은 함께 열 수 없다. 점선이 일직선 문제에는 없던 이음매다.

일직선이라면 0, 3, 5번을 골라 6 + 7 + 5 = 18이 최대다. 그런데 원형에서는 0번과 5번이 붙어 있어서 이 조합이 안 된다. 원형 조건을 지키는 조합을 몇 개 대 보자.

```text
1, 3, 5   → 2 + 7 + 5 = 14
0, 3      → 6 + 7     = 13
0, 2, 4   → 6 + 3 + 1 = 10
2, 5      → 3 + 5     = 8
1, 3      → 2 + 7     = 9
```

답은 14다. 일직선 답 18에서 무언가 하나를 빼서 고치는 방식으로는 이 14가 잘 안 나온다. 바로 다음 절의 이야기다.

## 일직선 답을 고쳐 쓰면 틀린다

처음 떠오르기 쉬운 생각은 "일단 일직선으로 풀고, 첫 집과 마지막 집을 둘 다 골랐으면 그중 작은 쪽을 뺀다"다.

```text
일직선 최적  0, 3, 5  → 18
작은 끝(5) 빼기  0, 3  → 13
```

13이 나온다. 답은 14다. 5번을 빼면 4번이 비어 있어도 이미 고른 집 구성이 그대로라, 그 자리에 다른 집을 넣어 더 좋게 만들 기회를 놓친다. 실제 답 1, 3, 5번은 0번을 버리는 대신 1번을 새로 고른 조합이라, 일직선 최적에서 출발해 한 칸을 지우는 것만으로는 닿지 않는다.

또 하나는 "첫 집과 마지막 집을 둘 다 빼고 가운데만 푼다"다. 0번과 5번 둘 다 안 쓰니 원형 조건은 확실히 지켜진다. 하지만 예시에서는 2, 3, 7, 1만 남아 2 + 7 = 9가 나온다. 두 끝 중 하나는 써도 되는데 둘 다 버려서 너무 많이 잃었다. `[1, 2, 3, 1]`에서도 3이 나오는데 답은 1 + 3 = 4다.

두 실수 모두 "끝 집 하나를 빼면 나머지 선택이 달라진다"는 걸 놓친다. 그래서 끝 집을 어떻게 처리할지를 먼저 정하고, 그 조건 아래에서 처음부터 다시 풀어야 한다.

## 모든 조합을 원형 조건까지 대 본다

정답을 확인하는 용도로 가장 먼저 쓸 수 있는 건 전부 대 보는 방법이다. 집 n개의 선택을 n비트 정수 하나로 나타낸다. i번 비트가 1이면 i번 집을 연다.

비트로 이웃 조건을 검사하는 법이 간단하다. `m & (m >> 1)`이 0이 아니면 붙어 있는 두 비트가 함께 켜진 것이다. 원형 조건은 0번 비트와 n-1번 비트가 둘 다 켜졌는지 따로 본다.

```js
function rob(nums) {
  const n = nums.length;
  if (n === 1) return nums[0];          // 집 하나는 그냥 연다
  let best = 0;
  for (let m = 0; m < (1 << n); m++) {
    if (m & (m >> 1)) continue;          // 일직선 이웃이 함께 켜짐
    if ((m & 1) && ((m >> (n - 1)) & 1)) continue; // 첫 집과 마지막 집이 함께 켜짐
    let sum = 0;
    for (let i = 0; i < n; i++) if ((m >> i) & 1) sum += nums[i];
    best = Math.max(best, sum);
  }
  return best;
}
```

예시에서 14가 나왔다. 시간은 조합 2ⁿ개에 합 계산 n번이라 O(2ⁿ × n), 공간은 O(1)이다. JavaScript의 비트 연산은 32비트라 n이 31을 넘으면 `1 << n`부터 깨지고, 그 전에 2^25쯤만 돼도 몇 초가 걸린다. 길이 100은 꿈도 못 꾼다.

그래도 이 코드는 쓸모가 있다. 뒤에 나오는 빠른 풀이를 짤 때 길이 12 정도의 무작위 배열 수천 개를 만들어 이 코드와 답을 비교하면, 경계 처리 실수가 금방 드러난다. 이 글의 풀이도 모두 그렇게 맞춰 봤다.

## 첫 집을 열었는지 기억하며 내려간다

전부 대 보는 풀이가 느린 이유는 같은 질문을 계속 다시 하기 때문이다. 일직선 문제에서는 "i번 집부터 끝까지에서 얻는 최댓값"을 한 번만 구해 적어 두면 됐다. 원형에서는 같은 i번이라도 답이 하나로 정해지지 않는다. 첫 집을 열었다면 마지막 집은 못 열고, 안 열었다면 열 수 있다.

그러면 그 사실을 상태에 같이 넣으면 된다. `go(i, firstTaken)`은 "첫 집을 열었는지가 firstTaken일 때, i번 집부터 끝까지에서 얻는 최댓값"이다.

1. 맨 처음에는 0번 집 앞에서 두 갈래로 나뉜다. 열면 `nums[0] + go(2, true)`, 안 열면 `go(1, false)`.
2. 그 뒤로는 일직선과 같다. `go(i) = max(go(i+1), nums[i] + go(i+2))`.
3. 다른 점은 마지막 집 하나뿐이다. firstTaken이 참이고 i가 n-1이면 그 집은 열 수 없으니 0이다.

```js
function rob(nums) {
  const n = nums.length;
  if (n === 1) return nums[0];
  const memo = [new Map(), new Map()];   // firstTaken = false / true 각각의 메모
  function go(i, firstTaken) {
    if (i >= n) return 0;                       // 집이 더 없다
    if (i === n - 1 && firstTaken) return 0;    // 첫 집을 열었으면 마지막 집은 못 연다
    const m = memo[firstTaken ? 1 : 0];
    if (m.has(i)) return m.get(i);
    const res = Math.max(
      go(i + 1, firstTaken),            // 이 집을 지나친다
      nums[i] + go(i + 2, firstTaken),  // 이 집을 연다
    );
    m.set(i, res);
    return res;
  }
  return Math.max(go(1, false), nums[0] + go(2, true));
}
```

상태가 `(i, firstTaken)`라 많아야 2n개이고, 상태마다 O(1)만 일하니 시간 O(n)이다. 메모가 2n칸, 재귀 깊이가 n이라 공간도 O(n)이다. 길이 100이라 재귀 깊이는 걱정할 일이 없다.

메모를 "안 구함 = 0"으로 두지 않고 `Map`의 `has`로 확인한 이유는 앞 글에서 짚은 것과 같다. 값이 0인 집이 이어지면 실제 답이 0인 칸을 계속 다시 계산하게 된다.

이 풀이는 원형 조건을 정면으로 다룬다는 장점이 있다. 조건을 그대로 상태에 담았으니 왜 맞는지 설명하기 쉽다. 그런데 코드를 다시 보면 firstTaken이 참인 갈래와 거짓인 갈래가 서로 섞이지 않는다. 처음 한 번 갈라진 뒤에는 각자 일직선 문제를 푸는 것과 똑같다. 그렇다면 처음부터 일직선 문제 두 개로 나눠 푸는 게 더 단순하다.

## 원을 한 군데 끊으면 일직선이 된다

원형 조건이 일직선과 다른 건 0번과 n-1번이 이웃이라는 것 하나다. 이웃이니 둘을 함께 고르는 답은 없다. 바꿔 말하면 어떤 올바른 답이든 아래 둘 중 적어도 하나에 들어간다.

- A: 0번 집을 안 연 답. 0번을 지우면 1번부터 n-1번까지의 일직선이 남는다.
- B: n-1번 집을 안 연 답. n-1번을 지우면 0번부터 n-2번까지의 일직선이 남는다.

거꾸로도 성립한다. A 쪽 일직선에서 고른 조합은 0번이 아예 없으니, 원으로 되돌려 놓아도 0번과 n-1번이 함께 골라지는 일이 없다. B도 마찬가지다. 그래서 A 쪽 일직선 최댓값과 B 쪽 일직선 최댓값 중 큰 쪽이 원형 답이다. 둘 다 안 연 답은 A와 B에 모두 들어가지만, 최댓값을 구할 때는 두 번 세도 상관없다.

예시에 대 보면 이렇다.

```text
A: 0번 빼기   [2, 3, 7, 1, 5]  → 2 + 7 + 5 = 14
B: 5번 빼기   [6, 2, 3, 7, 1]  → 6 + 7     = 13
답 = max(14, 13) = 14
```

앞 절의 메모 풀이와 비교하면, `go(1, false)`가 A이고 `nums[0] + go(2, true)`는 B의 일부다. B에는 0번을 안 연 경우도 들어 있으니 B가 조금 더 넓지만, 그 부분은 A에도 있어서 최댓값은 같다.

일직선 풀이를 표로 두 번 돌리면 이렇게 된다. 표의 `dp[k]`는 "구간 앞에서부터 k개 집을 봤을 때의 최댓값"이고, `dp[0] = 0`을 두면 첫 칸을 따로 처리하지 않아도 된다.

```js
function robLine(nums, lo, hi) {
  const len = hi - lo + 1;
  const dp = new Array(len + 1).fill(0); // dp[k] = 구간의 앞 k개 집까지의 최댓값
  for (let k = 1; k <= len; k++) {
    const take = (k >= 2 ? dp[k - 2] : 0) + nums[lo + k - 1]; // k번째 집을 연다
    dp[k] = Math.max(dp[k - 1], take);                        // 지나친다 vs 연다
  }
  return dp[len];
}

function rob(nums) {
  const n = nums.length;
  if (n === 1) return nums[0];          // 두 구간이 모두 비어 버리는 경우
  return Math.max(robLine(nums, 1, n - 1), robLine(nums, 0, n - 2));
}
```

시간은 일직선 풀이를 두 번 돌리니 O(2n) = O(n)이고, 표 때문에 공간이 O(n)이다. 배열을 잘라 복사하지 않고 `lo`, `hi` 인덱스만 넘겼다. 표가 남아 있으니 어느 집을 열었는지 되짚을 수 있다는 장점이 있지만, 답만 필요하면 표 전체를 들고 있을 이유가 없다.

`n === 1` 처리가 왜 필요한지 보자. n이 1이면 A 구간은 1부터 0, B 구간은 0부터 -1이라 둘 다 비어서 0이 나온다. 그런데 답은 `nums[0]`이다. 원을 끊는 생각은 "0번과 n-1번이 서로 다른 집"이라는 전제 위에 서 있어서, 둘이 같은 집인 n = 1에서는 성립하지 않는다.

### 0번과 n-1번 사이가 아니어도 끊을 수 있다

끊는 자리가 꼭 배열의 이음매일 필요는 없다. 원 위의 아무 이웃 쌍 (i, i+1)을 골라도 "둘 중 하나는 안 연다"가 성립하니, i번을 뺀 일직선과 i+1번을 뺀 일직선을 풀면 된다. 예시를 2번과 3번 사이에서 끊어 `[7, 1, 5, 6, 2, 3]`처럼 돌려 놓고 같은 방법을 써도 14가 나온다. 여섯 군데 어디서 끊어도 14였다.

배열에서는 0번과 n-1번 사이를 끊는 게 인덱스 계산이 가장 단순해서 그렇게 쓸 뿐이다. 이 사실을 알면 "원형 버퍼의 시작 위치가 바뀌면 답이 바뀌나" 같은 꼬리 질문에 바로 아니라고 답할 수 있다. 원은 어디서 읽기 시작하든 같은 원이다.

## 두 구간을 기록 두 개씩으로 걷는다

일직선 풀이의 점화식 `dp[k] = max(dp[k-1], dp[k-2] + x)`는 앞의 두 칸만 본다. 표 대신 변수 `prev`(두 집 앞까지), `cur`(바로 앞 집까지) 두 개면 충분하다. 이 부분은 [House Robber 글](/posts/leetcode-house-robber)의 두 변수 풀이 그대로다. 그걸 구간 두 개에 한 번씩 쓴다.

```js
function rob(nums) {
  const n = nums.length;
  if (n === 1) return nums[0];           // 집 하나는 자기 자신과 이웃이 아니다
  return Math.max(
    robLine(nums, 1, n - 1),             // A: 첫 집을 안 연다
    robLine(nums, 0, n - 2),             // B: 마지막 집을 안 연다
  );
}

function robLine(nums, lo, hi) {
  let prev = 0; // 두 집 앞까지의 최댓값
  let cur = 0;  // 바로 앞 집까지의 최댓값
  for (let i = lo; i <= hi; i++) {
    const next = Math.max(cur, prev + nums[i]); // 지나친다 vs 연다
    prev = cur;
    cur = next;
  }
  return cur;
}
```

두 기록을 0으로 시작하는 게 왜 편한지도 한 번 짚자. 구간 앞에 "돈이 0인 가상의 집 두 채"를 붙여 놓은 것과 같아서, 구간 길이가 1이든 2든 반복문만으로 답이 나온다. 길이 2짜리 원형 `[3, 9]`에서는 A가 `[9]`로 9, B가 `[3]`으로 3, 답 9다.

## 반복 한 번에 두 구간을 같이 민다

두 구간은 1번부터 n-2번까지가 겹친다. 배열을 두 번 읽는 게 마음에 걸리면, 반복문 하나에서 기록 네 개를 함께 밀 수 있다. i가 1 이상이면 A의 기록을, i가 n-2 이하이면 B의 기록을 갱신한다.

```js
function rob(nums) {
  const n = nums.length;
  if (n === 1) return nums[0];
  let p1 = 0, c1 = 0; // A: 1..n-1 구간의 두 기록
  let p2 = 0, c2 = 0; // B: 0..n-2 구간의 두 기록
  for (let i = 0; i < n; i++) {
    const x = nums[i];
    if (i >= 1) {                       // A 구간 안
      const next = Math.max(c1, p1 + x);
      p1 = c1; c1 = next;
    }
    if (i <= n - 2) {                   // B 구간 안
      const next = Math.max(c2, p2 + x);
      p2 = c2; c2 = next;
    }
  }
  return Math.max(c1, c2);
}
```

예시에서 14가 나왔고, 길이 1부터 12까지 무작위 배열 3,000개에서 앞의 네 풀이와 답이 모두 같았다. 복잡도는 O(n) 시간, O(1) 공간으로 앞 풀이와 같다. 배열을 한 번만 읽으니 값이 하나씩 흘러 들어오는 상황에 가깝지만, "어디가 마지막 집인지"를 미리 알아야 B를 멈출 수 있다는 점은 남는다. 그래서 진짜 스트림에서는 B를 하나 늦게 갱신하는 식으로 바꿔야 하고, 코드를 읽는 사람에게는 앞 풀이가 더 분명하다. 면접에서는 앞 풀이를 쓰고 "한 번에 할 수도 있다"고 말로 덧붙이는 정도면 된다.

## Python 슬라이스와 Java 인덱스

```python
from typing import List

class Solution:
    def rob(self, nums: List[int]) -> int:
        if len(nums) == 1:              # 집 하나는 그냥 연다
            return nums[0]

        def line(arr: List[int]) -> int:
            prev, cur = 0, 0            # 두 집 앞까지, 바로 앞 집까지의 최댓값
            for x in arr:
                prev, cur = cur, max(cur, prev + x)
            return cur

        # A: 첫 집 빼기, B: 마지막 집 빼기
        return max(line(nums[1:]), line(nums[:-1]))
```

`nums[1:]`와 `nums[:-1]`은 새 리스트를 만든다. 길이 100이라 상관없지만, 복사 없이 하려면 Java 코드처럼 시작과 끝 인덱스를 넘기면 된다. 슬라이스는 길이 1에서도 에러 없이 빈 리스트를 돌려주기 때문에, `len(nums) == 1` 처리를 빼먹어도 예외가 나지 않고 조용히 0이 나온다. 테스트에 `[5]`를 꼭 넣어야 잡힌다. 예시 입력에 14, `[1, 2, 3, 1]`에 4, `[5]`에 5가 나왔다.

```java
class Solution {
    public int rob(int[] nums) {
        int n = nums.length;
        if (n == 1) return nums[0];                        // 집 하나는 그냥 연다
        return Math.max(line(nums, 1, n - 1), line(nums, 0, n - 2)); // A, B
    }

    private int line(int[] nums, int lo, int hi) {
        int prev = 0, cur = 0;                             // 두 집 앞까지, 바로 앞 집까지
        for (int i = lo; i <= hi; i++) {
            int next = Math.max(cur, prev + nums[i]);      // 지나친다 vs 연다
            prev = cur;
            cur = next;
        }
        return cur;
    }
}
```

Java는 `Arrays.copyOfRange`로 잘라도 되지만 인덱스를 넘기는 쪽이 복사가 없다. 합이 많아야 100,000이라 `int`로 충분하고, 값 범위가 커져 21억을 넘을 수 있으면 `long`으로 바꾼다. 세 언어 모두 결과가 같았다.

## 다섯 풀이를 끊는 방식으로 나눠 보면

| 풀이 | 시간 | 추가 공간 | 언제 고르나 |
|---|---|---|---|
| 비트마스크로 모든 조합 | O(2ⁿ × n) | O(1) | n이 20 안쪽일 때 정답 확인용 |
| 첫 집 여부를 상태에 넣은 메모 | O(n) | O(n) | 원형 조건을 그대로 상태로 옮기고 싶을 때 |
| 두 구간을 표로 | O(n) | O(n) | 어느 집을 열었는지 되짚어야 할 때 |
| 두 구간을 두 변수로 | O(n) | O(1) | 기본 답. 일직선 함수를 재사용한다 |
| 반복 한 번에 네 기록 | O(n) | O(1) | 배열을 한 번만 읽어야 할 때 |

메모 풀이는 "원형 조건을 상태로 들고 다닌다", 아래 셋은 "원을 먼저 끊고 일직선을 푼다"다. 두 생각은 같은 계산을 다른 순서로 한 것이라 답도 복잡도도 같다. 다만 끊는 쪽은 이미 검증된 일직선 함수를 그대로 쓸 수 있어서 코드가 짧고 틀릴 곳이 적다.

## 원형에서 자주 나오는 실수

### 집이 하나일 때 0을 돌려주는 경우

```js
function rob(nums) {
  const n = nums.length;
  // n === 1 처리가 없다
  return Math.max(robLine(nums, 1, n - 1), robLine(nums, 0, n - 2));
}
```

`[5]`에서 0이 나온다. 두 구간이 모두 비기 때문이다. Python 슬라이스처럼 에러가 나지 않는 언어에서는 더 찾기 어렵다. 원을 끊는 풀이를 쓰면 이 한 줄은 늘 따라다닌다고 외워 두는 게 낫다.

### 양 끝을 둘 다 빼는 경우

```js
function rob(nums) {
  const n = nums.length;
  if (n === 1) return nums[0];
  return robLine(nums, 1, n - 2);       // 0번과 n-1번을 둘 다 버렸다
}
```

원형 조건은 확실히 지키지만 너무 많이 버린다. 예시에서 9(답 14), `[1, 2, 3, 1]`에서 3(답 4), `[2, 3, 2]`에서 3이 나온다. 마지막처럼 우연히 맞는 입력이 있어서 몇 개만 돌려 보면 통과해 버린다. "둘 다 안 연다"가 아니라 "둘 중 하나는 안 연다"가 조건이다.

### 일직선 답에서 작은 끝을 빼는 경우

앞에서 손으로 보였다. 예시에서 13이 나온다. 한 집을 빼면 나머지 최적 구성도 바뀔 수 있다는 걸 놓친 탐욕이다. 끝 집을 어떻게 할지 먼저 정하고 다시 푸는 수밖에 없다.

### 구간 끝을 하나 잘못 잡는 경우

`robLine(nums, 1, n)`처럼 끝을 n으로 주면 `nums[n]`이 `undefined`라 `prev + undefined`가 `NaN`이 되고, `Math.max`에 `NaN`이 섞이면 결과도 `NaN`이다. 반대로 `robLine(nums, 0, n - 3)`처럼 하나 더 줄이면 B 구간이 n-2번 집을 놓친다. 구간을 "닫힌 구간 lo부터 hi까지"로 정했으면 호출하는 쪽도 그 규칙으로 맞춘다.

## 원이 다른 모양으로 바뀌면

### 원형에서 가능한 선택의 수를 세라면

최댓값 대신 "이웃 없이 고르는 방법이 몇 가지인가"를 물으면 끊는 방법을 그대로 쓰면 안 된다. 둘 다 안 연 선택이 A와 B에 모두 들어가 두 번 세이기 때문이다. 포함-배제로 `A의 수 + B의 수 - 둘 다 안 연 경우의 수`를 계산한다. 길이 m 일직선에서 고르는 방법의 수는 피보나치 수 F(m+2)라서, 집 6채 원형이면 13 + 13 - 8 = 18이다. 비트마스크로 전부 세어 봐도 18이 나왔다. 최댓값은 겹쳐도 되고 개수는 겹치면 안 된다는 차이를 말할 수 있으면 좋은 꼬리 답이 된다.

### 어느 집을 열었는지도 알려 달라면

두 구간을 표로 푼 뒤 큰 쪽 표에서 끝부터 되짚는다. `dp[k]`가 `dp[k-1]`과 같으면 그 집은 지나친 것이고, 다르면 연 것이라 두 칸 앞으로 간다. 되짚은 위치 k를 `lo + k - 1`로 바꿔 원래 번호로 돌려놓는 걸 잊지 않는다.

```js
function robWithPath(nums) {
  const n = nums.length;
  if (n === 1) return { sum: nums[0], picked: [0] };
  function line(lo, hi) {
    const len = hi - lo + 1;
    const dp = new Array(len + 1).fill(0);
    for (let k = 1; k <= len; k++) {
      dp[k] = Math.max(dp[k - 1], (k >= 2 ? dp[k - 2] : 0) + nums[lo + k - 1]);
    }
    const picked = [];
    let k = len;
    while (k >= 1) {
      if (dp[k] === dp[k - 1]) k -= 1;          // k번째 집은 지나쳤다
      else { picked.push(lo + k - 1); k -= 2; } // 열었다. 원래 인덱스로 바꿔 적는다
    }
    return { sum: dp[len], picked: picked.reverse() };
  }
  const a = line(1, n - 1);   // A: 첫 집 빼기
  const b = line(0, n - 2);   // B: 마지막 집 빼기
  return a.sum >= b.sum ? a : b;
}
```

```text
[6, 2, 3, 7, 1, 5]        → { sum: 14,  picked: [1, 3, 5] }
[1, 2, 3, 1]              → { sum: 4,   picked: [0, 2] }
[200, 3, 140, 20, 10]     → { sum: 340, picked: [0, 2] }
```

첫 줄은 A 쪽에서, 둘째와 셋째 줄은 B 쪽에서 나왔다. 셋째 줄에서 `lo`를 더하지 않았다면 B는 `lo`가 0이라 우연히 맞고, A 쪽 답이었던 첫 줄은 0, 2, 4로 한 칸씩 밀려 틀린다. 공간은 표 두 개라 O(n)이 든다.

### 이웃 조건이 k칸으로 늘어나면

원형에서 최소 k칸 떨어져야 한다면 끝 쪽에서 서로 막는 집이 k-1채씩 생긴다. 0번 집을 연다고 정하면 n-k+1번부터 n-1번까지를 못 쓰고, 안 연다고 정하면 1번부터 일직선이다. 이렇게 "0번 집을 여나 안 여나"로 나누는 쪽이 일반적이다. k = 2면 이 글의 메모 풀이와 같은 모양이다.

LeetCode 918 Maximum Sum Circular Subarray도 원을 다룬다. 다만 거기서는 "끝을 넘어가는 구간"과 "안 넘어가는 구간"으로 나누고, 넘어가는 구간은 전체 합에서 가운데 최소 부분합을 빼서 구한다. 원을 경우 두 개로 쪼개서 각각 일직선으로 푼다는 뼈대는 같다. 원형 배열을 한 바퀴 도는 다른 예로는 [Gas Station](/posts/leetcode-gas-station)이 있다.

## 면접에서 나올 만한 질문

### 원형 조건을 어떻게 처리했나요?

첫 집과 마지막 집은 이웃이라 둘 중 하나는 반드시 안 연다는 점을 썼다. 그래서 첫 집을 뺀 일직선과 마지막 집을 뺀 일직선을 각각 House Robber로 풀고 큰 쪽을 답으로 냈다. 어떤 올바른 답이든 둘 중 한쪽에 들어가고, 각 쪽의 답은 원으로 되돌려도 조건을 어기지 않는다.

### 둘 다 안 연 경우가 양쪽에 겹치는데 괜찮나요?

최댓값을 구할 때는 괜찮다. 같은 후보를 두 번 봐도 최댓값은 변하지 않는다. 경우의 수를 세는 문제라면 두 번 세이므로 둘 다 안 연 경우의 수를 한 번 빼야 한다.

### 길이 1은 왜 따로 처리하나요?

n이 1이면 두 구간이 모두 비어 0이 나오는데, 답은 그 집 하나의 값이다. 끊는 방법은 첫 집과 마지막 집이 서로 다른 집이라는 전제가 있어야 성립해서, 둘이 같은 집인 길이 1에서는 맞지 않는다. 길이 2부터는 특별 처리 없이 맞는다.

### 일직선 답에서 양 끝을 둘 다 골랐을 때 작은 쪽만 빼면 안 되나요?

안 된다. 한 집을 빼면 그 옆 집을 새로 고를 수 있게 되는 등 나머지 최적 구성이 달라진다. `[6, 2, 3, 7, 1, 5]`는 일직선 답 18에서 5를 빼면 13이지만, 실제 답은 6을 버리고 2를 새로 고른 14다.

### 시간과 공간 복잡도는요?

일직선 풀이를 두 번 돌리니 시간은 O(n)이다. 각 일직선은 앞의 두 기록만 들고 가서 공간은 O(1)이다. 배열을 잘라 복사하면 O(n) 공간이 생기니 시작과 끝 인덱스를 넘기는 편이 낫다.

### 끊지 않고 원형 그대로 DP를 짤 수는 없나요?

짤 수 있다. "첫 집을 열었는가"를 상태에 넣어 `(i, firstTaken)`으로 메모하면 마지막 집에서만 그 상태를 보고 막으면 된다. 상태가 2n개라 O(n)이다. 다만 두 갈래가 처음 갈린 뒤 섞이지 않아서, 결국 일직선 두 번과 같은 계산이 된다.
