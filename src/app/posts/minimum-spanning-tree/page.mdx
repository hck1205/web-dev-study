사내망 공사 견적을 받았다고 해 보자. 지점 일곱 곳을 광케이블로 이어서 어느 지점에서든 다른 지점에 닿게 해야 한다. 두 지점 사이에 케이블을 깔 수 있는 구간이 열한 개 있고 구간마다 비용이 다르다. 열한 개를 다 깔면 당연히 통한다. 문제는 몇 개를 빼도 여전히 다 통하는지, 그중 가장 싼 조합이 무엇인지다.

이 조합을 최소 신장 트리(Minimum Spanning Tree, MST)라고 부른다. 크루스칼 알고리즘은 [유니온 파인드 글](/posts/ds-union-find)에서 고리 검사의 예로 한 번 돌려 봤다. 이 글은 그다음 질문들에 답한다. 왜 싼 것부터 고르기만 하면 정답인가, 출발점이 있는 프림은 왜 같은 답을 내나, 같은 비용의 선이 여럿이면 어떻게 되나, 그리고 면접에서 가장 많이 헷갈리는 질문, 최소 신장 트리와 최단 경로는 무엇이 다른가.

예제는 모두 같은 지도를 쓴다. 지점은 A부터 G까지, 구간과 비용은 A-B 7, A-D 5, B-C 8, B-D 9, B-E 7, C-E 5, D-E 15, D-F 6, E-F 8, E-G 9, F-G 11이다. 출력은 Node 22에서 직접 돌린 것이다.

## 고리 없이 모두 잇는 선 n-1개

그래프의 신장 트리(spanning tree)는 모든 정점을 포함하면서 고리가 없는 간선 부분집합이다. "신장"은 모든 정점에 뻗어 있다는 뜻이다. 정점이 n개면 신장 트리의 간선은 정확히 n - 1개다. 하나라도 적으면 떨어진 정점이 생기고, 하나라도 많으면 고리가 생긴다.

트리에는 쓸모 있는 성질이 하나 더 있다. 두 정점 사이를 잇는 경로가 정확히 하나뿐이다. 경로가 둘이면 그 둘이 고리를 만들기 때문이다. 뒤에서 병목 경로와 간선 추가를 다룰 때 이 성질을 쓴다.

고리가 있으면 왜 손해인지는 바로 보인다. 고리 위의 간선 하나를 빼도 나머지 길로 양끝이 여전히 이어진다. 비용이 양수라면 빼는 쪽이 무조건 싸다. 그래서 가장 싼 "모두 잇기"는 반드시 트리 모양이다.

신장 트리는 몇 개나 될까. 모든 쌍이 이어진 완전 그래프라면 케일리 공식으로 n^(n-2)개다. 정점 4개면 16개, 10개면 1억 개다. 다 만들어 보고 가장 싼 것을 고르는 방법은 정점이 스무 개만 넘어도 끝나지 않는다. 그런데 이 문제는 그리디로 정확히 풀린다. [그리디 알고리즘 글](/posts/greedy-algorithms)에서 말한 "그리디가 맞는 드문 경우"의 대표가 이것이다.

## 둘로 가르면 가장 싼 다리는 반드시 들어간다

정점을 아무렇게나 두 편으로 나눠 보자. 이렇게 나눈 것을 컷(cut)이라고 하고, 양 편을 잇는 간선을 컷을 건너는 간선이라고 한다. 컷 속성은 이렇다. 어떤 컷이든 그 컷을 건너는 간선 중 가장 싼 것은 어떤 최소 신장 트리에 반드시 들어 있다. 가장 싼 것이 하나뿐이면 모든 최소 신장 트리에 들어 있다.

증명은 바꿔치기 한 번이면 된다. 어떤 최소 신장 트리 T가 가장 싼 다리 e를 안 쓴다고 하자. T에 e를 더하면 고리가 하나 생긴다. 그 고리는 컷의 한쪽에서 다른 쪽으로 e를 타고 건넜다가 다시 돌아와야 하니, 컷을 건너는 다른 간선 f가 고리 위에 있다. f를 빼고 e를 넣으면 여전히 신장 트리이고, e가 가장 싸니 비용은 같거나 줄어든다. 그러니 e를 쓰는 최소 신장 트리가 있다.

뒤집은 성질도 있다. 고리 속성은 어떤 고리에서든 가장 비싼 간선이 하나뿐이라면 그 간선은 어떤 최소 신장 트리에도 없다는 것이다. 빼도 고리의 나머지로 이어지니까.

이 두 성질이 크루스칼과 프림의 정당성 전부다. 두 알고리즘은 "어떤 컷을 보느냐"만 다르다.

## 싼 선부터 줍는 크루스칼

크루스칼은 간선을 비용 순으로 정렬해 싼 것부터 본다. 양끝이 아직 다른 덩어리면 고르고, 같은 덩어리면 버린다. 어떤 간선을 고를 때, 그 간선 한쪽 끝이 속한 덩어리와 나머지를 가르는 컷을 생각하면 이 간선이 그 컷을 건너는 가장 싼 간선이다. 더 싼 간선은 이미 다 봤고, 그중 이 컷을 건너는 게 있었다면 두 덩어리가 이미 붙어 있었을 테니까. 그래서 컷 속성에 따라 고른 간선은 모두 정답에 들어간다.

같은 덩어리인지 묻는 일은 [유니온 파인드](/posts/ds-union-find)가 거의 상수 시간에 한다. 유니온 파인드 자체의 크기 규칙과 경로 압축은 그 글에 있고, 여기서는 크루스칼 쪽 뼈대만 적는다.

```js
function kruskal(n, edges) {
  const parent = Array.from({ length: n }, (_, i) => i);
  const find = (x) => {
    while (parent[x] !== x) {
      parent[x] = parent[parent[x]];          // 경로 절반화
      x = parent[x];
    }
    return x;
  };
  const sorted = [...edges].sort((p, q) => p[2] - q[2] || p[0] - q[0] || p[1] - q[1]); // 동점은 정점 번호로
  const chosen = [];
  let total = 0;
  for (const [u, v, w] of sorted) {
    const ru = find(u), rv = find(v);
    if (ru === rv) continue;                  // 이미 같은 덩어리: 고르면 고리
    parent[ru] = rv;
    chosen.push([u, v, w]);
    total += w;
    if (chosen.length === n - 1) break;       // 간선 n-1개면 끝
  }
  return { total, chosen, connected: chosen.length === n - 1 };
}
```

정렬 비교 함수의 뒤쪽 두 조건은 동점 간선의 순서를 고정한다. 없어도 답의 비용은 같지만, 같은 입력에 늘 같은 간선 집합을 내야 테스트와 로그를 비교하기 쉽다. 같은 지도에 돌리면서 고르고 버릴 때마다 한 줄씩 찍었다.

```text
take A-D(5)
take C-E(5)
take D-F(6)
take A-B(7)
take B-E(7)
skip B-C(8)
skip E-F(8)
skip B-D(9)
take E-G(9)
total 39 A-D(5) C-E(5) D-F(6) A-B(7) B-E(7) E-G(9)
```

간선 6개를 고르는 순간 멈췄다. F-G 11과 D-E 15는 보지도 않았다. 시간은 정렬하는 O(E log E)가 대부분이고, E log E와 E log V는 같은 꼴이다(E가 V²을 넘지 않으니 log E는 2 log V 이하다). 간선이 이미 정렬돼 들어오면 거의 O(E)에 끝난다.

크루스칼은 트리 하나를 키우지 않는다. 중간에는 덩어리 여러 개가 숲처럼 흩어져 있다가 마지막에 하나로 붙는다. 위 출력에서 A-D와 C-E는 서로 멀리 떨어진 두 덩어리로 시작했다.

## 트리를 한 칸씩 키우는 프림

프림은 정점 하나에서 출발해 트리를 키운다. 매번 "지금 트리에 든 정점"과 "아직 밖에 있는 정점"을 가르는 컷을 보고, 그 컷을 건너는 가장 싼 간선을 붙인다. 컷 속성을 그대로 코드로 옮긴 셈이다. 가장 싼 바깥 간선을 빨리 찾으려고 [힙](/posts/ds-heap)을 쓴다.

```js
function prim(adj, start) {
  const inTree = new Array(adj.length).fill(false);
  const heap = new MinHeap();                 // [비용, 바깥 정점, 트리 쪽 정점]
  inTree[start] = true;
  for (const [v, w] of adj[start]) heap.push([w, v, start]);
  let total = 0;
  const chosen = [];
  while (heap.size && chosen.length < adj.length - 1) {
    const [w, v, u] = heap.pop();
    if (inTree[v]) continue;                  // 양끝이 다 트리 안이면 고리가 된다. 버린다
    inTree[v] = true;
    total += w;
    chosen.push([u, v, w]);
    for (const [x, wx] of adj[v]) if (!inTree[x]) heap.push([wx, x, v]); // 새로 생긴 바깥 간선
  }
  return { total, chosen };
}
```

A에서 출발해 돌렸다. 고를 때마다 힙에 남은 후보 수를 함께 찍었다.

```text
take A-D(5) heap 1
take D-F(6) heap 3
take A-B(7) heap 4
take B-E(7) heap 5
take E-C(5) heap 6
skip B-C(8)
skip F-E(8)
skip D-B(9)
take E-G(9) heap 2
total 39 A-D(5) D-F(6) A-B(7) B-E(7) E-C(5) E-G(9)
```

## 같은 비용의 선이 여럿이면 답도 여럿이다

모든 간선 비용이 서로 다르면 최소 신장 트리는 하나뿐이다. 같은 비용이 있으면 여러 개일 수 있다. 네 정점을 고리 모양으로 잇고 네 간선 비용을 모두 1로 뒀다.

```text
kruskal 3 A-B B-C C-D
prim from A 3 A-B A-D B-C
```

크루스칼은 D-A를 뺐고, A에서 출발한 프림은 C-D를 뺐다. 둘 다 맞는 답이다. 정렬 방식이나 힙의 동점 처리가 조금만 달라도 빠지는 간선이 바뀌고, 이 그래프의 최소 신장 트리는 어느 간선을 빼느냐에 따라 네 개다. 비용은 모두 3이다.

정답이 여럿이어도 변하지 않는 것이 있다. 총비용은 같고, 고른 간선의 비용을 정렬한 목록도 모든 최소 신장 트리에서 같다. 테스트를 쓸 때 간선 목록을 비교하면 구현이나 언어 버전에 따라 깨질 수 있으니 총비용으로 비교하거나, 동점일 때 정점 번호로 순서를 고정한다. [최단 경로 글](/posts/shortest-path-algorithms)에서 본 동점 경로 문제와 같은 이야기다.

## 최소 신장 트리는 최단 경로 트리가 아니다

면접에서 가장 자주 나오는 함정이다. "최소 신장 트리를 따라가면 두 지점 사이의 최단 경로인가요?" 아니다. 같은 지도에서 A를 출발점으로 다익스트라를 돌려 각 정점까지의 최단 경로를 모은 트리, 즉 최단 경로 트리와 비교했다.

```text
SPT from A total 44 A-B(7) B-C(8) A-D(5) B-E(7) D-F(6) F-G(11)
shortest from A A=0 B=7 C=15 D=5 E=14 F=11 G=22
along MST from A A=0 B=7 C=19 D=5 E=14 F=11 G=23
```

최단 경로 트리는 간선 비용 합이 44로 최소 신장 트리의 39보다 비싸다. 대신 A에서 C까지 15에 간다. 최소 신장 트리를 따라가면 A-B-E-C로 19다. G도 최소 신장 트리에서는 23, 실제 최단은 22다.

두 트리가 푸는 문제가 다르다. 최소 신장 트리는 "전체를 잇는 비용"을 줄이고, 최단 경로 트리는 "한 출발점에서 각 지점까지 가는 비용"을 줄인다. 케이블 공사비를 줄이고 싶으면 앞의 것, 본사에서 각 지점까지의 지연을 줄이고 싶으면 뒤의 것이다. 최단 경로 트리는 출발점이 바뀌면 모양이 바뀌지만 최소 신장 트리는 출발점이라는 개념이 없다.

차이는 하나 더 있다. 최소 신장 트리는 음수 비용이 있어도 그대로 맞는다. 컷 속성의 증명 어디에도 비용이 양수라는 가정이 없다. 다익스트라가 음수에서 틀리는 것과 대조된다. 다만 앞에서 "고리가 있으면 손해"라고 한 말은 비용이 양수일 때 이야기라, 음수 간선이 있을 때 "비용이 가장 작은 연결된 부분 그래프"를 원하면 음수 간선을 전부 넣는 것이 답이 되고 그건 더 이상 트리가 아니다.

## 가장 무거운 선을 가장 가볍게: 병목 경로

최소 신장 트리가 최단 경로를 주지는 않지만, 경로에 관해 보장하는 성질이 하나 있다. 두 정점 사이의 트리 위 경로는 "지나는 간선 중 가장 비싼 것"을 가장 작게 만드는 경로다. 이걸 최소 병목 경로(minimax path)라고 부른다.

예를 들어 비용이 아니라 구간마다의 최대 지연이나 위험도라면, 전체 합보다 "가장 나쁜 구간 하나"가 중요할 수 있다. 모든 단순 경로를 다 뒤져서 가장 비싼 간선이 가장 작은 경로를 찾고, 최소 신장 트리 위의 경로와 비교했다.

```text
A->G: all paths min-max=9 (A-B-C-E-G) | MST path A-B-E-G max=9
D->C: all paths min-max=7 (D-A-B-E-C) | MST path D-A-B-E-C max=7
F->G: all paths min-max=9 (F-D-A-B-C-E-G) | MST path F-D-A-B-E-G max=9
```

세 쌍 모두 병목 값이 같다. A에서 G로 가는 경로에는 어떻게 가든 9 이상인 간선이 하나는 끼고, 트리 위 경로도 9다. 전부 뒤진 쪽이 A-B-C-E-G처럼 다른 경로를 내놓은 건 병목 값이 같은 경로가 여럿이라서다. 이유는 고리 속성에서 나온다. 트리 위 경로의 가장 비싼 간선 e보다 병목이 작은 다른 경로가 있다면, 그 경로와 e가 만드는 고리에서 e가 가장 비싸니 e는 트리에 있을 수 없다.

부호를 뒤집으면 최대 신장 트리가 된다. 간선 비용 대신 대역폭이나 도로 폭을 두고 비용이 큰 것부터 고르면, 트리 위 경로가 "가장 좁은 구간을 가장 넓게" 만드는 경로가 된다. 트럭이 지날 수 있는 가장 무거운 짐, 두 서버 사이에 낼 수 있는 가장 큰 대역폭 같은 질문에 쓴다. 정렬 방향만 바꾸면 되니 크루스칼이 편하다.

## 선 하나가 새로 생기면

이미 최소 신장 트리를 구해 둔 상태에서 새 구간 견적이 하나 들어왔다고 하자. 처음부터 다시 돌릴 필요가 없다. 새 간선 (u, v, w)를 트리에 더하면 트리 위 u와 v 사이 경로와 함께 고리가 하나 생긴다. 그 고리에서 가장 비싼 간선을 빼면 된다. 고리 속성이 그대로 쓰인다. 새 간선이 가장 비싸면 트리는 그대로다.

```text
add F-G(4): tree path F-D-A-B-E-G, max edge E-G(9) -> swap, total 34
add C-D(10): tree path C-E-B-A-D, max edge B-A(7) -> keep, total 39
```

F-G를 4에 깔 수 있다면 F에서 G까지 트리 경로의 가장 비싼 간선 E-G 9를 빼고 F-G 4를 넣는다. 비용이 39에서 34로 준다. C-D 10은 경로의 가장 비싼 간선 7보다 비싸니 버린다. 트리 경로를 찾는 데 O(V)라, 간선이 하나씩 들어올 때마다 처음부터 O(E log E)로 다시 돌리는 것보다 훨씬 싸다. 간선이 지워지는 쪽은 더 어렵다. 지운 간선이 트리에 있으면 둘로 갈린 두 덩어리를 잇는 가장 싼 간선을 다시 찾아야 해서 그 컷을 건너는 간선을 다 봐야 한다.

## 간선이 적을 때와 꽉 찼을 때

"희소 그래프는 크루스칼, 밀집 그래프는 프림"이라는 말이 있다. 실제로 재 봤다. 희소 그래프는 정점 10만, 간선 50만, 밀집 그래프는 정점 2,000개를 모두 이은 완전 그래프(간선 약 200만)다. 프림은 힙 버전과, 힙 없이 매번 배열을 훑는 O(V²) 버전 둘을 돌렸다.

```text
sparse V=100000 E=500000: kruskal 323ms total=46413216 | prim(heap) 1380ms total=46413216
dense V=2000 E=1999000: kruskal 1062ms | prim(heap) 3231ms | prim(array) 24ms  totals 735033 735033 735033
```

희소 그래프에서는 크루스칼이 빨랐다. 간선 50만 개를 한 번 정렬하고 유니온 파인드를 돌리는 쪽이, `[비용, 정점]` 배열을 힙에 수십만 번 넣고 빼는 쪽보다 쌌다. 프림 힙 버전은 객체 할당이 많은 단순한 구현이라 더 느리게 나왔다.

밀집 그래프에서는 배열 프림이 24ms로 압도적이었다. 크루스칼은 간선 200만 개를 정렬해야 하고, 힙 프림은 간선마다 힙에 넣는다. 배열 프림은 간선을 하나하나 저장할 필요도 없이 "바깥 정점마다 트리까지의 가장 싼 비용" 배열 하나만 고친다. 정점 V개마다 V칸을 훑으니 O(V²)이고, 간선이 V²에 가까우면 이게 최적이다. 정리하면 간선 목록으로 들어오고 희소하면 크루스칼, 인접 행렬이나 거리 함수로 주어지는 밀집 그래프면 배열 프림이다. 점 사이 거리로 비용이 정해지는 클러스터링이 뒤쪽에 해당한다.

```js
function primDense(n, cost) {                 // cost(u, v): 두 정점 사이 비용
  const inTree = new Uint8Array(n);
  const best = new Float64Array(n).fill(Infinity); // 바깥 정점 → 트리까지 가장 싼 비용
  best[0] = 0;
  let total = 0;
  for (let step = 0; step < n; step++) {
    let u = -1;
    for (let v = 0; v < n; v++) if (!inTree[v] && (u === -1 || best[v] < best[u])) u = v; // O(V)
    inTree[u] = 1;
    total += best[u];
    for (let v = 0; v < n; v++) {             // 새로 들어온 u 덕분에 싸지는 정점을 고친다. O(V)
      if (!inTree[v] && cost(u, v) < best[v]) best[v] = cost(u, v);
    }
  }
  return total;
}
```

여러 기계에 나눠 돌려야 하면 보루프카(Borůvka) 알고리즘이 쓰인다. 덩어리마다 밖으로 나가는 가장 싼 간선을 동시에 고르고 한꺼번에 붙이는 일을 반복한다. 매 단계 덩어리 수가 절반 이하로 줄어 log V단계면 끝나고, 단계마다 덩어리끼리 독립이라 병렬로 나누기 좋다.

## 현장에서 최소 신장 트리를 만나는 곳

이름처럼 망 설계에 쓰인다. 케이블, 배관, 전력망처럼 "모두 연결되기만 하면 되고 설치비를 줄이고 싶은" 문제다. 다만 실제 망은 선 하나가 끊기면 둘로 갈라지는 트리를 그대로 쓰지 않는다. 최소 신장 트리를 뼈대로 잡고 중요한 구간에 우회 선을 더하는 식으로 쓴다.

스위치 망에도 이름이 비슷한 것이 있다. 이더넷의 스패닝 트리 프로토콜(STP)은 고리가 있는 스위치 망에서 일부 포트를 막아 고리 없는 트리를 만든다. 고리가 있으면 브로드캐스트 프레임이 끝없이 돌기 때문이다. STP는 루트 브리지를 하나 뽑고 각 스위치가 루트까지 가장 싼 경로를 남기는 방식이라, 엄밀히는 최소 신장 트리보다 루트 기준 최단 경로 트리에 가깝다. 위에서 본 두 트리의 차이가 여기서도 나온다.

데이터 분석에서는 클러스터링에 쓴다. 점 사이 거리를 비용으로 최소 신장 트리를 만든 뒤, 가장 비싼 간선 k - 1개를 끊으면 k개 무리로 나뉜다. 좌표 평면에 점 11개를 세 무리로 흩어 두고, 거리를 비용으로 배열 프림을 돌린 뒤 가장 긴 간선 두 개를 끊었다.

```js
tree.sort((a, b) => b[2] - a[2]);        // 최소 신장 트리 간선을 긴 것부터
const keep = tree.slice(k - 1);          // 가장 긴 k-1개를 끊고 나머지만 남긴다
for (const [a, b] of keep) union(a, b);  // 남은 간선으로 이어진 덩어리가 무리다
```

```text
MST edges (heaviest first): p2-q1 6.00, p4-r1 5.39, p3-p4 1.41, r1-r2 1.41, r2-r3 1.41, q1-q2 1.41, q2-q3 1.41, p1-p2 1.00, p1-p3 1.00, r2-r4 1.00
cut 2 heaviest -> 3 clusters: [p1 p2 p3 p4] [q1 q2 q3] [r1 r2 r3 r4]
```

무리 사이를 잇는 두 간선(6.00, 5.39)이 다른 간선보다 확연히 길어서 끊자마자 세 무리로 갈렸다. 단일 연결(single-linkage) 계층 군집과 같은 결과다. 무리 사이 간격이 뚜렷할 때는 잘 맞고, 두 무리 사이에 점이 띄엄띄엄 다리처럼 놓여 있으면 그 다리를 따라 두 무리가 하나로 이어지는 약점이 있다. 이미지 분할, 외판원 문제의 근사(최소 신장 트리를 한 번 돌아 2배 이내 경로를 만드는 방법)도 같은 뼈대를 쓴다.

구현에서 자주 나오는 실수는 셋이다. 첫째, 그래프가 끊겨 있는데 확인하지 않는 것. 크루스칼은 덩어리마다 트리를 만든 숲(최소 신장 숲)을 조용히 돌려주고, 프림은 출발점이 속한 덩어리만 덮고 끝난다. 고른 간선이 n - 1개인지 꼭 확인한다. 둘째, 방향 그래프에 그대로 쓰는 것. 화살표가 있으면 컷 속성이 성립하지 않고, 한 정점에서 모두에게 닿는 가장 싼 방향 트리는 Chu-Liu/Edmonds 알고리즘이라는 별개의 문제다. 셋째, 프림에서 힙에서 꺼낸 간선의 바깥 끝이 이미 트리 안인지 확인하지 않는 것. 그러면 고리가 생기고 비용이 부풀려진다.

## 면접에서 나올 만한 질문

### 최소 신장 트리가 무엇인가요?

연결된 무방향 그래프에서 모든 정점을 잇고 고리가 없는 간선 집합, 즉 신장 트리 중 간선 비용 합이 가장 작은 것이다. 정점이 n개면 간선은 정확히 n - 1개다. 망을 까는 비용을 최소로 하거나 점들을 무리로 나누는 데 쓴다.

### 크루스칼과 프림은 어떻게 다르고, 왜 둘 다 맞나요?

크루스칼은 간선을 비용 순으로 정렬해 고리를 만들지 않는 것만 고르고, 프림은 정점 하나에서 트리를 키우며 바깥으로 나가는 가장 싼 간선을 붙인다. 둘 다 "어떤 컷이든 건너는 가장 싼 간선은 최소 신장 트리에 들어간다"는 컷 속성으로 정당화된다. 크루스칼은 고른 간선의 한쪽 덩어리와 나머지라는 컷을, 프림은 트리와 바깥이라는 컷을 본다. 그래서 고르는 순서는 달라도 비용이 같다.

### 그리디는 보통 틀리기 쉬운데 여기서는 왜 맞나요?

매 선택이 컷 속성으로 정당화되기 때문이다. 지금 고르는 간선이 어떤 컷을 건너는 가장 싼 간선이라는 게 보장되고, 그런 간선을 쓰는 최소 신장 트리가 늘 존재하니 한 번 고른 것을 되돌릴 필요가 없다. 동전 거스름돈처럼 지금의 최선이 나중을 막는 구조가 아니다.

### 시간 복잡도와, 어떤 그래프에서 무엇을 고르나요?

크루스칼은 정렬 때문에 O(E log E), 이진 힙 프림은 O(E log V)로 꼴은 같다. 힙 없이 배열을 훑는 프림은 O(V²)이라 간선이 V²에 가까운 밀집 그래프에서 가장 빠르다. 정점 2,000개 완전 그래프에서 배열 프림이 24ms, 크루스칼이 1초였다. 간선 목록으로 주어진 희소 그래프는 크루스칼이 구현도 쉽고 빨랐다.

### 최소 신장 트리 위의 경로가 두 정점 사이 최단 경로인가요?

아니다. 최소 신장 트리는 전체를 잇는 비용 합을 줄일 뿐, 특정 두 정점 사이 거리를 줄이지 않는다. 본문 예제에서 A에서 C까지 트리 위로는 19, 실제 최단은 15였다. 한 출발점에서 각 정점까지 최단 경로를 모은 최단 경로 트리는 비용 합이 44로 최소 신장 트리의 39보다 컸다.

### 최소 신장 트리가 여러 개일 수 있나요?

간선 비용이 모두 다르면 하나뿐이고, 같은 비용이 있으면 여러 개일 수 있다. 그래도 총비용은 같고, 고른 간선 비용을 정렬한 목록도 같다. 테스트에서는 간선 목록보다 총비용을 비교하는 편이 안전하다.

### 음수 비용이나 방향 그래프에서도 쓸 수 있나요?

음수 비용은 문제없다. 컷 속성의 증명이 비용의 부호를 쓰지 않기 때문이고, 다익스트라와 다른 점이다. 방향 그래프에는 그대로 쓸 수 없다. 한 루트에서 모든 정점에 닿는 가장 싼 방향 트리는 Chu-Liu/Edmonds 알고리즘으로 푸는 다른 문제다.

### 간선 하나가 새로 들어오면 처음부터 다시 구해야 하나요?

아니다. 새 간선을 트리에 더하면 고리가 하나 생기니, 트리 위 두 끝 사이 경로에서 가장 비싼 간선과 비교해 새 간선이 더 싸면 바꾸고 아니면 버린다. 경로를 찾는 데 O(V)라 다시 정렬하는 것보다 싸다. 본문 예제에서 F-G 4가 들어오자 E-G 9를 빼서 39가 34가 됐다.

### 최소 신장 트리로 풀 수 있는 다른 경로 문제가 있나요?

최소 병목 경로다. 트리 위 두 정점 사이 경로는 지나는 간선 중 가장 비싼 것을 가장 작게 만드는 경로다. 반대로 가장 좁은 구간을 가장 넓게 하는 경로, 예를 들어 최대 대역폭 경로는 비용이 큰 것부터 고르는 최대 신장 트리 위에 있다.

### 그래프가 끊겨 있으면 어떻게 되나요?

신장 트리가 없다. 크루스칼은 덩어리마다 트리를 만든 최소 신장 숲을 돌려주고, 프림은 출발점의 덩어리만 덮고 멈춘다. 그래서 끝난 뒤 고른 간선이 n - 1개인지 확인해 연결 여부를 판단해야 한다.
