[Jump Game II](https://leetcode.com/problems/jump-game-ii/)는 LeetCode 45번이다. [Jump Game](/posts/leetcode-jump-game)(55번)이 "마지막 칸에 닿을 수 있나"를 물었다면, 이 문제는 "닿을 수 있다는 건 보장할 테니 최소 몇 번 뛰나"를 묻는다. 질문이 예/아니오에서 최솟값으로 바뀌면서 풀이도 한 단계 깊어진다. 앞 글의 reach 풀이를 그대로 가져오면 틀리고, 범위를 "층"으로 나눠 세는 생각이 하나 더 필요하다.

이 글은 모든 경로 재귀부터 시작해서 여섯 가지 풀이를 본다. 마지막 풀이는 그리디라고 불리지만, 실제로는 BFS(가까운 곳부터 넓게 퍼지는 탐색)를 배열 위에서 줄 없이 한 것이다. 이 연결을 설명할 수 있으면 면접의 꼬리 질문 대부분에 답할 수 있다. 코드는 Node.js 22, Python 3.13, Java 21에서 돌렸다.

## 칸마다 최대 몇 칸까지 뛸 수 있다

정수 배열 `nums`가 있고 0번 칸에서 출발한다. `nums[i]`는 i번 칸에서 앞으로 뛸 수 있는 최대 칸 수다. 마지막 칸(n - 1번)에 도착하는 데 필요한 최소 점프 횟수를 돌려준다. 마지막 칸에 도착할 수 있는 입력만 들어온다.

풀이에 영향을 주는 제약은 이렇다.

- 배열 길이는 1 이상 10^4 이하다. O(n²)은 최악 5천만 번 정도라 통과는 하지만 여유가 없다.
- `nums[i]`는 0 이상 1000 이하다. 0인 칸이 있을 수 있지만, 도착이 보장되니 그 0을 건너뛰는 길이 반드시 있다.
- 배열 길이가 1이면 출발점이 곧 도착점이라 답은 0이다.

## 손으로 무리를 나눠 본다

이 글에서 쓸 예시다.

```text
nums = [2, 1, 3, 1, 1, 2, 1]
번호     0  1  2  3  4  5  6
```

0번에서 한 번 뛰면 1번 또는 2번에 간다. 이 둘이 "한 번 뛰어 닿는 칸"이다. 1번에서 한 번 더 뛰면 2번까지, 2번에서 한 번 더 뛰면 3번, 4번, 5번까지 간다. 그래서 "두 번 뛰어 처음 닿는 칸"은 3, 4, 5번이다. 3번에서 4번, 4번에서 5번, 5번에서 6번과 7번(배열 밖)이니, 6번은 세 번째 점프에서 처음 닿는다. 답은 3이다.

```text
점프 0번: 0
점프 1번: 1 2
점프 2번: 3 4 5
점프 3번: 6
```

실제 경로를 하나 적으면 0 → 2 → 5 → 6이다. 표를 보면 두 가지가 보인다. 하나는 각 줄이 언제나 이어진 번호라는 것이다. 다른 하나는 다음 줄의 끝이 "이번 줄의 칸들이 닿는 가장 먼 칸"으로 정해진다는 것이다. 이 두 성질이 마지막 풀이의 뼈대다.

## 모든 걸음을 다 해 본다

i번 칸에서 마지막까지의 최소 점프 수를 `go(i)`라 하면, 1칸부터 `nums[i]`칸까지 뛰어 본 결과 중 가장 작은 것에 1을 더한 값이다.

```js
function jump(nums) {
  const last = nums.length - 1;
  function go(i) {
    if (i >= last) return 0;                    // 이미 도착했다
    let best = Infinity;
    for (let step = 1; step <= nums[i]; step++) {
      best = Math.min(best, 1 + go(i + step));  // 이 걸음 뒤의 최솟값 + 지금 한 번
    }
    return best;                                // nums[i]가 0이면 Infinity가 남는다
  }
  return go(0);
}
```

앞 글의 재귀와 다른 점이 있다. 앞 글은 "닿는 길 하나"만 찾으면 바로 끝낼 수 있었지만, 여기서는 최솟값이라 모든 걸음을 끝까지 비교해야 한다. 가지치기가 안 된다.

모든 칸에 n을 적어 둔 길이 n 배열로 호출 수를 세어 봤다.

```text
brute n 14 calls 57345 ms 2.5
brute n 18 calls 1179649 ms 12.5
brute n 22 calls 23068673 ms 207.3
```

칸이 4개 늘 때마다 호출이 약 20배씩 는다. 시간은 O(2^n)이고, 공간은 재귀 깊이로 O(n)이다. 0인 칸에서 `Infinity`가 돌아오는 건 일부러 둔 것이다. 그 길로는 도착할 수 없으니 최솟값 비교에서 저절로 빠진다.

## 칸마다 답을 한 번만 구한다

`go(i)`는 i번에 어떻게 왔는지와 상관없으니 한 번 구한 값을 적어 둔다.

```js
function jump(nums) {
  const last = nums.length - 1;
  const memo = new Array(nums.length).fill(-1); // -1은 아직 모름
  function go(i) {
    if (i >= last) return 0;
    if (memo[i] !== -1) return memo[i];
    let best = Infinity;
    const far = Math.min(last, i + nums[i]);
    for (let j = i + 1; j <= far; j++) best = Math.min(best, 1 + go(j));
    return (memo[i] = best);
  }
  return go(0);
}
```

칸 n개마다 최대 n칸을 보니 O(n²), 공간은 O(n)이다. 그런데 이 코드는 1만 칸에서 Node 기본 스택을 넘겼다. 모두 1인 배열은 물론이고, 모두 1000인 배열에서도 터졌다. `j`를 가까운 칸부터 훑으니 `go(1)`이 `go(2)`를 부르고, 그게 `go(3)`을 부르는 식으로 깊이가 n까지 내려가기 때문이다. 재귀 순서가 값과 상관없이 깊이를 정해 버린다. 반복문으로 바꾼다.

## 앞에서부터 최솟값을 퍼뜨린다

`dp[j]`를 "j번 칸에 도착하는 최소 점프 수"로 정한다. 0번은 0이다. i번 칸의 값이 정해지면, i번에서 뛸 수 있는 모든 j마다 `dp[i] + 1`과 비교해 더 작은 값으로 바꾼다. i번의 값은 i보다 앞 칸들만 영향을 주니, 앞에서부터 차례로 퍼뜨리면 i번 차례에는 이미 확정되어 있다.

```js
function jump(nums) {
  const n = nums.length;
  const dp = new Array(n).fill(Infinity);
  dp[0] = 0;
  for (let i = 0; i < n; i++) {
    const far = Math.min(n - 1, i + nums[i]);
    for (let j = i + 1; j <= far; j++) {
      dp[j] = Math.min(dp[j], dp[i] + 1);       // i를 거쳐 j에 오는 길
    }
  }
  return dp[n - 1];
}
```

예시를 넣으면 `dp`는 `[0, 1, 1, 2, 2, 2, 3]`이 된다. 손으로 나눈 무리 표와 똑같다. 1, 2번이 1이고, 3, 4, 5번이 2, 6번이 3이다.

시간은 O(n × 최대 점프), 공간은 O(n)이다. 1만 칸에 모두 1000이면 1000만 번을 돌아 15ms였다. 제약 안에서는 충분하지만, 점프 거리 제한이 없는 변형이면 O(n²)이 된다.

이 표에서 눈여겨볼 게 있다. `dp` 값이 앞에서 뒤로 갈수록 줄어들지 않는다. 0, 1, 1, 2, 2, 2, 3처럼 같은 값이 이어지다가 1씩 오른다. 뒤 칸이 앞 칸보다 적게 뛰어 닿는 일이 없다는 뜻이다. 앞 칸에 닿는 길에서 마지막 점프를 조금 덜 뛰면 그 칸에 닿기 때문이다. 이 성질이 뒤의 두 풀이를 가능하게 한다.

## 끝에서부터 가장 먼 출발점을 찾는다

거꾸로 생각할 수도 있다. 마지막 칸에 한 번에 닿는 칸 중 가장 앞의 칸을 찾고, 거기를 새 목표로 다시 같은 일을 한다. 가장 앞의 칸을 고르는 이유는 위의 성질 때문이다. 앞 칸일수록 `dp` 값이 작거나 같으니, 같은 목표에 닿는 칸 중 가장 앞의 칸이 가장 적게 뛰어서 오는 칸이다.

```js
function jump(nums) {
  let pos = nums.length - 1, jumps = 0;
  while (pos > 0) {
    for (let i = 0; i < pos; i++) {             // 앞에서부터 찾으면 처음 만나는 게 가장 앞의 칸
      if (i + nums[i] >= pos) { pos = i; jumps++; break; }
    }
  }
  return jumps;
}
```

예시에서 목표가 바뀔 때마다 찍어 봤다.

```text
목표 6 <- 출발 5
목표 5 <- 출발 2
목표 2 <- 출발 0
jumps 3
```

6번에 닿는 칸은 5번뿐이고, 5번에 닿는 칸은 2, 3, 4번인데 그중 가장 앞의 2번을 고른다. 2번에 닿는 가장 앞의 칸은 0번이다. 거꾸로 읽으면 0 → 2 → 5 → 6이라 경로도 함께 나온다. 공간은 O(1)이다.

시간은 입력에 따라 크게 달라진다. 숫자가 크면 몇 번 안 돌고 끝나지만, 모두 1이면 목표가 한 칸씩만 당겨지고 매번 앞에서부터 다시 훑어서 O(n²)이다. 1만 칸 모두 1에서 72ms였다. 앞의 DP와 반대로, 이 풀이는 숫자가 작을 때 느리다.

## 한 번 뛰어 닿는 칸끼리 묶어 BFS를 한다

손으로 나눈 무리 표는 BFS의 층 그대로다. 칸을 정점, 점프를 간선으로 보면 모든 간선의 길이가 1인 그래프에서 0번부터 마지막 칸까지의 최단 거리를 묻는 문제가 된다. 간선 길이가 모두 같을 때는 BFS가 최단 거리를 바로 준다. 가까운 층부터 차례로 꺼내니까, 어떤 칸을 처음 줄에 넣는 순간의 거리가 그 칸의 최단 거리다. BFS 자체는 [그래프 탐색 글](/posts/ds-graph-bfs-dfs)에 있다.

그냥 BFS를 하면 칸마다 간선을 모두 봐서 O(n²)이다. 한 칸에서 뛸 수 있는 칸이 이어진 범위라는 성질을 쓰면 줄일 수 있다. 지금까지 줄에 넣은 가장 먼 칸 farthest를 기억해 두고, 새로 넣을 칸은 farthest 다음부터만 본다.

```js
function jump(nums) {
  const last = nums.length - 1;
  if (last === 0) return 0;
  const dist = new Array(nums.length).fill(-1);
  dist[0] = 0;
  const queue = [0];
  let head = 0, farthest = 0;                   // farthest: 줄에 넣은 가장 먼 칸
  while (head < queue.length) {
    const i = queue[head++];
    const end = Math.min(last, i + nums[i]);
    for (let j = farthest + 1; j <= end; j++) { // 처음 보는 칸만 넣는다
      dist[j] = dist[i] + 1;
      if (j === last) return dist[j];           // 처음 닿는 순간이 최단 거리다
      queue.push(j);
    }
    farthest = Math.max(farthest, end);
  }
  return -1;
}
```

아래 그림에서 다음을 누르면 줄에서 칸을 하나씩 꺼내며 새 칸을 넣는 과정을 볼 수 있다. 괄호 안 숫자가 그 칸까지의 점프 수다.

## 이번 점프의 끝에 닿으면 횟수를 센다

줄 대신 칸을 0번부터 차례로 훑는다. 두 숫자를 들고 간다.

- `curEnd`: 지금까지 센 점프 수로 닿을 수 있는 가장 먼 칸. 지금 층의 끝이다.
- `farthest`: 지금까지 훑은 칸에서 한 번 더 뛰어 닿는 가장 먼 칸. 다음 층의 끝이 될 값이다.

칸 i를 지날 때마다 `farthest`를 `i + nums[i]`와 비교해 늘린다. 그러다 i가 `curEnd`에 닿으면 지금 층을 다 본 것이다. 한 번 더 뛰어야 그 너머로 갈 수 있으니 점프 수를 하나 늘리고, 새 층의 끝을 `farthest`로 정한다.

```js
function jump(nums) {
  let jumps = 0, curEnd = 0, farthest = 0;
  for (let i = 0; i < nums.length - 1; i++) {   // 마지막 칸에서는 뛰지 않는다
    farthest = Math.max(farthest, i + nums[i]); // 다음 층이 어디까지 가나
    if (i === curEnd) {                         // 이번 층을 다 봤다
      jumps++;                                  // 한 번 더 뛴다
      curEnd = farthest;                        // 새 층의 끝
    }
  }
  return jumps;
}
```

예시에서 칸마다 값을 찍어 봤다.

```text

i 1 far 2 curEnd 2 jumps 1
i 2 far 5 curEnd 5 jumps 2 JUMP
i 3 far 5 curEnd 5 jumps 2
i 4 far 5 curEnd 5 jumps 2
i 5 far 7 curEnd 7 jumps 3 JUMP
```

### 왜 최소인가

i번째 층이 "정확히 i번 뛰어 처음 닿는 칸들"이라는 걸 보이면 된다. 0번째 층은 0번 칸 하나다. i번째 층이 맞다고 하면, i + 1번 뛰어서 닿는 칸은 i번째 층 이하의 어떤 칸에서 한 번 더 뛴 칸이다. 각 칸에서 뛰는 범위는 이어져 있고, 앞의 층들은 0번부터 이어져 있으니, 한 번 더 뛰어 닿는 칸 전체는 0번부터 `farthest`까지 이어진 범위가 된다. 그중 이미 앞 층에 있던 칸을 빼면 `curEnd + 1`부터 `farthest`까지가 남는다. 이게 코드가 만드는 새 층이다.

그래서 마지막 칸이 들어가는 층의 번호가 최소 점프 수다. 어느 칸으로 뛰었는지는 한 번도 정하지 않았다. 층의 끝만 셌을 뿐이다. 그리디라는 이름이 붙었지만 "한 칸을 골라 뛴다"는 그리디가 아니라, BFS의 층 번호를 세는 계산이다.

### 경로가 필요하면

면접관이 "어디로 뛰었는지도 알려 달라"고 하면, farthest를 만든 칸을 함께 기억한다. 층이 끝날 때마다 그 칸이 다음 점프의 출발점이다.

```js
function jumpPath(nums) {
  const path = [0];
  let curEnd = 0, farthest = 0, from = 0;      // from: farthest를 만든 칸
  for (let i = 0; i < nums.length - 1; i++) {
    if (i + nums[i] > farthest) { farthest = i + nums[i]; from = i; }
    if (i === curEnd) {
      if (from !== path[path.length - 1]) path.push(from);
      curEnd = farthest;
    }
  }
  if (nums.length > 1) path.push(nums.length - 1);
  return path;
}
```

```text
[0,2,5,6] [0] [0,1] [0,1,5]
```

예시, `[0]`, `[1, 2]`, `[2, 4, 1, 1, 1, 1]`을 넣은 결과다. 무작위 배열 2만 개로 경로의 길이가 최소 점프 수와 같고 모든 점프가 허용 범위 안인지 확인했다.

## Python과 Java로 옮기기

```python
from typing import List


class Solution:
    def jump(self, nums: List[int]) -> int:
        jumps = cur_end = farthest = 0
        for i in range(len(nums) - 1):         # 마지막 칸에서는 뛰지 않는다
            farthest = max(farthest, i + nums[i])
            if i == cur_end:                   # 이번 점프로 닿는 범위를 다 봤다
                jumps += 1
                cur_end = farthest
        return jumps
```

```text
[2, 1, 3, 1, 1, 2, 1] 3
[0] 0
[1, 2] 1
[2, 4, 1, 1, 1, 1] 2
[1, 1, 1, 1] 3
[5, 1, 1, 1, 1] 1
```

`range(len(nums) - 1)`은 길이가 1이면 빈 범위라 반복을 한 번도 안 돌고 0을 돌려준다. 따로 처리할 필요가 없다.

```java
class Solution {
    public int jump(int[] nums) {
        int jumps = 0, curEnd = 0, farthest = 0;
        for (int i = 0; i < nums.length - 1; i++) {   // 마지막 칸에서는 뛰지 않는다
            farthest = Math.max(farthest, i + nums[i]);
            if (i == curEnd) {                        // 이번 점프로 닿는 범위를 다 봤다
                jumps++;
                curEnd = farthest;
            }
        }
        return jumps;
    }
}
```

```text
[2, 1, 3, 1, 1, 2, 1] 3
[0] 0
[1, 2] 1
[2, 4, 1, 1, 1, 1] 2
[1, 1, 1, 1] 3
[5, 1, 1, 1, 1] 1
```

`main`에서 같은 여섯 입력을 넣었다. `i + nums[i]`는 최대 1만 + 1000이라 `int`로 충분하다. 세 언어 모두 코드 모양이 거의 같은 게 이 풀이의 장점이다.

## 풀이 비교

| 풀이 | 시간 | 공간 | 언제 고르나 |
|---|---|---|---|
| 모든 걸음 재귀 | O(2^n) | O(n) | 점화식을 세울 때 생각의 출발점으로만 |
| 메모이제이션 | O(n²) | O(n) | 재귀가 편할 때. 1만 칸이면 스택이 넘친다 |
| 앞에서 퍼뜨리는 DP | O(n × 최대 점프) | O(n) | 칸마다 비용이 다른 변형으로 넓힐 때 |
| 끝에서 가장 먼 출발점 | 최악 O(n²) | O(1) | 숫자가 큰 입력이 많을 때. 설명용 |
| 범위 BFS | O(n) | O(n) | 그래프로 보는 시각을 보여 줄 때 |
| 층 끝 세기 | O(n) | O(1) | 기본 답 |

면접에서는 층 끝 세기를 쓰고, 왜 맞는지 물으면 "BFS의 층을 배열 위에서 센 것"이라고 답한다. 칸마다 비용이 다르거나 뛸 수 있는 칸이 이어져 있지 않은 변형이 오면 DP나 일반 BFS로 돌아간다.

## 그럴듯하지만 틀리는 계산

### 매번 가장 멀리 뛴다

```js
let i = 0, jumps = 0;
while (i < nums.length - 1) { i += nums[i]; jumps++; }
```

`[2, 4, 1, 1, 1, 1]`에서 4가 나온다. 0번에서 2칸 뛰면 2번(1)에 떨어져 그 뒤로 한 칸씩 간다. 정답은 2다. 0번에서 1칸만 뛰어 1번(4)으로 가면 한 번에 5번이다. 멀리 뛰는 게 아니라 "다음에 멀리 갈 수 있는 칸"으로 가야 한다. 이 코드는 0인 칸에 떨어지면 끝나지도 않는다.

### 범위에서 숫자가 가장 큰 칸으로 뛴다

"다음에 멀리 갈 칸"을 숫자가 큰 칸으로 잘못 옮기는 실수다. 기준은 `nums[j]`가 아니라 `j + nums[j]`다. `[3, 3, 1, 2, 3, 3]`에서 0번이 닿는 1, 2, 3번 중 숫자가 가장 큰 건 1번(3)이지만, 1번에서는 4번까지 간다. 3번(2)은 숫자가 작아도 5번까지 간다. 숫자 기준으로 고르면 3이 나오고, 정답은 2다.

### 마지막 칸까지 반복한다

```js
for (let i = 0; i < nums.length; i++) {         // - 1이 빠졌다
```

`[1, 2]`에서 2가 나온다. i = 1에서 `curEnd`가 1이라 "층 끝에 닿았다"며 한 번 더 센다. 이미 마지막 칸에 서 있는데 뛰는 셈이다. `[0]`도 0이 아니라 1이 나온다. 마지막 칸은 출발점이 아니라 도착점이니 반복에서 뺀다.

### farthest를 늦게 갱신한다

```js
if (i === curEnd) { jumps++; curEnd = farthest; }
farthest = Math.max(farthest, i + nums[i]);     // 순서가 바뀌었다
```

층 끝 칸 자신의 점프 거리가 반영되기 전에 `curEnd`를 정해 버린다. 예시에서 i = 0일 때 `farthest`가 아직 0이라 `curEnd`도 0에 머물고, 그 뒤로는 i가 `curEnd`와 같아지지 않아 1이 나온다. 정답은 3이다. 갱신을 먼저 하고 비교한다.

### 도착할 수 없는 입력이 들어오면

이 문제는 도착을 보장하지만, 실무 코드나 변형 문제에서는 그 보장이 없다. 층 끝에 닿았는데 `farthest`가 지금 칸보다 멀지 않으면 더 나아갈 수 없다는 뜻이다. 한 줄을 더한다.

```js
if (i === curEnd) {
  if (farthest <= i) return -1;                 // 이번 층에서 한 칸도 더 못 나간다
  jumps++;
  curEnd = farthest;
}
```

`[1, 2, 0, 1, 0, 3]`에서 -1, `[0, 1]`에서 -1, `[2, 0, 3, 0, 0, 1]`에서 2가 나온다. 0을 포함한 무작위 배열 2만 개로 DP 결과(닿지 못하면 `Infinity`)와 맞춰 봤다. 이 한 줄이 없으면 `curEnd`가 제자리에 머물러 점프 수가 실제보다 작게 나온다.

### 의심스러운 기준은 작은 입력으로 맞춰 본다

위의 "숫자가 큰 칸" 같은 기준이 맞는지 헷갈리면, 확실한 DP와 무작위 입력으로 비교해 본다. 칸은 6개까지, 숫자는 1부터 3까지로 작게 잡았다.


## 조건이 바뀌면

### 칸마다 밟는 비용이 다르다면

각 칸에 밟는 비용이 있고 총비용을 최소로 해야 한다면, 층의 개수가 아니라 비용 합이 기준이라 BFS의 층이 의미를 잃는다. 앞에서 퍼뜨리는 DP가 그대로 통한다. `dp[j] = min(dp[i] + cost[j])`로 바꾸면 된다. 점프 거리가 k 이하로 고정이면 "앞의 k칸 중 최솟값"을 슬라이딩 윈도 최솟값으로 구해 O(n)이 된다. LeetCode 1696번 Jump Game VI가 점수 합을 최대로 하는 같은 모양의 문제이고, 덱(양쪽에서 넣고 빼는 줄)으로 창의 최댓값을 관리하는 [Sliding Window Maximum](/posts/leetcode-sliding-window-maximum)과 같은 도구를 쓴다. 비용이 음수가 아니고 간선이 자유로운 일반 그래프라면 다익스트라로 간다([최단 경로 글](/posts/shortest-path-algorithms)).

### 뛸 수 있는 칸이 이어져 있지 않다면

LeetCode 1345번 Jump Game IV는 옆 칸과 "값이 같은 칸"으로 뛸 수 있다. 값이 같은 칸들은 흩어져 있어서 farthest 하나로 범위를 줄일 수 없다. 값마다 칸 목록을 해시맵에 모아 두고 일반 BFS를 하며, 한 번 쓴 값의 목록은 지워서 같은 간선을 두 번 보지 않게 한다.

### 구간을 최소 개수로 덮어야 한다면

LeetCode 1024번 Video Stitching과 1326번 Minimum Number of Taps to Open to Water a Garden이 이 문제의 다른 얼굴이다. 구간마다 시작점에서 갈 수 있는 가장 먼 끝을 배열에 모으면 "i번에서 최대 몇 칸까지"가 되고, 층 끝 세기를 그대로 쓴다. 구간을 다루는 다른 방법은 [구간 문제 패턴 글](/posts/interval-problems-pattern)에 있다.

### 도착할 수 있는지만 묻는다면

[Jump Game](/posts/leetcode-jump-game)이다. 층을 나눌 필요가 없으니 farthest 하나만 들고 간다. 이 글의 코드에서 `curEnd`와 `jumps`를 지우면 거의 그 풀이가 된다.

## 면접에서 나올 만한 질문

### 이 풀이를 그리디라고 하나요, BFS라고 하나요?

계산 모양은 BFS다. 한 번 뛰어 닿는 칸들이 첫 층, 두 번 뛰어 처음 닿는 칸들이 둘째 층이고, 모든 간선 길이가 1이라 층 번호가 최단 거리다. 층이 언제나 이어진 칸 번호라서 줄 없이 끝 번호 두 개로 셀 수 있고, 이걸 흔히 그리디라고 부른다. 어느 칸으로 뛸지는 한 번도 정하지 않는다고 덧붙이면 좋다.

### curEnd와 farthest는 각각 무엇인가요?

`curEnd`는 지금까지 센 점프 수로 닿을 수 있는 가장 먼 칸, 즉 지금 층의 끝이다. `farthest`는 지금까지 훑은 칸에서 한 번 더 뛰어 닿는 가장 먼 칸으로, 다음 층의 끝이 될 값이다. i가 `curEnd`에 닿으면 지금 층을 다 본 것이라 점프 수를 늘리고 `curEnd`를 `farthest`로 옮긴다.

### 반복을 왜 n - 1번 칸 앞에서 멈추나요?

마지막 칸은 도착점이라 거기서 뛸 일이 없기 때문이다. 마지막 칸까지 돌면 `curEnd`가 정확히 n - 1인 입력에서 층 끝에 닿았다며 점프를 하나 더 센다. `[1, 2]`에서 2가 나오고 `[0]`에서 1이 나오는 실수가 이것이다.

### 매번 가장 멀리 뛰면 왜 틀리나요?

멀리 뛴 칸의 숫자가 작으면 그 뒤가 느려지기 때문이다. `[2, 4, 1, 1, 1, 1]`에서 최대로 뛰면 2번(1)에 떨어져 4번 뛰지만, 1칸만 뛰어 1번(4)으로 가면 2번에 끝난다. 기준은 뛴 거리가 아니라 그 칸에서 다시 닿는 곳, `j + nums[j]`다.

### DP 풀이와 비교해서 장단점은요?

층 끝 세기는 O(n) 시간, O(1) 공간이라 빠르지만, 모든 점프 비용이 같고 뛸 수 있는 칸이 이어진 범위일 때만 성립한다. 앞에서 퍼뜨리는 DP는 O(n × 최대 점프)로 느리지만, 칸마다 비용이 다르거나 조건이 붙는 변형으로 바로 넓힐 수 있다. 문제가 바뀌었을 때 어느 가정이 깨지는지 보고 고른다.

### 최소 점프 경로도 출력할 수 있나요?

층마다 `farthest`를 만든 칸을 기억해 두면 된다. 층이 끝날 때 그 칸이 다음 점프의 출발점이다. 예시에서는 0 → 2 → 5 → 6이 나온다. 공간은 경로 길이만큼만 더 든다.

### 도착할 수 없는 입력이면 어떻게 처리하나요?

층 끝에 닿았을 때 `farthest`가 지금 칸보다 멀지 않으면 더 나아갈 곳이 없으니 -1을 돌려준다. 이 검사가 없으면 `curEnd`가 제자리에 머물러 실제보다 작은 점프 수가 나온다. 원래 문제는 도착을 보장해서 필요 없지만, 변형에서는 꼭 넣는다.
