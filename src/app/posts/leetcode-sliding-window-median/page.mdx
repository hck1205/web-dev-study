[Sliding Window Median](https://leetcode.com/problems/sliding-window-median/)은 LeetCode 480번이고 난이도는 Hard다. 배열 위를 길이 k인 창이 한 칸씩 밀려 가는데, 창마다 그 안의 중앙값을 구한다. 중앙값은 값을 정렬했을 때 가운데 값이고, k가 짝수면 가운데 두 값의 평균이다.

이 문제는 두 문제를 합친 모양이다. 숫자가 계속 들어올 때 중앙값을 구하는 [Find Median from Data Stream](/posts/leetcode-find-median-from-data-stream)에 "오래된 값이 빠진다"는 조건이 붙었다. 두 힙으로 중앙값을 지키는 방법은 그 글에 자세히 있으니, 여기서는 "빠지는 값을 어떻게 지우나"에 집중한다. 창이 밀리는 틀 자체는 [슬라이딩 윈도 글](/posts/sliding-window-pattern)에 있다. 이 글은 창마다 정렬, 정렬된 창에 빼고 끼우기, 두 힙과 지연 삭제, 정렬 집합 두 개, 펜윅 트리까지 다섯 풀이를 본다. 코드는 Node.js 22, Python 3.13, Java 21에서 돌렸다.

## 창이 한 칸씩 밀릴 때마다 가운데 값을 낸다

정수 배열 `nums`와 창 크기 `k`가 주어진다. 왼쪽 끝부터 길이 k인 창을 한 칸씩 오른쪽으로 옮기며 창마다 중앙값을 구해 배열로 돌려준다. 창은 `n - k + 1`개다.

풀이를 고를 때 볼 제약은 이렇다.

- n은 최대 10^5, k는 1 이상 n 이하다. k가 크면 창마다 정렬하는 O(n · k log k)는 안 된다.
- 값은 32비트 정수 전 범위, 즉 -2^31 이상 2^31 - 1 이하다. 두 값을 더하면 32비트를 넘는다.
- 답은 실제 값과 10^-5 이내면 맞다고 본다. 평균이 `x.5`로 떨어지는 경우를 실수로 돌려주면 된다.

두 번째 줄이 Java와 C++에서 꼭 한 번은 틀리는 곳이다. 뒤에서 실제로 -1이 나오는 걸 본다.

## 일곱 개짜리 배열에서 창 다섯 개를 손으로 본다

이 글 내내 쓰는 예시다. `nums = [5, 2, 8, 1, 9, 3, 7]`, `k = 3`이다.

```text
창 위치  창 안의 값    정렬하면     중앙값
0~2      5 2 8        2 5 8        5
1~3      2 8 1        1 2 8        2
2~4      8 1 9        1 8 9        8
3~5      1 9 3        1 3 9        3
4~6      9 3 7        3 7 9        7
```

답은 `[5, 2, 8, 3, 7]`이다. k = 4로 바꾸면 창이 넷이고 답은 `[3.5, 5, 5.5, 5]`다. 첫 창 `5 2 8 1`을 정렬하면 `1 2 5 8`이라 (2 + 5) / 2 = 3.5다.

표에서 창이 한 칸 밀릴 때 바뀐 값은 둘뿐이다. 하나 들어오고 하나 나간다. 나머지 k - 2개는 그대로다. 그런데도 매번 처음부터 정렬하면 그 k - 2개를 다시 줄 세우는 셈이다. 바뀐 두 값만 손보는 방법을 찾는 게 이 문제다. 들어오는 값은 쉽다. 데이터 스트림 문제처럼 넣으면 된다. 어려운 건 나가는 값이다.

## 창마다 새로 정렬한다

가장 먼저 떠오르는 방법이다. 창마다 값을 잘라 정렬하고 가운데를 읽는다.

```js
const med = (a, k) => (k % 2 ? a[k >> 1] : (a[k / 2 - 1] + a[k / 2]) / 2);

function medianSlidingWindow(nums, k) {
  const out = [];
  for (let i = 0; i + k <= nums.length; i++) {
    const w = nums.slice(i, i + k).sort((x, y) => x - y); // 창을 잘라 정렬
    out.push(med(w, k));
  }
  return out;
}
```

창마다 O(k log k)라 전체는 O(n · k log k)다. n = 10^5에서 k = 3이면 28ms로 충분하지만, k = 1000이면 20초가 걸렸다. k가 커지면 쓸 수 없다.

평균을 `/ 2`로 구한 데 주의한다. JavaScript의 숫자는 64비트 실수라 21억 두 개를 더해도 정확하다. 정수 버릇대로 `>> 1`을 쓰면 32비트로 잘려서 틀린다. 이건 뒤에서 다시 본다.

## 정렬된 창에서 하나 빼고 하나 끼운다

창을 정렬된 배열로 계속 들고 다닌다. 창이 밀리면 나가는 값의 자리를 [이분 탐색](/posts/binary-search)으로 찾아 빼고, 들어오는 값의 자리를 찾아 끼운다.

```js
function lowerBound(a, x) {               // x 이상인 첫 자리
  let lo = 0, hi = a.length;
  while (lo < hi) {
    const m = (lo + hi) >> 1;
    if (a[m] < x) lo = m + 1;
    else hi = m;
  }
  return lo;
}

function medianSlidingWindow(nums, k) {
  const w = nums.slice(0, k).sort((x, y) => x - y); // 첫 창만 정렬
  const out = [med(w, k)];
  for (let i = k; i < nums.length; i++) {
    w.splice(lowerBound(w, nums[i - k]), 1);         // 나가는 값을 뺀다
    w.splice(lowerBound(w, nums[i]), 0, nums[i]);    // 들어오는 값을 끼운다
    out.push(med(w, k));
  }
  return out;
}
```

같은 값이 여러 개면 그중 아무거나 빼도 된다. 값이 같으니 남는 창의 모양이 같다.

자리 찾기는 O(log k)지만 빼고 끼울 때 뒤를 밀어서 창마다 O(k)다. 전체는 O(n · k)다. 이론으로는 k = 5만이면 50억 번이지만 실제로는 410ms였다. `splice`의 밀기가 메모리 블록 복사라 아주 빠르기 때문이다. k = 1000에서는 31ms로 다섯 풀이 중 가장 빨랐다. 이 문제의 크기에서는 사실 이 풀이로 충분하다. 다만 면접에서 "O(n · k)인데요?"를 들으면 다음 풀이가 필요하다.

## 두 힙에 나눠 담고 지울 값은 적어 둔다

데이터 스트림 중앙값처럼 창의 값을 두 무리로 나눈다.

- `lo`: 작은 절반. 최대 힙이라 맨 위가 작은 절반의 가장 큰 값이다.
- `hi`: 큰 절반. 최소 힙이라 맨 위가 큰 절반의 가장 작은 값이다.
- `lo`의 개수는 `hi`와 같거나 하나 많다. 그러면 k가 홀수일 때 `lo` 맨 위가 중앙값, 짝수일 때 두 맨 위의 평균이다.

문제는 창에서 나가는 값이 힙 맨 위에 있으리라는 보장이 없다는 것이다. 힙은 맨 위가 아닌 값을 빨리 찾지 못한다. 그래서 바로 지우지 않고 미룬다. 이걸 지연 삭제라 한다.

- `delayed`: 지울 예정인 값과 그 횟수를 적는 해시맵.
- 그 값이 언젠가 힙 맨 위로 올라오면 그때 꺼내 버린다. 이 정리를 `prune`이라 부르자.
- 힙에는 이미 지운 값이 섞여 있어서 배열 길이가 실제 개수가 아니다. 그래서 살아 있는 개수 `loN`, `hiN`를 따로 센다.

```js
class Heap {
  constructor(less) { this.a = []; this.less = less; } // less(x, y)가 참이면 x가 위로
  get size() { return this.a.length; }
  top() { return this.a[0]; }
  push(x) {
    const a = this.a;
    a.push(x);
    let i = a.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (!this.less(a[i], a[p])) break;
      [a[p], a[i]] = [a[i], a[p]];
      i = p;
    }
  }
  pop() {
    const a = this.a, t = a[0], last = a.pop();
    if (a.length) {
      a[0] = last;
      let i = 0;
      for (;;) {
        const l = 2 * i + 1, r = l + 1;
        let m = i;
        if (l < a.length && this.less(a[l], a[m])) m = l;
        if (r < a.length && this.less(a[r], a[m])) m = r;
        if (m === i) break;
        [a[m], a[i]] = [a[i], a[m]];
        i = m;
      }
    }
    return t;
  }
}

function medianSlidingWindow(nums, k) {
  const lo = new Heap((x, y) => x > y);   // 작은 절반, 최대 힙
  const hi = new Heap((x, y) => x < y);   // 큰 절반, 최소 힙
  const delayed = new Map();              // 지울 예정인 값 -> 횟수
  let loN = 0, hiN = 0;                   // 살아 있는 개수

  const prune = (h) => {                  // 맨 위에 지울 값이 있으면 치운다
    while (h.size) {
      const t = h.top(), c = delayed.get(t) || 0;
      if (!c) break;
      if (c === 1) delayed.delete(t); else delayed.set(t, c - 1);
      h.pop();
    }
  };
  const balance = () => {                 // lo가 hi와 같거나 하나 많게
    if (loN > hiN + 1) { hi.push(lo.pop()); loN--; hiN++; prune(lo); }
    else if (loN < hiN) { lo.push(hi.pop()); hiN--; loN++; prune(hi); }
  };
  const add = (x) => {
    if (!lo.size || x <= lo.top()) { lo.push(x); loN++; }
    else { hi.push(x); hiN++; }
    balance();
  };
  const remove = (x) => {
    delayed.set(x, (delayed.get(x) || 0) + 1);       // 바로 지우지 않고 적어 둔다
    if (x <= lo.top()) { loN--; if (x === lo.top()) prune(lo); }
    else { hiN--; if (hi.size && x === hi.top()) prune(hi); }
    balance();
  };
  const median = () => (k % 2 ? lo.top() : (lo.top() + hi.top()) / 2);

  for (let i = 0; i < k; i++) add(nums[i]);
  const out = [median()];
  for (let i = k; i < nums.length; i++) {
    add(nums[i]);                          // 들어오는 값
    remove(nums[i - k]);                   // 나가는 값
    out.push(median());
  }
  return out;
}
```

예시에서 창이 밀릴 때마다 힙 배열과 지울 예정 목록을 찍었다. `lo`는 최대 힙, `hi`는 최소 힙의 실제 배열이다.

```text
창 0~2  lo [5,2]    hi [8]    지울 예정 없음   중앙값 5
창 1~3  lo [2,1]    hi [8]    지울 예정 없음   중앙값 2
창 2~4  lo [8,1]    hi [9]    지울 예정 없음   중앙값 8
창 3~5  lo [3,1]    hi [9]    지울 예정 없음   중앙값 3
창 4~6  lo [7,1,3]  hi [9]    1이 한 번        중앙값 7
```

마지막 줄이 지연 삭제가 드러나는 순간이다. 창에서 1이 빠졌지만 1은 `lo`의 맨 위가 아니라서 배열에 그대로 남았다. `lo` 배열에는 셋이 있지만 살아 있는 건 7과 3 둘뿐이다. 아래 그림에서 다음을 누르며 창마다 무엇이 들어오고 나가는지 따라가 본다.

시간은 값 하나를 넣고 빼는 데 힙 연산 O(log n)이 상수 번이라 전체 O(n log n)이다. 여기서 log 안이 k가 아니라 n인 이유가 있다. 지운 값이 맨 위로 올라오기 전까지 힙에 남아 있어서, 힙 크기가 k를 넘어 최악에 n까지 커질 수 있다. 계속 커지는 값이 들어오면 작은 값들이 `lo` 바닥에 쌓인 채 치워지지 않는다. 0부터 99999까지 차례로 커지는 배열에 k = 100을 주었더니 두 힙 배열 길이의 합이 끝내 10만까지 커졌다. 창에는 100개뿐인데 말이다. 그래도 각 값은 한 번 들어가고 한 번 치워지니 전체 비용은 O(n log n)이다. 공간도 최악 O(n)이다. 측정은 k = 1000에서 102ms, k = 5만에서 87ms였다.

### 살아 있는 개수를 따로 세는 이유

균형은 "살아 있는 원소" 기준으로 맞춰야 한다. 힙 배열 길이로 맞추면 지운 값까지 세어 버린다. 마지막 창에서 `lo` 배열은 3칸이지만 살아 있는 건 2개다. 배열 길이로 보면 `lo`가 `hi`보다 2 많으니 7을 `hi`로 옮기려 들 것이고, 그러면 `lo` 맨 위가 3이 되어 중앙값을 3으로 낸다. 정답은 7이다.

반대로 맨 위만큼은 언제나 살아 있게 지킨다. `prune`을 맨 위가 바뀔 수 있는 모든 곳, 즉 `remove`와 `balance`의 꺼내기 뒤에 부르는 이유다. 맨 위가 살아 있으니 중앙값을 읽을 때와 들어온 값을 어느 쪽에 넣을지 비교할 때 지운 값에 속지 않는다.

### 지울 값이 어느 힙에 있다고 칠까

`remove(x)`에서 x를 `lo` 맨 위와 비교해 작거나 같으면 `lo`에서, 크면 `hi`에서 지운 것으로 친다. `lo`의 모든 값이 `hi`의 모든 값보다 작거나 같다는 규칙이 지켜지고 있어서 가능한 판단이다.

같은 값이 양쪽에 있으면 어떨까. x가 `lo` 맨 위와 같으면 `lo`에서 지운 것으로 치고 바로 `prune(lo)`를 부른다. 맨 위가 x라서 그 자리에서 진짜로 치워진다. x가 `lo` 맨 위보다 작으면 `hi`에는 x가 있을 수 없다. `hi`의 값은 모두 `lo` 맨 위 이상이기 때문이다. 그래서 적어 둔 x는 반드시 `lo`에서 치워진다. 같은 값이 많은 입력(값이 -4부터 4까지인 무작위 배열 2만 개)으로 창마다 정렬하는 풀이와 대조해 답이 모두 같았다.

## 지우기가 되는 정렬 집합 두 개

지연 삭제가 번거로운 이유는 힙이 임의의 값을 못 지우기 때문이다. 정렬된 순서를 유지하면서 넣기, 지우기, 맨 끝 보기가 모두 O(log k)인 자료구조가 있으면 바로 지울 수 있다. 균형 이진 탐색 트리다. Java에는 `TreeSet`이 있다.

`TreeSet`은 같은 값을 하나만 담는다. 그래서 값 대신 인덱스를 넣고, 비교는 "값, 같으면 인덱스" 순으로 한다. 그러면 같은 값도 서로 다른 원소가 되고, 창에서 나가는 인덱스를 정확히 지울 수 있다.

```java
import java.util.*;

class Solution {
    public double[] medianSlidingWindow(int[] nums, int k) {
        // 같은 값이 여러 개여도 구분되게 (값, 인덱스) 순으로 정렬한다
        Comparator<Integer> cmp = (a, b) -> nums[a] != nums[b] ? Integer.compare(nums[a], nums[b]) : Integer.compare(a, b);
        TreeSet<Integer> lo = new TreeSet<>(cmp), hi = new TreeSet<>(cmp); // 인덱스를 담는다
        double[] out = new double[nums.length - k + 1];
        for (int i = 0; i < nums.length; i++) {
            if (i >= k) {                         // 창에서 빠지는 인덱스를 지운다. O(log k)
                if (!lo.remove(i - k)) hi.remove(i - k);
            }
            lo.add(i);                            // 일단 작은 쪽에 넣고
            hi.add(lo.pollLast());                // 작은 쪽의 가장 큰 것을 큰 쪽으로
            if (hi.size() > lo.size()) lo.add(hi.pollFirst()); // 개수를 맞춘다
            if (i >= k - 1) {
                out[i - k + 1] = k % 2 == 1 ? nums[lo.last()]
                        : ((long) nums[lo.last()] + nums[hi.first()]) / 2.0; // long으로 더한다
            }
        }
        return out;
    }
}
```

```text
[5.0, 2.0, 8.0, 3.0, 7.0]
[3.5, 5.0, 5.5, 5.0]
[2.147483647E9]
```

예시의 k = 3, k = 4와 `[2147483647, 2147483647]`, k = 2의 결과다. 넣기 방식은 데이터 스트림 글의 "일단 작은 쪽에 넣고, 맨 위를 큰 쪽으로 넘기고, 많으면 되돌린다"와 같다. 지우기 직후 개수 차이가 2까지 벌어져도 이 세 줄이 다시 맞춘다는 걸 손으로 확인했고, 무작위 입력 2만 개로 정렬 풀이와 대조했다.

모든 연산이 O(log k)라 전체는 O(n log k)이고 공간은 O(k)다. 지연 삭제와 달리 힙이 k보다 커지지 않는다. 대가는 언어다. JavaScript에는 내장 균형 트리가 없고, Python 표준 라이브러리에도 없다. LeetCode의 Python 환경에는 `sortedcontainers`의 `SortedList`가 깔려 있어서 같은 일을 할 수 있지만, 코딩 테스트 환경마다 다르니 쓰기 전에 확인한다.

## 값 자리를 세는 펜윅 트리로 k번째 값을 찾는다

한 가지 길이 더 있다. 배열이 처음부터 다 주어지니, 나올 값의 목록을 미리 안다. 값을 정렬해 1부터 번호를 매기고(좌표 압축), 번호마다 "지금 창에 몇 개 있나"를 센다. 그러면 중앙값은 "누적 개수가 처음으로 k/2를 넘는 번호"다. 누적 개수를 빠르게 다루는 자료구조가 펜윅 트리다. 동작 원리는 [세그먼트 트리와 펜윅 트리 글](/posts/segment-tree-fenwick)에 있다.

```js
function medianSlidingWindow(nums, k) {
  const vals = [...new Set(nums)].sort((a, b) => a - b);  // 나올 값을 정렬
  const id = new Map(vals.map((v, i) => [v, i + 1]));     // 값 -> 1부터 시작하는 번호
  const m = vals.length;
  const bit = new Int32Array(m + 1);
  const update = (i, d) => { for (; i <= m; i += i & -i) bit[i] += d; };
  let LOG = 1;
  while ((1 << LOG) <= m) LOG++;
  const kth = (r) => {                       // r번째로 작은 값 (1부터)
    let pos = 0;
    for (let b = LOG; b >= 0; b--) {         // 큰 걸음부터 내디뎌 누적이 r보다 작은 마지막 자리를 찾는다
      const np = pos + (1 << b);
      if (np <= m && bit[np] < r) { pos = np; r -= bit[np]; }
    }
    return vals[pos];                        // 그다음 자리가 답
  };
  const median = () => (k % 2 ? kth((k >> 1) + 1) : (kth(k / 2) + kth(k / 2 + 1)) / 2);

  for (let i = 0; i < k; i++) update(id.get(nums[i]), 1);
  const out = [median()];
  for (let i = k; i < nums.length; i++) {
    update(id.get(nums[i - k]), -1);         // 나가는 값의 개수를 줄이고
    update(id.get(nums[i]), 1);              // 들어오는 값의 개수를 늘린다
    out.push(median());
  }
  return out;
}
```

넣기와 빼기는 O(log n), r번째 찾기도 펜윅 트리 위에서 걸음을 반씩 줄여 가며 O(log n)이다. 전체는 좌표 압축의 정렬을 포함해 O(n log n), 공간 O(n)이다. 지울 값을 미루지 않아서 생각할 거리가 적고, 같은 값 처리도 개수로 자연스럽게 된다. k = 5만에서 110ms로 지연 삭제 힙과 비슷했다.

이 방식은 값을 미리 다 알아야 한다. 값이 끝없이 들어오는 스트림에서는 좌표 압축을 할 수 없다. 대신 값의 범위가 작다면 압축 없이 값을 바로 번호로 쓸 수 있다.

## 창 크기 3, 1000, 5만에서 재 본다

| 풀이 | 시간 | 공간 | 언제 고르나 |
|---|---|---|---|
| 창마다 정렬 | O(n · k log k) | O(k) | k가 아주 작을 때. 정답 확인용 |
| 정렬된 창에 빼고 끼우기 | O(n · k) | O(k) | 이 문제 크기라면 실제로 가장 빠르다. 코드도 짧다 |
| 두 힙 + 지연 삭제 | O(n log n) | 최악 O(n) | 내장 균형 트리가 없는 언어에서 면접 정석 |
| 정렬 집합 두 개 | O(n log k) | O(k) | Java의 `TreeSet`, C++의 `multiset`을 쓸 수 있을 때 |
| 좌표 압축 + 펜윅 트리 | O(n log n) | O(n) | 배열이 미리 다 주어지고, 지연 삭제를 피하고 싶을 때 |

## heapq로 쓰는 지연 삭제

Python은 두 힙과 지연 삭제를 옮겼다.

```python
import heapq
from collections import defaultdict

def medianSlidingWindow(nums: list[int], k: int) -> list[float]:
    lo, hi = [], []                 # lo: 작은 절반(부호를 뒤집은 최대 힙), hi: 큰 절반(최소 힙)
    delayed = defaultdict(int)      # 지울 예정인 값 -> 남은 횟수
    lo_n = hi_n = 0                 # 각 힙에서 살아 있는 원소 수

    def prune(h, sign):
        while h and delayed[sign * h[0]]:
            delayed[sign * h[0]] -= 1
            heapq.heappop(h)

    def balance():
        nonlocal lo_n, hi_n
        if lo_n > hi_n + 1:
            heapq.heappush(hi, -heapq.heappop(lo)); lo_n -= 1; hi_n += 1; prune(lo, -1)
        elif lo_n < hi_n:
            heapq.heappush(lo, -heapq.heappop(hi)); hi_n -= 1; lo_n += 1; prune(hi, 1)

    def add(x):
        nonlocal lo_n, hi_n
        if not lo or x <= -lo[0]:
            heapq.heappush(lo, -x); lo_n += 1
        else:
            heapq.heappush(hi, x); hi_n += 1
        balance()

    def remove(x):
        nonlocal lo_n, hi_n
        delayed[x] += 1
        if x <= -lo[0]:
            lo_n -= 1
            if x == -lo[0]: prune(lo, -1)
        else:
            hi_n -= 1
            if hi and x == hi[0]: prune(hi, 1)
        balance()

    def median():
        return float(-lo[0]) if k % 2 else (-lo[0] + hi[0]) / 2

    for x in nums[:k]:
        add(x)
    out = [median()]
    for i in range(k, len(nums)):
        add(nums[i])
        remove(nums[i - k])
        out.append(median())
    return out
```

```text
[5.0, 2.0, 8.0, 3.0, 7.0]
[3.5, 5.0, 5.5, 5.0]
[2147483647.0]
```

`lo`는 부호를 뒤집어 담기 때문에 `delayed`를 볼 때도 원래 값으로 돌려서 봐야 한다. `prune`에 `sign`을 넘긴 이유다. `lo`에서 `delayed[lo[0]]`을 보면 -7을 찾게 되어 아무것도 치우지 못한다. 안쪽 함수가 바깥 변수 `lo_n`을 바꾸려면 `nonlocal`이 필요하다. 빼먹으면 `UnboundLocalError`가 난다. Python의 정수는 크기 제한이 없어서 21억 두 개를 더해도 넘치지 않는다. 평균은 `/`로 구한다. `//`를 쓰면 -0.5가 -1이 된다.

## 21억 두 개의 평균이 -1이 되는 이유

### 32비트 정수로 더한다

Java에서 `(a + b) / 2.0`처럼 쓰면 덧셈이 먼저 `int`로 일어난다. `a`와 `b`가 모두 2147483647이면 합이 32비트를 넘쳐 -2가 되고, 2.0으로 나눠 -1.0이 나온다. 실제로 찍어 보니 -1.0이었다. 정답은 2147483647이다. 한쪽을 `(long)`으로 바꿔 더하거나, `a / 2.0 + b / 2.0`처럼 먼저 나눈다. JavaScript에서도 정수 버릇으로 `(a + b) >> 1`을 쓰면 `>>`가 32비트로 잘라 똑같이 -1이 나온다.

### 지운 값으로 균형을 잰다

지연 삭제에서 `lo.size`, `hi.size` 같은 배열 길이로 균형을 맞추면 지운 값까지 센다. 앞에서 본 마지막 창에서 중앙값이 7 대신 3으로 나온다. 균형과 중앙값의 홀짝 판단은 살아 있는 개수로 한다.

### 맨 위를 치우지 않고 읽는다

`balance`에서 한쪽 맨 위를 다른 쪽으로 옮긴 뒤 `prune`을 부르지 않으면, 새로 드러난 맨 위가 이미 지운 값일 수 있다. 그 값을 중앙값으로 읽거나 다음 넣기의 비교 기준으로 쓰면 틀린다. "맨 위가 바뀔 수 있는 곳마다 prune"을 규칙으로 정해 둔다.

### 창을 다 채우기 전부터 답을 낸다

반복을 0부터 돌리며 매번 중앙값을 넣으면 창이 덜 찬 상태의 값까지 들어가 결과가 n개가 된다. 결과는 `n - k + 1`개다. 첫 창을 따로 채우고, 그다음부터 들어오고 나가는 쌍으로 돈다. k = n이면 결과가 하나, k = 1이면 원래 배열이 그대로 나온다.

## 창 문제를 바꾸면

### 중앙값이 아니라 최댓값이라면

[Sliding Window Maximum](/posts/leetcode-sliding-window-maximum)이다. 최댓값 하나만 필요하면 두 힙도 필요 없다. 값이 줄어드는 순서로 인덱스를 담는 덱 하나로 O(n)에 된다. 중앙값은 "가운데"라서 양쪽을 다 들고 있어야 하고, 최댓값은 "끝"이라서 한쪽만 들고 있으면 된다.

### 창 대신 p90을 구하라면

두 힙의 개수 비율을 1:1이 아니라 9:1로 유지하면 `lo` 맨 위가 p90이다. 지연 삭제는 그대로 쓴다. 펜윅 트리 풀이라면 찾는 순번만 `0.9k`로 바꾸면 된다. 응답 시간 대시보드가 최근 5분의 p90을 보여 줄 때 하는 일과 같은 계산이다.

### 창이 개수가 아니라 시간이라면

"최근 5분 동안 들어온 값"처럼 창 크기가 바뀐다. 나가는 값을 정하는 기준이 시각이 될 뿐, 넣고 빼는 구조는 같다. 다만 k가 고정이 아니라서 중앙값을 읽을 때 살아 있는 개수의 홀짝으로 정한다.

### 값이 끝없이 들어오고 지우기가 없다면

창이 없으니 지연 삭제도 필요 없다. 두 힙만으로 되는 [Find Median from Data Stream](/posts/leetcode-find-median-from-data-stream)으로 돌아간다.

크기 k 힙 하나로 k번째 값을 지키는 [Kth Largest Element in a Stream](/posts/leetcode-kth-largest-element-in-a-stream)도 같은 질문의 다른 모양이다. 그 문제에서 지우기 연산이 추가되면 이 글의 지연 삭제나 정렬 집합이 필요해진다.

## 면접에서 나올 만한 질문

### 데이터 스트림 중앙값과 무엇이 다른가요?

창에서 오래된 값이 빠진다는 점이다. 두 힙으로 작은 절반과 큰 절반을 나누는 건 같지만, 힙은 맨 위가 아닌 값을 빨리 지우지 못한다. 그래서 지울 값을 해시맵에 적어 두었다가 맨 위로 올라올 때 치우는 지연 삭제를 붙이고, 균형은 살아 있는 개수로 맞춘다.

### 지연 삭제를 쓰면 시간 복잡도는 어떻게 되나요?

O(n log n)이다. 값마다 한 번 넣고 한 번 치우며, 각 연산이 힙 크기의 로그다. 힙 크기는 지운 값이 남아 있어서 k가 아니라 최악 n까지 커질 수 있다. 그래서 log k가 아니라 log n이고 공간도 최악 O(n)이다.

### 왜 살아 있는 개수를 따로 세나요?

힙 배열에는 이미 창에서 빠진 값이 섞여 있어서 배열 길이가 실제 개수와 다르다. 배열 길이로 균형을 맞추면 지운 값까지 세어 엉뚱한 값을 옮기고, 중앙값이 틀린다. 넣고 지울 때마다 어느 쪽 개수가 바뀌었는지 직접 더하고 빼서 센다.

### 나가는 값이 어느 힙에 있는지 어떻게 아나요?

`lo` 맨 위와 비교한다. 작거나 같으면 `lo`, 크면 `hi`에 있다고 친다. `lo`의 값이 모두 `hi`의 값 이하라는 규칙 덕분이다. 같은 값이 양쪽에 있을 수 있지만, 그 값이 `lo` 맨 위와 같으면 바로 치워지고, 더 작으면 `hi`에는 있을 수 없어서 셈이 어긋나지 않는다.

### 지연 삭제 없이 푸는 방법은요?

임의의 원소를 O(log k)에 지울 수 있는 정렬 집합 두 개를 쓴다. Java라면 인덱스를 담고 "값, 같으면 인덱스" 순으로 비교하는 `TreeSet` 두 개다. 배열이 미리 주어지면 좌표 압축 후 펜윅 트리로 개수를 세고 k/2번째 값을 찾는 방법도 있다. 둘 다 지울 값을 미루지 않는다.

### O(n · k)인 배열 풀이는 정말 쓸모없나요?

아니다. 정렬된 창에서 이분 탐색으로 자리를 찾아 빼고 끼우면 밀기가 메모리 복사라 매우 빠르다. 10만 개에서 k = 1000이면 31ms로 두 힙의 102ms보다 빨랐고, k = 5만에서야 410ms로 졌다. 복잡도와 함께 실제 크기에서의 속도도 말할 수 있으면 좋다.

### Java로 짤 때 무엇을 조심하나요?

평균을 구할 때 두 `int`를 그대로 더하면 넘친다. 2147483647 두 개를 더해 2.0으로 나누면 -1.0이 나온다. `(long)`으로 바꿔 더한 뒤 `2.0`으로 나눈다. `TreeSet`에 값을 그대로 넣으면 같은 값이 하나로 합쳐지니 인덱스를 넣고 비교자에서 값이 같을 때 인덱스로 순서를 정한다.
