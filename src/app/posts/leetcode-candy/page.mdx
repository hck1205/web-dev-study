  어려운 점은 아이마다 왼쪽 친구와 오른쪽 친구를 동시에 신경 써야 한다는 것이다. 그래서 일을 둘로 나눈다. 먼저 왼쪽에서 오른쪽으로 걸으며 왼쪽 친구만 보고 사탕 수를 정한다. 그다음 오른쪽에서 왼쪽으로 걸으며 오른쪽 친구만 보고 모자란 아이에게 더 준다.

  계단을 떠올리면 쉽다. 점수가 오르는 곳은 올라가는 계단이고 내려가는 곳은 내려가는 계단이다. 계단 한 칸마다 사탕이 하나씩 늘어난다. 산꼭대기에 선 아이는 왼쪽 계단과 오른쪽 계단 중 더 긴 쪽만큼 받으면 양쪽 규칙을 다 지킨다. 두 번 걷기만 하면 모든 아이의 사탕 수가 정해진다.

[Candy](https://leetcode.com/problems/candy/)는 LeetCode 135번이고 Hard로 분류된다. 코드는 짧은데 Hard인 이유가 있다. 아이마다 양쪽 이웃이 모두 조건을 걸어서, 한 방향으로만 훑는 그리디가 통하지 않는다. "두 방향의 조건을 따로 풀고 합친다"는 생각 하나가 필요하고, 그게 왜 최소인지 설명할 수 있어야 한다.

이 글은 다섯 풀이를 본다. 고칠 게 없을 때까지 계속 고치는 반복, 왼쪽 배열과 오른쪽 배열을 따로 만드는 두 배열 풀이, 배열 하나로 두 번 훑는 풀이, 점수가 낮은 아이부터 채우는 풀이(정렬과 메모 재귀), 오르막과 내리막의 길이만 세는 O(1) 공간 풀이다. 그리디가 맞는지 확인하는 일반적인 방법은 [그리디 알고리즘 글](/posts/greedy-algorithms)에 있다. 코드는 Node.js 22, Python 3, Java 21에서 돌렸다.

## 옆 친구보다 점수가 높으면 사탕도 많이

아이 n명이 한 줄로 서 있고 i번째 아이의 점수가 `ratings[i]`다. 사탕을 다음 규칙으로 나눠 준다.

- 모든 아이는 사탕을 1개 이상 받는다.
- 바로 옆 아이보다 점수가 높은 아이는 그 아이보다 사탕을 더 많이 받는다.

필요한 사탕의 최소 개수를 돌려준다. 풀이를 고르는 데 영향을 주는 제약은 이렇다.

- 아이는 최대 2 × 10^4명이다. O(n²)은 4 × 10^8번이라 아슬아슬하게 느리다.
- 점수는 0 이상 2 × 10^4 이하이고 같은 점수가 있을 수 있다.
- 점수가 같은 이웃끼리는 아무 조건이 없다. 같은 점수인데 사탕이 달라도 된다.

마지막 조건을 놓치기 쉽다. "점수가 같으면 사탕도 같아야 한다"는 규칙은 없다. `[1, 2, 2]`의 답은 `[1, 2, 1]`로 4개다. 셋째 아이는 둘째 아이와 점수가 같으니 1개만 받아도 된다.

## 왼쪽만 보고 나눠 주면 생기는 일

이 글에서 계속 쓸 예시는 `ratings = [1, 3, 5, 4, 2, 1]`이다. 점수가 5까지 올라갔다가 1까지 내려가는 산 모양이다.

왼쪽에서 오른쪽으로 걸으며 왼쪽 친구만 신경 써 보자. 모두 1개에서 시작해, 왼쪽 친구보다 점수가 높으면 왼쪽 친구 + 1개를 준다.

```text
점수   1  3  5  4  2  1
사탕   1  2  3  1  1  1
```

오르막은 잘 처리됐다. 그런데 내리막이 틀렸다. 4점 아이(1개)는 오른쪽의 2점 아이(1개)보다 점수가 높은데 사탕이 같다. 내리막에서는 오른쪽 친구가 기준인데, 왼쪽에서 걸어오면 오른쪽 친구가 몇 개 받을지 아직 모른다.

정답은 이렇다.

```text
점수   1  3  5  4  2  1
사탕   1  2  4  3  2  1
```

합은 13이다. 내리막은 오른쪽 끝에서부터 1, 2, 3으로 올라오고, 꼭대기 5점 아이는 왼쪽 계단으로는 3개, 오른쪽 계단으로는 4개가 필요해서 큰 쪽인 4개를 받는다. 이 그림 안에 풀이가 다 들어 있다.

## 고칠 게 없을 때까지 다시 고친다

가장 먼저 떠오르는 방법은 규칙을 어긴 곳을 찾아 고치는 일을 반복하는 것이다. 모두 1개에서 시작하고, 어떤 아이가 옆 친구보다 점수가 높은데 사탕이 적거나 같으면 친구 + 1로 올린다. 한 바퀴 돌며 고친 게 없으면 끝이다.

```js
function candy(ratings) {
  const n = ratings.length;
  const candy = new Array(n).fill(1);
  let changed = true;
  while (changed) {                                    // 고친 게 없을 때까지 반복
    changed = false;
    for (let i = 0; i < n; i++) {
      if (i > 0 && ratings[i] > ratings[i - 1] && candy[i] <= candy[i - 1]) {
        candy[i] = candy[i - 1] + 1; changed = true;   // 왼쪽 친구보다 많이
      }
      if (i < n - 1 && ratings[i] > ratings[i + 1] && candy[i] <= candy[i + 1]) {
        candy[i] = candy[i + 1] + 1; changed = true;   // 오른쪽 친구보다 많이
      }
    }
  }
  return candy.reduce((a, b) => a + b, 0);
}
```

사탕은 올리기만 하고, 꼭 필요한 만큼만 올리니 끝나면 최솟값이다. 문제는 횟수다. 점수가 계속 내려가는 `[n, n-1, ..., 1]`이면 한 바퀴에 한 칸씩만 고쳐진다. 오른쪽 끝에서 시작된 변화가 왼쪽으로 한 칸씩 번지는데, 반복은 왼쪽에서 오른쪽으로 돌기 때문이다. 그래서 n바퀴가 돌고 O(n²)이다.

```text
2000 repeat 2001000 27.7
20000 repeat 200010000 2611.9
```

2만 명에서 2.6초다. 낭비가 어디서 오는지는 앞의 관찰에 있다. 왼쪽 친구 조건은 왼쪽에서 오른쪽으로 훑으면 한 번에 퍼지고, 오른쪽 친구 조건은 반대로 훑으면 한 번에 퍼진다. 방향을 맞춰 한 번씩 훑으면 반복이 필요 없다.

## 두 방향의 조건을 따로 푼다

규칙을 둘로 쪼갠다.

- 왼쪽 규칙: 왼쪽 친구보다 점수가 높으면 왼쪽 친구보다 사탕이 많다.
- 오른쪽 규칙: 오른쪽 친구보다 점수가 높으면 오른쪽 친구보다 사탕이 많다.

왼쪽 규칙만 지키는 최소 배분 `left`는 왼쪽에서 오른쪽으로 한 번 훑으면 나온다. 앞에서 해 본 그대로다. 오른쪽 규칙만 지키는 최소 배분 `right`는 오른쪽에서 왼쪽으로 한 번 훑으면 나온다. 그리고 i번째 아이의 답은 `max(left[i], right[i])`다.

```js
function candy(ratings) {
  const n = ratings.length;
  const left = new Array(n).fill(1);                   // 왼쪽 규칙만 지킬 때의 최소
  const right = new Array(n).fill(1);                  // 오른쪽 규칙만 지킬 때의 최소
  for (let i = 1; i < n; i++)
    if (ratings[i] > ratings[i - 1]) left[i] = left[i - 1] + 1;
  for (let i = n - 2; i >= 0; i--)
    if (ratings[i] > ratings[i + 1]) right[i] = right[i + 1] + 1;
  let sum = 0;
  for (let i = 0; i < n; i++) sum += Math.max(left[i], right[i]); // 두 규칙을 모두 지킨다
  return sum;
}
```

예시에서 `left`는 `[1, 2, 3, 1, 1, 1]`, `right`는 `[1, 1, 4, 3, 2, 1]`이고, 칸별 최댓값이 `[1, 2, 4, 3, 2, 1]`이다.

### 칸별 최댓값이 왜 최소인가

두 가지를 보이면 된다. 이 배분이 규칙을 지킨다는 것, 그리고 이보다 적게 줄 수 없다는 것이다.

먼저 적게 줄 수 없다. `left[i]`는 "i에서 왼쪽으로 점수가 계속 내려가는 칸 수 + 1"이다. 예를 들어 `left[2] = 3`은 0번, 1번, 2번이 점수 1, 3, 5로 계속 오르기 때문이다. 이 셋은 규칙 때문에 사탕이 적어도 1, 2, 3개여야 한다. 즉 어떤 올바른 배분에서도 i번째 아이는 `left[i]`개 이상 받는다. 같은 이유로 `right[i]`개 이상도 받는다. 그러니 `max(left[i], right[i])`개 이상 받아야 한다. 이건 하한이다.

다음은 규칙을 지킨다. i가 왼쪽 친구보다 점수가 높으면 `left[i] = left[i-1] + 1`이다. 그런데 i - 1번의 답이 `right[i-1]`일 수도 있지 않을까. i - 1이 i보다 점수가 낮으니 오른쪽 규칙에서 i - 1은 i 때문에 늘어날 일이 없다. 그래서 `right[i-1]`은 1이거나, i - 1에서 오른쪽으로 내리막이 시작될 때만 커지는데, i가 더 높으니 내리막이 아니다. `right[i-1] = 1`이다. 결국 i - 1의 답은 `left[i-1]`이고, i의 답은 `left[i]` 이상이니 더 많다. 오른쪽도 대칭이다.

모든 아이가 하한만큼 받고 그게 규칙을 지키니 최소다. 이 증명은 [그리디 알고리즘 글](/posts/greedy-algorithms#그리디인지-확인하는-순서)의 "하한을 보이고, 그 하한을 실제로 만든다"는 방식과 같다.

시간 O(n), 공간 O(n)이다. 앞에서 2.6초 걸린 2만 명 입력이 2.5ms로 줄었다.

## 배열 하나로 두 번 훑는다

`left`를 다 만든 뒤에 오른쪽에서 훑을 때, `right`를 따로 두지 않고 바로 최댓값을 적을 수 있다. 오른쪽에서 왼쪽으로 가며 `candy[i] = max(candy[i], candy[i+1] + 1)`로 고친다.

```js
function candy(ratings) {
  const n = ratings.length;
  const candy = new Array(n).fill(1);                  // 모두 한 개씩은 받는다
  for (let i = 1; i < n; i++)                          // 왼쪽 친구만 본다
    if (ratings[i] > ratings[i - 1]) candy[i] = candy[i - 1] + 1;
  for (let i = n - 2; i >= 0; i--)                     // 오른쪽 친구를 보며 모자라면 올린다
    if (ratings[i] > ratings[i + 1]) candy[i] = Math.max(candy[i], candy[i + 1] + 1);
  return candy.reduce((a, b) => a + b, 0);
}
```

여기서 `candy[i+1]`은 이미 "i + 1의 최종 답"이다. 오른쪽부터 고쳐 왔으니까. 그래서 `candy[i+1] + 1`은 `right[i]`가 아니라 최종 답 + 1인데, 앞의 증명에서 본 대로 i가 i + 1보다 높으면 i + 1의 최종 답은 `right[i+1]`과 같아서 결과가 같다.

예시에서 배열이 바뀌는 모습을 찍었다.

```text
L 2 [1,2,3,1,1,1]
R 4 [1,2,3,1,2,1]
R 3 [1,2,3,3,2,1]
R 2 [1,2,4,3,2,1]
```

왼쪽 훑기가 끝나면 `[1, 2, 3, 1, 1, 1]`이고, 오른쪽 훑기에서 4번, 3번, 2번이 차례로 올라간다. 2번(5점)은 3개를 갖고 있었는데 오른쪽 친구 3개보다 많아야 해서 4개가 된다. 아래 그림에서 다음을 누르면 두 번의 훑기를 따라갈 수 있다.

## 점수가 낮은 아이부터 채운다

전혀 다른 각도에서 볼 수도 있다. 규칙은 "점수가 낮은 이웃보다 많이"이니, 점수가 낮은 아이의 사탕이 먼저 정해져야 높은 아이의 사탕을 정할 수 있다. 그래서 점수가 낮은 아이부터 차례로 보면서, 자기보다 낮은 이웃의 사탕 + 1과 1 중 큰 값을 준다.

```js
function candy(ratings) {
  const n = ratings.length;
  const candy = new Array(n).fill(1);
  const order = [...ratings.keys()].sort((a, b) => ratings[a] - ratings[b]); // 점수가 낮은 아이부터
  for (const i of order) {
    if (i > 0 && ratings[i] > ratings[i - 1]) candy[i] = Math.max(candy[i], candy[i - 1] + 1);
    if (i < n - 1 && ratings[i] > ratings[i + 1]) candy[i] = Math.max(candy[i], candy[i + 1] + 1);
  }
  return candy.reduce((a, b) => a + b, 0);
}
```

i를 볼 때 i보다 점수가 낮은 이웃은 이미 정해졌다. 정렬 순서상 먼저 나왔기 때문이다. 점수가 같은 이웃은 조건이 없어서 순서가 섞여도 괜찮다. 정렬이 O(n log n)이라 전체 O(n log n), 공간 O(n)이다. 2만 명에서 5.5ms였다.

이 풀이는 문제를 그래프로 보여 준다. 점수가 낮은 아이에서 높은 이웃으로 화살표를 그리면 고리가 없는 그래프(DAG)가 되고, 아이의 사탕 수는 "그 아이로 들어오는 가장 긴 화살표 길 + 1"이다. 정렬은 이 그래프의 위상 정렬 노릇을 한다. 그래프의 위상 정렬은 [그래프 탐색 글](/posts/ds-graph-bfs-dfs)에 있다.

예시 `[1, 3, 5, 4, 2, 1]`에 화살표를 그리면 이렇다. 괄호 안은 점수다.

```text
0(1) → 1(3) → 2(5) ← 3(4) ← 4(2) ← 5(1)
```

2번으로 들어오는 길은 왼쪽에서 오는 0 → 1 → 2(화살표 2개)와 오른쪽에서 오는 5 → 4 → 3 → 2(화살표 3개)가 있다. 긴 쪽이 3이라 2번은 4개를 받는다. 두 번 훑기의 `left`와 `right`가 바로 이 두 길의 길이 + 1이었다. 한 줄에서는 들어오는 길이 왼쪽과 오른쪽 둘뿐이라 두 번 훑으면 끝나고, 격자처럼 길이 여러 방향에서 들어오면 이 그래프 관점이 필요해진다.

### 메모 재귀로 쓰면

같은 생각을 재귀로 쓰면 정렬도 필요 없다. 아이 i에게 필요한 사탕은 "자기보다 낮은 이웃에게 필요한 사탕 + 1"의 최댓값이고, 낮은 이웃이 없으면 1이다.

```js
function candy(ratings) {
  const n = ratings.length;
  const memo = new Array(n).fill(0);                   // 0이면 아직 모른다
  function need(i) {
    if (memo[i]) return memo[i];
    let c = 1;
    if (i > 0 && ratings[i] > ratings[i - 1]) c = Math.max(c, need(i - 1) + 1);
    if (i < n - 1 && ratings[i] > ratings[i + 1]) c = Math.max(c, need(i + 1) + 1);
    return (memo[i] = c);
  }
  let sum = 0;
  for (let i = 0; i < n; i++) sum += need(i);
  return sum;
}
```

아이마다 한 번만 계산하니 O(n)이다. 그런데 2만 명이 점수 순으로 내려가는 입력에서 `RangeError: Maximum call stack size exceeded`가 났다. 0번이 1번을, 1번이 2번을 부르며 재귀가 2만 단계로 깊어지기 때문이다. 길이 2만은 LeetCode 제약 안이니 이 코드는 제출하면 터진다. 재귀 깊이가 입력 크기에 비례하는 풀이는 JavaScript와 Python에서 특히 조심해야 한다. 2차원 격자처럼 두 방향 훑기가 통하지 않는 변형에서는 이 생각이 쓸모 있으니, 그때는 정렬 순서로 반복문을 쓴다.

## 오르막과 내리막의 길이만 센다

두 번 훑기는 배열 O(n)이 든다. 사탕 수가 계단 모양이라는 걸 쓰면 숫자 몇 개로 줄일 수 있다.

- 오르막(점수가 오른다): 사탕이 1, 2, 3, ...으로 하나씩 늘어난다.
- 평지(점수가 같다): 다시 1부터다. 같은 점수끼리는 조건이 없다.
- 내리막(점수가 내린다): 끝에서부터 1, 2, 3, ...이다. 내리막이 길어질수록 내리막에 있던 아이들이 모두 하나씩 더 받아야 한다.

그래서 세 숫자를 들고 다닌다. `up`은 지금 오르막의 길이, `down`은 지금 내리막의 길이, `peak`는 내리막 직전 꼭대기까지의 오르막 길이다.

```js
function candy(ratings) {
  const n = ratings.length;
  let total = 1, up = 0, down = 0, peak = 0;           // 첫 아이는 1개
  for (let i = 1; i < n; i++) {
    if (ratings[i] > ratings[i - 1]) {                 // 오르막: 앞 아이 + 1
      up++; down = 0; peak = up;
      total += up + 1;
    } else if (ratings[i] === ratings[i - 1]) {        // 평지: 다시 1개부터
      up = 0; down = 0; peak = 0;
      total += 1;
    } else {                                           // 내리막
      up = 0; down++;
      total += down;                                   // 새 아이 1개 + 내리막 아이들이 하나씩 더
      if (down > peak) total += 1;                     // 꼭대기도 내리막보다 높아야 한다
    }
  }
  return total;
}
```

내리막에서 `total += down`이 핵심 계산이다. 내리막이 d칸이 되면 새로 온 아이가 1개를 받고, 그 앞의 d - 1명이 하나씩 더 받아야 해서 합이 d만큼 는다. 꼭대기는 원래 `peak + 1`개를 갖고 있는데, 내리막이 `peak`보다 길어지면 꼭대기 바로 옆 아이가 꼭대기와 같아지니 꼭대기도 하나 더 받는다.

## Python과 Java로 옮긴 두 번 훑기

```python
from typing import List


class Solution:
    def candy(self, ratings: List[int]) -> int:
        n = len(ratings)
        candy = [1] * n                            # 모두 한 개씩은 받는다
        for i in range(1, n):                      # 왼쪽 친구보다 점수가 높으면 하나 더
            if ratings[i] > ratings[i - 1]:
                candy[i] = candy[i - 1] + 1
        for i in range(n - 2, -1, -1):             # 오른쪽 친구보다 높으면 그쪽 + 1 이상
            if ratings[i] > ratings[i + 1]:
                candy[i] = max(candy[i], candy[i + 1] + 1)
        return sum(candy)
```


`range(n - 2, -1, -1)`은 n - 2부터 0까지 거꾸로 돈다. 끝값 -1은 포함되지 않는다. 아이가 한 명이면 두 반복 모두 돌지 않고 1이 나온다.

```java
import java.util.*;

class Solution {
    public int candy(int[] ratings) {
        int n = ratings.length;
        int[] candy = new int[n];
        Arrays.fill(candy, 1);                              // 모두 한 개씩은 받는다
        for (int i = 1; i < n; i++)                         // 왼쪽 친구보다 높으면 하나 더
            if (ratings[i] > ratings[i - 1]) candy[i] = candy[i - 1] + 1;
        for (int i = n - 2; i >= 0; i--)                    // 오른쪽 친구보다 높으면 그쪽 + 1 이상
            if (ratings[i] > ratings[i + 1]) candy[i] = Math.max(candy[i], candy[i + 1] + 1);
        int sum = 0;
        for (int c : candy) sum += c;
        return sum;
    }
}
```

## 사탕을 잘못 세는 코드

### 한 방향으로만 훑는다

왼쪽에서 한 번만 훑으면 내리막을 처리하지 못한다. `[3, 2, 1]`에서 모두 1개로 3이 나온다. 정답은 `[3, 2, 1]`개씩 6이다. 한 방향 훑기는 그 방향의 이웃이 이미 정해져 있을 때만 통한다.

### 두 번째 훑기에서 max를 빼먹는다

```js
for (let i = n - 2; i >= 0; i--)
  if (ratings[i] > ratings[i + 1]) candy[i] = candy[i + 1] + 1;   // 왼쪽 결과를 덮어쓴다
```

꼭대기에서 왼쪽 계단이 더 길면 틀린다. `[1, 2, 3, 1]`에서 왼쪽 훑기로 꼭대기가 3개가 됐는데, 오른쪽 훑기가 `1 + 1 = 2`로 덮어써서 `[1, 2, 2, 1]`, 합 6이 나온다. 꼭대기 3점이 왼쪽 2점과 사탕이 같아 규칙을 어긴다. 정답은 7이다. 이 글의 예시 `[1, 3, 5, 4, 2, 1]`은 오른쪽 계단이 더 길어서 이 버그가 숨는다. 왼쪽이 긴 산과 오른쪽이 긴 산을 둘 다 테스트해야 한다.

### 점수가 같으면 사탕도 같게 준다

같은 점수에 같은 사탕을 맞추는 코드를 넣으면 `[1, 2, 2]`에서 `[1, 2, 2]`, 합 5가 나온다. 정답은 4다. 문제에 없는 조건을 스스로 만든 것이다. `[1, 2, 87, 87, 87, 2, 1]`은 정답이 13인데 이 코드로는 15가 나왔다. 같은 점수 셋이 모두 3개씩 받기 때문이다. 정답은 가운데 87점 아이가 1개만 받는 `[1, 2, 3, 1, 3, 2, 1]`이다.

### 두 번째 훑기를 같은 방향으로 한다

오른쪽 규칙을 고치는 반복을 왼쪽에서 오른쪽으로 돌리면, i를 고칠 때 i + 1은 아직 최종값이 아니다. `[3, 2, 1]`에서 0번을 볼 때 1번이 1개라 0번이 2개가 되고, 그 뒤 1번이 2개가 되어도 0번은 다시 고쳐지지 않는다. 합 5가 나오고 정답은 6이다. 오른쪽 규칙은 오른쪽부터 정해져야 한다.

### 계단 세기에서 평지 뒤의 peak를 남겨 둔다

계단 세기 풀이에서 평지를 만났을 때 `peak = 0`을 빼먹으면, 평지 앞 오르막의 꼭대기 길이가 남아 다음 내리막에서 꼭대기 보정이 늦게 들어간다. 평지가 산을 끊는다는 걸 코드에 반영해야 한다.

## 줄 모양이 바뀌면

### 아이들이 원으로 둘러앉았다면

첫 아이와 마지막 아이도 이웃이 된다. 점수가 가장 낮은 아이 m은 자기보다 낮은 이웃이 없으니 언제나 1개면 된다. 그래서 원을 m에서 끊어 m을 양 끝에 두면 직선 문제가 된다. 양 끝의 m은 같은 아이라 합에서 한 번 뺀다.

```js
function candyCircle(ratings) {
  const n = ratings.length;
  if (n <= 2) return candy(ratings);                   // 둘 이하는 원이어도 이웃이 같다
  let m = 0;
  for (let i = 1; i < n; i++) if (ratings[i] < ratings[m]) m = i;  // 가장 낮은 아이
  const line = [];
  for (let k = 0; k <= n; k++) line.push(ratings[(m + k) % n]);   // m에서 끊어 양 끝에 m
  const c = new Array(n + 1).fill(1);
  for (let i = 1; i <= n; i++) if (line[i] > line[i - 1]) c[i] = c[i - 1] + 1;
  for (let i = n - 1; i >= 0; i--) if (line[i] > line[i + 1]) c[i] = Math.max(c[i], c[i + 1] + 1);
  let sum = 0;
  for (let i = 0; i < n; i++) sum += c[i];             // 끝의 m은 앞의 m과 같은 아이라 뺀다
  return sum;
}
```

원에서 고칠 게 없을 때까지 반복하는 풀이와 무작위 입력 4만 개로 맞춰 봤다. `[2, 1, 3]`은 직선이면 5지만 원이면 3점 아이가 2점 아이의 이웃이 되어 6이다.

### 격자라면

아이들이 2차원 격자에 앉아 상하좌우 이웃과 비교한다면 두 방향 훑기가 통하지 않는다. 방향이 넷이라 어느 순서로 훑어도 아직 안 정해진 이웃이 남는다. 이때는 점수가 낮은 칸부터 정렬 순서로 채우는 풀이가 그대로 일반화된다. 칸마다 "낮은 이웃의 사탕 + 1"의 최댓값이다. LeetCode 329번 Longest Increasing Path in a Matrix가 같은 구조로, 가장 긴 증가 경로를 메모 재귀나 위상 정렬로 구한다.

### 누가 몇 개 받는지 돌려 달라면

두 번 훑기는 이미 아이별 사탕 배열을 만든다. 합 대신 배열을 돌려주면 된다. 계단 세기 풀이는 합만 알고 개별 값을 저장하지 않으니 이 변형에는 맞지 않는다.

### 점수가 같으면 사탕도 같아야 한다면

규칙이 바뀌면 같은 점수의 이웃을 한 덩어리로 묶어 생각한다. 덩어리끼리는 원래 규칙을 따르고, 덩어리 안은 모두 같은 값을 받는다. 덩어리를 한 칸으로 줄여 두 번 훑기를 한 뒤, 덩어리 크기를 곱해 더하면 된다.

같은 그리디 묶음의 다른 문제로는 [Hand of Straights](/posts/leetcode-hand-of-straights), [Merge Triplets to Form Target Triplet](/posts/leetcode-merge-triplets-to-form-target-triplet), [Valid Parenthesis String](/posts/leetcode-valid-parenthesis-string), [IPO](/posts/leetcode-ipo)가 있다. 양쪽에서 훑어 칸마다 합치는 모양은 [Trapping Rain Water](/posts/leetcode-trapping-rain-water)와 [Product of Array Except Self](/posts/leetcode-product-of-array-except-self)에서도 나온다.

## 면접에서 나올 만한 질문

### 왜 한 번 훑어서는 안 되나요?

아이마다 왼쪽과 오른쪽 이웃이 모두 조건을 걸기 때문이다. 왼쪽에서 훑으면 오른쪽 이웃의 사탕이 아직 정해지지 않아 내리막을 처리할 수 없다. 그래서 왼쪽 조건은 왼쪽에서, 오른쪽 조건은 오른쪽에서 한 번씩 훑어 각각 정한다.

### 두 값의 최댓값을 주는 게 왜 최소인가요?

왼쪽에서 이어지는 오르막 길이는 어떤 올바른 배분에서도 피할 수 없는 하한이고, 오른쪽도 마찬가지다. 그래서 두 하한의 최댓값보다 적게 줄 수 없다. 그리고 최댓값을 주면 실제로 두 규칙을 모두 지키니, 하한을 그대로 달성한 최소 배분이다.

### 두 번째 훑기에서 max를 쓰는 이유는?

첫 번째 훑기가 정한 값을 지키기 위해서다. 꼭대기에서 왼쪽 계단이 더 길면 왼쪽 결과가 더 크다. 그냥 덮어쓰면 `[1, 2, 3, 1]`처럼 꼭대기가 왼쪽 친구와 같아져 규칙을 어긴다.

### 공간을 O(1)로 줄일 수 있나요?

오르막 길이, 내리막 길이, 내리막 직전 꼭대기의 오르막 길이만 들고 다니면 된다. 내리막이 한 칸 늘 때마다 내리막의 아이들이 하나씩 더 받으니 내리막 길이만큼 더하고, 내리막이 꼭대기 오르막보다 길어지면 꼭대기에도 하나 더 준다. 평지를 만나면 셋 다 0으로 되돌린다.

### 점수가 같은 이웃은 어떻게 처리하나요?

아무 조건이 없다. 같은 점수인데 사탕이 달라도 된다. 그래서 두 번 훑기에서 같은 점수는 그냥 건너뛰고, 계단 세기에서는 평지로 보고 다시 1부터 센다. 같게 맞추면 `[1, 2, 2]`에서 4가 아니라 5가 나온다.

### 메모 재귀로 풀면 무엇이 문제인가요?

시간은 O(n)이지만 재귀 깊이가 n까지 갈 수 있다. 점수가 계속 내려가는 2만 명 입력에서 JavaScript 호출 스택이 넘쳤다. 같은 생각을 쓰려면 점수 순으로 정렬해 반복문으로 채운다.

### 정렬 풀이에서 점수가 같은 아이들의 순서는 상관없나요?

상관없다. 점수가 같은 이웃 사이에는 조건이 없어서 서로의 사탕 수에 영향을 주지 않는다. 아이 i를 볼 때 필요한 건 i보다 점수가 낮은 이웃의 값뿐이고, 그 이웃은 정렬 순서상 반드시 먼저 처리됐다. 그래서 같은 점수끼리는 어떤 순서로 봐도 결과가 같다.

### 원형으로 앉으면 어떻게 하나요?

점수가 가장 낮은 아이는 낮은 이웃이 없어 언제나 1개면 되니, 그 아이에서 원을 끊는다. 그 아이를 양 끝에 둔 직선으로 두 번 훑고, 같은 아이가 두 번 세어진 것을 한 번 뺀다.
