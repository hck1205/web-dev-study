<EasyIntro>

</EasyIntro>

도시와 양방향 길이 주어지고, 길마다 거리가 붙어 있다. 도시마다 임계 거리 안에 닿는 다른 도시가 몇 곳인지 세서 가장 적은 도시를 고르는 문제다. 출발점이 하나가 아니라 n개라서 지금까지의 최단 경로 문제와 다르다. 모든 쌍의 최단 거리가 필요한 문제의 대표이고, 플로이드-워셜을 쓸 자리가 이렇게 생긴다.

[LeetCode 1334. Find the City With the Smallest Number of Neighbors at a Threshold Distance](https://leetcode.com/problems/find-the-city-with-the-smallest-number-of-neighbors-at-a-threshold-distance/)는 Medium이다. 이 글은 도시마다 DFS를 돌리는 것부터 벨만-포드, 힙 다익스트라, 배열 다익스트라, 플로이드-워셜까지 다섯 가지 풀이를 짜고, 동점을 처리하는 부분을 따로 본다. 플로이드-워셜이 왜 성립하는지는 [최단 경로 알고리즘 글의 플로이드-워셜 절](/posts/shortest-path-algorithms#모든-쌍이-필요하면-플로이드-워셜)에, 출발점 하나짜리 다익스트라는 [Network Delay Time](/posts/leetcode-network-delay-time)에 있으니 여기서는 이 문제에 맞게 고르는 법과 틀리는 지점에 집중한다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 임계 거리 안에 이웃이 가장 적은 도시

도시는 0부터 n - 1까지다. `edges[i] = [a, b, w]`는 a와 b를 잇는 양방향 길이고 거리는 w다. 도시 i에서 최단 거리가 `distanceThreshold` 이하인 다른 도시를 i의 이웃이라고 하자. 이웃 수가 가장 적은 도시를 돌려준다. 그런 도시가 여럿이면 번호가 가장 큰 도시를 돌려준다.

풀이를 고를 때 보는 조건은 이렇다.

- 도시는 100개 이하다. 모든 쌍을 구하는 O(n³)도 100만 번이라 넉넉하다. 이 조건이 플로이드-워셜을 허락한다.
- 길은 많아야 n(n - 1) / 2개, 곧 4,950개다. 도시마다 길이 꽉 차 있을 수 있다.
- 거리와 임계 거리는 1 이상 1만 이하다. 음수가 없어 다익스트라도 쓸 수 있다. 가장 긴 최단 거리도 99 × 10^4 정도라 정수로 충분하다.
- 같은 두 도시 사이에 길은 하나뿐이다.

이 글에서 쓸 예시는 도시 5개, 길 5개이고 임계 거리는 4다.

```text
0 - 1 : 3     1 - 3 : 4     3 - 4 : 3
1 - 2 : 1     2 - 3 : 1
```

손으로 풀어 보자. 도시 0에서 1까지는 3이다. 2는 1을 거쳐 3 + 1 = 4, 3은 1에서 바로 가면 3 + 4 = 7이지만 2를 거치면 4 + 1 = 5다. 4는 5 + 3 = 8이다. 4 이하인 도시는 1과 2, 이웃은 두 곳이다.

같은 방법으로 도시마다 세면 이렇다.

```text
도시 0: 1(3) 2(4)               → 2곳
도시 1: 0(3) 2(1) 3(2)          → 3곳   4까지는 5라 빠진다
도시 2: 0(4) 1(1) 3(1) 4(4)     → 4곳
도시 3: 1(2) 2(1) 4(3)          → 3곳   0까지는 5
도시 4: 2(4) 3(3)               → 2곳   1까지는 5, 0까지는 8
```

이웃이 가장 적은 건 두 곳짜리 도시 0과 4다. 동점이니 번호가 큰 4가 답이다. 1에서 3으로 가는 길도 눈여겨보자. 바로 가는 길은 4인데 2를 거치면 2다. 임계 거리 4 안에 들어오는지는 이 차이로 갈리기도 하니, 바로 이어진 길만 보면 안 되고 최단 거리를 정확히 구해야 한다.

## 도시마다 길을 끝까지 따라가 보는 DFS

도시 하나를 출발점으로 잡고 길을 따라가 본다. 지금까지 온 거리가 임계 거리를 넘으면 더 가 볼 필요가 없고, 같은 도시에 더 짧게 와 본 적이 있어도 돌아온다. 이걸 도시마다 한 번씩 한다.

```js
function findTheCity(n, edges, distanceThreshold) {
  const graph = Array.from({ length: n }, () => []);
  for (const [a, b, w] of edges) {
    graph[a].push([b, w]);
    graph[b].push([a, w]); // 양방향
  }

  let answer = -1, bestCount = Infinity;
  for (let src = 0; src < n; src++) {
    const best = new Array(n).fill(Infinity); // src에서 각 도시까지 찾은 가장 짧은 거리
    const dfs = (u, d) => {
      // 임계 거리를 넘었거나 더 짧게 와 본 적이 있으면 돌아온다
      if (d > distanceThreshold || d >= best[u]) return;
      best[u] = d;
      for (const [v, w] of graph[u]) dfs(v, d + w);
    };
    dfs(src, 0);

    let count = 0;
    for (let v = 0; v < n; v++) {
      if (v !== src && best[v] <= distanceThreshold) count++;
    }
    if (count <= bestCount) { bestCount = count; answer = src; } // 같으면 번호가 큰 쪽
  }
  return answer;
}
```

임계 거리를 넘으면 끊는다는 가지치기가 이 문제에서는 꽤 듣는다. 예시에서는 다섯 도시를 다 합쳐 호출이 48번이었다. 하지만 도시 100개가 모두 이어진 그래프(길 4,950개, 거리는 1~1만 무작위)에 임계 거리 1만을 주니 호출이 7,805만 번, 시간이 1.2초였다. 한 도시의 거리가 줄어들 때마다 그 뒤를 처음부터 다시 훑기 때문이다. 시간을 다항식으로 묶을 수 없다.

## 도시마다 벨만-포드를 한 번씩

재귀 대신 도시마다 간선 전체를 n - 1번 훑는다. 길이 양방향이니 한 간선에서 두 방향을 모두 완화한다. 완화(relaxation)는 "a까지 거리 + w가 b까지 거리보다 작으면 줄인다"는 한 줄이다.

```js
function findTheCity(n, edges, distanceThreshold) {
  let answer = -1, bestCount = Infinity;
  for (let src = 0; src < n; src++) {
    const dist = new Array(n).fill(Infinity);
    dist[src] = 0;
    for (let round = 1; round < n; round++) {
      let changed = false;
      for (const [a, b, w] of edges) {
        if (dist[a] + w < dist[b]) { dist[b] = dist[a] + w; changed = true; }
        if (dist[b] + w < dist[a]) { dist[a] = dist[b] + w; changed = true; }
      }
      if (!changed) break; // 한 바퀴 동안 바뀐 게 없으면 이 도시는 끝
    }

    let count = 0;
    for (let v = 0; v < n; v++) {
      if (v !== src && dist[v] <= distanceThreshold) count++;
    }
    if (count <= bestCount) { bestCount = count; answer = src; }
  }
  return answer;
}
```

시간은 도시마다 O(n · E)라 전체 O(n² · E)다. 길이 꽉 찬 최악이면 100 × 100 × 4,950으로 약 5,000만 번이다. 바뀐 게 없으면 멈추는 덕분에 무작위 완전 그래프에서는 도시마다 평균 6바퀴로 끝났고 전체 20ms 남짓이었다. 하지만 바퀴 수는 입력에 달려 있다. 도시 100개를 한 줄로 이은 사슬에서는 도시마다 바퀴가 늘어 전체 5,050바퀴를 돌았다.

## 도시마다 다익스트라, 임계 거리에서 끊는다

거리가 모두 1 이상이니 도시마다 다익스트라를 돌려도 된다. 이 문제에는 덤이 하나 있다. 임계 거리를 넘는 도시는 이웃이 아니니 정확한 거리를 몰라도 된다. 그러니 임계 거리를 넘는 후보는 힙에 넣지도 않는다. 그러면 힙에서 꺼내는 도시가 곧 이웃이라 개수를 바로 센다.

```js
function findTheCity(n, edges, distanceThreshold) {
  const graph = Array.from({ length: n }, () => []);
  for (const [a, b, w] of edges) {
    graph[a].push([b, w]);
    graph[b].push([a, w]);
  }

  const countFrom = (src) => {
    const dist = new Array(n).fill(Infinity);
    dist[src] = 0;
    const heap = [[0, src]]; // [거리, 도시] 최소 힙
    // push, pop은 Network Delay Time 글의 이진 힙과 같다
    let count = -1; // 출발 도시 자신은 빼고 센다
    while (heap.length > 0) {
      const [d, u] = pop();
      if (d > dist[u]) continue; // 낡은 후보
      count++;                   // 꺼낸 도시는 임계 거리 안에서 확정된 이웃
      for (const [v, w] of graph[u]) {
        const nd = d + w;
        // 임계 거리를 넘는 후보는 힙에 넣지도 않는다
        if (nd <= distanceThreshold && nd < dist[v]) {
          dist[v] = nd;
          push([nd, v]);
        }
      }
    }
    return count;
  };

  let answer = -1, bestCount = Infinity;
  for (let src = 0; src < n; src++) {
    const c = countFrom(src);
    if (c <= bestCount) { bestCount = c; answer = src; }
  }
  return answer;
}
```

`push`와 `pop`은 [Network Delay Time의 힙 절](/posts/leetcode-network-delay-time#힙으로-다음-노드를-빨리-고른다)과 똑같은 이진 힙이라 줄였다. `count`를 -1에서 시작하는 건 처음 꺼내는 출발 도시 자신을 빼기 위해서다.

시간은 도시마다 O(E log E), 전체 O(n · E log E)다. 길이 적은 지도라면 가장 빠른 풀이다. 길이 꽉 찬 지도에서는 E가 n²에 가까워 O(n³ log n)이 되어 오히려 플로이드-워셜보다 일이 많다. 무작위 완전 그래프에서 30ms 안팎이었다. 길이 꽉 찬 지도에 맞게 바꾼 다익스트라가 다음 풀이다.

## 길이 꽉 찼으면 배열에서 가장 가까운 도시를 고른다

힙이 손해를 보는 건 길이 많을 때다. 길이 n²에 가까우면 힙에 후보가 그만큼 들어가고 넣고 뺄 때마다 log가 붙는다. 이럴 땐 힙을 버리고, 아직 확정하지 않은 도시 중 가장 가까운 것을 배열을 훑어 고른다. 도시가 100개라 한 번 고르는 데 100칸이다. 길은 인접 행렬로 들고 있으면 이웃을 훑는 것도 n칸이다.

```js
function findTheCity(n, edges, distanceThreshold) {
  // 인접 행렬: w[a][b] = 길의 거리, 없으면 Infinity
  const w = Array.from({ length: n }, () => new Array(n).fill(Infinity));
  for (const [a, b, c] of edges) { w[a][b] = c; w[b][a] = c; }

  let answer = -1, bestCount = Infinity;
  for (let src = 0; src < n; src++) {
    const dist = new Array(n).fill(Infinity);
    const done = new Array(n).fill(false);
    dist[src] = 0;
    let count = -1; // 출발 도시 자신은 빼고 센다
    for (let step = 0; step < n; step++) {
      // 아직 확정하지 않은 도시 중 가장 가까운 것을 고른다: O(n)
      let u = -1;
      for (let i = 0; i < n; i++) {
        if (!done[i] && (u === -1 || dist[i] < dist[u])) u = i;
      }
      if (dist[u] > distanceThreshold) break; // 남은 도시는 모두 임계 거리 밖
      done[u] = true;
      count++;
      for (let v = 0; v < n; v++) {
        if (dist[u] + w[u][v] < dist[v]) dist[v] = dist[u] + w[u][v];
      }
    }
    if (count <= bestCount) { bestCount = count; answer = src; }
  }
  return answer;
}
```

가장 가까운 남은 도시가 임계 거리를 넘으면 그 뒤의 도시는 모두 더 멀다. 다익스트라가 확정하는 거리는 커지기만 하기 때문이다. 그래서 `break`로 그 도시의 계산을 바로 끝낸다.

도시마다 고르기 n번, 고를 때마다 n칸과 이웃 n칸이라 O(n²)이고 전체는 O(n³)이다. 플로이드-워셜과 같은 급이다. 무작위 완전 그래프에서 약 8ms로, 힙 다익스트라의 30ms보다 빠르고 플로이드-워셜의 4~5ms보다는 조금 느렸다. 임계 거리에서 끊는 덕을 보려면 임계 거리가 작아야 하는데, 거리가 1~1만 무작위인 완전 그래프는 길이 워낙 많아 가장 먼 쌍도 최단 거리가 1,307이었다. 임계 거리 2,000이면 모든 도시가 서로 이웃이라 끊길 일이 없다. 이 그래프에서 임계 거리를 500으로 낮추면 이웃인 쌍이 44%로 줄어 끊기는 효과가 생긴다.

## 거쳐 갈 도시를 하나씩 늘리는 플로이드-워셜

모든 도시에서 모든 도시까지의 거리가 필요하다. 플로이드-워셜은 그걸 n × n 표 하나로 한 번에 구한다. 처음 표에는 바로 이어진 길의 거리만 적고, 나머지는 무한대로 둔다. 그다음 "도시 k를 거쳐 가면 더 짧은가"를 k = 0, 1, 2, …로 하나씩 늘려 가며 표 전체에 물어본다.

k번째 단계가 끝나면 표에는 "0부터 k까지의 도시만 중간에 거쳐 가도 될 때의 최단 거리"가 적혀 있다. 새로 k를 거쳐도 될 때, i에서 j로 가는 가장 짧은 길은 k를 안 거치거나(지금 표의 값), k를 한 번 거친다(i → k와 k → j를 각각 이전 표에서 가장 짧게). 그래서 `d[i][k] + d[k][j]`와 `d[i][j]` 중 작은 값을 고르면 된다. 모든 k를 다 넣고 나면 표가 최종 답이다.

```js
function findTheCity(n, edges, distanceThreshold) {
  // d[i][j]: i에서 j까지 지금까지 아는 최단 거리
  const d = Array.from({ length: n }, (_, i) =>
    Array.from({ length: n }, (_, j) => (i === j ? 0 : Infinity))
  );
  for (const [a, b, w] of edges) {
    d[a][b] = w; // 길이 양방향이라 두 칸에 적는다
    d[b][a] = w;
  }

  // k를 거쳐 가도 되는 도시로 하나씩 늘려 간다. k가 가장 바깥이어야 한다
  for (let k = 0; k < n; k++) {
    for (let i = 0; i < n; i++) {
      for (let j = 0; j < n; j++) {
        if (d[i][k] + d[k][j] < d[i][j]) d[i][j] = d[i][k] + d[k][j];
      }
    }
  }

  let answer = -1, bestCount = Infinity;
  for (let i = 0; i < n; i++) {
    let count = 0;
    for (let j = 0; j < n; j++) {
      if (i !== j && d[i][j] <= distanceThreshold) count++;
    }
    if (count <= bestCount) { // 같으면 번호가 큰 도시가 이긴다
      bestCount = count;
      answer = i;
    }
  }
  return answer;
}
```

### Python과 Java로 쓰면

Python에서 세 겹 반복 100만 번은 그대로 쓰면 느린 편이라, 안쪽 반복에서 쓰는 줄을 미리 변수에 잡아 둔다. `d[i][k]`가 무한대면 k를 거치는 길이 없으니 그 줄은 건너뛴다. 이렇게 쓰니 무작위 완전 그래프에서 60ms였다. `float("inf")`는 더해도 무한대라 넘침 걱정이 없다.

```python
from typing import List


def find_the_city(n: int, edges: List[List[int]], distance_threshold: int) -> int:
    INF = float("inf")
    d = [[0 if i == j else INF for j in range(n)] for i in range(n)]
    for a, b, w in edges:
        d[a][b] = d[b][a] = w

    for k in range(n):
        dk = d[k]  # 안쪽 반복에서 같은 줄을 여러 번 꺼내지 않게 미리 잡는다
        for i in range(n):
            di = d[i]
            dik = di[k]
            if dik == INF:
                continue  # i에서 k로 못 가면 k를 거치는 길도 없다
            for j in range(n):
                if dik + dk[j] < di[j]:
                    di[j] = dik + dk[j]

    answer, best = -1, INF
    for i in range(n):
        count = sum(1 for j in range(n) if i != j and d[i][j] <= distance_threshold)
        if count <= best:  # 같으면 번호가 큰 도시
            answer, best = i, count
    return answer


ex = [[0, 1, 3], [1, 2, 1], [1, 3, 4], [2, 3, 1], [3, 4, 3]]
print(find_the_city(5, ex, 4))
print(find_the_city(3, [[1, 2, 3]], 5))
print(find_the_city(2, [[0, 1, 2]], 1))
```

Java는 `int`로 표를 만든다. 무한대를 `Integer.MAX_VALUE`로 두면 `d[i][k] + d[k][j]`에서 넘쳐 음수가 되고, 그 음수가 `d[i][j]`보다 작다고 판정돼 표에 들어간다. `Integer.MAX_VALUE + 3`은 -2147483646이다. 그래서 무한대를 10억으로 둔다. 실제 최단 거리는 많아야 99 × 10^4라 10억보다 훨씬 작고, 10억 두 개를 더한 20억도 `int` 최댓값 약 21.4억 안이다.

```java
import java.util.*;

class Solution {
    public int findTheCity(int n, int[][] edges, int distanceThreshold) {
        // 경로 최대 길이는 99 × 10^4 정도라 10억이면 충분히 크고, 두 번 더해도 int를 넘지 않는다
        final int INF = 1_000_000_000;
        int[][] d = new int[n][n];
        for (int i = 0; i < n; i++) {
            Arrays.fill(d[i], INF);
            d[i][i] = 0;
        }
        for (int[] e : edges) {
            d[e[0]][e[1]] = e[2];
            d[e[1]][e[0]] = e[2];
        }

        for (int k = 0; k < n; k++)
            for (int i = 0; i < n; i++)
                for (int j = 0; j < n; j++)
                    if (d[i][k] + d[k][j] < d[i][j]) d[i][j] = d[i][k] + d[k][j];

        int answer = -1, best = Integer.MAX_VALUE;
        for (int i = 0; i < n; i++) {
            int count = 0;
            for (int j = 0; j < n; j++)
                if (i != j && d[i][j] <= distanceThreshold) count++;
            if (count <= best) { // 같으면 번호가 큰 도시
                best = count;
                answer = i;
            }
        }
        return answer;
    }
}
```

## 도시 100개에서 다섯 풀이 비교

도시 100개가 모두 이어진 지도(길 4,950개, 거리 1~1만 무작위, 임계 거리 1만)에서 잰 시간도 적었다.

|---|---|---|---|---|
| 도시마다 DFS | 최악 지수 | O(n + E) | 1.2초, 호출 7,805만 번 | 고르지 않는다 |
| 도시마다 벨만-포드 | O(n² · E) | O(n) | 약 20ms | 음수 길이 섞였을 때(사이클은 없어야 한다) |

벨만-포드가 다익스트라보다 빠르게 나온 건 조기 종료가 평균 6바퀴에 걸렸고 힙을 다루는 비용이 없기 때문이다. 입력이 불리하면 5,000만 번까지 간다. 면접에서는 플로이드-워셜로 짜고 "도시가 100개라 O(n³)이 100만 번"을 먼저 말한다. 도시가 1만 개로 커지면 1조 번이라 도시마다 다익스트라로 바꾼다는 것까지 덧붙이면 좋다.

## 동점 규칙과 반복 순서에서 틀린다

가장 흔한 실수는 동점 처리다. 최솟값을 고를 때 습관대로 `<`를 쓰면 같은 값에서 답이 바뀌지 않아 번호가 작은 도시가 남는다.

```js
// 틀린 코드: 같을 때 바꾸지 않는다
if (count < bestCount) { bestCount = count; answer = i; }
```

예시에서 이 코드는 4가 아니라 0을 낸다. 0과 4가 둘 다 두 곳인데 0을 먼저 봤기 때문이다.

두 번째는 플로이드-워셜의 반복 순서다. 거쳐 가는 도시 k가 가장 바깥 반복이어야 한다. `for i`, `for j`, `for k` 순서로 쓰면 `d[i][j]`를 정할 때 아직 다 구하지 않은 `d[i][k]`나 `d[k][j]`를 읽는다.

```js
// 틀린 코드: k가 가장 안쪽에 있다
for (let i = 0; i < n; i++)
  for (let j = 0; j < n; j++)
    for (let k = 0; k < n; k++)
      if (d[i][k] + d[k][j] < d[i][j]) d[i][j] = d[i][k] + d[k][j];
```

길이 0 - 1 - 3 - 2 순으로 거리 1, 1, 3인 사슬(길 `[0, 1, 1]`, `[1, 3, 1]`, `[2, 3, 3]`)에 임계 거리 5를 주면 맞는 답은 3이다. 도시마다 다른 세 도시가 모두 5 이내라 넷 다 세 곳이고, 동점이라 가장 큰 3이다. 그런데 이 코드는 2를 낸다. `d[0][2]`를 정하는 순간 `d[0][3]`이 아직 무한대라서 0에서 2까지의 거리 5를 끝내 찾지 못하고, 도시 0과 2의 이웃이 하나씩 모자라게 세진다.

세 번째는 길을 한쪽 방향으로만 적는 것이다. `d[a][b] = w`만 쓰면 b에서 a로 못 간다. 길이 `[1, 2, 3]` 하나뿐인 도시 셋(임계 거리 5)에서 맞는 답은 이웃이 없는 0이다. 한쪽만 적으면 도시 2의 이웃도 0곳이 되어 동점에서 2를 낸다.

네 번째는 임계 거리 비교를 `<`로 쓰는 것이다. 문제는 "이하"라서 거리가 임계 거리와 정확히 같은 도시도 이웃이다. 길 `[1, 2, 1]`에 임계 거리 1이면 1과 2는 서로 이웃이라 답은 0인데, `<`로 세면 모두 0곳이 되어 2를 낸다.

다섯 번째는 무게를 보고도 BFS로 처음 닿은 거리를 굳히는 것이다. 길 `[0, 1, 4]`, `[0, 2, 1]`, `[1, 2, 1]`에 임계 거리 2를 주면 0에서 1까지는 2를 거쳐 2라 이웃인데, BFS는 바로 간 4로 굳혀 이웃에서 뺀다. 맞는 답 2 대신 1이 나온다. BFS가 최단 거리를 주는 건 모든 길의 거리가 같을 때뿐이다([BFS·DFS 글](/posts/ds-graph-bfs-dfs#선에-무게가-붙으면-bfs가-틀린다)).

## 도시 문제가 커지거나 바뀌면

### 도시가 1만 개라면

O(n³)은 1조 번이라 안 된다. 길이 드물다면 도시마다 다익스트라를 돌리고 임계 거리에서 끊는다. 임계 거리가 작으면 도시마다 꺼내는 도시가 몇 개 안 되어 훨씬 빨라진다. 임계 거리가 크고 길도 많다면 모든 쌍을 정확히 구하는 것 자체가 비싸니 문제를 다시 봐야 한다.

### 길이 하나 추가될 때마다 답을 다시 구하라면

표 전체를 다시 돌릴 필요가 없다. 새 길 a - b(거리 w)가 생기면 모든 i, j 쌍마다 `d[i][a] + w + d[b][j]`와 `d[i][b] + w + d[a][j]`를 지금 값과 비교하면 된다. 한 번에 O(n²)이다. 길이 하나 끊길 때는 이렇게 간단히 되지 않는다. 그 길을 쓰던 최단 경로가 어디까지 영향을 받는지 알기 어려워서다.

### 실제 경로도 알려 달라면

표와 함께 `next[i][j]`(i에서 j로 갈 때 처음 들르는 도시)를 둔다. 처음엔 바로 이어진 길이면 j, 아니면 없음이고, `d[i][j]`를 k를 거쳐 줄일 때 `next[i][j] = next[i][k]`로 고친다. 경로는 i에서 시작해 `next`를 따라가면 나온다.

### 음수 거리가 섞이면

플로이드-워셜은 음수 길이 있어도 성립한다. 다만 길이 양방향이면 음수 길 하나가 곧 왕복 고리라 최단 거리가 끝없이 줄어든다. 단방향 그래프라면 끝난 뒤 `d[i][i]`가 음수인 도시가 있는지 보면 음수 사이클이 있는지 안다. 다익스트라는 음수가 섞이면 쓸 수 없다.

## 면접에서 나올 만한 질문

### 왜 플로이드-워셜을 골랐나

도시마다 다른 모든 도시까지의 거리가 필요한 모든 쌍 최단 거리 문제이고, 도시가 100개 이하라 O(n³)이 100만 번이기 때문이다. 길이 꽉 찰 수 있어서 도시마다 다익스트라를 돌리면 오히려 일이 더 많다. 코드도 세 겹 반복 하나라 짧고 틀릴 곳이 적다.

### 플로이드-워셜에서 k가 가장 바깥이어야 하는 이유는

k번째 단계가 "0부터 k까지의 도시만 거쳐 가도 될 때의 최단 거리"를 표 전체에 완성하는 DP이기 때문이다. k를 안쪽에 두면 `d[i][j]`를 정하는 순간 아직 구하지 않은 `d[i][k]`나 `d[k][j]`를 읽는다. 사슬 0 - 1 - 3 - 2 예시에서 이렇게 짜면 0에서 2까지의 거리를 끝내 찾지 못해 답이 틀린다.

### 동점은 어떻게 처리하나

번호가 큰 도시를 골라야 하므로 0번부터 보면서 이웃 수가 지금까지의 최솟값과 같을 때도 답을 바꾼다. 비교를 `<=`로 쓴다는 뜻이다. 거꾸로 큰 번호부터 보면서 `<`로 비교해도 같다. 습관대로 `<`를 쓰고 0번부터 보면 번호가 작은 도시가 남아 틀린다.

### 다익스트라로 풀면 무엇이 좋고 무엇이 나쁜가

도시마다 다익스트라를 돌리면 O(n · E log E)라 길이 드문 큰 지도에서 유리하다. 임계 거리를 넘는 후보를 힙에 넣지 않으면 꺼내는 도시가 곧 이웃이라 일이 더 준다. 하지만 이 문제처럼 길이 꽉 찰 수 있으면 E가 n²에 가까워 O(n³ log n)이 되어 플로이드-워셜보다 느리다.

### BFS로는 왜 안 되나

길마다 거리가 달라서다. BFS는 지나는 길의 개수가 적은 순서로 도시를 확정하는데, 길 개수가 적다고 거리가 짧은 건 아니다. 0에서 1로 바로 가면 4지만 2를 거치면 2인 지도에서 BFS는 4로 굳혀 이웃을 잘못 센다.

### 시간과 공간 복잡도는

플로이드-워셜은 세 겹 반복이라 O(n³), 표가 O(n²)다. 이웃을 세는 데 O(n²)이 더 들지만 O(n³)에 묻힌다. 도시 100개면 반복 100만 번, 표 1만 칸이다.

### Java에서 무한대를 어떻게 잡나

`Integer.MAX_VALUE`로 두면 두 값을 더할 때 넘쳐 음수가 되고, 그 음수가 더 짧은 거리로 표에 들어간다. 실제 거리의 최댓값(99 × 10^4)보다 충분히 크고 두 번 더해도 `int`를 넘지 않는 10억 같은 값을 쓴다. 아니면 더하기 전에 둘 중 하나가 무한대인지 먼저 검사한다.
