[Non-overlapping Intervals](https://leetcode.com/problems/non-overlapping-intervals/)는 LeetCode 435번이다. 구간 목록에서 몇 개를 지워 남은 구간이 서로 겹치지 않게 하려고 한다. 지워야 하는 최소 개수를 구한다.

[구간 문제 패턴](/posts/interval-problems-pattern)에서 이 문제를 "끝 순으로 정렬해야 할 때"의 대표로 다뤘다. 이 글은 거기서 한 걸음 더 들어간다. 모든 경우를 보는 브루트포스에서 출발해, 동적 계획법 두 가지를 거쳐 그리디에 도착한다. 그리디가 맞는 이유는 짧게만 짚고, 교환 논증의 자세한 증명은 [그리디 알고리즘](/posts/greedy-algorithms)에 맡긴다. DP를 굳이 다루는 이유는 구간에 가중치가 붙는 순간 그리디가 깨지고 DP만 남기 때문이다. 코드는 Node.js 22, Python 3.13, Java 21에서 돌렸다.

## 최소로 지운다는 건 최대로 남긴다는 뜻이다

입력 `intervals`는 `[start, end]` 쌍의 목록이고 `start < end`다. 정렬돼 있지 않다. 남은 구간 중 어떤 두 개도 겹치지 않도록 지워야 하는 최소 개수를 돌려준다.

풀이에 영향을 주는 조건은 이렇다.

- 구간 수는 최대 10^5다. O(n²)은 100억 번이라 통과하지 못한다. O(n log n)이 필요하다.
- 값은 −5 × 10^4 이상 5 × 10^4 이하다. 음수가 있다. 이 조건이 아래에서 실제 버그를 하나 만든다.
- 끝점이 닿는 건 겹치지 않는다. `[1, 2]`와 `[2, 3]`은 둘 다 남길 수 있다. [Merge Intervals](/posts/leetcode-merge-intervals)는 닿으면 합쳤는데, 이 문제는 반쯤 열린 구간처럼 다룬다.

"최소로 지워라"를 "최대로 남겨라"로 바꿔 읽는 게 첫걸음이다. 남길 수 있는 최대 개수를 k라 하면 답은 n − k다. 서로 겹치지 않는 구간을 최대한 많이 고르는 문제는 활동 선택 문제(activity selection)라는 이름으로 알고리즘 교과서에 나오는 고전이다.

## 체육관 예약 다섯 개를 손으로 골라 본다

이 글에서 계속 쓸 예시다.

```text
intervals = [1,4] [2,3] [3,5] [5,7] [6,8]
```

```text
 0  1  2  3  4  5  6  7  8
 |--|--|--|--|--|--|--|--|
    [========]                 [1,4]
       [==]                    [2,3]
          [=====]              [3,5]
                [=====]        [5,7]
                   [=====]     [6,8]
```

몇 개를 남길 수 있을까. `[2, 3]`, `[3, 5]`, `[5, 7]`을 고르면 3에서, 5에서 닿기만 하니 셋 다 남는다. `[1, 4]`는 `[2, 3]`과 `[3, 5]`를 둘 다 막고, `[6, 8]`은 `[5, 7]`과 겹친다. 넷을 남기는 방법은 없다. `[1, 4]`와 `[2, 3]`이 겹치니 둘 중 하나는 빠지고, `[5, 7]`과 `[6, 8]` 중 하나도 빠져야 하기 때문이다. 남길 수 있는 최대는 3, 답은 5 − 3 = 2다.

손으로 고를 때 나는 짧은 `[2, 3]`부터 잡았다. 짧은 걸 고르는 게 맞는 것 같았는데, 아래에서 보듯 그 규칙은 틀릴 때가 있다. 확실한 방법부터 본다.

## 남길 조합을 전부 시험한다

구간마다 남기거나 지우거나 두 가지라 조합은 2^n개다. 조합마다 남긴 구간이 서로 겹치지 않는지 확인하고, 그중 가장 많이 남긴 것을 고른다.

```js
function eraseOverlapIntervals(intervals) {
  const n = intervals.length;
  let best = 0;
  for (let mask = 0; mask < 1 << n; mask++) {           // mask의 i번째 비트 = i번째를 남기나
    const kept = [];
    for (let i = 0; i < n; i++) if (mask & (1 << i)) kept.push(intervals[i]);
    kept.sort((x, y) => x[0] - y[0]);                   // 시작 순으로 놓고 이웃끼리 확인
    let ok = true;
    for (let i = 1; i < kept.length; i++) if (kept[i][0] < kept[i - 1][1]) { ok = false; break; }
    if (ok) best = Math.max(best, kept.length);
  }
  return n - best;
}
```

남긴 구간을 시작 순으로 정렬해 이웃끼리만 확인해도 되는 건 [Meeting Rooms](/posts/leetcode-meeting-rooms)와 같은 이유다. 겹치는 짝이 있다면 정렬된 이웃 중에도 반드시 겹치는 짝이 있다.

시간은 O(2^n · n log n)이다. n = 20이면 100만 조합이라 버틸 만하지만, n = 40이면 1조다. 이 풀이는 정답을 확인하는 기준으로만 쓴다. 이 글의 다른 풀이들은 모두 무작위 입력 2만 개에서 이 풀이와 같은 답을 냈다. 비트 연산으로 부분집합을 도는 방법은 [비트 조작](/posts/bit-manipulation)에 있다.

조합을 다 보는 게 낭비인 이유는, 대부분의 조합이 "앞에서 이미 겹쳐서 볼 필요가 없는" 것들이기 때문이다. 앞에서 내린 결정을 기억해 두고 쓰면 된다. 그게 DP다.

## 마지막에 남긴 구간으로 상태를 정한다

구간을 끝 순으로 정렬해 두자. `dp[i]`를 "i번째 구간을 마지막으로 남길 때, 그 앞까지 포함해 남길 수 있는 최대 개수"라고 정한다. i번째를 남기려면 그 바로 앞에 남긴 구간 j는 i가 시작하기 전에 끝나야 한다. 끝이 i의 시작 이하인 j 중 `dp[j]`가 가장 큰 것을 고르고 1을 더한다.

```text
dp[i] = 1 + max(dp[j])   (j < i 이고 a[j]의 끝 <= a[i]의 시작)
        없으면 1
```

[최장 증가 부분 수열](/posts/leetcode-longest-increasing-subsequence)과 똑같은 모양이다. 거기서는 "앞 수가 더 작다"가 조건이었고, 여기서는 "앞 구간이 먼저 끝난다"가 조건이다.

```js
function eraseOverlapIntervals(intervals) {
  const n = intervals.length;
  const a = [...intervals].sort((x, y) => x[1] - y[1]); // 끝 순
  const dp = new Array(n).fill(1);                      // 자기 혼자만 남겨도 1개
  for (let i = 0; i < n; i++)
    for (let j = 0; j < i; j++)
      if (a[j][1] <= a[i][0]) dp[i] = Math.max(dp[i], dp[j] + 1); // j 다음에 i를 붙일 수 있다
  return n - Math.max(...dp);
}
```

예시를 끝 순으로 정렬하면 `[2,3] [1,4] [3,5] [5,7] [6,8]`이고, `dp`는 `[1, 1, 2, 3, 3]`이 된다. `[5, 7]` 자리의 3은 `[2, 3]` → `[3, 5]` → `[5, 7]` 사슬이다. 최댓값 3을 빼면 답은 2다.

시간은 이중 루프라 O(n²), 공간은 O(n)이다. 구간 1만 개에서 437ms가 걸렸다. 10^5개면 100배인 40초대라 통과하지 못한다. 정렬은 시작 순으로 해도 이 DP는 맞는다. j가 i 앞에서 끝나려면 j의 시작도 i의 시작보다 앞이니까. 그래도 끝 순으로 정렬해 둔 데는 이유가 있다. 다음 풀이에서 "끝이 i의 시작 이하인 j"가 정렬된 배열의 앞쪽 한 덩어리가 되기 때문이다.

## 남기거나 건너뛰거나, 재귀로 내려간다

같은 DP를 위에서 아래로 짤 수도 있다. 이번에는 시작 순으로 정렬하고 `best(i)`를 "i번째부터 끝까지에서 남길 수 있는 최대 개수"로 정한다. i번째 구간 앞에서 할 수 있는 선택은 둘이다.

- 지운다. 그러면 `best(i + 1)`이다.
- 남긴다. 그러면 i가 끝나기 전에 시작하는 구간은 모두 못 쓴다. i의 끝 이상에서 시작하는 첫 구간 j로 건너뛰어 `1 + best(j)`다. 시작 순으로 정렬돼 있으니 j는 이분 탐색으로 찾는다.

```js
function eraseOverlapIntervals(intervals) {
  const a = [...intervals].sort((x, y) => x[0] - y[0]); // 시작 순
  const n = a.length;
  const starts = a.map(x => x[0]);
  const next = (t) => {               // 시작이 t 이상인 첫 구간
    let lo = 0, hi = n;
    while (lo < hi) { const m = (lo + hi) >> 1; if (starts[m] < t) lo = m + 1; else hi = m; }
    return lo;
  };
  const memo = new Array(n).fill(-1);
  const best = (i) => {                // a[i..]에서 남길 수 있는 최대 개수
    if (i >= n) return 0;
    if (memo[i] >= 0) return memo[i];
    const skip = best(i + 1);                  // i를 지운다
    const take = 1 + best(next(a[i][1]));      // i를 남기고, i가 끝난 뒤 시작하는 곳으로 건너뛴다
    return (memo[i] = Math.max(skip, take));
  };
  return n - best(0);
}
```

`memo`가 없으면 같은 `best(i)`를 여러 갈래에서 다시 계산해 지수 시간이 된다. 있으면 i마다 한 번씩만 계산하고, 한 번에 이분 탐색 하나라 O(n log n)이다. 무작위 입력 2만 개에서 브루트포스와 같은 답을 냈다.

문제는 재귀 깊이다. `best(0)`이 `best(1)`을, 그게 `best(2)`를 부르니 깊이가 n까지 간다. `[i, i + 1]` 구간 10만 개를 넣었더니 바로 터졌다.

```text
big error: RangeError Maximum call stack size exceeded
```

구간 수를 바꿔 가며 찾아보니 Node 22 기본 설정에서는 이 코드가 7,800개 정도까지만 버텼다(함수 크기와 환경마다 다르다). Python은 기본 재귀 한도가 1000이라 더 일찍 막힌다. `sys.setrecursionlimit`로 올릴 수는 있지만 실제 C 스택이 모자라면 인터프리터가 통째로 죽는다. Java도 스레드 스택 크기에 따라 어느 깊이에서 `StackOverflowError`가 난다. 그래서 n이 10^5인 문제에서 탑다운은 생각을 정리하는 용도로 쓰고, 제출은 같은 점화식을 반복문으로 바꾼 바텀업으로 한다. 그게 다음 풀이다. 탑다운과 바텀업을 오가는 일반적인 방법은 [동적 계획법](/posts/dynamic-programming)에 있다.

## 이분 탐색으로 앞 구간을 바로 찾는다

이번에는 상태를 바꾼다. `dp[i]`를 "끝 순으로 정렬한 앞 i개 중에서 남길 수 있는 최대 개수"로 정한다. i번째 구간은 남기거나 지우거나 둘 중 하나다.

- 지우면 앞 i − 1개의 답 그대로다. `dp[i - 1]`.
- 남기면 i번째의 시작 이하에서 끝나는 구간들 중에서 고른 뒤 1을 더한다. 끝 순으로 정렬돼 있으니 그런 구간들은 앞쪽 p개다. `dp[p] + 1`.

p는 "끝이 s 이하인 구간 개수"이고, 끝 배열이 정렬돼 있으니 [이분 탐색](/posts/binary-search)으로 O(log n)에 찾는다.

```js
function eraseOverlapIntervals(intervals) {
  const n = intervals.length;
  const a = [...intervals].sort((x, y) => x[1] - y[1]);
  const dp = new Array(n + 1).fill(0);           // dp[i] = 앞 i개에서 남길 수 있는 최대
  for (let i = 1; i <= n; i++) {
    const [s] = a[i - 1];
    let lo = 0, hi = i - 1;                      // p = 앞 i-1개 중 끝이 s 이하인 개수
    while (lo < hi) {
      const m = (lo + hi + 1) >> 1;              // 올림: lo = m이 멈추지 않는 걸 막는다
      if (a[m - 1][1] <= s) lo = m; else hi = m - 1;
    }
    dp[i] = Math.max(dp[i - 1], dp[lo] + 1);     // 지우거나, 남기고 앞 p개의 답에 붙이거나
  }
  return n - dp[n];
}
```

아래 그림에서 다음을 누르면 `dp` 칸이 하나씩 채워진다. 칸은 끝 순으로 정렬한 구간이고, 오른쪽 상자는 찾은 p와 지금까지의 `dp`다. 값은 코드에 출력 줄을 넣어 찍은 그대로다.

시간은 정렬 O(n log n)과 이분 탐색 n번 O(n log n)이라 O(n log n), 공간은 O(n)이다. 10^5개에서 65ms였다. 이제 제한 안에 들어온다.

DP는 개수만 주지만, 어떤 구간을 남겼는지도 거꾸로 따라가면 복원된다. i번째 칸에서 `dp[i]`가 `dp[i - 1]`과 같으면 i를 지운 것으로 보고 한 칸 앞으로, 다르면 i를 남긴 것이니 기록하고 p 칸으로 건너뛴다. p는 채울 때 `prev` 배열에 적어 둔다.

```js
// 채우는 루프 안에서: prev[i] = lo;  dp[i] = Math.max(dp[i - 1], dp[lo] + 1);
const kept = [];
for (let i = n; i > 0; ) {
  if (dp[i] === dp[i - 1]) i--;                    // 지워도 같은 값이면 i는 지운 쪽으로 본다
  else { kept.push(a[i - 1]); i = prev[i]; }       // 남겼다면 p로 건너뛴다
}
kept.reverse();
```

예시에서 남긴 세 구간이 나온다. 그리디가 고른 것과 같다. 점수 변형에서도 같은 방법으로 어떤 일을 맡았는지 돌려줄 수 있다.

이 DP는 가중치 구간 스케줄링(weighted interval scheduling)이라는 이름의 정석 풀이다. 구간마다 점수가 있고 점수 합을 최대로 하라는 문제에서 `dp[p] + 1`을 `dp[p] + 점수`로 바꾸기만 하면 된다. 아래 변형에서 이 이야기를 다시 한다. 점수가 모두 1인 이 문제에서는 더 단순한 길이 있다.

## 가장 일찍 끝나는 구간을 남긴다

DP 표를 다시 보면 "남긴다"를 고른 구간이 `[2, 3]`, `[3, 5]`, `[5, 7]`이다. 끝 순으로 훑으며 "앞에서 남긴 구간과 겹치지 않으면 남긴다"를 한 것과 같다. 정말 그것만으로 충분할까.

충분하다. 끝 순으로 볼 때 가장 먼저 끝나는 구간 A를 남겨서 손해 보는 일은 없다. 어떤 최적해가 A 대신 B로 시작한다고 하자. B는 A보다 늦게 끝나거나 같이 끝난다. B를 A로 바꿔도 A가 더 일찍 끝나니 B 뒤에 오던 구간들과 여전히 겹치지 않는다. 개수는 같다. 그러니 A를 남기는 최적해가 항상 있다. A를 남긴 뒤에는 A와 겹치는 구간을 빼고 남은 구간에서 같은 논리를 되풀이한다. 이 "바꿔도 손해가 없다"는 논증을 교환 논증이라 부르고, 그림과 함께 한 증명은 [그리디 알고리즘](/posts/greedy-algorithms)에 있다.

코드는 아주 짧아진다. 마지막으로 남긴 구간의 끝 `end` 하나만 기억한다.

```js
function eraseOverlapIntervals(intervals) {
  const a = [...intervals].sort((x, y) => x[1] - y[1]); // 끝이 이른 순
  let removed = 0;
  let end = -Infinity;                // 아직 남긴 구간이 없다
  for (const [s, e] of a) {
    if (s >= end) end = e;            // 앞 구간이 끝난 뒤 시작하면 남긴다 (닿아도 된다)
    else removed++;                   // 겹치면 지운다
  }
  return removed;
}
```

지운 구간에서 `end`를 건드리지 않는 게 중요하다. 지운 구간은 없는 셈이니 체육관이 비는 시각도 그대로다. 그리고 지운 구간 `[1, 4]`는 끝이 4라, 남긴 `[2, 3]`보다 늦게 끝난다. 끝 순으로 정렬했으니 지금 보는 구간은 언제나 남긴 구간보다 늦게 끝나고, 둘이 겹치면 늦게 끝나는 지금 구간을 버리는 게 맞다.

시간은 정렬 O(n log n)과 한 번 훑기 O(n)이다. 공간은 정렬 복사본 O(n)이고, 입력을 정렬해도 된다면 정렬이 쓰는 만큼이다. 10^5개에서 58ms였다. DP + 이분 탐색(65ms)과 시간은 비슷하다. 둘 다 정렬이 대부분을 차지하기 때문이다. 그리디가 나은 건 코드가 짧고 추가 배열이 없다는 점이다.

## 시작 순으로 정렬해도 된다, 대신 늦게 끝나는 쪽을 버린다

시작 순으로 정렬하고 같은 코드를 돌리면 틀린다. 내 예시에서 돌려 봤다.

```text
naive start 3
```

정답은 2인데 3이 나왔다. 시작 순 첫 구간 `[1, 4]`를 남겼더니 `[2, 3]`과 `[3, 5]`가 막혔다. 패턴 글에서 본 것과 같은 실패다.

고치는 방법은 한 줄이다. 겹칠 때 무조건 지금 구간을 지우는 대신, 둘 중 끝이 늦은 쪽을 지운다. 지운 쪽이 아니라 남긴 쪽의 끝을 `end`로 두면 된다. 그러면 `end`는 `Math.min(end, e)`가 된다.

```js
function eraseOverlapIntervals(intervals) {
  const a = [...intervals].sort((x, y) => x[0] - y[0]); // 시작 순
  let removed = 0, end = -Infinity;
  for (const [s, e] of a) {
    if (s >= end) end = e;            // 겹치지 않으면 남긴다
    else {
      removed++;                      // 둘 중 하나는 지운다
      end = Math.min(end, e);         // 끝이 이른 쪽을 남긴 셈으로 친다
    }
  }
  return removed;
}
```

예시에서 `[1, 4]`를 남겼다가 `[2, 3]`을 만나면, 하나를 지우되 끝이 3인 `[2, 3]`을 남긴 것으로 바꾼다. 결과는 끝 순 그리디와 같고, 원리도 "끝이 이른 걸 남긴다"로 같다. 10^5개에서 56ms로 속도도 같았다. 시작 순 정렬은 [Merge Intervals](/posts/leetcode-merge-intervals)에서 손에 익은 코드라 면접에서 이 버전으로 쓰는 사람도 많다. 어느 쪽이든 왜 끝이 이른 걸 남기는지 말할 수 있으면 된다.

## 짧은 것부터 남기면 틀린다

손으로 풀 때 짧은 구간부터 잡았다고 했다. 이 규칙도 시험해 봤다. 짧은 구간부터 보면서 이미 남긴 것들과 겹치지 않으면 남긴다.

```text
shortest 2 ok 1
```

`[[1, 5], [4, 7], [6, 10]]`의 결과다. 가장 짧은 `[4, 7]`(길이 3)을 먼저 남기자 `[1, 5]`와 `[6, 10]`이 둘 다 막혀 두 개를 지웠다. `[4, 7]` 하나만 지우면 나머지 둘은 겹치지 않으니 정답은 1이다. 짧은 구간이 하필 두 구간 사이에 걸쳐 있으면 둘을 한꺼번에 막는다.

지우는 쪽에서 생각한 그리디도 하나 시험했다. "겹치는 상대가 가장 많은 구간부터 지운다"를 겹침이 없어질 때까지 되풀이하고, 상대 수가 같으면 목록에서 앞에 있는 것을 지운다. 무작위 입력 20만 개를 브루트포스와 대조했더니 구간 다섯 개짜리 반례가 나왔다.

```text
[[7,11],[11,15],[4,8],[4,6],[8,12]] 3 2
```

이 그리디는 3개를 지웠고 정답은 2다. 처음에 `[7, 11]`, `[4, 8]`, `[8, 12]`가 모두 상대 두 개와 겹쳐 동점인데, 맨 앞의 `[7, 11]`을 지운 게 잘못이었다. `[4, 8]`과 `[8, 12]`를 지우면 `[4, 6]`, `[7, 11]`, `[11, 15]`가 남는다. 동점을 다르게 깨면 이 입력은 맞힐 수 있지만, 그런 규칙을 붙일 때마다 새 반례를 찾아야 한다.

비슷한 착각으로 "겹치는 짝의 수가 답"이라는 것도 있다. `[[1, 10], [2, 3], [4, 5], [6, 7]]`은 겹치는 짝이 3개인데 답은 1이다. `[1, 10]` 하나가 세 짝에 모두 들어 있어서 그것만 지우면 된다.

"가장 일찍 시작하는 것", "가장 짧은 것", "겹치는 상대가 가장 많은 것을 지우기" 모두 그럴듯한데 반례가 있다. 그리디는 증명이 없으면 믿지 않는 게 안전하다. 그래서 면접에서는 그리디를 쓰기 전에 짧게라도 교환 논증을 말하고, 시간이 있으면 작은 입력에서 브루트포스와 대조해 본다.

## Python과 Java로 옮기기

끝 순 그리디를 옮긴다.

```python
from typing import List


class Solution:
    def eraseOverlapIntervals(self, intervals: List[List[int]]) -> int:
        removed = 0
        end = float("-inf")                                # 아직 남긴 구간이 없다
        for s, e in sorted(intervals, key=lambda iv: iv[1]):  # 끝이 이른 순
            if s >= end:                                   # 끝점이 닿는 건 괜찮다
                end = e                                    # 남긴다
            else:
                removed += 1                               # 겹치면 지운다
        return removed
```

```text
2
0 2
```

예시, 음수 구간 `[[-3, -1], [-1, 2]]`, 같은 구간 세 개를 넣은 결과다. 같은 구간이 셋이면 하나만 남기고 둘을 지운다.

```java
import java.util.*;

class Solution {
    public int eraseOverlapIntervals(int[][] intervals) {
        int[][] a = intervals.clone();
        Arrays.sort(a, (x, y) -> Integer.compare(x[1], y[1]));   // 끝이 이른 순
        int removed = 0;
        long end = Long.MIN_VALUE;                               // 아직 남긴 구간이 없다
        for (int[] iv : a) {
            if (iv[0] >= end) end = iv[1];                       // 남긴다
            else removed++;                                      // 겹치면 지운다
        }
        return removed;
    }
}
```

Java에는 `-Infinity` 같은 정수가 없어서 `end`의 초깃값으로 어떤 int보다도 작은 `Long.MIN_VALUE`를 썼다. 이 문제의 값 범위라면 `Integer.MIN_VALUE`도 되지만, long으로 두면 "첫 구간의 시작이 초깃값과 같으면 어떻게 되나"를 따질 필요가 없다. 비교자는 `Integer.compare`를 썼다. 이 문제는 값이 ±5 × 10^4라 빼기도 넘치지 않지만, 같은 코드를 값이 int 전체인 풍선 터뜨리기(452번)에 옮기면 빼기 비교가 넘쳐 틀린다. 그 실제 출력은 패턴 글에 있다.

Python은 `float("-inf")`와 정수 비교가 자연스럽게 된다. Python 정수는 크기 제한이 없어 오버플로 걱정이 없다.

## 실제로 틀리는 줄들

### 끝점이 닿는 것을 겹침으로 센다

`s >= end` 대신 `s > end`로 쓰면 닿기만 하는 구간을 지운다.

```text
strict 1 ok 0
```

`[[1, 2], [2, 3], [3, 4]]`의 결과다. 셋 다 남길 수 있는데 하나를 지웠다. 이 문제는 끝점이 닿아도 겹치지 않는다고 본다. Merge Intervals에서 `<=`로 합치던 습관이 여기서 반대로 작용한다. 문제마다 경계 정의를 확인하는 습관은 패턴 글의 "경계값" 섹션에 모아 뒀다.

### end를 0으로 시작한다

"아직 남긴 게 없다"를 `end = 0`으로 표현하면 값이 음수인 구간이 처음부터 막힌다.

```text
zero 2 ok 0
```

`[[-3, -1], [-1, 2]]`의 결과다. 첫 구간의 시작 −3이 0보다 작아서 지워졌고, 둘째도 마찬가지다. 실제로는 둘 다 남는다. 이 문제의 값은 −5 × 10^4까지 내려가서 이 버그로 실제로 틀린다. `-Infinity`로 두거나, 첫 구간을 남기고 `end = a[0][1]`로 시작한 뒤 1번부터 훑는다. 후자는 빈 배열에서 `a[0]`이 없어 터지니, 빈 입력이 올 수 있는 변형이라면 앞의 방법이 안전하다.

### 지운 구간의 끝으로 end를 바꾼다

겹쳐서 지운 구간에서 `end = e`를 하면, 실제로는 남기지 않은 구간이 체육관을 차지한 것처럼 계산한다. 끝 순 그리디에서는 지운 구간이 언제나 더 늦게 끝나니, `end`가 늘어나서 뒤의 구간을 괜히 막는다. 끝 순 그리디는 남길 때만 `end`를 바꾼다. 시작 순 버전은 반대로 지울 때도 `end`를 고치는데, 그건 `Math.min`으로 남긴 쪽의 끝을 고르는 것이라 뜻이 다르다. 두 버전의 코드를 섞어 쓰면 이 실수가 난다.

## 이 판단이 실제로 쓰이는 곳

한 자원을 두고 시간 요청이 몰릴 때 "최대한 많이 받아 주기"가 이 문제다. 강의실 하나에 신청이 몰린 학교, 방송 광고 슬롯 하나, 공용 장비 하나 같은 경우다. 끝이 이른 순으로 받으면 받은 개수가 최대라는 게 보장된다. 다만 실제 서비스에서는 요청마다 우선순위나 금액이 다른 경우가 많고, 그러면 위의 점수 DP로 넘어간다. 개수만 세는 그리디와 점수를 따지는 DP 중 어느 쪽이 맞는지는 "모든 요청의 가치가 같은가"로 정한다.

반대로 요청을 미리 모아 두지 못하고 들어오는 대로 받아야 한다면, 이 그리디도 DP도 그대로는 못 쓴다. 둘 다 전체 목록을 정렬할 수 있다는 걸 전제로 한다. 이 차이는 아래 "구간이 하나씩 들어온다면"에서 다시 짚는다.

| 끝 순 그리디 | O(n log n) | O(1) (정렬 제외) | 면접 기본 답. 가장 짧다 |
| 시작 순 + 늦게 끝나는 쪽 지우기 | O(n log n) | O(1) (정렬 제외) | 합치기 코드에서 출발하고 싶을 때. 원리는 끝 순과 같다 |

같은 무작위 입력에서 잰 시간을 모으면, 마지막 구간 DP는 1만 개에 437ms, DP + 이분 탐색은 10만 개에 65ms, 끝 순 그리디는 58ms, 시작 순 그리디는 56ms였다. 아래 셋은 정렬이 시간 대부분을 차지해서 차이가 거의 없다.

면접에서 고를 때는 속도보다 설명이 기준이 된다. 그리디는 짧지만 증명을 요구받고, DP는 길지만 점수 변형까지 그대로 버틴다.

## 면접관이 조건을 바꾸면

### 구간마다 점수가 있고 점수 합을 최대로 하라면

그리디가 깨진다. 일찍 끝나는 구간이 점수 1이고, 그것과 겹치는 긴 구간이 점수 100이면 긴 구간을 골라야 한다. DP + 이분 탐색 풀이에서 `dp[p] + 1`을 `dp[p] + 점수`로 바꾼다. 이 변형이 Maximum Profit in Job Scheduling(1235번)이다. 면접에서 그리디를 쓴 뒤 이 질문이 오면, DP 풀이를 알고 있었다는 게 큰 차이를 만든다.

작은 예로 확인해 보자. `[시작, 끝, 점수]`로 쓴다.

```text
[1,3,5] [2,9,50] [3,6,5] [6,9,5]
```

끝 순 그리디는 `[1, 3]`, `[3, 6]`, `[6, 9]`를 남겨 점수 15를 얻는다. 개수로는 최대지만, `[2, 9]` 하나만 남기면 50이다. DP는 `[2, 9]`를 볼 때 "지우면 앞의 최고 점수, 남기면 앞에서 2 이하에 끝난 구간들의 최고 점수 + 50"을 비교해 50을 고른다. 두 코드를 돌린 결과다.

```text
dp 50 greedy 15
```

Python으로는 `bisect_right`가 "끝이 s 이하인 개수"를 바로 준다. 점수 대신 1을 더하는 원래 문제 버전이다.

```python
from bisect import bisect_right


def erase_dp(intervals):
    a = sorted(intervals, key=lambda iv: iv[1])     # 끝 순
    ends = [e for _, e in a]
    dp = [0] * (len(a) + 1)                          # dp[i] = 앞 i개에서 남길 수 있는 최대
    for i, (s, e) in enumerate(a, 1):
        p = bisect_right(ends, s, 0, i - 1)          # 앞 i-1개 중 끝이 s 이하인 개수
        dp[i] = max(dp[i - 1], dp[p] + 1)
    return len(a) - dp[-1]
```

`bisect_right(ends, s, 0, i - 1)`의 마지막 두 인자는 탐색 범위다. 자기 자신(i − 1번 칸)은 끝이 시작보다 크니 범위에 넣어도 답은 같지만, 뜻을 분명히 하려고 앞 i − 1개로 막았다. 예시에서 2, 끝점만 닿는 사슬과 음수 구간에서 0이 나온다.

### 어떤 구간을 지웠는지도 달라면

그리디라면 `else` 쪽에서 지운 구간을 목록에 넣으면 된다. 정렬하면서 원래 인덱스를 함께 들고 가야 원래 위치로 알려 줄 수 있다. 지우는 조합은 하나가 아닐 수 있다는 것도 말해 둔다. 예시에서 그리디는 `[1, 4]`와 `[6, 8]`을 지우지만, `[6, 8]` 대신 `[5, 7]`을 지워도 `[2, 3]`, `[3, 5]`, `[6, 8]`이 남아 개수가 같다. 어떤 조합을 돌려줄지 기준(예: 원래 인덱스가 작은 쪽)이 있는지 물어본다.

### 끝점이 닿는 것도 겹침이라면

닫힌 구간이 된다. `s >= end`를 `s > end`로 바꾼다. 위에서 버그였던 코드가 이 정의에서는 정답이다. 화살 하나로 풍선을 최대한 많이 터뜨리는 Minimum Number of Arrows to Burst Balloons(452번)가 이 정의를 쓴다. 화살 수는 "겹치지 않게 남길 수 있는 최대 개수"와 같다. 같은 그리디에서 등호 하나와 반환값만 다르다.

### 구간이 하나씩 들어온다면

들어올 때마다 답을 갱신하라고 하면 그리디의 "끝 순으로 훑는다"를 쓸 수 없다. 끝이 이른 구간이 나중에 들어올 수 있기 때문이다. 들어온 구간들을 끝 기준 정렬 상태로 유지하고(균형 이진 탐색 트리), 답이 필요할 때마다 다시 훑으면 질의 하나에 O(n)이다. 질의가 잦다면 이 비용을 줄이는 자료구조를 따로 고민해야 하고, 면접에서는 여기까지 말하면 충분하다. 실제 예약 시스템은 대개 반대로 "겹치면 거절"한다. 그게 [My Calendar I](/posts/leetcode-my-calendar-i)(729번)이다.

### 방이 k개 있다면

방 k개에 최대한 많이 넣으라는 변형이다. 끝 순으로 훑으며, 지금 구간이 들어갈 수 있는 방 중 가장 늦게 빈 방(지금 시작 이하에서 끝난 방 중 끝이 가장 큰 방)에 넣는다. 일찍 빈 방은 아껴 둬야 뒤의 구간이 쓸 수 있다. 방의 끝 시각을 정렬된 구조에 담아 이분 탐색으로 찾는다. 방 개수 자체를 최소로 구하는 쪽은 [Meeting Rooms II](/posts/leetcode-meeting-rooms-ii)(253번, 프리미엄 문제)다.

같은 묶음의 다른 문제는 [Merge Intervals](/posts/leetcode-merge-intervals), [Insert Interval](/posts/leetcode-insert-interval), [Minimum Interval to Include Each Query](/posts/leetcode-minimum-interval-to-include-each-query)다.

## 면접에서 나올 만한 질문

### 왜 끝이 이른 순으로 정렬하나요?

남기는 개수를 최대로 하려면 체육관이 빨리 비어야 한다. 가장 먼저 끝나는 구간을 남겨도 손해가 없다는 교환 논증이 근거다. 어떤 최적해의 첫 구간을 그보다 일찍 끝나는 구간으로 바꿔도 뒤 구간들과 겹치지 않고 개수도 같다.

### 시작 순으로 정렬하면 안 되나요?

같은 코드를 시작 순으로 돌리면 틀린다. 일찍 시작하지만 늦게 끝나는 구간이 뒤를 다 막기 때문이다. 시작 순으로 하려면 겹칠 때 끝이 늦은 쪽을 지우고 `end`를 둘 중 작은 값으로 둔다. 결국 끝이 이른 쪽을 남긴다는 같은 원리다.

### 가장 짧은 구간부터 남기면 어떻게 되나요?

틀린다. `[[1, 5], [4, 7], [6, 10]]`에서 가장 짧은 `[4, 7]`을 남기면 양옆 둘이 다 막혀 두 개를 지운다. `[4, 7]`만 지우면 되니 정답은 1이다. 그럴듯한 그리디라도 증명이 없으면 반례를 먼저 찾아본다.

### 시간과 공간 복잡도는요?

정렬 O(n log n)에 한 번 훑기 O(n)이라 O(n log n)이다. 추가 공간은 마지막 끝 하나와 개수뿐이라 정렬을 빼면 O(1)이다. 정렬에 쓰는 공간은 언어의 정렬 구현에 따라 O(n)까지 든다.

### [1, 2]와 [2, 3]은 겹치나요?

이 문제에서는 겹치지 않는다. 그래서 남길 조건이 `s >= end`다. `>`로 쓰면 닿는 구간을 괜히 지운다. 닿는 것도 겹침으로 보는 452번 풍선 문제에서는 반대로 `>`가 맞다.

### 구간에 점수가 붙으면 어떻게 푸나요?

그리디는 깨지고 DP로 간다. 끝 순으로 정렬하고 `dp[i] = max(dp[i - 1], dp[p] + 점수)`로 채운다. p는 i의 시작 이하에서 끝나는 구간 개수이고 이분 탐색으로 찾는다. O(n log n)이다.

### 이 문제를 "남길 최대 개수"로 바꿔 생각하는 이유는요?

지울 최소 개수는 n에서 남길 최대 개수를 뺀 값이라 둘은 같은 문제다. 남길 쪽으로 생각하면 "서로 겹치지 않는 구간을 가장 많이 고르기"라는 잘 알려진 활동 선택 문제가 되고, 그리디의 근거도 그쪽에서 말하기 쉽다.
