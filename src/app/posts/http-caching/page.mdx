## 한 줄로 말하면

HTTP 캐시는 **"한 번 받은 건 저장해 두고, 다시 쓸 수 있으면 다시 가져오지 않는 것"** 이에요.

## 비유로 이해하기: 냉장고

매번 마트에 가는 건 느리고 힘들어요. 그래서 우유를 **냉장고에 넣어 두고**, 유통기한 안에는 냉장고에서 꺼내 마셔요.

- 유통기한이 **남아 있으면** → 마트에 안 가도 돼요. (캐시 사용)
- 유통기한이 **지났으면** → 마트에 "이 우유 아직 괜찮아요?" 하고 물어봐요. 괜찮다면 새로 사 오지 않고 그냥 써요. (재검증)

브라우저가 냉장고, 서버가 마트예요.

## 자주 보는 헤더 정리

| 헤더 | 쉬운 말 |
|---|---|
| `Cache-Control: max-age=3600` | "1시간 동안은 그냥 써도 돼요" |
| `Cache-Control: no-cache` | "저장은 해도 되는데, **쓰기 전에 꼭 물어보고** 써요" |
| `Cache-Control: no-store` | "**저장하지 마세요**" (민감한 정보) |
| `ETag` / `If-None-Match` | 버전 번호표로 "바뀌었나요?" 물어보기 |
| `Last-Modified` / `If-Modified-Since` | 수정 시각으로 "바뀌었나요?" 물어보기 |

<Callout kind="warning" title="no-cache는 '캐시하지 마'가 아니에요">
  이름이 헷갈리지만, `no-cache`는 "저장하지 마"가 아니라 "**쓰기 전에 서버에 확인해**"라는 뜻이에요. 저장 자체를 막고 싶으면 `no-store`를 써요.
</Callout>

## 웹사이트에서는 이렇게 써요

파일 이름에 **해시**(내용에서 만든 짧은 지문)를 붙이면, 내용이 바뀔 때 이름도 바뀌어요. 그래서 이름이 같다면 내용도 같다는 게 보장돼요. 이런 파일은 아주 오래 저장해도 안전해요.

```http
# app.3f9a1c.js — 이름이 곧 버전이니까 1년 동안 서버에 묻지 않아도 돼요
Cache-Control: public, max-age=31536000, immutable
```

HTML은 주소가 늘 같아서 내용이 바뀌어도 이름이 안 바뀌어요. 그래서 매번 확인하게 해요.

```http
Cache-Control: no-cache
```

## 내 말로 다시 설명해보기

<details>
<summary>Q1. 304 응답은 왜 빠를까요?</summary>

서버가 사진 본문을 다시 보내지 않고 "바뀌지 않았어요"라는 **아주 짧은 답**만 보내기 때문이에요. 브라우저는 이미 갖고 있는 사진을 그대로 써요.

</details>

<details>
<summary>Q2. 파일 이름에 해시를 붙이면 왜 오래 캐시해도 안전할까요?</summary>

내용이 바뀌면 **파일 이름도 바뀌어서** 브라우저가 새 파일로 인식하기 때문이에요. 같은 이름이라면 내용도 같으니 옛 파일을 써도 문제가 없어요.

</details>

<Callout kind="tip" title="12살 친구에게 설명한다면">

</Callout>
