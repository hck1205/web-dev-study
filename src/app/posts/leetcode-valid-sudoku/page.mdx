[Valid Sudoku](https://leetcode.com/problems/valid-sudoku/)는 LeetCode 36번 Medium 문제다. 알고리즘이 어려운 문제는 아니다. 그래도 면접에서 자주 나오는 이유가 있다. "같은 것이 두 번 나왔나"를 해시 집합으로 확인하는 [Contains Duplicate](/posts/leetcode-contains-duplicate)의 생각을 한 번에 스물일곱 곳에 적용해야 하고, 2차원 좌표를 상자 번호 하나로 바꾸는 식에서 실수가 잘 나오고, 같은 확인을 집합·문자열 키·비트로 각각 어떻게 담는지 설명할 거리가 많다.

이 글은 풀이를 네 가지로 놓는다. 줄·열·상자를 따로 세 번 훑기, 한 번 훑으며 집합 27개에 적기, 집합 하나에 문자열 키로 적기, 정수 27개의 비트로 적기다. 해시 집합이 왜 평균 O(1)에 찾는지는 [해시맵 글](/posts/ds-hash-map)에서, 비트 연산의 기초는 [비트 연산 글](/posts/bit-manipulation)에서 다뤘다. 코드는 모두 Node.js 22, Python 3.13, Java 21에서 직접 돌렸다.

## 채운 칸만 규칙을 지키는지 본다

9 × 9 판 `board`가 주어진다. 칸에는 `"1"`부터 `"9"`까지의 글자나 빈칸을 뜻하는 `"."`이 들어 있다. 채워진 칸만 보고 세 규칙을 지키는지 판단해 `true`나 `false`를 돌려준다.

- 각 가로줄(행)에 같은 숫자가 두 번 이상 없다.
- 각 세로줄(열)에 같은 숫자가 두 번 이상 없다.
- 판을 3 × 3으로 나눈 아홉 개의 상자 각각에 같은 숫자가 두 번 이상 없다.

중요한 단서가 하나 있다. 올바른 판이 꼭 풀 수 있는 판은 아니다. 문제는 지금 적힌 숫자가 규칙을 어겼는지만 묻는다. 끝까지 채울 수 있는지는 묻지 않는다. 이 차이는 뒤에서 실제 판으로 다시 본다.

판 크기가 9 × 9로 정해져 있다는 것도 풀이 선택에 영향을 준다. 칸이 81개로 고정이라 어떤 풀이든 엄밀히는 O(1)이다. 그래서 이 문제에서 복잡도를 말할 때는 판 한 변을 n이라 두고 일반화한 n × n 판(상자는 √n × √n)을 기준으로 말하는 편이 대화가 된다. 면접관도 대개 그쪽을 묻는다.

## 판 하나를 손으로 검사해 보기

글에서 쓸 판이다. 굵은 선 대신 `|`와 `-`로 상자를 나눴다.

```text
       0 1 2   3 4 5   6 7 8
  0    1 . 3 | . 5 . | . . .
  1    . . . | . 8 . | 1 . 3
  2    . 8 . | 1 . . | . . 6
       ------+-------+------
  3    . . . | 5 . 7 | . 9 .
  4    5 . 7 | . . . | . 3 .
  5    . . 1 | . 3 . | 5 . .
       ------+-------+------
  6    . 4 . | . . . | 9 . 2
  7    . 7 . | 9 . 2 | . . .
  8    9 . . | . . 5 | . 7 .
```

이 판은 올바르다. 0행을 보면 1, 3, 5뿐이고 겹치지 않는다. 0열은 1, 5, 9다. 왼쪽 위 상자(0번 상자)는 1, 3, 8이다. 행 9개, 열 9개, 상자 9개를 다 이렇게 보면 겹치는 곳이 없다.

여기서 (0, 3)에 8을 적으면 어떻게 될까. 0행에는 8이 없고, 3열에도 8이 없다. 그런데 (0, 3)이 속한 위 가운데 상자(1번 상자)에는 (1, 4)에 이미 8이 있다. 행과 열만 보면 놓친다. 세 규칙은 서로 독립이라 하나라도 빠뜨리면 틀린다.

사람이 판을 볼 때 실제로 하는 일은 "이 숫자를 이 줄에서 본 적이 있나"를 기억하는 것이다. 기억할 곳이 행 9개, 열 9개, 상자 9개로 27군데다. 풀이는 결국 이 27군데의 기억을 어떤 그릇에 담느냐의 차이다.

## 상자 번호를 구하는 식

행과 열은 칸의 좌표에서 바로 나온다. 상자는 한 번 계산해야 한다. 상자를 왼쪽 위부터 오른쪽으로, 다시 다음 줄로 0번부터 8번까지 번호를 매긴다.

```text
  상자 번호
  0 | 1 | 2
  --+---+--
  3 | 4 | 5
  --+---+--
  6 | 7 | 8
```

칸 (r, c)가 상자 줄 몇 번째에 있는지는 `r`을 3으로 나눈 몫, 상자 칸 몇 번째인지는 `c`를 3으로 나눈 몫이다. 상자 줄 하나에 상자가 3개씩 있으니 상자 번호는 `Math.floor(r / 3) * 3 + Math.floor(c / 3)`이다. 2차원 배열을 한 줄로 펼칠 때 `r * 열 수 + c`로 칸 번호를 매기는 것과 같은 모양이다. 아래 그림에서 칸 몇 개의 상자 번호를 차례로 구해 본다.

이 식에서 가장 많이 틀린다. 몫을 그냥 더한 `Math.floor(r / 3) + Math.floor(c / 3)`은 (0, 4)와 (4, 0)이 둘 다 1이 돼 서로 다른 상자를 같은 상자로 본다. JavaScript에서 `Math.floor`를 빼고 `(r / 3) * 3 + c / 3`으로 쓰면 `/`가 소수 나눗셈이라 `(r / 3) * 3`이 그냥 `r`로 돌아온다. 둘 다 올바른 판을 틀렸다고 판단하는 걸 뒤의 "틀리기 쉬운 자리" 절에서 실제로 돌려 본다. Python은 `//`, Java는 `int`끼리의 `/`가 몫을 주니 그대로 써도 된다.

## 줄, 열, 상자를 따로 세 번 훑기

가장 곧이곧대로 옮긴 풀이다. 규칙이 셋이니 세 번 검사한다. 행마다 집합 하나를 새로 만들어 칸을 넣어 보고, 이미 있으면 `false`다. 열과 상자도 똑같이 한다.

```js
function isValidSudoku(board) {
  // 1) 행마다
  for (let r = 0; r < 9; r++) {
    const seen = new Set();
    for (let c = 0; c < 9; c++) {
      const v = board[r][c];
      if (v === ".") continue;          // 빈칸은 건너뛴다
      if (seen.has(v)) return false;    // 같은 행에서 이미 봤다
      seen.add(v);
    }
  }
  // 2) 열마다
  for (let c = 0; c < 9; c++) {
    const seen = new Set();
    for (let r = 0; r < 9; r++) {
      const v = board[r][c];
      if (v === ".") continue;
      if (seen.has(v)) return false;
      seen.add(v);
    }
  }
  // 3) 상자마다: 상자 b의 왼쪽 위 칸은 (floor(b / 3) * 3, (b % 3) * 3)
  for (let b = 0; b < 9; b++) {
    const seen = new Set();
    const r0 = Math.floor(b / 3) * 3, c0 = (b % 3) * 3;
    for (let r = r0; r < r0 + 3; r++) {
      for (let c = c0; c < c0 + 3; c++) {
        const v = board[r][c];
        if (v === ".") continue;
        if (seen.has(v)) return false;
        seen.add(v);
      }
    }
  }
  return true;
}
```

여기서는 상자 번호를 칸에서 구하는 대신 거꾸로, 상자 번호 `b`에서 왼쪽 위 칸을 구한다. 상자 줄은 `b`를 3으로 나눈 몫, 상자 칸은 나머지다.

예시 판을 넣으면 `true`가 나온다. 판을 하나씩 고쳐서도 넣어 봤다. (0, 1)에 5를 넣으면 0행에 5가 두 번, (0, 1)에 4를 넣으면 1열에 4가 두 번, (0, 3)에 8을 넣으면 1번 상자에만 8이 두 번 나온다. 세 판 모두 `false`다. 겹치는 곳이 행·열·상자 중 한 곳뿐인 판을 일부러 만든 건, 세 검사 중 하나를 빠뜨린 코드를 잡기 위해서다.

시간은 n × n 판이면 칸을 세 번 보니 O(n²)이다. 9 × 9면 243번이다. 공간은 한 번에 집합 하나만 들고 있고 그 크기가 n 이하라 O(n)이다.

이 풀이는 맞고 읽기도 쉽다. 아쉬운 점은 같은 판을 세 번 읽고, 비슷한 반복문을 세 번 쓴다는 것이다. 코드가 길면 상자 반복문의 범위 같은 데서 오타가 나기 쉽다. 칸 하나를 볼 때 그 칸이 속한 행·열·상자를 한꺼번에 확인하면 한 번에 끝난다.

## 한 번 훑으며 출석부 27권에 적기

집합을 행용 9개, 열용 9개, 상자용 9개로 미리 만들어 둔다. 칸 (r, c)의 숫자 v를 볼 때 할 일은 두 가지이고 순서가 정해져 있다.

1. `rows[r]`, `cols[c]`, `boxes[b]` 세 집합 중 어디라도 v가 이미 있으면 `false`다.
2. 없으면 세 집합 모두에 v를 넣는다.

```js
function isValidSudoku(board) {
  const rows = Array.from({ length: 9 }, () => new Set());
  const cols = Array.from({ length: 9 }, () => new Set());
  const boxes = Array.from({ length: 9 }, () => new Set());

  for (let r = 0; r < 9; r++) {
    for (let c = 0; c < 9; c++) {
      const v = board[r][c];
      if (v === ".") continue;
      const b = Math.floor(r / 3) * 3 + Math.floor(c / 3); // 상자 번호
      // 1) 먼저 묻는다: 이 행, 이 열, 이 상자에서 v를 본 적이 있나
      if (rows[r].has(v) || cols[c].has(v) || boxes[b].has(v)) return false;
      // 2) 없으면 세 곳 모두에 적는다
      rows[r].add(v);
      cols[c].add(v);
      boxes[b].add(v);
    }
  }
  return true;
}
```

`Array.from({ length: 9 }, () => new Set())`은 집합 9개를 각각 새로 만든다. `new Array(9).fill(new Set())`로 쓰면 같은 집합 하나를 9칸이 함께 가리켜서, 0행에 넣은 숫자가 모든 행에 들어간 것처럼 보인다. 2차원 배열을 만들 때 흔히 나오는 실수라 이 모양을 손에 익혀 둔다.

아래 그림은 예시 판과 다른 작은 판이다. 왼쪽 위 세 줄에만 숫자 일곱 개가 있고, 마지막에 (2, 2)에 5가 들어온다.

```text

  0    5 3 . | . 7 .
  1    6 . . | 1 . .
  2    . 9 5 | . . .
```

(2, 2)의 5는 2행에도, 2열에도 처음 나온다. 하지만 0번 상자에는 (0, 0)에 이미 5가 있다. 그림에서 다음을 누르면 칸마다 세 출석부가 어떻게 바뀌는지 보인다. 각 단계의 기억 칸은 그 칸을 적고 난 뒤 세 출석부의 모습이다.

시간은 칸마다 집합 조회 세 번과 삽입 세 번이라 n × n 판에서 평균 O(n²)이다. 세 번 훑기와 등급은 같지만 판을 한 번만 읽고, 겹치는 칸을 만나는 순간 바로 끝난다. 공간은 집합 3n개에 각각 최대 n개가 들어가니 O(n²)이다. 9 × 9면 많아야 243개다.

공간이 세 번 훑기의 O(n)보다 커졌다. 판을 한 번만 읽는 대신 모든 행·열·상자의 기억을 동시에 들고 있어야 하기 때문이다. 9 × 9에서는 의미 없는 차이지만, 면접관이 "두 풀이의 차이는요?"라고 물으면 이 맞바꿈을 말하면 된다.

## 집합 하나에 이름표를 붙여 적기

집합 27개를 하나로 합칠 수도 있다. 숫자 대신 "어디서 본 숫자인지"를 문자열로 만들어 넣는다. (0, 4)의 7이라면 `"7 in row 0"`, `"7 in col 4"`, `"7 in box 1"` 세 개를 넣는다. 같은 문자열이 다시 들어오려 하면 같은 행·열·상자에 같은 숫자가 또 나왔다는 뜻이다.

```js
function isValidSudoku(board) {
  const seen = new Set(); // "숫자 in 어디" 이름표를 모두 한 집합에
  for (let r = 0; r < 9; r++) {
    for (let c = 0; c < 9; c++) {
      const v = board[r][c];
      if (v === ".") continue;
      const b = Math.floor(r / 3) * 3 + Math.floor(c / 3);
      const keys = [`${v} in row ${r}`, `${v} in col ${c}`, `${v} in box ${b}`];
      for (const k of keys) {
        if (seen.has(k)) return false;
        seen.add(k);
      }
    }
  }
  return true;
}
```

이 풀이는 코드가 가장 짧고, 규칙을 하나 더 붙이기 쉽다. 대각선에도 같은 숫자가 없어야 하는 변형 스도쿠라면 이름표를 하나 더 만들면 된다. Python에서는 문자열 대신 튜플 `(r, v)`, `(v, c)`, `(r // 3, c // 3, v)`를 넣는 모양이 자주 보인다. 튜플은 위치마다 모양이 달라 행 이름표와 열 이름표가 섞이지 않는다.

대가는 속도다. 칸마다 문자열 세 개를 새로 만들고 해시를 계산한다. 9 × 9에서는 상관없지만 같은 기법을 큰 격자에 쓰면 문자열 생성 비용이 눈에 띈다. 이름표 모양을 정할 때도 조심해야 한다. `"" + r + c`처럼 구분자 없이 이어 붙이면 큰 격자에서 (1, 12)와 (11, 2)가 둘 다 `"112"`가 된다. 구분자를 꼭 넣는다.

## 정수 27개의 비트에 적기

출석부에 들어갈 수 있는 숫자가 1부터 9까지 아홉 개뿐이다. 그럼 집합 대신 정수 하나의 비트 9개로 "봤다/안 봤다"를 담을 수 있다. 숫자 d를 봤으면 `d - 1`번 비트를 켠다. 1은 0번 비트(값 1), 9는 8번 비트(값 256)다.

```js
function isValidSudoku(board) {
  const rows = new Array(9).fill(0);  // 정수는 값이라 fill로 채워도 안전하다
  const cols = new Array(9).fill(0);
  const boxes = new Array(9).fill(0);
  for (let r = 0; r < 9; r++) {
    for (let c = 0; c < 9; c++) {
      const ch = board[r][c];
      if (ch === ".") continue;
      const bit = 1 << (ch.charCodeAt(0) - 49); // '1'의 문자 코드가 49다
      const b = Math.floor(r / 3) * 3 + Math.floor(c / 3);
      // 그 비트가 이미 켜져 있으면 이미 본 숫자다
      if ((rows[r] & bit) || (cols[c] & bit) || (boxes[b] & bit)) return false;
      rows[r] |= bit;
      cols[c] |= bit;
      boxes[b] |= bit;
    }
  }
  return true;
}
```

예를 들어 0행에서 1, 3, 5를 봤다면 `rows[0]`은 2진수로 `000010101`, 십진수로 21이다. 다음에 3이 오면 `bit`는 `000000100`(4)이고 `21 & 4`는 4라 참이니 겹친 것이다. 7이 오면 `bit`는 64이고 `21 & 64`는 0이라 처음 보는 숫자다.

여기서 집합의 `fill` 실수가 정수에서는 생기지 않는다. 정수는 값이라 9칸이 각자 자기 0을 갖는다. 집합은 객체라 `fill`이 같은 객체를 9칸에 나눠 줬던 것이다.

시간은 O(n²)로 같고, 칸마다 하는 일이 비트 연산 몇 번이라 상수가 가장 작다. 공간은 정수 3n개다. n이 32 이하라면 숫자 n개가 정수 하나에 들어가 O(n)이고, n이 그보다 크면 정수 여러 개를 이어 붙여야 해서 결국 집합과 비슷해진다. 이 풀이는 [Sudoku Solver](/posts/leetcode-sudoku-solver)로 넘어갈 때 특히 쓸모가 있다. 빈칸에 넣을 수 있는 후보가 `~(rows[r] | cols[c] | boxes[b]) & 511` 한 줄로 나오기 때문이다.

## Python과 Java로 옮기기

Python은 한 번 훑기 집합 27개 풀이를, Java는 같은 구조를 비트로 담은 풀이를 옮겼다. 구조는 같고, 담는 그릇만 다르다.

```python
from typing import List

class Solution:
    def isValidSudoku(self, board: List[List[str]]) -> bool:
        rows = [set() for _ in range(9)]
        cols = [set() for _ in range(9)]
        boxes = [set() for _ in range(9)]
        for r in range(9):
            for c in range(9):
                v = board[r][c]
                if v == ".":
                    continue
                b = (r // 3) * 3 + c // 3   # //는 정수 나눗셈
                if v in rows[r] or v in cols[c] or v in boxes[b]:
                    return False
                rows[r].add(v)
                cols[c].add(v)
                boxes[b].add(v)
        return True
```

예시 판을 넣으면 `True`, 같은 판의 (0, 3)에 `"8"`을 넣으면 `False`가 나온다.

`[set() for _ in range(9)]`는 집합을 9번 새로 만든다. `[set()] * 9`로 쓰면 JavaScript의 `fill`과 똑같이 집합 하나를 9칸이 함께 가리킨다. 리스트 곱셈은 안의 객체를 복사하지 않는다.

```java
class Solution {
    public boolean isValidSudoku(char[][] board) {
        int[] rows = new int[9], cols = new int[9], boxes = new int[9]; // 비트 d가 켜져 있으면 숫자 d+1을 봤다
        for (int r = 0; r < 9; r++) {
            for (int c = 0; c < 9; c++) {
                char ch = board[r][c];
                if (ch == '.') continue;
                int bit = 1 << (ch - '1');          // '1' → 1, '9' → 256
                int b = (r / 3) * 3 + c / 3;        // int끼리 나눗셈은 버림
                if ((rows[r] & bit) != 0 || (cols[c] & bit) != 0 || (boxes[b] & bit) != 0) return false;
                rows[r] |= bit;
                cols[c] |= bit;
                boxes[b] |= bit;
            }
        }
        return true;
    }

    public static void main(String[] args) {
        String[] g = {
            "1.3.5....", "....8.1.3", ".8.1....6",
            "...5.7.9.", "5.7....3.", "..1.3.5..",
            ".4....9.2", ".7.9.2...", "9....5.7."
        };
        char[][] board = new char[9][];
        for (int i = 0; i < 9; i++) board[i] = g[i].toCharArray();
        Solution s = new Solution();
        System.out.println(s.isValidSudoku(board));
        board[0][3] = '8';
        System.out.println(s.isValidSudoku(board));
    }
}
```

```text
true
false
```

Java의 `char`는 숫자처럼 뺄 수 있어서 `ch - '1'`이 바로 0부터 8까지의 정수가 된다. JavaScript는 문자열이라 `charCodeAt`을 거쳐야 했다. Java에서 `(rows[r] & bit)`를 `if` 조건에 그대로 쓰면 컴파일이 안 된다. `int`는 `boolean`이 아니니 `!= 0`을 붙인다. 판이 `char[][]`라 빈칸 비교도 `"."`가 아닌 `'.'`이다.

## 틀리기 쉬운 자리

### 상자 번호 식

예시 판은 올바른데, 상자 번호 식을 틀리게 쓰면 `false`가 나온다.

```text
Math.floor(r / 3) + Math.floor(c / 3)   →  false
(r / 3) * 3 + c / 3                     →  false
Math.floor(r / 3) * 3 + Math.floor(c / 3)  →  true
```

첫 번째 식은 (0, 4)의 5와 (4, 0)의 5를 둘 다 상자 1로 본다. 원래는 1번 상자와 3번 상자다. 두 번째 식은 `(r / 3) * 3`이 그냥 `r`이 돼서 상자 번호가 `r + c / 3`이 되고, (1, 6)의 1과 (2, 3)의 1이 둘 다 3으로 계산된다. 실제로 `(4 / 3) * 3 + 5 / 3`을 찍으면 `5.666666666666667`이 나온다. 상자 번호가 소수가 되는 순간 이 식은 상자를 전혀 구분하지 못한다.

### 빈칸까지 세는 경우

`"."`을 건너뛰지 않으면 빈칸이 두 개 이상인 줄은 전부 겹쳤다고 판단한다. 예시 판은 이 실수 하나로 `false`가 되고, 빈칸이 하나도 없는 완성된 판에서만 우연히 맞는다. 테스트에 다 채워진 판만 넣으면 이 버그를 못 잡는다.

### 집합을 fill로 나눠 갖는 경우

`new Array(9).fill(new Set())`, Python의 `[set()] * 9`는 집합 하나를 9칸이 함께 쓴다. 0행에 1을 넣으면 1행에서도 1이 이미 있는 것처럼 보여, (1, 6)의 1에서 `false`가 나온다.

### 올바른 판과 풀 수 있는 판

```text
  1 2 3 | 4 5 6 | 7 8 .
  . . . | . . . | . . .
  . . . | . . . | . . .
  ------+-------+------
  . . . | . . . | . . .
  . . . | . . . | . . 9
  ...나머지 빈칸
```

0행에 1부터 8까지 있고, (4, 8)에 9가 있다. 겹치는 곳이 없으니 이 판은 올바르다. 그런데 (0, 8)에는 0행 때문에 9만 들어갈 수 있고, 8열에 이미 9가 있어서 9도 못 넣는다. 후보를 실제로 세어 보면 빈 목록이다. 끝까지 채울 수 없는 판이지만 이 문제의 답은 `true`다. "풀 수 있나"까지 판단하려면 [Sudoku Solver](/posts/leetcode-sudoku-solver)처럼 백트래킹으로 실제로 채워 봐야 한다.

## 조건이 바뀌면

### 판이 n × n이라면

16 × 16(상자 4 × 4)이나 25 × 25 판이라면 9와 3을 n과 √n으로 바꾸면 된다. 상자 번호는 `Math.floor(r / k) * k + Math.floor(c / k)`, k = √n이다. 비트 풀이는 숫자가 n개라 n이 32를 넘으면 JavaScript의 32비트 비트 연산에 다 안 들어간다. 그때는 `BigInt`나 정수 배열로 비트를 이어 붙이거나, 집합 풀이로 돌아간다.

집합 풀이를 판 크기에 맞춰 일반화하면 이렇다. 16 × 16 판에서는 칸 값이 `"16"`처럼 두 글자일 수 있어서 판을 문자열 한 줄로 적을 수 없고, 칸마다 문자열을 하나씩 담은 2차원 배열로 받는다.

```js
function isValidBoard(board) {
  const n = board.length, k = Math.round(Math.sqrt(n)); // 상자 한 변
  const rows = Array.from({ length: n }, () => new Set());
  const cols = Array.from({ length: n }, () => new Set());
  const boxes = Array.from({ length: n }, () => new Set());
  for (let r = 0; r < n; r++) {
    for (let c = 0; c < n; c++) {
      const v = board[r][c];
      if (v === ".") continue;
      const b = Math.floor(r / k) * k + Math.floor(c / k);
      if (rows[r].has(v) || cols[c].has(v) || boxes[b].has(v)) return false;
      rows[r].add(v); cols[c].add(v); boxes[b].add(v);
    }
  }
  return true;
}

// 16 × 16 완성 판을 규칙으로 만든다: (r * 4 + floor(r / 4) + c) % 16 + 1
const big = Array.from({ length: 16 }, (_, r) =>
  Array.from({ length: 16 }, (_, c) => String(((r * 4 + Math.floor(r / 4) + c) % 16) + 1)));
console.log(isValidBoard(big));
[big[0][0], big[5][5]] = [big[5][5], big[0][0]]; // 두 칸을 맞바꾼다
console.log(big[0][0], big[5][5], isValidBoard(big));
```

완성 판을 만드는 식은 행마다 한 상자 폭(4칸)씩 밀고, 상자 줄이 바뀔 때 한 칸 더 미는 규칙이다. 9 × 9의 `123456789 / 456789123 / ...` 판도 같은 규칙이다. 두 칸을 맞바꾸면 0행에 11이 두 번 생겨 `false`가 된다.

### 칸이 하나씩 들어온다면

"사용자가 칸에 숫자를 하나 적을 때마다 규칙을 어겼는지 바로 알려 달라"는 요구라면 한 번 훑기 구조가 그대로 들어맞는다. 출석부 27권을 계속 들고 있으면서, 새 칸이 들어올 때 세 권만 확인하면 O(1)이다. 숫자를 지우는 것까지 받으려면 "봤다/안 봤다" 대신 "몇 번 봤다"를 세야 한다. 같은 행에 실수로 5를 두 번 넣었다가 하나를 지웠을 때, 집합이나 비트에서 5를 지우면 남아 있는 5까지 사라지기 때문이다. 개수를 세면 2에서 1로 줄어 남은 하나를 기억한다.

구역 27개마다 숫자별 개수를 세고, "개수가 2 이상인 칸"의 수를 따로 들고 가면 적기와 지우기가 모두 O(1)이다.

```js
class LiveSudoku {
  constructor() {
    // count[구역][숫자]: 구역 0~8은 행, 9~17은 열, 18~26은 상자
    this.count = Array.from({ length: 27 }, () => new Array(10).fill(0));
    this.conflicts = 0; // 개수가 2 이상인 (구역, 숫자) 쌍의 수
  }
  zones(r, c) { return [r, 9 + c, 18 + Math.floor(r / 3) * 3 + Math.floor(c / 3)]; }
  put(r, c, d) {
    for (const z of this.zones(r, c)) if (++this.count[z][d] === 2) this.conflicts++;
    return this.conflicts === 0;
  }
  erase(r, c, d) {
    for (const z of this.zones(r, c)) if (--this.count[z][d] === 1) this.conflicts--;
    return this.conflicts === 0;
  }
}

const s = new LiveSudoku();
console.log(s.put(0, 0, 5));   // 처음 적는 5
console.log(s.put(0, 7, 5));   // 같은 행에 5를 또 적는다
console.log(s.put(1, 1, 5));   // 0번 상자에도 5가 겹친다
console.log(s.erase(0, 7, 5)); // 행에서 겹친 5를 지운다. 상자는 아직 겹쳐 있다
console.log(s.erase(1, 1, 5)); // 상자에서 겹친 5도 지운다
```

```text
true
false
false
false
true
```

개수가 1에서 2로 올라가는 순간에만 `conflicts`를 늘리고, 2에서 1로 내려가는 순간에만 줄인다. 그래서 같은 숫자가 세 번 겹쳐도 그 구역은 한 번만 센다. 네 번째 줄이 `false`인 게 이 구조의 요점이다. 행의 겹침은 풀렸지만 상자의 겹침이 남아 있다는 걸 기억하고 있다.

### 어느 칸이 겹치는지 알려 달라면

`true`/`false` 대신 겹치는 칸 좌표를 돌려줘야 한다면 집합 대신 해시맵을 쓴다. 숫자 → 처음 본 좌표를 적어 두면, 겹치는 순간 지금 칸과 저장된 칸을 함께 돌려줄 수 있다. [Two Sum](/posts/leetcode-two-sum)에서 값 → 인덱스 장부를 쓰던 것과 같은 모양이다.

### 비슷한 문제

규칙을 지키는 판을 실제로 채우는 [Sudoku Solver](/posts/leetcode-sudoku-solver)가 이 문제의 바로 다음 단계다. 출석부 27권을 그대로 들고 들어가서, 빈칸마다 후보를 고르고 막히면 되돌아간다. 행·열·대각선마다 "이미 썼나"를 기억하는 [N-Queens](/posts/leetcode-n-queens)도 같은 기억 구조를 쓴다. 행과 열에 표시를 남기는 [Set Matrix Zeroes](/posts/leetcode-set-matrix-zeroes), 각 행과 열에 1부터 n까지가 다 있는지 묻는 LeetCode 2133. Check if Every Row and Column Contains All Numbers도 가까운 문제다.

## 면접에서 나올 만한 질문

### 상자 번호는 어떻게 구하나요?

칸 (r, c)의 상자 줄은 r을 3으로 나눈 몫, 상자 칸은 c를 3으로 나눈 몫이다. 상자 줄 하나에 상자가 3개씩 있으니 번호는 `(r / 3) * 3 + c / 3`(몫 나눗셈)이다. 몫을 그냥 더하면 (0, 4)와 (4, 0)처럼 다른 상자가 같은 번호가 되고, JavaScript에서 `Math.floor`를 빼면 소수가 섞여 상자를 구분하지 못한다.

### 왜 해시 집합을 썼나요?

각 행·열·상자에서 "이 숫자를 본 적이 있나"를 평균 O(1)에 확인하려고 썼다. 한 번 훑으면서 칸마다 세 집합에 먼저 묻고 없으면 넣으면, 겹치는 칸을 만나는 순간 바로 끝난다. 숫자가 1부터 9까지로 정해져 있으니 집합 대신 길이 9의 불리언 배열이나 비트 9개로 바꿔도 된다.

### 시간 복잡도는 얼마인가요?

9 × 9로 고정이면 칸이 81개라 O(1)이다. 판 한 변을 n으로 일반화하면 칸이 n²개고 칸마다 상수 번 확인하니 O(n²)다. 공간은 한 번 훑기 집합 풀이가 O(n²), 세 번 따로 훑는 풀이가 O(n), 비트 풀이는 n이 32 이하일 때 O(n)이다.

### 올바른 판이면 항상 풀 수 있나요?

아니다. 이 문제는 지금 채워진 칸이 규칙을 어기지 않았는지만 본다. 0행에 1부터 8이 있고 8열 다른 곳에 9가 있으면 겹치는 곳은 없지만 (0, 8)에 들어갈 숫자가 없다. 풀 수 있는지까지 보려면 백트래킹으로 실제로 채워 봐야 한다.

### 비트마스크로 바꾸면 무엇이 좋아지나요?

집합 객체 27개 대신 정수 27개로 같은 정보를 담아서 메모리 할당이 없고, 확인과 기록이 AND와 OR 한 번씩이라 상수가 작다. 더 큰 장점은 풀이기로 넘어갈 때다. 빈칸의 후보가 세 정수를 OR한 뒤 뒤집기만 하면 한 번에 나와서 백트래킹이 빨라진다.

### 칸을 지우는 연산까지 지원하려면요?

봤다/안 봤다 대신 개수를 세야 한다. 집합이나 비트에서는 같은 숫자가 두 번 들어간 상태에서 하나를 지우면 남은 하나의 기록까지 사라진다. 행·열·상자마다 숫자별 개수를 세고, 넣을 때 1을 더하고 지울 때 1을 빼면 개수가 2 이상인 곳이 겹친 곳이다.
