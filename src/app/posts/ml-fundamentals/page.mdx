이탈 예측 모델을 만든 데이터 팀이 회의에서 결과를 보여 준다. 다음 달에 떠날 고객을 맞히는 모델인데, 따로 떼어 둔 시험 데이터에서 정확도 99.7%, 실제로 떠난 고객의 99.2%를 찾아냈다. 마케팅 팀은 바로 쿠폰을 보내자고 한다. 배포 첫 달, 모델이 "떠날 것 같다"고 표시한 고객은 5,000명 중 다섯 명이었다. 그달 실제로 떠난 고객은 1,300명이 넘었다. 정확도는 73.6%로 떨어졌는데, 이건 모두에게 "안 떠난다"고 답하는 것보다도 못한 숫자다.

모델이 나빴던 게 아니다. 모델은 데이터에 있는 것을 아주 잘 배웠다. 문제는 데이터에 있으면 안 되는 것이 있었다는 데 있다. 이 글은 이 장면을 scikit-learn으로 직접 재현하면서, 머신러닝을 처음 붙여 보는 개발자가 알아야 할 기초를 순서대로 짚는다. 지도 학습과 비지도 학습, 특징과 라벨, 학습·검증·테스트 분할, 과적합과 편향-분산, 규제, 경사 하강의 직관, 그리고 가장 흔한 실수인 데이터 누수다. 모델을 어떤 지표로 평가할지(정확도가 왜 속이는지)는 [모델 평가 글](/posts/ml-model-evaluation)에서 이어서 본다.

실습 환경은 Python 3.13, scikit-learn 1.9.1, NumPy 2.5.3이다. 데이터는 모두 코드로 만든 가짜 데이터라서 같은 시드로 돌리면 같은 숫자가 나온다.

## 규칙을 쓰는 대신 예시에서 규칙을 찾는다

보통의 프로그램은 사람이 규칙을 쓴다. "30일 넘게 접속하지 않으면 이탈 위험"처럼. 머신러닝은 반대 방향이다. 과거 고객 수천 명의 기록과 실제로 떠났는지를 주면, 프로그램이 기록에서 규칙을 찾는다. 사람이 미처 생각하지 못한 조합(가입 기간이 짧고, 최근 문의가 늘었고, 사용 일수가 줄었다)도 찾는다.

용어 몇 개만 먼저 정리한다.

- 특징(feature): 모델에 넣는 입력 값. 가입 개월 수, 최근 30일 문의 수, 사용 일수 같은 것. 표로 치면 열이다.
- 라벨(label, target): 맞히려는 답. "다음 달에 떠났나"(0 또는 1).
- 샘플: 표의 한 행. 고객 한 명.
- 모델: 특징을 받아 라벨을 내는 함수. 학습은 이 함수의 숫자(가중치, 트리의 분기 기준)를 데이터에 맞게 정하는 일이다.

답이 있는 데이터로 배우는 것이 지도 학습(supervised learning)이다. 답이 범주면 분류(떠난다/안 떠난다, 스팸/정상), 숫자면 회귀(내일 판매량, 집값)다. 답이 없는 데이터에서 구조를 찾는 것이 비지도 학습(unsupervised learning)이다. 비슷한 고객끼리 묶는 군집화, 수백 개 특징을 몇 개로 줄이는 차원 축소, 평소와 다른 거래를 찾는 이상 탐지가 여기 들어간다. 문장을 벡터로 바꾸는 임베딩도 비지도에 가까운 방식으로 배운 결과물이다. 임베딩을 서비스에서 쓰는 법은 [임베딩 모델 글](/posts/embedding-models-applications)에 있다.

이 글은 지도 학습만 다룬다. 서비스 개발자가 가장 먼저 만나는 쪽이고, 이 글의 실수들이 가장 자주 나는 쪽이다.

## 시험지를 훔쳐보지 않게 데이터를 셋으로 나눈다

모델이 좋은지는 처음 보는 데이터에서 얼마나 맞히느냐로 판단한다. 배울 때 본 데이터로 채점하면 외운 모델이 이긴다. 그래서 데이터를 세 덩어리로 나눈다.

학습 세트(train)로 모델의 숫자를 정한다. 검증 세트(validation)로 여러 후보(트리 깊이, 규제 세기 같은 하이퍼파라미터, 아예 다른 알고리즘) 중 하나를 고른다. 테스트 세트(test)는 다 고른 뒤 마지막에 한 번 연다. 검증 세트를 보고 여러 번 고르다 보면 검증 세트에도 조금씩 맞춰지기 때문에, 한 번도 고르는 데 쓰지 않은 데이터가 하나 더 필요하다.

```python
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split

X, y = make_moons(n_samples=600, noise=0.35, random_state=0)  # 두 반달이 겹친 2차원 점들
X_tr, X_tmp, y_tr, y_tmp = train_test_split(X, y, test_size=0.4, random_state=0, stratify=y)
X_val, X_te, y_val, y_te = train_test_split(X_tmp, y_tmp, test_size=0.5, random_state=0, stratify=y_tmp)
print(len(X_tr), len(X_val), len(X_te))
```

```text
360 120 120
```

`stratify=y`는 세 덩어리에 0과 1의 비율을 똑같이 맞춘다. 사기 거래처럼 한쪽이 드문 데이터에서 이걸 빼면, 검증 세트에 사기가 거의 없는 일이 생긴다.

데이터가 적으면 검증 세트 120행이 운에 좌우된다. 그럴 때는 k-겹 교차 검증을 쓴다. 학습 데이터를 k조각으로 나눠 k번 돌아가며 한 조각을 검증에 쓰고 평균을 낸다. 교차 검증으로 점수를 얼마나 믿을 수 있는지는 [모델 평가 글](/posts/ml-model-evaluation)에서 계산한다.

## 외운 모델과 이해한 모델

결정 트리는 "x가 0.3보다 큰가" 같은 질문을 이어 붙여 분류하는 모델이다. 깊이를 제한하지 않으면 학습 데이터의 점 하나하나를 맞힐 때까지 질문을 늘린다. 깊이를 바꿔 가며 학습 세트와 검증 세트 점수를 나란히 찍어 봤다.

```python
from sklearn.tree import DecisionTreeClassifier

for d in [1, 2, 3, 4, 6, 8, 12, None]:
    m = DecisionTreeClassifier(max_depth=d, random_state=0).fit(X_tr, y_tr)
    print(f"depth={str(d):>4}  train={m.score(X_tr, y_tr):.3f}  val={m.score(X_val, y_val):.3f}  leaves={m.get_n_leaves()}")
```

```text
depth=   2  train=0.894  val=0.867  leaves=4
depth=   3  train=0.894  val=0.867  leaves=6
depth=   4  train=0.894  val=0.867  leaves=10

```

읽는 법은 두 줄의 차이를 보는 것이다. 깊이 1은 둘 다 낮다. 질문 하나로는 반달 모양을 못 나눈다. 이게 과소적합(underfitting)이다. 깊이 2~4에서 검증 점수가 0.867로 가장 높고 학습 점수와 차이도 작다. 깊이 6부터 학습 점수는 계속 오르는데 검증 점수는 그대로이거나 떨어진다. 깊이 12에서는 학습 데이터를 100% 맞히지만 처음 보는 데이터는 오히려 더 못 맞힌다. 잎이 47개라는 건 학습 데이터의 잡음(겹친 영역의 점들)까지 따로 칸을 만들어 외웠다는 뜻이다. 이게 과적합(overfitting)이다.

그래서 과적합을 알아채는 가장 단순한 신호는 "학습 점수는 오르는데 검증 점수는 멈추거나 내려간다"이다. 학습 점수만 보고 있으면 절대 안 보인다. 검증 점수로 깊이 4를 고르고 테스트 세트를 한 번 열면 0.842가 나온다. 검증 점수(0.867)보다 조금 낮은 건 자연스럽다. 검증 세트로 골랐기 때문에 검증 점수는 살짝 낙관적이다.

## 편향과 분산은 서로 당긴다

위 표를 다른 말로 하면 편향-분산 트레이드오프다.

편향(bias)은 모델이 너무 단순해서 생기는 오차다. 깊이 1 트리는 데이터를 아무리 많이 줘도 반달 모양을 못 그린다. 학습 점수부터 낮다. 분산(variance)은 모델이 너무 예민해서 생기는 오차다. 깊이 12 트리는 학습 데이터를 조금만 바꿔도 전혀 다른 트리가 된다. 학습 점수는 높고 검증 점수가 낮다.

복잡도를 올리면 편향은 줄고 분산은 는다. 그 사이 어딘가에 검증 오차가 가장 작은 지점이 있고, 검증 세트는 그 지점을 찾는 도구다. 현장에서 쓰는 처방도 이 둘로 갈린다.

- 학습 점수부터 낮다(편향이 크다): 특징을 더 넣는다, 더 표현력 있는 모델을 쓴다, 규제를 약하게 한다.
- 학습 점수는 높은데 검증 점수가 낮다(분산이 크다): 데이터를 더 모은다, 모델을 단순하게 한다, 규제를 세게 한다, 특징을 줄인다.

데이터를 더 모으는 처방은 분산이 클 때만 듣는다. 학습 점수부터 낮은 모델에 데이터를 열 배 줘도 그대로다. 데이터 수집에 돈을 쓰기 전에 학습 점수와 검증 점수를 먼저 나란히 본다.

## 가중치에 벌금을 매긴다

규제(regularization)는 분산을 줄이는 대표 수단이다. 모델이 데이터를 맞히는 것뿐 아니라 가중치가 커지는 것에도 벌점을 줘서, 가능하면 단순한 함수를 고르게 한다.

사인 곡선에 잡음을 섞은 점 15개에 다항식을 맞춰 봤다. 15차 다항식은 점 15개를 거의 다 지나갈 수 있다. 그게 문제다.

```python
from sklearn.preprocessing import PolynomialFeatures, StandardScaler
from sklearn.linear_model import LinearRegression, Ridge
from sklearn.pipeline import make_pipeline

f = lambda x: np.sin(2 * np.pi * x)
x_tr = rng.uniform(0, 1, 15); y_tr = f(x_tr) + rng.normal(0, 0.25, 15)     # 학습 15점
x_va = rng.uniform(0, 1, 200); y_va = f(x_va) + rng.normal(0, 0.25, 200)  # 검증 200점

models = {
    "deg1 linear":         make_pipeline(PolynomialFeatures(1), LinearRegression()),
    "deg4 linear":         make_pipeline(PolynomialFeatures(4),  StandardScaler(), LinearRegression()),
    "deg15 linear":        make_pipeline(PolynomialFeatures(15), StandardScaler(), LinearRegression()),
    "deg15 ridge a=0.001": make_pipeline(PolynomialFeatures(15), StandardScaler(), Ridge(alpha=0.001)),
    "deg15 ridge a=0.1":   make_pipeline(PolynomialFeatures(15), StandardScaler(), Ridge(alpha=0.1)),
    "deg15 ridge a=10":    make_pipeline(PolynomialFeatures(15), StandardScaler(), Ridge(alpha=10)),
}
# 각각 fit한 뒤 학습·검증 MSE와 가장 큰 가중치 절댓값을 찍는다
```

```text
deg1 linear          train MSE=0.157  val MSE=0.406  max|w|=1.1
deg4 linear          train MSE=0.025  val MSE=0.085  max|w|=6.0
deg15 linear         train MSE=0.017  val MSE=0.262  max|w|=2064.7
deg15 ridge a=0.001  train MSE=0.023  val MSE=0.121  max|w|=3.1
deg15 ridge a=0.1    train MSE=0.050  val MSE=0.189  max|w|=0.8
deg15 ridge a=10     train MSE=0.111  val MSE=0.349  max|w|=0.1
```

규제 없는 15차 다항식은 학습 오차가 가장 작은데 검증 오차는 4차의 세 배다. 가장 큰 가중치가 2,064다. 점 사이를 지나려고 곡선이 위아래로 크게 출렁인다는 뜻이다. 같은 15차에 아주 약한 릿지(alpha=0.001)를 걸면 가중치가 3 정도로 줄고 검증 오차가 절반이 된다. 그런데 alpha를 10까지 올리면 곡선이 거의 펴져서 다시 과소적합이 된다. 규제 세기도 하이퍼파라미터라 검증 세트로 고른다.

릿지(L2)는 가중치 제곱의 합에 벌점을 줘서 모든 가중치를 고르게 줄인다. 라소(L1)는 절댓값의 합에 벌점을 줘서 쓸모없는 특징의 가중치를 정확히 0으로 만든다. 특징이 많고 그중 일부만 쓸모 있다고 볼 때 라소를 쓴다. 트리 모델은 깊이 제한, 잎의 최소 샘플 수가 같은 역할을 하고, 신경망은 드롭아웃과 조기 종료(검증 오차가 오르기 시작하면 학습을 멈춘다)를 쓴다.

위 코드에서 `StandardScaler`를 다항식 뒤에 둔 이유도 있다. 규제는 가중치 크기에 벌점을 주는데, 특징마다 단위가 다르면(x와 x의 15제곱) 벌점이 불공평하게 걸린다. 특징을 평균 0, 표준편차 1로 맞춘 뒤에 걸어야 한다.

## 경사 하강: 기울기를 따라 조금씩 내려간다

모델의 숫자를 "정한다"는 건 구체적으로 무엇일까. 대부분의 모델은 오차 함수(손실)를 정의하고, 그 값이 가장 작아지는 가중치를 찾는다. 선형 회귀라면 손실은 예측과 정답 차이의 제곱 평균(MSE)이다.

가장 작은 곳을 찾는 일반적인 방법이 경사 하강(gradient descent)이다. 짙은 안개 속 산에서 골짜기를 찾는다고 생각하면 된다. 멀리는 안 보이지만 발밑의 기울기는 안다. 내려가는 방향으로 한 걸음 옮기고, 다시 기울기를 재고, 또 옮긴다. 기울기는 각 가중치를 조금 늘렸을 때 손실이 얼마나 변하는지(편미분)이고, 한 걸음의 크기가 학습률(learning rate)이다.

## 개발자가 챙길 통계 몇 가지

머신러닝을 쓰는 데 필요한 수학은 생각보다 좁다. 이 글을 읽는 데 필요한 건 이 정도다.

평균과 분산. 분산은 값들이 평균에서 얼마나 퍼져 있는지(차이 제곱의 평균), 표준편차는 그 제곱근이다. 표준화는 `(x - 평균) / 표준편차`로 특징마다 단위를 없애는 일이고, 그 평균과 표준편차는 학습 세트에서만 계산한다. 이게 왜 중요한지는 바로 다음 절에서 본다.

확률로 나오는 출력. 분류 모델은 대개 "떠날 확률 0.73" 같은 점수를 내고, 문턱값(기본 0.5)을 넘으면 1로 본다. 문턱값을 어디에 두느냐에 따라 놓치는 고객과 괜히 쿠폰을 받는 고객의 수가 바뀐다. 이 점수가 정말 확률처럼 믿을 만한지(보정)는 [모델 평가 글](/posts/ml-model-evaluation)의 몫이다.

기준선. 아무것도 배우지 않은 모델이 얼마를 맞히는지부터 계산한다. 이탈률이 25%인 데이터에서 전부 "안 떠난다"고 답하면 정확도 75%다. 모델이 76%면 거의 아무것도 못 배운 것이다. 처음 장면의 73.6%가 충격적인 이유가 여기 있다.

상관과 인과. 특징이 라벨과 강하게 같이 움직인다고 원인은 아니다. 다음 절의 누수가 바로 "결과가 남긴 흔적"을 원인처럼 배운 경우다.

## 누수 1: 결과가 남긴 흔적을 특징으로 썼다

이제 처음 장면을 재현한다. 고객 5,000명에게 가입 개월 수, 최근 30일 문의 수, 사용 일수를 주고, 이 셋이 약하게 이탈에 영향을 주게 만들었다. 그리고 데이터 팀이 하나를 더 넣었다. "마지막 로그인 후 경과 일수"다. 이 값은 데이터를 뽑은 날 기준으로 계산됐다. 데이터를 뽑은 건 이탈 여부를 확인한 뒤, 즉 다음 달 말이었다.

```python
# 데이터를 뽑은 날 기준으로 계산된 '마지막 로그인 후 경과 일수'
# 이미 떠난 고객은 당연히 오래됐다 (20~90일), 남은 고객은 며칠
days_since_login = np.where(churn == 1, rng.uniform(20, 90, n), rng.exponential(3, n))
X = np.column_stack([tenure, tickets, usage, days_since_login])
```

```text
churn rate 0.253
offline acc 0.997 recall 0.992
importances {'tenure': 0.0, 'tickets': 0.0, 'usage': 0.001, 'days_since_login': 0.999}
```

시험 세트 정확도 99.7%. 특징 중요도를 보면 모델이 쓴 건 사실상 경과 일수 하나다. 이건 이탈의 원인이 아니라 결과다. 떠났으니까 로그인을 안 한 것이다. 예측해야 하는 시점(이번 달 말, 아직 아무도 안 떠났을 때)에는 모든 고객의 경과 일수가 며칠이다. 그 데이터로 바꿔 넣으면 이렇게 된다.

```text
prod acc 0.736 recall 0.0 pred churn rate 0.001
baseline all-0 offline 0.747 prod 0.737
```

떠날 고객을 하나도 못 찾고, 전부 "안 떠난다"고 하는 기준선(73.7%)보다도 낮다. 이게 타깃 누수(target leakage)다. 라벨이 정해진 뒤에야 알 수 있는 정보가 특징에 섞인 것이다. 누수를 뺀 세 특징으로만 학습하면 결과는 이렇다.

```text
no-leak offline acc 0.765 recall 0.202
no-leak prod acc 0.758 recall 0.201
```

점수는 초라하다. 기준선보다 2%p 남짓 높고 떠날 고객의 20%를 찾는다. 대신 오프라인 숫자와 배포 숫자가 같다. 믿을 수 있는 76%가 믿을 수 없는 99.7%보다 낫다. 이 점수를 어떻게 끌어올리고, 정확도 대신 무엇을 봐야 하는지는 [모델 평가 글](/posts/ml-model-evaluation)로 넘긴다.

현장에서 타깃 누수는 이런 모양으로 온다. 환불 예측에 "환불 처리 담당자" 열, 대출 연체 예측에 "독촉 문자 발송 횟수", 질병 예측에 "처방된 약" 열이 들어 있다. 모두 결과가 정해진 뒤에 채워지는 값이다. 막는 방법은 특징마다 "이 값은 예측 시점에 이미 알 수 있나"를 묻는 것이다. 테이블에 기록된 시각(`created_at`, `updated_at`)과 예측 시점을 비교해서, 예측 시점 이후에 바뀐 값은 쓰지 않는다. 그리고 너무 좋은 점수는 축하하기 전에 의심한다. 특징 중요도에서 하나가 압도적이면 그 열부터 본다.

## 누수 2: 나누기 전에 전처리했다

두 번째 누수는 더 조용하다. 코드 순서 하나 때문에 생긴다.

특징이 5,000개이고 샘플이 200개인 데이터가 있다. 유전자 발현 데이터나 로그에서 뽑은 수천 개의 지표가 이런 모양이다. 여기서는 일부러 모든 특징과 라벨을 완전한 난수로 만들었다. 맞힐 수 있는 게 아무것도 없으니 정답은 50% 근처여야 한다. 특징이 너무 많으니 라벨과 가장 관련 있어 보이는 20개를 먼저 고르고, 교차 검증으로 점수를 냈다.

```python
X = rng.normal(size=(200, 5000)); y = rng.integers(0, 2, size=200)  # 전부 잡음

# 잘못된 순서: 전체 데이터로 특징을 고른 뒤 교차 검증
sel = SelectKBest(f_classif, k=20).fit(X, y)
print("leaky CV acc", cross_val_score(LogisticRegression(max_iter=1000), sel.transform(X), y, cv=5).mean())

# 올바른 순서: 고르는 일까지 파이프라인에 넣어 접힘마다 학습 데이터로만 고른다
pipe = make_pipeline(SelectKBest(f_classif, k=20), LogisticRegression(max_iter=1000))
print("pipeline CV acc", cross_val_score(pipe, X, y, cv=5).mean())
```

```text
leaky CV acc 0.845
pipeline CV acc 0.545
```

순수한 잡음에서 84.5%가 나왔다. 5,000개 중에는 우연히 이 200개의 라벨과 같이 움직이는 특징이 있기 마련이고, 전체 데이터로 고르면 검증 조각의 라벨까지 보고 그 우연을 골라 버린다. 검증 조각은 이미 한 번 엿본 시험지가 된다. 고르는 일을 파이프라인 안에 넣으면 교차 검증이 접힘마다 학습 조각으로만 고르고, 점수는 정직하게 동전 던지기 근처(54.5%)로 돌아온다.

같은 실수가 표준화, 결측값 채우기(전체 평균으로 채우기), 범주 인코딩(타깃 평균 인코딩), 오버샘플링(SMOTE를 나누기 전에 돌리기)에서도 난다. 효과의 크기는 경우마다 다르지만, 원칙은 하나다. 데이터에서 무언가를 계산하는 모든 단계는 학습 세트로만 `fit`하고, 검증·테스트 세트에는 `transform`만 한다. scikit-learn의 `Pipeline`이 이걸 강제해 주니, 전처리는 처음부터 파이프라인으로 쓰는 습관을 들인다. 운영에서도 그 파이프라인 객체를 통째로 저장해 쓰면, 학습 때와 예측 때 전처리가 달라지는 사고(학습 때는 표준화했는데 서빙 코드에서 빠뜨린 경우)도 같이 막힌다.

## 누수 3: 시간을 섞어 나눴다

판매량처럼 시간에 따라 쌓이는 데이터를 무작위로 섞어 나누면, 모델은 화요일과 목요일을 보고 수요일을 맞히게 된다. 실제로 해야 하는 일은 어제까지를 보고 내일을 맞히는 것이다.

2년치 일별 판매량을 만들었다. 조금씩 늘어나는 추세, 1년 주기의 계절, 주말 효과, 잡음(표준편차 6)이 있다. 특징은 날짜 번호, 요일, 7일 전 판매량이다. 같은 랜덤 포레스트를 두 가지 방식으로 검증했다.

```python
m = RandomForestRegressor(n_estimators=200, random_state=0)
rand = -cross_val_score(m, X, y, cv=KFold(5, shuffle=True, random_state=0), scoring="neg_mean_absolute_error")
ts = -cross_val_score(m, X, y, cv=TimeSeriesSplit(5), scoring="neg_mean_absolute_error")
```

```text
random KFold MAE [5.69 5.2  6.03 5.94 5.46] 5.66
TimeSeriesSplit MAE [ 8.84 11.55 17.02  6.83 10.56] 10.96
```

무작위로 섞으면 평균 절대 오차가 5.66이다. 잡음의 표준편차가 6이라서 사실상 잡음 말고는 다 맞힌다는 뜻이다. 과거로 학습하고 미래로 검증하는 `TimeSeriesSplit`에서는 10.96으로 두 배가 된다. 랜덤 포레스트는 본 적 없는 범위의 날짜 번호를 외삽하지 못해서, 추세가 이어지는 미래에서 계속 낮게 예측한다. 무작위 분할에서는 앞뒤 날짜가 다 학습에 있으니 이 약점이 가려졌다. 접힘마다 오차가 6.83에서 17.02까지 크게 흔들리는 것도 무작위 분할에서는 안 보이던 정보다. 계절에 따라 모델이 잘 맞는 시기와 못 맞는 시기가 있다는 뜻이다.

시간이 들어간 데이터는 항상 시간 순으로 나눈다. 마지막 몇 주를 테스트로 떼고, 검증도 그 앞 구간으로 한다. 특징을 만들 때도 같은 원칙이다. "최근 7일 평균"을 만들면서 오늘 값을 포함하거나, 미래 값이 들어가는 중앙 이동 평균을 쓰면 누수다. 이탈 예측 같은 문제도 사실은 시간 문제다. 1월 데이터로 학습하고 2월 데이터로 검증해야 배포 상황과 같다.

## 같은 사람이 양쪽에 있으면

시간 말고도 숨은 묶음이 있다. 고객 한 명의 주문 여러 건, 환자 한 명의 검사 사진 여러 장, 같은 사용자의 세션 여러 개. 이걸 행 단위로 섞어 나누면 같은 사람이 학습과 검증 양쪽에 들어가고, 모델은 사람을 알아보는 법을 배운다. 새 고객에게는 쓸 수 없는 능력이다. 이럴 때는 사람 단위로 나누는 `GroupKFold`나 `GroupShuffleSplit`을 쓴다.

```python
from sklearn.model_selection import GroupKFold

# customer_id가 같은 행은 항상 같은 쪽에 들어간다
scores = cross_val_score(pipe, X, y, cv=GroupKFold(n_splits=5), groups=customer_id)
```

중복 행도 같은 문제를 만든다. 크롤링한 데이터, 여러 번 적재된 로그에는 완전히 같은 행이 섞여 있기 쉽다. 나누기 전에 중복을 지운다. LLM 평가 세트를 만들 때도 같은 원리가 적용된다. 학습(또는 프롬프트 예시)에 쓴 문제가 평가 세트에 섞이면 점수가 부풀려진다. 이 이야기는 [LLM 평가 글](/posts/llm-evals)에도 나온다.

## 모델을 넘기기 전에 확인하는 것

개발자가 데이터 팀의 모델을 서비스에 붙이거나, 직접 간단한 모델을 만들 때 이 질문들을 먼저 해 본다.

1. 기준선이 얼마인가. 다수 클래스만 답하는 모델, "어제 값을 그대로 내는" 모델보다 얼마나 나은가.
2. 학습 점수와 검증 점수가 얼마나 차이 나나. 차이가 크면 과적합, 둘 다 낮으면 과소적합이다.
3. 특징 중요도에서 하나가 압도적이지 않은가. 그렇다면 그 특징이 예측 시점에 정말 있는 값인지 확인한다.
4. 데이터를 어떻게 나눴나. 시간 순인가, 사람 단위인가, 중복은 지웠나.
5. 전처리가 파이프라인 안에 있나. 학습 때와 서빙 때 같은 객체를 쓰나.
6. 테스트 세트를 몇 번 열었나. 여러 번 열어 보고 고쳤다면 그건 이미 검증 세트다.

이 중 하나라도 대답이 막히면, 오프라인 점수는 배포 첫날 무너질 수 있다. 배포한 뒤 실제로 성능이 유지되는지는 오프라인 지표가 아니라 [A/B 테스트](/posts/ab-testing) 같은 온라인 실험으로 확인한다.

## 점수보다 나누는 법이 먼저다

머신러닝 모델은 주어진 데이터에서 라벨을 맞히는 데 쓸모 있는 것은 무엇이든 배운다. 그게 원인이든, 결과가 남긴 흔적이든, 시험지를 엿본 우연이든 가리지 않는다. 그래서 모델링보다 먼저 정할 것은 데이터를 어떻게 나누고 무엇을 특징으로 허락하느냐다. 학습 세트로 배우고, 검증 세트로 고르고, 테스트 세트는 한 번만 연다. 예측 시점에 알 수 없는 값은 넣지 않고, 전처리는 파이프라인 안에서 학습 세트로만 맞추고, 시간과 사람은 섞지 않는다. 그다음에야 과적합과 규제, 어떤 지표로 잴지를 고민할 차례다.

## 면접에서 나올 만한 질문

### 학습, 검증, 테스트 세트를 왜 셋으로 나누나요?

학습 세트로 가중치를 정하고, 검증 세트로 하이퍼파라미터나 모델을 고르고, 테스트 세트로 최종 성능을 한 번 잰다. 검증 세트로 여러 번 고르다 보면 검증 세트에도 맞춰져서 점수가 낙관적이 되기 때문에, 고르는 데 한 번도 쓰지 않은 데이터가 따로 있어야 처음 보는 데이터에서의 성능을 정직하게 말할 수 있다. 데이터가 적으면 검증을 k-겹 교차 검증으로 대신한다.

### 과적합은 어떻게 알아채고 어떻게 줄이나요?

학습 점수는 계속 오르는데 검증 점수가 멈추거나 떨어지면 과적합이다. 트리 깊이 실험에서 깊이 12는 학습 100%, 검증 85%로 깊이 4보다 검증이 낮았다. 줄이는 방법은 데이터를 더 모으기, 모델을 단순하게 하기, 규제(릿지·라소, 트리 깊이 제한, 드롭아웃, 조기 종료), 특징 줄이기다. 반대로 학습 점수부터 낮으면 과소적합이라 처방이 반대다.

### 편향-분산 트레이드오프를 설명해 주세요.

편향은 모델이 너무 단순해서 생기는 오차, 분산은 학습 데이터에 너무 예민해서 생기는 오차다. 복잡도를 올리면 편향은 줄고 분산은 늘어서, 검증 오차가 가장 작은 중간 지점이 있다. 실무에서는 학습·검증 점수를 나란히 보고, 둘 다 낮으면 편향을, 차이가 크면 분산을 줄이는 쪽으로 처방한다. 데이터를 더 모으는 것은 분산이 클 때만 효과가 있다.

### 데이터 누수의 예를 들어 주세요.

결과가 정해진 뒤에야 알 수 있는 값을 특징으로 쓰는 타깃 누수가 대표적이다. 이탈 예측에 데이터 추출일 기준 "마지막 로그인 후 경과 일수"를 넣었더니 오프라인 정확도 99.7%가 배포 후 73.6%로 떨어졌다. 그 밖에 나누기 전에 전체 데이터로 표준화나 특징 선택을 하는 것, 시계열을 무작위로 섞어 나누는 것, 같은 고객의 행이 학습과 검증 양쪽에 들어가는 것도 누수다. 순수한 잡음에서도 분할 전 특징 선택만으로 84.5%가 나왔다.

### 시계열 데이터에서 무작위 분할이 왜 위험한가요?

모델이 앞뒤 날짜를 보고 가운데를 맞히는 보간 문제로 바뀌어서, 과거만 보고 미래를 맞혀야 하는 실제 상황보다 훨씬 쉬워지기 때문이다. 실험에서 같은 모델의 MAE가 무작위 분할 5.66, 시간 순 분할 10.96으로 두 배 차이 났다. 추세를 외삽하지 못하는 약점도 무작위 분할에서는 가려진다. 그래서 `TimeSeriesSplit`이나 마지막 구간을 떼는 방식으로 나누고, 이동 평균 같은 특징도 미래 값이 섞이지 않게 만든다.

### 전처리를 왜 파이프라인 안에 넣어야 하나요?

표준화의 평균, 결측값을 채울 값, 고를 특징처럼 데이터에서 계산하는 모든 것은 학습 세트로만 계산해야 하는데, 파이프라인이 교차 검증의 접힘마다 이걸 자동으로 지켜 준다. 밖에서 전체 데이터로 `fit`하면 검증 데이터 정보가 새어 점수가 부풀려진다. 운영에서도 같은 파이프라인 객체를 저장해 쓰면 학습 때와 서빙 때 전처리가 달라지는 사고를 막는다.

### 경사 하강에서 학습률이 너무 크면 어떻게 되나요?

골짜기 바닥을 건너뛰어 반대편으로 튀고, 매번 더 크게 튀면서 손실이 발산한다. 점 네 개에 직선을 맞추는 실험에서 학습률 0.05는 2,000걸음에 정답에 닿았지만 0.2는 10걸음 만에 가중치가 수천으로 커졌다. 너무 작으면 수렴이 느리다. 그래서 학습률을 검증 손실로 고르고, 특징을 표준화해 골짜기 모양을 고르게 만든다.
