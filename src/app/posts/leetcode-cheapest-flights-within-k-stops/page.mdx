최단 경로 문제에 "중간에 최대 k번만 들를 수 있다"는 조건이 하나 붙은 문제다. 이 한 줄 때문에 다익스트라를 그대로 쓰면 틀리고, 평소엔 느려서 잘 안 쓰던 벨만-포드가 가장 깔끔한 답이 된다.

[LeetCode 787. Cheapest Flights Within K Stops](https://leetcode.com/problems/cheapest-flights-within-k-stops/)는 Medium이다. 이 글은 길을 전부 따라가는 DFS, 층별 BFS, 바퀴 수를 k + 1로 묶은 벨만-포드, 비행 횟수까지 상태로 들고 다니는 다익스트라, 메모이제이션 DP까지 다섯 가지를 본다. 제한 없는 최단 경로는 [Network Delay Time](/posts/leetcode-network-delay-time)에서 여섯 가지로 풀었고, 알고리즘 일반론은 [최단 경로 알고리즘 글](/posts/shortest-path-algorithms)에 있다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 갈아타기 횟수가 정해진 가장 싼 표

도시는 0부터 n - 1까지다. `flights[i] = [from, to, price]`는 from에서 to로 가는 편도 표다. src에서 dst까지 가는 가장 싼 값을 구하되, 중간에 들르는 도시가 k개 이하여야 한다. 그런 길이 없으면 -1이다.

"중간에 k개 이하"는 "비행기를 k + 1번 이하로 탄다"와 같다. 들르는 도시가 0개면 직항 한 번, 1개면 두 번이다. 이 변환을 먼저 해 두면 코드가 헷갈리지 않는다.

풀이 선택에 영향을 주는 조건은 이렇다.

- n은 100 이하, 표는 n(n - 1)/2 = 4,950장 이하다. k는 n보다 작다.
- 값은 1 이상 10⁴ 이하다. 음수가 없으니 다익스트라를 쓸 여지는 있다. 비행이 최대 100번이라 합은 100만을 넘지 않아 `int`로 충분하다.
- 같은 (from, to) 표는 두 번 나오지 않는다.

이 글에서 쓸 예시는 도시 5개, 표 6장이다. 0에서 4로 간다.

```text
0 → 1 : 100     1 → 2 : 100     2 → 4 : 100
0 → 3 : 500     3 → 4 : 100     0 → 4 : 900
```

## 비행 횟수를 세며 길을 전부 따라가는 DFS

처음 떠오르는 방법은 출발에서 표를 하나씩 타 보며 모든 길을 걷는 것이다. 남은 비행 횟수를 들고 다니다 0이 되면 멈추고, 지금까지 찾은 답보다 비싸지면 돌아온다.

```js
function findCheapestPrice(n, flights, src, dst, k) {
  const graph = Array.from({ length: n }, () => []);
  for (const [u, v, w] of flights) graph[u].push([v, w]);
  let best = Infinity;
  const go = (u, cost, flightsLeft) => {
    if (cost >= best) return;               // 이미 더 싼 길을 안다
    if (u === dst) { best = cost; return; }
    if (flightsLeft === 0) return;          // 더 탈 수 없다
    for (const [v, w] of graph[u]) go(v, cost + w, flightsLeft - 1);
  };
  go(src, 0, k + 1);                        // 비행은 k + 1번까지
  return best === Infinity ? -1 : best;
}
```

방문 표시가 없다. 같은 도시를 다른 비용, 다른 남은 횟수로 다시 지날 수 있어야 하기 때문이다. 대신 남은 횟수가 줄어드니 끝없이 돌지는 않는다.

비용으로 가지치기를 하니 답이 있는 그래프에서는 생각보다 빠르다. 도시 100개, 표 4,950장 무작위 그래프에서 k = 5로 돌려 보니 표를 비싼 순서로 보게 해도 호출이 24만 번, 11ms였다. 문제는 목적지에 닿을 수 없을 때다. 가지치기할 답이 없으니 k + 1번 안에 걸을 수 있는 길을 전부 걷는다. 목적지로 들어오는 표를 모두 지운 같은 크기 그래프에서 세어 보면 이렇다.

```text
k = 2   호출 119,775번      34ms
k = 3   호출 5,917,873번    96ms
k = 4   호출 292,433,058번  3,496ms
```

k가 하나 늘 때마다 호출이 50배쯤 는다. 도시마다 나가는 표가 50장쯤이라 그렇다. k는 99까지 올 수 있으니 이 풀이는 안 된다.

같은 도시에 같은 남은 횟수로 다시 오면 그 뒤의 일은 똑같다. 비용만 다를 뿐이다. 그렇다면 "도시와 비행 횟수"마다 가장 싼 비용 하나만 기억하면 된다. 다음 풀이들은 모두 이 생각에서 나온다.

## 한 번 탈 때마다 한 층씩 넓히는 BFS

출발에서 비행 한 번으로 갈 수 있는 곳, 두 번으로 갈 수 있는 곳을 층으로 나눠 넓혀 간다. 층은 많아야 k + 1개다. 층마다 "이번에 값이 줄어든 도시"만 다음 층으로 넘기고, 이미 더 싸게 닿은 도시는 넘기지 않는다.

```js
function findCheapestPrice(n, flights, src, dst, k) {
  const graph = Array.from({ length: n }, () => []);
  for (const [u, v, w] of flights) graph[u].push([v, w]);
  const dist = new Array(n).fill(Infinity);
  dist[src] = 0;
  let level = [[src, 0]]; // [도시, 이 층에서의 비용]
  for (let step = 0; step <= k && level.length > 0; step++) {
    const next = [];
    for (const [u, cost] of level) {
      for (const [v, w] of graph[u]) {
        // 더 적은 비행으로 이미 이 값 이하로 닿았다면 넘길 필요가 없다
        if (cost + w < dist[v]) {
          dist[v] = cost + w;
          next.push([v, cost + w]);
        }
      }
    }
    level = next;
  }
  return dist[dst] === Infinity ? -1 : dist[dst];
}
```

여기서 `dist`를 모든 층이 함께 써도 되는 이유가 있다. 층은 비행 횟수 순으로 처리된다. 어떤 도시에 i번 비행으로 c원에 닿았다면, 그보다 많은 비행으로 c원 이상에 닿는 길은 쓸모가 없다. 비행도 많고 값도 비싸니 어느 쪽으로도 나을 게 없다. 그래서 `cost + w < dist[v]`일 때만 다음 층으로 넘긴다.

다음 층으로 넘기는 값은 `dist[v]`가 아니라 `cost + w`다. 층 안에서 같은 도시가 여러 번 갱신되면 큐에 여러 개 들어가는데, 각각 그때의 비용을 들고 간다. 더 싼 값이 나중에 들어와도 앞의 것은 그대로 남아 헛일을 조금 하지만 답은 맞다.

층마다 표를 많아야 한 번씩 보니 시간은 O(k · E)다. 무작위 100도시 그래프에서 k = 5일 때 8.5ms, k = 99일 때 1.6ms였다. k가 커도 값이 더 줄지 않으면 다음 층이 비어 일찍 끝나서 오히려 빨랐다.

## 바퀴 수를 k + 1로 묶은 벨만-포드

BFS 풀이를 더 단순하게 하면 벨만-포드가 된다. 벨만-포드는 간선 전체를 한 바퀴 훑을 때마다 "간선을 하나 더 쓴 최단 거리"를 구한다. 원래는 n - 1바퀴를 돌아 모든 최단 거리를 확정하지만, 여기서는 비행을 k + 1번까지만 허락하니 k + 1바퀴에서 멈추면 된다.

다만 한 가지를 꼭 지켜야 한다. 한 바퀴 안에서는 지난 바퀴의 값만 읽는다.

```js
function findCheapestPrice(n, flights, src, dst, k) {
  let dist = new Array(n).fill(Infinity);
  dist[src] = 0;
  // 비행을 최대 k + 1번 탄다. 바퀴마다 비행을 하나씩 더 허락한다
  for (let round = 0; round <= k; round++) {
    const next = dist.slice(); // 이번 바퀴는 지난 바퀴 값만 읽는다
    for (const [u, v, w] of flights) {
      if (dist[u] !== Infinity && dist[u] + w < next[v]) next[v] = dist[u] + w;
    }
    dist = next;
  }
  return dist[dst] === Infinity ? -1 : dist[dst];
}
```

`dist[u]`는 지난 바퀴 값, 즉 비행을 `round`번 이하로 탄 값이고, `next[v]`에 쓰는 건 비행을 `round + 1`번 이하로 탄 값이다. 읽는 배열과 쓰는 배열을 나눴기 때문에 한 바퀴에 비행이 딱 하나씩만 늘어난다.

### Python과 Java로 쓰면

Python은 `float("inf")`에 숫자를 더해도 `inf`라 `dist[u]`가 무한대인지 따로 검사하지 않아도 된다. 복사는 `dist[:]`로 한다.

```python
from typing import List


def find_cheapest_price(n: int, flights: List[List[int]], src: int, dst: int, k: int) -> int:
    INF = float("inf")
    dist = [INF] * n
    dist[src] = 0
    for _ in range(k + 1):  # 비행을 최대 k + 1번 탄다
        nxt = dist[:]  # 지난 바퀴 값을 복사해 두고 그것만 읽는다
        for u, v, w in flights:
            if dist[u] + w < nxt[v]:
                nxt[v] = dist[u] + w
        dist = nxt
    return -1 if dist[dst] == INF else dist[dst]


ex = [[0, 1, 100], [1, 2, 100], [2, 4, 100], [0, 3, 500], [3, 4, 100], [0, 4, 900]]
print([find_cheapest_price(5, ex, 0, 4, k) for k in range(4)])
print(find_cheapest_price(4, [[0, 1, 100], [1, 2, 100], [0, 2, 500], [2, 3, 100]], 0, 3, 1))
print(find_cheapest_price(3, [[0, 1, 100]], 0, 2, 1))
```

```text
[900, 600, 300, 300]
600
-1
```

Java는 `Integer.MAX_VALUE`를 무한대로 쓰면 `dist[u] + w`가 음수로 넘쳐 엉뚱하게 "더 싸다"가 된다. 그래서 `dist[u] != INF`를 먼저 검사한다. 무한대를 `1e9` 같은 큰 값으로 두는 방법도 있다. 최대 합이 100만이라 넘치지 않는다. 배열 복사는 `clone()`이다.

```java
import java.util.*;

class Solution {
    public int findCheapestPrice(int n, int[][] flights, int src, int dst, int k) {
        final int INF = Integer.MAX_VALUE;
        int[] dist = new int[n];
        Arrays.fill(dist, INF);
        dist[src] = 0;
        for (int round = 0; round <= k; round++) {
            int[] next = dist.clone(); // 지난 바퀴 값만 읽는다
            for (int[] f : flights) {
                int u = f[0], v = f[1], w = f[2];
                // INF에 더하면 음수로 넘치니 먼저 걸러 낸다
                if (dist[u] != INF && dist[u] + w < next[v]) next[v] = dist[u] + w;
            }
            dist = next;
        }
        return dist[dst] == INF ? -1 : dist[dst];
    }
}
```

```text
900 600 300 300
600
-1
```

## 비행 횟수까지 들고 다니는 다익스트라

다익스트라를 쓰고 싶다면 상태를 "도시"에서 "도시와 지금까지 탄 비행 수"로 넓혀야 한다. 힙에 `[비용, 도시, 탄 횟수]`를 넣고 싼 것부터 꺼낸다. 목적지를 처음 꺼내는 순간이 답이다. 힙은 싼 순서로 꺼내니, 처음 꺼낸 목적지 상태가 횟수 제한을 지키는 가장 싼 길이다.

문제는 같은 도시를 여러 번 꺼내도 되느냐다. 비용이 더 비싸도 비행을 덜 탔다면 그 뒤로 더 멀리 갈 수 있으니 버리면 안 된다. 그래서 "이 도시를 꺼냈을 때 탄 가장 적은 횟수"를 기억해 두고, 그보다 적은 횟수로 다시 꺼낼 때만 다시 펼친다. 나중에 꺼낸 것은 비용이 같거나 비싸니, 횟수까지 같거나 많으면 나을 게 없다.

```js
function findCheapestPrice(n, flights, src, dst, k) {
  const graph = Array.from({ length: n }, () => []);
  for (const [u, v, w] of flights) graph[u].push([v, w]);
  // fewest[u]: u를 꺼냈을 때 탄 가장 적은 비행 수
  const fewest = new Array(n).fill(Infinity);
  const heap = [[0, src, 0]]; // [비용, 도시, 탄 비행 수]. push, pop은 Network Delay Time 글의 힙과 같다
  // ... push, pop 생략
  while (heap.length > 0) {
    const [cost, u, used] = pop();
    if (u === dst) return cost;                    // 싼 순서로 꺼내니 처음 나온 목적지가 답
    if (used >= fewest[u] || used === k + 1) continue; // 더 싸게, 덜 타고 온 적이 있다 / 더 못 탄다
    fewest[u] = used;
    for (const [v, w] of graph[u]) push([cost + w, v, used + 1]);
  }
  return -1;
}
```

힙 코드는 [Network Delay Time 글](/posts/leetcode-network-delay-time#힙으로-다음-노드를-빨리-고른다)의 이진 힙과 같아서 생략했다. 같은 그래프에서 목적지에 닿는 경우 k = 99에서 1ms가 안 걸렸다. 싼 길부터 보다가 목적지를 꺼내는 즉시 끝나니, 답이 싸고 가까우면 아주 빠르다. 반대로 닿을 수 없는 그래프에서는 힙에 상태를 수천 개 넣고 다 꺼내야 해서 k = 3일 때 54ms로 벨만-포드(15.6ms)보다 느렸다.

Python으로는 `heapq`에 `(비용, 도시, 탄 횟수)` 튜플을 넣으면 된다. 힙을 직접 짤 필요가 없어서 코드가 벨만-포드만큼 짧아진다.

```python
import heapq
from collections import defaultdict
from typing import List


def find_cheapest_price_dijkstra(n: int, flights: List[List[int]], src: int, dst: int, k: int) -> int:
    graph = defaultdict(list)
    for u, v, w in flights:
        graph[u].append((v, w))
    fewest = [float("inf")] * n  # 그 도시를 꺼냈을 때 탄 가장 적은 비행 수
    heap = [(0, src, 0)]  # (비용, 도시, 탄 비행 수)
    while heap:
        cost, u, used = heapq.heappop(heap)
        if u == dst:
            return cost
        if used >= fewest[u] or used == k + 1:
            continue
        fewest[u] = used
        for v, w in graph[u]:
            heapq.heappush(heap, (cost + w, v, used + 1))
    return -1


ex = [[0, 1, 100], [1, 2, 100], [2, 4, 100], [0, 3, 500], [3, 4, 100], [0, 4, 900]]
print([find_cheapest_price_dijkstra(5, ex, 0, 4, k) for k in range(4)])
print(find_cheapest_price_dijkstra(4, [[0, 1, 100], [1, 2, 100], [0, 2, 500], [2, 3, 100]], 0, 3, 1))
```

```text
[900, 600, 300, 300]
600
```

Java는 `PriorityQueue<int[]>`에 세 값을 담는다. `fewest`를 `Integer.MAX_VALUE`로 채워도 더하기를 하지 않으니 넘치지 않는다.

```java
import java.util.*;

class Solution {
    public int findCheapestPrice(int n, int[][] flights, int src, int dst, int k) {
        List<List<int[]>> graph = new ArrayList<>();
        for (int i = 0; i < n; i++) graph.add(new ArrayList<>());
        for (int[] f : flights) graph.get(f[0]).add(new int[]{f[1], f[2]});
        int[] fewest = new int[n];
        Arrays.fill(fewest, Integer.MAX_VALUE);
        // [비용, 도시, 탄 비행 수]
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
        pq.offer(new int[]{0, src, 0});
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int cost = cur[0], u = cur[1], used = cur[2];
            if (u == dst) return cost;
            if (used >= fewest[u] || used == k + 1) continue;
            fewest[u] = used;
            for (int[] e : graph.get(u)) pq.offer(new int[]{cost + e[1], e[0], used + 1});
        }
        return -1;
    }
}
```

```text
600 600
```

예시 k = 1과 반례 그래프에서 모두 600이 나왔다.

상태 수는 도시 n개 × 비행 횟수 k + 2가지라 힙에 들어가는 건 많아야 O(k · E)개이고, 시간은 O(k · E log(k · E))다. 벨만-포드보다 이론상 느리지만 답을 찾으면 일찍 끝나는 장점이 있다.

## 같은 질문을 기억해 두는 DP

DFS의 낭비를 직접 고치는 방법도 있다. "src에서 비행 e번 이하로 v에 오는 가장 싼 값"을 `cost(v, e)`라고 하자. v로 들어오는 표 `u → v`를 마지막으로 탔다면 그 앞은 `cost(u, e - 1)`이다. 그래서 `cost(v, e)`는 들어오는 표마다 `cost(u, e - 1) + w`를 구해 가장 작은 것이다. 같은 `(v, e)`를 여러 번 묻게 되니 답을 기억해 둔다.

```js
function findCheapestPrice(n, flights, src, dst, k) {
  const into = Array.from({ length: n }, () => []); // into[v] = v로 들어오는 [u, w]
  for (const [u, v, w] of flights) into[v].push([u, w]);
  const memo = new Map();
  // cost(v, e): src에서 비행 e번 이하로 v에 오는 최소 비용
  const cost = (v, e) => {
    if (v === src) return 0;
    if (e === 0) return Infinity;
    const key = v * 101 + e;               // e는 101 미만이라 겹치지 않는다
    if (memo.has(key)) return memo.get(key);
    let best = Infinity;
    for (const [u, w] of into[v]) best = Math.min(best, cost(u, e - 1) + w);
    memo.set(key, best);
    return best;
  };
  const answer = cost(dst, k + 1);
  return answer === Infinity ? -1 : answer;
}
```

`v === src`이면 0을 돌려준다. 출발 도시로 돌아오는 고리를 다시 타는 건 값만 늘리니 볼 필요가 없다. 상태가 n × (k + 2)개이고 상태마다 들어오는 표를 훑으니 O(k · E)다. 벨만-포드와 같은 표를 위에서부터 채우는 셈이다. 실제로 이 DP를 아래에서부터 채우면 `dp[e][v]` 표가 되고, 한 줄 전 값만 쓰니 배열 두 개로 줄인 것이 위의 벨만-포드다.

아래에서부터 채우는 표를 직접 만들어 보면 벨만-포드와의 관계가 눈에 보인다. `dp[e][v]`는 비행 e번 이하로 v에 오는 가장 싼 값이다.

```js
function cheapestTable(n, flights, src, dst, k) {
  // dp[e][v]: 비행 e번 이하로 v에 오는 최소 비용
  const dp = Array.from({ length: k + 2 }, () => new Array(n).fill(Infinity));
  for (let e = 0; e <= k + 1; e++) dp[e][src] = 0;
  for (let e = 1; e <= k + 1; e++) {
    for (let v = 0; v < n; v++) dp[e][v] = dp[e - 1][v]; // 덜 타도 된다
    for (const [u, v, w] of flights) {
      if (dp[e - 1][u] + w < dp[e][v]) dp[e][v] = dp[e - 1][u] + w;
    }
  }
  return dp;
}
```

예시에서 k = 2로 표를 찍으면 이렇다.

```text
e\v        0     1     2     3     4
0          0     ∞     ∞     ∞     ∞
1          0   100     ∞   500   900
2          0   100   200   500   600
3          0   100   200   500   300
```

한 줄이 벨만-포드의 한 바퀴다. 맨 오른쪽 열을 위에서 아래로 읽으면 k = 0, 1, 2일 때의 답 900, 600, 300이 차례로 나온다. 각 줄은 바로 윗줄만 읽으니 표 전체를 들고 있을 필요가 없고, 두 줄만 남긴 것이 `dist`와 `next`다. 공간이 O(k · n)에서 O(n)으로 준다.

재귀 깊이는 k + 1까지라 100 정도로 얕다. 다만 Map 조회가 많아서 무작위 그래프 k = 99에서 16.6ms로 다섯 풀이 중 가장 느렸다.

## 다익스트라를 그대로 쓰면 틀리는 곳

가장 흔한 실수는 횟수를 무시한 다익스트라다. 예시에서 k = 1이어도 300을 낸다. 가장 싼 길이 횟수 제한을 넘는지 보지 않으니까.

횟수를 들고 다니면서도 도시마다 한 번만 꺼내는 다익스트라도 틀린다. 아래 그래프에서 0에서 3으로, k = 1로 가 보자.

```text
0 → 1 : 100    1 → 2 : 100    0 → 2 : 500    2 → 3 : 100
```

답은 0 → 2 → 3으로 600이다. 그런데 도시를 한 번만 꺼내면, 2를 먼저 1을 거쳐 200(비행 2번)에 꺼내 "처리 완료"로 표시한다. 거기서 3으로 가려면 비행이 3번이라 제한을 넘는다. 나중에 0에서 바로 온 2(500, 비행 1번)가 나오지만 2는 이미 처리됐다고 버린다. 결과는 -1이다. 위의 다익스트라가 `fewest`로 "덜 타고 왔으면 다시 펼친다"를 둔 이유다.

## 표 값을 구하는 다섯 방법 비교

시간은 도시 100개, 표 4,950장 무작위 그래프에서 잰 값이다. 괄호 안은 목적지로 들어오는 표를 지워 닿을 수 없게 만든 그래프다.

| 풀이 | 시간 | 공간 | k = 5 | 언제 고르나 |
|---|---|---|---|---|
| 가지치기 DFS | 최악 지수 | O(n + k) | 11ms (k = 4에서 3.5초) | 고르지 않는다 |
| 층별 BFS | O(k · E) | O(n + E) | 8.5ms | 층 개념을 설명하기 좋다 |
| 벨만-포드 k + 1바퀴 | O(k · E) | O(n) | 2.3ms | 기본 답. 짧고 틀리기 어렵다 |
| 횟수를 든 다익스트라 | O(k · E log(k · E)) | O(k · E) | 4.6ms | 답이 싸고 가까워 일찍 끝날 때 |
| 메모 DP | O(k · E) | O(n · k) | 4.2ms | 점화식을 먼저 세우는 사람에게 자연스럽다 |

면접에서는 벨만-포드로 답하고 "바퀴 수가 곧 비행 횟수라서 k + 1바퀴에서 멈춘다, 한 바퀴 안에서는 지난 바퀴 값만 읽는다" 두 문장을 설명하면 된다. 다익스트라로 답한다면 상태에 비행 횟수를 넣어야 하고 도시를 한 번만 꺼내면 틀린다는 걸 먼저 말한다.

## 제자리 갱신과 바퀴 수에서 틀린다

벨만-포드에서 배열을 복사하지 않고 제자리에서 고치면 틀린다.

```js
// 틀린 풀이: 같은 바퀴 안에서 방금 고친 값을 다시 읽는다
for (let round = 0; round <= k; round++) {
  for (const [u, v, w] of flights) {
    if (dist[u] + w < dist[v]) dist[v] = dist[u] + w;
  }
}
```

예시에서 k = 0인데 300이 나온다. 표가 `0→1, 1→2, 2→4` 순서로 적혀 있어서, 첫 바퀴에 0→1로 1을 고친 직후 1→2가 그 값을 읽고, 이어서 2→4가 또 읽는다. 한 바퀴에 비행 세 번을 탄 셈이다. 제한 없는 최단 경로에서는 오히려 빨라지는 최적화지만, 횟수를 세는 이 문제에서는 버그다. 표 순서에 따라 답이 맞을 때도 있어서 테스트 몇 개로는 안 잡힌다.

k를 비행 횟수로 착각해 `round < k`로 돌리면 한 바퀴 모자란다. k = 0일 때 직항조차 못 써서 -1이 나온다. 들르는 도시 k개는 비행 k + 1번이다.

Java에서 `Integer.MAX_VALUE + w`는 음수가 된다. `dist[u] != INF` 검사를 빠뜨리면 닿지 않은 도시에서 출발한 표가 "아주 싼 값"으로 퍼진다.

BFS 풀이에서 도시마다 방문 표시를 하고 처음 닿은 층에서만 값을 적으면, 이번엔 반대 방향으로 틀린다. 적은 비행으로 비싸게 닿은 값을 굳혀서, 비행을 한 번 더 타면 싸지는 길을 버린다. 위 반례 그래프에서 k = 2면 0 → 1 → 2 → 3으로 300이 답인데, 2를 첫 층에서 500으로 굳혀 600을 낸다.

src와 dst가 같다면 비행 없이 0이다. 이 문제는 둘이 다르다고 보장하지만, 위 풀이들은 모두 `dist[src] = 0`에서 시작하니 그대로 0을 낸다.

## 제한이 바뀌거나 경로가 필요하면

경로를 돌려달라고 하면 벨만-포드에서 `next[v]`를 고칠 때 "이번 바퀴에 v는 u에서 왔다"를 바퀴별 부모 배열에 적는다. 같은 도시라도 바퀴마다 부모가 다를 수 있어서, 목적지 값이 마지막으로 바뀐 바퀴에서 시작해 한 바퀴씩 내려가며 부모를 따라간다. 부모 배열 하나만 두고 덮어쓰면 나중 바퀴의 부모가 앞 바퀴의 것을 지워서, 따라간 경로가 횟수 제한을 넘을 수 있다.

k가 n - 2 이상이면 제한이 없는 것과 같다. 같은 도시를 두 번 지나지 않는 경로는 비행이 많아야 n - 1번이고, 값이 양수라 고리를 도는 경로는 더 비싸기 때문이다. k 제한이 없다면 그냥 최단 경로다. 값이 0 이상이니 [Network Delay Time](/posts/leetcode-network-delay-time)의 힙 다익스트라를 쓴다.

값에 음수가 섞여도 벨만-포드 k + 1바퀴는 그대로 맞다. 바퀴 수가 정해져 있어 음수 사이클이 있어도 끝나기 때문이다. 다익스트라 풀이는 깨진다.

비행 횟수 대신 "총 비행시간 T 이하에서 가장 싼 값"처럼 두 번째 비용이 정수 범위로 주어지면 상태를 (도시, 쓴 시간)으로 넓힌다. 시간 범위가 크면 상태가 폭발해서 이 문제보다 훨씬 어렵다. [LeetCode 1928. Minimum Cost to Reach Destination in Time](https://leetcode.com/problems/minimum-cost-to-reach-destination-in-time/)이 그 변형이고, (도시, 시간) 표를 채우는 DP로 푼다.

모든 쌍 사이 거리가 필요한 [Find the City With the Smallest Number of Neighbors at a Threshold Distance](/posts/leetcode-find-city-smallest-neighbors)는 플로이드-워셜, 곱셈으로 바뀐 [Path with Maximum Probability](/posts/leetcode-path-with-maximum-probability)는 다익스트라를 그대로 쓴다. 이 문제처럼 경로에 두 번째 조건이 붙을 때만 상태를 넓힌다는 것을 기억해 두면 고르기 쉽다.

## 면접에서 나올 만한 질문

### 일반 다익스트라가 이 문제에서 틀리는 이유는

다익스트라는 도시마다 가장 싼 값 하나만 들고 다니는데, 이 문제는 비행 횟수까지 따져야 한다. 가장 싼 길이 횟수를 넘으면 더 비싸지만 덜 타는 길이 답인데, 도시를 한 번 확정해 버리면 그 길이 버려진다. 예시에서 k = 1이면 300짜리 길을 버리고 600을 골라야 한다.

### 벨만-포드를 k + 1바퀴만 돌리면 되는 이유는

벨만-포드는 한 바퀴마다 간선을 하나 더 쓴 최단 거리를 만든다. 바퀴 수가 곧 비행 횟수이고, 들르는 도시 k개는 비행 k + 1번이니 k + 1바퀴에서 멈추면 "비행 k + 1번 이하로 가는 가장 싼 값"이 된다.

### 왜 바퀴마다 배열을 복사하나

한 바퀴 안에서 방금 고친 값을 다시 읽으면 그 바퀴에 비행을 여러 번 탄 셈이 되기 때문이다. 예시에서 복사하지 않으면 k = 0인데도 0→1→2→4를 한 바퀴에 타서 300이 나온다. 지난 바퀴 값만 읽어야 바퀴와 비행 횟수가 일치한다.

### 다익스트라로 풀려면 무엇을 바꾸나

상태를 (도시, 탄 비행 수)로 넓혀 힙에 넣고, 목적지를 처음 꺼낼 때 답을 낸다. 도시를 한 번만 꺼내면 틀리니 그 도시를 꺼낸 적이 있어도 더 적은 횟수로 왔으면 다시 펼친다. 시간은 O(k · E log(k · E))로 벨만-포드보다 크지만 답을 찾으면 일찍 끝난다.

### 시간과 공간 복잡도는

벨만-포드는 k + 1바퀴마다 표 E장을 보니 O(k · E), 배열 두 개라 공간 O(n)이다. 문제 최대 크기에서 100 × 4,950으로 50만 번이다. 층별 BFS와 메모 DP도 같은 O(k · E)이고, DFS는 목적지에 닿지 못하면 k가 늘 때마다 지수로 는다.

### 값에 음수가 있으면

벨만-포드는 그대로 맞다. 바퀴 수가 k + 1로 정해져 있어 음수 사이클이 있어도 끝나고, 각 바퀴는 여전히 "비행을 하나 더 쓴 최솟값"이다. 다익스트라 풀이는 꺼낸 순서가 비용 순이라는 전제가 깨져 쓸 수 없다.
