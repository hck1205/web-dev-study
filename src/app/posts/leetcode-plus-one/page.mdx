카드 번호, 주문 번호, 큰 정수를 자릿수 배열로 들고 다니는 코드는 생각보다 흔하다. 숫자 타입에 담기엔 너무 길거나, 앞에 붙은 0을 지키고 싶거나, 자리마다 따로 다뤄야 해서다. 그런 배열에 1을 더하는 일은 작아 보이지만 올림이 어디까지 번지는지, 배열이 길어져야 하는 순간이 언제인지를 정확히 알아야 한다. [Plus One](https://leetcode.com/problems/plus-one/)이 그 연습이다.

이 글은 풀이 여섯 개를 놓는다. 숫자로 바꿔 더하는 방법(어디서 틀리는지 보려고), 큰 수 타입으로 바꾸는 방법, 올림을 끝까지 들고 가는 일반 덧셈, 9가 아닌 칸에서 멈추는 방법, 마지막 9가 아닌 칸을 먼저 찾는 방법, 재귀다. 가장 짧은 풀이가 왜 평균적으로 한 칸 남짓만 보는지도 계산해 본다. 코드는 모두 Node.js 22, Python 3.13, Java 21에서 직접 돌렸다.

## 자릿수 배열에 1을 더한다

음이 아닌 정수 하나가 자릿수 배열 `digits`로 주어진다. 맨 앞이 가장 큰 자리다. 예를 들어 `[2, 4, 9, 9]`는 2499다. 이 수에 1을 더한 결과를 같은 모양의 배열로 돌려준다.

- 길이는 1 이상 100 이하다. 100자리 수는 어떤 언어의 기본 정수 타입에도 들어가지 않는다.
- 각 칸은 0~9이고, 수 자체가 0인 `[0]`이 아니면 맨 앞이 0이 아니다.

길이가 100이라 속도는 문제가 되지 않는다. 묻는 건 세 가지다. 숫자로 바꾸지 않고 칸을 직접 다룰 수 있는가, 올림을 정확히 처리하는가, 길이가 하나 늘어나는 경우를 놓치지 않는가.

## 2499와 999에 1을 더해 보기

손으로 해 본다. 2499에 1을 더하면 일의 자리 9가 10이 되어 0을 남기고 1을 올린다. 십의 자리 9도 같은 일을 겪는다. 백의 자리 4는 5가 되고, 더 올릴 게 없어 멈춘다.

```text
  2 4 9 9
+       1
---------
  2 5 0 0      ← 9 두 개가 0이 되고, 4가 5가 된 뒤 멈춘다
```

999는 끝까지 간다. 세 칸이 모두 0이 되고 올림 1이 배열 밖으로 나온다. 결과는 네 자리 1000이다.

```text
    9 9 9
+       1
---------
  1 0 0 0      ← 칸이 하나 늘었다
```

두 경우에서 규칙이 보인다. 오른쪽 끝부터 이어지는 9는 모두 0이 되고, 그 왼쪽의 첫 9가 아닌 칸이 1 늘어난다. 그런 칸이 없으면, 즉 전부 9였으면 결과는 `1` 뒤에 0이 원래 길이만큼 붙은 수다. 이 두 줄이 이 문제의 모든 풀이가 하는 일이다.

## 숫자로 바꿔서 더한다

가장 먼저 떠오르는 코드다.

```js
function plusOne(digits) {
  const n = Number(digits.join("")) + 1;     // [1, 2, 3] → "123" → 123 → 124
  return String(n).split("").map(Number);    // 124 → "124" → [1, 2, 4]
}
console.log(plusOne([1, 2, 3]));              // [1, 2, 4]
console.log(plusOne([9, 0, 0, 7, 1, 9, 9, 2, 5, 4, 7, 4, 0, 9, 9, 3, 1]));
// [9,0,0,7,1,9,9,2,5,4,7,4,0,9,9,4,0]  (정답은 ...9,9,3,2)
```

열일곱 자리 90071992547409931에 1을 더했더니 90071992547409932가 아니라 90071992547409940이 나왔다. JavaScript `Number`는 2^53 - 1(9,007,199,254,740,991)까지만 정수를 정확히 담는다. 그 위의 정수는 가까운 표현 가능한 값으로 반올림되어 이미 `Number(...)`에서 틀린 값이 된다. 합이 10^21 이상(22자리부터)이면 `String(n)`이 `1e+21` 같은 지수 표기를 내놓아 배열 모양부터 망가진다.

Java에서 `Long.parseLong`으로 바꾸면 19자리를 넘는 순간 `NumberFormatException`이 난다. 100자리까지 들어오는 이 문제에서는 쓸 수 없는 방법이다.

## 큰 수 타입으로 바꾼다

```js
function plusOne(digits) {
  return (BigInt(digits.join("")) + 1n).toString().split("").map(Number);
}
```

`BigInt`는 자릿수 제한이 없어서 답은 맞는다. Python이라면 `int("".join(map(str, digits))) + 1`, Java라면 `new BigInteger(...)`가 같은 역할을 한다. 문자열로 합치고, 큰 수로 해석하고, 더하고, 다시 문자열로 바꾸고, 쪼개는 데 각각 O(n)이라 전체도 O(n)이다.

채점은 통과하지만 면접관이 보고 싶은 건 이게 아니다. 자릿수 배열을 받았다는 건 "숫자 타입에 담기지 않는 수를 칸 단위로 다뤄 보라"는 뜻이다. 이 풀이는 아래 풀이들을 무작위 입력 2만 개로 검증할 때 정답지로만 썼다.

## 올림을 끝까지 들고 간다

세로 덧셈을 그대로 옮긴다. 더할 값 1을 처음의 올림(carry)으로 보고, 오른쪽 칸부터 "칸 값 + 올림"을 계산해 일의 자리는 칸에 남기고 십의 자리는 다음 올림으로 넘긴다.

```js
function plusOne(digits) {
  const out = digits.slice();                // 입력을 건드리지 않으려고 복사한다
  let carry = 1;                             // 더할 1을 처음 올림으로 본다
  for (let i = out.length - 1; i >= 0; i--) {
    const s = out[i] + carry;
    out[i] = s % 10;                         // 이 칸에 남는 숫자
    carry = Math.floor(s / 10);              // 다음 칸으로 넘길 올림(0 또는 1)
  }
  if (carry) out.unshift(carry);             // 전부 9였다면 맨 앞에 1을 붙인다
  return out;
}
console.log(plusOne([2, 4, 9, 9]), plusOne([9, 9, 9])); // [2, 5, 0, 0] [1, 0, 0, 0]
```

이 코드의 장점은 일반적이라는 것이다. `carry = 1`을 `carry = k`로 바꾸고 `carry`가 남아 있는 동안 반복을 이어 가면 1이 아니라 아무 수나 더할 수 있다. 두 배열을 더하는 문제로도 거의 그대로 옮겨 간다. [Multiply Strings](/posts/leetcode-multiply-strings)의 `addStrings`와 [Add Two Numbers](/posts/leetcode-add-two-numbers)가 같은 뼈대다.

시간은 항상 O(n)이다. 올림이 0이 된 뒤에도 남은 칸을 끝까지 돈다. 2499에서 백의 자리에서 이미 끝났는데 천의 자리 2도 `2 + 0`을 계산한다. 공간은 복사본 때문에 O(n)이다. 그리고 `unshift`는 배열 맨 앞에 끼워 넣느라 모든 칸을 한 칸씩 미는 O(n) 연산이다. 한 번뿐이라 차수는 그대로지만, 길이를 미리 알 수 있다면 피하는 편이 낫다.

올림이 0이 되는 순간 그 뒤의 칸은 바뀌지 않는다. 그렇다면 거기서 멈추면 된다.

## 9가 아닌 칸에서 멈춘다

1을 더할 때 올림은 항상 0 아니면 1이다. 칸 값이 9보다 작으면 1을 더해도 10이 되지 않으니 올림이 생기지 않는다. 그 칸만 1 늘리고 바로 돌려주면 된다. 칸 값이 9면 0으로 만들고 왼쪽으로 간다. 반복을 다 돌았는데 돌려주지 못했다면 전부 9였다는 뜻이다.

```js
function plusOne(digits) {
  for (let i = digits.length - 1; i >= 0; i--) {
    if (digits[i] < 9) {      // 1을 더해도 10이 되지 않는다
      digits[i]++;            // 올림이 여기서 멈춘다
      return digits;
    }
    digits[i] = 0;            // 9 + 1 = 10. 0을 남기고 왼쪽으로 올린다
  }
  // 여기까지 왔다면 전부 9였고, digits는 이제 전부 0이다
  const out = new Array(digits.length + 1).fill(0);
  out[0] = 1;                 // 1 뒤에 0이 원래 길이만큼
  return out;
}
```

`carry` 변수가 사라졌다. 반복이 계속된다는 것 자체가 "올림이 1"이라는 뜻이라서다. 일반 덧셈에서 1을 더한다는 조건을 끝까지 쓰면 이렇게 줄어든다.

전부 9인 경우 결과를 계산할 필요가 없다는 게 재미있다. 원래 배열은 모두 0이 됐으니 버리고, "1 다음에 0이 n개"라는 정해진 모양을 새로 만든다. Java라면 `new int[n + 1]`이 0으로 채워져 나오니 맨 앞만 1로 바꾸면 끝이다.

### 평균적으로 몇 칸을 보나

최악은 전부 9일 때라 O(n)이다. 그런데 평균은 어떨까. 끝자리가 9가 아닐 확률이 9/10이라 대부분은 한 칸에서 끝난다. 끝 두 자리가 99일 확률은 1/100, 끝 세 자리가 999일 확률은 1/1000이다. 그래서 보는 칸 수의 기댓값은 1 + 1/10 + 1/100 + ... ≈ 1.111이다.

실제로 0부터 999,999까지 모든 수에 1을 더한다고 치고 바뀌는 칸 수를 세어 봤다.

```text
바뀌는 칸 수 : 그런 수의 개수
1 : 900000
2 :  90000
3 :   9000
4 :    900
5 :     90
6 :      9
7 :      1      ← 999,999 하나. 일곱 자리 1,000,000이 된다
```

열 배씩 줄어드는 게 보인다. 모두 더해 100만으로 나누면 평균은 정확히 1.111111이다. 0부터 차례로 1씩 더해 가는 카운터라면 한 번에 평균 1.11칸만 바뀐다는 뜻이다. 이렇게 "가끔 비싸지만 길게 보면 한 번에 상수"인 비용을 분할 상환(amortized) 분석이라고 부른다. 2진수 카운터에 1을 더할 때 평균 2비트가 바뀌는 것과 같은 계산이고, [비트 연산](/posts/bit-manipulation)에서도 같은 모양이 나온다.

공간은 입력 배열을 그대로 고쳐 쓰니 O(1)이다. 전부 9인 경우만 새 배열 O(n)이 필요한데, 이건 답 자체의 크기라 피할 수 없다.

### 입력을 고쳐 써도 되나

이 풀이는 `digits`를 직접 바꾸고 그 배열을 돌려준다. LeetCode는 이걸 허용하지만, 실무 함수라면 호출한 쪽이 원래 배열을 계속 쓸 수 있으니 문제가 될 수 있다. 실제로 `const a = [1, 2, 3]; const r = plusOne(a);` 뒤에 `r === a`가 `true`였고, `a`는 `[1, 2, 4]`로 바뀌어 있었다. 전부 9인 `[9, 9]`를 넣으면 반대로 새 배열이 돌아오면서 원래 배열은 `[0, 0]`으로 망가진 채 남는다. 같은 함수가 어떤 입력에서는 같은 배열을, 어떤 입력에서는 다른 배열을 돌려주는 셈이다.

면접에서는 "입력을 바꿔도 되나요?"를 먼저 묻는 게 좋다. 안 된다면 맨 앞에서 `digits = digits.slice()`로 복사하면 되고, 그러면 공간이 O(n)이 된다.

## 마지막 9가 아닌 칸을 먼저 찾는다

손으로 풀 때 본 규칙을 그대로 코드로 옮길 수도 있다. "오른쪽에서 처음 만나는 9가 아닌 칸"을 먼저 찾고, 그 칸을 1 늘리고, 그 오른쪽을 모두 0으로 만든다.

```js
function plusOne(digits) {
  const k = digits.findLastIndex((d) => d !== 9);   // 오른쪽에서 첫 9가 아닌 칸
  if (k === -1) return [1, ...new Array(digits.length).fill(0)];  // 전부 9
  const out = digits.slice(0, k + 1);               // k까지는 그대로 복사
  out[k]++;                                         // k 칸만 1 늘린다
  return out.concat(new Array(digits.length - k - 1).fill(0));    // 오른쪽은 모두 0
}
console.log(plusOne([2, 4, 9, 9]), plusOne([9, 9]), plusOne([0])); // [2, 5, 0, 0] [1, 0, 0] [1]
```

`findLastIndex`는 ES2023에 들어온 메서드로 Node.js 18 이상에서 쓸 수 있다. 오래된 환경이라면 뒤에서부터 도는 `for` 문으로 같은 일을 한다.

앞 풀이와 하는 일은 같지만 "찾기"와 "고치기"가 나뉘어 있어 읽기 쉽다. 입력도 건드리지 않는다. 대신 복사가 들어가 시간과 공간이 항상 O(n)이다. 앞 풀이가 평균 1.11칸만 보는 것과 달리 이 풀이는 결과 배열 전체를 새로 만든다.

## 재귀로 왼쪽 칸에 넘긴다

"이 칸이 9면 0으로 만들고, 왼쪽 칸에 1을 더하는 일을 넘긴다"는 말을 그대로 재귀로 쓸 수 있다.

```js
function plusOne(digits, i = digits.length - 1) {
  if (i < 0) {                 // 맨 앞까지 올림이 왔다
    digits.unshift(1);
    return digits;
  }
  if (digits[i] < 9) {
    digits[i]++;
    return digits;
  }
  digits[i] = 0;
  return plusOne(digits, i - 1);   // 왼쪽 칸에 1을 더하는 일을 넘긴다
}
```

반복문 풀이와 정확히 같은 순서로 같은 칸을 바꾼다. 마지막 호출이 꼬리 호출이라 이론적으로는 반복문으로 바뀔 수 있지만, V8(Node.js, 크롬)은 꼬리 호출 최적화를 하지 않는다. 그래서 9가 길게 이어지면 호출 스택이 쌓인다. 내 환경에서 9를 7,906개까지는 버텼고 그보다 길면 `Maximum call stack size exceeded`가 났다. 길이 100인 이 문제에서는 상관없지만, 재귀로 쓸 이유도 없다. Python은 기본 재귀 한도가 1000이라 더 빨리 막힌다. 재귀를 반복으로 바꾸는 이야기는 [재귀와 백트래킹](/posts/recursion-backtracking)에 있다.

## Python과 Java에서 새 배열을 만드는 법

9가 아닌 칸에서 멈추는 풀이를 옮겼다.

```python
from typing import List

class Solution:
    def plusOne(self, digits: List[int]) -> List[int]:
        for i in range(len(digits) - 1, -1, -1):
            if digits[i] < 9:
                digits[i] += 1            # 올림이 여기서 멈춘다
                return digits
            digits[i] = 0                 # 9는 0이 되고 올림이 왼쪽으로 간다
        return [1] + digits               # 모두 9였다. digits는 이제 전부 0

s = Solution()
print(s.plusOne([1, 2, 3]), s.plusOne([2, 4, 9, 9]), s.plusOne([9, 9, 9]), s.plusOne([0]))
```

```text
[1, 2, 4] [2, 5, 0, 0] [1, 0, 0, 0] [1]
```

`[1] + digits`는 반복이 끝난 시점의 `digits`가 전부 0이라는 걸 이용한다. `[1] + [0] * len(digits)`로 써도 같다. `digits.insert(0, 1)`도 되지만 리스트 맨 앞에 끼우는 건 모든 원소를 미는 O(n)이고 입력 리스트를 바꾼다. Python에서 `range(len(digits) - 1, -1, -1)`의 가운데 `-1`은 "0까지 포함"이라는 뜻이다. `range(len(digits) - 1, 0, -1)`로 쓰면 맨 앞 칸을 빼먹는다.

```java
import java.util.Arrays;

class Solution {
    public int[] plusOne(int[] digits) {
        for (int i = digits.length - 1; i >= 0; i--) {
            if (digits[i] < 9) {
                digits[i]++;              // 올림이 여기서 멈춘다
                return digits;
            }
            digits[i] = 0;                // 9는 0이 되고 올림이 왼쪽으로 간다
        }
        int[] out = new int[digits.length + 1];   // Java 배열은 0으로 채워져 만들어진다
        out[0] = 1;
        return out;
    }

    public static void main(String[] args) {
        Solution s = new Solution();
        System.out.println(Arrays.toString(s.plusOne(new int[]{1, 2, 3})) + " "
            + Arrays.toString(s.plusOne(new int[]{2, 4, 9, 9})) + " "
            + Arrays.toString(s.plusOne(new int[]{9, 9, 9})) + " "
            + Arrays.toString(s.plusOne(new int[]{0})));
    }
}
```

```text
[1, 2, 4] [2, 5, 0, 0] [1, 0, 0, 0] [1]
```

Java 배열은 길이를 바꿀 수 없어서 전부 9인 경우엔 반드시 새 배열을 만든다. `new int[n + 1]`은 모든 칸이 0이라 따로 채울 필요가 없다. 배열을 출력할 때 `System.out.println(arr)`은 `[I@1b6d3586` 같은 주소 비슷한 문자열을 찍으니 `Arrays.toString`을 쓴다.

|---|---|---|---|---|
| Number로 바꾸기 | O(n) | O(n) | 아니오 | 쓰지 않는다. 2^53을 넘는 열일곱 자리부터 틀릴 수 있다 |

## 올림이 맨 앞까지 갈 때 틀린다

### 전부 9인 경우를 놓친다

```js
function plusOne(digits) {
  for (let i = digits.length - 1; i >= 0; i--) {
    if (digits[i] < 9) { digits[i]++; return digits; }
    digits[i] = 0;
  }
  return digits;          // 새 배열을 만들지 않았다
}
console.log(plusOne([9, 9]));   // [0, 0]
```

`[9, 9]`에 1을 더한 답이 `[0, 0]`이 된다. 테스트를 `[1, 2, 3]` 같은 평범한 입력으로만 하면 통과하니, 9 하나짜리 `[9]`와 전부 9인 입력을 꼭 넣는다.

### 반복 안에서 새 배열을 만든다

```js
if (i === 0 && digits[0] === 9) { digits[0] = 0; return [1, ...digits]; }
```

맨 앞 칸에서 특별 처리를 하는 코드인데, 이 줄이 반복의 어느 위치에 있느냐에 따라 맨 앞이 9가 아닌 경우를 망가뜨리거나 9를 0으로 바꾸기 전에 돌려주는 실수가 잦다. 반복이 돌려주지 못하고 끝났다는 사실 하나로 "전부 9였다"를 판단하는 쪽이 조건이 하나 적다.

### 9보다 작다를 "10보다 작다"로 쓴다

`if (digits[i] + 1 < 10)`과 `if (digits[i] < 9)`는 같다. 그런데 `if (digits[i] <= 9)`로 쓰면 9도 통과해 10이 칸에 들어간다. `[9]`가 `[10]`이 된다. 경계가 9인지 10인지는 "1을 더한 뒤에 한 자리로 남는가"로 판단한다.

### 문자열로 합칠 때 숫자 타입을 놓친다

`digits.join("") + 1`은 덧셈이 아니라 이어 붙이기라 `"123" + 1`이 `"1231"`이 된다. `Number`나 `BigInt`로 바꾸는 걸 잊으면 생기는 실수다. 큰 수 타입을 쓴다면 `BigInt(...) + 1n`처럼 더하는 쪽도 `BigInt`여야 한다. `BigInt`와 `Number`를 섞어 더하면 `TypeError`가 난다.

## BigInt를 정답지로 두고 무작위로 찔러 보기

손으로 고른 테스트는 내가 떠올린 경우만 확인한다. 이 문제처럼 "느리지만 확실히 맞는 방법"이 있으면 그걸 정답지로 두고 무작위 입력을 수만 개 넣어 비교하는 게 싸고 확실하다. 이 글의 풀이들도 이렇게 검증했다.

```js
const reference = (d) => (BigInt(d.join("")) + 1n).toString().split("").map(Number);

function randomDigits() {
  const n = 1 + Math.floor(Math.random() * 100);
  const nineBias = Math.random();                       // 9가 몰리는 입력을 일부러 섞는다
  const d = Array.from({ length: n }, () => (Math.random() < nineBias ? 9 : Math.floor(Math.random() * 10)));
  if (n > 1 && d[0] === 0) d[0] = 1;                    // 맨 앞 0은 문제 조건에 어긋난다
  return d;
}

let fail = 0, grew = 0;
for (let t = 0; t < 20000; t++) {
  const d = randomDigits();
  const want = reference(d);
  const got = plusOne(d.slice());                       // 입력을 고치는 함수라 복사본을 넘긴다
  if (want.length > d.length) grew++;
  if (JSON.stringify(got) !== JSON.stringify(want)) { fail++; console.log("틀림", d.join("")); }
}
console.log(`틀린 입력 ${fail}개, 길이가 늘어난 입력 ${grew}개`);
```

```text
틀린 입력 0개, 길이가 늘어난 입력 910개
```

`nineBias`가 중요하다. 자릿수를 고르게 뽑기만 하면 전부 9인 배열은 길이 3에서도 1000개 중 하나라 거의 나오지 않는다. 9가 나올 확률 자체를 입력마다 0~1 사이로 흔들어 두면, 2만 개 중 900개 넘게 전부 9인 입력이 섞인다(돌릴 때마다 조금씩 다르다). 틀리기 쉬운 경계가 어딘지 알고, 무작위 생성기가 그쪽으로 자주 가게 만드는 게 요령이다. 복사본을 넘기는 것도 놓치기 쉽다. 함수가 입력을 고치면 정답지와 비교하기 전에 원래 값이 사라진다.

## 현장에서 만나는 하나 올리기

이 문제의 모양은 실무에서 생각보다 자주 나온다. 가장 흔한 건 앞에 0이 붙은 고정 폭 번호다. 송장 번호 `000199` 다음 번호를 만들어야 하는데, `Number("000199") + 1`을 하면 `200`이 나와 앞의 0이 사라진다. `padStart`로 다시 채우면 되지만, 번호가 숫자 타입의 범위를 넘을 만큼 길거나 폭을 넘어가는 순간을 따로 알아내야 한다면 문자열을 칸 단위로 올리는 쪽이 정확하다.

```js
// 고정 폭 번호 문자열을 1 올린다. 폭을 넘으면 null
function nextSerial(s) {
  const d = s.split("");
  for (let i = d.length - 1; i >= 0; i--) {
    if (d[i] < "9") {                         // 숫자 문자끼리 비교해도 순서가 같다
      d[i] = String.fromCharCode(d[i].charCodeAt(0) + 1);
      return d.join("");
    }
    d[i] = "0";
  }
  return null;                                 // 전부 9였다. 폭을 늘릴지 정해야 한다
}
console.log(nextSerial("000199"), nextSerial("004999"), nextSerial("999999"));
// 000200 005000 null
```

구조는 이 글의 기본 풀이 그대로고, 다른 건 전부 9인 경우의 처리다. 배열 문제에서는 길이를 하나 늘렸지만, 번호 체계에서는 폭이 정해져 있으니 "넘쳤다"를 알려야 한다. 조용히 `000000`으로 돌아가면 이미 쓴 번호와 겹친다. 주행 거리계가 999,999에서 000,000으로 돌아가는 것과 같은 일이 데이터에서 일어나면 중복 키 오류나, 더 나쁘면 조용한 덮어쓰기로 나타난다. 그래서 넘치는 경우를 반환값으로 드러내고 호출한 쪽이 폭을 늘리거나 오류를 내게 한다.

여러 서버가 동시에 다음 번호를 만든다면 이 함수만으로는 부족하다. 두 요청이 같은 `000199`를 읽고 둘 다 `000200`을 만들 수 있어서다. 그때는 번호를 DB 시퀀스나 원자적 증가 연산(Redis `INCR` 같은 것)에 맡기고, 이 함수는 화면에 보일 형식을 만드는 데만 쓴다.

### 진법이 바뀌면 경계만 바뀐다

10진법에서 9가 경계였던 건 한 칸에 담을 수 있는 가장 큰 숫자가 9라서다. b진법이면 그 숫자가 b - 1이다. 코드에서 9를 `b - 1`로 바꾸면 끝난다.

```js
function plusOneBase(digits, b) {
  for (let i = digits.length - 1; i >= 0; i--) {
    if (digits[i] < b - 1) { digits[i]++; return digits; }  // 경계가 9에서 b - 1로
    digits[i] = 0;
  }
  return [1, ...digits];
}
console.log(plusOneBase([1, 0, 1, 1], 2));   // [1, 1, 0, 0]   1011 + 1 = 1100
console.log(plusOneBase([1, 1, 1], 2));      // [1, 0, 0, 0]
console.log(plusOneBase([0xa, 0xf, 0xf], 16).map((x) => x.toString(16)).join(""));  // b00
```

2진법에서는 오른쪽 끝의 1들이 모두 0이 되고 그 왼쪽의 0이 1이 된다. 16진수 `aff`에 1을 더하면 `f` 두 개가 0이 되고 `a`가 `b`가 되어 `b00`이다. 평균적으로 보는 칸 수도 진법에 따라 달라진다. b진법이면 1 + 1/b + 1/b² + ... = b / (b - 1)이라 10진법은 약 1.11칸, 2진법은 2칸이다.

## 1이 아닌 것을 더하거나 빼면

### k를 더하라면

989. Add to Array-Form of Integer가 이 문제다. "9가 아닌 칸에서 멈추기"는 1을 더할 때만 성립하니 쓸 수 없고, 올림을 끝까지 들고 가는 풀이로 돌아간다. 요령은 k 자체를 올림으로 쓰는 것이다. 오른쪽 칸부터 `s = digits[i] + k`를 계산해 `s % 10`을 남기고 `k = Math.floor(s / 10)`으로 넘긴다. 배열을 다 돌았는데 k가 남아 있으면 k의 자릿수를 앞에 붙인다. k가 배열보다 길 수 있어서 반복 조건이 `i >= 0 || k > 0`이 된다.

```js
function addToArrayForm(num, k) {
  const out = [];
  for (let i = num.length - 1; i >= 0 || k > 0; i--) {
    const s = (i >= 0 ? num[i] : 0) + k;   // 배열이 끝나도 k가 남으면 계속
    out.push(s % 10);
    k = Math.floor(s / 10);
  }
  return out.reverse();                    // 뒤에서부터 쌓았으니 뒤집는다
}
console.log(addToArrayForm([2, 7, 4], 181), addToArrayForm([9, 9], 1), addToArrayForm([0], 1000));
// [4, 5, 5] [1, 0, 0] [1, 0, 0, 0]
```

`push` 후 마지막에 한 번 `reverse`하면 `unshift`를 매번 하는 O(n²)을 피한다.

### 1을 빼라면

거울처럼 뒤집힌다. 오른쪽에서 0이 아닌 첫 칸을 1 줄이고, 그 오른쪽의 0은 모두 9가 된다. 1000 - 1 = 999처럼 맨 앞이 0이 되면 그 0을 지워야 하고, 입력이 `[0]`이면 음수가 되니 문제 조건을 먼저 확인한다. 길이가 늘어나는 대신 줄어드는 경우가 있다는 게 차이다.

### 자릿수가 거꾸로 들어오거나 연결 리스트라면

배열이 일의 자리부터 들어오면 앞에서부터 돌면 되고, 전부 9일 때 `push(1)`로 끝에 붙이니 `unshift`도 필요 없다. 연결 리스트로 들어오는 369. Plus One Linked List(프리미엄 문제)는 뒤로 갈 수 없어서 "마지막 9가 아닌 노드"를 앞에서부터 기억해 두고 끝까지 간 뒤, 그 노드를 1 늘리고 뒤를 0으로 만든다. 전부 9면 맨 앞에 새 노드를 붙인다. 이 글의 "마지막 9가 아닌 칸을 먼저 찾는" 풀이가 여기서 쓰인다.

### 2진수라면

67. Add Binary처럼 2진수 문자열에 1을 더하면 9 대신 1이 경계다. 오른쪽부터 1을 0으로 바꾸다 처음 만나는 0을 1로 바꾼다. 정수라면 `n + 1`을 비트로 보면 정확히 이 일이 일어나고, `n & (n + 1)`이 오른쪽 끝의 1들을 지우는 것도 같은 성질에서 나온다.

## 면접에서 나올 만한 질문

### 숫자로 바꿔서 1을 더하면 왜 안 되나요?

길이가 100까지라 기본 정수 타입에 담기지 않는다. JavaScript `Number`는 2^53 - 1까지만 정수를 정확히 담아서 그보다 큰 열일곱 자리 수부터 조용히 틀릴 수 있고, Java `long`은 19자리를 넘으면 변환 자체가 실패한다. 큰 수 타입을 쓰면 답은 맞지만, 자릿수 배열을 직접 다루라는 문제의 의도와 다르다.

### 결과 배열의 길이가 늘어나는 건 언제인가요?

모든 칸이 9일 때뿐이다. 하나라도 9가 아닌 칸이 있으면 올림이 그 칸에서 멈추니 길이가 그대로다. 전부 9면 결과는 항상 1 뒤에 0이 원래 길이만큼 붙은 모양이라, 계산하지 않고 그 모양의 새 배열을 만들면 된다.

### 시간 복잡도는요?

최악은 전부 9일 때라 O(n)이다. 하지만 끝자리가 9일 확률이 1/10, 끝 두 자리가 99일 확률이 1/100이라 평균적으로 보는 칸은 약 1.11개다. 0부터 차례로 1씩 더하는 카운터라면 한 번에 평균 상수 칸만 바뀌니, 분할 상환으로 O(1)이라고 말할 수 있다.

### 공간을 O(1)로 할 수 있나요?

입력 배열을 고쳐 쓰면 O(1)이다. 전부 9인 경우만 길이 n + 1짜리 새 배열이 필요한데, 그건 답의 크기라 피할 수 없다. 입력을 바꾸면 안 된다는 조건이 있으면 복사해야 해서 O(n)이 된다. 그래서 먼저 입력을 바꿔도 되는지 확인한다.

### carry 변수 없이 어떻게 올림을 처리했나요?

1을 더할 때 올림은 0 아니면 1이다. 칸이 9보다 작으면 올림이 생기지 않으니 그 칸을 1 늘리고 바로 돌려준다. 반복이 다음 칸으로 넘어간다는 것 자체가 올림이 1이라는 뜻이라 따로 변수를 둘 필요가 없다. k를 더하는 일반 문제에서는 이 성질이 깨지니 carry를 다시 둔다.

### 1이 아니라 k를 더하라면 무엇을 바꾸나요?

9에서 멈추는 지름길을 버리고 올림을 끝까지 들고 가는 덧셈으로 바꾼다. k 자체를 처음 올림으로 보고, 칸마다 칸 값과 올림을 더해 일의 자리를 남기고 나머지를 다음 올림으로 넘긴다. 배열이 끝나도 올림이 남아 있으면 계속 앞에 자릿수를 붙인다.

### 입력을 직접 고치는 풀이에 문제는 없나요?

호출한 쪽이 원래 배열을 계속 쓰면 값이 바뀌어 있어 버그가 된다. 게다가 전부 9인 경우엔 새 배열을 돌려주고 원래 배열은 전부 0으로 남아서, 같은 함수가 입력에 따라 같은 배열과 새 배열을 섞어 돌려준다. 실무 함수라면 복사본을 만들거나, 고친다는 걸 이름과 문서에 밝힌다.
