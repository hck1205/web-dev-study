조직도를 화면에 그린다고 해 보자. 대표 한 명을 맨 위 줄에, 본부장들을 둘째 줄에, 팀장들을 셋째 줄에 놓고 싶다. 데이터는 "이 사람의 부하 직원은 누구"라는 트리로 들어 있다. 트리를 평소처럼 재귀로 훑으면 대표 → 첫 본부장 → 그 아래 팀장 → … 순서로 한 갈래를 끝까지 내려간 뒤에야 둘째 본부장으로 넘어간다. 줄별로 그리려면 훑는 순서를 옆으로 바꿔야 한다.

[LeetCode 102. Binary Tree Level Order Traversal](https://leetcode.com/problems/binary-tree-level-order-traversal/)이 이 문제다. 너비 우선 탐색(BFS)의 교과서 같은 문제이고, 여기서 익히는 "큐 길이를 먼저 세어 두고 그만큼만 꺼낸다"는 장치는 오른쪽에서 본 모습, 지그재그 순회, 격자 최단 거리 같은 문제에 그대로 다시 나온다. 이 글은 층마다 트리를 처음부터 다시 훑는 느린 풀이부터 시작해, 큐를 쓰는 풀이 셋과 깊이를 들고 내려가는 DFS 풀이 둘까지 여섯 가지를 따라간다.

트리 구조와 순회 순서는 [이진 트리와 BST 글](/posts/ds-binary-tree-bst)에, 그래프에서의 BFS와 DFS는 [그래프 BFS·DFS 글](/posts/ds-graph-bfs-dfs)에 있다. 층 단위로 내려가는 BFS를 처음 본 건 [Maximum Depth of Binary Tree](/posts/leetcode-maximum-depth-of-binary-tree)에서였는데, 거기서는 층 수만 셌고 여기서는 층마다 값을 모은다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 층마다 묶어서 돌려준다

이진 트리의 뿌리가 주어진다. 노드 값을 층별로 묶어 돌려준다. 바깥 배열의 i번째 칸에는 뿌리에서 i번 내려간 층의 노드 값이 왼쪽에서 오른쪽 순서로 들어간다. 빈 트리면 빈 배열이다.

노드 수는 0 이상 2000 이하다. 노드를 모두 한 번씩 담아야 하니 O(n)이 하한이고, 2000이라 O(n²)도 400만 번이라 돌기는 한다. 하지만 이 문제의 요점은 BFS를 정확히 쓰는 것이라 O(n)을 기대한다.

이 글 내내 쓸 트리다.

```text
[8, 4, 12, 2, 6, null, 14, null, null, 5]

          8
        /   \
       4     12
      / \      \
     2   6      14
        /
       5

답: [[8], [4, 12], [2, 6, 14], [5]]
```

셋째 층을 보자. 2와 6은 4의 자식이고 14는 12의 자식이다. 부모가 달라도 같은 층이면 한 배열에 들어간다. 그리고 6의 자식 5는 넷째 층이라, 2, 6, 14와 섞이면 안 된다. 이 두 가지, 다른 부모의 자식을 한데 모으는 것과 다음 층을 섞지 않는 것이 문제의 전부다.

## 층마다 뿌리부터 다시 내려가기

가장 단순한 생각은 이렇다. "d번째 층의 노드를 왼쪽부터 모아라"라는 함수가 있으면, d를 0부터 트리 높이까지 늘려 가며 부르면 된다. d번째 층을 모으는 함수는 재귀로 쉽게 짠다. 뿌리에서 d를 하나씩 줄이며 왼쪽, 오른쪽 순서로 내려가다 d가 0이 되는 노드를 담는다.

```js
function height(node) {
  return node ? 1 + Math.max(height(node.left), height(node.right)) : 0;
}

// node에서 d번 더 내려간 층의 노드를 왼쪽부터 level에 담는다
function collect(node, d, level) {
  if (!node) return;
  if (d === 0) { level.push(node.val); return; }
  collect(node.left, d - 1, level);
  collect(node.right, d - 1, level);
}

function levelOrder(root) {
  const result = [];
  const h = height(root);
  for (let d = 0; d < h; d++) {
    const level = [];
    collect(root, d, level); // 매번 뿌리부터 다시 내려간다
    result.push(level);
  }
  return result;
}
```

왼쪽을 먼저 부르니 같은 층 안에서는 왼쪽 노드가 먼저 담긴다. 다른 부모의 자식도 같은 d에서 담기니 한 배열에 모인다. 답은 맞다.

문제는 d번째 층을 모을 때마다 그 위의 모든 층을 다시 지나간다는 것이다. 층 하나에 최대 O(n), 층이 h개라 O(n·h)다. 균형 잡힌 트리라면 h가 log n이라 O(n log n)으로 견딜 만하지만, 한쪽으로 기운 트리는 h가 n이라 O(n²)이 된다.

```text
일자 트리 노드 2000개   rescan 52 ms    BFS 2.3 ms
일자 트리 노드 4000개   rescan 175 ms   BFS 2.8 ms
일자 트리 노드 8000개   rescan 633 ms   BFS 4.2 ms
```

노드가 두 배가 되면 시간이 세 배 반쯤 늘었다. 같은 위쪽 층을 몇 번씩 다시 밟는 게 낭비라면, 한 층을 볼 때 다음 층에 갈 노드를 미리 줄 세워 두면 된다. 그 줄이 큐다.

## 노드와 층 번호를 짝으로 줄 세우기

큐(queue)는 먼저 넣은 것을 먼저 꺼내는 줄이다. 뿌리를 넣고, 하나 꺼낼 때마다 그 자식들을 뒤에 넣으면 노드가 층 순서대로 나온다. 위층 노드의 자식이 아래층 노드보다 늘 먼저 줄에 서기 때문이다.

남은 문제는 꺼낸 노드가 몇 번째 층인지 아는 것이다. 가장 직접적인 방법은 노드를 넣을 때 층 번호도 같이 적어 두는 것이다. 자식의 층 번호는 부모 번호에 1을 더한 값이다.

```js
function levelOrder(root) {
  const result = [];
  if (!root) return result;
  const queue = [[root, 0]]; // [노드, 층 번호]
  // shift() 대신 head 인덱스로 앞에서 읽는다 (shift는 O(n))
  for (let head = 0; head < queue.length; head++) {
    const [node, depth] = queue[head];
    if (result.length === depth) result.push([]); // 새 층이 시작됐다
    result[depth].push(node.val);
    if (node.left) queue.push([node.left, depth + 1]);
    if (node.right) queue.push([node.right, depth + 1]);
  }
  return result;
}
```

큐에서 노드는 층 번호가 줄어들지 않는 순서로 나온다. 그래서 `result.length === depth`이면 처음 보는 층이고, 빈 배열을 하나 새로 연다.

시간 O(n), 공간 O(n)이다. 각 노드가 큐에 한 번 들어가고 한 번 나온다. 큐에는 노드마다 `[노드, 번호]` 짝 배열이 하나씩 더 만들어지는 게 아쉽다. 층 번호는 사실 따로 적지 않아도 큐의 모양에서 알 수 있다.

## 큐 길이를 먼저 세어 두고 그만큼만 꺼낸다

한 층을 다 꺼내기 직전의 순간을 생각해 보자. 큐에는 정확히 이번 층의 노드만 들어 있다. 위층은 다 꺼냈고, 이번 층 노드를 아직 하나도 안 꺼냈으니 그 자식들(다음 층)도 아직 안 들어왔다. 그러니 그 순간의 큐 길이가 곧 이번 층의 노드 수다.

그 길이를 `size`로 먼저 고정해 두고 `size`개만 꺼낸다. 꺼내는 동안 자식들이 뒤에 들어오지만, 그 노드들은 `size` 바깥이라 이번 층에 섞이지 않는다. `size`개를 다 꺼내면 큐에는 다음 층만 남는다. 처음 순간과 같은 상태로 돌아왔으니 같은 일을 반복하면 된다.

```js
function levelOrder(root) {
  const result = [];
  if (!root) return result;
  const queue = [root];
  let head = 0; // 큐의 앞. 이 앞쪽은 이미 꺼낸 노드다
  while (head < queue.length) {
    const size = queue.length - head; // 이번 층의 노드 수를 먼저 고정한다
    const level = [];
    for (let k = 0; k < size; k++) {
      const node = queue[head++];
      level.push(node.val);
      // 자식은 뒤에 붙는다. size 바깥이라 다음 층 몫이다
      if (node.left) queue.push(node.left);
      if (node.right) queue.push(node.right);
    }
    result.push(level);
  }
  return result;
}
```

아래 그림은 예시 트리에서 큐가 변하는 모습이다. 기억 칸이 큐이고 왼쪽이 다음에 꺼낼 앞쪽이다. 초록색 칸은 이미 층 배열에 담긴 노드다.

시간은 O(n)이다. 노드마다 큐에 한 번 넣고 한 번 꺼낸다. 공간은 결과 배열을 빼고 큐가 차지하는 만큼인데, 큐에는 많아야 한 층과 다음 층 일부가 동시에 들어 있다. 그래서 트리의 최대 너비 w에 비례하는 O(w)다. 꽉 찬 이진 트리는 마지막 층에 노드 절반이 몰려 O(n)이고, 일자 트리는 O(1)이다. 위 JavaScript 코드는 꺼낸 노드를 배열에서 지우지 않아 실제로는 n칸을 다 쓰지만, 진짜 큐(Python의 `deque`, Java의 `ArrayDeque`)를 쓰면 O(w)가 된다.

### JavaScript에서 `shift()`를 쓰면

JavaScript에는 기본 큐가 없어서 배열의 `shift()`로 앞에서 꺼내는 코드가 많다. `shift()`는 남은 원소를 한 칸씩 앞으로 당기는 연산이라 배열이 길면 O(n)이다. 작은 배열에서는 V8이 빠르게 처리해서 티가 안 나지만, 노드가 수만 개를 넘으면 갑자기 느려진다. [Maximum Depth 글](/posts/leetcode-maximum-depth-of-binary-tree)에서 꽉 찬 트리로 재 봤을 때 노드 6만 5천 개에서 `shift()` 큐가 2.7초, 머리 인덱스나 층 배열 교체는 2ms였다. 이 문제는 노드가 2000개 이하라 괜찮지만, 습관은 `head` 인덱스로 들이는 편이 좋다.

### Python과 Java로 쓰면

```python
from collections import deque
from typing import List, Optional

def level_order(root: Optional[TreeNode]) -> List[List[int]]:
    result = []
    if root is None:
        return result
    queue = deque([root])
    while queue:
        level = []
        for _ in range(len(queue)):  # range가 시작할 때 길이를 한 번만 읽는다
            node = queue.popleft()
            level.append(node.val)
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
        result.append(level)
    return result
```

Python의 `range(len(queue))`는 만들어지는 순간 길이를 한 번 읽고 끝이라, 반복 중에 큐가 길어져도 횟수가 바뀌지 않는다. `size` 변수를 따로 두지 않아도 되는 이유다. 큐는 꼭 `deque`를 쓴다. 리스트의 `pop(0)`은 JavaScript의 `shift()`처럼 O(n)이다. 노드 13만 개짜리 꽉 찬 트리로 재 봤다.

```text
deque.popleft()   35 ms
list.pop(0)       11292 ms
```

300배 넘게 차이가 난다.

```java
import java.util.*;

class Solution {
    public List<List<Integer>> levelOrder(TreeNode root) {
        List<List<Integer>> result = new ArrayList<>();
        if (root == null) return result;
        Deque<TreeNode> queue = new ArrayDeque<>();
        queue.offer(root);
        while (!queue.isEmpty()) {
            int size = queue.size(); // 이번 층의 노드 수를 먼저 고정한다
            List<Integer> level = new ArrayList<>(size);
            for (int k = 0; k < size; k++) {
                TreeNode node = queue.poll();
                level.add(node.val);
                if (node.left != null) queue.offer(node.left);
                if (node.right != null) queue.offer(node.right);
            }
            result.add(level);
        }
        return result;
    }
}
```

Java는 `for (int k = 0; k < queue.size(); k++)`처럼 조건 안에서 `size()`를 부르면 매번 다시 읽어서 경계가 무너진다. 반드시 바깥에서 `int size`로 고정한다. 그리고 `ArrayDeque`는 `null`을 넣으면 `NullPointerException`을 던진다. 자식을 확인하지 않고 `queue.offer(node.left)`를 하면 잎에서 바로 터진다. `LinkedList`는 `null`을 받아 주기 때문에 다른 사람 코드에서 `null`을 넣고 꺼낼 때 거르는 방식을 볼 수도 있는데, 그 코드를 `ArrayDeque`로 바꾸면 깨진다.


## 큐 대신 층 배열을 통째로 바꾸기

`size`를 세는 대신 "지금 층"과 "다음 층"을 아예 다른 배열로 둘 수도 있다. 지금 층 배열을 돌며 자식을 다음 층 배열에 모으고, 다 돌면 다음 층을 지금 층으로 바꾼다.

```js
function levelOrder(root) {
  const result = [];
  let level = root ? [root] : [];
  while (level.length) {
    result.push(level.map((node) => node.val)); // 이번 층 값
    const next = [];
    for (const node of level) {
      if (node.left) next.push(node.left);
      if (node.right) next.push(node.right);
    }
    level = next; // 다음 층으로 갈아탄다
  }
  return result;
}
```

복잡도는 똑같이 O(n) 시간, O(w) 공간이다. 큐의 앞뒤를 신경 쓸 필요가 없고 층 경계가 배열 경계와 같아서 실수할 곳이 없다. `shift()` 문제도 처음부터 생기지 않는다. 층 배열 전체를 한 번에 손에 쥐고 있으니 "이번 층의 마지막 노드", "이번 층의 합" 같은 걸 구하기도 쉽다. 대신 층마다 새 배열을 만든다. 실제로 큰 차이는 없어서, 면접에서는 `size` 방식과 이 방식 중 손에 익은 쪽을 쓰면 된다.

## 깊이를 들고 내려가며 칸에 꽂아 넣기

BFS가 아니어도 이 문제는 풀린다. 노드마다 몇 번째 층인지만 알면, 결과 배열의 그 층 칸에 값을 넣으면 되기 때문이다. 재귀로 내려가면서 깊이를 인자로 넘긴다.

```js
function levelOrder(root) {
  const result = [];
  function dfs(node, depth) {
    if (!node) return;
    if (result.length === depth) result.push([]); // 이 깊이는 처음 왔다
    result[depth].push(node.val);
    dfs(node.left, depth + 1);  // 왼쪽을 먼저
    dfs(node.right, depth + 1);
  }
  dfs(root, 0);
  return result;
}
```

방문 순서는 층 순서가 아니다. 8, 4, 2, 6, 5까지 왼쪽 갈래를 끝까지 내려간 뒤에 12로 간다. 그런데도 층 안의 순서가 맞는 이유가 있다. 같은 층의 두 노드 중 왼쪽 노드는 언제나 오른쪽 노드보다 먼저 방문된다. 둘이 갈라지는 공통 조상에서 왼쪽 자식을 먼저 부르기 때문이다. 그래서 각 층 배열에는 왼쪽부터 차례로 쌓인다.

시간은 O(n), 공간은 재귀 호출 스택이 O(h)다. BFS의 O(w)와 비교하면 넓고 얕은 트리에서는 DFS가, 좁고 깊은 트리에서는 BFS가 메모리를 덜 쓴다. 다만 문제의 노드 수 2000이면 일자 트리라도 재귀 깊이 2000이라, Python 기본 재귀 한도 1000을 넘는다. Python으로 이 풀이를 낼 때는 그걸 짚어 둔다.

이 풀이는 "층 순회 = BFS"라는 고정 관념을 깨는 데 의미가 있다. 결과가 층별로 묶여 있기만 하면 되므로 방문 순서는 상관없다. 반대로 "가장 가까운 잎을 찾으면 바로 멈춰라"처럼 층 순서대로 방문하는 것 자체가 필요하면 DFS로는 일찍 멈출 수 없다.

## 재귀 없이 스택으로 같은 일을 하기

DFS 풀이를 반복문으로 옮기면 스택에 `[노드, 깊이]`를 넣는다. 스택은 나중에 넣은 것이 먼저 나오니, 왼쪽을 먼저 방문하려면 오른쪽을 먼저 넣어야 한다.

```js
function levelOrder(root) {
  const result = [];
  const stack = root ? [[root, 0]] : [];
  while (stack.length) {
    const [node, depth] = stack.pop();
    if (result.length === depth) result.push([]);
    result[depth].push(node.val);
    // 오른쪽을 먼저 넣어야 왼쪽이 먼저 나온다
    if (node.right) stack.push([node.right, depth + 1]);
    if (node.left) stack.push([node.left, depth + 1]);
  }
  return result;
}
```

넣는 순서를 거꾸로 하면 층마다 오른쪽부터 쌓인다. 예시 트리에서 `[[8], [12, 4], [14, 6, 2], [5]]`가 나온다. 시간 O(n), 공간 O(h)이고, 호출 스택 대신 힙 메모리를 써서 깊은 트리에서도 터지지 않는다. 무작위 트리 5000개로 여섯 풀이의 결과가 모두 같은지 대조했다.

## 여섯 풀이를 나란히 놓으면

| 풀이 | 시간 | 추가 공간 | 언제 고르나 |
|---|---|---|---|
| 층마다 다시 내려가기 | O(n·h), 최악 O(n²) | O(h) | 특정 층 하나만 필요할 때 |
| 큐에 층 번호를 같이 넣기 | O(n) | O(w) | 노드마다 층 번호가 따로 필요할 때 |
| 큐 길이 고정 (size) | O(n) | O(w) | 기본 답. 다른 BFS 문제로 그대로 넓어진다 |
| 층 배열 교체 | O(n) | O(w) | 층 전체를 한 번에 다룰 때, JS에서 큐가 없을 때 |
| DFS 재귀 + 깊이 | O(n) | O(h) | 넓고 얕은 트리, 층 순서 방문 자체는 필요 없을 때 |
| DFS 스택 + 깊이 | O(n) | O(h) | 위와 같고 트리가 깊을 수 있을 때 |

h는 트리 높이, w는 가장 넓은 층의 노드 수다. 결과 배열 O(n)은 모든 풀이에 똑같이 들어서 표에서 뺐다.

## 층 경계가 무너지는 실수들

### 반복 조건에서 큐 길이를 매번 다시 읽는다

가장 흔한 실수다. `size`를 고정하지 않고 반복 조건에 큐 길이를 그대로 쓴다.

```js
// size를 고정하지 않은 코드
while (queue.length) {
  const level = [];
  for (let k = 0; k < queue.length; k++) { // 꺼내고 넣을 때마다 길이가 바뀐다
    const node = queue.shift();
    level.push(node.val);
    if (node.left) queue.push(node.left);
    if (node.right) queue.push(node.right);
  }
  result.push(level);
}
// 예시 트리 → [[8, 4, 12], [2, 6], [14], [5]]
```

첫 층에서 8을 꺼내면 길이가 0이 됐다가 4, 12가 들어와 2가 된다. `k`가 1이 되어도 `1 < 2`라 계속 돌고, 다음 층 노드까지 첫 층에 섞인다. 꺼내면서 줄고 넣으면서 늘어나는 길이와 증가하는 `k`가 엇갈려, 층 경계가 입력에 따라 아무렇게나 잘린다. 크기는 반복 전에 한 번만 읽는다.

### 스택에 왼쪽부터 넣는다

반복 DFS에서 습관대로 왼쪽, 오른쪽 순서로 넣으면 층 안의 순서가 뒤집힌다. 앞에서 본 `[[8], [12, 4], [14, 6, 2], [5]]`가 나온다. 재귀 DFS에서 오른쪽을 먼저 부르는 실수도 같은 결과를 낸다. 층별로 묶이긴 했으니 얼핏 맞아 보여서, 둘째 층에 노드가 둘 이상인 테스트로 꼭 확인한다.

### 빈 트리에서 `[[]]`를 돌려준다

뿌리가 없는데 큐에 `null`을 넣고 시작하면, 빈 층 하나가 결과에 들어가거나 `null.val`에서 터진다. 빈 트리의 답은 `[]`다. 처음에 `root`가 없으면 바로 빈 배열을 돌려준다.

## 면접관이 이어서 묻는 것

층 순회의 변형은 대부분 "층 배열을 받은 뒤 무엇을 하느냐"만 다르다. 예시 트리에서 실제로 돌린 결과와 함께 본다.

### 아래층부터, 지그재그로

LeetCode 107은 아래층부터 돌려 달라는 문제다. 결과를 다 만든 뒤 뒤집으면 된다. `[[5], [2, 6, 14], [4, 12], [8]]`. 앞에 끼워 넣는 `unshift`를 층마다 쓰면 O(층 수²)이니 마지막에 한 번 뒤집는다.

LeetCode 103 Zigzag는 홀수 층을 오른쪽부터 읽는다. 층 배열을 만든 뒤 홀수 번째만 뒤집으면 `[[8], [12, 4], [2, 6, 14], [5]]`다. 큐에 넣는 순서를 바꾸려 하면 다음 층 순서까지 엉키니, 꺼내는 순서는 그대로 두고 담는 쪽(덱의 앞이나 뒤)만 바꾸는 게 안전하다.

### 오른쪽에서 보이는 노드만

[Binary Tree Right Side View](/posts/leetcode-binary-tree-right-side-view)다. 각 층의 마지막 노드가 오른쪽에서 보이는 노드라 `[8, 12, 14, 5]`가 답이다. 5는 왼쪽 갈래에 있지만 넷째 층의 유일한 노드라서 오른쪽에서도 보인다. "오른쪽 자식만 따라 내려가면 된다"고 답하면 이 5를 놓친다. DFS로 풀면 오른쪽 자식을 먼저 방문하면서 각 깊이에 처음 도착한 노드를 기록한다.

### 층마다 평균, 최댓값

LeetCode 637은 층 평균(`[8, 8, 7.333…, 5]`), 515는 층 최댓값이다. 층 배열을 모은 다음 계산해도 되고, 메모리를 아끼려면 배열 대신 합과 개수만 들고 다닌다. 값이 커서 합이 넘칠 수 있는 Java라면 `long`이나 `double`로 더한다.

### 추가 공간 없이 같은 층끼리 잇기

LeetCode 116 Populating Next Right Pointers는 노드마다 같은 층의 오른쪽 이웃을 가리키는 `next`를 채운다. 큐로 하면 쉽지만 "O(1) 공간으로"가 꼬리 질문이다. 윗층이 이미 `next`로 이어져 있으면, 윗층을 연결 리스트처럼 왼쪽부터 걸으며 아래층을 이을 수 있다. 꽉 찬 트리 기준이다.

```js
function connect(root) {
  let leftmost = root;
  while (leftmost && leftmost.left) {
    for (let cur = leftmost; cur; cur = cur.next) {
      cur.left.next = cur.right;                     // 같은 부모의 두 자식
      if (cur.next) cur.right.next = cur.next.left;  // 옆 부모의 왼쪽 자식
    }
    leftmost = leftmost.left; // 다음 층의 맨 왼쪽
  }
  return root;
}
// [1, 2, 3, 4, 5, 6, 7] → 층마다 next로 걸으면 [[1], [2, 3], [4, 5, 6, 7]]
```

큐가 하던 "다음에 볼 같은 층 노드"를 윗층의 `next`가 대신한다.

### 트리가 아니라 격자나 그래프라면

BFS의 `size` 고정은 격자에서 "몇 걸음 만에 도착하나"를 셀 때 그대로 쓴다. 한 층이 한 걸음이다. 다만 그래프는 같은 노드에 여러 길로 도착할 수 있어서 방문 표시가 꼭 필요하다. 트리에는 사이클이 없어서 방문 표시 없이도 됐다. 이어지는 문제로 [Rotting Oranges](/posts/leetcode-rotting-oranges)와 [Word Ladder](/posts/leetcode-word-ladder)가 있다.

### 같은 패턴의 다음 문제

층 순서는 트리를 문자열로 저장할 때도 쓴다. LeetCode가 트리를 `[8, 4, 12, ...]`로 적는 방식이 바로 층 순회이고, 그걸 직접 구현하는 문제가 [Serialize and Deserialize Binary Tree](/posts/leetcode-serialize-and-deserialize-binary-tree)다. 트리 묶음의 앞 문제는 [Lowest Common Ancestor of a BST](/posts/leetcode-lowest-common-ancestor-of-bst)이고, 전체 순서는 [LeetCode 공부 가이드](/posts/leetcode-study-guide)에 있다.

## 지금 줄에 선 사람 수를 먼저 센다

층 순회는 큐에 뿌리를 넣고, 매 바퀴 시작할 때 큐 길이를 세어 고정한 다음 그만큼만 꺼내며 자식을 뒤에 넣는 것으로 끝난다. 그 순간 큐에는 정확히 한 층만 들어 있다는 게 이 방법이 맞는 이유다. 시간은 O(n), 공간은 가장 넓은 층만큼이다. 결과가 층별로 묶이기만 하면 되니 깊이를 들고 내려가는 DFS로도 풀리고, 그때는 왼쪽을 먼저 방문해야 층 안 순서가 맞는다. 변형 문제는 대부분 층 배열을 받은 뒤 마지막 것을 고르거나, 뒤집거나, 더하는 일이다.

## 면접에서 나올 만한 질문

### 왜 큐를 쓰나요?

먼저 넣은 노드를 먼저 꺼내니, 위층 노드의 자식이 아래층 노드보다 늘 먼저 줄에 선다. 그래서 노드가 층 순서대로, 같은 층에서는 왼쪽부터 나온다. 스택을 쓰면 나중에 넣은 자식이 먼저 나와 한 갈래를 끝까지 내려가는 DFS 순서가 된다.

### 층 경계는 어떻게 나누나요?

한 층을 꺼내기 직전에는 큐에 그 층의 노드만 들어 있으니, 그 순간의 큐 길이를 `size`로 고정하고 그만큼만 꺼낸다. 꺼내는 동안 들어오는 자식은 `size` 바깥이라 다음 층으로 남는다. 반복 조건에서 큐 길이를 매번 다시 읽으면 다음 층이 섞인다.

### 시간과 공간 복잡도는요?

노드마다 큐에 한 번 넣고 한 번 꺼내서 시간은 O(n)이다. 큐에는 많아야 한 층과 다음 층 일부가 들어 있어 추가 공간은 가장 넓은 층의 크기 w에 비례하고, 꽉 찬 트리면 O(n), 일자 트리면 O(1)이다. 결과 배열은 따로 O(n)이다.

### DFS로도 풀 수 있나요?

된다. 깊이를 인자로 넘기며 결과의 그 깊이 칸에 값을 넣으면 된다. 왼쪽 자식을 먼저 방문하면 같은 층에서 왼쪽 노드가 항상 먼저 도착해 순서가 맞는다. 공간은 O(w) 대신 O(h)라, 넓고 얕은 트리에서는 오히려 유리하다.

### JavaScript에서 `shift()`를 쓰면 안 되나요?

이 문제 크기(2000개)에서는 괜찮지만 큰 입력에서는 안 된다. `shift()`는 남은 원소를 당기는 O(n) 연산이라 큐가 길면 전체가 O(n²)에 가까워진다. 머리 인덱스를 두고 읽거나, 층마다 새 배열로 갈아타면 O(n)이 유지된다. Python의 `list.pop(0)`도 같은 문제라 `deque`를 쓴다.

### 오른쪽에서 보이는 노드만 구하라면요?

층 순회에서 각 층의 마지막 노드만 고르면 된다. 오른쪽 자식만 따라 내려가는 풀이는 틀린다. 오른쪽 갈래가 짧고 왼쪽 갈래가 더 깊으면, 그 깊은 층의 노드는 왼쪽에 있어도 오른쪽에서 보인다.

### 추가 공간 O(1)로 층을 이을 수 있나요?

노드에 `next` 포인터를 채우는 문제라면 가능하다. 윗층이 이미 `next`로 이어져 있으니, 윗층을 연결 리스트처럼 걸으며 각 노드의 두 자식과 옆 노드의 자식을 이으면 아래층이 이어진다. 큐가 하던 일을 윗층의 `next`가 대신해서 추가 공간이 상수다.
