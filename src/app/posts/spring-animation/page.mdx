이 어색함은 곡선이 아니라 모델에서 온다. `transition: transform 300ms ease-out`은 "300ms 동안 이 모양으로 가라"는 시간표다. 시간표에는 지금 속도라는 개념이 없다. 스프링 애니메이션은 시간표 대신 힘을 정한다. 목표 쪽으로 당기는 힘과 움직임을 붙잡는 힘이 있고, 매 프레임 그 힘으로 속도와 위치를 갱신한다. 그래서 중간에 목표가 바뀌어도 지금 속도가 그대로 이어진다.

## 매 프레임 힘을 다시 계산한다

스프링은 고등학교 물리의 용수철 그대로다. 목표 위치를 1, 지금 위치를 x라고 하자. 용수철은 목표에서 벗어난 만큼 되돌리는 힘을 낸다. 공기 저항 같은 감쇠는 지금 속도에 비례해서 반대로 민다.

```text
용수철 힘 = −stiffness × (x − 목표)
감쇠 힘   = −damping × v
가속도 a  = (용수철 힘 + 감쇠 힘) / mass
```

화면에서는 이걸 프레임마다 조금씩 적분한다. 가장 흔한 방법은 속도를 먼저 갱신하고 그 속도로 위치를 옮기는 반암시적 오일러(semi-implicit Euler)다.

```js
// 한 프레임 (dt초) 진행
const a = (-stiffness * (x - target) - damping * v) / mass;
v += a * dt;
x += v * dt;
```

stiffness 100, damping 10, mass 1인 스프링을 60fps(dt = 1/60초)로 0에서 1까지 보내면 첫 몇 프레임은 이렇다. 실제로 Node 22에서 돌린 값이다.

## 세 숫자가 정하는 성격

stiffness는 용수철의 세기다. 크면 목표로 빨리 튀어 간다. damping은 브레이크다. 크면 덜 출렁이고, 너무 크면 끈적하게 느리다. mass는 무게다. 무거우면 같은 힘에도 천천히 움직이고 한 번 움직이면 잘 안 멈춘다.

셋을 따로 외우기보다 두 개의 묶음으로 보는 편이 쉽다.

```text
고유 진동수   ω₀ = √(stiffness / mass)              얼마나 빨리 오가나
감쇠비        ζ  = damping / (2 × √(stiffness × mass))   얼마나 출렁이나
```

ζ가 1보다 작으면 목표를 지나쳤다 돌아오고(과소감쇠), 1이면 넘치지 않으면서 가장 빨리 도착하고(임계감쇠), 1보다 크면 넘치지 않고 느릿하게 다가간다(과감쇠). 아래 그림은 stiffness 100, mass 1에서 damping만 바꾼 곡선이다. 가로가 0~1000ms, 가운데 선이 목표다. 넘침과 1% 안에 들어오는 시간은 1ms 간격으로 적분해서 잰 값이다.

## 얼마나 넘치나

과소감쇠 스프링이 처음 넘치는 양은 ζ만으로 정해진다.

```text
넘침 비율 = exp(−ζπ / √(1 − ζ²))
```

ζ = 0.5면 exp(−0.5π / √0.75) ≈ 0.163, 즉 16.3%다. 1ms 간격으로 적분한 값이 16.2%였으니 거의 같다(작은 차이는 적분 오차다). stiffness 300·damping 10과 stiffness 100·damping 10·mass 3은 ζ가 둘 다 0.289라서 넘침도 둘 다 38.7%다. 넘침은 같고 속도만 다르다.

자주 쓰는 프리셋을 같은 방법으로 재 보면 이렇다. react-spring의 `config` 프리셋 값(react-motion에서 이어진 tension/friction 값)이고 mass는 1이다.

| 프리셋 | stiffness | damping | ζ | 넘침 | 1% 안에 드는 시간 |
|---|---|---|---|---|---|
| default | 170 | 26 | 0.997 | 0% | 509ms |
| gentle | 120 | 14 | 0.639 | 7.2% | 582ms |
| wobbly | 180 | 12 | 0.447 | 20.7% | 651ms |
| stiff | 210 | 20 | 0.690 | 4.9% | 450ms |
| slow | 280 | 60 | 1.793 | 0% | 923ms |

default가 사실상 임계감쇠라 넘치지 않는다는 점은 의외였다. 스프링 라이브러리를 쓴다고 다 출렁이는 게 아니다. 톡 튀는 느낌을 원하면 ζ를 0.5~0.7 사이로 내려야 한다.

직접 재 보자. 아래 함수는 1ms 간격으로 5초 동안 적분해서 넘침(%, 소수 첫째 자리)과 마지막으로 목표에서 1% 넘게 벗어나 있던 시각(ms)을 돌려준다. 테스트의 기댓값은 같은 코드를 Node 22에서 돌려 확인한 값이다.

## 중간에 목표가 바뀌는 순간

처음 장면으로 돌아가자. 메뉴가 0에서 1로 열리는 중에 150ms 시점에서 목표를 0으로 바꾼다. 스프링(170, 26)으로 Node에서 그대로 돌려 보면 이렇다.

```js
// 0 → 1로 가던 중 150ms에 목표를 0으로 바꾼다 (메뉴를 열다가 바로 닫는 상황)
const k = 170, c = 26, m = 1, dt = 0.001;
let x = 0, v = 0, target = 1;
const log = [];
let xAt150 = 0;
for (let i = 1; i <= 400; i++) {
  if (i === 151) target = 0;
  const a = (-k * (x - target) - c * v) / m;
  v += a * dt; x += v * dt;
  if (i === 150) xAt150 = x;
  if ([100, 150, 151, 160, 180, 200, 250, 300].includes(i)) log.push(`${String(i).padStart(3)}ms  x=${x.toFixed(3)}  v=${v.toFixed(2)}/s`);
}
console.log("spring(170, 26)\n" + log.join("\n"));
// 같은 순간 cubic-bezier(0.22, 1, 0.36, 1) 300ms 전환을 현재 위치에서 0으로 새로 시작하면
// 새 전환의 시작 속도 = (p1y / p1x) × 이동 거리 / 지속 시간
const from = xAt150; // 위 스프링이 150ms에 있던 위치
const v0 = (1 / 0.22) * (0 - from) / 0.3;
console.log(`cubic-bezier 300ms로 새로 시작: 150ms 직후 v=${v0.toFixed(2)}/s`);
```

## CSS만으로 흉내 내기

라이브러리 없이 CSS로 스프링 느낌을 내는 방법은 두 가지다.

첫째, y 제어점이 1을 넘는 `cubic-bezier`다. 디자인 시스템에 `cubic-bezier(0.34, 1.56, 0.64, 1)`을 spring이라는 이름으로 두는 경우가 많다. 이 곡선의 y를 촘촘히 훑어 보면 시간의 57.3% 지점에서 1.0978까지 올라간다. 약 9.8% 한 번 넘치고 끝이다. 3차 베지어는 한 번만 휠 수 있어서 넘쳤다가 아래로 다시 내려가는 출렁임은 만들 수 없다.

둘째, `linear()` 이징이다. 점을 여러 개 찍고 그 사이를 직선으로 잇는 이징 함수라서, 스프링을 미리 적분한 값을 그대로 넣을 수 있다. 위 적분 코드에서 50ms마다 값을 뽑아 문자열로 만든다.

```js
function springToLinear(k, c, m, durMs, stepMs) {
  const dt = 0.001;
  let x = 0, v = 0;
  const pts = [];
  for (let i = 0; i <= durMs; i++) {
    if (i % stepMs === 0) pts.push(+x.toFixed(3));
    const a = (-k * (x - 1) - c * v) / m;
    v += a * dt;
    x += v * dt;
  }
  pts[pts.length - 1] = 1; // 끝은 정확히 목표에 맞춘다
  return `linear(${pts.join(", ")})`;
}
console.log(springToLinear(180, 12, 1, 800, 50)); // wobbly, 800ms
```

```text
linear(0, 0.183, 0.551, 0.899, 1.122, 1.204, 1.182, 1.111, 1.035, 0.982, 0.959, 0.96, 0.973, 0.99, 1.002, 1.008, 1)
```

```css
.menu {
  transition: transform 800ms
    linear(0, 0.183, 0.551, 0.899, 1.122, 1.204, 1.182, 1.111, 1.035, 0.982, 0.959, 0.96, 0.973, 0.99, 1.002, 1.008, 1);
}
```

`linear()`은 250ms에 120.4까지 넘쳤다가 500ms에 95.9로 목표 아래까지 내려간다. 진짜 출렁임이다. cubic-bezier는 109.3까지 한 번 올라갔다 내려오기만 한다. `linear()` 지원은 크롬·엣지 113, 파이어폭스 112, 사파리 17.2 무렵부터다. 같은 크로미움에서 `CSS.supports("transition-timing-function", "linear(0, 1.2, 1)")`는 `true`였다.

한계도 분명하다. `linear()`은 결국 미리 그린 시간표라서 길이가 고정이고, 중간에 목표가 바뀌면 지금 속도를 모른 채 새 시간표로 갈아탄다. 처음 장면의 문제는 그대로 남는다. 한 번 들어오고 끝나는 등장 애니메이션에는 `linear()`로 충분하고, 사용자가 중간에 끼어들거나 손으로 던지는 움직임에는 진짜 스프링이 필요하다.

감쇠비를 직접 받는 쪽(SwiftUI, Compose)과 damping 계수를 받는 쪽(react-spring, Motion)은 숫자의 뜻이 다르다. dampingFraction 0.5는 ζ = 0.5지만 damping 0.5는 거의 브레이크가 없다는 뜻이다. 디자이너가 "iOS에서 0.7로 했어요"라고 하면 ζ = 0.7이니, stiffness 100·mass 1 기준 damping = 2 × 0.7 × √100 = 14로 옮긴다.

## 스프링이 맞지 않는 자리

스프링은 끝나는 시간이 정해지지 않는다. 그래서 몇 가지 실수가 따라온다.

정착을 기다렸다가 다음 동작을 허락하는 코드가 흔하다. `onRest`에서 버튼을 다시 켜면 1% 오차까지 기다리느라 사용자가 0.5초 넘게 못 누를 수 있다. 상호작용은 목표를 바꾸는 순간 바로 허락하고, 정착은 시각적인 마무리로만 둔다. 출렁임이 이미 눈에 안 보이는데 계속 적분하며 렌더링하는 것도 낭비다. 라이브러리들은 속도와 거리가 아주 작아지면 멈추는 기준(rest speed, rest delta)을 둔다.

넘침이 의미를 해치는 곳도 있다. 진행률 바가 100%를 넘었다 돌아오면 "넘쳤다"는 잘못된 정보를 준다. 툴팁이나 글자가 많은 패널이 출렁이면 읽기 어렵다. 이런 곳에는 ζ = 1 이상이나 평범한 ease-out을 쓴다. 그리고 움직임 줄이기 설정을 켠 사람에게는 넘침과 출렁임부터 없앤다. 스프링을 쓴다고 이 설정이 저절로 반영되지는 않는다. 확인 방법은 [애니메이션 성능과 접근성](/posts/animation-performance)에 정리했다.

## 시간표를 쓸지 힘을 쓸지

곡선 애니메이션은 시간표이고 스프링은 힘이다. 스프링은 stiffness, damping, mass로 정하고, 성격은 감쇠비 ζ 하나로 대부분 설명된다. ζ가 1 아래면 넘치고, 넘치는 양은 ζ만으로 정해지며, 멈추는 속도는 damping / 2mass가 정한다. 끝나는 시간이 고정된 등장 애니메이션은 cubic-bezier나 `linear()`로 충분하고, 중간에 끼어들거나 손으로 던지는 움직임에는 속도를 이어받는 진짜 스프링을 쓴다.

## 면접에서 나올 만한 질문

### 스프링 애니메이션과 cubic-bezier 애니메이션은 무엇이 다른가요?

cubic-bezier는 정해진 시간 동안 진행률을 어떤 모양으로 바꿀지 정한 시간표이고, 스프링은 목표로 당기는 힘과 감쇠를 정해 매 프레임 속도와 위치를 적분한다. 그래서 스프링은 끝나는 시간이 파라미터에서 결과로 나오고, 지금 속도를 상태로 갖고 있다. 중간에 목표가 바뀌거나 드래그 속도를 넘겨받을 때 움직임이 끊기지 않는 이유가 이 속도 상태다.

### stiffness, damping, mass는 각각 무엇을 바꾸나요?

stiffness는 목표로 당기는 힘의 세기, damping은 속도에 비례한 브레이크, mass는 같은 힘에 대한 반응의 둔함이다. 이 셋은 감쇠비 ζ = damping / (2√(stiffness × mass))로 묶이고, ζ가 1보다 작으면 넘치고 1이면 넘치지 않으면서 가장 빨리 도착한다. 출렁임이 사라지는 속도는 damping / 2mass로 정해져서 stiffness를 올려도 빨리 멈추지 않는다.

### 넘침(overshoot)은 어떻게 계산하나요?

과소감쇠 스프링의 첫 넘침 비율은 exp(−ζπ / √(1 − ζ²))로 ζ만의 함수다. ζ = 0.5면 약 16.3%이고, 1ms 간격으로 적분해 보면 16.2%로 거의 같다. 그래서 stiffness와 mass를 바꿔도 ζ가 같으면 넘치는 양은 같고 걸리는 시간만 달라진다.

### CSS만으로 스프링을 만들 수 있나요?

비슷하게는 된다. y 제어점이 1을 넘는 cubic-bezier는 한 번만 넘치고 끝나며, 출렁임까지 원하면 스프링을 미리 적분한 값을 `linear()` 이징에 점으로 넣는다. 크로미움에서 재 보면 `linear()`은 목표 위아래로 실제로 출렁인다. 다만 둘 다 길이가 고정된 시간표라서 중간에 목표가 바뀌거나 초기 속도를 넘겨받는 상황은 해결하지 못한다.

### 사용자가 애니메이션 도중에 방향을 바꾸면 왜 CSS 전환은 끊겨 보이나요?

CSS 전환은 지금 위치에서 새 시간표를 시작하면서 이전 속도를 버리기 때문이다. 계산해 보면 +3.60/s로 열리던 메뉴가 ease-out 300ms로 다시 닫히는 순간 시작 속도가 −8.88/s로 튄다. 스프링은 위치와 속도를 그대로 두고 목표만 바꾸므로 속도가 3.60, 1.86, −0.57처럼 이어진다.

### 스프링 애니메이션의 정착을 기다렸다가 다음 동작을 허락하면 왜 안 되나요?

스프링은 끝나는 시간이 정해지지 않아서 작은 오차 범위에 들어올 때까지 생각보다 오래 걸린다. 그동안 버튼을 막으면 사용자는 이미 멈춘 것처럼 보이는 화면에서 못 누르는 상태가 된다. 상호작용은 목표를 바꾸는 즉시 허락하고 정착은 시각적 마무리로만 둔다. 라이브러리의 rest 기준으로 아주 작은 움직임은 끊어서 렌더링 낭비도 줄인다.
