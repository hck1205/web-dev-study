메신저에서 복사한 글이 띄어쓰기 없이 `catsxdog`처럼 붙어 버렸다고 해 보자. 아는 단어로 최대한 끊어 보면 `cats`, `x`, `dog`가 되고, 사전에 없는 `x` 한 글자가 남는다. 이렇게 "사전 단어로 덮고 남는 글자 수를 가장 적게" 만드는 것이 [LeetCode 2707. Extra Characters in a String](https://leetcode.com/problems/extra-characters-in-a-string/)이다.

[Word Break](/posts/leetcode-word-break)가 "남김없이 끊을 수 있나"를 묻는다면, 이 문제는 "못 끊는 글자가 몇 개까지 줄어드나"를 묻는다. 예/아니요가 개수로 바뀌었을 뿐 뼈대는 같은 [동적 계획법](/posts/dynamic-programming)이다. 이 글은 모든 끊는 방법을 다 해 보는 재귀에서 시작해, 메모, 바텀업 두 방향, 그리고 시작 위치마다 [트라이](/posts/ds-trie)를 한 번만 내려가는 풀이까지 다섯 가지를 본다. 트라이 자체는 [Implement Trie](/posts/leetcode-implement-trie)에서 만들었으니 여기서는 쓰는 법에 집중한다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 사전 단어로 덮고 남는 글자 세기

입력은 문자열 `s`와 단어 목록 `dictionary`다. `s`를 겹치지 않는 조각들로 나누는데, 각 조각은 사전 단어이거나 어디에도 속하지 않는 남는 글자다. 남는 글자 수의 최솟값을 돌려준다.

- `s` 길이와 사전 단어 수는 각각 50 이하, 단어 하나의 길이도 50 이하.
- 모두 소문자이고 사전 단어는 서로 다르다.

입력이 아주 작다. 그래서 O(n³)도 넉넉히 통과한다. 그런데도 이 문제가 트라이 패턴에 있는 이유는 "시작 위치에서 이어지는 사전 단어를 모두 찾기"를 가장 깔끔하게 하는 도구가 트라이이기 때문이다. 면접에서는 "s가 10만 글자라면"으로 꼭 넘어간다.

이 글에서 쓸 예시다.

```text
s          = "catsxdog"
dictionary = [cat, cats, dog, do]
답         = 1
```

손으로 끊어 보자. 앞에서 `cat`을 쓰면 `s`가 남고, 그다음 `x`도 남는다. 뒤의 `dog`까지 덮으면 남는 글자는 `s`, `x` 두 개다. `cats`를 쓰면 `x` 하나만 남는다. 뒤쪽도 `do`를 쓰면 `g`가 남으니 `dog`가 낫다.

여기서 두 가지가 보인다. 같은 자리에서 시작하는 사전 단어가 여러 개일 수 있다(`cat`과 `cats`, `do`와 `dog`). 그리고 그중 무엇이 좋은지는 그 뒤가 어떻게 끊기느냐에 달려 있다. 앞에서 바로 정할 수 없으니 뒤의 답을 알아야 한다. DP가 필요한 이유다.

## 끊는 방법을 전부 해 보는 재귀

위치 `i`에 섰다고 하자. 할 수 있는 일은 두 가지다.

1. `s[i]`를 남는 글자로 버리고 `i + 1`로 간다. 비용 1.
2. `s[i..j-1]`이 사전 단어면 그 단어로 덮고 `j`로 간다. 비용 0.

이 둘 중 가장 작은 쪽이 답이다. 끝(`i === n`)에 닿으면 남는 글자가 더 없으니 0이다.

```js
function minExtraChar(s, dictionary) {
  const dict = new Set(dictionary);
  const go = (i) => {
    if (i === s.length) return 0;
    let best = 1 + go(i + 1); // s[i]를 남는 글자로 버린다
    for (let j = i + 1; j <= s.length; j++) {
      // s[i..j-1]이 사전 단어면 그 단어로 덮고 j로 간다
      if (dict.has(s.slice(i, j))) best = Math.min(best, go(j));
    }
    return best;
  };
  return go(0);
}
```

`catsxdog`에는 1이 나온다. 답은 맞는데, 같은 `go(i)`를 여러 길에서 계속 다시 부른다. `go(4)`는 `cats`로 덮고 온 길에서도, `cat`을 쓰고 `s`를 버리고 온 길에서도 불린다.

얼마나 나빠지는지 재 보았다. `s = "aaa…a"`, 사전이 `[a, aa]`일 때 `go`를 부른 횟수다.

```text
n = 5   ->  119
n = 10  ->  9800
n = 15  ->  803760
```

n이 5 늘 때마다 80배쯤 커진다. 위치마다 "버리기", "a로 덮기", "aa로 덮기" 세 갈래가 생기니 지수로 늘어난다. n = 50이면 끝나지 않는다.

시간은 O(3^n) 근처의 지수, 공간은 재귀 깊이 O(n)이다. 같은 `i`의 답은 어느 길로 왔든 같으니, 한 번 구한 값을 적어 두면 된다.

## 같은 자리를 다시 풀지 않게 적어 두기

`go(i)`의 답은 `i`에만 달려 있다. 앞에서 무엇을 했든 `s[i..]`를 가장 잘 끊는 방법은 같다. 그래서 `i`마다 답을 한 번만 계산해 배열에 적어 둔다. 탑다운 메모다.

```js
function minExtraChar(s, dictionary) {
  const dict = new Set(dictionary);
  const n = s.length;
  const cache = new Array(n + 1).fill(-1); // -1은 아직 안 구했다는 뜻
  const go = (i) => {
    if (i === n) return 0;
    if (cache[i] !== -1) return cache[i];
    let best = 1 + go(i + 1);
    for (let j = i + 1; j <= n; j++) {
      if (dict.has(s.slice(i, j))) best = Math.min(best, go(j));
    }
    return (cache[i] = best);
  };
  return go(0);
}
```

`go(i)`는 위치마다 한 번만 본문을 돈다. 본문에서는 `j`를 n번까지 돌고, 돌 때마다 `s.slice(i, j)`로 길이 최대 n인 문자열을 새로 만들어 해시를 계산한다. 그래서 시간은 O(n³)이다. 공간은 `cache` O(n)과 재귀 깊이 O(n), 사전 집합 O(D·L)이다(D는 단어 수, L은 단어 최대 길이).

캐시 초깃값을 0으로 두면 안 된다. 답이 진짜 0인 칸(그 뒤가 사전 단어로 다 덮이는 칸)을 "안 구함"과 구별하지 못해서 다시 계산한다. 답은 맞지만 지수 시간으로 돌아간다. -1처럼 답이 될 수 없는 값을 쓴다.

재귀는 n이 50이면 아무 문제가 없지만, n이 10만이 되면 JS와 Python 모두 호출 스택이 넘친다. 그래서 같은 식을 반복문으로 바꾼다.

## 앞에서부터 채우는 표와 끝에서부터 채우는 표

바텀업으로 바꾸는 방법은 두 가지다. 어느 쪽을 "부분 문제"로 잡느냐가 다르다.

### 앞 i글자로 잡으면 단어가 끝나는 자리를 본다

`dp[i]`를 "`s`의 앞 `i`글자만 보았을 때 남는 글자의 최솟값"으로 잡는다. `dp[0] = 0`이다. `dp[i]`를 구할 때는 마지막 글자 `s[i-1]`을 보고 정한다.

- 마지막 글자를 버린다: `dp[i - 1] + 1`
- 어떤 사전 단어 `w`가 `i`에서 끝난다: `dp[i - w.length]`

사전 단어마다 "이 단어가 여기서 끝나나"를 `startsWith(w, i - w.length)`로 직접 확인한다. 사전이 작을 때 가장 짧게 쓸 수 있는 풀이다.

```js
function minExtraChar(s, dictionary) {
  const n = s.length;
  const dp = new Array(n + 1).fill(0); // dp[i] = 앞 i글자에서 남는 글자 최소 수
  for (let i = 1; i <= n; i++) {
    dp[i] = dp[i - 1] + 1; // s[i-1]을 버린다
    for (const w of dictionary) {
      // w가 위치 i에서 끝나면, w 앞까지의 답을 그대로 가져온다
      if (w.length <= i && s.startsWith(w, i - w.length)) {
        dp[i] = Math.min(dp[i], dp[i - w.length]);
      }
    }
  }
  return dp[n];
}
```

위치 n개마다 단어 D개를 길이 L까지 비교하니 시간은 O(n·D·L), 공간은 O(n)이다. 집합을 만들 필요도 없다. 사전이 수천 개로 커지면 위치마다 사전 전체를 훑는 게 부담이 된다. 맞을 가능성이 없는 단어(첫 글자부터 다른 단어)까지 다 비교하기 때문이다.

### 뒤 i글자로 잡으면 단어가 시작하는 자리를 본다

이번에는 `dp[i]`를 "`s[i..]`를 끊었을 때 남는 글자의 최솟값"으로 잡는다. 탑다운 메모의 `go(i)`와 같은 뜻이다. `dp[n] = 0`에서 시작해 `i`를 n-1부터 0까지 내려온다.

```js
function minExtraChar(s, dictionary) {
  const dict = new Set(dictionary);
  const n = s.length;
  const dp = new Array(n + 1).fill(0); // dp[n] = 0
  for (let i = n - 1; i >= 0; i--) {
    dp[i] = dp[i + 1] + 1; // s[i]를 버린다
    for (let j = i + 1; j <= n; j++) {
      // s[i..j-1]이 사전 단어면 그 뒤 dp[j]를 가져온다
      if (dict.has(s.slice(i, j))) dp[i] = Math.min(dp[i], dp[j]);
    }
  }
  return dp[0];
}
```

메모와 같은 O(n³) 시간, O(n + D·L) 공간이고 재귀가 없다. 두 방향 모두 답은 같다. 무작위 입력 3,000개로 다섯 풀이를 서로 비교했을 때 한 번도 어긋나지 않았다.

방향을 굳이 뒤로 잡은 데는 이유가 있다. `i`에서 "시작하는" 단어를 찾는 일은 `s[i]`, `s[i+1]`, …을 차례로 읽으며 트라이를 내려가는 일과 정확히 같다. 앞으로 잡으면 "끝나는" 단어를 찾아야 해서 트라이를 뒤집어 만들어야 한다. 다음 풀이가 이 방향을 쓴다.

이 풀이에 남은 낭비는 `j` 루프다. `s[i..j-1]`이 사전 단어의 앞부분조차 아니어도, 예를 들어 `xd`로 시작하는 단어가 하나도 없는데도 `j`를 끝까지 돌며 문자열을 만들고 해시를 계산한다.

## 시작 위치마다 트라이를 한 번만 내려가기

`i`에서 시작하는 사전 단어를 모두 찾고 싶다. 사전을 트라이로 만들어 두면 이렇게 된다.

1. 뿌리에서 출발해 `s[i]`, `s[i+1]`, …을 한 글자씩 따라 내려간다.
2. 내려간 노드에 끝 표시가 있으면 `s[i..j]`가 사전 단어다. `dp[j + 1]`로 후보를 갱신한다.
3. 자식이 없으면 그 뒤로는 어떤 사전 단어도 이어지지 않으니 바로 멈춘다.

3번이 핵심 이득이다. `xd`로 시작하는 단어가 없으면 `x`에서 한 칸 만에 끝난다. 그리고 문자열을 새로 만들지도, 해시를 계산하지도 않는다. 글자 하나를 읽을 때마다 자식 하나를 따라갈 뿐이다.

[Replace Words](/posts/leetcode-replace-words)에서는 처음 만난 끝 표시에서 멈췄다. 여기서는 멈추면 안 된다. `cat`의 끝 표시를 지나 `cats`까지 가야 더 좋은 답이 보인다. 끝 표시를 만나도 기록만 하고 자식이 끊길 때까지 계속 내려간다.

```js
function minExtraChar(s, dictionary) {
  // 1. 사전으로 트라이를 만든다. 노드는 글자 -> 자식 객체, end는 단어 끝 표시
  const root = {};
  for (const w of dictionary) {
    let node = root;
    for (const ch of w) node = node[ch] ??= {};
    node.end = true;
  }

  // 2. dp[i] = s[i..]에서 남는 글자 최소 수. 끝에서부터 채운다
  const n = s.length;
  const dp = new Array(n + 1).fill(0);
  for (let i = n - 1; i >= 0; i--) {
    dp[i] = dp[i + 1] + 1; // s[i]를 버리는 경우
    let node = root;
    for (let j = i; j < n; j++) {
      node = node[s[j]];
      if (!node) break; // 이 앞부분으로 시작하는 사전 단어가 없다
      if (node.end) dp[i] = Math.min(dp[i], dp[j + 1]); // s[i..j]가 사전 단어
    }
  }
  return dp[0];
}
```

트라이를 만드는 데 사전 글자 수 합만큼, O(D·L)이 든다. DP는 위치마다 많아야 min(n, L)칸 내려가니 O(n·min(n, L))다. 문자열 생성과 해시 계산이 없어서 같은 O(n²)라도 상수가 작다. 공간은 트라이 O(D·L)과 `dp` O(n)이다.

자식을 객체 대신 26칸 배열로 들 수도 있다. 소문자만 나온다는 조건이 있으니 Java처럼 배열이 빠른 언어에서는 배열이 낫다. JS에서는 객체로 써도 이 크기에서는 차이가 보이지 않는다. 자식 표현의 장단점은 [Implement Trie](/posts/leetcode-implement-trie)에서 재 보았다.

### Python과 Java로 쓰면

Python은 딕셔너리 트라이가 가장 자연스럽다. 끝 표시를 글자가 아닌 키 `"$"`로 넣으면 노드 하나로 자식과 끝 표시를 함께 든다.

```python
from typing import List

class Solution:
    def minExtraChar(self, s: str, dictionary: List[str]) -> int:
        root = {}
        for w in dictionary:
            node = root
            for ch in w:
                node = node.setdefault(ch, {})
            node["$"] = True  # 단어 끝 표시

        n = len(s)
        dp = [0] * (n + 1)
        for i in range(n - 1, -1, -1):
            dp[i] = dp[i + 1] + 1  # s[i]를 남는 글자로 버린다
            node = root
            for j in range(i, n):
                node = node.get(s[j])
                if node is None:
                    break
                if "$" in node:
                    dp[i] = min(dp[i], dp[j + 1])
        return dp[0]
```

`"$"`는 소문자가 아니라서 글자 자식과 겹치지 않는다. 대신 입력에 `$`가 나올 수 있는 변형에서는 이 방식을 쓰면 안 되고, `end` 필드를 따로 둔 클래스로 바꾼다. Python에는 재귀 깊이 기본 한도가 1,000이라서 탑다운 메모를 쓰면 n이 1,000을 넘을 때 `RecursionError`가 난다. 바텀업은 이 걱정이 없다.

Java는 26칸 배열 노드로 쓴다.

```java
class Solution {
    private static class Node {
        Node[] next = new Node[26];
        boolean end;
    }

    public int minExtraChar(String s, String[] dictionary) {
        Node root = new Node();
        for (String w : dictionary) {
            Node node = root;
            for (char ch : w.toCharArray()) {
                int c = ch - 'a';
                if (node.next[c] == null) node.next[c] = new Node();
                node = node.next[c];
            }
            node.end = true;
        }
        int n = s.length();
        int[] dp = new int[n + 1]; // 0으로 초기화되어 dp[n] = 0
        for (int i = n - 1; i >= 0; i--) {
            dp[i] = dp[i + 1] + 1;
            Node node = root;
            for (int j = i; j < n; j++) {
                node = node.next[s.charAt(j) - 'a'];
                if (node == null) break;
                if (node.end) dp[i] = Math.min(dp[i], dp[j + 1]);
            }
        }
        return dp[0];
    }
}
```

세 언어 모두 예시 `catsxdog`에 1, `sayhelloworld`와 `[hello, world]`에 3, `a`와 `[b]`에 1, `aaaa`와 `[aa, aaa]`에 0을 냈다. 답이 n을 넘지 않으니 오버플로 걱정은 없다. Java의 `int[]`가 0으로 초기화된다는 점 덕분에 `dp[n] = 0`을 따로 쓰지 않아도 된다.

## 다섯 풀이를 한 줄씩 대 보면

n은 `s` 길이, D는 사전 단어 수, L은 단어 최대 길이다.

| 풀이 | 시간 | 공간 | 언제 고르나 |
|---|---|---|---|
| 끊는 방법 전부 재귀 | 지수 | O(n) | 점화식을 세울 때 출발점으로만 |
| 탑다운 메모 + 집합 | O(n³) | O(n + D·L) | 재귀로 생각하는 게 편하고 n이 작을 때 |
| 앞에서 채우기 + 단어마다 비교 | O(n·D·L) | O(n) | 사전이 아주 작을 때. 코드가 가장 짧다 |
| 뒤에서 채우기 + 집합 | O(n³) | O(n + D·L) | 트라이 없이 바텀업으로 쓸 때 |
| 뒤에서 채우기 + 트라이 | O(D·L + n·min(n, L)) | O(n + D·L) | 면접 기본 답. n이나 D가 커져도 버틴다 |

이 문제의 제약(모두 50 이하)에서는 다섯 중 재귀만 빼면 모두 통과한다. 면접에서는 메모나 집합 바텀업을 먼저 말하고, "j 루프가 사전과 상관없는 앞부분까지 다 본다"는 낭비를 짚은 뒤 트라이로 넘어가는 흐름이 자연스럽다.

## 2,000글자로 늘려 재 보면

제약 안에서는 차이가 보이지 않는다. 그래서 `s`를 `a`, `b`, `c`로 된 무작위 문자열로 늘리고, 사전은 길이 2~10인 무작위 단어 47개로 두고 Node.js 22에서 재 보았다. 네 풀이 모두 같은 답을 냈다.

```text
n = 50     메모 0.094ms   앞에서+단어 비교 0.024ms   뒤에서+집합 0.074ms   트라이 0.019ms
n = 2000   메모 2324ms    앞에서+단어 비교 1.355ms   뒤에서+집합 2329ms    트라이 0.271ms
```

n이 40배 커지자 집합을 쓰는 두 풀이는 2초를 넘겼다. `j`를 끝까지 돌며 길이 최대 2,000인 문자열을 만들고 해시를 계산하니 O(n³)이 그대로 드러난다. 사전 단어가 10글자를 넘지 않는다는 걸 알면서도 `s.slice(i, 2000)`까지 만드는 셈이다.

트라이는 0.27ms다. `a`, `b`, `c` 세 글자뿐이라 자식이 잘 끊기지 않는데도 단어 길이 10을 넘겨 내려갈 길이 없으니 위치마다 10칸 안에서 멈춘다. 앞에서 채우고 단어마다 비교하는 풀이도 1.4ms로 빠르다. 위치마다 단어 47개를 많아야 10글자씩 비교하니 O(n·D·L)이 작다. 사전이 수천 개가 되면 이 풀이가 먼저 느려진다.

집합 풀이를 살리는 방법도 있다. `j`의 끝을 `Math.min(n, i + L)`로 막으면 쓸데없이 긴 문자열을 만들지 않는다. 그래도 위치마다 길이 L까지의 문자열을 L개 만드니 O(n·L²)이고, 트라이는 같은 일을 문자열 없이 O(n·L)로 한다.

## 눈앞의 가장 긴 단어를 덮으면 틀린다

가장 흔한 실수는 DP 대신 탐욕(greedy)으로 푸는 것이다. "지금 자리에서 맞는 가장 긴 사전 단어로 덮고 넘어간다, 없으면 한 글자 버린다."

```js
function minExtraChar(s, dictionary) {
  let i = 0, extra = 0;
  while (i < s.length) {
    let best = 0;
    for (const w of dictionary) if (s.startsWith(w, i)) best = Math.max(best, w.length);
    if (best) i += best; // 가장 긴 단어로 덮고 넘어간다
    else { extra++; i++; }
  }
  return extra;
}
// s = "abcd", dictionary = [ab, bcd] -> 2 (정답은 1)
```

`ab`로 덮으면 `c`, `d`가 남아 2가 된다. 정답은 `a`를 버리고 `bcd`로 덮는 1이다. 앞에서 단어를 쓰는 선택이 뒤에서 더 긴 단어를 쓸 기회를 빼앗는다. 그래서 "버린다"와 "덮는다"를 모두 해 보고 뒤의 답과 함께 비교해야 한다. 위 테스트의 "가장 긴 단어부터 덮으면 손해"가 이걸 잡는다.

두 번째는 [Replace Words](/posts/leetcode-replace-words) 습관대로 첫 끝 표시에서 멈추는 것이다.

```js
for (let j = i; j < n; j++) {
  node = node[s[j]];
  if (!node) break;
  if (node.end) { dp[i] = Math.min(dp[i], dp[j + 1]); break; } // 여기서 멈추면 안 된다
}
// s = "catsxdog" -> 3 (정답은 1)
```

`i = 5`에서 `do`에서 멈추니 `dog`를 놓쳐 `dp[5] = 1`이 되고, `i = 0`에서도 `cat`에서 멈춰 `cats`를 놓친다. 두 번 손해를 봐서 3이 나온다.

그 밖에 조심할 것들이다.

- `dp[i]`를 `Infinity`로 시작하고 "버리기" 후보 `dp[i + 1] + 1`을 빼먹으면, 사전 단어가 하나도 시작하지 않는 자리에서 답이 `Infinity`로 남는다. "버리기"는 언제나 가능한 선택이라 그게 기본값이다.
- 트라이 없이 `dict.has(s.slice(i, j))`를 쓸 때 `j`의 끝을 `n`이 아니라 `n - 1`로 잡으면 마지막 글자까지 가는 단어(`dog`)를 놓친다. `slice`의 끝은 포함하지 않으니 `j <= n`까지 돈다.
- 탑다운에서 캐시 초깃값을 0으로 두면 답이 0인 칸을 계속 다시 계산한다(위의 메모 풀이 참고).

## 조건을 바꾸어 묻는 꼬리 질문

### s가 10만 글자, 사전 단어가 짧다면

트라이 풀이는 위치마다 많아야 L칸 내려가니 O(n·L)이다. L이 50이면 500만 번이라 충분하다. 문제는 메모 풀이다. 재귀 깊이가 10만이 되어 스택이 넘치니 바텀업으로 쓴다. 집합 바텀업은 `j`를 `i + L`까지만 돌게 막으면 O(n·L²)로 버틸 수 있다.

### 사전 단어도 길고 많다면

트라이를 내려가는 길이가 길어지는 건 막을 수 없지만, 같은 앞부분을 공유하는 단어가 많으면 트라이가 그 공유분을 한 번만 걷게 해 준다. 시작 위치마다 내려가는 대신 `s` 전체를 한 번 훑으며 모든 사전 단어의 등장 위치를 찾는 아호-코라식(Aho-Corasick)도 있다. 등장 위치 목록을 얻으면 "`i`에서 시작하는 단어" 목록이 되니 DP는 그대로 쓴다. 아호-코라식은 [문자열 검색 글](/posts/string-search-algorithms)에서 다룬다.

### 남는 글자 수가 아니라 실제로 어떻게 끊는지 돌려 달라면

`dp[i]`를 갱신할 때 "어디로 갔는지"(`j + 1`, 버렸으면 `i + 1`)를 `next[i]`에 같이 적는다. 끝나고 나서 `i = 0`부터 `next`를 따라가면 끊는 방법 하나가 나온다. 모든 끊는 방법을 돌려 달라면 개수가 지수로 늘 수 있으니 백트래킹으로 넘어간다([Word Break II](https://leetcode.com/problems/word-break-ii/), 140번).

```js
function splitWithExtra(s, dictionary) {
  const root = {};
  for (const w of dictionary) {
    let node = root;
    for (const ch of w) node = node[ch] ??= {};
    node.end = true;
  }
  const n = s.length;
  const dp = new Array(n + 1).fill(0);
  const next = new Array(n).fill(0); // i에서 고른 다음 위치
  for (let i = n - 1; i >= 0; i--) {
    dp[i] = dp[i + 1] + 1;
    next[i] = i + 1; // 기본은 s[i]를 버린다
    let node = root;
    for (let j = i; j < n; j++) {
      node = node[s[j]];
      if (!node) break;
      if (node.end && dp[j + 1] < dp[i]) {
        dp[i] = dp[j + 1];
        next[i] = j + 1;
      }
    }
  }
  const pieces = [];
  for (let i = 0; i < n; i = next[i]) {
    const piece = s.slice(i, next[i]);
    // 한 글자짜리 조각 중 사전 단어가 아닌 것은 남는 글자다
    pieces.push(next[i] === i + 1 && !dictionary.includes(piece) ? `(${piece})` : piece);
  }
  return { extra: dp[0], pieces };
}
splitWithExtra("catsxdog", ["cat", "cats", "dog", "do"]);
// { extra: 1, pieces: [ 'cats', '(x)', 'dog' ] }
splitWithExtra("sayhelloworld", ["hello", "world"]);
// { extra: 3, pieces: [ '(s)', '(a)', '(y)', 'hello', 'world' ] }
```

`dp[j + 1] < dp[i]`처럼 엄격히 작을 때만 바꾸면 같은 값이면 먼저 본 쪽(버리기, 그다음 짧은 단어)이 남는다. 같은 값일 때 긴 단어를 고르고 싶다면 `<=`로 바꾼다. 어느 쪽이든 남는 글자 수는 같다.

### 남김없이 끊을 수 있는지만 묻는다면

답이 0인지 보면 된다. 그게 [Word Break](/posts/leetcode-word-break)(139번)다. 전용 풀이는 `dp`를 불리언으로 두고, 하나라도 참이 되면 바로 멈출 수 있어서 조금 더 빠르다.

### 버린 글자마다 비용이 다르다면

`dp[i + 1] + 1`의 1을 `cost[i]`로 바꾸면 끝이다. 사전 단어를 쓸 때도 비용이 있다면 `dp[j + 1] + wordCost` 같은 식으로 더한다. 뼈대가 "최솟값 DP"라서 비용 모양이 바뀌어도 그대로 간다.

## 버리기와 덮기를 뒤에서부터 비교한다

`dp[i]`는 "여기부터 끝까지 남는 글자의 최솟값"이고, 매번 "이 글자를 버린다"와 "여기서 시작하는 사전 단어로 덮는다"를 비교한다. 여기서 시작하는 사전 단어는 트라이를 `s[i]`부터 따라 내려가며 찾고, 끝 표시를 만나도 멈추지 않으며, 자식이 끊기면 멈춘다. 눈앞의 가장 긴 단어를 고르는 탐욕은 틀린다는 것까지 기억하면 이 문제는 끝이다.

## 면접에서 나올 만한 질문

### 왜 탐욕이 아니라 DP인가요?

지금 자리에서 단어를 고르는 선택이 뒤에서 쓸 수 있는 단어를 바꾸기 때문이다. `abcd`와 `[ab, bcd]`에서 가장 긴 `ab`를 쓰면 2가 남지만, `a`를 버리고 `bcd`를 쓰면 1이 남는다. 그래서 위치마다 "버리기"와 "여기서 시작하는 모든 단어"를 다 해 보고 뒤의 최적값과 함께 비교해야 하고, 뒤의 최적값이 위치에만 달려 있어서 DP로 묶인다.

### 점화식을 말해 보세요.

`dp[i]`를 `s[i..]`에서 남는 글자의 최솟값으로 둔다. `dp[n] = 0`이고, `dp[i] = min(dp[i + 1] + 1, s[i..j]가 사전 단어인 사전 단어가 되는 j마다 dp[j + 1])`이다. 앞 i글자 기준으로 잡아도 되는데, 그때는 `i`에서 끝나는 단어를 봐야 한다.

### 트라이를 쓰면 무엇이 좋아지나요?

`i`에서 시작하는 사전 단어를 찾을 때 문자열을 잘라 해시를 계산하지 않고 글자 하나에 자식 하나만 따라간다. 그리고 사전 단어의 앞부분조차 아닌 순간 바로 멈춘다. 집합 풀이는 O(n³)이지만 트라이는 O(D·L + n·min(n, L))이고, 단어가 짧으면 거의 O(n·L)이다.

### Replace Words처럼 첫 끝 표시에서 멈추면 안 되나요?

안 된다. Replace Words는 가장 짧은 어근을 원해서 첫 끝 표시가 답이지만, 여기서는 그 단어 뒤의 `dp` 값이 더 작은 다른 단어가 있을 수 있다. `catsxdog`에서 `cat`에서 멈추면 `cats`를 놓친다. 끝 표시는 후보로 기록만 하고 자식이 끊길 때까지 내려간다.

### 시간과 공간 복잡도는요?

트라이 풀이는 트라이를 만드는 데 O(D·L), DP는 위치마다 많아야 min(n, L)칸이라 O(n·min(n, L))이다. 공간은 트라이 노드 수 O(D·L)과 `dp` 배열 O(n)이다. 이 문제의 제약이 모두 50이라 실제로는 몇천 번 연산이다.

### 공간을 더 줄일 수 있나요?

`dp`는 `dp[i]`를 구할 때 `dp[i + 1]`부터 `dp[i + L]`까지만 쓰니, 길이 L + 1짜리 원형 버퍼로 줄일 수 있다. 하지만 트라이가 O(D·L)을 차지해서 전체 공간은 크게 줄지 않는다. 트라이가 부담이면 앞에서 채우는 풀이처럼 사전을 그대로 훑는 쪽으로 돌아가 시간과 맞바꾼다.

### 끊는 방법까지 돌려 달라면요?

`dp[i]`를 갱신할 때 고른 다음 위치를 `next[i]`에 같이 적고, 끝나고 나서 0부터 따라가며 조각을 모은다. 시간과 공간 복잡도는 그대로다. 가능한 끊는 방법을 전부 달라면 개수가 지수일 수 있어서 백트래킹으로 바꾼다.
