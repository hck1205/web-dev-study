[Maximum Product Subarray](https://leetcode.com/problems/maximum-product-subarray/)는 LeetCode 152번이다. 이어진 구간의 합을 최대로 하는 Maximum Subarray(53번)를 곱셈으로 바꾼 문제인데, 음수와 0 때문에 합에서 쓰던 카데인 알고리즘(Kadane, 지금 칸에서 끝나는 최댓값 하나만 들고 걷는 방법)을 그대로 옮기면 틀린다. 고치는 방법은 "가장 작은 값도 함께 들고 다닌다"는 한 줄이고, 그 한 줄이 왜 필요한지가 이 문제의 전부다.

카데인 알고리즘의 원래 모양은 [Best Time to Buy and Sell Stock](/posts/leetcode-best-time-to-buy-and-sell-stock)에서 다뤘고, DP의 기본은 [동적 계획법 글](/posts/dynamic-programming)에 있다. 이 글은 모든 구간을 곱해 보는 풀이부터 0으로 자르고 음수 개수를 세는 풀이, 앞뒤로 한 번씩 곱하는 풀이, 최댓값·최솟값 DP까지 여섯 가지를 놓는다. 코드는 Node.js 22, Python 3, Java 21에서 직접 돌렸다.

## 이어진 구간의 곱 중 가장 큰 값

정수 배열 `nums`에서 비어 있지 않은 연속 구간을 하나 골라 그 구간의 원소를 모두 곱한다. 이 곱의 최댓값을 돌려준다. 구간은 원소 하나여도 된다.

제약은 길이 1 이상 2 × 10^4 이하, 값 -10 이상 10 이하이고, 어떤 구간의 곱도 32비트 정수에 들어간다고 보장된다. 길이 2만이라 O(n²) = 4억 번은 언어에 따라 아슬아슬하고, O(n)이 목표다. 구간이 비어 있으면 안 된다는 조건 때문에 답이 음수일 수 있다. `[-2]`의 답은 -2다.

## 곱셈에서는 음수 두 개가 뒤집기를 한다

글 끝까지 쓸 예시다.

```text
인덱스   0    1    2    3    4    5    6
nums     2   -3   -2    4    0   -1    5
```

0은 그 구간에 들어가는 순간 곱을 0으로 만든다. 그러니 0을 사이에 두고 배열이 두 토막 `[2, -3, -2, 4]`와 `[-1, 5]`로 갈린다. 0 자체를 고르면 곱이 0이라 그것도 후보다.

왼쪽 토막에는 음수가 둘이다. 음수 두 개를 곱하면 양수라서 토막 전체 2 × -3 × -2 × 4 = 48이 된다. 오른쪽 토막은 음수가 하나라 전체를 고르면 -5고, 음수를 빼고 5만 고르는 게 낫다. 답은 48이다.

합이라면 -3 같은 음수는 들어오는 순간 손해라 그 앞을 버리는 판단이 맞았다. 곱셈에서는 2 × -3 = -6이 손해처럼 보여도, 다음 -2를 만나 12로 뒤집힌다. 지금 가장 나쁜 값이 다음에 가장 좋은 값이 될 수 있다는 것, 이게 합과 곱의 차이다.

## 모든 구간을 곱해 본다

시작 i와 끝 j를 모두 골라 곱한다. 다만 구간마다 처음부터 다시 곱할 필요는 없다. 시작 i를 정하고 j를 한 칸씩 늘리면, 앞 구간의 곱에 `nums[j]` 하나만 곱하면 된다.

```js
function maxProduct(nums) {
  let best = -Infinity;
  for (let i = 0; i < nums.length; i++) {
    let prod = 1;
    for (let j = i; j < nums.length; j++) {
      prod *= nums[j];                 // i..j 구간의 곱 = i..j-1 구간의 곱 × nums[j]
      best = Math.max(best, prod);
    }
  }
  return best;
}
```

시간 O(n²), 공간 O(1)이다. 구간마다 세 번째 반복으로 다시 곱하면 O(n³)인데, 곱을 이어 가는 것만으로 한 단계 내려왔다. 그래도 길이 2만이면 구간이 2억 개라 느리다.

`best`를 0이 아니라 `-Infinity`로 시작한 데도 이유가 있다. 답이 음수인 `[-2]`에서 0으로 시작하면 있지도 않은 "빈 구간"의 0을 돌려준다. 뒤의 실수 모음에서 다시 본다.

## 0으로 자르고 음수 개수를 센다

손으로 풀 때 쓴 생각을 그대로 코드로 옮길 수도 있다.

1. 0을 경계로 배열을 토막 낸다. 0이 하나라도 있으면 답은 최소 0이다.
2. 0이 없는 토막에서는 음수 개수가 짝수면 토막 전체의 곱이 가장 크다. 정수의 절댓값은 1 이상이라 곱할수록 절댓값이 줄지 않기 때문이다.
3. 음수 개수가 홀수면 음수 하나를 버려야 한다. 가장 많이 남기려면 첫 음수까지의 앞부분을 버리거나, 마지막 음수부터의 뒷부분을 버린다. 둘 중 곱이 큰 쪽이 그 토막의 답이다.
4. 토막이 음수 하나뿐이면 버리고 나면 비니, 그 음수 자체가 답이다.

```js
function maxProduct(nums) {
  let best = -Infinity;
  let seg = [];
  const solve = (a) => {                       // 0이 없는 토막의 최대 곱
    let total = 1;
    for (const x of a) total *= x;
    if (total > 0) return total;               // 음수가 짝수 개: 전체
    if (a.length === 1) return a[0];           // 음수 하나뿐인 토막
    const first = a.findIndex((x) => x < 0);
    let last = -1;
    for (let i = a.length - 1; i >= 0; i--) if (a[i] < 0) { last = i; break; }
    const cands = [];
    let p = 1;
    for (let i = first + 1; i < a.length; i++) p *= a[i]; // 첫 음수까지 버리기
    if (first + 1 < a.length) cands.push(p);
    p = 1;
    for (let i = 0; i < last; i++) p *= a[i];             // 마지막 음수부터 버리기
    if (last > 0) cands.push(p);
    return Math.max(...cands);
  };
  for (const x of nums) {
    if (x === 0) {
      best = Math.max(best, 0);                // 0 하나만 고르는 구간
      if (seg.length) best = Math.max(best, solve(seg));
      seg = [];
    } else seg.push(x);
  }
  if (seg.length) best = Math.max(best, solve(seg));
  return best;
}
```

예시의 오른쪽 토막 `[-1, 5]`는 음수가 하나라, 첫 음수까지 버리면 5가 남고 마지막 음수부터 버리면 아무것도 안 남는다. 그래서 5다. `[2, -5, -2, -4, 3]`처럼 음수가 셋이면 앞에서 2, -5를 버린 -2 × -4 × 3 = 24와 뒤에서 -4, 3을 버린 2 × -5 × -2 = 20 중 24다.

예시 전체를 이 코드로 따라가면 이렇다.

```text
토막 [2, -3, -2, 4]   음수 2개 → 전체 곱 48
0                     0 하나만 고르면 0
토막 [-1, 5]          음수 1개 → 첫 음수까지 버리면 [5] = 5, 마지막 음수부터 버리면 빈 구간
답 = max(48, 0, 5) = 48
```

토막마다 몇 번 훑을 뿐이라 시간 O(n)이다. 토막을 배열로 모으니 공간은 O(n)이지만, 인덱스만 들고 다니면 O(1)로 줄일 수 있다. 맞는 풀이지만 경우가 많아서 짜다가 틀리기 쉽다. "음수 하나를 버리려면 앞에서 버리거나 뒤에서 버린다"는 핵심만 남기면 훨씬 짧아진다.

## 앞에서 한 번, 뒤에서 한 번 곱해 본다

앞 풀이의 3번이 말하는 건 결국 이렇다. 토막의 최댓값은 "토막의 앞부분(prefix) 곱" 중 하나이거나 "토막의 뒷부분(suffix) 곱" 중 하나다. 첫 음수까지를 버린 것은 어떤 뒷부분이고, 마지막 음수부터를 버린 것은 어떤 앞부분이며, 전체는 둘 다다.

그러니 앞에서부터 누적 곱을 구하며 최댓값을 보고, 뒤에서부터 한 번 더 같은 걸 하면 된다. 0을 만나면 누적 곱이 0이 되니, 다음 칸부터 새 토막으로 다시 시작하도록 1로 되돌린다.

```js
function maxProduct(nums) {
  let best = -Infinity;
  let prod = 1;
  for (let i = 0; i < nums.length; i++) {       // 앞에서부터: 토막의 앞부분 곱
    prod *= nums[i];
    best = Math.max(best, prod);
    if (prod === 0) prod = 1;                   // 0 다음은 새 토막
  }
  prod = 1;
  for (let i = nums.length - 1; i >= 0; i--) {  // 뒤에서부터: 토막의 뒷부분 곱
    prod *= nums[i];
    best = Math.max(best, prod);
    if (prod === 0) prod = 1;
  }
  return best;
}
```

앞에서 가는 쪽만으로 왜 부족한지 `[-1, 3, 4, 0, -5, 2]`로 보자. 답은 3 × 4 = 12인데, 이건 첫 토막 `[-1, 3, 4]`의 뒷부분이다. 다음을 누르면 두 번의 훑기가 차례로 보인다.

시간 O(n), 공간 O(1)이다. 코드가 짧고 왜 맞는지도 앞 풀이로 설명된다. 0에서 곱을 1로 되돌리는 줄이 빠지면 0 뒤의 칸은 계속 0만 나온다. `[0, 2, 3, 0]`에서 답 6 대신 0이 나온다.

이 풀이는 면접에서 "다른 방법은 없나"에 내놓기 좋다. 다만 배열을 두 번 읽어야 해서 값이 하나씩 흘러 들어오는 상황에는 맞지 않는다. 한 번 훑기로 끝내려면 지금 칸에서 끝나는 구간을 상태로 들고 가야 한다.

## 지금 칸에서 끝나는 가장 큰 곱과 가장 작은 곱

합 문제의 카데인 알고리즘은 "i번 칸에서 끝나는 구간 중 가장 큰 합"을 `cur = max(x, cur + x)`로 이어 간다.

```js
function maxSubArray(nums) {
  let cur = nums[0], best = nums[0];
  for (let i = 1; i < nums.length; i++) {
    cur = Math.max(nums[i], cur + nums[i]); // 앞을 버리고 새로 시작 vs 이어 붙이기
    best = Math.max(best, cur);
  }
  return best;
}
```

이 글의 예시에 넣으면 `[4, 0, -1, 5]`의 합 8이 나온다. 지금까지의 합이 음수면 x에서 새로 시작하는 게 늘 낫다는 판단 하나로 끝난다. 곱으로 바꿔 `cur = max(x, cur * x)`라고 쓰면 틀린다. 예시에서 -3을 만나면 `max(-3, 2 × -3) = -3`이 남고, 다음 -2에서 `max(-2, -3 × -2) = 6`이 된다. 실제로는 2 × -3 × -2 = 12를 만들 수 있는데, -6이라는 "가장 작은 곱"을 버려서 놓쳤다.

그래서 칸마다 두 값을 함께 든다.

- `maxEnd[i]`: i번 칸에서 끝나는 구간의 곱 중 가장 큰 것
- `minEnd[i]`: i번 칸에서 끝나는 구간의 곱 중 가장 작은 것

i번 칸에서 끝나는 구간은 "x 하나만"이거나 "i-1번에서 끝나는 구간에 x를 이어 붙인 것"이다. 이어 붙인 것의 곱은 `maxEnd[i-1] × x`와 `minEnd[i-1] × x` 사이 어딘가인데, x가 양수면 앞의 것이, 음수면 뒤의 것이 가장 크다. 셋 중에서 고르면 부호를 따지지 않아도 된다.

```text
maxEnd[i] = max(x, maxEnd[i-1] × x, minEnd[i-1] × x)
minEnd[i] = min(x, maxEnd[i-1] × x, minEnd[i-1] × x)
답        = 모든 i에서 maxEnd[i]의 최댓값
```

```js
function maxProduct(nums) {
  const n = nums.length;
  const maxEnd = new Array(n), minEnd = new Array(n);
  maxEnd[0] = minEnd[0] = nums[0];           // 첫 칸에서 끝나는 구간은 그 칸 하나
  let best = nums[0];
  for (let i = 1; i < n; i++) {
    const x = nums[i];
    const a = maxEnd[i - 1] * x;             // 가장 큰 곱에 이어 붙이기
    const b = minEnd[i - 1] * x;             // 가장 작은 곱에 이어 붙이기
    maxEnd[i] = Math.max(x, a, b);           // x에서 새로 시작하는 것도 후보
    minEnd[i] = Math.min(x, a, b);
    best = Math.max(best, maxEnd[i]);
  }
  return best;
}
```

0을 만나면 a, b, x가 모두 0이라 두 값이 0으로 떨어진다. 다음 칸에서는 x 자체가 후보라 자연스럽게 새로 시작한다. 0을 따로 처리하지 않아도 되는 이유다.

시간 O(n), 공간 O(n)이다. 그런데 i번 칸은 i-1번 칸만 보니 배열이 필요 없다.

### 왜 가장 큰 것과 가장 작은 것 두 개면 충분한가

i-1번 칸에서 끝나는 구간은 i개나 있다. 그중 두 개만 기억해도 되는 이유가 궁금할 수 있다. x를 곱하는 일은 x가 양수면 크기 순서를 그대로 두고, 음수면 순서를 통째로 뒤집는다. 어느 쪽이든 곱한 뒤 가장 큰 값은 곱하기 전 양 끝, 즉 가장 큰 값이나 가장 작은 값에서 나온다. 가운데 있던 값이 곱한 뒤 맨 끝으로 튀어나오는 일은 없다. x가 0이면 모두 0이 되니 역시 상관없다.

예시의 2번 칸으로 확인해 보자. 1번 칸에서 끝나는 구간은 `[-3]`과 `[2, -3]` 두 개이고 곱은 -3과 -6이다. 여기에 -2를 곱하면 6과 12가 되고, -2에서 새로 시작하는 구간의 -2가 더해진다.

```text
1번 칸에서 끝나는 곱   -3   -6        (최대 -3, 최소 -6)
× -2                    6   12        (순서가 뒤집혀 최소였던 -6이 최대 12)
-2에서 새로 시작        -2
2번 칸의 최대 / 최소   12 / -2
```

구간이 몇 개든 양 끝 두 값만 들고 있으면 다음 칸의 양 끝이 정해진다. 이 성질을 단조성이라 부른다. 합에서는 x를 더해도 순서가 절대 뒤집히지 않아서 최댓값 하나로 충분했던 것이다.

## 음수를 만나면 두 기록을 맞바꾼다

배열 대신 변수 두 개 `curMax`, `curMin`을 쓴다. 이때 위의 세 후보 식을 그대로 써도 되고, 많이 쓰는 다른 모양도 있다. x가 음수면 곱한 뒤 큰 쪽과 작은 쪽이 뒤바뀌니, 곱하기 전에 미리 둘을 맞바꿔 두는 것이다. 그러면 큰 쪽은 늘 큰 쪽끼리, 작은 쪽은 작은 쪽끼리 계산된다.

```js
function maxProduct(nums) {
  let curMax = nums[0]; // 지금 칸에서 끝나는 구간의 가장 큰 곱
  let curMin = nums[0]; // 지금 칸에서 끝나는 구간의 가장 작은 곱
  let best = nums[0];
  for (let i = 1; i < nums.length; i++) {
    const x = nums[i];
    if (x < 0) [curMax, curMin] = [curMin, curMax]; // 음수를 곱하면 크기 순서가 뒤집힌다
    curMax = Math.max(x, curMax * x);  // x에서 새로 시작 vs 이어 붙이기
    curMin = Math.min(x, curMin * x);
    best = Math.max(best, curMax);
  }
  return best;
}
```

맞바꾸는 모양과 세 후보 모양 중 무엇을 쓸지는 취향이다. 세 후보 모양은 부호를 생각하지 않아도 돼서 실수가 적고, 맞바꾸는 모양은 "음수가 순서를 뒤집는다"는 이유가 코드에 드러나서 설명하기 좋다.

## Python과 Java로 옮긴 두 기록 풀이

```python
from typing import List

class Solution:
    def maxProduct(self, nums: List[int]) -> int:
        cur_max = cur_min = best = nums[0]
        for x in nums[1:]:
            if x < 0:                               # 음수를 곱하면 큰 쪽과 작은 쪽이 뒤바뀐다
                cur_max, cur_min = cur_min, cur_max
            cur_max = max(x, cur_max * x)           # x에서 새로 시작 vs 이어 붙이기
            cur_min = min(x, cur_min * x)
            best = max(best, cur_max)
        return best
```

Python은 `a, b = b, a`로 맞바꾼다. 정수 크기 제한이 없어서 곱이 아무리 커져도 넘치지 않는다. `nums[1:]`는 복사본을 만드니, 길이 2만에서 메모리가 신경 쓰이면 `for i in range(1, len(nums))`로 돈다. 세 후보 모양으로 쓸 때는 `cur_max, cur_min = max(x, cur_max * x, cur_min * x), min(x, cur_max * x, cur_min * x)`처럼 한 줄 동시 대입을 써야 한다. 이유는 뒤의 실수 모음에 있다.

```java
class Solution {
    public int maxProduct(int[] nums) {
        int curMax = nums[0], curMin = nums[0], best = nums[0];
        for (int i = 1; i < nums.length; i++) {
            int x = nums[i];
            if (x < 0) {                         // 음수면 큰 쪽과 작은 쪽을 맞바꾼다
                int tmp = curMax;
                curMax = curMin;
                curMin = tmp;
            }
            curMax = Math.max(x, curMax * x);    // 새로 시작 vs 이어 붙이기
            curMin = Math.min(x, curMin * x);
            best = Math.max(best, curMax);
        }
        return best;
    }
}
```

Java의 `int`는 21억을 넘으면 조용히 넘친다. 문제는 모든 구간의 곱이 32비트 안이라고 보장하지만, `curMin * x`처럼 답이 아닌 중간 곱도 어떤 구간의 곱이라 그 보장 안에 들어간다. 보장이 없는 변형이라면 `long`도 금방 넘친다. 10을 열 번 곱하면 `int`에서 1410065408이 나왔다. JavaScript의 `Number`는 넘치지 않는 대신 2^53을 넘으면 정밀도를 잃는다. 세 언어 모두 예시에 48, `[-2, 0, -1]`에 0, `[-2]`에 -2가 나왔다.

## 여섯 풀이를 훑는 횟수로 나누면

| 풀이 | 시간 | 추가 공간 | 언제 고르나 |
|---|---|---|---|
| 모든 구간 곱 (이어 곱하기) | O(n²) | O(1) | 정답 확인용 |
| 0으로 자르고 음수 세기 | O(n) | O(n) | 손으로 푼 생각을 그대로 설명할 때 |
| 앞뒤로 누적 곱 | O(n) | O(1) | 짧은 다른 풀이가 필요할 때 |
| maxEnd·minEnd 배열 | O(n) | O(n) | 점화식을 세울 때, 구간을 되짚을 때 |
| 두 기록, 세 후보 | O(n) | O(1) | 기본 답. 부호를 신경 쓰기 싫을 때 |
| 두 기록, 음수에서 맞바꾸기 | O(n) | O(1) | 기본 답. 스트림에도 쓴다 |

O(n³)짜리 "구간마다 처음부터 곱하기"는 표에서 뺐다. 곱을 이어 가는 것만으로 바로 O(n²)이 되니 굳이 쓸 이유가 없다.

## 부호와 0에서 틀리는 코드

### 최댓값 하나만 들고 다니는 경우

```js
let cur = nums[0], best = nums[0];
for (let i = 1; i < nums.length; i++) {
  cur = Math.max(nums[i], cur * nums[i]); // 카데인을 곱으로 옮겼다
  best = Math.max(best, cur);
}
```

예시에서 24(답 48), `[-2, 3, -4]`에서 3(답 24), `[2, -5, -2, -4, 3]`에서 10(답 24)이 나온다. 음수로 뒤집힐 가장 작은 곱을 버려서다. `[-2, -3, 7]`처럼 첫 칸부터 음수 두 개가 이어지면 우연히 맞아서 몇 개 테스트로는 안 잡힌다.

### 새 max로 min을 계산하는 경우

```js
mx = Math.max(x, mx * x, mn * x);
mn = Math.min(x, mx * x, mn * x); // 위에서 이미 바뀐 mx를 쓴다
```

min을 구할 때 이번 칸에서 이미 갱신된 mx를 쓰니, x를 두 번 곱한 값이 섞인다. `[2, -5, -2, -4, 3]`에서 480이 나온다. 있을 수 없는 값이다. 이전 값을 임시 변수에 받아 두거나(배열 풀이의 a, b), Python처럼 동시 대입을 쓴다.

### best를 0으로 시작하는 경우

`best = 0`으로 시작하면 답이 음수인 입력에서 0이 나온다. `[-2]`가 대표다. 구간은 비어 있을 수 없어서 0은 실제로 0을 골랐을 때만 답이 된다. 첫 칸 값으로 시작하거나 `-Infinity`로 시작한다.

### 앞뒤 곱에서 0 다음에 되돌리지 않는 경우

앞뒤로 누적 곱을 구하는 풀이에서 `if (prod === 0) prod = 1`을 빼면 0 뒤로는 모든 곱이 0이다. 양 끝에 0이 있는 `[0, 2, 3, 0]`에서 0(답 6), `[-1, 0, 5, 0, -1]`에서 0(답 5)이 나온다. 0이 한쪽 끝에만 있으면 반대쪽 훑기가 구해 주니, 0이 양쪽에 있는 입력을 넣어야 드러난다.

## 곱셈 구간 문제가 바뀌면

### 구간의 위치도 알려 달라면

`curMax`와 `curMin`마다 "그 구간이 어디서 시작했는지"를 함께 들고 간다. 맞바꿀 때 시작 위치도 같이 맞바꾸고, x에서 새로 시작하면 시작 위치를 i로 바꾼다. best가 바뀔 때 (시작, i)를 기록한다.

```js
function maxProductRange(nums) {
  let mx = nums[0], mn = nums[0], mxS = 0, mnS = 0; // 값과 그 구간의 시작 위치
  let best = nums[0], bs = 0, be = 0;
  for (let i = 1; i < nums.length; i++) {
    const x = nums[i];
    if (x < 0) { [mx, mn] = [mn, mx]; [mxS, mnS] = [mnS, mxS]; } // 시작 위치도 함께 바꾼다
    if (x >= mx * x) { mx = x; mxS = i; } else mx = mx * x;     // 새로 시작하면 시작이 i
    if (x <= mn * x) { mn = x; mnS = i; } else mn = mn * x;
    if (mx > best) { best = mx; bs = mxS; be = i; }
  }
  return [best, bs, be];
}
```

예시에 `[48, 0, 3]`, `[0, 2, 3, 0]`에 `[6, 1, 2]`, `[-2]`에 `[-2, 0, 0]`이 나왔다. 동점일 때 새로 시작하는 쪽을 고르면 같은 곱이라도 더 짧은 구간이 남는다.

### 곱이 양수인 가장 긴 구간을 구하라면

LeetCode 1567 Maximum Length of Subarray With Positive Product다. 곱의 크기가 아니라 부호만 중요하니, 칸마다 "여기서 끝나는 곱이 양수인 가장 긴 길이"와 "음수인 가장 긴 길이"를 든다. 양수를 만나면 둘 다 1씩 늘고(음수 쪽은 있을 때만), 음수를 만나면 둘이 맞바뀌며 1씩 늘고, 0이면 둘 다 0이 된다. 이 글의 맞바꾸기와 똑같은 뼈대다.

```js
function getMaxLen(nums) {
  let pos = 0, neg = 0, best = 0; // 여기서 끝나는 양수 곱·음수 곱 구간의 가장 긴 길이
  for (const x of nums) {
    if (x === 0) { pos = 0; neg = 0; }
    else if (x > 0) { pos = pos + 1; neg = neg > 0 ? neg + 1 : 0; }
    else { const p = pos; pos = neg > 0 ? neg + 1 : 0; neg = p + 1; } // 음수: 부호가 뒤바뀐다
    best = Math.max(best, pos);
  }
  return best;
}
```

`[1, -2, -3, 4]`에 4, `[0, 1, -2, -3, -4]`에 3, 이 글의 예시에 4가 나왔다.

### 곱이 k보다 작은 구간의 개수라면

[Subarray Product Less Than K](/posts/leetcode-subarray-product-less-than-k)(713)다. 값이 모두 양수라는 조건이 붙어서, 창을 넓히면 곱이 커지고 줄이면 작아지는 단조성이 생긴다. 그래서 [슬라이딩 윈도](/posts/sliding-window-pattern)로 O(n)에 센다. 음수가 섞인 이 문제에서는 그 단조성이 없어서 창을 쓸 수 없다.

### 원소 세 개의 곱을 최대로 하라면

LeetCode 628 Maximum Product of Three Numbers는 연속 조건이 없다. 정렬해서 "가장 큰 셋의 곱"과 "가장 작은 둘(음수일 수 있다) × 가장 큰 하나" 중 큰 쪽을 고른다. 여기서도 가장 작은 값이 음수 둘로 뒤집혀 답이 된다는 같은 생각이 나온다.

### 곱이 너무 커진다면

값의 범위가 커서 곱이 넘칠 수 있으면 로그를 씌워 곱을 합으로 바꾸는 방법이 떠오른다. 하지만 로그는 0과 음수에 정의되지 않아서, 부호는 따로 세고 절댓값에만 로그를 쓰는 식으로 나눠야 하고 부동소수점 오차도 생긴다. 실제 값을 돌려줘야 하면 Python의 큰 정수나 Java `BigInteger`, JavaScript `BigInt`로 같은 두 기록 풀이를 돌리는 게 단순하다.

비슷한 문제로는 Maximum Subarray(53), Maximum Length of Subarray With Positive Product(1567), [Subarray Product Less Than K](/posts/leetcode-subarray-product-less-than-k), [Product of Array Except Self](/posts/leetcode-product-of-array-except-self)(앞뒤 누적 곱을 쓰는 다른 문제), 이웃 조건이 붙는 [House Robber](/posts/leetcode-house-robber)가 있다.

## 면접에서 나올 만한 질문

### 왜 최솟값까지 들고 다니나요?

음수를 곱하면 크기 순서가 뒤집혀서, 지금 가장 작은 곱이 다음 칸에서 가장 큰 곱이 될 수 있기 때문이다. `[2, -3, -2]`에서 1번 칸의 가장 작은 곱 -6이 -2를 만나 12가 된다. 최댓값만 들면 이 -6을 버려 6밖에 못 만든다.

### 점화식을 말해 보세요.

i번 칸에서 끝나는 구간은 x 하나이거나 앞 칸에서 끝나는 구간에 x를 붙인 것이다. 그래서 `maxEnd[i] = max(x, maxEnd[i-1] × x, minEnd[i-1] × x)`, `minEnd[i]`는 같은 셋의 최솟값이다. 답은 모든 i의 `maxEnd[i]` 중 최댓값이고, 앞 칸만 보니 변수 두 개로 O(1) 공간이 된다.

### 0은 어떻게 처리하나요?

따로 처리하지 않아도 된다. 0을 곱하면 두 기록이 모두 0이 되고, 다음 칸에서는 x 자체가 후보라서 거기서 새로 시작한다. 0을 고르는 구간의 곱 0도 best 후보로 자연스럽게 들어간다.

### 다른 O(n) 풀이가 있나요?

앞에서 한 번, 뒤에서 한 번 누적 곱을 구하며 최댓값을 보는 방법이 있다. 0이 없는 토막의 최대 곱은 음수 개수가 짝수면 전체, 홀수면 첫 음수까지 버린 뒷부분이나 마지막 음수부터 버린 앞부분이라 둘 중 하나에 반드시 들어간다. 0을 만나면 누적 곱을 1로 되돌려야 한다.

### 합 문제의 카데인 알고리즘과 무엇이 다른가요?

합에서는 지금까지의 합이 음수면 버리는 게 늘 맞아서 최댓값 하나로 충분하다. 곱에서는 음수가 다음 음수를 만나 양수로 뒤집히니 버리면 안 되는 나쁜 값이 생긴다. 그래서 최댓값과 최솟값 두 상태를 들고, 음수를 만나면 둘을 맞바꾼다.

### 답이 음수일 수도 있나요?

있다. 구간은 비어 있을 수 없어서 `[-2]`의 답은 -2다. 그래서 best를 0으로 시작하면 틀리고, 첫 칸 값이나 `-Infinity`로 시작해야 한다.

### 오버플로는 어떻게 보나요?

문제는 모든 구간의 곱이 32비트 안이라고 보장하고, 중간에 들고 있는 값도 어떤 구간의 곱이라 그 안에 들어간다. 보장이 없다면 Java `int`는 조용히 넘치니 `long`이나 `BigInteger`가 필요하고, 값이 -10~10이어도 스무 개만 곱하면 `long`도 넘친다. 로그로 바꾸는 방법은 0과 음수 때문에 그대로는 못 쓴다.
