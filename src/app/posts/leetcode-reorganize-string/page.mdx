[Reorganize String](https://leetcode.com/problems/reorganize-string/)은 LeetCode 767번이고 난이도는 Medium이다. 문자열의 글자 순서를 바꿔서 같은 글자가 이웃하지 않게 만든다. 불가능하면 빈 문자열을 돌려준다. 답이 여러 개일 수 있고, 그중 아무거나 돌려주면 된다.

힙 패턴에 들어 있는 이유는 "가장 많이 남은 것부터 쓴다"는 탐욕 전략을 힙이 그대로 받쳐 주기 때문이다. 그런데 이 문제는 힙 없이 O(n)에 푸는 방법도 있다. 이 글은 되돌아가며 놓아 보기, 힙에서 두 글자씩 꺼내기, 힙에서 하나씩 꺼내고 방금 쓴 글자를 쉬게 하기, 짝수 칸 먼저 채우기까지 네 풀이를 본다. 왜 가장 많은 글자부터 써야 막히지 않는지도 따져 본다. 힙의 기본 동작은 [힙 글](/posts/ds-heap)에, 탐욕 전략이 맞는지 따지는 방법은 [탐욕 알고리즘 글](/posts/greedy-algorithms)에 있다. 코드는 Node.js 22, Python 3.13, Java 21에서 돌렸다.

## 같은 글자가 붙지 않게 다시 늘어놓는다

문자열 `s`가 주어진다. 글자의 순서만 바꿔서, 어떤 두 이웃한 글자도 같지 않은 문자열을 하나 만든다. 그런 문자열이 없으면 `""`를 돌려준다.

- `s`의 길이는 1 이상 500 이하다.
- 글자는 영어 소문자뿐이다. 글자 종류가 많아야 26가지라는 뜻이다.

길이가 500이라 O(n²)도 통과하지만, 글자 종류가 26개뿐이라는 사실이 더 중요하다. 힙에 들어가는 원소가 많아야 26개라서 힙 연산이 사실상 상수 시간이 된다. 개수를 세는 배열도 26칸이면 된다.

## 가능한지는 가장 많은 글자 하나가 정한다

이 글의 예시는 `"aaabbc"`다. a가 3개, b가 2개, c가 1개, 모두 6글자다.

손으로 먼저 놓아 본다. a가 가장 많으니 a끼리 떨어뜨리는 게 가장 급하다. a를 첫째, 셋째, 다섯째 칸에 놓으면 `a_a_a_`가 되고, 빈칸 셋에 b, b, c를 넣으면 `ababac`다. 이웃한 글자가 모두 다르다.

이번엔 `"aaab"`를 보자. a가 3개, b가 1개다. a 셋을 떨어뜨리려면 a 사이에 다른 글자가 최소 두 개 필요하다. 그런데 b는 하나뿐이다. `aba` 다음에 a를 놓으면 `abaa`가 되어 붙는다. 불가능하다.

일반화하면 이렇다. 길이가 n일 때 한 글자를 최대한 떨어뜨려 놓으면 0, 2, 4, ... 칸에 놓이고, 그런 칸은 `(n + 1) / 2`개(나머지 버림)다. n이 6이면 3칸, n이 7이면 4칸이다. 그래서 가장 많은 글자의 개수가 `(n + 1) / 2`를 넘으면 불가능하다.

반대 방향도 성립한다. 가장 많은 글자가 `(n + 1) / 2` 이하이면 언제나 가능하다. 이건 뒤에서 짝수 칸 채우기로 직접 만들어 보이며 확인한다. 결국 가능한지 판정은 개수를 세고 최댓값 하나만 비교하면 끝난다. 어려운 건 실제로 늘어놓는 방법이다.

## 되돌아가며 하나씩 놓아 본다

처음 떠올릴 만한 방법은 완전 탐색이다. 글자별 개수를 들고, 매 칸마다 "방금 놓은 글자가 아닌, 남아 있는 글자"를 하나 골라 놓는다. 끝까지 채우면 성공이고, 막히면 직전 선택을 되돌리고 다른 글자를 고른다. [백트래킹](/posts/recursion-backtracking)이다.

```js
function reorganizeString(s) {
  const cnt = new Map();
  for (const c of s) cnt.set(c, (cnt.get(c) || 0) + 1);
  const keys = [...cnt.keys()].sort();      // 고르는 순서는 알파벳 순
  const out = [];
  function go(prev) {
    if (out.length === s.length) return true;
    for (const c of keys) {
      if (c === prev || cnt.get(c) === 0) continue; // 방금 놓은 글자나 다 쓴 글자는 건너뛴다
      cnt.set(c, cnt.get(c) - 1);
      out.push(c);
      if (go(c)) return true;               // 끝까지 채웠으면 성공
      out.pop();                            // 막혔으면 되돌린다
      cnt.set(c, cnt.get(c) + 1);
    }
    return false;
  }
  return go("") ? out.join("") : "";
}
```

같은 글자끼리는 순서가 의미 없으니 위치마다 "어느 글자 종류를 놓나"만 고른다. 그래서 순열을 다 만드는 것보다는 훨씬 적게 돈다. 답이 있는 입력에서는 꽤 빨리 찾는다. a 250개, b 200개, c 50개짜리 500글자에서 함수 호출 501번 만에 답을 냈다. 한 번도 되돌아가지 않았다는 뜻이다.

문제는 불가능한 입력이다. 모든 경우를 다 돌아봐야 "없다"고 말할 수 있다. a를 하나 넘치게 넣고 나머지를 서로 다른 글자로 채운 입력으로 재 봤다.

```text
길이  호출 수        시간
8     158           0.5ms
12    12,662        9.8ms
16    2,127,246     317ms
18    34,035,938    4687ms
```

두 글자 늘 때마다 호출이 10배 넘게 늘어난다. 길이 500은 꿈도 못 꾼다. 여기서 앞 절의 판정을 먼저 하면 불가능한 입력은 바로 걸러진다. 그래도 탐색 자체는 지수 시간이고, 답이 있는 입력에서 운 좋게 빨랐던 것뿐이다. "어떤 글자를 고를지"를 규칙으로 정해 되돌아갈 일이 없게 만드는 것이 다음 풀이다.

## 가장 많이 남은 두 글자를 한 쌍씩 쓴다

손으로 풀 때 가장 많은 a부터 챙겼다. 그 직감을 규칙으로 만든다. 매번 가장 많이 남은 글자와 두 번째로 많이 남은 글자를 하나씩 꺼내 나란히 붙인다. 둘은 서로 다른 글자라서 쌍 안에서는 붙지 않는다. "가장 많이 남은 것 두 개"를 계속 꺼내는 데는 최대 힙이 맞다.

1. 글자별 개수를 세서 `[개수, 글자]`를 최대 힙에 넣는다.
2. 힙에 둘 이상 있는 동안 두 개를 꺼내 두 글자를 결과에 붙인다. 개수를 하나씩 줄이고, 남아 있으면 다시 넣는다.
3. 힙에 하나가 남았을 때 그 개수가 1이면 붙이고, 2 이상이면 불가능하다.

```js
class Heap {
  constructor() { this.a = []; }
  get size() { return this.a.length; }
  less(x, y) { return x[0] !== y[0] ? x[0] > y[0] : x[1] < y[1]; } // 개수가 많은 쪽, 같으면 알파벳이 앞선 쪽이 위
  push(x) {
    const a = this.a;
    a.push(x);
    let i = a.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (!this.less(a[i], a[p])) break;
      [a[p], a[i]] = [a[i], a[p]];
      i = p;
    }
  }
  pop() {
    const a = this.a, top = a[0], last = a.pop();
    if (a.length) {
      a[0] = last;
      let i = 0;
      for (;;) {
        const l = 2 * i + 1, r = l + 1;
        let m = i;
        if (l < a.length && this.less(a[l], a[m])) m = l;
        if (r < a.length && this.less(a[r], a[m])) m = r;
        if (m === i) break;
        [a[m], a[i]] = [a[i], a[m]];
        i = m;
      }
    }
    return top;
  }
}

function reorganizeString(s) {
  const cnt = new Map();
  for (const c of s) cnt.set(c, (cnt.get(c) || 0) + 1);
  const h = new Heap();
  for (const [c, k] of cnt) h.push([k, c]);
  let out = "";
  while (h.size >= 2) {
    const x = h.pop(), y = h.pop();     // 가장 많이 남은 둘
    out += x[1] + y[1];
    if (--x[0] > 0) h.push(x);          // 남았으면 다시 넣는다
    if (--y[0] > 0) h.push(y);
  }
  if (h.size) {
    const x = h.pop();
    if (x[0] > 1) return "";            // 한 글자가 2개 이상 남으면 붙을 수밖에 없다
    out += x[1];
  }
  return out;
}
```

개수가 같을 때 알파벳 순으로 정하게 한 건 결과를 늘 같게 하려는 것뿐이다. 답은 아무거나 돌려줘도 되니 이 규칙이 없어도 맞다.

`"aaabbc"`를 넣고 차례마다 힙을 찍었다.

```text
처음        힙 [3 a, 2 b, 1 c]
a, b 꺼냄   결과 ab      힙 [2 a, 1 c, 1 b]
a, b 꺼냄   결과 abab    힙 [1 a, 1 c]
a, c 꺼냄   결과 ababac  힙 []
```

두 번째 차례에서 b와 c가 1개씩 같아 알파벳이 앞선 b가 먼저 나왔다. 아래 그림에서 다음을 누르며 결과 칸이 두 개씩 채워지는 모습을 따라가 본다.

글자 종류를 k라 하면 힙에는 많아야 k개가 있다. 두 글자를 쓸 때마다 힙 연산을 네 번 하니 전체는 O(n log k)이고, k가 26 이하라 사실상 O(n)이다. 공간은 개수와 힙의 O(k)에 결과 문자열 O(n)이다. 500글자를 1만 번 돌려 368ms였다.

### 왜 가장 많은 것부터 쓰면 막히지 않나

이 탐욕이 실패하는 건 마지막에 한 글자가 2개 이상 남을 때뿐이다. 그런 일이 시작할 때 가능했던 입력에서 일어나지 않는다는 걸 보이면 된다.

남은 글자 수를 m, 가장 많이 남은 글자의 개수를 M이라 하자. 시작할 때 M이 `(m + 1) / 2` 이하라고 가정한다. 한 차례에 가장 많은 글자와 두 번째로 많은 글자를 하나씩 쓰면 m은 2 줄어든다. 그러면 허용치 `(m + 1) / 2`는 1 줄어든다. 새 최댓값도 1 줄어든다면 조건은 그대로 이어진다.

새 최댓값이 줄지 않는 경우는 하나뿐이다. 이번에 쓰지 않은 세 번째 글자가 M개였을 때다. 그러려면 셋이 모두 M개였다는 뜻이라 m은 3M 이상이고, 두 글자를 쓴 뒤에도 남은 수가 3M - 2 이상이다. 3M - 2개 중 M개는 M이 1 이상인 한 절반을 넘지 않는다. 어느 경우든 "가장 많은 글자가 남은 수의 절반을 넘지 않는다"는 조건이 다음 차례로 넘어간다. 그래서 마지막에 글자 하나만 남았을 때 그 개수는 1을 넘지 않는다. 길이 9 이하의 문자열을 무작위로 2만 개 만들어 완전 탐색과 대조해 봐도 가능 여부가 모두 같았다.

반대로 가장 많은 것을 먼저 쓰지 않으면 이 조건이 깨질 수 있다. `"aaabbc"`에서 b와 c를 먼저 쓰면 `bc` 뒤에 a 셋과 b 하나가 남는다. 남은 4글자 중 a가 3개라 절반을 넘는다. 이미 늦었다.

## 방금 쓴 글자를 한 박자 쉬게 한다

두 개씩 꺼내는 대신 한 글자씩 쓰는 방식도 많이 쓴다. 매번 가장 많이 남은 글자 하나를 꺼내 쓰고, 그 글자는 바로 힙에 넣지 않고 한 차례 옆에 들고 있는다. 다음 글자를 쓴 뒤에야 들고 있던 글자를 힙에 돌려놓는다. 방금 쓴 글자가 다음 칸에 나올 수 없게 하는 장치다.

```js
function reorganizeString(s) {
  const cnt = new Map();
  for (const c of s) cnt.set(c, (cnt.get(c) || 0) + 1);
  const h = new Heap();                      // 앞 풀이의 Heap
  for (const [c, k] of cnt) h.push([k, c]);
  let out = "", hold = null;                 // hold: 한 박자 쉬는 글자
  while (h.size) {
    const x = h.pop();
    out += x[1];
    x[0]--;
    if (hold) h.push(hold);                  // 쉬던 글자를 돌려놓는다
    hold = x[0] > 0 ? x : null;              // 방금 쓴 글자가 남았으면 쉬게 한다
  }
  return hold ? "" : out;                    // 쉬던 글자가 남았는데 쓸 게 없으면 실패
}
```

결과는 앞 풀이와 같은 `ababac`이고, 복잡도도 O(n log k)로 같다. 500글자 1만 번에 402ms로 거의 같았다.

이 방식이 쓸모 있는 건 변형 문제 때문이다. "같은 글자 사이에 최소 k칸을 두라"는 조건으로 바뀌면, 쉬는 글자를 하나가 아니라 큐에 k개까지 줄 세워 두면 된다. 두 개씩 꺼내는 방식은 k = 2에만 맞는 요령이라 그렇게 넓어지지 않는다. [Task Scheduler](/posts/leetcode-task-scheduler)가 같은 "힙 + 쉬는 줄" 구조다.

## 짝수 칸부터 채우면 힙도 필요 없다

손으로 풀 때 a를 첫째, 셋째, 다섯째 칸에 먼저 놓았다. 그 방법을 그대로 코드로 옮기면 힙이 필요 없다.

1. 글자별 개수를 센다. 가장 많은 글자가 `(n + 1) / 2`를 넘으면 `""`.
2. 가장 많은 글자를 인덱스 0, 2, 4, ...에 놓는다.
3. 나머지 글자를 아무 순서로나 이어서 놓는다. 짝수 칸이 끝나면 인덱스 1로 가서 1, 3, 5, ...를 채운다.

```js
function reorganizeString(s) {
  const n = s.length;
  const cnt = new Array(26).fill(0);
  for (let i = 0; i < n; i++) cnt[s.charCodeAt(i) - 97]++;
  let max = 0;
  for (let c = 1; c < 26; c++) if (cnt[c] > cnt[max]) max = c;
  if (cnt[max] > (n + 1) >> 1) return "";   // 가장 많은 글자가 짝수 칸 수를 넘으면 불가능
  const res = new Array(n);
  let idx = 0;
  const place = (c) => {
    while (cnt[c] > 0) {
      if (idx >= n) idx = 1;                // 짝수 칸이 끝나면 홀수 칸으로
      res[idx] = String.fromCharCode(97 + c);
      idx += 2;
      cnt[c]--;
    }
  };
  place(max);                               // 가장 많은 글자를 먼저
  for (let c = 0; c < 26; c++) place(c);    // 나머지는 알파벳 순으로
  return res.join("");
}
```

### 왜 같은 글자가 붙지 않나

놓는 순서를 한 줄로 펴 보면 0, 2, 4, ..., 1, 3, 5, ...다. 한 글자는 이 순서에서 연속된 구간을 차지한다. 짝수 칸 수를 E라 하자. 문자열에서 이웃한 두 칸 i와 i + 1은 하나는 짝수, 하나는 홀수라서 이 순서에서 적어도 E - 1만큼 떨어져 있다. 그러니 한 글자가 이웃한 두 칸을 함께 차지하려면 그 글자가 E개 이상이어야 한다.

가장 많은 글자는 E개 이하이고 맨 앞부터 짝수 칸에만 놓이니 붙지 않는다. 나머지 글자는 가장 많은 글자보다 많지 않다. 가장 많은 글자가 정확히 E개면 짝수 칸이 이미 다 차서 나머지는 홀수 칸에만 들어가니 붙지 않는다. E보다 적으면 나머지 글자도 E보다 적으니 이웃한 두 칸을 함께 차지할 수 없다. 이게 앞에서 미뤄 둔 "가장 많은 글자가 E 이하이면 언제나 가능하다"의 증명이기도 하다.

가장 많은 글자를 먼저 놓는 게 왜 꼭 필요한지는 틀리는 예로 뒤에서 본다.

## 500글자를 1만 번 늘어놓아 본다

| 풀이 | 시간 | 공간 | 언제 고르나 |
|---|---|---|---|
| 되돌아가며 놓기 | 지수 | O(n) | 거의 쓰지 않는다. "답을 모두 구하라"는 변형에서만 |
| 힙에서 두 글자씩 | O(n log k) | O(k) | 탐욕을 설명하기 쉽다. 면접에서 가장 많이 쓴다 |
| 힙에서 하나씩, 한 박자 쉬기 | O(n log k) | O(k) | 거리 조건이 k칸으로 넓어지는 변형까지 생각할 때 |
| 짝수 칸 먼저 채우기 | O(n) | O(26) | 거리 조건이 2로 고정이면 가장 빠르고 짧다 |

k는 글자 종류 수로 26 이하다. 결과 문자열의 O(n)은 모든 풀이에 공통이라 공간 칸에서 뺐다.

같은 Node.js에서 a 250개, b 200개, c 50개짜리 500글자를 1만 번 돌렸다. 두 글자씩 368ms, 한 박자 쉬기 402ms, 짝수 칸 224ms였다. 되돌아가기는 이 입력에서는 한 번에 답을 찾았지만 불가능한 18글자에서 4.7초가 걸렸다. 힙의 log k가 26칸짜리라 힙 풀이와 짝수 칸 풀이의 차이는 두 배를 넘지 않는다. 면접에서는 힙으로 탐욕을 설명하고, "O(n)으로 더 줄일 수 있나"에 짝수 칸 풀이를 꺼내는 흐름이 자연스럽다.

## Counter와 int[26]으로 옮긴다

Python은 힙 풀이와 짝수 칸 풀이를 함께 적었다.

```python
import heapq
from collections import Counter

def reorganizeString(s: str) -> str:
    h = [(-k, c) for c, k in Counter(s).items()]  # 개수에 -를 붙여 많은 글자가 맨 위로
    heapq.heapify(h)
    out = []
    while len(h) >= 2:
        k1, c1 = heapq.heappop(h)     # 가장 많이 남은 글자
        k2, c2 = heapq.heappop(h)     # 두 번째로 많이 남은 글자
        out += [c1, c2]
        if k1 + 1 < 0: heapq.heappush(h, (k1 + 1, c1))   # -3 + 1 = -2, 하나 썼다
        if k2 + 1 < 0: heapq.heappush(h, (k2 + 1, c2))
    if h:
        k, c = h[0]
        if k < -1:                    # 한 글자가 2개 이상 남았다
            return ""
        out.append(c)
    return "".join(out)

def reorganizeEven(s: str) -> str:
    n = len(s)
    cnt = Counter(s)
    order = sorted(cnt, key=lambda c: -cnt[c])   # 많은 글자부터
    if cnt[order[0]] > (n + 1) // 2:
        return ""
    res = [""] * n
    i = 0
    for c in order:
        for _ in range(cnt[c]):
            if i >= n:
                i = 1                 # 짝수 칸이 다 차면 홀수 칸으로
            res[i] = c
            i += 2
    return "".join(res)

for s in ["aaabbc", "aaab", "a", "aab", "vvvlo"]:
    print(repr(reorganizeString(s)), repr(reorganizeEven(s)))
```


부호를 뒤집어 쓰니 "개수를 하나 줄인다"가 `k + 1`이 된다. 여기서 `k - 1`을 쓰면 개수가 늘어나 반복이 끝나지 않는다. 헷갈리면 꺼낼 때 양수로 바꿔 두고 넣을 때만 `-`를 붙이는 편이 안전하다. 튜플 `(-k, c)`는 개수가 같으면 글자로 비교해서 결과가 늘 같게 나온다. 결과를 문자열에 `+=`로 붙이지 않고 리스트에 모아 마지막에 `"".join`한 것도 습관으로 들일 만하다.

Java는 짝수 칸 풀이를 옮겼다.

```java
class Solution {
    public String reorganizeString(String s) {
        int n = s.length();
        int[] cnt = new int[26];
        for (char ch : s.toCharArray()) cnt[ch - 'a']++;
        int max = 0;
        for (int c = 1; c < 26; c++) if (cnt[c] > cnt[max]) max = c;
        if (cnt[max] > (n + 1) / 2) return "";      // 가장 많은 글자가 절반을 넘으면 불가능
        char[] res = new char[n];
        int idx = 0;
        // 가장 많은 글자를 짝수 칸 0, 2, 4, ...에 먼저 놓는다
        while (cnt[max] > 0) { res[idx] = (char) ('a' + max); idx += 2; cnt[max]--; }
        for (int c = 0; c < 26; c++) {
            while (cnt[c] > 0) {
                if (idx >= n) idx = 1;                 // 짝수 칸이 끝나면 홀수 칸으로
                res[idx] = (char) ('a' + c);
                idx += 2;
                cnt[c]--;
            }
        }
        return new String(res);
    }
}
```

```text
'ababac'
''
'a'
'aba'
'vlvov'
```

Java에서 `(n + 1) / 2`는 정수 나눗셈이라 n이 7이면 4가 된다. 원하는 값이다. `'a' + max`는 `int`라서 `char`로 바꿔야 한다. 빼먹으면 컴파일 오류가 나서 바로 알 수 있다. 결과를 `String`에 `+=`로 붙이면 붙일 때마다 새 문자열을 만들어 O(n²)이 되니, `char[]`이나 `StringBuilder`를 쓴다.

## 마지막 한 글자에서 무너지는 코드들

### 가장 많은 글자를 먼저 놓지 않는다

짝수 칸 풀이에서 "가장 많은 글자 먼저"를 빼고 알파벳 순으로만 채우면 이렇게 된다.

```js
for (let c = 0; c < 26; c++) place(c);  // place(max)를 빼먹었다
```

`"abccc"`를 넣으면 a가 0번, b가 2번, c가 4번에 놓이고, 짝수 칸이 끝나 c 둘이 1번과 3번에 간다. 결과는 `acbcc`다. 3번과 4번의 c가 붙었다. c는 3개로 짝수 칸 수 3과 같아서 짝수 칸을 혼자 다 써야 했는데, 앞 글자들이 짝수 칸을 먼저 차지해 버렸다. 판정은 통과했는데 결과가 틀리니 테스트에서 놓치기 쉽다.

### 힙에 하나 남았을 때 개수를 보지 않는다

두 글자씩 꺼내는 풀이의 마지막을 "남은 글자를 그냥 붙인다"로 쓰면 불가능한 입력에서 틀린 답을 낸다.

```js
if (h.size) out += h.pop()[1];  // 개수가 2 이상이어도 한 글자만 붙인다
```

`"aaab"`를 넣으면 ab를 쓴 뒤 a가 2개 남는데, a 하나만 붙여 `aba`를 돌려준다. 글자가 하나 사라졌다. `"aaaab"`도 똑같이 `aba`를 낸다. 길이가 원래와 다른 답은 틀린 답이다. 남은 개수가 2 이상이면 `""`를 돌려줘야 한다.

### 절반 판정을 n / 2로 한다

가장 많은 글자가 `n / 2`를 넘으면 불가능하다고 쓰면 홀수 길이에서 틀린다. `"aab"`는 a가 2개이고 `aba`로 가능하다. 그런데 `2 > 3 / 2`는 참이고, 정수로 `2 > 3 >> 1`도 참이라 불가능하다고 판정해 버린다. 홀수 길이에서는 짝수 칸이 홀수 칸보다 하나 많다. 기준은 `(n + 1) / 2`(나머지 버림)다.

### 가장 많은 글자 하나만 피해서 놓는다

"방금 쓴 글자만 아니면 아무거나"로 앞에서부터 놓는 탐욕은 틀린다. `"aaabc"`에서 알파벳 순으로 고르면 a, b, a, c를 놓고 a 하나가 남아 `abaca`가 된다. 이건 운 좋게 맞는다. 그런데 `"bbbac"`처럼 많은 글자가 알파벳 뒤쪽이면 a, b, c, b까지 놓은 뒤 남은 b를 놓을 자리가 없어 막힌다. 답 `babcb`가 있는데도 찾지 못한다. 고를 때 "가장 많이 남은 것"을 보지 않으면 마지막에 한 글자가 몰린다.

## 거리 조건이 k로 늘어나면

### 같은 글자 사이를 k칸 이상 띄우라면

LeetCode 358번 Rearrange String k Distance Apart(프리미엄 문제)다. 한 박자 쉬는 풀이를 넓힌다. 쓴 글자를 큐에 넣고, 큐에 k개가 쌓이면 맨 앞 글자를 힙에 돌려놓는다. 힙이 비었는데 아직 글자가 남았으면 불가능하다. 짝수 칸 풀이도 "k칸 간격으로 놓기"로 넓힐 수 있지만, 가장 많은 글자가 여럿일 때 처리가 까다로워 힙 쪽이 덜 틀린다.

### 문자열이 아니라 정수 배열이라면

LeetCode 1054번 Distant Barcodes는 같은 문제를 정수로 낸다. 값의 범위가 넓으니 26칸 배열 대신 해시맵으로 센다. 답이 늘 존재한다고 보장해서 판정이 필요 없다.

### 쉬는 동안 빈 시간을 넣을 수 있다면

같은 작업 사이에 n칸을 두되 할 게 없으면 쉬어도 되고, 전체 시간을 최소로 하라는 문제가 [Task Scheduler](/posts/leetcode-task-scheduler)다. 불가능한 경우가 없는 대신 "쉬는 칸이 몇 개 필요한가"를 센다. 가장 많은 작업이 틀을 정한다는 생각이 이 글의 `(n + 1) / 2` 판정과 같은 뿌리다.

### 가능한 배치를 모두 구하라면

그때는 되돌아가며 놓는 풀이가 필요하다. 같은 글자는 구분하지 않으니 개수로 고르는 지금 방식이 중복을 만들지 않는다. 다만 답의 수 자체가 지수적으로 많아서 n이 작을 때만 의미가 있다.

가장 큰 것 두 개를 계속 꺼내는 힙 사용은 [Last Stone Weight](/posts/leetcode-last-stone-weight)에도 나온다. 거기서는 꺼낸 두 값을 부딪쳐 하나로 만들고, 여기서는 둘 다 하나씩 줄여 돌려놓는다.

## 면접에서 나올 만한 질문

### 가능한지 어떻게 바로 알 수 있나요?

가장 많은 글자의 개수가 `(n + 1) / 2`(나머지 버림)를 넘는지만 보면 된다. 한 글자를 최대한 떨어뜨려 놓을 수 있는 칸은 0, 2, 4, ... 칸이고 그 수가 `(n + 1) / 2`이기 때문이다. 넘지 않으면 짝수 칸 채우기로 늘 만들 수 있어서, 이 조건이 필요충분조건이다.

### 왜 힙을 쓰나요?

매번 가장 많이 남은 글자 두 개를 꺼내 하나씩 쓰고 다시 넣는 탐욕을 쓰는데, "가장 큰 것 꺼내기"와 "다시 넣기"를 반복하는 데 힙이 맞기 때문이다. 글자 종류가 26개 이하라 힙도 26칸을 넘지 않아 연산이 사실상 상수 시간이다. 전체는 O(n log 26)이다.

### 가장 많이 남은 글자부터 쓰는 탐욕이 맞다는 걸 어떻게 설명하나요?

"가장 많은 글자가 남은 글자 수의 절반을 넘지 않는다"는 조건이 매 차례 유지된다는 걸 보인다. 가장 많은 것과 두 번째를 하나씩 쓰면 남은 수가 2 줄고 최댓값도 대개 1 줄어서 조건이 이어진다. 그래서 마지막에 한 글자가 2개 이상 남는 일이 없다. 많은 글자를 뒤로 미루면 남은 글자 중 그 글자의 비율이 커져 조건이 깨진다.

### 힙 없이 O(n)으로 풀 수 있나요?

가장 많은 글자를 인덱스 0, 2, 4, ...에 먼저 놓고, 나머지 글자를 이어서 짝수 칸 끝까지, 그다음 1, 3, 5, ...에 채운다. 한 글자가 이웃한 두 칸을 함께 차지하려면 짝수 칸 수만큼 있어야 하는데, 그건 가장 많은 글자만 가능하고 그 글자는 짝수 칸에만 놓인다. 500글자 1만 번에서 힙의 368ms가 224ms로 줄었다.

### 짝수 칸 풀이에서 가장 많은 글자를 먼저 놓지 않으면요?

틀린다. `"abccc"`를 알파벳 순으로 채우면 a, b, c가 짝수 칸을 나눠 쓰고 c 둘이 홀수 칸에 가서 `acbcc`가 된다. c는 짝수 칸 수와 같은 3개라 짝수 칸을 혼자 다 써야 했다. 판정은 통과하고 결과만 틀려서 놓치기 쉬운 실수다.

### 같은 글자 사이를 k칸 띄우라면 어떻게 바꾸나요?

한 글자씩 꺼내는 힙 풀이에 대기 큐를 붙인다. 쓴 글자를 큐에 넣고 k개가 쌓이면 맨 앞 글자를 힙으로 돌려놓는다. 힙이 비었는데 큐에 아직 남은 글자가 있으면 불가능하다. 두 개씩 꺼내는 요령은 k = 2에만 맞아서 이렇게 넓어지지 않는다.

### 두 글자씩 꺼내는 풀이에서 놓치기 쉬운 곳은요?

마지막에 힙에 하나가 남았을 때 그 개수를 확인하는 것이다. 개수가 2 이상이면 같은 글자가 붙을 수밖에 없으니 `""`를 돌려줘야 한다. 확인 없이 한 글자만 붙이면 `"aaab"`에서 `aba`처럼 글자가 사라진 답이 나온다.
