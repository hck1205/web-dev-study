[LeetCode 124. Binary Tree Maximum Path Sum](https://leetcode.com/problems/binary-tree-maximum-path-sum/)은 트리 문제 묶음에서 가장 어려운 문제로 자주 꼽힌다. 코드는 열 줄 남짓인데, 한 함수가 "위로 돌려주는 값"과 "답으로 기록하는 값"이 서로 다르다는 걸 이해해야 풀린다. 이걸 섞으면 답이 그럴듯하게 틀린다. 면접에서는 그 두 값을 왜 따로 다루는지 설명하는 것이 곧 답이다.

이 글은 모든 시작점에서 걸어 보는 O(n²) 풀이부터 시작해, 꼭대기를 정하고 내려가 보기, 내려가는 값을 메모해 두기, 한 번의 후위 순회로 끝내기, 그걸 재귀 없이 돌리기까지 다섯 풀이를 따라간다. 자식의 답을 받아 내 답을 만드는 바텀업 재귀는 [Maximum Depth of Binary Tree](/posts/leetcode-maximum-depth-of-binary-tree)에서 처음 봤다. 이 글은 그 모양에 "답은 따로 기록한다"를 더한 것이다. 간선 수로 같은 구조를 푸는 [Diameter of Binary Tree](/posts/leetcode-diameter-of-binary-tree)를 먼저 보면 더 쉽다. 실행 결과는 Node.js 22, Python 3.13, Java 21에서 돌린 값이다.

## 길은 꼭대기에서 한 번만 꺾인다

이진 트리가 주어진다. 경로는 간선으로 이어진 노드들의 줄이고, 같은 노드를 두 번 지나지 않는다. 노드가 적어도 하나 있어야 하고, 뿌리를 지나지 않아도 된다. 경로 위 노드 값의 합이 가장 큰 경로의 합을 돌려준다.

풀이에 영향을 주는 제약이다.

- 노드 수는 1 이상 3×10^4 이하다. O(n²)이면 9억 번이라 시간 초과가 난다. 그리고 일자 트리면 깊이도 3만이라 재귀가 위험하다.
- 값은 -1000 이상 1000 이하다. 음수가 있다는 게 이 문제의 전부다. 양수만 있다면 트리 전체를 지나는 가장 긴 길을 찾으면 그만이다.
- 합은 최대 3×10^7 정도라 32비트 정수로 충분하다. 넘침 걱정은 합이 아니라 다른 곳에서 나온다(뒤에서 본다).

이 글의 예시 트리다.

```text
[-10, 9, 20, -6, null, 15, -7, null, null, null, null, 4]

          -10
         /    \
        9      20
       /      /  \
     -6     15    -7
                  /
                 4
```

트리에서 경로를 하나 고르면 그 경로에는 가장 위에 있는 노드가 꼭 하나 있다. 이 노드를 꼭대기라 부르자. 경로는 꼭대기의 왼쪽 아래에서 올라와 꼭대기를 지나 오른쪽 아래로 내려가거나, 한쪽으로만 내려간다. 꼭대기에서 위로 더 올라갈 수는 없다. 올라가면 그 위 노드가 꼭대기가 되니까. 그리고 꼭대기가 아닌 노드에서는 꺾일 수 없다. 부모에서 내려와 두 자식으로 갈라지면 같은 노드를 두 번 지나야 하기 때문이다.

## 모든 시작점에서 걸어 보기

가장 직접적인 방법은 모든 경로를 다 걸어 보는 것이다. 트리를 방향 없는 그래프로 보면, 어떤 노드에서 출발해 갈 수 있는 모든 곳까지 걸으며 합을 잴 수 있다. 출발점마다 그렇게 하면 모든 경로를 한 번씩(양 방향으로 두 번) 보게 된다.

```js
function maxPathSum(root) {
  // 부모 방향으로도 갈 수 있게 이웃 목록을 만든다
  const adj = new Map();
  (function link(n, parent) {
    if (!n) return;
    adj.set(n, []);
    if (parent) {
      adj.get(n).push(parent);
      adj.get(parent).push(n);
    }
    link(n.left, n);
    link(n.right, n);
  })(root, null);

  let best = -Infinity;
  for (const start of adj.keys()) {
    // start에서 출발하는 모든 경로를 걸으며 합을 잰다
    const stack = [[start, null, start.val]]; // [지금 노드, 온 노드, 지금까지의 합]
    while (stack.length) {
      const [node, from, sum] = stack.pop();
      best = Math.max(best, sum);
      for (const next of adj.get(node)) {
        if (next !== from) stack.push([next, node, sum + next.val]); // 되돌아가지 않는다
      }
    }
  }
  return best;
}
```

트리에는 사이클이 없어서 "온 노드로 되돌아가지 않기"만 지키면 같은 노드를 두 번 지나지 않는다. 출발점 하나에서 모든 노드에 한 번씩 닿으니 O(n), 출발점이 n개라 전체 O(n²)이다.

```text
노드 1000개   42 ms
노드 2000개   195 ms
노드 4000개   941 ms
```

노드가 두 배가 되면 시간이 네다섯 배씩 는다. 이 추세면 3만 개는 수십 초다. 모든 경로를 하나하나 보는 한 O(n²)을 벗어날 수 없다. 경로 대신 꼭대기를 기준으로 세면 개수가 n개로 줄어든다.

## 꼭대기를 정하고 양쪽으로 내려가 보기

모든 경로는 꼭대기가 하나씩 있다. 그러니 노드마다 "이 노드가 꼭대기인 경로 중 가장 큰 합"을 구해 그중 최댓값을 고르면 된다.

이 노드가 꼭대기라면 경로는 이 노드에서 왼쪽 아래로 한 줄, 오른쪽 아래로 한 줄 내려간다. 각 줄은 비워도 된다. 그러니 필요한 값은 "왼쪽 자식에서 출발해 아래로만 내려가는 경로의 최대 합"과 오른쪽 자식의 같은 값이다. 이 값을 이 글에서는 이득(gain)이라 부른다.

이득은 재귀로 구한다. 노드 하나에서 출발해 아래로 내려가는 경로는 자기 값에, 왼쪽 자식의 이득과 오른쪽 자식의 이득 중 큰 쪽을 더한 것이다. 둘 다 음수면 아무 쪽으로도 내려가지 않고 자기 혼자가 낫다.

```js
// node에서 출발해 아래로만 내려가는 경로의 최대 합
function down(node) {
  if (!node) return 0;
  return node.val + Math.max(0, down(node.left), down(node.right));
}

function maxPathSum(root) {
  let best = -Infinity;
  (function visit(n) {
    if (!n) return;
    // n이 꼭대기: 양쪽 이득이 음수면 그쪽은 가지 않는다(0)
    const through = n.val + Math.max(0, down(n.left)) + Math.max(0, down(n.right));
    best = Math.max(best, through);
    visit(n.left);
    visit(n.right);
  })(root);
  return best;
}
```

`Math.max(0, …)`이 이 문제의 첫 번째 열쇠다. 이득이 음수인 쪽은 경로에 넣지 않는 게 언제나 낫다. 음수를 더하면 합이 줄어들 뿐이고, 경로가 그쪽으로 꼭 가야 할 이유가 없다.

정확하지만 같은 계산을 반복한다. 노드마다 `down`을 부르고, `down`은 그 아래 서브트리 전체를 다시 훑는다. 깊이 d인 노드의 이득은 위쪽 조상 d개가 각각 한 번씩 다시 계산하니, 전체가 O(n·h)다. 균형 트리면 O(n log n)이지만 일자 트리면 O(n²)이다. 노드 4000개 일자 트리에서 187ms, 균형 트리에서는 1ms 안쪽이었다.

## 내려가는 이득을 적어 두기

같은 노드의 이득을 몇 번씩 다시 구하는 게 낭비라면, 한 번 구한 값을 표에 적어 두면 된다. [동적 계획법](/posts/dynamic-programming)의 메모이제이션 그대로다.

```js
function maxPathSum(root) {
  const memo = new Map(); // 노드 → 아래로 내려가는 최대 합
  function down(node) {
    if (!node) return 0;
    if (memo.has(node)) return memo.get(node);
    const v = node.val + Math.max(0, down(node.left), down(node.right));
    memo.set(node, v);
    return v;
  }

  let best = -Infinity;
  (function visit(n) {
    if (!n) return;
    best = Math.max(best, n.val + Math.max(0, down(n.left)) + Math.max(0, down(n.right)));
    visit(n.left);
    visit(n.right);
  })(root);
  return best;
}
```

노드마다 이득을 한 번만 계산하니 O(n)이다. 공간은 표가 O(n), 재귀가 O(h)다. 이미 충분히 빠르지만 트리를 두 번 훑고(꼭대기 방문, 이득 계산), 노드 수만큼의 Map을 따로 들고 있다.

그런데 잘 보면 이득을 계산하는 순간 이미 필요한 재료가 다 있다. 노드 `n`의 이득을 구하려면 왼쪽과 오른쪽 자식의 이득을 받아야 하는데, 그 두 값이 바로 `n`을 꼭대기로 하는 경로를 계산하는 재료다. 이득을 구하는 김에 꼭대기 값도 같이 기록하면 트리를 한 번만 돌면 되고 표도 필요 없다.

## 한 번의 후위 순회로 두 값을 함께 다루기

함수 `gain(node)` 하나가 두 가지 일을 한다.

- 기록: `node`를 꼭대기로 하는 경로의 최대 합 `node.val + 왼쪽 이득 + 오른쪽 이득`을 계산해 바깥 변수 `best`와 비교한다. 이 경로는 `node`에서 꺾인다.
- 돌려주기: 부모에게는 `node.val + max(왼쪽 이득, 오른쪽 이득)`을 돌려준다. 부모 입장에서 `node`는 경로의 중간이라 여기서 꺾일 수 없다. 한쪽만 고른다.

두 값이 다른 이유가 이 문제의 전부다. 부모가 `node`를 지나는 경로를 만들 때, 경로는 부모에서 `node`로 내려와 `node`의 한쪽 자식으로만 계속 갈 수 있다. 양쪽을 다 돌려주면 부모가 "왼쪽 아래 → `node` → 오른쪽 아래 → 다시 `node` → 부모"처럼 `node`를 두 번 지나는 불가능한 경로를 만든다.

```js
function maxPathSum(root) {
  let best = -Infinity; // 0이 아니다. 모든 값이 음수일 수 있다
  function gain(node) {
    if (!node) return 0;
    // 자식 이득이 음수면 그쪽은 가지 않는다
    const left = Math.max(0, gain(node.left));
    const right = Math.max(0, gain(node.right));
    // 기록: node에서 꺾이는 경로
    best = Math.max(best, node.val + left + right);
    // 돌려주기: 부모가 이어 붙일 수 있는 한쪽 줄
    return node.val + Math.max(left, right);
  }
  gain(root);
  return best;
}
```

자식을 먼저 계산하고 자기를 계산하니 후위 순회다. 예시 트리에서 노드마다 무엇을 기록하고 무엇을 올려 보내는지 따라가 보자. 칸은 트리를 층 순서로 펼친 것이고, 초록색 칸은 계산이 끝난 노드다.

### 바깥 변수 없이 두 값을 함께 돌려주기

`best`를 바깥 변수로 두는 게 마음에 걸리면, 함수가 두 값을 짝으로 돌려주게 해도 된다. 첫째는 위로 올릴 이득, 둘째는 이 서브트리 안에서 찾은 최고 기록이다.

```js
function maxPathSum(root) {
  // [위로 올릴 이득, 이 서브트리 안의 최대 경로 합]
  function solve(node) {
    if (!node) return [0, -Infinity];
    const [lg, lb] = solve(node.left);
    const [rg, rb] = solve(node.right);
    const l = Math.max(0, lg), r = Math.max(0, rg);
    return [node.val + Math.max(l, r), Math.max(lb, rb, node.val + l + r)];
  }
  return solve(root)[1];
}
```

빈 서브트리의 최고 기록은 `-Infinity`여야 한다. 0으로 두면 모든 값이 음수인 트리에서 "빈 경로 0"이 답으로 뽑힌다. 경로에는 노드가 적어도 하나 있어야 한다. 함수가 바깥 상태를 건드리지 않아 테스트하기 쉽고, 여러 스레드에서 동시에 불러도 안전하다. 대신 호출마다 배열을 하나 만든다.

### Python과 Java로 쓰면

```python
class Solution:
    def maxPathSum(self, root: Optional[TreeNode]) -> int:
        best = float("-inf")

        def gain(node):
            nonlocal best  # 바깥 변수를 고치려면 nonlocal이 필요하다
            if node is None:
                return 0
            left = max(0, gain(node.left))
            right = max(0, gain(node.right))
            best = max(best, node.val + left + right)
            return node.val + max(left, right)

        gain(root)
        return best
```

Python에서 안쪽 함수가 바깥 변수에 값을 다시 넣으려면 `nonlocal`이 필요하다. 빼먹으면 `best = …` 줄 때문에 `best`가 안쪽 지역 변수가 되어, 그 줄의 `max(best, …)`에서 `UnboundLocalError`가 난다. 리스트 `best = [float("-inf")]`를 두고 `best[0]`을 고치는 우회도 흔히 쓴다.

```java
class Solution {
    private int best;

    public int maxPathSum(TreeNode root) {
        best = Integer.MIN_VALUE; // 0으로 두면 모든 값이 음수일 때 틀린다
        gain(root);
        return best;
    }

    private int gain(TreeNode node) {
        if (node == null) return 0;
        int left = Math.max(0, gain(node.left));
        int right = Math.max(0, gain(node.right));
        best = Math.max(best, node.val + left + right);
        return node.val + Math.max(left, right);
    }
}
```

Java는 `best`를 필드로 둔다. 람다나 지역 클래스는 바깥의 지역 변수를 고칠 수 없어서(effectively final), 필드나 길이 1짜리 배열을 쓴다. `best`를 `maxPathSum` 안에서 매번 초기화하는 것도 잊으면 안 된다. 같은 `Solution` 객체로 여러 테스트를 돌리면 앞 테스트의 기록이 남는다.

`Integer.MIN_VALUE`는 비교에만 쓰고 더하지 않는다. 빈 자식의 이득을 `MIN_VALUE`로 돌려주고 음수 자르기를 빼먹으면 `-3 + Integer.MIN_VALUE`가 넘쳐서 `2147483645`가 된다. 노드 `-3` 하나짜리 트리에서 실제로 이 값이 답으로 나왔다. 빈 자식은 0을 돌려주고, 음수는 `Math.max(0, …)`으로 자르는 원래 코드는 이 넘침이 생길 틈이 없다.

## 재귀 없이 후위 순서로 돌기

노드가 3×10^4개까지라 일자 트리면 재귀가 3만 단계 쌓인다. 직접 돌려 봤다.

```text
Node.js 22   깊이 10000   RangeError: Maximum call stack size exceeded
Python 3.13  깊이 30000   RecursionError
Java 21      깊이 3000    통과
             깊이 30000   StackOverflowError  (-Xss64m이면 통과)
```

후위 순회를 반복문으로 바꾸는 가장 쉬운 방법은 이렇다. 스택으로 "나 → 왼쪽 → 오른쪽"이 아니라 "나 → 오른쪽 → 왼쪽" 순서가 나오게 노드를 모은 뒤 그 순서를 뒤집으면, "왼쪽 → 오른쪽 → 나"가 된다. 뒤집은 순서로 돌면 언제나 자식이 부모보다 먼저 나오니, 자식의 이득을 표에서 꺼내 쓸 수 있다.

```js
function maxPathSum(root) {
  // 1. 나 → 오른쪽 → 왼쪽 순서로 모은다 (스택에 왼쪽을 먼저 넣는다)
  const order = [];
  const stack = [root];
  while (stack.length) {
    const n = stack.pop();
    order.push(n);
    if (n.left) stack.push(n.left);
    if (n.right) stack.push(n.right);
  }
  // 2. 거꾸로 돌면 자식이 항상 부모보다 먼저 나온다
  const gain = new Map([[null, 0]]);
  let best = -Infinity;
  for (let i = order.length - 1; i >= 0; i--) {
    const n = order[i];
    const l = Math.max(0, gain.get(n.left));
    const r = Math.max(0, gain.get(n.right));
    best = Math.max(best, n.val + l + r);
    gain.set(n, n.val + Math.max(l, r));
  }
  return best;
}
```

`gain`에 `null → 0`을 미리 넣어 두면 빈 자식을 따로 확인하지 않아도 된다. 시간 O(n), 공간은 순서 배열과 표로 O(n)이다. 재귀 버전보다 메모리를 더 쓰지만 깊이 3만, 10만에서도 그대로 돈다. Python도 같은 구조로 옮기면 `RecursionError` 없이 통과했다.

```python
def max_path_sum(root):
    order, stack = [], [root]
    while stack:
        node = stack.pop()
        order.append(node)
        if node.left:
            stack.append(node.left)
        if node.right:
            stack.append(node.right)
    gain = {None: 0}
    best = float("-inf")
    for node in reversed(order):
        left = max(0, gain[node.left])
        right = max(0, gain[node.right])
        best = max(best, node.val + left + right)
        gain[node] = node.val + max(left, right)
    return best
```

## 다섯 풀이를 나란히 놓으면

| 풀이 | 시간 | 추가 공간 | 언제 고르나 |
|---|---|---|---|
| 모든 시작점에서 걷기 | O(n²) | O(n) | 정답 검증용 브루트포스 |
| 꼭대기마다 이득 다시 계산 | O(n·h), 최악 O(n²) | O(h) | 꼭대기라는 관점을 설명할 때 |
| 이득 메모이제이션 | O(n) | O(n) | DP로 접근했다는 걸 보여 줄 때 |
| 후위 순회 한 번 | O(n) | O(h) | 기본 답 |
| 반복 후위 순회 | O(n) | O(n) | 트리가 아주 깊을 수 있을 때 |

브루트포스부터 메모이제이션까지가 "무엇을 세는가"를 바꾸는 과정이다. 경로를 세면 O(n²)개, 꼭대기를 세면 n개다. 그다음은 꼭대기마다 필요한 재료(양쪽 이득)를 언제 계산하느냐의 차이다.

## 그럴듯하게 틀리는 네 가지

같은 예시 트리에서는 맞는 답을 내다가 다른 입력에서만 틀리는 실수가 많다. 각각 실제로 돌려 본 결과다.

### 답을 0에서 시작한다

```js
let best = 0; // 모두 음수인 트리에서 틀린다
// [-3] → 0 (정답 -3),  [-3, -1, -2] → 0 (정답 -1)
```

경로에는 노드가 적어도 하나 있어야 하는데, 0에서 시작하면 "아무 노드도 고르지 않은 경로"가 답이 되어 버린다. `-Infinity`나 뿌리 값, `Integer.MIN_VALUE`로 시작한다. 예시 트리처럼 양수가 하나라도 있으면 우연히 맞아서 더 늦게 발견된다.

### 위로 양쪽을 다 올려 보낸다

```js
return node.val + left + right; // 꺾인 경로를 부모에게 넘긴다
// [1, 2, 3, 4, 5] → 15 (정답 11)
```

트리 전체 합 15가 나왔다. 2에서 양쪽(4, 5)을 다 받은 11을 부모 1에게 넘기니, 1이 "4 → 2 → 5 → 다시 2 → 1 → 3"이라는 2를 두 번 지나는 경로를 만들었다. 정답은 4 → 2 → 5의 11이다. 기록은 양쪽, 올림은 한쪽이다.

### 음수 이득을 자르지 않는다

```js
const left = gain(node.left);   // Math.max(0, …)이 빠졌다
const right = gain(node.right);
// [2, -1, -2] → -1 (정답 2),  예시 트리 → 34 (정답 35)
```

예시 트리에서는 20의 오른쪽 이득 -3을 그대로 더해, 20에서 꺾이는 합이 35가 아니라 32가 됐다. 그래서 뿌리에서 꺾이는 34가 답으로 뽑혔다. `[2, -1, -2]`에서는 2 혼자가 답인데, 양쪽 음수를 억지로 더해 -1이 나왔다. 음수 쪽은 안 가는 선택지가 늘 있다.

### 답 대신 돌려준 값을 낸다

`return gain(root)`라고 쓰면 뿌리에서 아래로 한 줄 내려가는 최대 합이 나온다. 예시 트리에서 25다. 문제는 경로가 뿌리를 지나지 않아도 된다고 했고, 꺾여도 된다고 했다. 답은 `best`에 있다.

## 면접관이 이어서 묻는 것

### 경로 자체를 돌려 달라면

합 대신 경로의 노드 목록을 원하면, 기록할 때 꼭대기 노드도 함께 저장하고 이득을 노드별로 표에 남긴다. 끝난 뒤 꼭대기에서 양쪽으로, 이득이 양수인 동안 이득이 큰 자식을 따라 내려가 이어 붙이면 된다. 예시 트리는 `[15, 20]`, `[1, 2, 3, 4, 5]`는 `[4, 2, 5]`가 나왔다. 무작위 트리 3000개로 이렇게 복원한 경로의 합이 답과 같은지 확인했다.

### 경로가 뿌리에서 시작해야 한다면

꺾임이 없어지니 훨씬 쉽다. `gain(root)`가 바로 답이다. 예시 트리에서 -10 → 20 → 15의 25다. 잎에서 끝나야 한다는 조건까지 붙으면 음수 자르기를 할 수 없다(잎까지는 가야 하니까). LeetCode 112 Path Sum은 "뿌리에서 잎까지 합이 target인 경로가 있나"를 묻는 이 계열의 입문 문제다.

### 합 대신 간선 수라면

노드 값 대신 간선 하나를 길이 1로 세면 [Diameter of Binary Tree](/posts/leetcode-diameter-of-binary-tree)가 된다. 길이는 음수가 없어서 자르기가 필요 없고, "기록은 양쪽, 올림은 한쪽"은 그대로다. 값이 같은 노드끼리만 이어지는 가장 긴 경로(LeetCode 687 Longest Univalue Path)도 같은 틀에서 "자식 값이 나와 같을 때만 이어 붙인다"는 조건만 바뀐다.

### 위에서 아래로 내려가는 아무 구간의 합이 target인 경로 수라면

LeetCode 437 Path Sum III다. 경로가 꺾이지 않고 아래로만 가지만 시작과 끝이 자유롭다. 뿌리에서 지금 노드까지의 누적 합을 해시맵에 세어 두고, `누적 합 - target`이 몇 번 나왔는지 보는 [해시맵](/posts/ds-hash-map) 누적 합 기법으로 O(n)에 푼다. 배열의 부분합 문제를 트리 위로 옮긴 모양이다.

### 이진 트리가 아니라 일반 트리나 그래프라면

자식이 여러 개인 트리라면 꼭대기에서 고를 수 있는 줄이 두 개까지인 것은 그대로다. 자식 이득 중 가장 큰 두 개를 골라 기록하고, 가장 큰 하나를 올린다. 사이클이 있는 일반 그래프에서 같은 노드를 두 번 지나지 않는 최대 경로를 찾는 건 NP-난해 문제다. 이 문제가 O(n)에 풀리는 건 트리에 사이클이 없어서 "꼭대기 하나"라는 구조가 생기기 때문이다.

### 같은 패턴의 다른 문제

트리 묶음의 다른 글로 층 단위로 훑는 [Binary Tree Level Order Traversal](/posts/leetcode-binary-tree-level-order-traversal), 트리를 문자열로 바꾸는 [Serialize and Deserialize Binary Tree](/posts/leetcode-serialize-and-deserialize-binary-tree)가 있다. 전체 순서는 [LeetCode 공부 가이드](/posts/leetcode-study-guide)에 있다.

## 기록은 양쪽, 올림은 한쪽

모든 경로는 가장 높은 노드 하나에서만 꺾인다. 그래서 노드마다 자기를 꼭대기로 하는 경로의 합(자기 값 + 왼쪽 이득 + 오른쪽 이득)을 기록하고, 부모에게는 한쪽 줄만(자기 값 + 큰 쪽 이득) 올려 보낸다. 이득이 음수인 쪽은 0으로 잘라 가지 않고, 답은 0이 아니라 음의 무한대에서 시작한다. 후위 순회 한 번이라 O(n) 시간, O(h) 공간이고, 깊이가 3만까지 갈 수 있으니 반복 후위 순회도 손에 익혀 둔다. "함수가 돌려주는 값과 답이 다를 수 있다"는 이 생각은 지름, 가장 긴 같은 값 경로, 트리 DP 문제 전반에 그대로 쓰인다.

## 면접에서 나올 만한 질문

### 함수가 돌려주는 값과 기록하는 값이 왜 다른가요?

기록하는 값은 지금 노드에서 꺾이는 경로라 왼쪽과 오른쪽 이득을 둘 다 더한다. 돌려주는 값은 부모가 이어 붙일 경로인데, 부모 입장에서 지금 노드는 경로의 중간이라 꺾일 수 없으니 한쪽만 고른다. 양쪽을 다 돌려주면 부모가 같은 노드를 두 번 지나는 경로를 만들어, `[1, 2, 3, 4, 5]`에서 정답 11 대신 15가 나온다.

### 왜 자식 이득을 0과 비교해서 자르나요?

이득이 음수인 쪽을 경로에 넣으면 합이 줄어들 뿐이고, 경로가 그쪽으로 꼭 가야 할 이유가 없다. 0으로 자르는 건 "그쪽으로는 내려가지 않는다"는 선택이다. 자르지 않으면 `[2, -1, -2]`에서 2 대신 -1이 나온다.

### 답을 왜 0이 아니라 음의 무한대로 시작하나요?

경로에는 노드가 적어도 하나 있어야 한다. 모든 값이 음수면 답은 가장 큰 음수 노드 하나인데, 0에서 시작하면 그보다 커서 노드를 하나도 고르지 않은 0이 답이 된다. `-Infinity`, `Integer.MIN_VALUE`, 또는 뿌리 값으로 시작한다.

### 시간과 공간 복잡도는요?

후위 순회 한 번에 노드마다 상수 시간 일을 해서 O(n)이다. 추가 공간은 재귀 깊이 O(h)로, 균형 트리면 O(log n), 일자 트리면 O(n)이다. 모든 시작점에서 걷는 브루트포스는 O(n²)이고, 꼭대기마다 이득을 다시 구하면 O(n·h)다.

### 트리가 3만 깊이로 기울면요?

재귀가 스택을 넘친다. 이 환경에서 Node.js는 1만, Python은 기본 한도 1000 때문에 바로, Java 기본 스택은 3만에서 넘쳤다. "나 → 오른쪽 → 왼쪽" 순서로 모은 뒤 뒤집어 후위 순서를 만들고, 자식 이득을 표에 담아 반복문으로 돌리면 깊이와 상관없이 O(n)에 돈다.

### Java에서 조심할 점은요?

`best`를 필드로 두면 `maxPathSum`을 부를 때마다 초기화해야 한다. 그리고 `Integer.MIN_VALUE`는 비교에만 쓴다. 빈 자식의 이득을 `MIN_VALUE`로 돌려주고 거기에 음수를 더하면 넘쳐서 큰 양수가 된다. 노드 -3 하나짜리 트리에서 2147483645가 나왔다. 빈 자식은 0을 돌려주고 음수를 0으로 자르면 이 문제가 생기지 않는다.

### 자식이 여러 개인 트리라면 어떻게 바꾸나요?

꼭대기에서 꺾이는 경로는 여전히 두 갈래까지만 쓸 수 있다. 자식 이득 중 양수인 것 가운데 가장 큰 두 개를 더해 기록하고, 가장 큰 하나만 위로 올린다. 자식 수만큼 훑으며 상위 두 개를 유지하면 되니 전체는 여전히 O(n)이다.
