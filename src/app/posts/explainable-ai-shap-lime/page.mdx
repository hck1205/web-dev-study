대출 심사 모델을 배포하고 몇 주 지나서 고객센터에서 요청이 온다. 거절된 고객이 이유를 묻는데 화면에는 "승인 확률 2.1%"만 찍혀 있다는 것이다. 규정상 거절 사유를 안내해야 하고, 감사팀은 모델이 성별이나 나이 같은 걸 몰래 쓰고 있지 않은지 확인하고 싶어 한다. 모델은 결정 트리 수백 개를 더한 그래디언트 부스팅이라 트리 하나를 열어 봐서는 답이 나오지 않는다.

이럴 때 쓰는 도구가 SHAP과 LIME이다. 둘 다 "이 예측에서 각 특징이 얼마나 기여했나"를 숫자로 내놓는데, 계산 방식이 완전히 다르고 같은 사람에게 다른 답을 주기도 한다. 이 글은 작은 대출 데이터로 둘을 직접 돌려서, 섀플리 값을 손으로 계산한 결과가 라이브러리와 맞는지 보고, 두 방식이 어디서 갈리는지, 설명을 믿으면 안 되는 경우는 언제인지를 따라간다.

실험 환경은 Python 3.13, scikit-learn 1.9, shap 0.54, lime 0.2.0.1이다. 데이터는 아래처럼 직접 만들었다. 진짜 정답 규칙을 알고 있어야 설명이 맞는지 판단할 수 있기 때문이다. 모델 학습의 기본은 [딥러닝 기초 글](/posts/deep-learning-basics)에 있다.

```python
import numpy as np
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.model_selection import train_test_split

r = np.random.default_rng(42); n = 3000
income = r.uniform(20, 120, n)            # 연소득 (백만 원)
dti    = r.uniform(0, 80, n)              # 부채 비율 (%)
late   = r.poisson(0.8, n).clip(0, 5)     # 최근 2년 연체 횟수
years  = r.uniform(0, 20, n)              # 근속 연수
# 정답 규칙: 소득·근속은 승인 쪽, 부채·연체는 거절 쪽
logit = 0.05*(income-60) - 0.07*(dti-40) - 0.9*(late-0.8) + 0.12*(years-8)
y = (r.random(n) < 1 / (1 + np.exp(-logit))).astype(int)

X = np.c_[income, dti, late, years]
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.25, random_state=0)
model = GradientBoostingClassifier(random_state=0).fit(Xtr, ytr)
```

```text
approve rate 0.594  test acc 0.796
```

승인 비율 59.4%, 시험 정확도 79.6%다. 정답 규칙 자체에 무작위가 섞여 있어서 100%는 나올 수 없다. 설명할 고객은 연소득 4,500만 원, 부채 비율 55%, 연체 2회, 근속 1년인 사람이고, 모델은 이 사람의 승인 확률을 2.08%로 냈다.

## 모델 전체를 설명할까, 이 한 건을 설명할까

설명은 두 종류로 나뉜다. 전역 설명은 "이 모델은 대체로 무엇을 보고 판단하나"에 답한다. 감사팀의 질문이 이쪽이다. 지역 설명은 "이 고객은 왜 거절됐나"에 답한다. 고객센터의 질문이 이쪽이다. 둘은 답이 다를 수 있다. 모델이 평소에는 부채 비율을 가장 많이 보더라도, 특정 고객의 거절은 소득 때문일 수 있다.

전역 설명부터 보자. scikit-learn의 트리 모델에는 `feature_importances_`가 있고, 모델 종류와 상관없이 쓸 수 있는 순열 중요도(permutation importance)도 있다. 순열 중요도는 시험 데이터에서 특징 한 열만 무작위로 섞었을 때 정확도가 얼마나 떨어지는지를 잰다.

```python
from sklearn.inspection import permutation_importance
pi = permutation_importance(model, Xte, yte, n_repeats=10, random_state=0)
print(pi.importances_mean)          # 섞었을 때 정확도 하락
print(model.feature_importances_)   # 트리 분할에서 불순도를 줄인 양
```

```text
perm importance      income 0.1032  dti 0.1529  late 0.0309  years 0.0208
impurity importance  income 0.3849  dti 0.4311  late 0.0977  years 0.0862
```

두 방법 모두 부채 비율(dti) > 소득(income) > 연체(late), 근속(years) 순이다. 다만 숫자의 뜻이 다르다. 불순도 기반 중요도는 학습 데이터에서 트리가 그 특징으로 얼마나 자주, 얼마나 크게 나눴는지를 센다. 값의 종류가 많은 연속 특징이 나눌 자리가 많아서 부풀려지는 경향이 있고, 학습 데이터에서 계산하니 과적합한 특징도 높게 나온다. 순열 중요도는 시험 데이터에서 실제 성능 하락을 재니 이 문제가 덜하다. 둘이 크게 다르면 순열 중요도 쪽을 먼저 믿는다.

이 숫자들은 "모델에게 얼마나 중요한가"이지 "어느 방향인가"는 말해 주지 않는다. 소득이 높으면 승인 쪽인지 거절 쪽인지는 여기서 알 수 없다. 그리고 한 고객의 거절 사유로 쓸 수도 없다. 그래서 예측 하나를 쪼개는 방법이 필요하다.

## 기여를 공정하게 나누는 방법: 섀플리 값

섀플리 값은 게임 이론에서 왔다. 여러 사람이 함께 일해서 번 돈을 각자의 기여만큼 나누는 방법이다. 기여를 재는 가장 단순한 방법은 "그 사람이 빠지면 얼마나 줄어드나"인데, 이건 누구와 함께 있느냐에 따라 달라진다. 혼자서는 아무것도 못 하지만 특정 동료와 함께면 큰일을 하는 사람도 있다. 섀플리 값은 가능한 모든 동료 조합에서 "이 사람이 들어오기 전과 후의 차이"를 재서 정해진 비율로 평균 낸다.

모델 설명에 옮기면 사람은 특징, 번 돈은 예측값이다. 특징 집합 S만 이 고객의 값으로 알고 나머지는 모른다고 할 때의 예측을 v(S)라고 하자. "모른다"는 걸 표현하는 흔한 방법은 나머지 특징을 배경 데이터(학습 데이터에서 뽑은 100명)의 값으로 채워 예측한 뒤 평균 내는 것이다.

- v(공집합): 아무것도 모를 때. 배경 100명의 평균 예측 = 0.6336
- v(전체): 네 특징을 모두 이 고객 값으로 넣은 예측 = 0.0208

섀플리 값은 이 차이 0.6336 → 0.0208을 네 특징에 나눠 준다. 특징 i의 몫은 i를 포함하지 않는 모든 부분집합 S마다 `v(S ∪ i) - v(S)`를 구하고, `|S|! × (M - |S| - 1)! / M!`(M은 특징 수)의 가중치로 더한 값이다. 가중치는 "특징을 무작위 순서로 하나씩 넣을 때 i 앞에 정확히 S가 들어와 있을 확률"이다. 즉 모든 순서를 고르게 따져서 평균 낸다.

이렇게 나누면 좋은 성질이 몇 가지 생긴다. 몫을 다 더하면 정확히 v(전체) - v(공집합)이 된다(효율성). 어떤 조합에서도 기여가 같은 두 특징은 같은 몫을 받는다(대칭성). 예측에 전혀 영향이 없는 특징은 0을 받는다. 섀플리 값은 이 성질들을 모두 만족하는 유일한 분배 방법이라는 게 증명되어 있고, SHAP은 이걸 모델 설명에 가져온 방법이다.

## 평균 63%에서 이 고객의 2%까지

특징이 넷이면 부분집합은 2⁴ = 16개다. 16개 v(S)를 전부 계산하고 위 식대로 더했다.

```python
import itertools, math
x = np.array([45, 55, 2, 1.0])
bg = Xtr[np.random.default_rng(0).choice(len(Xtr), 100, replace=False)]
f = lambda A: model.predict_proba(A)[:, 1]

def v(S):                       # S에 든 특징만 x의 값으로, 나머지는 배경 값으로
    A = bg.copy(); A[:, list(S)] = x[list(S)]
    return f(A).mean()

M = 4
vals = {S: v(S) for k in range(M + 1) for S in itertools.combinations(range(M), k)}
for i in range(M):
    phi = 0
    for S, val in vals.items():
        if i in S: continue
        w = math.factorial(len(S)) * math.factorial(M - len(S) - 1) / math.factorial(M)
        phi += w * (vals[tuple(sorted(S + (i,)))] - val)
    print(i, round(phi, 4))
```

```text
phi income  -0.2196
phi dti     -0.1739
phi late    -0.1136
phi years   -0.1057
sum phi -0.6128  base+sum 0.0208
```

네 몫을 더하면 -0.6128이고, 평균 0.6336에 더하면 정확히 0.0208이 된다. shap 라이브러리로 같은 계산을 시키면 같은 숫자가 나온다.

```python
import shap
explainer = shap.Explainer(f, bg, algorithm="exact")
sv = explainer(x[None])
print(sv.values[0], sv.base_values[0])
```

```text
shap exact [-0.2196 -0.1739 -0.1136 -0.1057] base 0.6336
```

부채 비율이 1위, 소득이 2위로 순열 중요도와 순서가 같다. 순열 중요도와 달리 이 값은 "평균적으로 예측을 얼마나 움직였나"를 확률 단위로 말해 주고, 건별 값이 남아 있으니 방향도 볼 수 있다. 소득이 낮은 사람들의 몫은 음수, 높은 사람들의 몫은 양수로 모여 있는지를 점으로 찍어 보는 게 SHAP 문서의 요약 그림(beeswarm)과 의존 그림이다.

고객센터에 줄 답은 이렇게 만들 수 있다. "소득, 부채 비율, 연체 이력 순으로 거절에 영향을 줬다." 이 순서는 전역 중요도 순서(부채 비율이 1위)와 다르다는 데 주목한다. 모델 전체에서는 부채 비율이 가장 중요하지만, 이 고객은 소득이 평균에서 더 많이 벗어나 있어서 소득의 몫이 컸다.

그리고 출발점이 무엇이냐에 따라 숫자가 바뀐다는 것도 기억해 둔다. 배경 데이터를 전체 신청자로 잡았는지, 승인된 사람만으로 잡았는지에 따라 "평균보다 낮다"의 기준이 달라진다. 설명을 보여 줄 때 기준이 무엇인지 함께 적는다.

## 특징이 많아지면 계산이 폭발한다

정확한 섀플리 값은 부분집합을 전부 돌아야 한다. 특징 4개면 16개지만, 30개면 2³⁰ = 약 10억 7천만 개다. 부분집합마다 배경 100명을 예측하니 예측 호출이 천억 번이 넘는다. 실무 모델은 특징이 수십~수백 개라 정확한 계산은 불가능하다. 그래서 SHAP 라이브러리는 모델 종류에 따라 다른 근사를 쓴다.

Kernel SHAP은 모델 종류를 가리지 않는다. 부분집합을 일부만 뽑아 v(S)를 구한 뒤, 특정 가중치(섀플리 커널)를 준 선형 회귀로 몫을 추정한다. 뒤에서 볼 LIME과 구조가 같고, 가중치를 섀플리 값이 나오게 고른 것만 다르다. 느리고 뽑은 수에 따라 결과가 흔들린다.

Tree SHAP은 결정 트리 계열(랜덤 포레스트, XGBoost, LightGBM, scikit-learn 부스팅) 전용이다. 트리 구조를 따라가며 모든 부분집합의 효과를 한꺼번에 계산해서, 특징 수에 지수가 아니라 다항식으로 비례하는 시간에 정확한 값을 낸다. 표 데이터 모델이라면 대부분 이걸 쓴다. 다만 기본 설정(`tree_path_dependent`)은 "모르는 특징"을 배경 데이터 대신 트리의 학습 경로 비율로 처리해서, 위의 배경 데이터 방식과 숫자가 다를 수 있다. 그리고 부스팅 모델이면 확률이 아니라 로그 오즈(로지스틱 함수를 씌우기 전 점수) 단위로 몫을 낸다. 확률로 보고 싶으면 `model_output="probability"`와 배경 데이터를 함께 줘야 한다.

같은 고객에 Tree SHAP을 기본 설정으로 돌려 봤다.

```python
te = shap.TreeExplainer(model)                 # 기본: tree_path_dependent, 로그 오즈 단위
tv = te(x[None])
print(tv.values[0], tv.base_values[0], model.decision_function(x[None])[0])

te2 = shap.TreeExplainer(model, data=bg,
                         feature_perturbation="interventional",
                         model_output="probability")
print(te2(x[None]).values[0])
```

```text
tree_path_dependent (log-odds) [-1.5113 -1.1232 -0.9642 -0.8599] base 0.6081 sum -3.8506
model log-odds -3.8506
interventional probability [-0.2065 -0.1704 -0.1173 -0.1186] base 0.6336
```

로그 오즈 단위라 숫자 크기는 완전히 다르지만, 기준값 0.6081에 몫을 더하면 모델이 낸 로그 오즈 -3.8506과 정확히 맞고, 소득 > 부채 비율 > 연체 > 근속이라는 순서도 같다. 확률 단위로 바꾼 두 번째 결과는 앞의 정확 계산(-0.2196, -0.1739, -0.1136, -0.1057)과 소수 둘째 자리에서 조금 다르고, 연체와 근속의 순서가 뒤집혔다. 같은 "SHAP 값"이라도 단위와 설정, 구현에 따라 숫자가 달라진다는 뜻이다. 그래서 설명을 저장할 때는 숫자만이 아니라 어떤 설정으로 낸 값인지를 함께 남긴다.

속도 차이는 크다. 이 환경에서 Tree SHAP은 시험 데이터 750건 전체를 0.033초에 설명했고, 정확 계산은 50건에 0.16초가 걸렸다. 특징이 넷뿐인데도 건당 70배쯤 차이 난다. 특징이 늘면 정확 계산은 지수적으로 느려지고 Tree SHAP은 완만하게 느려진다.

딥러닝 모델에는 기울기를 이용하는 Deep SHAP, Gradient SHAP 같은 근사가 있다. 이미지·텍스트처럼 특징이 수천 개면 픽셀 묶음이나 토큰 단위로 묶어서 설명한다.

서빙 관점에서는 이 비용이 중요하다. 예측 한 건마다 설명을 실시간으로 붙이면 예측보다 설명이 훨씬 오래 걸릴 수 있다. 그래서 거절 건에만 계산하거나, 비동기로 계산해 예측 기록 옆에 저장해 두는 방식을 흔히 쓴다. 서빙 구조는 [모델 서빙 글](/posts/model-serving)에 있다.

## LIME: 주변을 흔들어 직선으로 근사한다

LIME(Local Interpretable Model-agnostic Explanations)은 다른 질문에서 출발한다. 복잡한 모델도 한 점 근처만 보면 단순하지 않을까? 지구는 둥글지만 내 동네 지도는 평면으로 그려도 되는 것과 같다. 그래서 설명할 고객 주변에 가짜 고객을 많이 만들고, 블랙박스 모델에게 그들의 예측을 받은 뒤, 그 결과를 가장 잘 흉내 내는 선형 모델을 맞춘다. 선형 모델의 계수가 곧 설명이다.

```python
from lime.lime_tabular import LimeTabularExplainer
le = LimeTabularExplainer(Xtr, feature_names=["income", "dti", "late", "years"],
                          class_names=["reject", "approve"],
                          discretize_continuous=True, random_state=0)

print(e.as_list(), e.local_pred, e.score)
```

LIME은 연체(late > 1)를 가장 큰 이유로 꼽았다. SHAP은 소득을 1위, 연체를 3위로 꼽았다. 같은 모델, 같은 고객인데 순서가 다르다.

## 같은 고객에 대한 두 설명이 다른 이유

둘은 서로 다른 질문에 답하고 있다. SHAP(위 설정)은 "배경 100명의 평균과 비교해서 이 고객의 정확한 값이 예측을 얼마나 바꿨나"를 묻는다. 소득 4,500만 원은 배경 평균(약 7,000만 원)보다 한참 낮아서 몫이 컸다.

LIME(기본 설정)은 특징을 구간으로 바꾼 뒤 "이 고객과 같은 구간에 있는 것이 확률을 얼마나 바꾸나"를 묻는다. 소득 4,500만 원은 43.86~68.08 구간에 들어가는데, 이 구간은 소득 분포의 두 번째 사분위라 그렇게 나쁜 구간이 아니다. 같은 구간 안에서 4,400만 원과 6,800만 원을 구분하지 않으니 소득의 몫이 작게 나온다. 반대로 연체 "1회 초과"는 학습 데이터의 약 19%만 들어 있는 구간이고, 이 구간에 있다는 것만으로 크게 깎인다.

또 하나 볼 숫자가 `score`다. 0.177은 선형 모델이 주변 표본의 블랙박스 예측을 18% 정도밖에 설명하지 못했다는 뜻이다. `local_pred` 0.12도 실제 예측 0.0208과 꽤 다르다. 근사가 잘 맞지 않았으니 이 계수를 그대로 믿기 어렵다. LIME 결과를 쓸 때는 이 두 값을 함께 확인한다.

LIME은 무작위 표본을 쓰니 돌릴 때마다 결과가 달라진다. 표본 5000개일 때는 순위가 조금만 흔들렸다.

```text

```

표본을 100개로 줄이면 이야기가 달라진다.

```text

```

부채 비율의 몫이 -0.007에서 -0.129로, 소득은 -0.146에서 +0.007로 부호까지 바뀐다. 같은 고객에게 어제와 오늘 다른 거절 사유를 안내하게 되는 셈이다. 빠르게 돌리려고 표본 수를 줄이는 게 LIME을 쓸 때 가장 흔한 실수다.

정리하면 고르는 기준은 이렇다. 트리 모델이고 일관된 숫자가 필요하면 Tree SHAP. 모델 종류가 다양하고 대략적인 경향만 빨리 보고 싶으면 LIME도 쓸 만하지만, 표본 수와 커널 폭을 고정하고 score를 같이 본다. 몫의 합이 예측과 맞아떨어져야 하는 보고(거절 사유 코드, 감사 기록)에는 SHAP이 낫다. LIME은 그런 보장을 하지 않는다.

## 비슷한 특징 둘이 공을 나눠 갖는다

이번에는 데이터에 "카드 한도"를 하나 더 넣었다. 카드 한도는 소득의 30%에 작은 잡음을 더한 값이라 소득과 상관계수가 0.993이다. 정답 규칙에는 카드 한도가 전혀 없다. 승인 여부는 여전히 소득, 부채 비율, 연체, 근속만으로 정해진다.

```python
card = 0.3 * income + r.normal(0, 1, n)   # 정답 규칙에는 없는 특징
```

```text
corr income-card 0.993
test acc 0.799
perm      income 0.0235  dti 0.1561  late 0.0360  years 0.0236  card_limit 0.0569
impurity  income 0.1331  dti 0.4153  late 0.0925  years 0.0837  card_limit 0.2755
mean|shap| income 0.0566 dti 0.1878  late 0.0592  years 0.0673  card_limit 0.1099
```

정확도는 79.9%로 거의 같다. 그런데 설명은 크게 바뀌었다. 소득의 순열 중요도는 0.1032에서 0.0235로 4분의 1이 됐고, 정답 규칙에 없는 카드 한도가 0.0569로 소득보다 높다. 평균 SHAP 크기도 카드 한도(0.1099)가 소득(0.0566)의 두 배다. 모델은 거의 같은 정보를 담은 두 열 중 아무거나 골라 썼고, 이번에는 카드 한도를 더 많이 고른 것이다.

순열 중요도가 낮게 나오는 이유도 여기 있다. 소득 열을 섞어도 카드 한도가 같은 정보를 들고 있으니 정확도가 별로 안 떨어진다. 그래서 "소득은 중요하지 않다"는 잘못된 결론이 나온다. 상관이 높은 특징이 있으면 묶어서 함께 섞거나(그룹 순열 중요도), 둘 중 하나를 빼고 다시 학습해 보는 게 낫다.

SHAP에는 문제가 하나 더 있다. 배경 데이터로 "모르는 특징"을 채울 때, 이 고객의 소득 4,500만 원은 그대로 두고 카드 한도는 배경의 다른 사람 값(예: 3,000만 원)으로 채운다. 소득 4,500만 원에 카드 한도 3,000만 원인 사람은 현실 데이터에 없다. 모델은 이런 조합을 본 적이 없으니 그 예측은 근거가 약하고, 그걸 평균 낸 몫도 마찬가지다. 특징을 서로 독립인 것처럼 다루는 방식(interventional)의 한계이고, 특징 사이 상관을 반영해서 채우는 조건부 방식은 계산이 훨씬 어렵다. 어느 쪽이 맞는지는 질문에 따라 다르다. "모델이 어떻게 계산하나"를 묻는다면 독립 방식이, "데이터에서 이 정보가 얼마나 가치 있나"를 묻는다면 조건부 방식이 가깝다.

## 설명은 원인이 아니다

위 실험에서 SHAP은 카드 한도가 거절에 크게 기여했다고 말했다. 이 말은 "모델이 카드 한도 열을 보고 그만큼 점수를 깎았다"는 뜻이다. 맞는 말이다. 하지만 "카드 한도를 올리면 승인될 것이다"는 뜻이 아니다. 진짜 규칙에서 카드 한도는 아무 역할도 하지 않는다. 고객이 카드 한도를 올려 다시 신청하면 모델은 승인 쪽으로 기울겠지만, 그 고객의 상환 능력은 하나도 바뀌지 않았다.

SHAP과 LIME은 모델을 설명하지 세상을 설명하지 않는다. 모델이 데이터의 상관관계를 배웠으면 설명도 상관관계를 보여 준다. 이걸 인과처럼 읽으면 두 가지 사고가 난다. 하나는 사업 판단을 잘못하는 것("카드 한도가 중요하니 한도를 늘려 주자"). 다른 하나는 고객에게 엉뚱한 조언을 하는 것이다.

고객에게 "무엇을 바꾸면 승인되나"를 알려 주고 싶다면 반사실 설명(counterfactual explanation)이 따로 있다. "부채 비율이 35%였다면 승인됐다"처럼 예측을 바꾸는 가장 작은 변화를 찾는다. 이것도 모델 기준의 답이라 진짜 인과는 아니지만, 바꿀 수 있는 특징(부채 비율)과 바꿀 수 없는 특징(나이)을 구분해 제약을 걸 수 있다. 인과를 알고 싶으면 실험(A/B 테스트)이나 인과 추론 방법이 필요하다. 실험 설계는 [A/B 테스트 글](/posts/ab-testing)에 있다.

같은 이유로 설명이 공정성을 증명해 주지도 않는다. 모델에서 성별 열을 뺐고 SHAP에서 성별 몫이 0으로 나와도, 성별과 상관된 다른 특징(특정 직군, 거주지)이 그 역할을 대신할 수 있다. 위의 카드 한도가 소득을 대신한 것과 같은 구조다. 공정성은 집단별 승인율, 오류율을 따로 재서 확인한다.

## 표가 아닌 데이터는 무엇을 특징으로 볼까

표 데이터에서는 열 하나가 특징 하나라 이야기가 깔끔했다. 텍스트와 이미지는 무엇을 "특징"으로 볼지부터 정해야 한다.

텍스트 분류 모델이면 단어나 토큰을 특징으로 본다. LIME은 문장에서 단어를 무작위로 지운 변형을 수천 개 만들어 예측 변화를 보고, SHAP도 토큰을 가렸다 드러냈다 하며 몫을 나눈다. "환불이 너무 늦어요"가 불만으로 분류됐다면 "늦어요"에 큰 몫이 붙는 식이다. 단어를 지운 문장은 문법이 깨진 낯선 입력이라, 표 데이터에서 본 비현실적인 조합 문제가 여기서도 생긴다.

이미지는 픽셀 하나하나를 특징으로 보면 수만 개라 계산이 안 된다. 비슷한 색의 픽셀을 덩어리(슈퍼픽셀)로 묶어 덩어리 단위로 가리거나, 기울기를 이용해 출력에 민감한 영역을 열 지도로 그린다. 열 지도가 사물 대신 배경(눈밭 사진이면 늑대라고 답하는 모델)을 가리키면, 모델이 엉뚱한 지름길을 배웠다는 신호다.

LLM은 사정이 또 다르다. 모델에게 "왜 그렇게 답했나"를 물으면 그럴듯한 이유를 문장으로 내놓지만, 그 문장이 실제 계산 과정을 그대로 보여 준다는 보장은 없다. 생성한 설명과 실제 판단 근거가 어긋날 수 있다는 연구가 여럿 있다. LLM 판단을 감사해야 한다면 근거 문서를 인용하게 하고 그 인용을 검증하는 쪽이 현실적이다. LLM 출력을 평가하는 방법은 [LLM 평가 글](/posts/llm-evals)에 있다.

## 규제가 요구하는 설명

설명 가능성이 기술 취향이 아니라 의무가 되는 영역이 있다. 대출 심사가 대표적이다.

EU의 AI법(AI Act, 2024년 발효)은 자연인의 신용도 평가를 고위험 AI로 분류한다. 고위험 시스템에는 배포하는 쪽이 출력을 해석하고 적절히 쓸 수 있을 만큼의 투명성과 사용 설명, 사람의 감독, 기록 보관 같은 요구가 붙고, 고위험 시스템의 결정으로 영향을 받은 사람이 그 결정에서 AI가 한 역할의 설명을 요구할 권리도 들어 있다. 의무별로 적용 시점이 단계적이고 일정을 조정하자는 논의도 있었으니, 실제 일정은 최신 공고로 확인한다. 그 전부터 GDPR은 사람에게 중대한 영향을 주는 자동화된 결정에는 "관련된 논리에 관한 의미 있는 정보"를 주도록 하고 있다. 국내에도 신용정보법의 자동화평가 설명 요구권, 개인정보보호법의 자동화된 결정에 대한 설명 요구 조항이 있다. 조문과 적용 범위는 법무 검토로 확인한다.

이 규정들은 SHAP을 쓰라고 정하지 않는다. 요구하는 건 결정에 영향을 준 주요 요인을 사람이 이해할 수 있게 알려 주는 것이다. 개발자가 할 일은 그 요구를 만족하는 근거를 남기는 것이다.

- 예측마다 모델 버전, 입력값, 예측값, 설명(상위 요인과 몫), 설명 방법과 배경 데이터 버전을 함께 기록한다. 나중에 같은 설명을 다시 만들 수 있어야 한다.
- 몫을 그대로 보여 주지 않고 사유 코드로 바꾼다. "부채 비율이 높음", "최근 연체 이력" 같은 문장 목록을 미리 정해 두고, 상위 몇 개 요인을 코드로 옮긴다.
- 바꿀 수 없거나 민감한 특징이 상위 요인으로 나오는지 정기적으로 본다.
- 설명 방법을 바꾸면 같은 고객의 사유가 바뀔 수 있으니 모델 배포처럼 버전을 관리한다.

모델, 데이터, 설정을 버전으로 묶어 다시 만들 수 있게 하는 방법은 [MLOps 글](/posts/what-is-mlops)에서 다룬다.

## 현장에서 설명이 쓸모 있는 순간

규제가 아니어도 설명은 디버깅 도구로 자주 쓴다.

학습 데이터에 정답이 새어 들어간 것(데이터 누수)을 잡을 때가 대표적이다. 정확도가 의심스럽게 높은데 SHAP을 보니 "상담 메모 길이" 같은 특징이 압도적이라면, 그 메모가 승인 이후에 쓰인 것일 가능성을 의심한다. 예측 시점에는 존재하지 않는 정보다.

배포 후 예측이 이상해졌을 때도 쓴다. 지난주와 이번 주의 평균 SHAP 값을 특징별로 비교하면 어느 특징이 예측을 다르게 끌고 있는지 보인다. 특정 특징의 몫이 갑자기 커졌다면 그 특징의 입력 파이프라인(단위가 바뀌었거나, 결측값이 0으로 채워지기 시작했거나)부터 본다. 학습과 서빙에서 특징 계산이 달라지는 문제는 [모델 서빙 글](/posts/model-serving)에서 따로 다룬다.

반대로 피해야 할 쓰임도 있다. 설명 숫자를 근거로 특징을 대량으로 빼는 것. 위에서 봤듯 상관된 특징이 있으면 중요한 특징의 몫이 작게 나온다. 빼기 전에 실제로 빼고 다시 학습해서 성능을 확인한다. 그리고 설명이 직관과 맞는다고 모델이 옳다고 믿는 것. 설명이 그럴듯해도 모델이 틀릴 수 있고, 반대로 설명이 낯설어도 모델이 맞을 수 있다. 성능은 평가 데이터로 따로 잰다.

## 숫자를 나눠 주는 두 방식

SHAP은 섀플리 값으로 예측과 평균의 차이를 특징에 나눠 준다. 몫의 합이 정확히 맞아떨어지고, 트리 모델이면 빠르고 정확하게 계산된다. LIME은 한 점 주변을 흔들어 단순한 모델로 흉내 내고, 모델을 가리지 않는 대신 표본과 설정에 따라 결과가 흔들린다. 둘 다 모델이 무엇을 보고 계산했는지를 말할 뿐이라, 상관된 특징이 있으면 몫이 엉뚱하게 갈리고, 인과나 공정성을 증명하지 못한다. 쓸 때는 기준(배경 데이터), 방법, 버전을 함께 남긴다.

## 면접에서 나올 만한 질문

### 전역 설명과 지역 설명은 무엇이 다른가

전역 설명은 모델이 대체로 어떤 특징을 중요하게 쓰는지, 지역 설명은 예측 한 건이 왜 그렇게 나왔는지에 답한다. 순열 중요도나 평균 SHAP 크기가 전역, 한 건의 SHAP 값이나 LIME 계수가 지역이다. 둘의 순서가 다를 수 있어서, 고객에게 거절 사유를 줄 때는 반드시 지역 설명을 쓴다.

### SHAP과 LIME의 차이는

SHAP은 섀플리 값으로 예측과 기준값의 차이를 특징에 나누고, 몫의 합이 예측과 정확히 맞는다. LIME은 한 점 주변에 표본을 만들어 가중 선형 모델로 근사하고, 그 계수를 설명으로 쓴다. LIME은 모델을 가리지 않고 빠르지만 표본 수와 커널 폭에 따라 결과가 흔들리고 합에 대한 보장이 없다. 트리 모델이면 정확하고 빠른 Tree SHAP을 먼저 쓴다.

### 섀플리 값은 어떻게 계산하고 왜 비싼가

특징 하나의 몫은 그 특징을 뺀 모든 부분집합에서 그 특징을 넣었을 때 예측이 얼마나 바뀌는지를, 무작위 순서로 넣는 경우를 고르게 반영하는 가중치로 평균 낸 값이다. 부분집합이 2의 특징 수 제곱만큼 있어서 특징이 30개면 10억 개가 넘는다. 그래서 Kernel SHAP처럼 표본을 뽑아 추정하거나, Tree SHAP처럼 트리 구조를 이용해 다항 시간에 계산한다.

### 특징 중요도를 믿으면 안 되는 경우는

상관이 높은 특징이 있을 때다. 한 특징을 섞어도 다른 특징이 같은 정보를 들고 있어서 순열 중요도가 낮게 나오고, SHAP 몫도 둘 사이에 임의로 갈린다. 실험에서 소득과 상관계수 0.993인 카드 한도를 넣었더니 정답 규칙에 없는 카드 한도가 소득보다 중요하게 나왔다. 불순도 기반 중요도는 연속 특징을 부풀리고 학습 데이터 기준이라 과적합한 특징도 높게 나온다.

### SHAP 값이 크면 그 특징을 바꾸면 결과가 바뀌나

모델의 예측은 바뀌겠지만 실제 결과가 바뀐다는 보장은 없다. SHAP은 모델이 그 특징을 보고 점수를 얼마나 바꿨는지를 말할 뿐 인과를 말하지 않는다. 상관된 대리 특징이 큰 몫을 받을 수 있다. 무엇을 바꾸면 되는지 알려 주려면 반사실 설명을, 진짜 효과를 알려면 실험이나 인과 추론을 쓴다.

### 민감한 특징을 빼고 SHAP에서 몫이 0이면 공정한 모델인가

아니다. 그 특징과 상관된 다른 특징이 대신 역할을 할 수 있다. 공정성은 설명이 아니라 집단별 승인율, 오탐·미탐률 같은 지표를 따로 재서 확인한다.

### 운영 중인 모델에 설명을 붙일 때 무엇을 남기나

예측마다 모델 버전, 입력, 예측, 상위 요인과 몫, 설명 방법과 배경 데이터 버전을 기록해서 나중에 같은 설명을 다시 만들 수 있게 한다. 고객에게는 몫 대신 미리 정한 사유 코드로 바꿔 안내한다. 설명 계산이 예측보다 비쌀 수 있으니 거절 건만 계산하거나 비동기로 계산해 저장한다.
