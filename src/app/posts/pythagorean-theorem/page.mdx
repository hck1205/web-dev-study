화면에서 두 점 사이의 거리를 구하는 코드를 보면 거의 항상 이 한 줄이 들어 있다.

```js
const distance = Math.sqrt(dx * dx + dy * dy);
```

가로로 `dx`, 세로로 `dy`만큼 떨어져 있으면 직선거리는 둘을 제곱해 더한 값의 제곱근이다. 너무 당연하게 써서 잊고 있었는데, 이게 중학교 때 외운 피타고라스 정리 그 자체다. 외운 공식 말고, 왜 그렇게 되는지 그림으로 다시 따라가 봤다.

## 직각삼각형의 세 변 사이에 있는 규칙

직각삼각형에서 직각을 끼고 있는 두 변을 a, b라 하고, 직각과 마주 보는 가장 긴 변(빗변)을 c라 하자. 그러면 언제나 다음이 성립한다.

```text
a² + b² = c²
```

조건은 딱 하나, 직각삼각형이어야 한다는 것이다. 각이 90도에서 조금만 벗어나도 등호가 깨진다. 그리고 c는 반드시 빗변이다. 세 변 중 아무거나 c에 넣으면 안 된다.

식을 넓이로 읽으면 더 와닿는다. a²은 한 변이 a인 정사각형의 넓이다. 그러니까 이 정리는 "짧은 두 변 위에 세운 정사각형 넓이를 더하면, 빗변 위에 세운 정사각형 넓이와 같다"는 말이다. 아래 그림에서 세 가지 직각삼각형으로 확인해 볼 수 있다. 다음을 누르면 삼각형 모양이 바뀌고, 정사각형도 따라 늘어나거나 줄어든다.

식으로 쓰면 한 줄이다. 큰 정사각형 넓이는 (a+b)²이고 삼각형 하나의 넓이는 ab/2다.

```text
(a + b)² = c² + 4 × ab/2
a² + 2ab + b² = c² + 2ab
a² + b² = c²
```

나는 이 증명이 좋은 게, 계산보다 "같은 것에서 같은 것을 빼면 같다"는 생각 하나로 끝나서다. a와 b가 어떤 값이든 그림이 똑같이 그려지니 모든 직각삼각형에 대해 성립한다.

## 3, 4, 5 같은 숫자들

첫 번째 그림의 (3, 4, 5), (5, 12, 13), (8, 15, 17)처럼 세 변이 모두 자연수인 직각삼각형의 세 수를 피타고라스 수라고 부른다. 하나를 찾으면 몇 배씩 늘린 것도 된다. (3, 4, 5)를 두 배 하면 (6, 8, 10)이다. 그래서 공약수가 없는 것들만 따로 원시 피타고라스 수라고 부른다.

원시 피타고라스 수는 공식으로 전부 만들 수 있다. m > n > 0인 자연수 m, n이 서로소이고 둘 중 하나만 짝수일 때 다음 세 수가 원시 피타고라스 수다. 이 방법은 유클리드 원론에 나온다.

```text
a = m² − n²,  b = 2mn,  c = m² + n²
```

m = 2, n = 1이면 (3, 4, 5), m = 3, n = 2면 (5, 12, 13), m = 4, n = 1이면 (15, 8, 17)이다. 대입해서 a² + b²을 전개하면 (m² + n²)²이 그대로 나온다.

## 거꾸로도 성립한다

정리를 뒤집어도 맞는다. 세 변이 a² + b² = c²을 만족하면 그 삼각형은 c의 맞은편 각이 직각이다. 이걸 역이라고 하는데, 길이만 재서 직각을 확인할 수 있다는 뜻이라 실용적이다. 끈에 같은 간격으로 매듭 12개를 짓고 3, 4, 5칸으로 삼각형을 만들면 직각이 나온다.

등호가 아니라 부등호면 각의 모양을 알 수 있다. c가 가장 긴 변일 때 a² + b² > c²이면 예각삼각형, a² + b² < c²이면 둔각삼각형이다. 이건 코사인 법칙 c² = a² + b² − 2ab·cos C에서 바로 보인다. C가 90도면 cos C가 0이라 마지막 항이 사라지고 피타고라스 정리가 된다. 피타고라스 정리는 코사인 법칙의 특별한 경우인 셈이다.

## 거리 공식이 되기까지

맨 처음의 `Math.sqrt(dx * dx + dy * dy)`로 돌아가 보자. 좌표 평면에서 두 점 (x₁, y₁), (x₂, y₂)를 잇는 선분을 빗변으로 삼으면, 가로 dx = x₂ − x₁, 세로 dy = y₂ − y₁인 직각삼각형이 생긴다. 빗변의 길이가 곧 거리다.

3차원으로 가도 같은 방법을 두 번 쓰면 된다. 바닥에서 대각선 길이를 먼저 구하고, 그 대각선과 높이 dz로 다시 직각삼각형을 만든다.

```text
d² = (dx² + dy²) + dz²
```

차원이 몇 개든 축마다 차이를 제곱해 더하고 제곱근을 씌우면 된다. 이걸 유클리드 거리라고 부르고, 임베딩 벡터처럼 수백 차원짜리 점 사이의 거리도 이렇게 잰다. 아래 편집기에서 n차원 거리 함수를 직접 만들어 보자. 실행하면 테스트가 돌아간다.

<CodePlayground
  caption="n차원 두 점 사이의 거리"
  functionName="distance"
  initialCode={`function distance(p, q) {
  // p, q는 같은 길이의 숫자 배열이다. 예) [0, 0], [3, 4]
  return 0;
}`}
  solution={`function distance(p, q) {
  let sum = 0;
  for (let i = 0; i < p.length; i++) {
    const d = q[i] - p[i];
    sum += d * d;
  }
  return Math.sqrt(sum);
}`}
  tests={[
    { args: [[0, 0], [3, 4]], expected: 5 },
    { args: [[1, 1], [6, 13]], expected: 13 },
    { args: [[1, 2, 3], [4, 6, 15]], expected: 13, label: "3차원 (3, 4, 12)" },
    { args: [[7, 7], [7, 7]], expected: 0, label: "같은 점" },
  ]}
/>

가장 가까운 점을 찾을 때처럼 거리끼리 비교만 하면 될 때는 제곱근을 빼도 된다. 제곱근은 크기 순서를 바꾸지 않기 때문에 제곱한 거리끼리 비교해도 결과가 같고, 계산은 더 싸다.

반대로 값이 아주 크거나 작으면 제곱하는 순간 문제가 생긴다. 1e200을 제곱하면 자바스크립트의 숫자 범위를 넘어 Infinity가 된다. `Math.hypot(dx, dy)`는 이런 넘침을 피하도록 계산해 준다. 정밀도가 중요한 곳이라면 직접 제곱하기보다 hypot을 쓰는 편이 낫다.

하나 더 풀어 보자. c가 n 이하인 피타고라스 수 (a < b < c)가 몇 개인지 세는 함수다. 처음엔 a와 b를 이중 반복문으로 돌리고 c가 정수인지 확인하는 방법이 떠오른다. 제곱근은 소수 오차가 있으니 반올림한 뒤 다시 제곱해서 확인하는 게 안전하다.

<CodePlayground
  caption="c ≤ n인 피타고라스 수 세기"
  functionName="countTriples"
  initialCode={`function countTriples(n) {
  let count = 0;
  // a < b < c <= n 이고 a² + b² = c² 인 경우를 센다
  return count;
}`}
  solution={`function countTriples(n) {
  let count = 0;
  for (let a = 1; a <= n; a++) {
    for (let b = a + 1; b <= n; b++) {
      const s = a * a + b * b;
      const c = Math.round(Math.sqrt(s));
      if (c <= n && c * c === s) count++;
    }
  }
  return count;
}`}
  tests={[
    { args: [5], expected: 1, label: "n = 5" },
    { args: [13], expected: 3, label: "n = 13" },
    { args: [20], expected: 6, label: "n = 20" },

## 이름은 피타고라스지만

이 정리가 피타고라스(기원전 6세기 무렵)의 이름으로 불리는 건 고대 그리스 전통 때문이다. 정작 피타고라스가 직접 쓴 글은 남아 있지 않아서, 그가 무엇을 증명했는지는 분명하지 않다.

관계 자체는 훨씬 전부터 알려져 있었다. 기원전 1800년 무렵 바빌로니아의 점토판 플림프턴 322에는 피타고라스 수와 관련된 숫자 목록이 적혀 있다. 고대 인도의 술바 수트라에도 제단을 만들며 쓴 같은 관계가 나오고, 중국의 주비산경에는 3, 4, 5를 다룬 구고(勾股) 이야기가 있다. 여러 문명이 각자 이 규칙에 닿았다는 점이 오히려 이 정리가 얼마나 기본적인지 보여 준다.

## 정리

직각삼각형에서 짧은 두 변 위 정사각형 넓이의 합은 빗변 위 정사각형 넓이와 같다. 한 변이 a+b인 정사각형 안에서 삼각형 네 개의 자리만 바꾸면 빈 곳이 c²에서 a² + b²으로 바뀌고, 뺀 것이 같으니 둘은 같다. 이 관계가 좌표로 가면 거리 공식이 되고, 차원을 늘리면 임베딩 벡터 사이의 거리가 된다. 다음에는 코사인 법칙과 내적이 같은 이야기라는 걸 이어서 보면 좋겠다.

## 면접에서 나올 만한 질문

### 두 점 사이의 거리를 구하는 함수를 작성해 보세요.

축마다 좌표 차이를 구해 제곱해서 더하고 제곱근을 씌운다. 2차원이면 `Math.sqrt(dx*dx + dy*dy)`이고, n차원도 반복문으로 같은 계산을 한다. 값이 매우 크거나 작을 수 있으면 제곱 과정에서 넘침이나 언더플로가 생길 수 있어서 `Math.hypot`을 쓰는 편이 안전하다고 덧붙이면 좋다.

### 가장 가까운 점을 찾을 때 제곱근을 생략해도 되는 이유는 무엇인가요?

거리는 0 이상이고 제곱근은 증가 함수라서, 제곱한 거리의 크기 순서와 실제 거리의 크기 순서가 같다. 비교만 필요하면 제곱 거리로 충분하고 제곱근 연산을 아낄 수 있다. 다만 실제 거리 값이 필요하거나 임계값과 비교할 때는 임계값도 제곱해서 비교해야 한다.

### 유클리드 거리와 맨해튼 거리는 어떻게 다른가요?

유클리드 거리는 두 점을 잇는 직선의 길이로, 피타고라스 정리로 구한다. 맨해튼 거리는 축을 따라서만 움직일 때의 거리로 각 축 차이의 절댓값을 더한다. 격자 위를 이동하는 문제(바둑판 길 찾기)에는 맨해튼 거리가 맞다. 차이를 제곱하지 않아서 한 축에서만 크게 벌어진 값에 덜 끌려간다는 차이도 있다.

### 세 변의 길이만 보고 직각삼각형인지 판단하려면?

세 변을 정렬해 가장 긴 변을 c로 두고 a² + b² = c²인지 본다. 피타고라스 정리의 역에 따라 같으면 직각삼각형이다. 정수면 그대로 비교하면 되지만 실수라면 부동소수점 오차가 있어서 작은 허용 오차 안에서 같은지 확인해야 한다. 더 나아가 a² + b²이 c²보다 크면 예각, 작으면 둔각삼각형이다.
