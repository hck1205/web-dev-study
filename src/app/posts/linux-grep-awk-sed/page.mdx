오후 2시 반쯤 "주문 버튼을 누르면 가끔 에러가 난다"는 문의가 들어왔다. 대시보드는 아직 없고, 서버에는 nginx 접근 로그 30분치 4990줄이 있다. 언제부터 몇 건이 났는지, 어떤 경로에서 났는지, 그 시각에 다른 이상은 없었는지를 몇 분 안에 알아야 한다. 이럴 때 손에 잡히는 도구가 grep, awk, sed다. grep은 줄을 고르고, awk는 줄을 칸으로 나눠 세고 더하고, sed는 줄을 고쳐 쓴다.

이 글은 실제로 그 4990줄을 만들어 놓고 세 도구로 장애를 좁혀 가며 옵션을 하나씩 본다. 기준은 Ubuntu 24.04 LTS의 GNU grep 3.11, GNU sed 4.9, 그리고 기본 awk인 mawk 1.3.4다(gawk를 설치하면 `awk`가 gawk로 바뀐다. 차이는 뒤에서 본다). 22.04도 옵션은 같다.

## 로그 한 줄을 칸으로 나눠 본다

nginx의 기본 `combined` 형식 끝에 요청 처리 시간(`$request_time`)을 붙여 쓰는 경우가 많다. 이 글의 로그도 그렇다.

```nginx
# /etc/nginx/nginx.conf 의 http 블록
log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                '$status $body_bytes_sent "$http_referer" "$http_user_agent" $request_time';
access_log /var/log/nginx/access.log main;
```

이 형식의 한 줄이다. 조각을 누르면 awk가 기본(공백)으로 나눴을 때 몇 번째 칸인지가 나온다.

실제로 첫 줄을 나눠 보면 이렇다.

```bash
# 칸 번호와 칸 수(NF) 확인
head -1 access.log | awk '{print "$1="$1, "$4="$4, "$7="$7, "$9="$9, "$10="$10, "NF="NF, "$NF="$NF}'
```

```text
$1=10.0.3.119 $4=[20/Oct/2026:14:00:00 $7=/api/products $9=200 $10=8283 NF=18 $NF=0.026
```

UA 뒤의 칸을 번호로 부르면 틀린다는 걸 확인해 두자. `$12`를 세면 UA가 아니라 UA의 첫 단어만 나온다.

```bash
# $12를 UA로 착각하면
awk '{print $12}' access.log | sort | uniq -c | sort -rn | head -3

# 따옴표로 나누면 UA가 통째로 6번째 칸이 된다
awk -F'"' '{print $6}' access.log | sort | uniq -c | sort -rn
```

```text
   4192 "Mozilla/5.0
    438 "kube-probe/1.31"
    360 "python-requests/2.31.0"
   2116 Mozilla/5.0 (iPhone; CPU iPhone OS 17_5 like Mac OS X)
   2076 Mozilla/5.0 (Windows NT 10.0; Win64; x64)
    438 kube-probe/1.31
    360 python-requests/2.31.0
```

`-F'"'`처럼 구분자를 바꾸는 것이 awk로 로그를 다룰 때 가장 쓸모 있는 기술 하나다. 그래도 형식이 복잡하면 nginx에서 처음부터 JSON 로그(`escape=json`)를 남기고 `jq`로 읽는 편이 실수가 적다.

## grep은 줄을 고른다

먼저 502가 몇 건인지 센다. 그냥 `502`로 찾으면 숫자가 더 나온다.

```bash
# 502가 들어간 줄 수
grep -c '502' access.log

# 상태 코드 자리의 502만 (앞뒤 공백까지 패턴에 넣는다)
grep -c ' 502 ' access.log

# 상태 칸이 아닌데 502가 들어간 줄
grep '502' access.log | grep -v '" 502 ' | head -3
```

이번 로그에서는 `-w`(단어 단위)로도 31건이 나왔지만, `-w`는 점이나 따옴표도 단어 경계로 보기 때문에 처리 시간이 `0.502`인 줄에도 걸린다(따로 넣어 본 줄에서 `grep -cw 502`가 1을 냈다). 칸으로 정확히 고르려면 다음에 볼 awk(`$9 == 502`)가 안전하다.

자주 쓰는 옵션을 같은 로그에 써 봤다.

```bash
# -E: 확장 정규식. 5xx 전부
grep -cE '" (500|502|503|504) ' access.log

# -v: 맞지 않는 줄. 헬스 체크를 빼고 센다
grep -vc 'kube-probe' access.log

# -o: 맞은 부분만 뽑는다. 상태 코드 분포
grep -oE '" [0-9]{3} ' access.log | sort | uniq -c | sort -rn

# -m1: 처음 하나만. 첫 502가 언제였나
grep -m1 '" 502 ' access.log
```

첫 502가 14:21:17이다. 마지막은 `grep '" 502 ' access.log | tail -1`로 보면 14:23:57이었다. 약 3분 동안 31건이다. 401이 382건인 것도 눈에 띈다. 이건 뒤에서 본다.

```bash
# 디렉터리 아래 .log 파일에서 찾고 줄 번호(-n)를 붙인다
grep -rn --include='*.log' 'Connection refused' /srv/r1log | head -1

# 어느 파일에 있는지만 (-l)
grep -rl 'Connection refused' /srv/r1log

zgrep -c '" 200 ' access.log.2.gz
```

에러 로그에 답이 있다. nginx가 업스트림 `10.0.2.15:8080`에 연결하려다 `Connection refused`를 받았다. 그 주소에서 아무도 듣고 있지 않았다는 뜻이다(TCP 연결이 거부되는 원리는 [포트와 소켓](/posts/ports-and-sockets)에 있다). 앱이 죽었거나 재시작 중이었다.

정규식의 점(`.`)은 아무 글자 하나라서 IP를 찾을 때 함정이 된다.

```bash
# 10.0.2.1을 찾으려 했는데
grep -c '10.0.2.1' access.log

# 점을 글자로, 뒤는 공백이나 줄 끝으로 막는다
grep -cE '10\.0\.2\.1( |$)' access.log

# 정규식이 필요 없으면 -F (고정 문자열, 빠르다)
grep -cF '10.0.2.15' error.log
```

```text
211
0
31
```

`10.0.2.1`이라는 클라이언트는 없는데 211줄이 나왔다. `10.0.2.103`, `10.0.2.15x` 같은 주소가 다 걸린 것이다. 차단 목록을 grep으로 만들다 이런 실수를 하면 엉뚱한 사용자를 막는다.

에러 로그에서 앞뒤 문맥이 필요하면 `-A`(뒤), `-B`(앞), `-C`(앞뒤) 줄 수를 준다. 자바 스택 트레이스처럼 에러가 여러 줄에 걸칠 때 `grep -A 20 'Exception'`으로 쓴다. 실시간으로 거를 때 grep 뒤에 또 파이프를 잇는다면 `tail -F access.log | grep --line-buffered '" 5' | awk ...`처럼 `--line-buffered`를 붙인다. grep은 출력이 터미널이 아니면 몇 KB씩 모았다가 내보내서, 없으면 한참 동안 "아무 일도 없는 것처럼" 보인다.

## awk는 칸을 세고 더한다

awk 프로그램은 `조건 { 동작 }`의 목록이다. 줄마다 조건을 보고 맞으면 동작을 한다. 조건을 빼면 모든 줄, 동작을 빼면 그 줄을 출력한다. `END { }`는 마지막 줄을 읽은 뒤 한 번 돈다. 여기에 이름으로 찾는 배열(연관 배열)을 더하면 대부분의 집계가 된다.

```bash
# 상태 코드별 건수: c["200"]++ 처럼 상태를 이름으로 센다
awk '{c[$9]++} END {for (s in c) print s, c[s]}' access.log | sort
```

```text
200 4564
401 382
404 13
502 31
```

아래 그림은 awk가 줄을 하나씩 읽으며 배열을 채우는 모습이다.

이제 장애를 분 단위로 본다. `$4`의 14번째 글자부터 5글자가 `14:21` 같은 시각이다.

```bash
# 5xx만 골라 분 단위로 센다
awk '$9 ~ /^5/ {m = substr($4, 14, 5); c[m]++} END {for (k in c) print k, c[k]}' access.log | sort

# 같은 시각의 전체 요청 수 (트래픽이 몰려서인지 확인)
awk '{m = substr($4, 14, 5); c[m]++} END {for (k in c) print k, c[k]}' access.log | sort | sed -n '20,25p'
```

502는 14:21~14:23의 3분에만 있고, 그 시각의 요청 수는 평소(분당 150 안팎)와 같다. 트래픽이 몰려서 생긴 장애가 아니라 업스트림 쪽 사건이다. 어떤 경로였는지도 본다.

```bash
# 502의 경로별 건수 (쿼리 문자열은 떼고)
awk '$9 == 502 {split($7, p, "?"); c[p[1]]++} END {for (k in c) print c[k], k}' access.log | sort -rn

# 에러 로그 쪽: 분 단위 건수와 업스트림 주소
awk '{print substr($2, 1, 5)}' error.log | uniq -c
grep -oE 'upstream: "[^"]+"' error.log | sed -E 's#upstream: "(http://[^/]+).*#\1#' | sort | uniq -c
```

```text

6 /api/orders/export
      8 14:21
     13 14:22
     10 14:23
     31 http://10.0.2.15:8080
```

접근 로그의 502 31건과 에러 로그의 `Connection refused` 31건이 분 단위까지 맞는다. 주문 API 서버 한 대(`10.0.2.15:8080`)가 3분 동안 응답하지 못했다. 다음에 볼 곳은 그 서버의 앱 로그와 재시작 기록이다. systemd로 돌린다면 `journalctl -u orders-api --since "14:20" --until "14:25"`다([systemd와 systemctl](/posts/linux-systemd-systemctl)). 업스트림이 한 대뿐이라 한 대가 내려가자 바로 502가 났다는 것도 개선할 점이다.

```bash
# 요청이 많은 IP 상위 5개
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -5
```

`203.0.113.45` 한 곳에서 로그인 실패가 360번, UA는 `python-requests`였다. 비밀번호 대입 시도다. 438건의 `10.0.0.1`은 쿠버네티스 헬스 체크(`kube-probe`)라 정상이다. 요청 수만 보고 판단하면 헬스 체크를 공격으로 오해한다. 막는 방법은 [iptables 기초](/posts/iptables-basics)의 SSH 무차별 대입 부분과 [레이트 리밋](/posts/rate-limiting-in-practice)으로 넘긴다.

느린 경로도 awk 한 줄로 본다.

```bash
# 경로별 건수, 평균, 최대 처리 시간 (평균 순)
awk '{n[$7]++; s[$7] += $NF; if ($NF > mx[$7]) mx[$7] = $NF}
     END {for (p in n) printf "%-20s %5d %8.3f %8.3f\n", p, n[p], s[p]/n[p], mx[p]}' access.log | sort -k3 -rn
```

평균은 느린 꼬리를 감춘다. 백분위(p95)는 awk만으로는 정렬이 번거로워 `sort`와 함께 쓴다. 정렬한 값에서 95% 위치의 값을 꺼낸다.

```bash
# export 경로의 p50, p95 (nearest-rank 방식)
awk '$7 == "/api/orders/export" {print $NF}' access.log | sort -n |
  awk '{a[NR] = $1} END {i = int(NR*0.95); if (i < NR*0.95) i++; print "n="NR, "p50="a[int((NR+1)/2)], "p95="a[i], "max="a[NR]}'
```

```text
n=96 p50=3.002 p95=4.568 max=4.76
```

시간 범위를 자를 때도 awk를 쓴다. 같은 날짜 안이라면 `$4`를 문자열로 비교해도 시각 순서가 맞는다.

```bash
# 14:21:00 이상 14:24:00 미만 구간의 줄 수
awk '$4 >= "[20/Oct/2026:14:21:00" && $4 < "[20/Oct/2026:14:24:00"' access.log | wc -l
```

```text
461
```

날짜가 바뀌는 구간은 `20/Oct`처럼 월 이름이 들어가 문자열 순서가 날짜 순서와 다르니 이 방법이 통하지 않는다. 그때는 줄 번호로 자르거나 `$time_iso8601`로 로그를 남긴다.

Ubuntu의 기본 awk는 mawk다. 이 글의 awk 명령은 mawk와 gawk에서 같은 결과를 냈다. 다만 gawk 전용 함수를 쓰면 mawk에서 멈춘다.

```bash

echo "b a c" | mawk '{n = split($0, a, " "); asort(a); print a[1]}'

# 지금 awk가 무엇인지
readlink -f /usr/bin/awk
```

```text

/usr/bin/gawk
```

내 노트북에서 되던 스크립트가 서버에서 안 되면 이 차이를 의심한다. 공유할 스크립트는 POSIX awk 기능만 쓰거나 첫 줄에 `#!/usr/bin/gawk -f`를 적고 gawk를 설치 목록에 넣는다.

## sed는 줄을 고쳐 쓴다

sed의 기본은 `s/찾을 것/바꿀 것/플래그`다. 로그를 남에게 보내기 전에 IP 뒤쪽을 가려 보자.

```bash
# IP의 뒤 두 자리를 가린다 (-E: 확장 정규식, \1: 첫 괄호에 잡힌 것)
head -2 access.log | sed -E 's/^([0-9]+\.[0-9]+)\.[0-9]+\.[0-9]+/\1.x.x/'
```

```text
10.0.x.x - - [20/Oct/2026:14:00:00 +0000] "GET /api/products HTTP/1.1" 200 8283 "-" "Mozilla/5.0 (Windows NT 10.0; Win64; x64)" 0.026
10.0.x.x - - [20/Oct/2026:14:00:00 +0000] "GET /api/orders HTTP/1.1" 200 5186 "-" "Mozilla/5.0 (iPhone; CPU iPhone OS 17_5 like Mac OS X)" 0.235
```

정규식은 기본으로 욕심이 많다. `.*`는 맞을 수 있는 가장 긴 곳까지 먹는다. 따옴표 사이를 바꾸려다 줄 대부분을 지우는 실수가 흔하다.

```bash
# 첫 따옴표부터 마지막 따옴표까지 한 덩어리로 먹는다
echo '"GET / HTTP/1.1" 200 "-" "curl/8.5.0"' | sed 's/".*"/Q/'

# 따옴표가 아닌 글자만 이어지게 하면 덩어리마다 따로 맞는다 (g: 줄의 모든 곳)
echo '"GET / HTTP/1.1" 200 "-" "curl/8.5.0"' | sed 's/"[^"]*"/Q/g'

# 경로처럼 /가 많으면 구분자를 바꾼다
echo 'root /var/www/old;' | sed 's#/var/www/old#/srv/site#'
```

```text
Q
Q 200 Q Q
root /srv/site;
```

sed의 정규식에는 `.*?` 같은 게으른 반복이 없다. `[^"]*`처럼 "멈출 글자가 아닌 것"으로 쓴다.

`-n`과 `p`로 원하는 줄만 출력하면 grep처럼도 쓴다. 범위 지정이 grep에 없는 장점이다.

```bash
# 3번째와 5번째 줄만
sed -n '3p;5p' access.log

# 처음 14:21:00이 나온 줄부터 처음 14:21:02가 나온 줄까지
sed -n '/14:21:00/,/14:21:02/p' access.log | head -4
```

범위의 끝 패턴이 끝내 안 나오면 파일 끝까지 출력한다는 점을 조심한다. 로그에 없는 시각을 끝으로 주면 수 GB가 화면에 쏟아진다.

설정 파일을 고칠 때는 앵커(`^`)를 꼭 쓴다. 주석 줄까지 바뀌는 걸 막는다.

```bash
# 앵커 없이: 주석 처리된 줄까지 바뀐다
sed 's/worker_processes .*/worker_processes auto;/' nginx.conf.sample

# 줄 맨 앞에서 시작하는 것만
sed 's/^worker_processes .*/worker_processes auto;/' nginx.conf.sample
```

```text
worker_processes auto;
# worker_processes auto;
keepalive_timeout 65;
worker_processes auto;
# worker_processes 4;
keepalive_timeout 65;
```

직접 해 봤다. 0.5초마다 한 줄씩 쓰는 프로그램이 도는 중에 `sed -i`를 했다.

```bash
# 바꾸기 전후 inode
ls -i app.log
sed -i 's/password=[^ ]*/password=***/' app.log
ls -i app.log

# 쓰는 프로그램이 지금 붙잡고 있는 파일
ls -l /proc/<쓰는 프로그램 PID>/fd | grep app.log

# 3초 뒤 파일 내용
cat app.log
```

```text
739594 app.log
739595 app.log
l-wx------ 1 root root 64 Oct 20 14:48 3 -> /srv/r1log/app.log (deleted)
line1 password=***
line2 password=***
```

프로그램은 7번째 줄까지 썼는데 파일에는 2줄뿐이다. 3~7번째 줄은 지워진 옛 inode에 들어갔다. 쓰는 중인 로그는 `sed -i`로 고치지 않는다. 복사본을 만들어 고치거나, 애초에 로그에 비밀 값이 찍히지 않게 앱을 고친다.

같은 이유로 심볼릭 링크도 깨진다. `-i`는 링크를 따라가지 않고 링크 자리에 일반 파일을 만든다.

```bash
# site.conf는 conf.d/real.conf를 가리키는 링크
ls -l site.conf
sed -i 's/80/8080/' site.conf
ls -l site.conf; cat conf.d/real.conf

# 링크를 따라가서 원본을 고치려면
sed -i --follow-symlinks 's/80/8080/' site.conf
```

```text
lrwxrwxrwx 1 root root 16 Oct 20 14:48 site.conf -> conf.d/real.conf
-rw-r--r-- 1 root root 13 Oct 20 14:48 site.conf
listen 80;
```

링크였던 `site.conf`가 일반 파일이 됐고 원본 `real.conf`는 그대로 80이다. nginx의 `sites-enabled/`가 이런 링크로 되어 있어서, 여기에 `sed -i`를 하면 `sites-available/`의 원본과 내용이 갈라진다. 하드 링크도 마찬가지로 끊긴다.

<Callout kind="warning" title="여러 서버에 sed -i를 돌리기 전에">
`-i`는 되돌리기 기능이 없다. 먼저 `-i` 없이 돌려 결과를 눈으로 보고, 실제로 바꿀 때는 `sed -i.bak`처럼 확장자를 줘서 원본을 남긴다. `diff file.bak file`로 바뀐 줄만 확인한 뒤 설정 검사(`nginx -t`, `sshd -t`)를 통과하면 reload한다. 문제가 생기면 `mv file.bak file`로 되돌린다. macOS의 BSD sed는 `-i ''`처럼 빈 확장자를 따로 줘야 해서 같은 스크립트가 거기서는 다르게 동작한다.
</Callout>

```bash
# 원본을 .bak으로 남기고 고친다
sed -i.bak 's/^keepalive_timeout .*/keepalive_timeout 30;/' n.conf
diff n.conf.bak n.conf
```

```text
3c3
< keepalive_timeout 65;
---
> keepalive_timeout 30;
```

## 장애 때 쓰는 명령 묶음

처음 문의로 돌아가면, 몇 분 동안 친 명령은 이 순서였다.

1. 언제, 얼마나: `grep -c '" 502 '`, `grep -m1`과 `tail -1`로 처음과 끝, awk로 분 단위 건수.
2. 트래픽 탓인가: 같은 시각 전체 요청 수와 비교. 여기서는 평소와 같아서 아니었다.
3. 어디서: awk로 경로별 건수, 에러 로그에서 업스트림 주소와 에러 문구(`Connection refused`는 듣는 프로세스 없음, `upstream timed out`은 느림, `no live upstreams`는 전부 실패 처리).
4. 같은 시각 다른 신호: 상위 IP와 401. 장애와 별개인 대입 공격을 발견했다.
5. 다음 단계로 넘기기: 업스트림 서버의 `journalctl`, 앱 로그, 배포 기록.

이 정도는 grep 몇 줄과 awk 몇 줄이면 된다. 같은 질문을 매주 묻게 되면 그때가 로그 수집기와 대시보드를 들일 때다. grep과 awk는 대시보드가 없는 서버, 대시보드에 안 잡힌 질문, 대시보드 숫자가 맞는지 확인할 때 계속 쓴다.

## 고르고, 세고, 고친다

grep은 글자로 줄을 고르고, awk는 칸으로 나눠 세고 더하며, sed는 줄을 고쳐 쓴다. grep은 칸을 모르니 상태 코드처럼 자리가 중요한 값은 awk로 고르고, 공백이 섞인 칸은 `$NF`나 `-F'"'`로 피한다. `sort | uniq -c | sort -rn`은 앞의 sort가 있어야 맞다. `sed -i`는 새 파일로 바꿔치기해서 inode가 바뀌니 쓰는 중인 파일과 심볼릭 링크에는 쓰지 않고, 쓸 때는 `.bak`과 `diff`로 확인한다.

## 면접에서 나올 만한 질문

### 접근 로그에서 상태 코드별 건수를 어떻게 세나요?

`awk '{c[$9]++} END {for (s in c) print s, c[s]}' access.log`처럼 awk의 연관 배열로 상태 칸을 센다. `grep -c 502`는 칸을 모르고 글자를 찾아서 응답 크기 2502 같은 값까지 세므로 틀린 숫자가 나온다. 실습 로그에서도 grep은 43건, 실제 502는 31건이었다.

### sort | uniq -c에서 sort를 빼면 어떻게 되나요?

uniq는 바로 붙어 있는 같은 줄만 합치기 때문에, 정렬하지 않으면 떨어져 있는 같은 값을 따로 세서 같은 IP가 여러 줄로 나오고 개수도 틀린다. 그래서 `sort | uniq -c | sort -rn | head`가 한 묶음이다. 마지막 sort에 -n이 없으면 숫자를 문자열로 비교해 9가 86보다 앞에 온다.

### awk에서 User-Agent 뒤의 칸을 번호로 부르면 왜 문제가 되나요?

awk는 기본으로 공백마다 칸을 나누는데 UA에는 공백이 줄마다 다른 개수로 들어 있어서, 그 뒤의 칸 번호가 줄마다 바뀐다. 마지막 칸은 `$NF`로 부르고, 따옴표로 둘러싼 칸은 `-F'"'`로 따옴표를 구분자로 쓰면 통째로 꺼낼 수 있다. 형식이 복잡하면 처음부터 JSON 로그를 남기는 편이 낫다.

### sed -i를 실행 중인 로그 파일에 쓰면 무슨 일이 생기나요?

sed -i는 임시 파일에 고친 내용을 쓰고 rename으로 원래 이름을 덮기 때문에 inode가 바뀐다. 파일을 열어 둔 프로세스는 옛 inode에 계속 써서 이후 로그가 지워진 파일로 들어가고, `/proc/<PID>/fd`에 `(deleted)`로 보이며 디스크 공간도 돌아오지 않는다. 같은 이유로 심볼릭 링크는 일반 파일로 바뀌고 하드 링크는 끊긴다.

### grep으로 IP를 찾을 때 주의할 점은요?

정규식의 점은 아무 글자 하나라서 `10.0.2.1`은 `10.0.2.103` 같은 주소에도 맞는다. 점을 `\.`으로 이스케이프하고 뒤를 공백이나 줄 끝으로 막거나, 정규식이 필요 없으면 `-F`로 고정 문자열을 찾는다. 차단 목록을 이렇게 만들다 틀리면 엉뚱한 사용자를 막는다.

### tail -f 결과를 grep으로 거르는데 출력이 늦게 나옵니다. 왜인가요?

grep은 출력이 터미널이 아니라 파이프로 갈 때 버퍼를 모아서 한꺼번에 내보낸다. 그래서 `tail -F log | grep pattern | 다른명령`에서는 몇 KB가 찰 때까지 아무것도 안 보인다. `grep --line-buffered`를 주면 줄마다 바로 내보낸다. 로그가 돌아가도 따라가려면 tail은 `-f`보다 `-F`를 쓴다.

### Ubuntu에서 awk 스크립트가 다른 서버에서는 안 도는 경우가 있습니다. 이유는요?

Ubuntu의 기본 awk는 mawk이고 gawk를 설치하면 awk가 gawk로 바뀐다. asort 같은 gawk 전용 함수는 mawk에서 "function asort never defined"로 멈춘다. 공유할 스크립트는 POSIX awk 기능만 쓰거나, gawk를 명시하고 설치 목록에 넣는다.
